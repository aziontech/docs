<DocCallout kind="tip">Not sure which one? Take the template path: it needs no local tooling, and everything you learn on it applies to the other two.</DocCallout>

## Before you start

All you need is an [Azion account](https://console.azion.com/signup). You can create one for free on the Hobby plan. Anything path-specific is listed in the path itself.

## Deploy a template via Console

Templates are ready-made projects (e-commerce, blogs, APIs, full-stack SSR) that go live in a few clicks. You do not need any local tooling.

<DocCallout kind="note">Templates with integrations or specific settings can ask for more input, such as accounts or tokens on other services. Templates integrated with GitHub, such as Astro Boilerplate, also need a GitHub account and ask you to connect it: select Connect with GitHub when prompted and confirm the connection in the window that opens. Each template's guide lists what it needs.</DocCallout>

<DocSteps>
  <DocStep title="Access Azion Console." />
  <DocStep title="Select + Create on the homepage." />
  <DocStep title="In the modal, select Templates." />
  <DocStep title="Select the Astro Boilerplate template, or browse and pick another one." />
  <DocStep title="Fill in the configuration page." />
  <DocStep title="Select Deploy, in the bottom-right corner." />
</DocSteps>

Follow the deploy through the logs window. When it finishes, the page shows your application's name, its deploy logs, and its Azion domain. Some templates also create a function and apply pre-defined configurations to optimize your application's performance. The template's guide lists what is included.

### Check the application

Copy the Azion domain from the confirmation page:

```bash
curl -I https://<your-azion-domain>
# HTTP/2 200
```

Open the same URL in the browser to see your application running.

<DocCallout kind="note">New URLs can take a few minutes to propagate to Azion's data centers. If you get an error right after deploying, wait a moment and try again.</DocCallout>

## Import a project from GitHub

<DocCallout kind="warning">You need a GitHub account and a repository built with a framework that the **Preset** list carries: Next.js, Angular, Astro, Hexo, React, or Vue. Before you start, check your framework and its version in [Frameworks compatibility](/en/documentation/devtools/runtime/frameworks/frameworks-compatibility/): a framework or a version that Azion does not support can fail at build time.</DocCallout>

<DocSteps>
  <DocStep title="In Azion Console, select + Create." />
  <DocStep title="Select Import from Git." />
  <DocStep title="Connect the Git account that owns the repository." />
  <DocStep title="Pick the repository to import." />
  <DocStep title="Name the application.">

  The Console fills **Application Name** with the repository name. The name must be unique on your account, and the storage bucket and the function of the project take the same name.

  </DocStep>
  <DocStep title="In Preset, select the framework of the repository.">

  The preset sets the initial settings for that framework.

  </DocStep>
  <DocStep title="In Root Directory, keep the default value.">

  The default value, `/`, applies when the project code is at the root of the repository.

  </DocStep>
  <DocStep title="In Install Command, enter the command that installs the project.">

  For example, `npm install`.

  </DocStep>
  <DocStep title="Select Deploy.">

  The **Deploy Log** panel shows the build until the Azion domain shows up.

  </DocStep>
</DocSteps>

If the deploy fails, the page shows **Creation failed**, and the **Deploy Log** panel carries the details of the failure. For every field of the import, refer to [Import a project from GitHub](/en/documentation/guides/application-development/automation/import-an-existing-project-from-github/).

### Check the application

```bash
curl -I https://<your-azion-domain>
# HTTP/2 200
```

Open the Azion domain in the browser to see your application running. If you get an error right away, wait a few minutes: new URLs take a moment to propagate to Azion's data centers.

## Deploy with Azion CLI

<DocCallout kind="warning">You need a local project that uses a supported framework, with its dependencies installed, or you create one from a template in step 3. Before you start, check your framework and its version in [Frameworks compatibility](/en/documentation/devtools/runtime/frameworks/frameworks-compatibility/): a framework or a version that Azion does not support can fail at build time.</DocCallout>

<DocPrompt client:visible kind="line" title="AI Assistant">Follow the "Deploy with Azion CLI" section of https://www.azion.com/en/documentation/fundamentals/first-deploy.md to deploy this project, and print the Azion domain once it answers 200. `azion login` and `azion init` need an interactive terminal: when you reach them, stop and ask me to run them. For the other commands, use flags instead of prompts.</DocPrompt>

<DocSteps>
  <DocStep title="Set up the Azion CLI">

  ```bash
  curl -fsSL https://cli.azion.app/install.sh | bash
  ```

  </DocStep>
  <DocStep title="Log in">

  ```bash
  azion login
  ```

  The CLI saves a personal token locally, which authorizes the commands that follow.

  In a script or a CI job, `azion login` cannot ask its questions. Pass the token with the global option [`--token`](/en/documentation/devtools/cli/globals/) instead. For a command that stops at a question, refer to [Troubleshoot Azion CLI](/en/documentation/devtools/cli/troubleshooting/#a-command-stops-with-eof-or-failed-to-parse-your-response).

  </DocStep>
  <DocStep title="Initialize or link the project">

  To start from a template, run the command where you want the project folder created. It asks for a preset, which is the framework, then for a template, and creates a folder with the project's name; accept installing the dependencies:

  ```bash
  azion init
  ```

  To use a project you already have, run the command in its root folder. It asks you to confirm the link, to accept or change the suggested application name, and to pick the preset that matches your framework; the `.gitignore` entry and the GitHub Actions workflow it offers are optional:

  ```bash
  azion link
  ```

  When either command asks whether to deploy, answer no: the next step does it.

  </DocStep>
  <DocStep title="Deploy">

  ```bash
  azion deploy
  ```

  The CLI builds the project, uploads it, creates the application with its domain, and prints the domain at the end.

  </DocStep>
  <DocStep title="Check the application">

  ```bash
  curl -I https://<your-azion-domain>
  # HTTP/2 200
  ```

  If you get an error right away, wait a few minutes: new URLs take a moment to propagate to Azion's data centers.

  </DocStep>
</DocSteps>

## What you built

You deployed an application to Azion's distributed infrastructure and confirmed it answers on its own domain. The workflow is the same one you will use for production projects.
