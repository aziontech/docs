You can read the requests a [Web Application Firewall (WAF)](/en/documentation/platform/firewall/waf/) rule set matched, and turn the legitimate ones into exceptions, from the **Tuning** tab in Azion Console. The Azion CLI and the API have no Tuning command. To write one exception by hand, refer to [Create a WAF exception](/en/documentation/guides/application-security/firewall-and-waf/configure-waf-allowed-rules/).

---

## Prerequisites

- A rule set that a rule of a Firewall applies with a _Set WAF_ behavior. Refer to [Create and apply a WAF rule set](/en/documentation/guides/application-security/firewall-and-waf/create-waf-rule-set/).
- A Workload whose deployment sets that Firewall. The **Tuning** tab requires one.
- Requests that the rule set scored in the last 3 days, the longest time range Tuning reads. WAF scored requests only when the Application sent them to a Connector.
- Access to [Azion Console](https://console.azion.com/). Refer to [Access Azion Console](/en/documentation/guides/platform/account-and-billing/how-to-access-azion-console/).

---

## Filter the Tuning records

A query reads one time range and at least one Workload. The other filters narrow it. To read the records in Azion Console:

<DocSteps>
  <DocStep title="Open the WAF Rules page">

  Access [Azion Console](https://console.azion.com/) > **WAF Rules**.

  </DocStep>
  <DocStep title="Select the rule set to tune" />
  <DocStep title="Select the Tuning tab" />
  <DocStep title="Choose a time range">

  The options run from **Last 1 hour** to **Last 3 days**.

  </DocStep>
  <DocStep title="Select one or more Workloads">

  This filter is required. On an account that still uses domains, the filter reads **Domain** instead of **Workload**.

  </DocStep>
  <DocStep title="(Optional) Select a Network List">

  The query then returns only the records whose client address the [Network List](/en/documentation/platform/firewall/network-shield/network-lists/) holds.

  </DocStep>
  <DocStep title="(Optional) Add a field filter">

  Select **Filter**, choose **Country** or **IP Address**, then select **Apply**.

  </DocStep>
</DocSteps>

The Console shows how many records it found, and lists one row per internal rule that matched, with the columns **Rule ID**, **Hits**, **Paths**, **IPs**, **Countries**, **Top 10 IP Addresses**, and **Top 10 Countries**.

:::note
The **IP Address** field cannot be combined with an IP or CIDR Network List, and the **Country** field cannot be combined with a country Network List. The Console warns you when a query carries both.
:::

For every filter and column of this tab, refer to [WAF Exceptions](/en/documentation/platform/firewall/waf/custom-allowed-rules/#tuning).

## Create exceptions from the records

Azion Console calls an exception an allowed rule. One selection writes several of them, one for each possible attack on each path. To allow records in Azion Console:

<DocSteps>
  <DocStep title="Select a rule ID in the results list">

  The **More Details** drawer opens with the occurrences of that rule ID.

  </DocStep>
  <DocStep title="Select the records to allow">

  Select the checkbox of each record.

  </DocStep>
  <DocStep title="Select Allow Rules" />
  <DocStep title="Enter the reason for allowing these rules">

  The reason becomes the description of each allowed rule.

  </DocStep>
  <DocStep title="Select Allow Rules to confirm" />
</DocSteps>

The Console shows how many allowed rules it created, and each one appears on the **Allowed Rules** tab of the rule set.

When the Console writes only part of a selection, it shows the message **Partial failure** with the number created. Select the remaining records and allow them again.
