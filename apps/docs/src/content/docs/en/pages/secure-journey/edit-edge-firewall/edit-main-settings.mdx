You can set the main settings of a [Firewall](/en/documentation/platform/firewall/) from Azion Console, the Azion CLI, or the API: its name, its WAF, Network Shield, and Functions switches, Debug Rules, and its status. The rules the Firewall runs belong to its **Rules Engine** tab instead. To add one, refer to [Create a Firewall rule](/en/documentation/guides/application-security/firewall-and-waf/work-with-rules-engine/).

A Firewall carries no domains: the deployment of a Workload sets it. To set a Firewall on a Workload, refer to [Set a Firewall on a Workload](/en/documentation/guides/application-security/firewall-and-waf/firewall-protect-your-domain/).

## Turn WAF, Network Shield, or Functions on or off

The **Modules** section of the main settings holds one switch each for [Web Application Firewall (WAF)](/en/documentation/platform/firewall/waf/), [Network Shield](/en/documentation/platform/firewall/network-shield/), and [Functions](/en/documentation/platform/firewall/functions/). A rule cannot use the criteria and behaviors that a switch gates while the switch is off, and a Firewall accepts rules only while at least one of the three switches is on. For what each switch adds to a rule, refer to [Nested resources and switches on a Firewall](/en/documentation/platform/firewall/how-it-works/#nested-resources-and-switches-on-a-firewall).

A Firewall created with the API, the Azion CLI, or the **Create Firewall** page starts with Network Shield and Functions on and WAF off. One created from a drawer in Azion Console starts with Functions off. Confirm that **Functions** is on before you add a Function Instance.

Bot Manager has no switch of its own. [Bot Manager](/en/documentation/platform/firewall/bot-manager/) runs as a Function Instance that a _Run Function_ behavior runs, so it needs Functions on the Firewall. To set it up, refer to [Bot Manager quickstart](/en/documentation/platform/firewall/bot-manager/quickstart/).

<Tabs client:visible sharedStore="interface">

<Fragment slot="panel.console">

### Console

To turn on WAF, Network Shield, or Functions in Azion Console:

<DocSteps>
  <DocStep title="Open the Firewall">

  Access [Azion Console](https://console.azion.com/) > **Firewalls**, then select the Firewall.

  </DocStep>
  <DocStep title="Select the Main Settings tab" />
  <DocStep title="Turn on the switch">

  In the **Modules** section, turn on each switch you need: **Web Application Firewall**, **Network Shield**, or **Functions**.

  </DocStep>
  <DocStep title="Save the settings">

  Select **Save**.

  </DocStep>
</DocSteps>

Azion Console shows `Your Firewall has been updated`. To turn one off, turn its switch off in the same section and select **Save**.

</Fragment>

<Fragment slot="panel.cli">

### CLI

To turn on WAF, Network Shield, or Functions with the Azion CLI, run `azion update firewall` with its flag set to `true`. This command turns on Network Shield, with the ID of your Firewall in place of `<firewall-id>`:

```bash
azion update firewall --firewall-id <firewall-id> --network-protection true
```

The command prints the ID of the Firewall it updated:

```text
Updated Firewall with ID <firewall-id>
```

The flag for WAF is `--waf-enabled`, and the flag for Functions is `--functions-enabled`. Set a flag to `false` to turn its switch off.

While a rule of the Firewall uses the `${network}` criterion, the CLI refuses to turn Network Shield off:

```bash
azion update firewall --firewall-id <firewall-id> --network-protection false
```

The error lists the IDs of the rules that use the criterion:

```text
Error: Failed to update the Firewall: ["Cannot disable firewall network protection module, because it is being referenced by the following rules: <rule-id>. Delete those rules or remove their network criteria, then disable the module."]. Check your settings and try again. If the error persists, contact Azion support
```

</Fragment>

<Fragment slot="panel.api">

### API

To turn on WAF, Network Shield, or Functions with the API, send a `PATCH` request to the Firewall. The body sets its `enabled` key inside `modules`. This request turns on Network Shield:

```bash
curl --request PATCH \
  --url https://api.azion.com/v4/workspace/firewalls/<firewall-id> \
  --header 'Accept: application/json' \
  --header 'Authorization: Token [TOKEN VALUE]' \
  --header 'Content-Type: application/json' \
  --data '{"modules":{"network_protection":{"enabled":true}}}'
```

The API answers `202` and returns the Firewall with Network Shield on:

```text
{"state":"pending","data":{"id":<firewall-id>,…,"modules":{…,"network_protection":{"enabled":true},…}}}
```

The key for WAF is `modules.waf.enabled`, and the key for Functions is `modules.functions.enabled`. `modules.ddos_protection` is read-only. Set `"enabled": false` to turn a switch off. The [Azion API reference](https://api.azion.com/) documents every key of a Firewall.

While a rule of the Firewall uses the `${network}` criterion, a `PATCH` that sets `network_protection` to `"enabled": false` is refused with `400`:

```text
{"errors":[{"code":"24005","title":"Cannot Disable Firewall Network Protection Module","detail":"Cannot disable firewall network protection module, because it is being referenced by the following rules: <rule-id>. Delete those rules or remove their network criteria, then disable the module.","status":"400","source":{"pointer":"/data/modules/network_protection/enabled"},"meta":{"referenced_in_rules":"<rule-id>"}}]}
```

</Fragment>

</Tabs>

Network Shield cannot be turned off while any rule of the Firewall uses the `${network}` criterion. The refusal lists the ID of each of those rules.

Save the main settings before you create a rule that needs a switch. The **Rules Engine** tab reads the saved settings. While a switch is off, the options it gates still appear in that tab with a suffix, such as _Set WAF - required WAF_ or _Network - required Network Shield_, but they cannot be selected. For the switch each criterion and behavior needs, refer to [Rules Engine for Firewall](/en/documentation/platform/firewall/rules-engine/#criteria).

## Log the rules a Firewall runs

With Debug Rules on, the Firewall logs each Rules Engine rule that runs on a request. [Real-Time Events](/en/documentation/platform/real-time-events/) and [Data Stream](/en/documentation/platform/data-stream/) show those rules in the `$traceback` field. The Real-Time Events GraphQL API shows them in the `stacktrace` field. Debug Rules is off in a new Firewall.

To turn on Debug Rules in Azion Console:

<DocSteps>
  <DocStep title="Open the Firewall">

  Access [Azion Console](https://console.azion.com/) > **Firewalls**, then select the Firewall.

  </DocStep>
  <DocStep title="Select the Main Settings tab" />
  <DocStep title="Turn on Debug Rules">

  In the **Debug Rules** section, turn on **Active**.

  </DocStep>
  <DocStep title="Save the settings">

  Select **Save**.

  </DocStep>
</DocSteps>

Azion Console shows `Your Firewall has been updated`. A rule that is missing from the `$traceback` field of a request did not run on that request. To read the field, refer to [Debug rules created with Rules Engine](/en/documentation/guides/application-development/getting-started/debug-rules/).

## Rename a Firewall

The name identifies the Firewall in the **Firewalls** list, and it is the heading of the Firewall's page. Every Firewall needs one, so the **Name** field cannot be left empty.

To rename the Firewall in Azion Console:

<DocSteps>
  <DocStep title="Open the Firewall">

  Access [Azion Console](https://console.azion.com/) > **Firewalls**, then select the Firewall.

  </DocStep>
  <DocStep title="Select the Main Settings tab" />
  <DocStep title="Enter the new name">

  In the **General** section, enter a unique, descriptive **Name**, such as `storefront-firewall`.

  </DocStep>
  <DocStep title="Save the settings">

  Select **Save**.

  </DocStep>
</DocSteps>

Azion Console shows `Your Firewall has been updated`, and the new name appears in the **Name** column of the **Firewalls** list.

## Deactivate a Firewall

The **Status** section of the main settings holds the Firewall's **Active** switch. The switch is on in a new Firewall.

To deactivate the Firewall in Azion Console:

<DocSteps>
  <DocStep title="Open the Firewall">

  Access [Azion Console](https://console.azion.com/) > **Firewalls**, then select the Firewall.

  </DocStep>
  <DocStep title="Select the Main Settings tab" />
  <DocStep title="Turn off the Firewall">

  In the **Status** section, turn off **Active**.

  </DocStep>
  <DocStep title="Save the settings">

  Select **Save**.

  </DocStep>
</DocSteps>

Azion Console shows `Your Firewall has been updated`. To activate the Firewall again, turn on **Active** in the **Status** section and select **Save**.

## Confirm the main settings of a Firewall

A read of the Firewall after a change returns the saved settings. Read them before you create a rule that needs a switch.

<Tabs client:visible sharedStore="interface">

<Fragment slot="panel.console">

### Console

To confirm the settings in Azion Console:

<DocSteps>
  <DocStep title="Open the Firewall">

  Access [Azion Console](https://console.azion.com/) > **Firewalls**, then select the Firewall.

  </DocStep>
  <DocStep title="Select the Main Settings tab">

  The tab holds four sections: **General**, **Modules**, **Debug Rules**, and **Status**.

  </DocStep>
</DocSteps>

Each switch in the **Modules** section shows whether WAF, Network Shield, or Functions is on in the Firewall.

</Fragment>

<Fragment slot="panel.cli">

### CLI

To confirm the settings with the Azion CLI, describe the Firewall in JSON, with its ID in place of `<firewall-id>`:

```bash
azion describe firewall --firewall-id <firewall-id> --format json
```

The output carries the `modules` object, with one `enabled` key per switch:

```json
{
 "modules": {
  "ddos_protection": { "enabled": true },
  "functions":       { "enabled": true },
  "network_protection": { "enabled": true },
  "waf":             { "enabled": false }
 },
 "product_version": "2.0"
}
```

In this Firewall, every switch except WAF is on.

</Fragment>

<Fragment slot="panel.api">

### API

To confirm the settings with the API, send a `GET` request to the Firewall:

```bash
curl --request GET \
  --url https://api.azion.com/v4/workspace/firewalls/<firewall-id> \
  --header 'Accept: application/json' \
  --header 'Authorization: Token [TOKEN VALUE]'
```

The API answers `200` and returns the Firewall:

```text
{"data":{"id":<firewall-id>,"name":"<firewall-name>",
 "modules":{"ddos_protection":{"enabled":true},"functions":{"enabled":true},
            "network_protection":{"enabled":true},"waf":{"enabled":true}},
 "debug":false,"active":true,…}}
```

`modules` holds one `enabled` key per switch, `debug` holds Debug Rules, and `active` holds the status. In this Firewall, every switch is on and Debug Rules is off.

</Fragment>

</Tabs>

Each main setting carries one name in each interface. The CLI flags apply to `azion create firewall` and `azion update firewall`, and every flag in this table except `--name` takes `true` or `false`:

| Setting | Azion Console | Azion CLI flag | API key |
| --- | --- | --- | --- |
| Name | **Name**, in **General** | `--name` | `name` |
| Functions | **Functions**, in **Modules** | `--functions-enabled` | `modules.functions.enabled` |
| Network Shield | **Network Shield**, in **Modules** | `--network-protection` | `modules.network_protection.enabled` |
| WAF | **Web Application Firewall**, in **Modules** | `--waf-enabled` | `modules.waf.enabled` |
| DDoS Protection | **DDoS Protection Unmetered**, in **Modules** | None | `modules.ddos_protection.enabled`, read-only |
| Debug Rules | **Active**, in **Debug Rules** | `--debug-rules` | `debug` |
| Status | **Active**, in **Status** | `--active` | `active` |

The saved settings reach traffic only after the change propagates. For more information on propagation, refer to [How Firewall works](/en/documentation/platform/firewall/how-it-works/#propagation).
