You can install [Bot Manager Lite](/en/documentation/platform/firewall/bot-manager/bot-manager-lite/) from Azion Marketplace and run it on the requests to your Workload, from Azion Console, starting with no Firewall. To create the Function Instance and the rule with the Azion CLI or the API, and to send a request that proves the Function scored it, refer to [Bot Manager quickstart](/en/documentation/platform/firewall/bot-manager/quickstart/).

---

## Prerequisites

- An Azion account. To sign in, refer to [How to access Azion Console](/en/documentation/guides/platform/account-and-billing/how-to-access-azion-console/).
- An Application served by a [Workload](/en/documentation/platform/workloads/), on a domain of the form `<id>.map.azionedge.net` or on a domain of your own.
- Turning on a Platform Resource can generate usage costs. For the metrics Bot Manager is billed on, refer to [Pricing](/en/documentation/fundamentals/pricing/#bot-manager).

## Install the integration from Marketplace

The Function is installed once per account, and the install runs in Azion Console. To install it:

<DocSteps>
  <DocStep title="Open Marketplace">

  Access [Azion Console](https://console.azion.com/) > **Marketplace**.

  </DocStep>
  <DocStep title="Find the integration">

  Find the Bot Manager Lite integration among the cards, then select its card. The **Category**, **Type**, and **Vendor** filters narrow the cards.

  </DocStep>
  <DocStep title="Select Install" />
</DocSteps>

The card shows `Successfully installed!` and `Latest version installed!`, and the Function appears in the **Function** list of the **Create Instance** drawer. In Azion Console > **Functions**, under **Edge Libraries**, the **Vendor** column shows its vendor.

## Create the Firewall

The [Firewall](/en/documentation/platform/firewall/) holds the Function Instance and the rule that runs it. To create one:

<DocSteps>
  <DocStep title="Open the Firewalls page">

  Access [Azion Console](https://console.azion.com/) > **Firewalls**, then select **Firewall**.

  </DocStep>
  <DocStep title="Name the Firewall">

  In the **General** section, enter a **Name**. For example: `storefront-firewall`.

  </DocStep>
  <DocStep title="Confirm that Functions is turned on">

  In the **Modules** section, the **Functions** switch is what lets a Firewall run an installed Function. A Firewall created on this page, with the Azion CLI, or with the API starts with **Functions** turned on.

  </DocStep>
  <DocStep title="(Optional) Turn on Debug Rules">

  In the **Debug Rules** section, turn on the **Active** switch. The Firewall then logs the rules it ran for each request, which tells you whether the rule of this guide ran.

  </DocStep>
  <DocStep title="Select Save" />
</DocSteps>

The Firewall carries a **Functions Instances** tab for as long as **Functions** stays turned on. For every setting on this form, refer to [Set a Firewall's main settings](/en/documentation/guides/application-security/firewall-and-waf/firewall-configure-main-settings/).

## Create the Function Instance

A [Function Instance](/en/documentation/platform/firewall/functions-instances/) takes its whole configuration from one JSON object. A key the object leaves out stays absent from the Function Instance. To see how a Function Instance stores its arguments, refer to [Fields](/en/documentation/platform/firewall/bot-manager/arguments/#fields).

Bot Manager Lite ships a default for eight arguments. A Function Instance created through the API with no `args` field receives a copy of them. Among them are a `threshold` of `30`, an `action` of `deny`, `internal_logs` at `0`, and a `log_tag` of `bot-manager-instance`.

Four arguments are enough for a first Function Instance:

```json
{
  "threshold": 30,
  "action": "deny",
  "internal_logs": 2,
  "log_tag": "storefront-bots"
}
```

`threshold` is the score a request reaches before the Function applies `action` to it. `internal_logs` at `2` writes a report line for every request, including one that scores `0`, so the first days of traffic become readable. `log_tag` identifies this Function Instance in those lines, so give each Function Instance a tag of its own. An `action` of `allow`, until you know how your own traffic scores, keeps the Function Instance from refusing a customer. For that window and its cost, refer to [Best practices for Firewall](/en/documentation/platform/firewall/best-practices/#bot-manager).

:::caution
The API checks that the arguments are a JSON object or array, and it checks no key. A misspelled argument such as `thresold` is stored as typed, the API and the Azion CLI raise no error, and `threshold` stays absent from the Function Instance. To see what the Function does without it, refer to [Threshold](/en/documentation/platform/firewall/bot-manager/arguments/#threshold).
:::

To create the Function Instance:

<DocSteps>
  <DocStep title="Open the Functions Instances tab">

  In **Firewalls**, select the Firewall you created, then select the **Functions Instances** tab.

  </DocStep>
  <DocStep title="Select Function">

  On a Firewall that carries no Function Instance yet, the same action reads **Function Instance**. The **Create Instance** drawer opens.

  </DocStep>
  <DocStep title="Name the Function Instance">

  In the **General** section, enter a **Name**. For example: `bot-manager-lite`.

  </DocStep>
  <DocStep title="Select the installed Function">

  In the **Function** section, select the Bot Manager Lite Function. The selector lists only the Functions in the account that run on a Firewall.

  </DocStep>
  <DocStep title="Enter the arguments">

  In the **Arguments** section, the JSON editor opens with the default arguments of the Function. Replace them with the object.

  </DocStep>
  <DocStep title="Select Save" />
</DocSteps>

The Function Instance is listed under **Functions Instances**, with its **Name**, **Function**, **Last Editor**, and **Last Modified**. The form carries no **Active** control, because Azion Console creates every Function Instance active.

To change an argument afterwards, select the Function Instance in the same tab, edit the **Arguments** section, and select **Save**. The change takes effect once it propagates, so wait before you read a response as the new configuration. For more information, refer to [Propagation](/en/documentation/platform/firewall/how-it-works/#propagation). For every argument the object accepts, with its type and its default, refer to [Bot Manager Lite](/en/documentation/platform/firewall/bot-manager/bot-manager-lite/#arguments).

## Create the rule

The Function Instance scores nothing until a rule runs it. A [Rules Engine for Firewall](/en/documentation/platform/firewall/rules-engine/) rule decides which requests reach the Function Instance, through a _Run Function_ behavior that runs it. To create the rule:

<DocSteps>
  <DocStep title="Open the Rules Engine tab">

  In **Firewalls**, select your Firewall, then select the **Rules Engine** tab.

  </DocStep>
  <DocStep title="Select Rule">

  The **Create Rule** drawer opens.

  </DocStep>
  <DocStep title="Name the rule">

  In the **General** section, enter a **Name**. For example: `Run Bot Manager Lite on every request`. The description is optional.

  </DocStep>
  <DocStep title="Set the criterion">

  In the **Criteria** section, select the _Request Uri_ variable, the _starts with_ operator, and `/` as the argument.

  </DocStep>
  <DocStep title="Add the Run Function behavior">

  In the **Behaviors** section, select _Run Function_. A second control appears, with the placeholder `Select a Function`: it lists the Function Instances on this Firewall, so select the one you named. A rule carries at most one _Run Function_ behavior.

  </DocStep>
  <DocStep title="Select Save" />
</DocSteps>

The Firewall runs the Function Instance on every request it receives.

A second criterion narrows that set. _Request Uri_ with the _does not match_ operator keeps the Function Instance off requests that carry nothing to score: static assets, and the `/.well-known/` path that automation and web API clients use. For the extensions to exclude and what the exclusion costs, refer to [Best practices for Firewall](/en/documentation/platform/firewall/best-practices/#bot-manager).

## Set the Firewall on the Workload

The deployment of the Workload sets the Firewall. To set your Firewall in Azion Console:

<DocSteps>
  <DocStep title="Open the Workloads page">

  Access [Azion Console](https://console.azion.com/) > **Workloads**.

  </DocStep>
  <DocStep title="Open the Workload">

  Select the Workload that serves your Application. Its edit form opens.

  </DocStep>
  <DocStep title="Select your Firewall">

  In the **Deployment Settings** section, select your Firewall in the **Firewall** field. **Application** and **Custom Page** keep the values the Workload serves today.

  </DocStep>
  <DocStep title="Select Save" />
</DocSteps>

After the save, the deployment of the Workload sets your Firewall, and the rule runs the Function Instance on each request to the Workload. A newly set Workload can take several minutes to apply the rules of its Firewall, so wait before you read anything into a response. For more information, refer to [Propagation](/en/documentation/platform/firewall/how-it-works/#propagation). For every field a deployment holds, refer to [Workload settings](/en/documentation/platform/workloads/settings/).

The report line the Function writes is where the result of a scored request is. For more information, refer to [Logs](/en/documentation/platform/firewall/bot-manager/logs/).
