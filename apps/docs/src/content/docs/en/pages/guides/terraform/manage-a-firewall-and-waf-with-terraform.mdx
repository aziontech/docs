You can declare a [Firewall](/en/documentation/platform/firewall/), its rules, the order of those rules, and a [Web Application Firewall (WAF)](/en/documentation/platform/firewall/waf/) rule set with the [Azion Terraform Provider](/en/documentation/devtools/terraform/). A Firewall inspects the requests received by a [Workload](/en/documentation/platform/workloads/) once that Workload's deployment sets that Firewall. The examples deny every path that starts with `/admin` and apply the WAF rule set in blocking mode to every other path.

---

## Prerequisites

- Terraform 1.17.2 or later. To install it, refer to [Install Terraform](/en/documentation/devtools/terraform/getting-started/#install-terraform).
- A personal token in the `AZION_API_TOKEN` environment variable. To set it, refer to [Provide your personal token](/en/documentation/devtools/terraform/getting-started/#provide-your-personal-token).
- A Terraform configuration that manages a Workload, its [Application](/en/documentation/platform/applications/), and its `azion_workload_deployment`. To write one, refer to [Manage an Application with Terraform](/en/documentation/guides/application-development/automation/manage-an-application-with-terraform/). The examples use the resource names of that page: `hello` for the Workload and the Application, and `run_function` for its rule.

---

## Declare the Firewall, its rules, and the WAF rule set

The Firewall side of the configuration declares five resources of four types:

- `azion_waf` is the WAF rule set: the threat families it scores and the sensitivity of each. The provider's `azion_waf_rule_set` resource manages exceptions, not this rule set.
- `azion_firewall_main_setting` is the Firewall, with WAF turned on in its `modules`.
- Each `azion_firewall_rule_engine` is one rule of the Firewall. `Deny /admin` answers `403` to every path that starts with `/admin`. `Apply storefront-waf` runs the WAF rule set in blocking mode on every other path.
- `azion_firewall_rule_engine_order` lists the rule IDs in the order the Firewall evaluates them.

In the directory of your configuration, create a `firewall.tf` file:

<Code client:visible lang="hcl" fileName="firewall.tf" code={`resource "azion_waf" "site" {
\x20 result = {
\x20   name   = "storefront-waf"
\x20   active = true
\x20   engine_settings = {
\x20     engine_version = "2021-Q3"
\x20     type           = "score"
\x20     attributes = {
\x20       rulesets = [1]
\x20       thresholds = [
\x20         {
\x20           threshold = {
\x20             threat      = "sql_injection"
\x20             sensitivity = "high"
\x20           }
\x20         },
\x20         {
\x20           threshold = {
\x20             threat      = "cross_site_scripting"
\x20             sensitivity = "high"
\x20           }
\x20         }
\x20       ]
\x20     }
\x20   }
\x20 }
}

resource "azion_firewall_main_setting" "site" {
\x20 data = {
\x20   name   = "storefront-firewall"
\x20   active = true
\x20   modules = {
\x20     waf = {
\x20       enabled = true
\x20     }
\x20   }
\x20 }
}

resource "azion_firewall_rule_engine" "deny_admin" {
\x20 firewall_id = azion_firewall_main_setting.site.data.id
\x20 results = {
\x20   name   = "Deny /admin"
\x20   active = true
\x20   behaviors = [
\x20     {
\x20       behavior = {
\x20         type = "deny"
\x20       }
\x20     }
\x20   ]
\x20   criteria = [
\x20     {
\x20       entries = [
\x20         {
\x20           criterion = {
\x20             variable    = "$\${request_uri}"
\x20             operator    = "starts_with"
\x20             conditional = "if"
\x20             argument    = "/admin"
\x20           }
\x20         }
\x20       ]
\x20     }
\x20   ]
\x20 }
}

resource "azion_firewall_rule_engine" "waf" {
\x20 firewall_id = azion_firewall_main_setting.site.data.id
\x20 results = {
\x20   name   = "Apply storefront-waf"
\x20   active = true
\x20   behaviors = [
\x20     {
\x20       behavior = {
\x20         type = "set_waf"
\x20         attributes = {
\x20           waf_id = azion_waf.site.result.id
\x20           mode   = "blocking"
\x20         }
\x20       }
\x20     }
\x20   ]
\x20   criteria = [
\x20     {
\x20       entries = [
\x20         {
\x20           criterion = {
\x20             variable    = "$\${request_uri}"
\x20             operator    = "starts_with"
\x20             conditional = "if"
\x20             argument    = "/"
\x20           }
\x20         }
\x20       ]
\x20     }
\x20   ]
\x20 }
}

resource "azion_firewall_rule_engine_order" "site" {
\x20 firewall_id = azion_firewall_main_setting.site.data.id
\x20 order = [
\x20   azion_firewall_rule_engine.deny_admin.results.id,
\x20   azion_firewall_rule_engine.waf.results.id,
\x20 ]
}`} />

`engine_version`, `engine_settings.type`, and `rulesets` each accept one value, the one in the example. The example declares two of the eight threat families in `thresholds`, and the rule set stores only the families it declares. For every threat and sensitivity, refer to [Rule sets](/en/documentation/platform/firewall/waf/rules-set/).

`$${request_uri}` writes the literal `${request_uri}` variable: the double `$` stops Terraform from reading it as an interpolation.

To change the order later, reorder the IDs in the `order` list and run `terraform apply`. The plan changes one resource.

The configuration declares a Firewall that evaluates `Deny /admin` first and `Apply storefront-waf` second.

## Attach the Firewall to the Workload

A Firewall inspects the requests received by a Workload once that Workload's deployment sets that Firewall, in the `firewall` attribute next to `application`.

To attach the Firewall:

1. Change the `azion_workload_deployment` resource of your configuration to match this block:

   <Code client:visible lang="hcl" code={`resource "azion_workload_deployment" "hello" {
   \x20 workload_id = azion_workload.hello.workload.id
   \x20 deployment = {
   \x20   name    = "hello-terraform"
   \x20   active  = true
   \x20   current = true
   \x20   strategy = {
   \x20     type = "default"
   \x20     attributes = {
   \x20       application = azion_application_main_setting.hello.application.application_id
   \x20       firewall    = azion_firewall_main_setting.site.data.id
   \x20     }
   \x20   }
   \x20 }
   \x20 depends_on = [
   \x20   azion_application_rule_engine.run_function,
   \x20   azion_firewall_rule_engine_order.site,
   \x20 ]
   }`} />

   The block sets `firewall` in `strategy` and adds the rule order to `depends_on`. Terraform then changes the deployment only after the rules exist in their order.

2. Check the configuration:

   <Code client:visible lang="bash" code={`terraform validate`} />

   ```text
   Success! The configuration is valid.
   ```

3. Apply the configuration, and enter `yes` when Terraform asks. The plan creates the five Firewall resources and changes the deployment in place:

   <Code client:visible lang="bash" code={`terraform apply`} />

   ```text
   Plan: 5 to add, 1 to change, 0 to destroy.
   ...
   azion_firewall_main_setting.site: Creation complete after 2s [id=104405]
   azion_waf.site: Creation complete after 2s [id=49819]
   azion_firewall_rule_engine.deny_admin: Creation complete after 2s [id=104405/170305]
   azion_firewall_rule_engine.waf: Creation complete after 2s [id=104405/170306]
   azion_firewall_rule_engine_order.site: Creation complete after 2s [id=104405]
   azion_workload_deployment.hello: Modifications complete after 2s [id=1795012149/362301]

   Apply complete! Resources: 5 added, 1 changed, 0 destroyed.
   ```

The Workload's deployment sets the Application and the Firewall. The Firewall holds two rules, in the order `Deny /admin`, `Apply storefront-waf`.

## Check the rules

`Deny /admin` answers `403` to every path that starts with `/admin`. The WAF rule set in blocking mode answers `400` with a **Bad Request** page when a threat family's score reaches its threshold. A request that no rule stops reaches the Application.

To check the rules, send three requests to the domain of your Workload. Replace `<your-workload-domain>` with that domain:

<Code client:visible lang="bash" code={`curl --silent --output /dev/null --write-out '%{http_code}\\n' "https://<your-workload-domain>/"
curl --silent --output /dev/null --write-out '%{http_code}\\n' "https://<your-workload-domain>/admin"
curl --silent --output /dev/null --write-out '%{http_code}\\n' "https://<your-workload-domain>/?id=1%27%20OR%20%271%27=%271"`} />

```text
200
403
400
```

The Application answers `/`, and `Deny /admin` refuses `/admin`. The WAF rule set blocks the request whose `id` query string carries a SQL injection pattern.

A Firewall added to a Workload that already serves requests can take about 10 minutes to take effect. Until then, `/admin` and the SQL injection request can alternate between `200` from the Application and the rules' codes. Repeat the requests every minute until each one returns its code three times in a row.
