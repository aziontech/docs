You can install the DataDome Bot Protection integration from Azion Marketplace and run it on a [Firewall](/en/documentation/platform/firewall/), from Azion Console. The integration detects and blocks automated threats such as credential stuffing, layer 7 DDoS, and scraping. For the other integrations that run on a Firewall, refer to [Marketplace integrations](/en/documentation/platform/marketplace/integrations/).

---

## Prerequisites

- An Azion account. To sign in, refer to [How to access Azion Console](/en/documentation/guides/platform/account-and-billing/how-to-access-azion-console/).
- An Application served by a [Workload](/en/documentation/platform/workloads/). The last section sets your Firewall on the deployment of that Workload.
- An active DataDome subscription, with a DataDome server-side API key. For the plans and their prices, refer to [datadome.co](https://datadome.co).
- Turning on a Platform Resource can generate usage costs. For more information, refer to [Pricing](/en/documentation/fundamentals/pricing/).

---

## Install the integration

The Function is installed once per account. To install it:

<DocSteps>
  <DocStep title="Open Marketplace">

  Access [Azion Console](https://console.azion.com/) > **Marketplace**.

  </DocStep>
  <DocStep title="Find the integration">

  Find the **DataDome Bot Protection** card, then select it. The **Category**, **Type**, and **Vendor** filters narrow the cards.

  </DocStep>
  <DocStep title="Select Install" />
</DocSteps>

The card shows `Successfully installed!` and `Latest version installed!`, and the Function appears in the **Function** list of the **Create Instance** drawer.

## Create the Firewall

The Firewall holds the Function Instance and the rule that runs it. To create one:

<DocSteps>
  <DocStep title="Open the Firewalls page">

  Access [Azion Console](https://console.azion.com/) > **Firewalls**, then select **Firewall**.

  </DocStep>
  <DocStep title="Name the Firewall">

  In the **General** section, enter a **Name**. For example: `datadome-firewall`.

  </DocStep>
  <DocStep title="Confirm that Functions is turned on">

  In the **Modules** section, the **Functions** switch is what lets a Firewall run an installed Function. A Firewall created on this page starts with **Functions** turned on.

  </DocStep>
  <DocStep title="Select Save" />
</DocSteps>

The Firewall shows a **Functions Instances** tab while **Functions** stays turned on. To use an existing Firewall instead, turn **Functions** on for it. For more information, refer to [Turn WAF, Network Shield, or Functions on or off](/en/documentation/guides/application-security/firewall-and-waf/firewall-configure-main-settings/#turn-waf-network-shield-or-functions-on-or-off).

## Create the Function Instance

The [Function Instance](/en/documentation/platform/firewall/functions-instances/) holds your DataDome server-side API key. To create it:

<DocSteps>
  <DocStep title="Open the Functions Instances tab">

  In **Firewalls**, select your Firewall, then select the **Functions Instances** tab.

  </DocStep>
  <DocStep title="Select Function">

  On a Firewall that carries no Function Instance yet, the same action reads **Function Instance**. The **Create Instance** drawer opens.

  </DocStep>
  <DocStep title="Name the Function Instance">

  In **Name**, enter a name. For example: `datadome`.

  </DocStep>
  <DocStep title="Select the installed Function">

  In **Function**, select the DataDome Bot Protection Function. The list holds only the Functions that run on a Firewall.

  </DocStep>
  <DocStep title="Enter your key">

  In **Arguments**, the JSON editor opens with the default arguments of the integration. Set `api_key` to your DataDome server-side API key.

  </DocStep>
  <DocStep title="Select Save" />
</DocSteps>

The Function Instance is listed in the **Functions Instances** tab.

## Create the rule

The Function Instance analyzes nothing until a rule runs it. A [Rules Engine for Firewall](/en/documentation/platform/firewall/rules-engine/) rule selects the requests that reach the Function Instance, through a _Run Function_ behavior. To create the rule:

<DocSteps>
  <DocStep title="Open the Rules Engine tab">

  In **Firewalls**, select your Firewall, then select the **Rules Engine** tab.

  </DocStep>
  <DocStep title="Select Rule">

  The **Create Rule** drawer opens.

  </DocStep>
  <DocStep title="Name the rule">

  In **Name**, enter a name. For example: `Run DataDome`.

  </DocStep>
  <DocStep title="Set the criterion">

  In the **Criteria** section, select the domains to protect. For example: _Host_ _matches_ `yourdomain.com`.

  </DocStep>
  <DocStep title="Add the Run Function behavior">

  In the **Behaviors** section, select _Run Function_. In the second control, with the placeholder `Select a Function`, select the DataDome Bot Protection Function Instance you created.

  </DocStep>
  <DocStep title="Select Save" />
</DocSteps>

The Firewall runs the Function Instance on every request to the domains in the criterion.

## Set the Firewall on the Workload

The deployment of the Workload sets the Firewall. To set your Firewall in Azion Console:

<DocSteps>
  <DocStep title="Open the Workloads page">

  Access [Azion Console](https://console.azion.com/) > **Workloads**.

  </DocStep>
  <DocStep title="Open the Workload">

  Select the Workload that serves your Application. Its edit form opens.

  </DocStep>
  <DocStep title="Select your Firewall">

  In the **Deployment Settings** section, select your Firewall in the **Firewall** field. **Application** and **Custom Page** keep the values the Workload serves today.

  </DocStep>
  <DocStep title="Select Save" />
</DocSteps>

After the save, the deployment of the Workload sets your Firewall, and DataDome Bot Protection runs on each request to the domains in the criterion. The DataDome Function sends the metadata of each request to the DataDome API, then allows, blocks, or challenges the request from the answer and from your DataDome dashboard settings. A newly set Workload can take several minutes to apply the rules of its Firewall. For more information, refer to [Propagation](/en/documentation/platform/firewall/how-it-works/#propagation).
