You can deploy a Next.js app to Azion with the `@aziontech/opennextjs-azion` adapter and the [Azion CLI](/en/documentation/devtools/cli/). The adapter builds the app for the `opennextjs` preset, and the CLI deploys it as an [application](/en/documentation/platform/applications/), a [function](/en/documentation/platform/functions/), and an [Object Storage](/en/documentation/platform/object-storage/) bucket. For a site with no server-side code, [Deploy a static export](/en/documentation/guides/application-development/frameworks/next/#deploy-a-static-export) is the shorter route.

---

## Prerequisites

- The [Azion CLI](/en/documentation/devtools/cli/#install-the-cli), [logged in](/en/documentation/devtools/cli/login/) to your account.
- Node.js and npm.
- A Next.js version the adapter supports: any version of Next.js 15, or the latest minor version of Next.js 14. For the details, refer to [Supported Next.js versions](/en/documentation/devtools/runtime/frameworks/nextjs-compatibility/#supported-nextjs-versions).

:::note
The adapter does not support Next.js 16. A Next.js 16 site that uses only static site generation (SSG) and needs no server can deploy as a fully static site. To deploy it, refer to [Deploy a static export](/en/documentation/guides/application-development/frameworks/next/#deploy-a-static-export).
:::

---

## Create a Next.js app

To create a Next.js 15 app and add the adapter to it:

1. Create the app with `create-next-app`, and change to its folder:

   ```bash
   npx create-next-app@15 my-next-app --use-npm
   cd my-next-app
   ```

2. Install the adapter as a development dependency:

   ```bash
   npm install -D @aziontech/opennextjs-azion
   ```

The app is ready to link. A new app already sets `"moduleResolution": "bundler"` in `tsconfig.json`, which the adapter needs.

---

## Prepare an existing Next.js app

To prepare an app that already exists:

1. In the app folder, install the project dependencies and the adapter as a development dependency:

   ```bash
   npm install
   npm install -D @aziontech/opennextjs-azion
   ```

2. In `tsconfig.json`, set `moduleResolution` to `bundler`:

   ```json
   "moduleResolution": "bundler"
   ```

Without this setting, the build or the deployed function can fail. If the build still fails on `open-next.config.ts`, refer to [Known issues](/en/documentation/devtools/runtime/frameworks/nextjs-compatibility/#known-issues).

---

## Link the app to Azion

`azion link` sets up the project folder for the `opennextjs` preset. It writes the `azion.config.cjs` file and the `azion/azion.json` file, and it creates nothing on Azion.

To link the app without questions, run this command in the app folder:

```bash
azion link --name my-next-app --preset opennextjs --auto
```

```text
Project successfully configured
Sucessfully written to your .gitignore file
Successfully created GitHub Actions workflow file at .github/workflows/azion-deploy.yml
Please, remember to run azion build --preset [preset-name], in order to generate the necessary configuration files
```

With `--auto`, the command also adds `.edge/`, `.vulcan`, and `.open-next` to `.gitignore` and writes a GitHub Actions workflow. For every flag, refer to [Azion CLI link](/en/documentation/devtools/cli/link-command/).

## Review the azion.config file

The `azion.config.cjs` file that `azion link` writes declares every resource the deploy creates, in the API v4 format:

```javascript
module.exports = {
  version: 4,
  build: {
    preset: 'opennextjs',
    polyfills: true
  },
  storage: [
    {
      name: '$BUCKET_NAME',
      prefix: '$BUCKET_PREFIX',
      dir: './.edge/assets',
      workloadsAccess: 'read_write'
    }
  ],
  connectors: [
    {
      name: '$CONNECTOR_NAME',
      active: true,
      type: 'storage',
      attributes: {
        bucket: '$BUCKET_NAME',
        prefix: '$BUCKET_PREFIX'
      }
    }
  ],
  functions: [
    {
      name: '$FUNCTION_NAME',
      path: './functions/worker.js',
      bindings: {
        storage: {
          bucket: '$BUCKET_NAME',
          prefix: '$BUCKET_PREFIX'
        }
      }
    }
  ],
  applications: [
    {
      name: '$APPLICATION_NAME',
      cache: [
        {
          name: '$APPLICATION_NAME',
          browser: { maxAgeSeconds: 7200 },
          edge: { maxAgeSeconds: 7200 }
        }
      ],
      rules: {
        request: [
          {
            name: 'Set storage origin for all requests _next_static and set cache policy',
            description: 'Serve Next.js static assets through edge connector and set cache policy',
            active: true,
            criteria: [[{ variable: '${uri}', conditional: 'if', operator: 'matches', argument: '^/_next/static/' }]],
            behaviors: [
              { type: 'set_connector', attributes: { value: '$CONNECTOR_NAME' } },
              { type: 'set_cache_policy', attributes: { value: '$APPLICATION_NAME' } },
              { type: 'deliver' }
            ]
          },
          {
            name: 'Deliver Static Assets and set cache policy',
            description: 'Serve static assets through edge connector and set cache policy',
            active: true,
            criteria: [[{ variable: '${uri}', conditional: 'if', operator: 'matches', argument: '.(css|js|ttf|woff|woff2|pdf|svg|jpg|jpeg|gif|bmp|png|ico|mp4|json)$' }]],
            behaviors: [
              { type: 'set_connector', attributes: { value: '$CONNECTOR_NAME' } },
              { type: 'set_cache_policy', attributes: { value: '$APPLICATION_NAME' } },
              { type: 'deliver' }
            ]
          },
          {
            name: 'Execute Function',
            description: 'Execute function for all requests',
            active: true,
            criteria: [[{ variable: '${uri}', conditional: 'if', operator: 'matches', argument: '^/' }]],
            behaviors: [
              { type: 'run_function', attributes: { value: '$FUNCTION_NAME' } },
              { type: 'forward_cookies' }
            ]
          }
        ]
      },
      functionsInstances: [
        {
          name: '$FUNCTION_INSTANCE_NAME',
          ref: '$FUNCTION_NAME'
        }
      ]
    }
  ],
  workloads: [
    {
      name: '$WORKLOAD_NAME',
      active: true,
      infrastructure: 1,
      deployments: [
        {
          name: '$DEPLOYMENT_NAME',
          current: true,
          active: true,
          strategy: { type: 'default', attributes: { application: '$APPLICATION_NAME' } }
        }
      ]
    }
  ]
}
```

The file declares these resources:

- **Storage**: a bucket that receives the `.edge/assets` folder, where the build writes the static assets and the Next.js cache files. Workloads can read and write the bucket.
- **Connector**: a storage connector that reads the bucket. The first two rules send `/_next/static/` paths and static file types to it with `set_connector`.
- **Function**: the server code of the app, bound to the same bucket so that it can read and write the Next.js cache.
- **Application**: a cache setting of 7,200 seconds in the browser and in Azion's cache, which the static rules apply with `set_cache_policy`. The `Execute Function` rule runs the function for every other request and forwards cookies to it.
- **Workload**: serves the application on an Azion domain.

The first deploy replaces each `$` placeholder with a name based on the project name. To change a cache setting, such as the options of `cacheByCookie` and `cacheByQueryString`, refer to [Application cache settings](/en/documentation/devtools/cli/azion-config-js/#application-cache-settings). For every other key, refer to [azion.config.js](/en/documentation/devtools/cli/azion-config-js/).

## Build the app

The first build creates `open-next.config.ts`, the adapter's configuration file, at the project root. In an interactive terminal, the build asks before it creates the file. `OPEN_NEXTJS_NO_INTERACTIVE_PROMPT=true` creates it without asking, which a CI job or a remote build needs.

To build the app without the question, run this command in the app folder:

```bash
OPEN_NEXTJS_NO_INTERACTIVE_PROMPT=true azion build
```

The build writes the function to `.edge/functions/worker.js`, the assets to `.edge/storage`, and the manifest to `.edge/manifest.json`. The `open-next.config.ts` file it creates sets the adapter's caches, queue, and wrapper:

```ts
import { defineAzionConfig } from "@aziontech/opennextjs-azion/config";
import StorageIncrementalCache from "@aziontech/opennextjs-azion/overrides/incremental-cache/storage-incremental-cache";
import MemoryCacheQueue from "@aziontech/opennextjs-azion/overrides/queue/memory-queue";
import StorageTagCache from "@aziontech/opennextjs-azion/overrides/tag-cache/storage-tag-cache";
import AzionWrapperNode from "@aziontech/opennextjs-azion/overrides/wrapper/azion-wrapper-node";

export default defineAzionConfig({
  incrementalCache: StorageIncrementalCache,
  queue: MemoryCacheQueue,
  wrapper: AzionWrapperNode,
  tagCache: StorageTagCache,
});
```

Commit `open-next.config.ts`. Later builds read it and no longer create it.

## Run the app locally

To build the app and serve it on your machine, run this command in the app folder:

```bash
azion dev
```

The command serves the build on `http://localhost:3333` and rebuilds the app when a file changes. Some Node.js and Web APIs behave differently on your machine than on Azion. For these limits, refer to [Known issues](/en/documentation/devtools/runtime/frameworks/nextjs-compatibility/#known-issues). For every flag, refer to [Azion CLI dev](/en/documentation/devtools/cli/dev-command/).

---

## Deploy the app

By default, `azion deploy` uploads the project and builds it on Azion. That remote build has no terminal, so commit `open-next.config.ts` before you deploy.

To deploy the app, run this command in the app folder:

```bash
azion deploy
```

The command opens the Console page that tracks the deploy. If the browser does not open, use the page URL the command prints. At the end, the command prints the URL of the application's domain, in the form `https://xxxxxxxxxx.map.azionedge.net`.

To build on your machine and deploy the result, run `azion deploy --local` instead. For the full output and every flag, refer to [Azion CLI deploy](/en/documentation/devtools/cli/deploy/).

The first deploy can take several minutes to answer from every location. A location that does not have the application yet answers with a `404` page that reads `There's nothing here yet`. Wait, and open the URL again.
