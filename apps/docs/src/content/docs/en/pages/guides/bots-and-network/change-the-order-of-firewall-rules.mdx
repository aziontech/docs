You can change the order in which a [Firewall](/en/documentation/platform/firewall/) runs its rules from Azion Console or the Azion CLI. A new rule takes the last position. For how the position of a rule decides which rules run, refer to [Rule order](/en/documentation/platform/firewall/how-it-works/#rule-order). To reorder the rules with the API, refer to [Reorder Application and Firewall rules](/en/documentation/guides/application-development/automation/reorder-application-and-firewall-rules/).

The examples move the rule `siem - deny listed addresses` above the rule that applies a WAF rule set, on the Firewall `<firewall-id>`. Replace them with your rules and your Firewall.

## Move a rule above another rule

The rule you move runs before every rule below it, so a request it denies never reaches them.

<Tabs client:visible sharedStore="interface">

<Fragment slot="panel.console">

### Console

To move the rule in Azion Console:

<DocSteps>
  <DocStep title="Open the Rules Engine tab of the Firewall">

  Access [Azion Console](https://console.azion.com/) > **Firewalls**, select the Firewall, then go to the **Rules Engine** tab.

  </DocStep>
  <DocStep title="Move the rule up">

  In the **Rules Engine** list, move `siem - deny listed addresses` above the rule that applies a WAF rule set.

  </DocStep>
  <DocStep title="Select Review Changes">

  The **Review Changes** dialog shows the new order.

  </DocStep>
  <DocStep title="Select Save" />
</DocSteps>

Azion Console shows the message **Reorder saved**, and the **Rules Engine** list shows `siem - deny listed addresses` above the rule that applies a WAF rule set.

</Fragment>

<Fragment slot="panel.cli">

### CLI

The Azion CLI sets the whole order at once, from the IDs of every rule of the Firewall. To read the IDs, list the rules of the Firewall:

```bash
azion list firewall-rule --firewall-id <firewall-id>
```

The command prints one row per rule, in the order the rules run. A name longer than 30 characters is cut short:

```text
ID              NAME                          ACTIVE  DESCRIPTION
<waf-rule-id>   <waf-rule-name>               true
<deny-rule-id>  siem - deny listed addresses  true
```

Send every rule ID of the Firewall in the new order, with the deny rule first:

```bash
azion update firewall-rule-order --firewall-id <firewall-id> --rule-ids "<deny-rule-id>,<waf-rule-id>"
```

The command confirms the new order:

```text
Ordered Rules Engine of Firewall with ID <firewall-id>
```

A list that leaves out a rule of the Firewall fails with this error:

```text
Error: Failed to order the rules in Rules Engine of the Firewall: ["When ordering you should provide the order for all rules."]. Check your settings and try again. If the error persists, contact Azion support.
```

To confirm the order, list the rules of the Firewall again:

```bash
azion list firewall-rule --firewall-id <firewall-id>
```

The command prints `siem - deny listed addresses` above the rule that applies a WAF rule set:

```text
ID              NAME                          ACTIVE  DESCRIPTION
<deny-rule-id>  siem - deny listed addresses  true
<waf-rule-id>   <waf-rule-name>               true
```

For every flag of the command, refer to [Azion CLI firewall-rule](/en/documentation/devtools/cli/resources/firewall-rule/#order-rules).

</Fragment>
</Tabs>

The Firewall runs `siem - deny listed addresses` before the rule that applies a WAF rule set, so a listed address is refused before WAF inspects it. Like any saved change, the new order propagates across Azion's distributed infrastructure before requests show it. For more information, refer to [Propagation](/en/documentation/platform/firewall/how-it-works/#propagation).

The [Block attackers automatically from SIEM detections](/en/documentation/use-cases/secure-applications-and-networks/block-attackers-automatically-from-siem-detections/) use case uses the values of this example.

In the [Screen file uploads for malicious content](/en/documentation/use-cases/secure-applications-and-networks/screen-file-uploads-for-malicious-content/) use case, this section takes these values:

| Setting | Value |
| --- | --- |
| Position | Below `upload - deny flagged senders` |
