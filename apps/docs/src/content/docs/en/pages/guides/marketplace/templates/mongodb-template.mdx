You can deploy an application integrated with MongoDB Atlas to Azion from the MongoDB Atlas Boilerplate template in Azion Console. To create an application without a template, refer to [Applications quickstart](/en/documentation/platform/applications/quickstart/).

The template's function calls the Atlas Data API. Until MongoDB retired it, that API let you create, retrieve, update, and delete items in your collections through standard HTTPS requests. Azion Web Platform runs your database project on Azion's distributed infrastructure, which gives your digital data and assets faster delivery, lower latency, and enhanced security.

The deployment creates a GitHub repository for your project, an [application](/en/documentation/platform/applications/) that runs it, a function for custom logic, and a domain to reach it. The template uses [Application Accelerator](/en/documentation/platform/applications/application-accelerator/) and [Functions](/en/documentation/platform/functions/), and their usage can generate costs. For more information, refer to [Pricing](/en/documentation/fundamentals/pricing/).

:::caution
MongoDB retired the [Atlas Data API](https://www.mongodb.com/docs/atlas/app-services/data-api/) on September 30, 2025. The template is still listed in Azion Console, but its function calls the Data API, so a new deployment cannot connect to your collection. Do not use this template for new projects. To reach MongoDB Atlas from a function, call your own API in front of the database.
:::

## Prerequisites

- An Azion account. To create one, refer to [Create an account](/en/documentation/fundamentals/creating-account/).
- Access to Azion Console. To sign in, refer to [Access Azion Console](/en/documentation/guides/platform/account-and-billing/how-to-access-azion-console/).
- A [MongoDB account](https://www.mongodb.com/cloud/atlas/register).
- A [cluster](https://www.mongodb.com/docs/atlas/create-database-deployment/) in MongoDB Atlas, with a new database added to it.
- A collection in that database, created to use with this template.
- The [Atlas Data API](https://www.mongodb.com/docs/atlas/app-services/data-api/) service, activated. MongoDB retired this service.
- An API key, generated in [Atlas Service](https://www.mongodb.com/docs/atlas/app-services/authentication/api-key/#std-label-api-key-authentication).
- A [GitHub account](https://github.com/signup). Azion connects to it and creates the project's repository there.

MongoDB processes and bills any cost of MongoDB usage separately, on the MongoDB platform. For more information, refer to the [MongoDB Atlas documentation](https://www.mongodb.com/docs/atlas/).

## Deploy the template

The MongoDB Atlas Boilerplate opens as a configuration form in Azion Console, and an asterisk marks each mandatory field. Every field that this procedure names is mandatory.

To deploy the template:

<DocSteps>
  <DocStep title="Open the template">

  Go to [MongoDB Atlas Boilerplate](https://console.azion.com/create/mongodb-atlas/mongodb--atlas) in Azion Console. The configuration form opens.

  </DocStep>
  <DocStep title="Connect Azion with your GitHub account">

  A window opens to confirm the installation of the [Azion GitHub App](/en/documentation/guides/application-development/automation/azion-github-app/), which connects your GitHub account with Azion. In that window, define the app's permissions and repository access.

  </DocStep>
  <DocStep title="Select the Git Scope">

  Select the **Git Scope** to work with.

  </DocStep>
  <DocStep title="Name the application">

  In **Application Name**, enter a unique name that you can remember. The name identifies the application on Azion. The storage bucket and the function that the template creates take the same name. If the name is already in use, the platform returns an error message.

  </DocStep>
  <DocStep title="Enter the MongoDB Atlas connection details">

  Enter the details that connect the application to your MongoDB Atlas data:

  - **Atlas API Token**: the token that authorizes the connection with the Atlas Data API.
  - **Atlas API URL**: the URL endpoint assigned to connect with the Atlas Data API.
  - **Collection Name**: the name of a collection created in the specified database.
  - **Database Name**: the name of the database created in the MongoDB Atlas data source.
  - **dataSource Name**: the name of the MongoDB Atlas data source or cluster that you created.

  </DocStep>
  <DocStep title="Start the deployment">

  Select **Deploy**.

  </DocStep>
</DocSteps>

A window shows the deployment logs while it runs. When the deployment completes, the page shows the application's details, a browser link to it, and options to continue. The deployment leaves you with:

- A GitHub repository for your project.
- A GitHub Action in that repository that, when activated, guarantees a continuous deployment workflow.
- An application on Azion Platform that runs your project and holds all its settings.
- A workload domain to access the application. You can also set up a custom domain for the application.
- A function that holds custom logic.
- An integration with MongoDB Atlas and the Atlas Data API. The Data API acted as a middleware to manage and access your database until MongoDB retired it.

The link can take a few minutes to start serving the application, while its configuration propagates across Azion's distributed infrastructure. If the page does not load, wait a few minutes and open the link again.

## Update the project

Every push to the GitHub repository that the MongoDB Atlas Boilerplate creates deploys automatically.

To update the deployed project, push your changes to that repository. Azion deploys them, and the application serves the new version.

## HTTPS request examples

These examples call the Atlas Data API, which MongoDB retired on September 30, 2025.

The integration with the Atlas Data API gave you access to the data through standard HTTPS requests. The API acted as a middleware that accessed and managed your data, and it sat between your cluster and the client requests.

You could create, retrieve, update, and delete items in your collections with any tool that sends standard HTTPS requests, such as your terminal or Postman. The API has a dedicated endpoint for each operation.

All the requests return a response in `JSON` or `EJSON` format, including the information according to the status code: `200 Success`, `400 Bad Request`, and `401 Unauthorized`.

:::tip
For more examples and to learn how to work with batches, go to the [Atlas Data API](https://www.mongodb.com/docs/atlas/app-services/data-api/) documentation.
:::

### Find a document

To find a document, send a `POST` request to the `findOne` endpoint:

```bash
curl -s "https://data.mongodb-api.com/app/$CLIENT_APP_ID/endpoint/data/v1/action/findOne" \
  -X POST \
  -H "apiKey: $API_KEY" \
  -H 'Content-Type: application/ejson' \
  -H "Accept: application/json" \
  -d '{
    "dataSource": "my-datasource",
    "database": "my-database-azion",
    "collection": "template",
    "filter": {
      "text": "Do the dishes"
    }
  }'
```

Where:

| Variable | Required | Type | Description |
|---|---|---|---|
| `dataSource` | Yes | String | The name of your data source or cluster |
| `database` | Yes | String | The name of the database in the data source |
| `collection` | Yes | String | The name of a created collection in the specified database |
| `filter` | Yes | Object | A query operator to filter the documents |

### Insert a document

To insert a document, send a `POST` request to the `insertOne` endpoint:

```bash
curl -s "https://data.mongodb-api.com/app/$CLIENT_APP_ID/endpoint/data/v1/action/insertOne" \
  -X POST \
  -H "apiKey: $API_KEY" \
  -H 'Content-Type: application/ejson' \
  -H "Accept: application/json" \
  -d '{
    "dataSource": "my-datasource",
    "database": "my-database-azion",
    "collection": "template",
    "document": {
      "status": "open",
      "text": "Do the dishes"
    }
  }'
```

Where:

| Variable | Required | Type | Description |
|---|---|---|---|
| `dataSource` | Yes | String | The name of your data source or cluster |
| `database` | Yes | String | The name of the database in the data source |
| `collection` | Yes | String | The name of a created collection in the specified database |
| `document` | Yes | Object | The document to insert into the collection |

### Update a document

To update a document, send a `POST` request to the `updateOne` endpoint:

```bash
curl -s "https://data.mongodb-api.com/app/$CLIENT_APP_ID/endpoint/data/v1/action/updateOne" \
  -X POST \
  -H "apiKey: $API_KEY" \
  -H 'Content-Type: application/ejson' \
  -H "Accept: application/json" \
  -d '{
    "dataSource": "my-datasource",
    "database": "my-database-azion",
    "collection": "template",
    "filter": {
      "_id": { "$oid": "64224f4d089104f1766116a5" }
    },
    "update": {
      "$set": {
        "status": "complete",
        "completedAt": { "$date": { "$numberLong": "1680105272788" } }
      }
    }
  }'
```

Where:

| Variable | Required | Type | Description |
|---|---|---|---|
| `dataSource` | Yes | String | The name of your data source or cluster |
| `database` | Yes | String | The name of the database in the data source |
| `collection` | Yes | String | The name of a created collection in the specified database |
| `filter` | Yes | Object | A query operator to filter the documents |
| `update` | Yes | Object | An update expression to apply to matching documents |

### Delete a document

To delete a document, send a `POST` request to the `deleteOne` endpoint:

```bash
curl -s "https://data.mongodb-api.com/app/$CLIENT_APP_ID/endpoint/data/v1/action/deleteOne" \
  -X POST \
  -H "apiKey: $API_KEY" \
  -H 'Content-Type: application/ejson' \
  -H "Accept: application/json" \
  -d '{
    "dataSource": "my-datasource",
    "database": "my-database-azion",
    "collection": "template",
    "filter": {
      "_id": { "$oid": "64224f3cd79f54ad342dd9b2" }
    }
  }'

```

Where:

| Variable | Required | Type | Description |
|---|---|---|---|
| `dataSource` | Yes | String | The name of your data source or cluster |
| `database` | Yes | String | The name of the database in the data source |
| `collection` | Yes | String | The name of a created collection in the specified database |
| `filter` | No | Object | A query operator to filter the documents |

## Manage the application

The settings that the MongoDB Atlas Boilerplate applies may not fit your application. You can change any of them at any time from Azion Console.

To open the application's settings:

<DocSteps>
  <DocStep title="Open the applications list">

  Access [Azion Console](https://console.azion.com/) > **Applications**. The list shows every application you created, in alphabetical order.

  </DocStep>
  <DocStep title="Select the application that the template created">

  To find it in a long list, search by its name. The search filters the list by **Application Name** only.

  </DocStep>
</DocSteps>

The application opens on a page that holds every setting you can configure. For more information, refer to [Main Settings](/en/documentation/platform/applications/main-settings/), [Rules Engine for Applications](/en/documentation/platform/applications/rules-engine/), and [Device Groups](/en/documentation/platform/applications/device-groups/).

## Add a custom domain

The MongoDB Atlas Boilerplate deployment assigns the application a [workload](/en/documentation/platform/workloads/) domain in the format `xxxxxxxxxx.map.azionedge.net`, which a browser can open. To serve the application from a domain you own, add a custom domain. To add one, refer to [Add a custom domain to a workload](/en/documentation/guides/platform/migration/configure-a-domain/). For more information, refer to [Domains](/en/documentation/platform/workloads/domains/).
