You can deploy a sandbox in which [Bot Manager Lite](/en/documentation/platform/firewall/bot-manager/bot-manager-lite/) scores the requests you send yourself from the Bot Manager Lite Starter Kit template, in Azion Console. The template creates every entity it uses, including the [Firewall](/en/documentation/platform/firewall/). To add Bot Manager Lite to a Firewall you already run, refer to [Add Bot Manager Lite to a Firewall](/en/documentation/guides/application-development/integrations/bot-manager-lite-integration-kit/).

---

## Prerequisites

- Bot Manager Lite installed from Marketplace. For more information, refer to [Install Bot Manager Lite](/en/documentation/guides/application-development/integrations/bot-manager-lite/).
- Access to Azion Console. To sign in, refer to [How to access Azion Console](/en/documentation/guides/platform/account-and-billing/how-to-access-azion-console/).
- The Function Instance runs on [Functions](/en/documentation/platform/functions/), which can generate usage costs. For the metrics Bot Manager is billed on, refer to [Pricing](/en/documentation/fundamentals/pricing/#bot-manager).

The template checks that Bot Manager Lite is installed before it creates anything. When it is not, the deployment fails and writes a log line that names the reason.

---

## Deploy the template

To deploy the template in Azion Console:

<DocSteps>
  <DocStep title="Open the template">

  Go to the [Bot Manager Lite Starter Kit](https://console.azion.com/create/azion/bot--manager-starter-kit) template.

  </DocStep>
  <DocStep title="Name the Application">

  In **Applications Name**, enter a name. The template gives the same name to the Firewall it creates.

  </DocStep>
  <DocStep title="Name the sample Function">

  In **Sample Function Name**, enter a name for the Function that serves the test page.

  </DocStep>
  <DocStep title="Select Deploy" />
</DocSteps>

The deployment shows its log as it runs. When it finishes, the account carries four new entities:

- An [Application](/en/documentation/platform/applications/) with **Functions** turned on, which runs the sample Function.
- A Function that serves the test page and its request buttons.
- A Firewall whose **Functions Instances** tab lists a Bot Manager Lite Function Instance, and whose **Rules Engine** tab lists the rule that runs it.
- A [Workload](/en/documentation/platform/workloads/) that answers on a domain in the format `<id>.map.azionedge.net`.

The Function Instance carries an `action` of `deny`, so a request that scores at or above the threshold receives a `403` response with Azion's default error page. It also writes a report log line for every request it scores. To read or change its arguments, open the Function Instance on the **Functions Instances** tab of the Firewall. For every argument a Function Instance accepts, refer to [Arguments](/en/documentation/platform/firewall/bot-manager/arguments/).

The Application serves the sample Function, not an origin you own, so the sandbox is a demonstration and not a running site. To reach it on a domain you own, add that domain to the Workload the template created.

The domain serves the test page only after the deployment propagates across Azion's distributed infrastructure, which takes several minutes. For more information, refer to [Propagation](/en/documentation/platform/firewall/how-it-works/#propagation).

## Send a good and a bad request

To score a request you send yourself:

<DocSteps>
  <DocStep title="Open the test page">

  In a browser, go to the domain of the Workload the template created.

  </DocStep>
  <DocStep title="Send a good request">

  Select **Send Request** for the good request. The page renders a success message.

  </DocStep>
  <DocStep title="Send a bad request">

  Select **Send Request** for the bad request. The page renders the `403` response that the `deny` action returns.

  </DocStep>
</DocSteps>

Each request the page sends produces one report log line, whatever it scored.

To send a refused request to a location you choose instead of the default error page, set `action` to `redirect` and give `redirect_to` the destination. For more information, refer to [Arguments](/en/documentation/platform/firewall/bot-manager/arguments/#action).

## Read what the Function Instance scored

To read the report log lines in Azion Console:

<DocSteps>
  <DocStep title="Open Real-Time Events">

  Access [Azion Console](https://console.azion.com/) > **Real-Time Events**, then select the **Functions Console** tab.

  </DocStep>
  <DocStep title="Read the report lines">

  Narrow the period to the requests the test page sent. Each report line opens with `[Bot-Protection]` in the **Log Body** column and carries the score of one request.

  </DocStep>
</DocSteps>

The scores come from requests the sandbox shaped, not from traffic of your own. Before a Function Instance refuses anything in front of an Application you run, set `threshold` and `action` from the scores your own traffic produces. For the fields a line carries, refer to [Logs](/en/documentation/platform/firewall/bot-manager/logs/). To forward the lines to a destination you own, refer to [Data Stream](/en/documentation/platform/data-stream/).
