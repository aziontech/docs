Send messages to a queue adds messages to a message queue. A queue stores messages in first-in-first-out (FIFO) order: a message enters at the back and leaves from the front. The sender adds a message asynchronously, and the receiving component processes it later. The integration supports three messaging services: RabbitMQ, Amazon SQS, and Kafka-REST. It is one of the [Marketplace integrations](/en/documentation/platform/marketplace/integrations/) that run on an application.

Four objects must exist before a request sends a message: the installed function, an application with the **Functions** module turned on, a function instance that holds the arguments, and a Rules Engine rule with the **Run Function** behavior. Each section below creates one of them.

---

## Prerequisites

- An Azion account. To sign in, refer to [How to access Azion Console](/en/documentation/guides/platform/account-and-billing/how-to-access-azion-console/).
- An [application](/en/documentation/platform/applications/) served by a [workload](/en/documentation/platform/workloads/). To create one, refer to [Applications quickstart](/en/documentation/platform/applications/quickstart/).
- A queue on RabbitMQ, Amazon SQS, or Kafka-REST, with its server URL and, where the service requires one, its authorization credentials. Configure the service before you create the function instance.
- Turning on a product or a module can generate usage costs. For more information, refer to [Pricing](/en/documentation/fundamentals/pricing/).

## Install the integration

The install adds the Send messages to a queue function to your account. To install it from Azion Console:

<DocSteps>
  <DocStep title="Open Marketplace">

  Access [Azion Console](https://console.azion.com/) > **Marketplace**.

  </DocStep>
  <DocStep title="Find the integration">

  Enter `Send messages to a queue` in the **Search on Marketplace** field, then select the integration's card. Browsing the cards and the categories reaches the same page.

  </DocStep>
  <DocStep title="Select Install" />
</DocSteps>

The card shows `Successfully installed!` and `Latest version installed!`. The function is then listed in the **Function** list of the **Create Instance** drawer.

## Turn on the Functions module

An application runs an installed function only when its **Functions** module is on. To turn on the module:

<DocSteps>
  <DocStep title="Open your application">

  Access [Azion Console](https://console.azion.com/) > **Applications** > **your application**.

  </DocStep>
  <DocStep title="Open the Modules section">

  In the **Main Settings** tab, go to the **Modules** section.

  </DocStep>
  <DocStep title="Turn on the Functions switch" />
  <DocStep title="Select Save" />
</DocSteps>

Azion Console confirms that the application was updated.

## Create the function instance

A function instance holds the arguments the Send messages to a queue function reads for one application. To create the instance in your application:

<DocSteps>
  <DocStep title="Open the Functions Instances tab">

  In **Applications**, select your application, then select the **Functions Instances** tab.

  </DocStep>
  <DocStep title="Select + Function">

  An application with no instance yet offers the same action as **Function Instance**. The **Create Instance** drawer opens.

  </DocStep>
  <DocStep title="Name the instance">

  In **Name**, enter a unique name that identifies the instance. For example: `send-messages-amqp`.

  </DocStep>
  <DocStep title="Select the function">

  In **Function**, select _Send messages to a queue_. The **Arguments** editor fills with the default arguments of the integration.

  </DocStep>
  <DocStep title="Edit the arguments">

  In **Arguments**, enter the arguments of your messaging service. Each service takes a different set of arguments and credentials, shown below.

  </DocStep>
  <DocStep title="Select Save" />
</DocSteps>

The instance appears in the **Functions Instances** tab with the name you entered.

### Arguments

The arguments are one JSON object. Three keys define the connection:

| Key | Description |
|---|---|
| `server_type` | The connection type. Takes `amqp`, `sqs`, or `kafka-rest` |
| `connection_url` | The server URL of the messaging service |
| `connection_authorization` | The type of authorization the connection requires. Optional |

The `connection_args` section passes extra parameters to the queue. Each service accepts different parameters, and all of them are optional.

For RabbitMQ, over AMQP:

```json
{
  "server_type": "amqp",
  "connection_url": "https://my-service.azion.com/queue",
  "connection_authorization": "Basic my_basic_auth",
  "connection_args: {	
   "routing_key: "my_queue",
   "payload: "my_custom_payload"
  }
}
```

For Amazon SQS:

```json
{
  "server_type": "sqs",
  "connection_url": "https://my-service.azion.com/sqs-queue",
  "connection_authorization": "Basic my_basic_auth",
  "connection_args: {
    "auth_params: "my_aditional_auth_params",
     "version": "2012-11-05",
    "expires": "Wed, 21 Oct 2015 07:28:00 GMT"
  }
}
```

For Kafka-REST:

```json
{
  "server_type": "kafka-rest",
  "connection_url": "https://my-service.azion.com/topics/my-topic",
 "connection_args: {
    "payload": "my_custom_payload"
  }
}
```

:::note
The integration connects to Kafka only through Kafka-REST, a module that provides an HTTP RESTful interface to a Kafka cluster. The Kafka clients for JavaScript, Kafka JS and Kafka Node, use Node.js features that are incompatible with Azion's infrastructure.
:::

## Create the rule

The instance runs only when a Rules Engine rule calls it. The rule below matches every request. To create the rule:

<DocSteps>
  <DocStep title="Open the Rules Engine tab">

  In **Applications**, select your application, then select the **Rules Engine** tab.

  </DocStep>
  <DocStep title="Select + Rule" />
  <DocStep title="Name the rule">

  In **Name**, enter a name for the rule. For example: `Send messages to a queue on every request`.

  </DocStep>
  <DocStep title="Select the phase">

  In the **Phase** section, select _Request Phase_.

  </DocStep>
  <DocStep title="Set the criterion">

  In the **Criteria** section, keep the `${uri}` variable and the _starts with_ operator, then enter `/` as the argument.

  </DocStep>
  <DocStep title="Add the Run Function behavior">

  In the **Behaviors** section, select _Run Function_, then select the instance you created by its name.

  </DocStep>
  <DocStep title="Select Save" />
</DocSteps>

The rule appears in the **Rules Engine** tab, under the request phase, and runs the Send messages to a queue instance on every request.

For every criterion and behavior a rule accepts, refer to [Rules Engine](/en/documentation/platform/applications/rules-engine/).
