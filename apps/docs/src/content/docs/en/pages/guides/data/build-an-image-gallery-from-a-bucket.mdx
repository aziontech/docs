In this tutorial, you will build an image gallery whose images live in an [Object Storage](/en/documentation/platform/object-storage/) bucket. You will upload two images to a bucket, write a Function that lists the bucket and serves each image, and publish the Function through an Application and a Workload.

Every resource the tutorial creates links to one created before it:

1. The bucket holds the images. Its **Workloads Access** is read only, so Functions read it and do not change it.
2. The [Function](/en/documentation/platform/functions/) reads the bucket with the `azion:storage` module, and builds the gallery page.
3. The [Application](/en/documentation/platform/applications/) has Functions turned on, a function instance that attaches the Function, and a request rule that runs it on every path.
4. The [Workload](/en/documentation/platform/workloads/) holds the domain that receives requests, and its deployment sets the Application that answers them.

The resources are the same in Azion Console, the Azion CLI, and the API. Select the interface you use, and every stage shows its steps.

## 1. Create the images

Create a directory for the tutorial and go to it. Then write two SVG images, an orange square and a blue circle:

```bash
echo '<svg xmlns="http://www.w3.org/2000/svg" width="160" height="160"><rect width="160" height="160" fill="orange"/></svg>' > orange.svg
echo '<svg xmlns="http://www.w3.org/2000/svg" width="160" height="160"><circle cx="80" cy="80" r="70" fill="steelblue"/></svg>' > blue.svg
```

The directory holds `orange.svg` and `blue.svg`.

Upload each image as the body of a `POST` request to its object key. `Storage-Content-Type` sets the type of the object:

```bash
for image in orange.svg blue.svg; do

    --header 'Content-Type: application/octet-stream' \
    --header 'Storage-Content-Type: image/svg+xml' \
    --data-binary @$image
  echo
done
```

```text

{"state":"executed","data":{"object_key":"blue.svg"}}
```

## 3. Write the Function

Create an `index.js` file with this code. In the third line, replace `<your-bucket-name>` with the name of your bucket:

```javascript title="index.js"
import Storage from 'azion:storage'

const BUCKET = '<your-bucket-name>'

export default {
  async fetch(request) {
    const storage = new Storage(BUCKET)
    const { pathname } = new URL(request.url)
    if (pathname === '/') {
      const { entries } = await storage.list()
      const figures = entries
        .filter((entry) => entry.key.endsWith('.svg'))
        .map((entry) => `<figure><img src="/images${entry.key}" alt="${entry.key.slice(1)}" width="160"><figcaption>${entry.key.slice(1)}</figcaption></figure>`)
        .join('')
      return new Response(`<!doctype html><html lang="en"><head><meta charset="utf-8"><title>Gallery</title></head><body><h1>Gallery</h1>${figures}</body></html>`, {
        headers: { 'content-type': 'text/html; charset=utf-8' }
      })
    }
    if (pathname.startsWith('/images/')) {
      try {
        const object = await storage.get(pathname.slice('/images/'.length))
        return new Response(object.content, { headers: { 'content-type': 'image/svg+xml' } })
      } catch (error) {
        return new Response('Not found', { status: 404 })
      }
    }
    return new Response('Not found', { status: 404 })
  }
}
```

The Function answers two routes, both read from the bucket:

- `GET /` lists the bucket with `storage.list()`. Each entry carries the key of an object with a leading slash, such as `/orange.svg`, and the Function writes one `<figure>` per SVG.
- `GET /images/<key>` reads one object with `storage.get(key)` and returns its content. A key with no object answers `404`.

For every method of the module, refer to [Object Storage API](/en/documentation/devtools/runtime/api-reference/storage/).

## 5. Create the Application

The Application needs three parts: the Application itself with Functions turned on, a function instance that attaches the Function, and a rule that runs the instance.

<Tabs client:visible sharedStore="interface">

<Fragment slot="panel.console">

### Console

To create the Application:

1. Access [Azion Console](https://console.azion.com/) > **Applications**.
2. Select **+ Application**.
3. In **Name**, enter `gallery`.
4. In **Modules**, turn on **Functions**.
5. Select **Create**.

The Console opens the new Application on its **Main Settings** tab.

To attach the Function:

1. Select the **Functions Instances** tab.
2. Select **+ Function**.
3. In **Name**, enter `gallery`.
4. In **Function**, select `gallery`.
5. Select **Save**.

To run the Function on every request:

1. Select the **Rules Engine** tab.
2. Select **+ Rule**.
3. In **Name**, enter `Run gallery`.
4. Keep **Request Phase** selected.
5. In **Criteria**, keep `${uri}` and **starts with**, and enter `/` as the argument.
6. In **Behaviors**, replace **Deliver** with **Run Function**.
7. In the function instance field that **Run Function** adds, select the `gallery` instance.
8. Select **Save**.

The rule appears in the request phase of the **Rules Engine** tab.

</Fragment>

<Fragment slot="panel.cli">

### CLI

Create the Application with Functions turned on:

```bash
azion create application --name gallery --function true --active true
```


Store the ID. Replace `1794609946` with your ID:

```bash
APPLICATION_ID=1794609946
```

```bash

```


Write the rule that runs the instance on every path to a `rule.json` file:

```bash
cat > rule.json <<EOF
{
  "name": "Run gallery",
  "criteria": [[{ "variable": "\${uri}", "conditional": "if", "operator": "starts_with", "argument": "/" }]],
  "behaviors": [{ "type": "run_function", "attributes": { "value": $INSTANCE_ID } }]
}
EOF
```

Create the rule in the request phase:

```bash
azion create rules-engine --application-id $APPLICATION_ID --phase request --file rule.json
```

```text

```

## 7. Open the gallery

A new Workload can take about ten minutes to propagate across the Azion network. Until then, the domain answers `404` with an HTML error page, and it can alternate between `404` and the Function's response for a few minutes.

If you used the Console, set `DOMAIN` to your domain first, with `DOMAIN=<your-domain>`. Request the gallery page:

```bash
curl "https://$DOMAIN/"
```

Repeat the request every minute until the page returns three times in a row. It lists one figure per image:

```html
<!doctype html><html lang="en"><head><meta charset="utf-8"><title>Gallery</title></head><body><h1>Gallery</h1><figure><img src="/images/blue.svg" alt="blue.svg" width="160"><figcaption>blue.svg</figcaption></figure><figure><img src="/images/orange.svg" alt="orange.svg" width="160"><figcaption>orange.svg</figcaption></figure></body></html>
```

Request one image and print its status and type:

```bash
curl --silent --output /dev/null --write-out '%{http_code} %{content_type}\n' "https://$DOMAIN/images/orange.svg"
```

```text
200 image/svg+xml
```

Open `https://<your-domain>/` in a browser to see the two images, each with its file name.

## 8. (Optional) Delete the resources

The gallery keeps running on your domain after the tutorial. If you want to remove the resources, delete them in the reverse order of their creation. Deleting the Workload also deletes its deployment, and deleting the Application also deletes its instance and its rule.

A bucket is deleted only when it is empty and no object was removed from it in the last 24 hours. To remove the bucket too, delete the objects first, and the bucket one day later.

<Tabs client:visible sharedStore="interface">

<Fragment slot="panel.console">

### Console

To delete the Workload:

1. Access [Azion Console](https://console.azion.com/) > **Workloads**.
2. In the `gallery` row, open the actions menu and select **Delete**.
3. In the **Delete Workload** dialog, enter `gallery`.
4. Select **Delete**.

Repeat the steps in **Applications** for the `gallery` Application, then in **Functions** for the `gallery` Function.

To delete the images:

1. Access [Azion Console](https://console.azion.com/) > **Object Storage**.
2. In the list of buckets, select the name of your bucket.
3. In the `blue.svg` row, open the actions menu and select **Delete**.
4. In the **Delete File** dialog, enter `blue.svg`.
5. Select **Delete**.

Repeat the steps for `orange.svg`. The bucket is empty.

One day later, delete the bucket:

1. Access [Azion Console](https://console.azion.com/) > **Object Storage**.
2. In the list of buckets, open the actions menu of your bucket and select **Delete**.
3. In the **Delete bucket** dialog, enter the name of your bucket.
4. Confirm the deletion.

Before the 24 hours pass, the Console answers with this error:

```text
Unable to delete a non-empty bucket. Additionally, objects deleted within the last 24 hours are also taken into consideration.
```
