In this tutorial, you will build a semantic search that returns the documents closest in meaning to a question, over data stored in [SQL Database](/en/documentation/platform/sql-database/). You will create a database, add a table with a vector column and an index over it, generate embeddings with OpenAI, store them, and query the table by similarity.

The work is split in two. A setup script runs once from your machine: it creates the database, waits until the database accepts statements, and stores the embeddings. A TypeScript function then answers each request with a search over those rows. Both reach the database through the [Azion SQL library](/en/documentation/devtools/azion-lib/sql/) and produce embeddings with the LangChain OpenAI package. The function runs locally with `azion dev`.

---

## Prerequisites

- Node.js version 20.6 or higher. The setup script reads its credentials with `node --env-file`, which earlier versions do not have.
- The Azion CLI installed and authorized. For more information, refer to [Azion CLI](/en/documentation/devtools/cli/).
- A TypeScript function project created with `azion init`. To create one, refer to [Deploy a function with Azion CLI](/en/documentation/guides/application-development/functions-and-runtime/deploy-function-with-cli/). The steps below run in the project folder.
- An Azion personal token. For more information, refer to [How to manage a personal token](/en/documentation/guides/platform/account-and-billing/personal-tokens/).
- SQL Database enabled on the account. The product is in Preview, and access is requested through the technical support team. To request it, refer to [Technical Support](/en/documentation/support/).
- An OpenAI API key. The embedding step calls the OpenAI API with it. To create one, refer to [Create and export an API key](https://developers.openai.com/api/docs/quickstart#create-and-export-an-api-key).

## 2. Create the database and wait until it is ready

`createDatabase` returns while the database is still being provisioned: its `status` reads `creating` and changes to `created` about 15 seconds later. A statement sent before that fails, so the script polls `getDatabase` until the status reads `created`. A database name is unique within the account, and `createDatabase` on a name the account already holds fails with error `14001` `Name Already In Use.`. The script reads the database first and creates it only when it is missing, so a second run reuses the database instead of failing.

Create a file named `setup.mjs` in the project folder and start it with the database step:

```javascript
import { createDatabase, getDatabase, useExecute, useQuery } from '@aziontech/sql'
import { OpenAIEmbeddings } from '@langchain/openai'

const DATABASE = 'vectorDatabase'

async function ensureDatabase() {
  let { data: database } = await getDatabase(DATABASE)

  if (!database) {
    const { error } = await createDatabase(DATABASE)
    // 14001 Name Already In Use: another run created it between the two calls.
    // Read it again, and stop only when it still does not exist.
    if (error) {
      ;({ data: database } = await getDatabase(DATABASE))
      if (!database) throw new Error(`createDatabase failed: ${error.message}`)
    }
  }

  for (let attempt = 1; attempt <= 20; attempt++) {
    const { data, error } = await getDatabase(DATABASE)
    if (error) throw new Error(`getDatabase failed: ${error.message}`)
    if (data?.status === 'created') return
    console.log(`Database status is ${data?.status}, waiting...`)
    await new Promise((resolve) => setTimeout(resolve, 3000))
  }

  throw new Error('The database did not reach the created status in 60 seconds')
}
```

`getDatabase` returns an empty object for a name that matches no database, so `database` is `undefined` until the database exists. The loop checks the status every 3 seconds and gives up after 20 attempts.

## 3. Create the table and the vector index

The table holds the text of each document and its embedding. A vector lives in a column of its own, declared with a blob type that carries its dimension count: `F32_BLOB(1536)` stores 1,536 32-bit floating-point elements, which is the number of dimensions the `text-embedding-3-small` model returns.

The index makes a search consult an approximate-nearest-neighbor structure instead of every row. It is built over `libsql_vector_idx(embedding, 'metric=cosine')`, and the table it covers needs a `ROWID` or a single-column primary key, which `id INTEGER PRIMARY KEY AUTOINCREMENT` provides.

Continue in `setup.mjs`. Both statements carry `IF NOT EXISTS`, so a second run leaves the table and the index as they are. Run them with `useExecute`, which carries the statements that create and write:

```javascript
async function ensureTable() {
  const { error } = await useExecute(DATABASE, [
    `CREATE TABLE IF NOT EXISTS documents (
      id INTEGER PRIMARY KEY AUTOINCREMENT,
      content TEXT NOT NULL,
      embedding F32_BLOB(1536)
    );`,
    `CREATE INDEX IF NOT EXISTS documents_idx ON documents (
      libsql_vector_idx(embedding, 'metric=cosine')
    );`
  ])

  if (error) throw new Error(`Table setup failed: ${error.message}`)
}
```

The database holds a `documents` table and a `documents_idx` index. Creating a vector index also adds a shadow table named `documents_idx_shadow`, which `getTables` and the EdgeSQL Shell both list beside the table.

## 4. Generate and store the embeddings

The embedding model turns text into a vector. `text-embedding-3-small` returns 1,536 dimensions, the number the `embedding` column declares, and the same model produces the vectors stored here and the vector the search uses in stage 5.

Continue in `setup.mjs`. The function counts the rows first and stores the documents only when the table is empty, so a second run does not duplicate them. It embeds each document with `embedQuery` and wraps the result in `vector('[...]')`, which converts an array of numbers into the type the column stores:

```javascript
const documents = [
  'Paris is the capital of France',
  'The Eiffel Tower is a French landmark',
  'London is the capital of England',
  'Big Ben is located in London',
  'Canberra is the capital of Australia',
  'The Great Barrier Reef is in Australia',
  'French cuisine is world-famous',
  'Tea is popular in England',
  'The English Channel separates Britain and France'
]

async function seedDocuments() {
  const { data: count, error: countError } = await useQuery(DATABASE, [
    'SELECT COUNT(*) AS total FROM documents;'
  ])
  if (countError) throw new Error(`Count failed: ${countError.message}`)

  if (count.results[0].rows[0][0] > 0) {
    console.log('The documents table already holds rows, skipping the insert')
    return
  }

  const embeddings = new OpenAIEmbeddings({
    model: 'text-embedding-3-small',
    apiKey: process.env.OPENAI_API_KEY
  })

  const insertStatements = []
  for (const doc of documents) {
    const embedding = await embeddings.embedQuery(doc)
    // The body carries SQL text, so double every single quote inside a value.
    const content = doc.replaceAll("'", "''")
    insertStatements.push(
      `INSERT INTO documents (content, embedding) VALUES ('${content}', vector('[${embedding}]'));`
    )
  }

  const { error } = await useExecute(DATABASE, insertStatements)
  if (error) throw new Error(`Insert failed: ${error.message}`)
}

await ensureDatabase()
await ensureTable()
await seedDocuments()
console.log('Setup complete')
```

Run the script from the project folder:

```bash
node --env-file=.env setup.mjs
```

The script prints `Database status is creating, waiting...` while the database is provisioned, and `Setup complete` at the end. The `documents` table holds one row per entry in the list, each with its text and its embedding, and the index covers those rows. Running the script again prints `Setup complete` without creating anything twice. `vector('[...]')` rejects a vector of more than 65,536 dimensions.

## 5. Query by similarity

A search embeds the question with the same model and asks the index for the nearest rows. `vector_top_k` takes the index name, the query vector, and the number of rows to return, and answers with an `id` column that the table joins on `rowid`:

```sql
SELECT content FROM vector_top_k('documents_idx', vector('[...]'), 2) JOIN documents ON documents.rowid = id;
```

The function only reads, so it creates nothing and answers every request the same way. Replace the contents of `main.ts`, the entry file of the project, with the search, and run the statement with `useQuery`, which carries the statements that return rows:

```typescript
import { useQuery } from '@aziontech/sql'
import { OpenAIEmbeddings } from '@langchain/openai'

export default async function vectorSearch() {
  const embeddings = new OpenAIEmbeddings({
    model: 'text-embedding-3-small',
    apiKey: process.env.OPENAI_API_KEY
  })

  const query = 'What is the capital of Australia?'
  const queryEmbedding = await embeddings.embedQuery(query)

  const { data: searchData, error: searchError } = await useQuery('vectorDatabase', [
    `SELECT content FROM vector_top_k('documents_idx', vector('[${queryEmbedding}]'), 2)
     JOIN documents ON documents.rowid = id;`
  ])

  if (searchError) {
    return Response.json({ error: searchError.message }, { status: 500 })
  }

  return Response.json({ data: searchData })
}
```

The answer carries `results`, one entry per statement, each with its `columns` and its `rows`. A statement that fails fails the whole call: `error` holds the database message, such as `no such table: documents`, and `data` is unset. That is why the function reads `error` before it reads `data`.

The function returns the two rows whose embeddings are nearest the question, and a failed search returns a JSON message with status `500`.

## 6. Run it

The function reads the rows the setup script stored. To run it locally:

<DocSteps>
  <DocStep title="Build the application">

  From the project folder, build it:

  ```bash
  azion build
  ```

  The build output is written to the project directory.

  </DocStep>
  <DocStep title="Start the local server">

  Serve the function from your machine:

  ```bash
  azion dev
  ```

  The function answers on the local address the command prints, `http://localhost:3333` by default.

  </DocStep>
  <DocStep title="Send a request">

  ```bash
  curl http://localhost:3333
  ```

  The function embeds `What is the capital of Australia?` and searches the index.

  </DocStep>
</DocSteps>

The response carries the two documents whose embeddings are nearest the question. Every later request runs the same search, because the function creates nothing. To search for something else, change the value of `query`, build again, and send the request again. To store other documents, change the `documents` list, delete the rows of the `documents` table, and run `setup.mjs` again.
