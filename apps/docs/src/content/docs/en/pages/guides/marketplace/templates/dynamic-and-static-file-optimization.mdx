You can deploy an application with standard cache policies to Azion from the Dynamic and Static File Optimization template in Azion Console. To create an application without a template, refer to [Applications quickstart](/en/documentation/platform/applications/quickstart/).

The template holds standard cache policies and settings for static content, dynamic content, and images. They improve delivery and performance based on the file extension of the requested content. The template also turns on image processing and optimization, so you deliver your content with Azion as a CDN.

The deployment creates an [application](/en/documentation/platform/applications/) that carries every cache rule and setting of the template. The application uses [Application Accelerator](/en/documentation/platform/applications/application-accelerator/) and [Image Processor](/en/documentation/platform/applications/image-processor/), and their usage can generate costs. For more information, refer to [Pricing](/en/documentation/fundamentals/pricing/).

After the deployment, link your origin to the application to apply these rules to your content and deliver it through Azion. For more information, refer to [Connectors](/en/documentation/platform/connectors/).

---

## Prerequisites

- An Azion account. To create one, refer to [Create an account](/en/documentation/fundamentals/creating-account/).
- Access to Azion Console. To sign in, refer to [Access Azion Console](/en/documentation/guides/platform/account-and-billing/how-to-access-azion-console/).
- A hosted origin that holds your content. The configuration form asks for its address.

---

## Deploy the template

The Dynamic and Static File Optimization template opens as a configuration form in Azion Console, and an asterisk marks each mandatory field.

To deploy the template:

<DocSteps>
  <DocStep title="Open the template">

  Go to [Dynamic and Static File Optimization](https://console.azion.com/create/azion/dynamic-and-static-file-optimization) in Azion Console. The configuration form opens.

  </DocStep>
  <DocStep title="Name the application">

  In **Application Name**, enter a unique name that you can remember. The name identifies the application on Azion. If the name is already in use, the platform returns an error message.

  </DocStep>
  <DocStep title="Enter the origin address">

  In **Origin Address**, enter the address of the hosted origin. The application fetches the original content from it. For example: `www.yourwebsite.com`.

  </DocStep>
  <DocStep title="(Optional) Override the Host header">

  Some origins need a different value in the `Host` header of the request that retrieves their content. In **Custom Host Header**, enter that value. To take the host value from the request URI, enter the `${host}` variable. For more information, refer to [Origins](/en/documentation/platform/connectors/origins/#host-header).

  </DocStep>
  <DocStep title="Start the deployment">

  Select **Deploy**.

  </DocStep>
</DocSteps>

A window shows the deployment logs while it runs. When the deployment completes, the deployment page confirms that the platform created the application. The page shows the application's details, a browser link to it, and options to continue.

The link can take a few minutes to start serving the application, while its configuration propagates across Azion's distributed infrastructure. If the page does not load, wait a few minutes and open the link again.

## Template rules and settings

The application that the Dynamic and Static File Optimization template deploys holds a rule with this criterion and behavior:

- **Criteria**: if `${uri}` *starts with* `/`.
- **Behavior**: then [Set Connector](/en/documentation/platform/applications/rules-engine/#set-connector) as `Default Origin`.

For image optimization and caching, the template covers the file extensions `.jpg`, `.jpeg`, `.bmp`, `.ico`, `.gif`, and `.png`. For static content, it supports the common static file extensions.

The template respects the cache settings that the origin sends, or uses a default TTL for cache instead. Its rules change the cache settings of static files by the file extension of the requested content, to improve delivery.

## Manage the application

The settings that the Dynamic and Static File Optimization template applies may not fit your application. You can change any of them at any time from Azion Console.

To open the application's settings:

<DocSteps>
  <DocStep title="Open the applications list">

  Access [Azion Console](https://console.azion.com/) > **Applications**. The list shows every application you created, in alphabetical order.

  </DocStep>
  <DocStep title="Select the application that the template created">

  To find it in a long list, search by its name. The search filters the list by **Application Name** only.

  </DocStep>
</DocSteps>

The application opens on a page that holds every setting you can configure. For more information, refer to [Main Settings](/en/documentation/platform/applications/main-settings/), [Rules Engine for Applications](/en/documentation/platform/applications/rules-engine/), and [Device Groups](/en/documentation/platform/applications/device-groups/). To change the cache policies, refer to [Configure cache policies for an application](/en/documentation/guides/application-performance/cache-and-purge/cache-settings/).

## Add a custom domain

The Dynamic and Static File Optimization deployment assigns the application a [workload](/en/documentation/platform/workloads/) domain in the format `xxxxxxxxxx.map.azionedge.net`, which a browser can open. To serve the application from a domain you own, add a custom domain. For more information, refer to [Domains](/en/documentation/platform/workloads/domains/) and [Add a custom domain to a workload](/en/documentation/guides/platform/migration/configure-a-domain/).
