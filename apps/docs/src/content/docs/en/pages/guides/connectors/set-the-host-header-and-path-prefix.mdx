You can set the `Host` header a [connector](/en/documentation/platform/connectors/) sends to its origin, and a path it prepends to every request, from Azion Console, the Azion CLI, or the API. Both settings apply to a connector of type `http`. The examples use `httpbin.org` as the origin, because it answers with the request it received, so each setting shows in its response. Replace it with the host name of your origin.

- A connector of type `http`, and a workload whose application points a rule at the connector with the `Set Connector` behavior. To create both, refer to [Connectors quickstart](/en/documentation/platform/connectors/quickstart/).
- The workload domain, or a domain of your own, that the workload answers on.

## Send the origin's own host name

By default, `host` is `${host}`, which sends the host the client requested. Keep the default for an origin that serves several virtual hosts and reads each request under its public name. Set a literal value when the origin answers only under its own name. The connector then sends that name for every request.

<Tabs client:visible sharedStore="interface">

<Fragment slot="panel.console">

To set the host name in Azion Console:

<DocSteps>
  <DocStep title="Open the connector">

  Access [Azion Console](https://console.azion.com/) > **Connectors**, then select your connector.

  </DocStep>
  <DocStep title="Enter the host name">

  In **Host**, enter `httpbin.org`.

  </DocStep>
  <DocStep title="Select Save" />
</DocSteps>

Azion Console shows `Connector has been updated`. The Console refuses a value that is not a host name, an IP address, or a variable, with `Host must be a valid hostname, IP address, or variable.`

</Fragment>

<Fragment slot="panel.cli">

The CLI updates a connector from a file that carries the whole connector: its `name`, `type`, `attributes.addresses`, and the connection options you set. A file with `connection_options` alone fails with `Failed to decode the given 'json' file`. Copy your connector's current values into the file, then change `host`.

To set the host name with the Azion CLI, save the connector as `connector.json`:

```json
{
  "name": "my-connector",
  "type": "http",
  "attributes": {
    "addresses": [{"address": "httpbin.org"}],
    "connection_options": {"transport_policy": "force_https", "host": "httpbin.org"}
  }
}
```

Then update the connector from the file. Replace `<connector-id>` with the ID of your connector:

```bash
azion update connector --connector-id <connector-id> --type http --file connector.json
```

```text
Updated Connector with ID <connector-id>
```

The connector now sends `Host: httpbin.org` to the origin.

</Fragment>

<Fragment slot="panel.api">

To set the host name with the API, send a `PATCH` request with only the key you change. A `PATCH` merges it into the stored connector:

```bash
curl --request PATCH \
  --url https://api.azion.com/v4/workspace/connectors/<connector-id> \
  --header 'Accept: application/json' \
  --header 'Authorization: Token [TOKEN VALUE]' \
  --header 'Content-Type: application/json' \
  --data '{"attributes":{"connection_options":{"host":"httpbin.org"}}}'
```

The API answers `202` with `"state": "pending"` and the full connector. `connection_options.host` reads `httpbin.org`, and the other connection options keep their values. An empty `host` is refused with `400` and `10018` `This field may not be blank.`

</Fragment>

</Tabs>

To send the client's host again, set the value back to `${host}`.

## Prepend a path

The path goes in front of the path the client requested, so the origin serves content from one of its directories. With `/anything`, a request for `/get` reaches the origin as `/anything/get`. With `/secure`, a request for `https://<your-domain>/index.html` reaches the origin as `/secure/index.html`. The prefix never appears in the client's URL. The value starts with `/`, and the default is no prefix.

For a bucket of Object Storage, a connector of type `storage` carries its own `prefix` instead. For more information, refer to [Connector settings](/en/documentation/platform/connectors/settings/#storage).

<Tabs client:visible sharedStore="interface">

<Fragment slot="panel.console">

To set the path in Azion Console:

<DocSteps>
  <DocStep title="Open the connector">

  Access [Azion Console](https://console.azion.com/) > **Connectors**, then select your connector.

  </DocStep>
  <DocStep title="Enter the path">

  In **Path**, enter `/anything`.

  </DocStep>
  <DocStep title="Select Save" />
</DocSteps>

Azion Console shows `Connector has been updated`. A path without the leading slash is refused with `Path must start with a forward slash (/)`.

</Fragment>

<Fragment slot="panel.cli">

To set the path with the Azion CLI, add `path_prefix` to the whole connector in `connector.json`:

```json
{
  "name": "my-connector",
  "type": "http",
  "attributes": {
    "addresses": [{"address": "httpbin.org"}],
    "connection_options": {"transport_policy": "force_https", "host": "httpbin.org", "path_prefix": "/anything"}
  }
}
```

Then update the connector from the file:

```bash
azion update connector --connector-id <connector-id> --type http --file connector.json
```

```text
Updated Connector with ID <connector-id>
```

To read the connection options back:

```bash
azion describe connector --connector-id <connector-id> --format json
```

The output carries the new path and the host name from the file:

```text
  "connection_options": {
   "dns_resolution": "both",
   "following_redirect": false,
   "host": "httpbin.org",
   "http_version_policy": "http1_1",
   "path_prefix": "/anything",
   "real_ip_header": "X-Real-IP",
   "real_port_header": "X-Real-PORT",
   "transport_policy": "force_https"
  },
```

`path_prefix` carries `/anything`, and `host` carries the name from the file.

</Fragment>

<Fragment slot="panel.api">

To set the path with the API, send a `PATCH` request with `path_prefix` alone:

```bash
curl --request PATCH \
  --url https://api.azion.com/v4/workspace/connectors/<connector-id> \
  --header 'Accept: application/json' \
  --header 'Authorization: Token [TOKEN VALUE]' \
  --header 'Content-Type: application/json' \
  --data '{"attributes":{"connection_options":{"path_prefix":"/anything"}}}'
```

The API answers `202` with `"state": "pending"` and the full connector, where `connection_options.path_prefix` reads `/anything`. A value without the leading slash, such as `anything`, is refused with `400` and `28009` `Invalid path format. Must be a valid path.`

</Fragment>

</Tabs>

## Verify what the origin receives

A connector change needs no new deployment. It reaches traffic over several minutes, and each data center applies it at its own moment. For more information, refer to [How Connectors works](/en/documentation/platform/connectors/how-it-works/#propagation).

To see the request the origin received, send a request through your workload. Replace `<workload-domain>` with the workload domain or your own domain:

```bash
curl -s -D - https://<workload-domain>/get
```

`httpbin.org` answers with the request it received, as JSON. Two fields show the connector's settings: `headers.Host` is the `Host` header, and `url` carries the path the origin received. This response comes from a connector with `host` at `${host}` and the path `/anything`:

```text
HTTP/2 200
…
server: gunicorn/19.9.0
…
  "headers": {
    …
    "Host": "<workload-domain>",
    …
  },
  …
  "url": "https://<workload-domain>/anything/get"
}
```

`url` carries `/anything/get`, so the path was prepended. `headers.Host` carries the workload domain, the host the client requested. With `host` at `httpbin.org`, `headers.Host` reads `httpbin.org` instead. Send the request several times: an answer with the previous values comes from a data center that has not applied the change yet.
