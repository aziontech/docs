You can deploy an AI agent built with LangGraph to Azion from the LangGraph AI Agent Boilerplate template in Azion Console. To create an application without a template, refer to [Applications quickstart](/en/documentation/platform/applications/quickstart/).

The template configures real-time agents that query and interact with data stored in [SQL Database](/en/documentation/platform/sql-database/), on Azion's distributed infrastructure. The template uses Vue `3.3.4`.

The deployment creates a GitHub repository for your project and a database in SQL Database. The database has two tables: one for conversation history and one for reference documents. The deployment also creates a backend application, built with LangGraph, that manages documents and runs the agent, and a Vue frontend for user interaction. The template uses [Application Accelerator](/en/documentation/platform/applications/application-accelerator/), [Functions](/en/documentation/platform/functions/), and SQL Database, and their usage can generate costs. For more information, refer to [Pricing](/en/documentation/fundamentals/pricing/).

---

## Prerequisites

- An Azion account. To create one, refer to [Create an account](/en/documentation/fundamentals/creating-account/).
- Access to Azion Console. To sign in, refer to [Access Azion Console](/en/documentation/guides/platform/account-and-billing/how-to-access-azion-console/).
- A [GitHub account](https://github.com/signup). Azion connects to it and creates the project's repository there.
- An [OpenAI](https://platform.openai.com/) API key.

## Deploy the template

The LangGraph AI Agent Boilerplate opens as a configuration form in Azion Console, and an asterisk marks each mandatory field.

To deploy the template:

<DocSteps>
  <DocStep title="Open the template">

  Go to [LangGraph AI Agent Boilerplate](https://console.azion.com/create/azion/langgraph-agent-boilerplate) in Azion Console. The configuration form opens.

  </DocStep>
  <DocStep title="Connect Azion with your GitHub account">

  A window opens to confirm the installation of the [Azion GitHub App](/en/documentation/guides/application-development/automation/azion-github-app/), which connects your GitHub account with Azion. In that window, define the app's permissions and repository access.

  </DocStep>
  <DocStep title="Select the Git Scope">

  Select the **Git Scope** to work with.

  </DocStep>
  <DocStep title="Name the agent">

  Enter a unique name that you can remember. By default, the database name follows the pattern `<your-agent-name>-database`. If the name is already in use, the platform returns an error message.

  </DocStep>
  <DocStep title="Enter your OpenAI API key" />
  <DocStep title="Select the authentication method">

  Select how users authenticate to access the agent, and enter the information that the method needs:

  - **No Auth**: the agent requires no authentication. Leave the fields blank.
  - **Basic Auth**: enter the token or password for basic authentication.
  - **Clerk Auth**: enter the public and private keys of [Clerk](https://clerk.com) to authenticate through that service. You can configure the rules of the authentication process in the dashboard of your Clerk account.

  </DocStep>
  <DocStep title="Start the deployment">

  Select **Deploy**.

  </DocStep>
</DocSteps>

A window shows the deployment logs while it runs. When the deployment completes, the page shows the application's details, a browser link to it, and options to continue.

The link can take a few minutes to start serving the application, while its configuration propagates across Azion's distributed infrastructure. If the page does not load, wait a few minutes and open the link again.

## Set up the database

The LangGraph AI Agent Boilerplate creates two tables in the database: one for conversation history and one for reference documents. Before the agent can use your own documents, set up the database and upload the documents from the backend project.

To set up the database and upload your documents:

1. Open the GitHub repository of the backend application that the deployment created. Its name is similar to `<your-agent-name>-backend-agent`.
2. Check that the project has a `.env` file with your environment variables. To create a new one, use this structure:

    ```bash
    AZION_TOKEN="[TOKEN VALUE]"
    OPENAI_API_KEY="[TOKEN VALUE]"
    OPENAI_MODEL= 'gpt-4o'
    EMBEDDING_MODEL= 'text-embedding-3-small'

    # Database and table names in SQL Database. The table names usually stay the same,
    # and the database name is the name of your agent followed by -database.
    MESSAGE_STORE_DB_NAME="<your-agent-name>-database"
    MESSAGE_STORE_TABLE_NAME='messages'
    VECTOR_STORE_DB_NAME="<your-agent-name>-database"
    VECTOR_STORE_TABLE_NAME='vectors'

    # Optional: Langsmith to trace the requests and responses
    LANGSMITH_API_KEY=
    LANGCHAIN_PROJECT=
    LANGCHAIN_TRACING_V2=false

    # Optional: Clerk authentication with your frontend
    CLERK_PUBLISHABLE_KEY=
    CLERK_SECRET_KEY=
    ```

    Not every variable is required. For what each one does, refer to [Backend environment variables](#backend-environment-variables).

3. In the project's `migrations` folder, run the vector database setup:

    ```bash
    yarn setup
    ```

    The setup configures the vector database and creates its `vectors` table. The `migrations/uploadDocs.ts` file only inserts documents into existing databases, so run this setup before the first upload.

4. If the project has no `migrations/files/` folder, create it.
5. Place your document files in `migrations/files/`. The supported formats are PDF, Markdown (`.md`), Text (`.txt`), and JSON.
6. Upload the documents:

    ```bash
    yarn upload-docs
    ```

    The upload splits the content of the files into smaller chunks and inserts the chunks into the vector store.

The database holds your reference documents, and the application can access them. For more details on how to configure the project, refer to the [template documentation](https://github.com/aziontech/azion-samples/tree/3cf53a690ac7f40508bc020adcfc61ba553d0b2f/templates/typescript/azion-react-agent).

The template also creates a table that stores the messages exchanged with the agent. By default, the table keeps messages for 14 days.

:::tip
To view your databases and tables and run SQL commands from a terminal, use the [EdgeSQL Shell](/en/documentation/platform/sql-database/edgesql-shell/), a command-line tool for SQL Database. You can also work with the databases through the Azion API v4. For the API operations, refer to [Databases and queries](/en/documentation/platform/sql-database/databases-and-queries/#list-databases).
:::

## Backend environment variables

The `.env` file of the backend project holds its environment variables. Not every variable is required.

| Environment variable | Description | Required |
| --- | --- | --- |
| `AZION_TOKEN` | The token for authenticating with Azion's platform. | Yes |
| `OPENAI_API_KEY` | Your API key for accessing OpenAI services. | Yes |
| `OPENAI_MODEL` | The OpenAI model that processes the requests. If not set, defaults to `gpt-4o`. | No |
| `EMBEDDING_MODEL` | The model that generates embeddings. If not set, defaults to `text-embedding-3-small`. To use a different model, create a database with columns configured for that model. | No |
| `LANGSMITH_API_KEY` | The API key for accessing Langsmith services. | No |
| `LANGCHAIN_PROJECT` | The Langchain project identifier. | No |
| `LANGCHAIN_TRACING_V2` | Turns Langchain tracing on or off. Set it to `true` or `false`. | No |
| `MESSAGE_STORE_DB_NAME` | The name of the database that stores the conversation history messages. By default, it is the same database that stores the documents. Default name: `<your-agent-name>-database`. | Yes |
| `MESSAGE_STORE_TABLE_NAME` | The name of the table, in the messages database, that stores the conversation history. Default name: `messages`. | Yes |
| `VECTOR_STORE_DB_NAME` | The name of the database that stores your documents as vector embeddings. By default, it is the same database that stores the messages. Default name: `<your-agent-name>-database`. | Yes |
| `VECTOR_STORE_TABLE_NAME` | The name of the table, in the documents database, that stores the embeddings. Default name: `vectors`. | Yes |
| `CLERK_PUBLISHABLE_KEY` | The public key of Clerk, for Clerk authentication with your frontend. | No |
| `CLERK_SECRET_KEY` | The private key of Clerk, for Clerk authentication with your frontend. | No |

## Customize the database setup

The backend project of the LangGraph AI Agent Boilerplate configures and initializes its databases in two files. You can edit them to fit the database configuration to your needs:

- **Vector database (RAG)**: `migrations/setupDatabase.ts` configures the vector database with `AzionVectorStore.initialize()`. It creates the `vectors` table with the embedding column that the model needs, for example `F32_BLOB(1536)` when `EMBEDDING_MODEL=text-embedding-3-small`.
- **Message database (tracing)**: `src/services/edgeSqlTracerService.ts` creates the message database when it does not exist. It creates the `messages` table with the DDL that `createSetupTableStatement()` generates. The configuration runs on demand, through the `handleErrors` method.

The `migrations/setupDatabase.ts` file offers two ways to configure the vector database. The active method, in use:

```typescript
AzionVectorStore.initialize(embeddingModel, { dbName, tableName }, { mode: "hybrid", columns: ["*"] })
```

The alternative method, commented out in the file:

```typescript
// const vectorStore = new AzionVectorStore(...);
// await vectorStore.setupDatabase({ mode: "hybrid", columns: ["*"] });
```

The `migrations/uploadDocs.ts` file processes the documents with the `getDocsFromFolder("migrations/files")` function. The function reads every supported file in the folder and splits the content into smaller chunks. It then inserts the chunks into the vector store for semantic search.

To read your documents from a different folder, edit `migrations/uploadDocs.ts` and change the argument of `getDocsFromFolder()`:

```typescript
// Example: changing to a custom folder
const docs = await getDocsFromFolder("my-custom-folder");
```

## Update the project

Every push to the GitHub repository that the LangGraph AI Agent Boilerplate creates deploys automatically.

To update the deployed project, push your changes to that repository. Azion deploys them, and the application serves the new version.

## Manage the application

The settings that the LangGraph AI Agent Boilerplate applies may not fit your application. You can change any of them at any time from Azion Console.

To open the application's settings:

<DocSteps>
  <DocStep title="Open the applications list">

  Access [Azion Console](https://console.azion.com/) > **Applications**. The list shows every application you created, in alphabetical order.

  </DocStep>
  <DocStep title="Select the application that the template created">

  To find it in a long list, search by its name. The search filters the list by application name only.

  </DocStep>
</DocSteps>

The application opens on a page that holds every setting you can configure. For more information, refer to [Main Settings](/en/documentation/platform/applications/main-settings/), [Rules Engine for Applications](/en/documentation/platform/applications/rules-engine/), and [Device Groups](/en/documentation/platform/applications/device-groups/).

## Add a custom domain

The LangGraph AI Agent Boilerplate deployment assigns the application a [workload](/en/documentation/platform/workloads/) domain in the format `xxxxxxxxxx.map.azionedge.net`, which a browser can open. To serve the application from a domain you own, add a custom domain. For more information, refer to [Domains](/en/documentation/platform/workloads/domains/) and [Add a custom domain to a workload](/en/documentation/guides/platform/migration/configure-a-domain/).
