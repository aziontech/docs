You can serve a status or error page from the Hello World function on an application, from Azion Console. The function answers on Azion's distributed infrastructure, so the request never reaches your origin. To install Hello World from Azion Marketplace with a status code and a body instead, refer to [Install the Hello World integration](/en/documentation/guides/application-development/integrations/hello-world/).

A status page reports the state of a service, so you can monitor it and inform its users. The example on this page answers requests to `www.myapplication.com/api_service` with a notice that the service is temporarily unavailable. With [Data Stream](/en/documentation/platform/data-stream/), you can also send the access records of the page to a SIEM (Security Information and Event Management), Big Data, or log servers, and analyze the data there.

---

## Prerequisites

- Access to Azion Console. To sign in, refer to [How to access Azion Console](/en/documentation/guides/platform/account-and-billing/how-to-access-azion-console/).
- An [application](/en/documentation/platform/applications/) that receives the requests for the status page.
- Application Accelerator and [Functions](/en/documentation/platform/functions/) turned on for the application. The _Run Function_ behavior requires both. For more information, refer to [Rules Engine for Applications](/en/documentation/platform/applications/rules-engine/#run-function).

---

## Create the function instance

An application runs a function through an instance, and the instance passes its Args to the function. Azion provides the Hello World function, and its Args set the HTTP status code and the message of the response. The example instance uses these Args:

```json
{
    "param":{
        "http_status": 503,
        "body": "We are working hard to serve you better!"
    }
}
```

To create the instance in Azion Console:

<DocSteps>
  <DocStep title="Open the application">

  Access [Azion Console](https://console.azion.com/) > **Applications**, then select the application that serves the status page.

  </DocStep>
  <DocStep title="Go to the Functions Instances tab" />
  <DocStep title="Select + Function Instance" />
  <DocStep title="Name the instance">

  Enter a distinctive name. For example: `MyHelloWorld`.

  </DocStep>
  <DocStep title="Select the function">

  In the **Function** field, select _Hello World_. The **Code** field shows the code of the function for reference only.

  </DocStep>
  <DocStep title="Enter the Args">

  In the **Args** tab, enter the JSON with your status code and message.

  </DocStep>
  <DocStep title="Select Save" />
</DocSteps>

The `MyHelloWorld` instance is on the application. It runs only after a Rules Engine rule selects it.

---

## Add the rule that runs the instance

A Rules Engine rule sets the criteria a request must meet and the behaviors that run when it does. You can add the behavior to the Default Rule or create a new rule. Here, a new rule runs `MyHelloWorld` when the URI starts with `/api_service`.

To create the rule in Azion Console:

<DocSteps>
  <DocStep title="Open the application">

  Access [Azion Console](https://console.azion.com/) > **Applications**, then select the application that serves the status page.

  </DocStep>
  <DocStep title="Select the Rules Engine tab" />
  <DocStep title="Select + Rule" />
  <DocStep title="Name the rule">

  Enter a name for the rule.

  </DocStep>
  <DocStep title="Set the criterion">

  In the **Criteria** section, select `${uri}` as the variable and `starts_with` as the operator, and enter `/api_service` as the argument.

  </DocStep>
  <DocStep title="Add the behavior">

  In the **Behaviors** section, select _Run Function_, then select `MyHelloWorld`.

  </DocStep>
  <DocStep title="Select Save" />
</DocSteps>

A request to `www.myapplication.com/api_service` returns the status code `503` with the body `We are working hard to serve you better!`.
