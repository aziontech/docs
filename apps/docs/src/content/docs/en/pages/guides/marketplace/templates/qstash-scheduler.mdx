You can deploy a task scheduler to Azion from the QStash Function Scheduler template in Azion Console. To create an application without a template, refer to [Applications quickstart](/en/documentation/platform/applications/quickstart/).

The template sets up and manages a custom function. The function receives a schedule that you configure and dispatches it through QStash, a message queue and task scheduler for serverless runtimes.

The deployment creates the function, a GitHub repository for your project, an [application](/en/documentation/platform/applications/) that runs the function, and a domain to reach it. The application uses [Functions](/en/documentation/platform/functions/), and its usage can generate costs. For more information, refer to [Pricing](/en/documentation/fundamentals/pricing/).

---

## Prerequisites

- An Azion account. To create one, refer to [Create an account](/en/documentation/fundamentals/creating-account/).
- Access to Azion Console. To sign in, refer to [Access Azion Console](/en/documentation/guides/platform/account-and-billing/how-to-access-azion-console/).
- A [GitHub account](https://github.com/signup). Azion connects to it and creates the project's repository there.
- An [Upstash account](https://console.upstash.com/).
- The **Current Signing Key**, the **Next Signing Key**, and the **QStash Token** of your Upstash account. Copy them from the **QStash** tab of the [Upstash Console](https://console.upstash.com/qstash).

:::caution
Upstash processes and bills the cost of QStash usage separately, on the Upstash platform. For more information, refer to [QStash Getting Started](https://upstash.com/docs/qstash/overall/getstarted).
:::

## Deploy the template

The QStash Function Scheduler opens as a configuration form in Azion Console, and an asterisk marks each mandatory field.

To deploy the template:

<DocSteps>
  <DocStep title="Open the template">

  Go to [QStash Function Scheduler](https://console.azion.com/create/upstash/qstash-edgefunction-scheduler) in Azion Console. The configuration form opens.

  </DocStep>
  <DocStep title="Connect Azion with your GitHub account">

  A window opens to confirm the installation of the [Azion GitHub App](/en/documentation/guides/application-development/automation/azion-github-app/), which connects your GitHub account with Azion. In that window, define the app's permissions and repository access.

  </DocStep>
  <DocStep title="Select the Git Scope">

  Select the **Git Scope** to work with.

  </DocStep>
  <DocStep title="Name the application">

  Enter a unique name that you can remember. The storage bucket and the function that the template creates take the same name. If the name is already in use, the platform returns an error message.

  </DocStep>
  <DocStep title="Enter the QStash signing keys">

  Both keys are mandatory. Copy each one from the **QStash** tab of your Upstash Console:

  - **QStash Current Signing Key**: the string that signs every message sent to the destination. Copy the value of `QSTASH_CURRENT_SIGNING_KEY`.
  - **QStash Next Signing Key**: the string that signs messages after you rotate your signing keys. Copy the value of `QSTASH_NEXT_SIGNING_KEY`.

  </DocStep>
  <DocStep title="Start the deployment">

  Select **Deploy**.

  </DocStep>
</DocSteps>

A window shows the deployment logs while it runs. When the deployment completes, the page shows the application, a link that opens it in a browser, and options to continue. The deployment leaves you with:

- A function built with the arguments you entered in the form.
- A GitHub repository that carries an automation for continuous deployment.
- An application, created and instantiated on Azion, and its domain.

The link can take a few minutes to start serving the application, while its configuration propagates across Azion's distributed infrastructure. If the page does not load, wait a few minutes and open the link again.

## Schedule tasks

After the QStash Function Scheduler deployment finishes and propagates, schedule tasks for the function from a terminal or from the Upstash Console. Schedule each task in a format that an HTTP request can carry, such as JSON, XML, or binary. The examples in this section use JSON.

### Schedule a task from a terminal

To schedule a task from your development environment:

<DocSteps>
  <DocStep title="Get the domain of your application" />
  <DocStep title="Copy your QStash token">

  In the **QStash** tab of the [Upstash Console](https://console.upstash.com/qstash), copy the `QSTASH_TOKEN`.

  </DocStep>
  <DocStep title="Open a terminal in your development environment" />
  <DocStep title="Send an HTTP POST request that schedules your messages">

  Run the example that matches the interval you need.

  </DocStep>
</DocSteps>

#### Publish the message once

To publish the message once:

```bash
curl --request POST "https://qstash.upstash.io/v1/publish/{add your domain here}" \
     -H "Authorization: Bearer {add your QStash token here}" \
     -H "Content-Type: application/json" \
     -d "{ \"hello\": \"world\"}"
```

#### Publish the message every minute

To publish the message every minute:

```bash
curl --request POST "https://qstash.upstash.io/v1/publish/{add your domain here}" \
     -H "Authorization: Bearer {add your QStash token here}" \
     -H "Content-Type: application/json" \
     -H "Upstash-Cron: * * * * *" \
     -d "{ \"hello\": \"world\"}"
```

#### Publish the message every 10 minutes

To publish the message every 10 minutes:

```bash
curl --request POST "https://qstash.upstash.io/v1/publish/{add your domain here}" \
     -H "Authorization: Bearer {add your QStash token here}" \
     -H "Content-Type: application/json" \
     -H "Upstash-Cron: */10 * * * *" \
     -d "{ \"hello\": \"world\"}"
```

#### Publish the message every hour

To publish the message every hour:

```bash
curl --request POST "https://qstash.upstash.io/v1/publish/{add your domain here}" \
     -H "Authorization: Bearer {add your QStash token here}" \
     -H "Content-Type: application/json" \
     -H "Upstash-Cron: 0 * * * *" \
     -d "{ \"hello\": \"world\"}"
```

The commands use these flags:

| Flag | Description |
|---|---|
| `--request POST` | Sets the request method. The HTTP POST method publishes, or schedules, an HTTP message. |
| `-H "Authorization"` | Carries the token that authenticates the request. Add your QStash token here. |
| `-H "Content-Type"` | Sets the content type of the request body, JSON in these examples. |
| `-H "Upstash-Cron"` | Schedules a cron-like job in Upstash, which runs the task at a fixed interval. |
| `-d` | Carries the data of the request body, including the JSON payload. The backslashes (`\`) before the double quotes (`"`) keep the quotes as part of the data inside the JSON payload. |

The task is scheduled, and it runs on the schedule you defined. To review and monitor your scheduled tasks, open the **QStash** tab of the [Upstash Console](https://console.upstash.com/qstash).

### Schedule a task from the Upstash Console

To schedule a task from the Upstash Console:

<DocSteps>
  <DocStep title="Copy the domain of your Azion application" />
  <DocStep title="Open the QStash tab">

  In the [Upstash Console](https://console.upstash.com/qstash), open the **QStash** tab.

  </DocStep>
  <DocStep title="Complete the form">

  Set the type field to _Scheduled_, and choose the delay. To send one immediate message instead, select _Once_.

  </DocStep>
  <DocStep title="Select Schedule" />
</DocSteps>

The task is scheduled and appears in the **Scheduled Jobs** section, where you can review and monitor it.

To publish a message with a REST API request instead, refer to [Publish a Message](https://upstash.com/docs/qstash/api-reference/messages/publish-a-message).

## Update the project

Every push to the GitHub repository that the QStash Function Scheduler creates deploys automatically.

To update the deployed project, push your changes to that repository. Azion deploys them, and the application serves the new version.

---

## Manage the application

The settings that the QStash Function Scheduler applies may not fit your application. You can change any of them at any time from [Azion Console](https://console.azion.com/). After the deployment, you also keep full control of your Upstash account and your QStash configuration.

To open the application's settings:

<DocSteps>
  <DocStep title="Open the applications list">

  Access [Azion Console](https://console.azion.com/) > **Applications**. The list shows every application on the account, in alphabetical order.

  </DocStep>
  <DocStep title="Select the application that the template created">

  To find it in a long list, search by its name. The search filters the list by **Application Name** only.

  </DocStep>
</DocSteps>

The application opens on a page that holds every setting you can configure. For more information, refer to [Main Settings](/en/documentation/platform/applications/main-settings/), [Rules Engine for Applications](/en/documentation/platform/applications/rules-engine/), and [Device Groups](/en/documentation/platform/applications/device-groups/). For questions about Upstash or QStash, refer to the [Upstash documentation](https://docs.upstash.com/).

## Add a custom domain

The QStash Function Scheduler deployment assigns the application a [workload](/en/documentation/platform/workloads/) domain in the format `xxxxxxxxxx.map.azionedge.net`, which a browser can open. To serve the application from a domain you own, add a custom domain. For more information, refer to [Add a custom domain to a workload](/en/documentation/guides/platform/migration/configure-a-domain/) and [Domains](/en/documentation/platform/workloads/domains/).
