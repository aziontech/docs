You can deploy a static Nuxt 3 application to Azion from the Nuxt 3 Static Boilerplate template in Azion Console. To create an application without a template, refer to [Applications quickstart](/en/documentation/platform/applications/quickstart/).

The Nuxt 3 Static Boilerplate holds the configurations to build a static application based on Nuxt 3. The template uses Nuxt `3.13.0`.

The deployment creates a GitHub repository for your project, an [application](/en/documentation/platform/applications/) that serves it, and a domain to reach it. The application uses [Application Accelerator](/en/documentation/platform/applications/application-accelerator/), [Functions](/en/documentation/platform/functions/), and [Cache](/en/documentation/platform/applications/cache/), and their usage can generate costs. For more information, refer to [Pricing](/en/documentation/fundamentals/pricing/).

---

## Prerequisites

- An Azion account. To create one, refer to [Create an account](/en/documentation/fundamentals/creating-account/).
- Access to Azion Console. To sign in, refer to [Access Azion Console](/en/documentation/guides/platform/account-and-billing/how-to-access-azion-console/).
- A [GitHub account](https://github.com/signup). Azion connects to it and creates the project's repository there.

---

## Deploy the template

The Nuxt 3 Static Boilerplate opens as a configuration form in Azion Console, and an asterisk marks each mandatory field.

To deploy the template:

<DocSteps>
  <DocStep title="Open the template">

  Go to [Nuxt 3 Static Boilerplate](https://console.azion.com/create/nuxt-static-boilerplate) in Azion Console. The configuration form opens.

  </DocStep>
  <DocStep title="Connect Azion with your GitHub account">

  A window opens to confirm the installation of the [Azion GitHub App](/en/documentation/guides/application-development/automation/azion-github-app/), which connects your GitHub account with Azion. In that window, define the app's permissions and repository access.

  </DocStep>
  <DocStep title="Select the Git scope to work with" />
  <DocStep title="Name the application">

  Enter a unique name that you can remember. The storage bucket and the function that the template creates take the same name. If the name is already in use, the platform returns an error message.

  </DocStep>
  <DocStep title="Start the deployment">

  Select **Deploy**.

  </DocStep>
</DocSteps>

A window shows the deployment logs while it runs. When the deployment completes, the page shows the application's details, a browser link to it, and options to continue.

The link can take a few minutes to start serving the application, while its configuration propagates across Azion's distributed infrastructure. If the page does not load, wait a few minutes and open the link again.

---

## Update the project

Every push to the GitHub repository that the Nuxt 3 Static Boilerplate creates deploys automatically.

To update the deployed project, push your changes to that repository. Azion deploys them, and the application serves the new version.

---

## Manage the application

The settings that the Nuxt 3 Static Boilerplate applies may not fit your application. You can change any of them at any time from Azion Console.

To open the application's settings:

<DocSteps>
  <DocStep title="Open the applications list">

  Access [Azion Console](https://console.azion.com/) > **Applications**. The list shows every application you created, in alphabetical order.

  </DocStep>
  <DocStep title="Select the application that the template created">

  To find it in a long list, search by its name. The search filters the list by application name only.

  </DocStep>
</DocSteps>

The application opens on a page that holds every setting you can configure. For more information, refer to [Main Settings](/en/documentation/platform/applications/main-settings/), [Rules Engine for Applications](/en/documentation/platform/applications/rules-engine/), and [Device Groups](/en/documentation/platform/applications/device-groups/).

---

## Add a custom domain

The Nuxt 3 Static Boilerplate deployment assigns the application a [workload](/en/documentation/platform/workloads/) domain in the format `xxxxxxxxxx.map.azionedge.net`, which a browser can open. To serve the application from a domain you own, add a custom domain. To list the domain on the workload and point its DNS record at the workload, refer to [Add a custom domain to a workload](/en/documentation/guides/platform/migration/configure-a-domain/). For more information, refer to [Domains](/en/documentation/platform/workloads/domains/).
