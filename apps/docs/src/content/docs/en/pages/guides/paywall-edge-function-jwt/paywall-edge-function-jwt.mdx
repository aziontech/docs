A paywall built with the JWT function has two parts: a function instance on a [firewall](/en/documentation/platform/firewall/) that validates the token, and a firewall rule that runs the instance on the content you restrict. The JWT function is a serverless solution available in Azion Marketplace, and it runs on a firewall, not on an application.

The origin application generates the token and sets its expiration. It also decides how access is controlled:

- The authentication method, such as OAuth, OpenID Connect, Auth0, or Keycloak.
- The number of access attempts or bytes a visitor spends before the sign-in prompt.
- How long a visitor browses without further authorization.

The token follows the Bearer Authentication Scheme, the standard for HTTP authentication. Every request carries a JSON object of authentication information in its header.

The JWT function validates that token on each request the firewall inspects. It follows the business rules defined in the token, and those rules combine with the criteria you set in the firewall's Rules Engine. The result decides the behavior: the request reaches the content, or it goes to the sign-in page of the origin application. Validation runs on the firewall, before the request reaches the application or the origin, so the origin does not process an unauthorized request.

---

## Prerequisites

- An application served by a [workload](/en/documentation/platform/workloads/). To create one, refer to [Applications quickstart](/en/documentation/platform/applications/quickstart/).
- The JWT function installed on the account. To install it, refer to [Install the JWT integration](/en/documentation/guides/application-development/integrations/jwt/).
- A firewall with the **Functions** module turned on, bound to the workload's deployment. To create one, refer to [Create the firewall](/en/documentation/guides/application-development/integrations/jwt/#create-the-firewall), and to bind it, [Bind a firewall to a workload](/en/documentation/guides/application-security/firewall-and-waf/firewall-protect-your-domain/#bind-the-firewall-to-the-workload).
- The list of KID and secret key pairs that the origin application uses to sign the token.

## Instantiate the JWT function on the firewall

A firewall runs a function through a function instance, and the instance carries the arguments passed into the execution context. For the full procedure on Azion Console and the Azion API, refer to [Instantiate a function on a firewall](/en/documentation/guides/application-security/firewall-and-waf/instantiate-functions/).

The **Arguments** field takes the list of KID (key ID) and secret key pairs that generate the signature of the token. The origin application defines the pairs. To create the instance:

<DocSteps>
  <DocStep title="Open the Functions Instances tab">

  Access [Azion Console](https://console.azion.com/) > **Firewalls**, select your firewall, then select the **Functions Instances** tab.

  </DocStep>
  <DocStep title="Select + Function">

  A firewall that has no instance shows the same action as **Function Instance**. The **Create Instance** drawer opens.

  </DocStep>
  <DocStep title="Name the instance">

  Enter a name for the instance. For example: `paywall-jwt`.

  </DocStep>
  <DocStep title="Select the JWT function in the Function list" />
  <DocStep title="Enter the KID and secret key pairs">

  In **Arguments**, enter the pairs in this format:

  ```json
  [{
    "kids": {
      "4546D4AA7F62F01A833A7ABE354030E7": "D6CB2342E44EFB6DD628276F36DA2359",
      "D6CB2342E44EFB6DD628276F36DA2359": "60BD8ED7A768E8BD6925BEB0A691AADB",
      "60BD8ED7A768E8BD6925BEB0A691AADB": "4546D4AA7F62F01A833A7ABE354030E7"
    }
  }]
  ```

  </DocStep>
  <DocStep title="Select Save" />
</DocSteps>

The instance appears in the **Functions Instances** tab of the firewall. It does not run until a firewall rule selects it.

## Add the rule that runs the function

A firewall rule states the conditions a request meets for its behaviors to run. A criterion reads as a variable, a comparison operator, and a string. The behavior that runs the function is **Run Function**, with the instance you created. Match the criteria to the paths you sell by subscription, and to the authentication the origin application already uses.

To create the rule:

<DocSteps>
  <DocStep title="Open the firewall">

  Access [Azion Console](https://console.azion.com/) > **Firewalls** > **your firewall**.

  </DocStep>
  <DocStep title="Go to the Rules Engine tab" />
  <DocStep title="Select + Rule" />
  <DocStep title="Name the rule">

  Enter a name for the rule. For example: `Paywall on news`.

  </DocStep>
  <DocStep title="Set the criterion">

  In the **Criteria** section, select `Request Uri`, _starts with_, and enter `/news`. The criterion reads `If ${request_uri} starts with /news`.

  </DocStep>
  <DocStep title="Add the Run Function behavior">

  In the **Behaviors** section, select **Run Function**, then select the instance by the name you gave it.

  </DocStep>
  <DocStep title="Select Save" />
</DocSteps>

The firewall runs the JWT function on every request to the workload whose URI starts with `/news`. New rules can take a few minutes to propagate.

:::note
The function returns an HTTP status code `400` or `401` when the token it receives is invalid. The code depends on the error.
:::
