You can read the URLs bot traffic reached most from the `botManagerBreakdownMetrics` dataset, in the GraphiQL Playground or with the GraphQL API. For the classification counts, refer to [Query Bot Manager data with GraphQL](/en/documentation/guides/platform/observability/query-bot-manager-data-with-graphql/).

---

## Prerequisites

- [Bot Manager](/en/documentation/platform/firewall/bot-manager/) running on your account. On an account with no Bot Manager data, the query answers `200` with an empty list.
- For the Playground, a signed-in Azion Console session in the same browser. Without it, the endpoint answers `401` with `Authentication credentials were not provided.` For more information, refer to [GraphiQL Playground](/en/documentation/devtools/graphql/graphql-playground/).
- For a GraphQL client, a personal token, sent in an `Authorization: Token [TOKEN VALUE]` header. For more information, refer to [Personal Tokens](/en/documentation/fundamentals/personal-tokens/).

---

## Query the URLs bots reached most

The dataset counts the requests Bot Manager classified as bots, by the host, the URL, and the IP address of each request. The query below filters it by a time range, sums `botRequests` per URL, and returns the five URLs with the highest total.

To query the URLs bots reached most:

<DocSteps>
  <DocStep title="Open the Playground">

  Go to `https://api.azion.com/v4/metrics/graphql`. From a GraphQL client, send the query to the same URL with your token.

  </DocStep>
  <DocStep title="Enter the query">

  Set `begin` and `end` to the period you want to read. The dataset is retained for 60 days:

  ```graphql
  query {
    botManagerBreakdownMetrics (
      filter: {
        tsRange: {
          begin: "2024-10-01T00:00:00"
          end: "2024-10-03T00:00:00"
        }
      }
      aggregate: {
        sum: botRequests
      }
      groupBy: [requestUrl]
      orderBy: [sum_DESC]
      limit: 5
    ) {
      requestUrl
      sum
    }
  }
  ```

  </DocStep>
  <DocStep title="Run the query and read the response">

  The response carries one object per URL, with the summed requests in `sum`:

  ```json
  {
    "data": {
      "botManagerBreakdownMetrics": [
        {
          "requestUrl": "example-host1.com/api/v1/resource",
          "sum": 333543
        },
        {
          "requestUrl": "example-host2.net/api/v2/data",
          "sum": 107281
        },
        {
          "requestUrl": "example-host3.org/api/v3/info",
          "sum": 103363
        },
        {
          "requestUrl": "example-host4.io/api/v4/details",
          "sum": 89668
        },
        {
          "requestUrl": "example-host5.co/api/v5/summary",
          "sum": 64060
        }
      ]
    }
  }
  ```

  </DocStep>
</DocSteps>

You now have the URLs bot traffic reached most in the period, ordered by the number of requests classified as bots. For every field of the dataset, refer to [botManagerBreakdownMetrics](/en/documentation/devtools/graphql/gql-real-time-metrics-fields/#bot-manager-breakdown-metrics).

## Change the grouping or the sum

The query above pairs one field of the dataset with one sum. The `groupBy` argument takes `host`, `remoteAddr`, `requestUrl`, and `ts`, and `sum` takes `botRequests` and `badBotRequests`. The `uniqRequestUrl` field can be selected but not grouped or summed: as a sum it is refused with `Value 'uniqRequestUrl' does not exist in 'BotManagerBreakdownMetricsAggregatedFields' enum.`

To read the same period another way:

<DocSteps>
  <DocStep title="Change the grouping">

  Set `groupBy` to `[host]` or to `[remoteAddr]`, and select the same field in place of `requestUrl`. The query then totals the requests per host or per source IP address.

  </DocStep>
  <DocStep title="Change the sum">

  Set `aggregate` to `sum: badBotRequests` to count only the requests classified as bad bots, which are a subset of the requests `botRequests` counts.

  </DocStep>
  <DocStep title="Run the query" />
</DocSteps>

The response carries one object per host, source IP address, or URL, with the chosen sum in `sum`.
