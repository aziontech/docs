You can deploy rate limiting to Azion from the Upstash Rate Limit template in Azion Console. To create an application without a template, refer to [Applications quickstart](/en/documentation/platform/applications/quickstart/). The [Upstash Rate Limiting integration](/en/documentation/guides/application-development/integrations/upstash-rate-limiting-integration/) is a different Azion Marketplace listing, which runs on a firewall.

The Upstash Rate Limit template implements rate limiting in a serverless environment, without extensive manual setup. It includes settings for limiting requests and for the window limit. The template works with [Functions](/en/documentation/platform/functions/), and you adjust its initial setup through the function's arguments.

The deployment creates a GitHub repository for your project, a function, an [application](/en/documentation/platform/applications/) that runs the function, and a domain to reach it. The repository carries a continuous deployment workflow, so you can configure and customize the setup further to fit your needs. The application uses Functions, and its usage can generate costs. For more information, refer to [Pricing](/en/documentation/fundamentals/pricing/).

---

## Prerequisites

- An Azion account. To create one, refer to [Create an account](/en/documentation/fundamentals/creating-account/).
- Access to Azion Console. To sign in, refer to [Access Azion Console](/en/documentation/guides/platform/account-and-billing/how-to-access-azion-console/).
- A [GitHub account](https://github.com/signup). Azion connects to it and creates the project's repository there.
- An [Upstash account](https://console.upstash.com/).
- A Global Database, created in the [Upstash Console](https://console.upstash.com/) for the best available latency.

:::caution
Upstash processes and bills the cost of Upstash usage separately, on the Upstash platform. For more information, refer to the [Upstash documentation](https://docs.upstash.com/redis/features/globaldatabase#pricing).
:::

## Deploy the template

The Upstash Rate Limit template opens as a configuration form in Azion Console, and an asterisk marks each mandatory field.

To deploy the template:

<DocSteps>
  <DocStep title="Open the template">

  Go to [Upstash Rate Limit](https://console.azion.com/create/upstash/upstash-ratelimit) in Azion Console. The configuration form opens.

  </DocStep>
  <DocStep title="Connect Azion with your GitHub account">

  A window opens to confirm the installation of the [Azion GitHub App](/en/documentation/guides/application-development/automation/azion-github-app/), which connects your GitHub account with Azion. In that window, define the app's permissions and repository access.

  </DocStep>
  <DocStep title="Select the Git Scope">

  Select the **Git Scope** to work with.

  </DocStep>
  <DocStep title="Name the application">

  Enter a unique name that you can remember. The storage bucket and the function that the template creates take the same name. If the name is already in use, the platform returns an error message.

  </DocStep>
  <DocStep title="Enter the Upstash REST URL">

  In **Upstash Redis Rest URL**, enter the `UPSTASH_REDIS_REST_URL` from your database page in the Upstash Console. The URL reaches your Upstash database over REST.

  </DocStep>
  <DocStep title="Enter the Upstash REST token">

  In **Upstash Redis Rest Token**, enter the `UPSTASH_REDIS_REST_TOKEN` from your database page in the Upstash Console. The token authorizes access to your Upstash database over REST.

  </DocStep>
  <DocStep title="(Optional) Set the request limit">

  In **Request Limit**, enter the maximum number of requests. For example: `6`.

  </DocStep>
  <DocStep title="(Optional) Set the window limit">

  In **Window Limit**, enter the time window for new requests. For example: `10 s`. The field accepts these units: `"ms" | "s" | "m" | "h" | "d"`.

  </DocStep>
  <DocStep title="Start the deployment">

  Select **Deploy**.

  </DocStep>
</DocSteps>

A window shows the deployment logs while it runs. When the deployment completes, the page shows information about the application, a link that opens it in a browser, and options to continue. The deployment leaves you with:

- A repository in your GitHub account, based on a [public template](https://github.com/aziontech/).
- A GitHub Action in that repository that enables continuous deployment.
- A function that provides the arguments for the rate limiting.
- An application on Azion and its domain.

The link can take a few minutes to start serving the application, while its configuration propagates across Azion's distributed infrastructure. If the page does not load, wait a few minutes and open the link again.

## Rate limiting behavior

The function that the Upstash Rate Limit template creates integrates the `upstash/redis` and `upstash/ratelimit` libraries and connects to your Upstash Global Database. On the `/login` route, it checks whether each client stays within the configured **Window** and **Limit**. The key for the limits is the metadata `["remote_addr"]`.

A client that exceeds the configured **Request Limit** within the defined **Window Limit** receives an `HTTP 429 Too Many Requests` response from the function. The function does not block the client permanently: the limitation is temporary and tied to the **Window Limit** you set.

When the time window resets, the request counter clears, and the client can send requests again up to the configured limit. For example, set a limit of `6` requests per `10 s`. A client that sends more than 6 requests within any 10-second window receives `429` responses until that window expires. After the window resets, the function serves requests normally.

To fine-tune the rate limiting behavior for your use case, adjust the **Window Limit** and **Request Limit** values in the function's arguments. You can change them at any time in [Azion Console](https://console.azion.com/).

## Update the project

Every push to the GitHub repository that the Upstash Rate Limit template creates deploys automatically.

To update the deployed project, push your changes to that repository. Azion deploys them, and the application serves the new version.

## Manage the application

The settings that the Upstash Rate Limit template applies may not fit your application. You can change any of them at any time from Azion Console. After the deployment, you also keep full control of your Upstash account and your database.

To open the application's settings:

<DocSteps>
  <DocStep title="Open the applications list">

  Access [Azion Console](https://console.azion.com/) > **Applications**. The list shows every application you created, in alphabetical order.

  </DocStep>
  <DocStep title="Select the application that the template created">

  To find it in a long list, search by the name you gave it during the deployment. The search filters the list by **Application Name** only.

  </DocStep>
</DocSteps>

The application opens on a page that holds every setting you can configure. For more information, refer to [Main Settings](/en/documentation/platform/applications/main-settings/), [Rules Engine for Applications](/en/documentation/platform/applications/rules-engine/), and [Device Groups](/en/documentation/platform/applications/device-groups/). For questions about Upstash, refer to the [Upstash documentation](https://docs.upstash.com/).

## Add a custom domain

The Upstash Rate Limit deployment assigns the application a [workload](/en/documentation/platform/workloads/) domain in the format `xxxxxxxxxx.map.azionedge.net`, which a browser can open. To serve the application from a domain you own, add a custom domain. For more information, refer to [Add a custom domain to a workload](/en/documentation/guides/platform/migration/configure-a-domain/) and [Domains](/en/documentation/platform/workloads/domains/).
