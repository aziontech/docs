You can read the lines a [Function](/en/documentation/platform/functions/) wrote with `console.log` from Azion Console or with a GraphQL query. [Real-Time Events](/en/documentation/platform/real-time-events/) keeps them in the Functions Console data source. The GraphQL API serves the same records as the `functionConsoleEvents` dataset, named `cellsConsoleEvents` before.

One request leaves several lines behind it rather than one record. The `id` field is the request identifier, and it groups every line of a single request. A result that holds five rows for one request is the expected shape.

Azion Runtime writes lines of its own alongside the ones your code writes. The `lineSource` field separates the two. `CONSOLE` marks a line written with `console.log`. `RUNTIME` marks a line Azion Runtime produced, such as an exception.

## Read the lines a Function wrote

Both interfaces read the same records, and both bound the search by a period first. They name the Function identifier differently. The Console filter labels it _Function Id_, and the GraphQL API takes the camelCase field `functionId`.

The period a search can ask for and the rows one query returns are both bounded. For each bound, refer to [Limits](/en/documentation/platform/real-time-events/limits/).

<Fragment slot="panel.console">

### Console

To read the lines from Azion Console:

<DocSteps>
  <DocStep title="Open Real-Time Events">

  Access [Azion Console](https://console.azion.com/) > **Real-Time Events**.

  </DocStep>
  <DocStep title="Select the data source">

  Select the **Functions Console** tab.

  </DocStep>
  <DocStep title="Open the period">

  Select the period field, which shows _Last 5 minutes_.

  </DocStep>
  <DocStep title="Select the period">

  Select **Quick**, and then select a period that covers the run, such as _Last 1 hour_.

  </DocStep>
  <DocStep title="Run the search">

  Select **Update**.

  </DocStep>
  <DocStep title="Open the filter">

  Select the filter icon.

  </DocStep>
  <DocStep title="Select the field">

  In **Filter**, select _Function Id_.

  </DocStep>
  <DocStep title="Set the condition">

  In **Operator**, select _Equals_, and then enter the identifier of the Function in the value field.

  </DocStep>
  <DocStep title="Apply the filter">

  Select **Apply**.

  </DocStep>
</DocSteps>

**Apply** runs the search again at once. The table holds the lines that Function wrote, one row per line.

The query field shows the condition, such as `'function id' = 9483`. The filter also offers _Not Equals_, _Contains_, and _Not Contains_, and fields such as _Level_ and _Line Source_. Select a row to open **More Details**, which carries every field of that record, including `line`, the message itself. For every field the data source carries, refer to [Data sources](/en/documentation/platform/real-time-events/data-sources/).

</Fragment>

<Fragment slot="panel.api">

### API

The GraphQL API serves the same lines as the `functionConsoleEvents` dataset. Send the query to `https://api.azion.com/v4/events/graphql` with an `Authorization: Token [TOKEN VALUE]` header. The same address serves the GraphiQL Playground in a browser, where the query runs without a request of your own. For the terminal path, refer to [GraphQL API first steps](/en/documentation/devtools/graphql/first-steps/).

This query returns 10 lines from a time range, the oldest first:

```graphql
query ConsoleLog {
  functionConsoleEvents(
    limit: 10,
    filter: {
      tsRange: {begin: "<your-period-start>", end: "<your-period-end>"}
    }
    orderBy: [ts_ASC]
  )
  {
    ts
    solutionId
    configurationId
    functionId
    id
    lineSource
    level
    line
  }
}
```

Replace `<your-period-start>` and `<your-period-end>` with the bounds of the run, in the form `YYYY-MM-DDTHH:MM:SS`.

The response carries the matching lines as JSON:

```json
{
    "data": {
        "functionConsoleEvents": [
            {
                "ts": "2026-09-21T12:09:54Z",
                "solutionId": "1234567890",
                "configurationId": "1234567891",
                "functionId": "9483",
                "id": "fa498cd9-cbep-4382-8bbb-32b029fe7411",
                "lineSource": "RUNTIME",
                "level": "ERROR",
                "line": "TypeError: Object not found"
            },
            {
                "ts": "2026-09-21T12:09:54Z",
                "solutionId": "1234567890",
                "configurationId": "1234567891",
                "functionId": "9483",
                "id": "fa498cd9-cbep-4382-8bbb-32b029fe7411",
                "lineSource": "RUNTIME",
                "level": "ERROR",
                "line": "TypeError: Object not found"
            },
            {
                "ts": "2026-09-21T12:09:54Z",
                "solutionId": "1234567890",
                "configurationId": "1234567891",
                "functionId": "9483",
                "id": "fa498cd9-cbep-4382-8bbb-32b029fe7411",
                "lineSource": "RUNTIME",
                "level": "ERROR",
                "line": "    at async mainFetch (ext:cells_fetch/26_fetch.js:266:12)"
            }
        ]
    }
}
```

The three rows carry one `id`, because one request produced all of them. Each reads `RUNTIME` in `lineSource` and `ERROR` in `level`, so Azion Runtime wrote them. A line written with `console.log` reads `CONSOLE` and `LOG` in the same two fields.

`functionId` identifies the Function, and `configurationId` identifies the workload the request arrived on. To return only the lines whose message matches a pattern, add `lineLike` to the filter. The `%` character stands for any sequence of characters, so `lineLike: "%TypeError%"` matches every line that contains `TypeError`. For every field the dataset carries, refer to [Real-Time Events GraphQL API fields](/en/documentation/devtools/graphql/gql-real-time-events-fields/#function-console-events).
