You can deploy the **AI Inference Starter Kit** template and manage what it creates from Azion Console. The template creates a Workload with its deployment, an Application, and a Function with its Function Instance, and the Function serves an OpenAI-compatible endpoint on the workload domain of the Workload.

The [AI Inference quickstart](/en/documentation/platform/ai-inference/quickstart/) covers the same deployment and adds a first request to the model.

## Prerequisites

The template uses [Application Accelerator](/en/documentation/platform/applications/application-accelerator/), [Functions](/en/documentation/platform/functions/), and [AI Inference](/en/documentation/platform/ai-inference/), which can generate usage-related costs. For the rates, refer to [Pricing](/en/documentation/fundamentals/pricing/).

## Deploy the template

To create these entities from one template:

<DocSteps>
  <DocStep title="Access Azion Console">

  Access [Azion Console](https://console.azion.com/) and select **+ Create**.

  </DocStep>
  <DocStep title="Select the AI Inference Starter Kit template">

  Under **Start from Template**, select **AI Inference Starter Kit**.

  </DocStep>
  <DocStep title="Enter a name for the application">

  In **Application Name**, enter a name made of letters, numbers, and underscores, such as the default `ai_inference_starter_kit`. A hyphen is refused with "The use of accents and/or special characters is not allowed."

  </DocStep>
  <DocStep title="Select Deploy">

  Select **Deploy**.

  </DocStep>
</DocSteps>

A window shows the deployment logs while the deployment runs. When it finishes, the page shows the domain under **Visit site**, the **Add custom domain** option, the **Deployment logs**, and **Resources created**, which lists the Workload and the Application.

:::note
The deployment takes several minutes to propagate to Azion's data centers. Until it propagates, the domain answers with Azion's placeholder `404`. Wait a few minutes, then select **Visit site** again.
:::

The Application answers on the workload domain of the Workload, in the form `xxxxxxxxxx.map.azionedge.net`, and the Function serves an OpenAI-compatible endpoint on any path of that domain. For the path a request takes from the domain to the model, refer to the architecture of [Add AI features to existing applications](/en/documentation/use-cases/build-and-run-ai-workloads/add-ai-features-to-existing-applications/).

## Update the function

The function the template installs holds the call to the model, and its page carries three tabs:

- **Main Settings** renames the function and changes its basic settings.
- **Code** holds the function code.
- **Arguments** defines the arguments the function uses.

To change the function:

<DocSteps>
  <DocStep title="Access Functions">

  Access [Azion Console](https://console.azion.com/) > **Edge Libraries** > **Functions**.

  </DocStep>
  <DocStep title="Select the function">

  Select the Function that carries the name you entered during the deployment, followed by a "(Build at …)" suffix. The list is alphabetical, and the **search bar** filters it by **Function Name** only.

  </DocStep>
  <DocStep title="Open the tab that holds the setting">

  Open the tab that holds the setting you want to change.

  </DocStep>
  <DocStep title="Select Save">

  Select **Save**.

  </DocStep>
</DocSteps>

The function has the changes you saved. For every setting a function holds, refer to [Functions](/en/documentation/platform/functions/).

The **Code** tab holds the code the template installs. On each request, the Function:

- Accepts only a `POST` request whose `Content-Type` header is exactly `application/json`. Any other request receives `400` with `{"error":"Request must be a POST request with JSON body"}`.
- Reads the model id from the `model` field of the request body. A body without it receives `400` with `{"error":"Missing 'model' field in request body"}`.
- Passes the whole body to `Azion.AI.run` and returns the model response. With `stream` set to `true`, it streams the response as server-sent events, one `data:` line per chunk, ending with `data: [DONE]`.

The code holds no model id. To call another model, change the `model` field of the request to its id, listed in [AI models](/en/documentation/platform/ai-inference/models/). For every field the body accepts, refer to [Model invocation](/en/documentation/platform/ai-inference/model-invocation/).

The model response keeps the chat completion shape, and the generated text sits at `choices[0].message.content`. Its `model` field carries the account's internal id for the model, which can differ from the id the request sent: `Qwen/Qwen3-30B-A3B-Instruct-2507-FP8` returns `qwen-qwen3-30b-a3b-instruct-2507-fp8`. To send a first request and read a full response, refer to the [AI Inference quickstart](/en/documentation/platform/ai-inference/quickstart/).

Before you change the code, read [AI Inference best practices](/en/documentation/platform/ai-inference/best-practices/) for the request patterns Azion recommends, and [AI Inference limits](/en/documentation/platform/ai-inference/limits/) for the conditions under which Azion terminates a model.

## Manage the application

The application page holds every setting the deployment created, and you can change any of them. To open it:

<DocSteps>
  <DocStep title="Access Applications">

  Access [Azion Console](https://console.azion.com/) > **Build** > **Applications**.

  </DocStep>
  <DocStep title="Select the application">

  Select the application that carries the name you entered during the deployment. The list is alphabetical, and the **search bar** filters it by **Application Name** only.

  </DocStep>
</DocSteps>

The application page opens on the settings you can adjust. For what each setting does, refer to [Applications quickstart](/en/documentation/platform/applications/quickstart/).
