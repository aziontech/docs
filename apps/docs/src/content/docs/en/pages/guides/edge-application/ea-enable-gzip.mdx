You can compress the responses of an [application](/en/documentation/platform/applications/) with gzip from Azion Console, with a rule in [Rules Engine for Applications](/en/documentation/platform/applications/rules-engine/).

Gzip is the standard method of lossless file compression for web applications. It uses the Deflate algorithm to reduce the size of a file before the file reaches the browser. Pages then render and download faster. For more about the format, refer to the [gzip website](https://www.gzip.org/).

When a rule with the gzip behavior matches a request, Azion looks in its cache for a compressed version of the file. If the cache holds one, Azion delivers it to the browser. Otherwise, Azion compresses the file, delivers it, and adds the compressed version to the cache. The browser then decompresses the file.

Applications also offers Brotli compression, which typically achieves better compression ratios than gzip and delivers smaller files. To turn on Brotli for an application, contact Azion Support. For more information, refer to [Support](/en/documentation/support/).

## Prerequisites

- An application that a [workload](/en/documentation/platform/workloads/) delivers, with a rule that sends its requests to an origin. To create both, refer to [Applications quickstart](/en/documentation/platform/applications/quickstart/).
- Access to Azion Console. To sign in, refer to [Access Azion Console](/en/documentation/guides/platform/account-and-billing/how-to-access-azion-console/).

## Turn on gzip compression

The rule in this section compresses content with gzip when the browser of the user supports it. Its behavior requires no Product on the application, and it runs in either phase. The rule matches every request of the application, because every path starts with `/`.

To create the rule in Azion Console:

<DocSteps>
  <DocStep title="Open the application">

  Access [Azion Console](https://console.azion.com/) > **Applications** > **your application**.

  </DocStep>
  <DocStep title="Select the Rules Engine tab" />
  <DocStep title="Select + Rule" />
  <DocStep title="Name the rule">

  In the **General** section, enter a **Name** for the rule, such as `gzip-compression`.

  </DocStep>
  <DocStep title="(Optional) Describe the rule">

  In **Description**, enter a short note about what the rule does.

  </DocStep>
  <DocStep title="Select the phase">

  In the **Phase** section, select **Request Phase** or **Response Phase**. The phase of a rule cannot change after you create the rule.

  </DocStep>
  <DocStep title="Set the criterion">

  In the **Criteria** section, select `${uri}` as the variable and `starts_with` as the operator.

  </DocStep>
  <DocStep title="Enter the path">

  Enter `/` as the argument. To compress only part of the application, set other criteria instead.

  </DocStep>
  <DocStep title="Add the gzip behavior">

  In the **Behaviors** section, select the behavior that turns on gzip compression. The API names it `enable_gzip`.

  </DocStep>
  <DocStep title="Select Save" />
</DocSteps>

The rule appears in the **Rules Engine** tab, under the phase you selected. When the browser supports gzip, the responses to the requests the rule matches arrive compressed. For the variables and operators other criteria can use, refer to [Criteria](/en/documentation/platform/applications/rules-engine/#criteria). For the behavior, refer to [Enable Gzip](/en/documentation/platform/applications/rules-engine/#enable-gzip).

## Confirm that responses are compressed

A response that Azion compressed with gzip carries the `Content-Encoding` header with the value `gzip`. Azion compresses the files whose MIME type is one of the supported MIME types on this page.

To confirm the compression in a browser:

1. Access a page of your application.
2. Inspect the page with the developer tools of your browser.
3. Select the request for a file of a supported MIME type, such as a CSS or JavaScript file.

The response headers of that request carry `Content-Encoding: gzip`.

## Supported MIME types

Azion applies gzip compression to the file types that this table lists. Azion identifies each file by its Multipurpose Internet Mail Extensions (MIME) type. A web server sends the MIME type of a file to the browser in the `Content-Type` header. The browser reads it to know what the document, file, or byte array is, and how to process it.

A MIME type is a type and a subtype joined by a slash. The type names the category of the data, such as `text` or `image`. The subtype names the exact format, such as `jpeg` or `png`. For example, when your browser finds an `<img>` HTML tag for a PNG image, it requests the image. The server answers with `Content-Type: image/png`.

A compressed file keeps the MIME type of the original file in its `Content-Type` header, because the browser decompresses the file once the request ends. The [Internet Assigned Numbers Authority (IANA)](https://www.iana.org/assignments/media-types/media-types.xhtml) is responsible for all official MIME types.
