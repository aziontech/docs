You can deploy a static Next.js application to Azion from the Next.js Static Boilerplate template in Azion Console. To create an application without a template, refer to [Applications quickstart](/en/documentation/platform/applications/quickstart/).

The Next.js Static Boilerplate creates a Next.js single-page application (SPA) on Azion's distributed infrastructure. It automates several steps, from repository management to deployment. The template uses Next.js `14.1.4`.

The deployment creates a GitHub repository for your project, an [application](/en/documentation/platform/applications/) that serves it, a domain to reach it, and a function for custom logic. The application uses [Functions](/en/documentation/platform/functions/), and its usage can generate costs. For more information, refer to [Pricing](/en/documentation/fundamentals/pricing/).

---

## Prerequisites

- An Azion account. To create one, refer to [Create an account](/en/documentation/fundamentals/creating-account/).
- Access to Azion Console. To sign in, refer to [Access Azion Console](/en/documentation/guides/platform/account-and-billing/how-to-access-azion-console/).
- A [GitHub account](https://github.com/signup). Azion connects to it and creates the project's repository there.

## Deploy the template

The Next.js Static Boilerplate opens as a configuration form in Azion Console, and an asterisk marks each mandatory field.

To deploy the template:

<DocSteps>
  <DocStep title="Open the template">

  Go to [Next.js Static Boilerplate](https://console.azion.com/create/nextjs/next-static-boilerplate) in Azion Console. The configuration form opens.

  </DocStep>
  <DocStep title="Connect Azion with your GitHub account">

  A window opens to confirm the installation of the [Azion GitHub App](/en/documentation/guides/application-development/automation/azion-github-app/), which connects your GitHub account with Azion. In that window, define the app's permissions and repository access.

  </DocStep>
  <DocStep title="Select the Git Scope">

  Select the **Git Scope** to work with.

  </DocStep>
  <DocStep title="Name the application">

  Enter a unique name that you can remember. The storage bucket and the function that the template creates take the same name. If the name is already in use, the platform returns an error message.

  </DocStep>
  <DocStep title="Start the deployment">

  Select **Deploy**.

  </DocStep>
</DocSteps>

A window shows the deployment logs while it runs. When the deployment completes, the page shows the application's details, a browser link to it, and options to continue.

The deployment leaves you with:

- A GitHub repository created from the [Next.js Static Boilerplate sample](https://github.com/aziontech/azion-samples/tree/dev/templates/nextjs/nextjs-static-boilerplate-14), with its dependencies installed.
- A GitHub Action in that repository that deploys every push, for continuous deployment.
- A commit in the repository that records the deployed version and the deployment timestamp, so the deployment history stays trackable.
- An application on Azion Web Platform, with a domain that hosts the Next.js project and a function for custom logic.

The template builds the project with Azion Web Platform resources.

The link can take a few minutes to start serving the application, while its configuration propagates across Azion's distributed infrastructure. If the page does not load, wait a few minutes and open the link again.

## Update the project

Every push to the GitHub repository that the Next.js Static Boilerplate creates deploys automatically.

To update the deployed project, push your changes to that repository. Azion deploys them, and the application serves the new version.

## Static export support

The core of Next.js supports static exports. You can start a project as a static site or an SPA, and later add features that require a server. With a static export, Next.js generates one HTML file per route, which breaks a strict SPA into individual HTML files. Any web server that serves HTML, CSS, and JavaScript static assets can host the project.

A static export supports some Next.js features and not others. Take both lists into account when you develop and manage the project. For more information, refer to [Static exports](https://nextjs.org/docs/app/building-your-application/deploying/static-exports) in the Next.js documentation.

### Supported features

- Server components
- Client components
- Image optimization through `next/image`, when you define a custom image loader in `next.config.js`
- Route handlers
- Browser APIs

### Unsupported features

These features require a Node.js server, or dynamic logic that the build process cannot compute, so a static export does not support them:

- Dynamic routes with `dynamicParams: true`
- Dynamic routes without `generateStaticParams()`
- Route handlers that rely on the request
- Cookies
- Rewrites
- Redirects
- Headers
- Middleware
- Incremental static regeneration
- Image optimization with the default loader
- Draft mode

## Manage the application

The settings that the Next.js Static Boilerplate applies may not fit your application. You can change any of them at any time from Azion Console.

To open the application's settings:

<DocSteps>
  <DocStep title="Open the applications list">

  Access [Azion Console](https://console.azion.com/) > **Applications**. The list shows every application you created, in alphabetical order.

  </DocStep>
  <DocStep title="Select the application that the template created">

  To find it in a long list, search by its name. The search filters the list by application name only.

  </DocStep>
</DocSteps>

The application opens on a page that holds every setting you can configure. For more information, refer to [Main Settings](/en/documentation/platform/applications/main-settings/), [Rules Engine for Applications](/en/documentation/platform/applications/rules-engine/), and [Device Groups](/en/documentation/platform/applications/device-groups/).

## Add a custom domain

The Next.js Static Boilerplate deployment assigns the application a [workload](/en/documentation/platform/workloads/) domain in the format `xxxxxxxxxx.map.azionedge.net`, which a browser can open. To serve the application from a domain you own, add a custom domain. To list the domain on the workload and point its DNS record at the workload, refer to [Add a custom domain to a workload](/en/documentation/guides/platform/migration/configure-a-domain/). For more information, refer to [Domains](/en/documentation/platform/workloads/domains/).
