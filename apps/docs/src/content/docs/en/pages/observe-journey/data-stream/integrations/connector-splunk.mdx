You can send the logs of a stream to [Splunk](https://www.splunk.com/) from Azion Console or with the Azion API. To choose the variables each log line carries to Splunk, refer to [Templates and payload](/en/documentation/platform/data-stream/templates-and-payload/).

[Data Stream](/en/documentation/platform/data-stream/) sends each batch of log lines to the HTTP Event Collector (HEC) of your Splunk instance and authenticates with a HEC token. In Azion Console, the stream form labels the endpoint field **Connector**, and Splunk is its *Splunk* option. For every field and its bounds, refer to [Endpoints](/en/documentation/platform/data-stream/endpoints/#splunk).

The example collects the requests of one Workload with the *Applications* data source.

### Console

- An Azion account with the **Edit Data Stream** permission. For the permissions, refer to [Stream settings](/en/documentation/platform/data-stream/stream-settings/#permissions).
- A [Workload](/en/documentation/platform/workloads/) on the account that receives requests.
- A Splunk account.
- An HTTP Event Collector set up for the type of your Splunk instance, and its URL. The URL format depends on the instance type: self-hosted or Splunk Cloud. For the formats, refer to [Endpoints](/en/documentation/platform/data-stream/endpoints/#splunk).
- A HEC token. The token must be enabled in Splunk.
- Access to Azion Console. To sign in, refer to [Access Azion Console](/en/documentation/guides/platform/account-and-billing/how-to-access-azion-console/).

</Fragment>

- A [Workload](/en/documentation/platform/workloads/) on the account that receives requests.
- A Splunk account.
- An HTTP Event Collector set up for the type of your Splunk instance, and its URL. The URL format depends on the instance type: self-hosted or Splunk Cloud. For the formats, refer to [Endpoints](/en/documentation/platform/data-stream/endpoints/#splunk).
- A HEC token. The token must be enabled in Splunk.
- A personal token. To create one, refer to [Manage personal tokens](/en/documentation/guides/platform/account-and-billing/personal-tokens/).
- The ID of the Workload.
- `curl`.

## Create the stream

The stream collects from the Workload you choose, through a workload filter. A workload filter leaves your other streams active.

:::caution
Saving an active stream with sampling on Applications, Functions, or WAF Events deactivates every other stream on the account, except Activity History streams.
:::

<Tabs client:visible sharedStore="interface">

<Fragment slot="panel.console">

### Console

To create the stream in Azion Console:

<DocSteps>
  <DocStep title="Open Data Stream">

  Access [Azion Console](https://console.azion.com/) > **Data Stream**.

  </DocStep>
  <DocStep title="Select + Stream" />
  <DocStep title="Name the stream">

  In the **General** section, enter a **Name**. For example: `logs-to-splunk`.

  </DocStep>
  <DocStep title="Select the data source">

  In the **Input** section, select *Applications* in **Data Source**.

  </DocStep>
  <DocStep title="Turn off Sampling">

  In the **Transform** section, turn off **Sampling** while **Option** is still *All Current and Future Workloads*, its starting value. A stream cannot carry sampling and a workload filter together.

  </DocStep>
  <DocStep title="Set the workload filter">

  In the **Transform** section, set **Option** to *Filter Workloads*. If your Console names domains where this guide names Workloads, the option reads *Filter Domains*.

  </DocStep>
  <DocStep title="Choose the Workload">

  In **Available Workload**, select your Workload and move it to **Chosen Workload** with the arrow. If your Console names domains, the lists read **Available Domain** and **Chosen Domain**.

  </DocStep>
  <DocStep title="Select the template">

  In the **Render Template** section, select *Applications Event Collector* in **Template**.

  </DocStep>
  <DocStep title="Select the Splunk endpoint">

  In the **Output** section, select *Splunk* in **Connector**.

  </DocStep>
  <DocStep title="Enter the HEC URL">

  In **URL**, enter the HEC URL of your Splunk instance. For example: `https://splunk.example.com:8088/services/collector`. To send to another index, add the index at the end of the URL, such as `?index=myindex`.

  </DocStep>
  <DocStep title="Enter the HEC token">

  In **API Key**, enter the HEC token of your Splunk instance.

  </DocStep>
  <DocStep title="Keep the stream active">

  In the **Status** section, keep **Active** turned on.

  </DocStep>
  <DocStep title="Select Save" />
</DocSteps>

The Console shows `Your data stream has been created`. The stream appears in the **Data Stream** list with `Splunk` in the **Connector** column and the **Active** status.

</Fragment>

<Fragment slot="panel.api">

### API

To create the stream with the API, send a `POST` request to `https://api.azion.com/v4/workspace/stream/streams`. Replace `[TOKEN VALUE]` with your personal token, `<workload-id>` with the ID of your Workload, and the Splunk values with your own:

```bash
curl -X POST 'https://api.azion.com/v4/workspace/stream/streams' \
  -H 'Content-Type: application/json' \
  -H 'Authorization: Token [TOKEN VALUE]' \
  -d '{
    "name": "logs-to-splunk",
    "active": true,
    "inputs": [
      { "type": "raw_logs", "attributes": { "data_source": "workloads" } }
    ],
    "transform": [
      { "type": "filter_workloads", "attributes": { "workloads": [<workload-id>] } },
      { "type": "render_template", "attributes": { "template": 2 } }
    ],
    "outputs": [
      {
        "type": "splunk",
        "attributes": {
          "url": "https://splunk.example.com:8088/services/collector",
          "api_key": "[API KEY]"
        }
      }
    ]
  }'
```

The `workloads` data source is *Applications* in the Console, and template `2` is *Applications Event Collector*. The `api_key` attribute takes the HEC token. The API answers `201` with the stored stream:

```json
{
  "state": "executed",
  "data": {
    "id": 12352,
    "name": "logs-to-splunk",
    "last_editor": "user@example.com",
    "created": "2026-01-01T12:10:33.000000Z",
    "last_modified": "2026-01-01T12:10:33.000000Z",
    "product_version": "1.0",
    …
    "outputs": [
      {
        "type": "splunk",
        "attributes": {
          "url": "https://splunk.example.com:8088/services/collector",
          "api_key": "[API KEY]"
        }
      }
    ]
  }
}
```

Keep the `id`: it identifies the stream in every later request, such as `/v4/workspace/stream/streams/12352`. For every key of the body, refer to [Stream settings](/en/documentation/platform/data-stream/stream-settings/#stream-object).

</Fragment>

</Tabs>

The API and the Console save the stream without contacting Splunk. A wrong URL or HEC token surfaces only when the stream sends.

After you create or activate a stream, it can take several minutes to start collecting events. It does not send the events from before that.

## Confirm the delivery

[Real-Time Events](/en/documentation/platform/real-time-events/data-sources/#data-stream) records every send of a stream, delivered or not, with a status code.

To make the stream send a batch:

1. Wait a few minutes after you save the stream.
2. Send a few requests to the Workload.
3. Wait about a minute. A stream sends a batch every 60 seconds, or sooner when it reaches 2,000 log lines.

<Tabs client:visible sharedStore="interface">

<Fragment slot="panel.console">

### Console

To find the sends in Azion Console:

<DocSteps>
  <DocStep title="Open Real-Time Events">

  Access [Azion Console](https://console.azion.com/) > **Real-Time Events**.

  </DocStep>
  <DocStep title="Select the Data Stream data source" />
  <DocStep title="Read the latest sends">

  Each row is one send. Find the rows with `SPLUNK` in **Endpoint Type**, and read their **Status Code**.

  </DocStep>
</DocSteps>

A **Status Code** of `200` means Splunk accepted the batch. **Streamed Lines** gives the number of log lines in the batch.

</Fragment>

<Fragment slot="panel.api">

### API

To read the sends with the API, query the `dataStreamedEvents` dataset of the Real-Time Events GraphQL API. Replace the dates with a range that covers the activation of the stream:

```bash
curl -X POST 'https://api.azion.com/v4/events/graphql' \
  -H 'Content-Type: application/json' \
  -H 'Authorization: Token [TOKEN VALUE]' \
  -d '{"query":"query { dataStreamedEvents(limit: 20, filter: {tsRange: {begin: \"2026-01-01T12:00:00\", end: \"2026-01-01T12:45:00\"}}, orderBy: [ts_DESC]) { ts endpointType statusCode streamedLines dataStreamed } }"}'
```

The API answers `200` with one record for each send, the latest first:

```json
{
  "data": {
    "dataStreamedEvents": [
      {
        "ts": "2026-01-01T12:16:04Z",
        "endpointType": "SPLUNK",
        "statusCode": 200,
        "streamedLines": 2,
        "dataStreamed": 2797
      }
    ]
  }
}
```

A send to Splunk carries `SPLUNK` in `endpointType`. A `statusCode` of `200` means Splunk accepted the batch, and `streamedLines` and `dataStreamed` give its size in log lines and bytes. An empty `dataStreamedEvents` list means the stream has not sent in the range. For every field, refer to [Real-Time Events fields](/en/documentation/devtools/graphql/gql-real-time-events-fields/#data-streamed-events).

</Fragment>

</Tabs>

If Real-Time Events shows no send for the stream after a minute, send another request to the Workload and check again.

A send that Splunk accepted shows `200`. A failed send can show a code the endpoint never returned, and `503` means Data Stream found the endpoint unavailable. To find the cause, refer to [Troubleshoot Data Stream](/en/documentation/platform/data-stream/troubleshooting/).
