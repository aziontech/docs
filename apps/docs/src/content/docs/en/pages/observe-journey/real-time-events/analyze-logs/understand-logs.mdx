You can read one event record of [Real-Time Events](/en/documentation/platform/real-time-events/) from Azion Console. What the record answers depends on the variables you read. Each data source carries its own set of preorganized variables. They report on the access, the behavior, and the performance of your applications and the related products.

For every variable a data source carries, with its description and an example, refer to [Data sources](/en/documentation/platform/real-time-events/data-sources/).

Two searches lead to that record. Run a [general search](#run-a-general-search) to return every record a data source wrote in the period. Run a [filtered search](#run-a-filtered-search) instead to return only the records that match the values you name.

---

## Prerequisites

- An Azion account. To create one, refer to [How to create an account on Azion](/en/documentation/fundamentals/creating-account/).
- Access to Azion Console. To sign in, refer to [How to access Azion Console](/en/documentation/guides/platform/account-and-billing/how-to-access-azion-console/).
- A product that already wrote records to the data source you want to search.

---

## Run a general search

A general search returns every record a data source wrote in the period, with every variable it carries. Run one when you want as much information as possible, or when you do not yet know what to investigate. It runs with the query field empty.

To run a general search in Azion Console:

<DocSteps>
  <DocStep title="Open Real-Time Events">

  Access [Azion Console](https://console.azion.com/) > **Real-Time Events**.

  </DocStep>
  <DocStep title="Select the data source">

  Select the tab of the data source, such as **Functions**.

  </DocStep>
  <DocStep title="Open the period">

  Select the period field, which shows _Last 5 minutes_.

  </DocStep>
  <DocStep title="Select the period">

  Select **Quick**, then select _Last 1 hour_.

  </DocStep>
  <DocStep title="Run the search">

  Select **Update**.

  </DocStep>
</DocSteps>

The results table holds every record that data source wrote in the period. Each row shows **Time** and **Log Body**. The table shows a count, such as "3 records found". A period with no record shows "No logs have been found for this period."

Consider an Application that does not show what you configured on a [Function](/en/documentation/platform/functions/). Select the **Functions** tab to see whether the right Function ran, and how long it took. Then select the **Functions Console** tab to read the lines the Function wrote to the console.

## Run a filtered search

A filtered search returns only the records whose field holds the value you name. Run one when you already know what you are going to analyze.

To run a filtered search in Azion Console:

<DocSteps>
  <DocStep title="Open Real-Time Events">

  Access [Azion Console](https://console.azion.com/) > **Real-Time Events**.

  </DocStep>
  <DocStep title="Select the data source">

  Select the **HTTP Requests** tab.

  </DocStep>
  <DocStep title="Open the filter">

  Select the filter icon.

  </DocStep>
  <DocStep title="Select the field">

  In the **Filter** dialog, select _Status_.

  </DocStep>
  <DocStep title="Select the operator">

  In **Operator**, select _Equals_.

  </DocStep>
  <DocStep title="Enter the value">

  In the value field, enter `400`.

  </DocStep>
  <DocStep title="Apply the filter">

  Select **Apply**.

  </DocStep>
</DocSteps>

The search runs at once, over the period the period field shows. The query field shows `status = 400`, and the results table holds only the matching records.

Consider a suspicion that malicious users are trying to reach your application. On the **HTTP Requests** tab, filter on a field that identifies the client. _Host_, _Remote Address_, and _Request Uri_ each narrow the result to a different property of the request.

For the query field, the period, and more example filters, refer to [Filter events](/en/documentation/guides/platform/observability/add-filters-events/).

## Search by request ID

A request ID reaches the record of one request and no others. The `requestId` field stores a unique identifier for each request, such as `5f222ae5938482c32a822dbf15e19f0f`.

A value you take from an HTTP response header, such as `X-Request-Id`, can carry a numeric suffix after a hyphen. For example: `5f222ae5938482c32a822dbf15e19f0f-1234`. The network layer appends that suffix, and the event record does not store it.

Search Real-Time Events, or the [GraphQL API](/en/documentation/devtools/graphql/overview/), with the base identifier alone. A search that includes the suffix can return no results, or a `400` error.

Where the header returns `5f222ae5938482c32a822dbf15e19f0f-1234`, search for `5f222ae5938482c32a822dbf15e19f0f`.

## Open one record

A row of the results table shows the record in two columns, **Time** and **Log Body**. **Log Body** lists its fields by their API names, such as `remoteAddress`, `requestUri`, and `status`. Opening the record lays out every field in its own row.

To open one record in Azion Console, select its row in the results table.

The **More Details** view opens, titled with the host of the record. Its **Field** and **Value** columns list every field of the record by API name, such as `host` and `upstreamStatus`. A **Table** and **Cards** toggle sets the layout of the view.

For what each of those fields means, refer to [Data sources](/en/documentation/platform/real-time-events/data-sources/).
