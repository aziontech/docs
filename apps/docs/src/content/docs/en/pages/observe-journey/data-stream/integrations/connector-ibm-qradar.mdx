You can send the logs of a stream to [IBM QRadar](https://www.ibm.com/qradar) from Azion Console or with the Azion API. To send the events of a Web Application Firewall to a SIEM instead of the requests of your Applications, refer to [Stream WAF events to a SIEM](/en/documentation/guides/application-security/firewall-and-waf/integrate-siems/).

[Data Stream](/en/documentation/platform/data-stream/) sends each batch of log lines to a URL of your QRadar instance. The URL is the only setting of this endpoint, with no key or token to enter. In Azion Console, the stream form labels the endpoint field **Connector**, and QRadar is its *IBM QRadar* option. For the field and its bounds, refer to [Endpoints](/en/documentation/platform/data-stream/endpoints/#ibm-qradar).

The example collects the requests of one Workload with the *Applications* data source.

## Create the stream

The stream collects from the Workload you choose, through a workload filter. A workload filter leaves your other streams active.

:::caution
Saving an active stream with sampling on Applications, Functions, or WAF Events deactivates every other stream on the account, except Activity History streams.
:::

<Tabs client:visible sharedStore="interface">

<Fragment slot="panel.console">

### Console

To create the stream in Azion Console:

<DocSteps>
  <DocStep title="Open Data Stream">

  Access [Azion Console](https://console.azion.com/) > **Data Stream**.

  </DocStep>
  <DocStep title="Select + Stream" />
  <DocStep title="Name the stream">

  In the **General** section, enter a **Name**. For example: `logs-to-qradar`.

  </DocStep>
  <DocStep title="Select the data source">

  In the **Input** section, select *Applications* in **Data Source**.

  </DocStep>
  <DocStep title="Turn off Sampling">

  In the **Transform** section, turn off **Sampling** while **Option** is still *All Current and Future Workloads*, its starting value. A stream cannot carry sampling and a workload filter together.

  </DocStep>
  <DocStep title="Set the workload filter">

  In the **Transform** section, set **Option** to *Filter Workloads*. If your Console names domains where this guide names Workloads, the option reads *Filter Domains*.

  </DocStep>
  <DocStep title="Choose the Workload">

  In **Available Workload**, select your Workload and move it to **Chosen Workload** with the arrow. If your Console names domains, the lists read **Available Domain** and **Chosen Domain**.

  </DocStep>
  <DocStep title="Select the template">

  In the **Render Template** section, select *Applications Event Collector* in **Template**.

  </DocStep>
  <DocStep title="Select the QRadar endpoint">

  In the **Output** section, select *IBM QRadar* in **Connector**.

  </DocStep>
  <DocStep title="Enter the QRadar URL">

  In **URL**, enter the URL of your QRadar instance. For example: `https://qradar.example.com:14440`.

  </DocStep>
  <DocStep title="Keep the stream active">

  In the **Status** section, keep **Active** turned on.

  </DocStep>
  <DocStep title="Select Save" />
</DocSteps>

The Console shows `Your data stream has been created`. The stream appears in the **Data Stream** list with `QRadar` in the **Connector** column and the **Active** status.

</Fragment>

<Fragment slot="panel.api">

### API

To create the stream with the API, send a `POST` request to `https://api.azion.com/v4/workspace/stream/streams`. Replace `[TOKEN VALUE]` with your personal token, `<workload-id>` with the ID of your Workload, and the `url` value with the URL of your QRadar instance:

```bash
curl -X POST 'https://api.azion.com/v4/workspace/stream/streams' \
  -H 'Content-Type: application/json' \
  -H 'Authorization: Token [TOKEN VALUE]' \
  -d '{
    "name": "logs-to-qradar",
    "active": true,
    "inputs": [
      { "type": "raw_logs", "attributes": { "data_source": "workloads" } }
    ],
    "transform": [
      { "type": "filter_workloads", "attributes": { "workloads": [<workload-id>] } },
      { "type": "render_template", "attributes": { "template": 2 } }
    ],
    "outputs": [
      {
        "type": "qradar",
        "attributes": {
          "url": "https://qradar.example.com:14440"
        }
      }
    ]
  }'
```

The `workloads` data source is *Applications* in the Console, and template `2` is *Applications Event Collector*. The `qradar` endpoint takes `url` as its only attribute. The API answers `201` with the stored stream:

```json
{
  "state": "executed",
  "data": {
    "id": 12355,
    "name": "logs-to-qradar",
    "last_editor": "user@example.com",
    "created": "2026-01-01T12:10:40.000000Z",
    "last_modified": "2026-01-01T12:10:40.000000Z",
    "product_version": "1.0",
    …
    "outputs": [
      {
        "type": "qradar",
        "attributes": {
          "url": "https://qradar.example.com:14440"
        }
      }
    ]
  }
}
```

Keep the `id`: it identifies the stream in every later request, such as `/v4/workspace/stream/streams/12355`. For every key of the body, refer to [Stream settings](/en/documentation/platform/data-stream/stream-settings/#stream-object).

</Fragment>

</Tabs>

The API and the Console save the stream without contacting the QRadar URL. A wrong URL surfaces only when the stream sends.

After you create or activate a stream, it can take several minutes to start collecting events. It does not send the events from before that.

## Confirm the delivery

[Real-Time Events](/en/documentation/platform/real-time-events/data-sources/#data-stream) keeps a record of each send of a stream, delivered or not, with a status code.

To make the stream send a batch:

1. Wait a few minutes after you save the stream.
2. Send a few requests to the Workload.
3. Wait about a minute. A stream sends a batch every 60 seconds, or sooner when it reaches 2,000 log lines.

<Tabs client:visible sharedStore="interface">

<Fragment slot="panel.console">

### Console

To find the sends in Azion Console:

<DocSteps>
  <DocStep title="Open Real-Time Events">

  Access [Azion Console](https://console.azion.com/) > **Real-Time Events**.

  </DocStep>
  <DocStep title="Select the Data Stream data source" />
  <DocStep title="Read the latest sends">

  Each row is one send. Find the rows with `QRADAR` in **Endpoint Type**, and read their **Status Code**.

  </DocStep>
</DocSteps>

A **Status Code** of `200` means QRadar accepted the batch. **Streamed Lines** gives the number of log lines in the batch.

</Fragment>

<Fragment slot="panel.api">

### API

To read the sends with the API, query the `dataStreamedEvents` dataset of the Real-Time Events GraphQL API. Replace the dates with a range that covers the activation of the stream:

```bash
curl -X POST 'https://api.azion.com/v4/events/graphql' \
  -H 'Content-Type: application/json' \
  -H 'Authorization: Token [TOKEN VALUE]' \
  -d '{"query":"query { dataStreamedEvents(limit: 20, filter: {tsRange: {begin: \"2026-01-01T12:00:00\", end: \"2026-01-01T12:45:00\"}}, orderBy: [ts_DESC]) { ts endpointType statusCode streamedLines dataStreamed } }"}'
```

The API answers `200` with one record for each send, the latest first:

```json
{
  "data": {
    "dataStreamedEvents": [
      {
        "ts": "2026-01-01T12:16:04Z",
        "endpointType": "QRADAR",
        "statusCode": 200,
        "streamedLines": 2,
        "dataStreamed": 2797
      }
    ]
  }
}
```

A send to QRadar carries `QRADAR` in `endpointType`. A `statusCode` of `200` means QRadar accepted the batch, and `streamedLines` and `dataStreamed` give its size in log lines and bytes. An empty `dataStreamedEvents` list means the stream has not sent in the range. For every field, refer to [Real-Time Events fields](/en/documentation/devtools/graphql/gql-real-time-events-fields/#data-streamed-events).

</Fragment>

</Tabs>

If Real-Time Events shows no send for the stream after a minute, send another request to the Workload and check again.

A send that QRadar accepted shows `200`. A failed send can show a code the endpoint never returned, and `503` means Data Stream found the endpoint unavailable. To find the cause, refer to [Troubleshoot Data Stream](/en/documentation/platform/data-stream/troubleshooting/).
