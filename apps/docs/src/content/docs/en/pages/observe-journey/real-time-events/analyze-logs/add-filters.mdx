You can narrow a [Real-Time Events](/en/documentation/platform/real-time-events/) search in Azion Console to the records whose field holds a value you name. The filter and the query field are controls of the classic view, which is the view Real-Time Events opens on.

A filter names a field, an operator, and a value. The fields a data source carries decide what a search can match. For each data source and its fields, refer to [Data sources](/en/documentation/platform/real-time-events/data-sources/).

A filter also cuts the rows a search reads inside the log database, which bounds the rows one query may read. A broad search reaches that bound first. For that bound, refer to [Limits](/en/documentation/platform/real-time-events/limits/).

---

## Prerequisites

- An Azion account. To create one, refer to [How to create an account on Azion](/en/documentation/fundamentals/creating-account/).
- Access to Azion Console. To sign in, refer to [How to access Azion Console](/en/documentation/guides/platform/account-and-billing/how-to-access-azion-console/).
- A data source that holds records over the period you want to search.
- The field you want to match. To read the fields one record carries, refer to [Read an event record](/en/documentation/guides/platform/observability/understand-logs/).

## Apply a filter

The **Filter** dialog builds the filter from a field, an operator, and a value. A search with an empty query field returns every record of the selected data source in the period.

To filter a search in Azion Console:

<DocSteps>
  <DocStep title="Open Real-Time Events">

  Access [Azion Console](https://console.azion.com/) > **Real-Time Events**.

  </DocStep>
  <DocStep title="Select the data source">

  Select the tab of the data source, such as **HTTP Requests**.

  </DocStep>
  <DocStep title="Open the filter">

  Select the filter icon.

  </DocStep>
  <DocStep title="Select the field">

  In the **Filter** dialog, select _Status_.

  </DocStep>
  <DocStep title="Select the operator">

  In **Operator**, select _Equals_.

  </DocStep>
  <DocStep title="Enter the value">

  In the value field, enter `400`.

  </DocStep>
  <DocStep title="Apply the filter">

  Select **Apply**.

  </DocStep>
</DocSteps>

The search runs at once. The query field shows `status = 400`, the chip _Status equals: 400_ appears, and the table holds only the matching records.

The filter covers the period the period field shows, _Last 5 minutes_ when the page opens. To search another period, refer to [Set the period](#set-the-period).

In the [Monitor website and API performance](/en/documentation/use-cases/improve-performance-and-reliability/monitor-website-and-api-performance/) use case, expect:

- **One request can be traced.** In **Real-Time Events**, each _HTTP Requests_ record of your domain carries `requestTime`, `upstreamResponseTime`, and `upstreamStatus`. `upstreamResponseTime` is the time the origin took to answer, and `upstreamStatus` is the status it returned. To reach those records, filter on the _Host_ field.

## Set the period

The period field bounds the records a search reads. It opens on _Last 5 minutes_.

To change the period of a search:

<DocSteps>
  <DocStep title="Open the period">

  Select the period field.

  </DocStep>
  <DocStep title="Select the period">

  Select **Quick**, then select _Last 1 hour_.

  </DocStep>
  <DocStep title="Run the search">

  Select **Update**.

  </DocStep>
</DocSteps>

The table holds the records of that period that match the query field.

**Quick** also takes a number and a unit after _Last_. Its **Commonly used** list offers periods from _Last 1 minute_ to _Last 1 year_. **Absolute** picks dates on a calendar.

Real-Time Events keeps records for 7 days, and Activity History records for 2 years. For retention, refer to [Limits](/en/documentation/platform/real-time-events/limits/).

## Edit the query field

The query field holds the filter in Azion Query Language. You can type one condition there instead of using the dialog.

To filter from the query field:

<DocSteps>
  <DocStep title="Enter the query">

  In the query field, enter `status = 301`.

  </DocStep>
  <DocStep title="Run the search">

  Select **Update**.

  </DocStep>
</DocSteps>

The table holds only the records whose status is `301`.

## Example filters

For a number field, such as _Status_, **Operator** offers seven choices:

- _Equals_
- _Less Than_
- _Less Than or Equal_
- _Greater Than_
- _Greater Than or Equal_
- _Not Equals_
- _Between_

Each row names the records a filter returns, and what to select in the **Filter** dialog:

| Records returned | Field | Operator | Value |
| ---------------- | ----- | -------- | ----- |
| Requests answered with `404` | _Status_ | _Equals_ | `404` |
| Requests answered with any status except `200` | _Status_ | _Not Equals_ | `200` |
| Requests answered with a server error | _Status_ | _Greater Than or Equal_ | `500` |

On the **HTTP Requests** tab, the field list of the **Filter** dialog also offers _Remote Address_, _Request Uri_, _Host_, and _Geoloc Country Name_.
