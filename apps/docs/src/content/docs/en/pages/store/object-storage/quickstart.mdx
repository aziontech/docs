This guide instructs you through storing your first object in [Object Storage](/en/documentation/platform/object-storage/). By the end you will have:

- Your first bucket, whose objects your [Applications](/en/documentation/platform/applications/) can read but not write.
- An object stored in that bucket, addressed by its key.
- The object listed in the bucket, which confirms the upload.

Serving a file to your users through an Application and a Connector takes three parts, in this order:

1. A **bucket** is the top-level container for objects. Buckets do not nest.
2. An **object** is a file stored in the bucket, under a key, with the content type it is served with. A `/` in a key is part of the key, not a folder.
3. A [Connector](/en/documentation/platform/connectors/) of type `storage` routes requests to the bucket once a rule of the Application sets that Connector.

This guide creates the bucket and the object and stops before the Connector, so no Application serves the object yet.

## Create a bucket

A bucket holds the objects you upload. This one is read only: your Applications can read its objects and cannot write them.

A bucket name is 6 to 63 characters of lowercase letters, numbers, and hyphens. It starts and ends with a letter or a number. A name is unique across every Azion account, so a short generic name is likely to be taken.

Some prefixes and suffixes are reserved, such as the prefix `azion`. For every naming rule, refer to [Buckets and objects](/en/documentation/platform/object-storage/buckets-and-objects/).

<Tabs client:visible sharedStore="interface">

<Fragment slot="panel.console">

### Console

To create the bucket in Azion Console:

<DocSteps>
  <DocStep title="Open the bucket list">

  Access [Azion Console](https://console.azion.com/) > **Object Storage** > **Buckets**.

  </DocStep>
  <DocStep title="Open the create form">

  Start a new bucket from the **Buckets** list. An account with no buckets yet offers **Bucket** on the empty list.

  </DocStep>
  <DocStep title="Name the bucket">

  Under **General**, in **Name**, enter a name of your own.

  </DocStep>
  <DocStep title="Keep the access level">

  Under **Settings**, keep **Workloads Access** as _Read Only_, the default.

  </DocStep>
  <DocStep title="Select Create Bucket" />
</DocSteps>

The bucket appears in **Buckets**, which lists its **Name**, **Size**, **Last Editor**, and **Last Modified**.

</Fragment>

<Fragment slot="panel.cli">

### CLI

To create the bucket with the Azion CLI, replace `my-first-bucket` with a name of your own and run:

<Code client:visible lang="bash" code={`azion create storage bucket --name my-first-bucket --workloads-access read_only`} />

The command confirms the bucket:

```text
Bucket created successfully
```

A name already in use, in your account or another, makes the command print `The name you've selected is already in use by another resource`. Choose a different name and run the command again.

The bucket exists and holds no objects. For every flag the command accepts, refer to [Azion CLI storage](/en/documentation/devtools/cli/resources/storage/).

</Fragment>

<Fragment slot="panel.api">

### API

To create the bucket with the Azion API, send a `POST` request to the buckets endpoint. Replace `[TOKEN VALUE]` with your personal token and `my-first-bucket` with a name of your own:

<Code client:visible lang="bash" code={`curl --request POST \\
\x20 --url https://api.azion.com/v4/workspace/storage/buckets \\
\x20 --header 'Accept: application/json' \\
\x20 --header 'Authorization: Token [TOKEN VALUE]' \\
\x20 --header 'Content-Type: application/json' \\
\x20 --data '{
\x20 "name": "my-first-bucket",
\x20 "workloads_access": "read_only"
}'`} />

A `201` carries the bucket:

```json
{
  "state": "executed",
  "data": {
    "name": "my-first-bucket",
    "workloads_access": "read_only",
    "last_editor": "user@example.com",
    "last_modified": "2026-01-01T12:14:08.914719+00:00",
    "product_version": "1.0"
  }
}
```

A `400` with the code `17000` means the name is already in use, in your account or another. Choose a different name and send the request again.

The bucket exists and holds no objects.

</Fragment>

</Tabs>

:::note
The access level, `workloads_access`, decides what a Connector and a Function of your Applications can do with the objects. Azion Console labels it **Workloads Access**, and the Azion CLI sets it with `--workloads-access`.

The access level does not restrict the Azion API or the S3 protocol. A personal token, or a credential with the `writeFiles` capability, writes to a `read_only` bucket. For more information, refer to [How Object Storage works](/en/documentation/platform/object-storage/how-it-works/).
:::

## Upload an object

An object is stored under a key, and the key is how every interface addresses it afterwards. A key holds 1 to 1,024 characters.

<Tabs client:visible sharedStore="interface">

<Fragment slot="panel.console">

### Console

To upload the file in Azion Console:

<DocSteps>
  <DocStep title="Open the bucket">

  In **Buckets**, select the bucket you created.

  </DocStep>
  <DocStep title="Add the file">

  Select **Upload files**, or drag the file onto the drop target. The file name becomes the object key. The Console refuses a file larger than 300 MB.

  </DocStep>
</DocSteps>

The object is stored in the bucket, under the key taken from the file name.

</Fragment>

<Fragment slot="panel.cli">

### CLI

To upload the file with the Azion CLI, give `--source` a path relative to your working directory. Replace the bucket name, the key, and the file path with your own:

<Code client:visible lang="bash" code={`azion create storage object --bucket-name my-first-bucket --object-key images/logo.png --source ./logo.png`} />

The command confirms the object:

```text
Object created successfully
```

The object is stored. The `images/` segment is part of the key, not a folder that had to exist first.

:::note
In Azion CLI 4.26.2, an absolute `--source` path fails with `no such file or directory`: the command prepends the working directory to it.
:::

</Fragment>

<Fragment slot="panel.api">

### API

To upload the file with the Azion API, send a `POST` request. The path names the bucket and the key, and the body carries the file. There is no create-then-write sequence: the object exists when the request succeeds.

Replace the key and the file path with your own. Set `Content-Type` to the type of your file, because the stored value is the one this header carries:

<Code client:visible lang="bash" code={`curl --request POST \\
\x20 --url https://api.azion.com/v4/workspace/storage/buckets/my-first-bucket/objects/images/logo.png \\
\x20 --header 'Accept: application/json' \\
\x20 --header 'Authorization: Token [TOKEN VALUE]' \\
\x20 --header 'Content-Type: image/png' \\
\x20 --data-binary '@./logo.png'`} />

A `201` carries the key the object is stored under:

```json
{
  "state": "executed",
  "data": {
    "object_key": "images/logo.png"
  }
}
```

The object is stored. The `images/` segment is part of the key, not a folder that had to exist first.

</Fragment>

</Tabs>

## Confirm the object is stored

The bucket lists what it holds, so you can confirm the upload without another interface.

<Tabs client:visible sharedStore="interface">

<Fragment slot="panel.console">

### Console

To find the object in Azion Console:

<DocSteps>
  <DocStep title="Open the bucket list">

  Access [Azion Console](https://console.azion.com/) > **Object Storage** > **Buckets**.

  </DocStep>
  <DocStep title="Select the bucket">

  Select the bucket you created.

  </DocStep>
  <DocStep title="Find the object by its key">

  The object is listed under its key. A key with a `/`, such as `images/logo.png`, groups under the segment before the `/`. That segment is a prefix, not a folder.

  </DocStep>
</DocSteps>

The object is listed under its key, which confirms the upload.

</Fragment>

<Fragment slot="panel.cli">

### CLI

To list what the bucket holds with the Azion CLI, run:

<Code client:visible lang="bash" code={`azion list storage object --bucket-name my-first-bucket --details`} />

The table carries one row per object, with its key, when it was last modified, and its size in bytes:

```text
KEY              LAST MODIFIED                    SIZE
images/logo.png  2026-01-01 12:07:27.3 +0000 UTC  408
```

Without `--details` the table carries the key and the modification time alone.

The object is listed under its key, which confirms the upload.

</Fragment>

<Fragment slot="panel.api">

### API

Two requests confirm the upload: one lists the bucket, and one reads the object back.

<DocSteps>
  <DocStep title="List the objects in the bucket">

  Send a `GET` request to the objects endpoint of the bucket:

  <Code client:visible lang="bash" code={`curl --request GET \\
  \x20 --url https://api.azion.com/v4/workspace/storage/buckets/my-first-bucket/objects \\
  \x20 --header 'Accept: application/json' \\
  \x20 --header 'Authorization: Token [TOKEN VALUE]'`} />

  The response lists each key with its last modification time and its size in bytes. `is_folder` says whether the entry is a prefix:

  ```json
  {
    "continuation_token": null,
    "results": [
      {
        "key": "images/logo.png",
        "last_modified": "2026-01-01T12:14:26.303000Z",
        "size": 408,
        "is_folder": false
      }
    ]
  }
  ```

  </DocStep>
  <DocStep title="Download the object">

  Read the object back into a local file, and confirm the content type Azion stored:

  <Code client:visible lang="bash" code={`curl --request GET \\
  \x20 --url https://api.azion.com/v4/workspace/storage/buckets/my-first-bucket/objects/images/logo.png \\
  \x20 --header 'Authorization: Token [TOKEN VALUE]' \\
  \x20 --output ./logo-downloaded.png --dump-header -`} />


  The response headers carry `HTTP/2 200` and the `content-type` the upload set, and the file is written to `./logo-downloaded.png`.

  </DocStep>
</DocSteps>

The object reads back with the content type you set, which confirms the upload.

</Fragment>

</Tabs>
