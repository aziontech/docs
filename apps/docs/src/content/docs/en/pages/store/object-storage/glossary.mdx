Definitions for the terms the [Object Storage](/en/documentation/platform/object-storage/) documentation uses.

| Term | Definition |
| --- | --- |
| access key | The public half of an [S3 credential](/en/documentation/platform/object-storage/s3-compatibility/), sent with every request signed for the S3 protocol. It identifies the credential and is readable again after creation, unlike the secret key. |
| `azion:storage` | The [Azion Runtime](/en/documentation/devtools/runtime/api-reference/storage/) module that a Function imports to call `get`, `put`, `list`, and `delete` on the objects of a bucket during a request. A Function writes only to a bucket whose workloads access is `read_write`. |
| bucket | The container Object Storage keeps objects in. Buckets do not nest, a name is unique across every Azion account, and the name cannot be changed after creation. [Buckets and objects](/en/documentation/platform/object-storage/buckets-and-objects/) documents every field and the rules a name follows. |
| capability | One of the six permissions an [S3 credential](/en/documentation/platform/object-storage/s3-compatibility/) can carry: `listFiles`, `readFiles`, `writeFiles`, `deleteFiles`, `listAllBucketNames`, and `listBuckets`. The Azion API rejects any other value. `writeFiles` lets the credential write and delete objects, and `deleteFiles` alone allows no operation. |
| Connector | The entity you create in [Connectors](/en/documentation/platform/connectors/), the Platform Resource that routes requests from your Applications to the origins that hold your content. A Connector of type `storage` routes requests to one bucket, narrowed to a prefix when it has one, and the Application answers them with the objects in that bucket. |
| grace period | The 24 hours a deleted object is retained before it is removed permanently. The Azion API stops listing and serving the object at once, and the bucket cannot be deleted until the period ends. [Buckets and objects](/en/documentation/platform/object-storage/buckets-and-objects/) documents the delete operations it applies to. |
| object | A file stored in a bucket, together with the key it is stored under and the content type it is served with. An object is replaced whole: uploading to a key that is in use overwrites the content that the Azion API returns, and an Application returns the new content once it holds no cached copy. Through the S3 protocol, the earlier version stays readable by its version ID for a period you cannot set, as [Object Storage limits](/en/documentation/platform/object-storage/limits/#scope) states. |
| object key | The string that identifies one object inside a bucket, between 1 and 1,024 characters. A key may contain the forward slash, which the interfaces read as a [prefix](/en/documentation/platform/object-storage/buckets-and-objects/). Azion Console renames or moves an object by copying it to the new key and deleting the old one. |
| Object Storage | A Platform Resource that [stores files as objects in buckets](/en/documentation/platform/object-storage/) on Azion's infrastructure and can serve them to your [Applications](/en/documentation/platform/applications/). Its interfaces are Azion Console, the Azion API, the Azion CLI, Azion Runtime, the [`@aziontech/storage` library](/en/documentation/devtools/azion-lib/storage/), and the S3 protocol, and the [Terraform Provider](/en/documentation/devtools/terraform/) manages its buckets. |
| prefix | A leading segment that a group of [object keys](/en/documentation/platform/object-storage/buckets-and-objects/) share, such as `assets/` in the key `assets/logo.svg`. Azion Console shows a prefix as a folder, and so does the Azion API when a list request sets `all_levels` to `false`, but a prefix exists only while a key starts with it. A [Connector](/en/documentation/platform/connectors/) of type `storage` with the prefix `assets` routes a request for `/logo.svg` to the object `assets/logo.svg`. |
| S3 credential | The entity that holds the access key and secret key pair that authenticates a request to the [S3 endpoint](/en/documentation/platform/object-storage/s3-compatibility/), scoped by its capabilities. The credential's list of buckets limits the objects it reaches, and a credential with no list reaches the objects of every bucket in the account. A credential cannot change after it is created, and it stops working once it expires or is deleted. |
| secret key | The private half of an [S3 credential](/en/documentation/platform/object-storage/s3-compatibility/), used to sign a request for the S3 protocol. It is returned only by the request that creates the credential and cannot be read or changed afterwards. A lost secret key is replaced by creating another credential. |
| `Storage-Content-Type` | A header the Azion API accepts on an upload and does not act on. The content type stored with an object comes from `Content-Type` or, when an upload through the Azion API sends none, from the extension of the key. [Buckets and objects](/en/documentation/platform/object-storage/buckets-and-objects/) documents the behavior. |
| workloads access | The bucket field that decides what a Connector and a Function of your Applications can do with the objects in it, set to `read_only`, `read_write`, or `restricted`. It does not restrict the Azion API or the S3 protocol, which are governed by the token or the credential the request carries. [Buckets and objects](/en/documentation/platform/object-storage/buckets-and-objects/) documents each value. |
