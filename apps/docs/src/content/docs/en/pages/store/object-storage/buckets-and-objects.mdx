A bucket is the container [Object Storage](/en/documentation/platform/object-storage/) keeps objects in: it holds objects directly, and buckets do not nest. An object is a file stored in a bucket, together with the key it is stored under and the content type it is served with. This page lists the fields of both, the operations the Azion API v4 exposes, and the errors they return. For the S3 protocol and its credentials, refer to [S3 compatibility](/en/documentation/platform/object-storage/s3-compatibility/).

---

## Bucket names

A bucket name is chosen at creation and cannot be changed afterwards. Azion Console checks the first and last character and the reserved prefixes and suffixes in its form. The Azion API refuses a name that breaks a rule with HTTP `400` and the code of that rule:

| Rule | Value | Refused with |
| --- | --- | --- |
| Length | 6 to 63 characters | `10048` below 6 characters, `10046` past 63 |
| Characters | Lowercase letters, numbers, and the hyphen (`-`) | `17002` |
| First and last character | A name begins and ends with a lowercase letter or a number | `17002` |
| Reserved prefixes | A name cannot begin with `azion`, `xn--`, `sthree-`, or `amzn-s3-demo-` | `17001` |
| Reserved suffixes | A name cannot end with `-s3alias` or `--ol-s3` | `17001` |
| Uniqueness | A name is unique across every Azion account, and never only within your own | `17000` |

Because names are global, a short generic name is likely to be taken. Naming a bucket for the content it holds and the access it needs keeps names available and readable, as in `media-assets-ro`.

## Bucket fields

| Field | Type | Required | Default | Description |
| --- | --- | --- | --- | --- |
| `name` | string, 6 to 63 characters | Yes | — | The bucket name. Read-only after creation |
| `workloads_access` | `read_only`, `read_write`, or `restricted` | Yes | — | What a Connector and a Function of your Applications can do with the objects |
| `last_editor` | string | — | — | The email of the user who last changed the bucket. Read-only |
| `last_modified` | date-time | — | — | When the bucket last changed. Read-only |
| `product_version` | string | — | `1.0` | A version string. Read-only |

A `PATCH` changes only `workloads_access`, and a `PATCH` that carries `name` is refused with `17004`. The API ignores a field it does not know, on a create and on a `PATCH`. For example, a request that adds `region` still creates or updates the bucket, and the response does not carry that field.

## Access levels

`workloads_access` decides what a [Connector](/en/documentation/platform/connectors/) of type `storage` and a [Function](/en/documentation/platform/functions/) of your [Applications](/en/documentation/platform/applications/) can do with the objects of a bucket. It does not restrict the Azion API or the S3 protocol. At every level, a request with a personal token reads and writes the objects, and so does an S3 request whose credential allows the operation.

| Value | In Azion Console | Connector of type `storage` | Function, through the Runtime API |
| --- | --- | --- | --- |
| `read_only` | _Read Only_ | `GET` returns the object. `PUT` and `DELETE` get `403`, and `POST` gets `501` | `get` and `list` work, and `put` fails |
| `read_write` | _Read & Write_ | `GET` returns the object, and `DELETE` deletes it. `PUT` gets `403`, and `POST` gets `501` | `get`, `put`, `list`, and `delete` work |
| `restricted` | _Restricted_ | `GET`, `PUT`, `POST`, and `DELETE` get `502` | `get`, `put`, and `list` fail with `Bucket not found` |

On a `read_only` bucket, the `put` of a Function fails with `StorageError: Access Denied to the bucket, review bucket policy`. On a `restricted` bucket, `get`, `put`, and `list` fail with a `StorageError` that reads `Bucket not found`, followed by the bucket name. The Connectors API also refuses to create a Connector of type `storage` for a `restricted` bucket, with `28007`, as [Connector settings](/en/documentation/platform/connectors/settings/#storage) lists.

In Azion Console, the **Workloads Access** field sits in the **Settings** section of a bucket and starts at _Read Only_. A bucket that is not _Restricted_ cannot return to _Restricted_ there. The option is disabled, with the note `A bucket open to Workloads can't return to Restricted.` The Azion API accepts that change, so a `PATCH` from `read_write` to `restricted` succeeds.

A change of level takes some time to reach the Connector and the Function. Until then, a request can get either level's behavior. Check the new level with one request before you depend on it.

Set `read_only` on a bucket that a Connector serves. Set `read_write` on a bucket that a Function writes to, and point no Connector at it. Set `restricted` on a bucket that only the Azion API or the S3 protocol reaches.

:::caution
Through a Connector, any client can delete an object of a `read_write` bucket with a `DELETE` request that carries no credentials.
:::

## Object keys and prefixes

An object key identifies one object inside a bucket. It is 1 to 1,024 characters and does not have to match the name of the file it came from. A key past 1,024 characters is refused with `503` `10100` `Service Unavailable`, not with a validation error.

A key may contain the forward slash (`/`), and the Azion API and the S3 protocol read a shared leading segment as a prefix. A prefix exists only through the keys under it. Uploading to the key `src/assets/logo.svg` in an empty bucket creates the object and the prefix in one request. The prefix leaves the listing when the last key under it is deleted.

Azion Console shows a prefix as a folder. The Azion API lists it with `is_folder` set to `true` when the list request sets `all_levels` to `false`.

```text
README.md
src/index.js
src/assets/logo.svg
```

In that bucket, `README.md` sits at the root, `src` is a prefix holding one object and one nested prefix, and `src/assets` holds `logo.svg`. Listing with `prefix=src/assets/` returns the key `src/assets/logo.svg` alone, with its full path. A Connector of type `storage` with the prefix `src/assets` serves that object at `/logo.svg`. The key it reads is the prefix followed by the request path.

The Azion API has no rename operation: copy the object to the new key, then delete the old one. Azion Console renames or moves an object the same way.

Uploading to a key that already holds an object replaces the object that the Azion API returns. An Application returns the new object once it holds no cached copy of the old one. Through the S3 protocol, the earlier version stays readable by its version ID for a period you cannot set, as [Object Storage limits](/en/documentation/platform/object-storage/limits/#scope) states.

## Content type

The content type stored with an object is the one the `Content-Type` header of the upload request carries. The Azion API, the S3 protocol, and a Connector return that stored type with the object.

When an upload through the Azion API carries no `Content-Type`, Azion sets the type from the extension of the key, not from the content:

| Key ends in | Stored content type |
| --- | --- |
| `.txt` | `text/plain` |
| `.json` | `application/json` |
| `.png` | `image/png`, even when the content is text |
| `.m3u8` | `application/vnd.apple.mpegurl` |
| `.ts` | `application/octet-stream` |
| No extension | `application/octet-stream`, even when the content is an image |

`curl --data-binary` without a `Content-Type` header sends `application/x-www-form-urlencoded`, and Azion stores and serves that type.

The API also accepts a `Storage-Content-Type` header. It has no effect on the stored content type, alone or next to `Content-Type`. For example, an upload that sends `Storage-Content-Type: image/png` and no `Content-Type` stores the type the key's extension sets. Set `Content-Type` on the upload request.

## Operations

Every operation is authenticated and sits under `https://api.azion.com/v4/workspace/storage`.

| Operation | Method and path |
| --- | --- |
| List buckets | `GET /buckets` |
| Create a bucket | `POST /buckets` |
| Retrieve a bucket | `GET /buckets/{bucket_name}` |
| Update a bucket | `PATCH /buckets/{bucket_name}` |
| Delete a bucket | `DELETE /buckets/{bucket_name}` |
| List objects | `GET /buckets/{bucket_name}/objects` |
| Download an object | `GET /buckets/{bucket_name}/objects/{object_key}` |
| Create an object | `POST /buckets/{bucket_name}/objects/{object_key}` |
| Replace an object | `PUT /buckets/{bucket_name}/objects/{object_key}` |
| Delete an object | `DELETE /buckets/{bucket_name}/objects/{object_key}` |
| Copy an object | `POST /buckets/{bucket_name}/objects/{object_key}/copy/{new_object_key}` |

`POST` on an object key creates the object, and replaces it when the key is already in use. `PUT` replaces an object that exists and returns `17013` for a key that does not, so it never creates one.

### Create a bucket

```bash
curl --request POST \
  --url https://api.azion.com/v4/workspace/storage/buckets \
  --header 'Accept: application/json' \
  --header 'Authorization: Token [TOKEN VALUE]' \
  --header 'Content-Type: application/json' \
  --data '{
  "name": "my-bucket-ro",
  "workloads_access": "read_only"
}'
```

The response carries `201` and the created bucket:

```json
{
  "state": "executed",
  "data": {
    "name": "my-bucket-ro",
    "workloads_access": "read_only",
    "last_editor": "user@example.com",
    "last_modified": "2026-01-01T12:00:00.442763+00:00",
    "product_version": "1.0"
  }
}
```

Retrieving a bucket returns the same object under `data` with no `state` key. Creating, updating, and deleting return `state`.

### List buckets

```bash
curl --request GET \
  --url 'https://api.azion.com/v4/workspace/storage/buckets?page_size=10' \
  --header 'Accept: application/json' \
  --header 'Authorization: Token [TOKEN VALUE]'
```

```json
{
  "count": 1,
  "total_pages": 1,
  "page": 1,
  "page_size": 10,
  "next": null,
  "previous": null,
  "results": [
    {
      "name": "my-bucket-ro",
      "workloads_access": "read_only",
      "last_editor": "user@example.com",
      "last_modified": "2026-01-01T12:00:00.442763+00:00",
      "product_version": "1.0"
    }
  ]
}
```

| Query parameter | Effect |
| --- | --- |
| `page`, `page_size` | Page through the list. `page_size` defaults to 10 and accepts up to 100 |
| `search` | Match part of a bucket name, ignoring case |
| `name` | Match a bucket name exactly, ignoring case |
| `bucket` | Returns no bucket, even for an exact name. Use `name` |
| `workloads_access` | Filter by access level. Accepts comma-separated values |
| `ordering` | Order the results by a field |
| `fields` | Return only the fields named, comma-separated |
| `last_editor`, `created`, `last_modified` | Filter by editor or date. The date filters accept the `__gte` and `__lte` suffixes |

Use `search` to match part of a name. The `name` parameter matches the whole name, so a partial value returns nothing. A `page_size` past 100 is refused with `10097`.

### List objects

```bash
curl --request GET \
  --url 'https://api.azion.com/v4/workspace/storage/buckets/my-bucket-ro/objects' \
  --header 'Accept: application/json' \
  --header 'Authorization: Token [TOKEN VALUE]'
```

```json
{
  "continuation_token": null,
  "results": [
    {
      "key": "src/assets/logo.svg",
      "last_modified": "2026-01-01T12:00:47.054000Z",
      "size": 12,
      "is_folder": false
    }
  ]
}
```

| Query parameter | Default | Effect |
| --- | --- | --- |
| `prefix` | empty | List only the keys under a prefix |
| `all_levels` | `true` | List every key. With `false`, a prefix is returned as one entry with `is_folder` set to `true`, `size` of `0`, and no `last_modified` |
| `max_object_count` | — | Number of keys per response, capped at 1,000 |
| `continuation_token` | — | Return the next page, using the token the previous response carried |

A response with more keys than `max_object_count` carries a `continuation_token`. Send it back in the next request to read the rest.

### Upload an object

```bash
curl --request POST \
  --url https://api.azion.com/v4/workspace/storage/buckets/my-bucket-ro/objects/src/assets/logo.svg \
  --header 'Accept: application/json' \
  --header 'Authorization: Token [TOKEN VALUE]' \
  --header 'Content-Type: image/svg+xml' \
  --data-binary '@./src/assets/logo.svg'
```

```json
{
  "state": "executed",
  "data": {
    "object_key": "src/assets/logo.svg"
  }
}
```

### Delete an object

```bash
curl --request DELETE \
  --url https://api.azion.com/v4/workspace/storage/buckets/my-bucket-ro/objects/src/assets/logo.svg \
  --header 'Accept: application/json' \
  --header 'Authorization: Token [TOKEN VALUE]'
```

The response carries `202` and `{"state": "pending"}`. The Azion API stops listing the key at once, and an Application with no cache setting of its own answers `404` for it at once. The object is removed permanently after a 24-hour grace period.

### Delete a bucket

A bucket is deleted only while it holds no objects. It is also not deleted within 24 hours of the last object being removed, because of that grace period. Both cases return `17006`. A bucket that never held an object is deleted at once.

A bucket that a Connector references is refused with `409` `17016`, and `meta.references` names that Connector and its ID.

## Authentication

Every request carries a [personal token](/en/documentation/guides/platform/account-and-billing/personal-tokens/):

```http
Authorization: Token [TOKEN VALUE]
```

The account also needs the storage permissions for the operation. The six permissions are View, Edit, and Delete for a Storage Bucket, and View, Edit, and Delete for a Storage Object. For more information, refer to [Teams permissions](/en/documentation/fundamentals/teams-permissions/). A request without a valid token is refused with `401`, as [Errors](#errors) lists.

---

## Errors

The response body carries one `errors` array. Each entry names the `code`, the `title`, a `detail`, and the `status`. Its `source.pointer` names the field the error applies to, such as `/data/name`, or holds `/data` when the error concerns the whole request. An authentication error carries `source.headers` with the value `Authorization` instead.

```json
{
  "errors": [
    {
      "code": "17000",
      "title": "Bucket Already Exists",
      "detail": "Bucket name 'my-bucket-ro' is already in use.",
      "status": "400",
      "source": {
        "pointer": "/data/name"
      },
      "meta": {
        "name": "my-bucket-ro"
      }
    }
  ]
}
```

| Code | Title | Status | Cause |
| --- | --- | --- | --- |
| `10001` | `Authentication Failed` | 401 | The token is not valid |
| `10002` | `Not Authenticated` | 401 | The request carries no token |
| `10039` | `Invalid Choice` | 400 | `workloads_access` carries a value outside the three the field accepts |
| `10046` | `Max Length` | 400 | The bucket name is longer than 63 characters |
| `10048` | `Min Length` | 400 | The bucket name is shorter than 6 characters |
| `10059` | `Required Field` | 400 | `name` or `workloads_access` is missing from a create request |
| `10097` | `Invalid Page Size` | 400 | `page_size` is past 100 |
| `10100` | `Service Unavailable` | 503 | The object key is longer than 1,024 characters |
| `17000` | `Bucket Already Exists` | 400 | The bucket name is in use, in your account or another |
| `17001` | `Bucket Name Not Available` | 400 | The bucket name begins or ends with a reserved string |
| `17002` | `Invalid Bucket Name` | 400 | The bucket name has a character outside the rule, or a hyphen at either end |
| `17004` | `Name Cannot Be Changed` | 400 | A `PATCH` request carries `name` |
| `17005` | `Bucket Does Not Exist` | 404 | The bucket named in the path does not exist |
| `17006` | `Cannot Delete Non Empty Bucket` | 400 | The bucket holds objects, or an object was removed from it within the last 24 hours |
| `17013` | `Object Does Not Exist` | 404 | The object key does not exist, on a download, a `PUT`, or a delete |
| `17016` | `Cannot Delete Referenced Bucket` | 409 | A Connector references the bucket |

[Bucket names](#bucket-names) lists the reserved strings and the characters a name accepts. The `17002` entry carries the pointer `/data/name`. In its `detail`, `letters` stands for lowercase letters: `Names can contain hyphen, numbers and letters (alphanumeric).`

The `10100` entry answers a key past 1,024 characters, although its `detail` reads `The service is temporarily unavailable.`

## The runtime API

The operations above are HTTP calls, addressed to `api.azion.com` and authenticated with a personal token. A Function reaches the same buckets another way: it imports the `azion:storage` module and calls `put`, `get`, `delete`, and `list` on a bucket. It sends no token, because the constructor takes the bucket name and nothing else. The access level of the bucket decides which of those calls work, as [Access levels](#access-levels) lists.

That module belongs to the runtime rather than to Object Storage. Its methods, its `StorageObject` shape, and the runtime versions it ships in are documented with the other runtime bindings, in [Storage runtime API](/en/documentation/devtools/runtime/api-reference/storage/).
