This guide instructs you through reading your first event record in [Real-Time Events](/en/documentation/platform/real-time-events/).

- Open Real-Time Events and identify the controls a search is built from.
- Read the records of the HTTP Requests data source over a period you set.
- Narrow the result to the records that carry one value.
- Open one record and read the fields the request wrote.

A search creates nothing. It is three choices, and every result comes from the combination of them:

1. The data source holds the records of one kind of event, such as the requests your [Applications](/en/documentation/platform/applications/) and [Firewalls](/en/documentation/platform/firewall/) receive. A search always reads one.
2. The time range bounds the period. A record outside that period is not read, whatever else matches it.
3. A filter narrows what the first two selected. It never widens them.

The GraphQL API makes the same three choices. It takes a dataset name, a `tsRange` argument, and the other filter arguments of that dataset.

## Open Real-Time Events

The records are reached two ways, and both read the same store.

<Tabs client:visible sharedStore="interface">

<Fragment slot="panel.console">

### Console

To open the page, access [Azion Console](https://console.azion.com/) > **Real-Time Events**.

The page presents these controls:

- One tab per data source, such as **HTTP Requests**, selects the records the search reads.
- The period field bounds the period the search covers. It opens on _Last 5 minutes_.
- The filter icon opens the **Filter** dialog, which narrows the result to the records that match a value. The query field shows each filter in Azion Query Language.
- **Refresh** runs the search again. After you change the period or the query, the button reads **Update**.

A search is one combination of these controls.

</Fragment>

<Fragment slot="panel.api">

### API

The GraphQL API serves the same records at `https://api.azion.com/v4/events/graphql`. That address also serves the GraphiQL Playground in a browser. Sign in to Azion Console at `https://console.azion.com`, then open the endpoint. Every query of this guide runs there.

A query sent from a terminal instead carries an `Authorization: Token [TOKEN VALUE]` header. For that path, refer to [GraphQL API first steps](/en/documentation/devtools/graphql/first-steps/).

The Playground is where you write and send each query of this guide.

</Fragment>

</Tabs>

## Search the records of one data source

HTTP Requests carries one record per request an application or a firewall received. The period a search can ask for is bounded by how long an event record is kept. For that bound and the others a query carries, refer to [Limits](/en/documentation/platform/real-time-events/limits/).

<Tabs client:visible sharedStore="interface">

<Fragment slot="panel.console">

### Console

To read the records of one data source in Azion Console:

<DocSteps>
  <DocStep title="Select the data source">

  Select the **HTTP Requests** tab.

  </DocStep>
  <DocStep title="Open the period">

  Select the period field, which shows _Last 5 minutes_.

  </DocStep>
  <DocStep title="Select the period">

  Select **Quick**, then select _Last 15 minutes_.

  </DocStep>
  <DocStep title="Run the search">

  Select **Update**.

  </DocStep>
</DocSteps>

The records of that period appear in a table, one row per request, with its **Time** and **Log Body**.

The page has one tab per data source. For each one and the variables it carries, refer to [Data sources](/en/documentation/platform/real-time-events/data-sources/).

</Fragment>

<Fragment slot="panel.api">

### API

In the GraphQL API, the HTTP Requests data source is the `workloadEvents` dataset. The controls of Azion Console are arguments on it:

- `tsRange` carries the period, as a `begin` and an `end` timestamp.
- `orderBy` sets the order the rows come back in, such as `[ts_DESC]` for the most recent first.
- `limit` caps how many rows the query returns.

Those three arguments are what the next stage sends. For the dataset each data source maps to, refer to [Data sources](/en/documentation/platform/real-time-events/data-sources/). For the fields each dataset carries, refer to [Real-Time Events GraphQL API fields](/en/documentation/devtools/graphql/gql-real-time-events-fields/).

</Fragment>

</Tabs>

## Narrow the search

A search over a period with no other condition reads every record in it. One value cuts that down to the records worth reading. It also keeps a search inside the bounds of the log database.

<Tabs client:visible sharedStore="interface">

<Fragment slot="panel.console">

### Console

To narrow the result in Azion Console:

<DocSteps>
  <DocStep title="Open the filter">

  Select the filter icon.

  </DocStep>
  <DocStep title="Select the field">

  In **Filter**, select _Status_.

  </DocStep>
  <DocStep title="Set the condition">

  In **Operator**, select _Equals_, and then enter `400` in the value field.

  </DocStep>
  <DocStep title="Apply the filter">

  Select **Apply**.

  </DocStep>
</DocSteps>

The search runs at once. The query field shows `status = 400`, and the table holds only the records whose status is `400`.

A filter takes a field, an operator, such as _Equals_, _Not Equals_, or _Between_, and a value.

</Fragment>

<Fragment slot="panel.api">

### API

A filter argument narrows the dataset the same way. `statusIn` takes a list of status codes, so `statusIn: [400]` returns the records whose status is `400`.

To return the most recent record that matched:

```graphql
{
  workloadEvents(
    limit: 1
    filter: {
      tsRange: { begin: "<your-period-start>", end: "<your-period-end>" }
      statusIn: [400]
    }
    orderBy: [ts_DESC]
  ) {
    ts
    requestId
    host
    status
  }
}
```

Replace `<your-period-start>` and `<your-period-end>` with timestamps in Coordinated Universal Time (UTC), in the form `YYYY-MM-DDTHH:MM:SS`, inside the last 7 days. The row the query returns:

```json
{
  "ts": "2026-11-26T20:18:46Z",
  "requestId": "485876cf3a7499bcac0545a095e2ef76",
  "host": "<your-workload-domain>",
  "status": 400
}
```

The row is one event record, and its `requestId` identifies the request that produced it.

</Fragment>

</Tabs>

## Read one event record

A record carries far more than the few values a result list shows. Reading all of it is what the search was for.

<Tabs client:visible sharedStore="interface">

<Fragment slot="panel.console">

### Console

To open the whole record in Azion Console, select a row in the results table.

The **More Details** view opens, with every field of that one record and its value, such as `remoteAddress`. You now have the values a single request wrote, field by field.

For what each variable means, data source by data source, refer to [Data sources](/en/documentation/platform/real-time-events/data-sources/). For how to read the values of one record, refer to [Read an event record](/en/documentation/guides/platform/observability/understand-logs/).

</Fragment>

<Fragment slot="panel.api">

### API

A response carries only the fields the query selected. To read more of a record, name more fields. Filter on the `requestId` the previous stage returned and extend the selection set:

```graphql
{
  workloadEvents(
    limit: 1
    filter: {
      tsRange: { begin: "<your-period-start>", end: "<your-period-end>" }
      requestIdEq: "<your-request-id>"
    }
  ) {
    ts
    requestId
    host
    requestUri
    status
    upstreamStatus
  }
}
```

Replace `<your-request-id>` with the `requestId` the previous stage returned, and use the same period. The row carries one value per field named:

```json
{
  "ts": "2026-11-26T20:18:46Z",
  "requestId": "485876cf3a7499bcac0545a095e2ef76",
  "host": "<your-workload-domain>",
  "requestUri": "-",
  "status": 400,
  "upstreamStatus": 0
}
```

You now have the record of one request, field by field. A field with no value, such as `requestUri` here, reads `-`. `upstreamStatus` reads `0` because the request never reached an origin. For every field `workloadEvents` carries, and the fields of the other datasets, refer to [Real-Time Events GraphQL API fields](/en/documentation/devtools/graphql/gql-real-time-events-fields/).

</Fragment>

</Tabs>
