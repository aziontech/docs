[Real-Time Events](/en/documentation/platform/real-time-events/) bounds how long it keeps a record and how much one query may read and return. This page states what Real-Time Events covers, each bound, and the answer a query receives past it.

For what Real-Time Events costs, refer to [Pricing](/en/documentation/fundamentals/pricing/#real-time-events).

---

## Scope

- **Activation**: Real-Time Events needs no activation, because the Platform Resources that serve your traffic write its records. The [Terraform Provider](/en/documentation/devtools/terraform/) has no resource for it.
- **Interfaces**: Azion Console and the GraphQL API search the records. The Azion CLI prints recent HTTP event logs and Function console logs with [Azion CLI logs](/en/documentation/devtools/cli/logs/).
- **Search delay**: a record becomes searchable some seconds after its request, so a search that runs at once can miss it. Search again before you conclude that the request was not served.
- **Retention**: a period that reaches past retention returns the records inside it and none older, with no error. Removal is permanent.
- **Broad searches**: a search with no filter over a long period can reach the bound on the rows a query reads. It then fails instead of returning part of the records. For how a filter changes the read, refer to [How a query is bounded](/en/documentation/platform/real-time-events/how-it-works/#how-a-query-is-bounded).
- **Request rate**: the GraphQL API limits the requests from each IP address and answers `429` with `You have reached the request rate limit!` past that limit.
- **Export and metrics**: Azion Console downloads the result of a search as a CSV file, as [Export query results to CSV](/en/documentation/guides/platform/observability/export-events-csv/) shows. Real-Time Events does not send records out on its own, and keeps them only for its retention period. [Data Stream](/en/documentation/platform/data-stream/) sends the records of Activity History, Applications, Functions, and WAF to an endpoint you run. For aggregated metrics of the same traffic, use [Real-Time Metrics](/en/documentation/platform/real-time-metrics/).

---

## Event retention

Real-Time Events keeps an event record for 168 hours, which is 7 days. Retention is therefore the outer bound of the period a query can ask for, whichever data source it reads.

[Activity History](/en/documentation/fundamentals/activity-history/) is the exception. Its data source keeps records for 2 years, and the Real-Time Events GraphQL API queries that full period.

## Query limits

One query carries three bounds of its own: the rows it returns, the fields it selects, and the size of its payload. The log database adds a fourth, on the rows one query reads before it returns anything.

### Default limits

Each row names what is bounded, the bound, and what a query past it receives. For the body of each error response, refer to [GraphQL API error responses](/en/documentation/devtools/graphql/error-responses/).

:::tip
Azion can raise these default limits on request, based on your plan. To request an increase, contact the [technical support](/en/documentation/support/) team.
:::

| Scope | Limit | Past the limit |
| --- | --- | --- |
| Rows returned per query | 10,000 rows | `400` and `The value for the query limit is invalid (must be between 0 to 10000 rows).` |
| Selected fields per query | 37 fields, and 36 on `workloadEvents` | `400` and `You have exceeded the limit amount allowed for selected fields (37 fields).` On `workloadEvents`, the 37th field returns `400` and `The query has reached a system limit. Please adjust your query and try again.` |
| Rows read inside the log database | 10 billion rows | `500` and a message that names the limit, `max rows: 10.00 billion` |

The row and field bounds belong to the GraphQL API itself. The `limit` argument of a query sets the row count, up to 10,000. For both bounds, refer to [GraphQL API limits](/en/documentation/devtools/graphql/limits/).

A GraphQL API payload carries at most 5 GB. A record becomes searchable some seconds after the event that produced it, and the delay can pass 30 seconds.

The 10-billion row bound is enforced by the log database rather than by the GraphQL API. It counts the rows a query reads, not the rows the query returns. A query over a long time range with no other filter can reach it, such as a search across the full 7 days of retention. To stay inside the bound, narrow the time range or filter on a host, an IP address, or an HTTP status code.
