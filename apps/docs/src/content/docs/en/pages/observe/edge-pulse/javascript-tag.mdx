The Edge Pulse JavaScript tag is the script that collects measurements from the browsers of the visitors to your pages. [Edge Pulse](/en/documentation/platform/edge-pulse/) serves it from Azion Console in two forms, the **Default Tag** and the **Pre-loading Tag**.

The tag is fully asynchronous. It respects the protocol in use, HTTP or HTTPS. It does not interfere with the loading process or with the internal structure of the delivered content.

---

## Tags

Both Edge Pulse tags go in the same place, in the HTML of the page and before the closing `body` tag. They differ in how they load the RUM Client, the script that takes the measurement.

| Tag | How it loads the RUM Client | When to choose it |
| --- | --- | --- |
| **Default Tag** | Inline JavaScript that waits for the load event, then adds the RUM Client to the page. | The page allows inline JavaScript. Waiting for the loading event keeps that event uninterrupted and leaves the visitor's experience unaffected. |
| **Pre-loading Tag** | A `script` element with the `async` attribute that loads the RUM Client from an external address, so the browser can download it before the load event fires. | The page carries a Content Security Policy that blocks inline JavaScript. That policy must also allow the `client.azionrum.net` address and `'unsafe-eval'`, because the RUM Client evaluates code it downloads. |

With either tag, the RUM Client starts measuring at least 2 seconds after the load event, so a visit that ends earlier sends nothing. When a Content Security Policy also restricts connections, it must allow `https://rum.azion.com` and `https://rum.azion.net` for the page-load record to be sent.

## Tag placement

Edge Pulse measures a page only when that page carries the tag. The tag is on the **Edge Pulse** page in [Azion Console](https://console.azion.com/), behind the **Copy script** button. One tag covers one page, and Edge Pulse collects nothing for a page that carries no tag.

The tag is published by hand, or through a tag management system. To copy the tag and add it to a page, refer to [Edge Pulse quickstart](/en/documentation/platform/edge-pulse/quickstart/).

---

## What the tag does not take

Azion Console offers no setting for the tag: the **Edge Pulse** page shows two read-only snippets and a **Copy script** button. The page has no setting for a sampling rate, for fields to leave out, or for traffic to exclude. Choosing between the **Default Tag** and the **Pre-loading Tag**, and choosing which pages carry a tag at all, are the two decisions available to you.

The RUM Client ignores route changes made with the History API, so a single-page application sends a measurement only on a full page load. A browser also sends at most one measurement every 30 minutes for each scheme and host, and only when it loads a tagged page. The browser keeps that interval in its local storage, so a private window or cleared storage starts it over. For how that interval works, refer to [How Edge Pulse works](/en/documentation/platform/edge-pulse/how-it-works/).

## Browser settings

Edge Pulse reads the `navigator.doNotTrack` setting of the visitor's browser. The value decides whether the visitor identifier survives from one visit to the next.

| Value | Behavior of Edge Pulse |
| --- | --- |
| `navigator.doNotTrack` set to `1` | If tracking was never allowed, and Edge Pulse therefore never used the local storage, an identifier is generated for each visit the visitor makes to the site. If the value is `1` but the visitor was tracked before, the previous identifier is deleted and a new one is generated. |
| `navigator.doNotTrack` set to any other value | Edge Pulse tracks, and the same identifier is used for each visit of a visitor. |

## Visitor identifier

Edge Pulse identifies a visitor with a value generated by the UUID4 algorithm, the random variant of the universally unique identifier scheme. It keeps that value in the local storage of the browser, the store a browser holds for one site and does not clear when the page closes. The `navigator.doNotTrack` setting decides how long the value lives.

To follow the identifier through a measurement, refer to [How Edge Pulse works](/en/documentation/platform/edge-pulse/how-it-works/).

## Collected data

The tag sends two kinds of record: a measurement of the page load, and the results of its tests against Azion data centers. The `pulseEvents` dataset of the [Real-Time Events](/en/documentation/platform/real-time-events/) GraphQL API holds the values of the page-load measurement.

Each page-load measurement carries five groups of values. The table lists what the tag reads for each group and the [`pulseEvents` fields](/en/documentation/devtools/graphql/gql-real-time-events-fields/#pulse-events) that hold it:

| Group | What the tag reads | Fields in `pulseEvents` |
| --- | --- | --- |
| Record | When the measurement was taken, the tag script that sent it, and the record type | `ts`, `scriptid`, `clientId`, `type` |
| Page and browser | The page address, the referring address, the `User-Agent`, and the platform | `locationhref`, `referrer`, `useragent`, `platform`, `browser` |
| Navigation | The navigation type the browser reported, its type codes, and the redirects followed | `navtype`, `typenavigate`, `typereload`, `typebackforward`, `typereserved`, `redirectcount` |
| Timing | The Navigation Timing values the browser recorded for the page load | `dns`, `tcp`, `ssl`, `ttfb`, `contentdownload`, `networkduration`, `rendertime`, `pageloadtime` |
| Connection | The connection class, round-trip time, and downlink speed the browser estimated | `effectivetype`, `rtt`, `downlink` |

The browser's Navigation Timing interface records each point of the page load in milliseconds, and the timing fields are computed from those points.

The data center tests record whether each tested data center answered and how long it took. They also record the resolver used for DNS resolution and the visitor's anonymous network. You cannot query these results: `pulseEvents` has no field for them.
