[Data Stream](/en/documentation/platform/data-stream/) applies default limits to how a stream batches and delivers log lines and to the fields of a stream. For the usage each plan includes, refer to [Azion pricing](https://www.azion.com/en/pricing/). Azion can raise a default limit based on your plan. To request an increase, contact the [technical support](/en/documentation/support/) team.

---

## Scope

- **Scope of a stream**: a stream on Applications, Functions, or WAF Events carries a sampling item or a workload filter. The API refuses a `transform` with neither (`32002`) or with both (`32007`). For both items, refer to [Stream settings](/en/documentation/platform/data-stream/stream-settings/#transform).
- **Scope of an Activity History stream**: an Activity History stream takes a sampling item or no scope item, and the API refuses a workload filter on it (`10088`). An Activity History stream saved with no sampling item is accepted, and it sends no event.
- **Sampling and the other streams**: saving an active stream with sampling on Applications, Functions, or WAF Events deactivates every other stream on the account, except Activity History streams. The streams it deactivates include streams with a workload filter on any of those three data sources. A sampling rate of 1 deactivates them as a rate of 100 does. An edit that changes only the name of an active stream with sampling also deactivates the other streams.
- **Streams that stay active**: saving an Activity History stream with sampling deactivates no other stream. An inactive stream with sampling deactivates none when you save it. A stream with a workload filter that you save or activate afterward runs beside the stream with sampling until that stream is saved again.
- **Start of a stream**: saving a stream as active is the only activation step it needs. After you create or activate a stream, it can take several minutes to start collecting events. It does not send the events from before that.
- **Edits and deactivation**: an edit, such as a new endpoint credential, can take several minutes to take effect, and until then the stream keeps its previous settings. A stream you deactivate can keep sending for a few minutes.
- **Endpoint failures**: when an endpoint is unavailable or answers with an error, the log lines of that send do not reach it. When an S3 endpoint refuses the stream's credential, Real-Time Events records each send with status `503`. The log lines of those sends do not reach the endpoint, and the stream does not send them again after you fix the credential. For the causes and fixes, refer to [Troubleshoot Data Stream](/en/documentation/platform/data-stream/troubleshooting/).
- **Storage of the logs**: Data Stream does not store or query logs. [Real-Time Events](/en/documentation/platform/real-time-events/) holds your products' raw events for 7 days and Activity History events for 2 years. Your endpoint keeps what a stream sends for as long as you decide.

## Default limits

Every value in this table applies to each stream or to the account that holds it. The API answers a request past a field bound with `400` and an `errors` array, and creates nothing.

| Scope | Limit | Past the limit |
| --- | --- | --- |
| Batch of log lines | 2,000 records or 60 seconds, whichever comes first. A record is one log line. For *Standard HTTP/HTTPS POST*, the batch also closes at **Payload Max Size**, in bytes. | The stream sends the batch to the endpoint. A stream with little traffic sends small batches. |
| Batch of log lines for *AWS Kinesis Data Firehose* | 500 records or 60 seconds, whichever comes first | The stream sends the batch to the endpoint. |
| **Payload Max Size**, `outputs[0].attributes.max_size` on a `standard` endpoint | 1,000,000 bytes or more. The Console fills in `1000000`. | A value below `1000000` is refused with `10050` `Min Value`. |
| Send timeout for an HTTP POST endpoint | 20 seconds | When the endpoint passes the availability check but does not receive the batch within 20 seconds, the send ends with status `504`. |
| Endpoint availability check | Once a minute. Every Azion server must report the endpoint available. | While the endpoint is unavailable, Data Stream does not send to it and discards the logs of that interval. Real-Time Events records the attempt with status `503`. The check runs again the next minute. |
| Endpoints per stream | 1 | When `outputs` holds two endpoints of the same type, the API answers `201` and keeps the last one. With an S3 and a Standard HTTP/HTTPS POST endpoint, it answers `500`. |
| Active streams right after you save an active stream with sampling on Applications, Functions, or WAF Events | That stream, plus any Activity History streams | Saving that stream as active deactivates every other stream except Activity History streams, with no API error. A rate of `100` counts as sampling. The Console warns before saving. |
| Stream `name` | 1 to 100 characters | A longer name is refused with `10046` `Max Length`. |
| Sampling rate, `transform[sampling].attributes.rate` | 1 to 100, an integer percentage | `0` is refused with `10050` `Min Value`, and `101` with `10068` `Max Value`. |
| Workload filter, `transform[filter_workloads].attributes.workloads` | 1 to 600 workload IDs, each a Workload on the account | A list outside the range is refused. An ID that is not a Workload on the account is refused with `32003` `Workloads Not Belong Account`. |
| Workloads on the account, for Azion Console | Fewer than 3,000 | At 3,000 Workloads or more, the Console blocks the create and edit forms, and the account manages its streams through the API only. |

To run several streams on Applications, Functions, or WAF Events at once, give each one a `filter_workloads` item instead of sampling. For the error codes and their fixes, refer to [Stream settings](/en/documentation/platform/data-stream/stream-settings/#errors).

Further bounds apply:

- Delivery of the logs to your infrastructure takes up to 3 minutes.
- On a `standard` endpoint, `payload_format` takes up to 250 characters, `log_line_separator` up to 100, and `max_size` up to 2,147,483,647 bytes.
- The Console accepts up to five **Custom Headers** on a *Standard HTTP/HTTPS POST* endpoint.
- A template's `data_set` takes up to 65,535 characters, and its `name` up to 100.
- An *AWS Kinesis Data Firehose* `stream_name` takes up to 64 characters.
- An *Apache Kafka* `kafka_topic` and `bootstrap_servers`, and an S3 `bucket_name`, each take up to 150 characters.

For the bounds of every endpoint field, refer to [Endpoints](/en/documentation/platform/data-stream/endpoints/).

## Usage records

[Real-Time Events](/en/documentation/platform/real-time-events/data-sources/#data-stream) records each send of a stream with the number of log lines in `streamedLines` and the size in bytes in `dataStreamed`. The size of a log line depends on the template and the event. To read the account's consumption, refer to [Query Data Stream usage data](/en/documentation/guides/platform/observability/query-data-stream-usage-data-with-graphql/). For the per-unit rates, refer to [Pricing](/en/documentation/fundamentals/pricing/#data-stream).
