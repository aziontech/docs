[Real-Time Events](/en/documentation/platform/real-time-events/) uses the terms in this glossary with a meaning of its own.

| Term | Definition |
| --- | --- |
| Activity History | One of the eight Real-Time Events data sources. It holds one record per action performed on an Azion account, as [Activity History](/en/documentation/fundamentals/activity-history/) registers it, and keeps that record for 2 years. For the variables the record carries, refer to [Data sources](/en/documentation/platform/real-time-events/data-sources/#activity-history). |
| Data Scan | One of the two metrics Real-Time Events is billed on, charged per GB. It measures the volume of data a query reads, so a search over a wide period scans more than a narrow one. For the amount included each month, refer to [Limits](/en/documentation/platform/real-time-events/limits/). |
| data source | The Azion product or service that produced the events you query. On a query it is the index the records are read from, so every search selects one. [Data sources](/en/documentation/platform/real-time-events/data-sources/) documents the eight Real-Time Events exposes and the variables each one carries. |
| dataset | The name the Real-Time Events GraphQL API gives a data source, and the word the newer Azion Console view uses for it. A dataset names its fields in camelCase, so the variable `Remote Address` in the classic Azion Console view is the field `remoteAddress` in a query, and a [Data Stream](/en/documentation/platform/data-stream/) payload writes the same field in snake_case. [Real-Time Events GraphQL API fields](/en/documentation/devtools/graphql/gql-real-time-events-fields/) lists every dataset and its fields. |
| event record | One entry a data source holds: the set of variables a product wrote for a single event, such as one request, one DNS query, or one action on an account. [How Real-Time Events works](/en/documentation/platform/real-time-events/how-it-works/) follows a record from the product that writes it to the query that reads it. To open one and read its variables, refer to [Read an event record](/en/documentation/guides/platform/observability/understand-logs/). |
| GraphiQL Playground | The in-browser client the Real-Time Events GraphQL API serves at `https://api.azion.com/v4/events/graphql`, where you compose and run a query against a dataset. To get a token and send a first query, refer to [GraphQL API first steps](/en/documentation/devtools/graphql/first-steps/). |
| retention | How long Real-Time Events keeps an event record queryable. Records are kept for 7 days, equal to 168 hours, and Activity History records for 2 years. [Limits](/en/documentation/platform/real-time-events/limits/) carries both values and the bounds a query carries. |
| Storage | One of the two metrics Real-Time Events is billed on, charged per GB. It measures the volume of event records kept. For the amount included each month, refer to [Limits](/en/documentation/platform/real-time-events/limits/). |
| time filter | The bound on the period a search covers, applied on top of the data source: the data source decides which records are read, and the time filter decides how far back the search reaches. A custom range reaches back as far as retention allows. [Data sources](/en/documentation/platform/real-time-events/data-sources/#time-filter) describes how the two combine. |
| variable | The name the classic Azion Console view gives one field of an event record. Each data source carries its own set, so the variables on an HTTP Requests record differ from the ones on an Edge DNS record. [Data sources](/en/documentation/platform/real-time-events/data-sources/) lists the variables of all eight, and [Filter events](/en/documentation/guides/platform/observability/add-filters-events/) shows how a search narrows on one. |
