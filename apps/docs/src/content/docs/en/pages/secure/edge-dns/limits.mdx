This page states where [Edge DNS](/en/documentation/platform/edge-dns/) stops and the default limits on the fields of a zone and on the fields and values of a record. For the usage each plan includes, refer to [Azion pricing](https://www.azion.com/en/pricing/). To request an increase, contact the [technical support](/en/documentation/support/) team.

---

## Scope

- **Authoritative only**: Edge DNS answers the queries for the domains its zones hold, and it resolves no other name. A query for any other domain gets `REFUSED`, so your users keep their own resolvers, as [How Edge DNS works](/en/documentation/platform/edge-dns/how-it-works/#the-resolution-path) shows.
- **Record types**: a zone holds 11 record types, A, AAAA, ANAME, CAA, CNAME, DS, MX, NS, PTR, SRV, and TXT, as [Record types](/en/documentation/platform/edge-dns/record-types/) describes. The API refuses any other type, such as `SOA`, with `10039`. Azion writes each zone's SOA record and the NS records of its apex itself, as [How Edge DNS works](/en/documentation/platform/edge-dns/how-it-works/#aname-at-the-apex) shows.
- **Apex**: a CNAME record is refused at the apex, the zone's domain itself, with `19005`. An ANAME record points the apex at a hostname instead: it answers as an A record, and its target must be under `azioncdn.net`, `azionedge.net`, or `azionedge.com`. For the steps, refer to [Point an apex domain with ANAME](/en/documentation/guides/application-security/dns/access-root-domain/).
- **Weighted policy**: weights share answers, not requests. Each nameserver keeps the answer it picked for the record's TTL or a few minutes, whichever is shorter. Each resolver then keeps that answer for the TTL it receives, so the shares even out only over many lookups, as [How Edge DNS works](/en/documentation/platform/edge-dns/how-it-works/#record-policies) explains. The policy applies to A, AAAA, ANAME, CNAME, and MX records, and the API refuses it on the other types with `19017`.
- **Nameservers**: the same three nameservers, `ns1.aziondns.net`, `ns2.aziondns.com`, and `ns3.aziondns.org`, serve every zone, and the API returns them read-only. Delegate the domain to all three at its registrar, as [Zones and records](/en/documentation/platform/edge-dns/zones-and-records/#nameservers-and-soa) shows.
- **Propagation**: a saved zone or record needs no deployment step, and each nameserver answers from a cache, as [How Edge DNS works](/en/documentation/platform/edge-dns/how-it-works/#caching-and-propagation) explains. A new zone or record can take about a minute to answer on every nameserver, and a change to an existing record can take a few minutes. A query for a name before it answers caches `NXDOMAIN` on that nameserver for up to one hour, the SOA minimum, so wait about a minute after you save a new name before you query it.
- **Observability**: the queries your zones receive appear as counts in the [Real-Time Metrics Edge DNS dashboard](/en/documentation/platform/real-time-metrics/secure-dashboards/#edge-dns), as one record per query in [Real-Time Events](/en/documentation/platform/real-time-events/data-sources/#edge-dns), and in both forms through the [GraphQL API](/en/documentation/devtools/graphql/features/#datasets).
- **DDoS protection**: [DDoS Protection](/en/documentation/platform/workloads/ddos-protection/ddos-mitigation/) also protects the DNS service, and the attacks it mitigates include DNS floods, even of well-formed queries. It is always on and needs no configuration.
- **Domain registration**: the domain stays registered at your registrar, where you set its nameservers and renew it, and you keep its zones and records correct. Azion may remove zones that are not in use, as the [Terms of Service](/en/documentation/agreements/tos/) state.

## Default limits

Each value below applies to one zone, one record, or one list request. A request past an API bound returns `400` with an `errors` array, and the zone or record stays as it was. Each API error is quoted as its code, its title, and its `detail` sentence.

| Scope | Limit | Past the limit |
| --- | --- | --- |
| Zone `name` | 1 to 50 characters | `10046` `Max Length`: `Ensure this field has no more than 50 characters.` |
| Zone `domain` | Up to 200 characters, the bound the API declares. The domain must end in a valid top-level domain, be hosted by no other zone in Azion, and sit under no domain that another account hosts. It is fixed at creation. | `19035` `Invalid Domain TLD`: `Your domain must use a valid TLD.` When a zone in any account already hosts the domain, `10012` `Unique Field`: `This field must be unique.` When the domain is a subdomain of a domain that another account hosts, `19001` `Domain Already In Use`: `Domain Belongs to Another Account.` An update that sends `domain` gets `19036` `Domain Cannot Be Modified`: `The domain cannot be changed in update operations. Please create a new record instead.` In the Console, a domain whose last label is not 2 to 63 letters, or whose other labels hold anything but letters, digits, and hyphens, shows `Invalid domain`. |
| Record `name` | Up to 255 characters | `10046` `Max Length`: `Ensure this field has no more than 255 characters.` |
| Label in a record `name` | Up to 63 characters per dot-separated label | `10076` `Invalid Pattern Match.` |
| Record `ttl`, in the API | 1 to 2,147,483,647 seconds | `0` gets `10050` `Min Value`: `Ensure this value is greater than or equal to 1.` A value above 2,147,483,647 gets `10068` `Max Value`: `Ensure this value is less than or equal to 2147483647.` |
| **TTL (seconds)**, in the Console | 1 to 604,800 seconds. The field pre-fills `3600`. | The field accepts `0`, and the API then refuses the record with `10050` `Min Value`: `Ensure this value is greater than or equal to 1.` |
| `ttl` of an ANAME record | `20` only. The Console pre-fills 20 when you select ANAME. | Any other value, including the default `3600`, gets `19011` `Invalid TTL For QTYPE`: `The TTL value is not valid for the selected record type.` |
| Values in one A, AAAA, ANAME, DS, MX, or NS record | Up to 10 values in `rdata` | `19007` `Invalid RData Size`: `The 'rdata' cannot contain more than 10 items for the selected record type.` |
| Values in one CNAME or PTR record | Exactly 1 value in `rdata` | `19006` `Invalid RData For CNAME Record`: `The 'rdata' cannot contain more than one item when 'type' is 'CNAME'.` A PTR record gets the same code, title, and detail. |
| Values in one TXT, CAA, or SRV record | More than 10 values are accepted | No 10-value bound applies. |
| SRV records on one name | 1 record. Its values have no 10-value bound. | A second SRV record on the name gets `19004` `Record Already Exists`: `There is already another record matching those data.` |
| TXT value | Up to 1,000 characters per value | `19024` `Invalid TXT Record Answer Size`: `You need to provide an answer with less than 1000 characters.` A value of exactly 1,000 characters is accepted. |
| Record `weight` | 0 to 255. A record with weight `0` is kept and never answered. | `10068` `Max Value`: `Ensure this value is less than or equal to 255.` |
| Record `description` | Up to 45 characters | `10046` `Max Length`: `Ensure this field has no more than 45 characters.` The Console **Description** helper states the 45-character limit but does not check it, so the API refuses the longer value on **Save**. |
| Items per list page, `page_size` | Up to 100 | `10097` `Invalid Page Size`: `Page size must be between 0 and 100.` |

To read a list longer than one page, set `page_size` to 100 and move through the pages with the `page` query parameter. For each error and its fix, refer to [Zones and records](/en/documentation/platform/edge-dns/zones-and-records/#errors).
