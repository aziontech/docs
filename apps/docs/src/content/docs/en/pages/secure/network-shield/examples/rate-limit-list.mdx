You can hold the clients in a [Network List](/en/documentation/platform/firewall/network-shield/network-lists/) to a request rate, with one rule of a [Firewall](/en/documentation/platform/firewall/), from Azion Console, the [Azion CLI](/en/documentation/devtools/cli/), or the API. To refuse those addresses instead of slowing them, refer to [Block requests by IP, ASN, or country](/en/documentation/guides/application-security/bots-and-network/blocklists-ip-addresses-edge/).

## Create the list of addresses to limit

The addresses to limit go in a list of the `ip_cidr` type, shown as _IP/CIDR_ in Azion Console. Its items are addresses and ranges, such as `203.0.113.0/24` and `198.51.100.7`. The rule stores the ID of the list rather than its items. An address you add to the list or remove from it therefore changes which clients are limited, and the rule needs no edit. For every field and type a list accepts, refer to [Network list fields](/en/documentation/platform/firewall/network-shield/network-lists/#network-list-fields) and [List types](/en/documentation/platform/firewall/network-shield/network-lists/#list-types).

<Tabs client:visible sharedStore="interface">

<Fragment slot="panel.console">

### Console

To create the list in Azion Console:

<DocSteps>
  <DocStep title="Open the Network Lists page">

  Access [Azion Console](https://console.azion.com/) > **Network Lists**.

  </DocStep>
  <DocStep title="Select Network List" />
  <DocStep title="Name the list">

  In the **General** section, enter a **Name**. For example: `Rate-limited addresses`.

  </DocStep>
  <DocStep title="Select the IP/CIDR type">

  In the **Network List Settings** section, select _IP/CIDR_. When the form opens, _ASN_ is the selected type.

  </DocStep>
  <DocStep title="Enter the addresses to limit">

  In the **List** field, enter each address or range on its own line. For example: `203.0.113.0/24` and `198.51.100.7`.

  </DocStep>
  <DocStep title="Save the list">

  Select **Save**.

  </DocStep>
</DocSteps>

Azion Console confirms with the message `Your network list has been created`. The list `Rate-limited addresses` then appears in **Network Lists**.

</Fragment>

<Fragment slot="panel.cli">

### CLI

To create the list with the Azion CLI, write it to a file named `network-list.json`:

```json
{"name":"Rate-limited addresses","type":"ip_cidr","items":["203.0.113.0/24","198.51.100.7"],"active":true}
```

Create the list from that file:

```bash
azion create network-list --file network-list.json
```

The output carries the ID of the list:

```text
Created Network List with ID <network-list-id>
```

Keep that ID, because the rule refers to `Rate-limited addresses` by it.

</Fragment>

<Fragment slot="panel.api">

### API

To create the list with the API, send it in a `POST` request to `/v4/workspace/network_lists`. Put your personal token in place of `[TOKEN VALUE]`:

```bash
curl -X POST https://api.azion.com/v4/workspace/network_lists \
  -H "Authorization: Token [TOKEN VALUE]" \
  -H "Accept: application/json" \
  -H "Content-Type: application/json" \
  -d '{"name":"Rate-limited addresses","type":"ip_cidr","items":["203.0.113.0/24","198.51.100.7"]}'
```

The API answers `201`. Its `state` of `executed` says the list was stored at once:

```json
{
  "state": "executed",
  "data": {
    "id": <network-list-id>,
    "name": "Rate-limited addresses",
    "type": "ip_cidr",
    "items": ["203.0.113.0/24", "198.51.100.7"],
    "last_editor": "<your-email>",
    "last_modified": "2026-01-01T12:00:00.000000Z",
    "created_at": "2026-01-01T12:00:00.000000Z",
    "active": true,
    "version_id": null,
    "version_state": null,
    "is_versioned": false,
    "version": null
  }
}
```

Keep the value of `data.id`. The rule takes it as the argument of its criterion.

</Fragment>

</Tabs>

## Create the rule that rate-limits the list

The rule joins the _Network_ criterion, with its _matches_ operator, to the _Set Rate Limit_ behavior. Only a client in the list makes that criterion true, so only those clients are limited. A request from any other client leaves the criterion false: the rule applies nothing, and the Firewall goes on to its next rule. The behavior in this guide allows each client IP address an average of `10` requests per second, with a burst of `10`. For what each field of the behavior counts, refer to [Set Rate Limit](/en/documentation/platform/firewall/rules-engine/#set-rate-limit).

<Tabs client:visible sharedStore="interface">

<Fragment slot="panel.console">

### Console

To create the rule that rate-limits the list in Azion Console:

<DocSteps>
  <DocStep title="Open the Firewall that your Workload's deployment sets">

  Access [Azion Console](https://console.azion.com/) > **Firewalls**, and select the Firewall.

  </DocStep>
  <DocStep title="Select the Rules Engine tab" />
  <DocStep title="Select Rule">

  Azion Console opens the **Create Rule** drawer.

  </DocStep>
  <DocStep title="Name the rule">

  In the **General** section, enter a **Name**. For example: `Rate-limit listed addresses`.

  </DocStep>
  <DocStep title="Set the Network criterion">

  In the **Criteria** section, select the _Network_ variable and the _matches_ operator.

  A variable that reads _Network - required Network Shield_ means that Network Shield is off on this Firewall. Turn it on in **Main Settings** > **Modules** and save the Firewall, and the variable becomes selectable.

  </DocStep>
  <DocStep title="Select your list">

  In the **Select a Network** dropdown, select the list of addresses to limit. For example: `Rate-limited addresses`.

  </DocStep>
  <DocStep title="Add the Set Rate Limit behavior">

  In the **Behaviors** section, select _Set Rate Limit_. **Rate Limit Type** starts at _Req/s_ and **Limit By** at _Client IP address_. Keep both values.

  </DocStep>
  <DocStep title="Set the average rate">

  In **Average Rate Limit**, enter `10`.

  </DocStep>
  <DocStep title="Set the burst size">

  In **Maximum Burst Size**, enter `10`.

  </DocStep>
  <DocStep title="Save the rule">

  Select **Save**.

  </DocStep>
</DocSteps>

Azion Console confirms with the message `Rule successfully created`. In the **Rules Engine** tab, the **Status** column of the rule reads _Active_.

</Fragment>

<Fragment slot="panel.cli">

### CLI

`azion create firewall-rule` takes the rule only as a JSON file, through `--file`, next to `--firewall-id`. To create it with the Azion CLI, write it to a file named `rule.json`. Put the ID of your list in place of `<network-list-id>`, as a number with no quotes:

```json
{
  "name": "Rate-limit listed addresses",
  "active": true,
  "criteria": [
    [
      { "variable": "${network}", "conditional": "if", "operator": "is_in_list", "argument": <network-list-id> }
    ]
  ],
  "behaviors": [
    {
      "type": "set_rate_limit",
      "attributes": {
        "type": "second",
        "limit_by": "client_ip",
        "average_rate_limit": 10,
        "maximum_burst_size": 10
      }
    }
  ]
}
```

Create the rule from that file on your Firewall. Put the ID of that Firewall in place of `<firewall-id>`:

```bash
azion create firewall-rule --firewall-id <firewall-id> --file rule.json
```

The output carries the ID of the rule:

```text
Created Firewall Rule with ID <rule-id>
```

The rule is active on the Firewall, and it limits the clients in `Rate-limited addresses` once it reaches traffic.

</Fragment>

<Fragment slot="panel.api">

### API

To create the rate-limit rule with the API, send a `POST` request to `/v4/workspace/firewalls/{firewall_id}/request_rules`. Write the ID of your Firewall in place of `<firewall-id>`. Put `data.id` from the list response in place of `<network-list-id>`, as a number with no quotes:

```bash
curl -X POST https://api.azion.com/v4/workspace/firewalls/<firewall-id>/request_rules \
  -H "Authorization: Token [TOKEN VALUE]" \
  -H "Accept: application/json" \
  -H "Content-Type: application/json" \
  -d '{
  "name": "Rate-limit listed addresses",
  "active": true,
  "criteria": [
    [
      { "variable": "${network}", "conditional": "if", "operator": "is_in_list", "argument": <network-list-id> }
    ]
  ],
  "behaviors": [
    {
      "type": "set_rate_limit",
      "attributes": {
        "type": "second",
        "limit_by": "client_ip",
        "average_rate_limit": 10,
        "maximum_burst_size": 10
      }
    }
  ]
}'
```

The API answers `202`, with a `state` of `pending` and the `id` of the rule it created.

</Fragment>

</Tabs>

:::note
In the JSON body of the CLI and the API, `${network}` names the _Network_ criterion and `is_in_list` its _matches_ operator. The `attributes` of `set_rate_limit` set `type` to `second`, which is _Req/s_ in Azion Console, and `limit_by` to `client_ip`, which is _Client IP address_. A list ID sent as a string, such as `"<network-list-id>"` in quotes, is refused with `400` and `25042 Invalid Operator Argument Type`. A Firewall with Network Shield off refuses the rule with `25047 Missing Required Modules`, because of its _Network_ criterion. For the operators of the criterion, refer to [The Network criterion](/en/documentation/platform/firewall/network-shield/network-lists/#the-network-criterion).
:::

## Confirm that the rate limit applies to listed clients

A rule you add reaches traffic several minutes after you save it, and no [propagation](/en/documentation/platform/firewall/how-it-works/#propagation) duration is guaranteed. Until it does, the rule limits no client. Send the requests again until they answer as expected.

_Set Rate Limit_ does not refuse a request over the rate at once. For example, with a rate of one request per second and a burst of `1`, requests that match one after another are each held about one second, then served. Only concurrent requests beyond the burst receive `429`, so a check that sends one request at a time can get no `429` at all. For how the burst queues requests, refer to [Rate limits](/en/documentation/platform/firewall/how-it-works/#rate-limits).

A refused request from a listed client receives `HTTP 429` and Azion's default error page, headed **Too Many Requests**. With a per-second rate, the response carries `retry-after: 1`, and no `x-ratelimit-` header. The response looks like this:

```text
HTTP/2 429
server: nginx
date: Thu, 01 Jan 2026 12:00:00 GMT
content-type: text/html; charset=utf-8
retry-after: 1
content-security-policy: default-src 'none'; style-src 'unsafe-inline' https://fonts.googleapis.com; font-src https://fonts.gstatic.com; img-src 'self' data:; base-uri 'none'; form-action 'none'; frame-ancestors 'none'
x-content-type-options: nosniff
x-azion-request-id: <request-id>
x-azion-edge-location: <edge-location>
alt-svc: h3=":443"; ma=86400

<title>Azion - Default error page</title> ... Too Many Requests ... Status Code 429
```

The rule limits whichever clients the list holds when a request arrives. A change to the items of the list reaches traffic within a few minutes, sooner than a rule you add. Until it settles, answers can switch between the old items and the updated ones, so repeat a request until the answers agree.
