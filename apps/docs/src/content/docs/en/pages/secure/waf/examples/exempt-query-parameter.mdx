You can create a WAF exception that stops one internal rule scoring the query string values on one path from Azion Console, the Azion CLI, or the API. For an exception on the request headers, refer to [Exempt request headers from one WAF rule](/en/documentation/guides/application-security/firewall-and-waf/exempt-request-header/).

The examples stop rule `1013`, the apostrophe rule, scoring the query string of the requests to `/search`, on the rule set `<waf-id>`. Replace them with your rule, path, and rule set.

## Create the exception

The condition is _Any Query String Value_, `any_query_string_value` in the API, which covers the value of every query string argument. A condition that names one argument, _Specific Query String Name_, is accepted, and in tests it did not clear a match on the argument it named.

A narrower condition carries the argument name in **Value**: _Specific Query String Value_, `specific_query_string_value` in the API. In another test, with rule `1013` and the argument `filter` in **Value**, it cleared the match on `filter` only. Another argument on the same path was still refused, and the argument's value in **Value** cleared nothing.

<Fragment slot="panel.console">

### Console

To create the exception in Azion Console:

<DocSteps>
  <DocStep title="Open the WAF Rules page">

  Access [Azion Console](https://console.azion.com/) > **WAF Rules**.

  </DocStep>
  <DocStep title="Select the rule set that blocked the request" />
  <DocStep title="Open the Allowed Rules tab and select + Allowed Rule" />
  <DocStep title="Select the rule to exempt">

  In **Rule ID**, select `1013`.

  </DocStep>
  <DocStep title="Describe the exception and restrict it to one path">

  In **Description**, enter `Allow apostrophes in the storefront search`. In **Path**, enter `/search`.

  </DocStep>
  <DocStep title="Select the part of the request">

  In **Condition**, select _Any Query String Value_. Keep the **Active** switch of the **Regex** section off, so the strings are compared as text.

  </DocStep>
  <DocStep title="Select Save" />
</DocSteps>

The **Allowed Rules** tab lists the exception.

</Fragment>

<Fragment slot="panel.cli">

### CLI

To create the exception with the Azion CLI, save it as `exception.json`:

```json
{
  "rule_id": 1013,
  "name": "Allow apostrophes in the storefront search",
  "path": "/search",
  "operator": "contains",
  "active": true,
  "conditions": [
    { "match": "any_query_string_value" }
  ]
}
```

Then create the exception from the file:

```bash
azion create waf-exceptions --waf-id <waf-id> --file exception.json
```

The command prints the ID of the new exception:

```text
Created WAF Exception with ID <exception-id>
```

Pass the body with `--file`. On Azion CLI 4.26.2, the `--conditions` flag sends an empty array whatever value it holds, and the API refuses it with `10049 Min Length List Field`.

</Fragment>

<Fragment slot="panel.api">

### API

To create the exception with the API, send a `POST` request to the exceptions endpoint of the rule set:

```bash
curl --request POST \
  --url https://api.azion.com/v4/workspace/wafs/<waf-id>/exceptions \
  --header 'Accept: application/json' \
  --header 'Authorization: Token [TOKEN VALUE]' \
  --header 'Content-Type: application/json' \
  --data '{
  "rule_id": 1013,
  "name": "Allow apostrophes in the storefront search",
  "path": "/search",
  "operator": "contains",
  "active": true,
  "conditions": [
    { "match": "any_query_string_value" }
  ]
}'
```

The API answers `202` and returns the exception:

```json
{
  "state": "pending",
  "data": {
    "id": <exception-id>,
    "rule_id": 1013,
    "name": "Allow apostrophes in the storefront search",
    "path": "/search",
    "conditions": [
      { "match": "any_query_string_value" }
    ],
    "operator": "contains",
    "active": true,
    ...
  }
}
```

</Fragment>

</Tabs>

Rule `1013` stops scoring the query string values of the requests to `/search`. In a test, the exception cleared the rule on a request to its path, and the same apostrophe in the query string still received `400` on another path. Send a request that the rule matched before, and check that it now passes.

:::caution
An exception also clears what the rule caught in attacks. In the same test, at the `highest` sensitivity, the injection `1' OR '1'='1` passed on the exempted path: without rule `1013`, it scored `2` for SQL injection, below the threshold.
:::

:::note[Note]
In tests, an exception took effect several minutes after it was created, and until then the answers alternated. Under `contains`, the exception applied to its exact `path`: a longer path that started with it still received `400`. `rule_id` defaults to `0`, which is every internal rule, so set it to the rule that matched.
:::
