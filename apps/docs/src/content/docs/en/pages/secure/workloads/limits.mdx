[Workloads](/en/documentation/platform/workloads/) is a Platform Resource that receives the requests sent to your domains, as their entry point, on Azion's distributed infrastructure. After it receives a request, a Workload forwards the request to the [Application](/en/documentation/platform/applications/) that this Workload's deployment sets. The deployment can also set the [Firewall](/en/documentation/platform/firewall/) that inspects requests first and the custom page set that replaces error responses. This page states where a Workload stops and the bounds Azion applies to it.

Each limit on this page is checked on every call, and the call fails past it.

A service plan also includes an amount of usage before a rate applies. That amount is a billing quantity: passing it changes what the account is charged rather than what the call returns. [Azion pricing](https://www.azion.com/en/pricing/) lists the plans and the usage each one includes. For the rates, refer to [Pricing](/en/documentation/fundamentals/pricing/#workloads).

## Scope

- **Domains**: a Workload answers on its workload domain, `<id>.map.azionedge.net` on production and `<id>.preview.azionedge.net` on staging, as soon as its deployment propagates, before you own any domain. Each domain you add points at the workload domain with a CNAME record. A production Workload can also answer on an `azion.app` hostname, which Azion Console labels **Azion Custom Domain**. For every rule a hostname follows, refer to [Workload settings](/en/documentation/platform/workloads/settings/#domains), and for the DNS records, refer to [Point a domain to a workload](/en/documentation/guides/platform/migration/point-domain-to-azion/).
- **Access to the workload domain**: with `workload_domain_allow_access` set to `false`, the workload domain answers `404`, and the Workload answers only on the hostnames in `domains`. That value fits a Workload whose own domains already serve traffic, and the API accepts it only while `domains` holds at least one hostname. For the order of that change, refer to [Workloads best practices](/en/documentation/platform/workloads/best-practices/#close-the-workload-domain-once-your-own-domain-serves-traffic).
- **DNS**: a Workload holds no DNS records. A domain's zone stays at your DNS provider, or in [Edge DNS](/en/documentation/platform/edge-dns/), and the Workload answers the hostnames it lists wherever their zone is hosted.
- **Infrastructure**: a Workload runs on the production network, for global availability, or on the staging network, for testing with limited propagation. The choice is fixed at creation, and a staging Workload takes no custom domain. For example, a configuration tested on a staging Workload reaches production as a second Workload, created on the production infrastructure. For the choice in each interface, refer to [Workload settings](/en/documentation/platform/workloads/settings/#infrastructure).
- **TLS**: the Transport Layer Security (TLS) settings of a Workload secure the connection from the client to Azion, while the connection to your origin is set on the [Connector](/en/documentation/platform/connectors/). The [Azion SAN certificate](/en/documentation/platform/certificate-manager/glossary/) covers the workload domain and the `azion.app` hostname, so a domain of your own needs a server certificate. Azion blocks TLS renegotiation by default. For the TLS versions and the cipher suites, refer to [Workload settings](/en/documentation/platform/workloads/settings/#tls).
- **mTLS**: with mutual TLS (mTLS) on, a Workload checks client certificates only on HTTPS connections, against a [Trusted CA certificate](/en/documentation/platform/certificate-manager/glossary/), in `enforce` or `permissive` mode. For both modes and every requirement, refer to [mTLS](/en/documentation/platform/workloads/mtls/).
- **Certificates and custom pages**: a Workload presents the certificates you bind from [Certificate Manager](/en/documentation/platform/certificate-manager/), and its deployment can set a custom page set from [Custom Pages](/en/documentation/platform/custom-pages/). The bounds on a certificate, a private key, a certificate revocation list (CRL), a custom page set, and its pages are on [Certificate Manager limits](/en/documentation/platform/certificate-manager/limits/) and [Custom Pages limits](/en/documentation/platform/custom-pages/limits/).
- **Deployment**: a Workload created through the API or Azion CLI starts with no deployment. The published API v4 reference has no endpoint for the deployment, so Azion Console, Azion CLI, and [Terraform](/en/documentation/devtools/terraform/workloads/) write it. For its fields, refer to [Workload settings](/en/documentation/platform/workloads/settings/#deployment).
- **Propagation**: a saved change to a Workload or its deployment takes several minutes to reach all of Azion's distributed infrastructure, with no guaranteed duration. Meanwhile, requests can receive the old or the new configuration, so repeat a request until the answers agree. For example, right after you turn on mTLS in `enforce` mode, some data centers still answer a client with no certificate. For more information, refer to [Propagation](/en/documentation/platform/workloads/how-it-works/#propagation).
- **Observability**: Azion's error page carries an `x-azion-request-id` header that identifies the request. [Data Stream](/en/documentation/platform/data-stream/) collects the events of the Workloads you associate with a stream, as [Associate workloads with a stream](/en/documentation/guides/platform/observability/data-stream-associate-workloads/) shows.

## Workloads

The bounds in this section apply to every Workload, on every service plan, unless a table names a plan. They cover what a Workload holds: its workload domain and the domains you add, its Transport Layer Security (TLS) and mutual TLS (mTLS) settings, its ports and HTTP versions, its infrastructure, and at most one deployment.

### Default limits

The API refuses a call past each bound in this table with the message in the Past the limit column. The Azion CLI prints that message inside `Error: Failed to update the Workload: [...]`, `Error: Failed to create the Workload: [...]`, or `Error: Failed to create the Workload Deployment: [...]`, followed by `Check your settings and try again. If the error persists, contact Azion support.`

| Scope | Limit | Past the limit |
| --- | --- | --- |
| Workload `name` | Up to 100 characters | `Ensure this field has no more than 100 characters.` |
| Deployments per Workload | 1 | `The maximum number of deployments allowed per workload is 1.` |
| `azion.app` domains per Workload | 1, whether two entries repeat one name or carry two names | `Duplicated usage of suffix in alternate_domains: 'azion.app'.` |
| An `azion.app` domain another Workload holds | Not available to a second Workload | `The custom hostname is not available.` |
| Format of a `domains` entry | A full hostname that conforms to RFC 1035; a wildcard such as `*.azion.app` is refused | `The domain does not conform to the format defined in RFC 1035.` |
| HTTP ports | `80`, `8008`, `8080`, and `8880` only | `Invalid choices for multiple choices field: [80, 8008, 8080, 8880].` |
| HTTP versions with `http3` | `versions` also holds `http1` and `http2` | `Missing required choices for multiple choices field: ['http1', 'http2'].` |
| Cipher suite, `tls.ciphers` | `1` to `8` | `"9" is not a valid choice.` The message quotes the value sent. |
| Infrastructure | Fixed at creation | `The infrastructure cannot be changed after Workload creation.` |
| Custom domains on a staging Workload | None; a staging Workload answers on its workload domain only | `Custom hostname is not available in the environment 'Staging Infrastructure'.` |

An `azion.app` domain belongs to one Workload in one account and cannot be shared between accounts or configurations. For example, to move an `azion.app` domain to a new Workload, remove it from the Workload that holds it first.

Five further bounds apply: a Workload lists up to 50 domains by default, `http_ports` holds 1 to 4 entries, `https_ports` holds 1 to 12 entries, `quic_ports` holds up to 12 entries, and `mtls.config.crl` lists up to 100 CRLs. For the 12 HTTPS ports a Workload accepts, refer to [Workload settings](/en/documentation/platform/workloads/settings/#protocols-and-ports).

The port bounds apply to the ports a Workload listens on. The port Azion connects to on your origin is set on a [Connector](/en/documentation/platform/connectors/), and it can be any port that exists on the origin. For the delivery and origin port combinations, refer to [Configure HTTP and HTTPS ports](/en/documentation/guides/application-development/getting-started/configure-ports/).

Azion raises the limit of 50 domains per Workload on request, based on your plan. To request an increase, contact the [technical support](/en/documentation/support/) team.
