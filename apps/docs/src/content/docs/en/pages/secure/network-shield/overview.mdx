**Network Shield** is a Platform Resource nested in [Firewall](/en/documentation/platform/firewall/) that matches the requests to your [Workloads](/en/documentation/platform/workloads/) by client address, before your [Application](/en/documentation/platform/applications/) receives them. A network-layer filter compares each client's address with lists of addresses, networks, or countries, and refuses the clients a policy excludes. Use Network Shield to block abusive addresses and networks, refuse countries you do not serve, or keep out every client outside your own networks.

Network Shield compares the client with one entity of its own:

- [Network Lists](/en/documentation/platform/firewall/network-shield/network-lists/) hold the IP addresses and ranges, Autonomous System Numbers (ASNs), or countries that a rule compares with the client. Keep each set of clients in one list, so that one change to its items reaches every rule that uses it.

## Request path

A Network List blocks nothing by itself. A Firewall rule uses the list through the _Network_ criterion, and the behaviors of that rule decide what happens to a client the list matches. That Firewall inspects only the requests to the Workloads whose deployments set it.

The diagram traces one request through a rule with the _Network_ criterion. Solid arrows carry the request, dotted arrows carry the response, and each label opens with its step number.

```mermaid

flowchart TD
  Client(["Client"])
  WL["Workload"]
  FW["Firewall"]
  NS["Network Shield"]
  App["Application"]
  Client -->|"1. request"| WL
  WL -->|"1. request"| FW
  FW -->|"2. client address"| NS
  NS -->|"3. match or no match"| FW
  FW -.->|"4. Firewall answer"| Client
  FW -->|"5. request"| App
  App -.->|"6. response"| Client
```

1. The request of a client reaches a Workload, whose deployment sets the Firewall and the Application. The Firewall inspects the request before the Application.
2. The Firewall runs its rules in order. A rule with the _Network_ criterion has Network Shield compare the client address with one Network List.
3. Network Shield reports whether the client is in the list. Under _matches_, the criterion is true for a listed client, and under _does not match_, it is true for a client outside the list.
4. When the criteria of the rule match, the rule applies its behaviors. _Deny (403 Forbidden)_, for example, answers the client with a refusal, and the rules after it never run.
5. When the criteria do not match, or no behavior ends the request, the Firewall moves to the next rule. The Application receives only the requests that every rule let through.
6. The Application answers, and its response reaches the client.

To see how one list becomes a blocklist or an allowlist, refer to [List matching](/en/documentation/platform/firewall/network-shield/list-matching/#client-address-comparison).
