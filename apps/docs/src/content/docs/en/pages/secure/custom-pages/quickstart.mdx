This guide instructs you through replacing the `404` your origin returns with your first page from [Custom Pages](/en/documentation/platform/workloads/#custom-pages).

- Create a custom page set with one page for status code `404`.
- Assign the set in the deployment of your [Workload](/en/documentation/platform/workloads/).
- Request a path your origin does not have and get your own page in its place.

Four elements take part, and each one leads to the next:

1. Your error page is at a path on the **Connector**. The Connector already exists. For more information, refer to [Connectors](/en/documentation/platform/connectors/).
2. The **custom page set** holds a page that replaces status code `404` with the content at that path on the Connector.
3. The **deployment** of the Workload sets the custom page set, next to the Application it already sets.
4. The **request** reaches a path that the Connector your Application uses answers with `404`, and the custom page set replaces that response.

A Workload uses a custom page set only once that Workload's deployment sets that custom page set. Then, when the Connector your Application uses answers `404`, the visitor receives the content of your page in place of that response. The response carries no redirect, and its status code is the one the page sets. This guide covers Azion Console and the API, and you assign the set in Azion Console. The Azion CLI has no command that updates a deployment, and the published API v4 reference has no endpoint for one.

## Create the custom page set

A custom page set is a named list of pages, and it needs at least one page. Each page replaces one status code with the content at a path on a Connector, and it can answer with a status code of its own. The page in this stage stays in cache for `0` seconds, its time to live (TTL), and answers with `404`.

<Tabs client:visible sharedStore="interface">

<Fragment slot="panel.console">

### Console

To create the set in Azion Console:

<DocSteps>
  <DocStep title="Open the Custom Pages page">

  Access [Azion Console](https://console.azion.com/) > **Custom Pages**.

  </DocStep>
  <DocStep title="Start a new set">

  Select **Create Custom Page**. The **Create Custom Page** page opens.

  </DocStep>
  <DocStep title="Name the set">

  In **Name**, enter a name for the set, such as `my-custom-pages`.

  </DocStep>
  <DocStep title="Add a page code">

  Select **+ Custom Page Code**.

  </DocStep>
  <DocStep title="Select the status code">

  In **Page Code**, select `404`.

  </DocStep>
  <DocStep title="Keep the Page Connector type">

  In **Type**, keep _Page Connector_.

  </DocStep>
  <DocStep title="Select your Connector">

  In **Connector**, select the Connector with your error page.

  </DocStep>
  <DocStep title="Enter the path of the page">

  In **Page Path (URI)**, enter the path of your page on the Connector, such as `/html`.

  </DocStep>
  <DocStep title="Set the cache time">

  In **Response TTL**, enter `0`.

  </DocStep>
  <DocStep title="Set the response status">

  In **Response Custom Status Code**, enter `404`.

  </DocStep>
  <DocStep title="Select Apply" />
  <DocStep title="Select Create" />
</DocSteps>

The set exists with one page for code `404`. It serves nothing until you assign it to your Workload. A set with no page code is refused with the message "You must have at least one custom page code".

</Fragment>

<Fragment slot="panel.api">

### API

To create the set with the API, send a `POST` request to the custom pages endpoint. Replace `[TOKEN VALUE]` with your personal token and `<connector-id>` with the ID of your Connector. Replace `/html` with the path of your page on the Connector:

<Code client:visible lang="bash" code={`curl --request POST \\
  --url https://api.azion.com/v4/workspace/custom_pages \\
  --header 'Accept: application/json' \\
  --header 'Authorization: Token [TOKEN VALUE]' \\
  --header 'Content-Type: application/json' \\
  --data '{"name": "my-custom-pages", "active": true, "pages": [
  {"code": "404", "page": {"type": "page_connector", "attributes": {"connector": <connector-id>, "ttl": 0, "uri": "/html", "custom_status_code": 404}}}
]}'`} />

The API answers with `202`, `"state": "pending"`, and the new set in `data`, its `id` included. A request with an empty `pages` list is refused with `Ensure this field has at least 1 elements.` Record the `id` of the new set to assign it to your Workload. The set exists with one page for code `404`, and it serves nothing until you assign it.

</Fragment>

</Tabs>

## Assign the set to your Workload

A Workload's deployment sets the Application that answers its requests, and it can also set a Firewall and a custom page set. A Workload holds at most one deployment, so you assign the custom page set by editing that deployment. The Application that the deployment already sets stays in place.

<Tabs client:visible sharedStore="interface">

<Fragment slot="panel.console">

### Console

To assign the set in Azion Console:

<DocSteps>
  <DocStep title="Open the Workloads page">

  Access [Azion Console](https://console.azion.com/) > **Workloads**.

  </DocStep>
  <DocStep title="Open your Workload">

  Select your Workload. The **Edit Workload** page opens.

  </DocStep>
  <DocStep title="Select the set">

  In **Deployment Settings**, select your set in **Custom Page**. Keep **Application** as it is.

  </DocStep>
  <DocStep title="Select Save" />
</DocSteps>

Azion Console shows the message "Your workload has been updated". The Workload's deployment sets your custom page set.

</Fragment>

<Fragment slot="panel.api">

### API

The published Azion API v4 reference has no endpoint for the deployment of a Workload. To assign the set, follow the Console panel.

</Fragment>

</Tabs>

## Request a page your origin answers with 404

The check is the same whichever interface assigned the set. In the command, replace `<your-workload-domain>` with the workload domain of your Workload, of the form `<id>.map.azionedge.net`. Replace `<missing-path>` with the path that the Connector your Application uses answers with `404`.

An assigned set does not serve at once. The change to the deployment spreads across Azion's distributed infrastructure, and that takes several minutes, with no guaranteed duration. While it spreads, a request can receive either your origin's `404` or your page. Repeat the request until your page answers. For more information, refer to [Propagation](/en/documentation/platform/workloads/how-it-works/#propagation).

Send a request to the missing path and print the response headers with the body:

<Code client:visible lang="bash" code={`curl -s -D - https://<your-workload-domain>/<missing-path>`} />

The response keeps status `404`, from the page's `custom_status_code`. Its body is the document at the page's path on your Connector. When that document is an HTML page, the response starts like this example, with your document as the body:

```text
HTTP/2 404 
content-type: text/html; charset=utf-8

<!DOCTYPE html>
<html>
  <head>
  </head>
  <body>
      <h1>Page not found</h1>
```

The response carries no `Location` header, so the client is not redirected. Your Workload answers a missing path with your own page.
