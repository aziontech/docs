You can declare a WAF rule set and the firewall rule that applies it in `azion.config.js`, with the deployment that binds the firewall to a workload. The [Azion CLI](/en/documentation/devtools/cli/) creates them from the file, so they live in the repository, under review alongside the application they protect.

---

## Prerequisites

You need the Azion CLI installed, a configured personal token, and the `@aziontech/config` package in the project, which `npm install -D @aziontech/config` adds.

---

## Declare the rule set and the rule

In `azion.config.js`, declare the rule set under `waf`, the firewall with `waf: true` and the rule that carries the `set_waf` behavior under `firewall`, and the workload deployment that names the firewall under `workloads`. The sample assumes the same file declares an application named `storefront` under `applications`, since a deployment can only name an application the file declares:

```javascript
import { defineConfig } from '@aziontech/config';

export default defineConfig({
  waf: [
    {
      name: 'storefront-waf',
      engineSettings: {
        engineVersion: '2021-Q3',
        type: 'score',
        attributes: {
          rulesets: [1],
          thresholds: [
            { threat: 'sql_injection', sensitivity: 'medium' },
            { threat: 'cross_site_scripting', sensitivity: 'medium' },
          ],
        },
      },
    },
  ],
  firewall: [
    {
      name: 'storefront-firewall',
      active: true,
      waf: true,
      rules: [
        {
          name: 'Apply storefront-waf',
          active: true,
          criteria: [
            {
              variable: '${request_uri}',
              conditional: 'if',
              operator: 'starts_with',
              argument: '/',
            },
          ],
          behaviors: [
            {
              type: 'set_waf',
              attributes: { mode: 'blocking', wafId: 'storefront-waf' },
            },
          ],
        },
      ],
    },
  ],
  workloads: [
    {
      name: 'storefront',
      deployments: [
        {
          name: 'storefront',
          current: true,
          active: true,
          strategy: {
            type: 'default',
            attributes: {
              application: 'storefront',
              firewall: 'storefront-firewall',
            },
          },
        },
      ],
    },
  ],
});
```

Run `azion deploy` in the project folder. The Azion CLI reads the file and creates what it declares: the rule set, the firewall with WAF turned on, the rule that applies the rule set, and the deployment that binds the firewall to the workload. Until a deployment names the firewall, its rules see no request.

`waf: true` on the firewall turns WAF on, and it stays off until you turn it on. A family you leave out of `thresholds` is not configured, so list every family you want scored. The `set_waf` behavior takes two attributes, `mode` and `wafId`. `wafId` names the rule set by its `name` in `waf` or by its ID. `mode` takes `learning` or `blocking` in this file: the same mode reads _Logging_ in Azion Console and `logging` in an API payload. For what each mode does, refer to [Scoring and modes](/en/documentation/platform/firewall/waf/scoring-and-modes/). For every field of the file, refer to [azion.config.js](/en/documentation/devtools/cli/azion-config-js/#firewall-rule-behaviors).
