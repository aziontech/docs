You can declare a [Firewall](/en/documentation/platform/firewall/) and the rule that applies a WAF rule set in `azion.config.js`, and create both from the file with the [Azion CLI](/en/documentation/devtools/cli/). To apply a rule set from Azion Console, the CLI commands, or the API, refer to [Create and apply a WAF rule set](/en/documentation/guides/application-security/firewall-and-waf/create-waf-rule-set/).

The example declares the Firewall `storefront-firewall`, with a rule that applies the rule set with the ID `12345` to every request. Replace them with your Firewall and the ID of your rule set.

---

## Prerequisites

- The Azion CLI, installed and authorized. The commands on this page match Azion CLI 4.26.2.
- The `@aziontech/config` package in the project folder. To add it, run `npm install -D @aziontech/config`.
- A WAF rule set, and its ID. To create one, refer to [Create and apply a WAF rule set](/en/documentation/guides/application-security/firewall-and-waf/create-waf-rule-set/).

---

## Declare the Firewall and the rule

To declare them, add the Firewall under `firewall` in `azion.config.js`, with `waf: true` and a rule whose `set_waf` behavior carries the ID of your rule set in `wafId`:

```javascript
import { defineConfig } from '@aziontech/config';

export default defineConfig({
  firewall: [
    {
      name: 'storefront-firewall',
      active: true,
      waf: true,
      rules: [
        {
          name: 'Apply storefront-waf',
          active: true,
          criteria: [
            {
              variable: '${request_uri}',
              conditional: 'if',
              operator: 'starts_with',
              argument: '/',
            },
          ],
          behaviors: [
            {
              type: 'set_waf',
              attributes: { mode: 'blocking', wafId: 12345 },
            },
          ],
        },
      ],
    },
  ],
});
```

The file declares a Firewall with WAF on, and one rule that applies the rule set in _Blocking_ mode to every request.

---

## Create the Firewall from the file

To create the Firewall and its rule, run this command in the project folder:

```bash
azion config apply
```

The command creates each resource and prints its ID:

```text
[Azion] [IaC] › ✔  success   Manifest generated successfully at <project-dir>/.edge/manifest.json
Creating azion.json file
Reading manifest.json file
Firewall storefront-firewall with id <firewall-id> successfully created
Firewall Rule Apply storefront-waf with id <rule-id> successfully created
Rules Engine of Firewall with id <firewall-id> successfully ordered
Configuration applied successfully: 1 resource(s) applied
```

The account holds the Firewall, with WAF on, and the rule that applies the rule set. Running the command again updates the same Firewall and rule, and keeps their IDs. The rule inspects no request until a Workload's deployment sets the Firewall. To set it, refer to [Set a Firewall on a Workload](/en/documentation/guides/application-security/firewall-and-waf/firewall-protect-your-domain/).

On Azion CLI 4.26.2, `azion config apply` handled four declarations differently from the file:

- **`wafId` takes an ID.** A `wafId` that holds the name of a rule set fails with `set_waf requires integer 'waf_id' attribute`, and the command stops after creating the Firewall.
- **`mode` takes `blocking`.** `learning` passes the file's validation and the API refuses it with `"learning" is not a valid choice.` `logging` fails the validation with `The mode must be one of: learning, blocking`.
- **A `waf` entry creates no rule set.** The command reports no rule set, and the account holds none afterward.
- **A deployment under `workloads` does not set the Firewall.** The command creates the Workload and its deployment, and the deployment reads `firewall: null`, whether the file names the Firewall or gives its ID.

For every field of the file, refer to [azion.config.js](/en/documentation/devtools/cli/azion-config-js/#firewall).
