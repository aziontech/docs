Definitions for the terms the **Certificate Manager** documentation uses.

| Term | Definition |
| --- | --- |
| Azion SAN certificate | Azion's own Transport Layer Security (TLS) certificate, which lists the hostnames it covers as Subject Alternative Names (SAN). A [Workload](/en/documentation/platform/workloads/) presents it on the [workload domain](/en/documentation/platform/workloads/how-it-works/#workload-domain-and-custom-domains), and on every hostname while `tls.certificate` is `null`, and it covers the workload domain and the [Azion custom domain](/en/documentation/platform/workloads/glossary/) at no additional cost. To present a certificate for your own domain instead, refer to [Certificates](/en/documentation/platform/certificate-manager/certificates/). |
| Certificate Manager | A Platform Resource that stores the certificates a [Workload](/en/documentation/platform/workloads/) uses for TLS, served in the API under `/v4/workspace/tls/`. It holds server certificates you upload, Let's Encrypt certificates Azion requests and renews, Trusted CA certificates, certificate revocation lists, and CSRs. [Certificate Manager](/en/documentation/platform/certificate-manager/) describes what it does for a Workload, and the [Certificate Manager quickstart](/en/documentation/platform/certificate-manager/quickstart/) binds a first certificate. |
| certificate revocation list (CRL) | The list of certificates that a certificate authority revoked before their expiration date, signed by that certificate authority. You upload it to Certificate Manager and attach it to a Workload in `mtls.config.crl`, at most 100 per Workload, beside the Trusted CA certificate. [Certificates](/en/documentation/platform/certificate-manager/certificates/) documents its fields. |
| certificate signing request (CSR) | A request for a certificate that you create in Certificate Manager and submit to a certificate authority (CA). The **Common Name** (`common_name`) sets the domain the certificate covers, and the CSR creates a certificate entry with no certificate yet. Once the CA signs the certificate, you add the PEM-encoded certificate to that entry, and [Certificates](/en/documentation/platform/certificate-manager/certificates/) lists every field. |
| digital certificate | A certificate that Certificate Manager stores, of any kind, under the name Azion Console and Azion CLI use for it, from the **Digital Certificate** field (`tls.certificate`) of a Workload to the `azion create digital-certificate` command. Its `type` is `edge_certificate` for a server certificate or `trusted_ca_certificate` for a Trusted CA certificate, and a Let's Encrypt certificate is one Azion requests and renews. [Certificates](/en/documentation/platform/certificate-manager/certificates/) compares the kinds. |
| Let's Encrypt certificate | A free TLS certificate signed by the Let's Encrypt certificate authority, which Azion requests and renews for you. Let's Encrypt validates the domain through an HTTP-01 or DNS-01 challenge that Azion completes, and renewal starts 30 days before the 90-day validity ends. [Issuance and renewal](/en/documentation/platform/certificate-manager/issuance-and-renewal/) covers the challenges and the retry policy. |
| Trusted CA certificate | The certificate of a certificate authority that you upload so a Workload can verify client certificates in [mTLS](/en/documentation/platform/workloads/mtls/), `trusted_ca_certificate` in the API and **Trusted CA Certificate** in Azion Console. The upload accepts intermediate certificates, and a Workload sets it in `mtls.config.certificate`, where a server certificate returns `Invalid certificate type, MUST be a Trusted CA.` To upload one, refer to [Configure mTLS on a workload](/en/documentation/guides/application-security/tls-and-certificates/associate-an-mtls-certificate/). |
