You can raise the sensitivity of one threat family of a WAF rule set from the API, and leave the other seven where they are. For what a level changes in the score a family blocks on, refer to [Scoring and modes](/en/documentation/platform/firewall/waf/scoring-and-modes/#scoring-and-sensitivity).

The example raises `sql_injection` to `high` on the rule set `<waf-id>`, and keeps the other seven families at `medium`. Replace them with your family, level, and rule set.

---

## Prerequisites

- A WAF rule set, and its ID. To create one, refer to [Create and apply a WAF rule set](/en/documentation/guides/application-security/firewall-and-waf/create-waf-rule-set/).
- A [personal token](/en/documentation/guides/platform/account-and-billing/personal-tokens/).

---

## Raise the family

A `PATCH` whose `engine_settings` carries `thresholds` replaces the whole array, so a body that carries only `sql_injection` leaves the rule set with that one family. Send all eight families, each once.

To raise the family, send a `PATCH` request to the rule set endpoint, with all eight families in `thresholds`:

```bash
curl --request PATCH \
  --url https://api.azion.com/v4/workspace/wafs/<waf-id> \
  --header 'Accept: application/json' \
  --header 'Authorization: Token [TOKEN VALUE]' \
  --header 'Content-Type: application/json' \
  --data '{
  "engine_settings": {
    "engine_version": "2021-Q3",
    "type": "score",
    "attributes": {
      "rulesets": [1],
      "thresholds": [
        { "threat": "cross_site_scripting", "sensitivity": "medium" },
        { "threat": "directory_traversal", "sensitivity": "medium" },
        { "threat": "evading_tricks", "sensitivity": "medium" },
        { "threat": "file_upload", "sensitivity": "medium" },
        { "threat": "identified_attack", "sensitivity": "medium" },
        { "threat": "remote_file_inclusion", "sensitivity": "medium" },
        { "threat": "sql_injection", "sensitivity": "high" },
        { "threat": "unwanted_access", "sensitivity": "medium" }
      ]
    }
  }
}'
```

The API answers `202` and returns the rule set with the eight entries you sent:

```json
{
  "state": "pending",
  "data": {
    "id": <waf-id>,
    "engine_settings": {
      "engine_version": "2021-Q3",
      "type": "score",
      "attributes": {
        "rulesets": [1],
        "thresholds": [
          { "threat": "cross_site_scripting", "sensitivity": "medium" },
          ...
          { "threat": "sql_injection", "sensitivity": "high" },
          { "threat": "unwanted_access", "sensitivity": "medium" }
        ]
      }
    },
    ...
  }
}
```

The rule set reads back with `sql_injection` at `high` and the other seven families at `medium`.

`sensitivity` takes `highest`, `high`, `medium`, `low`, or `lowest`, and another value returns `400` with `10039 Invalid Choice`. A `threat` repeated in the array returns `500` with `10067 Internal Server Error` and the message `A server error occurred.`, which names neither the field nor the duplicate. For every error the endpoint returns, refer to [Rule sets](/en/documentation/platform/firewall/waf/rules-set/#errors).
