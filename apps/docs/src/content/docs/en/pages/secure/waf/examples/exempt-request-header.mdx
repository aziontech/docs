You can create a WAF exception that stops one internal rule scoring the values of the request headers on one path from the API. For an exception on one query string parameter, with the Console and the CLI, refer to [Exempt query string values from one WAF rule](/en/documentation/guides/application-security/firewall-and-waf/exempt-query-parameter/).

The example stops rule `1005`, the pipe-character rule, scoring the headers of the requests to `/account`, on the rule set `<waf-id>`. Replace them with your rule, path, and rule set.

---

## Prerequisites

- The WAF rule set that blocked the request, and its ID.
- The ID of the internal rule that matched a header, read from the `wafMatch` field of the request's record, such as `0:1005:HEADERS:cookie`. To read it, refer to [Read the score of a blocked request](/en/documentation/guides/application-security/firewall-and-waf/read-block-score/).
- A [personal token](/en/documentation/guides/platform/account-and-billing/personal-tokens/).

---

## Create the exception

The condition is `any_http_header_value`, which covers the value of every request header. A condition that names one header, `specific_http_header_name` with `cookie` or `HTTP_COOKIE`, is accepted by the API, and in tests it did not clear a match on the `Cookie` header.

A narrower condition carries the header name in `value`: `{"match": "specific_http_header_value", "value": "cookie"}`. In another test, with rule `1005` and no `path`, it cleared the match on the `Cookie` header only. A query string parameter of the same request was still refused.

To create the exception, send a `POST` request to the exceptions endpoint of the rule set, with the rule ID, the path, and the condition:

```bash
curl --request POST \
  --url https://api.azion.com/v4/workspace/wafs/<waf-id>/exceptions \
  --header 'Accept: application/json' \
  --header 'Authorization: Token [TOKEN VALUE]' \
  --header 'Content-Type: application/json' \
  --data '{
  "rule_id": 1005,
  "name": "Allow the pipe character in request headers",
  "path": "/account",
  "operator": "contains",
  "active": true,
  "conditions": [
    { "match": "any_http_header_value" }
  ]
}'
```

The API answers `202` and returns the exception:

```json
{
  "state": "pending",
  "data": {
    "id": <exception-id>,
    "rule_id": 1005,
    "name": "Allow the pipe character in request headers",
    "path": "/account",
    "conditions": [
      { "match": "any_http_header_value" }
    ],
    "operator": "contains",
    "active": true,
    "last_editor": "user@example.com",
    "last_modified": "2026-01-01T12:00:00.000000Z"
  }
}
```

Rule `1005` stops scoring the header values of the requests to `/account`, and keeps scoring their query string. In a test, the exception cleared the rule on a `Cookie` header carrying `|`, and a query string argument carrying `|` on the same path still received `400`. Send a request that the rule matched before, and check that it now passes.

:::note[Note]
`any_http_header_value` carries no header name. A `name` key sent with it is dropped rather than refused: the API answers `202` and stores `{"match": "any_http_header_value"}` alone. In a test under `contains`, the exception applied to its exact `path`: a longer path that started with it, or that contained it, still received `400` for the same `Cookie` header. An exception with no `path` applied on every path tested.
:::

For the keys each of the fifteen match zones carries, refer to [Exception settings](/en/documentation/platform/firewall/waf/custom-allowed-rules/#match-zones).
