You can read which internal rules matched a blocked request, and the score each threat family gave it, from the [Real-Time Events](/en/documentation/platform/real-time-events/) GraphQL API. To find the same record in Azion Console, refer to [Find the WAF score of a blocked request](/en/documentation/guides/application-security/firewall-and-waf/how-to-find-waf-score/).

A blocked response carries `400` and Azion's default error page, headed **Bad Request**, and no header names WAF. Its `x-azion-request-id` header finds the record of the request.

---

## Prerequisites

- A [Firewall](/en/documentation/platform/firewall/) set by the deployment of your Workload, with a rule whose _Set WAF_ behavior applies a WAF rule set in `blocking` mode. To create the rule, refer to [Create and apply a WAF rule set](/en/documentation/guides/application-security/firewall-and-waf/create-waf-rule-set/). For the requests WAF inspected in tests, refer to [Modes](/en/documentation/platform/firewall/waf/scoring-and-modes/#modes).
- A [personal token](/en/documentation/guides/platform/account-and-billing/personal-tokens/), for the GraphQL query.

---

## Read the request ID

To read the request ID, send a request that WAF blocks, and print the response headers:

```bash
curl -i "https://<your-workload-domain>/?q=1%27%20OR%20%271%27%3D%271"
```

The response is `HTTP/2 400`, and the `x-azion-request-id` header carries the request ID:

```text
HTTP/2 400
server: nginx
date: Wed, 01 Jan 2026 12:00:00 GMT
content-type: text/html
x-azion-request-id: 0123456789abcdef0123456789abcdef
x-azion-edge-location: <location>
```

The request ID is the value the query of the next section filters on.

---

## Query the record of the request

To query the record, send a GraphQL query to `https://api.azion.com/v4/events/graphql`, over the `workloadEvents` dataset, filtered on the request ID and a window around the request:

```graphql
query {
  workloadEvents(
    limit: 1
    filter: { tsGte: "<start>", tsLt: "<end>", requestIdEq: "<request-id>" }
  ) {
    ts
    requestUri
    status
    upstreamStatus
    wafBlock
    wafLearning
    wafMatch
    wafScore
    wafAttackFamily
    wafAttackAction
  }
}
```

The API returns one row:

```json
{
  "ts": "2026-01-01T12:00:00Z",
  "requestUri": "/?q=1%27%20OR%20%271%27%3D%271",
  "status": 400,
  "upstreamStatus": 0,
  "wafBlock": "1",
  "wafLearning": "0",
  "wafMatch": "0:1009:ARGS:q,1:1013:ARGS:q",
  "wafScore": "0:$SQL:18,1:$XSS:32",
  "wafAttackFamily": "$SQL,$XSS",
  "wafAttackAction": "$BLOCK"
}
```

The row lists one entry per internal rule that matched in `wafMatch`, and one score per threat family in `wafScore`.

A `wafMatch` entry is shaped `<index>:<ruleId>:<zone>:<varName>`, so `1:1013:ARGS:q` names rule `1013` on the `q` argument. A `wafScore` entry is shaped `<index>:$<family>:<score>`, so a request carries one score per family rather than one score. `upstreamStatus` reads `0` because the request never reached an origin.

`wafBlock` reads `1` in _Logging_ mode too. `wafLearning` `1` and `wafAttackAction` `$LEARNING-BLOCK` mark a request that WAF recorded and let through, and `wafLearning` `0` with `$BLOCK` marks a request it refused.

:::note[Note]
A request that no _Set WAF_ behavior applied to carries `-` in every WAF field, and a request WAF inspected without a match reads `wafBlock` `0` and `$PASS`. Query the v4 path: the older `https://api.azion.com/events/graphql` answers `204` with an empty body. The fields are camelCase here, rather than the snake_case spellings a [Data Stream](/en/documentation/platform/data-stream/) payload uses.
:::
