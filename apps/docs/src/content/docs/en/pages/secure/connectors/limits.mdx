A rule in an Application sets a [Connector](/en/documentation/platform/connectors/) with the _Set Connector_ behavior. A Connector of type `http` holds the addresses of your origin, a `storage` Connector holds a bucket, and a `live_ingest` Connector holds a [Live Ingest](/en/documentation/platform/connectors/live-ingest/) region. This page shows where a Connector stops, the bounds of every Connector, and the bounds of [Load Balancer](/en/documentation/platform/connectors/load-balancer/) and [Origin Shield](/en/documentation/platform/connectors/origin-shield/) on a Connector.

Azion checks each value on this page when you create or update a Connector, and the API refuses the call past it. For what each plan includes and costs, refer to the [Load Balancer](/en/documentation/fundamentals/pricing/#load-balancer), [Origin Shield](/en/documentation/fundamentals/pricing/#origin-shield), and [Live Ingest](/en/documentation/fundamentals/pricing/#live-ingest) sections of Pricing.

## Scope

- **Connector types**: a Connector of type `http` reaches servers you run by hostname or IP address, such as a cloud server, a server in your data center, or an S3-compatible endpoint. It is the only type with addresses, connection options, Load Balancer, and Origin Shield. A Connector of type `storage` reads one [Object Storage](/en/documentation/platform/object-storage/) bucket of your account, narrowed to a prefix, and a Connector of type `live_ingest` sets the region where Live Ingest receives your stream. The type is fixed at creation, and a `PATCH` that changes it is refused with `28003`, as [Connector settings](/en/documentation/platform/connectors/settings/#general) lists.
- **Load Balancer and Origin Shield by type**: Load Balancer and Origin Shield can both be on in one Connector of type `http`. A `modules` key sent with a Connector of type `storage` or `live_ingest` is accepted and ignored, not refused, so neither one acts on that Connector. To confirm what a Connector carries, read it back, as [Connector settings](/en/documentation/platform/connectors/settings/#live-ingest) shows.
- **Bucket access**: a Connector of type `storage` reads a bucket only when the bucket's workloads access is read only or read write. Otherwise, the API refuses the Connector with `28007`, so change that access on the bucket first, as [Connector settings](/en/documentation/platform/connectors/settings/#storage) lists.
- **Timeouts**: a Connector without Load Balancer has no timeout you can set, and it follows the platform defaults in [How Connectors works](/en/documentation/platform/connectors/how-it-works/#connection-reuse-and-timeouts). With Load Balancer on, the connection timeout, the read and write timeout, and the retries on a connection failure become settings of the Connector.
- **Deletion**: the API refuses to delete a Connector while a rule still sets it, with `28000`, and the message names the rule. Remove or change that rule first, as [Troubleshoot Connectors](/en/documentation/platform/connectors/troubleshooting/) shows.
- **Propagation**: a change to a Connector takes effect with no new deployment, but it reaches Azion's distributed infrastructure in several minutes, and data centers apply it at different times. Until then, a request can meet the old or the new settings. To plan a change around it, refer to [Connectors best practices](/en/documentation/platform/connectors/best-practices/).
- **Testing**: a Connector receives only the requests of the rules that set it. A rule that matches one path sends only that path to the Connector you are trying, and every other path keeps its current origin, as the [Connectors quickstart](/en/documentation/platform/connectors/quickstart/) does.
- **DNS-level balancing**: Load Balancer chooses among the addresses of one Connector after the request reaches Azion. Weighted DNS records that split traffic between IP addresses when a name resolves belong to [Edge DNS](/en/documentation/platform/edge-dns/), as [Weight records to balance traffic](/en/documentation/guides/application-security/dns/load-balance-dns/) shows.
- **Origin offload**: Origin Shield lets your origin accept only the requests a Connector sends, and it stores no response. A second cache layer between Azion's cache and your origin, which reduces the requests that reach it, is [Tiered Cache](/en/documentation/platform/applications/cache/tiered-cache/), turned on per cache setting of an Application.
- **Origin IP ACL enforcement**: your origin's firewall enforces the allowlist, not Azion. Origin IP ACL gives your account the `Azion Origin Shield` list, and a client that connects to your origin directly is refused only where your firewall applies it, as [Origin IP ACL and HMAC](/en/documentation/platform/connectors/origin-shield/origin-ip-acl-and-hmac/#origin-ip-acl) explains.
- **Live Ingest encoder**: Live Ingest takes in a stream only over RTMP, from an encoder that authenticates with the username and password Azion provides. Azion can require an approved encoder, configuration, or endpoint, as [Ingestion and delivery](/en/documentation/platform/connectors/live-ingest/ingestion-and-delivery/#ingestion) describes.
- **Live Ingest region**: the region of a Connector of type `live_ingest` decides where the stream enters Azion, not where viewers connect. Viewers reach the stream through a Workload hostname, so choose the region with the shortest path from the encoder, as [Region](/en/documentation/platform/connectors/live-ingest/ingestion-and-delivery/#region) explains.
- **Live stream cache**: a request that a rule sends to a Connector of type `live_ingest` takes the live HLS cache policy of _Enforce HLS cache_, and a cache setting of the Application has no effect on it. For the cache time of each file type, refer to [Rules Engine for Applications](/en/documentation/platform/applications/rules-engine/#enforce-hls-cache).
- **HLS from your own origin**: _Enforce HLS cache_ applies only to a stream that Live Ingest takes in. For an HLS stream your own origin produces, give its playlists and segments cache settings of their own, as [Enforce HLS cache for live streaming](/en/documentation/guides/media-and-streaming/streaming/enforce-hls-cache/) shows.
- **SNI Check**: a `421 Misdirected Request` comes from the Workload, before any Connector runs. When SNI Check enforcement is on, Azion answers it to an HTTPS request whose host the Workload's certificate does not cover. With enforcement off, that request continues. For the decision steps, refer to [SNI Check](/en/documentation/platform/connectors/sni-check/).
- **API v3 origins**: on API v3, the origins of an Application carry the role of a Connector, and Connectors replaces them on API v4. For an account that still runs API v3, refer to [Origins](/en/documentation/platform/connectors/origins/). For the mapping between the two models, refer to [API v4 Migration](/en/documentation/fundamentals/api-v4-migration/).
- **Observability**: [Data Stream](/en/documentation/platform/data-stream/) records the origin side of each request in its `$upstream_*` variables, such as `$upstream_status`, the HTTP status code of the origin, and `$upstream_response_time`. A response served from cache carries `-` in both. `$upstream_addr`, in the *Applications + WAF Event Collector* preset, holds the address and port of each server the request was sent to. When Load Balancer chooses another origin, these variables hold one value per connection, as [Several values in one field](/en/documentation/platform/data-stream/data-sources-and-variables/#several-values-in-one-field) shows.

## Connectors

The bounds in this section apply to every Connector, whatever its type and service plan.

### Default limits

A create or update call that passes one of these bounds returns status `400` with an error code and message, shown for each row.

| Scope | Limit | Past the limit |
| --- | --- | --- |
| Connector `name` | 1 to 255 characters | Empty: `10018` `This field may not be blank.` More than 255 characters: `10046` `Ensure this field has no more than 255 characters.` |
| Connectors with the same `name` | 1 per Workspace | `28002` `A connector with this name already exists for this Workspace.` |
| Addresses per Connector without Load Balancer | 1 | `28004` `To use more than one address, you must enable the Load Balancer module.` Azion Console keeps **Add Address** unavailable until Load Balancer is on. |
| `address` | Up to 255 characters | `10046` `Ensure this field has no more than 255 characters.` |
| `http_port` and `https_port` | 1 to 65535 | Below 1: `10050` `Ensure this value is greater than or equal to 1.` Above 65535: `10068` `Ensure this value is less than or equal to 65535.` |
| `host` and `path_prefix` connection options | Up to 255 characters each | `10046` `Ensure this field has no more than 255 characters.` |
| `real_ip_header` and `real_port_header` connection options | Up to 100 characters each | `10046` `Ensure this field has no more than 100 characters.` |
| `bucket` and `prefix` on a Connector of type `storage` | Up to 255 characters each | `10046` `Ensure this field has no more than 255 characters.` |

For the fields these bounds apply to, refer to [Connector settings](/en/documentation/platform/connectors/settings/).

## Load Balancer

[Load Balancer](/en/documentation/platform/connectors/load-balancer/) balances requests across the addresses of a Connector of type `http`. The bounds in this section apply when Load Balancer is enabled on the Connector, on every service plan.

### Default limits

With Load Balancer enabled, a create or update call past one of these bounds returns status `400` with the error shown for each row.

| Scope | Limit | Past the limit |
| --- | --- | --- |
| Addresses per Connector | Up to 15 | `28011` `When the Load Balancer module is enabled, you can use up to 15 addresses.` |
| Address `weight` | 1 to 100 | Below 1: `10050` `Ensure this value is greater than or equal to 1.` Above 100: `10068` `Ensure this value is less than or equal to 100.` Azion Console shows `Weight must be between 1 and 100`. |
| `max_retries` | 0 to 20 retries | Below 0: `10050` `Ensure this value is greater than or equal to 0.` Above 20: `10068` `Ensure this value is less than or equal to 20.` |
| `connection_timeout` | 1 to 300 seconds | Below 1: `10050` `Ensure this value is greater than or equal to 1.` Above 300: `10068` `Ensure this value is less than or equal to 300.` |
| `read_write_timeout` | 1 to 600 seconds | Below 1: `10050` `Ensure this value is greater than or equal to 1.` Above 600: `10068` `Ensure this value is less than or equal to 600.` |

A Connector with Load Balancer enabled accepts a single address, so the 15-address bound is a ceiling and not a minimum. To request a higher limit, contact [Azion technical support](/en/documentation/support/).

For how the balancing method, the weight, and the server role of each address shape the distribution, refer to [Balancing methods](/en/documentation/platform/connectors/load-balancer/balancing-methods/).

## Origin Shield

[Origin Shield](/en/documentation/platform/connectors/origin-shield/) lets your origin accept only the requests a Connector sends. With hash-based message authentication code (HMAC) on, the Connector also signs its requests with HMAC credentials. The bounds in this section apply when Origin Shield is enabled on the Connector. For how Origin Shield is billed, refer to [Origin Shield](/en/documentation/fundamentals/pricing/#origin-shield) in Pricing.

### Default limits

HMAC takes one credential set per Connector, and that set applies to every address of the Connector. A create or update call that passes one of these bounds returns status `400` with an error code and message.

| Scope | Limit | Past the limit |
| --- | --- | --- |
| HMAC `region`, `service`, `access_key`, and `secret_key` | 1 to 255 characters each | Empty: `10018` `This field may not be blank.` More than 255 characters: `10046` `Ensure this field has no more than 255 characters.` |

For the HMAC fields and where each value comes from, refer to [Origin IP ACL and HMAC](/en/documentation/platform/connectors/origin-shield/origin-ip-acl-and-hmac/).
