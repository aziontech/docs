You can set a [Bot Manager Lite](/en/documentation/platform/firewall/bot-manager/bot-manager-lite/) Function Instance to refuse a request whose score reaches the threshold, from Azion Console, the Azion CLI, or the API. A refused request receives `403` with Azion's default error page.

## Set the action to deny

The object below differs from the observation object in one value: `action` reads `deny`. The Function Instance then answers `403` to a request whose score reaches `threshold`, instead of serving it. At `30`, the threshold Bot Manager Lite ships, a browser is not refused. A Chrome request carrying `Accept`, `Accept-Language`, `Accept-Encoding`, four `Sec-Fetch-*` headers, and `Upgrade-Insecure-Requests` reaches the Application under this object. `internal_logs` at `2` keeps a report line for every request, so a refusal leaves a record of the score behind it.

```json
{
  "threshold": 30,
  "action": "deny",
  "internal_logs": 2,
  "log_tag": "storefront-bots"
}
```

For every argument a Function Instance accepts, refer to [Arguments](/en/documentation/platform/firewall/bot-manager/arguments/#fields).

### Console

To set the action from Azion Console:

<DocSteps>
  <DocStep title="Open the Firewall that your Workload's deployment sets">

  Access [Azion Console](https://console.azion.com/) > **Firewalls**, then select that Firewall.

  </DocStep>
  <DocStep title="Select the Functions Instances tab" />
  <DocStep title="Open the Function Instance you want to change">

  On a Firewall that carries no Function Instance yet, select **Function Instance**, enter a **Name**, and select the Bot Manager Lite Function in the **Function** section.

  </DocStep>
  <DocStep title="Enter the object in the Arguments section">

  The section holds a JSON editor, because Bot Manager Lite carries no argument schema to build a form from.

  </DocStep>
  <DocStep title="Select Save" />
</DocSteps>

The Function Instance holds the new object. A rule that already runs the Function Instance keeps running it: the arguments change under the rule, and no rule has to be touched.

</Fragment>

<Fragment slot="panel.cli">

### CLI

To create the Function Instance with the Azion CLI, save the object as `bmargs.json`:

```json
{
  "threshold": 30,
  "action": "deny",
  "internal_logs": 2,
  "log_tag": "storefront-bots"
}
```

The `--args` flag of `azion create firewall-instance` takes the path to that file, and no inline JSON:

```bash
azion create firewall-instance --name bot-manager-lite --firewall-id <firewall-id> \
  --function-id <function-id> --args bmargs.json --active true
```

```text
Created Firewall Function Instance with ID 12346
```

The Azion CLI confirms the Function Instance with the ID it received. Record that ID: a [rule](/en/documentation/guides/application-security/bots-and-network/run-on-every-request/) runs the Function Instance by it, never by the ID of the Function.

To change the arguments of a Function Instance that already exists, update it with the same file:

```bash
azion update firewall-instance --firewall-id <firewall-id> --instance-id <instance-id> --args bmargs.json
```

```text
Updated Firewall Function Instance with ID <instance-id>
```

</Fragment>

<Fragment slot="panel.api">

### API

Send a `POST` request to the `functions` collection of your Firewall. Replace `<firewall-id>` with the ID of your Firewall, `[TOKEN VALUE]` with your personal token, and `12345` with the ID of the installed Bot Manager Lite Function:

```bash
curl --request POST \
  --url https://api.azion.com/v4/workspace/firewalls/<firewall-id>/functions \
  --header 'Accept: application/json' \
  --header 'Authorization: Token [TOKEN VALUE]' \
  --header 'Content-Type: application/json' \
  --data '{
  "name": "bot-manager-lite",
  "function": 12345,
  "active": true,
  "args": {
    "threshold": 30,
    "action": "deny",
    "internal_logs": 2,
    "log_tag": "storefront-bots"
  }
}'
```

The call answers `202` and returns the Function Instance as the platform stored it:

```json
{
  "state": "pending",
  "data": {
    "id": 12348,
    "name": "bot-manager-lite",
    "args": {
      "threshold": 30,
      "action": "deny",
      "internal_logs": 2,
      "log_tag": "storefront-bots"
    },
    "azion_form": {},
    "function": 12345,
    "active": true,
    "last_editor": "user@example.com",
    "last_modified": "2026-01-01T12:00:00.000000Z",
    "created_at": "2026-01-01T12:00:00.000000Z"
  }
}
```

`"state": "pending"` says the write was accepted and has yet to reach Azion's distributed infrastructure. `"azion_form": {}` is why Azion Console renders a JSON editor for this Function instead of a form.

To change the arguments of a Function Instance that already exists, send a `PATCH` request to `https://api.azion.com/v4/workspace/firewalls/<firewall-id>/functions/<instance-id>` with the new `args` in the body, such as `{"args": {"action": "deny"}}`. It also answers `202` with `"state": "pending"`.

</Fragment>

</Tabs>

:::note[Note]
A change to a Function Instance takes up to a few minutes to propagate, and answers alternate meanwhile, so wait before you read anything into a response. For more information, refer to [Propagation](/en/documentation/platform/firewall/how-it-works/#propagation).

The API checks no key of the arguments: a Function Instance whose `action` key is misspelled is stored with no error, looks configured to refuse, and refuses nothing. A `threshold` of `0` refuses every request the rule matches. A client that neither runs JavaScript nor keeps cookies never reaches a `403`, and never reaches the Application either. For what that client receives, refer to [Troubleshoot Firewall](/en/documentation/platform/firewall/troubleshooting/#bot-manager).
:::
