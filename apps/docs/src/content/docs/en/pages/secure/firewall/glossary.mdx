Definitions for the terms the **Firewall** documentation uses.

| Term | Definition |
| --- | --- |
| Allowed Rules | The Azion Console name for WAF exceptions, and the tab on a rule set where you create and manage them. The API and the CLI call the same entity an exception, and [Exceptions](/en/documentation/platform/firewall/waf/custom-allowed-rules/) documents it under both names. |
| allowlist | A Network List that a rule uses to admit only the clients it holds. A rule with the Network criterion, the _does not match_ operator (`is_not_in_list`), and the _Deny (403 Forbidden)_ behavior (`deny`) blocks every client outside the list. Allowlist names a use, not a list type: [Network Lists](/en/documentation/platform/firewall/network-shield/network-lists/) offers only the _IP/CIDR_, _ASN_, and _Countries_ types. |
| arguments | The JSON object a Function Instance passes to its Function, edited in the **Arguments** section of the instance form and sent as `args` through the API and the CLI. For Bot Manager it sets the threshold, the action, and the logging, and a key the Function does not read is stored and ignored, as [Arguments](/en/documentation/platform/firewall/bot-manager/arguments/#fields) documents. In a criterion, an argument is the value a variable is compared with. |
| ASN list | A Network List of type `asn`, _ASN_ in Azion Console, that matches a request by the Autonomous System Number (ASN) its client IP address belongs to. An ASN identifies a group of IP networks that one or more operators manage under one clear and unique routing policy. The API takes digits only, such as `64496`, and the Console form also accepts an `AS` prefix; [Network Lists](/en/documentation/platform/firewall/network-shield/network-lists/#list-types) compares the three types. |
| `az_asm` | One of the two session cookies Bot Manager Lite sets, alongside `az_botm`. Its value is a signed copy of the value in `az_botm`, and Bot Manager Lite scores a mismatch between the two. [Bot scoring](/en/documentation/platform/firewall/bot-manager/bot-scoring/#session-cookies) documents the pair. |
| `az_botm` | The unsigned cookie of the session pair Bot Manager Lite sets, carrying the `x-azion-request-id` of the response that set it. [Bot scoring](/en/documentation/platform/firewall/bot-manager/bot-scoring/#session-cookies) documents the pair and how long it lasts. |
| Azion IP Tor Exit Nodes | The Azion-maintained Network List of Tor exit nodes, the final points where the Tor network connects to the internet. It is an `ip_cidr` list with ID `2` that Azion keeps up to date, and a rule can use it but not change it. To block the clients it holds, refer to [Block Tor exit nodes](/en/documentation/guides/application-security/bots-and-network/block-tor-networks/). |
| Azion-maintained list | A Network List that Azion creates and keeps up to date, such as Azion IP Tor Exit Nodes. A rule uses it like any other Network List, but any write to it fails with `22004 Cannot Change Global Network List`. [Network Lists](/en/documentation/platform/firewall/network-shield/network-lists/#azion-maintained-lists) lists them. |
| behavior | What a rule applies to each request its criteria match. A Firewall offers six, _Deny (403 Forbidden)_, _Drop (Close Without Response)_, _Set Rate Limit_, _Set Custom Response_, _Set WAF_, and _Run Function_, and it refuses every rule while WAF, Network Shield, and Functions are all off. Only _Set WAF_ and _Run Function_ can be followed by another behavior in the same rule; [Rules Engine for Firewall](/en/documentation/platform/firewall/rules-engine/#behaviors) documents each one and what it needs. |
| Blocking | The WAF mode that refuses a request whose score reaches a threat family's threshold before it reaches your Application, answering `400`. It is one of the two modes the _Set WAF_ behavior accepts, `blocking` in the API, and it is set on the rule rather than on the rule set. [Scoring and modes](/en/documentation/platform/firewall/waf/scoring-and-modes/#modes) compares both modes. |
| blocklist | A Network List that a rule uses to refuse the clients it holds. A rule with the Network criterion, the _matches_ operator (`is_in_list`), and the _Deny (403 Forbidden)_ behavior (`deny`) blocks every client in the list and lets the others through. To build one, refer to [Block requests by IP, ASN, or country](/en/documentation/guides/application-security/bots-and-network/blocklists-ip-addresses-edge/). |
| bot category | The category Bot Manager records for a request in the `bot_category` log field, with values such as `Search Engine Bot`, `Bad Bot Signatures`, and `Credential Stuffing`. Bot Manager writes the one category the request best fits, and Bot Manager Lite writes a comma-joined list of the classes of every rule the request matched. [Logs](/en/documentation/platform/firewall/bot-manager/logs/#classification) lists every value. |
| Bot Manager | A Platform Resource nested in Firewall that scores each request on the evidence it carries, such as its headers, its address, and its session, and acts on the request when the score reaches a threshold. It is not a switch in **Modules**: it runs as a Function Instance on the Firewall, and a rule with the _Run Function_ behavior runs it. [The Bot Manager overview](/en/documentation/platform/firewall/bot-manager/) describes it, and Bot Manager Lite is its self-serve edition. |
| Bot Manager Lite | The self-serve edition of Bot Manager, installed from Azion Marketplace and run as a Function Instance on a Firewall. It scores each request against 26 static rules and computes no dynamic score. [Bot Manager Lite](/en/documentation/platform/firewall/bot-manager/bot-manager-lite/) lists the rules, the arguments, and the report log. |
| classification | The verdict Bot Manager records for a request in the `classified` log field: `legitimate`, `good bot`, `bad bot`, or `under evaluation`. The verdict follows the threshold in force, so the same score reads `legitimate` under one threshold and `bad bot` under a lower one. [Logs](/en/documentation/platform/firewall/bot-manager/logs/#classification) gives the conditions for each, and [Real-Time Metrics](/en/documentation/platform/real-time-metrics/secure-dashboards/#bot-manager) charts the four together. |
| collision | Two distinct users or devices that share one fingerprint, so Bot Manager scores them as one identity. With the `engine_version` argument set to `2`, Bot Manager derives the fingerprint with a JA4H method that produces fewer collisions than version `1`. [Arguments](/en/documentation/platform/firewall/bot-manager/arguments/#engine-version) compares the two versions. |
| comment | A note written after `#` at the end of an item in an `ip_cidr` list, stored with the item and always last on the line, after any due date. A line that starts with `#` is not a disabled line: the API refuses it as an invalid item with `22005 Invalid IP CIDR`. Lists of type `asn` and `countries` refuse comments, and [Network Lists](/en/documentation/platform/firewall/network-shield/network-lists/#item-annotations) documents the full item syntax. |
| condition | In WAF, the part of a request an exception matches: a match zone and, for a specific zone, the name or value it applies to. The Azion Console field is **Condition**, and the API takes `conditions` as an array with at least one entry; [Exceptions](/en/documentation/platform/firewall/waf/custom-allowed-rules/#match-zones) lists every option. In a Firewall rule, the conditions are the rule's criteria. |
| countries list | A Network List of type `countries`, _Countries_ in Azion Console, that matches a request by the country Azion resolves from its client IP address. The API takes two-letter uppercase ISO 3166-1 alpha-2 codes such as `DE`, and the Console form picks countries by name. A blocklist of this type blocks requests by country, the task known as geoblocking; [Network Lists](/en/documentation/platform/firewall/network-shield/network-lists/#list-types) compares the three types. |
| criterion | One condition a rule tests: a variable such as `${request_uri}`, a comparison operator, and an argument when the operator takes one. Some variables are refused until a nested resource is on: `${network}` needs Network Shield, and the seven header variables, `${request_args}`, and `${request_method}` need WAF. [Rules Engine for Firewall](/en/documentation/platform/firewall/rules-engine/#criteria) lists every variable and how criteria combine with `and` and `or`. |
| Custom Allowed Rules | A retired name for WAF exceptions that appears in no Azion interface. The Azion Console tab reads **Allowed Rules**, and the API and the CLI call the entity an exception. |
| DDoS Protection | A Feature of the Azion Platform that mitigates distributed denial-of-service (DDoS) attacks on every Workload, ahead of the Firewall a Workload's deployment sets. A Firewall's **Modules** section shows it as **DDoS Protection Unmetered**, tagged **Automatically enabled in all accounts**, with a switch that cannot be turned off. The API reports `modules.ddos_protection.enabled` as `true`, and [DDoS Protection](/en/documentation/platform/workloads/ddos-protection/ddos-mitigation/) documents the Feature. |
| Debug Rules | The **Main Settings** section that logs the Rules Engine rules executed on each request, `debug` in the API and off when you create a Firewall. With its **Active** switch on, executed rules appear in the `$traceback` field in [Data Stream](/en/documentation/platform/data-stream/) and [Real-Time Events](/en/documentation/platform/real-time-events/), and in the `stacktrace` field of the [Real-Time Events GraphQL API](/en/documentation/devtools/graphql/gql-real-time-events-fields/). [Debug rules created with Rules Engine](/en/documentation/guides/application-development/getting-started/debug-rules/) shows how to read them. |
| does not match | The Azion Console label of the comparison operator that is true when a value does not match a regular expression, or, on the Network criterion, when the client IP address has no match in the Network List, where it sends `is_not_in_list`. With the `deny` behavior on the Network criterion, it turns the list into an allowlist. [Rules Engine for Firewall](/en/documentation/platform/firewall/rules-engine/#operators) lists the operators each variable takes. |
| due date | The expiration date an item in an `ip_cidr` list can carry: `--LT` and a UTC date and time in `YYYY-MM-DDTHH:MM:SSZ` form, as in `192.0.2.2 --LT2030-01-01T00:00:00Z`. Azion checks it when you write the list's items, so an item already past its date is dropped then. The Console help calls it an expiration date, and [Network Lists](/en/documentation/platform/firewall/network-shield/network-lists/#item-annotations) documents its syntax. |
| dynamic score | The part of a score Bot Manager derives from a fingerprint's behavioral history, measured against the overall traffic pattern of the host. Bot Manager Lite runs static rules only, so its score carries no dynamic part. [Bot scoring](/en/documentation/platform/firewall/bot-manager/bot-scoring/#the-dynamic-score) describes the model. |
| exception | An entry on a rule set that exempts part of a request from one internal WAF rule, or from all of them, so a false positive stops being blocked. Azion Console calls it an allowed rule, and the API and the CLI call it an exception. [Exceptions](/en/documentation/platform/firewall/waf/custom-allowed-rules/#fields) documents the rule ID, conditions, and operator it carries. |
| false positive | A legitimate request that reaches a threat family's threshold and is treated as an attack. [Tuning](/en/documentation/platform/firewall/waf/custom-allowed-rules/#tuning) is where you find one, and an exception clears it. A false negative is the reverse, an attack whose score stays under the threshold, and raising a sensitivity level trades one for the other. |
| fingerprint | The identifier Bot Manager derives for the client behind a request, from what the request and the device's session carry, such as the IP address and the `User-Agent` header. It ties the later requests of one device together. Bot Manager reports it in the `azion_fingerprint` log field and Bot Manager Lite in `fingerprint`, as four underscore-separated segments; [Logs](/en/documentation/platform/firewall/bot-manager/logs/#fields) documents both. |
| Firewall | A Platform Resource that inspects the requests to your Workloads before your Application receives them, on Azion's distributed infrastructure. Each Firewall you create holds its own rules, and the deployment of a [Workload](/en/documentation/platform/workloads/) sets it, together with the Application, in the **Firewall** field of its **Deployment Settings**. A Firewall carries no domain of its own, and [Firewall](/en/documentation/platform/firewall/) documents the resource and its nested resources. |
| Function Instance | The entity that holds one Function and the arguments that Function receives on one Firewall, listed in Azion Console under the **Functions Instances** tab. The Function must be created for the `firewall` execution environment. A rule with the _Run Function_ behavior runs the instance, which is how Bot Manager runs, and [Function instances for Firewall](/en/documentation/platform/firewall/functions-instances/) documents the entity. |
| global network list | The API's name for an Azion-maintained list, found in the error `22004 Cannot Change Global Network List` that answers any write to one. For the lists Azion maintains, refer to [Network Lists](/en/documentation/platform/firewall/network-shield/network-lists/#azion-maintained-lists). |
| IP/CIDR list | A Network List of type `ip_cidr`, _IP/CIDR_ in Azion Console, that holds IPv4 and IPv6 addresses and CIDR ranges such as `198.51.100.0/24`. A rule matches a request when its client IP address falls inside one of the entries. It is the only type whose items accept a due date and a comment, and [Network Lists](/en/documentation/platform/firewall/network-shield/network-lists/#list-types) compares the three types. |
| item | One entry in a Network List: an IP address or CIDR range, an ASN, or a country code, according to the list type. Exact duplicates are removed silently, while equivalent notations such as `192.0.2.80` and `192.0.2.80/32` are both kept. [Network Lists](/en/documentation/platform/firewall/network-shield/network-lists/) documents the format each type accepts. |
| log tag | The identifier a Function Instance stamps on the report lines it writes, so you can tell one instance's records from another's in [Real-Time Events](/en/documentation/platform/real-time-events/). The `log_tag` argument sets it, as [Arguments](/en/documentation/platform/firewall/bot-manager/arguments/#fields) documents. Bot Manager Lite writes it in the line prefix, `[Bot-Protection][<log_tag>]`, and Bot Manager writes it as a `log_tag` field. |
| Logging | The WAF mode that scores a request and records the match without blocking it, `logging` in the API and the other mode the _Set WAF_ behavior accepts. The API refuses `learning` with `10039`, but other surfaces keep that name, such as the `wafLearning` field of [Real-Time Events](/en/documentation/platform/real-time-events/), labeled **WAF Learning**. [Scoring and modes](/en/documentation/platform/firewall/waf/scoring-and-modes/#modes) compares both modes and names the other surfaces. |
| Main Settings | The tab of a Firewall that holds its settings in four sections: **General**, for its name, **Modules**, **Debug Rules**, and **Status**. It holds no domains, because a Workload's deployment sets the Firewall. [Set a Firewall's main settings](/en/documentation/guides/application-security/firewall-and-waf/firewall-configure-main-settings/) covers each section. |
| match zone | The part of a request a WAF condition inspects, such as a query string value, a header name, or the raw body, out of 15 in all. Azion Console sets one through the **Condition** field, not through a control named match zone, and the API takes it as `conditions[].match`. [Exceptions](/en/documentation/platform/firewall/waf/custom-allowed-rules/#match-zones) lists all 15. |
| matches | The Azion Console label of the comparison operator that tests a value against a regular expression, or, on the Network criterion, the client IP address against a Network List, where it sends `is_in_list`. With the `deny` behavior on the Network criterion, it is how a blocklist works. In the API, `matches` itself is refused on `${network}` with `25039 Invalid Operator`, and [Rules Engine for Firewall](/en/documentation/platform/firewall/rules-engine/#operators) lists the operators each variable takes. |
| `modules` | The API field that carries the four switches of a Firewall: `ddos_protection`, `functions`, `network_protection`, and `waf`, each with an `enabled` value. Azion Console renders it as the **Modules** section of **Main Settings**. Bot Manager has no key there because it runs as a Function Instance, and [Firewall](/en/documentation/platform/firewall/) describes the nested resources. |
| Network criterion | The [Rules Engine for Firewall](/en/documentation/platform/firewall/rules-engine/#criteria) criterion that compares the client IP address of a request with a Network List: _Network_ in Azion Console and `${network}` in the API. It is the only criterion Network Shield adds, so while Network Shield is off, Azion Console shows _Network - required Network Shield_ and the API answers `25047 Missing Required Modules`. Its argument is the list ID as a JSON integer, and a string fails with `25042 Invalid Operator Argument Type`. |
| Network List | An entity that holds items of one type, fixed when you create it: an IP/CIDR list, an ASN list, or a countries list. A rule uses it by ID through the Network criterion, and one list can serve many rules and Firewalls, so a change to its items changes what every one of them matches. [Network Lists](/en/documentation/platform/firewall/network-shield/network-lists/) documents its fields. |
| Network Lists | The Azion Console page where you create and manage Network Lists, served in the API at `/v4/workspace/network_lists`. Network Lists holds the lists, and Network Shield is what lets a Firewall rule match requests against them. For fields, types, and errors, refer to [Network Lists](/en/documentation/platform/firewall/network-shield/network-lists/). |
| Network Shield | A Platform Resource nested in Firewall that matches the requests to your Workloads by client address: a rule compares the client with a Network List through the Network criterion. It is on when you create a Firewall, and while a rule uses `${network}` it cannot be turned off: the API answers `24005 Cannot Disable Firewall Network Protection Module`. Its switch is **Network Shield** in the **Modules** section of **Main Settings**; [the Network Shield overview](/en/documentation/platform/firewall/network-shield/) describes it, and [Pricing](/en/documentation/fundamentals/pricing/) carries its plan availability. |
| `network_protection` | The API name of Network Shield on a Firewall: `modules.network_protection.enabled` in a `/v4/workspace/firewalls` request body, `true` by default. The error `25047` names the same setting `network_protection_enabled`. [Network Shield](/en/documentation/platform/firewall/network-shield/) describes the resource. |
| Operator | The WAF exception field that decides how the exception compares its strings: `regex` or `contains`, with `contains` as the default. It governs the exception's `path` and its condition's name or value together, and Azion Console sets it with the **Active** switch in the **Regex** section of the allowed rule form, on for `regex`. [Exceptions](/en/documentation/platform/firewall/waf/custom-allowed-rules/#fields) documents it with the other fields. |
| phase | The stage of a request in which rules run. A Firewall has one, the request phase, so every rule it holds is a request rule, kept under `request_rules` in the API. An Application adds a response phase, and [How Firewall works](/en/documentation/platform/firewall/how-it-works/#functions-on-a-firewall) shows where a Function on a Firewall runs. |
| propagation | The time a saved change takes to reach Azion's distributed infrastructure, during which answers alternate between the previous configuration and the one you saved. [How Firewall works](/en/documentation/platform/firewall/how-it-works/#propagation) covers what to expect for each kind of change. |
| Reputation Intelligence | The check that raises a request's score when its IP address is on a reputation [Network List](/en/documentation/platform/firewall/network-shield/network-lists/). Bot Manager checks the Azion-managed Network Lists of the account by default, and Bot Manager Lite runs the check as rule `14` against the lists in `reputation_network_lists`, which is empty by default. It is also a `bot_category` value, listed on [Logs](/en/documentation/platform/firewall/bot-manager/logs/#classification). |
| rule | An entry in the Rules Engine of a Firewall that applies its behaviors to every request its criteria match. A Firewall evaluates its rules in order, and a behavior such as _Deny (403 Forbidden)_ ends the evaluation for that request. Each rule belongs to one Firewall, at `/v4/workspace/firewalls/<firewall-id>/request_rules` in the API; [Rules Engine for Firewall](/en/documentation/platform/firewall/rules-engine/#rule-fields) lists its fields. |
| rule ID | The identifier of one internal WAF rule, which an exception carries to scope itself to that rule. `0` means all rules and is the default. The API accepts 63 IDs, `0` included, listed on [Rule sets](/en/documentation/platform/firewall/waf/rules-set/#internal-rules). |
| rule set | The WAF entity that carries the eight threat families and the sensitivity level chosen for each, listed in Azion Console under **WAF Rules**. A rule set detects nothing on its own: a Firewall rule with the _Set WAF_ behavior applies it to the requests the rule matches. [Rule sets](/en/documentation/platform/firewall/waf/rules-set/#fields) documents its fields. |
| Rules Engine for Firewall | The Feature of Firewall that holds a Firewall's rules and applies them, in order, to every request the Firewall inspects. Azion Console shows it as the **Rules Engine** tab of a Firewall, where each rule pairs criteria with the behaviors it applies. [Rules Engine for Firewall](/en/documentation/platform/firewall/rules-engine/) documents every criterion and behavior. |
| Run Function | The Rules Engine for Firewall behavior that runs a Function Instance on the requests a rule matches, `run_function` in the API, with at most one per rule. It needs the **Functions** switch in **Modules**, which is on when you create the Firewall through the API, the CLI, or the **Create Firewall** page. [Rules Engine for Firewall](/en/documentation/platform/firewall/rules-engine/#run-function) documents it. |
| score | A number WAF or Bot Manager computes for a request and compares with a threshold. WAF keeps one per threat family, raised by each further piece of evidence of that threat, and in _Blocking_ mode refuses a request whose score reaches its family's threshold, as [Scoring and modes](/en/documentation/platform/firewall/waf/scoring-and-modes/#scoring-and-sensitivity) describes. Bot Manager keeps one total, raised by each static rule matched and, outside Bot Manager Lite, by the dynamic score, and runs the Function Instance's `action` when it reaches the threshold, as [Bot scoring](/en/documentation/platform/firewall/bot-manager/bot-scoring/#scoring) describes. |
| sensitivity level | The setting that fixes the threshold of one threat family, with five values from `highest` to `lowest` and a default of `medium`. A higher sensitivity sets a lower threshold, so WAF blocks more requests. [Rule sets](/en/documentation/platform/firewall/waf/rules-set/#sensitivity-levels) carries the score each level blocks at. |
| Set WAF | The Rules Engine for Firewall behavior that applies a rule set to the requests a rule matches, together with the mode it runs in, `set_waf` in the API. A rule carries at most one, and Azion Console offers it only while WAF is on for the Firewall. Without it a rule set never runs; [Rules Engine for Firewall](/en/documentation/platform/firewall/rules-engine/#set-waf) documents its fields. |
| static rule | A check Bot Manager runs against the attributes of a single request, such as its headers and metadata, with no reference to earlier traffic. Each rule a request matches raises its score. [Bot Manager Lite](/en/documentation/platform/firewall/bot-manager/bot-manager-lite/#rules) publishes the rules that edition runs and the score each one adds. |
| threat family | One of the eight classes of attack a WAF rule set scores, each with its own sensitivity level, such as SQL injection, cross-site scripting, and directory traversal. [Rule sets](/en/documentation/platform/firewall/waf/rules-set/#threat-families) names all eight and what each one detects. |
| threshold | The score at which WAF or Bot Manager acts on a request. In WAF, the sensitivity level of a threat family fixes it, and a higher sensitivity sets a lower threshold, as [Scoring and modes](/en/documentation/platform/firewall/waf/scoring-and-modes/#scoring-and-sensitivity) describes. In Bot Manager, the `threshold` argument sets it: at or above it the Function Instance runs its `action`, which [Arguments](/en/documentation/platform/firewall/bot-manager/arguments/#action) lists, and below it the request continues to your Application. |
| Tuning | The tab on a WAF rule set that lists the requests each internal rule matched over a window of up to the last 3 days, grouped by rule ID. A query narrows by domain, time range, [Network List](/en/documentation/platform/firewall/network-shield/network-lists/), IP address, and country, and **More Details** narrows one rule's occurrences further by path. Selected records become allowed rules in bulk, as [Exceptions](/en/documentation/platform/firewall/waf/custom-allowed-rules/#tuning) documents. |
| under evaluation | The classification Bot Manager records when it has not identified a bot and does not yet hold enough fingerprint data to rule out an attack. A fingerprint Bot Manager has not seen for a while returns to this state. [Bot scoring](/en/documentation/platform/firewall/bot-manager/bot-scoring/#under-evaluation) gives the timings, and [Logs](/en/documentation/platform/firewall/bot-manager/logs/#classification) covers the four classifications. |
| WAF | A Platform Resource nested in Firewall that detects attacks in the requests to your Workloads and refuses or records them: it scores each request against eight threat families and, when the score reaches a threshold, refuses the request in _Blocking_ mode or records it in _Logging_ mode. Its full name is Web Application Firewall, the label of its switch in **Modules**, `modules.waf.enabled` in the API, and it is off when you create a Firewall. Azion Console offers the _Set WAF_ behavior only while it is on, and [the WAF overview](/en/documentation/platform/firewall/waf/) describes it. |
