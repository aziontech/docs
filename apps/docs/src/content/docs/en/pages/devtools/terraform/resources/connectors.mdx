A connector sets how your applications communicate with the origins that hold your content. In API v4, connectors take the place of the origins of API v3. The Azion Terraform Provider manages [Connectors](/en/documentation/platform/connectors/) with one resource and reads them with two data sources. In provider v1.x, an origin resource that belonged to an application did this work. To move a v1.x configuration to connectors, refer to [Migrate from provider v1.x to v2.0](/en/documentation/devtools/terraform/terraform-migration-v3-to-v4/).

---

## Connector resources

| Resource | Description |
| --- | --- |
| [`azion_connector`](https://registry.terraform.io/providers/aziontech/azion/latest/docs/resources/connector) | Creates and manages a connector. |

`azion_connector` takes its settings in one nested attribute, `connector`. It requires `name`, a string that holds the unique name of the connector, and `type`, which is `http` or `storage`:

- An `http` connector requires `http_attributes.addresses`, a list of origin addresses. Each entry takes an `endpoint` with the `address` of the origin and the optional `http_port`, `https_port`, and `active`. `http_attributes` also takes the optional `connection_options` and the `load_balancer` and `origin_shield` modules.
- A `storage` connector requires `storage_attributes.bucket`, the name of the bucket that holds the content, and takes an optional `prefix`.

After apply, `connector.id` holds the numeric ID of the connector. The Terraform Registry page of the resource lists every argument.

## Example

This configuration pins provider 2.10.0, creates an HTTP connector to the `origin.example.com` origin on ports 80 and 443, reads the existing connectors, and outputs the ID of the connector. It reads your personal token from the `api_token` variable that the [Azion Terraform Provider quickstart](/en/documentation/devtools/terraform/getting-started/) declares.

```hcl
terraform {
  required_providers {
    azion = {
      source  = "aziontech/azion"
      version = "2.10.0"
    }
  }
}

provider "azion" {
  api_token = var.api_token
}

# Create an HTTP connector
resource "azion_connector" "my_origin" {
  connector = {
    name   = "my-origin"
    type   = "http"
    active = true

    http_attributes = {
      addresses = [
        {
          endpoint = {
            address    = "origin.example.com"
            http_port  = 80
            https_port = 443
          }
        }
      ]
    }
  }
}

# Query existing connectors
data "azion_connectors" "all" {}

output "connector_id" {
  value = azion_connector.my_origin.connector.id
}
```
