This glossary defines the terms that the [Azion CLI](/en/documentation/devtools/cli/) uses in its commands, in the files of a project, and across its documentation.

| Term | Definition |
| --- | --- |
| Azion Bundler | The open-source framework adapter, published at [aziontech/bundler](https://github.com/aziontech/bundler), that lets the output of a web framework run on the Azion Platform. `azion build` and `azion deploy` run it through `npx` with the preset of the project, and [Azion CLI](/en/documentation/devtools/cli/) describes where it fits. |
| Azion GitHub App | The GitHub App that connects your GitHub account to your Azion account, so you can import a repository and build, deploy, and manage it as an application. [Manage the Azion GitHub App](/en/documentation/guides/application-development/automation/azion-github-app/) describes how to manage the connection. |
| `azion.config.js` | The infrastructure-as-code file of a project, built from the default settings of its preset and used as the source of truth for its configuration. `azion link` writes it as `azion.config.cjs` and `azion sync --iac` as `azion.config.mjs`, and `azion deploy` reads the `.mjs` file when both exist, as [azion.config.js](/en/documentation/devtools/cli/azion-config-js/) describes. |
| `azion.json` | The file in the `azion` folder of a project where `azion deploy` writes the ID of every resource it creates. The next deploy reads these IDs and updates the same resources instead of creating new ones, as [Azion CLI deploy](/en/documentation/devtools/cli/deploy/) describes. |
| cascade delete | The `--cascade` flag of `azion delete application`, which deletes the resources listed in `azion/azion.json` of the current directory. Any `--cascade` flag, `--cascade=false` included, deletes them, so leave it out to delete only the application, as [Azion CLI application](/en/documentation/devtools/cli/resources/application/#delete) describes. |
| Git Scope | The required **Git Scope** field in Azion Console that picks the GitHub account whose repositories you import, with **Add GitHub Account** at the foot of its dropdown. The **Repository** field stays disabled until you pick a scope, as [Import a project from GitHub](/en/documentation/guides/application-development/automation/import-an-existing-project-from-github/) describes. |
| noun | The resource word in `azion <verb> <noun>`, such as `application` in `azion create application`. [Resource commands](/en/documentation/devtools/cli/resources/) lists every noun and the verbs it takes. |
| personal token | The credential that authenticates your CLI commands and your calls to the Azion API, which each profile holds. [Azion CLI personal-token](/en/documentation/devtools/cli/resources/personal-token/) creates, lists, describes, and deletes them. |
| preset | A set of default build and deploy settings for one framework or language, such as `astro`, `html`, or `javascript`, which you can replace in `azion.config.js`. [Azion CLI presets](/en/documentation/devtools/cli/resources/presets/) lists every preset the CLI offers. |
| profile | A CLI configuration in `~/.azion` that holds a personal token and the account details the CLI stores with it, so you can switch between accounts or environments with `azion profiles`. [Azion CLI profile](/en/documentation/devtools/cli/resources/profile/) creates and deletes them. |
| template | A starter project that `azion init` offers after you choose a preset, such as *Hello World* for the *Javascript* preset. [Azion CLI init](/en/documentation/devtools/cli/init/) sets up a project from a preset and a template. |
| workload deployment | The object that names the application, the firewall, and the custom page set that serve the traffic of a workload. A workload holds one deployment, and [Azion CLI workload-deployment](/en/documentation/devtools/cli/resources/workload-deployment/) creates, lists, and describes it. |
