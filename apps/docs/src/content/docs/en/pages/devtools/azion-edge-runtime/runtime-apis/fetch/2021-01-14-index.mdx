The `fetch()` function sends an HTTP request from your Azion Runtime code and returns a promise that resolves to a [Response](/en/documentation/devtools/runtime/api-reference/response/). You read that response, change it, or pass it back to the client through `event.respondWith()` or the return value of your handler. `fetch()` belongs to the [Fetch API](https://developer.mozilla.org/en-US/docs/Web/API/Fetch_API), which also defines the [`Request`](https://developer.mozilla.org/en-US/docs/Web/API/Request) and [`Response`](https://developer.mozilla.org/en-US/docs/Web/API/Response) objects, CORS, and the semantics of the HTTP `Origin` header. With these objects, your code handles, modifies, or builds requests and responses while it answers a request.

Use `fetch()` to forward a request to an origin server and return its response, or to call a REST or GraphQL API that supplies part of a response. You can also combine data from several backends in one function, or retrieve remote assets or configuration and rewrite them before delivery.

:::note
Under `azion dev`, a response from `fetch()` reports `type` as `default`, and `redirected` stays `false` after a followed redirect. A redirect under `redirect: 'error'` rejects with `TypeError: fetch failed`, and an expired timeout rejects with the message `The operation was aborted due to timeout`.
:::

## Syntax

```javascript
fetch(request, init)
```

### Parameters

| Parameter | Type | Description |
| --- | --- | --- |
| `request` | `Request` or string | Request to send: a `Request` object, or a string that holds the URL to fetch. |
| `init` | Object (`RequestInit`) | Options of the request. |

The `init` object takes these options. `method`, `headers`, `body`, and `redirect` are the fields that the [Request](/en/documentation/devtools/runtime/api-reference/request/#properties) object documents, and `signal` cancels the request:

| Option | Type | Description |
| --- | --- | --- |
| `method` | String | Request method, such as `POST`. |
| `headers` | `Headers` object | Headers of the request. |
| `body` | — | Payload of the request, such as a JSON string. |
| `redirect` | String | Redirect mode: `follow`, `error`, or `manual`. With `follow`, the default, `fetch()` follows the redirect and resolves to the final response. With `manual`, it resolves to the redirect response, such as a `301` with its `location` header. With `error`, the promise rejects. |
| `signal` | `AbortSignal` | Signal that cancels the request, such as `AbortSignal.timeout(300)` to stop waiting after 300 ms. |

## Limits

In a deployed function, Azion Runtime limits how long one `fetch()` call waits at three points:

- 20 seconds to connect to the server
- 60 seconds to receive the response headers
- 60 seconds between two chunks of a body sent without a `Content-Length` header

Each limit applies to one call, so the next `fetch()` in the same invocation gets the full time again. The limit on the body counts the time between two chunks, not the whole transfer, so a body that keeps receiving data can take longer than 60 seconds.

The wall-clock ceiling of the invocation still applies: 5 minutes, I/O wait included. One invocation can also make a limited number of outbound `fetch()` calls, and a function processes a body up to a maximum size. For these values, refer to [Functions limits](/en/documentation/platform/functions/limits/).

To bound a call more tightly, pass `AbortSignal.timeout()` as `signal` in `init`. The signal is a deadline for the whole call, the body included, so it also stops a body that is still receiving data. When it expires, the pending `fetch()`, `read()`, or `text()` rejects with an error whose `name` is `TimeoutError`, which your code catches. A signal longer than these three limits does not extend them.

## Errors

The promise that `fetch()` returns rejects with these errors in a deployed function:

| Error | Cause | What to do |
| --- | --- | --- |
| `TimeoutError: Signal timed out.` | The `AbortSignal.timeout()` passed as `signal` expired before the response arrived, or while your code read the body. In the second case, `read()` or `text()` rejects with this error. The error is a `DOMException` whose `name` is `TimeoutError`. | Catch the rejection and check `error.name`, or pass a longer timeout. |
| `TypeError: Fetch failed: Encountered redirect while redirect mode is set to 'error'` | The server answered with a redirect, and `redirect` is `error`. | Set `redirect` to `follow` or `manual`, or catch the rejection. |

## Examples

### Return the response of another server

This `fetch` handler answers every request with the response that `fetch()` receives from `https://example.com`:

```javascript
export default {
  async fetch(request, env, ctx) {
    return fetch("https://example.com")
  }
}
```

The handler returns a response with this status, this content type, and this body. The other response headers are cut, and the body is cut after its title:

```json
{
 "status": 200,
 "statusText": "OK",
 "headers": {
  …
  "content-type": "text/html; charset=utf-8",
  …
 },
 "body": "<!doctype html><html lang=en><head><meta charset=utf-8><link rel=icon href=data:,><meta name=viewport content=\"width=device-width,initial-scale=1\"><title>Example Domain</title>…"
}
```

### Stop reading a slow streamed body

This `fetch` handler gives the whole call 5 seconds to read a body that a server streams. The signal covers the headers and the body, so the handler catches the `TimeoutError` in either phase. A server error, such as a `503`, gets a `502` answer before the handler reads the body:

```javascript
export default {
  async fetch(request, env, ctx) {
    let received = 0
    try {
      const response = await fetch("https://<your-streaming-origin>/", {
        signal: AbortSignal.timeout(5000)
      })
      if (!response.ok) {
        return new Response(`The server answered with status ${response.status}`, { status: 502 })
      }
      const reader = response.body.getReader()
      while (true) {
        const { done, value } = await reader.read()
        if (done) break
        received += value.byteLength
      }
      return new Response(`Body complete. Bytes received: ${received}`)
    } catch (error) {
      if (error.name === "TimeoutError") {
        return new Response(`Timed out after 5 seconds. Bytes received: ${received}`, { status: 504 })
      }
      throw error
    }
  }
}
```

Replace `<your-streaming-origin>` with the host of a server that streams its response body.

When the signal expires before the body ends, the handler answers with status `504` and the bytes it read until then, such as `Timed out after 5 seconds. Bytes received: 2`. A body that ends within 5 seconds gets status `200` and `Body complete. Bytes received:` followed by the total.
