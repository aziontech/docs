An application carries the content delivery logic of the Azion Platform: its [cache settings](/en/documentation/platform/applications/cache/cache-settings/), the [Rules Engine](/en/documentation/platform/applications/rules-engine/) rules that process each request, its [device groups](/en/documentation/platform/applications/device-groups/), and the [function instances](/en/documentation/platform/applications/functions-instances/) it runs. The Azion Terraform Provider manages [Applications](/en/documentation/platform/applications/) with six resources and reads them with ten data sources. To move a v1.x configuration to these resources, refer to [Migrate from provider v1.x to v2.0](/en/documentation/devtools/terraform/terraform-migration-v3-to-v4/).

---

## Application resources

| Resource | Description |
| --- | --- |
| [`azion_application_main_setting`](https://registry.terraform.io/providers/aziontech/azion/latest/docs/resources/application_main_setting) | Creates and manages the main settings of an application. |
| [`azion_application_cache_setting`](https://registry.terraform.io/providers/aziontech/azion/latest/docs/resources/application_cache_setting) | Creates and manages a cache setting. |
| [`azion_application_device_group`](https://registry.terraform.io/providers/aziontech/azion/latest/docs/resources/application_device_group) | Creates and manages a device group. |
| [`azion_application_rule_engine`](https://registry.terraform.io/providers/aziontech/azion/latest/docs/resources/application_rule_engine) | Creates and manages a Rules Engine rule. |
| [`azion_application_rule_engine_order`](https://registry.terraform.io/providers/aziontech/azion/latest/docs/resources/application_rule_engine_order) | Sets the order of the Rules Engine rules of one phase. |
| [`azion_application_function_instance`](https://registry.terraform.io/providers/aziontech/azion/latest/docs/resources/application_functions_instance) | Creates and manages a function instance in an application. |

These resources take their settings in one nested attribute:

| Resource | Nested attribute | Fields |
| --- | --- | --- |
| `azion_application_main_setting` | `application` | Requires `name`. The optional `modules` turns on the `cache`, `functions`, `application_accelerator`, and `image_processor` modules. |
| `azion_application_cache_setting` | `cache_setting` | Requires `name`. The optional `browser_cache` and `modules` hold the cache policy. |
| `azion_application_device_group` | `device_group` | Requires `name` and `user_agent`, the regular expression that matches the devices of the group. |
| `azion_application_rule_engine` | `results` | Requires `name`, `phase` (`request` or `response`), `criteria`, and `behaviors`. |
| `azion_application_function_instance` | `data` | Requires `name` and `function_id`, the ID of a function that the `azion_function` resource manages. |

After apply, `application.application_id` holds the numeric ID of the application. A cache setting, a device group, a Rules Engine rule, and a function instance belong to one application, so each of their resources takes that ID in `application_id`, outside the nested attribute. `azion_application_rule_engine_order` takes `application_id`, the `phase`, and `order`, the list of rule IDs in the order they run. A module that `modules` omits returns to its default on every apply. The Terraform Registry page of each resource lists every argument.

## Example

This configuration pins provider 2.10.0 and creates an application with the cache and functions modules on. It adds a cache setting and a Rules Engine rule in the `request` phase that bypasses the cache for paths under `/api/`. It also creates a function, instantiates it in the application, and outputs the ID of the application. It reads your personal token from the `api_token` variable that the [Azion Terraform Provider quickstart](/en/documentation/devtools/terraform/getting-started/) declares. For more on the `azion_function` resource, refer to [Resources and data sources](/en/documentation/devtools/terraform/examples/#functions).

```hcl
terraform {
  required_providers {
    azion = {
      source  = "aziontech/azion"
      version = "2.10.0"
    }
  }
}

provider "azion" {
  api_token = var.api_token
}

# Create main application
resource "azion_application_main_setting" "my_app" {
  application = {
    name   = "my-application"
    active = true

    modules = {
      cache = {
        enabled = true
      }
      functions = {
        enabled = true
      }
    }
  }
}

# Configure cache
resource "azion_application_cache_setting" "my_cache" {
  application_id = azion_application_main_setting.my_app.application.application_id

  cache_setting = {
    name = "static-cache"

    browser_cache = {
      behavior = "override"
      max_age  = 3600
    }

    modules = {
      cache = {
        behavior = "override"
        max_age  = 86400
      }
    }
  }
}

# Create rule in Rules Engine
resource "azion_application_rule_engine" "my_rule" {
  application_id = azion_application_main_setting.my_app.application.application_id

  results = {
    name   = "bypass-cache-api"
    phase  = "request"
    active = true

    criteria = [
      {
        entries = [
          {
            criterion = {
              variable    = "$${uri}"
              operator    = "starts_with"
              conditional = "if"
              argument    = "/api/"
            }
          }
        ]
      }
    ]

    behaviors = [
      {
        behavior = {
          type = "bypass_cache"
        }
      }
    ]
  }
}

# Create a function
resource "azion_function" "my_function" {
  function = {
    name                  = "my-function"
    active                = true
    runtime               = "azion_js"
    execution_environment = "application"
    default_args          = jsonencode({})
    code = trimspace(<<-EOT
      addEventListener("fetch", (event) => {
        event.respondWith(new Response("Hello from Azion"));
      });
    EOT
    )
  }
}

# Instantiate the function in the application
resource "azion_application_function_instance" "my_function" {
  application_id = azion_application_main_setting.my_app.application.application_id

  data = {
    name        = "my-function-instance"
    function_id = azion_function.my_function.function.id
    active      = true
  }
}

output "application_id" {
  value = azion_application_main_setting.my_app.application.application_id
}
```

The criterion writes the `${uri}` variable as `$${uri}`. With a single `$`, Terraform reads it as an interpolation and fails.
