Azion Runtime is compatible with a part of the Node.js APIs, not with all of them. A function, and every npm package it depends on, can import the 68 Node.js modules in the table below. Each one resolves when the build bundles the function, and loads in a deployed function and under `azion dev`. The status of a module says how much of its API works when the function calls it.

:::note
Under `azion dev`, some modules behave differently from a deployed function. `node:fs` paths resolve under the `.edge/storage/` folder of the project, an import of `pipeline` from `node:stream` fails the build, and `timingSafeEqual()` and `generateKeyPairSync()` from `node:crypto` throw.
:::

---

## Module imports

A function imports a Node.js module with the standard `import` syntax and the `node:` prefix:

```javascript
import { AsyncLocalStorage } from "node:async_hooks";
import os from "node:os";
```

A polyfill is code that adds a feature to an environment that lacks it. The build resolves through polyfills the Node.js APIs that the runtime does not provide, and the `polyfills` setting of [azion.config.js](/en/documentation/devtools/cli/azion-config-js/) sets whether the build adds them. The list of APIs the build resolves through polyfills is in the [Azion Bundler repository](https://github.com/aziontech/bundler/blob/main/lib/build/bundlers/polyfills/polyfills-manager.js), which also accepts contributions.

## Module support

The table lists each module with its status. Where a module page exists, the module name links to it. The Notes column states what a function receives when it calls the module, where that behavior is known.

- 🟢 **Supported**: the API works normally at runtime.
- 🟡 **Partially supported**: only some methods or features are available.
- 🔴 **Build-only**: the module is included so the build completes without errors, but its API calls do not work at runtime.

:::note[About the Azion Cells runtime environment]
A function on Azion runs inside a **Cell**, the isolation environment Azion builds on **V8 isolates**. A Cell is a lightweight, secure execution context, and the code inside it has no direct access to the operating system underneath.

For multi-tenant security and infrastructure integrity, a Cell does not give a function:

- The properties of the machine that runs it. `node:os` and `process` return fixed values instead, such as `linux` for `os.platform()`, an empty string for `os.hostname()`, and `0` for `os.totalmem()`.
- DNS resolution through native system calls (`node:dns`, `node:dns/promises`).
- Low-level TCP or UDP sockets that require direct system calls.

The modules marked 🔴 **Build-only** are included as stubs, so that npm packages with static imports of them still build. Their calls do not work at runtime: `dns.lookup()` throws `Error: [unenv] dns.lookup is not implemented yet!`.
:::
