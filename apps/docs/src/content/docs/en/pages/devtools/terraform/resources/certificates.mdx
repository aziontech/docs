A digital certificate is the SSL/TLS certificate and private key pair that lets an application answer over HTTPS. The Azion Terraform Provider manages the certificates of [Certificate Manager](/en/documentation/platform/workloads/certificate-manager/certificates/) with four resources and reads them with four data sources. Besides uploading a certificate that you already have, the provider can request a Let's Encrypt certificate, create a certificate signing request (CSR), and upload a certificate revocation list (CRL) for mTLS.

---

## Certificate resources

| Resource | Description |
| --- | --- |
| [`azion_digital_certificate`](https://registry.terraform.io/providers/aziontech/azion/latest/docs/resources/digital_certificate) | Creates and manages a digital certificate from a certificate and private key that you upload. |
| [`azion_certificate_request`](https://registry.terraform.io/providers/aziontech/azion/latest/docs/resources/certificate_request) | Requests a Let's Encrypt certificate. |
| [`azion_certificate_signing_request`](https://registry.terraform.io/providers/aziontech/azion/latest/docs/resources/certificate_signing_request) | Creates a certificate signing request (CSR). |
| [`azion_crl`](https://registry.terraform.io/providers/aziontech/azion/latest/docs/resources/crl) | Creates and manages a certificate revocation list (CRL). |

`azion_digital_certificate` takes its settings in one nested attribute, `results`, which requires three string arguments: `name`, the name of the certificate; `certificate_content`, the SSL/TLS certificate in PEM format; and `private_key`, the private key in PEM format. The provider treats `certificate_content` and `private_key` as sensitive. After apply, `results.id` holds the numeric ID of the certificate.

`azion_certificate_request` also takes `results`, with `name`, `common_name`, `authority` (`lets_encrypt`), and `challenge` (`dns` or `http`). The provider can only create a certificate request: it has no update operation for it. `azion_certificate_signing_request` takes the subject fields of the CSR in `results`, and a change to any of them recreates the CSR. `azion_crl` takes `crl`, with `name`, `issuer`, and the `crl` content. The Terraform Registry page of each resource lists every argument.

## Data sources

| Data source | Description |
| --- | --- |
| [`azion_digital_certificates`](https://registry.terraform.io/providers/aziontech/azion/latest/docs/data-sources/digital_certificates) | Lists digital certificates. |
| [`azion_digital_certificate`](https://registry.terraform.io/providers/aziontech/azion/latest/docs/data-sources/digital_certificate) | Reads one digital certificate. |
| [`azion_crls`](https://registry.terraform.io/providers/aziontech/azion/latest/docs/data-sources/crls) | Lists certificate revocation lists. |
| [`azion_crl`](https://registry.terraform.io/providers/aziontech/azion/latest/docs/data-sources/crl) | Reads one certificate revocation list. |

## Example

This configuration pins provider 2.10.0, creates a certificate from a certificate file and a private key file in the `certificates` folder of the module, reads the existing certificates, and outputs the ID of the certificate. It reads your personal token from the `api_token` variable that the [Azion Terraform Provider quickstart](/en/documentation/devtools/terraform/getting-started/) declares.

{/* terraform-validate: skip — file() needs the PEM files on disk; the next sample validates the same resource with variables */}
```hcl
terraform {
  required_providers {
    azion = {
      source  = "aziontech/azion"
      version = "2.10.0"
    }
  }
}

provider "azion" {
  api_token = var.api_token
}

# Create digital certificate
resource "azion_digital_certificate" "my_cert" {
  results = {
    name                = "certificate-mydomain"
    certificate_content = file("${path.module}/certificates/mydomain.pem")
    private_key         = file("${path.module}/certificates/mydomain-key.pem")
  }
}

# Query existing certificates
data "azion_digital_certificates" "all" {}

output "certificate_id" {
  value = azion_digital_certificate.my_cert.results.id
}
```

To keep the certificate and the private key out of the configuration code, declare them as sensitive variables. This block replaces the `azion_digital_certificate` resource of the configuration above:

```hcl
variable "ssl_certificate" {
  type        = string
  description = "SSL certificate in PEM format"
  sensitive   = true
}

variable "ssl_private_key" {
  type        = string
  description = "SSL private key in PEM format"
  sensitive   = true
}

resource "azion_digital_certificate" "my_cert" {
  results = {
    name                = "my-certificate"
    certificate_content = var.ssl_certificate
    private_key         = var.ssl_private_key
  }
}
```

A shorter form, with `cert.pem` and `key.pem` at the root of the module, is on [Resources and data sources](/en/documentation/devtools/terraform/examples/).
