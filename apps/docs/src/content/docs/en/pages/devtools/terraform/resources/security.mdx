The security resources of the Azion Terraform Provider configure what stops a request before it reaches your application: protection against threats, geolocation blocking, and rate limiting. The provider manages a [Firewall](/en/documentation/platform/firewall/) and its rules, rule order, and function instances, Web Application Firewall (WAF) [rule sets](/en/documentation/platform/firewall/waf/rules-set/) and their [exceptions](/en/documentation/platform/firewall/waf/custom-allowed-rules/), and [Network Lists](/en/documentation/platform/firewall/network-shield/network-lists/) with seven resources. Twelve data sources read the same objects back: for each object type except the rule order, one lists the objects and one reads a single object.

---

## Security resources

| Resource | Description |
| --- | --- |
| [`azion_firewall_main_setting`](https://registry.terraform.io/providers/aziontech/azion/latest/docs/resources/firewall_main_setting) | Creates and manages the main settings of a firewall. |
| [`azion_firewall_rule_engine`](https://registry.terraform.io/providers/aziontech/azion/latest/docs/resources/firewall_rule_engine) | Creates and manages a Rules Engine rule of a firewall. |
| [`azion_firewall_rule_engine_order`](https://registry.terraform.io/providers/aziontech/azion/latest/docs/resources/firewall_rule_engine_order) | Sets the order of the Rules Engine rules of a firewall. |
| [`azion_firewall_functions_instance`](https://registry.terraform.io/providers/aziontech/azion/latest/docs/resources/firewall_functions_instance) | Creates and manages a function instance in a firewall. |
| [`azion_waf`](https://registry.terraform.io/providers/aziontech/azion/latest/docs/resources/waf) | Creates and manages a WAF rule set, which Azion Console lists under **WAF Rules**. |
| [`azion_waf_rule_set`](https://registry.terraform.io/providers/aziontech/azion/latest/docs/resources/waf_rule_set) | Creates and manages a [WAF exception](/en/documentation/platform/firewall/waf/custom-allowed-rules/), which Azion Console lists as an allowed rule, in one rule set. |
| [`azion_network_list`](https://registry.terraform.io/providers/aziontech/azion/latest/docs/resources/network_list) | Creates and manages a network list of IP addresses and CIDR ranges, countries, or ASNs. |

These resources take their settings in one nested attribute:

| Resource | Nested attribute | Fields |
| --- | --- | --- |
| `azion_firewall_main_setting` | `data` | Requires `name`. The optional `active` sets whether the firewall is active, and `modules` turns on the `waf`, `network_protection`, and `functions` modules. |
| `azion_firewall_rule_engine` | `results` | Requires `name`, `criteria`, and `behaviors`, such as `deny`, `drop`, `set_waf`, or `set_rate_limit`. |
| `azion_firewall_functions_instance` | `data` | Requires `name` and `function`, the ID of a function that the `azion_function` resource manages. |
| `azion_waf` | `result` | Requires `name`. The optional `engine_settings` holds the threat families and their sensitivity. |
| `azion_waf_rule_set` | `result` | Requires `name` and `conditions`, the parts of the request that the exception exempts. The optional `rule_id` is the internal rule it exempts, and `0` exempts all of them. |
| `azion_network_list` | `results` | Requires `name`, `type` (`ip_cidr`, `countries`, or `asn`), and `items`, the IP addresses and CIDR ranges, country codes, or ASNs of the list. |

The rule, rule order, and function instance resources take the ID of their firewall in `firewall_id`, and `azion_waf_rule_set` takes the ID of its rule set in `waf_id`, outside the nested attribute. After apply, `data.id` holds the numeric ID of a firewall and `result.id` the numeric ID of a WAF rule set. A rule set scores requests only when the firewall has the `waf` module on and a firewall rule runs the `set_waf` behavior with the rule set ID and a mode of `logging` or `blocking`. A firewall runs on a workload through the `firewall` attribute of a deployment strategy; for more information, refer to [Workloads resources](/en/documentation/devtools/terraform/workloads/). A module that `modules` omits returns to its default on every apply. The Terraform Registry page of each resource lists every argument.

## Example

This configuration pins provider 2.10.0 and creates a network list of blocked IP ranges and an active firewall with the WAF and network protection modules on. It creates a WAF rule set with an exception for the `/health` path, adds a firewall rule that denies requests from the network list, and adds a rule that runs the rule set in `blocking` mode on every request. It outputs the ID of the firewall. It reads your personal token from the `api_token` variable that the [Azion Terraform Provider quickstart](/en/documentation/devtools/terraform/getting-started/) declares.

```hcl
terraform {
  required_providers {
    azion = {
      source  = "aziontech/azion"
      version = "2.10.0"
    }
  }
}

provider "azion" {
  api_token = var.api_token
}

# Create network list for blocked IPs
resource "azion_network_list" "blocked_ips" {
  results = {
    name  = "blocked-ips"
    type  = "ip_cidr"
    items = ["192.0.2.0/24", "198.51.100.10"]
  }
}

# Create firewall
resource "azion_firewall_main_setting" "my_firewall" {
  data = {
    name   = "my-firewall"
    active = true

    modules = {
      waf = {
        enabled = true
      }
      network_protection = {
        enabled = true
      }
    }
  }
}

# Create a WAF rule set
resource "azion_waf" "my_waf" {
  result = {
    name   = "my-waf"
    active = true
  }
}

# Create WAF exception for the health check path
resource "azion_waf_rule_set" "health_check" {
  waf_id = azion_waf.my_waf.result.id

  result = {
    name     = "allow-health-check"
    active   = true
    path     = "/health"
    operator = "contains"
    rule_id  = 0

    conditions = [
      {
        condition = {
          match          = "any_url"
          condition_type = "generic"
        }
      }
    ]
  }
}

# Deny requests from the network list
resource "azion_firewall_rule_engine" "deny_blocked_ips" {
  firewall_id = azion_firewall_main_setting.my_firewall.data.id

  results = {
    name   = "deny-blocked-ips"
    active = true

    criteria = [
      {
        entries = [
          {
            criterion = {
              variable    = "$${network}"
              operator    = "is_in_list"
              conditional = "if"
              argument    = azion_network_list.blocked_ips.id
            }
          }
        ]
      }
    ]

    behaviors = [
      {
        behavior = {
          type = "deny"
        }
      }
    ]
  }
}

# Run the WAF on every request
resource "azion_firewall_rule_engine" "run_waf" {
  firewall_id = azion_firewall_main_setting.my_firewall.data.id

  results = {
    name   = "run-waf"
    active = true

    criteria = [
      {
        entries = [
          {
            criterion = {
              variable    = "$${request_uri}"
              operator    = "starts_with"
              conditional = "if"
              argument    = "/"
            }
          }
        ]
      }
    ]

    behaviors = [
      {
        behavior = {
          type = "set_waf"
          attributes = {
            waf_id = azion_waf.my_waf.result.id
            mode   = "blocking"
          }
        }
      }
    ]
  }
}

output "firewall_id" {
  value = azion_firewall_main_setting.my_firewall.data.id
}
```

The criteria write the `${network}` and `${request_uri}` variables as `$${network}` and `$${request_uri}`. With a single `$`, Terraform reads them as interpolations and fails. For `is_in_list`, the `argument` is the ID of the network list.
