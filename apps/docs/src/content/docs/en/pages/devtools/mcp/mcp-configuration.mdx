This guide instructs you through your first question to the Azion MCP servers from Claude Code. It connects the docs server, which only reads, and then shows how to add the four servers that change your account.

- Create a personal token in Azion Console.
- Register the docs server in Claude Code with one command.
- Check the tools and resources the server exposes with the MCP Inspector.
- Ask Claude Code a question that the server answers from the Azion documentation.

Three pieces connect, in this order:

1. The **personal token** identifies your Azion account.
2. The **server entry** `azion-docs` in Claude Code points at `https://docs-mcp.azion.com/mcp` and sends the token in the `Authorization` header of every request.
3. The **docs server** checks the token and gives Claude Code its tools and resources.

For more information about the servers, refer to [MCP server](/en/documentation/devtools/mcp/).

---

## Prerequisites

- An Azion account. To create one, refer to [Create an account](/en/documentation/fundamentals/creating-account/).
- Claude Code, installed on your machine.
- Node.js and npm. The MCP Inspector runs with `npx`.

---

## 1. Create a personal token

The servers accept an Azion personal token as their credential. To create the token in Azion Console:

<DocSteps>
  <DocStep title="Open the personal tokens page">

  Access [Azion Console](https://console.azion.com/) > **Account** > **Personal Token**. **Account** is the avatar menu.

  </DocStep>
  <DocStep title="Select + Personal Token" />
  <DocStep title="Name the token">

  In the **General** section, enter a **Name**. For example: `mcp-server`. The servers act with the permissions of this token, so scope it to what the agent needs.

  </DocStep>
  <DocStep title="Set the expiration">

  In the **Token** section, select a value in **Expires within**. The default is _1 day_.

  </DocStep>
  <DocStep title="Select Save" />
  <DocStep title="Copy the token">

  In the **Personal Token has been created** dialog, select **Copy**. The dialog shows the token only once, so store it before you continue.

  </DocStep>
  <DocStep title="Select Confirm" />
</DocSteps>

The token appears in the **Personal Tokens** list, and its value is in your clipboard. For more information, refer to [How to manage a personal token](/en/documentation/guides/platform/account-and-billing/personal-tokens/).

Keep the token safe:

- Never commit a token. Add every configuration file that holds one to `.gitignore`.
- Store the token in an environment variable when your client supports it.
- Rotate your tokens regularly.

## 2. Connect Claude Code

The `claude mcp add` command registers a server. The `-t http` flag selects the HTTP transport, `-s user` stores the server for every project, and `-H` sets the header that carries your token. Run the command, and replace `[TOKEN VALUE]` with your token:

```bash
claude mcp add "azion-docs" "https://docs-mcp.azion.com/mcp" -t http -s user -H "Authorization: Token [TOKEN VALUE]"
```

Claude Code stores the server in your user configuration, which is not a file in your project. The personal token goes in the `Token` scheme. A `Bearer` value is read as an OAuth access token, so a personal token sent as `Bearer` fails with `401`.

Claude Code has the docs server registered as `azion-docs`. To add another server, run the same command with its name and URL:

| Server | Name | URL |
| --- | --- | --- |
| build | `azion-build` | `https://build-mcp.azion.com/mcp` |
| secure | `azion-secure` | `https://secure-mcp.azion.com/mcp` |
| observe | `azion-observe` | `https://observe-mcp.azion.com/mcp` |
| storage | `azion-storage` | `https://storage-mcp.azion.com/mcp` |

These four servers create, change, and delete resources in your account. Add only the ones the agent needs. For what each one covers, refer to [Tools and resources](/en/documentation/devtools/mcp/tools/). For more information about Claude Code with Azion, refer to [Claude Code + Azion](/en/documentation/agent-setup/claude-code/).

## 3. Check the connection

The MCP Inspector connects to an MCP server and lists what the server exposes. Start the Inspector:

```bash
npx @modelcontextprotocol/inspector
```

To install the Inspector instead of running it through `npx`, run `npm install -g @modelcontextprotocol/inspector`.

To connect the Inspector to the docs server:

<DocSteps>
  <DocStep title="Select the transport">

  Set **Transport type** to _streamable-http_.

  </DocStep>
  <DocStep title="Enter the server address">

  In **URL**, enter `https://docs-mcp.azion.com/mcp`.

  </DocStep>
  <DocStep title="Enter the header">

  In **Authentication**, enter `Authorization: Token [TOKEN VALUE]`, with your token in place of `[TOKEN VALUE]`.

  </DocStep>
  <DocStep title="Select Connect" />
  <DocStep title="Open the Tools tab" />
  <DocStep title="Open the Resources tab" />
</DocSteps>

The **Tools** tab lists seven tools, and the **Resources** tab lists seven resources. For the full list, refer to [Tools and resources](/en/documentation/devtools/mcp/tools/#docs-server-tools).

A request without a token fails with `401`, and a request with an invalid token fails with `403`. To diagnose a failed connection, refer to [Troubleshoot the MCP server](/en/documentation/devtools/mcp/troubleshooting/).

## 4. Ask your first question

The `search_azion_docs_and_site` tool searches the Azion documentation and website. In a Claude Code session, ask a question that needs it:

```text
Search the Azion documentation: how to configure cache
```

The tool returns the documentation pages that best match the question, each with its title, content, and source URL. Claude Code builds its answer from these pages.

The other tools of the docs server return code samples, Azion CLI commands, Azion API operations, Terraform resources, and guides to deploy a static site. With the build and observe servers also connected, the agent can create rules and write GraphQL queries for your account. Try one of these prompts next:

- `I have a static website with HTML, CSS, and JavaScript files. Help me deploy it to Azion.`
- `Generate a query to analyze cache hit rates for my images.`
- `Create Rules Engine rules to add security headers including HSTS, X-Frame-Options, and CSP for my application. Preview them with dry_run first.`
- `My deployment is failing with error 503. How can I debug this?`

Claude Code answers questions about Azion from the docs server.

## Connect another client

Each client in the table below has its own setup page. Each page connects the docs server, and the other servers connect the same way with their URLs:

| Client | Where the server is configured | Setup page |
| --- | --- | --- |
| Cursor | `.cursor/mcp.json` | [Cursor + Azion](/en/documentation/agent-setup/cursor/) |
| GitHub Copilot | `.vscode/mcp.json` | [GitHub Copilot + Azion](/en/documentation/agent-setup/github-copilot/) |
| Windsurf | `.codeium/windsurf/mcp_config.json` | [Windsurf + Azion](/en/documentation/agent-setup/windsurf/) |
| Codex | `~/.codex/config.toml` | [Codex + Azion](/en/documentation/agent-setup/codex/) |
| Gemini CLI | `~/.gemini/settings.json` | [Gemini CLI + Azion](/en/documentation/agent-setup/gemini-cli/) |
| OpenCode | `opencode.json` | [OpenCode + Azion](/en/documentation/agent-setup/opencode/) |

Claude Desktop, Warp, and Kiro have no setup page. Their configurations follow.

### Claude Desktop

Claude Desktop starts the connection through `mcp-remote`, a bridge between a local client and a remote MCP server. The `npx` command downloads `mcp-remote` on first use, and the bridge needs Node.js 18 or later.

In the Claude Desktop settings, open the MCP configuration and add the docs server. Replace `[TOKEN VALUE]` with your token:

```json
{
  "mcpServers": {
    "azion-docs": {
      "command": "npx",
      "args": [
        "-y",
        "mcp-remote@latest",
        "https://docs-mcp.azion.com/mcp",
        "--header",
        "Authorization: Token [TOKEN VALUE]"
      ]
    }
  }
}
```

### Warp

Warp also connects through `mcp-remote`, with the same Node.js requirement. In the Warp MCP settings, add the docs server. This configuration has no `mcpServers` key around the server. Replace `[TOKEN VALUE]` with your token:

```json
{
  "azion-docs": {
    "command": "npx",
    "args": [
      "-y",
      "mcp-remote@latest",
      "https://docs-mcp.azion.com/mcp",
      "--header",
      "Authorization: Token [TOKEN VALUE]"
    ]
  }
}
```

### Kiro

Kiro sends the token in a header. Create the file `.kiro/settings/mcp.json` with the docs server. Replace `[TOKEN VALUE]` with your token:

```json
{
  "mcpServers": {
    "azion-docs": {
      "url": "https://docs-mcp.azion.com/mcp",
      "headers": {
        "Authorization": "Token [TOKEN VALUE]"
      }
    }
  }
}
```
