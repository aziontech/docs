The Azion CLI `deploy` command builds the project in the current directory and deploys it to Azion. It creates or updates the project's [Application](/en/documentation/platform/applications/), its [Workload](/en/documentation/platform/workloads/), and, for a static site, the [Object Storage](/en/documentation/platform/object-storage/) bucket that holds the files. By default the build runs on Azion; with `--local`, it runs on your machine. The options every command accepts, such as `--format`, `--out`, and `-y`, are on [Global options](/en/documentation/devtools/cli/globals/).

---

## Usage

`azion deploy` reads the project settings from the `azion` folder of the current directory and deploys the project.

This command deploys the project:

```bash
azion deploy
```

With `--local`, the deploy uploads the folder that the `dir` field of the `storage` entry names in the project's `azion.config` file. That folder is `./.edge/assets` with the `vue` preset and `./www` with the `html` preset. With `--local --debug`, the output names it, as in `Path to be uploaded: ./.edge/assets`. To upload another folder, set its path in `dir`.

To check which files a deploy with `--local` uploaded, list the objects of the bucket with `azion list storage object`. After a successful deploy, its keys start with the `prefix` field of `azion/azion.json`. For the command and its `--page-size` and `--next-page` flags, refer to [Azion CLI storage](/en/documentation/devtools/cli/resources/storage/#list).

### Flags

| Flag | Short | Type | Default | Description |
| --- | --- | --- | --- | --- |
| `--alias-env` | — | — | — | Passes `--alias-env` to the build phase of the deploy, so the variables read from the project's `.env` files get a prefix built from the project's name. For more information, refer to [Azion CLI build](/en/documentation/devtools/cli/build/). |
| `--auto` | — | — | — | Runs the whole command without stopping for a question. |
| `--config-dir` | — | string | `"azion"` | Relative path to the folder that holds your `azion.json` and `args.json` files. |
| `--config-file` | — | string | — | Path to the `azion.config` file to deploy with, such as `azion.staging.config.cjs`. Without it, the deploy uses the `azion.config.*` file in the current directory. In a remote deploy, the default, the file must be inside the project directory, because only that directory is uploaded. With `--local`, the deploy writes the storage prefix into this file and builds from it. A missing file, or a file outside the project in a remote deploy, is rejected before the deploy changes anything on your machine or on Azion. |
| `--dry-run` | — | — | — | Lists the steps the deploy would run, without running them. The dry run creates and changes no resource and leaves `azion/azion.json` untouched, and `--format json` prints the list as JSON. The steps are those of the `--local` flow, also when you run `azion deploy --dry-run` without `--local`. |
| `--env` | — | string | `".edge/.env"` | Relative path to your `.env` file. |
| `--local` | — | — | — | Runs the build and the deploy on your machine instead of on Azion. Use it when you need your own build environment or more control over the build. |
| `--no-prompt` | — | — | — | Returns the error instead of asking a question when a step fails. |
| `--path` | — | string | — | Deprecated. The deploy ignores it and uploads the folder that `azion.config` sets. |
| `--skip-build` | — | — | — | On a later deploy with `--local`, skips the build and the upload of static files. |
| `--skip-framework-build` | — | — | — | On a later deploy with `--local`, skips the framework build, such as `vite build`. |
| `--sync` | — | — | — | Synchronizes the local `azion.json` file with the remote resources. |
| `--workers` | — | int | auto-calculated based on CPU cores, max `20` | Number of upload workers that send files at the same time. |
| `--writable-bucket` | — | — | — | Creates the project bucket with read-write access. |

The CLI manages the storage credentials each route needs, so no upload asks you for one. A default deploy uploads the source files for the remote build, with the credentials in `~/.azion/<profile>/settings.toml`. With `--local`, the CLI uploads the built static files itself and keeps one credential set per bucket in `~/.azion/<profile>/credentials.toml`.

:::note
The behavior of `--path`, `--skip-build`, and `--skip-framework-build` on this page is that of Azion CLI 4.27.0 and later. To print the installed version, run `azion --version`. To update the CLI, refer to [Install the CLI](/en/documentation/devtools/cli/#install-the-cli).
:::

The deploy ignores `--path` and prints this warning:

```text
Flag --path has been deprecated, it is ignored and will be removed in a future release; set the storage directory in azion.config instead
```

What `--skip-build` and `--skip-framework-build` do depends on whether the project was deployed before and on where the build runs:

| Flag | First deploy | Later deploy with `--local` | Deploy without `--local` |
| --- | --- | --- | --- |
| `--skip-framework-build` | Ignored: the framework build runs | Skips the framework build and uploads its existing output | Ignored: Azion runs the framework build |
| `--skip-build` | Ignored: the build runs | Skips the build and the upload, and keeps the storage prefix | Ignored: Azion runs the build |

When you pass either flag to the first deploy with `--local`, the command prints `This is the project's first deploy, so --skip-build and --skip-framework-build are ignored: the project is built and its static files are generated and uploaded`. The first deploy runs the framework build, such as `vite build`, so the project folder needs its `package.json` and the app's source. A first deploy that stops at the build does not count, so the next deploy is a first deploy too.

On a later deploy with `--local`, `--skip-framework-build` runs the Azion build without the framework build. The `vue` preset copies the existing Vite output folder, `dist` by default, into `./.edge/assets`, and the deploy uploads that folder under a new storage prefix. Without that folder, the deploy stops with the storage folder error in [Errors](/en/documentation/devtools/cli/deploy/#errors).

With `--skip-build` instead, the deploy uploads no file and prints `Skipping the upload of static files: --skip-build was passed, so no new static files were generated`. It keeps the storage prefix of the previous deploy and updates each resource from `.edge/manifest.json`. The folder that `dir` names still has to hold files, or the deploy stops with the same storage folder error.

Without `--local`, the deploy runs the build on Azion and ignores both flags with no warning. Azion runs the framework build again and uploads its output instead of the folder you built.

## Examples

Each example shows the command and the output it prints.

### Deploy with a remote build

This command deploys a static site for the first time. The CLI uploads the source files, and the build runs on Azion:

```bash
azion deploy
```

The command prints a link to the **Deploy** page of Azion Console, where **Deploy Log** shows the progress of the deploy, and then the domain of the site:

```text
Running deploy command
Uploading source files

Upload completed successfully!
Please visit https://console.azion.com/create/deploy/00000000-0000-0000-0000-000000000002 in case it did not open automatically, to follow up the full deploy process
Your Application was deployed successfully

To visualize your application access the Domain: https://xxxxxxxxxx.map.azionedge.net
Your application is being deployed to all Azion Locations and it might take a few minutes.
```

The first deploy can take several minutes to answer from every location; later deploys take about two minutes.

### Deploy with a local build

This command deploys a change to the same site. The CLI builds the project on your machine, uploads the files, and updates each resource by the ID in `azion/azion.json`:

```bash
azion deploy --local
```

The command runs the build itself, whether or not an earlier `azion build` left a `.edge` folder. On a later deploy, `--skip-build` skips it, and `--skip-framework-build` skips only the framework build. ### Preview a deploy

This command simulates a local deploy of the same site:

```bash
azion deploy --local --dry-run
```

The command exits without changing any resource, and `azion/azion.json` keeps the same content.

## Errors

| Error | Cause | What to do |
| --- | --- | --- |
| `Failed to capture deploy logs: <reason>. Please check your account to verify if the resources were successfully created.` | The upload finished, and the CLI could not follow the build and the deploy that run on Azion. The deploy may have created only part of the project's resources. | Rerun with `--debug` to print the log of the build that runs on Azion. For every fix, refer to [Failed to capture deploy logs](/en/documentation/devtools/cli/troubleshooting/#azion-deploy-fails-with-failed-to-capture-deploy-logs). |
| `Error: Storage folder './.edge/assets' is missing or empty.` | The folder that `dir` names holds no file, such as when `dist` is missing with `--skip-framework-build`. | Build the app, such as with `npm run build`, and deploy again with `--local`, with or without `--skip-framework-build`. `--skip-build` does not refill the folder. If the project serves no static files, remove the `storage` entry from `azion.config`. |
