The Azion CLI `deploy` command builds the project in the current directory and deploys it to Azion. It creates or updates the project's [Application](/en/documentation/platform/applications/), its [Workload](/en/documentation/platform/workloads/), and, for a static site, the [Object Storage](/en/documentation/platform/object-storage/) bucket that holds the files. By default the build runs on Azion; with `--local`, it runs on your machine. The options every command accepts, such as `--format`, `--out`, and `-y`, are on [Global options](/en/documentation/devtools/cli/globals/).

---

## Usage

`azion deploy` reads the project settings from the `azion` folder of the current directory and deploys the project:

```bash
azion deploy [flags]
```

| Flag | Short | Type | Default | Description |
| --- | --- | --- | --- | --- |
| `--auto` | — | — | — | Runs the whole command without stopping for a question. |
| `--config-dir` | — | string | `"azion"` | Relative path to the folder that holds your `azion.json` and `args.json` files. |
| `--dry-run` | — | — | — | Simulates the deploy without changing any resource. |
| `--env` | — | string | `".edge/.env"` | Relative path to your `.env` file. |
| `--local` | — | — | — | Runs the build and the deploy on your machine instead of on Azion. Use it when you need your own build environment or more control over the build. |
| `--no-prompt` | — | — | — | Returns the error instead of asking a question when a step fails. |
| `--path` | — | string | — | Path to the folder that holds your static files. |
| `--skip-build` | — | — | — | Deploys without running the build first. |
| `--skip-framework-build` | — | — | — | Skips the framework build that runs before `azion build`. |
| `--sync` | — | — | — | Synchronizes the local `azion.json` file with the remote resources. |
| `--workers` | — | int | auto-calculated based on CPU cores, max `20` | Number of upload workers that send files at the same time. |
| `--writable-bucket` | — | — | — | Creates the project bucket with read-write access. |

For a static site, the CLI manages the storage credentials it uses to upload the files and keeps them in `~/.azion/<profile>/credentials.toml`. The deploy reads them from that file, so the upload needs no credential from you.

## Examples

Each example shows the command and the output it prints.

### Deploy with a remote build

This command deploys a static site for the first time. The CLI uploads the source files, and the build runs on Azion:

```bash
azion deploy
```

The command prints a link to the **Deploy** page of Azion Console, where **Deploy Log** shows the progress of the deploy, and then the domain of the site:

```text
Running deploy command
Uploading source files

Upload completed successfully!
Please visit https://console.azion.com/create/deploy/9241bdbc-fe9f-4fbb-803a-0ca3b15911d3 in case it did not open automatically, to follow up the full deploy process
Your Application was deployed successfully

To visualize your application access the Domain: https://mz0kbijeiw0.map.azionedge.net
Your application is being deployed to all Azion Locations and it might take a few minutes.
```

The first deploy can take several minutes to answer from every location; later deploys take about two minutes.

### Deploy with a local build

This command deploys a change to the same site. The CLI builds the project on your machine, uploads the files, and updates each resource by the ID in `azion/azion.json`:

```bash
azion deploy --local
```

The command runs the build itself, even when the project has no `.edge` folder from an earlier `azion build`. Before the build, it writes a new storage prefix into `azion.config.cjs`, or into `azion.config.mjs` when the project has both files:

### Preview a deploy

This command simulates a local deploy of the same site:

```bash
azion deploy --local --dry-run
```

The command exits without changing any resource, and `azion/azion.json` keeps the same content.
