The Azion CLI `workload-deployment` commands create, list, and describe the deployment of a workload in [Workloads](/en/documentation/platform/workloads/). A deployment names the application, the firewall, and the custom page set that serve the traffic of a workload, and a workload holds one deployment. The CLI has no command that updates or deletes a deployment. To change one, refer to [Workload settings](/en/documentation/platform/workloads/settings/). The options every command accepts, such as `--format`, `--out`, and `-y`, are on [Global options](/en/documentation/devtools/cli/globals/).

---

## Create

`azion create workload-deployment` creates a deployment in a workload with the settings you pass:

```bash
azion create workload-deployment [flags]
```

| Flag | Short | Type | Default | Description |
| --- | --- | --- | --- | --- |
| `--active` | — | string | — | Turns the deployment on (`true`) or off (`false`). |
| `--application-id` | — | int | — | ID of the application that serves the traffic of the workload. |
| `--current` | — | string | — | Takes `true` or `false`. With `true`, this deployment is the one the workload runs. |
| `--custom-page` | — | string | — | ID of the custom page set that replaces error responses for the workload. |
| `--file` | — | string | — | Path to a JSON file with the attributes of the deployment. Use `-` to read the JSON from standard input. |
| `--firewall-id` | — | int | — | ID of the firewall that runs its rules on requests before the application. |
| `--name` | — | string | — | Name of the deployment. |
| `--strategy-type` | — | string | — | Type of the deployment strategy, such as `default`. |
| `--workload-id` | — | int | — | ID of the workload that holds the deployment. |

This command creates a deployment named `my-deployment` in the workload with ID `1791031346`. The deployment sends the traffic to the application with ID `1791039173` and uses the custom page set with ID `974`:

```bash
azion create workload-deployment --workload-id 1791031346 --name my-deployment --strategy-type default --application-id 1791039173 --custom-page 974 --active true --current true
```

The command prints the ID of the deployment:

```text
Created Workload Deployment with ID 337251
```

## List

`azion list workload-deployment` lists the deployments of one workload, 50 to a page:

```bash
azion list workload-deployment [flags]
```

| Flag | Short | Type | Default | Description |
| --- | --- | --- | --- | --- |
| `--details` | — | — | — | Adds a column with the ID of the application and a column with the ID of the firewall to the `ID` and `CURRENT` columns. |
| `--filter` | — | string | — | Name to filter the list by. |
| `--order-by` | — | string | — | Field to sort the list by. |
| `--page` | — | int | `1` | Number of the page to return. |
| `--page-size` | — | int | `50` | Number of deployments on each page. |
| `--workload-id` | — | int | — | **Required**. ID of the workload whose deployments the command lists. Without it, the command asks `? Enter the Workload ID to list its Deployments`. |

This command lists the deployments of the workload with ID `1791031346`, with the application and firewall columns:

```bash
azion list workload-deployment --workload-id 1791031346 --details
```

The command prints one row per deployment. A deployment without a firewall shows `0` in the firewall column:

```text
ID      CURRENT  EDGE APPLICATION  EDGE FIREWALL
337251  true     1791039173        0
```

## Describe

`azion describe workload-deployment` prints the settings of one deployment:

```bash
azion describe workload-deployment [flags]
```

| Flag | Short | Type | Default | Description |
| --- | --- | --- | --- | --- |
| `--deployment-id` | — | int | — | ID of the deployment to describe. |
| `--workload-id` | — | int | — | ID of the workload that holds the deployment. |

## Use a JSON file

`azion create workload-deployment` reads the attributes of the deployment from a JSON file with `--file`.

This file creates an active deployment named `my-deployment-file` that sends the traffic to the application with ID `1791039173`. The command reads `name`, `active`, `current`, and `strategy` from it:

```json
{
  "name": "my-deployment-file",
  "active": true,
  "current": false,
  "strategy": {
    "type": "default",
    "attributes": {
      "application": 1791039173
    }
  }
}
```

The file holds no workload ID, so pass `--workload-id` on the command line with the file:

```bash
azion create workload-deployment --workload-id 1791031347 --file dep-create.json
```

The command prints the ID of the deployment:

```text
Created Workload Deployment with ID 337252
```

A workload holds one deployment. Passed for a workload that already holds a deployment, the same file fails with this error:

```text
Error: Failed to create the Workload Deployment: ["The maximum number of deployments allowed per workload is 1."]. Check your settings and try again. If the error persists, contact Azion support.
```
