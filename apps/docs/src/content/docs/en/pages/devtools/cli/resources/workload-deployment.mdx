The Azion CLI `workload-deployment` commands create, list, describe, and update the deployment of a [workload](/en/documentation/platform/workloads/). The deployment names the application that answers the workload's domains and, optionally, the [firewall](/en/documentation/platform/firewall/) that inspects requests first and the [custom page set](/en/documentation/platform/workloads/custom-pages/settings/) that replaces error responses. A workload holds one deployment. The CLI has no command that deletes a deployment. The options every command accepts, such as `--format`, `--out`, and `-y`, are on [Global options](/en/documentation/devtools/cli/globals/). This page matches Azion CLI 4.24.0.

---

## Create

`azion create workload-deployment` creates the deployment of a workload:

```bash
azion create workload-deployment [flags]
```

| Flag | Short | Type | Default | Description |
| --- | --- | --- | --- | --- |
| `--workload-id` | — | int | — | ID of the workload the deployment belongs to. Without it, and without `--file`, the command asks for it. |
| `--name` | — | string | — | Name of the deployment. Without it, and without `--file`, the command asks for it. |
| `--application-id` | — | int | — | ID of the application the deployment serves. Without it, and without `--file`, the command asks for it. |
| `--firewall-id` | — | int | — | ID of the firewall that inspects the workload's requests. |
| `--custom-page` | — | string | — | ID of the custom page set that replaces the workload's error responses. |
| `--strategy-type` | — | string | `default` | Type of the deployment strategy. |
| `--active` | — | string | — | Whether the deployment is active, `true` or `false`. |
| `--current` | — | string | — | Whether the deployment is the current one, `true` or `false`. |
| `--file` | — | string | — | Path to a JSON file with the attributes of the deployment. Use `-` to read the JSON from standard input. With `--file`, the command reads no other attribute flag. |

This command creates a deployment for the workload with ID `1234` that serves the application with ID `5678` and replaces error responses with the custom page set with ID `123`:

```bash
azion create workload-deployment --workload-id 1234 --name my-deployment --application-id 5678 --custom-page 123
```

The command prints the ID of the deployment:

```text
Created Workload Deployment with ID 4321
```

## List

`azion list workload-deployment` lists the deployments of a workload, 50 to a page:

```bash
azion list workload-deployment [flags]
```

| Flag | Short | Type | Default | Description |
| --- | --- | --- | --- | --- |
| `--workload-id` | — | int | — | ID of the workload whose deployments to list. Without it, the command asks for it. |
| `--details` | — | — | — | Adds the `EDGE APPLICATION` and `EDGE FIREWALL` columns to the `ID` and `CURRENT` columns. |
| `--filter` | — | string | — | Name to filter the list by. |
| `--order-by` | — | string | — | Field to sort the list by. |
| `--page` | — | int | `1` | Number of the page to return. |
| `--page-size` | — | int | `50` | Number of deployments on each page. |

This command lists the deployment of the workload with ID `1234`, with the application and the firewall it names:

```bash
azion list workload-deployment --workload-id 1234 --details
```

The command prints one row per deployment. `EDGE APPLICATION` and `EDGE FIREWALL` hold IDs, and an `EDGE FIREWALL` of `0` means the deployment names no firewall. The list shows no column for the custom page set; to see it, use `azion describe workload-deployment --format json`.

## Describe

`azion describe workload-deployment` prints the settings of the deployment of a workload:

```bash
azion describe workload-deployment [flags]
```

| Flag | Short | Type | Default | Description |
| --- | --- | --- | --- | --- |
| `--workload-id` | — | int | — | ID of the workload. Without it, the command asks for it. |
| `--deployment-id` | — | int | — | ID of the deployment to describe. Without it, the command asks for it. |

This command describes the deployment with ID `4321` of the workload with ID `1234`, as JSON:

```bash
azion describe workload-deployment --workload-id 1234 --deployment-id 4321 --format json
```

Without `--format json`, the command prints only the ID, the tag, and the current state of the deployment.

## Update

`azion update workload-deployment` changes the name, the state, or the strategy of the deployment of a workload:

```bash
azion update workload-deployment [flags]
```

| Flag | Short | Type | Default | Description |
| --- | --- | --- | --- | --- |
| `--workload-id` | — | int | — | ID of the workload. Without it, and without `--file`, the command asks for it. |
| `--deployment-id` | — | int | — | ID of the deployment to update. Without it, and without `--file`, the command asks for it. |
| `--name` | — | string | — | New name of the deployment. |
| `--active` | — | string | — | Whether the deployment is active, `true` or `false`. |
| `--current` | — | string | — | Whether the deployment is the current one, `true` or `false`. |
| `--strategy-type` | — | string | — | Type of the deployment strategy. The command sends `--edge-application`, `--edge-firewall`, and `--custom-page` only when this flag is set. |
| `--edge-application` | — | string | — | ID of the application the deployment serves. |
| `--edge-firewall` | — | string | — | ID of the firewall that inspects the workload's requests. |
| `--custom-page` | — | string | — | ID of the custom page set that replaces the workload's error responses. |
| `--file` | — | string | — | Path to a JSON file with the attributes to change. Use `-` to read the JSON from standard input. With `--file`, the command reads no other attribute flag and does not ask for the IDs, so pass `--workload-id` and `--deployment-id` with it. |

The flags that name the application and the firewall are `--edge-application` and `--edge-firewall` here, and `--application-id` and `--firewall-id` on create.

The command sends the strategy as one object. To change the custom page set, pass `--strategy-type` and the application and firewall the deployment already names, as `azion list workload-deployment --details` shows them. This command assigns the custom page set with ID `123` and keeps the application with ID `5678` and the firewall with ID `910`:

```bash
azion update workload-deployment --workload-id 1234 --deployment-id 4321 --strategy-type default --edge-application 5678 --edge-firewall 910 --custom-page 123
```

The command prints the ID of the updated deployment:

```text
Updated Workload Deployment with ID 4321
```

## Use a JSON file

`azion create workload-deployment` and `azion update workload-deployment` read the deployment from a JSON file with `--file`. The workload and deployment IDs are not part of the file: pass them with `--workload-id` and, on update, `--deployment-id`.

The file carries the fields of the deployment:

- `name`, `active`, and `current` describe the deployment.
- `strategy.type` is the type of the strategy, such as `default`.
- `strategy.attributes` carries `application`, the ID of the application, and optionally `firewall` and `custom_page`, the IDs of the firewall and the custom page set.

This file creates a current, active deployment that serves the application with ID `5678` behind the firewall with ID `910`, with the custom page set with ID `123`:

```json
{
  "name": "my-deployment",
  "active": true,
  "current": true,
  "strategy": {
    "type": "default",
    "attributes": {
      "application": 5678,
      "firewall": 910,
      "custom_page": 123
    }
  }
}
```

Pass the file to the create command with the ID of the workload:

```bash
azion create workload-deployment --workload-id 1234 --file deployment.json
```

To declare the deployment in a project instead, use the [`deployments`](/en/documentation/devtools/cli/azion-config-js/#workload-deployments) entry of `azion.config.js` and run `azion deploy`. Its `strategy.attributes.customPage` takes the set by name or ID.
