The `azion/applications` module is the Azion Lib library for [Applications](/en/documentation/platform/applications/). Its functions create, list, read, update, and delete applications. Inside an application, they manage its [origins](/en/documentation/platform/connectors/origins/), [cache settings](/en/documentation/platform/applications/cache/cache-settings/), [device groups](/en/documentation/platform/applications/device-groups/), [function instances](/en/documentation/platform/applications/functions-instances/), and [rules](/en/documentation/platform/applications/rules-engine/). The module calls Azion API v3, and each function takes one object argument.

Install the package:

```bash
npm install azion
```

The `azion` package receives bug fixes only, and its maintenance ends in December 2026.

The samples on this page are ES modules that use top-level `await`, and they run in Node.js. Most of them are TypeScript. A sample whose payload TypeScript rejects is JavaScript, and its section names the type that rejects it.

## Authentication

Functions that you import and call directly read your [personal token](/en/documentation/fundamentals/personal-tokens/) from the `AZION_TOKEN` environment variable. A client from [createAzionApplicationClient](#createazionapplicationclient) carries the token in its `token` field.

| Variable | Description |
| --- | --- |
| `AZION_TOKEN` | Your Azion personal token. |
| `AZION_DEBUG` | With `true`, turns on debug mode. |

For more information, refer to [How Azion Lib works](/en/documentation/devtools/azion-lib/how-it-works/).

## Response envelope

The `azion/applications` functions report a failure in one of two ways, depending on the object they act on:

- The application-level functions [createApplication](#createapplication), [getApplications](#getapplications), [getApplication](#getapplication), [patchApplication](#patchapplication), and [putApplication](#putapplication) return `{ data }` on success. When the API answers with an error status, they throw `Error: HTTP error! Status: <code> - <TEXT>`, so call them inside `try`/`catch`.
- [deleteApplication](#deleteapplication) and the functions for origins, cache settings, device groups, function instances, and rules do not throw. They return an [AzionApplicationResponse](#azionapplicationresponse), `{ data?, error? }`. On failure, `error` holds `{ message, operation }`, where `operation` names the call, such as `get origin`.

The samples for the application-level functions destructure `error` as well. On a failed request, those functions throw before the sample checks it.

A delete that succeeds still returns `{ error: { message: 'Expected JSON response, but got: ', operation } }`. The API answers a delete with an empty body, which the module reads as an error. The envelope cannot tell a successful delete from a failed one, so each delete sample on this page reads the object back. A `404` answer confirms the delete.

## Functions by resource

The module groups its functions by the object they manage. An application is addressed by `applicationId`, which every function except `createApplication` and `getApplications` takes. Rules also take a `phase`, and an origin is addressed by its `originKey`, a UUID.

| Resource | Functions |
| --- | --- |
| Application | [createApplication](#createapplication), [getApplications](#getapplications), [getApplication](#getapplication), [patchApplication](#patchapplication), [putApplication](#putapplication), [deleteApplication](#deleteapplication) |
| Origin | [createOrigin](#createorigin), [getOrigins](#getorigins), [getOrigin](#getorigin), [updateOrigin](#updateorigin), [deleteOrigin](#deleteorigin) |
| Cache setting | [createCacheSetting](#createcachesetting), [getCacheSettings](#getcachesettings), [getCacheSetting](#getcachesetting), [updateCacheSetting](#updatecachesetting), [deleteCacheSetting](#deletecachesetting) |
| Device group | [createDeviceGroup](#createdevicegroup), [getDeviceGroups](#getdevicegroups), [getDeviceGroup](#getdevicegroup), [updateDeviceGroup](#updatedevicegroup), [deleteDeviceGroup](#deletedevicegroup) |

An application that [createApplication](#createapplication) or [getApplication](#getapplication) returns also carries the functions of the five sub-resources as [application methods](#application-methods).

## createAzionApplicationClient

Creates a client that holds a token and exposes the six application-level functions as methods. `createAzionApplicationClient` is also the default export of the module. In TypeScript with `moduleResolution` set to `nodenext`, the default import is not callable, so import the named export. With `moduleResolution` set to `bundler`, both imports type-check.

```typescript
function createAzionApplicationClient(config?: Partial<{
  token: string;
  options?: AzionClientOptions;
}>): AzionApplicationsClient;
```

| Parameter | Type | Required | Description |
| --- | --- | --- | --- |
| `token` | `string` | No | Your Azion personal token. |
| `options` | [`AzionClientOptions`](#azionclientoptions) | No | Request options. No sample on this page passes them to the client. |

Returns an [AzionApplicationsClient](#azionapplicationsclient). Its methods take the same object as the matching function on this page. The client has no methods for origins, cache settings, device groups, function instances, or rules: call those functions directly, or use the [application methods](#application-methods).

This sample creates a client and prints its methods:

```typescript
import { createAzionApplicationClient } from 'azion/applications';

const client = createAzionApplicationClient({
  token: process.env.AZION_TOKEN,
});
console.log('client methods:', Object.keys(client));
```

Output:

```text
client methods: [
  'createApplication',
  'deleteApplication',
  'getApplication',
  'getApplications',
  'putApplication',
  'patchApplication'
]
```

## createApplication

Creates an application.

```typescript
function createApplication(params: {
  data: ApiCreateApplicationPayload;
  options?: AzionClientOptions;
}): Promise<AzionApplicationResponse<AzionApplication>>;
```

| Parameter | Type | Required | Description |
| --- | --- | --- | --- |
| `data` | [`ApiBaseApplicationPayload`](#apibaseapplicationpayload) | Yes | The settings of the application. `name` is required. |
| `options` | [`AzionClientOptions`](#azionclientoptions) | No | Request options. |

Returns `data` as the created [AzionApplication](#azionapplication), with the `id` the API assigned. On an error status, the function throws.

The type declares `application_acceleration`, but API v3 refuses it in a create request as an unknown field. With it, the function throws `Error: HTTP error! Status: 400 - BAD REQUEST`, so leave it out.

This sample is JavaScript, because TypeScript rejects the string `'http,https'` for `delivery_protocol`, whose type is the `DeliveryProtocol` enum:

```javascript
import { createApplication } from 'azion/applications';

// Create a new application
const { data: newApp, error } = await createApplication({
  data: {
    name: 'my-app',
    delivery_protocol: 'http,https',
  },
});
if (newApp) {
  console.log(`Application created: ${newApp.id} (${newApp.name}, ${newApp.delivery_protocol})`);
} else {
  console.error('Error creating application:', error);
}
```

Output:

```text
Application created: 1791120663 (my-app, http,https)
```

## getApplications

Lists the applications of the account, one page at a time.

```typescript
function getApplications(params?: {
  params?: ApiListApplicationsParams;
  options?: AzionClientOptions;
}): Promise<AzionApplicationCollectionResponse<AzionApplication>>;
```

| Parameter | Type | Required | Description |
| --- | --- | --- | --- |
| `params` | [`ApiListApplicationsParams`](#apilistapplicationsparams) | No | Pagination: `page` and `page_size`. Without ordering keys, the function asks for the list ordered by name, in ascending order. |
| `options` | [`AzionClientOptions`](#azionclientoptions) | No | Request options. |

Returns an [AzionApplicationCollectionResponse](#azionapplicationcollectionresponse): `data.results` holds the page, and `data.count` holds the number of applications in the account. On an error status, the function throws.

```typescript
import { getApplications } from 'azion/applications';

// List all applications
const { data: apps, error } = await getApplications({
  params: { page: 1, page_size: 20 },
});
if (apps) {
  console.log(`Found ${apps.count} applications; this page has ${apps.results.length}`);
} else {
  console.error('Error listing applications:', error);
}
```

Output:

```text
Found 22 applications; this page has 20
```

## deleteApplication

Deletes an application by its ID.

```typescript
function deleteApplication(params: {
  applicationId: number;
  options?: AzionClientOptions;
}): Promise<AzionApplicationResponse<void>>;
```

| Parameter | Type | Required | Description |
| --- | --- | --- | --- |
| `applicationId` | `number` | Yes | The ID of the application to delete. |
| `options` | [`AzionClientOptions`](#azionclientoptions) | No | Request options. |

Unlike the other application-level functions, `deleteApplication` returns an envelope and does not throw. A successful delete returns `error` with the message `Expected JSON response, but got: `, so the sample confirms the delete with [getApplication](#getapplication), which throws a 404 error for an application that no longer exists.

```typescript
import { deleteApplication, getApplication } from 'azion/applications';

// Delete an existing application
const applicationId = 1791120663; // Replace with the actual application ID

const { error: deleteError } = await deleteApplication({ applicationId });

// On success (HTTP 204) the envelope still carries an error, so confirm by reading it back;
// getApplication throws when the application does not exist
try {
  await getApplication({ applicationId });
  console.error('Error deleting application:', deleteError);
} catch (err) {
  console.log(`Application ${applicationId} deleted (read back: ${(err as Error).message})`);
}
```

Output:

```text
Application 1791120663 deleted (read back: HTTP error! Status: 404 - NOT FOUND)
```

## createOrigin

Creates an origin in an application. An origin is the server the application retrieves content from.

```typescript
function createOrigin(params: {
  applicationId: number;
  data: ApiCreateOriginPayload;
  options?: AzionClientOptions;
}): Promise<AzionApplicationResponse<AzionOrigin>>;
```

| Parameter | Type | Required | Description |
| --- | --- | --- | --- |
| `applicationId` | `number` | Yes | The ID of the application. |
| `data` | [`ApiCreateOriginPayload`](#azionorigin) | Yes | The settings of the origin. The sample sets `name`, `origin_type`, `addresses`, and `host_header`. |
| `options` | [`AzionClientOptions`](#azionclientoptions) | No | Request options. |

Returns `data` as the created [AzionOrigin](#azionorigin). The API identifies an origin by its `origin_key`, a UUID, which the other origin functions take as `originKey`.

This sample is JavaScript, because `ApiCreateOriginPayload` requires every origin field, including `origin_key` and the HMAC fields, and types `origin_type` as an enum:

```javascript
import { createOrigin } from 'azion/applications';

const applicationId = 1791120663; // Replace with the actual application ID

// Define the data for the new origin
const newOriginData = {
  name: 'my-origin',
  origin_type: 'single_origin',
  addresses: [{ address: 'example.com' }],
  host_header: '${host}',
};

// Create a new origin
const { data: newOrigin, error } = await createOrigin({ applicationId, data: newOriginData });

if (error) {
  console.error('Error creating origin:', error);
} else {
  console.log('Created origin:', newOrigin.origin_key, newOrigin.name, newOrigin.addresses);
}
```

Output:

```text
Created origin: 415d46c6-a3ba-45d5-b3d2-ce7764d44aa5 my-origin [
  {
    address: 'example.com',
    weight: null,
    server_role: 'primary',
    is_active: true
  }
]
```

## createCacheSetting

Creates a cache setting in an application. The application must have an origin first. On an application with none, the API refuses the cache setting, and the function returns `error` with the message `HTTP error! Status: 400 - BAD REQUEST`.

```typescript
function createCacheSetting(params: {
  applicationId: number;
  data: ApiBaseCacheSettingPayload;
  options?: AzionClientOptions;
}): Promise<AzionApplicationResponse<AzionCacheSetting>>;
```

| Parameter | Type | Required | Description |
| --- | --- | --- | --- |
| `applicationId` | `number` | Yes | The ID of the application. |
| `data` | [`ApiBaseCacheSettingPayload`](#apibasecachesettingpayload) | Yes | The settings of the cache setting. `name` is required. |
| `options` | [`AzionClientOptions`](#azionclientoptions) | No | Request options. |

`browser_cache_settings` takes `honor`, `override`, or `ignore`, and `cdn_cache_settings` takes `honor` or `override`. With `override`, the sample also sets the matching maximum TTL field, `browser_cache_settings_maximum_ttl` or `cdn_cache_settings_maximum_ttl`.

Returns `data` as the created [AzionCacheSetting](#azioncachesetting), with its `id`.

This sample is JavaScript, because TypeScript rejects string values for `browser_cache_settings` and `cdn_cache_settings`, whose types are enums the module does not export:

```javascript
import { createCacheSetting } from 'azion/applications';

const applicationId = 1791120663; // Replace with the actual application ID

// Create a new cache setting
const cacheSettingData = {
  name: 'my-cache-setting',
  browser_cache_settings: 'override',
  browser_cache_settings_maximum_ttl: 3600,
  cdn_cache_settings: 'override',
  cdn_cache_settings_maximum_ttl: 7200,
};

const { data: newCacheSetting, error } = await createCacheSetting({ applicationId, data: cacheSettingData });

if (error) {
  console.error('Error creating cache setting:', error);
} else {
  console.log('Cache setting created successfully:', newCacheSetting.id, newCacheSetting.name, newCacheSetting.cdn_cache_settings_maximum_ttl);
}
```

Output:

```text
Cache setting created successfully: 356569 my-cache-setting 7200
```


| `options` | [`AzionClientOptions`](#azionclientoptions) | No | Request options. |

`criteria` is a list of condition groups, and each group is a list of conditions with `variable`, `operator`, `conditional`, and `input_value`. `behaviors` lists the actions, each with a `name` and a `target`. For the variables, operators, and behavior names a rule can use, refer to [Rules Engine for Applications](/en/documentation/platform/applications/rules-engine/).

Returns `data` as the created [AzionRule](#azionrule), with its `id` and `order`. In the sample, `as const` keeps the literal types that `phase` and `conditional` need in TypeScript.

```typescript
import { createRule } from 'azion/applications';

const applicationId = 1791120663; // Replace with the actual application ID

// Define the data for the new rule
const ruleData = {
  name: 'Example Rule',
  phase: 'request' as const,
  criteria: [[{ variable: '${uri}', operator: 'starts_with', conditional: 'if' as const, input_value: '/example-path' }]],
  behaviors: [{ name: 'redirect_to_301', target: 'https://example.com' }],
};

// Create a new rule in the request phase
const { data: newRule, error } = await createRule({ applicationId, phase: 'request', data: ruleData });

if (error) {
  console.error('Error creating rule:', error);
} else {
  console.log('Created rule:', JSON.stringify(newRule));
}
```

```text
Created rule: {"id":744130,"name":"Example Rule","phase":"request","behaviors":[{"name":"redirect_to_301","target":"https://example.com"}],"criteria":[[{"variable":"${uri}","operator":"starts_with","conditional":"if","input_value":"/example-path"}]],"is_active":true,"order":1,"description":""}
```

```typescript
if (error) {
  console.log(`Rule ${ruleId} deleted (read back: ${error.message})`);
} else {
  console.error('Error deleting rule:', deleteError);
}
```

Output:

```text
Rule 744130 deleted (read back: HTTP error! Status: 404 - NOT FOUND)
```

## Application methods

An application that [createApplication](#createapplication) or [getApplication](#getapplication) returns carries the sub-resource functions as methods, already bound to its ID. Each method takes the same object as the matching function, without `applicationId`. The rule methods sit under `rules.request` and `rules.response`, which also fix the `phase`.

| Property | Type | Methods |
| --- | --- | --- |
| `origins` | `OriginOperations` | `createOrigin`, `getOrigins`, `getOrigin`, `updateOrigin`, `deleteOrigin` |
| `cache` | `CacheOperations` | `createCacheSetting`, `getCacheSettings`, `getCacheSetting`, `updateCacheSetting`, `deleteCacheSetting` |
| `devices` | `DeviceGroupOperations` | `createDeviceGroup`, `getDeviceGroups`, `getDeviceGroup`, `updateDeviceGroup`, `deleteDeviceGroup` |
| `functions` | `FunctionOperations` | `createFunctionInstance`, `getFunctionInstances`, `getFunctionInstance`, `updateFunctionInstance`, `deleteFunctionInstance` |
| `rules.request`, `rules.response` | `RuleOperations` | `createRule`, `getRules`, `getRule`, `updateRule`, `deleteRule` |

A list method needs an object argument, even an empty one: `{}`. This sample reads an application and lists each of its sub-resources through the methods:

```typescript
import { getApplication } from 'azion/applications';

const applicationId = 1791120663; // Replace with the actual application ID

// The application object carries the sub-resource operations, already bound to its ID
const { data: app, error } = await getApplication({ applicationId });
if (!app) throw new Error(error?.message);

const { data: cache } = await app.cache.getCacheSettings({});
console.log('app.cache.getCacheSettings:', cache?.results.map((c) => c.name));
const { data: origins } = await app.origins.getOrigins({});
console.log('app.origins.getOrigins:', origins?.results.map((o) => o.name));
const { data: rules } = await app.rules.request.getRules({});
console.log('app.rules.request.getRules:', rules?.results.map((r) => r.name));
const { data: devices } = await app.devices.getDeviceGroups({});
console.log('app.devices.getDeviceGroups:', devices?.count);
const { data: functions } = await app.functions.getFunctionInstances({});
console.log('app.functions.getFunctionInstances:', functions?.count);
```

Output:

```text
app.cache.getCacheSettings: [ 'my-other-cache-setting' ]
app.origins.getOrigins: [ 'my-origin-updated' ]
app.rules.request.getRules: [ 'Default Rule' ]
app.devices.getDeviceGroups: 0
app.functions.getFunctionInstances: 0
```

## Errors

The application-level functions throw these messages inside an `Error`. The other functions return them in `error.message`, and `error.operation` names the call, such as `create device group`.

| Message | Cause | What to do |
| --- | --- | --- |
| `HTTP error! Status: 401 - UNAUTHORIZED` | No valid token reached the call: `AZION_TOKEN` is unset or holds an invalid token, and no client `token` was passed. | Set `AZION_TOKEN` to a valid [personal token](/en/documentation/fundamentals/personal-tokens/), or pass `token` to [createAzionApplicationClient](#createazionapplicationclient). |
| `HTTP error! Status: 404 - NOT FOUND` | No application has that ID, or the application holds no object with that ID or origin key. | Check the ID with the matching list function, such as [getApplications](#getapplications) or [getOrigins](#getorigins). |
| `HTTP error! Status: 400 - BAD REQUEST` | API v3 refused the payload. The message does not carry the reason the API gives. Causes include `application_acceleration` in a create request, a cache setting on an application with no origin, a device group name with a space or a hyphen, and `sort` or `order` in a cache setting list. | Compare the payload with the section of the function you called, and remove or change the field it names. |
| `Expected JSON response, but got: ` | A delete succeeded, and the API answered with an empty body. | Read the object back. A `404` error confirms the delete. |
