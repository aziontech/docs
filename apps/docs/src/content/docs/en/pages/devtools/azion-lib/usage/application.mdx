The `azion/applications` module is the Azion Lib library for [Applications](/en/documentation/platform/applications/). Its functions create, list, read, update, and delete applications. Inside an application, they manage its [origins](/en/documentation/platform/connectors/origins/), [cache settings](/en/documentation/platform/applications/cache/cache-settings/), [device groups](/en/documentation/platform/applications/device-groups/), [function instances](/en/documentation/platform/applications/functions-instances/), and [rules](/en/documentation/platform/applications/rules-engine/). The module calls Azion API v3, and each function takes one object argument.

Install the package:

```bash
npm install azion
```

The `azion` package receives bug fixes only, and its maintenance ends in December 2026.

The samples in this section are ES modules that use top-level `await`, and they run in Node.js. Most of them are TypeScript. A sample whose payload TypeScript rejects is JavaScript, and its section names the type that rejects it.

## Authentication

Functions that you import and call directly read your [personal token](/en/documentation/fundamentals/personal-tokens/) from the `AZION_TOKEN` environment variable. A client from [createAzionApplicationClient](/en/documentation/devtools/azion-lib/application/application/#createazionapplicationclient) carries the token in its `token` field.

| Variable | Description |
| --- | --- |
| `AZION_TOKEN` | Your Azion personal token. |
| `AZION_DEBUG` | With `true`, turns on debug mode. |

For more information, refer to [How Azion Lib works](/en/documentation/devtools/azion-lib/how-it-works/).

## Response envelope

The `azion/applications` functions report a failure in one of two ways, depending on the object they act on:

- The application-level functions [createApplication](/en/documentation/devtools/azion-lib/application/application/#createapplication), [getApplications](/en/documentation/devtools/azion-lib/application/application/#getapplications), [getApplication](/en/documentation/devtools/azion-lib/application/application/#getapplication), [patchApplication](/en/documentation/devtools/azion-lib/application/application/#patchapplication), and [putApplication](/en/documentation/devtools/azion-lib/application/application/#putapplication) return `{ data }` on success. When the API answers with an error status, they throw `Error: HTTP error! Status: <code> - <TEXT>`, so call them inside `try`/`catch`.
- [deleteApplication](/en/documentation/devtools/azion-lib/application/application/#deleteapplication) and the functions for origins, cache settings, device groups, function instances, and rules do not throw. They return an [AzionApplicationResponse](/en/documentation/devtools/azion-lib/application/types/#azionapplicationresponse), `{ data?, error? }`. On failure, `error` holds `{ message, operation }`, where `operation` names the call, such as `get origin`.

The samples for the application-level functions destructure `error` as well. On a failed request, those functions throw before the sample checks it.

A delete that succeeds still returns `{ error: { message: 'Expected JSON response, but got: ', operation } }`. The API answers a delete with an empty body, which the module reads as an error. The envelope cannot tell a successful delete from a failed one, so each delete sample on this page reads the object back. A `404` answer confirms the delete.

## Errors

The application-level functions throw these messages inside an `Error`. The other functions return them in `error.message`, and `error.operation` names the call, such as `create device group`.

| Message | Cause | What to do |
| --- | --- | --- |
| `HTTP error! Status: 401 - UNAUTHORIZED` | No valid token reached the call: `AZION_TOKEN` is unset or holds an invalid token, and no client `token` was passed. | Set `AZION_TOKEN` to a valid [personal token](/en/documentation/fundamentals/personal-tokens/), or pass `token` to [createAzionApplicationClient](/en/documentation/devtools/azion-lib/application/application/#createazionapplicationclient). |
| `HTTP error! Status: 404 - NOT FOUND` | No application has that ID, or the application holds no object with that ID or origin key. | Check the ID with the matching list function, such as [getApplications](/en/documentation/devtools/azion-lib/application/application/#getapplications) or [getOrigins](/en/documentation/devtools/azion-lib/application/origin/#getorigins). |
| `HTTP error! Status: 400 - BAD REQUEST` | API v3 refused the payload. The message does not carry the reason the API gives. Causes include `application_acceleration` in a create request, a cache setting on an application with no origin, a device group name with a space or a hyphen, and `sort` or `order` in a cache setting list. | Compare the payload with the section of the function you called, and remove or change the field it names. |
| `Expected JSON response, but got: ` | A delete succeeded, and the API answered with an empty body. | Read the object back. A `404` error confirms the delete. |
