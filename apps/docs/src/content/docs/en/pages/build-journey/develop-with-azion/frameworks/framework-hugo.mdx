You can deploy a Hugo site on Azion from a template in Azion Console or with the [Azion CLI](/en/documentation/devtools/cli/). Both routes leave the site running on Azion and answering on an Azion domain.

Azion serves a Hugo site as a static application. The build writes the site to `./public`, and the deploy uploads that folder to a storage bucket that an [application](/en/documentation/platform/applications/) serves. For the full list of frameworks Azion builds, refer to [Frameworks compatibility](/en/documentation/devtools/runtime/frameworks/frameworks-compatibility/).

## Prerequisites

- An Azion account. To create one, refer to [Create an account](/en/documentation/fundamentals/creating-account/).

<Tabs client:visible sharedStore="interface">

<Fragment slot="panel.console">

- Access to Azion Console. To sign in, refer to [How to access Azion Console](/en/documentation/guides/platform/account-and-billing/how-to-access-azion-console/).
- A GitHub account. The template form connects it when it asks for it.

</Fragment>

<Fragment slot="panel.cli">

- The Azion CLI, installed and logged in. To set it up, refer to [Azion CLI quickstart](/en/documentation/devtools/cli/quickstart/).
- Node.js 18 or later, and npm. The Hugo Boilerplate installs Hugo as an npm dependency, so you do not install Hugo separately.
- A terminal and a code editor.

</Fragment>

</Tabs>

## Hugo templates

Azion deploys a Hugo template as a ready project. The Console route starts from one of these templates, and the CLI offers the same three:

| Template | Use |
| --- | --- |
| [Hugo Boilerplate](/en/documentation/guides/application-development/frameworks/hugo-boilerplate/) | Starter project |
| Influencer Hugo | Product showcase |
| Vex Hugo | Product landing page |

The Hugo Boilerplate has a guide of its own, linked in the table. Influencer Hugo and Vex Hugo share one guide: [Deploy an E-commerce with Hugo Templates](/en/documentation/guides/application-development/frameworks/hugo-ecommerce-collection/). For more information on templates, refer to [Azion Marketplace](/en/documentation/platform/marketplace/).

## Deploy the site

Both routes build the Hugo project and create the resources that serve it on Azion. Follow the panel of your route:

<Tabs client:visible sharedStore="interface">

<Fragment slot="panel.console">

To deploy a Hugo template from Azion Console:

<DocSteps>
  <DocStep title="Open the templates">

  Access [Azion Console](https://console.azion.com/) > **Create** > **Templates**.

  </DocStep>
  <DocStep title="Search for Hugo">

  In **Search by name, framework, or keyword**, enter `Hugo`.

  </DocStep>
  <DocStep title="Select the Hugo template you want" />
  <DocStep title="Connect your GitHub account">

  When the form shows **GitHub Connection**, select **Connect with GitHub** and install the [Azion GitHub App](/en/documentation/guides/application-development/automation/azion-github-app/).

  </DocStep>
  <DocStep title="Select a Git Scope">

  In **Git Scope**, select the scope for the template.

  </DocStep>
  <DocStep title="Fill in the settings the template asks for" />
  <DocStep title="Select Deploy" />
</DocSteps>

The deploy page shows the **Deploy Log** while the project builds. On success, it shows **Successfully created!**, the domain URL, and a **Manage** button that opens the application.

</Fragment>

<Fragment slot="panel.cli">

Run `azion init` with a project name. In the first picker, select _Hugo_; in the second, select a template:

```bash
azion init --name my-site --auto -y
```

The project lands in a `my-site` folder. Its `azion.config.cjs` sets the `hugo` preset and uploads `./public` to a storage bucket that workloads can only read. For every setting in that file, refer to [azion.config.js](/en/documentation/devtools/cli/azion-config-js/).

To build the site, run `azion build` from the project folder:

```bash
cd my-site
azion build
```

To deploy the site, run `azion deploy` from the project folder:

```bash
azion deploy
```

The deploy uploads the project and opens the Console page that tracks it, and it prints that page's URL in case no browser opens. At the end, it prints the URL of the site's domain. For the full output and every flag, refer to [Azion CLI deploy](/en/documentation/devtools/cli/deploy/).

To preview the site on your machine first, refer to [Azion CLI dev](/en/documentation/devtools/cli/dev-command/). For a Hugo project you already have, run `azion link` in its folder and select the Hugo preset, as [Azion CLI link](/en/documentation/devtools/cli/link-command/) describes.

## Check the site

The deploy gives you the URL of the site's Azion domain, in the form `https://xxxxxxxxxx.map.azionedge.net`. The Console deploy page shows it, and `azion deploy` prints it on completion. Open that URL in a browser to see the Hugo site.

The first deploy can take several minutes to answer from every location; later deploys take about two minutes. A location that has not received the site yet answers with a `404` page that reads `There's nothing here yet`. If you get that page, wait and request the URL again.
