You can put a Vue app on Azion from a template in Azion Console, from a GitHub repository you own, or with the [Azion CLI](/en/documentation/devtools/cli/). All three routes finish with the app live on an Azion domain.

Azion runs a Vue app as a static application. The deploy uploads the built files to a storage bucket, and an [application](/en/documentation/platform/applications/) serves them from there. To see which other frameworks Azion builds, refer to [Frameworks compatibility](/en/documentation/devtools/runtime/frameworks/frameworks-compatibility/).

## Vue templates

A Vue template is a complete starter project that Azion builds and deploys for you. The template picker of the Vue preset in `azion init` includes these three:

| Template | Use |
| --- | --- |
| [Vue.js with ButterCMS Starter Project](/en/documentation/guides/application-development/frameworks/butter-templates-collection/) | CMS integration |
| [Vue3/Vite Boilerplate](/en/documentation/guides/application-development/frameworks/vue-vite-boilerplate/) | Single-page application with Vite |
| [Vue Boilerplate](/en/documentation/guides/application-development/frameworks/vue-boilerplate/) | Single-page application |

Each template links to its guide. The ButterCMS starter shares its guide with the ButterCMS templates of other frameworks. For more information on templates, refer to [Azion Marketplace](/en/documentation/platform/marketplace/).

## Deploy the app

Every route builds the Vue project and creates the resources that serve it on Azion. Use the panel of the route you chose:

### Console

To deploy a Vue template from Azion Console:

<DocSteps>
  <DocStep title="Open the templates">

  Access [Azion Console](https://console.azion.com/) > **Create** > **Templates**.

  </DocStep>
  <DocStep title="Search for Vue">

  In **Search by name, framework, or keyword**, enter `Vue`.

  </DocStep>
  <DocStep title="Select the template to deploy" />
  <DocStep title="Connect your GitHub account">

  If the form shows **GitHub Connection**, select **Connect with GitHub** and install the [Azion GitHub App](/en/documentation/guides/application-development/automation/azion-github-app/).

  </DocStep>
  <DocStep title="Select a Git Scope">

  In **Git Scope**, select the scope where the template creates its repository.

  </DocStep>
  <DocStep title="Fill in the settings the template asks for" />
  <DocStep title="Select Deploy" />
</DocSteps>

A deploy page opens with the **Deploy Log** of the build. On success, **Successfully created!** appears, together with the domain URL and a **Manage** button that opens the application.

### CLI

To create the project, run `azion init` with a project name. In the preset picker, select _Vue_, and in the template picker, select a template:

```bash
azion init --name my-app --auto -y
```

With `-y`, the command installs the dependencies. With `--auto`, it does not ask whether to start a local development server or to deploy. The project is created in a `my-app` folder. Its `azion.config.cjs` sets the `vue` preset and uploads `./.edge/assets` to a storage bucket that workloads can only read. The file also generates two request rules for the application:

- `Deliver Static Assets and Set Cache Policy` serves files with a static extension, such as `.js` or `.css`, from the bucket. Its cache policy sets `maxAgeSeconds` to `7200` for the browser and for the cache.
- `Redirect to index.html` rewrites route requests to `/index.html`, so the Vue router resolves each route in the browser.

For every setting in that file, refer to [azion.config.js](/en/documentation/devtools/cli/azion-config-js/).

To build the app, move into the project folder and run `azion build`:

```bash
cd my-app
azion build
```

To deploy the app, run `azion deploy` from the project folder:

```bash
azion deploy
```

The deploy uploads the project and opens the Azion Console page that tracks it. If the browser does not open, use the URL of that page, which the command prints. At the end, the command prints the URL of the app's domain. For the full output and the flags that change a deploy, refer to [Azion CLI deploy](/en/documentation/devtools/cli/deploy/).

To run the app on your machine first, refer to [Azion CLI dev](/en/documentation/devtools/cli/dev-command/). For a Vue project you already have, run `azion link` in its folder and select the Vue preset, as described in [Azion CLI link](/en/documentation/devtools/cli/link-command/).

### GitHub

To deploy a Vue project from a GitHub repository:

<DocSteps>
  <DocStep title="Open Import from GitHub">

  Access [Azion Console](https://console.azion.com/) > **Create** > **Import from GitHub**.

  </DocStep>
  <DocStep title="Select the import card">

## Deploy a Vue app you already built

When you build the app yourself, such as with `npm run build`, Vite writes it to the `dist` folder. The Azion CLI can deploy that folder. Run the commands in the project folder, which holds `package.json` and the app's source.

The first deploy of the project runs `vite build` before it uploads the files. A folder that holds only `dist` cannot run that build, so its deploy fails.

:::note
These steps need Azion CLI 4.27.0 or later. To print the installed version, run `azion --version`. To update the CLI, refer to [Install the CLI](/en/documentation/devtools/cli/#install-the-cli).
:::

To install the dependencies of the project, run this command in the project folder:

<Code client:visible lang="bash" code={`npm install`} />

The command writes the `node_modules` folder. `azion link` needs the dependencies to generate the configuration of the preset.

To link the project with the Vue preset, run this command:

<Code client:visible lang="bash" code={`azion link --name <your-app-name> --preset vue --auto`} />

Replace `<your-app-name>` with a name for the Application. With `--auto`, the command asks no question and does not build or deploy the project. It writes the `azion` folder and an `azion.config` file, and it prints `Project successfully configured`.

To deploy the app for the first time, run the deploy with the build on your machine:

<Code client:visible lang="bash" code={`azion deploy --local`} />

The first deploy runs `vite build`, which writes `dist` again, and uploads the result. The command ends with the domain of the app:

```text
Your Application was deployed successfully

To visualize your application access the Domain: https://xxxxxxxxxx.map.azionedge.net
Your application is being deployed to all Azion Edge Locations and it might take a few minutes.
```

After a change to the app, build it with your own command:

<Code client:visible lang="bash" code={`npm run build`} />

Vite writes the app to `dist`:

```text
vite v8.3.8 building client environment for production...
…
dist/index.html                  0.45 kB │ gzip:  0.29 kB
dist/assets/vite-BF8QNONU.svg    8.70 kB │ gzip:  1.60 kB
dist/assets/hero-CLDdwZDr.png   13.05 kB
dist/assets/index-CsUDhMuy.css   4.10 kB │ gzip:  1.46 kB
dist/assets/index-CxOOyHPi.js   66.48 kB │ gzip: 26.09 kB

✓ built in 310ms
```

:::caution
Keep `--local` in the next command. Without it, the deploy runs the build on Azion and ignores `--skip-framework-build`. Azion then runs `vite build` again and uploads its output instead of your `dist` folder.
:::

To deploy that `dist` folder without running `vite build` again, run the deploy with `--skip-framework-build`:

<Code client:visible lang="bash" code={`azion deploy --local --skip-framework-build`} />

The output prints `Skipping framework build`. The `vue` preset copies the folder that `build.outDir` sets in `vite.config`, `dist` by default, into `.edge/assets`. The deploy uploads that folder under a new storage prefix. A storage prefix is the folder of the bucket that holds the files of one deploy.

The command ends with the same domain. For what each skip flag does on a first deploy or without `--local`, refer to [Azion CLI deploy flags](/en/documentation/devtools/cli/deploy/#flags).

The success message does not list the files that the deploy uploaded. To check them, list the objects of the bucket:

<Code client:visible lang="bash" code={`azion list storage object --bucket-name <your-bucket-name> --page-size 1000`} />

Replace `<your-bucket-name>` with the `bucket` field of `azion/azion.json`. The bucket keeps the files of earlier deploys, each under its own storage prefix. The list starts with the oldest keys, and a page holds 50 objects by default. When the page ends before the files of the last deploy, run the command again with `--next-page`.

After a successful deploy, its keys start with the `prefix` field of `azion/azion.json`:

```text
KEY                                       LAST MODIFIED
20260101120000/assets/hero-CLDdwZDr.png   2026-01-01 12:00:57.496 +0000 UTC
…
20260101120100/assets/hero-CLDdwZDr.png   2026-01-01 12:01:30.796 +0000 UTC
20260101120100/assets/index-CsUDhMuy.css  2026-01-01 12:01:30.79 +0000 UTC
20260101120100/assets/index-CxOOyHPi.js   2026-01-01 12:01:30.805 +0000 UTC
20260101120100/assets/vite-BF8QNONU.svg   2026-01-01 12:01:30.797 +0000 UTC
20260101120100/favicon.svg                2026-01-01 12:01:30.805 +0000 UTC
20260101120100/icons.svg                  2026-01-01 12:01:30.796 +0000 UTC
20260101120100/index.html                 2026-01-01 12:01:30.802 +0000 UTC
```

Every file of `dist` appears once under the prefix of the last deploy.

## Check the app

Each route returns the URL of the app's Azion domain, in the form `https://xxxxxxxxxx.map.azionedge.net`. The Console deploy page shows the URL, and `azion deploy` prints it on completion. Open the URL in a browser to load the Vue app.

The first deploy can take several minutes to answer from every location; later deploys take about two minutes. A location that has not received the app yet answers with a `404` page reading `There's nothing here yet`. If you get that page, wait and request the URL again.
