You can spread the requests of an [Application](/en/documentation/platform/applications/) across several origin servers with [Load Balancer](/en/documentation/platform/connectors/load-balancer/) on a [Connector](/en/documentation/platform/connectors/), from Azion Console or the API. A [Rules Engine](/en/documentation/platform/applications/rules-engine/) rule with the _Set Connector_ behavior sets that Connector, and Load Balancer distributes the requests among its addresses with a balancing method. To connect an Application to a single origin, refer to [Connect an application to an origin](/en/documentation/guides/application-development/getting-started/work-with-origins/).

An account that [has not migrated to API v4](/en/documentation/guides/application-security/access-and-compliance/verify-account-migration/) configures load balancing in the legacy Origins of the Application. For more information, refer to [Origins](/en/documentation/platform/connectors/origins/#load-balancer).

:::caution
With Load Balancer enabled, data transfer can generate usage-related costs. For more information, refer to [Pricing](/en/documentation/fundamentals/pricing/).
:::

## Plan the addresses

The example on this page balances three origin servers. Each one is hosted with a different storage provider or cloud service, because server outages rarely occur at the same time. All three hold the same content and are set up the same way for the Application. Two of them share the traffic, and the third stands by for the case where both fail.

| Address | Server | Load capacity | Weight | Server role | Active |
| --- | --- | --- | --- | --- | --- |
| `example.com` | Primary | High | `3` | `primary` | Always |
| `example.net` | Secondary | Medium, enough for large surges of traffic | `2` | `primary` | Always |
| `example.org` | Backup | Low | `1`, the default when the weight is left blank | `backup` | Always |

The weight follows the load capacity of each server. Both `example.com` and `example.net` are primary, so `example.com` receives about three requests for every two that `example.net` receives. `example.org` receives requests only when both primary addresses fail. It stays active, because an address that is not active receives no request, even as a backup. For how the weight, the server role, and the active state distribute requests, refer to [Balancing methods](/en/documentation/platform/connectors/load-balancer/balancing-methods/#weight).

## Create a Connector with Load Balancer

Load Balancer belongs to the Connector, under `attributes.modules` in the API. A Connector created without Load Balancer keeps it disabled until you turn it on. This is the `attributes.modules` object of a Connector of type `http` that the API created without Load Balancer:

```json
{
  "load_balancer": {
    "enabled": false,
    "config": null
  },
  "origin_shield": {
    "enabled": false,
    "config": null
  }
}
```

To balance the three addresses of the example with the [Round-Robin algorithm](/en/documentation/platform/connectors/load-balancer/balancing-methods/#balancing-method), the Connector carries these values. Each key is under `attributes`:

| Key | Value in the example |
| --- | --- |
| `type` | `http` |
| `modules.load_balancer.enabled` | `true` |
| `modules.load_balancer.config.method` | `round_robin` |
| `modules.load_balancer.config.max_retries` | `0` |
| `modules.load_balancer.config.connection_timeout` | `60` |
| `modules.load_balancer.config.read_write_timeout` | `120` |
| `addresses[].address` | `example.com`, `example.net`, and `example.org` |
| `addresses[].modules.load_balancer.weight` | `3`, `2`, and `1` |
| `addresses[].modules.load_balancer.server_role` | `primary`, `primary`, and `backup` |
| `addresses[].active` | `true`, `true`, and `true` |
| `connection_options.transport_policy` | `preserve` |
| `connection_options.host` | `${host}`, which forwards the `Host` header of the user's request |

In Azion Console, you set up a Connector in **Connectors**, not in a tab of the Application. For each field, refer to [Load Balancer](/en/documentation/platform/connectors/load-balancer/) and [Connector settings](/en/documentation/platform/connectors/settings/#addresses).

<Fragment slot="panel.console">

### Console

To create the Connector in Azion Console:

<DocSteps>
  <DocStep title="Open the Connectors page">

  Access [Azion Console](https://console.azion.com/) > **Connectors**.

  </DocStep>
  <DocStep title="Start a new Connector">

  Select **+ Connectors**.

  </DocStep>
  <DocStep title="Name the Connector">

  In the **General** section, enter `balanced-origins` in **Name**.

  </DocStep>
  <DocStep title="Select the HTTP type">

  In the **Connector Type** section, select _HTTP_.

  </DocStep>
  <DocStep title="Turn on Load Balancer">

  In the **Modules** section, turn on **Load Balancer**. The Connector then accepts more than one address.

  </DocStep>
  <DocStep title="Select the method">

  In the **Load Balancer Configuration** section, select _Round Robin_ in **Method**.

  </DocStep>
  <DocStep title="Turn off retries">

  Enter `0` in **Max Retries**, the value for no retries.

  </DocStep>
  <DocStep title="Set the timeouts">

  Enter `60` in **Connection Timeout** and `120` in **Read/Write Timeout**.

  </DocStep>
  <DocStep title="Set the first primary address">

  In the **Address Management** section, enter `example.com` in **Address** and `3` in **Weight**. Select _Primary_ in **Server Role**, and keep **Active** turned on.

  </DocStep>
  <DocStep title="Add a second address" />
  <DocStep title="Set the second primary address">

  Enter `example.net` in **Address** and `2` in **Weight**. Select _Primary_ in **Server Role**, and keep **Active** turned on.

  </DocStep>
  <DocStep title="Add a third address" />
  <DocStep title="Set the backup address">

  Enter `example.org` in **Address** and `1` in **Weight**. Select _Backup_ in **Server Role**, and keep **Active** turned on.

  </DocStep>
  <DocStep title="Keep the protocol of the user's request">

  In **Transport Protocol Policy**, select _Preserve_.

  </DocStep>
  <DocStep title="Forward the Host header of the user's request">

  In **Host**, enter `${host}`. The Connector sends this value in the `Host` header to the origin.

  </DocStep>
  <DocStep title="Select Save" />
</DocSteps>

Azion Console shows `Connector successfully created`.

</Fragment>

<Fragment slot="panel.api">

### API

To create the Connector with the API, send the values of the table in a `POST` request to the connectors endpoint:

```bash
curl --request POST \
  --url https://api.azion.com/v4/workspace/connectors \
  --header 'Accept: application/json' \
  --header 'Authorization: Token [TOKEN VALUE]' \
  --header 'Content-Type: application/json' \
  --data '{
  "name": "balanced-origins",
  "type": "http",
  "attributes": {
    "addresses": [
      { "address": "example.com", "active": true, "modules": { "load_balancer": { "weight": 3, "server_role": "primary" } } },
      { "address": "example.net", "active": true, "modules": { "load_balancer": { "weight": 2, "server_role": "primary" } } },
      { "address": "example.org", "active": true, "modules": { "load_balancer": { "weight": 1, "server_role": "backup" } } }
    ],
    "connection_options": { "transport_policy": "preserve", "host": "${host}" },
    "modules": {
      "load_balancer": {
        "enabled": true,
        "config": { "method": "round_robin", "max_retries": 0, "connection_timeout": 60, "read_write_timeout": 120 }
      }
    }
  }
}'
```

The API answers `202` with `"state": "pending"` and the Connector, its ID in `data.id`:

```json
{
  "state": "pending",
  "data": {
    "id": <connector-id>,
    "name": "balanced-origins",
    "active": true,
    "type": "http"
  }
}
```

Copy the ID. The rule that sets the Connector holds this ID in `attributes.value`.

## Send requests to the Connector

A Connector receives no request until a rule sets it. The rule in this section runs in the Request Phase of the Application. Its criterion matches every path, with the `${uri}` variable, the `starts_with` operator, and `/` as the argument, so the Connector receives every request of the Application. Its behavior sets the Connector.

The `${uri}` variable works on every Application. A criterion on `${request_uri}` needs [Application Accelerator](/en/documentation/platform/applications/application-accelerator/quickstart/) on the Application. For every variable and operator, refer to [Rules Engine for Applications](/en/documentation/platform/applications/rules-engine/#criteria).

<Tabs client:visible sharedStore="interface">

<Fragment slot="panel.console">

### Console

To create the rule in Azion Console:

<DocSteps>
  <DocStep title="Open the Application">

  Access [Azion Console](https://console.azion.com/) > **Applications**, then select your Application.

  </DocStep>
  <DocStep title="Select the Rules Engine tab" />
  <DocStep title="Start a rule">

  Select **+ Rule**.

  </DocStep>
  <DocStep title="Name the rule">

  In the **General** section, enter a **Name**, such as `balance-origins`.

  </DocStep>
  <DocStep title="Select the phase">

  In the **Phase** section, select _Request Phase_. A rule keeps the phase it is created in.

  </DocStep>
  <DocStep title="Set the criterion">

  In the **Criteria** section, set the variable to `${uri}`, the operator to `starts_with`, and the argument to `/`.

  </DocStep>
  <DocStep title="Set the Connector">

  In the **Behaviors** section, select _Set Connector_, then select the Connector with Load Balancer in **Connector**.

  </DocStep>
  <DocStep title="Save the rule">

  Select **Save**.

  </DocStep>
</DocSteps>

The rule appears in the **Rules Engine** tab of the Application, under **Request**.

</Fragment>

<Fragment slot="panel.api">

### API

To create the rule with the API, send a `POST` request to the `request_rules` endpoint of the Application. Replace `<application-id>` with the ID of your Application, and `<connector-id>` with the ID of the Connector:

```bash
curl --request POST \
  --url https://api.azion.com/v4/workspace/applications/<application-id>/request_rules \
  --header 'Accept: application/json' \
  --header 'Authorization: Token [TOKEN VALUE]' \
  --header 'Content-Type: application/json' \
  --data '{
  "name": "balance-origins",
  "active": true,
  "criteria": [
    [
      {
        "variable": "${uri}",
        "conditional": "if",
        "operator": "starts_with",
        "argument": "/"
      }
    ]
  ],
  "behaviors": [
    {
      "type": "set_connector",
      "attributes": {
        "value": <connector-id>
      }
    }
  ]
}'
```

The API answers `202` and returns the rule:

```json
{
  "state": "pending",
  "data": {
    "id": <rule-id>,
    "name": "balance-origins",
    "active": true,
    "criteria": [
      [
        {
          "conditional": "if",
          "variable": "${uri}",
          "operator": "starts_with",
          "argument": "/"
        }
      ]
    ],
    "behaviors": [
      {
        "type": "set_connector",
        "attributes": {
          "value": <connector-id>
        }
      }
    ],
    "description": "",
    "order": 0,
    "last_editor": "user@example.com",
    "last_modified": "2026-01-01T12:00:26.750242Z",
    "created_at": "2026-01-01T12:00:26.750262Z"
  }
}
```

On an Application with no other Request Phase rule, the rule takes `order` `0`.

</Fragment>

</Tabs>

For the behavior and its attributes, refer to [Set Connector](/en/documentation/platform/applications/rules-engine/#set-connector).

## Confirm that the Application answers

The rule takes a few minutes to propagate. Until then, the Application answers as it did before the rule existed.

To confirm the route, send a request to the domain of your Workload, with that domain in place of `<your-workload-domain>`:

```bash
curl -i https://<your-workload-domain>/
```

The response comes from one of the primary addresses of the Connector. A Workload's domain ends in `.map.azionedge.net`, and the API returns it in `workload_domain` when it creates the Workload. If the response does not come from your origin servers yet, send the request again until it does. If it never does, refer to [Troubleshoot Applications](/en/documentation/platform/applications/troubleshooting/).

## Balance the addresses on a v3 Application

An account that runs on API v3 has no Connectors: load balancing belongs to an origin of the Application, of the _Load Balancer_ type. To find out which model your account runs on, refer to [Verify your account migration](/en/documentation/guides/application-security/access-and-compliance/verify-account-migration/).

<Tabs client:visible>
<Fragment slot="tab.console">Console</Fragment>
<Fragment slot="tab.api">API v3</Fragment>

<Fragment slot="panel.console">

Load Balancer is a setting on the Application, and the addresses sit on one origin. To set both in Azion Console:

<DocSteps>
  <DocStep title="Open the Application">

  Access [Azion Console](https://console.azion.com/) > **Applications** > **your Application**.

  </DocStep>
  <DocStep title="Turn on Load Balancer">

  In the **Main Settings** tab, under **Modules**, turn on **Load Balancer**.

  </DocStep>
  <DocStep title="Save the Application" />
  <DocStep title="Open the origin">

  In the **Origins** tab, select **Default Origin** to balance the addresses the Application already uses, or **+ Origin** to add a separate one. Editing the default origin replaces the address the Application was created with.

  </DocStep>
  <DocStep title="Name the origin and choose its type">

  Enter a name and set **Type** to _Load Balancer_.

  </DocStep>
  <DocStep title="Choose the balancing method">

  In **Method**, select a method, such as _Round-Robin_.

  </DocStep>
  <DocStep title="Add the first address">

  In the first **Address** field, enter the primary server. In **Weight**, enter its share of the requests, such as `3` for a server with more capacity. In **Server Role**, keep _Primary_, and keep the address **Active**.

  </DocStep>
  <DocStep title="Add the other addresses">

  Select **+ Add Origin** for each further address. A **Weight** left blank takes `1`. An address with **Server Role** set to _Backup_ receives requests only when the primary addresses fail, and an address with **Active** off receives none.

  </DocStep>
  <DocStep title="Save the origin">

  Select **Save**.

  </DocStep>
</DocSteps>

</Fragment>

<Fragment slot="panel.api">

To balance the addresses with API v3, first read the `origin_key` of the origin you want to change. The request carries the header `Accept: application/json; version=3`:

```bash
curl --request GET \
  --url https://api.azionapi.net/edge_applications/<application-id> \
  --header 'Accept: application/json; version=3' \
  --header 'Authorization: Token [TOKEN VALUE]'
```

The response carries `origin_key`, a UUID, beside `origin_type` and the name of the origin:

```json
{
  "results": {
    "origin_id": 123456,
    "origin_key": "bdcd7003-ba53-4ed8-8ca0-05b1357cdafd",
    "name": "Default Origin",
    "origin_type": "single_origin"
  }
}
```

Then send a `PATCH` to that origin with the full list of addresses:

```bash
curl --request PATCH \
  --url https://api.azionapi.net/edge_applications/<application-id>/origins/<origin-key> \
  --header 'Accept: application/json; version=3' \
  --header 'Content-Type: application/json' \
  --header 'Authorization: Token [TOKEN VALUE]' \
  --data '{
  "name": "Default Origin (RR3)",
  "origin_type": "load_balancer",
  "method": "round_robin",
  "host_header": "${host}",
  "addresses": [
    { "address": "example.com", "weight": 3, "server_role": "primary", "is_active": true },
    { "address": "example.net", "weight": 2, "server_role": "primary", "is_active": true },
    { "address": "example.org", "weight": 1, "server_role": "backup", "is_active": true }
  ]
}'
```

| Key | What it carries |
| --- | --- |
| `origin_type` | `load_balancer` turns the origin into a balanced one. Load Balancer has to be on |
| `method` | The balancing method, such as `round_robin` |
| `addresses[].weight` | The share of requests the address takes. Omitted, it is `1` |
| `addresses[].server_role` | `primary`, or `backup` for an address that answers only when the primary ones fail |
| `addresses[].is_active` | `false` keeps the address in the list and out of rotation |

The response returns the origin as Azion stored it, with the addresses in the order you sent them:

```json
{
  "results": {
    "origin_id": 123456,
    "origin_key": "bdcd7003-ba53-4ed8-8ca0-05b1357cdafd",
    "name": "Default Origin (RR3)",
    "origin_type": "load_balancer",
    "method": "round_robin",
    "addresses": [
      { "address": "example.com", "weight": 3, "server_role": "primary", "is_active": true },
      { "address": "example.net", "weight": 2, "server_role": "primary", "is_active": true },
      { "address": "example.org", "weight": 1, "server_role": "backup", "is_active": true }
    ]
  }
}
```

</Fragment>

</Tabs>


On a v3 Application, the rule behavior that sets the origin is _Set Origin_, in place of _Set Connector_. For every field of the origin, refer to [Origins](/en/documentation/platform/connectors/origins/).
