You can put a Hexo site on Azion three ways: deploy the Hexo template from Azion Console, import your own repository from GitHub, or run the [Azion CLI](/en/documentation/devtools/cli/). Each route leaves the site live on an Azion domain.

Azion serves a Hexo site as a static application. The Hexo build generates the site in `./public`, and the deploy copies that folder to a storage bucket behind an [application](/en/documentation/platform/applications/). To see which other frameworks Azion builds, refer to [Frameworks compatibility](/en/documentation/devtools/runtime/frameworks/frameworks-compatibility/).

## Prerequisites

- An Azion account. To create one, refer to [Create an account](/en/documentation/fundamentals/creating-account/).

<Tabs client:visible sharedStore="interface">

<Fragment slot="panel.console">

- Access to Azion Console. To sign in, refer to [How to access Azion Console](/en/documentation/guides/platform/account-and-billing/how-to-access-azion-console/).
- A GitHub account. The template form connects it during the deploy when it asks for one.

</Fragment>

<Fragment slot="panel.github">

- Access to Azion Console. To sign in, refer to [How to access Azion Console](/en/documentation/guides/platform/account-and-billing/how-to-access-azion-console/).
- A GitHub account.
- A GitHub repository with a Hexo project in it.

</Fragment>

<Fragment slot="panel.cli">

- The Azion CLI, installed and logged in. To set it up, refer to [Azion CLI quickstart](/en/documentation/devtools/cli/quickstart/).
- Node.js 18 or later, with npm.
- A terminal and a code editor.

</Fragment>

</Tabs>

## Hexo templates

The Console route deploys a template, a Hexo project that is ready to build. It starts from this template:

| Template | Use |
| --- | --- |
| [Hexo Boilerplate](/en/documentation/guides/application-development/frameworks/hexo-boilerplate/) | Single-page application |

Hexo Boilerplate has a guide of its own, linked in the table. For the template catalog, refer to [Azion Marketplace](/en/documentation/platform/marketplace/). In the CLI route, the `azion init` template picker of the Hexo preset lists Hexo Boilerplate as its only entry.

---

## Deploy the site

Every route builds the Hexo project and creates the Azion resources that serve it. Follow the panel for your route:

<Tabs client:visible sharedStore="interface">

<Fragment slot="panel.console">

To deploy the Hexo template from Azion Console:

<DocSteps>
  <DocStep title="Open the templates">

  Access [Azion Console](https://console.azion.com/) > **Create** > **Templates**.

  </DocStep>
  <DocStep title="Find the Hexo template">

  In **Search by name, framework, or keyword**, enter `Hexo`.

  </DocStep>
  <DocStep title="Select Hexo Boilerplate" />
  <DocStep title="Connect your GitHub account">

  If the form shows **GitHub Connection**, select **Connect with GitHub** and install the [Azion GitHub App](/en/documentation/guides/application-development/automation/azion-github-app/).

  </DocStep>
  <DocStep title="Select a Git Scope">

  In **Git Scope**, select the scope for the template.

  </DocStep>
  <DocStep title="Fill in the settings the template asks for" />
  <DocStep title="Select Deploy" />
</DocSteps>

While the project builds, the deploy page shows the **Deploy Log**. A successful deploy shows **Successfully created!**, the domain URL, and a **Manage** button that opens the application.

</Fragment>

<Fragment slot="panel.github">

To deploy a Hexo project from your GitHub repository:

<DocSteps>
  <DocStep title="Open Import from GitHub">

  Access [Azion Console](https://console.azion.com/) > **Create** > **Import from GitHub**.

  </DocStep>
  <DocStep title="Select the import card">

  Select the card in the **Import from GitHub** tab. The **Import from GitHub** page opens.

  </DocStep>
  <DocStep title="Connect your GitHub account">

  If no GitHub account is connected, in **GitHub Connection**, select **Connect with GitHub**.

  </DocStep>
  <DocStep title="Select the repository">

  Select a **Git Scope**, then the **Repository** with the Hexo project.

  </DocStep>
  <DocStep title="Name the application">

  In **General**, enter an **Application Name**. The repository name fills the field first, and the storage bucket and the [function](/en/documentation/platform/functions/) get the same name.

  </DocStep>
  <DocStep title="Select the Hexo preset">

  Set **Preset** to _Hexo_.

  </DocStep>
  <DocStep title="Set the root directory">

  In **Root Directory**, keep `/` if the Hexo project is at the root of the repository.

  </DocStep>
  <DocStep title="Enter the install command">

  In **Install Command**, enter `npm install`.

  </DocStep>
  <DocStep title="Select Deploy" />
</DocSteps>

The deploy page opens. Its title is `Deploy:` and the application name, and it shows the **Deploy Log** while the project builds. A successful deploy shows **Successfully created!** and the domain URL.

For the **Variables** section and the other fields of the form, refer to [Import a project from GitHub](/en/documentation/guides/application-development/automation/import-an-existing-project-from-github/).

</Fragment>

To create the project, run `azion init` with a project name. In the preset picker, select _Hexo_; in the template picker, select _Hexo Boilerplate_:

```bash
azion init --name my-site --auto -y
```

With `-y`, the command installs the dependencies. With `--auto`, it does not ask whether to start a local development server or deploy. For the questions it asks without these options, refer to [Azion CLI init](/en/documentation/devtools/cli/init/). The command prints:

The project is in the `my-site` folder. Its `azion.config.cjs` sets the `hexo` preset, and it uploads `./public` to a storage bucket with read-only access for workloads. For the settings of that file, refer to [azion.config.js](/en/documentation/devtools/cli/azion-config-js/).

To build the site, go to the project folder and run `azion build`:

```bash
cd my-site
azion build
```

To deploy the site, run `azion deploy` from the project folder:

```bash
azion deploy
```

The deploy uploads the project and opens the Azion Console page that tracks it. If the browser does not open, use the URL of that page in the output. At the end, the command prints the URL of the site's domain. For the full output and the deploy flags, refer to [Azion CLI deploy](/en/documentation/devtools/cli/deploy/).

To preview the site locally before a deploy, refer to [Azion CLI dev](/en/documentation/devtools/cli/dev-command/). For a Hexo project you already have, run `azion link` in its folder and select the Hexo preset, as described in [Azion CLI link](/en/documentation/devtools/cli/link-command/).

## Check the site

Each route gives you the URL of the site's Azion domain, in the form `https://xxxxxxxxxx.map.azionedge.net`. In Azion Console, the deploy page shows it; in the CLI route, `azion deploy` prints it at the end. Open that URL in a browser to load the Hexo site.

The first deploy can take several minutes to answer from every location; later deploys take about two minutes. A location that does not have the site yet answers with a `404` page that reads `There's nothing here yet`. If you get that page, wait, then load the URL again.
