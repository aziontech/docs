**Application Accelerator** is a Platform Resource that unlocks four cache and rule capabilities on Azion's distributed infrastructure, for the requests received by an [Application](/en/documentation/platform/applications/). With it, an Application can vary the cache key by query string, cookie, [device group](/en/documentation/platform/applications/device-groups/), or request method, and cache `POST` and `OPTIONS` responses. Its cache settings accept a shorter minimum time to live (TTL), and its rules can use [Rules Engine](/en/documentation/platform/applications/rules-engine/) behaviors and variables reserved to Application Accelerator. Use Application Accelerator to cache a cookie-personalized page, a query-string API response, or a per-device catalog.

## Request path

Turning on Application Accelerator leaves every cache key as it was: a variation applies only through a [Set Cache Policy](/en/documentation/platform/applications/rules-engine/#set-cache-policy) rule. That rule applies the cache setting that holds the variation to the requests it matches. A [cache setting](/en/documentation/platform/applications/cache/cache-settings/), the set of values that tell [Cache](/en/documentation/platform/applications/cache/) how to store and serve a response and for how long, holds its variations in its own `modules.application_accelerator` object.

A cache key is the index entry for a cached object. By default, Azion builds it from the scheme, the host, and the path of the request, so each path is one object in cache. Unless a cache setting varies the key by query string, every query string of a path maps to that one object. Each variation a cache setting turns on appends its input to the key with a marker, as [Cache keys](/en/documentation/platform/applications/cache/cache-keys/#key-format) details.

A request that uses any method other than `GET` or `HEAD` is a complex request, and its key carries the method as a prefix.

1. The request reaches the Application with its scheme, host, path, and query string.
2. A _Set Cache Policy_ rule applies a cache setting to the request.
3. Cache builds the key from the request and from each variation in the cache setting.
4. When Cache holds a valid copy under that key, that copy becomes the response.
5. Otherwise, the [Connector](/en/documentation/platform/connectors/) routes the request to the origin server, and Cache stores the response under that key.

Two requests share a copy when they produce the same key, and they get separate copies when they do not.

For what turning on Application Accelerator unlocks, the cost of a variation, and purges, refer to [Cache variation](/en/documentation/platform/applications/application-accelerator/cache-variation/). That page also compares _Bypass Cache_ with a TTL of 0.
