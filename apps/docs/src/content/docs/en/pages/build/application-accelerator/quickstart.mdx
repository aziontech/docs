This guide instructs you through your first cache setting that varies the cache key. The example is a listing page whose response changes with one query string argument.

- Turn on [Application Accelerator](/en/documentation/platform/applications/application-accelerator/) on an Application.
- Create a [cache setting](/en/documentation/platform/applications/cache/cache-settings/) that holds the listing for 30 seconds and varies by the `category` argument.
- Add a Rules Engine rule that applies the cache setting to requests for `/products`.
- Request the listing twice, with two values of `category`, and read the cache key of each response.

Three parts of the Application produce that result, and each one depends on the one before it:

1. Application Accelerator is on or off in each Application separately. It unlocks the fields that vary the cache key, and it removes the 60-second floor on the cache TTL.
2. A cache setting belongs to the Application and holds the cache behavior, the Max Age, and the variation. It sets what the cache does, not which requests it does it to.
3. The [Rules Engine](/en/documentation/platform/applications/rules-engine/) rule applies the cache setting with the [Set Cache Policy](/en/documentation/platform/applications/rules-engine/#set-cache-policy) behavior. Its criteria decide which requests the cache setting covers.

A cache setting reaches a request only when a rule applies that cache setting, so creating one leaves traffic as it was.

`azion.config.js` and Azion Lib carry the same settings. For the field each interface sets, refer to [Application Accelerator settings](/en/documentation/platform/applications/application-accelerator/settings/).

## Turn on Application Accelerator

Application Accelerator is off in a new Application, and each Application turns it on separately.

<Tabs client:visible sharedStore="interface">

<Fragment slot="panel.console">

### Console

To turn on Application Accelerator in Azion Console:

<DocSteps>
  <DocStep title="Open the Applications page">

  Access [Azion Console](https://console.azion.com/) > **Applications**.

  </DocStep>
  <DocStep title="Select the Application that serves the listing" />
  <DocStep title="Go to the Main Settings tab" />
  <DocStep title="Turn on Application Accelerator">

  In the **Modules** section, turn on **Application Accelerator**.

  </DocStep>
  <DocStep title="Select Save" />
</DocSteps>

The Application now accepts the cache fields the rest of this guide uses.

</Fragment>

<Fragment slot="panel.cli">

### CLI

Find the ID of your Application in its Azion Console address, `console.azion.com/applications/edit/<application_id>/main-settings`, or in the output of `azion list application`. To turn on Application Accelerator with the Azion CLI, replace `<application_id>` with that ID:

<DocSteps>
  <DocStep title="Run the update command">

  <Code client:visible lang="bash" code={`azion update application --application-id <application_id> --application-accelerator true`} />

  </DocStep>
  <DocStep title="Read the output">

  The command confirms the Application it updated:

  ```text
  Updated Application with ID <application_id>
  ```

  </DocStep>
</DocSteps>

The Application now accepts the cache fields the rest of this guide uses.

</Fragment>

<Fragment slot="panel.api">

### API

Find the ID of your Application in its Azion Console address, `console.azion.com/applications/edit/<application_id>/main-settings`. To turn on Application Accelerator with the Azion API, replace `[TOKEN VALUE]` with your personal token and `<application_id>` with that ID:

<DocSteps>
  <DocStep title="Send the update request">

  <Code client:visible lang="bash" code={`curl --request PATCH \\
    --url https://api.azion.com/v4/workspace/applications/<application_id> \\
    --header 'Accept: application/json' \\
    --header 'Authorization: Token [TOKEN VALUE]' \\
    --header 'Content-Type: application/json' \\
    --data '{
    "modules": {
      "application_accelerator": {
        "enabled": true
      }
    }
  }'`} />

  </DocStep>
  <DocStep title="Read the response">

  A `202` carries `"state": "pending"`, and the response echoes every key of `modules`:

  ```json
  {
    "cache": { "enabled": true },
    "functions": { "enabled": true },
    "application_accelerator": { "enabled": true },
    "image_processor": { "enabled": false }
  }
  ```

  The other keys of `modules` keep the values the Application already held. Only `application_accelerator` changed.

  </DocStep>
</DocSteps>

The Application now accepts the cache fields the rest of this guide uses.

</Fragment>

</Tabs>

:::caution
Turning on Application Accelerator can generate usage-related costs. For more information, refer to [Pricing](/en/documentation/fundamentals/pricing/#application-accelerator).
:::

## Create a cache setting that varies by query string

The cache setting holds the cache behavior and the variation. The Max Age of `30` seconds that this stage sets is the point of the exercise. Without Application Accelerator, the shortest cache TTL an Application accepts is 60 seconds.

<Tabs client:visible sharedStore="interface">

<Fragment slot="panel.console">

### Console

To create the cache setting in Azion Console:

<DocSteps>
  <DocStep title="Go to the Cache Settings tab" />
  <DocStep title="Select + Cache" />
  <DocStep title="Name the cache setting">

  Enter a value in **Name**. For example: `product-listing`.

  </DocStep>
  <DocStep title="Set the cache behavior and the TTL">

  Under **Cache**, select _Override cache behavior_ and set **Max Age** to `30`.

  </DocStep>
  <DocStep title="Vary the cache key by the query string">

  Under **Application Accelerator**, open **Cache vary by Query String** and set **Behavior** to _Allowlist_.

  </DocStep>
  <DocStep title="Name the argument that varies the key">

  In **Fields**, enter `category`.

  </DocStep>
  <DocStep title="Sort the query string arguments">

  Turn on **Sort**.

  </DocStep>
  <DocStep title="Select Save" />
</DocSteps>

The cache setting appears in the **Cache Settings** tab. It holds an object for 30 seconds and gives each value of `category` its own cached object.

</Fragment>

<Fragment slot="panel.cli">

### CLI

`azion create cache-setting` takes `max_age` only in a `--file` body. To create the cache setting with the Azion CLI, send the body from a file:

<DocSteps>
  <DocStep title="Write the cache setting to a file">

  Save the following as `cache-setting.json`:

  <Code client:visible lang="json" code={`{
    "name": "product-listing",
    "browser_cache": { "behavior": "honor" },
    "modules": {
      "cache": {
        "behavior": "override",
        "max_age": 30
      },
      "application_accelerator": {
        "cache_vary_by_querystring": {
          "behavior": "allowlist",
          "fields": ["category"],
          "sort_enabled": true
        }
      }
    }
  }`} />

  </DocStep>
  <DocStep title="Create the cache setting">

  <Code client:visible lang="bash" code={`azion create cache-setting --application-id <application_id> --file cache-setting.json`} />

  The command prints the id of the new cache setting:

  ```text
  Created Cache Settings configuration with ID 123462
  ```

  </DocStep>
  <DocStep title="Read the cache setting back">

  <Code client:visible lang="bash" code={`azion describe cache-setting --application-id <application_id> --cache-setting-id 123462 --format json`} />

  This excerpt of the output carries the fields the file set:

  ```json
  {
    "id": 123462,
    "name": "product-listing",
    "modules": {
      "cache": {
        "max_age": 30
      },
      "application_accelerator": {
        "cache_vary_by_querystring": {
          "behavior": "allowlist",
          "fields": ["category"],
          "sort_enabled": true
        }
      }
    }
  }
  ```

  </DocStep>
</DocSteps>

The cache setting holds an object for 30 seconds and gives each value of `category` its own cached object. Record the id: the rule in the next stage selects the cache setting by it. For every flag the command accepts, refer to [`azion create cache-setting`](/en/documentation/devtools/cli/resources/cache-setting/#create).

</Fragment>

<Fragment slot="panel.api">

### API

To create the cache setting with the Azion API, replace `[TOKEN VALUE]` with your personal token and `<application_id>` with the ID of your Application:

<DocSteps>
  <DocStep title="Send the create request">

  <Code client:visible lang="bash" code={`curl --request POST \\
    --url https://api.azion.com/v4/workspace/applications/<application_id>/cache_settings \\
    --header 'Accept: application/json' \\
    --header 'Authorization: Token [TOKEN VALUE]' \\
    --header 'Content-Type: application/json' \\
    --data '{
    "name": "product-listing",
    "browser_cache": { "behavior": "honor" },
    "modules": {
      "cache": {
        "behavior": "override",
        "max_age": 30
      },
      "application_accelerator": {
        "cache_vary_by_querystring": {
          "behavior": "allowlist",
          "fields": ["category"],
          "sort_enabled": true
        }
      }
    }
  }'`} />

  </DocStep>
  <DocStep title="Read the response">

  A `201` carries `"state": "executed"` and the cache setting. This excerpt carries the `id` and the fields the request set:

  ```json
  {
    "state": "executed",
    "data": {
      "id": 123461,
      "name": "product-listing",
      "modules": {
        "cache": {
          "behavior": "override",
          "max_age": 30
        },
        "application_accelerator": {
          "cache_vary_by_querystring": {
            "behavior": "allowlist",
            "fields": ["category"],
            "sort_enabled": true
          }
        }
      }
    }
  }
  ```

  A `max_age` below 60 is accepted only while Application Accelerator is on.

  </DocStep>
</DocSteps>

The cache setting holds an object for 30 seconds and gives each value of `category` its own cached object. Record the `id`: the rule in the next stage selects the cache setting by it.

</Fragment>

</Tabs>

## Apply the cache setting with a rule

A cache setting reaches a request only when a rule applies that cache setting.

<Tabs client:visible sharedStore="interface">

<Fragment slot="panel.console">

### Console

To apply the cache setting to the listing path in Azion Console:

<DocSteps>
  <DocStep title="Go to the Rules Engine tab" />
  <DocStep title="Select + Rule" />
  <DocStep title="Name the rule">

  Enter a name for the rule. For example: `Cache the product listing`.

  </DocStep>
  <DocStep title="Set the phase">

  Select **Request Phase**.

  </DocStep>
  <DocStep title="Select the variable">

  In the **Criteria** section, select the `${uri}` variable.

  </DocStep>
  <DocStep title="Select the comparison operator">

  Select _starts with_ as the comparison operator.

  </DocStep>
  <DocStep title="Enter the argument">

  Enter `/products` as the argument.

  </DocStep>
  <DocStep title="Select the behavior">

  In the **Behaviors** section, select _Set Cache Policy_.

  </DocStep>
  <DocStep title="Select the cache setting you created" />
  <DocStep title="Select Save" />
</DocSteps>

The rule applies the cache setting to every request whose URI starts with `/products`.

</Fragment>

<Fragment slot="panel.cli">

### CLI

To add the rule with the Azion CLI, send the body from a file, so the shell leaves `${uri}` as written.

<DocSteps>
  <DocStep title="Write the rule to a file">

  Save the following as `rule.json`, with the id of your cache setting in `attributes.value`:

  <Code client:visible lang="json" code={`{
    "name": "Cache the product listing",
    "active": true,
    "criteria": [
      [
        {
          "conditional": "if",
          "variable": "\${uri}",
          "operator": "starts_with",
          "argument": "/products"
        }
      ]
    ],
    "behaviors": [
      {
        "type": "set_cache_policy",
        "attributes": { "value": 123462 }
      }
    ]
  }`} />

  </DocStep>
  <DocStep title="Create the rule">

  <Code client:visible lang="bash" code={`azion create rules-engine --application-id <application_id> --phase request --file rule.json`} />

  The command prints the id of the new rule:

  ```text
  Created Rules Engine with ID 234570
  ```

  </DocStep>
</DocSteps>

The rule applies the cache setting to every request whose URI starts with `/products`.

</Fragment>

<Fragment slot="panel.api">

### API

To add the rule with the Azion API, replace `[TOKEN VALUE]` with your personal token and `<application_id>` with the ID of your Application. Send the body from a file, so the shell leaves `${uri}` as written.

<DocSteps>
  <DocStep title="Write the rule to a file">

  Save the following as `rule.json`, with the `id` the cache setting create returned in `attributes.value`:

  <Code client:visible lang="json" code={`{
    "name": "Cache the product listing",
    "active": true,
    "criteria": [
      [
        {
          "conditional": "if",
          "variable": "\${uri}",
          "operator": "starts_with",
          "argument": "/products"
        }
      ]
    ],
    "behaviors": [
      {
        "type": "set_cache_policy",
        "attributes": { "value": 123461 }
      }
    ]
  }`} />

  </DocStep>
  <DocStep title="Send the create request">

  <Code client:visible lang="bash" code={`curl --request POST \\
    --url https://api.azion.com/v4/workspace/applications/<application_id>/request_rules \\
    --header 'Accept: application/json' \\
    --header 'Authorization: Token [TOKEN VALUE]' \\
    --header 'Content-Type: application/json' \\
    --data @rule.json`} />

  </DocStep>
  <DocStep title="Read the response">

  A `202` carries `"state": "pending"` and the rule. The rule carries its `id`, its `name`, whether it is `active`, and the behaviors it holds. It also carries its `order` among the rules of the Application.

  </DocStep>
</DocSteps>

The rule applies the cache setting to every request whose URI starts with `/products`.

</Fragment>

</Tabs>

A new rule can take a few minutes to propagate. Wait before you request the path.

## Read the cache key

Azion returns the cache key of an object when the request carries the Azion debug header `Pragma: azion-debug-cache`. Reading that key for two values of `category` shows the variation the cache setting created.

Your Application receives the requests of a Workload, and that Workload answers on its workload domain, in the format `xxxxxxxxx.map.azionedge.net`. To add a custom domain to that Workload, refer to [Add a custom domain to a workload](/en/documentation/guides/platform/migration/configure-a-domain/).

Replace `<your-azion-domain>` with the domain of that Workload, and request the listing with one value:

<Code client:visible lang="bash" code={`curl -I -H "Pragma: azion-debug-cache" "https://<your-azion-domain>/products?category=shoes"`} />

The response carries two Azion debug headers. This excerpt is from an Application served at `www.example.com`, and HTTP/2 sends header names in lowercase:

```text
x-cache: MISS from 203.0.113.10 with HTTP/2.0
x-cache-key: httpswww.example.com/products@@?category=shoes
```

`x-cache` carries the cache status, the IP address of the server that answered, and the protocol of the request. `x-cache-key` carries the cache key, which concatenates the scheme, the host, the path, `@@`, and the query string arguments the allowlist named.

Request the same path with a different value:

<Code client:visible lang="bash" code={`curl -I -H "Pragma: azion-debug-cache" "https://<your-azion-domain>/products?category=hats"`} />

The argument changed, so the key changed with it:

```text
x-cache-key: httpswww.example.com/products@@?category=hats
```

Two keys are two cached objects, which is what the allowlist asked for. For the full format of a cache key, refer to [Cache key format](/en/documentation/platform/applications/cache/cache-keys/#key-format).

Your Application now caches the `/products` listing for 30 seconds and keeps one object per value of `category`.
