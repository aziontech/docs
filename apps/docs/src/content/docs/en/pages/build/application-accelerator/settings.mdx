[Application Accelerator](/en/documentation/platform/applications/application-accelerator/) is a Platform Resource that varies the cache key of an [Application](/en/documentation/platform/applications/) beyond the URL, and each Application turns it on separately. It unlocks the fields that vary the cache key, the caching of `POST` and `OPTIONS` responses, a Max Age below 60 seconds, and the [Rules Engine](/en/documentation/platform/applications/rules-engine/) behaviors and variables that this page lists. This page carries the name, the type, and the default of each field, and the interface that sets it.

---

## Application Accelerator switch

Application Accelerator is off in a new Application, and the setting belongs to the Application, not to a [cache setting](/en/documentation/platform/applications/cache/cache-settings/). So one Application can have Application Accelerator on while another has it off. Each interface turns on the same setting, which API v4 stores in `modules.application_accelerator.enabled`:

| Interface | Where you set it | Field or flag |
| --- | --- | --- |
| Azion Console | The **Modules** section of the **Main Settings** tab of an Application | The **Application Accelerator** switch |
| Azion API v4 | `PATCH /workspace/applications/{id}` | `modules.application_accelerator.enabled` |
| [Azion CLI](/en/documentation/devtools/cli/) | `azion update application` | `--application-accelerator` |
| [`azion.config.js`](/en/documentation/devtools/cli/azion-config-js/) | The `AzionApplication` object | `applicationAcceleratorEnabled` |
| [Azion Lib](/en/documentation/devtools/azion-lib/application/) | The data passed to an Application update, because API v3 refuses the field on create | `application_acceleration` |

`modules.application_accelerator.enabled` is a boolean and defaults to `false`. `applicationAcceleratorEnabled` and `application_acceleration` are booleans, and the Azion CLI flag takes a string.

The [Azion Terraform Provider](/en/documentation/devtools/terraform/) manages the Application resource that carries the switch. Turning on Application Accelerator can generate usage-related costs. For more information, refer to [Pricing](/en/documentation/fundamentals/pricing/#application-accelerator).

## Cache variation

Every cache setting carries its own `modules.application_accelerator` object, which shares its name with the object of the Application. The Application's object holds only `enabled`, and the cache setting's object holds the variations. With Application Accelerator on in the Application, the fields of the cache setting's object can leave their defaults.

Those fields configure Advanced Cache Key. They decide which parts of a request, beyond the URL, produce a separate cached object. A cookie, device group, or cached `POST` or `OPTIONS` variation appends the `@@` separator to the cache key. A query-string variation appends the `?` separator and its arguments instead. For the format of a cache key, refer to [Cache key format](/en/documentation/platform/applications/cache/cache-keys/#key-format).

Each field maps to a control in the **Application Accelerator** section of a cache setting, in Azion Console:

| Field | Type | Default | Console control | What it sets |
| --- | --- | --- | --- | --- |
| `cache_vary_by_method` | array of enum, at most 2 values: `options`, `post` | `[]` | **Cache vary by Method**, one checkbox per method | The request methods whose responses are cached. |
| `cache_vary_by_querystring.behavior` | enum: `ignore`, `all`, `allowlist`, `denylist` | `ignore` | **Cache vary by Query String** > **Behavior** | The mode that decides how the query string varies the key. |
| `cache_vary_by_querystring.fields` | array of string | `[]` | **Cache vary by Query String** > **Fields** | The query string arguments the mode applies to. |
| `cache_vary_by_querystring.sort_enabled` | boolean | `false` | **Cache vary by Query String** > **Sort** | Whether the variations group under one key, ordered alphabetically. |
| `cache_vary_by_cookies.behavior` | enum: `ignore`, `all`, `allowlist`, `denylist` | `ignore` | **Cache vary by Cookies** > **Behavior** | The mode that decides how cookies vary the key. |
| `cache_vary_by_cookies.cookie_names` | array of string | `[]` | **Cache vary by Cookies** > **Fields** | The cookies the mode applies to. |
| `cache_vary_by_devices.behavior` | enum: `ignore`, `allowlist` | `ignore` | **Cache vary by Devices** > **Behavior** | The mode that decides how device groups vary the key. |
| `cache_vary_by_devices.device_group` | array of integer | `[]` | **Cache vary by Devices** > **Device Group** | The [device groups](/en/documentation/platform/applications/device-groups/) the mode applies to. |

In Azion Console, the **Behavior** dropdowns of **Cache vary by Query String** and **Cache vary by Cookies** show _Allowlist_, _Denylist_, _Ignore_, and _All_. The one of **Cache vary by Devices** shows _Allowlist_ and _Ignore_.

`allowlist` and `denylist` on the query string need at least one argument in `fields`, or the API returns error `21018`. While Application Accelerator is off in the Application, the API refuses a variation with error `21013`. For every error a cache setting returns, refer to [Cache settings](/en/documentation/platform/applications/cache/cache-settings/#errors).

One field on the same cache setting sits outside that object and still requires Application Accelerator:

| Field | Type | Default | Console control | What it sets |
| --- | --- | --- | --- | --- |
| `modules.cache.max_age` | integer, `0` to `31536000` seconds | `60` | **Cache** > **Max Age** | How long the cache holds the object. A value below 60 requires Application Accelerator. |

Without Application Accelerator, a `max_age` below 60 returns error `21021`. With Application Accelerator and Tiered Cache on, a value below 3 returns error `21020`.

For the ceilings that bound a cache setting, refer to [Limits](/en/documentation/platform/applications/limits/#application-accelerator).

## Cache setting flags in Azion CLI

`azion create cache-setting` writes most of these fields from the command line. Each flag sets one field of the cache setting:

| Flag | Field it sets | Default |
| --- | --- | --- |
| `--cache-by-query-string` | `cache_vary_by_querystring.behavior` | `ignore` |
| `--query-string-fields` | `cache_vary_by_querystring.fields` | None |
| `--cache-by-cookies` | `cache_vary_by_cookies.behavior` | `ignore` |
| `--cookie-names` | `cache_vary_by_cookies.cookie_names` | None |
| `--enable-caching-for-post` | `options` and `post` in `cache_vary_by_method`, with either value | None |
| `--enable-caching-for-options` | `options` in `cache_vary_by_method`, with either value | `false` |

On create, either value turns a method on, so caching `POST` without `OPTIONS` takes `cache_vary_by_method` in a `--file` body. [`azion update cache-setting`](/en/documentation/devtools/cli/resources/cache-setting/#update) honors `true` and `false`. On update, a call that passes one method flag drops the other method, so pass both flags to keep both.

`azion create cache-setting` takes `sort_enabled`, device-group variation, and the cache `max_age` only in a `--file` body. On `azion update cache-setting`, `--enable-caching-string-sort` sets `sort_enabled`. `--browser-cache-max-age` sets the browser value alone.

## HTTP methods

Application Accelerator adds five methods to the `GET` and `HEAD` an Application handles. The responses of two of them can be cached through `cache_vary_by_method`.

| Method added by Application Accelerator | Response can be cached |
| --- | --- |
| `OPTIONS` | Yes, when `cache_vary_by_method` carries `options` |
| `POST` | Yes, when `cache_vary_by_method` carries `post` |
| `PUT` | No |
| `PATCH` | No |
| `DELETE` | No |

A cached `POST` or `OPTIONS` object gets its own cache key. For the shape of that key, refer to [Cache key variations](/en/documentation/platform/applications/cache/cache-keys/#variations).

## Rules Engine behaviors

These Rules Engine behaviors require Application Accelerator on the Application that runs the rule. The table indexes them; [Rules Engine](/en/documentation/platform/applications/rules-engine/#behaviors) owns the arguments and the syntax of each one.

| Behavior | Phases | What it does |
| --- | --- | --- |
| [Add Request Cookie, Add Response Cookie](/en/documentation/platform/applications/rules-engine/#add-request-cookie-and-add-response-cookie) | Request, Response | Adds a cookie to the `Set-Cookie` header. |
| [Bypass Cache](/en/documentation/platform/applications/rules-engine/#bypass-cache) | Request | Stops Azion's cache from storing the origin response, and leaves the browser cache untouched. |
| [Capture Match Groups](/en/documentation/platform/applications/rules-engine/#capture-match-groups) | Request, Response | Stores a regular expression capture over a request field in a temporary variable. |
| [Filter Request Cookie, Filter Response Cookie](/en/documentation/platform/applications/rules-engine/#filter-request-cookie) | Request, Response | Removes a cookie from the request to the origin or the response to the user. |
| [Forward Cookies](/en/documentation/platform/applications/rules-engine/#forward-cookies) | Request | Forwards the `Set-Cookie` header of the origin to users, including on a cache hit. |
| [Rewrite Request](/en/documentation/platform/applications/rules-engine/#rewrite-request) | Request | Modifies the resource path requested from the origin. |

_Bypass Cache_ acts on Azion's cache and not on the [Tiered Cache](/en/documentation/platform/applications/cache/tiered-cache/) layer. An Application whose cache settings have Tiered Cache on keeps caching objects there for the minimum time to live.

Rule criteria can read `${request_uri}` and `${device_group}`, and both require Application Accelerator. A rule that reads `${request_uri}` without it is refused with `25047`. For the variables, refer to [Variables](/en/documentation/platform/applications/rules-engine/#variables), and for the groups `${device_group}` matches, refer to [Device Groups](/en/documentation/platform/applications/device-groups/).

[Set Cache Policy](/en/documentation/platform/applications/rules-engine/#set-cache-policy) works without Application Accelerator. It applies a cache setting of the Application, and it is how a cache setting reaches a request.

[Run Function](/en/documentation/platform/applications/rules-engine/#run-function) also works without Application Accelerator. It runs a Function Instance of the Application, and it requires [Functions](/en/documentation/platform/functions/).
