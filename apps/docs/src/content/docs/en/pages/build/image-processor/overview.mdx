**Image Processor** is a Platform Resource that builds derived images from origin images on Azion's distributed infrastructure, for the requests received by an [Application](/en/documentation/platform/applications/). On-request image transformation is a delivery model where the server builds each variant of an image at request time, as described in the request URL. Use Image Processor to serve an image in several sizes, crops, qualities, or formats, such as WEBP for browsers that accept it, from one file.

## Request path

The `ims` query-string parameter does not transform an image by itself: a rule with the [Optimize Images](/en/documentation/platform/applications/rules-engine/#optimize-images) behavior has to match the request first. Turning Image Processor on in an Application only makes that behavior available to its [Rules Engine](/en/documentation/platform/applications/rules-engine/) rules.

Solid arrows carry the request, and dotted arrows carry the response. Each label starts with the number of its step below.

  App -.->|"4, 5. derived image"| Client

1. A request for a path that holds an image reaches the Application, which runs its Request Phase rules, such as a rule with _Optimize Images_ that matches image requests. To build that rule step by step, refer to [Configure Image Processor on an application](/en/documentation/guides/application-performance/delivery-optimization/process-images/).
2. When no rule with _Optimize Images_ matches, the source image, the file on the origin, is delivered unprocessed.
3. A matching rule applies its behaviors. _Optimize Images_ applies Image Processor to the request. When the rule also carries _Set Cache Policy_, that behavior applies the [cache setting](/en/documentation/platform/applications/cache/cache-settings/) that holds the derived image. A rule can carry _Optimize Images_ alone, because the behavior takes no argument.
4. When the derived image is already cached, [Cache](/en/documentation/platform/applications/cache/) delivers it without processing.
5. Otherwise, Image Processor reads the source image without changing it, and applies `ims` to it, such as `?ims=fit-in/400x400`. The derived image is delivered. The Application's cache stores it only when the rule applies a cache setting with _Set Cache Policy_. Without one, every request reaches Image Processor, which answers a repeated transformation from its own cache.

For how the delivered format is chosen, how the cache tells derived images apart, and where Image Processor stops, refer to [Image delivery](/en/documentation/platform/applications/image-processor/image-delivery/).
