You invoke a model with two things: the model id, and a request body in the format the model takes. For a chat model, that body follows the OpenAI chat completions format. [AI Inference](/en/documentation/platform/ai-inference/) accepts that request through two interfaces, and both reach the same models. You call the `Azion.AI.run` binding inside a [Function](/en/documentation/platform/functions/), or you post to the OpenAI-compatible HTTP endpoint that an Application deployed from a template serves. The request fields are the same on both, and over HTTP the body also carries the model id.

## The Azion.AI.run binding

`Azion.AI.run` is the runtime binding a Function calls to invoke a model. It takes the model id first and the request body this page describes second, and the call is asynchronous. The first argument decides the model, so the body does not need the id, and a `model` field in the body is ignored. The binding takes no credential, no base URL, and no host. The binding belongs to the runtime rather than to AI Inference, so its parameters, the call, and its return value are documented with the other runtime bindings, in [AI Inference API](/en/documentation/devtools/runtime/api-reference/ai/).

`Azion.AI.models()` returns a promise that resolves to an array of the model ids your account can call:

```ts
const modelIds = await Azion.AI.models()
```

## The HTTP endpoint

An Application deployed from the [AI Inference Starter Kit](/en/documentation/guides/application-development/frameworks/ai-inference-starter-kit/) serves the endpoint on the domains of its Workload: the workload domain, in the form `xxxxxxxxxx.map.azionedge.net`, or a custom domain of that Workload. The Function the template installs reads the model id from the `model` field of the body, and passes the whole body to `Azion.AI.run`.

The endpoint takes a `POST` request with a JSON body that carries `model`, on any path of the domain. `/v1/chat/completions` is the path OpenAI clients use, and the same endpoint also serves embedding and reranking bodies. The `Content-Type` header must be exactly `application/json`: a header that adds a `charset` parameter is refused. The template configures no authentication in front of the endpoint. When you add authentication to your Application, include the header it requires, for example `-H "Authorization: Bearer [TOKEN VALUE]"`.

A request to a chat model over HTTP:

```bash
curl -X POST https://<your-application-domain>/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{
    "model": "qwen-qwen25-vl-3b-instruct-awq",
    "max_tokens": 16,
    "messages": [
      { "role": "user", "content": "Name one European capital." }
    ]
  }'
```

The endpoint returns the object the model returns:

```json
{
  "id": "chatcmpl-0cb926279c564d868e3e3e8a2fc20313",
  "object": "chat.completion",
  "created": 1794444659,
  "model": "qwen-qwen25-vl-3b-instruct-awq",
  "choices": [
    {
      "index": 0,
      "message": {
        "role": "assistant",
        "content": "Paris, France is a European capital.",
        "refusal": null,
        "annotations": null,
        "audio": null,
        "function_call": null,
        "tool_calls": [],
        "reasoning_content": null
      },
      "logprobs": null,
      "finish_reason": "stop",
      "stop_reason": null
    }
  ],
  "service_tier": null,
  "system_fingerprint": null,
  "usage": {
    "prompt_tokens": 24,
    "total_tokens": 33,
    "completion_tokens": 9,
    "prompt_tokens_details": null
  },
  "prompt_logprobs": null,
  "kv_transfer_params": null
}
```

## Request fields

These fields form the body of a chat model request, whether you send it through the binding or over HTTP. Over HTTP, the body also carries a `model` field holding the model id. Through the binding, the first parameter carries the id. Each chat model names the [OpenAI Chat API](https://developers.openai.com/api/reference/overview) as the endpoint it is compatible with. The types, defaults, and bounds below are the ones the chat models' request schema states. A dash in the Default column means the schema sets no default for that field.

| Field | Type | Required | Default | Description |
| --- | --- | --- | --- | --- |
| `messages` | array | Yes | — | The conversation sent to the model. Each entry is a system, user, assistant, or tool message object. |
| `temperature` | number | No | — | Sampling temperature. Minimum `0`, maximum `2`. |
| `top_p` | number | No | — | Top-p sampling value. Maximum `1`. |
| `n` | integer | No | `1` | Number of responses to generate. Minimum `1`. |
| `stream` | boolean | No | `false` | Streams the response instead of returning it whole. Accepts `true` or `false`. |
| `max_tokens` | integer | No | — | Maximum number of tokens the model generates for each response. Minimum `1`. |
| `presence_penalty` | number | No | — | Presence penalty applied to the output. Maximum `2`. |
| `frequency_penalty` | number | No | — | Frequency penalty applied to the output. Maximum `2`. |
| `tools` | array | No | — | The tool definitions the model may call. The model pages that support it show the shape. |

A value past a minimum or a maximum rejects with `validation error: Minimum` or `validation error: Maximum` before the model runs. The validator also accepts `top_p` down to `0` and both penalties down to `-2`, but the model server refuses a request that sets `temperature` and `top_p` to `0` and both penalties to `-2` together. With `n` set to `2`, `choices` carries two entries, and `max_tokens` applies to each.

A field the model does not know is ignored, with no error. A misspelled field name therefore changes nothing in the response: check each name against the tables on this page.

Context length, tool calling, and the input types a model accepts are per-model values, and they are not part of this schema. For the model you call, refer to [AI models](/en/documentation/platform/ai-inference/models/).

### Tool choice, seed, stop, and log probabilities

The chat models also accept the fields below, which the request schema does not list. The descriptions apply to Qwen3 30B A3B Instruct 2507 FP8.

| Field | Type | Description |
| --- | --- | --- |
| `tool_choice` | string or object | How the model picks a tool: `auto`, `none`, `required`, or an object that names one function. |
| `seed` | integer | A sampling seed: the same request with the same `seed` can return the same output. |
| `stream_options` | object | Options for a streamed response, such as `{"include_usage": true}`. Requires `stream` set to `true`. |
| `logprobs` | boolean | With `true`, fills `choices[].logprobs` with the log probability of each generated token. |
| `top_logprobs` | integer | The number of alternative tokens listed for each generated token, with `logprobs` set to `true`. |
| `stop` | array of strings | Sequences that end the generation before they are written. |

`auto` is the behavior with no `tool_choice`, `required` forces a tool call, and `none` prevents `tool_calls`. With `none`, Qwen3 30B can still write the call as text in `content`. On Qwen2.5 VL AWQ 3B and 7B, an object that names the tool returns `tool_calls`, with `finish_reason` set to `stop`. A `seed` that is not an integer, a `tool_choice` outside these values, and `stream_options` without `stream` are refused with `Request failed with status 400`.

With `logprobs`, each entry of `choices[].logprobs.content` carries `token`, `logprob`, `bytes`, and `top_logprobs`. With `stop`, the response ends before the sequence, and `finish_reason` is `stop`.

## Message objects

Every entry in the `messages` array is a message object, and its `role` field states which of the four objects it is. The `content` field takes text as a string, or, on a model that accepts images, an array of content parts.

| Role | Required fields |
| --- | --- |
| `system` | `role`, `content` |
| `user` | `role`, `content` |
| `assistant` | `role`, `content`; `content` is `null` when the message carries `tool_calls` |
| `tool` | `role`, `tool_call_id`, `content` |

A `messages` array that carries a previous turn:

```json
{
  "messages": [
    { "role": "system", "content": "You are a helpful assistant." },
    { "role": "user", "content": "Name three European capitals." },
    { "role": "assistant", "content": "Amsterdam, Athens, and Lisbon." },
    { "role": "user", "content": "Which of them is furthest south?" }
  ]
}
```

When a model calls a tool, its response carries `tool_calls`, with `content` set to `null` and `finish_reason` set to `tool_calls`. To return the result, send the conversation again with the assistant message as the model returned it, followed by a `tool` message. The `tool_call_id` of that message is the `id` of the tool call, and its `content` carries the result. The model then answers in text. A `messages` array that returns a tool result, sent with the same `tools` array as the first request:

```json
{
  "messages": [
    { "role": "system", "content": "You are a helpful assistant with access to tools." },
    { "role": "user", "content": "What is the weather in London?" },
    {
      "role": "assistant",
      "content": null,
      "tool_calls": [
        {
          "id": "chatcmpl-tool-789b0d0737f84d09b61eee169a3bea75",
          "type": "function",
          "function": { "name": "get_weather", "arguments": "{\"location\": \"London\"}" }
        }
      ]
    },
    {
      "role": "tool",
      "tool_call_id": "chatcmpl-tool-789b0d0737f84d09b61eee169a3bea75",
      "content": "{\"temperature_c\": 14, \"condition\": \"light rain\"}"
    }
  ]
}
```

A model that accepts images takes `content` as an array of content parts instead of a string. Each part states its `type`, and carries the field that type uses. The model pages of the models that accept images show this form; a text-only model takes the string.

| Content part | Type | Carries |
| --- | --- | --- |
| `type` | string | Which kind of part this is: `text` or `image_url`. |
| `text` | string | The text of the part, when `type` is `text`. |
| `image_url` | object | The image of the part, when `type` is `image_url`. |
| `image_url.url` | string | An `https` URL that serves the image, or a `data:` URL with the image in base64. |

A `content` array carrying text and an image:

```json
{
  "role": "user",
  "content": [
    { "type": "text", "text": "What is in this image?" },
    { "type": "image_url", "image_url": { "url": "<your-image-url>" } }
  ]
}
```

The URL must serve an image the model can fetch. A URL that serves no image fails with `Request failed with status 500`, which does not name the image as the cause. To find out whether a model accepts images, read the input types on its page in [AI models](/en/documentation/platform/ai-inference/models/).

## Streaming responses

With `stream` set to `true`, the two interfaces deliver the response in chunks, each a `chat.completion.chunk` object. The text of each chunk is in `choices[0].delta.content`, and the last chunk of text carries `finish_reason`.

- **Through the binding**, `Azion.AI.run` resolves to an async iterator of parsed chunk objects, which the Function reads with `for await`. No `[DONE]` item reaches the iterator.
- **Over HTTP**, the endpoint answers with `Content-Type: text/event-stream`, one `data:` line per chunk, and a final `data: [DONE]` line.

`usage` arrives only when the body sets `stream_options` to `{"include_usage": true}`. It comes in one more chunk at the end, whose `choices` array is empty:

```json
{
  "id": "chatcmpl-2d0e9241b82048c49b9f946c746818b1",
  "object": "chat.completion.chunk",
  "created": 1794443931,
  "model": "qwen-qwen3-30b-a3b-instruct-2507-fp8",
  "choices": [],
  "usage": {
    "prompt_tokens": 20,
    "total_tokens": 30,
    "completion_tokens": 10
  }
}
```

## Embedding requests

An embedding model takes a request body the chat schema does not define. `input` carries the text to embed and is the only required field. The other two shape the vector that comes back, and each accepts a fixed set of values. A value outside the set rejects with `validation error: Enum`.

| Field | Type | Required | Description |
| --- | --- | --- | --- |
| `input` | string, or an array of strings | Yes | The text to embed. An array returns one embedding per string. |
| `encoding_format` | string | No | The encoding of the embedding in the response: `float` or `base64`. |
| `dimensions` | integer | No | The size of the vector the model returns: `256`, `512`, `1024`, `2048`, or `4096`. |

Without `dimensions`, Qwen3 Embedding 4B returns a vector of 2560 numbers. With `dimensions` set to `4096`, the request is accepted and the vector still has 2560 numbers. With `base64`, the embedding is a string that decodes to little-endian 32-bit floats, 4 bytes per dimension. The vectors are normalized to a length of 1.

To store the vectors an embedding model returns and query them, refer to [Vector search](/en/documentation/platform/sql-database/vector-search/).

## Reranking requests

A reranking request does not carry a `messages` array. It carries a query and the documents to rank against it, and both are required.

| Field | Type | Carries |
| --- | --- | --- |
| `query` | string | The query the documents are ranked against. |
| `documents` | array of strings | The documents to rank by relevance to `query`. |
| `top_n` | integer | The number of results to return, highest scores first. |
| `max_tokens_per_doc` | integer | Declared by the schema, which states no default and no bounds. Accepted, with no documented effect. |

## Response fields

A model returns one object, whatever interface carried the request. The shape depends on what the model does, and the three below cover every model in the catalog. The model pages show a complete payload for the models that have one.

The `model` field carries the account's internal id for the model, in lowercase with hyphens, which can differ from the id the request sent. A request to `Qwen/Qwen3-30B-A3B-Instruct-2507-FP8` returns `qwen-qwen3-30b-a3b-instruct-2507-fp8`, and GPT-OSS 20B returns `gpt-oss-20b`, an id that `Azion.AI.run` refuses as input. Do not reuse the `model` field of a response as an id.

A chat model returns a `chat.completion` object:

| Field | Type | Carries |
| --- | --- | --- |
| `id` | string | The identifier of this completion. |
| `object` | string | `chat.completion`. |
| `created` | integer | When the completion was created. |
| `model` | string | The internal id of the model that answered. |
| `choices` | array | The generated responses, one entry per response requested through `n`. |
| `choices[].index` | integer | The position of the entry in `choices`. |
| `choices[].message` | object | The generated message. |
| `choices[].message.role` | string | `assistant`. |
| `choices[].message.content` | string, or null | The generated text. This is where a chat response is read from. |
| `choices[].message.reasoning_content` | string, or null | The reasoning the model returned, where it returns any. |
| `choices[].message.reasoning` | string, or null | The same reasoning, on Qwen3 30B and GPT-OSS 20B. |
| `choices[].message.tool_calls` | array | The tools the model chose to call. |
| `choices[].finish_reason` | string | Why generation stopped, such as `stop`, `length`, or `tool_calls`. |
| `choices[].stop_reason` | string, integer, or null | The stop condition that ended generation. |
| `choices[].logprobs` | object, or null | The log probabilities, when the request sets `logprobs`. |
| `usage` | object | The tokens the request and the response consumed. |
| `usage.prompt_tokens` | integer | The tokens read from the request. |
| `usage.completion_tokens` | integer | The tokens generated in the response. |
| `usage.total_tokens` | integer | The two added together. |
| `usage.prompt_tokens_details` | object, or null | The breakdown of the prompt tokens. |
| `prompt_logprobs` | object, or null | The log probabilities of the prompt, where the model returns them. |

`content` is `null` when the message carries `tool_calls`. It can also be `null` on GPT-OSS 20B, which fills `reasoning_content` first: with a small `max_tokens`, the reasoning can use the whole budget, and `finish_reason` is `length`.

A chat response also carries fields this table does not describe: `refusal`, `annotations`, `audio`, and `function_call` in the message; `token_ids` in each choice on Qwen3 30B; and `service_tier`, `system_fingerprint`, `prompt_token_ids`, and `kv_transfer_params` at the top level.

An embedding model returns a `list` object whose `data` array holds one embedding per input:

| Field | Type | Carries |
| --- | --- | --- |
| `id` | string | The identifier of this response. |
| `object` | string | `list`. |
| `created` | integer | When the response was created. |
| `model` | string | The internal id of the model that answered. |
| `data` | array | The embeddings, one entry per input. |
| `data[].index` | integer | The position of the entry in `data`. |
| `data[].object` | string | `embedding`. |
| `data[].embedding` | array of numbers, or string | The vector, or its base64 string when `encoding_format` is `base64`. |
| `usage` | object | The tokens the request consumed: `prompt_tokens`, `total_tokens`, `completion_tokens`, and `prompt_tokens_details`. |

A reranking model returns the ranked results:

| Field | Type | Carries |
| --- | --- | --- |
| `id` | string | The identifier of this response. |
| `model` | string | The internal id of the model that answered. |
| `results` | array | The ranked entries, highest score first. |
| `results[].index` | integer | The position the entry held in `documents`. |
| `results[].document` | object | The entry that was ranked. |
| `results[].document.text` | string | The text of that entry. |
| `results[].document.multi_modal` | null | A field the reranker returns with no value. |
| `results[].relevance_score` | number | How relevant the model judged the entry. |
| `usage.total_tokens` | integer | The tokens the request consumed. |

## Errors

`Azion.AI.run` rejects with an error object that carries `name` and `message` only, with no `code` and no `status` field. Read `message` to tell the cases apart:

| Error | Cause | What to do |
| --- | --- | --- |
| `AIError: model not found or not allowed` | The model id does not exist, or the account has no access to AI Inference. The message does not say which. | Copy the id from the model page, or list the ids with `Azion.AI.models()`. For access, refer to [AI Inference limits](/en/documentation/platform/ai-inference/limits/). |
| `AIError: validation error: <Type> {path: "<field>"}` | The body does not match the model's schema. The model does not run. | Fix the field that `path` names. |
| `Error: Request failed with status <N>` | The model server refused a request that passed validation. The message carries no reason. | Check the values the model server refuses, listed below. |

The validation `<Type>` is `Required` for a missing field, `WrongType` for a value of the wrong type, with a `detail` such as `The value must be integer`, `Minimum` or `Maximum` for a value past a bound, `Enum` for a value outside a fixed set, or `OneOf` for a message that matches no message object.

The model server refuses these with status `400`: a prompt longer than the context the model serves, which the message does not name as the cause; `temperature` and `top_p` at `0` with both penalties at `-2`; a `tools` request without `tool_choice` on Qwen2.5 VL AWQ 3B, Qwen2.5 VL AWQ 7B, or Nanonets-OCR-s; a `seed` that is not an integer; an unknown `tool_choice`; and `stream_options` without `stream`. An `image_url` that serves no image fails with status `500`.

The endpoint of the AI Inference Starter Kit returns its own errors as a JSON body with an `error` field:

| Status | Body | Cause |
| --- | --- | --- |
| `400` | `{"error":"Request must be a POST request with JSON body"}` | The method is not `POST`, or `Content-Type` is not exactly `application/json`. |
| `400` | `{"error":"Invalid JSON in request body"}` | The body does not parse as JSON. |
| `400` | `{"error":"Missing 'model' field in request body"}` | The body has no `model` field. |
| `400` | `{"error":"<model> not found or not allowed"}` | The binding rejected the id with `model not found or not allowed`. |
| `400` | `{"error":"Invalid input for <model>"}` | The binding rejected the body with a `validation error`. |
| `500` | `{"error":"AI internal error"}` | Any other error, such as a refusal from the model server. |
