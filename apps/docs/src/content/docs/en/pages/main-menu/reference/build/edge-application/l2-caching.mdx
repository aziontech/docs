**Tiered Cache** is a Feature of [Cache](/en/documentation/platform/applications/cache/) that adds a second cache layer between Azion's cache and your origin. The first layer is the cache of the data center that answered the request. The second layer sits in the region that the `topology` of a cache setting selects.

When a request misses the first layer, the data center asks the Tiered Cache layer before it asks the origin. A valid copy in that layer answers the miss, and the origin receives no request. You turn the layer on per cache setting, and it applies to the objects that setting caches. For how the two layers answer a request, refer to [Expiration and freshness](/en/documentation/platform/applications/cache/expiration-and-freshness/#tiered-cache).

An answer from the Tiered Cache layer arrives with less latency than one from the origin, and fewer requests reach the origin. The origin handles less load at a lower infrastructure cost. The price is one extra hop on a miss in the first layer. With [Application Accelerator](/en/documentation/platform/applications/application-accelerator/) on, Tiered Cache also sets a floor of 3 seconds on the time to live (TTL) of the cache setting.

## Interfaces

A cache setting turns Tiered Cache on in its `modules.cache.tiered_cache` object, and the four interfaces below write that object. The table names where the control sits in each one.

| Interface | Where | Value |
| --- | --- | --- |
| [Azion Console](https://console.azion.com/) | The **Cache** section of the **Create Cache Settings** drawer, under the **Cache Settings** tab of an Application in [Applications](/en/documentation/platform/applications/) | The **Tiered Cache** toggle, off on a new setting, and the **Tiered Cache Region** select, `nearest-region` by default |
| [Azion API v4](/en/documentation/devtools/api/) | `POST /v4/workspace/applications/{application_id}/cache_settings` | `modules.cache.tiered_cache.enabled`, `true` or `false`, and `modules.cache.tiered_cache.topology` |
| [Azion CLI](/en/documentation/devtools/cli/) | `azion create cache-setting --file` with the JSON body | The same `tiered_cache` object. The `--tiered-caching-enabled` flag alone is rejected with error `21001` |
| `azion.config.js` | An entry of the `cache` array, of type `AzionCache` | `tieredCache: { enabled, topology }` |

:::note
Two conditions bind the cache setting. Its `modules.cache.behavior` must be `override`, because the API rejects Tiered Cache under `honor` with error `21001`. The CLI sets the cache behavior only in the JSON body of `--file`. With [Application Accelerator](/en/documentation/platform/applications/application-accelerator/) on the Application, its `modules.cache.max_age` must be at least 3 seconds, or the API returns error `21020`. Without Application Accelerator, the 60-second floor of every cache setting holds, and the API returns `21021`.
:::

Tiered Cache is included on every service plan. For every field of a cache setting, with the title and the fix of each error, refer to [Cache settings](/en/documentation/platform/applications/cache/cache-settings/). For the Console steps that apply a setting to a path, refer to [Configure cache policies for an application](/en/documentation/guides/application-performance/cache-and-purge/cache-settings/).

## Topology

The `topology` of a cache setting selects where the Tiered Cache layer holds the objects that setting caches. Azion Console, the API, the CLI JSON body, and `azion.config.js` accept values such as the ones below, and the [Azion API reference](https://api.azion.com/) lists every accepted value. A value the API does not accept returns error `10039`, `Invalid Choice`.

| Value | Meaning |
| --- | --- |
| `nearest-region` | Nearest region |
| `us-east-1` | United States, east |

## TTL

The time to live (TTL) of an object in the Tiered Cache layer is the Max Age of its cache setting, the `modules.cache.max_age` field. While Tiered Cache and Application Accelerator are both on, that field has a floor of 3 seconds. A new cache setting starts at 60 seconds, the default of Max Age in Azion Console, the API, and the CLI. For example, on an Application with Application Accelerator on, a Max Age of 2 seconds with Tiered Cache on is rejected with error `21020`. The same setting at 3 seconds is accepted. Tiered Cache is designed for objects that stay cached for a long time.

The ceiling is the ceiling of the cache TTL itself. For the value and the error past it, refer to [Applications limits](/en/documentation/platform/applications/limits/#cache).

## Purge

[Real-Time Purge](/en/documentation/platform/applications/cache/real-time-purge/) removes an object from the Tiered Cache layer before its TTL ends. The layer is `tiered_cache` in the API body and in the `--layer` flag of `azion purge`. A cache key purge is the only type that reaches it. A URL or wildcard purge with that layer returns error `30001`, `Invalid Purge Layer For Purge Type`.

To remove an object held in both layers, purge Tiered Cache first and then Cache. In that order, the first layer is not refilled from a stale Tiered Cache copy. For the Console, API, and CLI steps, refer to [Purge cached content](/en/documentation/guides/application-performance/cache-and-purge/purge-cached-content/).

## Bypass Cache

A rule with the [Bypass Cache](/en/documentation/platform/applications/rules-engine/#bypass-cache) behavior in [Rules Engine](/en/documentation/platform/applications/rules-engine/) affects Azion's cache and not the Tiered Cache layer. An Application whose cache settings turn Tiered Cache on continues to cache objects in that layer for the minimum TTL. For the symptom this produces and what to do about it, refer to [Troubleshoot Applications](/en/documentation/platform/applications/troubleshooting/#cache).

## Observability

[Real-Time Metrics](/en/documentation/platform/real-time-metrics/) carries a **Tiered Cache** dataset beside its Cache dataset. [Real-Time Events](/en/documentation/platform/real-time-events/) carries a **Tiered Cache** dataset as well. Through GraphQL, you query the data that Tiered Cache transfers. For the query and its response, refer to [Query usage data from Tiered Cache](/en/documentation/guides/platform/observability/query-tiered-cache-usage-data-with-graphql/).
