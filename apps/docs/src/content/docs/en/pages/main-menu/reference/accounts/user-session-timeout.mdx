The **User Session Timeout** feature allows you to define a **maximum idle time**, ensuring that sessions are automatically terminated after a period of inactivity. It also allows you to define a **maximum session time** to avoid sessions staying open indefinitely. This implementation increases the platform's security, protecting sensitive user data and preventing unauthorized access due to prolonged sessions.

With User Session Timeout, you can:

- Configure a maximum idle time and session timeout to attend to compliance and security policies.
- Guarantee users' sessions and data are protected.

:::note
When an organization sets up the User Session Timeout, it applies to all account levels.

User Session Timeout is available for customers of all [Azion Support](https://www.azion.com/en/professional-services/) services.
:::

## Policy settings

:::note
To configure the User Session Timeout, you must have *Account Owner* privileges.
:::

A session timeout policy determines the maximum idle time for session termination and the maximum session time. You configure the policy through the [Azion API](https://api.azion.com/). Azion Console has no screen for it. For the steps, refer to [Configure User Session Timeout](/en/documentation/guides/application-security/access-and-compliance/configure-user-session-timeout/).

| Setting | API field | Range | Default |
| --- | --- | --- | --- |
| **Maximum idle time** | `max_idle_time` | From *1 minute* to *1440 minutes*, and not longer than the *configured maximum session time* | *1440 minutes*, equivalent to *1* day |
| **Maximum session time** | `max_session_time` | From *5 minutes* to *15 days*, in *minutes* | *21600*, equivalent to *15 days* in minutes |

### Maximum idle time

**Maximum idle time** refers to the period of inactivity after which a session is automatically terminated. It is defined by any API call or interface interaction within a session; if the time since the last access meets or exceeds the configured idle time, the session will expire, and the user will be logged out.

If the idle time setting is updated, active sessions will automatically conform to the new policy. For instance, if the idle time is reduced, sessions created before the update must follow the new duration and may be terminated if needed.

### Maximum session time

**Maximum session time** limits the total time a session can remain active, regardless of activity, ensuring sessions do not stay open indefinitely.

If the maximum session time setting is updated, active sessions will automatically conform to the new policy. For instance, if the maximum session time is reduced, sessions created before the update must follow the new duration and may be terminated if needed.
