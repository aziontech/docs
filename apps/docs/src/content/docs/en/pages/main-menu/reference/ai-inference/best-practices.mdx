Code that calls a model decides who can make the call, which model answers, what the model reads, and what the caller gets back. Each of those decisions is made in your code, before or after the call. Left to their defaults, an endpoint answers anyone, a mistyped field changes nothing without an error, and a response read too directly breaks on the first model that answers differently.

In [AI Inference](/en/documentation/platform/ai-inference/), that code is a [Function](/en/documentation/platform/functions/), and it calls a model with `Azion.AI.run`. The request fields are on [Model invocation](/en/documentation/platform/ai-inference/model-invocation/), the conditions Azion applies to a model are on [AI Inference limits](/en/documentation/platform/ai-inference/limits/), and the path of a request is on [How AI Inference works](/en/documentation/platform/ai-inference/how-it-works/).

In order, the practices cover the check on each request, the models a request can reach, the model id, the capabilities of each model, the spelling of each field, the size of the input and the output, the read of the response, and the errors. The specimens are JavaScript for a Function, and request bodies in JSON.

---

## Check each request in the Function before it calls a model

The [AI Inference Starter Kit](/en/documentation/guides/application-development/frameworks/ai-inference-starter-kit/) template configures no authentication in front of its endpoint, and its rule runs the Function on every path. Any client that reaches the domain can therefore call a model, and every call is billed in Compute Time and Requests. The cost of a check is a secret to keep and a header every client sends.

This Function rejects a request whose `Authorization` header does not carry the secret, before `Azion.AI.run` runs. The full shape also carries the next practice's model check and the last practice's error handling:

```js
const ALLOWED_MODELS = ["Qwen/Qwen3-30B-A3B-Instruct-2507-FP8"];

async function handleRequest(request) {
  const secret = Azion.env.get("INFERENCE_SECRET");
  if (!secret || request.headers.get("Authorization") !== `Bearer ${secret}`) {
    return new Response(JSON.stringify({ error: "Unauthorized" }), {
      status: 401,
      headers: { "Content-Type": "application/json" },
    });
  }

  const input = await request.json();
  const model = input["model"];
  if (!ALLOWED_MODELS.includes(model)) {
    return new Response(JSON.stringify({ error: `${model} is not allowed` }), {
      status: 403,
      headers: { "Content-Type": "application/json" },
    });
  }

  try {
    const modelResponse = await Azion.AI.run(model, input);
    return new Response(JSON.stringify(modelResponse), {
      headers: { "Content-Type": "application/json" },
    });
  } catch (e) {
    console.error(`${e.name}: ${e.message}`);
    if (e.message.includes("validation error")) {
      return new Response(JSON.stringify({ error: `Invalid input for ${model}` }), {
        status: 400,
        headers: { "Content-Type": "application/json" },
      });
    }
    if (e.message.includes("model not found")) {
      return new Response(JSON.stringify({ error: `${model} not found or not allowed` }), {
        status: 400,
        headers: { "Content-Type": "application/json" },
      });
    }
    return new Response(JSON.stringify({ error: "AI internal error" }), {
      status: 500,
      headers: { "Content-Type": "application/json" },
    });
  }
}

addEventListener("fetch", (event) => {
  event.respondWith(handleRequest(event.request));
});
```

`Azion.env.get` reads the secret from an environment variable stored on your Azion account, per [Environment variables](/en/documentation/devtools/runtime/api-reference/environment-variables/). When the variable does not exist, the call returns `undefined`, and the Function refuses every request. The check covers every domain of the Workload: a custom domain answers in addition to the workload domain, and only the **Workload Domain Allow Access** switch of the Workload closes the workload domain.

To check it, send a request without the header: the Function answers `401`.

## Choose in the Function which models a request can reach

The Function the template installs passes the `model` field of the request body to `Azion.AI.run` as it arrives. A client can therefore select any model the account can call, including one whose context, capabilities, or consumption you never planned for. The cost is a list to update each time you adopt a model.

In the Function of the first practice, the list is `const ALLOWED_MODELS = ["Qwen/Qwen3-30B-A3B-Instruct-2507-FP8"];`, and a request that names another model answers `403`. To map names of your own to model ids, with a key per team, refer to [Route model calls through a gateway function](/en/documentation/guides/ai/inference/route-model-calls-through-a-gateway-function/).

To check it, send a request whose `model` is not on the list: the Function answers `403`, and no model runs.

## Copy each model id from its model page, or list the ids with Azion.AI.models()

A model answers to its id and to nothing else: the first argument of `Azion.AI.run`, or the `model` field over HTTP, with no base URL or host beside it. Ids do not follow from the model name. Two forms can select the same model, `Qwen/Qwen2.5-VL-3B-Instruct-AWQ` and `qwen-qwen25-vl-3b-instruct-awq`, and no simple rule turns one into the other: `Qwen2.5` becomes `qwen25`. GPT-OSS 20B answers to `openai/gpt-oss-20b`, while `gpt-oss-20b` is refused.

Copy the id from the model's page in [AI models](/en/documentation/platform/ai-inference/models/), or list the ids your account can call from a Function:

```js
const modelIds = await Azion.AI.models();
```

Never reuse the `model` field of a response as an id: it carries an internal id, and GPT-OSS 20B returns `gpt-oss-20b`, the form that is refused.

To check it, run the call once: a wrong id rejects with `AIError: model not found or not allowed`. An account without access to AI Inference receives the same error, so confirm the access in [AI Inference limits](/en/documentation/platform/ai-inference/limits/) first.

## Send each model only the requests its page says it serves

What a model accepts belongs to that model. Each page in [AI models](/en/documentation/platform/ai-inference/models/) states its context length, from 8k to 131k tokens across the catalog, its input types, text only or text and images, and its tool calling: Yes, Named tool only, or No. The model server refuses a prompt longer than the context, and a `tools` request that leaves the choice to a model whose tool calling is not Yes, with `Request failed with status 400`. The message does not say which value caused it. Where a page states nothing, the capability is unknown, not absent: confirm it before your code depends on it.

For example, Qwen2.5 VL AWQ 3B and 7B refuse a `tools` request that leaves the choice to the model, and return `tool_calls` when the body names the tool: `"tool_choice": {"type": "function", "function": {"name": "get_weather"}}`. The cost is a check per model in your code, since the platform reports the mismatch only as a status.

To check it, read the capability on the model page whenever a call fails with status `400`.

## Spell each request field as Model invocation lists it

A field the model does not know is ignored, with no error. A misspelled field therefore changes nothing in the response, and nothing tells you it was not applied. The cost is a check against [Model invocation](/en/documentation/platform/ai-inference/model-invocation/) whenever you add a field.

A body that sets the sampling temperature spells it `"temperature": 0.7`. Written as `"temprature": 0.7`, the field is ignored, and the request runs as if it carried no temperature.

To check it, send the field once with a value past its bound, such as `"temperature": 2.1`: a correctly spelled field rejects with `validation error: Maximum`, and a misspelled one returns a normal response.

## Send the model only the input it needs, and bound the output

Everything a model reads comes from your Function, in the same execution that awaits the answer. The model reads the whole prompt, and the time it takes to generate is time the Function waits. That wait does not count against the 2-second CPU limit of the Function, but it does count toward its 5-minute execution time, which is wall-clock time, per [Functions limits](/en/documentation/platform/functions/limits/). AI Inference bills Compute Time and Requests, and Compute Time, the duration of active execution multiplied by the memory allocated, grows with a longer generation.

Send the section of a document that answers the question, not the whole document, and set `max_tokens` on every body, such as `"max_tokens": 1024`. The cost is a margin to keep: GPT-OSS 20B reasons before it answers, and with a small `max_tokens`, the reasoning can use the whole budget and return `content` set to `null`.

To check it, read `usage.prompt_tokens` and `usage.completion_tokens` in the response before and after you change a prompt.

## Read the response with optional chaining, and check why it stopped

The generated text of a chat model sits four levels into the response, at `choices[0].message.content`, and that text is not always there. `content` is `null` when the model returns `tool_calls`, and on GPT-OSS 20B when the reasoning uses the whole `max_tokens`. With `stream` set to `true`, `Azion.AI.run` resolves to an async iterator of chunks instead, with no `choices[0].message` at all.

Read each level with optional chaining, so a missing level returns `undefined` rather than throwing inside the Function:

```js
const summary = modelResponse?.choices?.[0]?.message?.content?.trim();
```

The cost is a branch for the empty case. To check it, read `choices[0].finish_reason` whenever the text is empty: `tool_calls` means the model chose a tool, and `length` means it ran out of `max_tokens`.

## Tell the three kinds of failure apart by their message

A failed `Azion.AI.run` call rejects with an error that carries `name` and `message` only, with no `code` and no `status`. The message tells the cases apart. `AIError: model not found or not allowed` covers an id that does not exist and an account without access. `AIError: validation error` covers a body that does not match the model's schema, before the model runs. `Error: Request failed with status <N>` covers a refusal from the model server, with no reason.

The Function of the first practice branches on the message: `e.message.includes("validation error")` and `e.message.includes("model not found")` answer `400`, and any other error answers `500`. It also writes each error with `console.error`. The cost is that a model server refusal reaches the caller with no cause, so the Function cannot tell the caller what to change. For every error and its cause, refer to [Model invocation](/en/documentation/platform/ai-inference/model-invocation/#errors).

To check it, open [Real-Time Events](/en/documentation/platform/real-time-events/): the Functions Console data source carries the lines the Function writes with `console.error`, `AIError` messages included.
