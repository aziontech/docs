**Edge Pulse** is a Platform Resource that collects page-load measurements from the browsers of the people who visit your pages. [Real user monitoring](https://www.azion.com/en/learning/observability/what-is-real-time-monitoring/) measures a site from its visitors' devices: a script in each page reports how the visit loaded, instead of a scheduled test. Use Edge Pulse to compare page load times across your pages, see which connection types your visitors have, and find pages reached through redirects.

Edge Pulse reaches your pages through one script:

- [Edge Pulse JavaScript tag](/en/documentation/platform/edge-pulse/javascript-tag/) is what you add to a page to have its loads measured, in one of two forms from Azion Console. The two forms load the script in different ways, which matters on a page with a Content Security Policy.

## Request path

A tagged page does not report every visit: a browser sends at most one record every 30 minutes for each scheme and host. Edge Pulse receives a record only from a page that carries the tag.

The diagram follows one page load until a query reads its record. Solid arrows carry a request, the thick arrow carries the page-load record, and dotted arrows carry the response. Each label starts with the number of its step in the list.

```mermaid
  Page[["Your tagged page"]]

  Reader(["Your GraphQL query"])
  Browser -->|"1. page request"| Page
  Browser -->|"2. script download"| Client
  Browser ==>|"3. page-load record"| EP
  Reader -->|"4. pulseEvents query"| EP
  EP -.->|"5. matching records"| Reader
```

1. A visitor's browser loads a page of yours that carries the Edge Pulse JavaScript tag.
2. The tag has the browser download the RUM Client, the script that takes the measurement. The measurement starts at least 2 seconds after the load event, so a visit that ends earlier sends nothing.
3. When 30 minutes have passed since that browser's last record for the same scheme and host, the RUM Client sends one page-load record. The time of that last record lives in the browser's local storage, so a private window starts over. The record carries the page address, the Navigation Timing values, the connection estimate, and the ID that the tag holds in its address.
4. You send a GraphQL query on the `pulseEvents` dataset to the endpoint of the Real-Time Events GraphQL API, with a token of your account.
5. The API answers with the matching records. In a test on one account, it returned the records carrying that account's client ID, about one minute after the browser sent them.
