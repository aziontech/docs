This guide instructs you through getting your first response from an AI Inference model.

- Deploy the AI Inference Starter Kit template as an Application.
- Open the workload domain of the Workload the template creates.
- Post a chat request to a model and read the answer it returns.
- Call another model by changing one field of the request.

The template creates these entities, and one request passes through them in this order:

1. A **Workload**, with its deployment. The Workload receives the request on its workload domain, in the form `xxxxxxxxxx.map.azionedge.net`, and its deployment sets the Application.
2. An **Application**, with Cache, Functions, and Application Accelerator turned on. Its one rule runs the Function on every path, through the Function Instance, and bypasses the cache.
3. A **Function** and its **Function Instance**, which binds the Function to the Application. The Function reads the model id from the `model` field of the request body, passes the whole body to `Azion.AI.run`, and returns the model response.

The Application and the Function take the name you enter, followed by a "(Build at …)" suffix. You write no code to reach a first response: the Function the template installs already serves an OpenAI-compatible endpoint.

---

## Prerequisites

This guide requires an Azion account with access to AI Inference. On the Hobby and Pro plans, access is available upon request, subject to approval. For the access each plan gives, refer to [AI Inference limits](/en/documentation/platform/ai-inference/limits/). The template creates every other entity the guide uses.

## Deploy the AI Inference Starter Kit template

:::caution
The template uses [Application Accelerator](/en/documentation/platform/applications/application-accelerator/), [Functions](/en/documentation/platform/functions/), and [AI Inference](/en/documentation/platform/ai-inference/). These products can generate usage-related costs. For the rates, refer to [Pricing](/en/documentation/fundamentals/pricing/#ai-inference).
:::

To create the Application that answers model requests:

<DocSteps>
  <DocStep title="Open Creation Center">

  Access [Azion Console](https://console.azion.com/) and select **+ Create**.

  </DocStep>
  <DocStep title="Select the AI Inference Starter Kit template">

  Under **Start from Template**, select **AI Inference Starter Kit**.

  </DocStep>
  <DocStep title="Name the Application">

  In **Application Name**, enter a name made of letters, numbers, and underscores. For example: `ai_inference_quickstart`. A hyphen is refused with "The use of accents and/or special characters is not allowed."

  </DocStep>
  <DocStep title="Select Deploy" />
</DocSteps>

A window shows the deployment logs while the deployment runs. When it finishes, the page shows the domain under **Visit site**, the **Add custom domain** option, the **Deployment logs**, and **Resources created**, which lists the Workload and the Application.

The Workload, the Application, and the Function exist, and the Function answers every request that reaches the domain.

---

## Open the workload domain

The domain under **Visit site** is the workload domain of the Workload, in the form `xxxxxxxxxx.map.azionedge.net`. It is the address a client sends a model request to.

To check that the domain answers, select **Visit site**.

:::note
The deployment takes several minutes to propagate to Azion's data centers. Until it propagates, the domain answers with Azion's placeholder `404`. Wait a few minutes, then select **Visit site** again.
:::

The page shows `{"error":"Request must be a POST request with JSON body"}`. That answer comes from the Function, which accepts only a `POST` request with a JSON body. Copy the domain: the model request goes to it.

---

## Send a request to the model

The Function answers on any path of the domain, and `/v1/chat/completions` is the path OpenAI clients use. The request body names the model in its `model` field and carries the conversation in `messages`. The `Content-Type` header must be exactly `application/json`.

To send a chat request to Qwen3 30B A3B Instruct 2507 FP8, replace `<your-application-domain>` with the domain you copied and run:

```bash
curl -X POST https://<your-application-domain>/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{
    "model": "Qwen/Qwen3-30B-A3B-Instruct-2507-FP8",
    "stream": false,
    "max_tokens": 1024,
    "temperature": 0.7,
    "top_p": 0.9,
    "messages": [
      { "role": "system", "content": "You are a helpful assistant." },
      { "role": "user", "content": "Name the European capitals." }
    ]
  }'
```

The model answers with one entry in `choices`, and the generated text sits at `choices[0].message.content`. The response below shortens that text:

```json
{
  "id": "chatcmpl-784835050db84a289185baceb0ccbc8e",
  "object": "chat.completion",
  "created": 1794444653,
  "model": "qwen-qwen3-30b-a3b-instruct-2507-fp8",
  "choices": [
    {
      "index": 0,
      "message": {
        "role": "assistant",
        "content": "There are 44 sovereign countries in Europe, each with its own capital city. Here is a list of all the European capitals:...",
        "refusal": null,
        "annotations": null,
        "audio": null,
        "function_call": null,
        "tool_calls": [],
        "reasoning": null,
        "reasoning_content": null
      },
      "logprobs": null,
      "finish_reason": "stop",
      "stop_reason": null,
      "token_ids": null
    }
  ],
  "service_tier": null,
  "system_fingerprint": null,
  "usage": {
    "prompt_tokens": 24,
    "total_tokens": 620,
    "completion_tokens": 596,
    "prompt_tokens_details": null
  },
  "prompt_logprobs": null,
  "prompt_token_ids": null,
  "kv_transfer_params": null
}
```

The `model` field carries the account's internal id for the model, `qwen-qwen3-30b-a3b-instruct-2507-fp8`, which differs from the id the request sent.

You have your first model response, served by your own Application.

If the account has no access to AI Inference, or the model id is wrong, the endpoint answers `400` with `{"error":"<model> not found or not allowed"}`. For every error the endpoint returns, refer to [Model invocation](/en/documentation/platform/ai-inference/model-invocation/#errors).

The template configures no authentication in front of the endpoint, so any client that reaches the domain can call a model. When you add authentication to your Application, include the header it requires, for example `-H "Authorization: Bearer [TOKEN VALUE]"`. For every field a request body accepts, refer to [Model invocation](/en/documentation/platform/ai-inference/model-invocation/).

## (Optional) Call another model

The Function reads the model id from the request, so calling another model changes only the `model` field of the body. The Function code needs no change. Model ids differ in form between models, so copy the id from the model's own page in [AI models](/en/documentation/platform/ai-inference/models/).

To send a chat request to Qwen2.5 VL AWQ 3B, run:

```bash
curl -X POST https://<your-application-domain>/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{
    "model": "qwen-qwen25-vl-3b-instruct-awq",
    "max_tokens": 16,
    "messages": [
      { "role": "user", "content": "Name one European capital." }
    ]
  }'
```

The response carries `"model": "qwen-qwen25-vl-3b-instruct-awq"`, and `choices[0].message.content` holds the answer of that model, such as `Paris, France is a European capital.`

The same Function answered both requests. Its code is in the **Code** tab of the Function, which the **Functions** item of the Console menu opens.
