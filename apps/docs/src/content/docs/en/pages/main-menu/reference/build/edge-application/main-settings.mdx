Main Settings is the set of values that apply to an [application](/en/documentation/platform/applications/) as a whole: its name, the Products enabled on it, whether it logs the rules each request runs, and whether it is active. Azion Console groups them in the **Main Settings** tab of the application, and the API returns them as fields of the application object. For the path a request takes through an application, refer to [How Applications works](/en/documentation/platform/applications/how-it-works/).

---

## Sections and fields

The **Main Settings** tab has four sections: **General**, **Modules**, **Debug Rules**, and **Status**. **General** holds the **Name** of the application. The tab carries **Cancel** and **Save**, and a change is saved with **Save**.

Each section maps to one or more fields of the application in the API. The last column holds the value each field takes when a create request sends only `name` and `active`.

| Section | Setting | API field | Type | Value at creation |
| --- | --- | --- | --- | --- |
| **General** | **Name** | `name` | string, 1 to 100 characters | The value the create request sends |
| **Modules** | One switch per Product | `modules.<product>.enabled` | boolean | `true` for `cache` and `functions`, `false` for `application_accelerator` and `image_processor` |
| **Debug Rules** | **Active** | `debug` | boolean | `false` |
| **Status** | **Active** | `active` | boolean | The value the create request sends, or `true` when the request omits it |

For example, an application you create through the API with only `name` and `active` has [Cache](/en/documentation/platform/applications/cache/) and [Functions](/en/documentation/platform/functions/) on from the start. [Application Accelerator](/en/documentation/platform/applications/application-accelerator/) stays off until you turn it on.

The **Active** switch in the **Status** section turns the application off and back on without deleting it. The API carries the same state in the `active` boolean.

## Products

The **Modules** section turns Products on or off for one application, and each application keeps its own set. Its **Default Modules** group holds one switch per Product: **Application Accelerator**, **Cache**, **Functions**, and **Image Processor**. A **Subscription modules** group carries a **Contact sales** action, and the section states that "Some modules require subscription."

| Product | Key in `modules` | CLI flag | What it covers on the application |
| --- | --- | --- | --- |
| Application Accelerator | `application_accelerator` | `--application-accelerator` | The behaviors marked `- Required Application Accelerator`, and the `${request_uri}` variable |
| Cache | `cache` | `--cache` | Caching of the content the application delivers |
| Functions | `functions` | `--function` on create, `--functions` on update | Function instances, run by a _Run Function_ behavior |
| [Image Processor](/en/documentation/platform/applications/image-processor/) | `image_processor` | `--image-processor` | The _Optimize Images_ behavior |

In Rules Engine, the Console marks a behavior that needs a Product with `- Required Application Accelerator`, `- Required Function`, or `- Required Image Processor`. A cache setting needs Application Accelerator for the variations of its **Application Accelerator** section and for a **Max Age** below 60 seconds. Cache settings are created in the **Cache Settings** tab and applied by a _Set Cache Policy_ behavior. Function instances are listed in the **Functions Instances** tab.

Cache is on when you create an application, and the Console notes that it is "Automatically enabled in all accounts." You can turn a Product on when your account supports it. You can turn it off when nothing on the application depends on it. Turning on a Product can generate usage-related costs. For more information, refer to [Pricing](/en/documentation/fundamentals/pricing/).

While Application Accelerator is off, the API refuses a request rule whose criterion reads `${request_uri}`. It also refuses a cache setting that varies the cache by method or by query string, or that sets a **Max Age** below 60 seconds. Each refusal carries one of the codes in Errors, and the same rule on `${uri}` is accepted. For the variables and behaviors each Product adds, refer to [Rules Engine for Applications](/en/documentation/platform/applications/rules-engine/).

Tiered Cache has no switch in the **Modules** section, because it is a switch inside each cache setting. For more information, refer to [Tiered Cache](/en/documentation/platform/applications/cache/tiered-cache/).

## Debug Rules

Debug Rules logs the Rules Engine rules that run on each request to the application. The setting is off when you create an application, and the API holds it in the `debug` boolean. In Azion Console, the **Active** switch of the **Debug Rules** section sets it. In [Azion CLI](/en/documentation/devtools/cli/), `--debug-enabled` sets it on `azion create application` and `azion update application`.

With Debug Rules on, the rules that ran on a request appear in the `$traceback` field of [Data Stream](/en/documentation/platform/data-stream/) and [Real-Time Events](/en/documentation/platform/real-time-events/). The Real-Time Events GraphQL API returns the same rules in the `stacktrace` field. A rule that is missing from that list did not run on the request.

For example, a _Set Cache Policy_ rule can seem to have no effect on a path. The `$traceback` of a request to that path then shows whether the rule ran at all. For the queries that read the field in each tool, refer to [Debug rules created with Rules Engine](/en/documentation/guides/application-development/getting-started/debug-rules/).

## Delivery and protocol settings

Main Settings carries no delivery or protocol settings. Domains, protocols, and certificates belong to the [workload](/en/documentation/platform/workloads/) that serves the application, and the **Deployment Settings** of the workload select the **Application** it runs.

In an account that has not migrated to API v4, the application itself holds its delivery protocols, ports, and TLS settings. For those settings, refer to [Main Settings | v3](/en/documentation/platform/applications/main-settings-v3/).

## API

The API serves applications at `https://api.azion.com/v4/workspace/applications`. Each call authenticates with a [personal token](/en/documentation/fundamentals/personal-tokens/) in the `Authorization: Token [TOKEN VALUE]` header, and a call with a body also sends `Content-Type: application/json`.

| Operation | Method and path |
| --- | --- |
| Create an application | `POST /workspace/applications` |
| List the applications of the account | `GET /workspace/applications` |
| Read one application | `GET /workspace/applications/<application-id>` |
| Replace an application | `PUT /workspace/applications/<application-id>` |
| Change part of an application | `PATCH /workspace/applications/<application-id>` |
| Delete an application | `DELETE /workspace/applications/<application-id>` |
| Clone an application | `POST /workspace/applications/<application-id>/clone` |

A create and a `PATCH` answer `202`, with `state` set to `pending`. A list and a read answer `200`.

`name` is the only field a create request requires. This call creates an application from a name and a status alone:

```bash
curl --request POST \
  --url https://api.azion.com/v4/workspace/applications \
  --header 'Accept: application/json' \
  --header 'Authorization: Token [TOKEN VALUE]' \
  --header 'Content-Type: application/json' \
  --data '{
  "name": "my-application",
  "active": true
}'
```

The API answers `202`. In this excerpt of the body, `modules` and `debug` carry the values the platform set at creation:

```text
{"state":"pending","data":{"id":<application-id>,"name":"my-application",…,"modules":{"cache":{"enabled":true},"functions":{"enabled":true},"application_accelerator":{"enabled":false},"image_processor":{"enabled":false}},"active":true,"debug":false,…}}
```

The `id` in `data` identifies the application in every later call, including the paths of its rules, such as `/workspace/applications/<application-id>/request_rules`.

This call turns on Application Accelerator on an existing application:

```bash
curl --request PATCH \
  --url https://api.azion.com/v4/workspace/applications/<application-id> \
  --header 'Accept: application/json' \
  --header 'Authorization: Token [TOKEN VALUE]' \
  --header 'Content-Type: application/json' \
  --data '{
  "modules": {
    "application_accelerator": {
      "enabled": true
    }
  }
}'
```

The API answers `202` with `state` set to `pending`. A body with `functions` in place of `application_accelerator` turns on Functions the same way, and its response repeats the `modules` object with all four keys.

## CLI

[Azion CLI](/en/documentation/devtools/cli/) reads and changes an application with six commands under the `application` noun. Each Product flag takes a string, such as `true`.

| Command | What it does | Flags |
| --- | --- | --- |
| `azion create application` | Creates an application | `--name`, `--active`, `--debug-enabled`, `--application-accelerator`, `--cache`, `--function`, `--image-processor`, `--file` |
| `azion update application` | Changes the application that `--application-id` names | `--application-id`, `--name`, `--active`, `--debug-enabled`, `--application-accelerator`, `--cache`, `--functions`, `--image-processor`, `--file` |
| `azion describe application` | Returns one application, with its `modules` object | `--application-id` |
| `azion list application` | Lists the applications of the account | `--details`, `--filter`, `--order-by`, `--page`, `--page-size` |
| `azion delete application` | Deletes the application that `--application-id` names | `--application-id`, `--cascade` |
| `azion clone application` | Copies an application under the name in `--name` | `--application-id`, `--name` |

The Functions flag is `--function` on `azion create application` and `--functions` on `azion update application`. On `azion delete application`, `--cascade` also deletes the resources that `azion deploy` created, and it defaults to `true`.

This command turns on Application Accelerator:

```bash
azion update application --application-id <application-id> --application-accelerator true
```

```text
Updated Application with ID <application-id>
```

The output of `azion describe application` includes the `modules` object of the application:

```bash
azion describe application --application-id <application-id>
```

On an application with all four Products on, the object reads:

```json
"modules": {
  "application_accelerator": { "enabled": true },
  "cache": { "enabled": true },
  "functions": { "enabled": true },
  "image_processor": { "enabled": true }
}
```

## Errors

A Product that is off on the application surfaces as a refusal of the object that needs it, with `400`. Each of these refusals names Application Accelerator. This body answers a request rule on `${request_uri}`:

```json
{
  "errors": [
    {
      "code": "25047",
      "title": "Missing Required Modules",
      "detail": " It requires any of the following modules to be enabled: ['application_accelerator'].",
      "status": "400",
      "source": { "pointer": "/data/criteria/0/0/variable" },
      "meta": {
        "message_prefix": "",
        "owner_modules": "any",
        "missing_required_modules": ["application_accelerator"]
      }
    }
  ]
}
```

`meta.missing_required_modules` lists the keys to turn on in the `modules` object of the application.

| Code | Title | Status | What causes it | What to do |
| --- | --- | --- | --- | --- |
| `25047` | Missing Required Modules | 400 | A request rule whose criteria read `${request_uri}`, on an application with Application Accelerator off | Turn on Application Accelerator, or match on `${uri}`, which the API accepts without it |
| `21013` | This Configuration Requires The Edge Application's Application Accelerator Module | 400 | A cache setting that varies the cache by method or by query string, on an application with Application Accelerator off. The pointer names the variation, such as `/data/modules/application_accelerator/cache_vary_by_method` | Turn on Application Accelerator, then save the cache setting again |
| `21021` | Edge Cache Max Age Lower Than The Minimum Allowed By Application's Application Accelerator Module | 400 | A cache setting whose `modules.cache.max_age` is below 60, on an application with Application Accelerator off. `meta.min_value` is `60` | Turn on Application Accelerator, or set **Max Age** to 60 seconds or more |
