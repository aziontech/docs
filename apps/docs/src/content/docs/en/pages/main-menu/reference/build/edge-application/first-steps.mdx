This guide instructs you through serving your origin's content from your first [Application](/en/documentation/platform/applications/).

- Create a [Connector](/en/documentation/platform/connectors/) that reaches your origin over HTTPS.
- Create an Application.
- Add a rule that sends every request to the Connector.
- Serve the Application from a [Workload](/en/documentation/platform/workloads/).
- Send a request to the workload domain and get your origin's answer.

Five parts make the chain, listed in the order this guide uses them:

1. The **Connector** holds the address of your origin and the way Azion connects to it.
2. The **Application** holds the rules that decide what happens to a request. A new Application has no rules.
3. The **rule** on the Application pairs a condition on the request, called a criterion, with an action called a behavior. In this guide, the criterion matches every request, and the _Set Connector_ behavior sends the request to the Connector.
4. The **Workload** holds a domain and receives the requests sent to it. Its **deployment**, a setting of the Workload, sets the Application that receives those requests.
5. The **request** goes to the workload domain, the hostname Azion assigns to the Workload. The rule of the Application matches the request, and the Connector routes it to your origin.

A Connector receives requests only once a rule sets it, and an Application only once a deployment sets it.

Each Application has four switches: [Cache](/en/documentation/platform/applications/cache/), [Functions](/en/documentation/platform/functions/), [Application Accelerator](/en/documentation/platform/applications/application-accelerator/), and [Image Processor](/en/documentation/platform/applications/image-processor/). In Azion Console, the switches are in **Main Settings** > **Modules**, and in the API, they are the keys of `modules`. A new Application starts with Cache and Functions turned on and the other two turned off, and this guide keeps all four as they are. The quickstarts of Cache, Application Accelerator, and Image Processor begin where this guide ends, with an Application that already serves content.

## Create a Connector to your origin

A Connector holds the address of your origin and the settings Azion uses to reach it. You create it on its own, outside any Application, and a rule sets it later. This Connector has one address and connects to your origin over HTTPS. It sends your origin's hostname in the `Host` header.

By default, a Connector sends the host the client requested, which here is your workload domain. An origin that routes by name may not answer that host. For more information, refer to [Host header](/en/documentation/platform/connectors/how-it-works/#host-header).

<Tabs client:visible sharedStore="interface">

<Fragment slot="panel.console">

### Console

To create the Connector in Azion Console:

<DocSteps>
  <DocStep title="Open the Connectors page">

  Access [Azion Console](https://console.azion.com/) > **Connectors**.

  </DocStep>
  <DocStep title="Start a new Connector">

  Select **+ Connectors**.

  </DocStep>
  <DocStep title="Name the Connector">

  In **General**, enter `origin-connector` as the **Name**.

  </DocStep>
  <DocStep title="Keep the HTTP type">

  In **Connector Type**, keep _HTTP_ selected.

  </DocStep>
  <DocStep title="Enter your origin's hostname as the address">

  Under **Address Management**, enter `<your-origin-hostname>` in **Address**, without a protocol or a port.

  </DocStep>
  <DocStep title="Send the same hostname in the Host header">

  In **Connection Options**, replace `${host}` in **Host** with `<your-origin-hostname>`, the same value as **Address**.

  </DocStep>
  <DocStep title="Connect to the origin over HTTPS only">

  In **Transport Protocol Policy**, select _Force HTTPS_.

  </DocStep>
  <DocStep title="Select Create" />
</DocSteps>

Azion Console shows the message "Connector successfully created". The Connector exists in your account, and the rule you add to the Application selects it. For every field of the Connector form, refer to [Connector settings](/en/documentation/platform/connectors/settings/).

</Fragment>

<Fragment slot="panel.cli">

### CLI

To create the Connector with the Azion CLI, put it in a JSON file first. Save this body as `connector.json`, and replace `<your-origin-hostname>` in both places:

<Code client:visible lang="json" code={`{
    "name": "origin-connector",
    "type": "http",
    "attributes": {
      "addresses": [
        { "address": "<your-origin-hostname>" }
      ],
      "connection_options": {
        "transport_policy": "force_https",
        "host": "<your-origin-hostname>"
      }
    }
}`} />

`addresses` lists the origin servers, and `connection_options.host` is the `Host` header the Connector sends. `force_https` makes every connection to the origin use HTTPS.

Create the Connector from the file:

<Code client:visible lang="bash" code={`azion create connector --type http --file connector.json`} />

The output carries the Connector's ID:

```text
Created Connector with ID <connector-id>
```

Record the ID: the rule passes it as `<connector-id>`.

</Fragment>

<Fragment slot="panel.api">

### API

To create the Connector with the API, send a `POST` request to the connectors endpoint. Replace `[TOKEN VALUE]` with your personal token, and `<your-origin-hostname>` with the hostname of your origin:

<Code client:visible lang="bash" code={`curl --request POST \\
    --url https://api.azion.com/v4/workspace/connectors \\
    --header 'Accept: application/json' \\
    --header 'Authorization: Token [TOKEN VALUE]' \\
    --header 'Content-Type: application/json' \\
    --data '{
    "name": "origin-connector",
    "type": "http",
    "attributes": {
      "addresses": [{ "address": "<your-origin-hostname>" }],
      "connection_options": {
        "transport_policy": "force_https",
        "host": "<your-origin-hostname>"
      }
    }
}'`} />

The response returns the Connector, with a value for every setting the request left out. This excerpt shows those values:

```json
{
  "state": "pending",
  "data": {
    "id": <connector-id>,
    "name": "origin-connector",
    "last_editor": "user@example.com",
    …
    "active": true,
    …
    "type": "http",
    "attributes": {
      "addresses": [
        {
          "active": true,
          "address": "<your-origin-hostname>",
          "http_port": 80,
          "https_port": 443,
          "modules": null
        }
      ],
      "connection_options": {
        "dns_resolution": "both",
        "transport_policy": "force_https",
        "http_version_policy": "http1_1",
        "host": "<your-origin-hostname>",
        "path_prefix": "",
        "following_redirect": false,
        "real_ip_header": "X-Real-IP",
        "real_port_header": "X-Real-PORT"
      },
      "modules": {
        "load_balancer": { "enabled": false, "config": null },
        "origin_shield": { "enabled": false, "config": null }
      }
    },
    …
  }
}
```

The Connector is active, and its address takes HTTPS connections on `https_port` `443`. [Load Balancer](/en/documentation/platform/connectors/load-balancer/) and [Origin Shield](/en/documentation/platform/connectors/origin-shield/) start turned off. Record the `id`: the rule passes it as `<connector-id>`.

</Fragment>

## Create the Application

An Application holds the rules that decide what happens to each request. It needs only a name, and every other setting keeps its default. The Application reaches your origin only through a rule that sets a Connector.

<DocSteps>
  <DocStep title="Open the Applications page">

  Access [Azion Console](https://console.azion.com/) > **Applications**.

  </DocStep>
  <DocStep title="Start a new Application">

  Select **+ Application**.

  </DocStep>
  <DocStep title="Name the Application">

  In **General**, enter `first-application` as the **Name**.

  </DocStep>
  <DocStep title="Select Create" />
</DocSteps>

The Application exists, and its **Rules Engine** tab holds no rules yet.

</Fragment>

<Fragment slot="panel.cli">

### CLI

To create the Application with the Azion CLI:

<Code client:visible lang="bash" code={`azion create application --name first-application --active true`} />

The output carries the Application's ID:


The Application is active and has no rules. Cache and Functions start turned on, and Application Accelerator and Image Processor start turned off. Record the ID: the rule and the deployment pass it as `<application-id>`.

## Send every request to the Connector

A rule in [Rules Engine for Applications](/en/documentation/platform/applications/rules-engine/) pairs criteria with behaviors. This rule runs in the Request Phase. Its criterion, `${uri}` starting with `/`, matches every request. Its behavior, _Set Connector_, sends each matching request to your Connector. For more information, refer to [Set Connector](/en/documentation/platform/applications/rules-engine/#set-connector).

The criterion uses `${uri}`, not `${request_uri}`. `${request_uri}` needs Application Accelerator turned on. On an Application with Application Accelerator turned off, the API refuses the rule with `400` and error `25047`, `Missing Required Modules`.

<Tabs client:visible sharedStore="interface">

<Fragment slot="panel.console">

### Console

To create the rule in Azion Console:

<DocSteps>
  <DocStep title="Open the Application">

  Access [Azion Console](https://console.azion.com/) > **Applications**, and select the Application you created.

  </DocStep>
  <DocStep title="Select the Rules Engine tab" />
  <DocStep title="Select + Rule" />
  <DocStep title="Name the rule">

  In **General**, enter `send-to-origin` as the **Name**.

  </DocStep>
  <DocStep title="Select the Request Phase">

  In **Phase**, select _Request Phase_. A rule's phase cannot change after you create the rule.

  </DocStep>
  <DocStep title="Set the criterion">

  Under **Criteria**, keep `${uri}` and _starts with_, and enter `/` as the argument.

  </DocStep>
  <DocStep title="Select the Set Connector behavior">

  Under **Behaviors**, select _Set Connector_.

  </DocStep>
  <DocStep title="Select your Connector">

  In the list of the _Set Connector_ behavior, select `origin-connector`.

  </DocStep>
  <DocStep title="Select Save" />
</DocSteps>

The rule appears in the **Rules Engine** tab, under the **Request** heading.

</Fragment>

<Fragment slot="panel.cli">

### CLI

To create the rule with the Azion CLI, keep the rule in a file: on a command line, the shell would expand `${uri}`. Save this body as `rule.json`, and replace `<connector-id>` with the ID of your Connector:

<Code client:visible lang="json" code={`{
    "name": "send-to-origin",
    "active": true,
    "criteria": [
      [
        {
          "variable": "\${uri}",
          "conditional": "if",
          "operator": "starts_with",
          "argument": "/"
        }
      ]
    ],
    "behaviors": [
      {
        "type": "set_connector",
        "attributes": { "value": <connector-id> }
      }
    ]
}`} />

Each group in `criteria` opens with a condition whose conditional is `if`.

Create the rule in the Request Phase of your Application. Replace `<application-id>` with the ID of your Application:

<Code client:visible lang="bash" code={`azion create rules-engine --application-id <application-id> --phase request --file rule.json`} />

The output carries the rule's ID:

```text
Created Rules Engine with ID <rule-id>
```

The rule is active on your Application, and it sends every request to your Connector.

</Fragment>

<Fragment slot="panel.api">

### API

To create the rule with the API, keep the request body in a file: on a command line, the shell would expand `${uri}`. Save this body as `rule.json`, and replace `<connector-id>` with the ID of your Connector:

<Code client:visible lang="json" code={`{
    "name": "send-to-origin",
    "active": true,
    "criteria": [
      [
        {
          "variable": "\${uri}",
          "conditional": "if",
          "operator": "starts_with",
          "argument": "/"
        }
      ]
    ],
    "behaviors": [
      {
        "type": "set_connector",
        "attributes": { "value": <connector-id> }
      }
    ]
}`} />

Each group in `criteria` opens with a condition whose conditional is `if`.

Send a `POST` request to the Request Phase rules of your Application. Replace `[TOKEN VALUE]` with your personal token, and `<application-id>` with the ID of your Application:

<Code client:visible lang="bash" code={`curl --request POST \\
    --url https://api.azion.com/v4/workspace/applications/<application-id>/request_rules \\
    --header 'Accept: application/json' \\
    --header 'Authorization: Token [TOKEN VALUE]' \\
    --header 'Content-Type: application/json' \\
    --data @rule.json`} />

The response carries the stored rule. This excerpt keeps its `id`, its criterion, its behavior, and its `order`:

```json
{
  "state": "pending",
  "data": {
    "id": <rule-id>,
    "name": "send-to-origin",
    "active": true,
    "criteria": [
      [
        {
          "conditional": "if",
          "variable": "${uri}",
          "operator": "starts_with",
          "argument": "/"
        }
      ]
    ],
    "behaviors": [
      {
        "type": "set_connector",
        "attributes": { "value": <connector-id> }
      }
    ],
    "description": "",
    "order": 0,
    …
  }
}
```

`order` is `0`, the position of the first rule on the Application. The rule is active, and it sends every request to your Connector.

## Serve the Application from a Workload

A Workload receives the requests sent to its domains. It holds those domains, the protocols, and the certificates, so you configure delivery on the Workload, not on the Application. The Workload's deployment sets the Application that receives those requests, and a Workload holds one deployment. A new Workload answers on a workload domain that Azion assigns under `map.azionedge.net`.

<Tabs client:visible sharedStore="interface">

<Fragment slot="panel.console">

### Console

To create the Workload and its deployment in Azion Console:

<DocSteps>
  <DocStep title="Open the Workloads page">

  Access [Azion Console](https://console.azion.com/) > **Workloads**.

  </DocStep>
  <DocStep title="Start a new Workload">

  Select **+ Workload**. The **Create Workload** page opens.

  </DocStep>
  <DocStep title="Name the Workload">

  Enter a name, such as `first-workload`.

  </DocStep>
  <DocStep title="Select your Application">

  Under **Deployment Settings**, set **Application** to the Application you created.

  </DocStep>
  <DocStep title="Leave Firewall and Custom Page empty" />
  <DocStep title="Select Save" />
</DocSteps>

The Workload exists, and its deployment sets your Application. To copy the address that the final request goes to, select **Copy Workload URL** in the message that Azion Console shows. The message closes after a few seconds, and the **Workload Domain** column of the Workloads list also shows the address.

</Fragment>

<Fragment slot="panel.cli">

### CLI

To create the Workload with the Azion CLI:

<Code client:visible lang="bash" code={`azion create workload --name first-workload --active true`} />

The output carries the Workload's ID:

```text
Created Workload with ID <workload-id>
```

To bind your Application, create the deployment of the Workload. Replace `<workload-id>` with the ID of the Workload and `<application-id>` with the ID of your Application:

<Code client:visible lang="bash" code={`azion create workload-deployment --workload-id <workload-id> --name first-deployment --application-id <application-id>`} />

The command prints the ID of the new deployment:

```text
Created Workload Deployment with ID <deployment-id>
```

To check the binding, list the deployments of the Workload with their details:

<Code client:visible lang="bash" code={`azion list workload-deployment --workload-id <workload-id> --details`} />

The `EDGE APPLICATION` column shows the ID of your Application:

```text
ID              CURRENT  EDGE APPLICATION  EDGE FIREWALL
<deployment-id> true     <application-id>  0
```

The deployment of the Workload sets your Application. A project that declares the Workload in `azion.config.js` gets its deployment from `azion deploy` instead, through the [`deployments`](/en/documentation/devtools/cli/azion-config-js/#workload-deployments) entry.

To find the workload domain, describe the Workload in JSON:

<Code client:visible lang="bash" code={`azion describe workload --workload-id <workload-id> --format json`} />

In the output, the `workload_domain` field holds the domain that the final request goes to:

```json
{
 …
 "id": <workload-id>,
 …
 "workload_domain": "<your-workload-domain>",
 …
}
```

</Fragment>

<Fragment slot="panel.api">

### API

To create the Workload with the API, send a `POST` request to the workloads endpoint. `infrastructure` set to `1` selects the production infrastructure, and `workload_domain_allow_access` set to `true` lets the Workload answer on its workload domain. Replace `[TOKEN VALUE]` with your personal token:

<Code client:visible lang="bash" code={`curl --request POST \\
    --url https://api.azion.com/v4/workspace/workloads \\
    --header 'Accept: application/json' \\
    --header 'Authorization: Token [TOKEN VALUE]' \\
    --header 'Content-Type: application/json' \\
    --data '{
    "name": "first-workload",
    "active": true,
    "infrastructure": 1,
    "workload_domain_allow_access": true
}'`} />

The response carries the starting settings of the Workload and the domain Azion assigned to it:

```json
{
  "state": "pending",
  "data": {
    "id": <workload-id>,
    "name": "first-workload",
    "active": true,
    …
    "infrastructure": 1,
    "tls": {
      "certificate": null,
      "ciphers": 7,
      "minimum_version": "tls_1_3"
    },
    "protocols": {
      "http": {
        "versions": ["http1", "http2", "http3"],
        "http_ports": [80],
        "https_ports": [443],
        "quic_ports": [443]
      }
    },
    …
    "domains": [],
    "workload_domain_allow_access": true,
    "workload_domain": "<your-workload-domain>",
    "product_version": "1.0"
  }
}
```

`domains` is empty, and `workload_domain` holds the domain that Azion assigned to the Workload. Record the `id` and the `workload_domain`.

To bind your Application to the Workload you created, run the command of the CLI panel that creates the deployment. You use the CLI here because the published Azion API v4 reference has no endpoint for the deployment of a Workload.

## Send a request through the Workload

This stage needs only `curl`, whichever interface you used to build the chain. In the command, replace `<your-workload-domain>` with the workload domain of the Workload you created.

A new Workload answers with your origin's response only after its first deployment reaches traffic. This can take several minutes, and Azion guarantees no duration. Until then, the workload domain answers `404` with a placeholder page. While the deployment spreads, answers to the same request can alternate between that `404` and your origin's response. Repeat the request until the answer comes from your origin. For more information, refer to [Propagation](/en/documentation/platform/applications/how-it-works/#propagation).

Send a request to the root path of your workload domain:

<Code client:visible lang="bash" code={`curl -i https://<your-workload-domain>/`} />

The response is the one your origin returns for `/`: its status, its headers, and its body. Every other path reaches your origin the same way, because the rule matches every URI that starts with `/`. Your Application now sends every request on the workload domain to your origin through the Connector.

When your origin refuses the TLS handshake, the response is a `502` with the page titled `Azion - Default error page`, not a page from your origin. For more information, refer to [Connection reuse and timeouts](/en/documentation/platform/connectors/how-it-works/#connection-reuse-and-timeouts).
