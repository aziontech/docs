**Real-Time Metrics** is a Platform Resource that shows the traffic of your Platform Resources as aggregated metrics, in [Azion Console](https://console.azion.com/) and through the [GraphQL API](/en/documentation/devtools/graphql/). A metric counts or sums many requests over a slice of time, so a chart of metrics shows a trend, not the requests behind it. Use Real-Time Metrics to measure requests and data transferred, see the bandwidth that cache saves, track status codes and threats, or compare two periods.

Real-Time Metrics groups its charts and controls on these pages:

- [Build dashboards](/en/documentation/platform/real-time-metrics/build-dashboards/) chart the requests, data, cache savings, status codes, and request times of your Applications, next to Tiered Cache, Function invocations, and Image Processor. Each chart names the field that returns its value through the API.
- [Secure dashboards](/en/documentation/platform/real-time-metrics/secure-dashboards/) count the threats that WAF identifies, the queries that Edge DNS answers, and the requests that Bot Manager classifies. They also show which IP addresses send the threats.
- [Observe dashboards](/en/documentation/platform/real-time-metrics/observe-dashboards/) chart the data that Data Stream sends to your endpoints, and the requests behind that data.
- [Filters and time range](/en/documentation/platform/real-time-metrics/filters-and-time-range/) sets the period and the filters that every chart of a dashboard follows. A chart's menu also copies the query that the chart sends, or exports its points as a CSV file.

## Request path

Real-Time Metrics has nothing to turn on and creates no entity in your account: it is active on every account. The Platform Resources that serve your traffic record each request, and Real-Time Metrics serves the totals of what they recorded, so a chart has data only after traffic arrives.

The diagram follows one request until it is part of a point on a chart. Solid arrows carry a request or a record, and dotted arrows carry the response. Each label starts with the number of its step in the list.

```mermaid
flowchart TD
  Client(["Client"])
  App["Application"]
  Agg["Aggregation"]
  RTM["Real-Time Metrics"]
  Reader(["Console chart, your query, or Grafana"])
  Client -->|"1. request"| App
  App -->|"2. event"| Agg
  Agg -->|"3. metric per time slice"| RTM
  Reader -->|"4. GraphQL query"| RTM
  RTM -.->|"5. rows"| Reader
```

1. A client sends a request, and the Platform Resource that handles it, such as an Application or WAF, records it as an event.
2. Azion adds the events of each time slice into metrics, such as a count of requests or a sum of bytes. This takes minutes, so the newest points of a chart can still rise.
3. Real-Time Metrics keeps the metrics in datasets, one dataset for each kind of traffic.
4. A Console chart, a query you write, and a Grafana dashboard each send a GraphQL query to the same API. To query the API from Grafana, refer to [Install the Azion plugin for Grafana](/en/documentation/guides/platform/observability/integrate-grafana/).
5. The API answers with the rows of the dataset, and a chart plots one point per row. Because all three read the same rows, a chart and your own query return the same numbers for the same range and filters.
