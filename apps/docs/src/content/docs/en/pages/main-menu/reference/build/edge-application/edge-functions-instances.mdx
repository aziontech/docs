A Function Instance is the entity that binds one [Function](/en/documentation/platform/functions/) to one [Application](/en/documentation/platform/applications/). The Function Instance carries the Args, the arguments passed into the context of the Function's execution in JSON format: `args` in the API, and the **Arguments** section in Azion Console. A Function Instance sets its name, its Args, its form schema, and whether it is active, and it leaves the code of the Function as it is.

A rule in [Rules Engine](/en/documentation/platform/applications/rules-engine/) invokes the Function Instance, not the Function. The same Function can be instantiated in more than one Application, and each Function Instance carries its own Args. A Function Instance runs only when a rule with _Run Function_ invokes it.

A [Firewall](/en/documentation/platform/firewall/) instantiates Functions the same way. A Function Instance on a Firewall runs its Function before the request reaches the Application, so the Function can stop the request there. A Function Instance on an Application runs its Function as part of serving the request. For the Function Instances of a Firewall, refer to [Function instances for Firewall](/en/documentation/platform/firewall/functions-instances/). For their bounds, refer to [Firewall limits](/en/documentation/platform/firewall/limits/#rules-and-function-instances).

## Function Instance fields

The [Azion API](https://api.azion.com/) creates a Function Instance under the Application it belongs to. These are the fields you set:

| Field | Type | Required | Description |
| --- | --- | --- | --- |
| `name` | string, 1 to 100 characters | Yes | Name of the Function Instance. |
| `function` | integer | Yes | ID of the Function the Function Instance binds, not of the Function Instance. |
| `args` | JSON object or array | No | Arguments passed into the context of the Function's execution. |
| `azion_form` | JSON object | No | A JSON Schema that renders the args as a form. |
| `active` | boolean | No | Whether the Function Instance is active. |

When the Function Instance sets no args, the `default_args` of the Function are used. When it sets no `azion_form`, an empty object is used.

The API returns four more fields:

- `id`, the ID of the Function Instance.
- `last_editor`, the email address of the account that last changed it.
- `last_modified`, the timestamp of that change.
- `created_at`, the timestamp of creation.

A `POST` request to the `functions` resource of an Application creates a Function Instance:

```bash
curl --request POST \
  --url https://api.azion.com/v4/workspace/applications/<application-id>/functions \
  --header 'Accept: application/json' \
  --header 'Authorization: Token [TOKEN VALUE]' \
  --header 'Content-Type: application/json' \
  --data '{
  "name": "My instance Name",
  "function": <function-id>,
  "active": true
}'
```

The API answers `202` with the created object:

```json
{
  "state": "pending",
  "data": {
    "id": <function-instance-id>,
    "name": "My instance Name",
    "args": {},
    "azion_form": {},
    "function": <function-id>,
    "active": true,
    "last_editor": "your-email@example.com",
    "last_modified": "2025-08-14T16:41:56.699896Z",
    "created_at": "2025-08-14T16:41:56.812345Z"
  }
}
```

The `"state": "pending"` value means the change takes a few minutes to propagate before it takes effect.

The API serves the Function Instances of an Application under `/workspace/applications/<application-id>/functions`. In the path of one Function Instance, `<function-instance-id>` is the ID of the Function Instance, not of the Function:

| Operation | Method and path |
| --- | --- |
| Create a Function Instance | `POST /workspace/applications/<application-id>/functions` |
| List the Function Instances of an Application | `GET /workspace/applications/<application-id>/functions` |
| Read one Function Instance | `GET /workspace/applications/<application-id>/functions/<function-instance-id>` |
| Replace a Function Instance | `PUT /workspace/applications/<application-id>/functions/<function-instance-id>` |
| Change part of a Function Instance | `PATCH /workspace/applications/<application-id>/functions/<function-instance-id>` |
| Delete a Function Instance | `DELETE /workspace/applications/<application-id>/functions/<function-instance-id>` |

[Instantiate a function on an application](/en/documentation/guides/application-development/getting-started/instantiate-functions/) shows how to create a Function Instance in Azion Console. In the `azion.config.js` file that [Azion CLI](/en/documentation/devtools/cli/) reads, a Function Instance carries `name`, `args`, and `active`, and `ref` names the Function by name or by ID.

## Args

Args are the arguments a Function Instance passes into the context of the Function's execution, written as a JSON object or array. The code reads a key at run time and the Function Instance decides its value, so one Function behaves differently in each place it is instantiated. A Function can define default Args of its own: the Args of a Function Instance override the keys they repeat, and every key the Function Instance leaves out keeps its default value.

An Args object that sets one key:

```json
{
  "value": "hello_world"
}
```

The Args object holds a maximum of 100 KB, and an object above that ceiling makes the Function fail at instantiation. For every Functions limit, refer to [Functions limits](/en/documentation/platform/functions/limits/).

Args are the configuration of one Function Instance. Sensitive values such as API keys, credentials, and access tokens belong in [environment variables](/en/documentation/platform/functions/environment-variables/) instead.

## Run Function behavior

_Run Function_ is the [Rules Engine](/en/documentation/platform/applications/rules-engine/#run-function) behavior that invokes a Function Instance. The rule holds the ID of the Function Instance, and the phase and the criteria of the rule decide when it runs. When a request meets those criteria, the Function runs on Azion's distributed infrastructure.

_Run Function_ is available in the Request Phase and in the Response Phase, and it requires [Functions](/en/documentation/platform/functions/) turned on in the Application. In the Response Phase, it runs only Functions written in Lua. In the Azion API, the behavior is `run_function`, and its `value` attribute holds the ID of the Function Instance.

For the execution phases, the criteria, and the order behaviors run in, refer to [How Functions works](/en/documentation/platform/functions/how-it-works/).

## CLI

Azion CLI manages Function Instances with five commands under the `function-instance` noun. Every command takes `--application-id`, and a command that acts on one Function Instance takes its ID in `--instance-id`.

| Command | What it does | Flags |
| --- | --- | --- |
| `azion create function-instance` | Creates a Function Instance | `--application-id`, `--function-id`, `--name`, `--args`, `--active`, `--file` |
| `azion list function-instance` | Lists the Function Instances of an Application | `--application-id`, `--details`, `--filter`, `--order-by`, `--page`, `--page-size` |
| `azion describe function-instance` | Returns one Function Instance | `--application-id`, `--instance-id` |
| `azion update function-instance` | Changes a Function Instance | `--application-id`, `--instance-id`, `--function-id`, `--name`, `--args`, `--active`, `--file` |
| `azion delete function-instance` | Deletes a Function Instance | `--application-id`, `--instance-id` |

`--function-id` sets the `function` field, and `--args` sets `args`. On `azion create function-instance` and `azion update function-instance`, `--active` defaults to `true`.
