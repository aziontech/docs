Rules Engine for Firewall is the Feature of [Firewall](/en/documentation/platform/firewall/) that holds the rules a Firewall applies to each request before the [Application](/en/documentation/platform/applications/) receives it. A rule pairs criteria, which decide whether a request matches, with behaviors, which the rule applies to each request that matches. A rule that chooses how an Application serves an allowed request belongs to [Rules Engine for Applications](/en/documentation/platform/applications/rules-engine/).

---

## Rule fields

Each Firewall holds its own list of rules, which Azion Console shows in the Firewall's **Rules Engine** tab and the API serves under `/v4/workspace/firewalls/<firewall-id>/request_rules`. In the Console, **Rule** opens the **Create Rule** drawer, and each table on this page names the Console label beside the API value. A rule carries 10 fields: five that a request sets, and five that the platform sets and returns.

| Field | Type | Required | Default | Description |
| --- | --- | --- | --- | --- |
| `id` | integer | Read-only | — | The identifier every later call on the rule uses. The rule list does not show it, and `azion list firewall-rule` prints it as `ID` |
| `name` | string, 1 to 100 characters | Yes | — | The rule name, unique on the Firewall. The Console renders it as the **Name** field and asks for a unique, descriptive name |
| `description` | string, up to 1,000 characters | No | `""` | A comment on the rule, shown in the **Description** column of the rule list. Past 1,000 characters, the Console shows `Description should not exceed 1000 characters` |
| `active` | boolean | No | `true` | Whether the rule is active. The Console renders it as the **Active** switch in the **Status** section, and the rule list shows _Active_ or _Inactive_ |
| `criteria` | array of 1 to 5 blocks, each an array of 1 to 10 criteria | Yes | — | The conditions a request must meet. Each value is listed in Criteria |
| `behaviors` | array of 1 to 10 behavior objects | Yes | — | What the rule does to a request that matches. Each value is listed in Behaviors |
| `order` | integer | Read-only | Assigned at create | The rule's position in the Firewall's list of rules |
| `last_editor` | string | Read-only | — | The account that last changed the rule, shown in the **Last Editor** column |
| `last_modified` | date-time | Read-only | — | When the rule last changed, shown in the **Last Modified** column |
| `created_at` | date-time | Read-only | — | When the rule was created |

The platform assigns `order` in creation order: the first rule on a Firewall carries `0`, and the eleventh carries `10`. The Console numbers the same positions from `1`, so the rule whose `order` is `0` is the one its list shows as `1`. To change the order, reorder the rules in the Console rule list, or send the IDs of every rule in the new order through the API or the CLI.

## Criteria

Criteria decide which requests a rule acts on. Each criterion names a variable, a comparison operator, and, for most operators, an argument to compare the variable with. The **Create Rule** drawer opens with one criterion already set to _Request Uri_ and _starts with_, and `${request_uri}` `starts_with` `/` matches every request the Workload receives.

The table lists the variables in Console order. Nine of them require [Web Application Firewall (WAF)](/en/documentation/platform/firewall/waf/) on the Firewall, and `Network` requires [Network Shield](/en/documentation/platform/firewall/network-shield/). The other five work once any one of WAF, Network Shield, or [Functions](/en/documentation/platform/functions/) is on: with all three off, the API refuses every rule with `25047`, whatever its criteria.

| Variable | API variable | Requires | What it holds | Example |
| --- | --- | --- | --- | --- |
| Header Accept | `${header_accept}` | WAF | The media types the client accepts in the response | `application/json` |
| Header Accept Encoding | `${header_accept_encoding}` | WAF | The content encodings, usually compression algorithms, the client accepts in the response | `gzip` |
| Header Accept Language | `${header_accept_language}` | WAF | The language the client expects | `en-US` |
| Header Cookie | `${header_cookie}` | WAF | The cookies the client sends with the request | `session_id=abc123` |
| Header Origin | `${header_origin}` | WAF | The origin of a cross-site request or a preflight request: a URI naming the server, with no path | `https://example.com` |
| Header Referer | `${header_referer}` | WAF | The address of the document, or of the element in it, from which the request URI was obtained | `https://example.com/landing-page` |
| Header User Agent | `${header_user_agent}` | WAF | The string that identifies the client application, operating system, vendor, or version | `Mozilla/5.0` |
| Host | `${host}` | Any of WAF, Network Shield, Functions | In order of precedence: the hostname in the request line, the value of the `Host` header, or the name of the server that serves the request | `api.example.com` |
| Network | `${network}` | Network Shield | The client IP address, compared with the IP addresses and CIDR ranges, ASNs, or countries of a Network List | `2` |
| Request Args | `${request_args}` | WAF | The arguments in the query string of the request | `page=1` |
| Request Method | `${request_method}` | WAF | The HTTP method of the request | `POST` |
| Request Uri | `${request_uri}` | Any of WAF, Network Shield, Functions | The URI of the request, without its query string | `/api/v1/` |
| Scheme | `${scheme}` | Any of WAF, Network Shield, Functions | The scheme of the request, HTTP or HTTPS | `https` |
| Ssl Verification Status | `${ssl_verification_status}` | Any of WAF, Network Shield, Functions | The result of the client certificate verification, as one of three fixed values | `CERTIFICATE_VERIFICATION_ERROR` |
| Client Certificate Validation | `${client_certificate_validation}` | Any of WAF, Network Shield, Functions | Whether the client certificate passed verification | `true` |

When the Firewall lacks the nested resource a variable requires, the Console still lists the variable but does not let you select it. The label then carries a suffix, such as _Header Accept - required WAF_ or _Network - required Network Shield_. The API refuses such a rule with `400` and code `25047`, and the `detail` names the variable and the module it needs.

`Network` compares the client IP address with a [Network List](/en/documentation/platform/firewall/network-shield/network-lists/). In the Console, the argument becomes the **Select a Network** list, which shows every Network List in the account and closes with **Create Network List**. In the API, the argument is the list ID as a JSON integer, and the same ID sent as a string is refused with `400` and code `25042`. For example, `2` is the Tor exit node list Azion provides, and any rule can use it.

Once a rule on the Firewall uses `${network}`, Network Shield cannot be turned off on that Firewall. The API answers `400` with code `24005` and names the rules that use it.

`Request Args` holds nothing when the request has no query string, and an empty variable does not match. For example, a rule on `${request_args}` `matches` `.*` skips every POST that carries its payload in the body and none in the query string.

`Ssl Verification Status` takes one of three values, which the Console offers in the **Select an SSL status** list:

| Value | API argument | Meaning |
| --- | --- | --- |
| _Success_ | `SUCCESS` | The client certificate passed validation |
| _Certificate Verification Error_ | `CERTIFICATE_VERIFICATION_ERROR` | The client certificate was not valid |
| _Missing Client Certificate_ | `MISSING_CLIENT_CERTIFICATE` | The request carried no client certificate |

`Client Certificate Validation` takes one value, `true`, which the Console offers as the single entry _Valid_ in the **Select a validation result** list. The operator _is equal_ matches a request whose client certificate passed validation, and _is not equal_ matches one that carried no certificate or one that was not valid. The API refuses any other argument for either variable with `25046`.

### Operators

A criterion compares its variable with its argument through an operator. The Console labels each operator in lowercase, and the API sends the value in the second column as `operator`.

| Operator | API value | The criterion matches when | Argument |
| --- | --- | --- | --- |
| is equal | `is_equal` | The value equals the argument, compared character by character | String |
| is not equal | `is_not_equal` | The value is not exactly the argument | String |
| starts with | `starts_with` | The value starts with the argument | String |
| does not start with | `does_not_start_with` | The value does not start with the argument | String |
| matches | `matches` | The value matches the regular expression in the argument | Regular expression |
| does not match | `does_not_match` | The value does not match the regular expression in the argument | Regular expression |
| exists | `exists` | The variable has a value. `Request Args` exists when the query string carries an argument | None |
| does not exist | `does_not_exist` | The variable has no value. `Request Args` does not exist when the query string carries no argument | None |

The Console hides the argument field for _exists_ and _does not exist_, and replaces it with a list for `Network`, `Ssl Verification Status`, and `Client Certificate Validation`, which accept only a value from their own list. The API refuses an argument on _exists_ or _does not exist_ with `25040`, and a missing argument on any other operator with `25041`.

`Network` is the exception to the table. Its _matches_ and _does not match_ carry the API values `is_in_list` and `is_not_in_list`, and both compare the client IP address with the Network List the argument names. The API refuses `matches` on `${network}` with `400` and code `25039`.

Each variable offers only some of the operators, and the API refuses any other pairing with `25039`:

| Variable | Operators |
| --- | --- |
| Header Accept, Header Accept Encoding, Header Accept Language, Header Cookie, Header Origin, Header Referer, Header User Agent | matches, does not match |
| Host | is equal, is not equal, matches, does not match |
| Network | matches (`is_in_list`), does not match (`is_not_in_list`) |
| Request Args | is equal, is not equal, matches, does not match, exists, does not exist |
| Request Method | is equal, is not equal |
| Request Uri | is equal, is not equal, starts with, does not start with, matches, does not match |
| Scheme, Ssl Verification Status, Client Certificate Validation | is equal, is not equal |

### Conditionals

Criteria combine inside blocks, and a rule holds from 1 to 5 blocks of 1 to 10 criteria each. Inside a block, the first criterion carries the conditional `if`, and each later criterion carries `and` or `or`. Blocks are joined by And, which the Console prints between them, so a request matches the rule only when it matches every block. The API refuses a first criterion that carries `and` or `or` with `25043`.

In the Console, **And** and **Or** add a criterion to a block, and **Add Criteria** adds a block. The Console disables **And** and **Or** at 10 criteria in a block, and **Add Criteria** at 5 blocks. The dividers between criteria show the conditional as If, And, or Or.

In the API, `criteria` is a list of blocks, and each block is a list of criterion objects. The rule in this example holds one block of two criteria. It denies a request only when the client IP address is in the Network List and the URI starts with `/ip-deny`:

```json
{
  "name": "ip-deny",
  "active": true,
  "criteria": [
    [
      { "variable": "${network}", "conditional": "if", "operator": "is_in_list", "argument": <network-list-id> },
      { "variable": "${request_uri}", "conditional": "and", "operator": "starts_with", "argument": "/ip-deny" }
    ]
  ],
  "behaviors": [{ "type": "deny" }]
}
```

The `<network-list-id>` placeholder stands for an integer with no quotes around it.

## Behaviors

Behaviors are what a rule does to a request that matches its criteria. The Console labels the first behavior row **Then** and each later row **And**, and **Add Behavior** adds a row. In the API, each behavior is an object with a `type`, and the behaviors that take settings carry them in `attributes`.

The Requires column names what the Firewall must have on for the behavior. When WAF or Functions is off, the Console shows _Set WAF - required WAF_ or _Run Function - required Functions_ and does not let you select it. The API accepts _Set WAF_ once any one of WAF, Network Shield, or Functions is on.

| Behavior | API `type` | Requires | Attributes | What the client receives |
| --- | --- | --- | --- | --- |
| Deny (403 Forbidden) | `deny` | Any of WAF, Network Shield, Functions | None | `403`, with Azion's default error page headed Forbidden |
| Drop (Close Without Response) | `drop` | Any of WAF, Network Shield, Functions | None | No response: no status line and no body |
| Set Rate Limit | `set_rate_limit` | Any of WAF, Network Shield, Functions | `type`, `limit_by`, `average_rate_limit`, `maximum_burst_size` | `429` for a request the limit does not admit, with the default error page headed Too Many Requests |
| Set WAF | `set_waf` | WAF in the Console; any of WAF, Network Shield, Functions in the API | `waf_id`, `mode` | `400` for a request the rule set blocks in `blocking` mode, with the default error page headed Bad Request |
| Run Function | `run_function` | Functions | `value` | Whatever the code of the Function Instance does with the request |
| Set Custom Response | `set_custom_response` | Any of WAF, Network Shield, Functions | `status_code`, `content_type`, `content_body` | The status code, `Content-Type`, and body the attributes set |

Only _Run Function_ and _Set WAF_ can be followed by another behavior, and each appears at most once in a rule. In the Console, choosing _Deny (403 Forbidden)_, _Drop (Close Without Response)_, _Set Rate Limit_, or _Set Custom Response_ removes every behavior row after it. The API refuses a behavior after _Deny_ or _Drop_ with `25010`, a repeated behavior with `25011`, and _Deny_ followed by _Drop_ with `25012`.

### Deny (403 Forbidden)

_Deny (403 Forbidden)_ refuses the request with `403` and takes no attributes. The body is Azion's default error page headed Forbidden, about 10 KB of HTML, which shows the client IP address and the request ID. No response header names the Firewall or the rule. In the API, the behavior is `{ "type": "deny" }`.

### Drop (Close Without Response)

_Drop (Close Without Response)_ closes the request without answering it and takes no attributes. The client receives no status line and no body, immediately. A script that reads the status code sees `000`, and a browser shows a connection error. In the API, the behavior is `{ "type": "drop" }`.

Over HTTP/2, curl reports the reset stream and exits with code 92:

```text
curl: (92) HTTP/2 stream 1 was not closed cleanly: PROTOCOL_ERROR (err 1)
```

Over HTTP/1.1 and plain HTTP, curl exits with code 52:

```text
curl: (52) Empty reply from server
```

### Set Rate Limit

_Set Rate Limit_ caps the rate of the requests the rule matches. A request the rate and the burst do not admit receives `429`, with the default error page headed Too Many Requests. With a per-second limit, the `429` response carries `retry-after: 1` and no `x-ratelimit-` header.

| Attribute | Console field | Values | Description |
| --- | --- | --- | --- |
| `type` | **Rate Limit Type** | `second` (_Req/s_) or `minute` (_Req/min_) | The period the rate counts over. Defaults to `second` |
| `limit_by` | **Limit By** | `client_ip` (_Client IP address_) or `global` (_Global_) | Whether the rate counts per client IP address or across all requests. Required. The Console preselects _Client IP address_ |
| `average_rate_limit` | **Average Rate Limit** | Integer, at least 1 | The requests allowed per second or per minute, as `type` sets. Required. The Console accepts up to 31,536,000 |
| `maximum_burst_size` | **Maximum Burst Size** | Integer, at least 1 | The extra requests tolerated in a short peak. Required when `type` is `second`, and refused with `25034` when it is `minute`. The Console hides the field for _Req/min_ |

A rate limit of 10 requests per second per client IP address, with a burst of 10:

```json
{
  "type": "set_rate_limit",
  "attributes": { "type": "second", "limit_by": "client_ip", "average_rate_limit": 10, "maximum_burst_size": 10 }
}
```

For how the rate and the burst admit requests, refer to [How Firewall works](/en/documentation/platform/firewall/how-it-works/).

### Set WAF

_Set WAF_ applies a WAF [rule set](/en/documentation/platform/firewall/waf/rules-set/) to the requests the rule matches. A rule set runs only when a rule carries this behavior, and a rule carries at most one. Rule sets live in Azion Console under **WAF Rules**.

:::note
Each Firewall resolves its own _Set WAF_ behaviors: a rule set applied on one Firewall does not change which rule set another Firewall applies. Inside one Firewall, when two rules that match a request carry _Set WAF_, the later rule's rule set and mode applied in tests, with the same or different criteria. Refer to [How Set WAF resolves across firewalls](/en/documentation/platform/firewall/waf/scoring-and-modes/#how-set-waf-resolves-across-firewalls).
:::

| Attribute | Console control | Values | Description |
| --- | --- | --- | --- |
| `waf_id` | **Select a WAF** | Integer | The ID of the rule set to apply. Required |
| `mode` | **Select a WAF mode** | `logging` (_Logging_) or `blocking` (_Blocking_) | Whether WAF refuses the requests the rule set flags. Required |

In `blocking` mode, a request the rule set blocks receives `400` with the default error page headed Bad Request, and no response header names WAF. In `logging` mode, WAF does not refuse the request. The API refuses a `set_waf` behavior with no `mode`, and any `mode` other than `logging` or `blocking`, including `learning`.

A behavior that applies a rule set in `blocking` mode:

```json
{ "type": "set_waf", "attributes": { "waf_id": <waf-rule-set-id>, "mode": "blocking" } }
```

### Run Function

_Run Function_ runs a [Function Instance](/en/documentation/platform/firewall/functions-instances/) of the Firewall on the requests the rule matches, and requires Functions on the Firewall. A Firewall created through the API, the CLI, or the Console create page has Functions on, and the Console create drawer starts it off.

The attribute `value` holds the ID of the Function Instance, not of the Function. Instances live in the Firewall's **Functions Instances** tab. In the Console, **Select a Function** lists the instances of this Firewall, and **Create Function Instance** creates one from that list.

A behavior that runs one Function Instance:

```json
{ "type": "run_function", "attributes": { "value": <function-instance-id> } }
```

To create an instance, refer to [Instantiate a function on a firewall](/en/documentation/guides/application-security/firewall-and-waf/instantiate-functions/). For the code a Firewall Function runs, refer to [Functions for Firewall](/en/documentation/platform/firewall/functions/).

### Set Custom Response

_Set Custom Response_ answers the request with the status code, content type, and body it sets. The three settings go in `attributes`, as with every behavior that takes settings.

| Attribute | Console field | Values | Description |
| --- | --- | --- | --- |
| `status_code` | **Status Code** | Integer, 200 to 499 | The status code of the response. Required |
| `content_type` | **Content Type** | String, up to 255 characters | The value of the `Content-Type` header. Defaults to an empty string |
| `content_body` | **Content Body** | String, up to 500 characters | The body of the response. Defaults to an empty string |

## API

Every rule operation is authenticated and sits under `https://api.azion.com/v4/workspace/firewalls/<firewall-id>/request_rules`. A request carries a personal token in the `Authorization` header under the `Token` scheme, and a request with a body also carries `Content-Type: application/json`.

| Operation | Method and path |
| --- | --- |
| Create a rule | `POST /request_rules` |
| List the rules of a Firewall | `GET /request_rules` |
| Retrieve a rule | `GET /request_rules/{request_rule_id}` |
| Update a rule | `PUT /request_rules/{request_rule_id}` |
| Update part of a rule | `PATCH /request_rules/{request_rule_id}` |
| Delete a rule | `DELETE /request_rules/{request_rule_id}` |
| Reorder the rules of a Firewall | `PUT /request_rules/order` |

A create, an update with `PUT` or `PATCH`, a reorder, and a delete answer `202`, and a read answers `200`. A reorder sends `order`, the IDs of every rule of the Firewall in the new order, and answers with the reordered list. A list that leaves out a rule is refused with `25002`.

This call creates a rule that denies every request whose URI starts with `/deny-test`:

```bash
curl --request POST \
  --url https://api.azion.com/v4/workspace/firewalls/<firewall-id>/request_rules \
  --header 'Accept: application/json' \
  --header 'Authorization: Token [TOKEN VALUE]' \
  --header 'Content-Type: application/json' \
  --data '{
  "name": "deny-test",
  "active": true,
  "criteria": [[{ "variable": "${request_uri}", "conditional": "if", "operator": "starts_with", "argument": "/deny-test" }]],
  "behaviors": [{ "type": "deny" }]
}'
```

The response carries `202` and a `state` of `pending`. The response excerpt keeps the fields the platform added:

```text
{"state":"pending","data":{"id":<rule-id>,…,"behaviors":[{"type":"deny"}],"description":"","order":0}}
```

The platform adds `description`, an empty string when the create sends none, and `order`, the rule's position on the Firewall. The `id` in `data` is the handle every later call on the rule uses.

A `PUT` or a `PATCH` on `/request_rules/{request_rule_id}` also answers with a `state` of `pending`. The response carries the whole rule in `data`: the 10 fields that Rule fields lists, with the new values. A `GET` of the rule sent right after the update returns the new values too, with no `state` key. To check that a change to a rule reaches traffic, refer to [Propagation](/en/documentation/platform/firewall/how-it-works/#propagation).

## CLI

Azion CLI manages rules with the `firewall-rule` and `firewall-rule-order` commands. A rule's criteria and behaviors go in the same JSON body the API takes, which `create` and `update` read from `--file`.

| Command | What it does |
| --- | --- |
| `azion create firewall-rule` | Creates a rule from a JSON file, with `--firewall-id` and `--file` |
| `azion list firewall-rule` | Lists the rules of a Firewall, with `--firewall-id`. `--details` adds the `LAST EDITOR` and `LAST MODIFIED` columns |
| `azion describe firewall-rule` | Returns one rule, with `--firewall-id` and `--rule-id`. `--format json` prints the full record |
| `azion update firewall-rule` | Updates a rule from a JSON file, with `--firewall-id`, `--rule-id`, and `--file` |
| `azion delete firewall-rule` | Deletes a rule, with `--firewall-id` and `--rule-id` |
| `azion update firewall-rule-order` | Reorders the rules of a Firewall, with `--firewall-id` and `--rule-ids`, the comma-separated IDs of the rules in the new order |

This file describes a rule that denies requests from the countries in a Network List on `/cli-rule`:

```json
{
  "name": "cli-rule",
  "description": "Deny requests from countries in the list on /cli-rule.",
  "active": true,
  "criteria": [
    [
      { "variable": "${network}", "conditional": "if", "operator": "is_in_list", "argument": <network-list-id> },
      { "variable": "${request_uri}", "conditional": "and", "operator": "starts_with", "argument": "/cli-rule" }
    ]
  ],
  "behaviors": [
    { "type": "deny" }
  ]
}
```

Save it as `rule.json`, replace `<network-list-id>` with the list ID as an integer, and create the rule:

```bash
azion create firewall-rule --firewall-id <firewall-id> --file rule.json
```

```text
Created Firewall Rule with ID <rule-id>
```

## Errors

Every rejected rule, reorder, or Firewall update on this page answers `400` with an `errors` array. Each entry carries a `code`, a `title`, a `detail`, the `status`, and a `source` pointer naming the field, and some entries add a `meta` object:

```json
{
  "errors": [
    {
      "code": "25047",
      "title": "Missing Required Modules",
      "detail": "variable \"${network}\" is not available for this Edge Firewall. It requires ANY of the following modules to be enabled: ['network_protection_enabled'].",
      "status": "400",
      "source": { "pointer": "/data/criteria" },
      "meta": {
        "message_prefix": "variable \"${network}\" is not available for this Edge Firewall.",
        "owner_modules": "ANY",
        "missing_required_modules": ["network_protection_enabled"]
      }
    }
  ]
}
```

| Code | Title | Message | Cause | Fix |
| --- | --- | --- | --- | --- |
| `10018` | Blank Field | `This field may not be blank.` | `name` is an empty string. | Send a name. |
| `10039` | Invalid Choice | `"<value>" is not a valid choice.` | An enum field holds a value outside its list, such as the variable `$(network)`, the operator `does_not_starts_with`, a `conditional` other than `if`, `and`, or `or`, a `mode` of `learning`, or a rate limit `type` of `hour`. | Send a listed value. The `source` pointer names the field, such as `/data/criteria/0/0/conditional`. |
| `10046` | Max Length | `Ensure this field has no more than 100 characters.` | A string is longer than its maximum: 100 for `name`, 1,000 for `description`, 255 for `content_type`, and 500 for `content_body`. | Shorten the value. |
| `10049` | Min Length List Field | `Ensure this field has at least 1 elements.` | `criteria` or `behaviors` is an empty list. | Send at least one block and one behavior. |
| `10050` | Min Value | `Ensure this value is greater than or equal to 1.` | `average_rate_limit` or `maximum_burst_size` is below 1, or `status_code` is below 200. | Send a value inside the attribute's range. |
| `10059` | Required Field | `This field is required.` | A required field is absent, such as `limit_by`, the `mode` of a `set_waf` behavior, or `status_code`. | Add the field the `source` pointer names. |
| `10065` | List Field Max Length | `Ensure this field has no more than 5 elements.` | More than 5 blocks, more than 10 criteria in a block, or more than 10 behaviors. | Split the conditions across rules. |
| `10068` | Max Value | `Ensure this value is less than or equal to 499.` | `status_code` is above 499. | Send a status code from 200 to 499. |
| `24005` | Cannot Disable Firewall Network Protection Module | `Cannot disable firewall network protection module, because it is being referenced by the following rules: <rule-id>. Delete those rules or remove their network criteria, then disable the module.` | Turning Network Shield off on a Firewall whose rules use `${network}`. | Change or delete the rules the message lists, then turn Network Shield off. |
| `25002` | Missing Rules In Order | `When ordering you should provide the order for all rules.` | A reorder leaves out a rule of the Firewall. | Send the IDs of every rule. |
| `25010` | Behavior Marked As Final | `The behavior 'deny' is marked as final. No subsequent behaviors can be configured after a final behavior.` | A behavior follows _Deny_ or _Drop_. | Put the final behavior last, or move the other behavior to another rule. |
| `25011` | Duplicated Behavior | `The behavior 'deny' is duplicated.` | The same behavior appears twice in a rule. A repeated _Set WAF_ is named `set_waf_ruleset_and_waf_mode`. | Keep one of each behavior. |
| `25012` | Incompatible Behavior | `The behavior 'deny' is incompatible with the following behaviors: ['drop'].` | _Deny_ followed by _Drop_ in the same rule. | Keep one of the two. |
| `25030` | Entity Not Found | `Network List '<network-list-id>' not found.` | A `${network}` argument names a Network List that does not exist, or a `run_function` `value` names a Function Instance that does not exist, with the message `Function Instance '<id>' not found.` | Send the ID of an existing Network List or Function Instance. |
| `25031` | Entity Not Active | `Network List '<network-list-id>' is not active.` | A `${network}` argument names an inactive Network List. | Activate the list, then create the rule. |
| `25034` | Invalid Rate Limit Parameter | `'maximum_burst_size' cannot be used when rate limit type is 'minute'.` | A per-minute rate limit carries `maximum_burst_size`. | Remove `maximum_burst_size`. |
| `25035` | Required Rate Limit Parameter | `'maximum_burst_size' is required when rate limit type is 'second'.` | A per-second rate limit, including one with no `type`, lacks `maximum_burst_size`. | Add `maximum_burst_size`. |
| `25036` | Invalid Informed WAF | `The informed WAF (<waf-id>) is not valid.` | A `waf_id` names no rule set. `meta.waf_id` repeats the value. | Send the ID of an existing rule set. |
| `25039` | Invalid Operator | `The operator 'matches' is not valid for the '${network}' variable.` | An operator the variable does not offer, such as `matches` on `${network}` or `starts_with` on `${host}`. | Send an operator from the variable's row in Operators. |
| `25040` | Operator Does Not Require An Argument | `The operator 'exists' does not require an argument.` | `exists` or `does_not_exist` carries an argument. | Remove `argument`. |
| `25041` | Operator Requires An Argument | `The operator 'is_equal' requires an argument.` | Any other operator has no argument. | Add `argument`. |
| `25042` | Invalid Operator Argument Type | `The argument type '<network-list-id>' is not valid for the operator 'is_in_list'.` | A `${network}` argument sent as a string, such as `"57102"`, the type the v4 API specification gives it. | Send the Network List ID as a JSON integer. |
| `25043` | Invalid Conditional For First Criterion | `The conditional 'and' is invalid for the first criterion.` | The first criterion of a block carries `and` or `or`. | Send `if` on the first criterion. |
| `25046` | Invalid Argument Choice | `The argument 'FOO' is not a valid choice for the criterion.` | An argument outside the list of `${ssl_verification_status}` or `${client_certificate_validation}`. | Send a value from the variable's list. |
| `25047` | Missing Required Modules | `variable "${network}" is not available for this Edge Firewall. It requires ANY of the following modules to be enabled: ['network_protection_enabled'].` | A variable or behavior whose nested resource is off. With WAF, Network Shield, and Functions all off, every rule fails, and the behavior entry reads `It requires any of the following modules to be enabled: ['waf_enabled', 'network_protection_enabled', 'edge_functions_enabled'].` | Turn on what the message names: `waf_enabled` is WAF, `network_protection_enabled` is Network Shield, and `edge_functions_enabled` is Functions. |
| `25048` | Firewall Rule Name Already In Use | `Firewall already have a rule with this name.` | Another rule on the Firewall carries the same `name`. | Send another name. |

The Azion CLI prints the API message inside its own error. For `25030` on a _Run Function_ behavior, the last line reads:

```text
Error: failed to create the Firewall Rule: ["Function Instance '<function-instance-id>' not found."]
```

A behavior written with `name` instead of `type` fails in the CLI with `Error: Failed to decode the given 'json' file. Verify if the file format is JSON or fix its content according to the JSON format specification at https://www.json.org/json-en.html`, although the file is valid JSON. Write each behavior with `type`.
