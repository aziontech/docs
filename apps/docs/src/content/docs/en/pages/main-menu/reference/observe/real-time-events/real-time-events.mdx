**Real-Time Events** is a Platform Resource that serves your event records from Azion's distributed infrastructure, in [Azion Console](https://console.azion.com/) and through the [GraphQL API](/en/documentation/devtools/graphql/). An _event record_, or _log_, describes one request or action, such as its source address, path, and status, so you can search what happened later. Use Real-Time Events to trace a slow request through an [Application](/en/documentation/platform/applications/), inspect an attack, debug a [Function](/en/documentation/platform/functions/), or check who changed your account.

Real-Time Events sorts the records it keeps by kind of event:

- [Data sources](/en/documentation/platform/real-time-events/data-sources/) lets you find the kind of event record that answers your question, such as the requests your Applications and Firewalls receive. Each data source also names its dataset in the GraphQL API.

## Request path

Real-Time Events records nothing on its own: a record exists only after a Platform Resource handles a request or an action.

The diagram follows one request until a search reads its record. Solid arrows carry a request, the thick arrow carries the event record, and dotted arrows carry the response. Each label starts with the number of its step in the list.

```mermaid
%%{init: {"layout": "elk", "elk": {"cycleBreakingStrategy": "MODEL_ORDER"}, "themeVariables": {"fontSize": "13px"}, "flowchart": {"nodeSpacing": 24, "rankSpacing": 36, "padding": 8, "wrappingWidth": 150, "useMaxWidth": true}, "sequence": {"width": 120, "actorMargin": 30, "useMaxWidth": true}}}%%
flowchart TD
  Client(["Client"])
  App["Application or Firewall"]
  RTE["Real-Time Events"]
  Reader(["Console search or your query"])
  Client -->|"1. request"| App
  App ==>|"2. event record"| RTE
  Reader -->|"4. GraphQL query"| RTE
  RTE -.->|"5. matching records"| Reader
```

1. A client sends a request, and the Platform Resource that handles it, such as an Application or a Firewall, serves it.
2. That Platform Resource writes one event record for the request, with a value for each field of its data source. A request that also runs a Function leaves a record in the data source of Functions too, and other events, such as a DNS query or a change to your account, go to data sources of their own.
3. Real-Time Events keeps the record until its retention period ends, and then removes it, whether or not a search read it. The record becomes searchable some seconds after the request, so a search that runs at once can miss it.
4. A search in Azion Console and a query you write both send a GraphQL query to the same API. The query names one data source, a period, and the filters that narrow it.
5. The API answers with the records that match, and each record carries only the fields that the query selects.
