**Account Lockout Policy** is a security feature that protects accounts from unauthorized access. If a user repeatedly enters the wrong password, exceeding the maximum allowed number of failed login attempts, the user account will be temporarily locked to prevent further attempts.

It significantly increases the security of user accounts and the organization as a whole and reduces the risk of vulnerabilities, such as brute-force attacks.

Implementing **Account Lockout Policy**, you can:

- Configure a policy according to the organization's needs, limiting failed login attempts to prevent unauthorized access.
- Set the time required for a user to attempt to log in again after a lockout.
- Adjust the severity of the policy, if necessary.
- Manually authorize a locked-out user to log in again before completing the lockout period, for exceptional cases.
- Monitor unauthorized access attempts and take the necessary actions.

:::note
When an organization sets up the Account Lockout Policy, it applies to all account levels.

Account Lockout Policy is not enabled on an account by default, and Azion enables it on request. To request it, refer to [Support guidelines](/en/documentation/support/).
:::

## Policy settings

:::note
To configure the Account Lockout Policy, you must have *Account Owner* privileges.
:::

You configure the policy through the [Azion API](https://api.azion.com/). Azion Console has no screen for it. For the steps, refer to [Configure Account Lockout Policy](/en/documentation/guides/application-security/access-and-compliance/configure-account-lockout-policy/).

| Setting | API field | Type | Default | Description |
| --- | --- | --- | --- | --- |
| **Status** | `active` | Boolean | *inactive* (`false`) | The Account Lockout Policy status, as either **active** or **inactive**. |
| **Maximum Attempts** | `max_attempts` | Integer | *3* attempts | The maximum number of failed attempts before lockout. |
| **Blocking Period** | `blocking_period` | Integer, in minutes | *1440*, equivalent to *24 hours in minutes* | How long a user account remains locked after reaching the maximum number of failed login attempts. During this period, the user cannot attempt to log in again, preventing unauthorized access. |

---

## Logs

Account Lockout Policy generates logs including information about the failed login attempts and account lockouts. With these logs, you can monitor security events, identify potential threats, and troubleshoot issues related to user account access. For the steps, refer to [Check Account Lockout Policy logs](/en/documentation/guides/application-security/access-and-compliance/account-lockout-policy-logs/).

---

## Manual unlock

The *Account Owner* can manually unlock the access of a user who was locked, for exceptional cases, using the Account Lockout Policy logs to identify the lockout. For the steps, refer to [Unlock a user from Account Lockout Policy](/en/documentation/guides/application-security/access-and-compliance/unlock-account-lockout-policy/).
