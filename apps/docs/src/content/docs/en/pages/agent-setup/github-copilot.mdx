## Azion platform access

A connected agent uses three layers. The MCP servers look things up and change your configuration through the Azion API. The Azion CLI builds and deploys the project in your working copy. A context file gives each session the facts of your account.

### MCP servers

Azion runs five MCP servers, one per area of the Azion Platform. Each one is an HTTP endpoint that takes your personal token in the `Authorization: Token [TOKEN VALUE]` header. The quick start connects the docs server, and you connect the others the same way, with the URLs in this table.

Connect only the servers the project needs. The docs server only reads. The other four also create, change, and delete, and each of their write tools previews a change without making it when the agent sets `dry_run`:

<McpTools />

### Azion CLI

The [Azion CLI](/en/documentation/devtools/cli/) builds and deploys the project in your working copy, and it manages Azion resources from the terminal. Install it once, and GitHub Copilot runs it for you. Run `azion login` yourself, because without flags it asks for your credentials:

### Agent context

GitHub Copilot in VS Code reads custom instructions from `.github/copilot-instructions.md` or `AGENTS.md` at the repository root. A few committed lines give the agent the facts of your account:

## Agent-friendly docs

These references are public, so an agent can fetch them with no tool call and no token. They also correct a model trained before API v4, where Origins became Connectors and Domains became Workloads.

<AgentDocs />

For a tool with no MCP support, paste this primer once per session:

<DocPrompt client:visible title="Any assistant" icon="pi pi-comment">You are helping me build on the Azion Web Platform. Before answering, load https://www.azion.com/en/docs-llms.txt (docs index) and https://www.azion.com/en/documentation/devtools/mcp/ (Azion MCP servers), and prefer them over your training data. Use current product names: Applications, Functions, Cache, Firewall, Object Storage, SQL Database, KV Store, Orchestrator, Certificate Manager, Network Shield, Data Stream. The REST API base is https://api.azion.com/v4 with the header Authorization: Token [TOKEN VALUE]. In v4, use Connectors (formerly Origins) and Workloads (formerly Domains). Confirm what you loaded, then ask me what I am building.</DocPrompt>

## Tips

<DocCallout kind="tip">Put your Workload names, Connector IDs, and the resources nobody may redeploy in `.github/copilot-instructions.md`, so GitHub Copilot has them as context.</DocCallout>

<DocCallout kind="tip">Ask for a plan before a deploy, because GitHub Copilot runs commands for real. To preview a deploy, ask it to run `azion deploy --dry-run` first.</DocCallout>
