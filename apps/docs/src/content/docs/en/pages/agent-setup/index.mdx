## Understanding agents

Common types, concepts, and tradeoffs.

### Workflow

<DocCardGroup cols={2}>
	<DocCard title="Terminal" icon="pi pi-desktop" label="Runs in a shell. Best for automation, scripting, and CI pipelines." />
	<DocCard title="IDE" icon="pi pi-code" label="A full editor with the agent first-class: visual diffs and multi-file edits." />
	<DocCard title="Extension" icon="pi pi-th-large" label="Plugs into the editor you already use. Lightest install, keeps your setup." />
	<DocCard title="Desktop" icon="pi pi-window-maximize" label="A chat app installed on your computer, outside the editor and the terminal. Connects to the MCP servers like any other client." />
	<DocCard title="Cloud" icon="pi pi-cloud" label="Hosted, with no local install. Ideal for asynchronous, long-running work — and the shape the AI Assistant in the Console takes." />
</DocCardGroup>

### Key concepts

<DocCardGroup cols={2}>
	<DocCard title="MCP" icon="pi pi-server" label="The Model Context Protocol — the standard that lets an agent call external tools. Azion ships five MCP servers, one per area of the platform, and every agent on this page speaks to them." />
	<DocCard title="Agent context" icon="pi pi-file" label="The files an agent reads before it answers: llms.txt for the documentation index, AGENTS.md for your project’s own conventions." />
	<DocCard title="Model flexibility" icon="pi pi-sliders-h" label="Locked ties you to the maker’s own models. BYOK takes your provider key. Multi-provider switches between several." />
	<DocCard title="Context" icon="pi pi-database" label="Session forgets at the end of a conversation. Project memory persists in a file you commit. Indexed codebase keeps a searchable index of the whole repository." />
</DocCardGroup>

### Common tradeoffs

<DocCardGroup cols={2}>
	<DocCard title="Cloud vs. local" icon="pi pi-cloud-upload" label="Cloud runs long tasks without holding your machine, and sends your code somewhere. Local keeps everything on disk, and stops when your laptop does." />
	<DocCard title="Proprietary vs. open source" icon="pi pi-github" label="Open source can be audited, forked and self-hosted. Proprietary tends to ship the newest capability first." />
	<DocCard title="Locked model vs. BYOK" icon="pi pi-key" label="A locked model is tuned for its own agent and priced as one subscription. BYOK lets you choose the model per task and pay per token." />
	<DocCard title="Session vs. indexed codebase" icon="pi pi-search" label="An index answers questions about code nobody opened, at the cost of a copy of the repository. A session only knows what it was shown." />
</DocCardGroup>
