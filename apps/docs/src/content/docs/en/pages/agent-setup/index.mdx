Each Azion MCP server is one HTTP endpoint. To connect a client that this page does not list, point it at `https://docs-mcp.azion.com/mcp` or another of the five servers, and send your [personal token](/en/documentation/fundamentals/personal-tokens/) in the `Authorization: Token [TOKEN VALUE]` header. A client that starts only local servers reaches the endpoint through [`mcp-remote`](/en/documentation/devtools/mcp/glossary/). For more information, refer to [MCP server quickstart](/en/documentation/devtools/mcp/quickstart/).

## Agent types and concepts

These cards define the workflows and terms that the comparison table uses, and the tradeoffs between them.

### Workflow

<DocCardGroup cols={2}>
	<DocCard title="Terminal" icon="pi pi-desktop" label="An agent you run as a command in a shell. Use it for automation, scripts, and CI pipelines." />
	<DocCard title="IDE" icon="pi pi-code" label="An editor built around its agent, with visual diffs and edits across several files." />
	<DocCard title="Extension" icon="pi pi-th-large" label="An agent installed inside an editor you already use, so your editor settings stay as they are." />
	<DocCard title="Desktop" icon="pi pi-window-maximize" label="A chat app installed on your computer, outside the editor and the terminal. It connects to the MCP servers like any other client." />
	<DocCard title="Cloud" icon="pi pi-cloud" label="An agent that runs on the servers of its vendor, with nothing to install. Use it for long tasks that run while you do other work. Copilot, the assistant in Azion Console, is hosted the same way." />
</DocCardGroup>

### Key concepts

<DocCardGroup cols={2}>
	<DocCard title="MCP" icon="pi pi-server" label="The Model Context Protocol, an open standard that defines how an agent lists the tools of a server and calls them. Azion runs five MCP servers, one per area of the Azion Platform." />
	<DocCard title="Agent context" icon="pi pi-file" label="The file of project conventions that an agent reads at the start of each session, such as AGENTS.md, CLAUDE.md, or GEMINI.md. An agent reads llms.txt, the documentation index, only when it fetches it." />
	<DocCard title="Model" icon="pi pi-sliders-h" label="Locked means the agent runs only the models of its maker. Multi-provider means you pick among models from several providers, and some of these agents also take your own API key." />
	<DocCard title="Pricing" icon="pi pi-wallet" label="Paid means the agent needs a paid plan or a paid API key. Free tier means a free plan exists, with paid plans for more use. Your provider means the agent is free, and you pay the model provider you connect." />
	<DocCard title="Context" icon="pi pi-database" label="Session means the agent keeps nothing after the conversation ends. Project memory means it reads a file of conventions at the start of each session. Indexed codebase means it also keeps a searchable index of the repository." />
</DocCardGroup>

### Common tradeoffs

<DocCardGroup cols={2}>
	<DocCard title="Cloud vs. local" icon="pi pi-cloud-upload" label="A cloud agent works on a copy of your repository on the servers of its vendor, so a long task does not need your computer. A local agent works on the files on your computer, and it stops when your computer stops." />
	<DocCard title="Proprietary vs. open source" icon="pi pi-github" label="An open source agent publishes the code of its client under an open source license, so you can read, audit, and change it. The code of a proprietary agent is closed, so only its vendor can change it." />
	<DocCard title="Locked vs. multi-provider" icon="pi pi-key" label="A locked agent runs the models of one maker, billed by that maker. A multi-provider agent lets you pick the model for each task, and with your own API key you pay that provider for what you use." />
	<DocCard title="Session vs. indexed codebase" icon="pi pi-search" label="An agent with an index can search code that the conversation never opened. An agent without one knows only the files it opens and the text you give it." />
</DocCardGroup>
