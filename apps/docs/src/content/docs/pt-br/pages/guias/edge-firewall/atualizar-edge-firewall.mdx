Você pode migrar cada configuração de um rule set obsoleto do Firewall para um [Firewall](/pt-br/documentacao/plataforma/firewall/) pelo Azion Console, como uma regra no [Rules Engine para Firewall](/pt-br/documentacao/plataforma/firewall/rules-engine/). Para adicionar uma regra que nenhum rule set obsoleto tinha, consulte [Crie uma regra de Firewall](/pt-br/documentacao/guias/seguranca-de-aplicacoes/firewall-e-waf/trabalhar-com-rules-engine/).

Cada seção desta página recria uma configuração como uma regra do Firewall: o bloqueio geográfico e o bloqueio de IP também precisam de uma [Network List](/pt-br/documentacao/plataforma/firewall/network-shield/network-lists/), e um secure token precisa de uma Function Instance. Depois que o Firewall aplicar as regras, você remove os rule sets obsoletos das suas Applications.

---

## Pré-requisitos

- Acesso ao Azion Console. Para entrar, consulte [Acesse Azion Console](/pt-br/documentacao/guias/plataforma/conta-e-billing/como-acessar-o-azion-console/).
- Um Firewall definido pelo deployment do Workload que serve a Application com o rule set obsoleto. Para criar um Firewall e defini-lo, consulte [Primeiros passos com Firewall](/pt-br/documentacao/plataforma/firewall/primeiros-passos/). Para definir um Firewall que você já tem, consulte [Defina um Firewall em um Workload](/pt-br/documentacao/guias/seguranca-de-aplicacoes/firewall-e-waf/proteja-seu-dominio/).
- Os valores do rule set obsoleto: os domínios de referrer aceitos, os países bloqueados, os endereços IP bloqueados, o secret do token, o rate limit e os rule sets do WAF.
- Para um secure token, a Function Secure Token na sua conta, instalada pelo Marketplace.
- Para um rule set do WAF, o rule set a aplicar. Para criar um, consulte [Crie e aplique um WAF rule set](/pt-br/documentacao/guias/seguranca-de-aplicacoes/firewall-e-waf/criar-waf-rule-set/).

## Migre um bloqueio por referrer

Um bloqueio por referrer nega uma requisição cujo header `Referer` não corresponde a nenhum dos domínios que o rule set obsoleto aceita. Em um Firewall, uma regra combina uma condição _Header Referer_ por domínio aceito com o comportamento _Deny (403 Forbidden)_. A variável _Header Referer_ precisa de WAF no Firewall. Enquanto WAF está desativado, a variável aparece como _Header Referer - required WAF_ e não pode ser selecionada.

Para migrar o bloqueio por referrer no Azion Console:

<DocSteps>
  <DocStep title="Abra o Firewall que o seu Workload define">

  Acesse [Azion Console](https://console.azion.com/) > **Firewalls** e selecione o Firewall.

  </DocStep>
  <DocStep title="Ative WAF">

  Na aba **Main Settings**, ative **Web Application Firewall**.

  </DocStep>
  <DocStep title="Salve as configurações principais">

  Selecione **Save**. Azion Console mostra `Your Firewall has been updated`.

  </DocStep>
  <DocStep title="Selecione a aba Rules Engine" />
  <DocStep title="Inicie uma nova regra">

  Selecione **Rule**. O drawer **Create Rule** abre.

  </DocStep>
  <DocStep title="Dê um nome à regra">

  Na seção **General**, informe um **Name**, como `referrer-block`. Uma **Description** é opcional.

  </DocStep>
  <DocStep title="Defina o primeiro domínio aceito">

  Na seção **Criteria**, selecione _Header Referer_ como a variável e _does not match_ como o operador. Informe um domínio aceito como argumento, como `example.com`.

  </DocStep>
  <DocStep title="Adicione os outros domínios aceitos">

  Para cada domínio aceito restante, selecione **And**. Depois, defina _Header Referer_, _does not match_ e esse domínio.

  </DocStep>
  <DocStep title="Adicione o comportamento">

  Na seção **Behaviors**, selecione _Deny (403 Forbidden)_.

  </DocStep>
  <DocStep title="Salve a regra">

  Selecione **Save**.

  </DocStep>
</DocSteps>

Azion Console mostra `Rule successfully created`. A regra aparece na aba **Rules Engine** com _Active_ na coluna **Status**.

Azion Console permite no máximo 10 condições em um grupo de critérios e cinco grupos em uma regra. Para mais domínios aceitos, selecione **Add Criteria** para iniciar outro grupo, que Azion Console une ao primeiro com _And_. Para saber como _does not match_ compara o header, consulte [Rules Engine para Firewall](/pt-br/documentacao/plataforma/firewall/rules-engine/#operadores).

## Migre o bloqueio geográfico

O bloqueio geográfico migra para uma Network List do tipo _Countries_ e uma regra que nega requisições por essa lista. A variável _Network_ da regra precisa de Network Shield no Firewall. Um Firewall começa com Network Shield ativado. Enquanto ele está desativado, a variável aparece como _Network - required Network Shield_ e não pode ser selecionada.

Para criar a Network List no Azion Console:

<DocSteps>
  <DocStep title="Abra a página Network Lists">

  Acesse [Azion Console](https://console.azion.com/) > **Network Lists**.

  </DocStep>
  <DocStep title="Inicie uma nova Network List">

  Selecione **Network List**. A página **Create Network List** abre.

  </DocStep>
  <DocStep title="Dê um nome à lista">

  Na seção **General**, informe um **Name**, como `geo-block`.

  </DocStep>
  <DocStep title="Selecione o tipo Countries">

  Na seção **Network List Settings**, selecione _Countries_. O formulário abre com _ASN_ selecionado.

  </DocStep>
  <DocStep title="Adicione os países">

  Em **Countries**, selecione cada país que o rule set obsoleto listava.

  </DocStep>
  <DocStep title="Salve a lista">

  Selecione **Save**.

  </DocStep>
</DocSteps>

Azion Console mostra `Your network list has been created`. O tipo de uma lista não pode mudar depois que você a cria. Para reutilizar uma lista _Countries_ que você já tem, abra-a em **Network Lists**, adicione os países e selecione **Save**.

Para criar a regra que nega requisições pela lista:

<DocSteps>
  <DocStep title="Abra o Firewall que o seu Workload define">

  Acesse [Azion Console](https://console.azion.com/) > **Firewalls** e selecione o Firewall.

  </DocStep>
  <DocStep title="Confirme que Network Shield está ativado">

  Na aba **Main Settings**, confirme que **Network Shield** está ativado. Se estiver desativado, ative-o e selecione **Save**.

  </DocStep>
  <DocStep title="Selecione a aba Rules Engine" />
  <DocStep title="Inicie uma nova regra">

  Selecione **Rule**. O drawer **Create Rule** abre.

  </DocStep>
  <DocStep title="Dê um nome à regra">

  Na seção **General**, informe um **Name**, como `geo-block`. Uma **Description** é opcional.

  </DocStep>
  <DocStep title="Defina o critério">

  Na seção **Criteria**, selecione _Network_ como a variável. Selecione _matches_ para uma blocklist ou _does not match_ para uma allowlist.

  </DocStep>
  <DocStep title="Selecione a lista">

  Em **Select a Network**, selecione a lista, como `geo-block`.

  </DocStep>
  <DocStep title="Adicione o comportamento">

  Na seção **Behaviors**, selecione _Deny (403 Forbidden)_.

  </DocStep>
  <DocStep title="Salve a regra">

  Selecione **Save**.

  </DocStep>
</DocSteps>

Azion Console mostra `Rule successfully created`. Uma regra de blocklist nega as requisições dos países da lista. Uma regra de allowlist nega as requisições de todos os outros países.

## Migre um secure token

Um secure token migra para uma Function Instance da Function Secure Token. Uma regra do Firewall executa a instância com o comportamento _Run Function_. Os argumentos da instância carregam o secret que compõe o hash do token. Instale primeiro a Function Secure Token pelo Marketplace, para que o campo **Function** possa oferecê-la.

Para criar a Function Instance no Azion Console:

<DocSteps>
  <DocStep title="Abra o Firewall que o seu Workload define">

  Acesse [Azion Console](https://console.azion.com/) > **Firewalls** e selecione o Firewall.

  </DocStep>
  <DocStep title="Confirme que Functions está ativado">

  Na aba **Main Settings**, confirme que **Functions** está ativado. Se estiver desativado, ative-o e selecione **Save**.

  </DocStep>
  <DocStep title="Selecione a aba Functions Instances">

  A aba aparece apenas enquanto **Functions** está ativado.

  </DocStep>
  <DocStep title="Inicie uma nova instância">

  Selecione **Function**.

  </DocStep>
  <DocStep title="Dê um nome à instância">

  Na seção **General**, informe um **Name**, como `secure-token`.

  </DocStep>
  <DocStep title="Selecione a Function">

  Em **Function**, selecione a Function Secure Token.

  </DocStep>
  <DocStep title="Informe os argumentos">

  Em **Arguments**, informe os argumentos que a Function Secure Token espera, com o secret do rule set obsoleto. Para esses argumentos, consulte [Instale a integração Secure Token](/pt-br/documentacao/guias/desenvolvimento-de-aplicacoes/integracoes/secure-token/).

  </DocStep>
  <DocStep title="Salve a instância">

  Selecione **Save**.

  </DocStep>
</DocSteps>

A instância aparece na aba **Functions Instances**, com a Function Secure Token na coluna **Function**. Para saber como uma instância passa os argumentos dela para a Function, consulte [Function Instances no Firewall](/pt-br/documentacao/plataforma/firewall/functions-instances/#argumentos).

Para criar a regra que executa a instância:

<DocSteps>
  <DocStep title="Selecione a aba Rules Engine">

  No mesmo Firewall, selecione a aba **Rules Engine**.

  </DocStep>
  <DocStep title="Inicie uma nova regra">

  Selecione **Rule**. O drawer **Create Rule** abre.

  </DocStep>
  <DocStep title="Dê um nome à regra">

  Na seção **General**, informe um **Name**, como `secure-token`. Uma **Description** é opcional.

  </DocStep>
  <DocStep title="Defina o domínio">

  Na seção **Criteria**, selecione _Host_ como a variável e _is equal_ como o operador. Informe o domínio que serve o conteúdo protegido, como `<your-domain>`.

  </DocStep>
  <DocStep title="Defina o caminho">

  Selecione **And**. Depois, selecione _Request Uri_ e _starts with_ e informe o caminho protegido, como `/classes`.

  </DocStep>
  <DocStep title="Adicione o comportamento">

  Na seção **Behaviors**, selecione _Run Function_.

  </DocStep>
  <DocStep title="Selecione a instância">

  Em **Select a Function**, selecione a instância, como `secure-token`. A lista contém as Function Instances deste Firewall.

  </DocStep>
  <DocStep title="Salve a regra">

  Selecione **Save**.

  </DocStep>
</DocSteps>

Azion Console mostra `Rule successfully created`. A regra executa a instância Secure Token em cada requisição para esse domínio cujo caminho começa com o caminho protegido. Para todas as opções do comportamento, consulte [Rules Engine para Firewall](/pt-br/documentacao/plataforma/firewall/rules-engine/#run-function).

## Migre o bloqueio de IP

O bloqueio de IP migra para uma Network List do tipo _IP/CIDR_ e uma regra que nega requisições por essa lista. A variável _Network_ da regra precisa de Network Shield no Firewall. Um Firewall começa com Network Shield ativado. Enquanto ele está desativado, a variável aparece como _Network - required Network Shield_ e não pode ser selecionada.

Para criar a Network List no Azion Console:

<DocSteps>
  <DocStep title="Abra a página Network Lists">

  Acesse [Azion Console](https://console.azion.com/) > **Network Lists**.

  </DocStep>
  <DocStep title="Inicie uma nova Network List">

  Selecione **Network List**. A página **Create Network List** abre.

  </DocStep>
  <DocStep title="Dê um nome à lista">

  Na seção **General**, informe um **Name**, como `ip-block`.

  </DocStep>
  <DocStep title="Selecione o tipo IP/CIDR">

  Na seção **Network List Settings**, selecione _IP/CIDR_. O formulário abre com _ASN_ selecionado.

  </DocStep>
  <DocStep title="Adicione os endereços">

  Em **List**, cole os endereços IP bloqueados do rule set obsoleto, um endereço IP ou CIDR por linha.

  </DocStep>
  <DocStep title="Salve a lista">

  Selecione **Save**.

  </DocStep>
</DocSteps>

Azion Console mostra `Your network list has been created`. A lista mantém uma cópia de cada item que você cola duas vezes. Para reutilizar uma lista _IP/CIDR_ que você já tem, abra-a em **Network Lists**, adicione os endereços e selecione **Save**.

Para criar a regra que nega requisições pela lista:

  Selecione **Rule**. O drawer **Create Rule** abre.

  </DocStep>
  <DocStep title="Dê um nome à regra">

  Na seção **General**, informe um **Name**, como `ip-block`. Uma **Description** é opcional.

  </DocStep>
  <DocStep title="Defina o critério">

  Na seção **Criteria**, selecione _Network_ como a variável. Selecione _matches_ para uma blocklist ou _does not match_ para uma allowlist.

  </DocStep>
  <DocStep title="Selecione a lista">

  Em **Select a Network**, selecione a lista, como `ip-block`.

  </DocStep>
  <DocStep title="Adicione o comportamento">

  Na seção **Behaviors**, selecione _Deny (403 Forbidden)_.

  </DocStep>
  <DocStep title="Salve a regra">

  Selecione **Save**.

  </DocStep>
</DocSteps>

Azion Console mostra `Rule successfully created`. Uma regra de blocklist nega as requisições dos endereços da lista. Uma regra de allowlist nega as requisições de todos os outros endereços.

## Migre o rate limit

O rate limit migra para uma regra com o comportamento _Set Rate Limit_. O comportamento não precisa de nenhum switch específico, então as configurações principais do Firewall continuam como estão, desde que WAF, Network Shield ou Functions esteja ativado.

Para migrar o rate limit no Azion Console:

<DocSteps>
  <DocStep title="Abra o Firewall que o seu Workload define">

  Acesse [Azion Console](https://console.azion.com/) > **Firewalls** e selecione o Firewall.

  </DocStep>
  <DocStep title="Selecione a aba Rules Engine" />
  <DocStep title="Inicie uma nova regra">

  Selecione **Rule**. O drawer **Create Rule** abre.

  </DocStep>
  <DocStep title="Dê um nome à regra">

  Na seção **General**, informe um **Name**, como `rate-limit`. Uma **Description** é opcional.

  </DocStep>
  <DocStep title="Defina o critério">

  Na seção **Criteria**, a condição abre com _Request Uri_ e _starts with_. Informe `/` para limitar toda requisição.

  </DocStep>
  <DocStep title="Adicione o comportamento">

  Na seção **Behaviors**, selecione _Set Rate Limit_.

  </DocStep>
  <DocStep title="Selecione a unidade da taxa">

  Em **Rate Limit Type**, selecione _Req/s_ ou _Req/min_.

  </DocStep>
  <DocStep title="Informe a taxa média">

  Em **Average Rate Limit**, informe a taxa média do rule set obsoleto. O valor é no mínimo `1`.

  </DocStep>
  <DocStep title="Selecione o que o limite conta">

  Em **Limit By**, selecione _Client IP address_ ou _Global_, como o rule set obsoleto fazia.

  </DocStep>
  <DocStep title="Informe o tamanho do burst">

  Com _Req/s_, informe o tamanho do burst do rule set obsoleto em **Maximum Burst Size**. O valor é no mínimo `1`.

  </DocStep>
  <DocStep title="Salve a regra">

  Selecione **Save**.

  </DocStep>
</DocSteps>

Azion Console mostra `Rule successfully created`. **Maximum Burst Size** aparece apenas com _Req/s_. Para todos os campos do comportamento, consulte [Rules Engine para Firewall](/pt-br/documentacao/plataforma/firewall/rules-engine/#set-rate-limit).

Quando a regra entra em vigor, as requisições que chegam ao mesmo tempo além do burst recebem `429`. As requisições enviadas uma após a outra ficam retidas por cerca de um segundo e depois são atendidas. Para mais informações, consulte [Como Firewall funciona](/pt-br/documentacao/plataforma/firewall/como-funciona/#rate-limits).

## Migre um rule set do WAF

Um rule set do WAF que uma Application aplicava migra para uma regra do Firewall com o comportamento _Set WAF_. Uma regra carrega um único comportamento _Set WAF_, então cada rule set do WAF que você migra precisa de uma regra própria. No Azion Console, _Set WAF_ precisa de WAF no Firewall. Enquanto WAF está desativado, o comportamento aparece como _Set WAF - required WAF_ e não pode ser selecionado.

Para migrar um rule set do WAF no Azion Console:

<DocSteps>
  <DocStep title="Abra o Firewall que o seu Workload define">

  Acesse [Azion Console](https://console.azion.com/) > **Firewalls** e selecione o Firewall.

  </DocStep>
  <DocStep title="Ative WAF">

  Na aba **Main Settings**, ative **Web Application Firewall**.

  </DocStep>
  <DocStep title="Salve as configurações principais">

  Selecione **Save**. Azion Console mostra `Your Firewall has been updated`.

  </DocStep>
  <DocStep title="Selecione a aba Rules Engine" />
  <DocStep title="Inicie uma nova regra">

  Selecione **Rule**. Para adicionar o rule set a uma regra que você já tem, selecione essa regra.

  </DocStep>
  <DocStep title="Dê um nome à regra">

  Na seção **General**, informe um **Name**, como `waf-rule-set`. Uma **Description** é opcional.

  </DocStep>
  <DocStep title="Defina o critério">

  Na seção **Criteria**, a condição abre com _Request Uri_ e _starts with_. Informe `/` para inspecionar toda requisição.

  </DocStep>
  <DocStep title="Adicione o comportamento">

  Na seção **Behaviors**, selecione _Set WAF_.

  </DocStep>
  <DocStep title="Selecione o rule set">

  Em **Select a WAF**, selecione o rule set do WAF.

  </DocStep>
  <DocStep title="Selecione o modo">

  Em **Select a WAF mode**, selecione _Logging_ ou _Blocking_.

  </DocStep>
  <DocStep title="Salve a regra">

  Selecione **Save**.

  </DocStep>
</DocSteps>

Azion Console mostra `Rule successfully created`. Para saber o que cada modo faz, consulte [Score e modos](/pt-br/documentacao/plataforma/firewall/waf/score-e-modos/#modos). Para todas as opções do comportamento, consulte [Rules Engine para Firewall](/pt-br/documentacao/plataforma/firewall/rules-engine/#set-waf).

## Remova os rule sets obsoletos das suas Applications

Remova um rule set obsoleto de uma Application somente depois que o Firewall aplicar as regras que o substituem. Removê-lo antes deixa as requisições que ele cobria sem nenhuma das duas proteções.

Uma regra adicionada a um Firewall que já recebia tráfego chegou a ele de 262 a 319 segundos depois de salva, e uma alteração nos itens de uma Network List em uso, de 41 a 156 segundos depois. Nenhuma duração é garantida, e um Workload cujo deployment passa a definir um Firewall pode levar mais tempo. Enquanto uma alteração se propaga, as requisições podem receber a resposta antiga e a nova, alternadamente. Para mais informações, consulte [Propagação](/pt-br/documentacao/plataforma/firewall/como-funciona/#propagacao).

Para confirmar que o Firewall aplica uma regra, envie uma requisição a que a regra corresponda. Envie a requisição de novo até que a resposta seja a que a regra define. Uma requisição que corresponde a uma regra _Deny (403 Forbidden)_ recebe `403` e a página de erro padrão da Azion. Para uma regra de Network List, a linha `Your IP` dessa página mostra o endereço que o Firewall comparou com a lista.

Para remover um rule set obsoleto de uma Application no Azion Console:

<DocSteps>
  <DocStep title="Abra a Application">

  No Azion Console, abra cada Application que usava um rule set obsoleto.

  </DocStep>
  <DocStep title="Selecione a aba Rules Engine" />
  <DocStep title="Abra cada regra que aplica um rule set obsoleto">

  Selecione cada regra cujo comportamento aplica um rule set obsoleto do Firewall ou um rule set do WAF.

  </DocStep>
  <DocStep title="Exclua o comportamento">

  Exclua esse comportamento da regra. Para remover a regra inteira, exclua-a da lista de regras e confirme.

  </DocStep>
  <DocStep title="Salve a regra">

  Selecione **Save**.

  </DocStep>
</DocSteps>

A Application deixa de aplicar o rule set obsoleto, e as regras do Firewall inspecionam as requisições do Workload. Para mais informações sobre o Rules Engine de uma Application, consulte [Rules Engine para Applications](/pt-br/documentacao/plataforma/applications/rules-engine/).
