Você pode criar um [Firewall](/pt-br/documentacao/plataforma/firewall/) que pontua requisições com [Bot Manager Lite](/pt-br/documentacao/plataforma/firewall/bot-manager/bot-manager-lite/) e recusa endereços de Tor exit nodes a partir do template Bot Manager Lite and TOR Block Starter Kit, no Azion Console. Para adicionar Bot Manager Lite a um Firewall que você já executa, consulte [Adicione Bot Manager Lite a um Firewall](/pt-br/documentacao/guias/desenvolvimento-de-aplicacoes/integracoes/bot-manager-lite-integration-kit/). Para criar a Function Instance e a regra você mesmo, consulte [Primeiros passos com Bot Manager](/pt-br/documentacao/plataforma/firewall/bot-manager/primeiros-passos/).

---

## Pré-requisitos

- Bot Manager Lite instalado pelo Marketplace. Para mais informações, consulte [Instale o Bot Manager Lite](/pt-br/documentacao/guias/desenvolvimento-de-aplicacoes/integracoes/bot-manager-lite/).
- Acesso ao Azion Console. Para entrar, consulte [Acesse Azion Console](/pt-br/documentacao/guias/plataforma/conta-e-billing/como-acessar-o-azion-console/).
- Opcionalmente, os IDs dos Workloads cujas requisições o Firewall inspeciona. Sem eles, o template cria o Firewall e nenhum deployment o define.
- A Function Instance é executada em [Functions](/pt-br/documentacao/plataforma/functions/), e a regra de recusa usa o [Network Shield](/pt-br/documentacao/plataforma/firewall/network-shield/). Os dois podem gerar custos de uso. Para as métricas pelas quais o Bot Manager é cobrado, consulte [Preços](/pt-br/documentacao/fundamentos/precos/#bot-manager).

O template verifica se o Bot Manager Lite está instalado antes de criar qualquer coisa. Quando não está, a implantação falha e escreve uma linha de log que informa o motivo.

## Implante o template

Para implantar o template no Azion Console:

<DocSteps>
  <DocStep title="(Opcional) Copie os IDs dos Workloads">

  Acesse [Azion Console](https://console.azion.com/) > **Workloads**, selecione um Workload cujas requisições o Firewall inspeciona e copie o ID dele do endereço. O endereço termina em `/workloads/edit/<workload-id>`.

  </DocStep>
  <DocStep title="Abra o template">

  Acesse o template [Bot Manager Lite and TOR Block Starter Kit](https://console.azion.com/create/azion/bot--manager-and-tor-block-starter-kit).

  </DocStep>
  <DocStep title="Informe os IDs dos Workloads">

  Em **Domain ID(s)**, informe os IDs que você copiou. O campo é opcional. Se ele ficar vazio, o template cria o Firewall e nenhum deployment o define. Para defini-lo em um Workload depois, consulte [Defina um Firewall em um Workload](/pt-br/documentacao/guias/seguranca-de-aplicacoes/firewall-e-waf/proteja-seu-dominio/).

  </DocStep>
  <DocStep title="Selecione Deploy" />
</DocSteps>

Quando a implantação termina, a conta carrega um novo Firewall com **Functions** e **Network Shield** ativados. A aba **Functions Instances** dele lista uma Function Instance do Bot Manager Lite. A aba **Rules Engine** dele lista as regras que executam a Function Instance, verificam se os Workloads que você informou são válidos e recusam uma requisição cujo endereço está na [Network List](/pt-br/documentacao/plataforma/firewall/network-shield/network-lists/) `Azion IP Tor Exit Nodes`.

A Function Instance carrega três argumentos:

```json
{
  "threshold": 10,
  "action": "allow",
  "internal_logs": 2
}
```

Um `threshold` de `10` é menor que o `30` com que o Bot Manager Lite é entregue, então a Function Instance aplica `action` a requisições que o padrão entregue deixa passar. Uma `action` de `allow` não recusa nenhuma requisição, então é a regra que usa a Network List que recusa um endereço Tor. Um `internal_logs` de `2` escreve uma linha de log de report para cada requisição, qualquer que seja a pontuação. Para os valores que cada argumento aceita, consulte [Argumentos](/pt-br/documentacao/plataforma/firewall/bot-manager/argumentos/).

## Pontue endereços de Tor exit nodes

`Azion IP Tor Exit Nodes` é a Network List com ID `2`, mantida pela Azion. A regra `14` do Bot Manager Lite soma 6 pontos para cada lista em `reputation_network_lists` que contém o endereço do cliente. O template não define `reputation_network_lists`, então a Function Instance pontua um endereço Tor como qualquer outro endereço.

Para adicionar a lista Tor aos argumentos no Azion Console:

<DocSteps>
  <DocStep title="Abra a Function Instance">

  Acesse [Azion Console](https://console.azion.com/) > **Firewalls**, selecione o Firewall que o template criou e, em seguida, selecione a aba **Functions Instances** e a Function Instance do Bot Manager Lite.

  </DocStep>
  <DocStep title="Adicione a lista aos argumentos">

  Na seção **Arguments**, adicione `reputation_network_lists` com o ID `2`:

  ```json
  {
    "threshold": 10,
    "action": "allow",
    "internal_logs": 2,
    "reputation_network_lists": [2]
  }
  ```

  </DocStep>
  <DocStep title="Selecione Save" />
</DocSteps>

Depois que a alteração se propaga, uma requisição de um Tor exit node pontua 6 pontos a mais do que a mesma requisição de outro endereço. Para a tabela de regras por trás dessa pontuação, consulte [Bot Manager Lite](/pt-br/documentacao/plataforma/firewall/bot-manager/bot-manager-lite/#regras). Para quanto tempo uma alteração leva para alcançar as requisições, consulte [Propagação](/pt-br/documentacao/plataforma/firewall/como-funciona/#propagacao).

:::caution[Atenção]
A API verifica se os argumentos são um objeto ou um array JSON, e não verifica nenhuma chave. Uma chave digitada errado, como `reputation_network_list`, é armazenada como foi digitada, a API e o Azion CLI não retornam nenhum erro, e a Function nunca a lê.
:::

## Leia o que a Function Instance pontuou

Com `internal_logs` definido como `2`, a Function Instance escreve uma linha de log de report para cada requisição que pontua, incluindo uma requisição que pontuou `0`. Para ler as linhas no Azion Console:

<DocSteps>
  <DocStep title="Abra o Real-Time Events">

  Acesse [Azion Console](https://console.azion.com/) > **Real-Time Events** e selecione a aba **Functions Console**.

  </DocStep>
  <DocStep title="Leia as linhas de report">

  Restrinja o período às requisições que você quer ler. Cada linha de report abre com `[Bot-Protection]` na coluna **Log Body** e carrega a pontuação de uma requisição.

  </DocStep>
</DocSteps>

A aba **Functions Console** mostra o que a Function Instance pontuou. Uma `action` de `allow` não recusa nada, então defina `threshold` e `action` pelas pontuações que o seu próprio tráfego produz, e não pelos valores do template. Para os campos que uma linha carrega, consulte [Logs](/pt-br/documentacao/plataforma/firewall/bot-manager/logs/). Para encaminhar as linhas para um destino seu, consulte [Data Stream](/pt-br/documentacao/plataforma/data-stream/).
