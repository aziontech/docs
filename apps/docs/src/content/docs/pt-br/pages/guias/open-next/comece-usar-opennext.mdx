Você pode fazer o deploy de um app Next.js na Azion com o adaptador `@aziontech/opennextjs-azion` e a [Azion CLI](/pt-br/documentacao/devtools/cli/). O adaptador faz o build do app para o preset `opennextjs`, e a CLI faz o deploy dele como uma [Application](/pt-br/documentacao/plataforma/applications/), uma [Function](/pt-br/documentacao/plataforma/functions/) e um bucket do [Object Storage](/pt-br/documentacao/plataforma/object-storage/). Para um site sem código no servidor, [Fazer o deploy de um static export](/pt-br/documentacao/guias/desenvolvimento-de-aplicacoes/frameworks/next/#fazer-o-deploy-de-um-static-export) é o caminho mais curto.

---

## Pré-requisitos

- A [Azion CLI](/pt-br/documentacao/devtools/cli/#instalar-a-azion-cli), [conectada](/pt-br/documentacao/devtools/cli/login/) à sua conta.
- Node.js e npm.
- Uma versão do Next.js que o adaptador suporta: qualquer versão do Next.js 15 ou a última versão minor do Next.js 14. Para os detalhes, consulte [Versões do Next.js suportadas](/pt-br/documentacao/devtools/runtime/frameworks/nextjs-compatibility/#versoes-do-nextjs-suportadas).

:::note[nota]
O adaptador não suporta o Next.js 16. Um site em Next.js 16 que usa apenas geração de site estático (SSG) e não precisa de servidor pode fazer o deploy como um site totalmente estático. Para fazer esse deploy, consulte [Fazer o deploy de um static export](/pt-br/documentacao/guias/desenvolvimento-de-aplicacoes/frameworks/next/#fazer-o-deploy-de-um-static-export).
:::

## Crie um app Next.js

Para criar um app Next.js 15 e adicionar o adaptador a ele:

1. Crie o app com o `create-next-app` e entre na pasta dele:

   ```bash
   npx create-next-app@15 my-next-app --use-npm
   cd my-next-app
   ```

2. Instale o adaptador como dependência de desenvolvimento:

   ```bash
   npm install -D @aziontech/opennextjs-azion
   ```

O app está pronto para o link. Um app novo já define `"moduleResolution": "bundler"` no `tsconfig.json`, que o adaptador exige.

---

## Prepare um app Next.js existente

Para preparar um app que já existe:

1. Na pasta do app, instale as dependências do projeto e o adaptador como dependência de desenvolvimento:

   ```bash
   npm install
   npm install -D @aziontech/opennextjs-azion
   ```

2. No `tsconfig.json`, defina `moduleResolution` como `bundler`:

   ```json
   "moduleResolution": "bundler"
   ```

Sem essa configuração, o build ou a Function publicada podem falhar. Se o build ainda falhar no `open-next.config.ts`, consulte [Problemas conhecidos](/pt-br/documentacao/devtools/runtime/frameworks/nextjs-compatibility/#problemas-conhecidos).

## Faça o link do app com a Azion

O `azion link` configura a pasta do projeto para o preset `opennextjs`. Ele grava o arquivo `azion.config.cjs` e o arquivo `azion/azion.json` e não cria nada na Azion.

Para fazer o link do app sem perguntas, execute este comando na pasta do app:

```bash
azion link --name my-next-app --preset opennextjs --auto
```

```text
Project successfully configured
Sucessfully written to your .gitignore file
Successfully created GitHub Actions workflow file at .github/workflows/azion-deploy.yml
Please, remember to run azion build --preset [preset-name], in order to generate the necessary configuration files
```

Com `--auto`, o comando também adiciona `.edge/`, `.vulcan` e `.open-next` ao `.gitignore` e grava um workflow do GitHub Actions. Para todas as flags, consulte [Azion CLI link](/pt-br/documentacao/devtools/cli/link-comando/).

## Revise o arquivo azion.config

O arquivo `azion.config.cjs` que o `azion link` grava declara todos os recursos que o deploy cria, no formato da API v4:

```javascript
module.exports = {
  version: 4,
  build: {
    preset: 'opennextjs',
    polyfills: true
  },
  storage: [
    {
      name: '$BUCKET_NAME',
      prefix: '$BUCKET_PREFIX',
      dir: './.edge/assets',
      workloadsAccess: 'read_write'
    }
  ],
  connectors: [
    {
      name: '$CONNECTOR_NAME',
      active: true,
      type: 'storage',
      attributes: {
        bucket: '$BUCKET_NAME',
        prefix: '$BUCKET_PREFIX'
      }
    }
  ],
  functions: [
    {
      name: '$FUNCTION_NAME',
      path: './functions/worker.js',
      bindings: {
        storage: {
          bucket: '$BUCKET_NAME',
          prefix: '$BUCKET_PREFIX'
        }
      }
    }
  ],
  applications: [
    {
      name: '$APPLICATION_NAME',
      cache: [
        {
          name: '$APPLICATION_NAME',
          browser: { maxAgeSeconds: 7200 },
          edge: { maxAgeSeconds: 7200 }
        }
      ],
      rules: {
        request: [
          {
            name: 'Set storage origin for all requests _next_static and set cache policy',
            description: 'Serve Next.js static assets through edge connector and set cache policy',
            active: true,
            criteria: [[{ variable: '${uri}', conditional: 'if', operator: 'matches', argument: '^/_next/static/' }]],
            behaviors: [
              { type: 'set_connector', attributes: { value: '$CONNECTOR_NAME' } },
              { type: 'set_cache_policy', attributes: { value: '$APPLICATION_NAME' } },
              { type: 'deliver' }
            ]
          },
          {
            name: 'Deliver Static Assets and set cache policy',
            description: 'Serve static assets through edge connector and set cache policy',
            active: true,
            criteria: [[{ variable: '${uri}', conditional: 'if', operator: 'matches', argument: '.(css|js|ttf|woff|woff2|pdf|svg|jpg|jpeg|gif|bmp|png|ico|mp4|json)$' }]],
            behaviors: [
              { type: 'set_connector', attributes: { value: '$CONNECTOR_NAME' } },
              { type: 'set_cache_policy', attributes: { value: '$APPLICATION_NAME' } },
              { type: 'deliver' }
            ]
          },
          {
            name: 'Execute Function',
            description: 'Execute function for all requests',
            active: true,
            criteria: [[{ variable: '${uri}', conditional: 'if', operator: 'matches', argument: '^/' }]],
            behaviors: [
              { type: 'run_function', attributes: { value: '$FUNCTION_NAME' } },
              { type: 'forward_cookies' }
            ]
          }
        ]
      },
      functionsInstances: [
        {
          name: '$FUNCTION_INSTANCE_NAME',
          ref: '$FUNCTION_NAME'
        }
      ]
    }
  ],
  workloads: [
    {
      name: '$WORKLOAD_NAME',
      active: true,
      infrastructure: 1,
      deployments: [
        {
          name: '$DEPLOYMENT_NAME',
          current: true,
          active: true,
          strategy: { type: 'default', attributes: { application: '$APPLICATION_NAME' } }
        }
      ]
    }
  ]
}
```

O arquivo declara estes recursos:

- **Storage**: um bucket que recebe a pasta `.edge/assets`, onde o build grava os assets estáticos e os arquivos de cache do Next.js. Os Workloads podem ler e gravar no bucket.
- **Connector**: um connector de storage que lê o bucket. As duas primeiras regras enviam os caminhos `/_next/static/` e os tipos de arquivo estático para ele com `set_connector`.
- **Function**: o código de servidor do app, vinculado ao mesmo bucket para ler e gravar o cache do Next.js.
- **Application**: uma cache setting de 7.200 segundos no navegador e no cache da Azion, que as regras estáticas aplicam com `set_cache_policy`. A regra `Execute Function` executa a Function em todas as outras requisições e encaminha os cookies para ela.
- **Workload**: serve a Application em um domínio da Azion.

O primeiro deploy substitui cada placeholder `$` por um nome baseado no nome do projeto. Para mudar uma cache setting, como as opções de `cacheByCookie` e `cacheByQueryString`, consulte [Cache settings da aplicação](/pt-br/documentacao/devtools/cli/azion-config-js/#cache-settings-da-aplicacao). Para todas as outras chaves, consulte [azion.config.js](/pt-br/documentacao/devtools/cli/azion-config-js/).

## Faça o build do app

O primeiro build cria o `open-next.config.ts`, o arquivo de configuração do adaptador, na raiz do projeto. Em um terminal interativo, o build pergunta antes de criar o arquivo. `OPEN_NEXTJS_NO_INTERACTIVE_PROMPT=true` cria o arquivo sem perguntar, o que um job de CI ou um build remoto exige.

Para fazer o build do app sem a pergunta, execute este comando na pasta do app:

```bash
OPEN_NEXTJS_NO_INTERACTIVE_PROMPT=true azion build
```

O build grava a Function em `.edge/functions/worker.js`, os assets em `.edge/storage` e o manifesto em `.edge/manifest.json`. O arquivo `open-next.config.ts` que ele cria define os caches, a fila e o wrapper do adaptador:

```ts
import { defineAzionConfig } from "@aziontech/opennextjs-azion/config";
import StorageIncrementalCache from "@aziontech/opennextjs-azion/overrides/incremental-cache/storage-incremental-cache";
import MemoryCacheQueue from "@aziontech/opennextjs-azion/overrides/queue/memory-queue";
import StorageTagCache from "@aziontech/opennextjs-azion/overrides/tag-cache/storage-tag-cache";
import AzionWrapperNode from "@aziontech/opennextjs-azion/overrides/wrapper/azion-wrapper-node";

export default defineAzionConfig({
  incrementalCache: StorageIncrementalCache,
  queue: MemoryCacheQueue,
  wrapper: AzionWrapperNode,
  tagCache: StorageTagCache,
});
```

Faça o commit do `open-next.config.ts`. Os builds seguintes leem o arquivo e não o criam de novo.

## Execute o app localmente

Para fazer o build do app e servi-lo na sua máquina, execute este comando na pasta do app:

```bash
azion dev
```

O comando serve o build em `http://localhost:3333` e faz o build do app de novo quando um arquivo muda. Algumas APIs do Node.js e da Web se comportam de forma diferente na sua máquina e na Azion. Para esses limites, consulte [Problemas conhecidos](/pt-br/documentacao/devtools/runtime/frameworks/nextjs-compatibility/#problemas-conhecidos). Para todas as flags, consulte [Azion CLI dev](/pt-br/documentacao/devtools/cli/dev-comando/).

## Faça o deploy do app

Por padrão, o `azion deploy` envia o projeto e faz o build dele na Azion. Esse build remoto não tem terminal, então faça o commit do `open-next.config.ts` antes do deploy.

Para fazer o deploy do app, execute este comando na pasta do app:

```bash
azion deploy
```

O comando abre a página do Console que acompanha o deploy. Se o navegador não abrir, use a URL da página que o comando imprime. No final, o comando imprime a URL do domínio da Application, no formato `https://xxxxxxxxxx.map.azionedge.net`.

Para fazer o build na sua máquina e o deploy do resultado, execute `azion deploy --local`. Para a saída completa e todas as flags, consulte [Azion CLI deploy](/pt-br/documentacao/devtools/cli/deploy/).

O primeiro deploy pode levar vários minutos para responder em todas as localidades. Uma localidade que ainda não tem a Application responde com uma página `404` que diz `There's nothing here yet`. Aguarde e abra a URL novamente.
