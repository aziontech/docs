Você pode abrir uma [aplicação](/pt-br/documentacao/plataforma/applications/) no seu próprio domínio a partir de um dispositivo antes de [alterar os registros DNS do domínio](/pt-br/documentacao/guias/plataforma/migracao/apontar-dominio-para-a-azion/). O arquivo `hosts` desse dispositivo envia o domínio para a Azion, enquanto todos os outros visitantes continuam chegando ao seu provedor atual. Para executar uma aplicação na sua própria máquina, use [Azion CLI](/pt-br/documentacao/devtools/cli/) em vez disso.

---

## Pré-requisitos

- Uma aplicação servida por um workload. Para criar uma aplicação e servi-la, consulte [Primeiros passos com Applications](/pt-br/documentacao/plataforma/applications/primeiros-passos/).
- Seu domínio, [adicionado aos domínios desse workload](/pt-br/documentacao/guias/plataforma/migracao/configurar-dominio/). Para mais informações, consulte [Workloads](/pt-br/documentacao/plataforma/workloads/).
- Permissões de administrador no seu dispositivo. Linux e macOS concedem essas permissões por meio do `sudo`.
- Um terminal, como o Windows PowerShell ou o Terminal no macOS.
- No Windows, um editor de texto, como o Bloco de Notas.
- Uma conexão com a internet.

---

## Encontre os endereços IP do domínio do seu workload

O domínio do seu workload é o endereço `azionedge.net` que a Azion atribui ao workload. Ele resolve para endereços IP da Azion que dependem de onde o dispositivo está. Execute a consulta no dispositivo em que você vai testar.

Execute uma ferramenta de consulta DNS, como o `host`, com o domínio do seu workload no lugar de `<your-workload-domain>`:

```bash
host <your-workload-domain>
```

O comando imprime uma linha `has address` para cada endereço IP para o qual o domínio do workload resolve. Copie um desses endereços.

---

## Mapeie seu domínio para o endereço IP

O arquivo `hosts` mapeia nomes para endereços IP em um dispositivo. Adicione uma linha para cada domínio que você quer testar: o endereço IP que você copiou, um ou mais espaços e, em seguida, o domínio. Mapeie apenas um domínio que você adicionou ao workload.

Por exemplo, estas linhas enviam `example.com` e `www.example.com` para o endereço `192.0.2.10`:

```text
# Teste na Azion
192.0.2.10    example.com
192.0.2.10    www.example.com
```

O arquivo ignora o texto que vem depois de um `#` em uma linha. Um comentário como `# Teste na Azion` marca as linhas que você adiciona, para que você as encontre quando terminar.

O local do arquivo e o editor dependem do sistema operacional do seu dispositivo.

### Edite o arquivo hosts no Windows

No Windows, o arquivo `hosts` fica em `C:\Windows\System32\drivers\etc\`. Quando o Windows está instalado em outra unidade, a mesma pasta fica nessa unidade.

Para editar o arquivo no Windows:

<DocSteps>
  <DocStep title="Abra o Bloco de Notas como administrador">

  Abra o Bloco de Notas, ou outro editor de texto, com suas permissões de administrador.

  </DocStep>
  <DocStep title="Abra o arquivo hosts">

  Abra o arquivo `hosts` da pasta `etc`.

  </DocStep>
  <DocStep title="Adicione suas linhas">

  Adicione suas linhas depois da linha `localhost`.

  </DocStep>
  <DocStep title="Salve o arquivo">

  Selecione **Arquivo** > **Salvar**.

  </DocStep>
</DocSteps>

O arquivo `hosts` contém suas linhas, e o Windows resolve cada domínio delas para o endereço IP que você inseriu.

### Edite o arquivo hosts no Linux

No Linux, o arquivo é `/etc/hosts`. Para editá-lo com o editor `vim`:

<DocSteps>
  <DocStep title="Abra um terminal">

  Na maioria das distribuições, o terminal fica em **Applications** > **Utilities** > **Terminal**.

  </DocStep>
  <DocStep title="Abra o arquivo no vim">

  Execute este comando:

  ```bash
  sudo vim /etc/hosts
  ```

  </DocStep>
  <DocStep title="Digite sua senha">

  Digite sua senha do sistema e pressione **Enter**. O arquivo abre no `vim`.

  </DocStep>
  <DocStep title="Adicione suas linhas">

  Com as teclas de seta, vá até a linha depois de `localhost`. Pressione `i` para começar a digitar e, em seguida, adicione suas linhas.

  </DocStep>
  <DocStep title="Saia do modo de inserção">

  Pressione **Esc**.

  </DocStep>
  <DocStep title="Salve e feche o arquivo">

  Digite `:x` e pressione **Enter**.

  </DocStep>
</DocSteps>

O `vim` salva `/etc/hosts` e fecha, e o Linux resolve cada domínio das suas linhas para o endereço IP que você inseriu.

### Edite o arquivo hosts no macOS

No macOS, o arquivo é `/private/etc/hosts`. Para editá-lo com o editor `nano`:

<DocSteps>
  <DocStep title="Abra o Terminal">

  No **Launchpad**, procure **Terminal** e abra-o.

  </DocStep>
  <DocStep title="Abra o arquivo no nano">

  Execute este comando:

  ```bash
  sudo nano /private/etc/hosts
  ```

  </DocStep>
  <DocStep title="Digite sua senha">

  Digite sua senha do sistema e pressione **Enter**. O arquivo abre no `nano`.

  </DocStep>
  <DocStep title="Adicione suas linhas">

  Com as teclas de seta, vá até a linha depois de `localhost` e adicione suas linhas.

  </DocStep>
  <DocStep title="Salve o arquivo">

  Pressione **Ctrl+O** e, em seguida, pressione **Enter** para manter o nome do arquivo.

  </DocStep>
  <DocStep title="Feche o nano">

  Pressione **Ctrl+X**.

  </DocStep>
</DocSteps>

O `nano` salva `/private/etc/hosts` e fecha, e o macOS resolve cada domínio das suas linhas para o endereço IP que você inseriu.

## Abra a aplicação no seu domínio

Com o arquivo `hosts` salvo, as requisições do seu dispositivo para os domínios mapeados vão para a Azion. Isso vale mesmo enquanto os registros DNS públicos do domínio ainda apontam para o seu provedor atual.

Um navegador pode manter um cache de DNS próprio. Se ele já visitou seu domínio, ele pode reutilizar o endereço público que guardou em cache e ignorar o arquivo `hosts`. Para abrir o domínio sem esse cache, use uma destas opções:

- Uma janela privada ou anônima.
- Um navegador que você não usou para visitar o domínio.
- Seu navegador habitual, depois de limpar o cache dele.

Em seguida, digite seu domínio na barra de endereços. O navegador mostra a aplicação que o seu workload serve.

Teste a aplicação antes de alterar o DNS público do domínio. Depois, aponte os registros DNS do domínio para a Azion, ou [mova os nameservers dele](/pt-br/documentacao/guias/plataforma/migracao/migrar-ns-para-a-azion/) para [Edge DNS](/pt-br/documentacao/plataforma/edge-dns/). Quando terminar, exclua as linhas que você adicionou, para que o dispositivo volte a resolver o domínio pelo DNS público.
