Você pode criar uma exceção do [Web Application Firewall (WAF)](/pt-br/documentacao/plataforma/firewall/waf/), que tira uma parte de uma requisição do score de uma regra interna, pelo Azion Console, pela Azion CLI ou pela API. Para transformar várias requisições correspondidas em exceções de uma vez, consulte [Ajuste um WAF rule set](/pt-br/documentacao/guias/seguranca-de-aplicacoes/firewall-e-waf/tune-waf/).

## Crie a exceção

Uma exceção indica a regra interna que ela isenta, o caminho que cobre e ao menos uma condição que indica a parte da requisição. O Azion Console chama uma exceção de allowed rule, na aba **Allowed Rules** do rule set. Para todos os campos e as quinze match zones, consulte [WAF Exceptions](/pt-br/documentacao/plataforma/firewall/waf/custom-allowed-rules/#campos).

O exemplo elimina um falso positivo. Uma API em `/api/v1/data` lê um parâmetro de query string `filter` cujos valores carregam um apóstrofo:

```text
GET /api/v1/data?filter=name%20LIKE%20%27test%27
```

A regra interna `1013` corresponde ao apóstrofo, e um rule set com todas as famílias em `medium` recusa a requisição com `400`.

A comparação é definida uma vez para a exceção inteira: `regex` lê o caminho e a condição como expressões regulares, e `contains`, o padrão, não.

<Tabs client:visible sharedStore="interface">

<Fragment slot="panel.console">

### Console

Para criar a exceção no Azion Console:

<DocSteps>
  <DocStep title="Abra a página WAF Rules">

  Acesse [Azion Console](https://console.azion.com/) > **WAF Rules**.

  </DocStep>
  <DocStep title="Selecione o rule set que pontua a requisição" />
  <DocStep title="Selecione a aba Allowed Rules" />
  <DocStep title="Selecione Allowed Rule" />
  <DocStep title="Selecione a regra a isentar">

  Em **Rule ID**, selecione a regra que produziu o falso positivo. Neste exemplo, a regra `1013`.

  </DocStep>
  <DocStep title="Registre por que a requisição é permitida">

  Em **Description**, insira para que serve a exceção. Por exemplo: `Allow apostrophes in the data API filter`.

  </DocStep>
  <DocStep title="Restrinja a exceção a um caminho">

  Em **Path**, insira `/api/v1/data`.

  </DocStep>
  <DocStep title="Indique a parte da requisição">

  Em **Condition**, selecione _Specific Query String Value_ e insira `filter`, o nome do parâmetro, no campo **Value**.

  </DocStep>
  <DocStep title="Escolha a comparação">

  Deixe desativado o switch **Active** da seção **Regex** para `contains`, ou ative-o para `regex`.

  </DocStep>
  <DocStep title="Salve a exceção" />
</DocSteps>

A exceção aparece na aba **Allowed Rules**, em uma linha com **Rule ID**, **Description**, **Path**, **Conditions**, **Status**, **Last Editor** e **Last Modified**.

</Fragment>

<Fragment slot="panel.cli">

### CLI

A Azion CLI lê a exceção de um arquivo. A flag `--conditions` envia um array vazio com qualquer valor, e a API o recusa com `400` e `10049 Ensure this field has at least 1 elements.` Para criar a exceção com a Azion CLI:

<DocSteps>
  <DocStep title="Escreva a exceção em um arquivo">

  Salve o seguinte como `exception.json`:

  ```json
  {
    "rule_id": 1013,
    "name": "Allow apostrophes in the data API filter",
    "path": "/api/v1/data",
    "operator": "contains",
    "active": true,
    "conditions": [
      { "match": "specific_query_string_value", "value": "filter" }
    ]
  }
  ```

  </DocStep>
  <DocStep title="Crie a exceção">

  Substitua `<waf-id>` pelo ID do seu rule set:

  ```bash
  azion create waf-exceptions --waf-id <waf-id> --file exception.json
  ```

  </DocStep>
  <DocStep title="Leia a saída">

  O comando imprime o ID da exceção:

  ```text
  Created WAF Exception with ID <exception-id>
  ```

  </DocStep>
</DocSteps>

Anote o ID. A próxima seção lê a exceção de volta com ele.

</Fragment>

<Fragment slot="panel.api">

### API

Para criar a exceção com a API:

<DocSteps>
  <DocStep title="Envie a requisição de criação">

  Substitua `<waf-id>` pelo ID do seu rule set e `[TOKEN VALUE]` pelo seu personal token:

  ```bash
  curl --request POST \
    --url https://api.azion.com/v4/workspace/wafs/<waf-id>/exceptions \
    --header 'Accept: application/json' \
    --header 'Authorization: Token [TOKEN VALUE]' \
    --header 'Content-Type: application/json' \
    --data '{
    "rule_id": 1013,
    "name": "Allow apostrophes in the data API filter",
    "path": "/api/v1/data",
    "operator": "contains",
    "active": true,
    "conditions": [
      { "match": "specific_query_string_value", "value": "filter" }
    ]
  }'
  ```

  </DocStep>
  <DocStep title="Leia a resposta">

  A API responde `202`, e `"state": "pending"` significa que a exceção ainda está se propagando:

  ```json
  {
    "state": "pending",
    "data": {
      "id": 123456,
      "rule_id": 1013,
      "name": "Allow apostrophes in the data API filter",
      "path": "/api/v1/data",
      "conditions": [
        { "match": "specific_query_string_value", "value": "filter" }
      ],
      "operator": "contains",
      "active": true,
      "last_editor": "user@example.com",
      "last_modified": "2026-01-01T12:00:00.000000Z"
    }
  }
  ```

  </DocStep>
</DocSteps>

Anote o `id`. A próxima seção lê a exceção de volta com ele. Dos seis campos do corpo, só `name` e `conditions` são obrigatórios: `rule_id` tem `0` como padrão, que representa todas as regras, `operator` tem `contains` e `active` tem `true`.

</Fragment>

</Tabs>

A exceção isenta a regra `1013` no valor de `filter` em `/api/v1/data`, e a regra continua pontuando todos os outros parâmetros e caminhos. Ela se propaga pela infraestrutura distribuída da Azion antes que as requisições a reflitam, então uma requisição recusada logo depois da criação não quebrou nada. Espere e envie-a de novo.

:::caution[Atenção]
Duas formas não eliminaram a correspondência nas execuções observadas. Uma condição _Specific Query String Name_ com `filter` deixou o valor de `filter` sendo pontuado, e um **Path** que continha só o início do caminho da requisição não cobriu a requisição. Defina **Path** com o caminho exato da requisição, ou deixe-o vazio para cobrir todo caminho.
:::

## Confirme o que a exceção cobre

:::caution[Atenção]
Uma chave que a forma da condição não carrega é descartada, não recusada. Uma condição enviada como `{"match": "any_http_header_value", "name": "cookie"}` é aceita com `202` e é lida de volta como `{"match": "any_http_header_value"}`. A exceção então cobre todos os headers da requisição em vez de um, e a resposta não indica isso.
:::

Para perceber uma chave descartada, leia a exceção de volta e compare as `conditions` dela com as que você enviou.

<Fragment slot="panel.cli">

### CLI

`azion describe waf-exceptions` imprime a exceção armazenada. Leia essa saída em vez de `azion list waf-exceptions`, cuja coluna **RULE ID** não imprime a regra. Para ler a exceção de volta com a Azion CLI:

<DocSteps>
  <DocStep title="Descreva a exceção">

  Substitua `<waf-id>` e `<exception-id>` pelos seus IDs:

  ```bash
  azion describe waf-exceptions --waf-id <waf-id> --exception-id <exception-id> --format json
  ```

  </DocStep>
  <DocStep title="Compare as condições com o que você enviou">

  O comando imprime a exceção com as chaves em ordem alfabética:

  ```json
  {
   "active": true,
   "conditions": [
    {
     "match": "specific_query_string_value",
     "value": "filter"
    }
   ],
   "id": 123457,
   "last_editor": "user@example.com",
   "last_modified": "2026-01-01T12:00:00.000000Z",
   "name": "Allow apostrophes in the data API filter",
   "operator": "contains",
   "path": "/api/v1/data",
   "rule_id": 1013
  }
  ```

  </DocStep>
</DocSteps>

A condição armazenada carrega a chave `value`. Uma condição armazenada que contém só `match` cobre todos os parâmetros de query string.

</Fragment>

### API

Para ler a exceção de volta com a API:

<DocSteps>
  <DocStep title="Envie a requisição de leitura">

  Substitua `<waf-id>` e `<exception-id>` pelos seus IDs:

  ```bash
  curl --request GET \
    --url https://api.azion.com/v4/workspace/wafs/<waf-id>/exceptions/<exception-id> \
    --header 'Accept: application/json' \
    --header 'Authorization: Token [TOKEN VALUE]'
  ```

  </DocStep>
  <DocStep title="Compare as condições com o que você enviou">

  A API responde `200` com a exceção armazenada:

  ```json
  {
    "data": {
      "id": 123456,
      "rule_id": 1013,
      "name": "Allow apostrophes in the data API filter",
      "path": "/api/v1/data",
      "conditions": [
        { "match": "specific_query_string_value", "value": "filter" }
      ],
      "operator": "contains",
      "active": true,
      "last_editor": "user@example.com",
      "last_modified": "2026-01-01T12:00:00.000000Z"
    }
  }
  ```

  </DocStep>
</DocSteps>

A condição armazenada carrega a chave `value`. Uma condição armazenada que contém só `match` cobre todos os parâmetros de query string.
