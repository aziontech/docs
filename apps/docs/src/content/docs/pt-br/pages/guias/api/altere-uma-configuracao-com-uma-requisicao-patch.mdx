Você pode alterar uma configuração de um recurso da [API da Azion](/pt-br/documentacao/devtools/api/) v4 com uma requisição `PATCH`. O `PATCH` mantém toda configuração que você deixa fora do corpo. Uma requisição `PUT`, por outro lado, substitui o recurso inteiro. A maioria dos endpoints da API v4 para um único recurso aceita os dois métodos.

Os exemplos alteram um [cache setting](/pt-br/documentacao/plataforma/applications/cache/cache-settings/) de uma [Application](/pt-br/documentacao/plataforma/applications/).

---

## Pré-requisitos

- Um personal token. Para criar um, consulte [Gerencie personal tokens](/pt-br/documentacao/guias/plataforma/conta-e-billing/personal-tokens/).
- `curl`, para chamar a API, e `jq`, para editar o corpo JSON de uma requisição `PUT`.
- Uma Application com um cache setting. Para criar um, consulte [Crie um cache setting](/pt-br/documentacao/guias/performance-e-confiabilidade/cache-e-purge/ajustar-cache-settings/).

---

## Encontre o ID do cache setting

O caminho de item de um cache setting leva dois IDs: o da Application e o do cache setting.

Para encontrar o ID do cache setting:

1. Guarde o seu token e o ID da Application em variáveis do shell. Substitua os dois valores pelos seus:

   ```bash
   export AZION_API_TOKEN="[TOKEN VALUE]"
   APPLICATION_ID=<your-application-id>
   ```

2. Liste os cache settings da Application. O parâmetro `fields` limita cada resultado ao ID e ao nome:

   ```bash
   curl --silent "https://api.azion.com/v4/workspace/applications/$APPLICATION_ID/cache_settings?fields=id,name" \
     --header "Authorization: Token $AZION_API_TOKEN"
   ```

   ```json
   {
     "count": 1,
     "total_pages": 1,
     "page": 1,
     "page_size": 10,
     "next": null,
     "previous": null,
     "results": [
       {"id": 395100, "name": "static-assets"}
     ]
   }
   ```

3. Guarde o `id` do cache setting que você quer alterar. Substitua o valor por esse `id`:

   ```bash
   CACHE_SETTING_ID=<your-cache-setting-id>
   ```

`APPLICATION_ID` e `CACHE_SETTING_ID` guardam os dois IDs do caminho do cache setting.

## Altere uma configuração com PATCH

Um corpo de `PATCH` leva só as configurações a alterar. Uma configuração dentro de um objeto aninhado, como `max_age` dentro de `browser_cache`, também muda sozinha.

`browser_cache.max_age` define o tempo de cache no navegador só enquanto `browser_cache.behavior` for `override`. Com `honor`, o navegador mantém os cabeçalhos `Cache-Control` e `Expires` que a sua origem envia.

Envie uma requisição `PATCH` que define o tempo de cache no navegador como 600 segundos. Substitua os três valores pelos seus:

```bash
export AZION_API_TOKEN="[TOKEN VALUE]"
APPLICATION_ID=<your-application-id>
CACHE_SETTING_ID=<your-cache-setting-id>
curl --silent --request PATCH "https://api.azion.com/v4/workspace/applications/$APPLICATION_ID/cache_settings/$CACHE_SETTING_ID" \
  --header "Authorization: Token $AZION_API_TOKEN" \
  --header 'Content-Type: application/json' \
  --data '{"browser_cache": {"max_age": 600}}'
```

A resposta traz o cache setting inteiro. Este trecho mostra `browser_cache` e `modules.cache`, o cache que a Azion guarda:

```json
{
  "state": "executed",
  "data": {
    "id": 395100,
    "name": "static-assets",
    "browser_cache": {"behavior": "override", "max_age": 600},
    "modules": {
      "cache": {"behavior": "override", "max_age": 86400, ...},
      ...
    },
    ...
  }
}
```

O tempo de cache no navegador é de 600 segundos, porque `browser_cache.behavior` é `override` neste cache setting. O `behavior` dele e as configurações de `modules.cache` mantêm os seus valores.

## Substitua o cache setting com PUT

Um corpo de `PUT` precisa levar toda configuração que você quer manter, por isso você o monta a partir de uma cópia salva do cache setting.

:::caution[Atenção]
Uma configuração que o corpo de um `PUT` deixa de fora volta ao valor padrão. Em um cache setting, um corpo de `PUT` com só `name` e `browser_cache` define `modules.cache` como `"behavior": "honor"` e `"max_age": 60`. Um corpo sem um campo obrigatório, como `name`, retorna `400` com o código `10059`.
:::

Para substituir o cache setting:

1. Salve o cache setting atual em um arquivo. Substitua os três valores pelos seus:

   ```bash
   export AZION_API_TOKEN="[TOKEN VALUE]"
   APPLICATION_ID=<your-application-id>
   CACHE_SETTING_ID=<your-cache-setting-id>
   curl --silent "https://api.azion.com/v4/workspace/applications/$APPLICATION_ID/cache_settings/$CACHE_SETTING_ID" \
     --header "Authorization: Token $AZION_API_TOKEN" \
   > cache-setting.json
   ```

   O comando não imprime nada. O arquivo `cache-setting.json` guarda o cache setting dentro de `data`.

2. Altere a cópia e envie-a em uma requisição `PUT`. Este filtro do `jq` define `modules.cache.max_age` como 3.600 segundos e passa todo o resto sem alteração:

   ```bash
   jq '.data | .modules.cache.max_age = 3600' cache-setting.json \
   | curl --silent --request PUT "https://api.azion.com/v4/workspace/applications/$APPLICATION_ID/cache_settings/$CACHE_SETTING_ID" \
     --header "Authorization: Token $AZION_API_TOKEN" \
     --header 'Content-Type: application/json' \
     --data @-
   ```

   ```json
   {
     "state": "executed",
     "data": {
       "id": 395100,
       "name": "static-assets",
       "browser_cache": {"behavior": "override", "max_age": 600},
       "modules": {
         "cache": {"behavior": "override", "max_age": 3600, ...},
         ...
       },
       ...
     }
   }
   ```

`modules.cache.max_age` é de 3.600 segundos, e toda outra configuração da cópia continua igual. Com `honor` em `modules.cache.behavior`, a Azion usa `max_age` só quando a sua origem não envia nem `Cache-Control` nem `Expires`. Você não precisa remover os campos `id` e `created_at` da cópia: a requisição `PUT` os aceita.
