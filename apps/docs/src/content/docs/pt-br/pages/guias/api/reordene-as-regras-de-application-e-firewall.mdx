Você pode reordenar as regras de uma [Application](/pt-br/documentacao/plataforma/applications/) ou de um [Firewall](/pt-br/documentacao/plataforma/firewall/) com uma requisição `PUT` à [API da Azion](/pt-br/documentacao/devtools/api/) v4. A requisição envia um array `order` com o ID de cada regra da lista, na nova ordem. Uma lista tem as regras de uma fase da Application, ou todas as regras de um Firewall.

Para reordenar regras de Firewall pelo Azion Console ou pela Azion CLI, consulte [Altere a ordem das regras de Firewall](/pt-br/documentacao/guias/seguranca-de-aplicacoes/bots-e-rede/alterar-a-ordem-das-regras-de-firewall/). Para reordenar regras de Application no Azion Console, mova-as na lista da aba **Rules Engine**. Para o comando da Azion CLI, consulte a [seção CLI do Rules Engine para Applications](/pt-br/documentacao/plataforma/applications/rules-engine/#cli).

---

## Pré-requisitos

- Um personal token. Para criar um, consulte [Gerencie personal tokens](/pt-br/documentacao/guias/plataforma/conta-e-billing/personal-tokens/).
- `curl`, para chamar a API.
- Uma Application com duas ou mais regras na fase que você quer reordenar, ou um Firewall com duas ou mais regras.

---

## Reordene as regras de requisição de uma Application

O campo `order` de uma regra é a posição dela na fase, a partir de `0`. A requisição de reordenação define todas as posições da fase de uma só vez.

Para reordenar as regras de requisição:

1. Guarde o seu token e o ID da Application em variáveis do shell. Substitua os dois valores pelos seus:

   <Code client:visible lang="bash" code={`export AZION_API_TOKEN="[TOKEN VALUE]"
   APPLICATION_ID=<your-application-id>`} />

2. Liste as regras de requisição na ordem atual. O parâmetro `fields` mantém o ID, o nome e a posição de cada regra:

   <Code client:visible lang="bash" code={`curl --silent "https://api.azion.com/v4/workspace/applications/$APPLICATION_ID/request_rules?fields=id,name,order&ordering=order&page_size=100" \\
   \x20 --header "Authorization: Token $AZION_API_TOKEN"`} />

   A resposta lista as regras por posição:

   ```json
   {
     "count": 3,
     ...
     "results": [
       {
         "id": 1550922,
         "name": "Redirect old blog",
         "order": 0
       },
       {
         "id": 1550924,
         "name": "Deny admin",
         "order": 1
       },
       {
         "id": 1550927,
         "name": "Bypass cache for API",
         "order": 2
       }
     ]
   }
   ```

   Uma página tem no máximo 100 regras. Se `next` não for `null`, leia também as próximas páginas. Para ler todas as páginas, consulte [Percorra uma lista com filtros e ordenação](/pt-br/documentacao/guias/desenvolvimento-de-aplicacoes/automacao/percorra-uma-lista-com-filtros-e-ordenacao/).

3. Envie uma requisição `PUT` com todos os IDs de regra da fase na nova ordem. Substitua os IDs pelos seus. Este exemplo move `Deny admin` para a primeira posição:

   <Code client:visible lang="bash" code={`curl --silent --request PUT "https://api.azion.com/v4/workspace/applications/$APPLICATION_ID/request_rules/order" \\
   \x20 --header "Authorization: Token $AZION_API_TOKEN" \\
   \x20 --header 'Content-Type: application/json' \\
   \x20 --data '{"order": [1550924, 1550922, 1550927]}'`} />

   A API responde `202`. A resposta traz a primeira página das regras na nova ordem, com um `page_size` de 10. Este trecho mostra o ID, o nome e a posição de cada regra:

   ```json
   {
     "count": 3,
     ...
     "page_size": 10,
     ...
     "results": [
       {
         "id": 1550924,
         "name": "Deny admin",
         ...
         "order": 0,
         ...
       },
       {
         "id": 1550922,
         "name": "Redirect old blog",
         ...
         "order": 1,
         ...
       },
       {
         "id": 1550927,
         "name": "Bypass cache for API",
         ...
         "order": 2,
         ...
       }
     ]
   }
   ```

   Com mais de 10 regras, a resposta traz as 10 primeiras, e `count` e `total_pages` informam o restante. A nova ordem vale mesmo assim para todas as regras que você enviou: liste as regras de novo para ler todas elas.

`Deny admin` é a primeira regra de requisição da Application. A nova ordem só chega ao tráfego depois de se propagar, e a Azion não garante nenhum tempo de propagação. Para conferir, repita uma requisição que atende aos critérios de uma regra movida até que todas as respostas sejam as esperadas. Para a ordem em que uma Application executa as regras dela e para a propagação, consulte [Como Applications funciona](/pt-br/documentacao/plataforma/applications/como-funciona/).

## Reordene as regras de resposta de uma Application

A fase de resposta tem a sua própria lista de posições e o seu próprio caminho de reordenação, `response_rules/order`.

Para reordenar as regras de resposta:

1. Guarde o seu token e o ID da Application em variáveis do shell. Substitua os dois valores pelos seus:

   <Code client:visible lang="bash" code={`export AZION_API_TOKEN="[TOKEN VALUE]"
   APPLICATION_ID=<your-application-id>`} />

2. Liste as regras de resposta na ordem atual:

   <Code client:visible lang="bash" code={`curl --silent "https://api.azion.com/v4/workspace/applications/$APPLICATION_ID/response_rules?fields=id,name,order&ordering=order&page_size=100" \\
   \x20 --header "Authorization: Token $AZION_API_TOKEN"`} />

   A resposta lista as regras por posição:

   ```json
   {
     "count": 2,
     ...
     "results": [
       {
         "id": 1550944,
         "name": "Add frame header",
         "order": 0
       },
       {
         "id": 1550945,
         "name": "Remove server header",
         "order": 1
       }
     ]
   }
   ```

   Uma página tem no máximo 100 regras. Se `next` não for `null`, leia também as próximas páginas.

3. Envie uma requisição `PUT` com todos os IDs de regra de resposta na nova ordem. Substitua os IDs pelos seus:

   <Code client:visible lang="bash" code={`curl --silent --request PUT "https://api.azion.com/v4/workspace/applications/$APPLICATION_ID/response_rules/order" \\
   \x20 --header "Authorization: Token $AZION_API_TOKEN" \\
   \x20 --header 'Content-Type: application/json' \\
   \x20 --data '{"order": [1550945, 1550944]}'`} />

   A API responde `202`. A resposta traz a primeira página das regras de resposta na nova ordem:

   ```json
   {
     "count": 2,
     ...
     "results": [
       {
         "id": 1550945,
         "name": "Remove server header",
         ...
         "order": 0,
         ...
       },
       {
         "id": 1550944,
         "name": "Add frame header",
         ...
         "order": 1,
         ...
       }
     ]
   }
   ```

`Remove server header` é a primeira regra de resposta da Application, e as regras de requisição mantêm as suas posições. A nova ordem só chega ao tráfego depois de se propagar, e a Azion não garante nenhum tempo de propagação. Para conferir, repita uma requisição que atende aos critérios de uma regra movida até que todas as respostas sejam as esperadas. Para mais informações, consulte [Propagação](/pt-br/documentacao/plataforma/applications/como-funciona/#propagacao).

## Reordene as regras de um Firewall

Um Firewall tem uma lista de [regras](/pt-br/documentacao/plataforma/firewall/rules-engine/), e o caminho de reordenação dele é `request_rules/order` sob o Firewall.

Para reordenar as regras de um Firewall:

1. Guarde o seu token e o ID do Firewall em variáveis do shell. Substitua os dois valores pelos seus:

   <Code client:visible lang="bash" code={`export AZION_API_TOKEN="[TOKEN VALUE]"
   FIREWALL_ID=<your-firewall-id>`} />

2. Liste as regras na ordem atual:

   <Code client:visible lang="bash" code={`curl --silent "https://api.azion.com/v4/workspace/firewalls/$FIREWALL_ID/request_rules?fields=id,name,order&ordering=order&page_size=100" \\
   \x20 --header "Authorization: Token $AZION_API_TOKEN"`} />

   A resposta lista as regras por posição:

   ```json
   {
     "count": 2,
     ...
     "results": [
       {
         "id": 170225,
         "name": "Deny wp-login",
         "order": 0
       },
       {
         "id": 170226,
         "name": "Drop xmlrpc",
         "order": 1
       }
     ]
   }
   ```

   Uma página tem no máximo 100 regras. Se `next` não for `null`, leia também as próximas páginas.

3. Envie uma requisição `PUT` com todos os IDs de regra do Firewall na nova ordem. Substitua os IDs pelos seus:

   <Code client:visible lang="bash" code={`curl --silent --request PUT "https://api.azion.com/v4/workspace/firewalls/$FIREWALL_ID/request_rules/order" \\
   \x20 --header "Authorization: Token $AZION_API_TOKEN" \\
   \x20 --header 'Content-Type: application/json' \\
   \x20 --data '{"order": [170226, 170225]}'`} />

   A API responde `202`. A resposta traz a primeira página das regras do Firewall na nova ordem:

   ```json
   {
     "count": 2,
     ...
     "results": [
       {
         "id": 170226,
         "name": "Drop xmlrpc",
         ...
         "order": 0
       },
       {
         "id": 170225,
         "name": "Deny wp-login",
         ...
         "order": 1
       }
     ]
   }
   ```

`Drop xmlrpc` é a primeira regra do Firewall. A nova ordem só chega ao tráfego depois de se propagar, e a Azion não garante nenhum tempo de propagação. Para conferir, repita uma requisição que atende aos critérios de uma regra movida até que todas as respostas sejam as esperadas. Para a ordem em que um Firewall executa as regras dele e para a propagação, consulte [Como Firewall funciona](/pt-br/documentacao/plataforma/firewall/como-funciona/).

## Corrija uma ordem rejeitada

A API rejeita um array `order` que não lista cada regra da fase, ou do Firewall, exatamente uma vez. Nos três caminhos de reordenação, ela responde `400`, mantém as posições atuais e informa o problema em `errors[0].code`:

| Código | Título | Causa | Correção |
| --- | --- | --- | --- |
| `25002` | Missing Rules In Order | O array deixa de fora uma regra, ou está vazio. | Liste de novo todas as páginas de regras e envie todos os IDs. |
| `25001` | Invalid Rules | O array tem um ID que não é uma regra desta lista. | Remova o ID. |
| `25000` | Duplicated Rules | O array tem um ID duas vezes. | Mantenha uma cópia do ID. |

Com `25001`, `meta.not_found_ids` lista os IDs que não são regras da lista. Um ID de regra de requisição em uma ordem de resposta é um deles. Com `25000`, `meta.duplicated_ids` lista os IDs repetidos.

Por exemplo, um array que deixa de fora uma das regras de requisição retorna este corpo:

```json
{
  "errors": [
    {
      "code": "25002",
      "title": "Missing Rules In Order",
      "detail": "When ordering you should provide the order for all rules.",
      "status": "400",
      "source": {
        "pointer": "/data/order"
      }
    }
  ]
}
```

Depois da correção, a requisição `PUT` retorna a primeira página das regras na nova ordem.
