Você pode implantar uma aplicação Next.js estática na Azion a partir do template Next.js Static Boilerplate no Azion Console. Para criar uma aplicação sem um template, consulte [Primeiros passos com Applications](/pt-br/documentacao/plataforma/applications/primeiros-passos/).

O Next.js Static Boilerplate cria uma single-page application (SPA) Next.js na infraestrutura distribuída da Azion. Ele automatiza várias etapas, do gerenciamento do repositório até a implantação. O template usa Next.js `14.1.4`.

A implantação cria um repositório no GitHub para o seu projeto, uma [aplicação](/pt-br/documentacao/plataforma/applications/) que o entrega, um domínio para acessá-lo e uma função para lógica personalizada. A aplicação usa [Functions](/pt-br/documentacao/plataforma/functions/), e o uso dele pode gerar custos. Para mais informações, consulte [Preços](/pt-br/documentacao/fundamentos/precos/).

---

## Pré-requisitos

- Uma conta Azion. Para criar uma, consulte [Criar uma conta](/pt-br/documentacao/fundamentos/criar-uma-conta/).
- Acesso ao Azion Console. Para entrar, consulte [Como acessar o Azion Console](/pt-br/documentacao/guias/plataforma/conta-e-billing/como-acessar-o-azion-console/).
- Uma [conta no GitHub](https://github.com/signup). A Azion se conecta a essa conta e cria nela o repositório do projeto.

## Implante o template

O Next.js Static Boilerplate abre como um formulário de configuração no Azion Console, e um asterisco marca cada campo obrigatório.

Para implantar o template:

<DocSteps>
  <DocStep title="Abra o template">

  Acesse [Next.js Static Boilerplate](https://console.azion.com/create/nextjs/next-static-boilerplate) no Azion Console. O formulário de configuração abre.

  </DocStep>
  <DocStep title="Conecte a Azion à sua conta do GitHub">

  Uma janela abre para confirmar a instalação do [Azion GitHub App](/pt-br/documentacao/guias/desenvolvimento-de-aplicacoes/automacao/azion-github-app/), que conecta a sua conta do GitHub à Azion. Nessa janela, defina as permissões do app e o acesso aos repositórios.

  </DocStep>
  <DocStep title="Selecione o Git scope com o qual trabalhar" />
  <DocStep title="Nomeie a aplicação">

  Insira um nome único e fácil de lembrar. O bucket de armazenamento e a função que o template cria recebem o mesmo nome. Se o nome já estiver em uso, a plataforma retorna uma mensagem de erro.

  </DocStep>
  <DocStep title="Inicie a implantação">

  Selecione **Deploy**.

  </DocStep>
</DocSteps>

Uma janela mostra os logs da implantação enquanto ela é executada. Quando a implantação termina, a página mostra os detalhes da aplicação, um link para abri-la no navegador e opções para continuar.

Ao final da implantação, você tem:

- Um repositório no GitHub criado a partir do [exemplo do Next.js Static Boilerplate](https://github.com/aziontech/azion-samples/tree/dev/templates/nextjs/nextjs-static-boilerplate-14), com as dependências instaladas.
- Uma GitHub Action nesse repositório que implanta cada push, para implantação contínua.
- Um commit no repositório que registra a versão implantada e o timestamp da implantação, para que o histórico de implantações continue rastreável.
- Uma aplicação na Azion Web Platform, com um domínio que hospeda o projeto Next.js e uma função para lógica personalizada.

O template faz o build do projeto com recursos da Azion Web Platform.

O link pode levar alguns minutos para começar a entregar a aplicação, enquanto a configuração dela se propaga pela infraestrutura distribuída da Azion. Se a página não carregar, aguarde alguns minutos e abra o link novamente.

## Atualize o projeto

Cada push para o repositório do GitHub que o Next.js Static Boilerplate cria é implantado automaticamente.

Para atualizar o projeto implantado, faça push das suas alterações para esse repositório. A Azion implanta as alterações, e a aplicação entrega a nova versão.

## Suporte a static exports

O núcleo do Next.js oferece suporte a static exports. Você pode iniciar um projeto como um site estático ou uma SPA e, depois, adicionar recursos que exigem um servidor. Com um static export, o Next.js gera um arquivo HTML por rota, o que divide uma SPA estrita em arquivos HTML individuais. Qualquer servidor web que entregue assets estáticos HTML, CSS e JavaScript pode hospedar o projeto.

Um static export oferece suporte a alguns recursos do Next.js e não a outros. Leve as duas listas em consideração ao desenvolver e gerenciar o projeto. Para mais informações, consulte [Static exports](https://nextjs.org/docs/app/building-your-application/deploying/static-exports) na documentação do Next.js.

### Recursos suportados

- Componentes do servidor
- Componentes do cliente
- Otimização de imagem
- Otimização de imagem com `next/image`, quando você define um loader de imagem personalizado em `next.config.js`
- Manipuladores de rota
- APIs do navegador

### Recursos não suportados

Esses recursos exigem um servidor Node.js, ou uma lógica dinâmica que o processo de build não consegue computar, então um static export não oferece suporte a eles:

- Rotas dinâmicas com `dynamicParams: true`
- Rotas dinâmicas sem `generateStaticParams()`
- Manipuladores de rota que dependem da requisição
- Cookies
- Rewrites
- Redirecionamentos
- Cabeçalhos
- Middleware
- Regeneração estática incremental
- Otimização de imagem com o loader padrão
- Modo draft

## Gerencie a aplicação

As configurações que o Next.js Static Boilerplate aplica podem não servir para a sua aplicação. Você pode alterar qualquer uma delas a qualquer momento pelo Azion Console.

Para abrir as configurações da aplicação:

<DocSteps>
  <DocStep title="Abra a lista de aplicações">

  Acesse [Azion Console](https://console.azion.com/) > **Applications**. A lista mostra todas as aplicações que você criou, em ordem alfabética.

  </DocStep>
  <DocStep title="Selecione a aplicação que o template criou">

  Para encontrá-la em uma lista longa, busque pelo nome dela. A busca filtra a lista apenas pelo nome da aplicação.

  </DocStep>
</DocSteps>

A aplicação abre em uma página que reúne todas as configurações que você pode definir. Para mais informações, consulte [Main Settings](/pt-br/documentacao/plataforma/applications/main-settings/), [Rules Engine para Applications](/pt-br/documentacao/plataforma/applications/rules-engine/) e [Device Groups](/pt-br/documentacao/plataforma/applications/device-groups/).

## Adicione um domínio personalizado

A implantação do Next.js Static Boilerplate atribui à aplicação um domínio de [workload](/pt-br/documentacao/plataforma/workloads/) no formato `xxxxxxxxxx.map.azionedge.net`, que um navegador consegue abrir. Para entregar a aplicação em um domínio seu, adicione um domínio personalizado. Para listar o domínio no workload e apontar o registro DNS dele para o workload, consulte [Adicione um domínio a um workload](/pt-br/documentacao/guias/plataforma/migracao/configurar-dominio/). Para mais informações, consulte [Domains](/pt-br/documentacao/plataforma/workloads/domains/).
