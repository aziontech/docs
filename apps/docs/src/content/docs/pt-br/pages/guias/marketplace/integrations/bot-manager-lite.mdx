Você pode instalar o [Bot Manager Lite](/pt-br/documentacao/plataforma/firewall/bot-manager/bot-manager-lite/) pelo Azion Marketplace e executá-lo nas requisições ao seu Workload, pelo Azion Console, começando sem nenhum Firewall. Para criar a Function Instance e a regra com a Azion CLI ou com a API, e para enviar uma requisição que prova que a Function a pontuou, consulte [Primeiros passos com Bot Manager](/pt-br/documentacao/plataforma/firewall/bot-manager/primeiros-passos/).

---

## Pré-requisitos

- Uma conta Azion. Para entrar, consulte [Como acessar o Azion Console](/pt-br/documentacao/guias/plataforma/conta-e-billing/como-acessar-o-azion-console/).
- Uma Application servida por um [Workload](/pt-br/documentacao/plataforma/workloads/), em um domínio no formato `<id>.map.azionedge.net` ou em um domínio seu.
- Ativar um recurso da plataforma pode gerar custos de uso. Para as métricas pelas quais o Bot Manager é cobrado, consulte [Preços](/pt-br/documentacao/fundamentos/precos/#bot-manager).

## Instale a integração pelo Marketplace

A Function é instalada uma vez por conta, e a instalação é feita no Azion Console. Para instalá-la:

<DocSteps>
  <DocStep title="Abra o Marketplace">

  Acesse [Azion Console](https://console.azion.com/) > **Marketplace**.

  </DocStep>
  <DocStep title="Encontre a integração">

  Encontre a integração Bot Manager Lite entre os cards e selecione o card dela. Os filtros **Category**, **Type** e **Vendor** estreitam os cards.

  </DocStep>
  <DocStep title="Selecione Install" />
</DocSteps>

O card mostra `Successfully installed!` e `Latest version installed!`, e a Function aparece na lista **Function** do drawer **Create Instance**. Em Azion Console > **Functions**, em **Edge Libraries**, a coluna **Vendor** mostra o fornecedor dela.

## Crie o Firewall

O [Firewall](/pt-br/documentacao/plataforma/firewall/) guarda a Function Instance e a regra que a executa. Para criar um:

<DocSteps>
  <DocStep title="Abra a página Firewalls">

  Acesse [Azion Console](https://console.azion.com/) > **Firewalls** e selecione **Firewall**.

  </DocStep>
  <DocStep title="Nomeie o Firewall">

  Na seção **General**, insira um **Name**. Por exemplo: `storefront-firewall`.

  </DocStep>
  <DocStep title="Confirme que Functions está ativado">

  Na seção **Modules**, o switch **Functions** é o que permite a um Firewall executar uma Function instalada. Um Firewall criado nesta página, com a Azion CLI ou com a API começa com **Functions** ativado.

  </DocStep>
  <DocStep title="(Opcional) Ative Debug Rules">

  Na seção **Debug Rules**, ative o switch **Active**. O Firewall passa então a registrar as regras que executou para cada requisição, o que informa se a regra deste guia foi executada.

  </DocStep>
  <DocStep title="Selecione Save" />
</DocSteps>

O Firewall carrega uma aba **Functions Instances** enquanto **Functions** permanecer ativado. Para cada configuração deste formulário, consulte [Defina as configurações principais de um Firewall](/pt-br/documentacao/guias/seguranca-de-aplicacoes/firewall-e-waf/firewall-definir-main-settings/).

## Crie a Function Instance

Uma [Function Instance](/pt-br/documentacao/plataforma/firewall/functions-instances/) tira toda a sua configuração de um objeto JSON. Uma chave que o objeto deixa de fora fica ausente da Function Instance. Para ver como uma Function Instance armazena os argumentos, consulte [Campos](/pt-br/documentacao/plataforma/firewall/bot-manager/argumentos/#campos).

O Bot Manager Lite entrega um default para oito argumentos. Uma Function Instance criada pela API sem o campo `args` recebe uma cópia deles. Entre eles estão um `threshold` de `30`, uma `action` de `deny`, `internal_logs` em `0` e um `log_tag` de `bot-manager-instance`.

Quatro argumentos bastam para uma primeira Function Instance:

```json
{
  "threshold": 30,
  "action": "deny",
  "internal_logs": 2,
  "log_tag": "storefront-bots"
}
```

`threshold` é o score que uma requisição alcança antes de a Function aplicar `action` a ela. `internal_logs` em `2` grava uma linha de report para toda requisição, incluindo uma que pontua `0`, então os primeiros dias de tráfego se tornam legíveis. `log_tag` identifica esta Function Instance nessas linhas, então dê a cada Function Instance uma tag própria. Uma `action` de `allow`, até você saber como o seu próprio tráfego pontua, impede a Function Instance de recusar um cliente. Para essa janela e o custo dela, consulte [Boas práticas de Firewall](/pt-br/documentacao/plataforma/firewall/boas-praticas/#bot-manager).

:::caution[Atenção]
A API verifica se os argumentos são um objeto ou um array JSON e não verifica nenhuma chave. Um argumento escrito errado, como `thresold`, é armazenado como foi digitado, a API e a Azion CLI não levantam erro, e `threshold` fica ausente da Function Instance. Para ver o que a Function faz sem ele, consulte [Threshold](/pt-br/documentacao/plataforma/firewall/bot-manager/argumentos/#threshold).
:::

Para criar a Function Instance:

<DocSteps>
  <DocStep title="Abra a aba Functions Instances">

  Em **Firewalls**, selecione o Firewall que você criou e depois selecione a aba **Functions Instances**.

  </DocStep>
  <DocStep title="Selecione Function">

  Em um Firewall que ainda não carrega nenhuma Function Instance, a mesma ação aparece como **Function Instance**. O drawer **Create Instance** abre.

  </DocStep>
  <DocStep title="Nomeie a Function Instance">

  Na seção **General**, insira um **Name**. Por exemplo: `bot-manager-lite`.

  </DocStep>
  <DocStep title="Selecione a Function instalada">

  Na seção **Function**, selecione a Function do Bot Manager Lite. O seletor lista apenas as Functions da conta que são executadas em um Firewall.

  </DocStep>
  <DocStep title="Insira os argumentos">

  Na seção **Arguments**, o editor JSON abre com os argumentos default da Function. Substitua-os pelo objeto.

  </DocStep>
  <DocStep title="Selecione Save" />
</DocSteps>

A Function Instance aparece em **Functions Instances**, com o seu **Name**, **Function**, **Last Editor** e **Last Modified**. O formulário não carrega um controle **Active**, porque o Azion Console cria toda Function Instance ativa.

Para alterar um argumento depois, selecione a Function Instance na mesma aba, edite a seção **Arguments** e selecione **Save**. A alteração entra em vigor depois de propagar, então espere antes de ler uma resposta como a nova configuração. Para mais informações, consulte [Propagação](/pt-br/documentacao/plataforma/firewall/como-funciona/#propagacao). Para cada argumento que o objeto aceita, com o seu tipo e o seu default, consulte [Bot Manager Lite](/pt-br/documentacao/plataforma/firewall/bot-manager/bot-manager-lite/#argumentos).

## Crie a regra

A Function Instance não pontua nada até que uma regra a execute. Uma regra do [Rules Engine para Firewall](/pt-br/documentacao/plataforma/firewall/rules-engine/) decide quais requisições alcançam a Function Instance, por um comportamento _Run Function_ que a executa. Para criar a regra:

<DocSteps>
  <DocStep title="Abra a aba Rules Engine">

  Em **Firewalls**, selecione o seu Firewall e depois selecione a aba **Rules Engine**.

  </DocStep>
  <DocStep title="Selecione Rule">

  O drawer **Create Rule** abre.

  </DocStep>
  <DocStep title="Nomeie a regra">

  Na seção **General**, insira um **Name**. Por exemplo: `Run Bot Manager Lite on every request`. A descrição é opcional.

  </DocStep>
  <DocStep title="Defina o critério">

  Na seção **Criteria**, selecione a variável _Request Uri_, o operador _starts with_ e `/` como argumento.

  </DocStep>
  <DocStep title="Adicione o comportamento Run Function">

  Na seção **Behaviors**, selecione _Run Function_. Um segundo controle aparece, com o placeholder `Select a Function`: ele lista as Function Instances deste Firewall, então selecione a que você nomeou. Uma regra carrega no máximo um comportamento _Run Function_.

  </DocStep>
  <DocStep title="Selecione Save" />
</DocSteps>

O Firewall executa a Function Instance em toda requisição que recebe.

Um segundo critério estreita esse conjunto. _Request Uri_ com o operador _does not match_ mantém a Function Instance fora das requisições que não carregam nada a pontuar: os assets estáticos e o caminho `/.well-known/` que clientes de automação e de web API usam. Para as extensões a excluir e o que a exclusão custa, consulte [Boas práticas de Firewall](/pt-br/documentacao/plataforma/firewall/boas-praticas/#bot-manager).

## Defina o Firewall no Workload

O deployment do Workload define o Firewall. Para definir o seu Firewall no Azion Console:

<DocSteps>
  <DocStep title="Abra a página Workloads">

  Acesse [Azion Console](https://console.azion.com/) > **Workloads**.

  </DocStep>
  <DocStep title="Abra o Workload">

  Selecione o Workload que serve a sua Application. O formulário de edição dele abre.

  </DocStep>
  <DocStep title="Selecione o seu Firewall">

  Na seção **Deployment Settings**, selecione o seu Firewall no campo **Firewall**. **Application** e **Custom Page** mantêm os valores que o Workload serve hoje.

  </DocStep>
  <DocStep title="Selecione Save" />
</DocSteps>

Depois de salvar, o deployment do Workload define o seu Firewall, e a regra executa a Function Instance em cada requisição ao Workload. Um Workload recém-definido pode levar vários minutos para aplicar as regras do seu Firewall, então espere antes de tirar conclusões de uma resposta. Para mais informações, consulte [Propagação](/pt-br/documentacao/plataforma/firewall/como-funciona/#propagacao). Para cada campo que um deployment guarda, consulte [Configurações de Workload](/pt-br/documentacao/plataforma/workloads/configuracoes/).

A linha de report que a Function grava é onde está o resultado de uma requisição pontuada. Para mais informações, consulte [Logs](/pt-br/documentacao/plataforma/firewall/bot-manager/logs/).
