Você pode assinar um JSON Web Token (JWT) com um segredo compartilhado e verificá-lo depois, com o pacote `@aziontech/jwt` da [Azion Lib](/pt-br/documentacao/devtools/azion-lib/). Os exemplos rodam no Node.js, assinam com o algoritmo padrão `HS256` e não precisam de conta Azion nem de personal token. Para assinar com um par de chaves, consulte [Chaves e algoritmos](/pt-br/documentacao/devtools/azion-lib/jwt/#chaves-e-algoritmos).

---

## Pré-requisitos

- Node.js e npm. O script é um módulo ES que usa `await` no nível superior.
- Um segredo para assinar os tokens, guardado fora do seu código. Os exemplos o leem da variável de ambiente `JWT_SECRET`.

---

## Instale o pacote

O script importa o `@aziontech/jwt` do diretório `node_modules` do projeto dele.

Em um diretório vazio, crie o projeto e instale o pacote:

```bash
npm init -y
npm install @aziontech/jwt
```

O npm imprime o novo `package.json`, e a instalação termina com:

```text
added 1 package, and audited 2 packages in 2s

found 0 vulnerabilities
```

O projeto tem o `@aziontech/jwt` nas dependências do `package.json`.

---

## Escreva o script de tokens

O script executa uma de três funções do pacote, escolhida pelo primeiro argumento:

- `sign` chama [`sign`](/pt-br/documentacao/devtools/azion-lib/jwt/#assinar-um-token). A claim `sub` é o valor que você passa, e `exp` expira o token depois do número inteiro de segundos do terceiro argumento: `3600` por padrão.
- `verify` chama [`verify`](/pt-br/documentacao/devtools/azion-lib/jwt/#verificar-um-token), que confere a assinatura e as claims de tempo e retorna o payload.
- `decode` chama [`decode`](/pt-br/documentacao/devtools/azion-lib/jwt/#decodificar-um-token), que lê as claims sem conferir a assinatura.

O `verify` rejeita um token inválido com um erro. O script imprime o `name` do erro, como `JwtTokenExpired`, porque o pacote não exporta as classes de erro. Para cada nome de erro, consulte [Erros](/pt-br/documentacao/devtools/azion-lib/jwt/#erros).

Crie um arquivo `token.mjs`:

```javascript title="token.mjs"
import { decode, sign, verify } from '@aziontech/jwt';

const secret = process.env.JWT_SECRET;
if (!secret) {
  console.error('Set the JWT_SECRET variable first');
  process.exit(1);
}
const [command, value, ttl = '3600'] = process.argv.slice(2);

if (command === 'sign') {
  const now = Math.floor(Date.now() / 1000);
  const token = await sign({ sub: value, iat: now, exp: now + Number(ttl) }, secret);
  console.log(token);
} else if (command === 'verify') {
  try {
    const payload = await verify(value, secret);
    console.log('valid', payload);
  } catch (err) {
    console.error('invalid', err.name);
    process.exit(1);
  }
} else if (command === 'decode') {
  const { header, payload } = decode(value);
  console.log(header, payload);
}
```

Sem `JWT_SECRET`, o script imprime `Set the JWT_SECRET variable first` e termina com o código `1`. Sem segredo, o próprio `sign` falha com um `TypeError`.

## Assine um token

O script lê o segredo de `JWT_SECRET`, por isso o segredo fica fora do código do script.

Para assinar um token:

1. Guarde o seu segredo na variável `JWT_SECRET`. Substitua `[TOKEN VALUE]` pelo seu segredo:

   ```bash
   export JWT_SECRET=[TOKEN VALUE]
   ```

   Todo script que você inicia nesse terminal lê o segredo, até o terminal ser fechado.

2. Assine um token para o subject `user-42` que expira em uma hora, e guarde-o na variável `TOKEN`:

   ```bash
   TOKEN=$(node token.mjs sign user-42)
   echo $TOKEN
   ```

   ```text
   eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.eyJzdWIiOiJ1c2VyLTQyIiwiaWF0IjoxNzk1MDE1MDM2LCJleHAiOjE3OTUwMTg2MzZ9.t3cTNN4fokGaviVPcrxFJkP6mjzs0OcXaKfCZhwYSeA
   ```

`TOKEN` guarda um token assinado. As letras dele diferem do exemplo, porque o payload leva o horário atual.

## Verifique um token

O `verify` retorna o payload só quando a assinatura corresponde ao segredo e nenhuma claim de tempo falha. Um `exp` no passado, ou um `nbf` ou `iat` no futuro, rejeita o token. Um token sem a claim `exp` nunca expira, então o script sempre define uma.

Assine um token e verifique-o com o mesmo segredo. Substitua `[TOKEN VALUE]` pelo seu segredo:

```bash
export JWT_SECRET=[TOKEN VALUE]
TOKEN=$(node token.mjs sign user-42)
node token.mjs verify $TOKEN
```

```text
valid { sub: 'user-42', iat: 1795015036, exp: 1795018636 }
```

O token é válido, e o script imprime as claims dele. Os horários são timestamps Unix, em segundos.

---

## Rejeite um token inválido

Dois tokens falham na verificação: um que outro segredo assinou e um cuja claim `exp` está no passado. Nos dois casos, o script imprime `invalid` com o nome do erro e termina com o código `1`.

Para ver as duas rejeições:

1. Assine um token com o seu segredo e verifique-o com um segredo diferente. Substitua `[TOKEN VALUE]` pelo seu segredo:

   ```bash
   export JWT_SECRET=[TOKEN VALUE]
   TOKEN=$(node token.mjs sign user-42)
   JWT_SECRET=another-secret node token.mjs verify $TOKEN
   ```

   ```text
   invalid JwtTokenSignatureMismatched
   ```

2. Assine um token que expirou há 60 segundos e verifique-o:

   ```bash
   EXPIRED=$(node token.mjs sign user-42 -60)
   node token.mjs verify $EXPIRED
   ```

   ```text
   invalid JwtTokenExpired
   ```

O script rejeita um token que outro segredo assinou e um token que expirou.

---

## Leia as claims sem verificar

O `decode` lê o cabeçalho e as claims de qualquer token, inclusive um expirado, porque não confere a assinatura nem as claims de tempo. Use-o para inspecionar um token, nunca para confiar nele.

Assine um token que expirou há 60 segundos e decodifique-o. Substitua `[TOKEN VALUE]` pelo seu segredo:

```bash
export JWT_SECRET=[TOKEN VALUE]
EXPIRED=$(node token.mjs sign user-42 -60)
node token.mjs decode $EXPIRED
```

```text
{ alg: 'HS256', typ: 'JWT' } { sub: 'user-42', iat: 1795015036, exp: 1795014976 }
```

A saída mostra o algoritmo que o cabeçalho do token indica e um `exp` anterior a `iat`.
