Você pode enviar cada arquivo de uma pasta local para um bucket do [Object Storage](/pt-br/documentacao/plataforma/object-storage/) com um script Node.js. O script usa o pacote `@aziontech/storage` da [Azion Lib](/pt-br/documentacao/devtools/azion-lib/). Cada objeto recebe como key o caminho do arquivo dentro da pasta. O script escolhe o content type do objeto pela extensão do arquivo.

---

## Pré-requisitos

- Node.js 24.21.0 ou posterior, e npm. O script é um módulo ES que lê a pasta com a opção `recursive` do `readdir` e o `parentPath` de cada entrada.
- Um personal token. Para criar um, consulte [Gerencie personal tokens](/pt-br/documentacao/guias/plataforma/conta-e-billing/personal-tokens/).
- Um bucket. Para criar um com Node.js, consulte [Crie um bucket](/pt-br/documentacao/devtools/azion-lib/primeiros-passos/#crie-um-bucket). Os exemplos usam um bucket chamado `site-assets-4940`.
- Uma pasta para enviar. Os exemplos usam uma pasta `public` com três arquivos: `index.html`, `css/site.css` e `img/logo.svg`.

---

## Instale o pacote

O script importa o `@aziontech/storage` do diretório `node_modules` do projeto dele.

No diretório que guarda a pasta a enviar, crie o projeto e instale o pacote:

<Code client:visible lang="bash" code={`npm init -y
npm install @aziontech/storage`} />

O npm imprime o novo `package.json`, e a instalação termina com:

```text
added 2 packages, and audited 3 packages in 2s

found 0 vulnerabilities
```

O projeto tem o `@aziontech/storage` nas dependências do `package.json`.

## Escreva o script de envio

O script primeiro lê o bucket com [`getBucket`](/pt-br/documentacao/devtools/azion-lib/storage/#obter-um-bucket), que o busca pelo nome exato. Quando o bucket não existe, o script para. Para cada arquivo da pasta, a função [`createObject`](/pt-br/documentacao/devtools/azion-lib/storage/#criar-um-objeto) cria então um objeto. A key dele é o caminho do arquivo dentro da pasta, com `/` entre as partes, como `css/site.css`.

O `createObject` guarda o content type que você passa em `params.content_type`, e o Object Storage o retorna no cabeçalho `Content-Type` do objeto. Sem ele, o `createObject` envia `application/octet-stream`, e o objeto mantém esse tipo. O Object Storage [detecta um tipo](/pt-br/documentacao/plataforma/object-storage/buckets-e-objetos/#content-type) só em um envio sem o cabeçalho `Content-Type`. O script escolhe o content type pela extensão do arquivo.

Em seguida, a função [`getObjects`](/pt-br/documentacao/devtools/azion-lib/storage/#obter-objetos) lista os objetos do bucket. O script conta quantas das keys que ele enviou estão nessa lista. Por isso, objetos que o bucket já guardava não mudam a contagem. Cada função lê o seu personal token da variável de ambiente `AZION_TOKEN`.

O `getObjects` pede no máximo 10.000 objetos por padrão. Em um bucket maior, uma key enviada pode faltar na lista.

O script recebe a pasta e o nome do bucket como os seus dois argumentos. Crie um arquivo `upload.mjs`:

<Code client:visible lang="javascript" fileName="upload.mjs" code={`import { readdir, readFile } from 'node:fs/promises';
import { extname, join, relative, sep } from 'node:path';
import { createObject, getBucket, getObjects } from '@aziontech/storage';

const [folder, bucket] = process.argv.slice(2);
const contentTypes = {
\x20 '.html': 'text/html',
\x20 '.css': 'text/css',
\x20 '.js': 'text/javascript',
\x20 '.json': 'application/json',
\x20 '.svg': 'image/svg+xml',
\x20 '.png': 'image/png',
\x20 '.jpg': 'image/jpeg',
\x20 '.txt': 'text/plain',
};

const { error: bucketError } = await getBucket({ name: bucket });
if (bucketError) {
\x20 console.error(\`Upload failed: \${bucketError.message}\`);
\x20 process.exit(1);
}

const uploaded = [];
const entries = await readdir(folder, { recursive: true, withFileTypes: true });
for (const entry of entries.filter((item) => item.isFile())) {
\x20 const file = join(entry.parentPath, entry.name);
\x20 const key = relative(folder, file).split(sep).join('/');
\x20 const contentType = contentTypes[extname(file)] ?? 'application/octet-stream';
\x20 const { error } = await createObject({
\x20   bucket,
\x20   key,
\x20   content: await readFile(file),
\x20   params: { content_type: contentType },
\x20 });
\x20 if (error) {
\x20   console.error(\`Upload failed for \${key}: \${error.message}\`);
\x20   process.exit(1);
\x20 }
\x20 uploaded.push(key);
\x20 console.log(\`Uploaded \${key} (\${contentType})\`);
}

const { data, error: listError } = await getObjects({ bucket });
if (listError) {
\x20 console.error(\`Check failed: \${listError.message}\`);
\x20 process.exit(1);
}
const stored = new Set(data.objects.map((object) => object.key));
const confirmed = uploaded.filter((key) => stored.has(key)).length;
console.log(\`\${confirmed} of \${uploaded.length} files are in \${bucket}\`);
if (confirmed !== uploaded.length) process.exit(1);`} />

O script imprime o erro ou a contagem e termina com o código `1` quando:

- O bucket não existe.
- Um envio falha.
- Uma key enviada falta na lista.

Para enviar outro tipo de arquivo com o content type dele, adicione a extensão a `contentTypes`.

O script envia todos os arquivos da pasta, inclusive arquivos ocultos como `.DS_Store`. Remova os arquivos que você não quer publicar antes de executá-lo.

## Envie a pasta

O script envia os arquivos um de cada vez e para no primeiro envio que falha.

Para enviar a pasta:

1. No terminal em que você executa o script, guarde o seu personal token na variável `AZION_TOKEN`. Substitua `[TOKEN VALUE]` pelo seu token:

   <Code client:visible lang="bash" code={`export AZION_TOKEN=[TOKEN VALUE]`} />

   Todo script que você inicia nesse terminal lê o token, até o terminal ser fechado.

2. Execute o script com a pasta e o nome do seu bucket:

   <Code client:visible lang="bash" code={`node upload.mjs public site-assets-4940`} />

   ```text
   Uploaded index.html (text/html)
   Uploaded img/logo.svg (image/svg+xml)
   Uploaded css/site.css (text/css)
   3 of 3 files are in site-assets-4940
   ```

3. (Opcional) Execute o script de novo depois de alterar um arquivo. Um envio para uma key existente substitui o objeto, por isso a contagem não muda:

   <Code client:visible lang="bash" code={`node upload.mjs public site-assets-4940`} />

   ```text
   Uploaded index.html (text/html)
   Uploaded img/logo.svg (image/svg+xml)
   Uploaded css/site.css (text/css)
   3 of 3 files are in site-assets-4940
   ```

O bucket guarda um objeto por arquivo da pasta, cada um com o content type dele.

Quando nenhum bucket tem o nome que você passou, como `site-assets`, o script imprime `Upload failed: The specified bucket does not exist.` e não envia nada.
