Você pode ler quais regras internas corresponderam a uma requisição que o [Web Application Firewall (WAF)](/pt-br/documentacao/plataforma/firewall/waf/) recusou e quanto cada família de ameaça pontuou, no Real-Time Events do Azion Console ou na API GraphQL. Para saber como um score decide um bloqueio, consulte [Score e modos](/pt-br/documentacao/plataforma/firewall/waf/score-e-modos/#score-e-sensibilidade).

## Capture o request ID

Uma requisição recusada recebe `400` e nunca chega à sua origem. Nenhum header dessa resposta indica o WAF, a regra interna ou o score, então o request ID é o valor que encontra o evento. Para capturá-lo:

1. Envie ao seu Workload uma requisição em formato de injeção:

   ```bash
   curl -i "https://<your-workload-domain>/?q=1%27%20OR%20%271%27%3D%271"
   ```

   O WAF recusa a requisição:

   ```text
   HTTP/2 400
   server: nginx
   content-type: text/html
   x-azion-request-id: 0123456789abcdef0123456789abcdef
   x-azion-edge-location: <location>
   ```

2. Anote o valor de `x-azion-request-id`.

O corpo é a página de erro padrão da Azion, com o título **Bad Request**. Um visitante que reporta uma recusa pode ler o mesmo valor na linha **Request ID** do bloco **Error Details** dessa página.

## Encontre o evento

O [Real-Time Events](/pt-br/documentacao/plataforma/real-time-events/) contém uma linha por requisição, e a linha carrega a decisão do WAF.

<Tabs client:visible sharedStore="interface">

<Fragment slot="panel.console">

### Console

Para abrir o evento no Azion Console:

<DocSteps>
  <DocStep title="Abra o Real-Time Events">

  Acesse [Azion Console](https://console.azion.com/) > **Real-Time Events**.

  </DocStep>
  <DocStep title="Selecione a aba HTTP Requests" />
  <DocStep title="Defina um intervalo de tempo que contenha a requisição" />
  <DocStep title="Filtre pelo request ID">

  No campo de busca, filtre pelo request ID que você anotou.

  </DocStep>
  <DocStep title="Selecione a requisição na lista de resultados" />
</DocSteps>

O evento abre com os campos de WAF dele, entre eles **WAF Block** e **WAF Learning**.

</Fragment>

<Fragment slot="panel.api">

### API

Para ler o evento com a API GraphQL:

<DocSteps>
  <DocStep title="Escreva a query">

  Salve o seguinte como `waf-event.json`, com o seu request ID em `requestIdEq` e uma janela de tempo ao redor da requisição em `tsGte` e `tsLt`:

  ```json
  {
    "query": "query { workloadEvents(limit: 3, filter: { tsGte: \"2026-01-01T11:55:00\", tsLt: \"2026-01-01T12:05:00\", requestIdEq: \"0123456789abcdef0123456789abcdef\" }) { ts requestId host requestUri status upstreamStatus wafBlock wafMatch wafLearning wafScore wafAttackFamily wafAttackAction wafEvheaders wafTotalBlocked wafTotalProcessed } }"
  }
  ```

  </DocStep>
  <DocStep title="Envie a query">

  Substitua `[TOKEN VALUE]` pelo seu personal token:

  ```bash
  curl --request POST \
    --url https://api.azion.com/v4/events/graphql \
    --header 'Accept: application/json' \
    --header 'Authorization: Token [TOKEN VALUE]' \
    --header 'Content-Type: application/json' \
    --data @waf-event.json
  ```

  </DocStep>
  <DocStep title="Leia o evento">

  A API responde `200`, e a linha carrega a decisão:

  ```json
  {
    "ts": "2026-01-01T12:00:00Z",
    "requestId": "0123456789abcdef0123456789abcdef",
    "host": "<your-workload-domain>",
    "requestUri": "/?q=1%27%20OR%20%271%27%3D%271",
    "status": 400,
    "upstreamStatus": 0,
    "wafBlock": "1",
    "wafMatch": "0:1009:ARGS:q,1:1013:ARGS:q",
    "wafLearning": "0",
    "wafScore": "0:$SQL:18,1:$XSS:32",
    "wafAttackFamily": "$SQL,$XSS",
    "wafAttackAction": "$BLOCK",
    "wafEvheaders": "<base64>",
    "wafTotalBlocked": 0,
    "wafTotalProcessed": 0
  }
  ```

  </DocStep>
</DocSteps>

`wafEvheaders` é base64. Decodificado, ele carrega os headers da requisição recusada.

:::note[nota]
O endpoint é `/v4/events/graphql`, e o dataset é `workloadEvents`. A mesma query enviada a `https://api.azion.com/events/graphql` responde `204` com o corpo vazio, e não existe dataset `wafEvents`. Os campos de WAF de `workloadEvents` são camelCase: `wafBlock`, não `waf_block`.
:::

</Fragment>

</Tabs>

## Leia a correspondência e o score

`wafMatch` e `wafScore` carregam a decisão. Cada um é uma string com uma entrada por correspondência, separadas por vírgulas, e cada um mostra `-` em uma requisição que não correspondeu a nenhuma regra interna. Para lê-los:

1. Leia `wafMatch`, no formato `<index>:<ruleId>:<zone>:<varName>`. Em `0:1009:ARGS:q,1:1013:ARGS:q`, as regras internas `1009` e `1013` corresponderam cada uma ao argumento `q`, na zona `ARGS`. Para saber o que cada ID de regra detecta, consulte [WAF Rule Sets](/pt-br/documentacao/plataforma/firewall/waf/rule-sets/#regras-internas).
2. Leia `wafScore`, no formato `<index>:$<family>:<score>`, com um score por família de ameaça. Em `0:$SQL:18,1:$XSS:32`, a família SQL injection pontua `18` e a família cross-site scripting pontua `32`. Uma família bloqueia quando o score dela alcança o limiar do nível de sensibilidade dela. Para os limiares, consulte [WAF Rule Sets](/pt-br/documentacao/plataforma/firewall/waf/rule-sets/#niveis-de-sensibilidade).
3. Leia `wafAttackAction` para distinguir uma recusa de uma decisão registrada. Ele mostra `$BLOCK` quando o WAF recusou a requisição e `$LEARNING-BLOCK` quando uma regra em modo _Logging_ registrou a decisão e serviu a requisição.

`wafBlock` mostra `1` nos dois modos quando o rule set sinaliza a requisição, e `wafLearning` mostra `1` só no modo _Logging_. `wafAttackFamily` lista as famílias que pontuaram, como `$SQL,$XSS`. O Azion Console mostra esses campos com labels como **WAF Block** e **WAF Learning**.

`wafTotalProcessed` e `wafTotalBlocked` mostram `0` na linha de uma requisição recusada, então não dizem nada sobre uma recusa.
