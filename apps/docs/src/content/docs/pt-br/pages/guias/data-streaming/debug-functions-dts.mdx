Você pode enviar as mensagens de log das suas Functions para um endpoint com um stream do [Data Stream](/pt-br/documentacao/plataforma/data-stream/), pelo Azion Console ou pela Azion API. Para rastrear quais regras do Rules Engine rodaram em uma requisição, consulte [Depure regras criadas com Rules Engine](/pt-br/documentacao/guias/desenvolvimento-de-aplicacoes/primeiros-passos/debug-regras/).

Uma Function escreve mensagens de log com `console.log`. A fonte de dados *Functions* traz cada mensagem com o nível, a origem e o ID da requisição, e o template *Functions Event Collector* coloca cada mensagem em uma linha de log própria. Para conhecer todas as variáveis da fonte de dados, consulte [Fontes de dados e variáveis](/pt-br/documentacao/plataforma/data-stream/fontes-de-dados-e-variaveis/#functions).

## Crie o stream

O stream lê a fonte de dados *Functions* de um Workload por meio de um filtro de workloads. Salvar um stream ativo com sampling em Applications, Functions ou WAF Events desativa todos os outros streams da conta, exceto os streams de Activity History. Um stream com filtro de workloads que você salva ou ativa depois roda ao lado do stream com sampling até que esse stream seja salvo de novo.

<Tabs client:visible sharedStore="interface">

<Fragment slot="panel.console">

### Console

Para criar o stream no Azion Console:

<DocSteps>
  <DocStep title="Abra a página Data Stream">

  Acesse [Azion Console](https://console.azion.com/) > **Data Stream**.

  </DocStep>
  <DocStep title="Selecione + Stream" />
  <DocStep title="Dê um nome ao stream">

  Na seção **General**, digite um **Name**. Por exemplo: `functions-debug`.

  </DocStep>
  <DocStep title="Selecione a fonte de dados Functions">

  Na seção **Input**, selecione *Functions* em **Data Source**.

  </DocStep>
  <DocStep title="Desative Sampling">

  Na seção **Transform**, desative **Sampling** enquanto **Option** ainda está em *All Current and Future Workloads*, o valor inicial. Um stream não pode ter sampling e um filtro de workloads ao mesmo tempo.

  </DocStep>
  <DocStep title="Escolha o Workload">

  Na seção **Transform**, defina **Option** como *Filter Workloads*. Em **Available Workload**, selecione o Workload da Function e mova-o para **Chosen Workload** com a seta. Para os controles da lista de seleção, consulte [Associe workloads a um stream](/pt-br/documentacao/guias/plataforma/observabilidade/data-stream-associar-workloads/). Se o seu Console mostra domínios onde este guia mostra Workloads, o mesmo controle aparece como *Filter Domains*. A lista de seleção passa a mostrar **Available Domain** e **Chosen Domain**.

  </DocStep>
  <DocStep title="Selecione o template">

  Na seção **Render Template**, selecione *Functions Event Collector* em **Template**. O campo **Data Set** mostra as chaves de cada linha de log.

  </DocStep>
  <DocStep title="Selecione o endpoint">

  Na seção **Output**, selecione seu endpoint em **Connector** e preencha os campos que ele mostra. Cada endpoint tem os próprios campos, listados em [Endpoints](/pt-br/documentacao/plataforma/data-stream/endpoints/).

  </DocStep>
  <DocStep title="Mantenha o stream ativo">

  Na seção **Status**, mantenha **Active** ativado.

  </DocStep>
  <DocStep title="Selecione Save" />
</DocSteps>

O Console mostra `Your data stream has been created`. O stream aparece na lista **Data Stream** com `functions_console` na coluna **Source** e o status *Active*.

</Fragment>

<Fragment slot="panel.api">

### API

Para criar o stream com a API, envie uma requisição `POST` para `https://api.azion.com/v4/workspace/stream/streams`. Este exemplo envia as linhas de log para um endpoint HTTP. Substitua `<workload-id>` pelo ID do seu Workload, e a `url` e o header pelos valores do seu endpoint:

```bash
curl -X POST 'https://api.azion.com/v4/workspace/stream/streams' \
  -H 'Content-Type: application/json' \
  -H 'Authorization: Token [TOKEN VALUE]' \
  -d '{
    "name": "functions-debug",
    "active": true,
    "inputs": [
      { "type": "raw_logs", "attributes": { "data_source": "functions_console" } }
    ],
    "transform": [
      { "type": "filter_workloads", "attributes": { "workloads": [<workload-id>] } },
      { "type": "render_template", "attributes": { "template": 86 } }
    ],
    "outputs": [
      {
        "type": "standard",
        "attributes": {
          "url": "https://logs.example.com/ingest",
          "headers": { "Authorization": "Bearer [API KEY]" }
        }
      }
    ]
  }'
```

A fonte de dados `functions_console` é *Functions* no Console, e o template `86` é *Functions Event Collector*. Uma resposta `201` traz o stream armazenado em `data`. Guarde o `id` dele: ele identifica o stream em todas as requisições seguintes, como `/v4/workspace/stream/streams/<stream-id>`. Para todas as chaves do corpo, consulte [Configurações do stream](/pt-br/documentacao/plataforma/data-stream/configuracoes-do-stream/#objeto-do-stream).

</Fragment>

</Tabs>

Salvar o stream verifica o formato de cada campo e não contata o endpoint. Uma URL ou uma credencial errada só aparece quando o stream envia. Um stream que você cria ou ativa pode levar vários minutos para começar a coletar eventos, e ele não envia os eventos de antes disso.

No caso de uso [Implantar servidores MCP remotos](/pt-br/documentacao/casos-de-uso/construir-e-executar-workloads-de-ai/implantar-servidores-mcp-remotos/), esta seção usa estes valores:

| Configuração | Valor |
| --- | --- |
| Data Source | _Functions_. Na API, `functions_console` |
| Template | _Functions Event Collector_, cuja variável `$log_message` carrega cada linha que a Function grava. Na API, `86` |
| Opção | _Filter Workloads_, com o Workload que o `azion deploy` criou como o único Workload escolhido |
| Connector | _Standard HTTP/HTTPS POST_, com a URL da sua plataforma de logs e o header que ela exige para aceitar a requisição |

Depois que você salva o stream, ele pode levar vários minutos para começar a coletar eventos, e ele não envia os eventos de antes disso. A sua plataforma de logs passa a receber uma linha por tool call, cada uma com o `$request_id` da requisição que a gerou.

No caso de uso [Governar o acesso a múltiplos modelos de IA](/pt-br/documentacao/casos-de-uso/construir-e-executar-workloads-de-ai/governar-o-acesso-a-multiplos-modelos-de-ia/), esta seção usa estes valores:

| Configuração | Valor |
| --- | --- |
| Data Source | _Functions_. Na API, `functions_console` |
| Template | _Functions Event Collector_, cuja variável `$log_message` carrega cada linha que a Function grava. Na API, `86` |
| Opção | _Filter Workloads_, com o Workload do gateway como o único Workload escolhido |
| Connector | _Standard HTTP/HTTPS POST_, com a URL da sua plataforma de analytics e o header que ela exige para aceitar a requisição |

Depois que você salva o stream, ele pode levar vários minutos para começar a coletar eventos, e ele não envia os eventos de antes disso. A sua plataforma de analytics passa a receber uma linha `model_call` por requisição e uma linha `route_failed` por rota que falhou.

## Confirme a entrega

[Real-Time Events](/pt-br/documentacao/plataforma/real-time-events/fontes-de-dados/#data-stream) registra cada envio de um stream, entregue ou não, com um código de status. Um stream envia um lote a cada 60 segundos, ou antes, quando chega a 2.000 linhas de log.

Para que o novo stream tenha eventos para enviar:

1. Aguarde alguns minutos depois de salvar o stream.
2. Envie algumas requisições que executam a Function.

<Tabs client:visible sharedStore="interface">

<Fragment slot="panel.console">

### Console

Para encontrar os envios no Azion Console:

<DocSteps>
  <DocStep title="Abra a página Real-Time Events">

  Acesse [Azion Console](https://console.azion.com/) > **Real-Time Events**.

  </DocStep>
  <DocStep title="Selecione a fonte de dados Data Stream" />
  <DocStep title="Leia os envios mais recentes">

  Cada linha é um envio. Encontre as linhas cujo **Endpoint Type** corresponde ao seu endpoint, como `HTTP_POST`, e leia o **Status Code** delas.

  </DocStep>
</DocSteps>

Um **Status Code** `200` significa que o endpoint aceitou o lote. **Streamed Lines** informa o número de linhas de log do lote.

</Fragment>

<Fragment slot="panel.api">

### API

Para ler os envios com a API, faça uma query no dataset `dataStreamedEvents` da API GraphQL do Real-Time Events. Substitua as datas por um intervalo que cubra a ativação do stream:

```bash
curl -X POST 'https://api.azion.com/v4/events/graphql' \
  -H 'Content-Type: application/json' \
  -H 'Authorization: Token [TOKEN VALUE]' \
  -d '{"query":"query { dataStreamedEvents(limit: 20, filter: {tsRange: {begin: \"2026-10-02T19:25:00\", end: \"2026-10-02T19:45:00\"}}, orderBy: [ts_DESC]) { ts jobName endpointType statusCode streamedLines url } }"}'
```

A API responde `200` com um registro para cada envio, do mais recente para o mais antigo:

```json
{
  "data": {
    "dataStreamedEvents": [
      {
        "ts": "2026-10-02T19:29:00Z",
        …
        "endpointType": "HTTP_POST",
        "statusCode": 405,
        "streamedLines": 2,
        "url": "https://example.com/logs"
      },
      …
    ]
  }
}
```

`statusCode` traz o código de status do envio, e `streamedLines`, as linhas de log do lote. Um `statusCode` `200` significa que o endpoint aceitou o lote, e uma lista `dataStreamedEvents` vazia significa que o stream não enviou nada no intervalo. Para todos os campos, consulte [Campos do Real-Time Events](/pt-br/documentacao/devtools/graphql/campos-gql-real-time-events/#eventos-de-dados-transmitidos).

</Fragment>

</Tabs>

Se Real-Time Events não mostrar nenhum envio do stream depois de um minuto, envie outra requisição que executa a Function e confira de novo.

Um envio que o endpoint aceitou mostra `200`. Um envio que falhou pode mostrar um código que o endpoint nunca retornou, e `503` significa que Data Stream encontrou o endpoint indisponível. Para encontrar a causa, consulte [Solucione problemas de Data Stream](/pt-br/documentacao/plataforma/data-stream/solucao-de-problemas/).

No endpoint, cada linha de log traz as chaves do template *Functions Event Collector*. Leia estas chaves para depurar a Function:

- `logLevel` contém o nível da mensagem: `ERROR`, `WARN`, `INFO`, `DEBUG` ou `TRACE`. Ela traz a variável `$log_level`.
- `logMessage` contém a mensagem que a Function passou para a função de log. Ela traz a variável `$log_message`.
- `messageSource` mostra `CONSOLE` para uma mensagem escrita com a console API, como `console.log`, e `RUNTIME` para uma mensagem de erro.
- `requestID` identifica a requisição, então as mensagens de uma mesma requisição compartilham esse valor.

Para manter os nomes das variáveis como chaves, ou para enviar menos variáveis, selecione um template personalizado. Para um exemplo de data set, consulte [Templates e payload](/pt-br/documentacao/plataforma/data-stream/templates-e-payload/#templates-personalizados).

No caso de uso [Implantar servidores MCP remotos](/pt-br/documentacao/casos-de-uso/construir-e-executar-workloads-de-ai/implantar-servidores-mcp-remotos/), espere:

- **Cada tool call é registrada.** Depois da chamada a `get_order`, a sua plataforma de logs recebe uma linha cuja mensagem guarda `"event":"tool_call"` e `"tool":"get_order"`.

No caso de uso [Governar o acesso a múltiplos modelos de IA](/pt-br/documentacao/casos-de-uso/construir-e-executar-workloads-de-ai/governar-o-acesso-a-multiplos-modelos-de-ia/), espere:

- **Cada chamada é registrada.** A sua plataforma de analytics recebe uma linha `model_call` para cada requisição enviada ao gateway, com `"team":"checkout-team"`. Para ler as linhas de uma requisição, abra a fonte de dados **Functions Console** no [Real-Time Events](/pt-br/documentacao/plataforma/real-time-events/primeiros-passos/), onde a variável `ID` agrupa as linhas de uma única requisição.

No caso de uso [Inspecionar uploads de arquivos em busca de conteúdo malicioso](/pt-br/documentacao/casos-de-uso/proteger-aplicacoes-e-redes/inspecionar-uploads-de-arquivos-em-busca-de-conteudo-malicioso/), espere:

- **O veredito de cada upload chega ao SIEM.** Depois do upload do arquivo de teste, o SIEM recebe uma linha de aviso cujo `logMessage` diz `[AI] true`.
