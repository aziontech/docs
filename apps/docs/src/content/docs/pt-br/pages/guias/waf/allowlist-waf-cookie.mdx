Você pode pontuar as requisições que carregam um cookie escolhido contra um segundo rule set do [Web Application Firewall (WAF)](/pt-br/documentacao/plataforma/firewall/waf/), que guarda uma exceção, pelo Azion Console. Use essa configuração quando usuários autenticados, ou uma ferramenta de terceiros integrada, precisarem de uma política que o restante do seu tráfego não tem. Para uma exceção em um único rule set, consulte [Crie uma exceção do WAF](/pt-br/documentacao/guias/seguranca-de-aplicacoes/firewall-e-waf/configurar-waf-allowed-rules/).

---

## Pré-requisitos

- Um Firewall com o WAF ativado. Consulte [Defina as configurações principais de um Firewall](/pt-br/documentacao/guias/seguranca-de-aplicacoes/firewall-e-waf/firewall-definir-main-settings/).
- Um Workload cujo deployment define o Firewall e uma Application que envia as requisições dela a um Connector. O WAF inspecionou requisições somente quando a Application as enviou a um Connector. Consulte [Defina um Firewall em um Workload](/pt-br/documentacao/guias/seguranca-de-aplicacoes/firewall-e-waf/proteja-seu-dominio/).
- O nome e o valor do cookie que a sua origem emite.
- Acesso ao [Azion Console](https://console.azion.com/). Consulte [Acesse Azion Console](/pt-br/documentacao/guias/plataforma/conta-e-billing/como-acessar-o-azion-console/).

---

## Crie o rule set primário

O rule set primário pontua as requisições que não carregam o cookie. Para criá-lo no Azion Console:

<DocSteps>
  <DocStep title="Abra a página WAF Rules">

  Acesse [Azion Console](https://console.azion.com/) > **WAF Rules**.

  </DocStep>
  <DocStep title="Selecione WAF Rule" />
  <DocStep title="Dê um nome ao rule set">

  Na seção **General**, insira um **Name**. Por exemplo: `storefront-primary`.

  </DocStep>
  <DocStep title="Defina as famílias de ameaça">

  Na seção **Threat Type Configuration**, defina a sensibilidade de cada família de ameaça.

  </DocStep>
  <DocStep title="Mantenha o switch Active ativado" />
  <DocStep title="Salve o rule set" />
</DocSteps>

O rule set aparece em **WAF Rules**. Ele não pontua nenhuma requisição até que uma regra de um Firewall o aplique.

---

## Crie o rule set secundário

O rule set secundário pontua as requisições que carregam o cookie, com as mesmas sensibilidades do primário. Para criá-lo no Azion Console:

<DocSteps>
  <DocStep title="Selecione WAF Rule">

  Na página **WAF Rules**, comece um segundo rule set.

  </DocStep>
  <DocStep title="Dê um nome ao rule set">

  Na seção **General**, insira um **Name**. Por exemplo: `storefront-cookie`.

  </DocStep>
  <DocStep title="Repita as famílias de ameaça do rule set primário">

  Na seção **Threat Type Configuration**, defina cada família com a sensibilidade do rule set primário.

  </DocStep>
  <DocStep title="Mantenha o switch Active ativado" />
  <DocStep title="Salve o rule set" />
</DocSteps>

Os dois rule sets carregam a mesma política. A exceção da próxima seção é o que os torna diferentes.

## Adicione a exceção do cookie

Uma exceção impede que uma regra interna pontue uma parte de uma requisição e deixa a regra pontuando todo o resto. O Azion Console chama uma exceção de allowed rule. Para adicionar uma ao rule set secundário:

<DocSteps>
  <DocStep title="Abra o rule set secundário">

  Em **WAF Rules**, selecione o rule set que você criou na seção anterior.

  </DocStep>
  <DocStep title="Selecione a aba Allowed Rules" />
  <DocStep title="Selecione Allowed Rule" />
  <DocStep title="Selecione a regra a ser permitida">

  Em **Rule ID**, selecione a regra interna que o seu cookie aciona. Este exemplo usa `1005`, `Possible SQL Injection attack: MySQL keyword (|) found in Body, Path, Query String or Cookies`.

  </DocStep>
  <DocStep title="Descreva a exceção">

  Em **Description**, explique por que essa regra é permitida.

  </DocStep>
  <DocStep title="Deixe o campo Path vazio">

  Um **Path** vazio cobre todo caminho. Um **Path** igual a `/` não cobriu requisições a outros caminhos nas execuções observadas.

  </DocStep>
  <DocStep title="Restrinja a exceção ao header Cookie">

  Em **Condition**, selecione _Specific HTTP Header Value_ e insira `cookie`, o nome do header, no campo **Value**.

  </DocStep>
  <DocStep title="Deixe desativado o switch Active da seção Regex" />
  <DocStep title="Salve a allowed rule" />
</DocSteps>

A allowed rule aparece em **Allowed Rules**, com **Rule ID**, **Description**, **Path**, **Conditions** e **Status**. Todas as outras regras internas do rule set secundário continuam pontuando as requisições.

:::caution[Atenção]
Reabra a allowed rule e confirme que **Condition** exibe _Specific HTTP Header Value_ com `cookie`. Uma condição _Specific HTTP Header Name_ com `cookie` não eliminou uma correspondência no header `Cookie` nas execuções observadas, e a allowed rule é salva de qualquer maneira.
:::

Um cookie vem do cliente e pode ser forjado. Quem descobrir o nome e o valor do cookie envia o mesmo header e alcança o rule set secundário. Mantenha a exceção restrita a um único **Rule ID**.

## Aplique o rule set primário a todas as requisições

Uma regra do [Rules Engine para Firewall](/pt-br/documentacao/plataforma/firewall/rules-engine/) seleciona requisições pelos critérios dela, e o comportamento _Set WAF_ dela aplica um rule set em um modo. Uma regra carrega no máximo um comportamento _Set WAF_, então essa configuração usa duas regras.

:::caution[Atenção]
Baseie o critério na URI da requisição, não na query string. Um critério como `Request Args` _matches_ `.*` não corresponde a uma requisição sem query string, então um `POST` com os campos no corpo escapa do rule set.
:::

Para criar a primeira regra no Azion Console:

<DocSteps>
  <DocStep title="Abra a aba Rules Engine do Firewall">

  Acesse [Azion Console](https://console.azion.com/) > **Firewalls**, selecione o Firewall e vá para a aba **Rules Engine**.

  </DocStep>
  <DocStep title="Selecione Rule" />
  <DocStep title="Dê um nome à regra">

  Insira um nome. Por exemplo: `Apply storefront-primary`.

  </DocStep>
  <DocStep title="Defina o critério">

  Na seção **Criteria**, selecione a variável `Request Uri`, o operador _starts with_ e `/` como argumento.

  </DocStep>
  <DocStep title="Adicione o comportamento Set WAF">

  Na seção **Behaviors**, selecione **Set WAF** e, em seguida, o rule set primário e _Blocking_ como modo.

  </DocStep>
  <DocStep title="Salve a regra" />
</DocSteps>

O Firewall aplica o rule set primário a toda requisição dos Workloads cujo deployment o define.

---

## Aplique o rule set secundário às requisições com o cookie

A segunda regra lê o header `Cookie`. Quando duas regras que carregam _Set WAF_ correspondem a uma requisição, o rule set e o modo da regra posterior se aplicam, então mantenha esta regra abaixo da primeira. Para criá-la no Azion Console:

<DocSteps>
  <DocStep title="Selecione Rule">

  Na aba **Rules Engine**, comece uma segunda regra.

  </DocStep>
  <DocStep title="Dê um nome à regra">

  Insira um nome. Por exemplo: `Apply storefront-cookie`.

  </DocStep>
  <DocStep title="Defina o critério">

  Na seção **Criteria**, selecione a variável `Header Cookie`, o operador _matches_ e o seu cookie como argumento. Por exemplo: `partner-access=b7c1f2e4`. O operador _matches_ lê o argumento como uma expressão regular.

  </DocStep>
  <DocStep title="Adicione o comportamento Set WAF">

  Na seção **Behaviors**, selecione **Set WAF** e, em seguida, o rule set secundário e _Blocking_ como modo.

  </DocStep>
  <DocStep title="Salve a regra" />
</DocSteps>

Uma requisição que carrega o cookie é pontuada contra o rule set secundário: a regra `1005` deixa de pontuar o header `Cookie` dela, e todas as outras regras internas continuam pontuando a requisição. Uma requisição sem o cookie é pontuada contra o rule set primário. As regras se propagam pela infraestrutura distribuída da Azion antes que as requisições as reflitam. Para mais informações, consulte [Propagação](/pt-br/documentacao/plataforma/firewall/como-funciona/#propagacao).
