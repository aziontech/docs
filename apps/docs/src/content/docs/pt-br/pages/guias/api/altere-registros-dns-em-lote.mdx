Você pode criar, atualizar e excluir vários registros do [Edge DNS](/pt-br/documentacao/plataforma/edge-dns/) de uma zona com loops de shell sobre a [API da Azion](/pt-br/documentacao/devtools/api/) v4. O endpoint de registros recebe um registro por requisição, por isso cada loop envia uma requisição por registro. Para adicionar, editar ou excluir um único registro pelo Azion Console, pela CLI ou pela API, consulte [Adicione, edite ou exclua um registro](/pt-br/documentacao/guias/seguranca-de-aplicacoes/dns/adicionar-registros/).

---

## Pré-requisitos

- Um personal token. Para criar um, consulte [Gerencie personal tokens](/pt-br/documentacao/guias/plataforma/conta-e-billing/personal-tokens/).
- Permissão para editar o Edge DNS. Consulte [Permissões de equipes](/pt-br/documentacao/fundamentos/teams-permissions/).
- `curl`, para chamar a API, e `jq`, para ler o arquivo de registros e as respostas da API.
- Uma zona no Edge DNS. Para criar uma, consulte [Crie uma zona](/pt-br/documentacao/plataforma/edge-dns/primeiros-passos/#crie-uma-zona). Os exemplos usam uma zona para o domínio `example.org`.

---

## Encontre o ID da zona

Todo caminho de registro leva o ID da zona dele.

Para encontrar o ID da zona:

1. Guarde o seu token em uma variável do shell. Substitua o valor pelo seu token:

   <Code client:visible lang="bash" code={`export AZION_API_TOKEN="[TOKEN VALUE]"`} />

2. Busque o seu domínio nas zonas. Substitua o domínio pelo seu:

   <Code client:visible lang="bash" code={`curl --silent "https://api.azion.com/v4/workspace/dns/zones?fields=id,domain&search=example.org" \\
   \x20 --header "Authorization: Token $AZION_API_TOKEN"`} />

   ```json
   {
     "count": 1,
     "total_pages": 1,
     "page": 1,
     "page_size": 10,
     "next": null,
     "previous": null,
     "results": [
       {
         "id": 8068,
         "domain": "example.org"
       }
     ]
   }
   ```

3. Guarde o `id` da zona cujo `domain` é o seu. Substitua o valor por esse `id`, ou o shell recusa a linha:

   <Code client:visible lang="bash" code={`ZONE_ID=<your-zone-id>`} />

`ZONE_ID` guarda o ID da zona, e toda requisição deste guia lê essa variável.

## Crie registros a partir de um arquivo

Um arquivo JSON guarda um objeto por registro. Cada objeto precisa de `name`, `type` e `rdata`, e este arquivo também define `ttl`, que tem 3.600 segundos como padrão. Um registro ANAME aceita só o `ttl` `20`, por isso o objeto dele define `"ttl": 20`. Para o formato do valor de cada tipo de registro, consulte [Tipos de registro](/pt-br/documentacao/plataforma/edge-dns/tipos-de-registro/).

:::caution[Atenção]
Um valor de CNAME ou MX não leva ponto no final. A API recusa esse valor com `400` e o código `19002`, `Invalid Domain Name`. Por exemplo, ela recusa o valor de CNAME `example.org.` e o valor de MX `20 mail2.example.org.`.
:::

Para criar os registros:

1. Crie um arquivo `records.json` com os registros. Substitua os nomes e os valores pelos seus:

   <Code client:visible lang="json" fileName="records.json" code={`[
   \x20 {
   \x20   "name": "www",
   \x20   "type": "CNAME",
   \x20   "rdata": ["example.org"],
   \x20   "ttl": 3600
   \x20 },
   \x20 {
   \x20   "name": "shop",
   \x20   "type": "A",
   \x20   "rdata": ["192.0.2.10", "192.0.2.11"],
   \x20   "ttl": 300
   \x20 },
   \x20 {
   \x20   "name": "api",
   \x20   "type": "A",
   \x20   "rdata": ["192.0.2.20"],
   \x20   "ttl": 300
   \x20 },
   \x20 {
   \x20   "name": "@",
   \x20   "type": "MX",
   \x20   "rdata": ["10 mail.example.org"],
   \x20   "ttl": 3600
   \x20 },
   \x20 {
   \x20   "name": "@",
   \x20   "type": "TXT",
   \x20   "rdata": ["v=spf1 -all"],
   \x20   "ttl": 3600
   \x20 }
   ]`} />

2. Envie uma requisição `POST` por registro. O loop imprime uma linha por registro, com o nome e o tipo do arquivo. O campo `errors` da linha traz o erro quando a API recusa o registro, e `null` nos outros casos. Substitua `[TOKEN VALUE]` e `<your-zone-id>` pelos seus valores:

   <Code client:visible lang="bash" code={`export AZION_API_TOKEN="[TOKEN VALUE]"
   ZONE_ID=<your-zone-id>
   jq -c '.[]' records.json | while read -r record; do
   \x20 curl --silent "https://api.azion.com/v4/workspace/dns/zones/$ZONE_ID/records" \\
   \x20   --header "Authorization: Token $AZION_API_TOKEN" \\
   \x20   --header 'Content-Type: application/json' \\
   \x20   --data "$record" \\
   \x20 | jq -c --argjson record "$record" '{name: $record.name, type: $record.type, id: .data.id, errors}'
   done`} />

   ```text
   {"name":"www","type":"CNAME","id":612521,"errors":null}
   {"name":"shop","type":"A","id":612522,"errors":null}
   {"name":"api","type":"A","id":612523,"errors":null}
   {"name":"@","type":"MX","id":612524,"errors":null}
   {"name":"@","type":"TXT","id":612525,"errors":null}
   ```

A zona guarda um registro por objeto do arquivo. Um registro recusado não interrompe o loop: a linha dele traz o erro, e o próximo registro é enviado.

Você pode rodar o loop de novo depois de corrigir um registro recusado. Um nome e um tipo guardam um único registro com a [política `simple`](/pt-br/documentacao/plataforma/edge-dns/como-funciona/#politicas-de-registro), a padrão.

Um segundo registro desses é recusado com o código `19004`, `Record Already Exists`. Para um segundo CNAME com o mesmo nome, o código é `19014`, `CNAME Record Name Conflict`. Em uma segunda execução do mesmo arquivo, o loop imprime:

```text
{"name":"www","type":"CNAME","id":null,"errors":[{"code":"19014","title":"CNAME Record Name Conflict","detail":"A CNAME with this name already exists for this sub-domain.","status":"400","source":{"pointer":"/data"}}]}
{"name":"shop","type":"A","id":null,"errors":[{"code":"19004","title":"Record Already Exists","detail":"There is already another record matching those data.","status":"400","source":{"pointer":"/data"}}]}
{"name":"api","type":"A","id":null,"errors":[{"code":"19004","title":"Record Already Exists","detail":"There is already another record matching those data.","status":"400","source":{"pointer":"/data"}}]}
{"name":"@","type":"MX","id":null,"errors":[{"code":"19004","title":"Record Already Exists","detail":"There is already another record matching those data.","status":"400","source":{"pointer":"/data"}}]}
{"name":"@","type":"TXT","id":null,"errors":[{"code":"19004","title":"Record Already Exists","detail":"There is already another record matching those data.","status":"400","source":{"pointer":"/data"}}]}
```

Registros com política Weighted podem compartilhar um nome e um tipo, por isso a API aceita um segundo registro desses. Antes de rodar o loop de novo, remova do arquivo os registros com política Weighted que já existem.

Espere cerca de um minuto depois de salvar um registro antes de consultar o nome dele. Uma consulta feita antes de o registro responder deixa uma resposta negativa em cache nesse nameserver por até 1 hora. Essa resposta é `NXDOMAIN` para um nome novo, ou `NOERROR` vazio para um tipo novo em um nome existente. Para corrigir, consulte [Um registro novo retorna NXDOMAIN](/pt-br/documentacao/plataforma/edge-dns/solucao-de-problemas/#um-registro-novo-retorna-nxdomain).

## Atualize vários registros

Um loop lista os registros, seleciona com o `jq` os que vão mudar e envia uma requisição `PATCH` para cada um. Um corpo de `PATCH` leva só os campos a alterar, por isso os demais campos do registro mantêm os seus valores.

:::note[nota]
A requisição de listagem lê uma página de até 100 registros, o máximo de uma página. Em uma zona com mais registros, o loop altera só os registros da primeira página. Para ler todas as páginas, consulte [Percorra uma lista com filtros e ordenação](/pt-br/documentacao/guias/desenvolvimento-de-aplicacoes/automacao/percorra-uma-lista-com-filtros-e-ordenacao/).
:::

Defina o time to live (TTL) de todo registro A da zona como 600 segundos. Substitua `[TOKEN VALUE]` e `<your-zone-id>` pelos seus valores:

<Code client:visible lang="bash" code={`export AZION_API_TOKEN="[TOKEN VALUE]"
ZONE_ID=<your-zone-id>
curl --silent "https://api.azion.com/v4/workspace/dns/zones/$ZONE_ID/records?page_size=100&fields=id,type" \\
\x20 --header "Authorization: Token $AZION_API_TOKEN" \\
| jq -r '.results[] | select(.type == "A") | .id' \\
| while read -r record_id; do
\x20 curl --silent --request PATCH "https://api.azion.com/v4/workspace/dns/zones/$ZONE_ID/records/$record_id" \\
\x20   --header "Authorization: Token $AZION_API_TOKEN" \\
\x20   --header 'Content-Type: application/json' \\
\x20   --data '{"ttl": 600}' \\
\x20 | jq -c '{name: .data.name, type: .data.type, ttl: .data.ttl, errors}'
done`} />

```text
{"name":"shop","type":"A","ttl":600,"errors":null}
{"name":"api","type":"A","ttl":600,"errors":null}
```

Todo registro A da zona tem um TTL de 600 segundos, e os outros campos dele mantêm os valores.

Uma alteração em um registro pode levar alguns minutos para chegar a todos os nameservers. Depois, os resolvers mantêm o valor antigo até o TTL dele expirar.

## Exclua vários registros

Um loop lista os registros, seleciona todo registro com um dado nome, seja qual for o tipo, e envia uma requisição `DELETE` para cada um.

:::caution[Atenção]
Um registro excluído não pode ser restaurado. Para um registro com política Weighted, defina antes o peso dele como `0`. Para os passos, consulte [Defina o peso 0 antes de excluir um registro com política Weighted](/pt-br/documentacao/plataforma/edge-dns/boas-praticas/#defina-o-peso-0-antes-de-excluir-um-registro-com-politica-weighted).
:::

:::note[nota]
A requisição de listagem lê uma página de até 100 registros, o máximo de uma página. Em uma zona com mais registros, o loop exclui só os registros correspondentes da primeira página. Para ler todas as páginas, consulte [Percorra uma lista com filtros e ordenação](/pt-br/documentacao/guias/desenvolvimento-de-aplicacoes/automacao/percorra-uma-lista-com-filtros-e-ordenacao/).
:::

Para excluir os registros chamados `api` e `shop`:

1. Liste os registros chamados `api` e `shop` antes de excluí-los. Substitua `[TOKEN VALUE]` e `<your-zone-id>` pelos seus valores:

   <Code client:visible lang="bash" code={`export AZION_API_TOKEN="[TOKEN VALUE]"
   ZONE_ID=<your-zone-id>
   curl --silent "https://api.azion.com/v4/workspace/dns/zones/$ZONE_ID/records?page_size=100&fields=id,name,type,rdata,ttl" \\
   \x20 --header "Authorization: Token $AZION_API_TOKEN" \\
   | jq -c '.results[] | select(.name == "api" or .name == "shop")'`} />

   ```text
   {"id":612522,"name":"shop","ttl":600,"type":"A","rdata":["192.0.2.10","192.0.2.11"]}
   {"id":612523,"name":"api","ttl":600,"type":"A","rdata":["192.0.2.20"]}
   ```

2. Exclua os registros que a lista mostra. Substitua `[TOKEN VALUE]` e `<your-zone-id>` pelos seus valores:

   <Code client:visible lang="bash" code={`export AZION_API_TOKEN="[TOKEN VALUE]"
   ZONE_ID=<your-zone-id>
   curl --silent "https://api.azion.com/v4/workspace/dns/zones/$ZONE_ID/records?page_size=100&fields=id,name" \\
   \x20 --header "Authorization: Token $AZION_API_TOKEN" \\
   | jq -r '.results[] | select(.name == "api" or .name == "shop") | .id' \\
   | while read -r record_id; do
   \x20 curl --silent --request DELETE "https://api.azion.com/v4/workspace/dns/zones/$ZONE_ID/records/$record_id" \\
   \x20   --header "Authorization: Token $AZION_API_TOKEN"
   \x20 echo " $record_id"
   done`} />

   ```text
   {"state":"executed"} 612522
   {"state":"executed"} 612523
   ```

Verifique os registros que restam na zona. Substitua `[TOKEN VALUE]` e `<your-zone-id>` pelos seus valores:

<Code client:visible lang="bash" code={`export AZION_API_TOKEN="[TOKEN VALUE]"
ZONE_ID=<your-zone-id>
curl --silent "https://api.azion.com/v4/workspace/dns/zones/$ZONE_ID/records?page_size=100&fields=id,name,type,rdata,ttl" \\
\x20 --header "Authorization: Token $AZION_API_TOKEN" \\
| jq -c '.results[]'`} />

```text
{"id":612521,"name":"www","ttl":3600,"type":"CNAME","rdata":["example.org"]}
{"id":612524,"name":"@","ttl":3600,"type":"MX","rdata":["10 mail.example.org"]}
{"id":612525,"name":"@","ttl":3600,"type":"TXT","rdata":["v=spf1 -all"]}
```

A zona não guarda mais os registros chamados `api` e `shop`.
