Neste tutorial, você vai construir uma busca semântica que retorna os documentos de significado mais próximo a uma pergunta, sobre dados armazenados em [SQL Database](/pt-br/documentacao/plataforma/sql-database/). Você vai criar um banco de dados, adicionar uma tabela com uma coluna vetorial e um índice sobre ela, gerar embeddings com a OpenAI, armazená-los e consultar a tabela por similaridade.

O trabalho é dividido em duas partes. Um script de setup roda uma vez a partir da sua máquina: ele cria o banco de dados, espera até que o banco aceite instruções e armazena os embeddings. Uma função TypeScript então responde a cada requisição com uma busca sobre essas linhas. Os dois acessam o banco de dados pela [biblioteca SQL da Azion](/pt-br/documentacao/devtools/azion-lib/sql/) e produzem embeddings com o pacote LangChain OpenAI. A função roda localmente com `azion dev`.

---

## Pré-requisitos

- Node.js versão 20.6 ou superior. O script de setup lê suas credenciais com `node --env-file`, que versões anteriores não têm.
- Azion CLI instalada e autorizada. Para mais informações, consulte [Azion CLI](/pt-br/documentacao/devtools/cli/).
- Um projeto de função TypeScript criado com `azion init`. Para criar um, consulte [Faça o deploy de uma function com a Azion CLI](/pt-br/documentacao/guias/desenvolvimento-de-aplicacoes/functions-e-runtime/deploy-function-with-cli/). Os passos abaixo rodam na pasta do projeto.
- Um personal token da Azion. Para mais informações, consulte [Como criar um personal token](/pt-br/documentacao/guias/plataforma/conta-e-billing/personal-tokens/).
- SQL Database habilitado na conta. O produto está em Preview, e o acesso é solicitado pelo time de suporte técnico. Para solicitá-lo, consulte [Technical Support](/pt-br/documentacao/suporte/).
- Uma OpenAI API key. A etapa de embedding chama a OpenAI API com ela. Para criar uma, consulte [Create and export an API key](https://developers.openai.com/api/docs/quickstart#create-and-export-an-api-key).

## 2. Crie o banco de dados e espere até que ele fique pronto

`createDatabase` retorna enquanto o banco de dados ainda está sendo provisionado: seu `status` é `creating` e passa a `created` cerca de 15 segundos depois. Uma instrução enviada antes disso falha, então o script consulta `getDatabase` até que o status seja `created`. O nome de um banco de dados é único na conta, e `createDatabase` com um nome que a conta já tem falha com o erro `14001` `Name Already In Use.`. O script lê o banco de dados primeiro e só o cria quando ele não existe, então uma segunda execução reaproveita o banco em vez de falhar.

Crie um arquivo chamado `setup.mjs` na pasta do projeto e comece pela etapa do banco de dados:

```javascript
import { createDatabase, getDatabase, useExecute, useQuery } from '@aziontech/sql'
import { OpenAIEmbeddings } from '@langchain/openai'

const DATABASE = 'vectorDatabase'

async function ensureDatabase() {
  let { data: database } = await getDatabase(DATABASE)

  if (!database) {
    const { error } = await createDatabase(DATABASE)
    // 14001 Name Already In Use: another run created it between the two calls.
    // Read it again, and stop only when it still does not exist.
    if (error) {
      ;({ data: database } = await getDatabase(DATABASE))
      if (!database) throw new Error(`createDatabase failed: ${error.message}`)
    }
  }

  for (let attempt = 1; attempt <= 20; attempt++) {
    const { data, error } = await getDatabase(DATABASE)
    if (error) throw new Error(`getDatabase failed: ${error.message}`)
    if (data?.status === 'created') return
    console.log(`Database status is ${data?.status}, waiting...`)
    await new Promise((resolve) => setTimeout(resolve, 3000))
  }

  throw new Error('The database did not reach the created status in 60 seconds')
}
```

`getDatabase` retorna um objeto vazio para um nome que não corresponde a nenhum banco de dados, então `database` é `undefined` até que o banco exista. O loop verifica o status a cada 3 segundos e desiste depois de 20 tentativas.

## 3. Crie a tabela e o índice vetorial

A tabela guarda o texto de cada documento e seu embedding. Um vetor vive em uma coluna própria, declarada com um tipo blob que carrega sua contagem de dimensões: `F32_BLOB(1536)` guarda 1.536 elementos de ponto flutuante de 32 bits, que é o número de dimensões que o modelo `text-embedding-3-small` retorna.

O índice faz uma busca consultar uma estrutura de vizinhos aproximados mais próximos em vez de cada linha. Ele é construído sobre `libsql_vector_idx(embedding, 'metric=cosine')`, e a tabela que ele cobre precisa de um `ROWID` ou de uma `PRIMARY KEY` de coluna única, que `id INTEGER PRIMARY KEY AUTOINCREMENT` fornece.

Continue em `setup.mjs`. As duas instruções carregam `IF NOT EXISTS`, então uma segunda execução deixa a tabela e o índice como estão. Rode-as com `useExecute`, que atende as instruções que criam e escrevem:

```javascript
async function ensureTable() {
  const { error } = await useExecute(DATABASE, [
    `CREATE TABLE IF NOT EXISTS documents (
      id INTEGER PRIMARY KEY AUTOINCREMENT,
      content TEXT NOT NULL,
      embedding F32_BLOB(1536)
    );`,
    `CREATE INDEX IF NOT EXISTS documents_idx ON documents (
      libsql_vector_idx(embedding, 'metric=cosine')
    );`
  ])

  if (error) throw new Error(`Table setup failed: ${error.message}`)
}
```

O banco de dados passa a ter uma tabela `documents` e um índice `documents_idx`. Criar um índice vetorial também adiciona uma tabela sombra chamada `documents_idx_shadow`, que tanto `getTables` quanto o EdgeSQL Shell listam ao lado da tabela.

## 4. Gere e armazene os embeddings

O modelo de embedding transforma texto em um vetor. `text-embedding-3-small` retorna 1.536 dimensões, o número que a coluna `embedding` declara, e o mesmo modelo produz os vetores armazenados aqui e o vetor que a busca usa na etapa 5.

Continue em `setup.mjs`. A função conta as linhas primeiro e só armazena os documentos quando a tabela está vazia, então uma segunda execução não os duplica. Ela gera o embedding de cada documento com `embedQuery` e envolve o resultado em `vector('[...]')`, que converte um array de números no tipo que a coluna guarda:

```javascript
const documents = [
  'Paris is the capital of France',
  'The Eiffel Tower is a French landmark',
  'London is the capital of England',
  'Big Ben is located in London',
  'Canberra is the capital of Australia',
  'The Great Barrier Reef is in Australia',
  'French cuisine is world-famous',
  'Tea is popular in England',
  'The English Channel separates Britain and France'
]

async function seedDocuments() {
  const { data: count, error: countError } = await useQuery(DATABASE, [
    'SELECT COUNT(*) AS total FROM documents;'
  ])
  if (countError) throw new Error(`Count failed: ${countError.message}`)

  if (count.results[0].rows[0][0] > 0) {
    console.log('The documents table already holds rows, skipping the insert')
    return
  }

  const embeddings = new OpenAIEmbeddings({
    model: 'text-embedding-3-small',
    apiKey: process.env.OPENAI_API_KEY
  })

  const insertStatements = []
  for (const doc of documents) {
    const embedding = await embeddings.embedQuery(doc)
    // The body carries SQL text, so double every single quote inside a value.
    const content = doc.replaceAll("'", "''")
    insertStatements.push(
      `INSERT INTO documents (content, embedding) VALUES ('${content}', vector('[${embedding}]'));`
    )
  }

  const { error } = await useExecute(DATABASE, insertStatements)
  if (error) throw new Error(`Insert failed: ${error.message}`)
}

await ensureDatabase()
await ensureTable()
await seedDocuments()
console.log('Setup complete')
```

Rode o script na pasta do projeto:

```bash
node --env-file=.env setup.mjs
```

O script imprime `Database status is creating, waiting...` enquanto o banco de dados é provisionado e `Setup complete` no final. A tabela `documents` passa a ter uma linha por entrada da lista, cada uma com seu texto e seu embedding, e o índice cobre essas linhas. Rodar o script de novo imprime `Setup complete` sem criar nada duas vezes. `vector('[...]')` rejeita um vetor com mais de 65.536 dimensões.

## 5. Consulte por similaridade

Uma busca gera o embedding da pergunta com o mesmo modelo e pede ao índice as linhas mais próximas. `vector_top_k` recebe o nome do índice, o vetor de consulta e o número de linhas a retornar, e responde com uma coluna `id` pela qual a tabela é juntada em `rowid`:

```sql
SELECT content FROM vector_top_k('documents_idx', vector('[...]'), 2) JOIN documents ON documents.rowid = id;
```

A função apenas lê, então não cria nada e responde a toda requisição da mesma forma. Substitua o conteúdo de `main.ts`, o arquivo de entrada do projeto, pela busca, e rode a instrução com `useQuery`, que atende as instruções que retornam linhas:

```typescript
import { useQuery } from '@aziontech/sql'
import { OpenAIEmbeddings } from '@langchain/openai'

export default async function vectorSearch() {
  const embeddings = new OpenAIEmbeddings({
    model: 'text-embedding-3-small',
    apiKey: process.env.OPENAI_API_KEY
  })

  const query = 'What is the capital of Australia?'
  const queryEmbedding = await embeddings.embedQuery(query)

  const { data: searchData, error: searchError } = await useQuery('vectorDatabase', [
    `SELECT content FROM vector_top_k('documents_idx', vector('[${queryEmbedding}]'), 2)
     JOIN documents ON documents.rowid = id;`
  ])

  if (searchError) {
    return Response.json({ error: searchError.message }, { status: 500 })
  }

  return Response.json({ data: searchData })
}
```

A resposta carrega `results`, uma entrada por instrução, cada uma com suas `columns` e suas `rows`. Uma instrução que falha faz a chamada inteira falhar: `error` guarda a mensagem do banco de dados, como `no such table: documents`, e `data` não é preenchido. É por isso que a função lê `error` antes de ler `data`.

A função retorna as duas linhas cujos embeddings estão mais próximos da pergunta, e uma busca que falha retorna uma mensagem JSON com status `500`.

## 6. Execute a função

A função lê as linhas que o script de setup armazenou. Para executá-la localmente:

<DocSteps>
  <DocStep title="Construa a aplicação">

  Na pasta do projeto, construa-a:

  ```bash
  azion build
  ```

  A saída do build é escrita no diretório do projeto.

  </DocStep>
  <DocStep title="Inicie o servidor local">

  Sirva a função a partir da sua máquina:

  ```bash
  azion dev
  ```

  A função responde no endereço local que o comando imprime, `http://localhost:3333` por padrão.

  </DocStep>
  <DocStep title="Envie uma requisição">

  ```bash
  curl http://localhost:3333
  ```

  A função gera o embedding de `What is the capital of Australia?` e busca no índice.

  </DocStep>
</DocSteps>

A resposta carrega os dois documentos cujos embeddings estão mais próximos da pergunta. Toda requisição seguinte roda a mesma busca, porque a função não cria nada. Para buscar outra coisa, mude o valor de `query`, faça o build de novo e envie a requisição novamente. Para armazenar outros documentos, mude a lista `documents`, apague as linhas da tabela `documents` e rode `setup.mjs` de novo.
