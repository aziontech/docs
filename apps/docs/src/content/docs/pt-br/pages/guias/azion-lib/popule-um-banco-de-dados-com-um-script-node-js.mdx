Você pode carregar um schema e as primeiras linhas em um banco de dados do [SQL Database](/pt-br/documentacao/plataforma/sql-database/) com um script Node.js. O script usa o pacote `@aziontech/sql` da [Azion Lib](/pt-br/documentacao/devtools/azion-lib/). Ele lê as instruções de um arquivo SQL, por isso o mesmo arquivo popula um banco de dados em qualquer ambiente.

---

## Pré-requisitos

- Node.js e npm. O script é um módulo ES que usa `await` no nível superior, e o `@aziontech/sql` precisa do `fetch` global do Node.js.
- Um personal token. Para criar um, consulte [Gerencie personal tokens](/pt-br/documentacao/guias/plataforma/conta-e-billing/personal-tokens/).
- Um banco de dados. Para criar um, consulte [Crie e gerencie bancos de dados](/pt-br/documentacao/guias/desenvolvimento-de-aplicacoes/dados/gerenciar-bancos-dados-edge-sql/). Os exemplos usam um banco de dados chamado `storefront-db`.

---

## Instale o pacote

O script importa o `@aziontech/sql` do diretório `node_modules` do projeto dele.

Em um diretório vazio, crie o projeto e instale o pacote:

<Code client:visible lang="bash" code={`npm init -y
npm install @aziontech/sql`} />

O npm imprime o novo `package.json`, e a instalação termina com:

```text
added 2 packages, and audited 3 packages in 2s

found 0 vulnerabilities
```

O projeto tem o `@aziontech/sql` nas dependências do `package.json`.

## Escreva o arquivo de seed

O arquivo de seed guarda as instruções SQL, na ordem em que o banco de dados as executa. Termine cada instrução com um `;` no fim da linha dela, porque o script divide o arquivo nesse ponto. Um `;` dentro de um valor fica na instrução dele, como em `'Pen; blue'`.

O banco de dados para na primeira instrução que falha, e as instruções anteriores continuam aplicadas. Como uma segunda execução recomeça da primeira instrução, escreva cada instrução para que ela possa ser executada duas vezes. `CREATE TABLE IF NOT EXISTS` ignora uma tabela que já existe, e `INSERT OR REPLACE` sobrescreve uma linha com a mesma chave. Para mais informações, consulte [Envie as instruções relacionadas em uma única chamada](/pt-br/documentacao/plataforma/sql-database/boas-praticas/#envie-as-instrucoes-relacionadas-em-uma-unica-chamada).

Crie um arquivo `seed.sql`:

<Code client:visible lang="sql" fileName="seed.sql" code={`CREATE TABLE IF NOT EXISTS products (
\x20 id INTEGER PRIMARY KEY,
\x20 name TEXT NOT NULL,
\x20 price_cents INTEGER NOT NULL
);
INSERT OR REPLACE INTO products (id, name, price_cents) VALUES (1, 'Notebook', 1290);
INSERT OR REPLACE INTO products (id, name, price_cents) VALUES (2, 'Pen; blue', 350);
INSERT OR REPLACE INTO products (id, name, price_cents) VALUES (3, 'Backpack', 8900);`} />

O arquivo `seed.sql` guarda uma instrução `CREATE TABLE` e três instruções `INSERT OR REPLACE`.

## Escreva o script de seed

As funções do `@aziontech/sql` encontram um banco de dados por uma busca no nome, e a busca também encontra parte de um nome: `storefront` encontra `storefront-db`. Por isso, o script primeiro lê o banco de dados com [`getDatabase`](/pt-br/documentacao/devtools/azion-lib/sql/#obter-um-banco-de-dados) e para, a menos que o nome seja exatamente igual.

Em seguida, a função [`useExecute`](/pt-br/documentacao/devtools/azion-lib/sql/#executar-statements) envia todas as instruções do arquivo ao banco de dados em uma única chamada. A função [`useQuery`](/pt-br/documentacao/devtools/azion-lib/sql/#executar-consultas) executa `SELECT COUNT(*)` na tabela `products`, para que o script confirme o seed. Cada função lê o seu personal token da variável de ambiente `AZION_TOKEN`.

O script recebe o nome do banco de dados como primeiro argumento. Crie um arquivo `seed.mjs`:

<Code client:visible lang="javascript" fileName="seed.mjs" code={`import { readFile } from 'node:fs/promises';
import { getDatabase, useExecute, useQuery } from '@aziontech/sql';

const database = process.argv[2];
const { data: found } = await getDatabase(database);
if (found?.name !== database) {
\x20 console.error(\`Seed failed: no database is named \${database}\`);
\x20 process.exit(1);
}

const sql = await readFile('seed.sql', 'utf8');
const statements = sql
\x20 .split(/;\\s*$/m)
\x20 .map((statement) => statement.trim())
\x20 .filter(Boolean);

const { data, error } = await useExecute(database, statements);
if (error) {
\x20 console.error(\`Seed failed: \${error.message}\`);
\x20 process.exit(1);
}
console.log(\`Ran \${data.results.length} statements on \${database}\`);

const { data: check, error: checkError } = await useQuery(database, ['SELECT COUNT(*) FROM products']);
if (checkError) {
\x20 console.error(\`Check failed: \${checkError.message}\`);
\x20 process.exit(1);
}
console.log(\`products has \${check.results[0].rows[0][0]} rows\`);`} />

Quando a verificação do nome, o seed ou a contagem falha, o script imprime o erro e termina com o código `1`. A consulta de contagem cita a tabela `products`: quando o seu arquivo de seed cria outras tabelas, cite uma delas ali.

## Execute o seed

Para executar o seed:

1. No terminal em que você executa o script, guarde o seu personal token na variável `AZION_TOKEN`. Substitua `[TOKEN VALUE]` pelo seu token:

   <Code client:visible lang="bash" code={`export AZION_TOKEN=[TOKEN VALUE]`} />

   Todo script que você inicia nesse terminal lê o token, até o terminal ser fechado.

2. Execute o script com o nome completo do seu banco de dados:

   <Code client:visible lang="bash" code={`node seed.mjs storefront-db`} />

   ```text
   Ran 4 statements on storefront-db
   products has 3 rows
   ```

3. (Opcional) Execute o script de novo. As instruções ignoram a tabela existente e sobrescrevem as linhas, por isso a contagem não muda:

   <Code client:visible lang="bash" code={`node seed.mjs storefront-db`} />

   ```text
   Ran 4 statements on storefront-db
   products has 3 rows
   ```

O banco de dados guarda a tabela `products` e as três linhas dela.

Quando nenhum banco de dados tem exatamente o nome que você passou, como `storefront`, o script imprime `Seed failed: no database is named storefront` e não escreve nada. Quando uma instrução falha, ele imprime o erro do banco de dados, como `Seed failed: no such table: nope`.
