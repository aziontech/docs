Você pode colocar sob o Terraform recursos que já existem na sua conta Azion com blocos `import`. O Terraform lê cada recurso pelo [Azion Terraform Provider](/pt-br/documentacao/devtools/terraform/) e o adiciona ao state do Terraform. Com a opção `-generate-config-out` do `terraform plan`, o Terraform também escreve a configuração de cada recurso. Para migrar uma configuração do provider v1.x, consulte [Migre do provider v1.x para o v2.0](/pt-br/documentacao/devtools/terraform/migration-v3-to-v4/).

Os exemplos importam uma [Application](/pt-br/documentacao/plataforma/applications/) e um dos seus [cache settings](/pt-br/documentacao/plataforma/applications/cache/cache-settings/).

---

## Pré-requisitos

- Terraform 1.17.2 ou posterior, para os blocos `import` e a opção `-generate-config-out` do `terraform plan`. Para instalá-lo, consulte [Instale o Terraform](/pt-br/documentacao/devtools/terraform/getting-started/#instale-o-terraform).
- Um [personal token](/pt-br/documentacao/fundamentos/personal-tokens/) na variável de ambiente `AZION_API_TOKEN`. Para defini-la, consulte [Informe o seu personal token](/pt-br/documentacao/devtools/terraform/getting-started/#informe-o-seu-personal-token).
- O ID de cada recurso a importar. Os exemplos usam uma Application com o ID `1795011484` e o cache setting `395100` dela. Para listar os IDs com a [Azion CLI](/pt-br/documentacao/devtools/cli/), consulte [azion list application](/pt-br/documentacao/devtools/cli/recursos/application/#listar) e [azion list cache-setting](/pt-br/documentacao/devtools/cli/recursos/cache-setting/#listar).

---

## Declare os recursos a importar

Um bloco `import` diz ao Terraform qual recurso da conta adicionar ao state. O argumento `to` guarda o endereço do recurso na sua configuração, e o argumento `id` guarda o ID de importação. O ID de importação depende do tipo de recurso:

| Tipo de recurso | ID de importação |
| --- | --- |
| `azion_application_main_setting` | `<application_id>` |
| `azion_application_cache_setting` | `<application_id>/<cache_setting_id>` |

Em um diretório vazio, crie um arquivo `main.tf` com o provider e um bloco `import` por recurso. Substitua os IDs pelos seus:

<Code client:visible lang="hcl" fileName="main.tf" code={`terraform {
\x20 required_providers {
\x20   azion = {
\x20     source  = "aziontech/azion"
\x20     version = "2.10.0"
\x20   }
\x20 }
}

provider "azion" {}

import {
\x20 to = azion_application_main_setting.site
\x20 id = "1795011484"
}

import {
\x20 to = azion_application_cache_setting.static_assets
\x20 id = "1795011484/395100"
}`} />

A configuração declara duas importações e nenhum bloco de recurso: o `terraform plan -generate-config-out` escreve os blocos de recurso.

Para o ID de importação de qualquer outro tipo de recurso, consulte a [documentação do provider](https://registry.terraform.io/providers/aziontech/azion/2.10.0/docs).

## Gere a configuração

O `terraform plan` com `-generate-config-out` lê cada recurso da conta e escreve o bloco de recurso dele em um arquivo novo.

Para gerar a configuração:

1. Baixe o provider:

   <Code client:visible lang="bash" code={`terraform init`} />

   ```text
   - Installing aziontech/azion v2.10.0...
   - Installed aziontech/azion v2.10.0 (self-signed, key ID 60105B099A0FF3B3)
   ...
   Terraform has been successfully initialized!
   ```

2. Planeje a importação e escreva a configuração em `generated.tf`:

   <Code client:visible lang="bash" code={`terraform plan -generate-config-out=generated.tf`} />

   ```text
     # azion_application_cache_setting.static_assets will be imported
     # (config will be generated)
   ...
     # azion_application_main_setting.site will be imported
     # (config will be generated)
   ...
   Plan: 2 to import, 0 to add, 0 to change, 0 to destroy.

   Warning: Config generation is experimental

   Generating configuration during import is currently experimental, and the
   generated configuration format may change in future versions.
   ...
   Terraform has generated configuration and written it to generated.tf.
   ```

   O Terraform mostra um aviso de que a geração de configuração é experimental, então revise o arquivo gerado no próximo passo.

3. Abra o `generated.tf` e revise-o. Cada bloco de recurso traz valores lidos da conta, como o Max Age do cache setting:

   {/* terraform-validate: skip */}
   {/* keep-fence */}
   ```hcl title="generated.tf"
   resource "azion_application_main_setting" "site" {
     application = {
       active = true
       debug  = false
       modules = {
         ...
       }
     }
   }

   resource "azion_application_cache_setting" "static_assets" {
     application_id = 1795011484
     cache_setting = {
       browser_cache = {
         behavior = "override"
         max_age  = 600
       }
       modules = {
         ...
         cache = {
           behavior = "override"
           ...
           max_age = 3600
           ...
         }
       }
       name = "static-assets"
     }
   }
   ```

4. (Opcional) Para que o cache setting dependa da Application, referencie a Application no `generated.tf` em vez do ID literal dela:

   <Code client:visible lang="hcl" code={`application_id = azion_application_main_setting.site.application.application_id`} />

O arquivo `generated.tf` guarda um bloco de recurso por bloco `import`. Com a referência do passo 4, o `terraform plan` continua mostrando `2 to import, 0 to add, 0 to change, 0 to destroy`.

## Importe os recursos

O `terraform apply` adiciona os recursos ao state do Terraform. Quando o plano mostra `0 to add, 0 to change, 0 to destroy`, o apply não altera nada na conta. Quando ele mostra uma alteração, o apply faz essa alteração na conta.

Para importar os recursos:

1. Aplique a importação:

   <Code client:visible lang="bash" code={`terraform apply`} />

   Digite `yes` quando o Terraform pedir para executar as ações:

   ```text
   azion_application_main_setting.site: Importing... [id=1795011484]
   azion_application_main_setting.site: Import complete [id=1795011484]
   azion_application_cache_setting.static_assets: Importing... [id=1795011484/395100]
   azion_application_cache_setting.static_assets: Import complete [id=1795011484/395100]

   Apply complete! Resources: 2 imported, 0 added, 0 changed, 0 destroyed.
   ```

2. Verifique se a configuração corresponde à conta:

   <Code client:visible lang="bash" code={`terraform plan`} />

   ```text
   No changes. Your infrastructure matches the configuration.
   ```

O Terraform gerencia os dois recursos, e a configuração dele corresponde aos valores deles na conta.

## Altere um recurso importado

Um recurso importado muda como qualquer outro recurso que o Terraform gerencia: edite o bloco dele e aplique. Depois da importação, uma alteração feita no [Azion Console](https://console.azion.com/) ou na API aparece como drift no próximo `terraform plan`. O próximo apply desfaz essa alteração. Para mais informações, consulte [A configuração é o estado desejado](/pt-br/documentacao/devtools/terraform/como-funciona/#a-configuracao-e-o-estado-desejado).

Para alterar o Max Age do cache setting importado:

1. No `generated.tf`, altere `max_age` dentro de `modules.cache` de `3600` para `7200` segundos.

2. Aplique a alteração:

   <Code client:visible lang="bash" code={`terraform apply`} />

   O Terraform mostra a alteração antes de pedir confirmação. Digite `yes`:

   ```text
     ~ resource "azion_application_cache_setting" "static_assets" {
         ~ cache_setting  = {
             ...
             ~ modules       = {
                 ~ cache                   = {
                     ~ max_age          = 3600 -> 7200
   ...
   Apply complete! Resources: 0 added, 1 changed, 0 destroyed.
   ```

O cache setting tem um Max Age de 7.200 segundos na conta.
