Você pode associar [Workloads](/pt-br/documentacao/plataforma/workloads/) a um stream do [Data Stream](/pt-br/documentacao/plataforma/data-stream/) pelo Azion Console ou com a Azion API. Para coletar de todos os Workloads com sampling em vez de escolhê-los, consulte [Configure sampling em um stream](/pt-br/documentacao/guias/plataforma/observabilidade/configurar-sampling/).

Um stream com filtro de workloads coleta os logs dos Workloads associados a ele e os envia ao endpoint dele. Um stream pode coletar de um único Workload ou de vários. Para cada campo do filtro, consulte [Configurações do stream](/pt-br/documentacao/plataforma/data-stream/configuracoes-do-stream/#transform).

Salvar um stream ativo com sampling em Applications, Functions ou WAF Events desativa todos os outros streams da conta, exceto os streams de Activity History. Um stream com filtro de workloads que você salva ou ativa depois roda ao lado do stream com sampling até que esse stream seja salvo de novo.

## Crie um stream para seus Workloads

Você escolhe os Workloads no mesmo formulário que define a fonte de dados, o template e o endpoint do stream. O exemplo usa a fonte de dados *Applications*.

Os eventos do Activity History pertencem à conta, e não a um Workload. Um stream de Activity History aceita um item de sampling ou nenhum item de escopo, e a API recusa um filtro de workloads nele (`10088`). Quando ele não carrega um item de sampling, a API o aceita, e o stream não envia nenhum evento.

<Tabs client:visible sharedStore="interface">

<Fragment slot="panel.console">

### Console

Para criar o stream no Azion Console:

<DocSteps>
  <DocStep title="Abra a página Data Stream">

  Acesse [Azion Console](https://console.azion.com/) > **Data Stream**.

  </DocStep>
  <DocStep title="Selecione + Stream" />
  <DocStep title="Dê um nome ao stream">

  Na seção **General**, digite um **Name**. Por exemplo: `workloads-to-http`.

  </DocStep>
  <DocStep title="Selecione a fonte de dados">

  Na seção **Input**, selecione *Applications* em **Data Source**. Para as outras fontes de dados, consulte [Fontes de dados e variáveis](/pt-br/documentacao/plataforma/data-stream/fontes-de-dados-e-variaveis/).

  </DocStep>
  <DocStep title="Desative Sampling">

  Na seção **Transform**, **Option** começa em *All Current and Future Workloads*, com **Sampling** ativado. Desative **Sampling** antes de alterar **Option**, para que o stream não tenha sampling.

  *All Current and Future Workloads* cobre todos os Workloads da conta, incluindo os que você criar depois. Salvar um stream ativo com sampling em Applications, Functions ou WAF Events desativa todos os outros streams da conta, exceto os streams de Activity History.

  </DocStep>
  <DocStep title="Escolha Filter Workloads">

  Defina **Option** como *Filter Workloads*. A lista de seleção **Workloads** se abre. Se o seu Console nomeia domínios, o controle aparece como *All Current and Future Domains* e *Filter Domains*. A lista de seleção passa a mostrar **Available Domain** e **Chosen Domain**.

  </DocStep>
  <DocStep title="Mova os Workloads para Chosen Workload">

  Use os controles da lista de seleção:

  - Para encontrar um Workload em **Available Workload**, digite caracteres na caixa de busca ou role a lista.
  - Para mover um Workload para **Chosen Workload**, selecione-o e depois selecione a seta `>`.
  - Para mover vários de uma vez, selecione-os com `ctrl` no Windows e no Linux ou `command` no Mac e depois selecione `>`.
  - Para mover todos os Workloads que a lista mostra, selecione `>>`.
  - Para remover Workloads de **Chosen Workload**, selecione-os e depois selecione `<`. Para remover todos, selecione `<<`.

  </DocStep>
  <DocStep title="Selecione o template">

  Na seção **Render Template**, selecione *Applications Event Collector* em **Template**. Para os outros templates, consulte [Templates e payload](/pt-br/documentacao/plataforma/data-stream/templates-e-payload/#templates-predefinidos).

  </DocStep>
  <DocStep title="Defina o endpoint">

  Na seção **Output**, selecione seu endpoint no campo rotulado **Connector** e preencha os campos dele. Para os campos de cada endpoint, consulte [Endpoints](/pt-br/documentacao/plataforma/data-stream/endpoints/).

  </DocStep>
  <DocStep title="Mantenha o stream ativo">

  Na seção **Status**, mantenha **Active** ativado.

  </DocStep>
  <DocStep title="Selecione Save" />
  <DocStep title="Cancele o aviso de sampling">

  Se o diálogo **Attention** se abrir, **Sampling** ainda está ativado. Para salvar o stream sem sampling:

  1. Selecione **Cancel**.
  2. Defina **Option** de volta como *All Current and Future Workloads*.
  3. Desative **Sampling**.
  4. Defina **Option** como *Filter Workloads* de novo.
  5. Confira que os seus Workloads estão em **Chosen Workload**.
  6. Selecione **Save**.

  </DocStep>
</DocSteps>

O Console mostra `Your data stream has been created`, e a lista **Data Stream** mostra o stream com o status *Active*.

</Fragment>

<Fragment slot="panel.api">

### API

Para criar o stream com a API, envie uma requisição `POST` com um item `filter_workloads` em `transform`. Substitua `[TOKEN VALUE]` pelo seu personal token, `<workload-id>` pelo ID do seu Workload e os valores do endpoint pelos seus:

```bash
curl -X POST 'https://api.azion.com/v4/workspace/stream/streams' \
  -H 'Content-Type: application/json' \
  -H 'Authorization: Token [TOKEN VALUE]' \
  -d '{
    "name": "workloads-to-http",
    "active": true,
    "inputs": [
      { "type": "raw_logs", "attributes": { "data_source": "workloads" } }
    ],
    "transform": [
      { "type": "filter_workloads", "attributes": { "workloads": [<workload-id>] } },
      { "type": "render_template", "attributes": { "template": 2 } }
    ],
    "outputs": [
      {
        "type": "standard",
        "attributes": {
          "url": "https://logs.example.com/ingest",
          "headers": { "Authorization": "Bearer [TOKEN]" }
        }
      }
    ]
  }'
```

A fonte de dados `workloads` é *Applications* no Console, e o template `2` é *Applications Event Collector*. Para coletar de vários Workloads, liste os IDs deles em `workloads`, de 1 a 600. A API responde `201` com o stream armazenado:

```json
{
  "state": "executed",
  "data": {
    "id": 12345,
    "name": "workloads-to-http",
    "last_editor": "user@example.com",
    "created": "2026-01-01T12:00:00.000000Z",
    "last_modified": "2026-01-01T12:00:00.000000Z",
    "product_version": "1.0",
    …
    "transform": [
      { "type": "filter_workloads", "attributes": { "workloads": [<workload-id>] } },
      { "type": "render_template", "attributes": { "template": 2 } }
    ],
    …
  }
}
```

O array `transform` contém o filtro de workloads que você enviou. Um ID que não é um Workload da sua conta é recusado com `400`:

```json
{"errors":[{"code":"32003","title":"Workloads Not Belong Account","detail":"Workloads [1] do not belong to the account.","status":"400","source":{"pointer":"/data/transform/0/attributes/workloads"},"meta":{"invalid_workloads":[1]}}]}
```

A API não tem opção para todos os Workloads. Em Applications, Functions ou WAF Events, um stream sem `filter_workloads` precisa de um item `sampling`. Salvar um stream ativo com sampling nessas fontes de dados desativa todos os outros streams da conta, exceto os streams de Activity History. Para esse caminho, consulte [Configure sampling em um stream](/pt-br/documentacao/guias/plataforma/observabilidade/configurar-sampling/).

</Fragment>

</Tabs>

O stream é salvo sem contatar o endpoint. Um stream que você cria ou ativa pode levar vários minutos para começar a coletar eventos, e ele não envia os eventos de antes disso.

## Confirme a entrega

[Real-Time Events](/pt-br/documentacao/plataforma/real-time-events/fontes-de-dados/#data-stream) registra cada envio de um stream, entregue ou não, com um código de status.

Para que o novo stream tenha eventos para enviar:

1. Aguarde alguns minutos depois de salvar o stream.
2. Envie algumas requisições a um Workload escolhido.

<Tabs client:visible sharedStore="interface">

<Fragment slot="panel.console">

### Console

Para encontrar os envios no Azion Console:

<DocSteps>
  <DocStep title="Abra a página Real-Time Events">

  Acesse [Azion Console](https://console.azion.com/) > **Real-Time Events**.

  </DocStep>
  <DocStep title="Selecione a fonte de dados Data Stream" />
  <DocStep title="Leia os envios mais recentes">

  Cada linha é um envio. Leia **Endpoint Type**, **Status Code** e **Streamed Lines** dela.

  </DocStep>
</DocSteps>

Um **Status Code** `200` significa que o endpoint aceitou o lote.

</Fragment>

<Fragment slot="panel.api">

### API

Para ler os envios com a API, faça uma query no dataset `dataStreamedEvents` da API GraphQL do Real-Time Events. Substitua as datas por um intervalo que cubra a ativação do stream:

```bash
curl -X POST 'https://api.azion.com/v4/events/graphql' \
  -H 'Content-Type: application/json' \
  -H 'Authorization: Token [TOKEN VALUE]' \
  -d '{"query":"query { dataStreamedEvents(limit: 20, filter: {tsRange: {begin: \"2026-10-02T19:45:00\", end: \"2026-10-02T20:30:00\"}}, orderBy: [ts_DESC]) { ts endpointType statusCode streamedLines dataStreamed } }"}'
```

A API responde `200` com um registro para cada envio, o mais recente primeiro:

```json
{
  "data": {
    "dataStreamedEvents": [
      {
        "ts": "2026-10-02T19:47:04Z",
        "endpointType": "S3",
        "statusCode": 200,
        "streamedLines": 2,
        "dataStreamed": 2797
      }
    ]
  }
}
```

Um `statusCode` `200` significa que o endpoint aceitou o lote, e `streamedLines` conta as linhas de log que ele levou. Uma lista `dataStreamedEvents` vazia significa que o stream não enviou nada no intervalo.

</Fragment>

</Tabs>

Se Real-Time Events não mostrar nenhum envio do stream depois de um minuto, envie outra requisição ao Workload e confira de novo.

Um envio que o endpoint aceitou mostra `200`. Um envio que falhou pode mostrar um código que o endpoint nunca retornou, e `503` significa que Data Stream encontrou o endpoint indisponível. Para encontrar a causa, consulte [Solucione problemas de Data Stream](/pt-br/documentacao/plataforma/data-stream/solucao-de-problemas/).
