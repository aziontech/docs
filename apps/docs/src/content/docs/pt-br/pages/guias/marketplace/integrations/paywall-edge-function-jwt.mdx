Um paywall construído com a função JWT tem duas partes: uma instância de função em um [firewall](/pt-br/documentacao/plataforma/firewall/) que valida o token e uma regra de firewall que executa a instância no conteúdo que você restringe. A função JWT é uma solução serverless disponível no Azion Marketplace e roda em um firewall, não em uma aplicação.

A aplicação de origem gera o token e define sua expiração. Ela também determina como o acesso é controlado:

- O método de autenticação, como OAuth, OpenID Connect, Auth0 ou Keycloak.
- O número de tentativas de acesso ou de bytes que um visitante consome antes de precisar fazer login.
- Por quanto tempo um visitante navega sem autorização adicional.

O token segue o Bearer Authentication Scheme, o padrão de autenticação HTTP. Cada requisição carrega no cabeçalho um objeto JSON com as informações de autenticação.

A função JWT valida esse token em cada requisição que o firewall inspeciona. Ela segue as regras de negócio definidas no token e essas regras se combinam com os critérios que você define no Rules Engine do firewall. O resultado determina o comportamento aplicado: a requisição alcança o conteúdo ou vai para a página de login da aplicação de origem. A validação acontece no firewall, antes de a requisição chegar à aplicação ou à origem, então a origem não processa uma requisição não autorizada.

## Pré-requisitos

- Uma aplicação servida por um [workload](/pt-br/documentacao/plataforma/workloads/). Para criar uma, consulte [Primeiros passos com Applications](/pt-br/documentacao/plataforma/applications/primeiros-passos/).
- A função JWT instalada na conta. Para instalar, consulte [Use a integração JWT no Azion Marketplace](/pt-br/documentacao/guias/desenvolvimento-de-aplicacoes/integracoes/jwt/).
- Um firewall com o módulo **Functions** ativado, vinculado ao deployment do workload. Para criar um, consulte [Crie o firewall](/pt-br/documentacao/guias/desenvolvimento-de-aplicacoes/integracoes/jwt/#crie-o-firewall) e, para vinculá-lo, [Vincule um firewall a um workload](/pt-br/documentacao/guias/seguranca-de-aplicacoes/firewall-e-waf/proteja-seu-dominio/#vincule-o-firewall-ao-workload).
- A lista de pares de KID e chave secreta que a aplicação de origem usa para assinar o token.

## Instancie a função JWT no firewall

Um firewall executa uma função por meio de uma instância de função e a instância carrega os argumentos passados para o contexto de execução. Para o procedimento completo em Azion Console e na Azion API, consulte [Instancie uma função em um firewall](/pt-br/documentacao/guias/seguranca-de-aplicacoes/firewall-e-waf/instanciar-functions/).

O campo **Arguments** recebe a lista de pares de KID (key ID) e chave secreta que geram a assinatura do token. A aplicação de origem define os pares. Para criar a instância:

<DocSteps>
  <DocStep title="Abra a aba Functions Instances">

  Acesse [Azion Console](https://console.azion.com/) > **Firewalls**, selecione seu firewall e, em seguida, a aba **Functions Instances**.

  </DocStep>
  <DocStep title="Selecione + Function">

  Um firewall que não tem instância mostra a mesma ação como **Function Instance**. A gaveta **Create Instance** se abre.

  </DocStep>
  <DocStep title="Nomeie a instância">

  Insira um nome para a instância. Por exemplo: `paywall-jwt`.

  </DocStep>
  <DocStep title="Selecione a função JWT na lista Function" />
  <DocStep title="Insira os pares de KID e chave secreta">

  Em **Arguments**, insira os pares neste formato:

  ```json
  [{
    "kids": {
      "4546D4AA7F62F01A833A7ABE354030E7": "D6CB2342E44EFB6DD628276F36DA2359",
      "D6CB2342E44EFB6DD628276F36DA2359": "60BD8ED7A768E8BD6925BEB0A691AADB",
      "60BD8ED7A768E8BD6925BEB0A691AADB": "4546D4AA7F62F01A833A7ABE354030E7"
    }
  }]
  ```

  </DocStep>
  <DocStep title="Selecione Save" />
</DocSteps>

A instância aparece na aba **Functions Instances** do firewall. Ela não é executada até que uma regra de firewall a selecione.

## Adicione a regra que executa a função

Uma regra de firewall define as condições que uma requisição atende para que seus comportamentos sejam executados. Um critério é formado por variável, operador de comparação e string. O comportamento que executa a função é o **Run Function**, com a instância que você criou. Ajuste os critérios aos caminhos que você vende por assinatura e à autenticação que a aplicação de origem já usa.

Para criar a regra:

<DocSteps>
  <DocStep title="Abra o firewall">

  Acesse [Azion Console](https://console.azion.com/) > **Firewalls** > **seu firewall**.

  </DocStep>
  <DocStep title="Vá para a aba Rules Engine" />
  <DocStep title="Selecione + Rule" />
  <DocStep title="Nomeie a regra">

  Insira um nome para a regra. Por exemplo: `Paywall on news`.

  </DocStep>
  <DocStep title="Defina o critério">

  Na seção **Criteria**, selecione `Request Uri`, _starts with_ e insira `/news`. O critério fica `If ${request_uri} starts with /news`.

  </DocStep>
  <DocStep title="Adicione o behavior Run Function">

  Na seção **Behaviors**, selecione **Run Function** e, em seguida, a instância pelo nome que você deu a ela.

  </DocStep>
  <DocStep title="Selecione Save" />
</DocSteps>

O firewall executa a função JWT em toda requisição ao workload cuja URI começa com `/news`. Novas regras podem levar alguns minutos para propagar.

:::note[nota]
A função retorna um código de status HTTP `400` ou `401` quando o token recebido é inválido. O código depende do erro.
:::
