Você pode implantar uma aplicação integrada ao MongoDB Atlas na Azion a partir do template MongoDB Atlas Boilerplate no Azion Console. Para criar uma aplicação sem um template, consulte [Primeiros passos com Applications](/pt-br/documentacao/plataforma/applications/primeiros-passos/).

O template integra a aplicação à Atlas Data API. Com essa integração, você pode criar, recuperar, atualizar e excluir itens nas suas *collections* por meio de requisições HTTPS padrão. Azion Web Platform executa o seu projeto de banco de dados na infraestrutura distribuída da Azion, que dá aos seus dados e ativos digitais entrega mais rápida, menor latência e segurança aprimorada.

A implantação cria um repositório no GitHub para o seu projeto, uma [aplicação](/pt-br/documentacao/plataforma/applications/) que o executa, uma função para lógica personalizada e um domínio para acessá-lo. O template usa [Application Accelerator](/pt-br/documentacao/plataforma/applications/application-accelerator/) e [Functions](/pt-br/documentacao/plataforma/functions/), e o uso deles pode gerar custos. Para mais informações, consulte [Preços](/pt-br/documentacao/fundamentos/precos/).

:::caution[Atenção]
A MongoDB encerrou a [Atlas Data API](https://www.mongodb.com/docs/atlas/app-services/data-api/) em 30 de setembro de 2025. O template ainda aparece no Azion Console, mas a função dele chama a Data API, então uma nova implantação não consegue se conectar à sua *collection*. Não use este template em novos projetos. Para acessar o MongoDB Atlas a partir de uma função, chame uma API própria na frente do banco de dados.
:::

## Pré-requisitos

- Uma conta Azion. Para criar uma, consulte [Criar uma conta](/pt-br/documentacao/fundamentos/criar-uma-conta/).
- Acesso ao Azion Console. Para entrar, consulte [Como acessar o Azion Console](/pt-br/documentacao/guias/plataforma/conta-e-billing/como-acessar-o-azion-console/).
- Uma [conta na MongoDB](https://www.mongodb.com/cloud/atlas/register).
- Um [cluster](https://www.mongodb.com/docs/atlas/create-database-deployment/) no MongoDB Atlas, com um novo *database* adicionado a ele.
- Uma *collection* nesse *database*, criada para ser usada com este template.
- O serviço [Atlas Data API](https://www.mongodb.com/docs/atlas/app-services/data-api/) ativado.
- Uma API key gerada no [Atlas Service](https://www.mongodb.com/docs/atlas/app-services/authentication/api-key/#std-label-api-key-authentication).
- Uma [conta no GitHub](https://github.com/signup). A Azion se conecta a essa conta e cria nela o repositório do projeto.

A MongoDB processa e cobra separadamente, na plataforma dela, qualquer custo gerado pelo uso da MongoDB. Para mais informações, consulte a [documentação da MongoDB Atlas](https://www.mongodb.com/docs/atlas/).

## Implante o template

O MongoDB Atlas Boilerplate abre como um formulário de configuração no Azion Console, e um asterisco marca cada campo obrigatório. Todos os campos que este procedimento cita são obrigatórios.

Para implantar o template:

<DocSteps>
  <DocStep title="Abra o template">

  Acesse [MongoDB Atlas Boilerplate](https://console.azion.com/create/mongodb-atlas/mongodb--atlas) no Azion Console. O formulário de configuração abre.

  </DocStep>
  <DocStep title="Conecte a Azion à sua conta do GitHub">

  Uma janela abre para confirmar a instalação do [Azion GitHub App](/pt-br/documentacao/guias/desenvolvimento-de-aplicacoes/automacao/azion-github-app/), que conecta a sua conta do GitHub à Azion. Nessa janela, defina as permissões do app e o acesso aos repositórios.

  </DocStep>
  <DocStep title="Selecione o Git scope com o qual trabalhar" />
  <DocStep title="Nomeie a aplicação">

  Em **Application Name**, insira um nome único e fácil de lembrar. O nome identifica a aplicação na Azion. O bucket de armazenamento e a função que o template cria recebem o mesmo nome. Se o nome já estiver em uso, a plataforma retorna uma mensagem de erro.

  </DocStep>
  <DocStep title="Insira os dados de conexão do MongoDB Atlas">

  Insira os dados que conectam a aplicação aos seus dados no MongoDB Atlas:

  - **Atlas API Token**: o token que autoriza a conexão com a Atlas Data API.
  - **Atlas API URL**: a URL do endpoint atribuído para conectar com a Atlas Data API.
  - **Collection Name**: o nome de uma *collection* criada no *database* especificado.
  - **Database Name**: o nome do *database* criado na *data source* do MongoDB Atlas.
  - **dataSource Name**: o nome da *data source* ou do cluster que você criou no MongoDB Atlas.

  </DocStep>
  <DocStep title="Inicie a implantação">

  Selecione **Deploy**.

  </DocStep>
</DocSteps>

Uma janela mostra os logs da implantação enquanto ela é executada. Quando a implantação termina, a página mostra os detalhes da aplicação, um link para abri-la no navegador e opções para continuar. Ao final da implantação, você tem:

- Um repositório no GitHub para o seu projeto.
- Uma GitHub Action nesse repositório que, ao ser ativada, garante um fluxo de trabalho de implantação contínua.
- Uma aplicação na Azion Platform que executa o seu projeto e reúne todas as configurações dele.
- Um domínio de workload para acessar a aplicação. Você também pode configurar um domínio personalizado para a aplicação.
- Uma função que contém lógica personalizada.
- Uma integração com o MongoDB Atlas e a Atlas Data API, que atua como um middleware para gerenciar e acessar o seu banco de dados.

O link pode levar alguns minutos para começar a entregar a aplicação, enquanto a configuração dela se propaga pela infraestrutura distribuída da Azion. Se a página não carregar, aguarde alguns minutos e abra o link novamente.

## Atualize o projeto

Cada push para o repositório do GitHub que o MongoDB Atlas Boilerplate cria é implantado automaticamente.

Para atualizar o projeto implantado, faça push das suas alterações para esse repositório. A Azion implanta as alterações, e a aplicação entrega a nova versão.

## Exemplos de requisições HTTPS

Estes exemplos chamam a Atlas Data API, que a MongoDB encerrou em 30 de setembro de 2025.

A integração com a Atlas Data API dá acesso aos dados por meio de requisições HTTPS padrão. A API atua como um middleware que acessa e gerencia os seus dados, e ela fica entre o seu cluster e as requisições dos clientes.

Você pode criar, recuperar, atualizar e excluir itens nas suas *collections* com qualquer ferramenta que envie requisições HTTPS padrão, como o seu terminal ou o Postman. A API tem um endpoint dedicado para cada operação.

Todas as requisições retornam uma resposta no formato `JSON` ou `EJSON`, com as informações de acordo com o código de status: `200 Success`, `400 Bad Request` e `401 Unauthorized`.

:::tip[dica]
Para mais exemplos e para aprender a trabalhar com lotes (*batches*), acesse a documentação da [Atlas Data API](https://www.mongodb.com/docs/atlas/app-services/data-api/).
:::

### Encontre um documento

Para encontrar um documento, envie uma requisição `POST` para o endpoint `findOne`:

```bash
curl -s "https://data.mongodb-api.com/app/$CLIENT_APP_ID/endpoint/data/v1/action/findOne" \
  -X POST \
  -H "apiKey: $API_KEY" \
  -H 'Content-Type: application/ejson' \
  -H "Accept: application/json" \
  -d '{
    "dataSource": "my-datasource",
    "database": "my-database-azion",
    "collection": "template",
    "filter": {
      "text": "Do the dishes"
    }
  }'
```

Onde:

| Variável | Obrigatória | Tipo | Descrição |
|---|---|---|---|
| `dataSource` | Sim | String | O nome da sua *data source* ou do seu cluster |
| `database` | Sim | String | O nome do *database* na *data source* |
| `collection` | Sim | String | O nome de uma *collection* criada no *database* especificado |
| `filter` | Sim | Object | Um operador de consulta para filtrar os documentos |

### Insira um documento

Para inserir um documento, envie uma requisição `POST` para o endpoint `insertOne`:

```bash
curl -s "https://data.mongodb-api.com/app/$CLIENT_APP_ID/endpoint/data/v1/action/insertOne" \
  -X POST \
  -H "apiKey: $API_KEY" \
  -H 'Content-Type: application/ejson' \
  -H "Accept: application/json" \
  -d '{
    "dataSource": "my-datasource",
    "database": "my-database-azion",
    "collection": "template",
    "document": {
      "status": "open",
      "text": "Do the dishes"
    }
  }'
```

Onde:

| Variável | Obrigatória | Tipo | Descrição |
|---|---|---|---|
| `dataSource` | Sim | String | O nome da sua *data source* ou do seu cluster |
| `database` | Sim | String | O nome do *database* na *data source* |
| `collection` | Sim | String | O nome de uma *collection* criada no *database* especificado |
| `document` | Sim | Object | O documento a inserir na *collection* |

### Atualize um documento

Para atualizar um documento, envie uma requisição `POST` para o endpoint `updateOne`:

```bash
curl -s "https://data.mongodb-api.com/app/$CLIENT_APP_ID/endpoint/data/v1/action/updateOne" \
  -X POST \
  -H "apiKey: $API_KEY" \
  -H 'Content-Type: application/ejson' \
  -H "Accept: application/json" \
  -d '{
    "dataSource": "my-datasource",
    "database": "my-database-azion",
    "collection": "template",
    "filter": {
      "_id": { "$oid": "64224f4d089104f1766116a5" }
    },
    "update": {
      "$set": {
        "status": "complete",
        "completedAt": { "$date": { "$numberLong": "1680105272788" } }
      }
    }
  }'
```

Onde:

| Variável | Obrigatória | Tipo | Descrição |
|---|---|---|---|
| `dataSource` | Sim | String | O nome da sua *data source* ou do seu cluster |
| `database` | Sim | String | O nome do *database* na *data source* |
| `collection` | Sim | String | O nome de uma *collection* criada no *database* especificado |
| `filter` | Sim | Object | Um operador de consulta para filtrar os documentos |
| `update` | Sim | Object | Uma expressão de atualização a aplicar aos documentos correspondentes |

### Exclua um documento

Para excluir um documento, envie uma requisição `POST` para o endpoint `deleteOne`:

```bash
curl -s "https://data.mongodb-api.com/app/$CLIENT_APP_ID/endpoint/data/v1/action/deleteOne" \
  -X POST \
  -H "apiKey: $API_KEY" \
  -H 'Content-Type: application/ejson' \
  -H "Accept: application/json" \
  -d '{
    "dataSource": "my-datasource",
    "database": "my-database-azion",
    "collection": "template",
    "filter": {
      "_id": { "$oid": "64224f3cd79f54ad342dd9b2" }
    }
  }'

```

Onde:

| Variável | Obrigatória | Tipo | Descrição |
|---|---|---|---|
| `dataSource` | Sim | String | O nome da sua *data source* ou do seu cluster |
| `database` | Sim | String | O nome do *database* na *data source* |
| `collection` | Sim | String | O nome de uma *collection* criada no *database* especificado |
| `filter` | Não | Object | Um operador de consulta para filtrar os documentos |

## Gerencie a aplicação

As configurações que o MongoDB Atlas Boilerplate aplica podem não servir para a sua aplicação. Você pode alterar qualquer uma delas a qualquer momento pelo Azion Console.

Para abrir as configurações da aplicação:

<DocSteps>
  <DocStep title="Abra a lista de aplicações">

  Acesse [Azion Console](https://console.azion.com/) > **Applications**. A lista mostra todas as aplicações que você criou, em ordem alfabética.

  </DocStep>
  <DocStep title="Selecione a aplicação que o template criou">

  Para encontrá-la em uma lista longa, busque pelo nome dela. A busca filtra a lista apenas pelo **Application Name**.

  </DocStep>
</DocSteps>

A aplicação abre em uma página que reúne todas as configurações que você pode definir. Para mais informações, consulte [Main Settings](/pt-br/documentacao/plataforma/applications/main-settings/), [Rules Engine para Applications](/pt-br/documentacao/plataforma/applications/rules-engine/) e [Device Groups](/pt-br/documentacao/plataforma/applications/device-groups/).

## Adicione um domínio personalizado

A implantação do MongoDB Atlas Boilerplate atribui à aplicação um domínio de [workload](/pt-br/documentacao/plataforma/workloads/) no formato `xxxxxxxxxx.map.azionedge.net`, que um navegador consegue abrir. Para entregar a aplicação em um domínio seu, adicione um domínio personalizado. Para adicionar um, consulte [Adicione um domínio a um workload](/pt-br/documentacao/guias/plataforma/migracao/configurar-dominio/). Para mais informações, consulte [Domains](/pt-br/documentacao/plataforma/workloads/domains/).
