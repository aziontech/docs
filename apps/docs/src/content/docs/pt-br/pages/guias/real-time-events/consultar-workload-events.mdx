Você pode ler o registro de evento de uma única requisição no [Real-Time Events](/pt-br/documentacao/plataforma/real-time-events/). Use o Azion Console ou uma consulta à API GraphQL dele. Os registros ficam na fonte de dados HTTP Requests, que a API chama de dataset `workloadEvents`. Ela guarda um registro por requisição que uma [Application](/pt-br/documentacao/plataforma/applications/) ou um [Firewall](/pt-br/documentacao/plataforma/firewall/) recebeu.

As duas interfaces escrevem a mesma condição de maneiras diferentes. No Azion Console, um filtro de status aparece como `status = 400` no campo de consulta. A API GraphQL recebe o argumento em camelCase `statusIn: [400]`. As duas listam os campos de um registro pelos mesmos nomes em camelCase, como `requestId`.

### Console

- Uma Application ou um Firewall que já atende tráfego. Assim, a fonte de dados HTTP Requests tem registros para ler.
- Um valor que identifique a requisição: um host, um código de status HTTP ou o request id que uma resposta carrega no cabeçalho `x-azion-request-id`.
- Acesso ao Azion Console. Para entrar, consulte [Como acessar o Azion Console](/pt-br/documentacao/guias/plataforma/conta-e-billing/como-acessar-o-azion-console/).

</Fragment>

<Fragment slot="panel.api">

### API

- Uma Application ou um Firewall que já atende tráfego. Assim, a fonte de dados HTTP Requests tem registros para ler.
- Um valor que identifique a requisição: um host, um código de status HTTP ou o request id que uma resposta carrega no cabeçalho `x-azion-request-id`.
- Um personal token. Para criar um, consulte [Personal Tokens](/pt-br/documentacao/fundamentos/personal-tokens/).

</Fragment>

O período que uma consulta pode pedir é limitado por quanto tempo um registro de evento é mantido. Para esse limite e os outros que uma consulta carrega, consulte [Limites](/pt-br/documentacao/plataforma/real-time-events/limites/).

## Leia o registro de uma requisição

<Tabs client:visible sharedStore="interface">

<Fragment slot="panel.console">

### Console

Uma busca é uma fonte de dados, um período e um filtro sobre eles. Para abrir o registro de uma requisição no Azion Console:

<DocSteps>
  <DocStep title="Abra Real-Time Events">

  Acesse [Azion Console](https://console.azion.com/) > **Real-Time Events**.

  </DocStep>
  <DocStep title="Selecione a fonte de dados">

  Selecione a aba **HTTP Requests**.

  </DocStep>
  <DocStep title="Abra o período">

  Selecione o campo de período, que mostra _Last 5 minutes_.

  </DocStep>
  <DocStep title="Selecione o período">

  Selecione **Quick** e depois um período que contenha a requisição, como _Last 24 hours_.

  </DocStep>
  <DocStep title="Execute a busca">

  Selecione **Update**.

  </DocStep>
  <DocStep title="Abra o filtro">

  Selecione o ícone de filtro.

  </DocStep>
  <DocStep title="Selecione o campo">

  Em **Filter**, selecione _Request Id_.

  </DocStep>
  <DocStep title="Defina a condição">

  Em **Operator**, selecione _Equals_ e digite o request id no campo de valor.

  </DocStep>
  <DocStep title="Aplique o filtro">

  Selecione **Apply**.

  </DocStep>
  <DocStep title="Abra o registro">

  Selecione a linha da requisição na tabela de resultados.

  </DocStep>
</DocSteps>

A visualização **More Details** abre, com todos os campos daquela única requisição e o valor de cada um.

**Apply** executa a busca na mesma hora. Sem um request id em mãos, filtre por outro valor que você tem, como _Host_ ou _Status_. Um filtro de status aparece como `status = 400` no campo de consulta, e você também pode digitá-lo ali e selecionar **Update**. Para o significado de cada campo desta fonte de dados, consulte [Fontes de dados](/pt-br/documentacao/plataforma/real-time-events/fontes-de-dados/).

:::note[nota]
Azion Console também oferece uma visualização mais recente de Real-Time Events, em Preview, acessada por **Switch to new view**. As etapas seguem a visualização clássica, que é a visualização em que Real-Time Events abre.
:::

</Fragment>

### API

A API GraphQL serve os mesmos registros em `https://api.azion.com/v4/events/graphql`. Esse endereço também serve o GraphiQL Playground em um navegador: entre no Azion Console em `https://console.azion.com` e depois abra o endpoint. Para enviar a consulta de um terminal, envie-a com um cabeçalho `Authorization: Token [TOKEN VALUE]`, como descreve [Primeiros passos da API GraphQL](/pt-br/documentacao/devtools/graphql/primeiros-passos/).

Uma consulta sobre `workloadEvents` carrega as mesmas três escolhas. `tsRange` delimita o período, um argumento de filtro como `requestIdEq` reduz o que é lido dentro dele e o conjunto de seleção nomeia os campos com que a resposta volta.

Para retornar o registro de uma requisição:

```graphql
{
  workloadEvents(
    limit: 1
    filter: {
      tsRange: { begin: "<your-period-start>", end: "<your-period-end>" }
      requestIdEq: "<your-request-id>"
    }
  ) {
    ts
    requestId
    host
    status
    upstreamStatus
  }
}
```

Substitua `<your-period-start>` e `<your-period-end>` por timestamps em torno da requisição, no formato `YYYY-MM-DDTHH:MM:SS`. Substitua `<your-request-id>` pelo valor do cabeçalho `x-azion-request-id`.

A consulta retorna uma única linha:

```json
{
  "ts": "2026-01-01T12:00:00Z",
  "requestId": "0123456789abcdef0123456789abcdef",
  "host": "<your-workload-domain>",
  "status": 400,
  "upstreamStatus": 0
}
```

A linha é o registro de evento daquela requisição. Um `upstreamStatus` `0` significa que a requisição nunca chegou a uma origem.

Uma resposta carrega os campos que a consulta selecionou e nenhum outro, portanto, para ler mais campos do mesmo registro, nomeie-os na consulta. Para todos os campos que `workloadEvents` carrega, consulte [Campos da API GraphQL do Real-Time Events](/pt-br/documentacao/devtools/graphql/campos-gql-real-time-events/).
