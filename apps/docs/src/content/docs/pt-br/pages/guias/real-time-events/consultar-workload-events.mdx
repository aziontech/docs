Você pode ler o registro de evento de uma única requisição no [Real-Time Events](/pt-br/documentacao/plataforma/real-time-events/), no Azion Console ou com uma consulta à API GraphQL dele. Os registros ficam na fonte de dados HTTP Requests, que a API entrega como o dataset `workloadEvents`: um registro por requisição que uma [aplicação](/pt-br/documentacao/plataforma/applications/) ou um [firewall](/pt-br/documentacao/plataforma/firewall/) recebeu.

As duas interfaces nomeiam o mesmo valor de maneiras diferentes. Azion Console recebe o nome da variável em minúsculas, com underscores, como em `status='400'`. A API GraphQL recebe o campo em camelCase, como em `statusIn: [400]`.

---

## Pré-requisitos

- Uma aplicação ou um firewall que já atende tráfego, para que a fonte de dados HTTP Requests tenha registros para ler.
- Um valor que identifique a requisição: um host, um código de status HTTP ou o request id que uma resposta carrega no cabeçalho `x-azion-request-id`.
- Acesso ao Azion Console, para o procedimento no Console. Para entrar, consulte [Como acessar o Azion Console](/pt-br/documentacao/guias/plataforma/conta-e-billing/como-acessar-o-azion-console/).
- Um personal token, para a consulta GraphQL. Para criar um, consulte [Personal Tokens](/pt-br/documentacao/fundamentos/personal-tokens/).

O período que uma consulta pode pedir é limitado por quanto tempo um registro de evento é mantido. Para esse limite e os outros que uma consulta carrega, consulte [Limites](/pt-br/documentacao/plataforma/real-time-events/limites/).

## Leia o registro de uma requisição

<Fragment slot="tab.console">Console</Fragment>

<Fragment slot="panel.console">

Uma busca é uma fonte de dados, um período e um filtro sobre eles. Para abrir o registro de uma requisição no Azion Console:

<DocSteps>
  <DocStep title="Abra Real-Time Events">

  Acesse [Azion Console](https://console.azion.com) > **Products menu** > **Observe** > **Real-Time Events**.

  </DocStep>
  <DocStep title="Selecione a fonte de dados">

  Em **Data Sources**, selecione _HTTP Requests_.

  </DocStep>
  <DocStep title="Defina o período">

  Em **Time Filter**, selecione um período que contenha a requisição. O filtro abre em _Last 15 minutes_.

  </DocStep>
  <DocStep title="Reduza o resultado">

  Em **Filter by**, informe uma condição construída com os valores que você tem:

  ```text
  host='<your-workload-domain>' AND status='400'
  ```

  </DocStep>
  <DocStep title="Selecione Refresh" />
  <DocStep title="Abra o registro">

  Selecione a linha da requisição na tabela de resultados.

  </DocStep>
</DocSteps>

A visualização **More details** abre, com todas as variáveis que a fonte de dados HTTP Requests guarda para aquela única requisição.

**Filter by** lê SQL, e `AND`, `OR` e `NOT` combinam termos. Para a sintaxe completa, consulte [Filtrar eventos](/pt-br/documentacao/guias/plataforma/observabilidade/adicionar-filtros-events/). Para o significado de cada variável desta fonte de dados, consulte [Fontes de dados](/pt-br/documentacao/plataforma/real-time-events/fontes-de-dados/).

:::note[nota]
Azion Console também oferece uma visualização mais recente de Real-Time Events, em Preview, acessada por **Switch to new view**. As etapas acima seguem a classic view, que é a visualização em que Real-Time Events abre.
:::

</Fragment>

<Fragment slot="panel.api">

A API GraphQL serve os mesmos registros em `https://api.azion.com/v4/events/graphql`. Esse endereço também serve o GraphiQL Playground em um navegador: entre no Azion Console em `https://console.azion.com` e depois abra o endpoint. Para enviar a consulta de um terminal, envie-a com um cabeçalho `Authorization: Token [TOKEN VALUE]`, como descreve [Primeiros passos da API GraphQL](/pt-br/documentacao/devtools/graphql/primeiros-passos/).

Uma consulta sobre `workloadEvents` carrega as mesmas três escolhas. `tsRange` delimita o período, um argumento de filtro como `requestIdEq` reduz o que é lido dentro dele e o conjunto de seleção nomeia os campos com que a resposta volta.

Para retornar o registro de uma requisição, substituindo os timestamps e o request id pelos seus:

```graphql
{
  workloadEvents(
    limit: 1
    filter: {
      tsRange: { begin: "2026-01-01T11:55:00", end: "2026-01-01T12:05:00" }
      requestIdEq: "0123456789abcdef0123456789abcdef"
    }
  ) {
    ts
    requestId
    host
    status
    upstreamStatus
  }
}
```

A consulta retorna uma única linha:

```json
{
  "ts": "2026-01-01T12:00:00Z",
  "requestId": "0123456789abcdef0123456789abcdef",
  "host": "<your-workload-domain>",
  "status": 400,
  "upstreamStatus": 0
}
```

A linha é o registro de evento daquela requisição. Um `upstreamStatus` `0` significa que a requisição nunca chegou a uma origem.

Uma resposta carrega os campos que a consulta selecionou e nenhum outro, portanto ler mais de um registro significa nomear mais campos. Para todos os campos que `workloadEvents` carrega, consulte [Campos da API GraphQL do Real-Time Events](/pt-br/documentacao/devtools/graphql/campos-gql-real-time-events/).
