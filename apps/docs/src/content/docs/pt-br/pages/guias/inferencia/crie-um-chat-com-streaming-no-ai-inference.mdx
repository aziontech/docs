Neste tutorial, você vai criar uma página de chat cujas respostas chegam em streaming de um modelo no [AI Inference](/pt-br/documentacao/plataforma/ai-inference/). Você vai escrever uma Function que chama o modelo, publicá-la por meio de uma Application e de um Workload e enviar uma pergunta a ela.

Cada recurso que o tutorial cria se liga a um criado antes dele:

1. A [Function](/pt-br/documentacao/plataforma/functions/) guarda o código: uma página de chat e um endpoint que envia cada pergunta ao modelo.
2. A [Application](/pt-br/documentacao/plataforma/applications/) tem Functions ativado, uma function instance que vincula a Function e uma regra de requisição que a executa em todos os caminhos.
3. O [Workload](/pt-br/documentacao/plataforma/workloads/) guarda o domínio que recebe as requisições, e o deployment dele define a Application que as responde.

Os recursos são os mesmos no Azion Console, na Azion CLI e na API. Selecione a interface que você usa, e cada etapa mostra os passos dela.

## 1. Escreva a Function

Crie um diretório para o tutorial, entre nele e crie um arquivo `index.js` com este código:

```javascript title="index.js"
const MODEL = 'Qwen/Qwen3-30B-A3B-Instruct-2507-FP8'

const PAGE = `<!doctype html>
<html lang="en">
<head><meta charset="utf-8"><title>Chat</title></head>
<body>
  <form id="form">
    <label for="prompt">Ask a question</label>
    <input id="prompt" name="prompt" required>
    <button type="submit">Send</button>
  </form>
  <pre id="answer"></pre>
  <script>
    document.getElementById('form').addEventListener('submit', async (event) => {
      event.preventDefault()
      const answer = document.getElementById('answer')
      answer.textContent = ''
      const response = await fetch('/api/chat', {
        method: 'POST',
        headers: { 'content-type': 'application/json' },
        body: JSON.stringify({ prompt: document.getElementById('prompt').value })
      })
      const reader = response.body.getReader()
      const decoder = new TextDecoder()
      while (true) {
        const { done, value } = await reader.read()
        if (done) break
        answer.textContent += decoder.decode(value, { stream: true })
      }
    })
  </script>
</body>
</html>`

async function chat(request) {
  const { prompt } = await request.json()
  if (typeof prompt !== 'string' || prompt.trim() === '') {
    return new Response('prompt is required', { status: 400 })
  }
  let chunks
  try {
    chunks = await Azion.AI.run(MODEL, {
      stream: true,
      max_tokens: 300,
      messages: [
        { role: 'system', content: 'You are a helpful assistant. Answer in three sentences or fewer.' },
        { role: 'user', content: prompt }
      ]
    })
  } catch (error) {
    return new Response(`AI Inference error: ${error.message}`, { status: 502 })
  }
  const encoder = new TextEncoder()
  const body = new ReadableStream({
    async start(controller) {
      for await (const chunk of chunks) {
        const text = chunk?.choices?.[0]?.delta?.content
        if (text) controller.enqueue(encoder.encode(text))
      }
      controller.close()
    }
  })
  return new Response(body, { headers: { 'content-type': 'text/plain; charset=utf-8' } })
}

export default {
  async fetch(request) {
    const { pathname } = new URL(request.url)
    if (pathname === '/api/chat' && request.method === 'POST') return chat(request)
    if (pathname === '/') return new Response(PAGE, { headers: { 'content-type': 'text/html; charset=utf-8' } })
    return new Response('Not found', { status: 404 })
  }
}
```

A Function responde a duas rotas:

- `GET /` devolve a página de chat. A página envia a pergunta para `/api/chat` e escreve a resposta à medida que ela chega.
- `POST /api/chat` chama o modelo com `stream: true`. Assim, `Azion.AI.run` resolve num iterador assíncrono de chunks, e a Function escreve o texto de cada chunk, `choices[0].delta.content`, na resposta. Para todos os campos da requisição e dos chunks, consulte [Invocação de modelos](/pt-br/documentacao/plataforma/ai-inference/invocacao-de-modelos/).

Quando a chamada ao modelo falha, a Function responde `502` com a mensagem de erro, para que o motivo chegue ao navegador. Uma pergunta vazia responde `400` e não executa nenhum modelo.

## 2. Crie a Function

<Tabs client:visible sharedStore="interface">

<Fragment slot="panel.console">

### Console

Para criar a Function no Azion Console:

1. Acesse [Azion Console](https://console.azion.com/) > **Functions**.
2. Selecione **+ Function**.
3. Em **Name**, digite `ai-chat`.
4. Mantenha **Application** selecionado em **Execution Environment**.
5. Selecione a aba **Code**.
6. Substitua o código de exemplo do editor pelo conteúdo do `index.js`.
7. Selecione **Save**.

O Console mostra a mensagem **Your function has been created**, e `ai-chat` aparece na lista de Functions.

</Fragment>

<Fragment slot="panel.cli">

### CLI

Crie a Function a partir do `index.js`:

```bash
azion create function --name ai-chat --code index.js --execution-environment application --active true
```

```text
Created function with ID 110005
```

Guarde o ID que o seu comando imprimiu. Substitua `110005` pelo seu ID:

```bash
FUNCTION_ID=110005
```

</Fragment>

<Fragment slot="panel.api">

### API

Guarde o seu personal token numa variável do shell. Substitua `<your-personal-token>` pelo seu token:

```bash
export AZION_API_TOKEN="<your-personal-token>"
```

Envie uma requisição `POST` ao endpoint de functions. O `jq` lê o `index.js` para o campo `code`:

```bash
jq -n --rawfile code index.js \
  '{name: "ai-chat", code: $code, runtime: "azion_js", execution_environment: "application"}' \
| curl --silent https://api.azion.com/v4/workspace/functions \
  --header "Authorization: Token $AZION_API_TOKEN" \
  --header 'Content-Type: application/json' \
  --data @- \
| tee function.json
```

```json
{"state": "pending", "data": {"id": 110012, "name": "ai-chat", "active": true, "runtime": "azion_js", "execution_environment": "application", ...}}
```

Guarde o ID da Function:

```bash
FUNCTION_ID=$(jq .data.id function.json)
```

</Fragment>

</Tabs>

A conta guarda a Function. Ela só é executada depois que uma Application a vincula.

## 3. Crie a Application

A Application precisa de três partes: a própria Application com Functions ativado, uma function instance que vincula a Function e uma regra que executa a instance.

<Tabs client:visible sharedStore="interface">

<Fragment slot="panel.console">

### Console

Para criar a Application:

1. Acesse [Azion Console](https://console.azion.com/) > **Applications**.
2. Selecione **+ Application**.
3. Em **Name**, digite `ai-chat`.
4. Em **Modules**, ative **Functions**.
5. Selecione **Create**.

O Console abre a Application nova na aba **Main Settings**.

Para vincular a Function:

1. Selecione a aba **Functions Instances**.
2. Selecione **+ Function**.
3. Em **Name**, digite `ai-chat`.
4. Em **Function**, selecione `ai-chat`.
5. Selecione **Save**.

A instance aparece na aba **Functions Instances**.

Para executar a Function em toda requisição:

1. Selecione a aba **Rules Engine**.
2. Selecione **+ Rule**.
3. Em **Name**, digite `Run ai-chat`.
4. Mantenha **Request Phase** selecionado.
5. Em **Criteria**, mantenha `${uri}` e **starts with**, e digite `/` como argumento.
6. Em **Behaviors**, troque **Deliver** por **Run Function**.
7. No campo de function instance que **Run Function** adiciona, selecione a instance `ai-chat`.
8. Selecione **Save**.

A regra aparece na fase de requisição da aba **Rules Engine**.

</Fragment>

<Fragment slot="panel.cli">

### CLI

Crie a Application com Functions ativado:

```bash
azion create application --name ai-chat --function true --active true
```

```text
Created Application with ID 1794599906
```

Guarde o ID. Substitua `1794599906` pelo seu ID:

```bash
APPLICATION_ID=1794599906
```

Vincule a Function à Application:

```bash
azion create function-instance --application-id $APPLICATION_ID --function-id $FUNCTION_ID --name ai-chat
```

```text
Created Function Instance with ID 64698
```

Guarde o ID. Substitua `64698` pelo seu ID:

```bash
INSTANCE_ID=64698
```

Escreva num arquivo `rule.json` a regra que executa a instance em todos os caminhos:

```bash
cat > rule.json <<EOF
{
  "name": "Run ai-chat",
  "criteria": [[{ "variable": "\${uri}", "conditional": "if", "operator": "starts_with", "argument": "/" }]],
  "behaviors": [{ "type": "run_function", "attributes": { "value": $INSTANCE_ID } }]
}
EOF
```

Crie a regra na fase de requisição:

```bash
azion create rules-engine --application-id $APPLICATION_ID --phase request --file rule.json
```

```text
Created Rules Engine with ID 1547491
```

</Fragment>

```bash

```

```bash

  --header "Authorization: Token $AZION_API_TOKEN" \
  --header 'Content-Type: application/json' \
  --data "{\"name\": \"Run ai-chat\", \"criteria\": [[{\"variable\": \"\${uri}\", \"conditional\": \"if\", \"operator\": \"starts_with\", \"argument\": \"/\"}]], \"behaviors\": [{\"type\": \"run_function\", \"attributes\": {\"value\": $INSTANCE_ID}}]}"
```

```json
{"state": "pending", "data": {"id": 1547525, "name": "Run ai-chat", "active": true, "order": 0, ...}}
```

</Fragment>

</Tabs>

A Application executa a Function em toda requisição que recebe.

## 5. Converse com o modelo

Um Workload novo pode levar cerca de dez minutos para se propagar pela rede da Azion. Até lá, o domínio responde `404` com uma página de erro em HTML, e pode alternar entre `404` e a resposta da Function por alguns minutos.

Abra `https://<your-domain>/` num navegador, em que `<your-domain>` é o domínio do seu Workload. Quando a página mostrar o campo **Ask a question**, a Function está servindo o seu domínio.

Envie uma pergunta ao endpoint de chat. Se você usou o Console, defina antes `DOMAIN` com o seu domínio, com `DOMAIN=<your-domain>`:

```bash
curl --no-buffer --request POST "https://$DOMAIN/api/chat" \
  --header 'Content-Type: application/json' \
  --data '{"prompt": "What is a CDN?"}'
```

A resposta é o texto do modelo, em três frases ou menos. O `--no-buffer` imprime cada parte do texto assim que ela chega ao terminal. No navegador, digite a mesma pergunta em **Ask a question** e selecione **Send**: a página escreve a resposta abaixo do formulário.

Quando a conta não tem acesso ao AI Inference, o endpoint responde `502` com o erro que `Azion.AI.run` lançou:

```text
AI Inference error: model not found or not allowed
```

Para solicitar acesso, consulte [Acesso por plano](/pt-br/documentacao/plataforma/ai-inference/limites/#acesso-por-plano). A mesma mensagem também aparece quando o ID do modelo está errado; para as causas, consulte [Solucione problemas de AI Inference](/pt-br/documentacao/plataforma/ai-inference/solucao-de-problemas/).

## 6. (Opcional) Exclua os recursos

O chat continua no ar no seu domínio depois do tutorial. Se você quiser remover os recursos, exclua-os na ordem inversa da criação. Excluir o Workload também exclui o deployment dele, e excluir a Application também exclui a instance e a regra dela.

<Tabs client:visible sharedStore="interface">

<Fragment slot="panel.console">

### Console

Para excluir o Workload:

1. Acesse [Azion Console](https://console.azion.com/) > **Workloads**.
2. Na linha `ai-chat`, abra o menu de ações e selecione **Delete**.
3. Na caixa de diálogo **Delete Workload**, digite `ai-chat`.
4. Selecione **Delete**.

Repita os passos em **Applications** para a Application `ai-chat` e depois em **Functions** para a Function `ai-chat`. Cada caixa de diálogo pede o nome do recurso.

Os três recursos não aparecem mais nas listas.

</Fragment>

<Fragment slot="panel.cli">

### CLI

Exclua o Workload:

```bash
azion delete workload --workload-id $WORKLOAD_ID
```

```text
Workload 1794590465 was successfully deleted
```

Exclua a Application:

```bash
azion delete application --application-id $APPLICATION_ID
```

```text
Application 1794599906 was successfully deleted
```

```bash

```


</Fragment>

<Fragment slot="panel.api">

### API

Exclua o Workload, a Application e a Function:


A conta não guarda mais a Function, a Application nem o Workload. A remoção também se propaga, então o domínio pode continuar respondendo por alguns minutos.
