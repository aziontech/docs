Você pode ler as linhas que uma [Function](/pt-br/documentacao/plataforma/functions/) escreveu com `console.log` pelo Azion Console ou com uma consulta GraphQL. [Real-Time Events](/pt-br/documentacao/plataforma/real-time-events/) as guarda na fonte de dados Functions Console. A API GraphQL entrega os mesmos registros como o dataset `functionConsoleEvents`, antes chamado de `cellsConsoleEvents`.

Uma requisição deixa várias linhas, em vez de um único registro. O campo `id` é o identificador da requisição e agrupa todas as linhas de uma única requisição. Um resultado com cinco linhas para uma requisição é o formato esperado.

Azion Runtime escreve linhas próprias junto com as que seu código escreve. O campo `lineSource` separa as duas. `CONSOLE` marca uma linha escrita com `console.log`. `RUNTIME` marca uma linha que Azion Runtime produziu, como uma exceção.

## Leia as linhas que uma Function escreveu

As duas interfaces leem os mesmos registros, e as duas delimitam a busca por um período primeiro. Elas nomeiam o identificador da Function de maneiras diferentes. O filtro do Console o chama de _Function Id_, e a API GraphQL recebe o campo em camelCase `functionId`.

O período que uma busca pode pedir e as linhas que uma consulta retorna são ambos limitados. Para cada limite, consulte [Limites](/pt-br/documentacao/plataforma/real-time-events/limites/).

<Tabs client:visible sharedStore="interface">

<Fragment slot="panel.console">

### Console

Para ler as linhas pelo Azion Console:

<DocSteps>
  <DocStep title="Abra Real-Time Events">

  Acesse [Azion Console](https://console.azion.com/) > **Real-Time Events**.

  </DocStep>
  <DocStep title="Selecione a fonte de dados">

  Selecione a aba **Functions Console**.

  </DocStep>
  <DocStep title="Abra o período">

  Selecione o campo de período, que mostra _Last 5 minutes_.

  </DocStep>
  <DocStep title="Selecione o período">

  Selecione **Quick** e depois um período que cubra a execução, como _Last 1 hour_.

  </DocStep>
  <DocStep title="Execute a busca">

  Selecione **Update**.

  </DocStep>
  <DocStep title="Abra o filtro">

  Selecione o ícone de filtro.

  </DocStep>
  <DocStep title="Selecione o campo">

  Em **Filter**, selecione _Function Id_.

  </DocStep>
  <DocStep title="Defina a condição">

  Em **Operator**, selecione _Equals_ e digite o identificador da Function no campo de valor.

  </DocStep>
  <DocStep title="Aplique o filtro">

  Selecione **Apply**.

  </DocStep>
</DocSteps>

**Apply** executa a busca de novo na mesma hora. A tabela carrega as linhas que aquela Function escreveu, uma linha da tabela por linha de log.

O campo de consulta mostra a condição, como `'function id' = 9483`. O filtro também oferece _Not Equals_, _Contains_ e _Not Contains_, e campos como _Level_ e _Line Source_. Selecione uma linha para abrir **More Details**, que carrega todos os campos daquele registro, incluindo `line`, a mensagem em si. Para todos os campos que a fonte de dados carrega, consulte [Fontes de dados](/pt-br/documentacao/plataforma/real-time-events/fontes-de-dados/).

</Fragment>

<Fragment slot="panel.api">

### API

A API GraphQL entrega as mesmas linhas como o dataset `functionConsoleEvents`. Envie a consulta para `https://api.azion.com/v4/events/graphql` com um cabeçalho `Authorization: Token [TOKEN VALUE]`. O mesmo endereço serve o GraphiQL Playground em um navegador, onde a consulta roda sem uma requisição sua. Para o caminho pelo terminal, consulte [Primeiros passos da API GraphQL](/pt-br/documentacao/devtools/graphql/primeiros-passos/).

Esta consulta retorna 10 linhas de um intervalo de tempo, as mais antigas primeiro:

```graphql
query ConsoleLog {
  functionConsoleEvents(
    limit: 10,
    filter: {
      tsRange: {begin: "<your-period-start>", end: "<your-period-end>"}
    }
    orderBy: [ts_ASC]
  )
  {
    ts
    solutionId
    configurationId
    functionId
    id
    lineSource
    level
    line
  }
}
```

Substitua `<your-period-start>` e `<your-period-end>` pelos limites da execução, no formato `YYYY-MM-DDTHH:MM:SS`.

A resposta carrega as linhas correspondentes em JSON:

```json
{
    "data": {
        "functionConsoleEvents": [
            {
                "ts": "2026-09-21T12:09:54Z",
                "solutionId": "1234567890",
                "configurationId": "1234567891",
                "functionId": "9483",
                "id": "fa498cd9-cbep-4382-8bbb-32b029fe7411",
                "lineSource": "RUNTIME",
                "level": "ERROR",
                "line": "TypeError: Object not found"
            },
            {
                "ts": "2026-09-21T12:09:54Z",
                "solutionId": "1234567890",
                "configurationId": "1234567891",
                "functionId": "9483",
                "id": "fa498cd9-cbep-4382-8bbb-32b029fe7411",
                "lineSource": "RUNTIME",
                "level": "ERROR",
                "line": "TypeError: Object not found"
            },
            {
                "ts": "2026-09-21T12:09:54Z",
                "solutionId": "1234567890",
                "configurationId": "1234567891",
                "functionId": "9483",
                "id": "fa498cd9-cbep-4382-8bbb-32b029fe7411",
                "lineSource": "RUNTIME",
                "level": "ERROR",
                "line": "    at async mainFetch (ext:cells_fetch/26_fetch.js:266:12)"
            }
        ]
    }
}
```

As três linhas carregam um mesmo `id`, porque uma única requisição produziu todas elas. Cada uma lê `RUNTIME` em `lineSource` e `ERROR` em `level`, portanto quem as escreveu foi Azion Runtime. Uma linha escrita com `console.log` lê `CONSOLE` e `LOG` nesses mesmos dois campos.

`functionId` identifica a Function e `configurationId` identifica o workload em que a requisição chegou. Para retornar apenas as linhas cuja mensagem corresponde a um padrão, acrescente `lineLike` ao filtro. O caractere `%` representa qualquer sequência de caracteres, portanto `lineLike: "%TypeError%"` corresponde a todas as linhas que contêm `TypeError`. Para todos os campos que o dataset carrega, consulte [Campos da API GraphQL do Real-Time Events](/pt-br/documentacao/devtools/graphql/campos-gql-real-time-events/#eventos-de-console-de-functions).
