Você pode clonar uma [Application](/pt-br/documentacao/plataforma/applications/) ou um [Firewall](/pt-br/documentacao/plataforma/firewall/) com um novo nome com uma requisição `POST` à [API da Azion](/pt-br/documentacao/devtools/api/) v4. Para clonar uma Application pelo Azion Console, consulte [Clone uma aplicação](/pt-br/documentacao/guias/desenvolvimento-de-aplicacoes/primeiros-passos/clonar-applications/).

Os exemplos clonam uma Application que tem um [cache setting](/pt-br/documentacao/plataforma/applications/cache/cache-settings/), uma Function Instance, duas regras de requisição e uma regra de resposta. Eles também clonam um Firewall que tem uma Function Instance e duas regras de requisição.

---

## Pré-requisitos

- Um personal token. Para criar um, consulte [Gerencie personal tokens](/pt-br/documentacao/guias/plataforma/conta-e-billing/personal-tokens/).
- `curl`, para chamar a API, e `jq`, para ler IDs das respostas.
- O ID da Application ou do Firewall a clonar.

---

## Clone uma Application

O endpoint de clone recebe um campo obrigatório, `name`: de 1 a 100 caracteres que nenhuma outra Application usa.

Para clonar a Application:

1. Guarde o seu token e o ID da Application em variáveis do shell. Substitua os dois valores pelos seus:

   ```bash
   export AZION_API_TOKEN="[TOKEN VALUE]"
   APPLICATION_ID=<your-application-id>
   ```

2. Envie uma requisição `POST` ao endpoint de clone da Application, com o nome da cópia:

   ```bash
   curl --silent "https://api.azion.com/v4/workspace/applications/$APPLICATION_ID/clone" \
     --header "Authorization: Token $AZION_API_TOKEN" \
     --header 'Content-Type: application/json' \
     --data '{"name": "shop-production"}' \
   | tee application-clone.json
   ```

   A API responde `202`, e a resposta traz a nova Application. Este trecho mostra o ID e o nome dela:

   ```json
   {
     "state": "pending",
     "data": {
       "id": 1795012549,
       "name": "shop-production",
       ...
     }
   }
   ```

3. Guarde o ID da cópia:

   ```bash
   CLONE_ID=$(jq .data.id application-clone.json)
   ```

A conta tem uma nova Application chamada `shop-production`, e `CLONE_ID` guarda o ID dela. Um nome que outra Application já usa retorna `400` com o código `31000` e o título `Name Already In Use`. Um corpo sem `name` retorna `400` com o código `10059`.

Uma requisição só chega à cópia depois que o deployment de um Workload define essa Application. Para mais informações, consulte [Workloads](/pt-br/documentacao/plataforma/workloads/).

---

## Verifique o que o clone da Application contém

A cópia contém os cache settings, as Function Instances e as regras da original. Cada um tem um ID novo. As regras de requisição da cópia apontam para os cache settings e as Function Instances da cópia, e não para os da original.

Para verificar a cópia:

1. Guarde o seu token e o ID da cópia. Substitua os dois valores pelos seus:

   ```bash
   export AZION_API_TOKEN="[TOKEN VALUE]"
   CLONE_ID=<your-clone-id>
   ```

2. Liste os cache settings da cópia:

   ```bash
   curl --silent "https://api.azion.com/v4/workspace/applications/$CLONE_ID/cache_settings?fields=id,name" \
     --header "Authorization: Token $AZION_API_TOKEN"
   ```

   A resposta lista os cache settings da cópia:

   ```json
   {
     "count": 1,
     ...
     "results": [
       {"id": 395158, "name": "static-assets"}
     ]
   }
   ```

3. Liste as Function Instances da cópia:

   ```bash
   curl --silent "https://api.azion.com/v4/workspace/applications/$CLONE_ID/functions?fields=id,name,function" \
     --header "Authorization: Token $AZION_API_TOKEN"
   ```

   A resposta lista as Function Instances da cópia, com a Function que cada uma executa:

   ```json
   {
     "count": 1,
     ...
     "results": [
       {"id": 64950, "name": "hello", "function": 110767}
     ]
   }
   ```

4. Liste as regras de requisição da cópia, com os behaviors delas:

   ```bash
   curl --silent "https://api.azion.com/v4/workspace/applications/$CLONE_ID/request_rules?fields=id,name,order,behaviors" \
     --header "Authorization: Token $AZION_API_TOKEN"
   ```

   A resposta lista as regras de requisição da cópia, com os behaviors delas:

   ```json
   {
     "count": 2,
     ...
     "results": [
       {
         "id": 1551022,
         "name": "Cache images",
         "behaviors": [{"type": "set_cache_policy", "attributes": {"value": 395158}}],
         "order": 0
       },
       {
         "id": 1551023,
         "name": "Run hello",
         "behaviors": [{"type": "run_function", "attributes": {"value": 64950}}],
         "order": 1
       }
     ]
   }
   ```

5. Liste as regras de resposta da cópia:

   ```bash
   curl --silent "https://api.azion.com/v4/workspace/applications/$CLONE_ID/response_rules?fields=id,name,order" \
     --header "Authorization: Token $AZION_API_TOKEN"
   ```

   A resposta lista as regras de resposta da cópia:

   ```json
   {
     "count": 1,
     ...
     "results": [
       {"id": 1551024, "name": "Add header", "order": 0}
     ]
   }
   ```

As regras copiadas apontam para `395158` e `64950`, o cache setting e a Function Instance da cópia. Na original, o mesmo cache setting e a mesma Function Instance mantêm os próprios IDs, `395157` e `64949`. Uma alteração em um cache setting ou em uma regra da cópia não altera a original.

## Clone um Firewall

O endpoint de clone de um Firewall também recebe um campo obrigatório, `name`: de 1 a 250 caracteres que nenhum outro Firewall usa.

Para clonar o Firewall:

1. Guarde o seu token e o ID do Firewall em variáveis do shell. Substitua os dois valores pelos seus:

   ```bash
   export AZION_API_TOKEN="[TOKEN VALUE]"
   FIREWALL_ID=<your-firewall-id>
   ```

2. Envie uma requisição `POST` ao endpoint de clone do Firewall, com o nome da cópia:

   ```bash
   curl --silent "https://api.azion.com/v4/workspace/firewalls/$FIREWALL_ID/clone" \
     --header "Authorization: Token $AZION_API_TOKEN" \
     --header 'Content-Type: application/json' \
     --data '{"name": "shop-production-firewall"}' \
   | tee firewall-clone.json
   ```

   A API responde `202`, e a resposta traz o novo Firewall:

   ```json
   {
     "state": "pending",
     "data": {
       "id": 104385,
       "name": "shop-production-firewall",
       "modules": {
         "ddos_protection": {"enabled": true},
         "functions": {"enabled": true},
         "network_protection": {"enabled": true},
         "waf": {"enabled": false}
       },
       ...
     }
   }
   ```

3. Guarde o ID da cópia:

   ```bash
   FIREWALL_CLONE_ID=$(jq .data.id firewall-clone.json)
   ```

4. Liste as Function Instances da cópia:

   ```bash
   curl --silent "https://api.azion.com/v4/workspace/firewalls/$FIREWALL_CLONE_ID/functions?fields=id,name,function" \
     --header "Authorization: Token $AZION_API_TOKEN"
   ```

   A resposta lista as Function Instances da cópia:

   ```json
   {
     "count": 1,
     ...
     "results": [
       {"id": 23047, "name": "passthrough", "function": 110768}
     ]
   }
   ```

5. Liste as regras de requisição da cópia, com os behaviors delas:

   ```bash
   curl --silent "https://api.azion.com/v4/workspace/firewalls/$FIREWALL_CLONE_ID/request_rules?fields=id,name,order,behaviors" \
     --header "Authorization: Token $AZION_API_TOKEN"
   ```

   A resposta lista as regras de requisição da cópia:

   ```json
   {
     "count": 2,
     ...
     "results": [
       {"id": 170280, "name": "Block admin", "behaviors": [{"type": "deny"}], "order": 0},
       {"id": 170281, "name": "Run passthrough", "behaviors": [{"type": "run_function", "attributes": {"value": 23047}}], "order": 1}
     ]
   }
   ```

A conta tem um novo Firewall chamado `shop-production-firewall`, com cópias das regras e das Function Instances do original. A regra `run_function` copiada aponta para `23047`, a Function Instance da cópia. Um nome que outro Firewall já usa retorna `400` com o código `24002` e o título `Name Already In Use`. Um corpo sem `name` retorna `400` com o código `10059`.

A cópia só inspeciona requisições depois que o deployment de um Workload define esse Firewall. Para mais informações, consulte [Workloads](/pt-br/documentacao/plataforma/workloads/).
