Neste tutorial, você vai proteger uma API com um [Firewall](/pt-br/documentacao/plataforma/firewall/) que aplica um conjunto de regras de [WAF](/pt-br/documentacao/plataforma/firewall/waf/) a todos os caminhos que começam com `/api`. Você vai publicar uma API pequena, criar o conjunto de regras de WAF e o Firewall, fazer o deploy dos dois num Workload e enviar uma SQL injection que o WAF bloqueia.

Cada recurso que o tutorial cria se liga a um criado antes dele:

1. A [Function](/pt-br/documentacao/plataforma/functions/) é a API: ela responde a toda requisição com o caminho e a query string que recebeu.
2. A [Application](/pt-br/documentacao/plataforma/applications/) executa a Function em todos os caminhos.
3. O conjunto de regras de WAF define quais ameaças o WAF detecta e a sensibilidade dele a cada uma.
4. O Firewall tem o WAF ativado e uma regra que aplica o conjunto de regras em modo de bloqueio aos caminhos que começam com `/api`.
5. O [Workload](/pt-br/documentacao/plataforma/workloads/) guarda o domínio, e o deployment dele define o Firewall que inspeciona cada requisição e a Application que a responde.

Os recursos são os mesmos no Azion Console, na Azion CLI e na API. Selecione a interface que você usa, e cada etapa mostra os passos dela.

## 1. Escreva a API

Crie um diretório para o tutorial, entre nele e crie um arquivo `index.js` com este código:

```javascript title="index.js"
export default {
  async fetch(request) {
    const { pathname, searchParams } = new URL(request.url)
    return Response.json({ path: pathname, query: Object.fromEntries(searchParams) })
  }
}
```

A Function devolve o caminho e a query string de cada requisição como JSON, então cada resposta mostra o que chegou até ela.

## 3. Crie a Application

A Application precisa de três partes: a própria Application com Functions ativado, uma function instance que vincula a Function e uma regra que executa a instance em todos os caminhos.

<Tabs client:visible sharedStore="interface">

<Fragment slot="panel.console">

### Console

Para criar a Application:

1. Acesse [Azion Console](https://console.azion.com/) > **Applications**.
2. Selecione **+ Application**.
3. Em **Name**, digite `protected-api`.
4. Em **Modules**, ative **Functions**.
5. Selecione **Create**.

Para vincular a Function:

1. Selecione a aba **Functions Instances**.
2. Selecione **+ Function**.
3. Em **Name**, digite `protected-api`.
4. Em **Function**, selecione `protected-api`.
5. Selecione **Save**.

Para executar a Function em toda requisição:

1. Selecione a aba **Rules Engine**.
2. Selecione **+ Rule**.
3. Em **Name**, digite `Run protected-api`.
4. Mantenha **Request Phase** selecionado.
5. Em **Criteria**, mantenha `${uri}` e **starts with**, e digite `/` como argumento.
6. Em **Behaviors**, troque **Deliver** por **Run Function**.
7. No campo de function instance que **Run Function** adiciona, selecione a instance `protected-api`.
8. Selecione **Save**.

</Fragment>

<Fragment slot="panel.cli">

### CLI

Crie a Application com Functions ativado:

```bash
azion create application --name protected-api --function true --active true
```

```text
Created Application with ID 1794609956
```

Guarde o ID. Substitua `1794609956` pelo seu ID:

```bash
APPLICATION_ID=1794609956
```

Vincule a Function à Application:

```bash
azion create function-instance --application-id $APPLICATION_ID --function-id $FUNCTION_ID --name protected-api
```

```text
Created Function Instance with ID 64719
```

Guarde o ID. Substitua `64719` pelo seu ID:

```bash
INSTANCE_ID=64719
```

Escreva a regra que executa a instance em todos os caminhos e crie-a na fase de requisição:

```bash
cat > rule.json <<EOF
{
  "name": "Run protected-api",
  "criteria": [[{ "variable": "\${uri}", "conditional": "if", "operator": "starts_with", "argument": "/" }]],
  "behaviors": [{ "type": "run_function", "attributes": { "value": $INSTANCE_ID } }]
}
EOF
azion create rules-engine --application-id $APPLICATION_ID --phase request --file rule.json
```

```text
Created Rules Engine with ID 1547680
```

</Fragment>

<Fragment slot="panel.api">

### API

Crie a Application com Functions ativado, vincule a Function e adicione a regra que a executa:

```bash
curl --silent https://api.azion.com/v4/workspace/applications \
  --header "Authorization: Token $AZION_API_TOKEN" \
  --header 'Content-Type: application/json' \
  --data '{"name": "protected-api", "modules": {"functions": {"enabled": true}}}' \
| tee application.json
APPLICATION_ID=$(jq .data.id application.json)

curl --silent https://api.azion.com/v4/workspace/applications/$APPLICATION_ID/functions \
  --header "Authorization: Token $AZION_API_TOKEN" \
  --header 'Content-Type: application/json' \
  --data "{\"name\": \"protected-api\", \"function\": $FUNCTION_ID}" \
| tee instance.json
INSTANCE_ID=$(jq .data.id instance.json)

curl --silent https://api.azion.com/v4/workspace/applications/$APPLICATION_ID/request_rules \
  --header "Authorization: Token $AZION_API_TOKEN" \
  --header 'Content-Type: application/json' \
  --data "{\"name\": \"Run protected-api\", \"criteria\": [[{\"variable\": \"\${uri}\", \"conditional\": \"if\", \"operator\": \"starts_with\", \"argument\": \"/\"}]], \"behaviors\": [{\"type\": \"run_function\", \"attributes\": {\"value\": $INSTANCE_ID}}]}"
```

Cada chamada responde com `"state": "pending"` e o recurso novo, com o `id` dele.

</Fragment>

</Tabs>

A Application executa a Function em toda requisição que recebe.

## 4. Crie o conjunto de regras de WAF

O conjunto de regras verifica oito tipos de ameaça, cada um com sensibilidade média, que é o que o Azion Console propõe para um conjunto novo.

<Tabs client:visible sharedStore="interface">

<Fragment slot="panel.console">

### Console

Para criar o conjunto de regras:

1. Acesse [Azion Console](https://console.azion.com/) > **WAF Rules**.
2. Selecione **+ WAF Rule**.
3. Em **Name**, digite `protected-api`.
4. Em **Threat Type Configuration**, mantenha os oito tipos de ameaça ativados, cada um com **Sensitivity Medium**.
5. Selecione **Save**.

O Console mostra a mensagem **Your WAF rule has been created**.

</Fragment>

<Fragment slot="panel.cli">

### CLI

Crie o conjunto de regras:

```bash
azion create waf --name protected-api --active true --engine-version 2021-Q3 --type score --rulesets 1 \
  --thresholds "cross_site_scripting=medium,directory_traversal=medium,evading_tricks=medium,file_upload=medium,identified_attack=medium,remote_file_inclusion=medium,sql_injection=medium,unwanted_access=medium"
```

```text
Created WAF with ID 49213
```

Guarde o ID. Substitua `49213` pelo seu ID:

```bash
WAF_ID=49213
```

</Fragment>

<Fragment slot="panel.api">

### API

Crie o conjunto de regras:

```bash
curl --silent https://api.azion.com/v4/workspace/wafs \
  --header "Authorization: Token $AZION_API_TOKEN" \
  --header 'Content-Type: application/json' \
  --data '{"name": "protected-api", "engine_settings": {"engine_version": "2021-Q3", "type": "score", "attributes": {"rulesets": [1], "thresholds": [
    {"threat": "cross_site_scripting", "sensitivity": "medium"},
    {"threat": "directory_traversal", "sensitivity": "medium"},
    {"threat": "evading_tricks", "sensitivity": "medium"},
    {"threat": "file_upload", "sensitivity": "medium"},
    {"threat": "identified_attack", "sensitivity": "medium"},
    {"threat": "remote_file_inclusion", "sensitivity": "medium"},
    {"threat": "sql_injection", "sensitivity": "medium"},
    {"threat": "unwanted_access", "sensitivity": "medium"}]}}}' \
| tee waf.json
```

```json
{"state": "pending", "data": {"id": 49210, "active": true, "engine_settings": {...}, ...}}
```

```bash
WAF_ID=$(jq .data.id waf.json)
```

</Fragment>

</Tabs>

## 5. Crie o Firewall

O Firewall precisa do WAF ativado e de uma regra que aplica o conjunto de regras aos caminhos que começam com `/api`, em modo de bloqueio. As requisições a outros caminhos chegam à Application sem inspeção do WAF.

<Tabs client:visible sharedStore="interface">

<Fragment slot="panel.console">

### Console

Para criar o Firewall:

1. Acesse [Azion Console](https://console.azion.com/) > **Firewalls**.
2. Selecione **+ Firewall**.
3. Em **Name**, digite `protected-api`.
4. Em **Modules**, ative **Web Application Firewall**.
5. Selecione **Create**.

O Console abre o Firewall novo na aba **Main Settings**.

Para aplicar o conjunto de regras a `/api`:

1. Selecione a aba **Rules Engine**.
2. Selecione **+ Rule**.
3. Em **Name**, digite `Apply the WAF to /api`.
4. Em **Criteria**, mantenha **Request Uri** e **starts with**, e digite `/api` como argumento.
5. Em **Behaviors**, selecione **Set WAF**.
6. No campo de WAF que **Set WAF** adiciona, selecione `protected-api`.
7. Em **Select a WAF mode**, selecione **Blocking**.
8. Selecione **Save**.

A regra aparece na aba **Rules Engine** do Firewall.

</Fragment>

<Fragment slot="panel.cli">

### CLI

Crie o Firewall com o WAF ativado:

```bash
azion create firewall --name protected-api --active true --waf-enabled true
```

```text
Created Firewall with ID 103570
```

Guarde o ID. Substitua `103570` pelo seu ID:

```bash
FIREWALL_ID=103570
```

Escreva a regra que aplica o conjunto de regras a `/api` e crie-a no Firewall:

```bash
cat > firewall-rule.json <<EOF
{
  "name": "Apply the WAF to /api",
  "criteria": [[{ "variable": "\${request_uri}", "conditional": "if", "operator": "starts_with", "argument": "/api" }]],
  "behaviors": [{ "type": "set_waf", "attributes": { "waf_id": $WAF_ID, "mode": "blocking" } }]
}
EOF
azion create firewall-rule --firewall-id $FIREWALL_ID --file firewall-rule.json
```

```text
Created Firewall Rule with ID 169033
```

</Fragment>

<Fragment slot="panel.api">

### API

Crie o Firewall com o WAF ativado:

```bash
curl --silent https://api.azion.com/v4/workspace/firewalls \
  --header "Authorization: Token $AZION_API_TOKEN" \
  --header 'Content-Type: application/json' \
  --data '{"name": "protected-api", "modules": {"waf": {"enabled": true}}}' \
| tee firewall.json
FIREWALL_ID=$(jq .data.id firewall.json)
```

```json
{"state": "pending", "data": {"id": 103571, "modules": {"ddos_protection": {"enabled": true}, "functions": {"enabled": true}, "network_protection": {"enabled": true}, "waf": {"enabled": true}}, ...}}
```

Adicione a regra que aplica o conjunto de regras a `/api`:

```bash
curl --silent https://api.azion.com/v4/workspace/firewalls/$FIREWALL_ID/request_rules \
  --header "Authorization: Token $AZION_API_TOKEN" \
  --header 'Content-Type: application/json' \
  --data "{\"name\": \"Apply the WAF to /api\", \"criteria\": [[{\"variable\": \"\${request_uri}\", \"conditional\": \"if\", \"operator\": \"starts_with\", \"argument\": \"/api\"}]], \"behaviors\": [{\"type\": \"set_waf\", \"attributes\": {\"waf_id\": $WAF_ID, \"mode\": \"blocking\"}}]}"
```

```json
{"state": "pending", "data": {"id": 169034, "name": "Apply the WAF to /api", "active": true, ...}}
```

</Fragment>

</Tabs>

O Firewall aplica o conjunto de regras a `/api` em modo de bloqueio. O `mode` é obrigatório: um comportamento `set_waf` sem ele é recusado.

## 6. Crie o Workload

O deployment do Workload define tanto o Firewall quanto a Application, então toda requisição passa pelo Firewall antes de chegar à Application.

<Tabs client:visible sharedStore="interface">

<Fragment slot="panel.console">

### Console

Para criar o Workload e o deployment dele:

1. Acesse [Azion Console](https://console.azion.com/) > **Workloads**.
2. Selecione **+ Workload**.
3. Em **Name**, digite `protected-api`.
4. Em **Deployment Settings**, selecione `protected-api` em **Application**.
5. Em **Firewall**, selecione `protected-api`.
6. Selecione **Save**.

A lista de Workloads mostra o domínio na coluna **Workload Domain**, no formato `xxxxxxxxxxx.map.azionedge.net`.

</Fragment>

<Fragment slot="panel.cli">

### CLI

Crie o Workload:

## 7. Teste a proteção

Um Workload novo pode levar cerca de dez minutos para se propagar pela rede da Azion. Até lá, o domínio responde `404` com uma página de erro em HTML, e pode alternar entre `404` e as respostas abaixo por alguns minutos. Se você usou o Console, defina antes `DOMAIN` com o seu domínio, com `DOMAIN=<your-domain>`.

Envie uma requisição normal à API:

```bash
curl --silent --get "https://$DOMAIN/api/orders" --data-urlencode "id=42"
```

Repita a cada minuto até a API responder três vezes seguidas:

```json
{"path":"/api/orders","query":{"id":"42"}}
```

Envie uma SQL injection no mesmo parâmetro e imprima o código de status:

```bash
curl --silent --output /dev/null --write-out '%{http_code}\n' --get "https://$DOMAIN/api/orders" --data-urlencode "id=42' OR '1'='1"
```

```text
400
```

O WAF bloqueou a requisição antes de ela chegar à Function. O corpo é a página de erro padrão da Azion.

Envie a mesma injection para `/`, que a regra do Firewall não cobre:

```bash
curl --silent --get "https://$DOMAIN/" --data-urlencode "id=42' OR '1'='1"
```

```json
{"path":"/","query":{"id":"42' OR '1'='1"}}
```

A requisição chegou à Function, porque só os caminhos que começam com `/api` passam pelo conjunto de regras.

## 8. (Opcional) Exclua os recursos

A API protegida continua no ar no seu domínio depois do tutorial. Se você quiser remover os recursos, exclua o Workload primeiro, porque o deployment dele usa o Firewall e a Application. Depois, exclua o Firewall antes do conjunto de regras que ele aplica.

<Tabs client:visible sharedStore="interface">

<Fragment slot="panel.console">

### Console

Para excluir o Workload:

1. Acesse [Azion Console](https://console.azion.com/) > **Workloads**.
2. Na linha `protected-api`, abra o menu de ações e selecione **Delete**.
3. Na caixa de diálogo **Delete Workload**, digite `protected-api`.
4. Selecione **Delete**.

Repita os passos nesta ordem: **Firewalls** para o Firewall, **WAF Rules** para o conjunto de regras, **Applications** para a Application e **Functions** para a Function. Cada caixa de diálogo pede o nome do recurso.

</Fragment>

<Fragment slot="panel.cli">

### CLI

Exclua os recursos em ordem. Cada comando imprime uma confirmação:

```bash
azion delete workload --workload-id $WORKLOAD_ID
```

```text
Workload 1794600546 was successfully deleted
```

```bash
azion delete firewall --firewall-id $FIREWALL_ID
```

```text
Firewall 103570 was successfully deleted
```

```bash
azion delete waf --waf-id $WAF_ID
```

```text
WAF 49213 was successfully deleted
```

```bash
azion delete application --application-id $APPLICATION_ID
```

```text
Application 1794609956 was successfully deleted
```

```bash
azion delete function --function-id $FUNCTION_ID
```

```text
Function 110036 was successfully deleted
```

</Fragment>

<Fragment slot="panel.api">

### API

Exclua os recursos em ordem:

```bash
for resource in workloads/$WORKLOAD_ID firewalls/$FIREWALL_ID wafs/$WAF_ID applications/$APPLICATION_ID functions/$FUNCTION_ID; do
  curl --silent --request DELETE https://api.azion.com/v4/workspace/$resource \
    --header "Authorization: Token $AZION_API_TOKEN"
  echo
done
```

```text
{"state":"pending"}
{"state":"pending"}
{"state":"pending"}
{"state":"pending"}
{"state":"pending"}
```

</Fragment>

</Tabs>

A conta não guarda mais os recursos do tutorial. A remoção também se propaga, então o domínio pode continuar respondendo por alguns minutos.
