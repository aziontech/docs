Neste tutorial, você vai proteger uma API com um [Firewall](/pt-br/documentacao/plataforma/firewall/) que aplica um rule set do [WAF](/pt-br/documentacao/plataforma/firewall/waf/) a todo caminho que começa com `/api`. Você vai publicar uma API pequena, criar o rule set do WAF e o Firewall, fazer o deploy dos dois em um Workload e enviar uma SQL injection que o WAF bloqueia.

Cada recurso que o tutorial cria se liga a um criado antes dele:

1. A [Function](/pt-br/documentacao/plataforma/functions/) é a API: ela responde a toda requisição com o caminho e a query string que recebeu.
2. A [Application](/pt-br/documentacao/plataforma/applications/) executa a Function em todo caminho.
3. O rule set do WAF define quais famílias de ameaça o WAF pontua e quão sensível ele é a cada uma.
4. O Firewall tem o WAF ativado e uma regra que aplica o rule set em modo _Blocking_ aos caminhos que começam com `/api`.
5. O [Workload](/pt-br/documentacao/plataforma/workloads/) contém o domínio, e o deployment dele define o Firewall que inspeciona cada requisição e a Application que responde a ela.

O tutorial usa o Azion Console. Para criar um Firewall e as regras dele com a Azion CLI ou a API, consulte [Primeiros passos com Firewall](/pt-br/documentacao/plataforma/firewall/primeiros-passos/) e [Crie e aplique um WAF rule set](/pt-br/documentacao/guias/seguranca-de-aplicacoes/firewall-e-waf/criar-waf-rule-set/).

---

## Pré-requisitos

- Uma conta Azion. Para criar uma, consulte [Criar uma conta](/pt-br/documentacao/fundamentos/criar-uma-conta/).
- Acesso ao Azion Console. Para entrar, consulte [Acesse Azion Console](/pt-br/documentacao/guias/plataforma/conta-e-billing/como-acessar-o-azion-console/).
- `curl`, para enviar requisições à sua API.

---

## 1. Escreva a API

Crie um diretório para o tutorial, entre nele e crie um arquivo `index.js` com este código:

```javascript title="index.js"
export default {
  async fetch(request) {
    const { pathname, searchParams } = new URL(request.url)
    return Response.json({ path: pathname, query: Object.fromEntries(searchParams) })
  }
}
```

A Function devolve como JSON o caminho e a query string de cada requisição, então cada resposta mostra o que chegou a ela.

---

## 2. Crie a Function

Para criar a Function no Azion Console:

1. Acesse [Azion Console](https://console.azion.com/) > **Functions**.
2. Selecione **+ Function**.
3. Em **Name**, insira `protected-api`.
4. Mantenha **Application** selecionado em **Execution Environment**.
5. Selecione a aba **Code**.
6. Substitua o código de exemplo do editor pelo conteúdo de `index.js`.
7. Selecione **Save**.

O Console mostra a mensagem **Your function has been created**, e a conta passa a ter a Function.

---

## 3. Crie a Application

A Application tem três partes: Functions ativado, uma Function Instance da Function e uma regra que a executa em todo caminho.

Para criar a Application:

1. Acesse [Azion Console](https://console.azion.com/) > **Applications**.
2. Selecione **+ Application**.
3. Em **Name**, insira `protected-api`.
4. Em **Modules**, ative **Functions**.
5. Selecione **Create**.

Para anexar a Function:

1. Selecione a aba **Functions Instances**.
2. Selecione **+ Function**.
3. Em **Name**, insira `protected-api`.
4. Em **Function**, selecione `protected-api`.
5. Selecione **Save**.

Para executar a Function em toda requisição:

1. Selecione a aba **Rules Engine**.
2. Selecione **+ Rule**.
3. Em **Name**, insira `Run protected-api`.
4. Mantenha **Request Phase** selecionado.
5. Em **Criteria**, mantenha `${uri}` e **starts with** e insira `/` como argumento.
6. Em **Behaviors**, substitua **Deliver** por **Run Function**.
7. No campo que **Run Function** adiciona, selecione a Function Instance `protected-api`.
8. Selecione **Save**.

A Application executa a Function em toda requisição que recebe.

---

## 4. Crie o rule set do WAF

O rule set pontua oito famílias de ameaça, cada uma em sensibilidade média, o que o Azion Console propõe para um rule set novo.

Para criar o rule set:

1. Acesse [Azion Console](https://console.azion.com/) > **WAF Rules**.
2. Selecione **+ WAF Rule**.
3. Em **Name**, insira `protected-api`.
4. Em **Threat Type Configuration**, mantenha as oito famílias de ameaça ativadas, cada uma com **Sensitivity Medium**.
5. Selecione **Save**.

O Console mostra a mensagem **Your WAF rule has been created**. A conta passa a ter o rule set, e ele não pontua nada até que uma regra do Firewall o aplique.

---

## 5. Crie o Firewall

O Firewall precisa do WAF ativado e de uma regra que aplique o rule set aos caminhos que começam com `/api`, em modo _Blocking_. As requisições a outros caminhos chegam à Application sem inspeção do WAF.

Para criar o Firewall:

1. Acesse [Azion Console](https://console.azion.com/) > **Firewalls**.
2. Selecione **+ Firewall**.
3. Em **Name**, insira `protected-api`.
4. Em **Modules**, ative **Web Application Firewall**.
5. Selecione **Create**.

O Console abre o Firewall novo na aba **Main Settings**.

Para aplicar o rule set a `/api`:

1. Selecione a aba **Rules Engine**.
2. Selecione **+ Rule**.
3. Em **Name**, insira `Apply the WAF to /api`.
4. Em **Criteria**, mantenha **Request Uri** e **starts with** e insira `/api` como argumento.
5. Em **Behaviors**, selecione **Set WAF**.
6. No campo de WAF que **Set WAF** adiciona, selecione `protected-api`.
7. Em **Select a WAF mode**, selecione **Blocking**.
8. Selecione **Save**.

A regra aparece na aba **Rules Engine** do Firewall, que aplica o rule set a `/api` em modo _Blocking_.

---

## 6. Crie o Workload

O deployment do Workload define tanto o Firewall quanto a Application, então toda requisição passa pelo Firewall antes de chegar à Application.

Para criar o Workload e o deployment dele:

1. Acesse [Azion Console](https://console.azion.com/) > **Workloads**.
2. Selecione **+ Workload**.
3. Em **Name**, insira `protected-api`.
4. Em **Deployment Settings**, selecione `protected-api` em **Application**.
5. Em **Firewall**, selecione `protected-api`.
6. Selecione **Save**.

A lista de Workloads mostra o domínio na coluna **Workload Domain**, no formato `xxxxxxxxxxx.map.azionedge.net`.

---

## 7. Teste a proteção

Um Workload novo responde vários minutos depois do deployment dele, quando a mudança se propaga pela infraestrutura distribuída da Azion. Em testes, isso levou de 6 a 9 minutos, e nenhuma duração é garantida. Até lá, o domínio responde `404` com uma página HTML, e as respostas podem alternar entre `404` e as respostas a seguir.

Defina `DOMAIN` com o domínio do seu Workload:

```bash
DOMAIN=<your-workload-domain>
```

Envie uma requisição normal à API:

```bash
curl --silent --get "https://$DOMAIN/api/orders" --data-urlencode "id=42"
```

Repita a cada minuto até a API responder três vezes seguidas:

```json
{"path":"/api/orders","query":{"id":"42"}}
```

Envie uma SQL injection no mesmo parâmetro e imprima o código de status:

```bash
curl --silent --output /dev/null --write-out '%{http_code}\n' --get "https://$DOMAIN/api/orders" --data-urlencode "id=42' OR '1'='1"
```

```text
400
```

O WAF bloqueou a requisição antes que ela chegasse à Function. O corpo é a página de erro padrão da Azion, com o título **Bad Request**.

Envie a mesma injection para `/`, que a regra do Firewall não cobre:

```bash
curl --silent --get "https://$DOMAIN/" --data-urlencode "id=42' OR '1'='1"
```

```json
{"path":"/","query":{"id":"42' OR '1'='1"}}
```

A requisição chegou à Function, porque só os caminhos que começam com `/api` passam pelo rule set.

---

## 8. Exclua os recursos

A API protegida continua no ar no seu domínio depois do tutorial, então esta etapa é opcional. Para remover os recursos, exclua o Workload primeiro, porque o deployment dele usa o Firewall e a Application. Depois, exclua o Firewall antes do rule set que ele aplica.

Para excluir o Workload:

1. Acesse [Azion Console](https://console.azion.com/) > **Workloads**.
2. Na linha `protected-api`, abra o menu de ações e selecione **Delete**.
3. Na caixa de diálogo **Delete Workload**, insira `protected-api`.
4. Selecione **Delete**.

Repita os passos nesta ordem: **Firewalls** para o Firewall, **WAF Rules** para o rule set, **Applications** para a Application e **Functions** para a Function. Cada caixa de diálogo pede o nome do recurso.

A conta não tem mais os recursos do tutorial.
