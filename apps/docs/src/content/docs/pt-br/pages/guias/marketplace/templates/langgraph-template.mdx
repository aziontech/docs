Você pode implantar um agente de IA criado com LangGraph na Azion a partir do template LangGraph AI Agent Boilerplate no Azion Console. Para criar uma aplicação sem um template, consulte [Primeiros passos com Applications](/pt-br/documentacao/plataforma/applications/primeiros-passos/).

O template configura agentes em tempo real que consultam e interagem com dados armazenados no [SQL Database](/pt-br/documentacao/plataforma/sql-database/), na infraestrutura distribuída da Azion. O template usa Vue `3.3.4`.

A implantação cria um repositório no GitHub para o seu projeto e um banco de dados no SQL Database. O banco de dados tem duas tabelas: uma para o histórico de conversas e outra para os documentos de referência. A implantação também cria uma aplicação backend, desenvolvida com LangGraph, que gerencia documentos e executa o agente. Além disso, cria um frontend em Vue para a interação do usuário. O template usa [Application Accelerator](/pt-br/documentacao/plataforma/applications/application-accelerator/), [Functions](/pt-br/documentacao/plataforma/functions/) e SQL Database, e o uso deles pode gerar custos. Para mais informações, consulte [Preços](/pt-br/documentacao/fundamentos/precos/).

---

## Pré-requisitos

- Uma conta Azion. Para criar uma, consulte [Criar uma conta](/pt-br/documentacao/fundamentos/criar-uma-conta/).
- Acesso ao Azion Console. Para entrar, consulte [Como acessar o Azion Console](/pt-br/documentacao/guias/plataforma/conta-e-billing/como-acessar-o-azion-console/).
- Uma [conta no GitHub](https://github.com/signup). A Azion se conecta a essa conta e cria nela o repositório do projeto.
- Uma chave de API da [OpenAI](https://platform.openai.com/).

## Implante o template

O LangGraph AI Agent Boilerplate abre como um formulário de configuração no Azion Console, e um asterisco marca cada campo obrigatório.

Para implantar o template:

<DocSteps>
  <DocStep title="Abra o template">

  Acesse [LangGraph AI Agent Boilerplate](https://console.azion.com/create/azion/langgraph-agent-boilerplate) no Azion Console. O formulário de configuração abre.

  </DocStep>
  <DocStep title="Conecte a Azion à sua conta do GitHub">

  Uma janela abre para confirmar a instalação do [Azion GitHub App](/pt-br/documentacao/guias/desenvolvimento-de-aplicacoes/automacao/azion-github-app/), que conecta a sua conta do GitHub à Azion. Nessa janela, defina as permissões do app e o acesso aos repositórios.

  </DocStep>
  <DocStep title="Selecione o Git scope com o qual trabalhar" />
  <DocStep title="Nomeie o agente">

  Insira um nome único e fácil de lembrar. Por padrão, o nome do banco de dados segue o padrão `<agent_name>-database`. Se o nome já estiver em uso, a plataforma retorna uma mensagem de erro.

  </DocStep>
  <DocStep title="Insira a sua chave de API da OpenAI" />
  <DocStep title="Selecione o método de autenticação">

  Selecione como os usuários se autenticam para acessar o agente e insira as informações que o método exige:

  - **No Auth**: o agente não exige autenticação. Deixe os campos em branco.
  - **Basic Auth**: insira o token ou a senha para a autenticação básica.
  - **Clerk Auth**: insira as chaves pública e privada do [Clerk](https://clerk.com) para autenticar por esse serviço. Você pode configurar as regras do processo de autenticação no dashboard da sua conta Clerk.

  </DocStep>
  <DocStep title="Inicie a implantação">

  Selecione **Deploy**.

  </DocStep>
</DocSteps>

Uma janela mostra os logs da implantação enquanto ela é executada. Quando a implantação termina, a página mostra os detalhes da aplicação, um link para abri-la no navegador e opções para continuar.

O link pode levar alguns minutos para começar a entregar a aplicação, enquanto a configuração dela se propaga pela infraestrutura distribuída da Azion. Se a página não carregar, aguarde alguns minutos e abra o link novamente.

## Configure o banco de dados

O LangGraph AI Agent Boilerplate cria duas tabelas no banco de dados: uma para o histórico de conversas e outra para os documentos de referência. Antes que o agente use os seus próprios documentos, configure o banco de dados e faça o upload deles pelo projeto backend.

Para configurar o banco de dados e fazer o upload dos seus documentos:

1. Abra o repositório do GitHub da aplicação backend que a implantação criou. O nome dele é semelhante a `<seu-nome-de-agente>-backend-agent`.
2. Verifique se o projeto tem um arquivo `.env` com as suas variáveis de ambiente. Para criar um novo, use esta estrutura:

    ```bash
    AZION_TOKEN="azion_token"
    OPENAI_API_KEY="your_openai_key"
    OPENAI_MODEL= 'gpt-4o'
    EMBEDDING_MODEL= 'text-embedding-3-small'

    # EdgeSQL database and table names. Usually, table names are not changed,
    # and the database name is the name of your agent + database: agent_name_database
    MESSAGE_STORE_DB_NAME="yourdb-database"
    MESSAGE_STORE_TABLE_NAME='messages'
    VECTOR_STORE_DB_NAME="yourdb-database"
    VECTOR_STORE_TABLE_NAME='vectors'

    # Optional: Langsmith to trace the requests and responses
    LANGSMITH_API_KEY=
    LANGCHAIN_PROJECT=
    LANGCHAIN_TRACING_V2=false

    # Optional: Clerk authentication with your frontend
    CLERK_PUBLISHABLE_KEY=
    CLERK_SECRET_KEY=
    ```

    Nem todas as variáveis são obrigatórias. Para saber o que cada uma faz, consulte [Variáveis de ambiente do backend](#variaveis-de-ambiente-do-backend).

3. Na pasta `migrations` do projeto, execute o setup do banco de vetores:

    ```bash
    yarn setup
    ```

    O setup configura o banco de vetores e cria a tabela `vectors` dele. O arquivo `migrations/uploadDocs.ts` apenas insere documentos em bancos de dados existentes, então execute este setup antes do primeiro upload.

4. Coloque os seus arquivos de documentos na pasta `migrations/files/`. Se a pasta `files` não existir, crie-a. Os formatos suportados são PDF, Markdown (`.md`), Texto (`.txt`) e JSON.
5. Faça o upload dos documentos:

    ```bash
    yarn upload-docs
    ```

    O upload divide o conteúdo dos arquivos em chunks menores e insere os chunks no vector store.

O banco de dados guarda os seus documentos de referência, e a aplicação pode acessá-los. Para mais detalhes sobre como configurar o projeto, consulte a [documentação do template](https://github.com/aziontech/azion-samples/tree/3cf53a690ac7f40508bc020adcfc61ba553d0b2f/templates/typescript/azion-react-agent).

O template também cria uma tabela que armazena as mensagens trocadas com o agente. Por padrão, a tabela mantém as mensagens por 14 dias.

:::tip[dica]
Para visualizar os seus bancos de dados e tabelas e executar comandos SQL pelo terminal, use o [EdgeSQL Shell](/pt-br/documentacao/plataforma/sql-database/edgesql-shell/). Ele é uma ferramenta de linha de comando para o SQL Database. Você também pode trabalhar com os bancos de dados pela [API v4 da Azion](/pt-br/documentacao/plataforma/sql-database/bancos-de-dados-e-consultas/#listar-bancos-de-dados).
:::

## Variáveis de ambiente do backend

A aplicação backend do LangGraph AI Agent Boilerplate lê a configuração dela do arquivo `.env` do projeto. Nem todas as variáveis são obrigatórias.

| Variável de ambiente | Descrição | Obrigatória |
| --- | --- | --- |
| `AZION_TOKEN` | O token para autenticação na plataforma da Azion. | Sim |
| `OPENAI_API_KEY` | Sua chave de API para acessar os serviços da OpenAI. | Sim |
| `OPENAI_MODEL` | O modelo da OpenAI que processa as requisições. Se não for definido, o valor padrão é `gpt-4o`. | Não |
| `EMBEDDING_MODEL` | O modelo que gera os embeddings. Se não for definido, o valor padrão é `text-embedding-3-small`. Para usar um modelo diferente, crie um banco de dados com colunas configuradas para esse modelo. | Não |
| `LANGSMITH_API_KEY` | A chave de API para acessar os serviços da Langsmith. | Não |
| `LANGCHAIN_PROJECT` | O identificador do projeto Langchain. | Não |
| `LANGCHAIN_TRACING_V2` | Ativa ou desativa o rastreamento do Langchain. Defina como `true` ou `false`. | Não |
| `MESSAGE_STORE_DB_NAME` | O nome do banco de dados que armazena as mensagens do histórico de conversas. Por padrão, é o mesmo banco de dados que armazena os documentos. Nome padrão: `<nome-do-agente>-database`. | Sim |
| `MESSAGE_STORE_TABLE_NAME` | O nome da tabela, no banco de dados de mensagens, que armazena o histórico de conversas. Nome padrão: `messages`. | Sim |
| `VECTOR_STORE_DB_NAME` | O nome do banco de dados que armazena os seus documentos como embeddings de vetores. Por padrão, é o mesmo banco de dados que armazena as mensagens. Nome padrão: `<nome-do-agente>-database`. | Sim |
| `VECTOR_STORE_TABLE_NAME` | O nome da tabela, no banco de dados de documentos, que armazena os embeddings. Nome padrão: `vectors`. | Sim |

## Personalize a configuração do banco de dados

O projeto backend do LangGraph AI Agent Boilerplate configura e inicializa os bancos de dados em dois arquivos. Você pode editá-los para adaptar a configuração dos bancos às suas necessidades:

- **Banco de vetores (RAG)**: `migrations/setupDatabase.ts` configura o banco de vetores com `AzionVectorStore.initialize()`. Ele cria a tabela `vectors` com a coluna de embedding que o modelo exige, por exemplo `F32_BLOB(1536)` quando `EMBEDDING_MODEL=text-embedding-3-small`.
- **Banco de mensagens (tracing)**: `src/services/edgeSqlTracerService.ts` cria o banco de dados de mensagens quando ele não existe. Ele cria a tabela `messages` com o DDL que `createSetupTableStatement()` gera. A configuração é feita sob demanda, pelo método `handleErrors`.

O arquivo `migrations/setupDatabase.ts` oferece duas formas de configurar o banco de vetores. O método ativo, em uso:

```typescript
AzionVectorStore.initialize(embeddingModel, { dbName, tableName }, { mode: "hybrid", columns: ["*"] })
```

O método alternativo, comentado no arquivo:

```typescript
// const vectorStore = new AzionVectorStore(...);
// await vectorStore.setupDatabase({ mode: "hybrid", columns: ["*"] });
```

O arquivo `migrations/uploadDocs.ts` processa os documentos com a função `getDocsFromFolder("migrations/files")`. A função lê todos os arquivos suportados da pasta e divide o conteúdo em chunks menores. Em seguida, insere os chunks no vector store para busca semântica.

Para ler os seus documentos de uma pasta diferente, edite `migrations/uploadDocs.ts` e altere o argumento de `getDocsFromFolder()`:

```typescript
// Exemplo: mudando para uma pasta personalizada
const docs = await getDocsFromFolder("minha-pasta-personalizada");
```

## Atualize o projeto

Cada push para o repositório do GitHub que o LangGraph AI Agent Boilerplate cria é implantado automaticamente.

Para atualizar o projeto implantado, faça push das suas alterações para esse repositório. A Azion implanta as alterações, e a aplicação entrega a nova versão.

## Gerencie a aplicação

As configurações que o LangGraph AI Agent Boilerplate aplica podem não servir para a sua aplicação. Você pode alterar qualquer uma delas a qualquer momento pelo Azion Console.

Para abrir as configurações da aplicação:

<DocSteps>
  <DocStep title="Abra a lista de aplicações">

  Acesse [Azion Console](https://console.azion.com/) > **Applications**. A lista mostra todas as aplicações que você criou, em ordem alfabética.

  </DocStep>
  <DocStep title="Selecione a aplicação que o template criou">

  Para encontrá-la em uma lista longa, busque pelo nome dela. A busca filtra a lista apenas pelo nome da aplicação.

  </DocStep>
</DocSteps>

A aplicação abre em uma página que reúne todas as configurações que você pode definir. Para mais informações, consulte [Main Settings](/pt-br/documentacao/plataforma/applications/main-settings/), [Rules Engine para Applications](/pt-br/documentacao/plataforma/applications/rules-engine/) e [Device Groups](/pt-br/documentacao/plataforma/applications/device-groups/).

## Adicione um domínio personalizado

A implantação do LangGraph AI Agent Boilerplate atribui à aplicação um domínio de [workload](/pt-br/documentacao/plataforma/workloads/) no formato `xxxxxxxxxx.map.azionedge.net`, que um navegador consegue abrir. Para entregar a aplicação em um domínio seu, adicione um domínio personalizado. Para mais informações, consulte [Domains](/pt-br/documentacao/plataforma/workloads/domains/) e [Adicione um domínio a um workload](/pt-br/documentacao/guias/plataforma/migracao/configurar-dominio/).
