Você pode enviar os logs de um stream para um container do [Azure Blob Storage](https://azure.microsoft.com/en-us/products/storage/blobs) pelo Azion Console ou com a Azion API. Para enviá-los a um workspace do Azure Monitor, consulte [Envie logs para o Azure Monitor](/pt-br/documentacao/guias/plataforma/observabilidade/azure-monitor-endpoint/).

[Data Stream](/pt-br/documentacao/plataforma/data-stream/) grava as linhas de log em um container da sua conta de armazenamento do Azure. O formulário do stream define o endpoint no campo **Connector**, em que o Azure Blob Storage é a opção *Azure Blob Storage*. Para cada campo e seus limites, consulte [Endpoints](/pt-br/documentacao/plataforma/data-stream/endpoints/#azure-blob-storage).

O exemplo coleta as requisições de um workload com a fonte de dados *Applications*.

## Pré-requisitos

- Uma conta Azion com a permissão **Edit Data Stream**. Para as permissões, consulte [Configurações do stream](/pt-br/documentacao/plataforma/data-stream/configuracoes-do-stream/#permissoes).
- Um [workload](/pt-br/documentacao/plataforma/workloads/) da conta que receba requisições.
- Uma conta de armazenamento do Azure e o nome dela, como `mystorageaccount`.
- Um container na conta de armazenamento. O container precisa existir antes que o stream envie para ele.
- Um token de assinatura de acesso compartilhado (SAS) para o container, com as permissões de criação, leitura, gravação e listagem.

## Crie o stream

Um filtro de workloads seleciona o workload do qual o stream coleta. Seus outros streams continuam ativos, o que não acontece com o sampling.

<Tabs client:visible sharedStore="interface">

<Fragment slot="panel.console">

Para criar o stream no Azion Console:

<DocSteps>
  <DocStep title="Abra a página do Data Stream">

  Acesse [Azion Console](https://console.azion.com/) > **Data Stream**.

  </DocStep>
  <DocStep title="Selecione + Stream" />
  <DocStep title="Dê um nome ao stream">

  Na seção **General**, insira um **Name**. Por exemplo: `logs-to-azure-blob`.

  </DocStep>
  <DocStep title="Selecione a fonte de dados">

  Na seção **Input**, selecione *Applications* em **Data Source**.

  </DocStep>
  <DocStep title="Desligue o Sampling">

  Na seção **Transform**, desligue **Sampling** enquanto **Option** ainda está como *All Current and Future Workloads*, o valor inicial. Um stream não pode ter sampling e um filtro de workloads ao mesmo tempo.

  </DocStep>
  <DocStep title="Escolha o workload">

  Na seção **Transform**, defina **Option** como *Filter Workloads*. Selecione seu workload em **Available Workload** e use a seta para movê-lo para **Chosen Workload**.

  </DocStep>
  <DocStep title="Selecione o template">

  Na seção **Render Template**, selecione *Applications Event Collector* em **Template**.

  </DocStep>
  <DocStep title="Selecione o endpoint Azure Blob Storage">

  Na seção **Output**, selecione *Azure Blob Storage* em **Connector**.

  </DocStep>
  <DocStep title="Informe a localização do container">

  Insira o nome da conta de armazenamento em **Storage Account**, como `mystorageaccount`. Insira o nome do container em **Container Name**, como `azion-logs`.

  </DocStep>
  <DocStep title="Insira o token SAS">

  Cole o token SAS do container em **Blob SAS Token**.

  </DocStep>
  <DocStep title="Mantenha o stream ativo">

  Na seção **Status**, mantenha **Active** ligado.

  </DocStep>
  <DocStep title="Selecione Save" />
</DocSteps>

O Console mostra `Your data stream has been created`. A lista do **Data Stream** mostra o stream com `Azure Blob Storage` na coluna **Connector** e o status **Active**.

</Fragment>

<Fragment slot="panel.api">

Para criar o stream com a API, envie uma requisição `POST` para `https://api.azion.com/v4/workspace/stream/streams`. Substitua `[TOKEN VALUE]` pelo seu personal token, `<workload-id>` pelo ID do seu workload e os valores de armazenamento pelos seus:

```bash
curl -X POST 'https://api.azion.com/v4/workspace/stream/streams' \
  -H 'Content-Type: application/json' \
  -H 'Authorization: Token [TOKEN VALUE]' \
  -d '{
    "name": "logs-to-azure-blob",
    "active": true,
    "inputs": [
      { "type": "raw_logs", "attributes": { "data_source": "workloads" } }
    ],
    "transform": [
      { "type": "filter_workloads", "attributes": { "workloads": [<workload-id>] } },
      { "type": "render_template", "attributes": { "template": 2 } }
    ],
    "outputs": [
      {
        "type": "azure_blob_storage",
        "attributes": {
          "storage_account": "mystorageaccount",
          "container_name": "azion-logs",
          "blob_sas_token": "[SAS TOKEN]"
        }
      }
    ]
  }'
```

A fonte de dados `workloads` é *Applications* no Console, e o template `2` é o *Applications Event Collector*. A API responde `201` com o stream armazenado:

```json
{
  "state": "executed",
  "data": {
    "id": 19565,
    "name": "logs-to-azure-blob",
    "last_editor": "user@example.com",
    "created": "2026-10-02T19:55:44.587850Z",
    "last_modified": "2026-10-02T19:55:44.587829Z",
    "product_version": "1.0",
    …
    "outputs": [
      {
        "type": "azure_blob_storage",
        "attributes": {
          "storage_account": "mystorageaccount",
          "container_name": "azion-logs",
          "blob_sas_token": "[SAS TOKEN]"
        }
      }
    ]
  }
}
```

O `id` identifica o stream em todas as requisições seguintes, como `/v4/workspace/stream/streams/19565`. Para cada chave do corpo, consulte [Configurações do stream](/pt-br/documentacao/plataforma/data-stream/configuracoes-do-stream/#objeto-do-stream).

</Fragment>

</Tabs>

Nem a API nem o Console contatam o container ao salvar o stream. Uma conta de armazenamento, um nome de container ou um token SAS errado só aparece quando o stream envia. Uma ativação entra em vigor depois de um a dois minutos.

## Confirme a entrega

[Real-Time Events](/pt-br/documentacao/plataforma/real-time-events/fontes-de-dados/#data-stream) registra cada envio de um stream, com o código de status que o endpoint retornou, seja o envio bem-sucedido ou não. Envie algumas requisições ao workload e aguarde cerca de um minuto. Um stream envia um lote a cada 60 segundos, ou antes, quando o lote chega a 2.000 linhas de log.

<Tabs client:visible sharedStore="interface">

<Fragment slot="panel.console">

Para encontrar os envios no Azion Console:

<DocSteps>
  <DocStep title="Abra a página do Real-Time Events">

  Acesse [Azion Console](https://console.azion.com/) > **Real-Time Events**.

  </DocStep>
  <DocStep title="Selecione a fonte de dados Data Stream" />
  <DocStep title="Leia os envios mais recentes">

  Cada linha é um envio. Encontre as linhas com `AZURE_BLOB_STORAGE` em **Endpoint Type** e leia o **Status Code** delas.

  </DocStep>
</DocSteps>

Um **Status Code** `200` significa que o container aceitou o lote. **Streamed Lines** informa o número de linhas de log do lote.

</Fragment>

<Fragment slot="panel.api">

Para ler os envios com a API, consulte o dataset `dataStreamedEvents` da API GraphQL do Real-Time Events. Substitua as datas por um intervalo que comece na ativação do stream:

```bash
curl -X POST 'https://api.azion.com/v4/events/graphql' \
  -H 'Content-Type: application/json' \
  -H 'Authorization: Token [TOKEN VALUE]' \
  -d '{"query":"query { dataStreamedEvents(limit: 20, filter: {tsRange: {begin: \"2026-10-02T19:45:00\", end: \"2026-10-02T20:30:00\"}}, orderBy: [ts_DESC]) { ts endpointType statusCode streamedLines dataStreamed } }"}'
```

A API responde `200` com um registro para cada envio, do mais recente para o mais antigo. Este registro vem de um stream que envia para um bucket S3:

```json
{
  "data": {
    "dataStreamedEvents": [
      {
        "ts": "2026-10-02T19:47:04Z",
        "endpointType": "S3",
        "statusCode": 200,
        "streamedLines": 2,
        "dataStreamed": 2797
      }
    ]
  }
}
```

Um envio ao Azure Blob Storage traz `AZURE_BLOB_STORAGE` em `endpointType`. Um `statusCode` `200` significa que o container aceitou o lote de `streamedLines` linhas de log e `dataStreamed` bytes. Uma lista `dataStreamedEvents` vazia significa que o stream não enviou nada no intervalo. Para cada campo, consulte [Campos da API GraphQL do Real-Time Events](/pt-br/documentacao/devtools/graphql/campos-gql-real-time-events/#datastreamedevents-data-stream).

</Fragment>

</Tabs>

Um status diferente de `200` vem do endpoint, exceto `503`, que significa que o Data Stream encontrou o endpoint indisponível. Para as causas, consulte [Solucionar problemas de Data Stream](/pt-br/documentacao/plataforma/data-stream/solucao-de-problemas/).
