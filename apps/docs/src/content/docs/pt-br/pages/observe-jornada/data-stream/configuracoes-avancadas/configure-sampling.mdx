Você pode configurar o sampling em um stream do [Data Stream](/pt-br/documentacao/plataforma/data-stream/) pelo Azion Console ou com a Azion API. Para limitar um stream aos workloads que você escolher, o que mantém os outros streams ativos, consulte [Associe workloads a um stream](/pt-br/documentacao/guias/plataforma/observabilidade/data-stream-associar-workloads/).

O sampling envia uma porcentagem dos eventos que um stream coleta, escolhidos aleatoriamente. Uma taxa menor reduz o volume, e o custo, dos dados que você coleta e analisa. Um stream com sampling cobre todos os workloads da conta, incluindo os workloads criados depois. Para os limites de cada campo, consulte [Configurações do stream](/pt-br/documentacao/plataforma/data-stream/configuracoes-do-stream/#transform).

:::caution[Atenção]
Salvar um stream ativo com sampling desativa todos os outros streams da conta, em qualquer taxa, incluindo `100`. A API não retorna erro nem aviso. Para executar vários streams ao mesmo tempo, dê a cada um deles um filtro de workloads em vez de sampling.
:::

## Pré-requisitos

- Um stream na sua conta Azion. Para criar um, consulte [Primeiros passos do Data Stream](/pt-br/documentacao/plataforma/data-stream/primeiros-passos/).
- A permissão **Edit Data Stream**. Para mais informações, consulte [Configurações do stream](/pt-br/documentacao/plataforma/data-stream/configuracoes-do-stream/#permissoes).

<Tabs client:visible sharedStore="interface">

<Fragment slot="panel.console">

- Acesso ao Azion Console. Para entrar, consulte [Como acessar o Azion Console](/pt-br/documentacao/guias/plataforma/conta-e-billing/como-acessar-o-azion-console/).
- Uma conta com menos de 3.000 workloads. Com 3.000 workloads ou mais, o Console bloqueia os formulários de stream e você gerencia os streams apenas pela API.

- O ID do stream e o ID do template dele. A resposta da listagem de `GET /v4/workspace/stream/streams?fields=id,name,active,transform` traz os dois: o `id` do stream e o `template` no item `render_template` do `transform` dele.

## Defina a taxa de sampling

A taxa é um número inteiro de 1 a 100: a porcentagem de eventos que o stream envia. Uma taxa de `100` envia todos os eventos e continua contando como sampling.

<Tabs client:visible sharedStore="interface">

<Fragment slot="panel.console">

Para definir a taxa de sampling no Azion Console:

<DocSteps>
  <DocStep title="Abra a página Data Stream">

  Acesse [Azion Console](https://console.azion.com/) > **Data Stream**.

  </DocStep>
  <DocStep title="Abra o stream">

  Na lista, selecione a linha do stream. O formulário de criação, aberto com **+ Stream**, tem a mesma seção **Transform**.

  </DocStep>
  <DocStep title="Selecione todos os workloads">

  Na seção **Transform**, defina **Option** como *All Current and Future Workloads*. A chave **Sampling** aparece apenas com essa opção.

  </DocStep>
  <DocStep title="Ative o Sampling">

  Se **Sampling** estiver desligado, ligue-o. **Sampling Rate (%)** aparece.

  </DocStep>
  <DocStep title="Insira a taxa">

  Em **Sampling Rate (%)**, insira a porcentagem de eventos a enviar. Por exemplo: `60`.

  </DocStep>
  <DocStep title="Selecione Save" />
  <DocStep title="Confirme o aviso de sampling">

  O diálogo **Attention** mostra `After activating and saving these settings, all other Data Streams will be disabled.` Selecione **Confirm**.

  </DocStep>
</DocSteps>

O Console mostra `Your data stream has been updated`.

</Fragment>

<Fragment slot="panel.api">

Para definir a taxa com a API, envie uma requisição `PATCH` com o array `transform` do stream. Defina `rate` no item `sampling` e mantenha o item `render_template` com o ID do template do seu stream. Este exemplo mantém o template `2`, *Applications Event Collector*. Substitua `<stream-id>` pelo ID do seu stream:

```bash
curl -X PATCH 'https://api.azion.com/v4/workspace/stream/streams/<stream-id>' \
  -H 'Content-Type: application/json' \
  -H 'Authorization: Token [TOKEN VALUE]' \
  -d '{
  "transform": [
    { "type": "sampling", "attributes": { "rate": 50 } },
    { "type": "render_template", "attributes": { "template": 2 } }
  ]
}'
```

A API responde `200` com o stream, que agora traz a nova taxa:

```json
{
  "state": "executed",
  "data": {
    "id": 19569,
    "name": "sampled-stream",
    …
    "transform": [
      { "type": "sampling", "attributes": { "rate": 50 } },
      { "type": "render_template", "attributes": { "template": 2 } }
    ],
    …
  }
}
```

O `transform` que você envia substitui o armazenado, então envie todos os itens que o stream mantém. Uma taxa fora do intervalo de 1 a 100 é recusada com `400`: `0` com `10050` `Min Value`, e `101` com `10068` `Max Value`. Uma taxa válida não retorna nenhum aviso de que os outros streams foram desativados.

</Fragment>

</Tabs>

Data Stream escolhe os eventos amostrados aleatoriamente. O diálogo **Attention** também informa `Sampling percentage is statistical and not absolutely precise. When multiple Data Streams have different sampling rates, the system uses the lowest percentage.`

Uma troca de stream ativo entra em vigor após um a dois minutos, e outras edições levam alguns minutos para se propagar. Durante esse intervalo, um stream que o salvamento desativou pode continuar enviando.

## Verifique quais streams estão ativos

Depois de salvar, o stream com sampling é o único stream ativo da conta. Aguarde dois minutos e verifique o status de cada stream.

<Tabs client:visible sharedStore="interface">

<Fragment slot="panel.console">

Para verificar os streams no Azion Console:

<DocSteps>
  <DocStep title="Abra a página Data Stream">

  Acesse [Azion Console](https://console.azion.com/) > **Data Stream**.

  </DocStep>
  <DocStep title="Leia a coluna Status">

  O stream que você salvou mostra *Active*. Todos os outros streams mostram *Inactive*.

  </DocStep>
  <DocStep title="Abra o stream">

  Selecione a linha do stream. **Sampling Rate (%)** mostra a taxa armazenada.

  </DocStep>
</DocSteps>

Apenas o stream com sampling está *Active*, na taxa que você definiu.

</Fragment>

<Fragment slot="panel.api">

Para verificar os streams com a API, liste-os com o estado `active` e o `transform` de cada um:

```bash
curl -X GET 'https://api.azion.com/v4/workspace/stream/streams?fields=id,name,active,transform' \
  -H 'Authorization: Token [TOKEN VALUE]'
```

A API responde `200` com uma entrada para cada stream:

```json
{
  "count": 4,
  "total_pages": 1,
  "page": 1,
  "page_size": 10,
  "next": null,
  "previous": null,
  "results": [
    {
      "id": 19553,
      "name": "activity-to-bucket",
      "active": false,
      "transform": [
        { "type": "sampling", "attributes": { "rate": 100 } },
        { "type": "render_template", "attributes": { "template": 251 } }
      ]
    },
    …
    {
      "id": 19554,
      "name": "sampled-stream",
      "active": true,
      "transform": [
        { "type": "sampling", "attributes": { "rate": 100 } },
        { "type": "render_template", "attributes": { "template": 251 } }
      ]
    },
    …
  ]
}
```

Nessa resposta, o stream `19554` foi o último salvo com sampling, então é o único com `"active": true`. O item `sampling` dele traz a taxa que ele usa.

</Fragment>

</Tabs>

Para ver o que o stream envia, consulte os envios dele no [Real-Time Events](/pt-br/documentacao/plataforma/real-time-events/fontes-de-dados/#data-stream). Cada envio é registrado com o status code do endpoint e o número de linhas de log que ele levou.
