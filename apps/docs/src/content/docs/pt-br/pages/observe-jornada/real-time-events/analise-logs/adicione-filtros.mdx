Você pode reduzir uma busca no [Real-Time Events](/pt-br/documentacao/plataforma/real-time-events/) do Azion Console aos registros cujo campo carrega um valor. O filtro e o campo de consulta são controles da visualização clássica. O Real-Time Events abre nessa visualização.

Um filtro nomeia um campo, um operador e um valor. Os campos que uma fonte de dados carrega decidem o que uma busca pode corresponder. Para cada fonte de dados e os campos dela, consulte [Fontes de dados](/pt-br/documentacao/plataforma/real-time-events/fontes-de-dados/).

Um filtro também reduz as linhas que uma busca lê dentro do banco de logs, que limita as linhas que uma consulta pode ler. Uma busca ampla alcança esse limite primeiro. Para esse limite, consulte [Limites](/pt-br/documentacao/plataforma/real-time-events/limites/).

---

## Pré-requisitos

- Uma conta Azion. Para criar uma, consulte [Como criar uma conta na Azion](/pt-br/documentacao/fundamentos/criar-uma-conta/).
- Acesso ao Azion Console. Para entrar, consulte [Como acessar o Azion Console](/pt-br/documentacao/guias/plataforma/conta-e-billing/como-acessar-o-azion-console/).
- Uma fonte de dados que carregue registros no período que você quer buscar.
- O campo que você quer corresponder. Para ler os campos que um registro carrega, consulte [Ler um registro de evento](/pt-br/documentacao/guias/plataforma/observabilidade/entender-logs/).

## Aplique um filtro

O diálogo **Filter** monta o filtro a partir de um campo, um operador e um valor. Uma busca com o campo de consulta vazio retorna todos os registros da fonte de dados selecionada no período.

Para filtrar uma busca no Azion Console:

<DocSteps>
  <DocStep title="Abra Real-Time Events">

  Acesse [Azion Console](https://console.azion.com/) > **Real-Time Events**.

  </DocStep>
  <DocStep title="Selecione a fonte de dados">

  Selecione a aba da fonte de dados, como **HTTP Requests**.

  </DocStep>
  <DocStep title="Abra o filtro">

  Selecione o ícone de filtro.

  </DocStep>
  <DocStep title="Selecione o campo">

  No diálogo **Filter**, selecione _Status_.

  </DocStep>
  <DocStep title="Selecione o operador">

  Em **Operator**, selecione _Equals_.

  </DocStep>
  <DocStep title="Informe o valor">

  No campo de valor, digite `400`.

  </DocStep>
  <DocStep title="Aplique o filtro">

  Selecione **Apply**.

  </DocStep>
</DocSteps>

A busca é executada na mesma hora. O campo de consulta mostra `status = 400` e o chip _Status equals: 400_ aparece. A tabela carrega apenas os registros que correspondem.

O filtro cobre o período que o campo de período mostra, _Last 5 minutes_ quando a página abre. Para buscar outro período, consulte [Defina o período](#defina-o-periodo).

No caso de uso [Monitorar a performance de sites e APIs](/pt-br/documentacao/casos-de-uso/melhorar-performance-e-confiabilidade/monitorar-a-performance-de-sites-e-apis/), espere:

- **Uma requisição pode ser rastreada.** No **Real-Time Events**, cada registro de _HTTP Requests_ do seu domínio carrega `requestTime`, `upstreamResponseTime` e `upstreamStatus`. `upstreamResponseTime` é o tempo que a origem levou para responder, e `upstreamStatus` é o status que ela retornou. Para chegar a esses registros, filtre pelo campo _Host_.

## Defina o período

O campo de período delimita os registros que uma busca lê. Ele abre em _Last 5 minutes_.

Para mudar o período de uma busca:

<DocSteps>
  <DocStep title="Abra o período">

  Selecione o campo de período.

  </DocStep>
  <DocStep title="Selecione o período">

  Selecione **Quick** e depois _Last 1 hour_.

  </DocStep>
  <DocStep title="Execute a busca">

  Selecione **Update**.

  </DocStep>
</DocSteps>

A tabela carrega os registros desse período que correspondem ao campo de consulta.

**Quick** também recebe um número e uma unidade depois de _Last_. A lista **Commonly used** oferece períodos de _Last 1 minute_ a _Last 1 year_. **Absolute** escolhe datas em um calendário.

O Real-Time Events mantém registros por 7 dias, e os registros de Activity History por 2 anos. Para a retenção, consulte [Limites](/pt-br/documentacao/plataforma/real-time-events/limites/).

---

## Edite o campo de consulta

O campo de consulta carrega o filtro em Azion Query Language. Você pode digitar uma condição ali em vez de usar o diálogo.

Para filtrar pelo campo de consulta:

<DocSteps>
  <DocStep title="Informe a consulta">

  No campo de consulta, digite `status = 301`.

  </DocStep>
  <DocStep title="Execute a busca">

  Selecione **Update**.

  </DocStep>
</DocSteps>

A tabela carrega apenas os registros cujo status é `301`.

---

## Exemplos de filtros

Para um campo numérico, como _Status_, **Operator** oferece sete opções:

- _Equals_
- _Less Than_
- _Less Than or Equal_
- _Greater Than_
- _Greater Than or Equal_
- _Not Equals_
- _Between_

Cada linha nomeia os registros que um filtro retorna, e o que selecionar no diálogo **Filter**:

| Registros retornados | Campo | Operador | Valor |
| -------------------- | ----- | -------- | ----- |
| Requisições respondidas com `404` | _Status_ | _Equals_ | `404` |
| Requisições respondidas com qualquer status exceto `200` | _Status_ | _Not Equals_ | `200` |
| Requisições respondidas com um erro de servidor | _Status_ | _Greater Than or Equal_ | `500` |

Na aba **HTTP Requests**, a lista de campos do diálogo **Filter** também oferece _Remote Address_, _Request Uri_, _Host_ e _Geoloc Country Name_.
