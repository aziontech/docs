Você pode enviar os logs de um stream para o [Splunk](https://www.splunk.com/) pelo Azion Console ou com a Azion API. Para escolher as variáveis que cada linha de log leva ao Splunk, consulte [Templates e payload](/pt-br/documentacao/plataforma/data-stream/templates-e-payload/).

[Data Stream](/pt-br/documentacao/plataforma/data-stream/) envia cada lote de linhas de log para o HTTP Event Collector (HEC) da sua instância do Splunk e se autentica com um token HEC. No Azion Console, o formulário do stream rotula o campo do endpoint como **Connector**, e a opção do Splunk é *Splunk*. Para ver todos os campos e os limites deles, consulte [Endpoints](/pt-br/documentacao/plataforma/data-stream/endpoints/#splunk).

O exemplo coleta as requisições de um Workload com a fonte de dados *Applications*.

## Crie o stream

O stream coleta do Workload que você escolher, por meio de um filtro de workloads. Um filtro de workloads mantém seus outros streams ativos.

:::caution[Atenção]
Salvar um stream ativo com sampling em Applications, Functions ou WAF Events desativa todos os outros streams da conta, exceto os streams de Activity History.
:::

<Tabs client:visible sharedStore="interface">

<Fragment slot="panel.console">

### Console

Para criar o stream no Azion Console:

<DocSteps>
  <DocStep title="Abra o Data Stream">

  Acesse [Azion Console](https://console.azion.com/) > **Data Stream**.

  </DocStep>
  <DocStep title="Selecione + Stream" />
  <DocStep title="Dê um nome ao stream">

  Na seção **General**, informe um **Name**. Por exemplo: `logs-to-splunk`.

  </DocStep>
  <DocStep title="Selecione a fonte de dados">

  Na seção **Input**, selecione *Applications* em **Data Source**.

  </DocStep>
  <DocStep title="Desative o Sampling">

  Na seção **Transform**, desative **Sampling** enquanto **Option** ainda estiver em *All Current and Future Workloads*, o valor inicial. Um stream não pode ter sampling e filtro de workloads ao mesmo tempo.

  </DocStep>
  <DocStep title="Defina o filtro de workloads">

  Na seção **Transform**, defina **Option** como *Filter Workloads*. Se o seu Console nomeia domínios onde este guia nomeia Workloads, a opção aparece como *Filter Domains*.

  </DocStep>
  <DocStep title="Escolha o Workload">

  Em **Available Workload**, selecione seu Workload e mova-o para **Chosen Workload** com a seta. Se o seu Console nomeia domínios, as listas mostram **Available Domain** e **Chosen Domain**.

  </DocStep>
  <DocStep title="Selecione o template">

  Na seção **Render Template**, selecione *Applications Event Collector* em **Template**.

  </DocStep>
  <DocStep title="Selecione o endpoint Splunk">

  Na seção **Output**, selecione *Splunk* em **Connector**.

  </DocStep>
  <DocStep title="Informe a URL do HEC">

  Em **URL**, informe a URL do HEC da sua instância do Splunk. Por exemplo: `https://splunk.example.com:8088/services/collector`. Para enviar a outro índice, adicione o índice ao final da URL, como `?index=myindex`.

  </DocStep>
  <DocStep title="Informe o token HEC">

  Em **API Key**, informe o token HEC da sua instância do Splunk.

  </DocStep>
  <DocStep title="Mantenha o stream ativo">

  Na seção **Status**, mantenha **Active** ativado.

  </DocStep>
  <DocStep title="Selecione Save" />
</DocSteps>

O Console mostra `Your data stream has been created`. O stream aparece na lista do **Data Stream** com `Splunk` na coluna **Connector** e o status **Active**.

</Fragment>

<Fragment slot="panel.api">

### API

Para criar o stream com a API, envie uma requisição `POST` para `https://api.azion.com/v4/workspace/stream/streams`. Substitua `[TOKEN VALUE]` pelo seu personal token, `<workload-id>` pelo ID do seu Workload e os valores do Splunk pelos seus:

```bash
curl -X POST 'https://api.azion.com/v4/workspace/stream/streams' \
  -H 'Content-Type: application/json' \
  -H 'Authorization: Token [TOKEN VALUE]' \
  -d '{
    "name": "logs-to-splunk",
    "active": true,
    "inputs": [
      { "type": "raw_logs", "attributes": { "data_source": "workloads" } }
    ],
    "transform": [
      { "type": "filter_workloads", "attributes": { "workloads": [<workload-id>] } },
      { "type": "render_template", "attributes": { "template": 2 } }
    ],
    "outputs": [
      {
        "type": "splunk",
        "attributes": {
          "url": "https://splunk.example.com:8088/services/collector",
          "api_key": "[API KEY]"
        }
      }
    ]
  }'
```

A fonte de dados `workloads` é *Applications* no Console, e o template `2` é *Applications Event Collector*. O atributo `api_key` recebe o token HEC. A API responde `201` com o stream armazenado:

```json
{
  "state": "executed",
  "data": {
    "id": 12352,
    "name": "logs-to-splunk",
    "last_editor": "user@example.com",
    "created": "2026-01-01T12:10:33.000000Z",
    "last_modified": "2026-01-01T12:10:33.000000Z",
    "product_version": "1.0",
    …
    "outputs": [
      {
        "type": "splunk",
        "attributes": {
          "url": "https://splunk.example.com:8088/services/collector",
          "api_key": "[API KEY]"
        }
      }
    ]
  }
}
```

Guarde o `id`: ele identifica o stream em todas as requisições seguintes, como `/v4/workspace/stream/streams/12352`. Para ver todas as chaves do corpo, consulte [Configurações do stream](/pt-br/documentacao/plataforma/data-stream/configuracoes-do-stream/#objeto-do-stream).

</Fragment>

</Tabs>

A API e o Console salvam o stream sem contatar o Splunk. Uma URL ou um token HEC errado só aparece quando o stream envia.

Depois que você cria ou ativa um stream, ele pode levar vários minutos para começar a coletar eventos. Ele não envia os eventos de antes disso.

## Confirme a entrega

[Real-Time Events](/pt-br/documentacao/plataforma/real-time-events/fontes-de-dados/#data-stream) registra todos os envios de um stream, entregues ou não, com um código de status.

Para fazer o stream enviar um lote:

1. Aguarde alguns minutos depois de salvar o stream.
2. Envie algumas requisições ao Workload.
3. Aguarde cerca de um minuto. Um stream envia um lote a cada 60 segundos, ou antes, quando chega a 2.000 linhas de log.

<Tabs client:visible sharedStore="interface">

<Fragment slot="panel.console">

### Console

Para encontrar os envios no Azion Console:

<DocSteps>
  <DocStep title="Abra o Real-Time Events">

  Acesse [Azion Console](https://console.azion.com/) > **Real-Time Events**.

  </DocStep>
  <DocStep title="Selecione a fonte de dados Data Stream" />
  <DocStep title="Leia os envios mais recentes">

  Cada linha é um envio. Encontre as linhas com `SPLUNK` em **Endpoint Type** e leia o **Status Code** delas.

  </DocStep>
</DocSteps>

Um **Status Code** `200` significa que o Splunk aceitou o lote. **Streamed Lines** mostra o número de linhas de log do lote.

</Fragment>

<Fragment slot="panel.api">

### API

Para ler os envios com a API, consulte o dataset `dataStreamedEvents` da API GraphQL do Real-Time Events. Substitua as datas por um intervalo que cubra a ativação do stream:

```bash
curl -X POST 'https://api.azion.com/v4/events/graphql' \
  -H 'Content-Type: application/json' \
  -H 'Authorization: Token [TOKEN VALUE]' \
  -d '{"query":"query { dataStreamedEvents(limit: 20, filter: {tsRange: {begin: \"2026-01-01T12:00:00\", end: \"2026-01-01T12:45:00\"}}, orderBy: [ts_DESC]) { ts endpointType statusCode streamedLines dataStreamed } }"}'
```

A API responde `200` com um registro para cada envio, do mais recente para o mais antigo:

```json
{
  "data": {
    "dataStreamedEvents": [
      {
        "ts": "2026-01-01T12:16:04Z",
        "endpointType": "SPLUNK",
        "statusCode": 200,
        "streamedLines": 2,
        "dataStreamed": 2797
      }
    ]
  }
}
```

Um envio para o Splunk traz `SPLUNK` em `endpointType`. Um `statusCode` `200` significa que o Splunk aceitou o lote, e `streamedLines` e `dataStreamed` dão o tamanho dele em linhas de log e em bytes. Uma lista `dataStreamedEvents` vazia significa que o stream não enviou nada no intervalo. Para ver todos os campos, consulte [Campos do Real-Time Events](/pt-br/documentacao/devtools/graphql/campos-gql-real-time-events/#eventos-de-dados-transmitidos).

</Fragment>

</Tabs>

Se Real-Time Events não mostrar nenhum envio para o stream depois de um minuto, envie outra requisição ao Workload e confira de novo.

Um envio que o Splunk aceitou mostra `200`. Um envio que falhou pode mostrar um código que o endpoint nunca retornou, e `503` significa que Data Stream encontrou o endpoint indisponível. Para encontrar a causa, consulte [Solucione problemas de Data Stream](/pt-br/documentacao/plataforma/data-stream/solucao-de-problemas/).
