Este guia orienta você a armazenar o seu primeiro objeto no [Object Storage](/pt-br/documentacao/plataforma/object-storage/). No fim, você vai ter:

- O seu primeiro bucket, cujos objetos as suas [Applications](/pt-br/documentacao/plataforma/applications/) podem ler, mas não gravar.
- Um objeto armazenado nesse bucket, endereçado pela sua chave.
- O objeto listado no bucket, o que confirma o upload.

Servir um arquivo aos seus usuários por uma Application e um Connector exige três partes, nesta ordem:

1. Um **bucket** é o contêiner de nível mais alto para objetos. Buckets não são aninhados.
2. Um **objeto** é um arquivo armazenado no bucket, sob uma chave, com o content type com que é servido. Uma `/` em uma chave faz parte da chave, não é uma pasta.
3. Um [Connector](/pt-br/documentacao/plataforma/connectors/) do tipo `storage` encaminha requisições ao bucket depois que uma regra da Application define esse Connector.

Este guia cria o bucket e o objeto e para antes do Connector, então nenhuma Application serve o objeto ainda.

## Crie um bucket

Um bucket guarda os objetos dos quais você faz upload. Este é somente de leitura: as suas Applications podem ler os objetos dele e não podem gravá-los.

Um nome de bucket tem de 6 a 63 caracteres entre letras minúsculas, números e hífens. Ele começa e termina com uma letra ou um número. Um nome é único em todas as contas Azion, então um nome curto e genérico provavelmente já está em uso.

Alguns prefixos e sufixos são reservados, como o prefixo `azion`. Para todas as regras de nome, consulte [Buckets e objetos](/pt-br/documentacao/plataforma/object-storage/buckets-e-objetos/).

<Tabs client:visible sharedStore="interface">

<Fragment slot="panel.console">

### Console

Para criar o bucket pelo Azion Console:

<DocSteps>
  <DocStep title="Abra a lista de buckets">

  Acesse [Azion Console](https://console.azion.com/) > **Object Storage** > **Buckets**.

  </DocStep>
  <DocStep title="Abra o formulário de criação">

  Inicie um novo bucket a partir da lista de **Buckets**. Uma conta que ainda não tem buckets oferece **Bucket** na lista vazia.

  </DocStep>
  <DocStep title="Nomeie o bucket">

  Em **General**, em **Name**, insira um nome seu.

  </DocStep>
  <DocStep title="Mantenha o nível de acesso">

  Em **Settings**, mantenha **Workloads Access** como _Read Only_, o padrão.

  </DocStep>
  <DocStep title="Selecione Create Bucket" />
</DocSteps>

O bucket aparece em **Buckets**, que lista o seu **Name**, **Size**, **Last Editor** e **Last Modified**.

</Fragment>

<Fragment slot="panel.cli">

### CLI

Para criar o bucket com a Azion CLI, substitua `my-first-bucket` por um nome seu e execute:

<Code client:visible lang="bash" code={`azion create storage bucket --name my-first-bucket --workloads-access read_only`} />

O comando confirma o bucket:

```text
Bucket created successfully
```

Com um nome já em uso, na sua conta ou em outra, o comando imprime `The name you've selected is already in use by another resource`. Escolha um nome diferente e execute o comando outra vez.

O bucket existe e não guarda nenhum objeto. Para todas as flags que o comando aceita, consulte [Azion CLI storage](/pt-br/documentacao/devtools/cli/recursos/storage/).

</Fragment>

<Fragment slot="panel.api">

### API

Para criar o bucket com a Azion API, envie uma requisição `POST` ao endpoint de buckets. Substitua `[TOKEN VALUE]` pelo seu personal token e `my-first-bucket` por um nome seu:

<Code client:visible lang="bash" code={`curl --request POST \\
\x20 --url https://api.azion.com/v4/workspace/storage/buckets \\
\x20 --header 'Accept: application/json' \\
\x20 --header 'Authorization: Token [TOKEN VALUE]' \\
\x20 --header 'Content-Type: application/json' \\
\x20 --data '{
\x20 "name": "my-first-bucket",
\x20 "workloads_access": "read_only"
}'`} />

Um `201` carrega o bucket:

```json
{
  "state": "executed",
  "data": {
    "name": "my-first-bucket",
    "workloads_access": "read_only",
    "last_editor": "user@example.com",
    "last_modified": "2026-01-01T12:14:08.914719+00:00",
    "product_version": "1.0"
  }
}
```

Um `400` com o código `17000` significa que o nome já está em uso, na sua conta ou em outra. Escolha um nome diferente e envie a requisição outra vez.

O bucket existe e não guarda nenhum objeto.

</Fragment>

</Tabs>

:::note[nota]
O nível de acesso, `workloads_access`, decide o que um Connector e uma Function das suas Applications fazem com os objetos. Azion Console o chama de **Workloads Access**, e a Azion CLI o define com `--workloads-access`.

O nível de acesso não restringe a Azion API nem o protocolo S3. Um personal token, ou uma credencial com a capability `writeFiles`, grava em um bucket `read_only`. Para mais informações, consulte [Como o Object Storage funciona](/pt-br/documentacao/plataforma/object-storage/como-funciona/).
:::

## Faça upload de um objeto

Um objeto é armazenado sob uma chave e a chave é como toda interface o endereça depois. Uma chave tem de 1 a 1.024 caracteres.

<Tabs client:visible sharedStore="interface">

<Fragment slot="panel.console">

### Console

Para fazer upload do arquivo pelo Azion Console:

<DocSteps>
  <DocStep title="Abra o bucket">

  Em **Buckets**, selecione o bucket que você criou.

  </DocStep>
  <DocStep title="Adicione o arquivo">

  Selecione **Upload files** ou arraste o arquivo até a área de destino. O nome do arquivo se torna a chave do objeto. O Console recusa um arquivo maior que 300 MB.

  </DocStep>
</DocSteps>

O objeto é armazenado no bucket, sob a chave retirada do nome do arquivo.

</Fragment>

<Fragment slot="panel.cli">

### CLI

Para fazer upload do arquivo com a Azion CLI, passe para `--source` um caminho relativo ao seu diretório de trabalho. Substitua o nome do bucket, a chave e o caminho do arquivo pelos seus:

<Code client:visible lang="bash" code={`azion create storage object --bucket-name my-first-bucket --object-key images/logo.png --source ./logo.png`} />

O comando confirma o objeto:

```text
Object created successfully
```

O objeto está armazenado. O segmento `images/` faz parte da chave, não é uma pasta que precisava existir antes.

:::note[nota]
Na Azion CLI 4.26.2, `--source` com caminho absoluto falha com `no such file or directory`: o comando antepõe o diretório de trabalho a ele.
:::

</Fragment>

<Fragment slot="panel.api">

### API

Para fazer upload do arquivo com a Azion API, envie uma requisição `POST`. O caminho informa o bucket e a chave, e o corpo leva o arquivo. Não existe uma sequência de criar e depois escrever: o objeto existe quando a requisição tem sucesso.

Substitua a chave e o caminho do arquivo pelos seus. Defina `Content-Type` com o tipo do seu arquivo, porque o valor armazenado é o que este header carrega:

<Code client:visible lang="bash" code={`curl --request POST \\
\x20 --url https://api.azion.com/v4/workspace/storage/buckets/my-first-bucket/objects/images/logo.png \\
\x20 --header 'Accept: application/json' \\
\x20 --header 'Authorization: Token [TOKEN VALUE]' \\
\x20 --header 'Content-Type: image/png' \\
\x20 --data-binary '@./logo.png'`} />

Um `201` carrega a chave sob a qual o objeto está armazenado:

```json
{
  "state": "executed",
  "data": {
    "object_key": "images/logo.png"
  }
}
```

O objeto está armazenado. O segmento `images/` faz parte da chave, não é uma pasta que precisava existir antes.

</Fragment>

</Tabs>

## Confirme que o objeto está armazenado

O bucket lista o que guarda, então você pode confirmar o upload sem outra interface.

<Tabs client:visible sharedStore="interface">

<Fragment slot="panel.console">

### Console

Para encontrar o objeto pelo Azion Console:

<DocSteps>
  <DocStep title="Abra a lista de buckets">

  Acesse [Azion Console](https://console.azion.com/) > **Object Storage** > **Buckets**.

  </DocStep>
  <DocStep title="Selecione o bucket">

  Selecione o bucket que você criou.

  </DocStep>
  <DocStep title="Encontre o objeto pela sua chave">

  O objeto é listado sob a sua chave. Uma chave com uma `/`, como `images/logo.png`, agrupa sob o segmento antes da `/`. Esse segmento é um prefixo, não uma pasta.

  </DocStep>
</DocSteps>

O objeto está listado sob a sua chave, o que confirma o upload.

</Fragment>

<Fragment slot="panel.cli">

### CLI

Para listar o que o bucket guarda com a Azion CLI, execute:

<Code client:visible lang="bash" code={`azion list storage object --bucket-name my-first-bucket --details`} />

A tabela carrega uma linha por objeto, com a chave, a última modificação e o tamanho em bytes:

```text
KEY              LAST MODIFIED                    SIZE
images/logo.png  2026-01-01 12:07:27.3 +0000 UTC  408
```

Sem `--details`, a tabela carrega apenas a chave e o horário de modificação.

O objeto está listado sob a sua chave, o que confirma o upload.

</Fragment>

<Fragment slot="panel.api">

### API

Duas requisições confirmam o upload: uma lista o bucket e a outra lê o objeto de volta.

<DocSteps>
  <DocStep title="Liste os objetos do bucket">

  Envie uma requisição `GET` ao endpoint de objetos do bucket:

  <Code client:visible lang="bash" code={`curl --request GET \\
  \x20 --url https://api.azion.com/v4/workspace/storage/buckets/my-first-bucket/objects \\
  \x20 --header 'Accept: application/json' \\
  \x20 --header 'Authorization: Token [TOKEN VALUE]'`} />

  A resposta lista cada chave com a última modificação e o tamanho em bytes. `is_folder` diz se a entrada é um prefixo:

  ```json
  {
    "continuation_token": null,
    "results": [
      {
        "key": "images/logo.png",
        "last_modified": "2026-01-01T12:14:26.303000Z",
        "size": 408,
        "is_folder": false
      }
    ]
  }
  ```

  </DocStep>
  <DocStep title="Faça download do objeto">

  Leia o objeto de volta para um arquivo local e confirme o content type que a Azion armazenou:

  <Code client:visible lang="bash" code={`curl --request GET \\
  \x20 --url https://api.azion.com/v4/workspace/storage/buckets/my-first-bucket/objects/images/logo.png \\
  \x20 --header 'Authorization: Token [TOKEN VALUE]' \\
  \x20 --output ./logo-downloaded.png --dump-header -`} />


  Os headers da resposta carregam `HTTP/2 200` e o `content-type` que o upload definiu, e o arquivo é escrito em `./logo-downloaded.png`.

  </DocStep>
</DocSteps>

O objeto é lido de volta com o content type que você definiu, o que confirma o upload.

</Fragment>

</Tabs>
