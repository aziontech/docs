[Object Storage](/pt-br/documentacao/plataforma/object-storage/) responde a requisições S3 em seu próprio endpoint, então uma ferramenta, um SDK ou uma biblioteca que fala o protocolo S3 alcança os mesmos buckets e os mesmos objetos que a API da Azion v4 alcança. O que muda é a credencial: a API v4 carrega um personal token, e o endpoint S3 carrega uma requisição assinada com Signature Version 4 (SigV4) usando um access key e um secret key. Esta página lista a credencial que guarda esse par de chaves, as capabilities que ela concede, as configurações de conexão e as operações S3 que Azion suporta. Para os passos que configuram um cliente, consulte [Usar ferramentas compatíveis com S3](/pt-br/documentacao/guias/desenvolvimento-de-aplicacoes/dados/protocolo-s3-para-object-storage/).

---

## Configurações de conexão

Um cliente S3 precisa do endpoint, da região e do par de chaves de uma credencial.

| Configuração | Valor |
| --- | --- |
| Endpoint | `s3.us-east-005.azionstorage.net` |
| Região | `us-east-005` |
| Access key | O `access_key` que a credencial retorna |
| Secret key | O `secret_key` que a credencial retorna |

O endpoint não valida a região da assinatura, então uma requisição assinada para outra região, como `us-east-1`, também funciona. Defina `us-east-005`, a região do host name do endpoint.

Um cliente que monta seus próprios host names usa o template no estilo DNS `%(bucket).s3.us-east-005.azionstorage.net`.

As duas formas de endereço alcançam o mesmo objeto. O estilo virtual-host carrega o bucket no host name, e o estilo path carrega o bucket no primeiro segmento do caminho:

```text
my-bucket-ro.s3.us-east-005.azionstorage.net/file.txt
s3.us-east-005.azionstorage.net/my-bucket-ro/file.txt
```

Quem tem uma URL pré-assinada de `GetObject` lê o objeto pelo endpoint, sem outra autenticação. Os [Termos de Serviço](/pt-br/documentacao/contratos/tds/) dizem que a entrega a usuários finais deve passar por uma Application que usa Connectors. Eles também sujeitam o acesso direto aos objetos, fora de uma Application, a rate limits. Para servir objetos aos seus usuários, use uma [Application](/pt-br/documentacao/plataforma/applications/) cuja regra define um [Connector](/pt-br/documentacao/plataforma/connectors/) do tipo `storage`, que encaminha as requisições ao bucket.

## Credenciais

Uma credencial guarda o par de chaves com que um cliente S3 assina, as operações que esse par de chaves pode executar e os buckets que ele pode alcançar. Crie uma pela API da Azion v4 em `https://api.azion.com/v4/workspace/storage/credentials`, que esta página documenta, ou no Azion Console.

No Azion Console: **Credentials** › **Object Storage**, ou a aba **Credentials** de um bucket. Azion Console exige pelo menos um bucket e uma data de expiração, que a API deixa opcionais.

Uma credencial é independente do nível de acesso do bucket. `workloads_access` decide apenas o que um Connector e uma [Function](/pt-br/documentacao/plataforma/functions/) das suas Applications podem fazer com os objetos. Uma credencial que carrega `writeFiles` grava em um bucket em qualquer nível, `restricted` incluído. Para os níveis de acesso, consulte [Buckets e objetos](/pt-br/documentacao/plataforma/object-storage/buckets-e-objetos/#niveis-de-acesso).

| Campo | Tipo | Obrigatório | Padrão | Descrição |
| --- | --- | --- | --- | --- |
| `name` | string | Sim | — | O nome da credencial: letras, números e hífens |
| `capabilities` | array de strings | Sim | — | As operações que a credencial pode executar, entre os seis valores em [Capabilities](#capabilities) |
| `buckets` | array de nomes de bucket | Não | `[]`, todos os buckets da conta | Os buckets que a credencial alcança |
| `expiration_date` | date-time, UTC ISO 8601 | Não | `null` | Quando a credencial expira. Precisa ser posterior à data de criação |

:::caution[Atenção]
`buckets` é plural, aceita um array e é o campo que limita o escopo de uma credencial. Uma requisição de criação que o omite, ou que envia `bucket` no singular, produz uma credencial que alcança todos os buckets da conta. A resposta então carrega `"buckets": []`.
:::

Uma credencial não muda depois de criada: um `PATCH` ou um `PUT` nela é recusado com `405` `10007`. Para alterar as capabilities, os buckets ou a data de expiração, crie outra credencial e exclua a antiga.

### Criar uma credencial

Crie a credencial com o personal token da conta que é dona dos buckets:

```bash
curl --request POST \
  --url https://api.azion.com/v4/workspace/storage/credentials \
  --header 'Accept: application/json' \
  --header 'Authorization: Token [TOKEN VALUE]' \
  --header 'Content-Type: application/json' \
  --data '{
  "name": "my-credential",
  "capabilities": ["listFiles", "readFiles", "writeFiles", "deleteFiles", "listAllBucketNames", "listBuckets"],
  "buckets": ["my-bucket-ro"],
  "expiration_date": "2026-12-31T23:59:59Z"
}'
```

A resposta carrega `201` e a credencial, com as duas chaves:

```json
{
  "state": "executed",
  "data": {
    "id": 1236,
    "name": "my-credential",
    "access_key": "[ACCESS KEY]",
    "secret_key": "[SECRET KEY]",
    "capabilities": [
      "listAllBucketNames",
      "listBuckets",
      "listFiles",
      "readFiles",
      "writeFiles",
      "deleteFiles"
    ],
    "buckets": ["my-bucket-ro"],
    "expiration_date": "2026-12-31T23:59:59Z",
    "last_editor": "user@example.com",
    "created_at": "2026-01-01T12:03:16.829681Z",
    "last_modified": "2026-01-01T12:03:16.829695Z"
  }
}
```

`secret_key` é retornado por esta resposta e por nenhuma outra chamada. Guarde-o quando a credencial for criada; para substituir um secret key que não foi guardado, crie outra credencial.

### Listar credenciais

```bash
curl --request GET \
  --url https://api.azion.com/v4/workspace/storage/credentials \
  --header 'Accept: application/json' \
  --header 'Authorization: Token [TOKEN VALUE]'
```

A resposta é paginada:

```json
{
  "count": 1,
  "total_pages": 1,
  "page": 1,
  "page_size": 10,
  "next": null,
  "previous": null,
  "results": [
    {
      "id": 1236,
      "name": "ci-upload",
      "access_key": "[ACCESS KEY]",
      "capabilities": ["listFiles", "readFiles", "writeFiles"],
      "buckets": ["my-bucket-ro"],
      "expiration_date": "2027-01-31T23:59:59Z",
      "created_at": "2026-01-01T12:03:16.829681Z",
      "last_modified": "2026-01-01T12:03:16.829695Z",
      "last_editor": "user@example.com"
    }
  ]
}
```

Para ler uma credencial, envie `GET` para `https://api.azion.com/v4/workspace/storage/credentials/<credential-id>`. A resposta carrega os mesmos campos em `data`, sem `secret_key`.

Nenhuma chamada depois da requisição de criação retorna `secret_key`. Substitua um secret key perdido criando outra credencial e excluindo a antiga.

### Excluir uma credencial

Exclua uma credencial pelo `id` que a resposta de criação retornou:

```bash
curl --request DELETE \
  --url https://api.azion.com/v4/workspace/storage/credentials/<credential-id> \
  --header 'Accept: application/json' \
  --header 'Authorization: Token [TOKEN VALUE]'
```

A resposta carrega `200` e `{"state": "executed"}`. A partir daí, uma requisição assinada com o par de chaves dela recebe `403`.

## Capabilities

Uma capability nomeia as operações S3 que uma credencial permite. O array `capabilities` aceita estes seis valores e nenhum outro, e um valor fora dos seis retorna `17008`. A última coluna lista o que cada capability permite sozinha, em um bucket do escopo da credencial:

| Capability | No Azion Console | Operações S3 que ela permite sozinha |
| --- | --- | --- |
| `listFiles` | List Files | ListObjectsV2 |
| `readFiles` | Read Files | GetObject, HeadObject |
| `writeFiles` | Write Files | PutObject, CreateMultipartUpload, DeleteObject |
| `deleteFiles` | Delete Files | Nenhuma |
| `listAllBucketNames` | List All Bucket Names | ListBuckets |
| `listBuckets` | List Buckets | HeadBucket |

`writeFiles` também exclui, porque permite `DeleteObject`. `deleteFiles` sozinha não permite nenhuma operação, nem `DeleteObject`, embora a API aceite uma credencial que carrega apenas `deleteFiles`. Nenhuma capability sozinha permite `CopyObject`, e uma credencial com as seis permite todas as operações de [Operações suportadas](#operacoes-suportadas).

Para uma chave que não existe, o status depende das capabilities, como indica [Erros](#erros).

:::caution[Atenção]
Uma credencial com `listAllBucketNames` lista o nome de todos os buckets da conta com `ListBuckets`, mesmo quando `buckets` a limita a um bucket.
:::

## Operações suportadas

A Azion suporta as dezesseis operações S3 abaixo, e uma credencial com as seis capabilities permite cada uma delas. Os [Termos de Serviço](/pt-br/documentacao/contratos/tds/) atribuem essas operações a classes de cobrança, e [Preços](/pt-br/documentacao/fundamentos/precos/#object-storage) traz as tarifas.

A última coluna traz a forma [s3cmd](https://s3tools.org/s3cmd) de cada operação, como exemplo de como um cliente a expressa.

| Operação | O que ela faz | Comando s3cmd |
| --- | --- | --- |
| ListBuckets | Lista os buckets da conta | `s3cmd ls` |
| HeadBucket | Verifica um bucket: `200`, `404` quando ele não existe, `403` fora do escopo | `s3cmd info s3://BUCKET` |
| ListMultipartUploads | Lista os multipart uploads em andamento em um bucket | `s3cmd multipart s3://BUCKET` |
| ListObjects | Lista os objetos de um bucket, ordenados por chave | `s3cmd ls s3://BUCKET` |
| ListObjectsV2 | Lista os objetos de um bucket e pagina com um continuation token | `s3cmd ls s3://BUCKET` |
| CopyObject | Copia um objeto que já está armazenado | `s3cmd cp s3://BUCKET/OBJECT1 s3://BUCKET/OBJECT2` |
| GetObject | Retorna um objeto, ou um intervalo de bytes dele com `Range` | `s3cmd get s3://BUCKET/OBJECT LOCAL_FILE` |
| HeadObject | Retorna os metadados de um objeto, sem o objeto em si | `s3cmd info s3://BUCKET/OBJECT` |
| DeleteObject | Remove um objeto de um bucket | `s3cmd del s3://BUCKET/OBJECT` |
| DeleteObjects | Remove vários objetos em uma requisição, com as chaves no corpo XML | `s3cmd del s3://BUCKET/PREFIX --recursive` |
| AbortMultipartUpload | Encerra um multipart upload sem montá-lo | `s3cmd abortmp s3://BUCKET/OBJECT Id` |
| CompleteMultipartUpload | Monta no objeto as partes enviadas | Chamada por `s3cmd put` |
| CreateMultipartUpload | Inicia um multipart upload e retorna o `uploadId` que agrupa suas partes | Chamada por `s3cmd put` |
| ListParts | Lista as partes enviadas para um multipart upload | `s3cmd listmp s3://BUCKET/OBJECT Id` |
| PutObject | Faz upload de um objeto | `s3cmd put FILE s3://BUCKET/OBJECT` |
| UploadPart | Faz upload de uma parte de um multipart upload | Chamada por `s3cmd put` |

As duas operações de listagem paginam: uma resposta que não traz todas as chaves define `IsTruncated` como true. `ListObjectsV2` também retorna um `NextContinuationToken`, que a próxima requisição envia como o parâmetro de consulta `continuation-token`. Com `Delimiter=/`, uma listagem retorna as chaves da raiz e uma entrada `CommonPrefixes` por prefixo, como `assets/`.

As seis operações de multipart carregam um upload grande em partes. `CreateMultipartUpload` abre o upload, `UploadPart` envia cada parte, `CompleteMultipartUpload` as monta e `AbortMultipartUpload` encerra um upload que não foi concluído; `ListParts` e `ListMultipartUploads` informam o que está em andamento. Um cliente que divide arquivos grandes as chama a partir do seu próprio comando de upload, então elas raramente são chamadas diretamente.

Além das dezesseis, o endpoint responde a estas operações assim:

| Operação | Resposta |
| --- | --- |
| ListObjectVersions | Lista as versões anteriores de uma chave e os objetos excluídos |
| GetObject com um ID de versão | Retorna essa versão, inclusive a versão de um objeto excluído |
| CreateBucket, DeleteBucket | `403` `AccessDenied` |
| GetBucketLocation, GetBucketVersioning, PutBucketVersioning | `403` `AccessDenied` |
| GetBucketLifecycleConfiguration, PutBucketLifecycleConfiguration | `403` `AccessDenied` |
| PutObjectAcl | `501` `NotImplemented` |
| PutObject com `If-None-Match: *` | `501` `NotImplemented` |

Uma versão anterior fica por um prazo que você não define, como indicam os [Limites do Object Storage](/pt-br/documentacao/plataforma/object-storage/limites/#escopo). Crie e exclua buckets pela API da Azion, pelo Azion Console, pela Azion CLI ou pelo Terraform Provider.

### Status da resposta

Uma requisição assinada ao endpoint retorna estes status:

| Operação | Requisição assinada | Status |
| --- | --- | --- |
| ListBuckets | `GET /` | `200` |
| ListObjectsV2 | `GET /<bucket>?list-type=2` | `200` |
| PutObject | `PUT /<bucket>/<key>` | `200` |
| GetObject | `GET /<bucket>/<key>` | `200` |
| HeadObject | `HEAD /<bucket>/<key>` | `200` |
| DeleteObject | `DELETE /<bucket>/<key>` | `204` |

As duas operações de listagem respondem em XML, como o protocolo S3 define.

## Autenticação

Uma requisição a `s3.us-east-005.azionstorage.net` é assinada com Signature Version 4, a partir do `access_key` e do `secret_key` da credencial. A assinatura também nomeia uma região, que o endpoint não valida, como indica [Configurações de conexão](#configuracoes-de-conexao). Um cliente S3 assina cada requisição assim que tem as configurações de conexão. Uma requisição sem assinatura é recusada com `401` e o código `UnauthorizedAccess`.

Esta não é a autenticação que a API da Azion v4 usa. Uma chamada a `https://api.azion.com/v4/workspace/storage` carrega um [personal token](/pt-br/documentacao/guias/plataforma/conta-e-billing/personal-tokens/) em um header `Authorization`, e o que a chamada pode fazer vem das permissões da conta. Uma requisição S3 assinada não carrega token, e o que ela pode fazer vem das `capabilities` da credencial e do seu escopo de `buckets`.

As duas se encontram em um ponto: criar, listar e excluir uma credencial são chamadas da API v4, então elas carregam o personal token. Tudo o que o endpoint S3 responde é assinado com o par de chaves que a chamada de criação retornou.

## Erros

Uma requisição de credencial que é rejeitada retorna o envelope de erro que toda resposta da API do Object Storage usa. Para os outros códigos que ela pode retornar, consulte [Buckets e objetos](/pt-br/documentacao/plataforma/object-storage/buckets-e-objetos/#erros).

| Código | Título | Status | Causa |
| --- | --- | --- | --- |
| `10007` | `Method Not Allowed` | 405 | Um `PATCH` ou um `PUT` é enviado a uma credencial, que não muda |
| `10059` | `Required Field` | 400 | `name` ou `capabilities` está ausente em uma requisição de criação |
| `17007` | `Invalid Credential Name` | 400 | `name` carrega um caractere que não é letra, número ou hífen |
| `17008` | `Not Allowed Capabilities` | 400 | `capabilities` carrega um valor fora dos seis. `meta.allowed_capabilities` os lista |
| `17009` | `Expiration Before Creation` | 400 | `expiration_date` está no passado |

O `detail` da entrada `17007` diz `Names are limited to 100 alphanumeric characters and can contain hyphen, numbers and letters.`

O endpoint S3 responde no formato de erro do protocolo S3, com estes status e códigos:

| Status | Código | Causa |
| --- | --- | --- |
| `401` | `UnauthorizedAccess` | A requisição não carrega assinatura |
| `403` | `AccessDenied` | A credencial não tem a capability ou o bucket, ou o endpoint recusa a operação |
| `403` | `InvalidAccessKeyId` | A credencial expirou ou foi excluída |
| `404` | `NoSuchKey` | A chave não existe, para uma credencial com as seis capabilities |
| `501` | `NotImplemented` | O endpoint não implementa a operação, ou um header que ela carrega |

Para uma chave que não existe, uma credencial com uma única capability recebe `403` no lugar de `404`, qualquer que seja a capability.
