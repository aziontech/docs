Você pode adicionar um registro MX a uma zona do [Edge DNS](/pt-br/documentacao/plataforma/edge-dns/) pelo Azion Console, pela Azion CLI ou pela Azion API. O registro abaixo nomeia dois servidores de e-mail para `example.com`, cada um com uma prioridade, para que os e-mails enviados a endereços do domínio cheguem a eles. Para adicionar outro tipo de registro, consulte [Adicione, edite ou exclua um registro](/pt-br/documentacao/guias/seguranca-de-aplicacoes/dns/adicionar-registros/).

## Adicione o registro MX

Um registro MX guarda todos os servidores de e-mail de um nome, um valor por servidor, até 10 valores. Cada valor é uma prioridade, um espaço e o hostname do servidor de e-mail. O registro fica em `@`, o apex da zona, para receber e-mails de endereços como `user@example.com`. Para as regras do valor, consulte [MX](/pt-br/documentacao/plataforma/edge-dns/tipos-de-registro/#mx).

<Tabs client:visible sharedStore="interface">

<Fragment slot="panel.console">

Para adicionar o registro no Azion Console:

<DocSteps>
  <DocStep title="Abra a página do Edge DNS">

  Acesse [Azion Console](https://console.azion.com/) > **Edge DNS**.

  </DocStep>
  <DocStep title="Abra a aba Records da zona">

  Na página **Zones**, selecione a linha da zona e, depois, a aba **Records**.

  </DocStep>
  <DocStep title="Selecione + Record">

  O drawer **Create Record** se abre.

  </DocStep>
  <DocStep title="Informe o nome do registro">

  Em **Name**, informe `@`. O Console adiciona o domínio para você, então o registro responde por `example.com`.

  </DocStep>
  <DocStep title="Selecione o tipo de registro MX">

  Em **Record Type**, selecione *MX - Mail exchange*.

  </DocStep>
  <DocStep title="Mantenha o TTL">

  Mantenha **TTL (seconds)** em `3600`.

  </DocStep>
  <DocStep title="Informe um servidor de e-mail por linha">

  Em **Value**, informe `10 mail.example.com` na primeira linha e `20 mail2.example.com` na segunda.

  </DocStep>
  <DocStep title="Selecione Save" />
</DocSteps>

O Console mostra `Edge DNS Record has been created`, e o registro aparece na tabela **Records** com os dois valores.

</Fragment>

<Fragment slot="panel.cli">

Para adicionar o registro pela Azion CLI, repita `--rdata` uma vez por servidor de e-mail. Substitua `<zone-id>` pelo ID da sua zona:

```bash
azion create dns-record --zone-id <zone-id> --name @ --type MX \
  --rdata "10 mail.example.com" --rdata "20 mail2.example.com" --ttl 3600
```

O comando exibe o ID do registro:

```text
Created DNS record with ID 100775
```

Para ler o registro, liste os registros da zona:

```bash
azion list dns-record --zone-id <zone-id>
```

O registro MX mostra os dois valores em uma linha, separados por vírgula:

```text
ID      NAME  TYPE  TTL   RDATA
…
100775  @     MX    3600  10 mail.example.com, 20 mail2.example.com
…
```

A zona guarda um registro MX em `@` com dois servidores de e-mail.

</Fragment>

<Fragment slot="panel.api">

Para adicionar o registro pela Azion API, envie uma requisição `POST` ao endpoint de registros da zona. Substitua `<zone-id>` pelo `id` da sua zona:

```bash
curl -X POST https://api.azion.com/v4/workspace/dns/zones/<zone-id>/records \
  -H "Authorization: Token [TOKEN VALUE]" \
  -H "Content-Type: application/json" \
  -d '{"name":"@","type":"MX","rdata":["10 mail.example.com","20 mail2.example.com"],"ttl":3600}'
```

Um `201` retorna o registro, com um item em `rdata` por servidor de e-mail:

```json
{
  "state": "executed",
  "data": {
    "id": 100178,
    "description": "",
    "name": "@",
    "ttl": 3600,
    "type": "MX",
    "rdata": ["10 mail.example.com", "20 mail2.example.com"],
    "policy": "simple",
    "weight": 255
  }
}
```

A zona guarda um registro MX em `@` com dois servidores de e-mail.

</Fragment>

</Tabs>

Um segundo registro MX no mesmo nome é recusado com `19004` `Record Already Exists`. Para adicionar um servidor de e-mail depois, edite o registro existente e adicione um valor.

## Confira a resposta

Consulte o registro MX do domínio diretamente no nameserver da Azion, sem o cache do seu resolver. Substitua `example.com` pelo seu domínio:

```bash
dig +short @ns1.aziondns.net example.com MX
```

O nameserver retorna uma linha por valor, com a prioridade primeiro:

```text
10 mail.example.com.
20 mail2.example.com.
```

:::caution[Atenção]
Consulte o nome apenas depois de salvar o registro. Um nome consultado antes de o registro existir recebe a resposta `NXDOMAIN` por até uma hora, o mínimo do SOA.
:::

Se o comando não exibir nada, consulte [Um registro novo retorna NXDOMAIN](/pt-br/documentacao/plataforma/edge-dns/solucao-de-problemas/#um-registro-novo-retorna-nxdomain). Uma alteração em um registro MX existente pode levar alguns minutos para chegar a todos os nameservers. Para entender os motivos, consulte [Cache e propagação](/pt-br/documentacao/plataforma/edge-dns/como-funciona/#cache-e-propagacao).
