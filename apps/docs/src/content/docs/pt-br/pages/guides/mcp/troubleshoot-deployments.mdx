Você pode depurar um deploy que falha com o erro 503 pedindo um fluxo de trabalho a um agente de código conectado aos [MCP servers da Azion](/pt-br/documentacao/devtools/mcp/) e, em seguida, verificando cada ponto que ele levanta. O mesmo agente propõe formas de melhorar as pontuações de Core Web Vitals de um site. O servidor de docs apenas lê a documentação. O servidor de build pode aplicar uma correção na sua conta, e cada ferramenta de escrita dele mostra a requisição sem executá-la quando o agente define `dry_run`. Para problemas com os próprios MCP servers, consulte [Solucionar problemas do MCP server](/pt-br/documentacao/devtools/mcp/solucao-de-problemas/).

---

## Pré-requisitos

- Uma aplicação com deploy na Azion que retorna o erro 503, e a URL dela.
- Um agente de código conectado ao servidor de docs, `https://docs-mcp.azion.com/mcp`. Para escrever a query GraphQL, conecte também o servidor de observe, `https://observe-mcp.azion.com/mcp`. Para conectar um servidor, consulte [Primeiros passos com o MCP server](/pt-br/documentacao/devtools/mcp/configuracao/).
- A Azion CLI instalada, com login. Para instalar a CLI e fazer login, consulte [Primeiros passos com a Azion CLI](/pt-br/documentacao/devtools/cli/primeiros-passos/).
- `curl` na sua máquina.

## Depure um erro 503 com o seu agente

O agente busca o erro na documentação da Azion e retorna um fluxo de depuração de cinco verificações. Você executa cada verificação, em ordem, e informa ao agente o que encontrar. Para depurar o deploy:

<DocSteps>
  <DocStep title="Pergunte ao seu agente sobre o erro">

  Envie ao agente um prompt que nomeie o erro, como:

  ```text
  Meu deploy está falhando com erro 503. Como posso debugar?
  ```

  O prompt chega à ferramenta `search_azion_docs_and_site`, que retorna a documentação da Azion sobre depuração.

  </DocStep>
  <DocStep title="Verifique os logs do deploy">

  Leia os logs de eventos HTTP das suas aplicações com a Azion CLI:

  ```bash
  azion logs http --tail
  ```

  O comando imprime os logs dos últimos 5 minutos e continua em execução, uma entrada por requisição com o status dela. Procure as entradas com status `503`. `--limit` define quantas entradas o comando mostra, e `--pretty` imprime cada campo em uma linha própria. Para os logs de console de uma function, execute `azion logs cells`. Para todas as flags, consulte [Azion CLI logs](/pt-br/documentacao/devtools/cli/logs/).

  </DocStep>
  <DocStep title="Verifique a configuração do connector">

  A Azion chega à sua origem por meio de um connector. O agente busca a documentação de solução de problemas de connectors e entrega uma lista de verificação dos problemas comuns de connectors. Para os sintomas e as correções, consulte [Solucionar problemas de Connectors](/pt-br/documentacao/plataforma/connectors/solucao-de-problemas/).

  </DocStep>
  <DocStep title="Teste a conectividade da origem">

  Solicite os headers da sua origem diretamente, substituindo o host pelo seu:

  ```bash
  curl -I https://<your-origin-host>
  ```

  O comando imprime a linha de status e os headers que a origem retorna.

  </DocStep>
  <DocStep title="Revise o Rules Engine">

  Com o agente, verifique as regras da sua aplicação em busca de loops de redirecionamento e valide as configurações de cache que as regras aplicam. Para os critérios e behaviors que uma regra recebe, consulte [Rules Engine para Applications](/pt-br/documentacao/plataforma/applications/rules-engine/).

  </DocStep>
  <DocStep title="Monitore o Real-Time Metrics">

  Peça ao agente uma query GraphQL que analise os erros da sua aplicação no [Real-Time Metrics](/pt-br/documentacao/plataforma/real-time-metrics/). Para saber como o servidor de observe escreve e valida uma query, consulte [Gere queries GraphQL com o MCP server](/pt-br/documentacao/guias/plataforma/observabilidade/gerar-queries-graphql-com-mcp/).

  </DocStep>
</DocSteps>

Você termina com as entradas de log das requisições que falham, os resultados das verificações do connector e da origem, e as regras a corrigir. Aplique cada alteração na sua aplicação, ou peça a um agente conectado ao servidor de build que a aplique, com uma prévia `dry_run` antes.

## Otimize os Core Web Vitals com o seu agente

Um pedido para melhorar as pontuações de Core Web Vitals de um site retorna propostas em quatro áreas. Para pedi-las, envie ao agente um prompt como:

```text
Otimize as pontuações de Core Web Vitals do meu site
```

O agente fornece:

- Estratégias de otimização de imagens.
- Recomendações de configuração de cache.
- Regras do Rules Engine para resource hints.
- Queries GraphQL para monitorar as melhorias.

Você aplica as regras e as alterações de cache na sua aplicação, ou pede a um agente conectado ao servidor de build que as crie, e executa as queries com a GraphQL API. Para criar uma regra pelo servidor de build, consulte [Crie regras do Rules Engine com o MCP server](/pt-br/documentacao/guias/desenvolvimento-de-aplicacoes/primeiros-passos/gerar-regras-do-rules-engine-com-mcp/).
