Você pode apontar um subdomínio para outro host com um registro CNAME no [Edge DNS](/pt-br/documentacao/plataforma/edge-dns/) pelo Azion Console, pela Azion CLI ou pela Azion API. O registro abaixo torna `blog.example.com` um alias de `www.example.com`, então uma consulta por `blog` recebe o endereço de `www`. Um CNAME não pode ter o nome `@`: para apontar o domínio raiz, consulte [Aponte um domínio raiz com ANAME](/pt-br/documentacao/guias/seguranca-de-aplicacoes/dns/acessar-root-domain/).

## Pré-requisitos

- Uma zona para o seu domínio no Edge DNS. Para criar uma, consulte [Crie, edite ou exclua uma zona](/pt-br/documentacao/guias/seguranca-de-aplicacoes/dns/edge-dns-definir-main-settings/).
- O hostname para o qual o alias aponta. Este exemplo usa `www.example.com`, um registro A em `www` na mesma zona, que responde `192.0.2.1`.
- A permissão **Edit Edge DNS**. Ela requer **View Edge DNS**. Consulte [Permissões de equipes](/pt-br/documentacao/fundamentos/teams-permissions/).

## Adicione o registro CNAME

O nome do registro é relativo à zona: você informa `blog`, e o Edge DNS o serve como `blog.example.com`. O valor é o único hostname para o qual o alias aponta. Substitua `example.com` pelo seu domínio em todas as etapas.

<Tabs client:visible sharedStore="interface">

<Fragment slot="panel.console">

Para adicionar o registro CNAME pelo Azion Console:

<DocSteps>
  <DocStep title="Abra a página do Edge DNS">

  Acesse [Azion Console](https://console.azion.com/) > **Edge DNS**.

  </DocStep>
  <DocStep title="Abra a zona">

  Na página **Zones**, selecione a linha da zona.

  </DocStep>
  <DocStep title="Selecione a aba Records" />
  <DocStep title="Selecione + Record">

  O drawer **Create Record** é aberto.

  </DocStep>
  <DocStep title="Informe o subdomínio">

  Em **Name**, informe `blog`. O Console mostra o seu domínio depois do campo e o adiciona para você.

  </DocStep>
  <DocStep title="Selecione o tipo CNAME">

  Em **Record Type**, selecione *CNAME - Canonical name*.

  </DocStep>
  <DocStep title="Mantenha o TTL">

  Mantenha **TTL (seconds)** em `3600`.

  </DocStep>
  <DocStep title="Informe o hostname de destino">

  Em **Value**, informe `www.example.com`.

  </DocStep>
  <DocStep title="Selecione Save" />
</DocSteps>

O Console mostra `Edge DNS Record has been created`, e `blog` aparece na tabela **Records**.

</Fragment>

<Fragment slot="panel.cli">

Para adicionar o registro CNAME pela Azion CLI, substitua `<zone-id>` pelo ID da sua zona e execute:

```bash
azion create dns-record --zone-id <zone-id> --name blog --type CNAME --rdata www.example.com --ttl 3600
```

O comando mostra o ID do registro:

```text
Created DNS record with ID 100774
```

A zona contém o alias. Passe apenas `blog` em `--name`: um nome digitado com o domínio é servido com o domínio duas vezes.

</Fragment>

<Fragment slot="panel.api">

Para adicionar o registro CNAME pela Azion API, envie uma requisição `POST` ao endpoint de registros da zona. Substitua `<zone-id>` pelo `id` da sua zona e `[TOKEN VALUE]` pelo seu personal token:

```bash
curl -X POST https://api.azion.com/v4/workspace/dns/zones/<zone-id>/records \
  -H "Authorization: Token [TOKEN VALUE]" \
  -H "Content-Type: application/json" \
  -d '{"name":"blog","type":"CNAME","rdata":["www.example.com"],"ttl":3600}'
```

Um `201` retorna o registro:

```json
{
  "state": "executed",
  "data": {
    "id": 100177,
    "description": "",
    "name": "blog",
    "ttl": 3600,
    "type": "CNAME",
    "rdata": ["www.example.com"],
    "policy": "simple",
    "weight": 255
  }
}
```

A zona contém o alias. `rdata` carrega o único hostname de destino, e `policy` e `weight` mantêm os seus valores padrão.

</Fragment>

</Tabs>

Depois que `blog` contém o CNAME, ele não contém nenhum outro tipo de registro: o Edge DNS recusa um registro MX ou CAA em `blog` com `19018`. Para todas as regras de CNAME e os seus erros, consulte [Tipos de registro](/pt-br/documentacao/plataforma/edge-dns/tipos-de-registro/#cname).

## Confira a resposta

Consulte o nameserver da Azion diretamente, sem o cache do seu resolver. Esta verificação funciona antes de você delegar o domínio à Azion.

:::caution[Atenção]
Consulte `blog` apenas depois de salvar o registro. Um nome consultado antes de o seu registro existir é respondido com `NXDOMAIN` por até uma hora, o mínimo do SOA.
:::

Para consultar o alias em `ns1.aziondns.net`, substitua `example.com` pelo seu domínio:

```bash
dig +short @ns1.aziondns.net blog.example.com A
```

O nameserver retorna o hostname de destino e, depois, o endereço do destino:

```text
www.example.com.
192.0.2.1
```

O destino está na mesma zona, então o Edge DNS responde o CNAME e o registro A de `www` em uma única resposta. Um nome que ninguém consultou antes de você salvá-lo responde em segundos. Uma alteração posterior no registro pode levar alguns minutos para chegar a todos os nameservers. Para saber como as respostas ficam em cache, consulte [Como o Edge DNS funciona](/pt-br/documentacao/plataforma/edge-dns/como-funciona/#cache-e-propagacao).

Se o comando não mostrar nada, consulte [Um registro novo retorna NXDOMAIN](/pt-br/documentacao/plataforma/edge-dns/solucao-de-problemas/#um-registro-novo-retorna-nxdomain).
