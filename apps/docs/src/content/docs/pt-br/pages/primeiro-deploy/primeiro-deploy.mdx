## Antes de começar

Tudo o que você precisa é de uma [conta Azion](https://console.azion.com/signup). Você pode criar uma gratuitamente no plano Hobby. O que for específico de um caminho está listado no próprio caminho.

## Faça o deploy de um template pelo Console

Templates são projetos prontos (e-commerce, blogs, APIs, SSR full-stack) que entram no ar em poucos cliques. Você não precisa de nenhuma ferramenta local.

<DocCallout kind="note">Templates com integrações ou configurações específicas podem pedir mais informações, como contas ou tokens em outros serviços. Templates integrados ao GitHub, como o Astro Boilerplate, pedem para conectar sua conta: selecione Connect with GitHub quando solicitado e confirme a conexão na janela que se abre. O guia de cada template lista o que ele precisa.</DocCallout>

<DocSteps>
  <DocStep title="Acesse o Azion Console." />
  <DocStep title="Clique em + Create na página inicial." />
  <DocStep title="No modal, selecione Templates." />
  <DocStep title="Selecione o template Astro Boilerplate, ou navegue e escolha outro." />
  <DocStep title="Preencha a página de configuração." />
  <DocStep title="Clique em Deploy, no canto inferior direito." />
</DocSteps>

Acompanhe o deploy pela janela de logs. Quando terminar, a página mostra o nome da sua aplicação, os logs do deploy e o domínio Azion dela. Alguns templates também criam uma função e aplicam configurações predefinidas para otimizar o desempenho da aplicação. O guia do template lista o que está incluído.

### Confira a aplicação

Copie o domínio Azion da página de confirmação:

```bash
curl -I https://<your-azion-domain>
# HTTP/2 200
```

Abra a mesma URL no navegador para ver sua aplicação rodando.

<DocCallout kind="note">URLs novas podem levar alguns minutos para se propagar até os data centers da Azion. Se você receber um erro logo após o deploy, aguarde um momento e tente de novo.</DocCallout>

## Importe um projeto do GitHub

<DocCallout kind="warning">Você precisa de uma conta no GitHub e de um repositório construído com um framework que a lista **Preset** traz: Next.js, Angular, Astro, Hexo, React ou Vue. Antes de começar, confira o seu framework e a versão dele em [Compatibilidade de frameworks](/pt-br/documentacao/devtools/runtime/frameworks/compatibilidade-frameworks/): um framework ou uma versão que a Azion não suporta pode falhar no build.</DocCallout>

<DocSteps>
  <DocStep title="No Azion Console, clique em + Create." />
  <DocStep title="Selecione Import from Git." />
  <DocStep title="Conecte a conta Git que possui o repositório." />
  <DocStep title="Escolha o repositório a importar." />
  <DocStep title="Dê um nome à aplicação.">

  O Console preenche **Application Name** com o nome do repositório. O nome precisa ser único na sua conta, e o bucket de storage e a função do projeto recebem o mesmo nome.

  </DocStep>
  <DocStep title="Em Preset, selecione o framework do repositório.">

  O preset define as configurações iniciais para esse framework.

  </DocStep>
  <DocStep title="Em Root Directory, mantenha o valor padrão.">

  O valor padrão, `/`, vale quando o código do projeto está na raiz do repositório.

  </DocStep>
  <DocStep title="Em Install Command, informe o comando que instala o projeto.">

  Por exemplo, `npm install`.

  </DocStep>
  <DocStep title="Selecione Deploy.">

  O painel **Deploy Log** mostra o build até o domínio Azion aparecer.

  </DocStep>
</DocSteps>

Se o deploy falhar, a página mostra **Creation failed**, e o painel **Deploy Log** traz os detalhes da falha. Para todos os campos da importação, consulte [Importe um projeto do GitHub](/pt-br/documentacao/guias/desenvolvimento-de-aplicacoes/automacao/importar-um-projeto-existente-do-github/).

### Confira a aplicação

```bash
curl -I https://<your-azion-domain>
# HTTP/2 200
```

Abra o domínio Azion no navegador para ver sua aplicação rodando. Se você receber um erro de imediato, aguarde alguns minutos: URLs novas levam um momento para se propagar até os data centers da Azion.

## Faça o deploy com a Azion CLI

<DocCallout kind="warning">Você precisa de um projeto local que use um framework suportado, com as dependências instaladas, ou cria um a partir de um template no passo 3. Antes de começar, confira o seu framework e a versão dele em [Compatibilidade de frameworks](/pt-br/documentacao/devtools/runtime/frameworks/compatibilidade-frameworks/): um framework ou uma versão que a Azion não suporta pode falhar no build.</DocCallout>

<DocPrompt client:visible kind="line" title="Assistente de IA">Siga a seção "Faça o deploy com a Azion CLI" de https://www.azion.com/pt-br/documentacao/fundamentos/primeiro-deploy.md para fazer o deploy deste projeto e imprima o domínio Azion quando ele responder 200. `azion login` e `azion init` precisam de terminal interativo: quando chegar neles, pare e me peça para rodá-los. Nos demais comandos, use flags em vez de perguntas.</DocPrompt>

<DocSteps>
  <DocStep title="Configure a Azion CLI">

  ```bash
  curl -fsSL https://cli.azion.app/install.sh | bash
  ```

  </DocStep>
  <DocStep title="Faça login">

  ```bash
  azion login
  ```

  A CLI salva um personal token localmente, que autoriza os comandos seguintes.

  Em um script ou em um job de CI, `azion login` não consegue fazer as perguntas dele. Passe o token com a opção global [`--token`](/pt-br/documentacao/devtools/cli/globals/). Para um comando que para em uma pergunta, consulte [Solucionar problemas da Azion CLI](/pt-br/documentacao/devtools/cli/solucao-de-problemas/#um-comando-para-com-eof-ou-failed-to-parse-your-response).

  </DocStep>
  <DocStep title="Inicialize ou vincule o projeto">

  Para começar de um template, execute o comando onde quer que a pasta do projeto seja criada. Ele pergunta um preset, que é o framework, depois um template, e cria uma pasta com o nome do projeto; aceite instalar as dependências:

  ```bash
  azion init
  ```

  Para usar um projeto que você já tem, execute o comando na pasta raiz dele. Ele pede para confirmar o vínculo, aceitar ou alterar o nome sugerido para a aplicação e escolher o preset que corresponde ao seu framework; a entrada no `.gitignore` e o workflow do GitHub Actions que ele oferece são opcionais:

  ```bash
  azion link
  ```

  Quando qualquer um dos comandos perguntar se deve fazer o deploy, responda não: o próximo passo faz isso.

  </DocStep>
  <DocStep title="Faça o deploy">

  ```bash
  azion deploy
  ```

  A CLI faz o build do projeto, envia os arquivos, cria a aplicação com o domínio dela e imprime o domínio ao final.

  </DocStep>
  <DocStep title="Confira a aplicação">

  ```bash
  curl -I https://<your-azion-domain>
  # HTTP/2 200
  ```

  Se você receber um erro de imediato, aguarde alguns minutos: URLs novas levam um momento para se propagar até os data centers da Azion.

  </DocStep>
</DocSteps>

## O que você construiu

Você publicou uma aplicação na rede global da Azion e confirmou que ela responde no próprio domínio. O fluxo é o mesmo que você vai usar em projetos de produção.
