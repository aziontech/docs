Uma aplicação reúne a lógica de entrega de conteúdo da Azion Platform: as suas [configurações de cache](/pt-br/documentacao/plataforma/applications/cache/cache-settings/), as regras do [Rules Engine](/pt-br/documentacao/plataforma/applications/rules-engine/) que processam cada requisição, os seus [device groups](/pt-br/documentacao/plataforma/applications/device-groups/) e as [instâncias de function](/pt-br/documentacao/plataforma/applications/functions-instances/) que ela executa. O Azion Terraform Provider gerencia [Applications](/pt-br/documentacao/plataforma/applications/) com seis recursos e lê aplicações com dez data sources. Para migrar uma configuração v1.x para esses recursos, consulte [Migre do provider v1.x para o v2.0](/pt-br/documentacao/devtools/terraform/migration-v3-to-v4/).

## Recursos de aplicação

| Recurso | Descrição |
| --- | --- |
| [`azion_application_main_setting`](https://registry.terraform.io/providers/aziontech/azion/latest/docs/resources/application_main_setting) | Cria e gerencia as configurações principais de uma aplicação. |
| [`azion_application_cache_setting`](https://registry.terraform.io/providers/aziontech/azion/latest/docs/resources/application_cache_setting) | Cria e gerencia uma configuração de cache. |
| [`azion_application_device_group`](https://registry.terraform.io/providers/aziontech/azion/latest/docs/resources/application_device_group) | Cria e gerencia um device group. |
| [`azion_application_rule_engine`](https://registry.terraform.io/providers/aziontech/azion/latest/docs/resources/application_rule_engine) | Cria e gerencia uma regra do Rules Engine. |
| [`azion_application_rule_engine_order`](https://registry.terraform.io/providers/aziontech/azion/latest/docs/resources/application_rule_engine_order) | Define a ordem das regras do Rules Engine de uma fase. |
| [`azion_application_function_instance`](https://registry.terraform.io/providers/aziontech/azion/latest/docs/resources/application_function_instance) | Cria e gerencia uma instância de function em uma aplicação. |

Cada recurso recebe as suas configurações em um único atributo aninhado:

| Recurso | Atributo aninhado | Campos obrigatórios |
| --- | --- | --- |
| `azion_application_main_setting` | `application` | `name`. O opcional `modules` ativa os módulos `cache`, `functions`, `application_accelerator` e `image_processor`. |
| `azion_application_cache_setting` | `cache_setting` | `name`. Os opcionais `browser_cache` e `modules` guardam a política de cache. |
| `azion_application_device_group` | `device_group` | `name` e `user_agent`, a expressão regular que identifica os dispositivos do grupo. |
| `azion_application_rule_engine` | `results` | `name`, `phase` (`request` ou `response`), `criteria` e `behaviors`. |
| `azion_application_function_instance` | `data` | `name` e `function_id`, o ID de uma function que o recurso `azion_function` gerencia. |

Depois do apply, `application.application_id` contém o ID numérico da aplicação. Uma configuração de cache, um device group, uma regra do Rules Engine e uma instância de function pertencem a uma aplicação, então cada um desses recursos recebe esse ID em `application_id`, fora do atributo aninhado. `azion_application_rule_engine_order` recebe `application_id`, a `phase` e `order`, a lista de IDs das regras na ordem em que elas são executadas. Um módulo que `modules` omite volta ao seu padrão a cada apply. A página de cada recurso no Terraform Registry lista todos os argumentos.

## Exemplo

Esta configuração fixa o provider na versão 2.10.0 e cria uma aplicação com os módulos de cache e functions ativos. Ela adiciona uma configuração de cache e uma regra do Rules Engine na fase `request` que ignora o cache para os caminhos sob `/api/`. Ela também cria uma function, instancia essa function na aplicação e retorna o ID da aplicação em um output. Ela lê o seu personal token da variável `api_token` que [Primeiros passos com o Azion Terraform Provider](/pt-br/documentacao/devtools/terraform/getting-started/) declara. Para saber mais sobre o recurso `azion_function`, consulte [Recursos e data sources](/pt-br/documentacao/devtools/terraform/examples/#functions).

```hcl
terraform {
  required_providers {
    azion = {
      source  = "aziontech/azion"
      version = "2.10.0"
    }
  }
}

provider "azion" {
  api_token = var.api_token
}

# Create main application
resource "azion_application_main_setting" "my_app" {
  application = {
    name   = "my-application"
    active = true

    modules = {
      cache = {
        enabled = true
      }
      functions = {
        enabled = true
      }
    }
  }
}

# Configure cache
resource "azion_application_cache_setting" "my_cache" {
  application_id = azion_application_main_setting.my_app.application.application_id

  cache_setting = {
    name = "static-cache"

    browser_cache = {
      behavior = "override"
      max_age  = 3600
    }

    modules = {
      cache = {
        behavior = "override"
        max_age  = 86400
      }
    }
  }
}

# Create rule in Rules Engine
resource "azion_application_rule_engine" "my_rule" {
  application_id = azion_application_main_setting.my_app.application.application_id

  results = {
    name   = "bypass-cache-api"
    phase  = "request"
    active = true

    criteria = [
      {
        entries = [
          {
            criterion = {
              variable    = "$${uri}"
              operator    = "starts_with"
              conditional = "if"
              argument    = "/api/"
            }
          }
        ]
      }
    ]

    behaviors = [
      {
        behavior = {
          type = "bypass_cache"
        }
      }
    ]
  }
}

# Create a function
resource "azion_function" "my_function" {
  function = {
    name                  = "my-function"
    active                = true
    runtime               = "azion_js"
    execution_environment = "application"
    default_args          = jsonencode({})
    code                  = <<-EOT
      addEventListener("fetch", (event) => {
        event.respondWith(new Response("Hello from Azion"));
      });
    EOT
  }
}

# Instantiate the function in the application
resource "azion_application_function_instance" "my_function" {
  application_id = azion_application_main_setting.my_app.application.application_id

  data = {
    name        = "my-function-instance"
    function_id = azion_function.my_function.function.id
    active      = true
  }
}

output "application_id" {
  value = azion_application_main_setting.my_app.application.application_id
}
```

O critério escreve a variável `${uri}` como `$${uri}`. Com um único `$`, o Terraform lê a variável como uma interpolação e falha.
