O comando `deploy` da Azion CLI faz o build do projeto no diretório atual e o deploy dele na Azion. Ele cria ou atualiza a [Application](/pt-br/documentacao/plataforma/applications/) do projeto, o [Workload](/pt-br/documentacao/plataforma/workloads/) dele e, para um site estático, o bucket do [Object Storage](/pt-br/documentacao/plataforma/object-storage/) que guarda os arquivos. Por padrão, o build é executado na Azion; com `--local`, ele é executado na sua máquina. As opções que todo comando aceita, como `--format`, `--out` e `-y`, estão em [Opções globais](/pt-br/documentacao/devtools/cli/globals/).

---

## Uso

`azion deploy` lê as configurações do projeto na pasta `azion` do diretório atual e faz o deploy do projeto:

```bash
azion deploy [flags]
```

| Flag | Curta | Tipo | Padrão | Descrição |
| --- | --- | --- | --- | --- |
| `--auto` | — | — | — | Executa o comando inteiro sem parar para uma pergunta. |
| `--config-dir` | — | string | `"azion"` | Caminho relativo para a pasta que guarda os seus arquivos `azion.json` e `args.json`. |
| `--dry-run` | — | — | — | Simula o deploy sem alterar nenhum recurso. |
| `--env` | — | string | `".edge/.env"` | Caminho relativo para o seu arquivo `.env`. |
| `--local` | — | — | — | Executa o build e o deploy na sua máquina em vez de na Azion. Use-a quando você precisa do seu próprio ambiente de build ou de mais controle sobre o build. |
| `--no-prompt` | — | — | — | Retorna o erro em vez de fazer uma pergunta quando uma etapa falha. |
| `--path` | — | string | — | Caminho para a pasta que guarda os seus arquivos estáticos. |
| `--skip-build` | — | — | — | Faz o deploy sem executar o build antes. |
| `--skip-framework-build` | — | — | — | Pula o build do framework que é executado antes de `azion build`. |
| `--sync` | — | — | — | Sincroniza o arquivo `azion.json` local com os recursos remotos. |
| `--workers` | — | int | auto-calculated based on CPU cores, max `20` | Número de workers de upload que enviam arquivos ao mesmo tempo. |
| `--writable-bucket` | — | — | — | Cria o bucket do projeto com acesso de leitura e gravação. |

Para um site estático, a CLI gerencia as credenciais de storage que usa para enviar os arquivos e as guarda em `~/.azion/<profile>/credentials.toml`. O deploy as lê desse arquivo, então o upload não precisa de nenhuma credencial sua.

## Exemplos

Cada exemplo mostra o comando e a saída que ele imprime.

### Fazer o deploy com um build remoto

Este comando faz o primeiro deploy de um site estático. A CLI envia os arquivos de código-fonte, e o build é executado na Azion:

```bash
azion deploy
```

O comando imprime um link para a página **Deploy** do Azion Console, onde **Deploy Log** mostra o progresso do deploy, e depois o domínio do site:

```text

Please visit https://console.azion.com/create/deploy/9241bdbc-fe9f-4fbb-803a-0ca3b15911d3 in case it did not open automatically, to follow up the full deploy process

To visualize your application access the Domain: https://mz0kbijeiw0.map.azionedge.net

```

O primeiro deploy pode levar vários minutos para responder a partir de todas as localidades; os deploys seguintes levam cerca de dois minutos.

### Fazer o deploy com um build local

Este comando faz o deploy de uma alteração no mesmo site. A CLI faz o build do projeto na sua máquina, envia os arquivos e atualiza cada recurso pelo ID em `azion/azion.json`:

```bash
azion deploy --local
```

O comando executa o build por conta própria, mesmo quando o projeto não tem uma pasta `.edge` de um `azion build` anterior. Antes do build, ele grava um novo prefixo de storage em `azion.config.cjs`, ou em `azion.config.mjs` quando o projeto tem os dois arquivos:

### Pré-visualizar um deploy

Este comando simula um deploy local do mesmo site:

```bash
azion deploy --local --dry-run
```

O comando termina sem alterar nenhum recurso, e `azion/azion.json` mantém o mesmo conteúdo.
