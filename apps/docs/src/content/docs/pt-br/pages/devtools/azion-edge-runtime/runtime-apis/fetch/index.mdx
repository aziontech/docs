A função `fetch()` envia uma requisição HTTP a partir do seu código no Azion Runtime e retorna uma promise que resolve em um [Response](/pt-br/documentacao/devtools/runtime/api-reference/response/). Você lê essa resposta, a altera ou a devolve ao cliente por meio de `event.respondWith()` ou do valor de retorno do seu handler. `fetch()` faz parte da [Fetch API](https://developer.mozilla.org/en-US/docs/Web/API/Fetch_API), que também define os objetos [`Request`](https://developer.mozilla.org/en-US/docs/Web/API/Request) e [`Response`](https://developer.mozilla.org/en-US/docs/Web/API/Response), o CORS e a semântica do cabeçalho HTTP `Origin`. Com esses objetos, seu código trata, modifica ou constrói requisições e respostas enquanto responde a uma requisição.

Use `fetch()` para encaminhar uma requisição a um servidor de origem e retornar a resposta dele, ou para chamar uma API REST ou GraphQL que fornece parte de uma resposta. Você também pode combinar dados de vários backends em uma única function, ou buscar assets ou configurações remotas e reescrevê-los antes da entrega.

:::note[nota]
Com `azion dev`, uma resposta de `fetch()` informa `type` como `default`, e `redirected` continua `false` depois de um redirecionamento seguido. Um redirecionamento com `redirect: 'error'` rejeita com `TypeError: fetch failed`, e um timeout expirado rejeita com a mensagem `The operation was aborted due to timeout`.
:::

## Sintaxe

```javascript
fetch(request, init)
```

### Parâmetros

| Parâmetro | Tipo | Descrição |
| --- | --- | --- |
| `request` | `Request` ou string | Requisição a enviar: um objeto `Request` ou uma string com a URL a buscar. |
| `init` | Object (`RequestInit`) | Opções da requisição. |

O objeto `init` aceita estas opções. `method`, `headers`, `body` e `redirect` são os campos que o objeto [Request](/pt-br/documentacao/devtools/runtime/api-reference/request/#propriedades) documenta, e `signal` cancela a requisição:

| Opção | Tipo | Descrição |
| --- | --- | --- |
| `method` | String | Método da requisição, como `POST`. |
| `headers` | Objeto `Headers` | Cabeçalhos da requisição. |
| `body` | — | Payload da requisição, como uma string JSON. |
| `redirect` | String | Modo de redirecionamento: `follow`, `error` ou `manual`. Com `follow`, o padrão, `fetch()` segue o redirecionamento e resolve na resposta final. Com `manual`, ela resolve na resposta de redirecionamento, como um `301` com o cabeçalho `location`. Com `error`, a promise é rejeitada. |
| `signal` | `AbortSignal` | Sinal que cancela a requisição, como `AbortSignal.timeout(300)` para parar de esperar após 300 ms. |

## Limites

Em uma function após o deploy, Azion Runtime limita quanto tempo uma chamada `fetch()` espera em três pontos:

- 20 segundos para se conectar ao servidor.
- 60 segundos para receber os cabeçalhos da resposta.
- 60 segundos entre dois chunks de um corpo enviado sem o cabeçalho `Content-Length`.

Cada limite vale para uma chamada, então o próximo `fetch()` na mesma invocação recebe o tempo inteiro de novo. O limite de 20 segundos cobre só a conexão, e a leitura do corpo fica sob o limite de 60 segundos entre dois chunks. Esse limite conta o tempo entre dois chunks, não a transferência inteira, então um corpo cujos chunks chegam com menos de 60 segundos de intervalo pode levar mais tempo no total.

O teto de tempo de relógio da invocação continua valendo: 5 minutos, com a espera de I/O incluída. Uma invocação também pode fazer um número limitado de chamadas `fetch()` de saída, e uma function processa um corpo até um tamanho máximo. Para esses valores, consulte [Limites de Functions](/pt-br/documentacao/plataforma/functions/limites/).

Para limitar uma chamada com mais rigor, passe `AbortSignal.timeout()` como `signal` em `init`. O sinal é um prazo para a chamada inteira, com o corpo incluído, então ele também interrompe um corpo cujos chunks ainda chegam. Um sinal com um timeout mais longo não estende nenhum dos três limites.

Quando o sinal expira, a chamada `fetch()` pendente é rejeitada com um erro cujo `name` é `TimeoutError`, que seu código captura. Um `read()` pendente de um [ReadableStreamDefaultReader](/pt-br/documentacao/devtools/runtime/api-reference/readable-default-reader/), ou um `text()` pendente do `Response`, é rejeitado com o mesmo erro.

## Erros

Em uma function após o deploy, `fetch()` e as leituras do corpo da resposta são rejeitados com estes erros:

| Erro | Causa | O que fazer |
| --- | --- | --- |
| `TimeoutError: Signal timed out.` | O `AbortSignal.timeout()` passado como `signal` expirou antes de a resposta chegar, ou enquanto seu código lia o corpo. O erro é uma `DOMException` cujo `name` é `TimeoutError`. | Capture a rejeição e verifique `error.name`, ou passe um timeout maior. |
| `TypeError: Fetch failed: Encountered redirect while redirect mode is set to 'error'` | O servidor respondeu com um redirecionamento, e `redirect` é `error`. | Defina `redirect` como `follow` ou `manual`, ou capture a rejeição. |

## Exemplos

Os dois exemplos são handlers `fetch` completos. O primeiro retorna a resposta de outro servidor e o segundo interrompe uma chamada que não termina em até 5 segundos.

### Retornar a resposta de outro servidor

Este handler `fetch` responde a cada requisição com a resposta que `fetch()` recebe de `https://example.com`:

```javascript
export default {
  async fetch(request, env, ctx) {
    return fetch("https://example.com")
  }
}
```

O handler retorna uma resposta com este status, este tipo de conteúdo e este corpo. Os outros cabeçalhos da resposta foram cortados, e o corpo foi cortado depois do título:

```json
{
 "status": 200,
 "statusText": "OK",
 "headers": {
  …
  "content-type": "text/html; charset=utf-8",
  …
 },
 "body": "<!doctype html><html lang=en><head><meta charset=utf-8><link rel=icon href=data:,><meta name=viewport content=\"width=device-width,initial-scale=1\"><title>Example Domain</title>…"
}
```

### Parar de ler um corpo lento em streaming

Este handler `fetch` dá 5 segundos à chamada inteira, com os cabeçalhos e o corpo, para ler um corpo que um servidor envia em streaming. Como o sinal cobre as duas fases, o handler captura o `TimeoutError` em qualquer uma delas. Quando o servidor responde com um status fora da faixa 200–299, como `404` ou `503`, o handler responde com `502` e não lê o corpo:

```javascript
const TIMEOUT_MS = 5000

export default {
  async fetch(request, env, ctx) {
    let received = 0
    try {
      const response = await fetch("https://<your-streaming-origin>/", {
        signal: AbortSignal.timeout(TIMEOUT_MS)
      })
      if (!response.ok) {
        return new Response(`The server answered with status ${response.status}`, { status: 502 })
      }
      if (!response.body) {
        return new Response("Body complete. Bytes received: 0")
      }
      const reader = response.body.getReader()
      while (true) {
        const { done, value } = await reader.read()
        if (done) break
        received += value.byteLength
      }
      return new Response(`Body complete. Bytes received: ${received}`)
    } catch (error) {
      if (error.name === "TimeoutError") {
        return new Response(`Timed out after ${TIMEOUT_MS / 1000} seconds. Bytes received: ${received}`, { status: 504 })
      }
      throw error
    }
  }
}
```

Substitua `<your-streaming-origin>` pelo host de um servidor que envia o corpo da resposta em streaming. `TIMEOUT_MS` define o prazo em milissegundos, e a mensagem o informa em segundos.

Quando o sinal expira antes de o corpo terminar, o handler responde com o status `504` e o número de bytes que leu até então, como `Timed out after 5 seconds. Bytes received: 2`. Quando a chamada inteira termina em até 5 segundos, o handler responde com o status `200` e `Body complete. Bytes received:` seguido do total. Uma resposta sem corpo, como um `204`, dá o total `0`.
