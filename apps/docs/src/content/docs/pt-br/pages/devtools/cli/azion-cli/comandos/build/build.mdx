O comando `build` da Azion CLI faz o build do projeto no diretório atual na sua máquina e grava o resultado na pasta `.edge`. Ele executa o Azion Bundler com o preset do projeto e gera `.edge/manifest.json`, o arquivo que um deploy local lê. O comando não faz o deploy de nada. As opções que todo comando aceita, como `--format`, `--out` e `-y`, estão em [Opções globais](/pt-br/documentacao/devtools/cli/globals/).

---

## Uso

`azion build` lê as configurações do projeto na pasta `azion` do diretório atual. Execute-o na pasta raiz do projeto:

```bash
azion build [flags]
```

| Flag | Curta | Tipo | Padrão | Descrição |
| --- | --- | --- | --- | --- |
| `--config-dir` | — | string | `"azion"` | Caminho relativo para a pasta que guarda os seus arquivos `azion.json` e `args.json`. |
| `--entry` | — | string | `./main.js` | Ponto de entrada do código do build. |
| `--preset` | — | string | — | Preset com que o build do projeto é feito, quando você quer um preset diferente do preset do próprio projeto. Os nomes de preset são os que `azion list presets` imprime. Para mais informações, consulte [Azion CLI presets](/pt-br/documentacao/devtools/cli/recursos/presets/). |
| `--skip-framework-build` | — | — | — | Pula o build do framework que é executado antes do build da Azion. Use-a quando você já fez o build do framework. |
| `--use-node-polyfills` | — | string | — | Adiciona polyfills do Node.js ao build, para que o código que chama APIs específicas do Node.js continue compatível. |
| `--use-own-worker` | — | string | — | Informa ao build que o seu código declara a própria expressão de worker, como `addEventListener("fetch")`, para que o build não injete um provider. Use-a quando o seu código já configura o worker. |

O build grava estes arquivos em `.edge`:

- `.edge/manifest.json`, o manifesto que `azion deploy --local` lê.
- `.edge/functions/handler.js` para um preset estático, ou `.edge/functions/index.js` para o preset JavaScript.
- `.edge/storage/metadata.json` e uma pasta de storage com o nome do bucket e do prefixo de storage.

Até o primeiro deploy, a pasta de storage tem os nomes literais `$BUCKET_NAME/$BUCKET_PREFIX`, os placeholders do arquivo `azion.config` do projeto. O deploy substitui os placeholders nesse arquivo pelo nome do bucket e por um prefixo de storage. Para o preset `html`, o build não cria nenhuma pasta `dist`.

`azion deploy --local` executa o mesmo build antes de enviar os arquivos. Use `azion build` para verificar um build na sua máquina antes de fazer o deploy.

## Exemplos

Cada exemplo mostra o comando e a saída que ele imprime.

### Fazer o build de um site estático

Este comando faz o build de um site configurado com o preset `html`:

```bash
azion build
```

O comando executa o Azion Bundler com o preset do projeto e imprime o caminho do manifesto que gera:

```text
Building your Application. This process may take a few minutes
Running build step command:

$ npx --yes  @aziontech/bundler@1.1.4 build --preset html
…
[Azion] [Build] › ℹ  info      Using preset: html
[Azion] [Pre-Build] › ℹ  info      Starting pre-build...
[Azion] [Pre-Build] › ℹ  info      Pre-build completed successfully
[Azion] [Build] › ℹ  info      Using built-in handler from "html" preset.
[Azion] [Build] › ℹ  info      Starting build...
[Azion] [Build] › ✔  success   Build completed successfully
[Azion] [Post-Build] › ℹ  info      Starting post-build...
[Azion] [Post-Build] › ✔  success   Post-build completed successfully
[Azion] [Storage] › ℹ  info      Using provided prefix for storage '$BUCKET_NAME': $BUCKET_PREFIX
[Azion] [IaC] › ✔  success   Manifest generated successfully at <project-dir>/.edge/manifest.json
Your Application was built successfully
```

Depois do build, a pasta `.edge` guarda esta árvore. A árvore contém `handler.dev.js` quando `azion dev` já rodou no projeto antes do build:

```text
.edge
.edge/functions
.edge/functions/handler.dev.js
.edge/functions/handler.js
.edge/manifest.json
.edge/storage
.edge/storage/$BUCKET_NAME
.edge/storage/$BUCKET_NAME/$BUCKET_PREFIX
.edge/storage/metadata.json
```

### Fazer o build de um projeto de framework

Este comando faz o build de um projeto configurado com o preset `angular`:

```bash
azion build
```

Na etapa de pre-build, o Azion Bundler executa o build do próprio framework, aqui `ng build`, e depois o build da Azion. `--skip-framework-build` deixa o build do framework de fora:

…
