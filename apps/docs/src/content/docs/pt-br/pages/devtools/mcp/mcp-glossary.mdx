Este glossário define os termos usados pelos [Azion MCP Servers](/pt-br/documentacao/devtools/mcp/) nas respostas deles, na configuração de um agente de código e em toda a sua documentação.

| Termo | Definição |
| --- | --- |
| `dry_run` | A entrada que faz uma ferramenta de escrita do servidor de build, secure, observe ou storage retornar a requisição da Azion API que enviaria, sem enviá-la. A prévia traz o método, a URL, os headers e o corpo, inclusive o seu personal token no header `Authorization`. [Crie regras do Rules Engine com o MCP server](/pt-br/documentacao/guias/desenvolvimento-de-aplicacoes/primeiros-passos/gerar-regras-do-rules-engine-com-mcp/) o usa antes de toda escrita. |
| ferramenta | Uma função que um MCP server oferece e que um agente de código chama pelo nome com argumentos JSON, como `search_azion_docs_and_site` com uma `query`. As ferramentas do servidor de docs apenas leem. As ferramentas de build, secure, observe e storage também criam, alteram e excluem recursos, e cada ferramenta de escrita recebe `dry_run`. [Ferramentas e recursos](/pt-br/documentacao/devtools/mcp/ferramentas/) lista as ferramentas de cada servidor. |
| MCP server | Um dos cinco servidores [Model Context Protocol](https://modelcontextprotocol.io) hospedados que a Azion mantém, cada um no caminho `/mcp` do próprio host: `docs-mcp.azion.com`, `build-mcp.azion.com`, `secure-mcp.azion.com`, `observe-mcp.azion.com` e `storage-mcp.azion.com`. O servidor de docs busca na documentação, nos exemplos de código, nos comandos da CLI, nas operações da API e nos recursos do Terraform da Azion, e os outros quatro leem e alteram os recursos da sua conta. [Azion MCP Servers](/pt-br/documentacao/devtools/mcp/) descreve o que eles oferecem, e [Configuração de agentes](/pt-br/documentacao/agent-setup/) conecta cada agente de código a eles. |
| `mcp-remote` | O pacote que conecta a um MCP server, por HTTP, um cliente que inicia os servidores dele como processos locais. O `npx` baixa e executa o pacote com a URL do servidor e o header `Authorization`, como em `npx -y mcp-remote@latest https://docs-mcp.azion.com/mcp --header "Authorization: Token [TOKEN VALUE]"`. [Primeiros passos com o MCP server](/pt-br/documentacao/devtools/mcp/primeiros-passos/) mostra os clientes que o usam. |
| personal token | A credencial da Azion que autentica cada requisição aos MCP servers: `azion` seguido de 35 letras e dígitos, 40 caracteres no total. Um cliente a envia como `Authorization: Token [TOKEN VALUE]`. Um personal token enviado com o esquema `Bearer` falha com 401. Uma requisição sem o header recebe 401 `No authentication provided`, e uma requisição com um token inválido recebe 403 `Authentication failed`. [Personal Tokens](/pt-br/documentacao/fundamentos/personal-tokens/) descreve como um token é criado e quando ele expira. |
| `Pragma: azion-debug-cache` | O header de requisição que faz uma resposta da Azion trazer os headers de debug de cache dela, como `x-cache`, `x-cache-key` e `x-cache-expires-in`. [Teste o comportamento do cache com o MCP server](/pt-br/documentacao/guias/performance-e-confiabilidade/cache-e-purge/testar-cache-com-mcp/) o usa para ler o estado do cache de um site após o deploy, e [Primeiros passos com Cache](/pt-br/documentacao/plataforma/applications/cache/primeiros-passos/) explica `x-cache` e `x-cache-key`. |
| prompt | Um template de mensagem que um servidor Model Context Protocol pode oferecer aos clientes dele. [Execute um MCP server na Azion](/pt-br/documentacao/guias/desenvolvimento-de-aplicacoes/automacao/executar-mcp-server/) mostra como adicionar prompts a um servidor seu. |
| recurso | Um documento que um cliente lê de um MCP server pela URI dele, como lê um arquivo, sem chamar uma ferramenta. O servidor de docs da Azion oferece sete recursos em Markdown, em `azion://guides/deploy/` e `azion://guides/test-cache/`. [Ferramentas e recursos](/pt-br/documentacao/devtools/mcp/ferramentas/) lista cada URI. |
| streamable HTTP | O transporte do Model Context Protocol que os MCP servers usam: um cliente envia cada mensagem como um POST HTTP para o caminho `/mcp` do servidor, como `https://docs-mcp.azion.com/mcp`. Os servidores exigem TLS 1.3. As configurações de cliente chamam esse transporte de `http` ou `streamable-http`, e [Como o MCP server funciona](/pt-br/documentacao/devtools/mcp/como-funciona/) descreve o fluxo da requisição. |
