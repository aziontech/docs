Um workload é o objeto que recebe o tráfego de um conjunto de domínios e guarda as configurações de TLS deles, e o deployment dele nomeia a aplicação que responde. O Azion Terraform Provider gerencia [Workloads](/pt-br/documentacao/plataforma/workloads/) com dois recursos e lê workloads com quatro data sources. Um workload pode ter vários deployments, e cada deployment é um recurso `azion_workload_deployment` separado. No provider v1.x, um único recurso de domínio fazia o trabalho desses dois recursos. Para migrar uma configuração v1.x para eles, consulte [Migre do provider v1.x para o v2.0](/pt-br/documentacao/devtools/terraform/migration-v3-to-v4/).

---

## Recursos de workload

| Recurso | Descrição |
| --- | --- |
| [`azion_workload`](https://registry.terraform.io/providers/aziontech/azion/latest/docs/resources/workload) | Cria e gerencia um workload. |
| [`azion_workload_deployment`](https://registry.terraform.io/providers/aziontech/azion/latest/docs/resources/workload_deployment) | Cria e gerencia um deployment de um workload. |

Cada recurso recebe as suas configurações em um único atributo aninhado. `azion_workload` recebe `workload`, que exige `name`, uma string que contém o nome único do workload. O mesmo atributo guarda as configurações opcionais `domains`, `active`, `tls`, `protocols` e `mtls`. Depois do apply, `workload.id` contém o ID numérico do workload.

`azion_workload_deployment` exige `workload_id`, o ID numérico do workload do qual ele faz o deploy, e `deployment`, que exige um `name` e uma `strategy`. A strategy recebe `type = "default"` e, em `attributes`, o ID numérico da aplicação que responde em `application`, além dos IDs opcionais `firewall` e `custom_page`. O deployment é o único lugar que vincula uma aplicação a um workload: `azion_workload` não recebe ID de aplicação. A página de cada recurso no Terraform Registry lista todos os argumentos.

## Data sources

| Data source | Descrição |
| --- | --- |
| [`azion_workloads`](https://registry.terraform.io/providers/aziontech/azion/latest/docs/data-sources/workloads) | Lista workloads. |
| [`azion_workload`](https://registry.terraform.io/providers/aziontech/azion/latest/docs/data-sources/workload) | Lê um workload. |
| [`azion_workload_deployments`](https://registry.terraform.io/providers/aziontech/azion/latest/docs/data-sources/workload_deployments) | Lista deployments de workloads. |
| [`azion_workload_deployment`](https://registry.terraform.io/providers/aziontech/azion/latest/docs/data-sources/workload_deployment) | Lê um deployment. |

## Exemplo

Esta configuração fixa o provider na versão 2.10.0, cria uma aplicação, cria um workload para o domínio `www.example.com` e faz o deploy da aplicação no workload. Ela também lê os workloads existentes e retorna o ID do workload em um output. Ela lê o seu personal token da variável `api_token`, declarada em [Primeiros passos com o Azion Terraform Provider](/pt-br/documentacao/devtools/terraform/getting-started/).

```hcl
terraform {
  required_providers {
    azion = {
      source  = "aziontech/azion"
      version = "2.10.0"
    }
  }
}

provider "azion" {
  api_token = var.api_token
}

# Create the application that answers on the workload
resource "azion_application_main_setting" "my_app" {
  application = {
    name   = "my-application"
    active = true
  }
}

# Create a workload
resource "azion_workload" "my_workload" {
  workload = {
    name    = "my-workload"
    active  = true
    domains = ["www.example.com"]
  }
}

# Deploy the application on the workload
resource "azion_workload_deployment" "my_deployment" {
  workload_id = azion_workload.my_workload.workload.id

  deployment = {
    name    = "my-deployment"
    active  = true
    current = true

    strategy = {
      type = "default"
      attributes = {
        application = azion_application_main_setting.my_app.application.application_id
      }
    }
  }
}

# Query existing workloads
data "azion_workloads" "all" {}

output "workload_id" {
  value = azion_workload.my_workload.workload.id
}
```
