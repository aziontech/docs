Um certificado digital é o par de certificado SSL/TLS e chave privada que permite a uma aplicação responder por HTTPS. O Azion Terraform Provider gerencia os certificados do [Certificate Manager](/pt-br/documentacao/plataforma/workloads/certificate-manager/certificados/) com quatro recursos e os lê com quatro data sources. Além de enviar um certificado que você já tem, o provider pode solicitar um certificado Let's Encrypt, criar uma solicitação de assinatura de certificado (CSR) e enviar uma lista de revogação de certificados (CRL) para mTLS.

---

## Recursos de certificado

| Recurso | Descrição |
| --- | --- |
| [`azion_digital_certificate`](https://registry.terraform.io/providers/aziontech/azion/latest/docs/resources/digital_certificate) | Cria e gerencia um certificado digital a partir de um certificado e de uma chave privada que você envia. |
| [`azion_certificate_request`](https://registry.terraform.io/providers/aziontech/azion/latest/docs/resources/certificate_request) | Solicita um certificado Let's Encrypt. |
| [`azion_certificate_signing_request`](https://registry.terraform.io/providers/aziontech/azion/latest/docs/resources/certificate_signing_request) | Cria uma solicitação de assinatura de certificado (CSR). |
| [`azion_crl`](https://registry.terraform.io/providers/aziontech/azion/latest/docs/resources/crl) | Cria e gerencia uma lista de revogação de certificados (CRL). |

`azion_digital_certificate` recebe as suas configurações em um único atributo aninhado, `results`, que exige três argumentos do tipo string: `name`, o nome do certificado; `certificate_content`, o certificado SSL/TLS em formato PEM; e `private_key`, a chave privada em formato PEM. O provider trata `certificate_content` e `private_key` como sensíveis. Depois do apply, `results.id` contém o ID numérico do certificado.

`azion_certificate_request` também recebe `results`, com `name`, `common_name`, `authority` (`lets_encrypt`) e `challenge` (`dns` ou `http`). O provider só consegue criar uma solicitação de certificado: ele não tem operação de atualização para ela. `azion_certificate_signing_request` recebe os campos de subject da CSR em `results`, e uma mudança em qualquer um deles recria a CSR. `azion_crl` recebe `crl`, com `name`, `issuer` e o conteúdo da lista em `crl`. A página de cada recurso no Terraform Registry lista todos os argumentos.

## Exemplo

Esta configuração fixa o provider na versão 2.10.0, cria um certificado a partir de um arquivo de certificado e de um arquivo de chave privada na pasta `certificates` do diretório indicado por `path.module`, lê os certificados existentes e exibe o ID do certificado em um output. Ela lê o seu personal token da variável `api_token` que [Primeiros passos com o Azion Terraform Provider](/pt-br/documentacao/devtools/terraform/getting-started/) declara.

{/* terraform-validate: skip — file() needs the PEM files on disk; the next sample validates the same resource with variables */}
```hcl
terraform {
  required_providers {
    azion = {
      source  = "aziontech/azion"
      version = "2.10.0"
    }
  }
}

provider "azion" {
  api_token = var.api_token
}

# Create digital certificate
resource "azion_digital_certificate" "my_cert" {
  results = {
    name                = "certificate-mydomain"
    certificate_content = file("${path.module}/certificates/mydomain.pem")
    private_key         = file("${path.module}/certificates/mydomain-key.pem")
  }
}

# Query existing certificates
data "azion_digital_certificates" "all" {}

output "certificate_id" {
  value = azion_digital_certificate.my_cert.results.id
}
```

Para manter o certificado e a chave privada fora do código da configuração, declare-os como variáveis sensíveis. Este bloco substitui o recurso `azion_digital_certificate` da configuração acima:

```hcl
variable "ssl_certificate" {
  type        = string
  description = "SSL certificate in PEM format"
  sensitive   = true
}

variable "ssl_private_key" {
  type        = string
  description = "SSL private key in PEM format"
  sensitive   = true
}

resource "azion_digital_certificate" "my_cert" {
  results = {
    name                = "my-certificate"
    certificate_content = var.ssl_certificate
    private_key         = var.ssl_private_key
  }
}
```

Uma forma mais curta, com `cert.pem` e `key.pem` na raiz do diretório indicado por `path.module`, está em [Recursos e data sources](/pt-br/documentacao/devtools/terraform/examples/).
