Um connector define como as suas aplicações se comunicam com as origens que guardam o seu conteúdo. Na API v4, os connectors substituem as origens da API v3. O Azion Terraform Provider gerencia [Connectors](/pt-br/documentacao/plataforma/connectors/) com um recurso e os lê com dois data sources. No provider v1.x, um recurso de origem que pertencia a uma aplicação fazia esse trabalho. Para mover uma configuração v1.x para connectors, consulte [Migre do provider v1.x para a v2.0](/pt-br/documentacao/devtools/terraform/migration-v3-to-v4/).

---

## Recursos de connector

| Recurso | Descrição |
| --- | --- |
| [`azion_connector`](https://registry.terraform.io/providers/aziontech/azion/latest/docs/resources/connector) | Cria e gerencia um connector. |

`azion_connector` exige `name`, uma string que contém o nome único do connector, e exporta `id`, uma string que contém o ID único do connector. A página do recurso no Terraform Registry lista todos os argumentos.

## Data sources

| Data source | Descrição |
| --- | --- |
| [`azion_connectors`](https://registry.terraform.io/providers/aziontech/azion/latest/docs/data-sources/connectors) | Lista connectors. |
| [`azion_connector`](https://registry.terraform.io/providers/aziontech/azion/latest/docs/data-sources/connector) | Lê um connector. |

## Exemplo

Esta configuração fixa a versão do provider, cria um connector, lê os connectors existentes e exibe o ID do connector em um output. Ela lê o seu personal token da variável `api_token` que [Primeiros passos com o Azion Terraform Provider](/pt-br/documentacao/devtools/terraform/getting-started/) declara.

```hcl
terraform {
  required_providers {
    azion = {
      source  = "aziontech/azion"
      version = "2.0.0"
    }
  }
}

provider "azion" {
  api_token = var.api_token
}

# Create a connector
resource "azion_connector" "my_origin" {
  name = "my-origin"

  # Origin configuration
}

# Query existing connectors
data "azion_connectors" "all" {}

output "connector_id" {
  value = azion_connector.my_origin.id
}
```
