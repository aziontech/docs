Os recursos de segurança do Azion Terraform Provider configuram o que bloqueia uma requisição antes que ela chegue à sua aplicação: proteção contra ameaças, bloqueio por geolocalização e rate limiting. O provider gerencia um [Firewall](/pt-br/documentacao/plataforma/firewall/) e as suas regras, a ordem delas e as suas instâncias de functions, os [rule sets](/pt-br/documentacao/plataforma/firewall/waf/rule-sets/) do Web Application Firewall (WAF) e as suas [exceções](/pt-br/documentacao/plataforma/firewall/waf/custom-allowed-rules/), e [Network Lists](/pt-br/documentacao/plataforma/firewall/network-shield/network-lists/) com sete recursos. Doze data sources leem os mesmos objetos de volta: para cada tipo de objeto, exceto a ordem das regras, um lista os objetos e outro lê um único objeto.

---

## Recursos de segurança

| Recurso | Descrição |
| --- | --- |
| [`azion_firewall_main_setting`](https://registry.terraform.io/providers/aziontech/azion/latest/docs/resources/firewall_main_setting) | Cria e gerencia as configurações principais de um firewall. |
| [`azion_firewall_rule_engine`](https://registry.terraform.io/providers/aziontech/azion/latest/docs/resources/firewall_rule_engine) | Cria e gerencia uma regra do Rules Engine de um firewall. |
| [`azion_firewall_rule_engine_order`](https://registry.terraform.io/providers/aziontech/azion/latest/docs/resources/firewall_rule_engine_order) | Define a ordem das regras do Rules Engine de um firewall. |
| [`azion_firewall_functions_instance`](https://registry.terraform.io/providers/aziontech/azion/latest/docs/resources/firewall_functions_instance) | Cria e gerencia uma instância de function em um firewall. |
| [`azion_waf`](https://registry.terraform.io/providers/aziontech/azion/latest/docs/resources/waf) | Cria e gerencia um WAF rule set, que Azion Console lista em **WAF Rules**. |
| [`azion_waf_rule_set`](https://registry.terraform.io/providers/aziontech/azion/latest/docs/resources/waf_rule_set) | Cria e gerencia uma [exceção de WAF](/pt-br/documentacao/plataforma/firewall/waf/custom-allowed-rules/), que Azion Console lista como uma allowed rule, em um rule set. |
| [`azion_network_list`](https://registry.terraform.io/providers/aziontech/azion/latest/docs/resources/network_list) | Cria e gerencia uma network list de endereços IP e intervalos CIDR, países ou ASNs. |

Estes recursos recebem as suas configurações em um único atributo aninhado:

| Recurso | Atributo aninhado | Campos |
| --- | --- | --- |
| `azion_firewall_main_setting` | `data` | Exige `name`. O opcional `active` define se o firewall está ativo, e `modules` ativa os módulos `waf`, `network_protection` e `functions`. |
| `azion_firewall_rule_engine` | `results` | Exige `name`, `criteria` e `behaviors`, como `deny`, `drop`, `set_waf` ou `set_rate_limit`. |
| `azion_firewall_functions_instance` | `data` | Exige `name` e `function`, o ID de uma function que o recurso `azion_function` gerencia. |
| `azion_waf` | `result` | Exige `name`. O opcional `engine_settings` guarda as famílias de ameaças e a sensibilidade delas. |
| `azion_waf_rule_set` | `result` | Exige `name` e `conditions`, as partes da requisição que a exceção isenta. O opcional `rule_id` é a regra interna que ela isenta, e `0` isenta todas. |
| `azion_network_list` | `results` | Exige `name`, `type` (`ip_cidr`, `countries` ou `asn`) e `items`, os endereços IP e intervalos CIDR, os códigos de país ou os ASNs da lista. |

Os recursos de regra, de ordem das regras e de instância de function recebem o ID do firewall em `firewall_id`, e `azion_waf_rule_set` recebe o ID do rule set em `waf_id`, fora do atributo aninhado. Depois do apply, `data.id` contém o ID numérico de um firewall e `result.id`, o ID numérico de um WAF rule set. Um rule set só pontua requisições quando o firewall tem o módulo `waf` ativo e uma regra do firewall executa o behavior `set_waf` com o ID do rule set e o modo `logging` ou `blocking`. Um firewall é executado em um workload pelo atributo `firewall` da strategy de um deployment; para mais informações, consulte [Recursos de Workloads](/pt-br/documentacao/devtools/terraform/workloads/). Um módulo que `modules` omite volta ao seu padrão a cada apply. A página de cada recurso no Terraform Registry lista todos os argumentos.

## Exemplo

Esta configuração fixa o provider na versão 2.10.0 e cria uma network list de intervalos IP bloqueados e um firewall ativo com os módulos de WAF e de proteção de rede ativos. Ela cria um WAF rule set com uma exceção para o caminho `/health`, adiciona uma regra de firewall que nega as requisições vindas da network list e uma regra que executa o rule set no modo `blocking` em todas as requisições. Ela exibe o ID do firewall em um output e lê o seu personal token da variável `api_token` que [Primeiros passos com o Azion Terraform Provider](/pt-br/documentacao/devtools/terraform/getting-started/) declara.

```hcl
terraform {
  required_providers {
    azion = {
      source  = "aziontech/azion"
      version = "2.10.0"
    }
  }
}

provider "azion" {
  api_token = var.api_token
}

# Create network list for blocked IPs
resource "azion_network_list" "blocked_ips" {
  results = {
    name  = "blocked-ips"
    type  = "ip_cidr"
    items = ["192.0.2.0/24", "198.51.100.10"]
  }
}

# Create firewall
resource "azion_firewall_main_setting" "my_firewall" {
  data = {
    name   = "my-firewall"
    active = true

    modules = {
      waf = {
        enabled = true
      }
      network_protection = {
        enabled = true
      }
    }
  }
}

# Create a WAF rule set
resource "azion_waf" "my_waf" {
  result = {
    name   = "my-waf"
    active = true
  }
}

# Create WAF exception for the health check path
resource "azion_waf_rule_set" "health_check" {
  waf_id = azion_waf.my_waf.result.id

  result = {
    name     = "allow-health-check"
    active   = true
    path     = "/health"
    operator = "contains"
    rule_id  = 0

    conditions = [
      {
        condition = {
          match          = "any_url"
          condition_type = "generic"
        }
      }
    ]
  }
}

# Deny requests from the network list
resource "azion_firewall_rule_engine" "deny_blocked_ips" {
  firewall_id = azion_firewall_main_setting.my_firewall.data.id

  results = {
    name   = "deny-blocked-ips"
    active = true

    criteria = [
      {
        entries = [
          {
            criterion = {
              variable    = "$${network}"
              operator    = "is_in_list"
              conditional = "if"
              argument    = azion_network_list.blocked_ips.id
            }
          }
        ]
      }
    ]

    behaviors = [
      {
        behavior = {
          type = "deny"
        }
      }
    ]
  }
}

# Run the WAF on every request
resource "azion_firewall_rule_engine" "run_waf" {
  firewall_id = azion_firewall_main_setting.my_firewall.data.id

  results = {
    name   = "run-waf"
    active = true

    criteria = [
      {
        entries = [
          {
            criterion = {
              variable    = "$${request_uri}"
              operator    = "starts_with"
              conditional = "if"
              argument    = "/"
            }
          }
        ]
      }
    ]

    behaviors = [
      {
        behavior = {
          type = "set_waf"
          attributes = {
            waf_id = azion_waf.my_waf.result.id
            mode   = "blocking"
          }
        }
      }
    ]
  }
}

output "firewall_id" {
  value = azion_firewall_main_setting.my_firewall.data.id
}
```

Os critérios escrevem as variáveis `${network}` e `${request_uri}` como `$${network}` e `$${request_uri}`. Com um único `$`, o Terraform lê as variáveis como interpolações e falha. Para `is_in_list`, o `argument` é o ID da network list.
