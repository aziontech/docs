O Azion Runtime é compatível com uma parte das APIs do Node.js, não com todas. Uma function, e cada pacote npm de que ela depende, pode importar os 68 módulos do Node.js da tabela abaixo. Cada um é resolvido quando o build empacota a function e carrega em uma function após o deploy e no `azion dev`. O status de um módulo informa quanto da API dele funciona quando a function o chama.

:::note[nota]
No `azion dev`, alguns módulos se comportam de forma diferente de uma function após o deploy. Os caminhos de `node:fs` são resolvidos na pasta `.edge/storage/` do projeto, um import de `pipeline` de `node:stream` faz o build falhar, e `timingSafeEqual()` e `generateKeyPairSync()` de `node:crypto` lançam erro.
:::

## Importação de módulos

Uma function importa um módulo do Node.js com a sintaxe padrão de `import` e o prefixo `node:`:

```javascript
import { AsyncLocalStorage } from "node:async_hooks";
import os from "node:os";
```

Um polyfill é um código que adiciona um recurso a um ambiente que não o tem. O build resolve por meio de polyfills as APIs do Node.js que o runtime não oferece, e a configuração `polyfills` do [azion.config.js](/pt-br/documentacao/devtools/cli/azion-config-js/) define se o build os adiciona. A lista de APIs que o build resolve por meio de polyfills está no [repositório do Azion Bundler](https://github.com/aziontech/bundler/blob/main/lib/build/bundlers/polyfills/polyfills-manager.js), que também aceita contribuições.

## Suporte aos módulos

A tabela lista cada módulo com o seu status. Quando existe uma página do módulo, o nome do módulo leva a ela. A coluna Observações informa o que uma function recebe quando chama o módulo, quando esse comportamento é conhecido.

- 🟢 **Suportado**: a API funciona normalmente em tempo de execução.
- 🟡 **Parcialmente suportado**: apenas alguns métodos ou recursos estão disponíveis.
- 🔴 **Somente para build**: o módulo é incluído para que o build seja concluído sem erros, mas as chamadas à API dele não funcionam em tempo de execução.

:::note[nota]
Uma function na Azion executa dentro de uma **Cell**, o ambiente de isolamento que a Azion constrói sobre **V8 isolates**. Uma Cell é um contexto de execução leve e seguro, e o código dentro dela não tem acesso direto ao sistema operacional subjacente.

Por segurança multilocatário e integridade da infraestrutura, uma Cell não oferece a uma function:

- As propriedades da máquina que a executa. `node:os` e `process` retornam valores fixos no lugar delas, como `linux` para `os.platform()`, uma string vazia para `os.hostname()` e `0` para `os.totalmem()`.
- Resolução de DNS por meio de chamadas de sistema nativas (`node:dns`, `node:dns/promises`).
- Sockets TCP ou UDP de baixo nível que exigem chamadas de sistema diretas.

Os módulos marcados como 🔴 **Somente para build** são incluídos como stubs, para que pacotes npm com imports estáticos deles ainda passem pelo build. As chamadas deles não funcionam em tempo de execução: `dns.lookup()` lança `Error: [unenv] dns.lookup is not implemented yet!`.
:::
