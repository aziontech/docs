O módulo `node:module` dá acesso ao sistema de módulos do Node.js, que abrange CommonJS e ES modules, como descreve a [documentação do module do Node.js](https://nodejs.org/api/module.html). No Node.js, o sistema de módulos organiza o código em arquivos e bibliotecas reutilizáveis. No Azion Runtime, `import module from "node:module"` faz o build, e você o usa para inspecionar o sistema de módulos, por exemplo para listar os módulos nativos que uma function pode importar.

Os membros abaixo se comportam da mesma forma em uma function com deploy feito e com `azion dev`. `module.builtinModules` é um array de 65 nomes, de `_http_agent` a `zlib`. `module.createRequire()` retorna `undefined` em vez de uma função require, então uma chamada ao resultado dela lança um `TypeError`. `module.isBuiltin()` não existe. `SourceMap`, `_findPath`, `_initPaths`, `_load`, `_nodeModulePaths`, `_preloadModules`, `_resolveFilename` e `_resolveLookupPaths` não são suportados.

---

## Exemplo

A function abaixo registra em log o nome de cada módulo nativo e responde quando a lista termina:

```javascript
/**
 * An example of using the Node.js Module API in an Azion Function.
 * @example
 * // Build and run locally with the Azion CLI:
 * azion build
 * azion dev
 */
import module from "node:module";

export default {
  /**
   * An example of using the Node.js Module API in an Azion Function.
   * @param {Request} request
   * @returns {Promise<Response>}
   */
  async fetch(request, env, ctx) {
    return new Promise((resolve, reject) => {
      module.builtinModules.forEach((moduleName) => {
        console.log(moduleName);
      });
      resolve(new Response("Done"));
    });
  },
};
```

A function registra em log os 65 nomes, um por linha, de `_http_agent` a `zlib`, e responde com este corpo:

```text
Done
```
