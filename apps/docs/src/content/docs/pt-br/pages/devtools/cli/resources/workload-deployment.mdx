Os comandos `workload-deployment` da Azion CLI criam, listam e descrevem o deployment de um [workload](/pt-br/documentacao/plataforma/workloads/). O deployment nomeia a aplicação que responde aos domínios do workload e, opcionalmente, o [firewall](/pt-br/documentacao/plataforma/firewall/) que inspeciona as requisições antes e o [conjunto de custom pages](/pt-br/documentacao/plataforma/workloads/custom-pages/configuracoes/) que substitui as respostas de erro. Um workload tem um deployment, então o `azion create workload-deployment` só funciona em um workload que ainda não tem um. A CLI não tem comando que atualiza ou exclui um deployment. Para alterar o deployment de um workload, defina os campos dele nas configurações de deployment do workload no Azion Console. Um projeto que declara o workload no `azion.config.js` recebe o deployment da entrada [`deployments`](/pt-br/documentacao/devtools/cli/azion-config-js/#deployments-do-workload) quando você roda `azion deploy`. As opções que todo comando aceita, como `--format`, `--out` e `-y`, estão em [Opções globais](/pt-br/documentacao/devtools/cli/globals/). Esta página corresponde à Azion CLI 4.24.0.

## Criar

`azion create workload-deployment` cria o deployment de um workload:

```bash
azion create workload-deployment [flags]
```

| Flag | Curta | Tipo | Padrão | Descrição |
| --- | --- | --- | --- | --- |
| `--workload-id` | — | int | — | ID do workload ao qual o deployment pertence. Sem ela, e sem `--file`, o comando pede o valor. |
| `--name` | — | string | — | Nome do deployment. Sem ela, e sem `--file`, o comando pede o valor. |
| `--application-id` | — | int | — | ID da aplicação que o deployment serve. Sem ela, e sem `--file`, o comando pede o valor. |
| `--firewall-id` | — | int | — | ID do firewall que inspeciona as requisições do workload. |
| `--custom-page` | — | string | — | ID do conjunto de custom pages que substitui as respostas de erro do workload. |
| `--strategy-type` | — | string | `default` | Tipo da estratégia do deployment. |
| `--active` | — | string | — | Se o deployment está ativo, `true` ou `false`. |
| `--current` | — | string | — | Se o deployment é o atual, `true` ou `false`. |
| `--file` | — | string | — | Caminho para um arquivo JSON com os atributos do deployment. Use `-` para ler o JSON da entrada padrão. Com `--file`, o comando não lê nenhuma outra flag de atributo. |

Este comando cria um deployment para o workload com ID `1234` que serve a aplicação com ID `5678` e substitui as respostas de erro pelo conjunto de custom pages com ID `123`:

```bash
azion create workload-deployment --workload-id 1234 --name my-deployment --application-id 5678 --custom-page 123
```

O comando imprime o ID do deployment:

```text
Created Workload Deployment with ID 4321
```

## Listar

`azion list workload-deployment` lista os deployments de um workload, 50 por página:

```bash
azion list workload-deployment [flags]
```

| Flag | Curta | Tipo | Padrão | Descrição |
| --- | --- | --- | --- | --- |
| `--workload-id` | — | int | — | ID do workload cujos deployments serão listados. Sem ela, o comando pede o valor. |
| `--details` | — | — | — | Adiciona as colunas `EDGE APPLICATION` e `EDGE FIREWALL` às colunas `ID` e `CURRENT`. |
| `--filter` | — | string | — | Nome pelo qual filtrar a lista. |
| `--order-by` | — | string | — | Campo pelo qual ordenar a lista. |
| `--page` | — | int | `1` | Número da página a retornar. |
| `--page-size` | — | int | `50` | Número de deployments em cada página. |

Este comando lista o deployment do workload com ID `1234`, com a aplicação e o firewall que ele nomeia:

```bash
azion list workload-deployment --workload-id 1234 --details
```

O comando imprime uma linha por deployment. `EDGE APPLICATION` e `EDGE FIREWALL` trazem IDs, e um `EDGE FIREWALL` igual a `0` indica que o deployment não nomeia firewall. A lista não tem coluna para o conjunto de custom pages; para vê-lo, use `azion describe workload-deployment --format json`.

## Descrever

`azion describe workload-deployment` imprime as configurações do deployment de um workload:

```bash
azion describe workload-deployment [flags]
```

| Flag | Curta | Tipo | Padrão | Descrição |
| --- | --- | --- | --- | --- |
| `--workload-id` | — | int | — | ID do workload. Sem ela, o comando pede o valor. |
| `--deployment-id` | — | int | — | ID do deployment a descrever. Sem ela, o comando pede o valor. |

Este comando descreve o deployment com ID `4321` do workload com ID `1234`, em JSON:

```bash
azion describe workload-deployment --workload-id 1234 --deployment-id 4321 --format json
```

Sem `--format json`, o comando imprime só o ID, a tag e o estado atual do deployment.

## Usar um arquivo JSON

`azion create workload-deployment` lê o deployment de um arquivo JSON com `--file`. O ID do workload não faz parte do arquivo: passe-o com `--workload-id`.

O arquivo traz os campos do deployment:

- `name`, `active` e `current` descrevem o deployment.
- `strategy.type` é o tipo da estratégia, como `default`.
- `strategy.attributes` traz `application`, o ID da aplicação, e opcionalmente `firewall` e `custom_page`, os IDs do firewall e do conjunto de custom pages.

Este arquivo cria um deployment atual e ativo que serve a aplicação com ID `5678` atrás do firewall com ID `910`, com o conjunto de custom pages com ID `123`:

```json
{
  "name": "my-deployment",
  "active": true,
  "current": true,
  "strategy": {
    "type": "default",
    "attributes": {
      "application": 5678,
      "firewall": 910,
      "custom_page": 123
    }
  }
}
```

Passe o arquivo para o comando create com o ID do workload:

```bash
azion create workload-deployment --workload-id 1234 --file deployment.json
```

Para declarar o deployment em um projeto, use a entrada [`deployments`](/pt-br/documentacao/devtools/cli/azion-config-js/#deployments-do-workload) do `azion.config.js` e rode `azion deploy`. O `strategy.attributes.customPage` dela recebe o conjunto por nome ou por ID. Com o `azion deploy`, o deployment nomeia a aplicação que o deploy cria para o projeto, mesmo quando `strategy.attributes.application` traz o ID de outra aplicação.
