Você pode reunir as evidências que identificam um problema na Azion Web Platform antes de abrir um ticket de suporte. As mesmas evidências podem permitir que você resolva o problema sozinho, com a [investigação básica de problemas](/pt-br/documentacao/suporte/investigacao-problemas-basico/). Para enviar o ticket, consulte [Abra um ticket de suporte](/pt-br/documentacao/suporte/abrir-tickets/).

---

## Registre o request ID

O request ID identifica uma requisição na Azion Web Platform. Toda resposta o carrega no header `x-azion-request-id`, e a página de erro da Azion o mostra como **Request ID**.

Para ler o request ID de uma URL, envie uma requisição que imprime somente os headers da resposta:

<Code lang="bash" code={`curl -sI https://<your-domain>/<affected-path>`} />

A resposta carrega o request ID e o código do data center da Azion que respondeu:

```text
x-azion-request-id: 6c8df71c4168dd821bb4d0b832056124
x-azion-edge-location: SDU
```

Para todos os headers que a Azion adiciona a uma resposta, consulte [Headers de resposta para diagnóstico](/pt-br/documentacao/suporte/headers-de-diagnostico/).

---

## Registre o horário em UTC

O Real-Time Events registra cada requisição em Tempo Universal Coordenado (UTC) por padrão. Registre a data e o horário do problema em UTC, ou informe o fuso horário ao lado do horário.

---

## Encontre a requisição no Real-Time Events

O campo `requestId` do [Real-Time Events](/pt-br/documentacao/plataforma/real-time-events/) armazena o mesmo identificador do header de resposta. Uma busca por request ID retorna o registro de uma única requisição.

Um valor tirado de um header de resposta pode carregar um sufixo numérico depois de um hífen, como `5f222ae5938482c32a822dbf15e19f0f-1234`. O registro do evento não armazena o sufixo. Busque somente pelo identificador base, porque uma busca que inclui o sufixo pode não retornar resultados ou retornar um erro `400`. Para a sintaxe da busca, consulte [Ler um registro de evento](/pt-br/documentacao/guias/plataforma/observabilidade/entender-logs/#buscar-por-request-id).

## Capture os headers de debug

O header de requisição `Pragma: azion-debug-cache` faz a Azion adicionar headers de cache e de localização à resposta. Esses headers mostram se a resposta veio do cache e sob qual cache key.

Para capturar os headers de debug:

<Code lang="bash" code={`curl -sI -H "Pragma: azion-debug-cache" https://<your-domain>/<affected-path>`} />

A resposta carrega o código de localização `x-azion-edge-pop`, o status do cache e a cache key, junto com os outros headers de debug:

```text
x-azion-edge-pop: EQN
x-cache: MISS from 179.191.172.25 with HTTP/2.0
x-cache-key: httpswww.azion.com/en/
```

Guarde a saída completa para o ticket. Para ler cada valor, consulte [Headers de resposta para diagnóstico](/pt-br/documentacao/suporte/headers-de-diagnostico/).

## Registre o UUID do dispositivo afetado

O Azion netinfo mostra um UUID para o dispositivo que o abre, então leia o UUID no dispositivo que apresenta o problema.

Para registrar o UUID:

1. No dispositivo afetado, abra `https://netinfo.azion.com` em um navegador.
2. Copie o valor do campo **UUID**.

O UUID vai na descrição do ticket.

## Reúna as evidências do produto afetado

Alguns produtos precisam de evidências próprias. Reúna os itens do produto que apresenta o problema:

| Produto | Evidências |
| :--- | :--- |
| [Edge DNS](/pt-br/documentacao/plataforma/edge-dns/solucao-de-problemas/) | A saída do `dig` ou do `host` que mostra a resposta inesperada, os nomes e tipos de registro afetados, o nameserver consultado, como `ns1.aziondns.net`, e onde você observou o problema |
| [MCP servers da Azion](/pt-br/documentacao/devtools/mcp/solucao-de-problemas/) | A mensagem de erro, a URL do servidor, o cliente e a versão dele, a configuração do cliente sem o token e os passos que reproduzem o sintoma |
| Solicitações do [Acordo de Nível de Serviço](/pt-br/documentacao/contratos/sla/) | A configuração impactada, a data e o horário com o fuso horário, as regiões de teste, a URL de teste, os códigos recebidos, os números dos tickets relacionados e os logs do serviço de monitoramento |

## Descreva o problema

Um ticket cobre um produto. A descrição informa ao Suporte Azion o que reproduzir e qual resultado você espera.

Escreva estes itens na descrição do ticket:

- A URL da página do Azion Console que contém as configurações com o problema.
- O comportamento que você esperava e o comportamento que você observou.
- As condições em que o problema ocorre: navegador, aplicação, sistema operacional, provedor de internet e tipo de conexão.
- Os passos que reproduzem o problema.
- O request ID, o horário em UTC e o UUID das seções acima.

Com esses itens na descrição, o ticket está pronto para envio.
