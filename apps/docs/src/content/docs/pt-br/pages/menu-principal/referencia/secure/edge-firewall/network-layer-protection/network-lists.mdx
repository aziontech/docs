Uma Network List é uma entidade nomeada que contém endereços IP e intervalos CIDR, Autonomous System Numbers (ASNs) ou países. Uma regra de [Firewall](/pt-br/documentacao/plataforma/firewall/) a usa por meio do critério _Network_, que [Network Shield](/pt-br/documentacao/plataforma/firewall/network-shield/) adiciona, para comparar o endereço do cliente de uma requisição com a lista. Uma Network List não precisa de um Firewall, e não corresponde a nada até que uma regra a use em um Firewall que o deployment de um [Workload](/pt-br/documentacao/plataforma/workloads/) define.

---

## Campos da Network List

Uma Network List carrega quatro campos que uma requisição define e quatro que a plataforma define e retorna. Uma criação e um `PUT` precisam enviar `name`, `type` e `items`, enquanto um `PATCH` envia apenas os campos que altera.

| Campo | Rótulo no Console | Tipo | Obrigatório | Padrão | Descrição |
| --- | --- | --- | --- | --- | --- |
| `name` | **Name** | string, de 1 a 250 caracteres | Sim | — | O nome da lista. É a opção que o dropdown **Select a Network** de uma regra mostra, e pode mudar a qualquer momento. Um nome vazio é recusado com `10018`. |
| `type` | _ASN_, _IP/CIDR_ ou _Countries_; **Network List Type** no formulário de edição e **List Type** na lista | string: `ip_cidr`, `asn` ou `countries` | Sim | — | O que são os itens. Tipos de lista traz o formato de item de cada tipo. O Console pré-seleciona _ASN_. |
| `items` | **List**, ou **Countries** em uma lista de países | array de 1 a 20.000 strings, cada uma com 1 a 250 caracteres | Sim | — | As entradas a que uma regra corresponde. Duplicatas exatas são removidas, e o `type` define a ordem do restante. |
| `active` | Nenhum | boolean | Não | `true` | Se uma regra pode usar a lista. O Console não tem controle para esse campo. |
| `id` | **ID**, na lista | integer | Somente leitura | — | O identificador que uma regra carrega como argumento de `${network}`. |
| `last_editor` | **Last Editor** | string | Somente leitura | — | O e-mail da conta que alterou a lista pela última vez, ou `Azion` em uma lista mantida pela Azion. |
| `last_modified` | **Last Modified** | date-time | Somente leitura | — | Quando a lista foi alterada pela última vez. |
| `created_at` | Nenhum | date-time | Somente leitura | — | Quando a lista foi criada. É `null` em uma lista mantida pela Azion. |

O `type` nunca muda depois da criação. Uma atualização que envia outro tipo é recusada com `22002`, mesmo quando os itens são válidos para o novo tipo, e o Console bloqueia o tipo com a tag `The type cannot be changed after the network list is created`. Para corresponder a outro tipo de entrada, crie uma Network List desse tipo.

O `type` também define a ordem de `items` na resposta a uma criação ou a uma atualização e em um `GET` posterior da lista:

- Uma lista `ip_cidr` retorna os itens na ordem de envio. Quando uma requisição envia o mesmo item duas vezes, a lista mantém a primeira ocorrência no lugar dela.
- Uma lista `asn` ou `countries` retorna os itens em uma ordem que a plataforma define, que não é a ordem de envio nem a ordem crescente ou alfabética. Essa ordem se mantém entre leituras dos mesmos itens.

Definir `active` como `false` nunca pausa uma regra que está correspondendo. Uma lista que uma regra usa não pode receber `false` (`22003`), e uma regra não pode usar uma lista com `false` (`25031`). Para que uma lista deixe de corresponder, altere ou exclua as regras que a usam.

Uma resposta também carrega `version_id`, `version_state`, `is_versioned` e `version`, que uma requisição não define.

Várias regras em vários Firewalls podem usar uma mesma Network List. Uma regra armazena o `id` da lista, não os itens dela, então uma gravação em `items` não exige mudança nas regras. A API armazena a gravação na hora. Para saber como uma mudança chega ao tráfego, consulte [Correspondência de listas](/pt-br/documentacao/plataforma/firewall/network-shield/correspondencia-de-listas/).

## Tipos de lista

O `type` de uma lista define o formato de cada item nela. Cada tipo tem um valor na API e um rótulo no Console.

| Tipo | Rótulo no Console | Formato do item | Exemplo | Anotações |
| --- | --- | --- | --- | --- |
| `ip_cidr` | _IP/CIDR_ | Um endereço IPv4 ou IPv6, com ou sem comprimento de prefixo. | `192.0.2.10`, `198.51.100.0/24`, `2001:db8::/32` | Uma data de expiração e um comentário, conforme Anotações de item. |
| `asn` | _ASN_ | Um Autonomous System Number de `1` a `2147483647`, apenas dígitos. `AS64496`, `0` e `2147483648` são recusados com `22011`. | `64496`, do intervalo reservado para documentação. | Nenhuma. Um item com anotação é recusado com `22011`. |
| `countries` | _Countries_ | Um código de país ISO 3166-1 alpha-2 com duas letras maiúsculas. `de`, `Germany` e `XX` são recusados com `22015`. | `DE` | Nenhuma. Um item com anotação é recusado com `22015`. |

No Azion Console, o campo **List** recebe uma entrada por linha para _IP/CIDR_ e _ASN_. Ele aceita prefixos IPv4 de `/0` a `/32` e prefixos IPv6 até `/128` e, em uma lista _ASN_, também aceita um ASN escrito como `AS13335`, que ele envia sem o `AS`. O campo verifica cada linha antes de salvar e nomeia cada uma que recusa, com mensagens como `--LT must be a valid UTC date and time in the format YYYY-MM-DDTHH:MM:SSZ`, `add a space before --LT`, `the --LT date must be in the future` e `a line cannot start with a comment (#); add the IP/CIDR before it`. O campo **Countries** é uma seleção múltipla por nome de país, e o Console envia o código de duas letras de cada país selecionado.

## Anotações de item

Um item `ip_cidr` pode carregar uma data de expiração, um comentário ou os dois, depois do endereço. Itens `asn` e `countries` não aceitam nenhum deles. Um item com anotação segue esta sintaxe:

```text
<ip-or-cidr>[ --LTYYYY-MM-DDTHH:MM:SSZ][ #comment]
```

A plataforma aceita estes itens e os armazena exatamente como foram enviados:

```text
192.0.2.1 #comment
192.0.2.2 --LT2030-01-01T00:00:00Z
192.0.2.5/32 --LT2030-01-01T00:00:00Z #both
2001:db8::1 --LT2030-01-01T00:00:00Z
192.0.2.9 #a comment with spaces
```

| Parte | Sintaxe | Restrições |
| --- | --- | --- |
| Data de expiração | `--LT` e uma data e hora em UTC, `YYYY-MM-DDTHH:MM:SSZ` | Um espaço antes de `--LT`, o marcador em maiúsculas, segundos inteiros e um `Z` no final. Uma data sem hora ou com frações de segundo é recusada com `22007`, e um `--lt` em minúsculas torna o item inválido (`22005`). |
| Comentário | `#` e qualquer texto | Por último na linha, depois da data de expiração quando o item carrega os dois. Um `--LT` depois do `#` é recusado com `22009`. Uma linha que começa com `#` é um item inválido (`22005`), e não uma linha desativada. |

As anotações contam para os 250 caracteres que um item comporta. Sempre que uma requisição grava `items`, em uma criação ou em uma atualização, a plataforma processa os itens antes de armazená-los:

- Duplicatas exatas são removidas sem aviso. Notações equivalentes não são duplicatas, então `192.0.2.80` e `192.0.2.80/32` são mantidos.
- Um item cuja data de expiração já passou é descartado sem aviso. Quando todos os itens estão expirados, a gravação é recusada com `22019`.
- A API não recusa um item sem espaço antes de `--LT`: uma criação cujo único item era `192.0.2.2--LT2030-01-01T00:00:00Z` respondeu `201` e não armazenou nenhum item.
- Os itens restantes são armazenados como foram enviados, com as anotações. Uma lista `ip_cidr` os mantém na ordem de envio, enquanto uma lista `asn` ou `countries` os retorna na ordem que o `type` dela define.

A plataforma não remove um item quando a data de expiração dele passa depois da gravação. O item continua armazenado, mesmo em gravações que deixam `items` de fora, até que uma gravação posterior de `items`, ou `azion update network-list --remove-item`, o remova. Para saber como uma data de expiração chega ao tráfego, consulte [Correspondência de listas](/pt-br/documentacao/plataforma/firewall/network-shield/correspondencia-de-listas/).

## Listas mantidas pela Azion

A Azion mantém Network Lists que uma regra de qualquer conta pode usar e que nenhuma conta pode alterar. A página **Network Lists** no Azion Console e `GET /v4/workspace/network_lists` retornam essas listas ao lado das listas que você cria.

| ID | Nome | Tipo | Mantida por |
| --- | --- | --- | --- |
| `2` | `Azion IP Tor Exit Nodes` | `ip_cidr` | Azion |

A lista `2` contém os endereços IP de exit nodes do Tor, e a Azion a fornece a todas as contas. O `last_editor` dela mostra `Azion`, e o `last_modified` muda quando a Azion atualiza os itens. Uma regra a usa como qualquer lista que você cria, com `2` como argumento de `${network}`. Para ver uma regra que a usa, consulte [Bloqueie exit nodes do Tor](/pt-br/documentacao/guias/seguranca-de-aplicacoes/bots-e-rede/bloquear-redes-tor/).

Qualquer gravação em uma lista mantida pela Azion é recusada com `22004`, mesmo uma gravação que não altera nada.

Uma conta também recebe a lista `Azion Origin Shield` quando pelo menos um dos seus [Connectors](/pt-br/documentacao/plataforma/connectors/) tem Origin IP ACL ativado. A lista contém os prefixos IPv4 e IPv6 que a infraestrutura da Azion usa para se conectar às origens. A página [Origin Shield](/pt-br/documentacao/plataforma/connectors/origin-shield/) documenta essa lista e como a Azion anuncia as atualizações dela.

## O critério Network

Uma regra de Firewall usa uma Network List por meio do critério `${network}`. A tabela nomeia a variável, os dois operadores, o argumento e a configuração de Firewall que o critério exige:

| Parte | API | Azion Console | O que faz |
| --- | --- | --- | --- |
| Variável | `${network}` | _Network_ | Compara o endereço do cliente que enviou a requisição, ou o ASN ou o país desse endereço, com a lista. |
| Operador | `is_in_list` | _matches_ | É verdadeiro quando o cliente está na lista. |
| Operador | `is_not_in_list` | _does not match_ | É verdadeiro quando o cliente não está na lista. |
| Argumento | O `id` da lista, como inteiro JSON | O nome da lista, escolhido em **Select a Network** | Nomeia a lista. Um `id` enviado como string é recusado com `25042`. |
| Requisito | `modules.network_protection.enabled` definido como `true` | **Main Settings** > **Modules** > **Network Shield** | O Firewall precisa estar com Network Shield ativado, e um Firewall novo vem com ele ativado por padrão. Caso contrário, a regra é recusada com `25047`, e o Console mostra a variável como _Network - required Network Shield_. Network Shield ativado também atende à condição de toda regra, que exige pelo menos um de [Web Application Firewall (WAF)](/pt-br/documentacao/plataforma/firewall/waf/), Network Shield ou [Functions](/pt-br/documentacao/plataforma/functions/) ativado. |

Uma lista funciona como blocklist com _matches_ e _Deny (403 Forbidden)_, e como allowlist com _does not match_ e o mesmo comportamento. Em um corpo de requisição para `/v4/workspace/firewalls/{firewall_id}/request_rules`, o critério é uma entrada de um bloco `criteria`:

```json
{
  "name": "Deny listed addresses",
  "active": true,
  "criteria": [
    [
      { "variable": "${network}", "conditional": "if", "operator": "is_in_list", "argument": <network-list-id> }
    ]
  ],
  "behaviors": [ { "type": "deny" } ]
}
```

Para conhecer os outros critérios que uma regra pode encadear com `${network}` e os comportamentos que uma regra aplica quando corresponde, consulte [Rules Engine para Firewall](/pt-br/documentacao/plataforma/firewall/rules-engine/#criterios). Para conhecer a janela de contagem e a chave de um rate limit, consulte [Set Rate Limit](/pt-br/documentacao/plataforma/firewall/rules-engine/#set-rate-limit).

## API

Toda operação fica sob `https://api.azion.com/v4` e carrega um token de [Personal Tokens](/pt-br/documentacao/fundamentos/personal-tokens/) em um header `Authorization: Token [TOKEN VALUE]`. Uma requisição com corpo também envia `Content-Type: application/json`. Para mais informações, consulte [Azion API](/pt-br/documentacao/devtools/api/).

| Método | Caminho | O que faz |
| --- | --- | --- |
| `GET` | `/v4/workspace/network_lists` | Lista as Network Lists da conta, incluindo as listas mantidas pela Azion, sem os `items`. Responde `200`. |
| `POST` | `/v4/workspace/network_lists` | Cria uma lista. Responde `201` com um `state` igual a `executed`. |
| `GET` | `/v4/workspace/network_lists/{network_list_id}` | Retorna uma lista com os `items`. Responde `200` sem a chave `state`. |
| `PUT` | `/v4/workspace/network_lists/{network_list_id}` | Substitui uma lista e exige `name`, `type` e `items`. Responde `200`. |
| `PATCH` | `/v4/workspace/network_lists/{network_list_id}` | Altera os campos que envia. Responde `200`. |
| `DELETE` | `/v4/workspace/network_lists/{network_list_id}` | Exclui uma lista. Responde `200` com um `state` igual a `executed`, ou `400` com `22018` enquanto uma regra usa a lista. |

Um `PATCH` que envia `items` substitui o array inteiro em vez de acrescentar itens a ele, então uma atualização envia todos os itens que a lista mantém. Para adicionar ou remover itens avulsos sem reenviar a lista, use `--add-item` e `--remove-item` na Azion CLI.

`GET /v4/workspace/network_lists` aceita estes parâmetros de query, e a resposta carrega `count`, `total_pages`, `page`, `page_size`, `next`, `previous` e `results`:

| Parâmetro | O que faz |
| --- | --- |
| `id` | Filtra por id. Aceita valores separados por vírgula. |
| `name` | Filtra por nome, com correspondência parcial que não diferencia maiúsculas de minúsculas. |
| `last_editor` | Filtra pelo último editor, com correspondência parcial que não diferencia maiúsculas de minúsculas. |
| `last_modified__gte`, `last_modified__lte` | Filtra por uma data de última alteração igual ou posterior, ou igual ou anterior, ao valor. |
| `list_type__in` | Filtra por tipo. Aceita valores separados por vírgula. O parâmetro mantém o nome `list_type`, embora o campo seja `type`. |
| `search` | Filtra por um termo de busca. |
| `ordering` | Nomeia o campo que ordena os resultados. |
| `fields` | Nomeia os campos a retornar, separados por vírgula. |
| `page` | Seleciona uma página de resultados. |
| `page_size` | Define quantas listas vêm por página, de 1 a 100. O padrão é 10. |

`GET /v4/workspace/network_lists/{network_list_id}` também aceita `fields`. Em uma lista `ip_cidr`, `ipv4=true` retorna apenas os itens IPv4, e `ipv6=true` apenas os itens IPv6.

Esta requisição cria uma lista `ip_cidr` e envia `192.0.2.10` duas vezes:

```bash
curl -X POST https://api.azion.com/v4/workspace/network_lists \
  -H "Authorization: Token [TOKEN VALUE]" \
  -H "Accept: application/json" \
  -H "Content-Type: application/json" \
  -d '{"name":"Blocked addresses","type":"ip_cidr","items":["192.0.2.10","198.51.100.0/24","2001:db8::/32","192.0.2.10"]}'
```

A resposta carrega `201` e armazena o endereço repetido uma única vez:

```json
{
  "state": "executed",
  "data": {
    "id": <network-list-id>,
    "name": "Blocked addresses",
    "type": "ip_cidr",
    "items": ["192.0.2.10", "198.51.100.0/24", "2001:db8::/32"],
    "last_editor": "<your-email>",
    "last_modified": "2026-01-01T12:00:00.000000Z",
    "created_at": "2026-01-01T12:00:00.000000Z",
    "active": true,
    "version_id": null,
    "version_state": null,
    "is_versioned": false,
    "version": null
  }
}
```

## CLI

[Azion CLI](/pt-br/documentacao/devtools/cli/) gerencia Network Lists com o substantivo `network-list`. A tabela lista as flags da Azion CLI 4.26.2.

| Comando | O que faz | Flags principais |
| --- | --- | --- |
| `azion create network-list` | Cria uma lista. | `--name`, `--type`, `--items`, `--active`, `--file` |
| `azion list network-list` | Lista as Network Lists da conta. | `--details`, `--filter`, `--order-by`, `--page` (padrão `1`), `--page-size` (padrão `50`) |
| `azion describe network-list` | Retorna uma lista. | `--network-list-id`, `--format json` |
| `azion update network-list` | Altera uma lista. | `--network-list-id`, `--name`, `--items`, `--add-item`, `--remove-item`, `--active`, `--file` |
| `azion delete network-list` | Exclui uma lista. | `--network-list-id` |

`--type` aceita `asn`, `countries` ou `ip_cidr`, e `--items`, `--add-item` e `--remove-item` aceitam valores separados por vírgula. `--items` substitui todos os itens, como faz um `PATCH`, enquanto `--add-item` e `--remove-item` leem a lista primeiro e alteram apenas os itens que nomeiam. `--remove-item` encontra um item exatamente como está armazenado, incluindo a data de expiração `--LT` e o comentário `#`. Com apenas o endereço de um item com anotação, ele não altera nada e ainda assim imprime `Updated Network List with ID <network-list-id>`. `--file` aceita um arquivo JSON com os campos de Campos da Network List. `azion update network-list` também aceita `--type`, que a API recusa com `22002` porque um tipo nunca muda.

A flag de id é `--network-list-id`, e `--id` é recusada como flag desconhecida. Sem `--items` nem `--file`, `azion create network-list` pede os itens e falha quando nenhum terminal responde, então um script sempre passa uma das duas. `azion list network-list --format json` imprime as colunas da tabela, e não os registros. Na Azion CLI 4.26.2, `azion list network-list --filter` retornou todas as listas, qualquer que fosse o valor recebido. A ajuda de `azion describe network-list` mostra `--with-code` em um exemplo, e o comando a recusa como flag desconhecida.

Uma criação pela linha de comando imprime o id novo:

```bash
azion create network-list --name "Blocked countries" --type countries --items "DE,US"
```

```text
Created Network List with ID <network-list-id>
```

Um item adicionado a uma lista existente mantém os itens que já estão nela:

```bash
azion update network-list --network-list-id <network-list-id> --add-item "192.0.2.72"
```

```text
Updated Network List with ID <network-list-id>
```

Uma exclusão imprime `Network List <network-list-id> was successfully deleted`. Quando a API recusa um comando, a CLI imprime o detalhe da API. A exclusão de uma lista em uso imprime `Error: Failed to delete Network List: ["You can not delete the network list in use by Firewall(s)."]`.

## Erros

Uma requisição recusada retorna um array `errors`. Cada entrada carrega um `code`, um `title`, um `detail`, o `status` e um ponteiro `source` que nomeia o campo. Um erro de item acrescenta `meta.index` e `meta.value`, e nomeia apenas o primeiro item inválido. Este corpo responde a uma criação cujos itens são `192.0.2.1`, `abc` e `198.51.100.300`, e aponta apenas `abc`:

```json
{
  "errors": [
    {
      "code": "22005",
      "title": "Invalid IP CIDR",
      "detail": "IP CIDR is invalid.",
      "status": "400",
      "source": { "pointer": "/data/items" },
      "meta": { "index": 1, "value": "abc" }
    }
  ]
}
```

`meta.index` conta os itens que restam depois que os itens expirados são descartados, então ele pode ser menor que a posição do item na requisição. Todos os erros da tabela respondem `400`, exceto `10004`, que responde `404`. A coluna Mensagem cita o `detail`.

| Código | Título | Mensagem | Causa | Correção |
| --- | --- | --- | --- | --- |
| `10004` | Not Found | `Not found.` | O id da lista não existe na conta, ou a lista foi excluída. | Leia os ids com `GET /v4/workspace/network_lists`. |
| `10018` | Blank Field | `This field may not be blank.` | `name` é uma string vazia. | Envie um nome. |
| `10039` | Invalid Choice | `"<value>" is not a valid choice.` | Um `type` diferente de `ip_cidr`, `asn` ou `countries`, como `geo`. Em uma regra, a variável escrita como `$(network)`. | Envie um dos três tipos e escreva a variável como `${network}`. |
| `10046` | Max Length | `Ensure this field has no more than 250 characters.` | Um `name` ou um item com mais de 250 caracteres, incluindo as anotações. | Encurte o valor que o ponteiro `source` nomeia. |
| `10049` | Min Length List Field | `Ensure this field has at least 1 elements.` | Um array `items` vazio. | Envie pelo menos um item. |
| `10059` | Required Field | `This field is required.` | Falta um campo obrigatório, como `type` em uma criação ou `type` e `items` em um `PUT`. Um corpo que usa os nomes da v3 `list_type` e `ip_list` recebe o erro duas vezes, para `type` e `items`. | Envie `name`, `type` e `items`. |
| `10065` | List Field Max Length | `Ensure this field has no more than 20000 elements.` | Mais de 20.000 itens. | Envie 20.000 itens ou menos. |
| `10097` | Invalid Page Size | `Page size must be between 0 and 100.` | Um `page_size` acima de 100, ou `0`, na operação de listagem. A mensagem admite 0, e a API o recusa. | Peça de 1 a 100 listas por página. |
| `22002` | Cannot Change Network List Type | `You can not change the network list type.` | Uma atualização que envia um `type` diferente do tipo da lista. | Crie uma Network List do tipo de que você precisa e aponte as regras para ela. |
| `22003` | Cannot Disable Network List In Use | `You can not disable the network list in use by Firewall(s).` | `active: false` em uma lista que uma regra usa. | Altere ou exclua as regras que usam a lista. |

| `22005` | Invalid IP CIDR | `IP CIDR is invalid.` | Um item `ip_cidr` que não é um endereço ou intervalo IPv4 ou IPv6, incluindo uma linha que começa com `#` e um `--lt` em minúsculas. | Corrija o item que `meta.index` e `meta.value` nomeiam. |
| `22007` | Due Date Invalid Format | `Due date with invalid format, needs to start with --LT and end with Z.` | Uma data de expiração sem hora, ou com frações de segundo. | Escreva a data como `--LTYYYY-MM-DDTHH:MM:SSZ`. |
| `22009` | Invalid Commentary Prefix | `Commentary must start with #.` | Um `--LT` depois do `#` de um comentário, como `192.0.2.2 #x --LT2030-01-01T00:00:00Z`. | Coloque a data de expiração antes do comentário. |
| `22011` | Invalid ASN Number | `This ASN Number is not valid.` | Um item `asn` que não tem apenas dígitos ou que fica fora do intervalo de Tipos de lista, como `abc`, `AS64496` ou um item com comentário. | Envie apenas o número. |

| `22018` | Cannot Delete In Use Network List | `You can not delete the network list in use by Firewall(s).` | Um `DELETE` em uma lista que uma regra usa. | `22019` | All Network Items Are Expired | `All items in the network items are past their expiration date.` | Todos os itens carregam uma data de expiração que já passou. | Envie pelo menos um item sem data de expiração ou com uma data futura. |

| `25030` | Entity Not Found | `Network List '<network-list-id>' not found.` | Um argumento de `${network}` que nomeia uma lista que a conta não tem. | Envie o id de uma lista da conta. |
| `25031` | Entity Not Active | `Network List '<network-list-id>' is not active.` | Um argumento de `${network}` que nomeia uma lista com `active: false`. | Defina o `active` da lista como `true` e, depois, crie a regra. |
| `25039` | Invalid Operator | `The operator 'matches' is not valid for the '${network}' variable.` | `matches`, o rótulo do Console, enviado como operador de `${network}`. | Envie `is_in_list` ou `is_not_in_list`. |
| `25042` | Invalid Operator Argument Type | `The argument type '<network-list-id>' is not valid for the operator 'is_in_list'.` | Um argumento de `${network}` enviado como string JSON. | Envie o id da lista como inteiro JSON. |

## Limites

Uma Network List comporta de 1 a 20.000 itens de até 250 caracteres cada, com um nome de 1 a 250 caracteres, e uma requisição de listagem retorna até 100 listas por página. Para conhecer cada limite e o que acontece quando ele é ultrapassado, consulte [Limites de Firewall](/pt-br/documentacao/plataforma/firewall/limites/#network-shield).
