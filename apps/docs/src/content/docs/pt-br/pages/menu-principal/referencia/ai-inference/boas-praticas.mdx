O código que chama um modelo decide quem pode fazer a chamada, qual modelo responde, o que o modelo lê e o que o chamador recebe de volta. Cada uma dessas decisões é tomada no seu código, antes ou depois da chamada. Deixadas no padrão, um endpoint responde a qualquer um, um campo digitado errado não muda nada e não gera erro, e uma resposta lida de forma direta demais quebra no primeiro modelo que responde de outro jeito.

No [AI Inference](/pt-br/documentacao/plataforma/ai-inference/), esse código é uma [Function](/pt-br/documentacao/plataforma/functions/), e ela chama um modelo com `Azion.AI.run`. Os campos da requisição estão em [Invocação de modelos](/pt-br/documentacao/plataforma/ai-inference/invocacao-de-modelos/), as condições que Azion aplica a um modelo estão em [Limites do AI Inference](/pt-br/documentacao/plataforma/ai-inference/limites/), e o caminho de uma requisição está em [Como AI Inference funciona](/pt-br/documentacao/plataforma/ai-inference/como-funciona/).

Em ordem, as práticas cobrem a checagem de cada requisição, os modelos que uma requisição alcança, o id do modelo, as capacidades de cada modelo, a grafia de cada campo, o tamanho da entrada e da saída, a leitura da resposta e os erros. Os espécimes são JavaScript para uma Function e corpos de requisição em JSON.

## Confira cada requisição na Function antes de ela chamar um modelo

O template [AI Inference Starter Kit](/pt-br/documentacao/guias/desenvolvimento-de-aplicacoes/frameworks/ai-inference-starter-kit/) não configura nenhuma autenticação na frente do endpoint dele, e a regra dele executa a Function em todo path. Qualquer cliente que alcança o domínio pode, portanto, chamar um modelo, e cada chamada é cobrada em Compute Time e Requests. O custo de uma checagem é um segredo a guardar e um header que todo cliente envia.

Esta Function recusa uma requisição cujo header `Authorization` não carrega o segredo, antes de `Azion.AI.run` rodar. O formato completo também carrega a checagem de modelo da próxima prática e o tratamento de erros da última:

```js
const ALLOWED_MODELS = ["Qwen/Qwen3-30B-A3B-Instruct-2507-FP8"];

async function handleRequest(request) {
  const secret = Azion.env.get("INFERENCE_SECRET");
  if (!secret || request.headers.get("Authorization") !== `Bearer ${secret}`) {
    return new Response(JSON.stringify({ error: "Unauthorized" }), {
      status: 401,
      headers: { "Content-Type": "application/json" },
    });
  }

  const input = await request.json();
  const model = input["model"];
  if (!ALLOWED_MODELS.includes(model)) {
    return new Response(JSON.stringify({ error: `${model} is not allowed` }), {
      status: 403,
      headers: { "Content-Type": "application/json" },
    });
  }

  try {
    const modelResponse = await Azion.AI.run(model, input);
    return new Response(JSON.stringify(modelResponse), {
      headers: { "Content-Type": "application/json" },
    });
  } catch (e) {
    console.error(`${e.name}: ${e.message}`);
    if (e.message.includes("validation error")) {
      return new Response(JSON.stringify({ error: `Invalid input for ${model}` }), {
        status: 400,
        headers: { "Content-Type": "application/json" },
      });
    }
    if (e.message.includes("model not found")) {
      return new Response(JSON.stringify({ error: `${model} not found or not allowed` }), {
        status: 400,
        headers: { "Content-Type": "application/json" },
      });
    }
    return new Response(JSON.stringify({ error: "AI internal error" }), {
      status: 500,
      headers: { "Content-Type": "application/json" },
    });
  }
}

addEventListener("fetch", (event) => {
  event.respondWith(handleRequest(event.request));
});
```

`Azion.env.get` lê o segredo de uma variável de ambiente guardada na sua conta Azion, conforme [API de variáveis de ambiente](/pt-br/documentacao/devtools/runtime/api-reference/environment-variables/). Quando a variável não existe, a chamada retorna `undefined`, e a Function recusa todas as requisições. A checagem cobre todos os domínios do Workload: um domínio personalizado responde além do workload domain, e só o switch **Workload Domain Allow Access** do Workload fecha o workload domain.

Para conferir, envie uma requisição sem o header: a Function responde `401`.

## Escolha na Function quais modelos uma requisição alcança

A Function que o template instala passa o campo `model` do corpo da requisição para `Azion.AI.run` como ele chega. Um cliente pode, portanto, selecionar qualquer modelo que a conta pode chamar, inclusive um cujo contexto, capacidades ou consumo você nunca previu. O custo é uma lista a atualizar a cada modelo que você adota.

Na Function da primeira prática, a lista é `const ALLOWED_MODELS = ["Qwen/Qwen3-30B-A3B-Instruct-2507-FP8"];`, e uma requisição que indica outro modelo recebe `403`. Para mapear nomes seus para ids de modelo, com uma chave por time, consulte [Rotear chamadas de modelo por uma Function de gateway](/pt-br/documentacao/guias/ai/inferencia/rotear-chamadas-de-modelo-por-uma-function-de-gateway/).

Para conferir, envie uma requisição cujo `model` não está na lista: a Function responde `403`, e nenhum modelo roda.

## Copie cada id de modelo da página do modelo, ou liste os ids com Azion.AI.models()

Um modelo responde ao id dele e a nada mais: o primeiro argumento de `Azion.AI.run`, ou o campo `model` por HTTP, sem URL base nem host ao lado. Os ids não decorrem do nome do modelo. Duas formas podem selecionar o mesmo modelo, `Qwen/Qwen2.5-VL-3B-Instruct-AWQ` e `qwen-qwen25-vl-3b-instruct-awq`, e nenhuma regra simples transforma uma na outra: `Qwen2.5` vira `qwen25`. O GPT-OSS 20B responde a `openai/gpt-oss-20b`, enquanto `gpt-oss-20b` é recusado.

Copie o id da página do modelo em [Modelos de AI](/pt-br/documentacao/plataforma/ai-inference/modelos/), ou liste os ids que a sua conta pode chamar a partir de uma Function:

```js
const modelIds = await Azion.AI.models();
```

Nunca use o campo `model` de uma resposta como id: ele carrega um id interno, e o GPT-OSS 20B retorna `gpt-oss-20b`, a forma que é recusada.

Para conferir, execute a chamada uma vez: um id errado é recusado com `AIError: model not found or not allowed`. Uma conta sem acesso ao AI Inference recebe o mesmo erro, então confirme o acesso em [Limites do AI Inference](/pt-br/documentacao/plataforma/ai-inference/limites/) primeiro.

## Envie a cada modelo somente as requisições que a página dele diz que ele serve

O que um modelo aceita pertence a esse modelo. Cada página em [Modelos de AI](/pt-br/documentacao/plataforma/ai-inference/modelos/) declara o comprimento de contexto, de 8k a 131k tokens no catálogo, os tipos de entrada, somente texto ou texto e imagens, e a chamada de ferramentas: Sim, Só com a ferramenta nomeada ou Não. O servidor do modelo recusa um prompt maior que o contexto, e uma requisição com `tools` que deixa a escolha a um modelo cuja chamada de ferramentas não é Sim, com `Request failed with status 400`. A mensagem não diz qual valor causou a recusa. Quando uma página não declara nada, a capacidade é desconhecida, não ausente: confirme-a antes que o seu código dependa dela.

Por exemplo, o Qwen2.5 VL AWQ 3B e o 7B recusam uma requisição com `tools` que deixa a escolha para o modelo, e retornam `tool_calls` quando o corpo indica a ferramenta: `"tool_choice": {"type": "function", "function": {"name": "get_weather"}}`. O custo é uma checagem por modelo no seu código, já que a plataforma informa a incompatibilidade só como um status.

Para conferir, leia a capacidade na página do modelo sempre que uma chamada falhar com status `400`.

## Escreva cada campo da requisição como Invocação de modelos o lista

Um campo que o modelo não conhece é ignorado, sem erro. Um campo escrito errado, portanto, não muda nada na resposta, e nada avisa que ele não foi aplicado. O custo é uma conferência em [Invocação de modelos](/pt-br/documentacao/plataforma/ai-inference/invocacao-de-modelos/) sempre que você acrescenta um campo.

Um corpo que define a temperatura de amostragem a escreve `"temperature": 0.7`. Escrito como `"temprature": 0.7`, o campo é ignorado, e a requisição roda como se não tivesse temperatura.

Para conferir, envie o campo uma vez com um valor além do limite dele, como `"temperature": 2.1`: um campo escrito certo é recusado com `validation error: Maximum`, e um escrito errado retorna uma resposta normal.

## Envie ao modelo somente a entrada de que ele precisa e limite a saída

Tudo o que um modelo lê vem da sua Function, na mesma execução que aguarda a resposta. O modelo lê o prompt inteiro, e o tempo que ele leva para gerar é tempo que a Function espera. Essa espera não conta no limite de 2 segundos de CPU da Function, mas conta no tempo de execução de 5 minutos dela, que é tempo de relógio, conforme [Limites de Functions](/pt-br/documentacao/plataforma/functions/limites/). AI Inference cobra Compute Time e Requests, e o Compute Time, a duração da execução ativa multiplicada pela memória alocada, cresce com uma geração mais longa.

Envie a seção de um documento que responde à pergunta, não o documento inteiro, e defina `max_tokens` em todo corpo, como `"max_tokens": 1024`. O custo é uma margem a manter: o GPT-OSS 20B raciocina antes de responder, e com um `max_tokens` pequeno o raciocínio pode usar todo o orçamento e retornar `content` igual a `null`.

Para conferir, leia `usage.prompt_tokens` e `usage.completion_tokens` na resposta antes e depois de mudar um prompt.

## Leia a resposta com optional chaining e confira por que ela parou

O texto gerado por um modelo de chat fica quatro níveis dentro da resposta, em `choices[0].message.content`, e esse texto nem sempre está lá. `content` é `null` quando o modelo retorna `tool_calls`, e no GPT-OSS 20B quando o raciocínio usa todo o `max_tokens`. Com `stream` igual a `true`, `Azion.AI.run` resolve para um iterador assíncrono de chunks, sem nenhum `choices[0].message`.

Leia cada nível com optional chaining, para que um nível ausente retorne `undefined` em vez de lançar um erro dentro da Function:

```js
const summary = modelResponse?.choices?.[0]?.message?.content?.trim();
```

O custo é um desvio para o caso vazio. Para conferir, leia `choices[0].finish_reason` sempre que o texto vier vazio: `tool_calls` significa que o modelo escolheu uma ferramenta, e `length` significa que o `max_tokens` acabou.

## Distinga os três tipos de falha pela mensagem

Uma chamada a `Azion.AI.run` que falha rejeita com um erro que carrega somente `name` e `message`, sem `code` nem `status`. A mensagem distingue os casos. `AIError: model not found or not allowed` cobre um id que não existe e uma conta sem acesso. `AIError: validation error` cobre um corpo que não corresponde ao schema do modelo, antes de o modelo rodar. `Error: Request failed with status <N>` cobre uma recusa do servidor do modelo, sem motivo.

A Function da primeira prática desvia pela mensagem: `e.message.includes("validation error")` e `e.message.includes("model not found")` respondem `400`, e qualquer outro erro responde `500`. Ela também escreve cada erro com `console.error`. O custo é que uma recusa do servidor do modelo chega ao chamador sem causa, então a Function não consegue dizer ao chamador o que mudar. Para todos os erros e as causas deles, consulte [Invocação de modelos](/pt-br/documentacao/plataforma/ai-inference/invocacao-de-modelos/#erros).

Para conferir, abra [Real-Time Events](/pt-br/documentacao/plataforma/real-time-events/): a fonte de dados Functions Console carrega as linhas que a Function escreve com `console.error`, mensagens `AIError` incluídas.
