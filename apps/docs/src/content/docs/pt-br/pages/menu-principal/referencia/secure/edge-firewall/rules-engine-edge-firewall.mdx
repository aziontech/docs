Rules Engine para Firewall é a feature de [Firewall](/pt-br/documentacao/plataforma/firewall/) que guarda as regras que um Firewall aplica a cada requisição antes que a [Application](/pt-br/documentacao/plataforma/applications/) a receba. Uma regra combina critérios, que decidem se uma requisição corresponde, com comportamentos, que a regra aplica a cada requisição que corresponde. Uma regra que escolhe como uma Application serve uma requisição permitida pertence ao [Rules Engine para Applications](/pt-br/documentacao/plataforma/applications/rules-engine/).

---

## Campos da regra

Cada Firewall tem a sua própria lista de regras, que Azion Console mostra na aba **Rules Engine** e a API disponibiliza em `/v4/workspace/firewalls/<firewall-id>/request_rules`. No Console, **Rule** abre o drawer **Create Rule**, e cada tabela desta página mostra o rótulo do Console ao lado do valor da API. Uma regra carrega 10 campos: cinco que uma requisição define e cinco que a plataforma define e retorna.

| Campo | Tipo | Obrigatório | Padrão | Descrição |
| --- | --- | --- | --- | --- |
| `id` | integer | Somente leitura | — | O identificador que toda chamada posterior sobre a regra usa. A lista de regras não o mostra, e `azion list firewall-rule` o imprime como `ID` |
| `name` | string, de 1 a 100 caracteres | Sim | — | O nome da regra, único no Firewall. O Console o mostra como o campo **Name** e pede um nome único e descritivo |
| `description` | string, até 1.000 caracteres | Não | `""` | Um comentário sobre a regra, mostrado na coluna **Description** da lista de regras. Com mais de 1.000 caracteres, o Console mostra `Description should not exceed 1000 characters` |
| `active` | boolean | Não | `true` | Se a regra está ativa. O Console o mostra como o switch **Active** na seção **Status**, e a lista de regras mostra _Active_ ou _Inactive_ |
| `criteria` | array de 1 a 5 blocos, cada um sendo um array de 1 a 10 critérios | Sim | — | As condições que uma requisição precisa atender. Cada valor está listado em Critérios |
| `behaviors` | array de 1 a 10 objetos de comportamento | Sim | — | O que a regra faz com uma requisição que corresponde. Cada valor está listado em Comportamentos |
| `order` | integer | Somente leitura | Atribuído na criação | A posição da regra na lista de regras do Firewall |
| `last_editor` | string | Somente leitura | — | A conta que alterou a regra pela última vez, mostrada na coluna **Last Editor** |
| `last_modified` | date-time | Somente leitura | — | Quando a regra foi alterada pela última vez, mostrado na coluna **Last Modified** |
| `created_at` | date-time | Somente leitura | — | Quando a regra foi criada |

A plataforma atribui `order` na ordem de criação: a primeira regra de um Firewall carrega `0`, e a décima primeira carrega `10`. O Console numera as mesmas posições a partir de `1`, então a regra cujo `order` é `0` é a que a lista dele mostra como `1`. Para mudar a ordem, reordene as regras na lista de regras do Console, ou envie os IDs de todas as regras na nova ordem pela API ou pela CLI.

## Critérios

Os critérios decidem sobre quais requisições uma regra age. Cada critério nomeia uma variável, um operador de comparação e, para a maioria dos operadores, um argumento com o qual a variável é comparada. O drawer **Create Rule** abre com um critério já definido como _Request Uri_ e _starts with_, e `${request_uri}` `starts_with` `/` corresponde a toda requisição que o Workload recebe.

A tabela lista as variáveis na ordem do Console. Nove delas exigem [Web Application Firewall (WAF)](/pt-br/documentacao/plataforma/firewall/waf/) no Firewall, e `Network` exige [Network Shield](/pt-br/documentacao/plataforma/firewall/network-shield/). As outras cinco funcionam quando qualquer um de WAF, Network Shield ou [Functions](/pt-br/documentacao/plataforma/functions/) está ativado: com os três desativados, a API recusa toda regra com `25047`, quaisquer que sejam os critérios dela.

| Variável | Variável na API | Requer | O que contém | Exemplo |
| --- | --- | --- | --- | --- |
| Header Accept | `${header_accept}` | WAF | Os media types que o cliente aceita na resposta | `application/json` |
| Header Accept Encoding | `${header_accept_encoding}` | WAF | As codificações de conteúdo, em geral algoritmos de compressão, que o cliente aceita na resposta | `gzip` |
| Header Accept Language | `${header_accept_language}` | WAF | O idioma que o cliente espera | `en-US` |
| Header Cookie | `${header_cookie}` | WAF | Os cookies que o cliente envia com a requisição | `session_id=abc123` |
| Header Origin | `${header_origin}` | WAF | A origem de uma requisição cross-site ou de uma requisição preflight: uma URI que nomeia o servidor, sem caminho | `https://example.com` |
| Header Referer | `${header_referer}` | WAF | O endereço do documento, ou do elemento nele, de onde a URI da requisição foi obtida | `https://example.com/landing-page` |
| Header User Agent | `${header_user_agent}` | WAF | A string que identifica a aplicação cliente, o sistema operacional, o fornecedor ou a versão | `Mozilla/5.0` |
| Host | `${host}` | Qualquer um de WAF, Network Shield, Functions | Em ordem de precedência: o hostname na linha da requisição, o valor do header `Host` ou o nome do servidor que atende a requisição | `api.example.com` |
| Network | `${network}` | Network Shield | O endereço IP do cliente, comparado com os endereços IP e intervalos CIDR, os ASNs ou os países de uma Network List | `2` |
| Request Args | `${request_args}` | WAF | Os argumentos na query string da requisição | `page=1` |
| Request Method | `${request_method}` | WAF | O método HTTP da requisição | `POST` |
| Request Uri | `${request_uri}` | Qualquer um de WAF, Network Shield, Functions | A URI da requisição, sem a query string | `/api/v1/` |
| Scheme | `${scheme}` | Qualquer um de WAF, Network Shield, Functions | O esquema da requisição, HTTP ou HTTPS | `https` |
| Ssl Verification Status | `${ssl_verification_status}` | Qualquer um de WAF, Network Shield, Functions | O resultado da verificação do certificado de cliente, em um de três valores fixos | `CERTIFICATE_VERIFICATION_ERROR` |
| Client Certificate Validation | `${client_certificate_validation}` | Qualquer um de WAF, Network Shield, Functions | Se o certificado de cliente passou na verificação | `true` |

Quando o Firewall não tem o recurso aninhado que uma variável exige, o Console ainda lista a variável, mas não permite selecioná-la. O rótulo então carrega um sufixo, como _Header Accept - required WAF_ ou _Network - required Network Shield_. A API recusa essa regra com `400` e o código `25047`, e o `detail` nomeia a variável e o módulo de que ela precisa.

`Network` compara o endereço IP do cliente com uma [Network List](/pt-br/documentacao/plataforma/firewall/network-shield/network-lists/). No Console, o argumento passa a ser a lista **Select a Network**, que mostra todas as Network Lists da conta e termina com **Create Network List**. Na API, o argumento é o ID da lista como um inteiro JSON, e o mesmo ID enviado como string é recusado com `400` e o código `25042`. Por exemplo, `2` é a lista de exit nodes do Tor que a Azion fornece, e qualquer regra pode usá-la.

Depois que uma regra do Firewall usa `${network}`, Network Shield não pode ser desativado nesse Firewall. A API responde `400` com o código `24005` e nomeia as regras que o usam.

`Request Args` não contém nada quando a requisição não tem query string, e uma variável vazia não corresponde. Por exemplo, uma regra com `${request_args}` `matches` `.*` ignora todo POST que carrega o payload no corpo e nada na query string.

`Ssl Verification Status` recebe um de três valores, que o Console oferece na lista **Select an SSL status**:

| Valor | Argumento na API | Significado |
| --- | --- | --- |
| _Success_ | `SUCCESS` | O certificado do cliente passou na validação |
| _Certificate Verification Error_ | `CERTIFICATE_VERIFICATION_ERROR` | O certificado do cliente não era válido |
| _Missing Client Certificate_ | `MISSING_CLIENT_CERTIFICATE` | A requisição não carregava certificado de cliente |

`Client Certificate Validation` recebe um único valor, `true`, que o Console oferece como a entrada única _Valid_ na lista **Select a validation result**. O operador _is equal_ corresponde a uma requisição cujo certificado de cliente passou na validação, e _is not equal_ corresponde a uma que não carregava certificado ou cujo certificado não era válido. A API recusa qualquer outro argumento para as duas variáveis com `25046`.

### Operadores

Um critério compara a sua variável com o seu argumento por meio de um operador. O Console rotula cada operador em letras minúsculas, e a API envia o valor da segunda coluna como `operator`.

| Operador | Valor na API | O critério corresponde quando | Argumento |
| --- | --- | --- | --- |
| is equal | `is_equal` | O valor é igual ao argumento, comparado caractere por caractere | String |
| is not equal | `is_not_equal` | O valor não é exatamente o argumento | String |
| starts with | `starts_with` | O valor começa com o argumento | String |
| does not start with | `does_not_start_with` | O valor não começa com o argumento | String |
| matches | `matches` | O valor corresponde à expressão regular do argumento | Expressão regular |
| does not match | `does_not_match` | O valor não corresponde à expressão regular do argumento | Expressão regular |
| exists | `exists` | A variável tem um valor. `Request Args` existe quando a query string carrega um argumento | Nenhum |
| does not exist | `does_not_exist` | A variável não tem valor. `Request Args` não existe quando a query string não carrega nenhum argumento | Nenhum |

O Console oculta o campo de argumento para _exists_ e _does not exist_, e o substitui por uma lista para `Network`, `Ssl Verification Status` e `Client Certificate Validation`, que aceitam somente um valor da sua própria lista. A API recusa um argumento em _exists_ ou _does not exist_ com `25040`, e a falta de argumento em qualquer outro operador com `25041`.

`Network` é a exceção à tabela. Os seus _matches_ e _does not match_ carregam os valores de API `is_in_list` e `is_not_in_list`, e os dois comparam o endereço IP do cliente com a Network List que o argumento nomeia. A API recusa `matches` em `${network}` com `400` e o código `25039`.

Cada variável oferece apenas alguns dos operadores, e a API recusa qualquer outra combinação com `25039`:

| Variável | Operadores |
| --- | --- |
| Header Accept, Header Accept Encoding, Header Accept Language, Header Cookie, Header Origin, Header Referer, Header User Agent | matches, does not match |
| Host | is equal, is not equal, matches, does not match |
| Network | matches (`is_in_list`), does not match (`is_not_in_list`) |
| Request Args | is equal, is not equal, matches, does not match, exists, does not exist |
| Request Method | is equal, is not equal |
| Request Uri | is equal, is not equal, starts with, does not start with, matches, does not match |
| Scheme, Ssl Verification Status, Client Certificate Validation | is equal, is not equal |

### Condicionais

Os critérios se combinam dentro de blocos, e uma regra tem de 1 a 5 blocos de 1 a 10 critérios cada. Dentro de um bloco, o primeiro critério carrega o condicional `if`, e cada critério seguinte carrega `and` ou `or`. Os blocos são unidos por And, que o Console exibe entre eles, então uma requisição corresponde à regra somente quando corresponde a todos os blocos. A API recusa um primeiro critério que carrega `and` ou `or` com `25043`.

No Console, **And** e **Or** adicionam um critério a um bloco, e **Add Criteria** adiciona um bloco. O Console desabilita **And** e **Or** quando um bloco chega a 10 critérios, e **Add Criteria** quando a regra chega a 5 blocos. Os divisores entre critérios mostram o condicional como If, And ou Or.

Na API, `criteria` é uma lista de blocos, e cada bloco é uma lista de objetos de critério. A regra deste exemplo tem um bloco de dois critérios. Ela nega uma requisição somente quando o endereço IP do cliente está na Network List e a URI começa com `/ip-deny`:

```json
{
  "name": "ip-deny",
  "active": true,
  "criteria": [
    [
      { "variable": "${network}", "conditional": "if", "operator": "is_in_list", "argument": <network-list-id> },
      { "variable": "${request_uri}", "conditional": "and", "operator": "starts_with", "argument": "/ip-deny" }
    ]
  ],
  "behaviors": [{ "type": "deny" }]
}
```

O placeholder `<network-list-id>` representa um inteiro, sem aspas ao redor.

## Comportamentos

Os comportamentos são o que uma regra faz com uma requisição que corresponde aos seus critérios. O Console rotula a primeira linha de comportamento como **Then** e cada linha seguinte como **And**, e **Add Behavior** adiciona uma linha. Na API, cada comportamento é um objeto com um `type`, e os comportamentos que recebem configurações as carregam em `attributes`.

A coluna Requer nomeia o que o Firewall precisa ter ativado para o comportamento. Quando WAF ou Functions está desativado, o Console mostra _Set WAF - required WAF_ ou _Run Function - required Functions_ e não permite selecioná-lo. A API aceita _Set WAF_ quando qualquer um de WAF, Network Shield ou Functions está ativado.

| Comportamento | `type` na API | Requer | Atributos | O que o cliente recebe |
| --- | --- | --- | --- | --- |
| Deny (403 Forbidden) | `deny` | Qualquer um de WAF, Network Shield, Functions | Nenhum | `403`, com a página de erro padrão da Azion intitulada Forbidden |
| Drop (Close Without Response) | `drop` | Qualquer um de WAF, Network Shield, Functions | Nenhum | Nenhuma resposta: nem linha de status nem corpo |
| Set Rate Limit | `set_rate_limit` | Qualquer um de WAF, Network Shield, Functions | `type`, `limit_by`, `average_rate_limit`, `maximum_burst_size` | `429` para uma requisição que o limite não admite, com a página de erro padrão intitulada Too Many Requests |
| Set WAF | `set_waf` | WAF no Console; qualquer um de WAF, Network Shield, Functions na API | `waf_id`, `mode` | `400` para uma requisição que o rule set bloqueia no modo `blocking`, com a página de erro padrão intitulada Bad Request |
| Run Function | `run_function` | Functions | `value` | O que o código da Function Instance fizer com a requisição |
| Set Custom Response | `set_custom_response` | Qualquer um de WAF, Network Shield, Functions | `status_code`, `content_type`, `content_body` | O status code, o `Content-Type` e o corpo que os atributos definem |

Somente _Run Function_ e _Set WAF_ podem ser seguidos por outro comportamento, e cada um aparece no máximo uma vez em uma regra. No Console, escolher _Deny (403 Forbidden)_, _Drop (Close Without Response)_, _Set Rate Limit_ ou _Set Custom Response_ remove todas as linhas de comportamento depois dele. A API recusa um comportamento depois de _Deny_ ou _Drop_ com `25010`, um comportamento repetido com `25011` e _Deny_ seguido de _Drop_ com `25012`.

### Deny (403 Forbidden)

_Deny (403 Forbidden)_ recusa a requisição com `403` e não recebe atributos. O corpo é a página de erro padrão da Azion intitulada Forbidden, com cerca de 10 KB de HTML, que mostra o endereço IP do cliente e o ID da requisição. Nenhum header de resposta nomeia o Firewall ou a regra. Na API, o comportamento é `{ "type": "deny" }`.

### Drop (Close Without Response)

_Drop (Close Without Response)_ encerra a requisição sem respondê-la e não recebe atributos. O cliente não recebe linha de status nem corpo, de imediato. Um script que lê o status code vê `000`, e um navegador mostra um erro de conexão. Na API, o comportamento é `{ "type": "drop" }`.

Em HTTP/2, o curl informa o reset do stream e sai com o código 92:

```text
curl: (92) HTTP/2 stream 1 was not closed cleanly: PROTOCOL_ERROR (err 1)
```

Em HTTP/1.1 e em HTTP simples, o curl sai com o código 52:

```text
curl: (52) Empty reply from server
```

### Set Rate Limit

_Set Rate Limit_ limita a taxa das requisições a que a regra corresponde. Uma requisição que a taxa e o burst não admitem recebe `429`, com a página de erro padrão intitulada Too Many Requests. Com um limite por segundo, a resposta `429` carrega `retry-after: 1` e nenhum header `x-ratelimit-`.

| Atributo | Campo no Console | Valores | Descrição |
| --- | --- | --- | --- |
| `type` | **Rate Limit Type** | `second` (_Req/s_) ou `minute` (_Req/min_) | O período em que a taxa é contada. O padrão é `second` |
| `limit_by` | **Limit By** | `client_ip` (_Client IP address_) ou `global` (_Global_) | Se a taxa é contada por endereço IP do cliente ou sobre todas as requisições. Obrigatório. O Console pré-seleciona _Client IP address_ |
| `average_rate_limit` | **Average Rate Limit** | Inteiro, no mínimo 1 | As requisições permitidas por segundo ou por minuto, conforme `type` define. Obrigatório. O Console aceita até 31.536.000 |
| `maximum_burst_size` | **Maximum Burst Size** | Inteiro, no mínimo 1 | As requisições extras toleradas em um pico curto. Obrigatório quando `type` é `second`, e recusado com `25034` quando é `minute`. O Console oculta o campo para _Req/min_ |

Um rate limit de 10 requisições por segundo por endereço IP do cliente, com burst de 10:

```json
{
  "type": "set_rate_limit",
  "attributes": { "type": "second", "limit_by": "client_ip", "average_rate_limit": 10, "maximum_burst_size": 10 }
}
```

Para saber como a taxa e o burst admitem requisições, consulte [Como Firewall funciona](/pt-br/documentacao/plataforma/firewall/como-funciona/).

### Set WAF

_Set WAF_ aplica um [rule set](/pt-br/documentacao/plataforma/firewall/waf/rule-sets/) de WAF às requisições a que a regra corresponde. Um rule set só é executado quando uma regra carrega esse comportamento, e uma regra carrega no máximo um. Os rule sets ficam no Azion Console em **WAF Rules**.

:::note[nota]
Cada Firewall resolve os seus próprios comportamentos _Set WAF_: um rule set aplicado em um Firewall não muda o rule set que outro Firewall aplica. Dentro de um Firewall, quando duas regras que correspondem a uma requisição carregam _Set WAF_, o rule set e o modo da regra posterior foram aplicados nos testes, com critérios iguais ou diferentes. Consulte [Como Set WAF é resolvido entre firewalls](/pt-br/documentacao/plataforma/firewall/waf/score-e-modos/#como-set-waf-e-resolvido-entre-firewalls).
:::

| Atributo | Controle no Console | Valores | Descrição |
| --- | --- | --- | --- |
| `waf_id` | **Select a WAF** | Inteiro | O ID do rule set a aplicar. Obrigatório |
| `mode` | **Select a WAF mode** | `logging` (_Logging_) ou `blocking` (_Blocking_) | Se WAF recusa as requisições que o rule set sinaliza. Obrigatório |

No modo `blocking`, uma requisição que o rule set bloqueia recebe `400` com a página de erro padrão intitulada Bad Request, e nenhum header de resposta nomeia WAF. No modo `logging`, WAF não recusa a requisição. A API recusa um comportamento `set_waf` sem `mode` e qualquer `mode` diferente de `logging` ou `blocking`, inclusive `learning`.

Um comportamento que aplica um rule set no modo `blocking`:

```json
{ "type": "set_waf", "attributes": { "waf_id": <waf-rule-set-id>, "mode": "blocking" } }
```

### Run Function

_Run Function_ executa uma [Function Instance](/pt-br/documentacao/plataforma/firewall/functions-instances/) do Firewall nas requisições a que a regra corresponde, e exige Functions ativado no Firewall. Um Firewall criado pela API, pela CLI ou pela página de criação do Console tem Functions ativado, e o drawer de criação do Console começa com ele desativado.

O atributo `value` contém o ID da Function Instance, não o da Function. As instâncias ficam na aba **Functions Instances** do Firewall. No Console, **Select a Function** lista as instâncias deste Firewall, e **Create Function Instance** cria uma a partir dessa lista.

Um comportamento que executa uma Function Instance:

```json
{ "type": "run_function", "attributes": { "value": <function-instance-id> } }
```

Para criar uma instância, consulte [Instancie uma função em um firewall](/pt-br/documentacao/guias/seguranca-de-aplicacoes/firewall-e-waf/instanciar-functions/). Para o código que uma Function de Firewall executa, consulte [Functions no Firewall](/pt-br/documentacao/plataforma/firewall/functions/).

### Set Custom Response

_Set Custom Response_ responde à requisição com o status code, o content type e o corpo que define. As três configurações vão em `attributes`, como em todo comportamento que recebe configurações.

| Atributo | Campo no Console | Valores | Descrição |
| --- | --- | --- | --- |
| `status_code` | **Status Code** | Inteiro, de 200 a 499 | O status code da resposta. Obrigatório |
| `content_type` | **Content Type** | String, até 255 caracteres | O valor do header `Content-Type`. O padrão é uma string vazia |
| `content_body` | **Content Body** | String, até 500 caracteres | O corpo da resposta. O padrão é uma string vazia |

## API

Toda operação de regra é autenticada e fica em `https://api.azion.com/v4/workspace/firewalls/<firewall-id>/request_rules`. Uma requisição carrega um personal token no header `Authorization`, com o esquema `Token`, e uma requisição com corpo também carrega `Content-Type: application/json`.

| Operação | Método e caminho |
| --- | --- |
| Criar uma regra | `POST /request_rules` |
| Listar as regras de um Firewall | `GET /request_rules` |
| Consultar uma regra | `GET /request_rules/{request_rule_id}` |
| Atualizar uma regra | `PUT /request_rules/{request_rule_id}` |
| Atualizar parte de uma regra | `PATCH /request_rules/{request_rule_id}` |
| Excluir uma regra | `DELETE /request_rules/{request_rule_id}` |
| Reordenar as regras de um Firewall | `PUT /request_rules/order` |

Uma criação, uma atualização com `PUT` ou `PATCH`, uma reordenação e uma exclusão respondem `202`, e uma leitura responde `200`. Uma reordenação envia `order`, os IDs de todas as regras do Firewall na nova ordem, e responde com a lista reordenada. Uma lista que deixa de fora uma regra é recusada com `25002`.

Esta chamada cria uma regra que nega toda requisição cuja URI começa com `/deny-test`:

```bash
curl --request POST \
  --url https://api.azion.com/v4/workspace/firewalls/<firewall-id>/request_rules \
  --header 'Accept: application/json' \
  --header 'Authorization: Token [TOKEN VALUE]' \
  --header 'Content-Type: application/json' \
  --data '{
  "name": "deny-test",
  "active": true,
  "criteria": [[{ "variable": "${request_uri}", "conditional": "if", "operator": "starts_with", "argument": "/deny-test" }]],
  "behaviors": [{ "type": "deny" }]
}'
```

A resposta carrega `202` e um `state` igual a `pending`. Este trecho da resposta mantém os campos que a plataforma adicionou:

```text
{"state":"pending","data":{"id":<rule-id>,…,"behaviors":[{"type":"deny"}],"description":"","order":0}}
```

A plataforma adiciona `description`, uma string vazia quando a criação não envia nenhuma, e `order`, a posição da regra no Firewall. O `id` em `data` é o identificador que toda chamada posterior sobre a regra usa.

Um `PUT` ou um `PATCH` em `/request_rules/{request_rule_id}` também responde com um `state` igual a `pending`. A resposta carrega a regra inteira em `data`: os 10 campos que Campos da regra lista, com os valores novos. Um `GET` da regra enviado logo depois da atualização também retorna os valores novos, sem a chave `state`. Para verificar se a mudança em uma regra chegou ao tráfego, consulte [Propagação](/pt-br/documentacao/plataforma/firewall/como-funciona/#propagacao).

## CLI

Azion CLI gerencia regras com os comandos `firewall-rule` e `firewall-rule-order`. Os critérios e os comportamentos de uma regra vão no mesmo corpo JSON que a API recebe, que `create` e `update` leem de `--file`.

| Comando | O que faz |
| --- | --- |
| `azion create firewall-rule` | Cria uma regra a partir de um arquivo JSON, com `--firewall-id` e `--file` |
| `azion list firewall-rule` | Lista as regras de um Firewall, com `--firewall-id`. `--details` adiciona as colunas `LAST EDITOR` e `LAST MODIFIED` |
| `azion describe firewall-rule` | Retorna uma regra, com `--firewall-id` e `--rule-id`. `--format json` imprime o registro completo |
| `azion update firewall-rule` | Atualiza uma regra a partir de um arquivo JSON, com `--firewall-id`, `--rule-id` e `--file` |
| `azion delete firewall-rule` | Exclui uma regra, com `--firewall-id` e `--rule-id` |
| `azion update firewall-rule-order` | Reordena as regras de um Firewall, com `--firewall-id` e `--rule-ids`, os IDs das regras na nova ordem, separados por vírgula |

Este arquivo descreve uma regra que nega, em `/cli-rule`, as requisições dos países de uma Network List:

```json
{
  "name": "cli-rule",
  "description": "Deny requests from countries in the list on /cli-rule.",
  "active": true,
  "criteria": [
    [
      { "variable": "${network}", "conditional": "if", "operator": "is_in_list", "argument": <network-list-id> },
      { "variable": "${request_uri}", "conditional": "and", "operator": "starts_with", "argument": "/cli-rule" }
    ]
  ],
  "behaviors": [
    { "type": "deny" }
  ]
}
```

Salve-o como `rule.json`, substitua `<network-list-id>` pelo ID da lista como inteiro e crie a regra:

```bash
azion create firewall-rule --firewall-id <firewall-id> --file rule.json
```

```text
Created Firewall Rule with ID <rule-id>
```

## Erros

Toda regra, reordenação ou atualização de Firewall recusada nesta página responde `400` com um array `errors`. Cada entrada carrega um `code`, um `title`, um `detail`, o `status` e um ponteiro `source` que nomeia o campo, e algumas entradas adicionam um objeto `meta`:

```json
{
  "errors": [
    {
      "code": "25047",
      "title": "Missing Required Modules",
      "detail": "variable \"${network}\" is not available for this Edge Firewall. It requires ANY of the following modules to be enabled: ['network_protection_enabled'].",
      "status": "400",
      "source": { "pointer": "/data/criteria" },
      "meta": {
        "message_prefix": "variable \"${network}\" is not available for this Edge Firewall.",
        "owner_modules": "ANY",
        "missing_required_modules": ["network_protection_enabled"]
      }
    }
  ]
}
```

| Código | Título | Mensagem | Causa | Correção |
| --- | --- | --- | --- | --- |
| `10018` | Blank Field | `This field may not be blank.` | `name` é uma string vazia. | Envie um nome. |
| `10039` | Invalid Choice | `"<value>" is not a valid choice.` | Um campo enum tem um valor fora da sua lista, como a variável `$(network)`, o operador `does_not_starts_with`, um `conditional` diferente de `if`, `and` ou `or`, um `mode` igual a `learning` ou um `type` de rate limit igual a `hour`. | Envie um valor listado. O ponteiro `source` nomeia o campo, como `/data/criteria/0/0/conditional`. |
| `10046` | Max Length | `Ensure this field has no more than 100 characters.` | Uma string é maior que o seu máximo: 100 para `name`, 1.000 para `description`, 255 para `content_type` e 500 para `content_body`. | Encurte o valor. |
| `10049` | Min Length List Field | `Ensure this field has at least 1 elements.` | `criteria` ou `behaviors` é uma lista vazia. | Envie pelo menos um bloco e um comportamento. |
| `10050` | Min Value | `Ensure this value is greater than or equal to 1.` | `average_rate_limit` ou `maximum_burst_size` é menor que 1, ou `status_code` é menor que 200. | Envie um valor dentro do intervalo do atributo. |
| `10059` | Required Field | `This field is required.` | Falta um campo obrigatório, como `limit_by`, o `mode` de um comportamento `set_waf` ou `status_code`. | Adicione o campo que o ponteiro `source` nomeia. |
| `10065` | List Field Max Length | `Ensure this field has no more than 5 elements.` | Mais de 5 blocos, mais de 10 critérios em um bloco ou mais de 10 comportamentos. | Divida as condições entre regras. |
| `10068` | Max Value | `Ensure this value is less than or equal to 499.` | `status_code` é maior que 499. | Envie um status code de 200 a 499. |
| `24005` | Cannot Disable Firewall Network Protection Module | `Cannot disable firewall network protection module, because it is being referenced by the following rules: <rule-id>. Delete those rules or remove their network criteria, then disable the module.` | Desativar Network Shield em um Firewall cujas regras usam `${network}`. | Altere ou exclua as regras que a mensagem lista e, depois, desative Network Shield. |
| `25002` | Missing Rules In Order | `When ordering you should provide the order for all rules.` | Uma reordenação deixa de fora uma regra do Firewall. | Envie os IDs de todas as regras. |
| `25010` | Behavior Marked As Final | `The behavior 'deny' is marked as final. No subsequent behaviors can be configured after a final behavior.` | Um comportamento vem depois de _Deny_ ou _Drop_. | Coloque o comportamento final por último, ou mova o outro comportamento para outra regra. |
| `25011` | Duplicated Behavior | `The behavior 'deny' is duplicated.` | O mesmo comportamento aparece duas vezes em uma regra. Um _Set WAF_ repetido é nomeado `set_waf_ruleset_and_waf_mode`. | Mantenha um de cada comportamento. |
| `25012` | Incompatible Behavior | `The behavior 'deny' is incompatible with the following behaviors: ['drop'].` | _Deny_ seguido de _Drop_ na mesma regra. | Mantenha um dos dois. |
| `25030` | Entity Not Found | `Network List '<network-list-id>' not found.` | Um argumento de `${network}` nomeia uma Network List que não existe, ou um `value` de `run_function` nomeia uma Function Instance que não existe, com a mensagem `Function Instance '<id>' not found.` | Envie o ID de uma Network List ou de uma Function Instance existente. |
| `25031` | Entity Not Active | `Network List '<network-list-id>' is not active.` | Um argumento de `${network}` nomeia uma Network List inativa. | Ative a lista e, depois, crie a regra. |
| `25034` | Invalid Rate Limit Parameter | `'maximum_burst_size' cannot be used when rate limit type is 'minute'.` | Um rate limit por minuto carrega `maximum_burst_size`. | Remova `maximum_burst_size`. |
| `25035` | Required Rate Limit Parameter | `'maximum_burst_size' is required when rate limit type is 'second'.` | Um rate limit por segundo, inclusive um sem `type`, não tem `maximum_burst_size`. | Adicione `maximum_burst_size`. |
| `25036` | Invalid Informed WAF | `The informed WAF (<waf-id>) is not valid.` | Um `waf_id` não nomeia nenhum rule set. `meta.waf_id` repete o valor. | Envie o ID de um rule set existente. |
| `25039` | Invalid Operator | `The operator 'matches' is not valid for the '${network}' variable.` | Um operador que a variável não oferece, como `matches` em `${network}` ou `starts_with` em `${host}`. | Envie um operador da linha da variável em Operadores. |
| `25040` | Operator Does Not Require An Argument | `The operator 'exists' does not require an argument.` | `exists` ou `does_not_exist` carrega um argumento. | Remova `argument`. |
| `25041` | Operator Requires An Argument | `The operator 'is_equal' requires an argument.` | Qualquer outro operador não tem argumento. | Adicione `argument`. |
| `25042` | Invalid Operator Argument Type | `The argument type '<network-list-id>' is not valid for the operator 'is_in_list'.` | Um argumento de `${network}` enviado como string, como `"57102"`, o tipo que a especificação da API v4 dá a ele. | Envie o ID da Network List como inteiro JSON. |
| `25043` | Invalid Conditional For First Criterion | `The conditional 'and' is invalid for the first criterion.` | O primeiro critério de um bloco carrega `and` ou `or`. | Envie `if` no primeiro critério. |
| `25046` | Invalid Argument Choice | `The argument 'FOO' is not a valid choice for the criterion.` | Um argumento fora da lista de `${ssl_verification_status}` ou de `${client_certificate_validation}`. | Envie um valor da lista da variável. |
| `25047` | Missing Required Modules | `variable "${network}" is not available for this Edge Firewall. It requires ANY of the following modules to be enabled: ['network_protection_enabled'].` | Uma variável ou um comportamento cujo recurso aninhado está desativado. Com WAF, Network Shield e Functions desativados, toda regra falha, e a entrada do comportamento diz `It requires any of the following modules to be enabled: ['waf_enabled', 'network_protection_enabled', 'edge_functions_enabled'].` | Ative o que a mensagem nomeia: `waf_enabled` é WAF, `network_protection_enabled` é Network Shield e `edge_functions_enabled` é Functions. |
| `25048` | Firewall Rule Name Already In Use | `Firewall already have a rule with this name.` | Outra regra do Firewall carrega o mesmo `name`. | Envie outro nome. |

Azion CLI imprime a mensagem da API dentro do seu próprio erro. Para `25030` em um comportamento _Run Function_, a última linha diz:

```text
Error: failed to create the Firewall Rule: ["Function Instance '<function-instance-id>' not found."]
```

Um comportamento escrito com `name` em vez de `type` falha na CLI com `Error: Failed to decode the given 'json' file. Verify if the file format is JSON or fix its content according to the JSON format specification at https://www.json.org/json-en.html`, embora o arquivo seja um JSON válido. Escreva cada comportamento com `type`.
