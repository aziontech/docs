A Azion adiciona headers de diagnóstico às respostas que entrega. Dois headers chegam em toda resposta, e o header de requisição `Pragma: azion-debug-cache` adiciona os headers de localização e de cache. Com HTTP/2, os nomes dos headers chegam em letras minúsculas.

---

## Headers em toda resposta

Estes headers chegam em toda resposta, com ou sem os headers de debug:

| Header | O que carrega |
| :--- | :--- |
| `x-azion-request-id` | Um identificador único da requisição. A página de erro da Azion mostra o mesmo valor como **Request ID**, e o Real-Time Events o armazena no campo `requestId`. |
| `x-azion-edge-location` | O código do data center da Azion que processou a requisição. Os códigos são publicados na [Azion Status Page](https://status.azion.com/), e a página de erro da Azion mostra o mesmo valor como **Edge Location**. |

Para encontrar uma requisição nos logs pelo identificador, consulte [Reúna informações para o Suporte Azion](/pt-br/documentacao/suporte/reunir-informacoes/#encontre-a-requisicao-no-real-time-events).

---

## Headers de debug

Uma requisição que carrega `Pragma: azion-debug-cache` recebe estes headers, além dos headers de toda resposta. Sem ele, a resposta não carrega nenhum deles.

| Header | O que carrega |
| :--- | :--- |
| `x-azion-edge-pop` | Um código de localização, para debug junto com os headers de cache. O valor pode ser diferente do `x-azion-edge-location` da mesma resposta. |
| `x-cache` | O status do cache, o endereço IP do servidor que respondeu à requisição e o protocolo |
| `x-cache-key` | A cache key sob a qual a cópia está armazenada, que é o argumento de uma purga por cache key |
| `x-cache-file` | O hash MD5 da cache key |
| `x-cache-since` | O timestamp Unix de quando a cópia foi armazenada |
| `x-cache-expire` | O timestamp Unix de quando a cópia expira |
| `x-cache-expires-in` | Os segundos que faltam até a cópia expirar |
| `x-cache-valid` | O TTL configurado para a cópia, em segundos |
| `x-cache-config` | O ID da configuração da Azion que atendeu a requisição |
| `x-cache-id` | Um identificador da requisição, diferente em cada resposta |
| `x-cache-location` | Retornado com os outros headers de debug, por exemplo `/` |

Um `-` no lugar do status em `x-cache` significa ausência de status: o conteúdo está impedido de ser cacheado. Para cada valor de status, como `HIT` e `MISS`, consulte [Cache keys](/pt-br/documentacao/plataforma/applications/cache/cache-keys/).

Requisições consecutivas podem chegar a servidores diferentes, e `x-cache` nomeia o servidor que respondeu a cada uma. Para ler os headers de cache passo a passo, consulte [Verifique o status de cache de uma resposta](/pt-br/documentacao/guias/performance-e-confiabilidade/cache-e-purge/verificar-tempo-de-cache-da-pagina/).
