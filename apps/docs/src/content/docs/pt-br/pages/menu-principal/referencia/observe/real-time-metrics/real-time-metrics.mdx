**Real-Time Metrics** é um recurso da plataforma que mostra o tráfego dos seus recursos como métricas agregadas, no [Azion Console](https://console.azion.com/) e pela [API GraphQL](/pt-br/documentacao/devtools/graphql/). Uma métrica conta ou soma muitas requisições em uma fatia de tempo, então um gráfico de métricas mostra a tendência, não cada requisição. Use Real-Time Metrics para medir requisições e dados transferidos, ver a banda que o cache economiza, acompanhar status codes e ameaças ou comparar dois períodos.

Real-Time Metrics reúne os gráficos e os controles dele nestas páginas:

- [Dashboards de Build](/pt-br/documentacao/plataforma/real-time-metrics/dashboards-build/) mostram as requisições, os dados, a economia de cache, os status codes e os tempos de requisição das suas Applications, com as invocações de Functions, Tiered Cache e Image Processor. Cada gráfico informa o campo que retorna o valor dele pela API.
- [Dashboards de Secure](/pt-br/documentacao/plataforma/real-time-metrics/dashboards-secure/) contam as ameaças que o WAF identifica, as consultas que o Edge DNS responde e as requisições que o Bot Manager classifica. Eles também mostram quais endereços IP enviam as ameaças.
- [Dashboards de Observe](/pt-br/documentacao/plataforma/real-time-metrics/dashboards-observe/) mostram em gráficos os dados que o Data Stream envia aos seus endpoints e as requisições por trás desses dados.
- [Filtros e intervalo de tempo](/pt-br/documentacao/plataforma/real-time-metrics/filtros-e-intervalo-de-tempo/) define o período e os filtros que todos os gráficos de um dashboard seguem. O menu de um gráfico também copia a query que o gráfico envia ou exporta os pontos dele como um arquivo CSV.

## Caminho da requisição

Real-Time Metrics não tem nada para ativar e não cria nenhuma entidade na sua conta: ele está ativo em todas as contas. Os recursos da plataforma que servem o seu tráfego registram cada requisição, e Real-Time Metrics serve os totais do que eles registraram, então um gráfico tem dados somente depois que o tráfego chega.

O diagrama acompanha uma requisição até ela fazer parte de um ponto em um gráfico. As setas contínuas levam uma requisição ou um registro, e as setas pontilhadas levam a resposta. Cada rótulo começa com o número da etapa correspondente na lista.

```mermaid
  Reader(["Gráfico do Console, sua query ou Grafana"])
  Client -->|"1. requisição"| App

  Agg -->|"3. métrica por fatia de tempo"| RTM
  Reader -->|"4. query GraphQL"| RTM
  RTM -.->|"5. linhas"| Reader
```

1. Um cliente envia uma requisição, e o recurso da plataforma que a trata, como uma Application ou o WAF, registra a requisição como um evento.
2. A Azion soma os eventos de cada fatia de tempo em métricas, como uma contagem de requisições ou uma soma de bytes. Isso leva minutos, então os pontos mais recentes de um gráfico ainda podem subir.
3. Real-Time Metrics mantém as métricas em datasets, um dataset para cada tipo de tráfego.
4. Um gráfico do Console, uma query que você escreve e um dashboard do Grafana enviam, cada um, uma query GraphQL para a mesma API. Para consultar a API pelo Grafana, consulte [Instale o plugin da Azion para Grafana](/pt-br/documentacao/guias/plataforma/observabilidade/integrar-grafana/).
5. A API responde com as linhas do dataset, e um gráfico plota um ponto por linha. Como os três leem as mesmas linhas, um gráfico e a sua própria query retornam os mesmos números para o mesmo intervalo e os mesmos filtros.
