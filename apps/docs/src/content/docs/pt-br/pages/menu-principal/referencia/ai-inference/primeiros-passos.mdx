Este guia conduz você até a primeira resposta de um modelo do AI Inference.

- Implante o template AI Inference Starter Kit como uma Application.
- Abra o workload domain do Workload que o template cria.
- Envie uma requisição de chat a um modelo e leia a resposta que ele retorna.
- Chame outro modelo mudando um campo da requisição.

O template cria estas entidades, e uma requisição passa por elas nesta ordem:

1. Um **Workload**, com o deployment dele. O Workload recebe a requisição no workload domain dele, na forma `xxxxxxxxxx.map.azionedge.net`, e o deployment dele define a Application.
2. Uma **Application**, com Cache, Functions e Application Accelerator ativados. A única regra dela executa a Function em todo path, pela Function Instance, e ignora o cache.
3. Uma **Function** e a **Function Instance** dela, que vincula a Function à Application. A Function lê o id do modelo no campo `model` do corpo da requisição, passa o corpo inteiro para `Azion.AI.run` e retorna a resposta do modelo.

A Application e a Function recebem o nome que você insere, seguido do sufixo "(Build at …)". Você não escreve nenhum código para chegar à primeira resposta: a Function que o template instala já serve um endpoint compatível com OpenAI.

---

## Pré-requisitos

Este guia requer uma conta Azion com acesso ao AI Inference. Nos planos Hobby e Pro, o acesso está disponível sob solicitação, sujeito a aprovação. Para o acesso que cada plano dá, consulte [Limites do AI Inference](/pt-br/documentacao/plataforma/ai-inference/limites/). O template cria todas as outras entidades que o guia usa.

## Implante o template AI Inference Starter Kit

:::caution[Atenção]
O template usa [Application Accelerator](/pt-br/documentacao/plataforma/applications/application-accelerator/), [Functions](/pt-br/documentacao/plataforma/functions/) e [AI Inference](/pt-br/documentacao/plataforma/ai-inference/). Esses produtos podem gerar custos de uso. Para conhecer os valores, consulte [Preços](/pt-br/documentacao/fundamentos/precos/#ai-inference).
:::

Para criar a Application que responde às requisições de modelo:

<DocSteps>
  <DocStep title="Abra a Creation Center">

  Acesse [Azion Console](https://console.azion.com/) e selecione **+ Create**.

  </DocStep>
  <DocStep title="Selecione o template AI Inference Starter Kit">

  Em **Start from Template**, selecione **AI Inference Starter Kit**.

  </DocStep>
  <DocStep title="Dê um nome à Application">

  Em **Application Name**, insira um nome feito de letras, números e sublinhados. Por exemplo: `ai_inference_quickstart`. Um hífen é recusado com "The use of accents and/or special characters is not allowed."

  </DocStep>
  <DocStep title="Selecione Deploy" />
</DocSteps>

Uma janela mostra os logs da implantação enquanto ela é executada. Quando ela termina, a página mostra o domínio em **Visit site**, a opção **Add custom domain**, os **Deployment logs** e **Resources created**, que lista o Workload e a Application.

O Workload, a Application e a Function existem, e a Function responde a toda requisição que chega ao domínio.

---

## Abra o workload domain

O domínio em **Visit site** é o workload domain do Workload, na forma `xxxxxxxxxx.map.azionedge.net`. É o endereço para o qual um cliente envia uma requisição de modelo.

Para conferir que o domínio responde, selecione **Visit site**.

:::note[nota]
O deployment leva alguns minutos para se propagar aos data centers da Azion. Até que ele se propague, o domínio responde com o `404` de placeholder da Azion. Aguarde alguns minutos e selecione **Visit site** novamente.
:::

A página mostra `{"error":"Request must be a POST request with JSON body"}`. Essa resposta vem da Function, que aceita somente uma requisição `POST` com um corpo JSON. Copie o domínio: a requisição ao modelo vai para ele.

---

## Envie uma requisição ao modelo

A Function responde em qualquer path do domínio, e `/v1/chat/completions` é o path que os clientes da OpenAI usam. O corpo da requisição indica o modelo no campo `model` e carrega a conversa em `messages`. O header `Content-Type` precisa ser exatamente `application/json`.

Para enviar uma requisição de chat ao Qwen3 30B A3B Instruct 2507 FP8, substitua `<your-application-domain>` pelo domínio que você copiou e execute:

```bash
curl -X POST https://<your-application-domain>/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{
    "model": "Qwen/Qwen3-30B-A3B-Instruct-2507-FP8",
    "stream": false,
    "max_tokens": 1024,
    "temperature": 0.7,
    "top_p": 0.9,
    "messages": [
      { "role": "system", "content": "You are a helpful assistant." },
      { "role": "user", "content": "Name the European capitals." }
    ]
  }'
```

O modelo responde com uma entrada em `choices`, e o texto gerado fica em `choices[0].message.content`. A resposta abaixo encurta esse texto:

```json
{
  "id": "chatcmpl-784835050db84a289185baceb0ccbc8e",
  "object": "chat.completion",
  "created": 1794444653,
  "model": "qwen-qwen3-30b-a3b-instruct-2507-fp8",
  "choices": [
    {
      "index": 0,
      "message": {
        "role": "assistant",
        "content": "There are 44 sovereign countries in Europe, each with its own capital city. Here is a list of all the European capitals:...",
        "refusal": null,
        "annotations": null,
        "audio": null,
        "function_call": null,
        "tool_calls": [],
        "reasoning": null,
        "reasoning_content": null
      },
      "logprobs": null,
      "finish_reason": "stop",
      "stop_reason": null,
      "token_ids": null
    }
  ],
  "service_tier": null,
  "system_fingerprint": null,
  "usage": {
    "prompt_tokens": 24,
    "total_tokens": 620,
    "completion_tokens": 596,
    "prompt_tokens_details": null
  },
  "prompt_logprobs": null,
  "prompt_token_ids": null,
  "kv_transfer_params": null
}
```

O campo `model` carrega o id interno do modelo na conta, `qwen-qwen3-30b-a3b-instruct-2507-fp8`, que é diferente do id que a requisição enviou.

Você tem a sua primeira resposta de modelo, servida pela sua própria Application.

Se a conta não tem acesso ao AI Inference, ou se o id do modelo está errado, o endpoint responde `400` com `{"error":"<model> not found or not allowed"}`. Para todos os erros que o endpoint retorna, consulte [Invocação de modelos](/pt-br/documentacao/plataforma/ai-inference/invocacao-de-modelos/#erros).

O template não configura nenhuma autenticação na frente do endpoint, então qualquer cliente que alcança o domínio pode chamar um modelo. Quando você adiciona autenticação à sua Application, inclua o header que ela exige, por exemplo `-H "Authorization: Bearer [TOKEN VALUE]"`. Para conhecer todos os campos que um corpo de requisição aceita, consulte [Invocação de modelos](/pt-br/documentacao/plataforma/ai-inference/invocacao-de-modelos/).

## (Opcional) Chame outro modelo

A Function lê o id do modelo na requisição, então chamar outro modelo muda somente o campo `model` do corpo. O código da Function não precisa de nenhuma mudança. A forma dos ids varia entre os modelos, então copie o id da própria página do modelo em [Modelos de AI](/pt-br/documentacao/plataforma/ai-inference/modelos/).

Para enviar uma requisição de chat ao Qwen2.5 VL AWQ 3B, execute:

```bash
curl -X POST https://<your-application-domain>/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{
    "model": "qwen-qwen25-vl-3b-instruct-awq",
    "max_tokens": 16,
    "messages": [
      { "role": "user", "content": "Name one European capital." }
    ]
  }'
```

A resposta carrega `"model": "qwen-qwen25-vl-3b-instruct-awq"`, e `choices[0].message.content` contém a resposta desse modelo, como `Paris, France is a European capital.`

A mesma Function respondeu às duas requisições. O código dela fica na aba **Code** da Function, que Azion Console lista em **Edge Libraries** > **Functions**.
