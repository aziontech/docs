Uma Function Instance é a entidade que vincula uma [Function](/pt-br/documentacao/plataforma/functions/) a uma [Application](/pt-br/documentacao/plataforma/applications/). A Function Instance carrega os Args, os argumentos passados para o contexto da execução da Function em formato JSON: `args` na API, e a seção **Arguments** no Azion Console. Uma Function Instance define o nome, os Args, o schema do formulário e se ela está ativa, e mantém o código da Function como ele está.

Uma regra em [Rules Engine](/pt-br/documentacao/plataforma/applications/rules-engine/) invoca a Function Instance, não a Function. A mesma Function pode ser instanciada em mais de uma Application, e cada Function Instance carrega os próprios Args. Uma Function Instance só é executada quando uma regra com _Run Function_ a invoca.

Um [Firewall](/pt-br/documentacao/plataforma/firewall/) instancia Functions da mesma forma. Uma Function Instance em um Firewall executa a sua Function antes que a requisição chegue à Application, então a Function pode interromper a requisição ali. Uma Function Instance em uma Application executa a sua Function como parte de servir a requisição. Para as Function Instances de um Firewall, consulte [Instâncias de função no Firewall](/pt-br/documentacao/plataforma/firewall/functions-instances/). Para os limites delas, consulte [Limites de Firewall](/pt-br/documentacao/plataforma/firewall/limites/#regras-e-instancias-de-funcao).

## Campos da Function Instance

A [API da Azion](https://api.azion.com/) cria uma Function Instance sob a Application à qual ela pertence. Estes são os campos que você define:

| Campo | Tipo | Obrigatório | Descrição |
| --- | --- | --- | --- |
| `name` | string, de 1 a 100 caracteres | Sim | Nome da Function Instance. |
| `function` | integer | Sim | ID da Function que a Function Instance vincula, não da Function Instance. |
| `args` | JSON object ou array | Não | Argumentos passados para o contexto da execução da Function. |
| `azion_form` | JSON object | Não | Um JSON Schema que renderiza os args como formulário. |
| `active` | boolean | Não | Se a Function Instance está ativa. |

Quando a Function Instance não define args, os `default_args` da Function são usados. Quando ela não define `azion_form`, um objeto vazio é usado.

A API retorna mais quatro campos:

- `id`, o ID da Function Instance.
- `last_editor`, o endereço de e-mail da conta que a alterou pela última vez.
- `last_modified`, o timestamp dessa alteração.
- `created_at`, o timestamp da criação.

Uma requisição `POST` ao recurso `functions` de uma Application cria uma Function Instance:

```bash
curl --request POST \
  --url https://api.azion.com/v4/workspace/applications/<application-id>/functions \
  --header 'Accept: application/json' \
  --header 'Authorization: Token [TOKEN VALUE]' \
  --header 'Content-Type: application/json' \
  --data '{
  "name": "My instance Name",
  "function": <function-id>,
  "active": true
}'
```

A API responde `202` com o objeto criado:

```json
{
  "state": "pending",
  "data": {
    "id": <function-instance-id>,
    "name": "My instance Name",
    "args": {},
    "azion_form": {},
    "function": <function-id>,
    "active": true,
    "last_editor": "your-email@example.com",
    "last_modified": "2025-08-14T16:41:56.699896Z",
    "created_at": "2025-08-14T16:41:56.812345Z"
  }
}
```

O valor `"state": "pending"` significa que a alteração leva alguns minutos para propagar antes de entrar em vigor.

A API serve as Function Instances de uma Application em `/workspace/applications/<application-id>/functions`. No path de uma Function Instance, `<function-instance-id>` é o ID da Function Instance, não da Function:

| Operação | Método e path |
| --- | --- |
| Criar uma Function Instance | `POST /workspace/applications/<application-id>/functions` |
| Listar as Function Instances de uma Application | `GET /workspace/applications/<application-id>/functions` |
| Ler uma Function Instance | `GET /workspace/applications/<application-id>/functions/<function-instance-id>` |
| Substituir uma Function Instance | `PUT /workspace/applications/<application-id>/functions/<function-instance-id>` |
| Alterar parte de uma Function Instance | `PATCH /workspace/applications/<application-id>/functions/<function-instance-id>` |
| Excluir uma Function Instance | `DELETE /workspace/applications/<application-id>/functions/<function-instance-id>` |

[Instancie uma função em uma aplicação](/pt-br/documentacao/guias/desenvolvimento-de-aplicacoes/primeiros-passos/instanciar-functions/) mostra como criar uma Function Instance no Azion Console. No arquivo `azion.config.js` que [Azion CLI](/pt-br/documentacao/devtools/cli/) lê, uma Function Instance carrega `name`, `args` e `active`, e `ref` nomeia a Function por nome ou por ID.

## Args

Args são os argumentos que uma Function Instance passa para o contexto da execução da Function, escritos como um objeto ou um array JSON. O código lê uma chave em tempo de execução e a Function Instance decide o valor dela, então uma mesma Function se comporta de forma diferente em cada lugar onde é instanciada. Uma Function pode definir Args padrão próprios, e a Function os lê somente quando a Function Instance não define Args. Os Args definidos na Function Instance substituem os padrões por inteiro, então uma chave que a Function Instance deixa de fora fica ausente, em vez de manter o valor padrão.

Um objeto Args que define uma chave:

```json
{
  "value": "hello_world"
}
```

O objeto Args comporta no máximo 100 KB, e um objeto acima desse teto faz a Function falhar na instanciação. Para todos os limites de Functions, consulte [Limites de Functions](/pt-br/documentacao/plataforma/functions/limites/).

Args são a configuração de uma Function Instance. Valores sensíveis, como chaves de API, credenciais e tokens de acesso, pertencem às [variáveis de ambiente](/pt-br/documentacao/plataforma/functions/environment-variables/).

## Behavior Run Function

_Run Function_ é o behavior de [Rules Engine](/pt-br/documentacao/plataforma/applications/rules-engine/#run-function) que invoca uma Function Instance. A regra guarda o ID da Function Instance, e a fase e os critérios da regra decidem quando ela é executada. Quando uma requisição atende a esses critérios, a Function é executada na infraestrutura distribuída da Azion.

_Run Function_ está disponível na Request Phase e na Response Phase, e exige [Functions](/pt-br/documentacao/plataforma/functions/) ativado na Application. Na Response Phase, ele executa somente Functions escritas em Lua. Na API da Azion, o behavior é `run_function`, e o atributo `value` dele carrega o ID da Function Instance. Enquanto Functions está desativado, a API também recusa criar uma Function Instance na Application, com HTTP `400` e o erro `29003`, `Edge Functions Module Is Not Enabled`.

Para as fases de execução, os critérios e a ordem em que os behaviors são executados, consulte [Como Functions funciona](/pt-br/documentacao/plataforma/functions/como-funciona/).

## CLI

Azion CLI gerencia Function Instances com cinco comandos sob o substantivo `function-instance`. Todo comando recebe `--application-id`, e um comando que age sobre uma Function Instance recebe o ID dela em `--instance-id`.

| Comando | O que faz | Flags |
| --- | --- | --- |
| `azion create function-instance` | Cria uma Function Instance | `--application-id`, `--function-id`, `--name`, `--args`, `--active`, `--file` |
| `azion list function-instance` | Lista as Function Instances de uma Application | `--application-id`, `--details`, `--filter`, `--order-by`, `--page`, `--page-size` |
| `azion describe function-instance` | Retorna uma Function Instance | `--application-id`, `--instance-id` |
| `azion update function-instance` | Altera uma Function Instance | `--application-id`, `--instance-id`, `--function-id`, `--name`, `--args`, `--active`, `--file` |
| `azion delete function-instance` | Exclui uma Function Instance | `--application-id`, `--instance-id` |

`--function-id` define o campo `function`, e `--args` define `args`. Em `azion create function-instance` e `azion update function-instance`, o padrão de `--active` é `true`.
