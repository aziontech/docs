Uma instância de função é o objeto que vincula uma [função](/pt-br/documentacao/plataforma/functions/) a uma [aplicação](/pt-br/documentacao/plataforma/applications/). A instância carrega os Args, os argumentos passados para o contexto da execução da função em formato JSON: `args` na API, e a seção **Arguments** no Azion Console. O código da função não pode ser editado na instanciação: uma instância define o nome, os Args, o schema do formulário e se ela está ativa.

Uma regra em [Rules Engine](/pt-br/documentacao/plataforma/applications/rules-engine/) invoca a instância, não a função. A mesma função pode ser instanciada em mais de uma aplicação, e cada instância carrega os próprios Args. Uma instância que nenhuma regra nomeia nunca é executada.

Um [firewall](/pt-br/documentacao/plataforma/firewall/) instancia funções da mesma forma. Uma instância em um firewall executa a sua função antes que a requisição chegue à aplicação, então a função pode interromper a requisição ali. Uma instância em uma aplicação executa a sua função como parte de servir a requisição. Consulte [Instâncias de função no Firewall](/pt-br/documentacao/plataforma/firewall/functions-instances/) para conhecer o objeto do firewall, e [Limites de Firewall](/pt-br/documentacao/plataforma/firewall/limites/#regras-e-instancias-de-funcao) para conhecer os limites dele.

## Campos da instância

A [API da Azion](https://api.azion.com/) cria uma instância sob a aplicação à qual ela pertence. Estes são os campos que você define:

| Campo | Tipo | Obrigatório | Descrição |
| --- | --- | --- | --- |
| `name` | string, de 1 a 100 caracteres | Sim | Nome da instância. |
| `function` | integer | Sim | ID da função que a instância vincula, não da instância. |
| `args` | JSON object ou array | Não | Argumentos passados para o contexto da execução da função. |
| `azion_form` | JSON object | Não | Um JSON Schema que renderiza os args como formulário. |
| `active` | boolean | Não | Se a instância está ativa. |

Quando a instância não define args, os `default_args` da função são usados. Quando ela não define `azion_form`, um objeto vazio é usado.

A API retorna mais quatro campos:

- `id`, o ID da instância.
- `last_editor`, o endereço de e-mail da conta que a alterou pela última vez.
- `last_modified`, o timestamp dessa alteração.
- `created_at`, o timestamp da criação.

Uma requisição `POST` ao recurso `functions` de uma aplicação cria uma instância:

```bash
curl --request POST \
  --url https://api.azion.com/v4/workspace/applications/<application-id>/functions \
  --header 'Accept: application/json' \
  --header 'Authorization: Token [TOKEN VALUE]' \
  --header 'Content-Type: application/json' \
  --data '{
  "name": "My instance Name",
  "function": <function-id>,
  "active": true
}'
```

A API responde `202` com o objeto criado:

```json
{
  "state": "pending",
  "data": {
    "id": <function-instance-id>,
    "name": "My instance Name",
    "args": {},
    "azion_form": {},
    "function": <function-id>,
    "active": true,
    "last_editor": "your-email@example.com",
    "last_modified": "2025-08-14T16:41:56.699896Z",
    "created_at": "2025-08-14T16:41:56.812345Z"
  }
}
```

O valor `"state": "pending"` significa que a alteração leva alguns minutos para propagar antes de entrar em vigor.

A API serve as instâncias de uma aplicação em `/workspace/applications/<application-id>/functions`. No path de uma instância, `<function-instance-id>` é o ID da instância, não da função:

| Operação | Método e path |
| --- | --- |
| Criar uma instância | `POST /workspace/applications/<application-id>/functions` |
| Listar as instâncias de uma aplicação | `GET /workspace/applications/<application-id>/functions` |
| Ler uma instância | `GET /workspace/applications/<application-id>/functions/<function-instance-id>` |
| Substituir uma instância | `PUT /workspace/applications/<application-id>/functions/<function-instance-id>` |
| Alterar parte de uma instância | `PATCH /workspace/applications/<application-id>/functions/<function-instance-id>` |
| Excluir uma instância | `DELETE /workspace/applications/<application-id>/functions/<function-instance-id>` |

Você cria o mesmo objeto na aba **Functions Instances** de uma aplicação em Azion Console. No arquivo `azion.config.js` que [Azion CLI](/pt-br/documentacao/devtools/cli/) lê, uma instância carrega `name`, `args` e `active`, e `ref` nomeia a função por nome ou por ID.

## Args

Args são os argumentos que uma instância passa para o contexto da execução da função, escritos como um objeto ou um array JSON. O código lê uma chave em tempo de execução e a instância decide o valor dela, então uma mesma função se comporta de forma diferente em cada lugar onde é instanciada. Uma função pode definir Args padrão próprios: os Args de uma instância sobrescrevem as chaves que repetem, e toda chave que a instância deixa de fora mantém o valor padrão.

Um objeto Args que define uma chave:

```json
{
  "value": "hello_world"
}
```

O objeto Args comporta no máximo 100 KB, e um objeto acima desse teto faz a função falhar na instanciação. Para todos os limites de Functions, consulte [Limites de Functions](/pt-br/documentacao/plataforma/functions/limites/).

Args são configuração por instância. Valores sensíveis, como chaves de API, credenciais e tokens de acesso, pertencem às [variáveis de ambiente](/pt-br/documentacao/plataforma/functions/environment-variables/).

## Behavior Run Function

_Run Function_ é o behavior de [Rules Engine](/pt-br/documentacao/plataforma/applications/rules-engine/#run-function) que invoca uma instância. A regra nomeia a instância, a fase de execução e os critérios que a acionam. Quando uma requisição atende a esses critérios, a função é executada na infraestrutura distribuída da Azion.

_Run Function_ está disponível na Request Phase e na Response Phase, e exige [Functions](/pt-br/documentacao/plataforma/functions/) na aplicação. Na Response Phase, ele executa somente funções com o runtime Lua. Na API da Azion, o behavior é `run_function` e o atributo `value` dele carrega o ID da instância.

Para as fases de execução, os critérios e a ordem em que os behaviors são executados, consulte [Como Functions funciona](/pt-br/documentacao/plataforma/functions/como-funciona/).

## CLI

Azion CLI gerencia instâncias com cinco comandos sob o substantivo `function-instance`. Todo comando recebe `--application-id`, e um comando que age sobre uma instância recebe o ID dela em `--instance-id`.

| Comando | O que faz | Flags |
| --- | --- | --- |
| `azion create function-instance` | Cria uma instância | `--application-id`, `--function-id`, `--name`, `--args`, `--active`, `--file` |
| `azion list function-instance` | Lista as instâncias de uma aplicação | `--application-id`, `--details`, `--filter`, `--order-by`, `--page`, `--page-size` |
| `azion describe function-instance` | Retorna uma instância | `--application-id`, `--instance-id` |
| `azion update function-instance` | Altera uma instância | `--application-id`, `--instance-id`, `--function-id`, `--name`, `--args`, `--active`, `--file` |
| `azion delete function-instance` | Exclui uma instância | `--application-id`, `--instance-id` |

`--function-id` define o campo `function`, e `--args` define `args`. Em `azion create function-instance` e `azion update function-instance`, o padrão de `--active` é `true`.
