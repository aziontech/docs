**Tiered Cache** é uma feature de [Cache](/pt-br/documentacao/plataforma/applications/cache/) que adiciona uma segunda camada de cache entre o data center que responde a uma requisição e a sua origem. A primeira camada é o cache desse data center. A segunda camada fica na região que a `topology` de um cache setting seleciona.

Quando uma requisição resulta em um miss na primeira camada, o data center consulta a camada do Tiered Cache antes que a requisição siga para a origem. Uma cópia válida do objeto requisitado nessa camada responde ao miss, e a origem não recebe nenhuma requisição. Você ativa a camada por cache setting, e ela se aplica aos objetos que esse setting coloca em cache. Para saber como as duas camadas respondem a uma requisição, consulte [Expiração e atualização](/pt-br/documentacao/plataforma/applications/cache/expiracao-e-atualizacao/#tiered-cache).

Uma resposta da camada do Tiered Cache chega com menos latência do que uma resposta da origem, e menos requisições chegam à origem. A origem lida com menos carga a um custo de infraestrutura menor. O preço é um salto extra em um miss na primeira camada. Com [Application Accelerator](/pt-br/documentacao/plataforma/applications/application-accelerator/) ativo, Tiered Cache também define um piso de 3 segundos no tempo de vida (TTL) do cache setting.

## Interfaces

Um cache setting ativa Tiered Cache no seu objeto `modules.cache.tiered_cache`, e as quatro interfaces abaixo escrevem esse objeto. A tabela nomeia onde o controle fica em cada uma.

| Interface | Onde | Valor |
| --- | --- | --- |
| [Azion Console](https://console.azion.com/) | A seção **Cache** do drawer **Create Cache Settings**, na aba **Cache Settings** de uma Application em [Applications](/pt-br/documentacao/plataforma/applications/) | O toggle **Tiered Cache**, desativado em um setting novo, e o select **Tiered Cache Region**, com `nearest-region` como padrão. Ativar o toggle desabilita _Honor cache policies_ e seleciona _Override cache behavior_ |
| [Azion API v4](/pt-br/documentacao/devtools/api/) | `POST /v4/workspace/applications/{application_id}/cache_settings` | `modules.cache.tiered_cache.enabled`, `true` ou `false`, e `modules.cache.tiered_cache.topology`, `nearest-region` quando o corpo não o envia |
| [Azion CLI](/pt-br/documentacao/devtools/cli/) | `azion create cache-setting --file` com o corpo JSON | O mesmo objeto `tiered_cache`. A flag `--tiered-caching-enabled` sozinha é recusada com o erro `21001` |
| `azion.config.js` | Uma entrada do array `cache`, do tipo `AzionCache` | `tieredCache: { enabled, topology }` |

:::note[nota]
Duas condições se aplicam ao cache setting. O seu `modules.cache.behavior` precisa ser `override`, porque a API recusa Tiered Cache sob `honor` com o erro `21001`. A CLI só define o comportamento de cache no corpo JSON do `--file`. Com [Application Accelerator](/pt-br/documentacao/plataforma/applications/application-accelerator/) ativo na Application, o `modules.cache.max_age` do cache setting precisa ser de pelo menos 3 segundos, ou a API retorna o erro `21020`. Sem Application Accelerator, vale o piso de 60 segundos de todo cache setting, e a API retorna `21021`.
:::

Tiered Cache está incluído em todos os planos de serviço. Para todos os campos de um cache setting, com o título e a correção de cada erro, consulte [Cache settings](/pt-br/documentacao/plataforma/applications/cache/cache-settings/). Para os passos no Console que aplicam um setting a um path, consulte [Configure políticas de cache para uma aplicação](/pt-br/documentacao/guias/performance-e-confiabilidade/cache-e-purge/cache-settings/).

## Topology

A `topology` de um cache setting seleciona onde a camada do Tiered Cache mantém os objetos que esse setting coloca em cache. Azion Console, a API, o corpo JSON da CLI e o `azion.config.js` aceitam valores como `nearest-region` e `us-east-1`, e a [referência da Azion API](https://api.azion.com/) lista todos os valores aceitos. Um valor que a API não aceita retorna o erro `10039`, `Invalid Choice`.

---

## TTL

O tempo de vida (TTL) de um objeto na camada do Tiered Cache é o Max Age do seu cache setting, o campo `modules.cache.max_age`. Enquanto Tiered Cache e Application Accelerator estão ativos, esse campo tem um piso de 3 segundos. Um cache setting novo começa em 60 segundos, o padrão do Max Age no Azion Console, na API e na CLI. Por exemplo, em uma Application com Application Accelerator ativo, um Max Age de 2 segundos com Tiered Cache ativo é recusado com o erro `21020`. O mesmo setting com 3 segundos é aceito.

O teto é o teto do próprio TTL de cache. Para o valor e o erro além dele, consulte [Limites de Applications](/pt-br/documentacao/plataforma/applications/limites/#cache).

## Purge

[Real-Time Purge](/pt-br/documentacao/plataforma/applications/cache/real-time-purge/) remove um objeto da camada do Tiered Cache antes do fim do seu TTL. A camada é `tiered_cache` no corpo da API e na flag `--layer` do `azion purge`. Um purge por cache key é o único tipo que a alcança. Um purge por URL ou por wildcard com essa camada retorna o erro `30001`, `Invalid Purge Layer For Purge Type`.

Para remover um objeto mantido nas duas camadas, purgue primeiro Tiered Cache e depois Cache. Nessa ordem, a primeira camada não é reabastecida por uma cópia desatualizada do Tiered Cache. Para os passos no Console, na API e na CLI, consulte [Purgue conteúdo em cache](/pt-br/documentacao/guias/performance-e-confiabilidade/cache-e-purge/purgar-conteudo-em-cache/).

## Bypass Cache

Uma regra com o behavior [Bypass Cache](/pt-br/documentacao/plataforma/applications/rules-engine/#bypass-cache) no [Rules Engine](/pt-br/documentacao/plataforma/applications/rules-engine/) afeta o cache da Azion, e não a camada do Tiered Cache. Uma Application cujos cache settings ativam Tiered Cache continua a colocar objetos em cache nessa camada pelo Max Age do cache setting, o seu campo `modules.cache.max_age`. Para o sintoma que isso produz e o que fazer a respeito, consulte [Solucione problemas de Applications](/pt-br/documentacao/plataforma/applications/solucao-de-problemas/#cache).

## Observabilidade

[Real-Time Metrics](/pt-br/documentacao/plataforma/real-time-metrics/) carrega um dataset de Tiered Cache ao lado do seu dataset de Cache. [Real-Time Events](/pt-br/documentacao/plataforma/real-time-events/) também carrega um dataset de Tiered Cache. Por GraphQL, você consulta os dados que Tiered Cache transfere. Para a consulta e a sua resposta, consulte [Consulte dados de uso do Tiered Cache](/pt-br/documentacao/guias/plataforma/observabilidade/consultar-dados-de-uso-tiered-cache-com-graphql/).
