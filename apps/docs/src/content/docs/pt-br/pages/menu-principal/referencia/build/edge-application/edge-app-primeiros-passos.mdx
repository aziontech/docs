Este guia orienta você a entregar o conteúdo da sua origem pela sua primeira [Application](/pt-br/documentacao/plataforma/applications/).

- Crie um [Connector](/pt-br/documentacao/plataforma/connectors/) que alcança a sua origem por HTTPS.
- Crie uma Application.
- Adicione uma regra que envia toda requisição para o Connector.
- Entregue a Application por um [Workload](/pt-br/documentacao/plataforma/workloads/).
- Envie uma requisição para o domínio de workload e receba a resposta da sua origem.

Cinco partes formam a cadeia, listadas na ordem em que este guia as usa:

1. O **Connector** guarda o endereço da sua origem e a forma como a Azion se conecta a ela.
2. A **Application** guarda as regras que decidem o que acontece com uma requisição. Uma Application nova não tem regras.
3. A **regra** na Application combina uma condição sobre a requisição, chamada critério, com uma ação chamada behavior. Neste guia, o critério corresponde a toda requisição, e o behavior _Set Connector_ envia a requisição para o Connector.
4. O **Workload** guarda um domínio e recebe as requisições enviadas a ele. O **deployment** dele, uma configuração do Workload, define a Application que recebe essas requisições.
5. A **requisição** vai para o domínio de workload, o hostname que a Azion atribui ao Workload. A regra da Application corresponde à requisição, e o Connector a encaminha para a sua origem.

Um Connector só recebe requisições depois que uma regra o define, e uma Application só depois que um deployment a define.

Cada Application tem quatro interruptores: [Cache](/pt-br/documentacao/plataforma/applications/cache/), [Functions](/pt-br/documentacao/plataforma/functions/), [Application Accelerator](/pt-br/documentacao/plataforma/applications/application-accelerator/) e [Image Processor](/pt-br/documentacao/plataforma/applications/image-processor/). No Azion Console, os interruptores ficam em **Main Settings** > **Modules**, e na API, eles são as chaves de `modules`. Uma Application nova começa com Cache e Functions ativados e os outros dois desativados, e este guia mantém os quatro como estão. Os primeiros passos de Cache, Application Accelerator e Image Processor começam onde este guia termina, com uma Application que já entrega conteúdo.

## Crie um Connector para a sua origem

Um Connector guarda o endereço da sua origem e as configurações que a Azion usa para alcançá-la. Você o cria à parte, fora de qualquer Application, e uma regra o define depois. Este Connector tem um endereço e se conecta à sua origem por HTTPS. Ele envia o hostname da sua origem no header `Host`.

Por padrão, um Connector envia o host que o cliente requisitou, que aqui é o seu domínio de workload. Uma origem que roteia por nome pode não responder a esse host. Para mais informações, consulte [Header Host](/pt-br/documentacao/plataforma/connectors/como-funciona/#header-host).

<Tabs client:visible sharedStore="interface">

<Fragment slot="panel.console">

### Console

Para criar o Connector pelo Azion Console:

<DocSteps>
  <DocStep title="Abra a página Connectors">

  Acesse [Azion Console](https://console.azion.com/) > **Connectors**.

  </DocStep>
  <DocStep title="Inicie um novo Connector">

  Selecione **+ Connectors**.

  </DocStep>
  <DocStep title="Nomeie o Connector">

  Em **General**, insira `origin-connector` como **Name**.

  </DocStep>
  <DocStep title="Mantenha o tipo HTTP">

  Em **Connector Type**, mantenha _HTTP_ selecionado.

  </DocStep>
  <DocStep title="Insira o hostname da sua origem como endereço">

  Em **Address Management**, insira `<your-origin-hostname>` em **Address**, sem protocolo e sem porta.

  </DocStep>
  <DocStep title="Envie o mesmo hostname no header Host">

  Em **Connection Options**, substitua `${host}` em **Host** por `<your-origin-hostname>`, o mesmo valor de **Address**.

  </DocStep>
  <DocStep title="Conecte-se à origem somente por HTTPS">

  Em **Transport Protocol Policy**, selecione _Force HTTPS_.

  </DocStep>
  <DocStep title="Selecione Save" />
</DocSteps>

Azion Console mostra a mensagem "Connector successfully created". O Connector existe na sua conta, e a regra que você adiciona à Application o seleciona. Para todos os campos do formulário do Connector, consulte [Configurações de connector](/pt-br/documentacao/plataforma/connectors/configuracoes/).

</Fragment>

<Fragment slot="panel.cli">

### CLI

Para criar o Connector pela Azion CLI, coloque-o primeiro em um arquivo JSON. Salve este corpo como `connector.json` e substitua `<your-origin-hostname>` nos dois lugares:

<Code client:visible lang="json" code={`{
    "name": "origin-connector",
    "type": "http",
    "attributes": {
      "addresses": [
        { "address": "<your-origin-hostname>" }
      ],
      "connection_options": {
        "transport_policy": "force_https",
        "host": "<your-origin-hostname>"
      }
    }
}`} />

`addresses` lista os servidores de origem, e `connection_options.host` é o header `Host` que o Connector envia. `force_https` faz toda conexão com a origem usar HTTPS.

Crie o Connector a partir do arquivo:

<Code client:visible lang="bash" code={`azion create connector --type http --file connector.json`} />

A saída traz o ID do Connector:

```text
Created Connector with ID <connector-id>
```

Anote o ID: a regra o passa como `<connector-id>`.

</Fragment>

```json
    "last_editor": "user@example.com",
    …

    …
    "type": "http",
    "attributes": {
      "addresses": [
        {
          "active": true,
          "address": "<your-origin-hostname>",
          "http_port": 80,
          "https_port": 443,
          "modules": null
        }
      ],
      "connection_options": {
        "dns_resolution": "both",
        "transport_policy": "force_https",
        "http_version_policy": "http1_1",
        "host": "<your-origin-hostname>",
        "path_prefix": "",
        "following_redirect": false,
        "real_ip_header": "X-Real-IP",
        "real_port_header": "X-Real-PORT"
      },
      "modules": {
        "load_balancer": { "enabled": false, "config": null },
        "origin_shield": { "enabled": false, "config": null }
      }

    …

```

O Connector está ativo, e o endereço dele aceita conexões HTTPS na `https_port` `443`. [Load Balancer](/pt-br/documentacao/plataforma/connectors/load-balancer/) e [Origin Shield](/pt-br/documentacao/plataforma/connectors/origin-shield/) começam desativados. Anote o `id`: a regra o passa como `<connector-id>`.

## Envie toda requisição para o Connector

Uma regra no [Rules Engine para Applications](/pt-br/documentacao/plataforma/applications/rules-engine/) combina critérios com behaviors. Esta regra roda na Request Phase. O critério dela, `${uri}` começando com `/`, corresponde a toda requisição. O behavior dela, _Set Connector_, envia cada requisição correspondente para o seu Connector. Para mais informações, consulte [Set Connector](/pt-br/documentacao/plataforma/applications/rules-engine/#set-connector).

O critério usa `${uri}`, não `${request_uri}`. `${request_uri}` precisa de Application Accelerator ativado. Em uma Application com Application Accelerator desativado, a API recusa a regra com `400` e o erro `25047`, `Missing Required Modules`.

<Tabs client:visible sharedStore="interface">

<Fragment slot="panel.console">

### Console

Para criar a regra pelo Azion Console:

<DocSteps>
  <DocStep title="Abra a Application">

  Acesse [Azion Console](https://console.azion.com/) > **Applications** e selecione a Application que você criou.

  </DocStep>
  <DocStep title="Selecione a aba Rules Engine" />
  <DocStep title="Selecione + Rule" />
  <DocStep title="Nomeie a regra">

  Em **General**, insira `send-to-origin` como **Name**.

  </DocStep>
  <DocStep title="Selecione a Request Phase">

  Em **Phase**, selecione _Request Phase_. A fase de uma regra não pode mudar depois que você cria a regra.

  </DocStep>
  <DocStep title="Defina o critério">

  Em **Criteria**, mantenha `${uri}` e _starts with_. Em seguida, insira `/` como argumento.

  </DocStep>
  <DocStep title="Selecione o behavior Set Connector">

  Em **Behaviors**, selecione _Set Connector_.

  </DocStep>
  <DocStep title="Selecione o seu Connector">

  Na lista do behavior _Set Connector_, selecione `origin-connector`.

  </DocStep>
  <DocStep title="Selecione Save" />
</DocSteps>

A regra aparece na aba **Rules Engine**, sob o título **Request**.

</Fragment>

<Fragment slot="panel.cli">

### CLI

Para criar a regra pela Azion CLI, mantenha a regra em um arquivo: em uma linha de comando, o shell expandiria `${uri}`. Salve este corpo como `rule.json` e substitua `<connector-id>` pelo ID do seu Connector:

<Code client:visible lang="json" code={`{
    "name": "send-to-origin",
    "active": true,
    "criteria": [
      [
        {
          "variable": "\${uri}",
          "conditional": "if",
          "operator": "starts_with",
          "argument": "/"
        }
      ]
    ],
    "behaviors": [
      {
        "type": "set_connector",
        "attributes": { "value": <connector-id> }
      }
    ]
}`} />

Cada grupo em `criteria` abre com uma condição cujo conditional é `if`.

Crie a regra na Request Phase da sua Application. Substitua `<application-id>` pelo ID da sua Application:

<Code client:visible lang="bash" code={`azion create rules-engine --application-id <application-id> --phase request --file rule.json`} />

A saída traz o ID da regra:

```text
Created Rules Engine with ID <rule-id>
```

A regra está ativa na sua Application e envia toda requisição para o seu Connector.

</Fragment>

<Fragment slot="panel.api">

### API

Para criar a regra pela API, mantenha o corpo da requisição em um arquivo: em uma linha de comando, o shell expandiria `${uri}`. Salve este corpo como `rule.json` e substitua `<connector-id>` pelo ID do seu Connector:

<Code client:visible lang="json" code={`{
    "name": "send-to-origin",
    "active": true,
    "criteria": [
      [
        {
          "variable": "\${uri}",
          "conditional": "if",
          "operator": "starts_with",
          "argument": "/"
        }
      ]
    ],
    "behaviors": [
      {
        "type": "set_connector",
        "attributes": { "value": <connector-id> }
      }
    ]
}`} />

Cada grupo em `criteria` abre com uma condição cujo conditional é `if`.

Envie uma requisição `POST` para as regras da Request Phase da sua Application. Substitua `[TOKEN VALUE]` pelo seu personal token e `<application-id>` pelo ID da sua Application:

<Code client:visible lang="bash" code={`curl --request POST \\
    --url https://api.azion.com/v4/workspace/applications/<application-id>/request_rules \\
    --header 'Accept: application/json' \\
    --header 'Authorization: Token [TOKEN VALUE]' \\
    --header 'Content-Type: application/json' \\
    --data @rule.json`} />

A resposta traz a regra armazenada. Este trecho mantém o `id`, o critério, o behavior e o `order` dela:

```json
{
  "state": "pending",
  "data": {
    "id": <rule-id>,
    "name": "send-to-origin",
    "active": true,
    "criteria": [
      [
        {
          "conditional": "if",
          "variable": "${uri}",
          "operator": "starts_with",
          "argument": "/"
        }
      ]
    ],
    "behaviors": [
      {
        "type": "set_connector",
        "attributes": { "value": <connector-id> }
      }
    ],
    "description": "",
    "order": 0,
    …
  }
}
```

`order` é `0`, a posição da primeira regra na Application. A regra está ativa e envia toda requisição para o seu Connector.

## Entregue a Application por um Workload

Um Workload recebe as requisições enviadas aos domínios dele. Ele guarda esses domínios, os protocolos e os certificados, então você configura a entrega no Workload, não na Application. O deployment do Workload define a Application que recebe essas requisições, e um Workload tem um único deployment. Um Workload novo responde em um domínio de workload que a Azion atribui sob `map.azionedge.net`.

Para criar o Workload pela Azion CLI:

<Code client:visible lang="bash" code={`azion create workload --name first-workload --active true`} />


Para vincular a sua Application, crie o deployment do Workload. Substitua `<workload-id>` pelo ID do Workload e `<application-id>` pelo ID da sua Application:

<Code client:visible lang="bash" code={`azion create workload-deployment --workload-id <workload-id> --name first-deployment --application-id <application-id>`} />

O comando imprime o ID do deployment novo:

```text

```

Para conferir o vínculo, liste os deployments do Workload com os detalhes deles:

<Code client:visible lang="bash" code={`azion list workload-deployment --workload-id <workload-id> --details`} />

```text
ID              CURRENT  EDGE APPLICATION  EDGE FIREWALL
<deployment-id> true     <application-id>  0
```

Para encontrar o domínio de workload, descreva o Workload em JSON:

<Code client:visible lang="bash" code={`azion describe workload --workload-id <workload-id> --format json`} />

```json
{
 …
 "id": <workload-id>,
 …
 "workload_domain": "<your-workload-domain>",
 …
}
```

    "name": "first-workload",
    "active": true,
    "infrastructure": 1,
    "workload_domain_allow_access": true
}'`} />

A resposta traz as configurações iniciais do Workload e o domínio que a Azion atribuiu a ele:

```json
{
  "state": "pending",
  "data": {
    "id": <workload-id>,
    "name": "first-workload",
    "active": true,
    …
    "infrastructure": 1,
    "tls": {
      "certificate": null,
      "ciphers": 7,
      "minimum_version": "tls_1_3"
    },
    "protocols": {
      "http": {
        "versions": ["http1", "http2", "http3"],
        "http_ports": [80],
        "https_ports": [443],
        "quic_ports": [443]
      }
    },

    "domains": [],
    "workload_domain_allow_access": true,

  }
}
```

`domains` está vazio, e `workload_domain` guarda o domínio que a Azion atribuiu ao Workload. Anote o `id` e o `workload_domain`.

Para vincular a sua Application ao Workload que você criou, execute o comando do painel CLI que cria o deployment. Você usa a CLI aqui porque a referência publicada da API v4 da Azion não tem endpoint para o deployment de um Workload.

## Envie uma requisição pelo Workload

Esta etapa precisa apenas do `curl`, qualquer que seja a interface que você usou para montar a cadeia. No comando, substitua `<your-workload-domain>` pelo domínio de workload do Workload que você criou.

Um Workload novo só retorna a resposta da sua origem depois que o primeiro deployment dele chega ao tráfego. Isso pode levar vários minutos, e a Azion não garante nenhuma duração. Até lá, o domínio de workload responde `404` com uma página provisória. Enquanto o deployment se propaga, as respostas à mesma requisição podem alternar entre esse `404` e a resposta da sua origem. Repita a requisição até a resposta vir da sua origem. Para mais informações, consulte [Propagação](/pt-br/documentacao/plataforma/applications/como-funciona/#propagacao).

Envie uma requisição para o caminho raiz do seu domínio de workload:

<Code client:visible lang="bash" code={`curl -i https://<your-workload-domain>/`} />

A resposta é a que a sua origem retorna para `/`: o status, os headers e o corpo dela. Qualquer outro caminho chega à sua origem da mesma forma, porque a regra corresponde a toda URI que começa com `/`. A sua Application agora envia toda requisição no domínio de workload para a sua origem pelo Connector.

Quando a sua origem recusa o handshake TLS, a resposta é um `502` com a página intitulada `Azion - Default error page`, não uma página da sua origem. Para mais informações, consulte [Reutilização de conexões e timeouts](/pt-br/documentacao/plataforma/connectors/como-funciona/#reutilizacao-de-conexoes-e-timeouts).
