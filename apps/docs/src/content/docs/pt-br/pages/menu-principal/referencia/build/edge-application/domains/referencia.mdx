Um domínio carrega as configurações abaixo, no Azion Console e na API v3. Esta página lista cada configuração com o rótulo no Console, o campo da API e o que ela faz. Para o número de CNAMEs que um domínio aceita, consulte [Limites do Domains](/pt-br/documentacao/plataforma/domains/limites/).

---

## Campos do domínio

Na API v3, você cria um domínio com um `POST` para `https://api.azionapi.net/domains` com o header `Accept: application/json; version=3`.

| Rótulo no Console | Campo da API | Descrição |
| --- | --- | --- |
| Name | `name` | O nome da entrada na conta. Não é um hostname |
| Environment Type | | O ambiente do domínio: [Global Edge Network ou Staging Network](#ambiente) |
| Applications | `edge_application_id` | O ID da aplicação que o domínio atende |
| Firewall | | O firewall que inspeciona as requisições do domínio |
| CNAME | `cnames` | Os hostnames que o domínio atende, um por linha no Azion Console |
| CNAME access only | `cname_access_only` | `false` mantém o endereço da Azion acessível. `true` atende somente os hostnames listados |
| Digital Certificate | `digital_certificate_id` | O certificado do domínio. `null` seleciona o certificado **Azion SAN** |
| Mutual Authentication | `is_mtls_enabled` | `true` pede um certificado a cada cliente. Consulte [mTLS](#mtls) |
| Mode | `mtls_verification` | `enforce` ou `permissive` |
| Trusted CA Certificate | `mtls_trusted_ca_certificate_id` | O certificado do tipo `trusted_ca_certificate` em relação ao qual o certificado de cliente é verificado |

A resposta devolve o domínio como a Azion o armazenou. Além dos campos acima, ela carrega estes:

| Campo da API | Descrição |
| --- | --- |
| `id` | O ID do domínio |
| `is_active` | Se o domínio está ativo |
| `domain_name` | O endereço Azion do domínio, no formato `xxxxxxxxxx.map.azionedge.net` |

## Ambiente

Antes de entrar em operação, você pode ativar uma instância de teste para visualizar as configurações. Ao criar um novo domínio, você pode escolher o tipo de ambiente:

- **Global Edge Network**: ambiente de produção da aplicação. O Azion domain tem o formato `xxxx.map.azionedge.net`.
- **Staging Network**: ambiente para testar a aplicação. Essa configuração não afeta o ambiente de produção. O Azion domain tem o formato `xxxx.preview.azionedge.net`.

Para ativar a seleção de ambiente, entre em contato com a [equipe de Vendas](https://www.azion.com/pt-br/contato/).

## CNAME

É o serviço padrão responsável pela criação das configurações de CNAME, tornando possível personalizar o domínio da aplicação.

Você pode restringir o acesso à sua aplicação a partir do Azion domain ao ativar **CNAME Access Only**.

O limite padrão é de 50 CNAMEs por domínio. Para o limite e como aumentá-lo, consulte [Limites do Domains](/pt-br/documentacao/plataforma/domains/limites/).

## Certificado digital

Para utilizar seu domínio em HTTPS, você precisa de um certificado TLS (X.509). Sem custos adicionais, você pode incluir seus certificados TLS no [Azion Console](https://console.azion.com/) ou gerar um certificado Let's Encrypt™, que a Azion gerencia automaticamente.

## mTLS

Um domínio pode pedir um certificado a cada cliente durante o handshake TLS e validá-lo em relação a um certificado de CA confiável. A Azion ativa o mTLS por conta, então, para usá-lo, entre em contato com a [equipe de Vendas](https://www.azion.com/pt-br/contato/). O modelo Open Banking exige mTLS, então domínios que servem serviços financeiros e pagamentos costumam precisar dele. Para o que a verificação faz e o que cada modo decide, consulte [mTLS](/pt-br/documentacao/plataforma/workloads/mtls/).

Um domínio carrega três campos de mTLS:

| Campo | Tipo | Descrição |
| --- | --- | --- |
| `is_mtls_enabled` | boolean | `true` pede um certificado a cada cliente |
| `mtls_verification` | string | `enforce` ou `permissive` |
| `mtls_trusted_ca_certificate_id` | integer | O certificado do tipo `trusted_ca_certificate` em relação ao qual o certificado de cliente é verificado |

No Azion Console, o formulário do domínio carrega os três na seção **Mutual Authentication Settings**: o switch **Mutual Authentication**, **Mode** com os cards **Enforce** e **Permissive**, e **Trusted CA Certificate**, que é obrigatório e termina com **Create Digital Trusted CA certificate**. O formulário não tem campo para uma lista de revogação de certificados: uma CRL é vinculada a um workload, em `mtls.config.crl`.

Na API v3, os três campos viajam junto com o resto do domínio, em um `POST` para `https://api.azionapi.net/domains`:

```json
{
  "name": "mydomain.com",
  "cnames": ["mydomain.com"],
  "digital_certificate_id": null,
  "edge_application_id": <application-id>,
  "is_mtls_enabled": true,
  "mtls_verification": "enforce",
  "mtls_trusted_ca_certificate_id": <trusted-ca-id>
}
```

O certificado de CA confiável em si é enviado com `certificate_type` igual a `trusted_ca_certificate`, em um `POST` para `https://api.azionapi.net/digital_certificates`. Uma conta na API v4 define o mTLS no workload, e [Configure mTLS em um workload](/pt-br/documentacao/guias/seguranca-de-aplicacoes/tls-e-certificados/associar-um-certificado-mtls/) traz esses passos.

## Stage local de um domínio personalizado

O arquivo local `etc/hosts` mapeia endereços IP para domínios. Quando você [mapeia seu domínio para os endereços IP do seu workload](/pt-br/documentacao/guias/desenvolvimento-de-aplicacoes/primeiros-passos/testar-edge-application-atraves-do-arquivo-hosts/) no seu arquivo `hosts`, você força a resolução DNS do seu computador a acessar esse domínio pela Azion e não pelos servidores DNS públicos. Assim, você pode testar sua aplicação localmente como se já estivesse implantada no seu domínio personalizado antes de [apontar seu domínio](/pt-br/documentacao/guias/plataforma/migracao/apontar-dominio-para-a-azion/) para a Azion.
