Você invoca um modelo com duas coisas: o id do modelo e um corpo de requisição no formato que o modelo recebe. Para um modelo de chat, esse corpo segue o formato de chat completions da OpenAI. [AI Inference](/pt-br/documentacao/plataforma/ai-inference/) aceita essa requisição por duas interfaces, e as duas alcançam os mesmos modelos. Você chama o binding `Azion.AI.run` dentro de uma [Function](/pt-br/documentacao/plataforma/functions/), ou envia uma requisição POST para o endpoint HTTP compatível com OpenAI que uma Application implantada a partir de um template serve. Os campos da requisição são os mesmos nas duas interfaces, e por HTTP o corpo também carrega o id do modelo.

## O binding Azion.AI.run

`Azion.AI.run` é o binding de runtime que uma Function chama para invocar um modelo. Ele recebe primeiro o id do modelo e depois o corpo da requisição que esta página descreve, e a chamada é assíncrona. O primeiro argumento decide o modelo, então o corpo não precisa do id, e um campo `model` no corpo é ignorado. O binding não recebe credencial, URL base nem host. O binding pertence ao runtime, e não ao AI Inference, então os parâmetros, a chamada e o valor de retorno dele estão documentados com os outros bindings do runtime, em [AI Inference API](/pt-br/documentacao/devtools/runtime/api-reference/ai/).

`Azion.AI.models()` retorna uma promise que resolve para um array com os ids de modelo que a sua conta pode chamar:

```ts
const modelIds = await Azion.AI.models()
```

## O endpoint HTTP

Uma Application implantada a partir do [AI Inference Starter Kit](/pt-br/documentacao/guias/desenvolvimento-de-aplicacoes/frameworks/ai-inference-starter-kit/) serve o endpoint nos domínios do Workload dela: o workload domain, na forma `xxxxxxxxxx.map.azionedge.net`, ou um domínio personalizado desse Workload. A Function que o template instala lê o id do modelo no campo `model` do corpo e passa o corpo inteiro para `Azion.AI.run`.

O endpoint recebe uma requisição `POST` com um corpo JSON que carrega `model`, em qualquer path do domínio. `/v1/chat/completions` é o path que os clientes da OpenAI usam, e o mesmo endpoint também serve corpos de embedding e de reranking. O header `Content-Type` precisa ser exatamente `application/json`: um header que acrescenta um parâmetro `charset` é recusado. O template não configura nenhuma autenticação na frente do endpoint. Quando você adiciona autenticação à sua Application, inclua o header que ela exige, por exemplo `-H "Authorization: Bearer [TOKEN VALUE]"`.

Uma requisição a um modelo de chat por HTTP:

```bash
curl -X POST https://<your-application-domain>/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{
    "model": "qwen-qwen25-vl-3b-instruct-awq",
    "max_tokens": 16,
    "messages": [
      { "role": "user", "content": "Name one European capital." }
    ]
  }'
```

O endpoint retorna o objeto que o modelo retorna:

```json
{
  "id": "chatcmpl-0cb926279c564d868e3e3e8a2fc20313",
  "object": "chat.completion",
  "created": 1794444659,
  "model": "qwen-qwen25-vl-3b-instruct-awq",
  "choices": [
    {
      "index": 0,
      "message": {
        "role": "assistant",
        "content": "Paris, France is a European capital.",
        "refusal": null,
        "annotations": null,
        "audio": null,
        "function_call": null,
        "tool_calls": [],
        "reasoning_content": null
      },
      "logprobs": null,
      "finish_reason": "stop",
      "stop_reason": null
    }
  ],
  "service_tier": null,
  "system_fingerprint": null,
  "usage": {
    "prompt_tokens": 24,
    "total_tokens": 33,
    "completion_tokens": 9,
    "prompt_tokens_details": null
  },
  "prompt_logprobs": null,
  "kv_transfer_params": null
}
```

## Campos da requisição

Estes campos formam o corpo de uma requisição a um modelo de chat, seja pelo binding, seja por HTTP. Por HTTP, o corpo também carrega um campo `model` com o id do modelo. Pelo binding, o primeiro parâmetro carrega o id. Cada modelo de chat indica a [OpenAI Chat API](https://developers.openai.com/api/reference/overview) como o endpoint com o qual é compatível. Os tipos, os padrões e os limites abaixo são os que o schema de requisição dos modelos de chat declara. Um traço na coluna Padrão significa que o schema não define padrão para o campo.

| Campo | Tipo | Obrigatório | Padrão | Descrição |
| --- | --- | --- | --- | --- |
| `messages` | array | Sim | — | A conversa enviada ao modelo. Cada entrada é um objeto de mensagem de system, user, assistant ou tool. |
| `temperature` | number | Não | — | Temperatura de amostragem. Mínimo `0`, máximo `2`. |
| `top_p` | number | Não | — | Valor de amostragem top-p. Máximo `1`. |
| `n` | integer | Não | `1` | Número de respostas a gerar. Mínimo `1`. |
| `stream` | boolean | Não | `false` | Envia a resposta em stream em vez de retorná-la inteira. Aceita `true` ou `false`. |
| `max_tokens` | integer | Não | — | Número máximo de tokens que o modelo gera para cada resposta. Mínimo `1`. |
| `presence_penalty` | number | Não | — | Penalidade de presença aplicada à saída. Máximo `2`. |
| `frequency_penalty` | number | Não | — | Penalidade de frequência aplicada à saída. Máximo `2`. |
| `tools` | array | Não | — | As definições de ferramentas que o modelo pode chamar. As páginas dos modelos que a suportam mostram o formato. |

Um valor além de um mínimo ou de um máximo é recusado com `validation error: Minimum` ou `validation error: Maximum` antes de o modelo rodar. O validador também aceita `top_p` até `0` e as duas penalidades até `-2`, mas o servidor do modelo recusa uma requisição que define `temperature` e `top_p` como `0` e as duas penalidades como `-2` ao mesmo tempo. Com `n` igual a `2`, `choices` carrega duas entradas, e `max_tokens` vale para cada uma.

Um campo que o modelo não conhece é ignorado, sem erro. Um nome de campo escrito errado, portanto, não muda nada na resposta: confira cada nome com as tabelas desta página.

O context length, o tool calling e os tipos de entrada que um modelo aceita são valores por modelo, e não fazem parte deste schema. Para o modelo que você chama, consulte [Modelos de AI](/pt-br/documentacao/plataforma/ai-inference/modelos/).

### Escolha de ferramenta, seed, parada e log probabilities

Os modelos de chat também aceitam os campos abaixo, que o schema de requisição não lista. As descrições valem para o Qwen3 30B A3B Instruct 2507 FP8.

| Campo | Tipo | Descrição |
| --- | --- | --- |
| `tool_choice` | string ou object | Como o modelo escolhe uma ferramenta: `auto`, `none`, `required` ou um objeto que indica uma função. |
| `seed` | integer | Uma semente de amostragem: a mesma requisição com o mesmo `seed` pode retornar a mesma saída. |
| `stream_options` | object | Opções de uma resposta em stream, como `{"include_usage": true}`. Exige `stream` igual a `true`. |
| `logprobs` | boolean | Com `true`, preenche `choices[].logprobs` com a log probability de cada token gerado. |
| `top_logprobs` | integer | O número de tokens alternativos listados para cada token gerado, com `logprobs` igual a `true`. |
| `stop` | array de strings | Sequências que encerram a geração antes de serem escritas. |

`auto` é o comportamento sem `tool_choice`, `required` força uma chamada de ferramenta e `none` impede `tool_calls`. Com `none`, o Qwen3 30B ainda pode escrever a chamada como texto em `content`. No Qwen2.5 VL AWQ 3B e no 7B, um objeto que indica a ferramenta retorna `tool_calls`, com `finish_reason` igual a `stop`. Um `seed` que não é inteiro, um `tool_choice` fora desses valores e `stream_options` sem `stream` são recusados com `Request failed with status 400`.

Com `logprobs`, cada entrada de `choices[].logprobs.content` carrega `token`, `logprob`, `bytes` e `top_logprobs`. Com `stop`, a resposta termina antes da sequência, e `finish_reason` é `stop`.

## Objetos de mensagem

Cada entrada do array `messages` é um objeto de mensagem, e o campo `role` indica qual dos quatro objetos ela é. O campo `content` recebe texto como string ou, em um modelo que aceita imagens, um array de partes de conteúdo.

| Role | Campos obrigatórios |
| --- | --- |
| `system` | `role`, `content` |
| `user` | `role`, `content` |
| `assistant` | `role`, `content`; `content` é `null` quando a mensagem carrega `tool_calls` |
| `tool` | `role`, `tool_call_id`, `content` |

Um array `messages` que carrega um turno anterior:

```json
{
  "messages": [
    { "role": "system", "content": "You are a helpful assistant." },
    { "role": "user", "content": "Name three European capitals." },
    { "role": "assistant", "content": "Amsterdam, Athens, and Lisbon." },
    { "role": "user", "content": "Which of them is furthest south?" }
  ]
}
```

Quando um modelo chama uma ferramenta, a resposta dele carrega `tool_calls`, com `content` igual a `null` e `finish_reason` igual a `tool_calls`. Para devolver o resultado, envie a conversa de novo com a mensagem do assistant como o modelo a retornou, seguida de uma mensagem `tool`. O `tool_call_id` dessa mensagem é o `id` da chamada de ferramenta, e o `content` dela carrega o resultado. O modelo então responde em texto. Um array `messages` que devolve o resultado de uma ferramenta, enviado com o mesmo array `tools` da primeira requisição:

```json
{
  "messages": [
    { "role": "system", "content": "You are a helpful assistant with access to tools." },
    { "role": "user", "content": "What is the weather in London?" },
    {
      "role": "assistant",
      "content": null,
      "tool_calls": [
        {
          "id": "chatcmpl-tool-789b0d0737f84d09b61eee169a3bea75",
          "type": "function",
          "function": { "name": "get_weather", "arguments": "{\"location\": \"London\"}" }
        }
      ]
    },
    {
      "role": "tool",
      "tool_call_id": "chatcmpl-tool-789b0d0737f84d09b61eee169a3bea75",
      "content": "{\"temperature_c\": 14, \"condition\": \"light rain\"}"
    }
  ]
}
```

Um modelo que aceita imagens recebe `content` como um array de partes de conteúdo em vez de uma string. Cada parte indica o seu `type` e carrega o campo que esse tipo usa. As páginas dos modelos que aceitam imagens mostram esse formato; um modelo somente de texto recebe a string.

| Parte de conteúdo | Tipo | Carrega |
| --- | --- | --- |
| `type` | string | Qual é o tipo desta parte: `text` ou `image_url`. |
| `text` | string | O texto da parte, quando `type` é `text`. |
| `image_url` | object | A imagem da parte, quando `type` é `image_url`. |
| `image_url.url` | string | Uma URL `https` que serve a imagem, ou uma URL `data:` com a imagem em base64. |

Um array `content` que carrega texto e uma imagem:

```json
{
  "role": "user",
  "content": [
    { "type": "text", "text": "What is in this image?" },
    { "type": "image_url", "image_url": { "url": "<your-image-url>" } }
  ]
}
```

A URL precisa servir uma imagem que o modelo consiga buscar. Uma URL que não serve imagem falha com `Request failed with status 500`, que não indica a imagem como causa. Para saber se um modelo aceita imagens, consulte os tipos de entrada na página dele em [Modelos de AI](/pt-br/documentacao/plataforma/ai-inference/modelos/).

## Respostas em stream

Com `stream` igual a `true`, as duas interfaces entregam a resposta em chunks, cada um um objeto `chat.completion.chunk`. O texto de cada chunk fica em `choices[0].delta.content`, e o último chunk de texto carrega `finish_reason`.

- **Pelo binding**, `Azion.AI.run` resolve para um iterador assíncrono de objetos de chunk já interpretados, que a Function lê com `for await`. Nenhum item `[DONE]` chega ao iterador.
- **Por HTTP**, o endpoint responde com `Content-Type: text/event-stream`, uma linha `data:` por chunk e uma linha final `data: [DONE]`.

`usage` chega somente quando o corpo define `stream_options` como `{"include_usage": true}`. Ele vem em um chunk a mais no fim, cujo array `choices` é vazio:

```json
{
  "id": "chatcmpl-2d0e9241b82048c49b9f946c746818b1",
  "object": "chat.completion.chunk",
  "created": 1794443931,
  "model": "qwen-qwen3-30b-a3b-instruct-2507-fp8",
  "choices": [],
  "usage": {
    "prompt_tokens": 20,
    "total_tokens": 30,
    "completion_tokens": 10
  }
}
```

## Requisições de embedding

Um modelo de embedding recebe um corpo de requisição que o schema de chat não define. `input` carrega o texto a converter em embedding e é o único campo obrigatório. Os outros dois definem o vetor retornado, e cada um aceita um conjunto fixo de valores. Um valor fora do conjunto é recusado com `validation error: Enum`.

| Campo | Tipo | Obrigatório | Descrição |
| --- | --- | --- | --- |
| `input` | string ou array de strings | Sim | O texto a converter em embedding. Um array retorna um embedding por string. |
| `encoding_format` | string | Não | A codificação do embedding na resposta: `float` ou `base64`. |
| `dimensions` | integer | Não | O tamanho do vetor que o modelo retorna: `256`, `512`, `1024`, `2048` ou `4096`. |

Sem `dimensions`, o Qwen3 Embedding 4B retorna um vetor de 2560 números. Com `dimensions` igual a `4096`, a requisição é aceita e o vetor continua com 2560 números. Com `base64`, o embedding é uma string que decodifica em floats de 32 bits little-endian, 4 bytes por dimensão. Os vetores vêm normalizados para comprimento 1.

Para armazenar os vetores que um modelo de embedding retorna e consultá-los, consulte [Vector search](/pt-br/documentacao/plataforma/sql-database/vector-search/).

## Requisições de reranking

Uma requisição de reranking não carrega um array `messages`. Ela carrega uma consulta e os documentos a classificar em relação a ela, e os dois são obrigatórios.

| Campo | Tipo | Carrega |
| --- | --- | --- |
| `query` | string | A consulta contra a qual os documentos são classificados. |
| `documents` | array de strings | Os documentos a classificar por relevância em relação a `query`. |
| `top_n` | integer | O número de resultados a retornar, das maiores pontuações para as menores. |
| `max_tokens_per_doc` | integer | Declarado pelo schema, que não indica padrão nem limites. Aceito, sem efeito documentado. |

## Campos da resposta

Um modelo retorna um objeto, qualquer que seja a interface que carregou a requisição. O formato depende do que o modelo faz, e os três abaixo cobrem todos os modelos do catálogo. As páginas dos modelos mostram um payload completo para os modelos que têm um.

O campo `model` carrega o id interno do modelo na conta, em minúsculas com hífens, que pode ser diferente do id que a requisição enviou. Uma requisição a `Qwen/Qwen3-30B-A3B-Instruct-2507-FP8` retorna `qwen-qwen3-30b-a3b-instruct-2507-fp8`, e o GPT-OSS 20B retorna `gpt-oss-20b`, um id que `Azion.AI.run` recusa como entrada. Não use o campo `model` de uma resposta como id.

Um modelo de chat retorna um objeto `chat.completion`:

| Campo | Tipo | Carrega |
| --- | --- | --- |
| `id` | string | O identificador desta completion. |
| `object` | string | `chat.completion`. |
| `created` | integer | Quando a completion foi criada. |
| `model` | string | O id interno do modelo que respondeu. |
| `choices` | array | As respostas geradas, uma entrada por resposta solicitada em `n`. |
| `choices[].index` | integer | A posição da entrada em `choices`. |
| `choices[].message` | object | A mensagem gerada. |
| `choices[].message.role` | string | `assistant`. |
| `choices[].message.content` | string ou null | O texto gerado. É daqui que uma resposta de chat é lida. |
| `choices[].message.reasoning_content` | string ou null | O raciocínio que o modelo retornou, quando ele retorna algum. |
| `choices[].message.reasoning` | string ou null | O mesmo raciocínio, no Qwen3 30B e no GPT-OSS 20B. |
| `choices[].message.tool_calls` | array | As ferramentas que o modelo escolheu chamar. |
| `choices[].finish_reason` | string | Por que a geração parou, como `stop`, `length` ou `tool_calls`. |
| `choices[].stop_reason` | string, integer ou null | A condição de parada que encerrou a geração. |
| `choices[].logprobs` | object ou null | As log probabilities, quando a requisição define `logprobs`. |
| `usage` | object | Os tokens que a requisição e a resposta consumiram. |
| `usage.prompt_tokens` | integer | Os tokens lidos da requisição. |
| `usage.completion_tokens` | integer | Os tokens gerados na resposta. |
| `usage.total_tokens` | integer | Os dois somados. |
| `usage.prompt_tokens_details` | object ou null | O detalhamento dos tokens do prompt. |
| `prompt_logprobs` | object ou null | As log probabilities do prompt, quando o modelo as retorna. |

`content` é `null` quando a mensagem carrega `tool_calls`. Ele também pode ser `null` no GPT-OSS 20B, que preenche `reasoning_content` primeiro: com um `max_tokens` pequeno, o raciocínio pode usar todo o orçamento, e `finish_reason` é `length`.

Uma resposta de chat também carrega campos que esta tabela não descreve: `refusal`, `annotations`, `audio` e `function_call` na mensagem; `token_ids` em cada choice no Qwen3 30B; e `service_tier`, `system_fingerprint`, `prompt_token_ids` e `kv_transfer_params` no nível de cima.

Um modelo de embedding retorna um objeto `list` cujo array `data` contém um embedding por entrada:

| Campo | Tipo | Carrega |
| --- | --- | --- |
| `id` | string | O identificador desta resposta. |
| `object` | string | `list`. |
| `created` | integer | Quando a resposta foi criada. |
| `model` | string | O id interno do modelo que respondeu. |
| `data` | array | Os embeddings, um por entrada. |
| `data[].index` | integer | A posição da entrada em `data`. |
| `data[].object` | string | `embedding`. |
| `data[].embedding` | array de números ou string | O vetor, ou a string base64 dele quando `encoding_format` é `base64`. |
| `usage` | object | Os tokens que a requisição consumiu: `prompt_tokens`, `total_tokens`, `completion_tokens` e `prompt_tokens_details`. |

Um modelo de reranking retorna os resultados classificados:

| Campo | Tipo | Carrega |
| --- | --- | --- |
| `id` | string | O identificador desta resposta. |
| `model` | string | O id interno do modelo que respondeu. |
| `results` | array | As entradas classificadas, da maior pontuação para a menor. |
| `results[].index` | integer | A posição que a entrada ocupava em `documents`. |
| `results[].document` | object | A entrada que foi classificada. |
| `results[].document.text` | string | O texto dessa entrada. |
| `results[].document.multi_modal` | null | Um campo que o reranker retorna sem valor. |
| `results[].relevance_score` | number | O quanto o modelo julgou a entrada relevante. |
| `usage.total_tokens` | integer | Os tokens que a requisição consumiu. |

## Erros

`Azion.AI.run` rejeita com um objeto de erro que carrega somente `name` e `message`, sem campo `code` nem `status`. Leia `message` para distinguir os casos:

| Erro | Causa | O que fazer |
| --- | --- | --- |
| `AIError: model not found or not allowed` | O id do modelo não existe, ou a conta não tem acesso ao AI Inference. A mensagem não diz qual. | Copie o id da página do modelo, ou liste os ids com `Azion.AI.models()`. Para o acesso, consulte [Limites do AI Inference](/pt-br/documentacao/plataforma/ai-inference/limites/). |
| `AIError: validation error: <Type> {path: "<field>"}` | O corpo não corresponde ao schema do modelo. O modelo não roda. | Corrija o campo que `path` indica. |
| `Error: Request failed with status <N>` | O servidor do modelo recusou uma requisição que passou na validação. A mensagem não traz o motivo. | Confira os valores que o servidor do modelo recusa, listados abaixo. |

O `<Type>` da validação é `Required` para um campo ausente, `WrongType` para um valor do tipo errado, com um `detail` como `The value must be integer`, `Minimum` ou `Maximum` para um valor além de um limite, `Enum` para um valor fora de um conjunto fixo, ou `OneOf` para uma mensagem que não corresponde a nenhum objeto de mensagem.

O servidor do modelo recusa estes casos com status `400`: um prompt maior que o contexto que o modelo serve, que a mensagem não indica como causa; `temperature` e `top_p` em `0` com as duas penalidades em `-2`; uma requisição com `tools` sem `tool_choice` no Qwen2.5 VL AWQ 3B, no Qwen2.5 VL AWQ 7B ou no Nanonets-OCR-s; um `seed` que não é inteiro; um `tool_choice` desconhecido; e `stream_options` sem `stream`. Uma `image_url` que não serve imagem falha com status `500`.

O endpoint do AI Inference Starter Kit retorna os próprios erros como um corpo JSON com um campo `error`:

| Status | Corpo | Causa |
| --- | --- | --- |
| `400` | `{"error":"Request must be a POST request with JSON body"}` | O método não é `POST`, ou `Content-Type` não é exatamente `application/json`. |
| `400` | `{"error":"Invalid JSON in request body"}` | O corpo não é um JSON válido. |
| `400` | `{"error":"Missing 'model' field in request body"}` | O corpo não tem o campo `model`. |
| `400` | `{"error":"<model> not found or not allowed"}` | O binding recusou o id com `model not found or not allowed`. |
| `400` | `{"error":"Invalid input for <model>"}` | O binding recusou o corpo com um `validation error`. |
| `500` | `{"error":"AI internal error"}` | Qualquer outro erro, como uma recusa do servidor do modelo. |
