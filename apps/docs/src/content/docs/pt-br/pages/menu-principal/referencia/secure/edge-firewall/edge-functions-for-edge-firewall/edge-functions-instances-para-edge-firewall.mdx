Uma Function Instance contém uma [Function](/pt-br/documentacao/plataforma/functions/) e os argumentos que essa Function recebe em um [Firewall](/pt-br/documentacao/plataforma/firewall/). Ela só é executada quando um comportamento _Run Function_ de uma regra do [Rules Engine para Firewall](/pt-br/documentacao/plataforma/firewall/rules-engine/) a executa. Por exemplo, um Firewall pode ter duas Function Instances de [Bot Manager Lite](/pt-br/documentacao/plataforma/firewall/bot-manager/bot-manager-lite/) com valores de `threshold` diferentes, e cada regra executa uma delas.

---

## Campos da instância

Cada Firewall tem as suas próprias Function Instances. Azion Console as lista na aba **Functions Instances** do Firewall, onde o botão **Function** abre um drawer com três seções: **General**, **Function** e **Arguments**. A API disponibiliza os mesmos registros em `/v4/workspace/firewalls/<firewall-id>/functions`, e Azion CLI com o substantivo `firewall-instance`. Uma Function Instance carrega nove campos: cinco que uma requisição define e quatro que a plataforma define e retorna.

| Campo | Tipo | Obrigatório | Padrão | Descrição |
| --- | --- | --- | --- | --- |
| `id` | integer | Somente leitura | — | O ID da Function Instance. Um comportamento _Run Function_ o envia em `value`, e toda chamada sobre uma instância o recebe no caminho |
| `name` | string, de 1 a 100 caracteres | Sim | — | O nome da instância. O Console o mostra como o campo **Name** e pede um nome único e descritivo |
| `function` | integer | Sim | — | O ID da Function que a instância contém, que não é o ID da instância. A Function precisa ter o ambiente de execução `firewall`. O Console o mostra como o seletor **Function** |
| `args` | objeto ou array JSON, com menos de 100.000 bytes | Não | Os `default_args` da Function | Os argumentos que a Function recebe, armazenados exatamente como enviados. O Console os mostra como o editor **Arguments**. Para os padrões e a validação deles, consulte [Argumentos](/pt-br/documentacao/plataforma/firewall/functions-instances/#argumentos) |
| `azion_form` | objeto JSON | Não | `{}` | Um JSON Schema que renderiza os argumentos como um formulário |
| `active` | boolean | Não | `true` | Sempre `true`. A API recusa `false` com `29002`, e o Console envia `true` quando cria uma instância e não oferece nenhum controle para alterá-lo |
| `last_editor` | string | Somente leitura | — | A conta que alterou a instância pela última vez, mostrada na coluna **Last Editor** |
| `last_modified` | date-time | Somente leitura | — | Quando a instância foi alterada pela última vez, mostrado na coluna **Last Modified** |
| `created_at` | date-time | Somente leitura | — | Quando a instância foi criada |

A lista **Functions Instances** mostra as colunas **Name**, **Function**, **Last Editor** e **Last Modified**. Ela não tem coluna de status, e **Delete** é a única ação de linha.

O seletor **Function** lista somente as Functions da conta cujo `execution_environment` é `firewall`, e o rodapé **Create Function** dele cria uma. A API recusa uma Function com qualquer outro ambiente com `29001`.

Functions do Azion Marketplace, como Bot Manager Lite, Secure Token e JWT, também são executadas em um Firewall. Uma Function do Marketplace chega à conta pelo Azion Console, porque nem Azion CLI nem a API têm uma operação de instalação. O código dela não pode ser modificado. Para mais informações, consulte [Como o Marketplace funciona](/pt-br/documentacao/plataforma/marketplace/como-funciona/).

Uma Function Instance nunca altera o código da sua Function. Ela define o nome e os argumentos.

A aba **Functions Instances** só aparece quando [Functions](/pt-br/documentacao/plataforma/functions/) está ativado no Firewall. O switch é **Functions**, na aba **Main Settings** do Firewall, e `modules.functions.enabled` na API. Functions está ativado quando um Firewall é criado pela API, pela CLI ou pela página de criação do Console. O drawer de criação do Console é a exceção e começa com Functions desativado.

Uma Application tem a mesma entidade em uma aba de mesmo nome. Uma Function Instance em um Firewall executa a sua Function antes que a requisição chegue à Application, então a Function pode interromper a requisição ali. Uma Function Instance em uma Application executa a sua Function como parte de servir a requisição. Para mais informações, consulte [Function Instances](/pt-br/documentacao/plataforma/applications/functions-instances/).

## Argumentos

Os argumentos de uma Function Instance são o valor JSON no campo `args`, e a Function os lê cada vez que a instância é executada. Eles permitem que uma Function se comporte de forma diferente em cada instância: o código continua o mesmo, e só os valores mudam.

No Azion Console, a seção **Arguments** do drawer da instância os edita. Quando a Function selecionada carrega um `azion_form` não vazio, a seção oferece dois modos: _Form_, o padrão, que monta um formulário a partir desse schema, e _JSON_. Caso contrário, o editor JSON aparece sozinho.

O texto de ajuda do editor orienta o código a ler um argumento como `event.args.arg_name`, porque `event.args` é um objeto. Para o lado do código de uma Function em um Firewall, consulte [Functions no Firewall](/pt-br/documentacao/plataforma/firewall/functions/).

Um objeto `args` que define quatro argumentos do Bot Manager Lite:

```json
{
  "threshold": 30,
  "action": "deny",
  "internal_logs": 2,
  "log_tag": "storefront-bots"
}
```

As quatro chaves estão entre os argumentos para os quais Bot Manager Lite traz valores padrão. Uma chave que a Function não lê é salva da mesma forma, e a Function a ignora.

### Argumentos padrão

O registro de uma Function carrega `default_args`, os valores de argumento com que a Function é distribuída, ao lado do seu `azion_form`. O comando `azion describe function --function-id <function-id>` retorna os dois. Quando uma requisição cria uma Function Instance sem o campo `args`, a API copia os `default_args` da Function para a instância. Quando a instância define `args`, esse objeto substitui os padrões por inteiro, e a instância armazena apenas as chaves dele.

Uma Function Instance criada com `args` igual a `{}` armazena `{}`. Por exemplo, uma instância com `args` igual a `{}` de uma Function que traz um `threshold` de `30` nos seus `default_args` não mostra nenhum `threshold`.

Os oito argumentos padrão do Bot Manager Lite são `action`, `bad_fingerprint_list`, `disabled_rules`, `good_fingerprint_list`, `internal_logs`, `log_headers`, `log_tag` e `threshold`. Para saber o que cada um faz, consulte [Argumentos](/pt-br/documentacao/plataforma/firewall/bot-manager/argumentos/).

### Validação de argumentos

A plataforma verifica três propriedades de `args`. O Azion Console recusa um conteúdo que não pode ser interpretado, com `Invalid JSON`. A API recusa um valor que não é um objeto ou um array JSON, com `23001`, e um valor grande demais, com `23000`.

Um objeto com uma chave, enviado como JSON compacto, é recusado com 100.000 bytes e aceito com 99.999 bytes. Para todos os limites que um Firewall aplica, consulte [Limites de Firewall](/pt-br/documentacao/plataforma/firewall/limites/).

Nada verifica as chaves ou os valores em relação à Function. A plataforma armazena cada chave como foi enviada, com o seu tipo JSON, inclusive uma chave que a Function nunca lê, e o salvamento é concluído. Por exemplo, uma instância com `"thresold": 5` é salva e retorna na leitura exatamente como foi digitada, e não define `threshold`. Nem a API nem a Azion CLI informam a chave com erro de digitação, então compare o nome de cada chave com a documentação da Function antes de salvar.

## Comportamento Run Function

Uma Function Instance só é executada quando um comportamento _Run Function_ de uma regra de Firewall a executa. Quando uma requisição corresponde aos critérios dessa regra, a plataforma executa a Function com os argumentos da instância. A Function é executada na infraestrutura distribuída da Azion, antes que a requisição chegue à Application. O que o cliente recebe depende, então, do que a Function faz com a requisição.

Na API, o comportamento é `run_function`, e o atributo `value` contém o `id` da instância, nunca o ID da Function:

```json
{ "type": "run_function", "attributes": { "value": <function-instance-id> } }
```

No Azion Console, escolher _Run Function_ adiciona a lista **Select a Function**. A lista contém as Function Instances deste Firewall, e não as Functions da conta, e o rodapé **Create Function Instance** dela cria uma. Cada regra pode ter um comportamento _Run Function_, então uma regra executa uma instância.

O comportamento exige Functions ativado no Firewall. Quando Functions está desativado no Firewall, o Console mostra _Run Function - required Functions_ e não permite selecioná-lo. No Azion Console, a opção também exige acesso a Functions na conta: sem ele, a opção mantém o rótulo _Run Function_ e não pode ser selecionada.

Uma regra que executa uma instância em toda requisição, porque `${request_uri}` `starts_with` `/` corresponde a toda URI:

```json
{
  "name": "Run Bot Manager on every request",
  "active": true,
  "criteria": [[{ "variable": "${request_uri}", "conditional": "if", "operator": "starts_with", "argument": "/" }]],
  "behaviors": [{ "type": "run_function", "attributes": { "value": <function-instance-id> } }]
}
```

Para a ordem em que um Firewall executa as suas regras, consulte [Como Firewall funciona](/pt-br/documentacao/plataforma/firewall/como-funciona/).

## API

As operações de instância ficam em `https://api.azion.com/v4/workspace/firewalls/<firewall-id>/functions`. Cada chamada se autentica com um personal token no header `Authorization: Token [TOKEN VALUE]`, e uma chamada com corpo adiciona `Content-Type: application/json`.

| Operação | Método e caminho |
| --- | --- |
| Listar as instâncias de um Firewall | `GET /functions` |
| Criar uma instância | `POST /functions` |
| Consultar uma instância | `GET /functions/{function_id}` |
| Substituir uma instância | `PUT /functions/{function_id}` |
| Atualizar parte de uma instância | `PATCH /functions/{function_id}` |
| Excluir uma instância | `DELETE /functions/{function_id}` |

Nesses caminhos, `{function_id}` recebe o ID da instância, não o ID da Function. Criar, substituir, atualizar ou excluir uma instância responde `202`. Ler uma instância responde `200`, com o registro em `data` e sem a chave `state`.

Crie uma instância do Bot Manager Lite com quatro argumentos definidos, em que `<function-id>` é o ID da Function Bot Manager Lite na sua conta:

```bash
curl --request POST \
  --url https://api.azion.com/v4/workspace/firewalls/<firewall-id>/functions \
  --header 'Accept: application/json' \
  --header 'Authorization: Token [TOKEN VALUE]' \
  --header 'Content-Type: application/json' \
  --data '{
  "name": "bot-manager-lite",
  "function": <function-id>,
  "active": true,
  "args": { "threshold": 30, "action": "deny", "internal_logs": 2, "log_tag": "storefront-bots" }
}'
```

A resposta é `202`, com um `state` igual a `pending` e a instância em `data`. Este trecho mantém `id` e os campos que a chamada enviou:

```json
{
  "state": "pending",
  "data": {
    "id": <function-instance-id>,
    "name": "bot-manager-lite",
    "args": { "threshold": 30, "action": "deny", "internal_logs": 2, "log_tag": "storefront-bots" },
    "azion_form": {},
    "function": <function-id>,
    "active": true
  }
}
```

A plataforma armazena `azion_form` como `{}` porque a chamada não enviou nenhum. O `id` em `data` é o valor que um comportamento _Run Function_ envia.

## CLI

O substantivo `firewall-instance` da Azion CLI cria, lista, lê, atualiza e exclui instâncias.

| Comando | O que faz |
| --- | --- |
| `azion create firewall-instance` | Cria uma instância, com `--name`, `--firewall-id`, `--function-id`, `--args` e `--active`, ou com `--file` |
| `azion list firewall-instance` | Lista as instâncias de um Firewall, com `--firewall-id`, nas colunas `ID`, `NAME`, `ACTIVE` e `FUNCTION` |
| `azion describe firewall-instance` | Retorna uma instância, com `--firewall-id` e `--instance-id`. `--format json` imprime o registro |
| `azion update firewall-instance` | Altera uma instância, com `--firewall-id`, `--instance-id` e as flags de `create` |
| `azion delete firewall-instance` | Exclui uma instância, com `--firewall-id` e `--instance-id` |

A flag `--args` recebe o caminho de um arquivo JSON, não JSON inline. Com JSON inline, a CLI responde `Error: failed to read args file: open <json>: no such file or directory`. Um arquivo que define três argumentos:

```json
{"threshold": 10, "action": "deny", "log_tag": "bm-probe"}
```

Salve-o como `args.json` e, depois, crie a instância:

```bash
azion create firewall-instance --name my-instance --firewall-id <firewall-id> \
  --function-id <function-id> --args args.json --active true
```

```text
Created Firewall Function Instance with ID <function-instance-id>
```

Releia a instância:

```bash
azion describe firewall-instance --firewall-id <firewall-id> --instance-id <function-instance-id> --format json
```

Os argumentos retornam com as chaves, os valores e os tipos JSON que o arquivo enviou. Um trecho do registro:

```json
{
 "active": true,
 "args": { "action": "deny", "log_tag": "bm-probe", "threshold": 10 },
 "azion_form": {},
 "function": <function-id>,
 "id": <function-instance-id>,
 "name": "my-instance"
}
```

Na criação, Azion CLI imprime a mensagem de um erro da API dentro de `Error: failed to create the Firewall Function Instance: [...]`, ou dentro de `Error: failed to create the Firewall Rule: [...]` para uma regra.

## Erros

Toda chamada de instância ou de regra recusada nesta página responde `400` com um array `errors`. Cada entrada carrega um `code`, um `title`, um `detail`, o `status` e um ponteiro `source` que nomeia o campo, e algumas entradas adicionam um objeto `meta`:

```json
{
  "errors": [
    {
      "code": "23000",
      "title": "JSON Args Size Too Big",
      "detail": "Value size (in bytes) is too big. Maximum size allowed is 100000 bytes.",
      "status": "400",
      "source": { "pointer": "/data/args" },
      "meta": { "max_size": 100000 }
    }
  ]
}
```

| Código | Título | Mensagem | Causa | Correção |
| --- | --- | --- | --- | --- |
| `10046` | Max Length | `Ensure this field has no more than 100 characters.` | Um `name` com mais de 100 caracteres. | Envie um nome com 100 caracteres ou menos. |
| `23000` | JSON Args Size Too Big | `Value size (in bytes) is too big. Maximum size allowed is 100000 bytes.` | Um valor de `args` no limite ou acima dele, como um payload de 102.400 bytes. | Reduza `args` para menos de 100.000 bytes. |
| `23001` | Invalid JSON Format | `Invalid JSON format. Only JSON objects and arrays are allowed.` | Um valor de `args` que é uma string ou um número. | Envie um objeto ou um array JSON. |
| `25011` | Duplicated Behavior | `The behavior 'run_function' is duplicated.` | Uma regra com dois comportamentos `run_function`. | Mantenha um _Run Function_ por regra, e execute a outra instância a partir de outra regra. |
| `25030` | Entity Not Found | `Function Instance '<id>' not found.` | Um `value` de `run_function` que não nomeia nenhuma instância deste Firewall, como o ID da Function em vez do ID da instância dela. | Envie o `id` de uma instância existente. |
| `29000` | Name Already In Use | `The name is already in use.` | Um `name` que outra Function Instance do mesmo Firewall já tem. | Escolha um nome que nenhuma outra instância deste Firewall use. |
| `29001` | Invalid Function Runtime | `Invalid edge function runtime. You should use a function designed for Edge Firewall.` | Uma `function` cujo `execution_environment` é `application`. | Instancie uma Function cujo `execution_environment` é `firewall`. |
| `29002` | Cant Deactivate Function Instance | `You can't deactivate a function instance.` | Um `active` igual a `false`, na criação ou na atualização. | Envie `true`, ou deixe `active` de fora. |
| `29005` | Function Not Found | `The function was not found.` | Um ID de `function` que não nomeia nenhuma Function da conta, como `99999999`. | Envie o ID de uma Function existente. |

O Azion Console verifica o editor **Arguments** antes de chamar a API. Um conteúdo que não pode ser interpretado como JSON mostra `Invalid JSON`. Corrija o JSON e, depois, salve.
