**Edge Pulse** é um recurso da plataforma que coleta medições de carregamento de página nos browsers das pessoas que visitam as suas páginas. O [monitoramento de usuários reais](https://www.azion.com/pt-br/learning/observability/o-que-e-monitoramento-tempo-real/) mede um site nos dispositivos dos visitantes: um script em cada página informa como a visita carregou, sem teste agendado. Use Edge Pulse para comparar o tempo de carregamento das suas páginas, ver os tipos de conexão dos visitantes e achar páginas alcançadas por redirecionamento.

Edge Pulse chega às suas páginas por meio de um script:

- A [tag JavaScript do Edge Pulse](/pt-br/documentacao/plataforma/edge-pulse/tag-javascript/) mede os carregamentos da página em que você a coloca, em uma de duas formas do Azion Console. As duas formas carregam o script de maneiras diferentes, o que importa em uma página com Content Security Policy.

## Caminho da requisição

Uma página com a tag não informa cada visita: um browser envia no máximo um registro a cada 30 minutos para cada esquema e host. Edge Pulse só recebe um registro de uma página que carrega a tag.

O diagrama acompanha um carregamento de página até uma consulta ler o registro dele. As setas contínuas levam uma requisição, a seta grossa leva o registro de carregamento da página e as setas pontilhadas levam a resposta. Cada rótulo começa com o número da etapa correspondente na lista.

```mermaid
flowchart TD
  Browser(["Browser do visitante"])
  Page[["A sua página com a tag"]]
  Client["RUM Client"]
  EP["Edge Pulse"]
  Reader(["A sua consulta GraphQL"])
  Browser -->|"1. requisição da página"| Page
  Browser -->|"2. download do script"| Client
  Browser ==>|"3. registro de carregamento"| EP
  Reader -->|"4. consulta em pulseEvents"| EP
  EP -.->|"5. registros correspondentes"| Reader
```

1. O browser de um visitante carrega uma página sua que carrega a tag JavaScript do Edge Pulse.
2. A tag faz o browser baixar o RUM Client, o script que faz a medição. A medição começa pelo menos 2 segundos depois do evento load, então uma visita que termina antes não envia nada.
3. Passados 30 minutos desde o último registro desse browser para o mesmo esquema e host, o RUM Client envia um registro de carregamento. O horário desse último registro fica no local storage do browser, então uma janela privada recomeça a contagem. O registro leva o endereço da página, os valores de Navigation Timing, a estimativa de conexão e o ID que a tag tem no endereço.
4. Você envia uma consulta GraphQL no dataset `pulseEvents` ao endpoint da API GraphQL do Real-Time Events, com um token da sua conta.
5. A API responde com os registros correspondentes. Em um teste em uma conta, ela retornou os registros com o client ID dessa conta, cerca de um minuto após o envio pelo browser.
