WebSocket é um protocolo, especificado na [RFC 6455](https://datatracker.ietf.org/doc/html/rfc6455), que mantém uma conexão TCP aberta nos dois sentidos entre um cliente e um servidor. Depois de um handshake, os dois lados trocam dados por ela em tempo real. **WebSocket Proxy** é uma feature de Applications que transporta essa conexão entre os seus usuários e a sua origem. A conexão passa por uma [Application](/pt-br/documentacao/plataforma/applications/) que atua como proxy reverso para essa origem. Use WebSocket Proxy para aplicações em tempo real, como jogos online, chat, notificações e streaming ao vivo.

WebSocket Proxy serve quando o servidor WebSocket é a sua origem, porque a Application apenas transporta a conexão até ela. Quando uma [Function](/pt-br/documentacao/plataforma/functions/) deve agir ela mesma como servidor ou cliente WebSocket, use a [WebSocket API](/pt-br/documentacao/devtools/runtime/api-reference/websocket/), que trata um upgrade do lado do servidor com `upgradeWebSocket()`.

## Disponibilidade

A Azion ativa WebSocket Proxy em uma conta somente mediante solicitação. Para solicitá-lo, consulte [Diretrizes de suporte](/pt-br/documentacao/suporte/).

## Suporte no cliente e na origem

Uma conexão WebSocket por meio de uma Application precisa de suporte nativo a WebSocket nas duas pontas: o cliente que abre a conexão e o servidor na origem. A maioria dos navegadores oferece suporte nativo a WebSocket. Para a lista de navegadores com suporte nativo, consulte [Can I use](https://caniuse.com/websockets).

## Headers de upgrade

Uma Application com WebSocket Proxy habilitado lê dois headers de requisição para decidir se uma requisição abre uma conexão WebSocket. Ela trata a requisição como uma conexão WebSocket, e faz o proxy dela até a origem, quando `Upgrade` traz `websocket` e `Connection` traz o token `upgrade`. O token vale com qualquer combinação de maiúsculas e minúsculas, sozinho ou em uma lista como `Connection: keep-alive, Upgrade`.

| Header | Valor |
| --- | --- |
| `Upgrade` | `websocket` |
| `Connection` | `upgrade` |

Quando o cliente omite um dos headers, ou envia um valor que não indica o upgrade, a Application não realiza o upgrade em direção à origem.

As regras de um Firewall, em [Rules Engine para Firewall](/pt-br/documentacao/plataforma/firewall/rules-engine/), podem inspecionar uma requisição WebSocket antes que o upgrade seja concluído.

## Erros

Uma conexão WebSocket por meio de uma Application se completa com `101 Switching Protocols`. Qualquer outro status significa que o upgrade não foi concluído, mesmo um `2xx` de sucesso ou um `3xx` de redirecionamento:

| Status | Causa | O que fazer |
| --- | --- | --- |
| Qualquer status diferente de `101` | O cliente, a Application ou a origem não completou a conexão WebSocket | Verifique o cliente, a origem e os [headers de upgrade](/pt-br/documentacao/plataforma/applications/websocket/#headers-de-upgrade) |

O cliente e a origem precisam de suporte nativo a WebSocket, e a requisição precisa dos dois headers de upgrade com os seus valores.

---

## Limites

A Azion recicla as conexões keepalive nos seus servidores aproximadamente a cada 15 minutos, e pode encerrar uma conexão WebSocket ativa que fique aberta além desse tempo. A sua aplicação então precisa detectar a conexão encerrada e restabelecê-la. Para o tempo máximo de uma conexão WebSocket, e para saber como solicitar um limite maior para o seu plano, consulte [Limites de Applications](/pt-br/documentacao/plataforma/applications/limites/).
