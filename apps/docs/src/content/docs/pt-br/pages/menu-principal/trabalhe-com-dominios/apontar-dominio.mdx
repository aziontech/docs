Você pode enviar o tráfego de um hostname seu para um [workload](/pt-br/documentacao/plataforma/workloads/) com um registro DNS no seu provedor de DNS ou no [Edge DNS](/pt-br/documentacao/plataforma/edge-dns/). Para que o workload aceite o hostname primeiro, consulte [Adicione um domínio a um workload](/pt-br/documentacao/guias/plataforma/migracao/configurar-dominio/).

A Azion gera um hostname para cada workload, o workload domain, no formato `<id>.map.azionedge.net` na infraestrutura de produção. O seu registro DNS envia os resolvedores do seu hostname para esse workload domain. O registro e o workload funcionam como um par. O workload responde apenas aos hostnames listados nos seus domínios, e um hostname listado não recebe tráfego até que o DNS o envie para lá.

Uma conta que opera na API v3 com Domains aponta os seus registros para o endereço de cada domínio, em vez disso. Para mais informações, consulte [Domains](/pt-br/documentacao/plataforma/workloads/domains/).

---

## Pré-requisitos

- Um workload na infraestrutura de produção que lista o seu hostname nos seus domínios. Um workload de staging, cujo workload domain termina em `.preview.azionedge.net`, recusa todo hostname personalizado.
- O workload domain. Azion Console o mostra no campo **Workload Domain** do workload, e a [Azion CLI](/pt-br/documentacao/devtools/cli/) e a [Azion API](https://api.azion.com/) o retornam em `workload_domain`.
- Acesso aos registros DNS do seu domínio, no seu provedor de DNS ou no Edge DNS.

Para testar o workload no seu hostname antes de alterar qualquer registro DNS, consulte [Teste uma aplicação pelo arquivo hosts](/pt-br/documentacao/guias/desenvolvimento-de-aplicacoes/primeiros-passos/testar-edge-application-atraves-do-arquivo-hosts/).

## Crie um registro CNAME para um subdomínio

Um subdomínio, como `www.example.com`, chega ao workload por um registro `CNAME`. O registro informa aos resolvedores que o hostname é um alias do workload domain, então eles continuam a consulta ali e retornam os endereços da infraestrutura distribuída da Azion.

O registro recebe estes valores:

| Campo | Valor |
| --- | --- |
| Name | A parte de host do seu hostname, como `www` para `www.example.com` |
| Type | `CNAME` |
| Value | O workload domain, como `<id>.map.azionedge.net` |

Para criar o registro no seu provedor de DNS:

<DocSteps>
  <DocStep title="Entre no seu provedor de DNS" />
  <DocStep title="Abra os registros DNS do seu domínio">

  Selecione o seu domínio e abra a página em que o seu provedor de DNS gerencia os registros dele.

  </DocStep>
  <DocStep title="Crie o registro CNAME">

  Informe o nome, o tipo e o valor da tabela. Se já existir um registro para o hostname, edite-o.

  </DocStep>
  <DocStep title="Salve o registro" />
</DocSteps>

O seu provedor de DNS lista o registro `CNAME`, com o workload domain como valor. Quando o Edge DNS guarda a zona do seu domínio, crie o mesmo registro nessa zona.

Alguns provedores de DNS aceitam um registro wildcard, `*`, que envia todo subdomínio, como `www.example.com` e `blog.example.com`, para um único destino. Um workload recusa uma entrada wildcard nos seus domínios com `The domain does not conform to the format defined in RFC 1035.`, então liste no workload cada hostname que o registro wildcard envia.

## Aponte um domínio apex com Edge DNS

Um domínio apex é o seu domínio sem subdomínio, como `example.com`. Um workload aceita um domínio apex como hostname, mas alguns provedores de DNS não permitem apontar o apex para outro hostname. Nesse caso, um registro `CNAME` no apex não é uma opção.

Em vez disso, Edge DNS aponta o apex para o workload com um registro `ANAME`. O registro funciona quando o Edge DNS responde pelo seu domínio, ou seja, quando os nameservers do seu domínio apontam para a Azion. Para mais informações, consulte [Edge DNS](/pt-br/documentacao/plataforma/edge-dns/).

Para criar o registro `ANAME`, consulte [Acesse IPs por meio de um root domain (ANAME)](/pt-br/documentacao/guias/seguranca-de-aplicacoes/dns/acessar-root-domain/).

## Confira se o hostname resolve

Os resolvedores podem levar algum tempo para carregar um registro novo ou alterado. Para conferir a resposta para o seu hostname, consulte-o com o `dig`. Substitua `www.example.com` pelo seu hostname:

```bash
dig +short www.example.com
```

Quando os resolvedores carregam um registro `CNAME`, a resposta lista o workload domain que você informou como valor.

As requisições ao seu hostname passam então a chegar à aplicação do deployment do workload. Cada alteração de workload se espalha pela infraestrutura distribuída da Azion ao longo de vários minutos. Se você listou o seu hostname no workload nos últimos minutos, algumas requisições ainda podem receber a configuração anterior. Envie a requisição novamente até que todas as respostas coincidam.

Uma requisição `https://` ao seu hostname também exige um certificado de servidor que cubra o hostname, vinculado ao workload. Para obter um, consulte [Solicite um certificado Let's Encrypt](/pt-br/documentacao/guias/seguranca-de-aplicacoes/tls-e-certificados/como-gerar-um-certificado-lets-encrypt/) ou [Envie um certificado digital](/pt-br/documentacao/guias/seguranca-de-aplicacoes/tls-e-certificados/certificado-digital/).
