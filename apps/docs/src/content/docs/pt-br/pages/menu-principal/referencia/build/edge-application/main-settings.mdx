Main Settings é o conjunto de valores que se aplicam a uma [aplicação](/pt-br/documentacao/plataforma/applications/) como um todo: o nome, os Produtos habilitados nela, se ela registra as regras que cada requisição executa e se ela está ativa. Azion Console agrupa esses valores na aba **Main Settings** da aplicação, e a API os retorna como campos do objeto da aplicação. Para o caminho que uma requisição percorre em uma aplicação, consulte [Como Applications funciona](/pt-br/documentacao/plataforma/applications/como-funciona/).

---

## Seções e campos

A aba **Main Settings** tem quatro seções: **General**, **Modules**, **Debug Rules** e **Status**. **General** guarda o **Name** da aplicação. A aba traz **Cancel** e **Save**, e uma alteração é salva com **Save**.

Cada seção corresponde a um ou mais campos da aplicação na API. A última coluna traz o valor que cada campo assume quando uma requisição de criação envia apenas `name` e `active`.

| Seção | Configuração | Campo da API | Tipo | Valor na criação |
| --- | --- | --- | --- | --- |
| **General** | **Name** | `name` | string, de 1 a 100 caracteres | O valor que a requisição de criação envia |
| **Modules** | Um switch por Produto | `modules.<product>.enabled` | boolean | `true` para `cache` e `functions`, `false` para `application_accelerator` e `image_processor` |
| **Debug Rules** | **Active** | `debug` | boolean | `false` |
| **Status** | **Active** | `active` | boolean | O valor que a requisição de criação envia, ou `true` quando a requisição o omite |

Por exemplo, uma aplicação que você cria pela API apenas com `name` e `active` tem [Cache](/pt-br/documentacao/plataforma/applications/cache/) e [Functions](/pt-br/documentacao/plataforma/functions/) ativados desde o início. [Application Accelerator](/pt-br/documentacao/plataforma/applications/application-accelerator/) fica desativado até você ativá-lo.

O switch **Active** da seção **Status** desativa a aplicação e a ativa de novo sem excluí-la. A API carrega o mesmo estado no boolean `active`.

---

## Produtos

A seção **Modules** ativa ou desativa Produtos em uma aplicação, e cada aplicação mantém o próprio conjunto. O grupo **Default Modules** dessa seção tem um switch por Produto: **Application Accelerator**, **Cache**, **Functions** e **Image Processor**. Um grupo **Subscription modules** traz uma ação **Contact sales**, e a seção informa que "Some modules require subscription."

| Produto | Chave em `modules` | Flag da CLI | O que cobre na aplicação |
| --- | --- | --- | --- |
| Application Accelerator | `application_accelerator` | `--application-accelerator` | Os behaviors marcados com `- Required Application Accelerator` e a variável `${request_uri}` |
| Cache | `cache` | `--cache` | O armazenamento em cache do conteúdo que a aplicação entrega |
| Functions | `functions` | `--function` na criação, `--functions` na atualização | As instâncias de função, executadas por um behavior _Run Function_ |
| [Image Processor](/pt-br/documentacao/plataforma/applications/image-processor/) | `image_processor` | `--image-processor` | O behavior _Optimize Images_ |

No Rules Engine, Azion Console marca um behavior que precisa de um Produto com `- Required Application Accelerator`, `- Required Function` ou `- Required Image Processor`. Um cache setting precisa de Application Accelerator para as variações da seção **Application Accelerator** e para um **Max Age** menor que 60 segundos. Os cache settings são criados na aba **Cache Settings** e aplicados por um behavior _Set Cache Policy_. As instâncias de função ficam listadas na aba **Functions Instances**.

Cache fica ativado quando você cria uma aplicação, e Azion Console informa que ele é "Automatically enabled in all accounts." Você pode ativar um Produto quando a sua conta oferece suporte a ele. Você pode desativá-lo quando nada na aplicação depende dele. Ativar um Produto pode gerar custos relacionados ao uso. Para mais informações, consulte [Preços](/pt-br/documentacao/fundamentos/precos/).

Enquanto Application Accelerator está desativado, a API recusa uma regra de requisição cujo critério lê `${request_uri}`. Ela também recusa um cache setting que varia o cache por método ou por query string, ou que define um **Max Age** menor que 60 segundos. Cada recusa traz um dos códigos da seção Erros, e a mesma regra com `${uri}` é aceita. Para as variáveis e os behaviors que cada Produto adiciona, consulte [Rules Engine para Applications](/pt-br/documentacao/plataforma/applications/rules-engine/).

Tiered Cache não tem switch na seção **Modules**, porque ele é um switch dentro de cada cache setting. Para mais informações, consulte [Tiered Cache](/pt-br/documentacao/plataforma/applications/cache/tiered-cache/).

## Debug Rules

Debug Rules registra as regras do Rules Engine executadas em cada requisição à aplicação. A configuração fica desativada quando você cria uma aplicação, e a API a guarda no boolean `debug`. No Azion Console, o switch **Active** da seção **Debug Rules** a define. Na [Azion CLI](/pt-br/documentacao/devtools/cli/), `--debug-enabled` a define em `azion create application` e em `azion update application`.

Com Debug Rules ativado, as regras executadas em uma requisição aparecem no campo `$traceback` do [Data Stream](/pt-br/documentacao/plataforma/data-stream/) e do [Real-Time Events](/pt-br/documentacao/plataforma/real-time-events/). A API GraphQL do Real-Time Events retorna as mesmas regras no campo `stacktrace`. Uma regra que não está nessa lista não foi executada na requisição.

Por exemplo, uma regra _Set Cache Policy_ pode parecer sem efeito em um path. O `$traceback` de uma requisição a esse path mostra, então, se a regra chegou a ser executada. Para as consultas que leem o campo em cada ferramenta, consulte [Depure regras criadas com Rules Engine](/pt-br/documentacao/guias/desenvolvimento-de-aplicacoes/primeiros-passos/debug-regras/).

## Configurações de entrega e protocolo

Main Settings não traz configurações de entrega nem de protocolo. Domínios, protocolos e certificados pertencem ao [workload](/pt-br/documentacao/plataforma/workloads/) que serve a aplicação, e as **Deployment Settings** do workload selecionam a **Application** que ele executa.

Em uma conta que não migrou para a API v4, a própria aplicação guarda os protocolos de entrega, as portas e as configurações de TLS. Para essas configurações, consulte [Main Settings | v3](/pt-br/documentacao/plataforma/applications/main-settings-v3/).

## API

A API serve as aplicações em `https://api.azion.com/v4/workspace/applications`. Cada chamada se autentica com um [personal token](/pt-br/documentacao/fundamentos/personal-tokens/) no header `Authorization: Token [TOKEN VALUE]`, e uma chamada com corpo também envia `Content-Type: application/json`.

| Operação | Método e path |
| --- | --- |
| Criar uma aplicação | `POST /workspace/applications` |
| Listar as aplicações da conta | `GET /workspace/applications` |
| Ler uma aplicação | `GET /workspace/applications/<application-id>` |
| Substituir uma aplicação | `PUT /workspace/applications/<application-id>` |
| Alterar parte de uma aplicação | `PATCH /workspace/applications/<application-id>` |
| Excluir uma aplicação | `DELETE /workspace/applications/<application-id>` |
| Clonar uma aplicação | `POST /workspace/applications/<application-id>/clone` |

Uma criação e um `PATCH` respondem `202`, com `state` definido como `pending`. Uma listagem e uma leitura respondem `200`.

`name` é o único campo que uma requisição de criação exige. Esta chamada cria uma aplicação apenas com um nome e um status:

```bash
curl --request POST \
  --url https://api.azion.com/v4/workspace/applications \
  --header 'Accept: application/json' \
  --header 'Authorization: Token [TOKEN VALUE]' \
  --header 'Content-Type: application/json' \
  --data '{
  "name": "my-application",
  "active": true
}'
```

A API responde `202`. Neste trecho do corpo, `modules` e `debug` trazem os valores que a plataforma definiu na criação:

```text
{"state":"pending","data":{"id":<application-id>,"name":"my-application",…,"modules":{"cache":{"enabled":true},"functions":{"enabled":true},"application_accelerator":{"enabled":false},"image_processor":{"enabled":false}},"active":true,"debug":false,…}}
```

O `id` em `data` identifica a aplicação em todas as chamadas seguintes, incluindo os paths das regras dela, como `/workspace/applications/<application-id>/request_rules`.

Esta chamada ativa Application Accelerator em uma aplicação existente:

```bash
curl --request PATCH \
  --url https://api.azion.com/v4/workspace/applications/<application-id> \
  --header 'Accept: application/json' \
  --header 'Authorization: Token [TOKEN VALUE]' \
  --header 'Content-Type: application/json' \
  --data '{
  "modules": {
    "application_accelerator": {
      "enabled": true
    }
  }
}'
```

A API responde `202` com `state` definido como `pending`. Um corpo com `functions` no lugar de `application_accelerator` ativa Functions da mesma forma, e a resposta repete o objeto `modules` com as quatro chaves.

## CLI

[Azion CLI](/pt-br/documentacao/devtools/cli/) lê e altera uma aplicação com seis comandos sob o substantivo `application`. Cada flag de Produto recebe uma string, como `true`.

| Comando | O que faz | Flags |
| --- | --- | --- |
| `azion create application` | Cria uma aplicação | `--name`, `--active`, `--debug-enabled`, `--application-accelerator`, `--cache`, `--function`, `--image-processor`, `--file` |
| `azion update application` | Altera a aplicação que `--application-id` nomeia | `--application-id`, `--name`, `--active`, `--debug-enabled`, `--application-accelerator`, `--cache`, `--functions`, `--image-processor`, `--file` |
| `azion describe application` | Retorna uma aplicação, com o objeto `modules` dela | `--application-id` |
| `azion list application` | Lista as aplicações da conta | `--details`, `--filter`, `--order-by`, `--page`, `--page-size` |
| `azion delete application` | Exclui a aplicação que `--application-id` nomeia | `--application-id`, `--cascade` |
| `azion clone application` | Copia uma aplicação com o nome em `--name` | `--application-id`, `--name` |

A flag de Functions é `--function` em `azion create application` e `--functions` em `azion update application`. Em `azion delete application`, `--cascade` também exclui os recursos que `azion deploy` criou, e o padrão dela é `true`.

Este comando ativa Application Accelerator:

```bash
azion update application --application-id <application-id> --application-accelerator true
```

```text
Updated Application with ID <application-id>
```

A saída de `azion describe application` inclui o objeto `modules` da aplicação:

```bash
azion describe application --application-id <application-id>
```

Em uma aplicação com os quatro Produtos ativados, o objeto fica assim:

```json
"modules": {
  "application_accelerator": { "enabled": true },
  "cache": { "enabled": true },
  "functions": { "enabled": true },
  "image_processor": { "enabled": true }
}
```

## Erros

Um Produto desativado na aplicação aparece como a recusa do objeto que precisa dele, com `400`. Cada uma dessas recusas nomeia Application Accelerator. Este corpo responde a uma regra de requisição com `${request_uri}`:

```json
{
  "errors": [
    {
      "code": "25047",
      "title": "Missing Required Modules",
      "detail": " It requires any of the following modules to be enabled: ['application_accelerator'].",
      "status": "400",
      "source": { "pointer": "/data/criteria/0/0/variable" },
      "meta": {
        "message_prefix": "",
        "owner_modules": "any",
        "missing_required_modules": ["application_accelerator"]
      }
    }
  ]
}
```

`meta.missing_required_modules` lista as chaves que devem ser ativadas no objeto `modules` da aplicação.

| Código | Título | Status | O que causa | O que fazer |
| --- | --- | --- | --- | --- |
| `25047` | Missing Required Modules | 400 | Uma regra de requisição cujos critérios leem `${request_uri}`, em uma aplicação com Application Accelerator desativado | Ative Application Accelerator, ou faça a correspondência com `${uri}`, que a API aceita sem ele |
| `21013` | This Configuration Requires The Edge Application's Application Accelerator Module | 400 | Um cache setting que varia o cache por método ou por query string, em uma aplicação com Application Accelerator desativado. O pointer nomeia a variação, como `/data/modules/application_accelerator/cache_vary_by_method` | Ative Application Accelerator e, em seguida, salve o cache setting novamente |
| `21021` | Edge Cache Max Age Lower Than The Minimum Allowed By Application's Application Accelerator Module | 400 | Um cache setting cujo `modules.cache.max_age` é menor que 60, em uma aplicação com Application Accelerator desativado. `meta.min_value` é `60` | Ative Application Accelerator, ou defina **Max Age** como 60 segundos ou mais |
