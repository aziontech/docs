Uma exceção é uma entrada em um rule set do [WAF](/pt-br/documentacao/plataforma/firewall/waf/) que isenta parte de uma requisição de uma regra interna, ou de todas elas. Ela tem efeito em todo [Firewall](/pt-br/documentacao/plataforma/firewall/) com uma regra cujo comportamento [_Set WAF_](/pt-br/documentacao/plataforma/firewall/rules-engine/#set-waf) aplica esse rule set. O Azion Console chama a mesma entidade de allowed rule, e a API e a Azion CLI a chamam de exceção.

---

## Campos

O Azion Console lista as exceções de um rule set na aba **Allowed Rules**, onde **Allowed Rule** abre o painel **Create Allowed Rule**, e a descrição de cada campo indica o rótulo dele no Console. Uma exceção carrega seis campos que uma requisição pode definir. Outros três são definidos pela plataforma e retornados em uma resposta, nunca enviados.

| Campo | Tipo | Obrigatório | Padrão | Descrição |
| --- | --- | --- | --- | --- |
| `id` | integer | Somente leitura | — | O identificador que toda chamada posterior usa |
| `rule_id` | integer | Não | `0` | A regra interna a que a exceção se aplica. `0` significa todas as regras. É fixado na criação, e uma alteração posterior retorna `26005`. O Console o renderiza como o dropdown **Rule ID** |
| `name` | string, de 1 a 255 caracteres | Sim | — | Texto livre indicando para que serve a exceção. Duas exceções podem ter o mesmo nome. O Console o renderiza como o campo **Description** |
| `path` | string, até 255 caracteres, nullable | Não | `null` | Restringe a exceção a um path de requisição, que nos testes correspondeu somente de forma exata. Uma exceção sem `path` se aplicou em todos os paths testados. O Console o renderiza como o campo **Path** |
| `conditions` | array de objetos, com pelo menos 1 entrada | Sim | — | As partes da requisição que a exceção cobre, listadas em Condições. O Console renderiza cada entrada como um campo **Condition** |
| `operator` | string | Não | `contains` | Como as strings da exceção são comparadas: `contains` ou `regex`. O Console o renderiza como o switch **Active** da seção **Regex**, que envia `regex` quando ligado |
| `active` | boolean | Não | `true` | Se a exceção está em vigor. Uma exceção inativa permanece no rule set e deixa de isentar qualquer coisa. O Console o renderiza como o switch **Active** da seção **Status** |
| `last_editor` | string | Somente leitura | — | O e-mail da conta que alterou a exceção pela última vez |
| `last_modified` | date-time | Somente leitura | — | Quando a exceção foi alterada pela última vez |

A menor exceção que a API aceita carrega um `name` e uma condição. Ela então se aplica a todas as regras, em todos os paths, com `contains`, e está ativa.

`rule_id` recebe um identificador das regras internas, e `0` representa todas elas. Para a lista de identificadores e o que cada regra detecta, consulte [Rule sets do WAF](/pt-br/documentacao/plataforma/firewall/waf/rule-sets/#regras-internas). Os mesmos identificadores nomeiam as linhas da tela de Tuning, e o Console mostra a descrição de cada regra ao lado do identificador dela.

`last_editor` e `last_modified` são retornados pela API e pela CLI. O formulário do Console não os exibe.

### Condições

Uma condição nomeia uma match zone e, onde a zona é específica, a string a que essa zona se aplica. O formato de uma condição é fixado pelo seu valor de `match`, e há três.

| Formato | Chaves | Match zones que o aceitam |
| --- | --- | --- |
| Genérico | `match` | As nove zonas cujo nome não carrega `specific` |
| Específico em um nome | `match` e `name` | `specific_body_form_field_name`, `specific_http_header_name`, `specific_query_string_name` |
| Específico em um valor | `match` e `value` | `specific_body_form_field_value`, `specific_http_header_value`, `specific_query_string_value` |

O `name` ou o `value` de uma condição carrega entre 1 e 255 caracteres. Uma condição `specific_*` enviada sem nenhum dos dois retorna `400` com `10059 Required Field`, e uma enviada com uma string vazia retorna `400` com `10018 Blank Field`. Um caractere como `[` ou `é` retorna `400` com `26000 Invalid Zone Input`, e `[` faz isso tanto sob `regex` quanto sob `contains`.

```json
{ "match": "any_query_string_value" }
```

```json
{ "match": "specific_query_string_name", "name": "q" }
```

```json
{ "match": "specific_query_string_value", "value": "q" }
```

Uma exceção pode carregar várias condições, e toda entrada é mantida, dentro de dois limites. No máximo uma condição usa uma match zone `specific_*`, e uma segunda retorna `26004`. Duas condições não podem visar a mesma parte da requisição, como `any_query_string_name` com `any_query_string_value`, e um par assim retorna `26003`. Uma zona genérica e uma zona `specific_*` na mesma parte são aceitas juntas, como `any_query_string_value` com `specific_query_string_name`.

### Operador

`operator` decide como as strings da exceção são comparadas, e governa dois lugares ao mesmo tempo: o `path` da exceção e o `name` ou `value` da condição.

Sob o padrão `contains`, nenhuma das duas strings é lida como um padrão. Nos testes, o `path` da exceção correspondeu ao path da requisição somente de forma exata. Uma exceção em `/hdr` não cobriu `/hdrx` nem `/other/hdr`, uma em `/x6` não cobriu `/x6/data`, e uma em `/` não cobriu outros paths. Para o que cada condição liberou em tempo de execução, consulte Match zones.

Sob `regex`, ambas são expressões regulares, e cada uma é validada separadamente. Um `path` malformado retorna `400` com `26008 Invalid Regex Value` e um ponteiro `source` de `/data/path`; um `name` de condição malformado retorna o mesmo código com um ponteiro de `/data/conditions/0/name`. **Não há como tornar uma delas uma expressão regular e a outra um literal.** `regex` amplia as duas juntas, então uma exceção que precisa de um padrão na condição também precisa de um no `path`.

O Console renderiza a escolha como o switch **Active** da seção **Regex**, que trata os campos de condição como expressões regulares em todas as match zones. O switch envia `regex` quando ligado e `contains` quando desligado.

## Match zones

Uma match zone é a parte de uma requisição que uma condição compara. A API a recebe como `conditions[].match`. O Azion Console rotula o campo como **Condition**, e não como match zone, e o inicializa com _Any HTTP Header Value_.

São quinze, listadas a seguir na ordem em que o Console as oferece. Uma opção que começa com `Specific` revela um campo **Name** ou **Value** adicional, e qual dos dois aparece é fixado pela opção.

| Opção do Console | Valor da API | Formato da condição | O que compara |
| --- | --- | --- | --- |
| Any HTTP Header Value | `any_http_header_value` | Genérico | O valor de cada header da requisição, como `Mozilla/5.0` ou `application/json` |
| Any HTTP Header Name | `any_http_header_name` | Genérico | O nome de cada header da requisição, como `User-Agent` ou `Authorization` |
| Specific HTTP Header Value | `specific_http_header_value` | Específico em um valor | O `value` da condição. Nos testes, um nome de header em `value` liberou a correspondência somente nesse header |
| Specific HTTP Header Name | `specific_http_header_name` | Específico em um nome | O `name` da condição, como `cookie`. Nos testes, não liberou uma correspondência nesse header |
| Any Query String Value | `any_query_string_value` | Genérico | O valor de cada parâmetro de query string. Em `?id=123&user=admin`, `123` e `admin` |
| Any Query String Name | `any_query_string_name` | Genérico | O nome de cada parâmetro de query string. Em `?id=123&user=admin`, `id` e `user` |
| Specific Query String Value | `specific_query_string_value` | Específico em um valor | O `value` da condição. Nos testes, um nome de parâmetro em `value` liberou a correspondência somente nesse parâmetro |
| Specific Query String Name | `specific_query_string_name` | Específico em um nome | O `name` da condição, como `token`. Nos testes, não liberou uma correspondência nesse parâmetro |
| Body Form Field Value | `body_form_field_value` | Genérico | O valor de cada campo de formulário no corpo da requisição |
| Body Form Field Name | `body_form_field_name` | Genérico | O nome de cada campo de formulário no corpo da requisição |
| Specific Body Form Field Value | `specific_body_form_field_value` | Específico em um valor | O `value` da condição, contra o valor de cada campo de formulário no corpo |
| Specific Body Form Field Name | `specific_body_form_field_name` | Específico em um nome | O `name` da condição, como `api_key`, contra o nome de um campo de formulário no corpo |
| Any URL | `any_url` | Genérico | A URL da requisição |
| Raw Body | `raw_body` | Genérico | O corpo da requisição não interpretado, como um payload JSON ou XML |
| File Extension | `file_extension` | Genérico | A extensão de arquivo na requisição, como `.php`, `.exe` ou `.sh` |

Um valor fora desse conjunto retorna `400` com `10039 Invalid Choice` e um ponteiro `source` que nomeia a condição, como `/data/conditions/0/match`.

**`specific_http_header_value` com um nome de header em `value` liberou um header nos testes.** As duas chaves dele são `match` e `value`. Uma exceção `{"match": "specific_http_header_value", "value": "cookie"}` com a regra `1005` liberou uma correspondência em um header `Cookie` cujo valor não continha `cookie`. Um caractere pipe em um parâmetro de query string da mesma requisição continuou sendo recusado.

**`specific_http_header_name` armazena um nome de header, mas em tempo de execução não liberou uma correspondência nesse header.** A API armazena a string exatamente como ela é enviada, então `cookie`, `Cookie` e `HTTP_COOKIE` são todos aceitos e todos lidos de volta sem alteração. Em um teste, uma exceção com `name` `cookie` ou `HTTP_COOKIE` e o ID da regra de uma correspondência no header `Cookie` deixou essa correspondência em vigor por 24 minutos. Uma exceção com `any_http_header_value` e o mesmo `rule_id` a liberou.

Da mesma forma, `specific_query_string_name` não liberou uma correspondência no seu parâmetro em 24 minutos, enquanto `any_query_string_value` com o `rule_id` liberou todos os parâmetros. `specific_query_string_value` com o nome de parâmetro `filter` em `value` liberou a correspondência somente em `filter`, e outro parâmetro continuou sendo recusado. A mesma zona com o valor do parâmetro em `value` não liberou a correspondência.

:::caution[Atenção]
Uma chave que o formato da condição não carrega é descartada, não rejeitada. Uma condição enviada como `{"match": "any_http_header_value", "name": "cookie"}` retorna `202` e é lida de volta como `{"match": "any_http_header_value"}`, sem o `name`. A exceção passa a cobrir todos os headers da requisição em vez de um, e nada na resposta, na leitura de volta ou no Console indica isso. Para isentar um header ou um parâmetro de query string, use `specific_http_header_value` ou `specific_query_string_value` com o nome dele em `value`, o formato que liberou um único campo nos testes.
:::

## Tuning

**Tuning** é uma aba de um rule set que lista as requisições a que cada regra interna correspondeu ao longo de uma janela escolhida, uma linha por ID da regra, e transforma os registros selecionados em exceções em massa. Ela lê somente as requisições de um Workload cujo deployment define um Firewall com um comportamento _Set WAF_ que aplica o rule set. Uma consulta precisa de um Workload, ou de um domínio em uma conta que ainda usa Domains, e os outros filtros a restringem.

| Filtro | O que restringe |
| --- | --- |
| Workload ou Domain | As requisições lidas. Obrigatório |
| Time Range | A janela ao longo da qual as requisições são lidas: `Last 1 hour`, `Last 3 hours`, `Last 6 hours`, `Last 12 hours`, `Last day`, `Last 2 days` ou `Last 3 days`, a janela mais longa disponível |
| Network Lists | As requisições cujo endereço de origem está em uma [Network List](/pt-br/documentacao/plataforma/firewall/network-shield/network-lists/) |
| IP Address | As requisições vindas de um ou mais endereços de origem. O Console o recusa junto com um filtro de Network List _IP/CIDR_ |
| Country | O país de onde a requisição veio. O Console o recusa junto com um filtro de Network List _Countries_ |
| Path | Somente em **More Details**, que lista as ocorrências por trás de um ID da regra e também recebe os outros filtros |

Cada linha carrega as colunas **Rule ID**, **Hits**, **Paths**, **IPs**, **Countries**, **Top 10 IP Addresses** e **Top 10 Countries**. **Allow Rules** grava os registros selecionados no rule set como exceções, uma para cada possível ataque em cada URI, e **Create from Tuning**, na aba **Allowed Rules**, abre esta tela.

Para o procedimento, consulte [Ajuste um WAF rule set](/pt-br/documentacao/guias/seguranca-de-aplicacoes/firewall-e-waf/tune-waf/). Para saber por que o tuning é repetido em vez de feito uma única vez, consulte [Score e modos](/pt-br/documentacao/plataforma/firewall/waf/score-e-modos/).

## API

Toda operação é autenticada e fica sob `https://api.azion.com/v4/workspace/wafs/{waf_id}/exceptions`. Uma requisição carrega um token de [Personal Tokens](/pt-br/documentacao/fundamentos/personal-tokens/) no header `Authorization` sob o esquema `Token`, e uma requisição com corpo também carrega `Content-Type: application/json`. A API gerencia exceções independentemente do Console, então uma delas pode ser criada, alterada ou removida a partir de um script.

| Operação | Método e path |
| --- | --- |
| Criar uma exceção | `POST /wafs/{waf_id}/exceptions` |
| Listar exceções | `GET /wafs/{waf_id}/exceptions` |
| Recuperar uma exceção | `GET /wafs/{waf_id}/exceptions/{exception_id}` |
| Substituir uma exceção | `PUT /wafs/{waf_id}/exceptions/{exception_id}` |
| Atualizar parte de uma exceção | `PATCH /wafs/{waf_id}/exceptions/{exception_id}` |
| Remover uma exceção | `DELETE /wafs/{waf_id}/exceptions/{exception_id}` |

Uma criação, uma substituição, uma atualização parcial e uma remoção respondem `202`. Uma leitura responde `200`.

As operações da tabela são chamadas de API comuns, então a gestão de exceções cabe em um pipeline de entrega como qualquer outra mudança de configuração. A evidência a partir da qual uma exceção é escrita vem de outra superfície: Tuning é uma tela do Azion Console, e a API não a expõe. Um script lê essa evidência no [Real-Time Events](/pt-br/documentacao/plataforma/real-time-events/), onde `wafMatch` nomeia as regras internas a que uma requisição correspondeu e `wafScore` informa o score que cada família de ameaças alcançou. Ele então cria uma exceção para cada falso positivo que esses registros confirmam.

A Azion CLI é a outra superfície, e na Azion CLI 4.26.2 a flag `--conditions`, `azion update waf-exceptions` e `azion delete waf-exceptions` falham. Um script, portanto, cria exceções com `--file` e as altera ou remove pela API.

### Criar uma exceção

```bash
curl --request POST \
  --url https://api.azion.com/v4/workspace/wafs/12345/exceptions \
  --header 'Accept: application/json' \
  --header 'Authorization: Token [TOKEN VALUE]' \
  --header 'Content-Type: application/json' \
  --data '{
  "rule_id": 1013,
  "name": "docs-rework-waf-exc-generic",
  "path": "/search",
  "operator": "contains",
  "active": true,
  "conditions": [
    { "match": "any_query_string_value" }
  ]
}'
```

A resposta carrega `202`, e não `201`:

```json
{
  "state": "pending",
  "data": {
    "id": 123456,
    "rule_id": 1013,
    "name": "docs-rework-waf-exc-generic",
    "path": "/search",
    "conditions": [
      { "match": "any_query_string_value" }
    ],
    "operator": "contains",
    "active": true,
    "last_editor": "[ACCOUNT EMAIL]",
    "last_modified": "2026-01-01T12:00:00.000000Z"
  }
}
```

O `state` igual a `pending` indica que a exceção foi aceita, e o `id` em `data` é o identificador que toda chamada posterior usa. `last_editor` carrega o e-mail da conta que alterou a exceção pela última vez, e o valor deste exemplo é um placeholder.

A mesma chamada com o corpo a seguir armazena uma condição `specific_query_string_name` no parâmetro chamado `q`. A resposta carrega `202`, um novo `id` igual a `123457` e a condição ecoada sem alteração.

```json
{
  "rule_id": 1013,
  "name": "docs-rework-waf-exc-specific",
  "path": "/search",
  "operator": "contains",
  "active": true,
  "conditions": [
    { "match": "specific_query_string_name", "name": "q" }
  ]
}
```

O corpo a seguir armazena, em vez disso, uma condição `specific_query_string_value`. Ele responde `202` com um `id` igual a `123458`.

```json
{
  "rule_id": 1013,
  "name": "docs-rework-waf-exc-value",
  "path": "/search",
  "operator": "contains",
  "active": true,
  "conditions": [
    { "match": "specific_query_string_value", "value": "q" }
  ]
}
```

### Listar exceções

```bash
curl --request GET \
  --url https://api.azion.com/v4/workspace/wafs/12345/exceptions \
  --header 'Accept: application/json' \
  --header 'Authorization: Token [TOKEN VALUE]'
```

A resposta carrega `200` e o envelope de coleção a seguir, com uma exceção por entrada em `results`, cada uma no formato da resposta de criação.

| Campo | O que carrega |
| --- | --- |
| `count` | Exceções que o rule set contém |
| `total_pages` | Páginas em que o resultado se divide, no `page_size` atual |
| `page` | A página que esta resposta carrega |
| `page_size` | Exceções por página. O padrão é 10 |
| `next` | A URL da página seguinte, ou `null` |
| `previous` | A URL da página anterior, ou `null` |
| `results` | Uma exceção por entrada, carregando os campos listados em Campos |

O endpoint aceita `created_at__gte`, `created_at__lte`, `description`, `fields`, `id`, `last_editor`, `last_modified__gte`, `last_modified__lte`, `ordering`, `page`, `page_size`, `path` e `search` como query parameters. `page_size` vai de 1 a 100 e tem 10 como padrão. Um valor acima de 100 retorna `400` com `10097 Invalid Page Size`.

### Recuperar, atualizar e remover uma exceção

`GET /wafs/{waf_id}/exceptions/{exception_id}` responde `200` e retorna a exceção em `data`, sem a chave `state`.

`PUT /wafs/{waf_id}/exceptions/{exception_id}` substitui uma exceção e recebe o mesmo corpo de uma criação. Ele responde `202` com um `state` igual a `pending`. O array `conditions` é substituído, e não mesclado, então uma substituição envia todas as condições que a exceção deve manter. Uma substituição que omite `active` o redefine como `true`.

`rule_id` não pode mudar depois da criação. Uma substituição ou uma atualização parcial que carrega outro `rule_id` retorna `26005`, assim como uma substituição que omite `rule_id` em uma exceção cujo `rule_id` não é `0`.

`PATCH /wafs/{waf_id}/exceptions/{exception_id}` recebe apenas os campos enviados e responde `202`. Um corpo `{"active": false}` desativa uma exceção e deixa o resto dela como estava. Um array `conditions` em uma atualização parcial substitui o array inteiro.

`DELETE /wafs/{waf_id}/exceptions/{exception_id}` responde `202` com o corpo `{"state": "pending"}`.

## CLI

A [Azion CLI](/pt-br/documentacao/devtools/cli/) gerencia exceções sob o substantivo `waf-exceptions`. As flags a seguir são as que a Azion CLI 4.26.2 carrega, sem as flags globais que todo comando recebe.

| Comando | O que faz |
| --- | --- |
| `azion create waf-exceptions` | Cria uma exceção em um rule set |
| `azion list waf-exceptions` | Lista as exceções que um rule set contém |
| `azion describe waf-exceptions` | Retorna uma exceção |
| `azion update waf-exceptions` | Altera uma exceção |
| `azion delete waf-exceptions` | Remove uma exceção |

`azion create waf-exceptions` e `azion update waf-exceptions` compartilham as suas flags, exceto `--exception-id`, que pertence à atualização.

| Flag | O que define |
| --- | --- |
| `--waf-id` | O rule set a que a exceção pertence |
| `--name` | O nome da exceção |
| `--rule-id` | A regra interna a que a exceção se aplica |
| `--path` | O path a que a exceção fica restrita |
| `--operator` | `regex` ou `contains` |
| `--active` | `true` ou `false`. O padrão é `true` |
| `--conditions` | As condições, em JSON. Consulte o alerta a seguir antes de usá-la |
| `--file` | Um arquivo JSON que carrega o corpo, ou `-` para ler o corpo da entrada padrão |
| `--exception-id` | A exceção a alterar. Somente `azion update waf-exceptions` |

`azion list waf-exceptions` recebe `--waf-id`, `--details`, `--filter`, `--order-by`, `--page` com padrão `1` e `--page-size` com padrão `50`. `azion describe waf-exceptions` e `azion delete waf-exceptions` recebem, cada um, `--waf-id` e `--exception-id`.

:::caution[Atenção]
Na Azion CLI 4.26.2, `azion create waf-exceptions --conditions` envia um array `conditions` vazio qualquer que seja o valor recebido, e a API rejeita a requisição com `400` e `10049 Min Length List Field`. Crie a exceção a partir de um arquivo, com `--file`.

Na mesma versão, `azion update waf-exceptions` e `azion delete waf-exceptions` respondem que o ID ou o endpoint não existe, para uma exceção que existe, e a deixam sem alteração. Substitua, atualize e exclua exceções pela API.

A coluna `RULE ID` de `azion list waf-exceptions` imprime um valor que não é o ID da regra, e `--filter` retorna todas as exceções do rule set. Leia o ID da regra com `azion describe waf-exceptions` ou pela API.
:::

Escreva o corpo em um arquivo:

```json
{
  "rule_id": 1013,
  "name": "docs-rework-waf-exc-cli-file",
  "path": "/",
  "operator": "contains",
  "active": true,
  "conditions": [
    { "match": "any_query_string_value" }
  ]
}
```

Depois crie a exceção a partir dele:

```bash
azion create waf-exceptions --waf-id 12345 --file exc.json
```

```text
Created WAF Exception with ID 123459
```

`azion describe waf-exceptions` retorna uma exceção, com as chaves ordenadas pela CLI:

```bash
azion describe waf-exceptions --waf-id 12345 --exception-id 123457 --format json
```

```json
{
 "active": true,
 "conditions": [
  {
   "match": "specific_query_string_name",
   "name": "q"
  }
 ],
 "id": 123457,
 "last_editor": "[ACCOUNT EMAIL]",
 "last_modified": "2026-01-01T12:00:02.000000Z",
 "name": "docs-rework-waf-exc-specific",
 "operator": "contains",
 "path": "/search",
 "rule_id": 1013
}
```

## Erros

Uma requisição rejeitada responde `400` com um array `errors`, exceto `10004`, que responde `404`, e `10009`, que responde `415`. Cada entrada carrega um `code`, um `title`, um `detail`, o `status` e um ponteiro `source` que nomeia o campo a que a rejeição se refere. Para uma condição, o ponteiro indexa o array, então `/data/conditions/0/name` nomeia a primeira condição:

```json
{
  "errors": [
    {
      "code": "10059",
      "title": "Required Field",
      "detail": "This field is required.",
      "status": "400",
      "source": {
        "pointer": "/data/conditions/0/name"
      }
    }
  ]
}
```

| Código | Título | Mensagem | Causa | Correção |
| --- | --- | --- | --- | --- |
| `10004` | Not Found | `Not found.` | Um `waf_id` ou um `exception_id` que não existe. | Verifique cada segmento do path. |
| `10009` | Unsupported Media Type | `Unsupported media type "<media-type>" in request.` | Uma escrita enviada com um `Content-Type` diferente de `application/json`. | Envie `Content-Type: application/json`. |
| `10018` | Blank Field | `This field may not be blank.` | `name`, ou o `name` ou o `value` de uma condição, é uma string vazia. | Envie de 1 a 255 caracteres. |
| `10039` | Invalid Choice | `"<value>" is not a valid choice.` | Um valor fora de um enum: `rule_id`, `operator` ou o `match` de uma condição. | Envie um dos valores listados em Campos e Match zones. O ponteiro `source` nomeia o campo. |
| `10046` | Max Length | `Ensure this field has no more than 255 characters.` | `name`, `path`, ou o `name` ou o `value` de uma condição, tem mais de 255 caracteres. | Encurte o valor. |
| `10049` | Min Length List Field | `Ensure this field has at least 1 elements.` | Um array `conditions` vazio, que é o que `azion create waf-exceptions --conditions` sempre envia. | Envie pelo menos uma condição, pela API ou com `azion create waf-exceptions --file`. |
| `10059` | Required Field | `This field is required.` | Um campo obrigatório está ausente: `name`, `conditions`, ou o `name` ou o `value` de uma condição `specific_*`. | Adicione o campo que o ponteiro `source` nomeia. |
| `10097` | Invalid Page Size | `Page size must be between 0 and 100.` | Um `page_size` igual a `0` ou acima de 100 em uma requisição de listagem. | Peça de 1 a 100. |
| `26000` | Invalid Zone Input | `Enter a valid string with letters, numbers, symbols and space.` | O `name` ou o `value` de uma condição carrega um caractere que a API recusa, como `[` ou `é`. | Remova o caractere. |
| `26003` | Conflicting Match Conditions. | `More than one match condition on the same target.` | Duas condições visam a mesma parte da requisição, como duas entradas `specific_query_string_name`. `meta.zone_value` nomeia a parte. | Mantenha uma condição por parte, ou divida-as entre exceções. |
| `26004` | Only One 'specific' Match Condition Is Allowed Per WAF Exception. | `We support only one 'specific' match condition is allowed per WAF Exception.` | Duas condições `specific_*` em uma exceção. | Crie uma exceção para cada condição `specific_*`. |
| `26005` | Immutable WAF Exception Field | `You can't change it after creating the WAF Exception.` | Uma substituição ou uma atualização parcial altera `rule_id`, incluindo uma substituição que o omite em uma exceção cujo `rule_id` não é `0`. | Envie o `rule_id` atual, ou crie outra exceção para a outra regra. |
| `26008` | Invalid Regex Value | `The value '<value>' for this field is not valid regex value.` | `operator` é `regex` e o `path` da exceção, ou o `name` ou o `value` de uma condição, não é um padrão válido. | Corrija o padrão que o ponteiro `source` nomeia. O `meta.regex_value` da entrada repete o valor que falhou. |

Um `rule_id` igual a `0` não é um erro. É o valor legal que significa todas as regras, e responde `202` como qualquer outro.

A Azion CLI imprime a mensagem da API dentro do próprio erro. Para `10049`, a última linha diz:

```text
Error: failed to create the WAF Exception: ["Ensure this field has at least 1 elements."]
```
