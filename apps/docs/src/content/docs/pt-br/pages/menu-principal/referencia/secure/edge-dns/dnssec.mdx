O **DNSSEC** é uma feature do [Edge DNS](/pt-br/documentacao/plataforma/edge-dns/) que assina as respostas de uma zona. Quando ele está ativado, a Azion também gera os valores de delegation signer (DS) do domínio, para o seu registrador publicar. Para entender como as assinaturas e a validação funcionam, consulte [Como o Edge DNS funciona](/pt-br/documentacao/plataforma/edge-dns/como-funciona/#dnssec). Para o procedimento, consulte [Ative o DNSSEC em uma zona](/pt-br/documentacao/guias/seguranca-de-aplicacoes/dns/ativar-dnssec/).

---

## Configuração do DNSSEC

Um campo ativa ou desativa o DNSSEC de uma zona. No Azion Console: **Main Settings** › **DNSSEC** › **Enable DNSSEC**, e a mesma seção na página **Create Zone**.

| Console | Campo da API | Flag da CLI | Tipo | Obrigatório | Padrão | Valores |
| --- | --- | --- | --- | --- | --- | --- |
| **Enable DNSSEC** | `enabled` | `--enabled=true` ou `--enabled=false` | boolean | Sim, em um `PUT` | Desativado no Console, `false` na API | `true` assina a zona e gera os valores DS dela. `false` interrompe as assinaturas, e `delegation_signer` passa a `null` até o DNSSEC ser ativado de novo, quando volta com os mesmos valores. |

O DNSSEC não exige nenhuma solicitação à equipe de suporte da Azion: você mesmo o ativa, pelo Console, pela CLI ou pela API. A API não recebe chave, algoritmo nem tipo de digest, porque `enabled` é o único campo que uma requisição envia. O restante do objeto é somente leitura:

| Operação | API | CLI |
| --- | --- | --- |
| Ler o DNSSEC | `GET /v4/workspace/dns/zones/<zone-id>/dnssec` | `azion describe dnssec --zone-id <zone-id>` |
| Ativar o DNSSEC | `PATCH /v4/workspace/dns/zones/<zone-id>/dnssec` com `{"enabled":true}` | `azion update dnssec --zone-id <zone-id> --enabled=true` |
| Desativar o DNSSEC | `PATCH /v4/workspace/dns/zones/<zone-id>/dnssec` com `{"enabled":false}` | `azion update dnssec --zone-id <zone-id> --enabled=false` |

A API também aceita `PUT` no mesmo caminho, com o mesmo corpo. Toda requisição leva o header `Authorization: Token [TOKEN VALUE]`. O `azion describe dnssec` imprime `Enabled:` e `Status:` e, com `--format json`, imprime o objeto inteiro, inclusive `delegation_signer`. O `azion update dnssec` imprime `DNSSEC of DNS zone <zone-id> was updated`.

Escreva a flag da CLI com sinal de igual: `--enabled=true` ou `--enabled=false`. Escrita com espaço, `--enabled false` é lida como `true`: o comando imprime a linha de sucesso e ativa o DNSSEC, ou o mantém ativado.

## Status

O campo `status` do DNSSEC indica a etapa a que a Azion chegou ao assinar uma zona e gerar os valores DS dela. A API o retorna no objeto DNSSEC da zona, e o `azion describe dnssec` o imprime como `Status:`. O Console não mostra o status; leia-o com a API ou a CLI.

| Status | `enabled` | `delegation_signer` | O que significa |
| --- | --- | --- | --- |
| `unconfigured` | `false` | `null` | O DNSSEC nunca foi ativado na zona. |
| `waiting` | `true` | `null` | O DNSSEC está ativado, e a Azion assina a zona e gera os valores DS dela. O status passa para `ready` quando a Azion termina. |
| `ready` | `true` | Os quatro valores DS | A Azion assinou a zona, e os valores DS estão prontos para entregar ao seu registrador. |
| `ready` | `false` | `null` | O DNSSEC foi desativado depois que a zona foi assinada. A zona não está assinada. |

A primeira requisição que ativa o DNSSEC de uma zona retorna o status `waiting`, antes de os valores DS existirem:

```json
{
  "state": "executed",
  "data": {
    "enabled": true,
    "status": "waiting",
    "delegation_signer": null
  }
}
```

O status `ready` descreve apenas o lado da Azion. Uma zona chega a `ready` esteja ou não o domínio delegado aos nameservers da Azion, e antes de qualquer registrador ter o registro DS. Os resolvers que validam só começam a verificar as assinaturas da zona quando o registrador publica o registro DS.

Depois que o DNSSEC é desativado, `status` continua `ready`, enquanto `enabled` passa a `false` e `delegation_signer` passa a `null`. Leia `enabled` para saber se a zona está assinada.

## Registro DS

O registro DS liga as chaves de uma zona à zona pai. A Azion assina os registros `DNSKEY` da zona com uma chave de assinatura de chaves. O registro DS contém um hash dessa chave, o digest. O registrador publica o registro DS para que os resolvers que validam possam confiar nas chaves da zona.

Quando o status do DNSSEC é `ready` com `enabled` definido como `true`, a API retorna os quatro valores DS em `delegation_signer`:

```json
{
  "data": {
    "enabled": true,
    "status": "ready",
    "delegation_signer": {
      "algorithm_type": {"id": 13, "slug": "ECDSAP256SHA256"},
      "digest": "3d22…fc79",
      "digest_type": {"id": 2, "slug": "SHA256"},
      "key_tag": 12345
    }
  }
}
```

No Console, os mesmos quatro valores aparecem como campos bloqueados abaixo de **Enable DNSSEC**, cada um com um botão de cópia. Antes de os valores existirem, cada campo mostra `Create to show` na página **Create Zone** e `Save to show` em **Main Settings**.

| Console | Campo da API | Exemplo | O que é |
| --- | --- | --- | --- |
| **Key Tag** | `key_tag` | `12345` | O identificador da chave de assinatura de chaves da zona, um inteiro de 1 a 65.535. |
| **Algorithm** | `algorithm_type` | `13`, `ECDSAP256SHA256` | O algoritmo das chaves da zona. A API retorna o número dele em `id` e o nome em `slug`; o Console mostra o nome. |
| **Digest Type** | `digest_type` | `2`, `SHA256` | A função de hash que gerou o digest, com o número em `id` e o nome em `slug`. |
| **Digest** | `digest` | `3d22…fc79` | O hash da chave de assinatura de chaves da zona, uma string hexadecimal de 64 caracteres com `SHA256`. |

A Azion escolhe o algoritmo e o tipo de digest; nenhum campo os define. Adicione o registro DS no seu registrador só depois da delegação aos nameservers da Azion. Ele leva os quatro valores nesta ordem: key tag, número do algoritmo, número do tipo de digest e digest. Para os valores da tabela, o registro fica assim:

```text
12345 13 2 3d22…fc79
```

O registry do domínio de topo (TLD) do domínio precisa oferecer suporte a DNSSEC para que o registro DS seja publicado. Depois que você adiciona o registro, o registrador e o registry do TLD o publicam no próprio ritmo.

A Azion gera as chaves da zona e as publica, e você não adiciona nenhum registro DNSSEC à zona. Quando o status é `ready` com `enabled` definido como `true`, os nameservers da Azion publicam dois registros `DNSKEY` com algoritmo 13. As flags `257` marcam a chave de assinatura de chaves, e as flags `256` marcam a chave de assinatura de zona. A chave de assinatura de zona assina os outros registros da zona, e cada resposta leva um registro `RRSIG`, a assinatura dela.

Um registro DS dentro da sua zona, criado com a opção *DS - Delegation Signer* de **Record Type** no Azion Console, é outro registro. Ele mostra que uma zona filha delegada é confiável. Para o formato dele, consulte [Tipos de registro](/pt-br/documentacao/plataforma/edge-dns/tipos-de-registro/#ds).

Para verificar a cadeia de confiança depois que o registry publica o registro DS, use o [DNSSEC Analyzer](https://dnssec-analyzer.verisignlabs.com/).

## Efeitos da desativação do DNSSEC

Um domínio assinado só continua válido quando o registro DS sai do registrador e expira dos caches dos resolvers antes de o DNSSEC ser desativado. Para os passos em todas as interfaces, consulte [Desative o DNSSEC](/pt-br/documentacao/guias/seguranca-de-aplicacoes/dns/ativar-dnssec/#desative-o-dnssec).

Na ordem inversa, o domínio pode ficar indisponível para os resolvers que validam. Enquanto o registrador ainda publica o registro DS, ou os resolvers ainda o mantêm em cache, eles esperam respostas assinadas. A Azion não envia mais essas respostas.

Desativar o DNSSEC de uma zona muda estes valores e respostas:

- `enabled` passa a `false`, e `delegation_signer` passa a `null`.
- `status` continua `ready`.
- Em cerca de 5 minutos, os nameservers da Azion deixam de adicionar registros `RRSIG` às respostas e deixam de servir os registros `DNSKEY` da zona.
- Os resolvers podem manter os registros `DNSKEY` da zona em cache até que o time to live (TTL) de 3.600 segundos deles expire.

Ativar o DNSSEC de novo na mesma zona retorna na hora o status `ready` e os mesmos quatro valores DS. As respostas assinadas voltam em cerca de 5 minutos.

Uma consulta `DNSKEY` feita com o DNSSEC desativado recebe uma resposta vazia. Os nameservers da Azion mantêm essa resposta por até 1 hora, o mínimo do start of authority (SOA). Nesse intervalo, um resolver que valida e que tem o registro DS pode falhar ao validar a zona.

Adicione o registro DS de novo no seu registrador só depois que uma consulta `DNSKEY` aos nameservers da Azion retornar as duas chaves. Para verificar as chaves, consulte [Verifique as assinaturas](/pt-br/documentacao/guias/seguranca-de-aplicacoes/dns/ativar-dnssec/#verifique-as-assinaturas).
