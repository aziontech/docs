## Use os nomes oficiais

Toda oferta tem um nome oficial, e toda página usa esse nome. Os nomes vêm do catálogo oficial de nomes da Azion, que Product Marketing mantém para todo o conteúdo da Azion: documentação, site e material de vendas. A visão geral de cada recurso da plataforma, a raiz da seção, reflete esse catálogo. Este guia não repete os nomes atuais, porque uma cópia fica errada no dia em que um nome muda.

O catálogo dá um nome por oferta. Não existe um nome de marketing separado do nome da documentação. A primeira menção pode trazer o nome completo com a sigla entre parênteses, e toda menção depois dela usa só a sigla:

- Correto: `Web Application Firewall (WAF) inspeciona requisições HTTP e HTTPS. Aplique um conjunto de regras WAF ao firewall.`
- Incorreto: um segundo `Web Application Firewall (WAF)` na mesma página.

Chame a plataforma de **Azion Platform**, ou de **Azion Web Platform** quando o contexto pedir. Nunca escreva `Azion Edge Platform` nem `Plataforma Edge da Azion`. No possessivo, a plataforma é um substantivo comum, em minúscula: `a plataforma da Azion`.

## Mantenha nomes depreciados fora das páginas atuais

A Azion renomeou suas ofertas ao longo do tempo. Os nomes antigos ainda aparecem em páginas antigas, URLs e nomes de diretórios, e por isso parecem atuais. Trate esses nomes como história, não como sinônimos. Um nome depreciado não muda de novo, então esta lista não fica desatualizada como uma lista de nomes atuais:

| Depreciado | Atual |
| --- | --- |
| Edge Application | Applications |
| Edge Firewall | Firewall |
| Edge Connector | Connectors |
| Real-Time Manager | Console |
| Edge AI | AI Inference |
| Application Acceleration | Application Accelerator |
| Edge Cache | Cache |
| Edge Functions | Functions |
| Image Processing | Image Processor |
| Edge Orchestrator | Orchestrator |
| Edge KV | KV Store |
| Edge Storage | Object Storage |
| Edge SQL | SQL Database |

| Data Streaming | Data Stream |

**Edge DNS** e **Edge Pulse** são nomes oficiais atuais. A palavra *Edge* neles não indica um nome depreciado.

## Nomeie o recurso em que o leitor trabalha

A Azion descreve o que oferece com quatro termos (Platform, Product, Platform Resource e Feature). Eles são conceitos relacionados, não quatro níveis de uma hierarquia: um recurso da plataforma pode ou não ser um produto, e uma feature pode pertencer à plataforma ou a um recurso da plataforma.

| Termo | Responde | Definição |
| --- | --- | --- |
| Plataforma | O que é a experiência integrada da Azion? | A infraestrutura distribuída da Azion, sua tecnologia integrada e as interfaces para construir, proteger e escalar workloads, como o Console, a API e a CLI |
| Produto | Que oferta a Azion leva ao mercado? | Uma oferta de mercado formada por um ou mais recursos da plataforma e features que resolve um problema do cliente, como WAF ou Object Storage |
| Recurso da plataforma | O que o leitor cria ou gerencia? | Uma entidade identificável que o cliente cria, configura, opera ou gerencia, e que o Console, a API, a CLI ou a documentação podem referenciar, como uma aplicação, um firewall, uma função ou um bucket |
| Feature | O que o leitor pode fazer ou ativar? | Uma funcionalidade visível da plataforma ou de um recurso da plataforma, que um produto pode incluir, como regras personalizadas de firewall ou DNSSEC |

A documentação usa a nomenclatura de recurso da plataforma. Produto é um termo de go-to-market, usado principalmente em material de marketing e vendas, e a tabela o define para o leitor reconhecê-lo lá. Uma página de documentação chama cada seção pelo nome oficial e chama a oferta de recurso da plataforma, nunca de produto: ela nomeia o que o leitor cria ou gerencia, e liga um recurso da plataforma a outro com um verbo.

Uma feature sempre tem escopo, então diga se ela vale para a plataforma ou para um recurso da plataforma. Um campo ou uma opção de um recurso é uma configuração, não uma feature.

**Applications**, **Firewall**, **Connectors**, **Workloads**, **Custom Pages** e **Certificate Manager** são exemplos de tipos de recurso da plataforma; o catálogo de nomes tem a lista completa. A coisa que o leitor cria é uma instância, em minúscula: uma aplicação, um firewall, um connector.

Azion Console, a API, a CLI, o Terraform Provider e o Copilot também são recursos da plataforma. São eles que o leitor usa para chegar à plataforma, então uma página pode chamá-los de interfaces: `Crie a aplicação no Console ou com a API.`

- Correto: `Configure um firewall para proteger a aplicação.`
- Correto: a linha da sidebar que abre o WAF dentro de Firewall diz `WAF`, nunca `Firewall WAF` nem `Web Application Firewall`, porque um rótulo nunca repete o pai.

## Nomeie um módulo pelo seu host

Um módulo é parte de um recurso da plataforma, ou de outro módulo, e depende desse host para funcionar. Web Application Firewall (WAF), Network Shield, Bot Manager e DDoS Protection são módulos do Firewall. Cache, Application Accelerator e Image Processor são módulos de Applications, e Tiered Cache é um módulo do Cache. Um módulo também pode ser um produto, como o WAF, ou não, como o DDoS Protection: ele está sempre ativo e não é empacotado nem vendido sozinho.

Descreva um módulo com o módulo primeiro e o host como contexto:

- Correto: `Web Application Firewall (WAF) é um módulo do Firewall que inspeciona requisições HTTP e HTTPS.`
- Incorreto: `Firewall é um produto que inclui o WAF.`

A palavra *add-on* está aposentada. *Modules* também continua onde o Console mostra, dentro de um caminho de cliques: `Na seção **Modules**, ative o Application Accelerator.` Um módulo JavaScript, um módulo ES e um campo de API como `modules.application_accelerator` mantêm seus nomes.

## Use verbo no singular com um nome de forma plural

Um nome de recurso da plataforma nomeia uma coisa só, qualquer que seja a forma. Applications, Functions e Connectors levam verbo no singular: `Applications armazena conteúdo em cache`, `Functions executa seu código` — nunca `Applications armazenam`. O inglês dos EUA concorda da mesma forma: `Applications caches content`, nunca `Applications cache`.

## Escreva em minúscula a coisa que o cliente constrói

O nome de um recurso da plataforma leva maiúscula. A coisa que o cliente cria com eles é um substantivo comum, e fica em minúscula.

- Correto: `Use **Applications** para construir suas próprias aplicações.`
- Correto: `**Functions** executa suas funções na infraestrutura distribuída da Azion.`
- Incorreto: `Faça o deploy da sua primeira Application.`

A distinção mantém o nome do tipo com significado. Uma página que escreve os dois em maiúscula deixa o leitor sem saber o que é o tipo e o que é a instância.

## Mantenha nomes históricos em documentos históricos

Changelogs, release notes e contratos datados registram o que era verdade no dia da publicação. Esses documentos mantêm os nomes da época da publicação. Um Termos de Serviço de 2020 mantém os nomes que eram corretos em 2020.

Não renomeie uma oferta em um documento histórico. Um nome atualizado reescreve o registro e separa o texto da sua data.

## Deixe estes termos em inglês dos EUA

Os nomes da plataforma, dos produtos e dos recursos da plataforma nunca são traduzidos. A coisa que o cliente cria com eles é traduzida: `Functions executa suas funções`.

Estes termos são vocabulário técnico genérico, não nomes de recurso da plataforma. Eles ficam em inglês dos EUA nos dois idiomas:

`data center` · `serverless` · `on-premise` · `template` · `compliance` · `e-commerce` · `e-mail` · `keywords` · `meta description`

Uma tradução cria um segundo nome para um conceito que o leitor já conhece em inglês dos EUA. A documentação usa um termo para cada conceito, em todas as páginas.

As strings `edge` e `edge computing` também ficam sem tradução onde já aparecem. Isso é orientação de tradução, não permissão para usá-las. Texto novo nomeia a infraestrutura distribuída da Azion.

## Nomeie a infraestrutura

A plataforma roda na infraestrutura distribuída da Azion, nunca "na rede global". O local físico é um `data center`, nunca um edge location nem um PoP; `data center` fica em inglês, nunca "centro de dados". A unidade de infraestrutura dentro de um data center não tem nome oficial: escreva `a infraestrutura no data center`, nunca `nó` nem `edge node`. A rede em si aparece só como o recurso da plataforma **Our Network**.
