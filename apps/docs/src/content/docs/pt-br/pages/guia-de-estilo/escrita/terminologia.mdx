## Use os nomes oficiais

Toda oferta tem um nome oficial, e toda página usa esse nome. Os nomes vêm do catálogo oficial de nomes da Azion, que Product Marketing mantém para todo o conteúdo da Azion: documentação, site e material de vendas. A visão geral de cada recurso de plataforma, a raiz da seção, reflete esse catálogo. Este guia não repete os nomes atuais, porque uma cópia fica errada no dia em que um nome muda.

O catálogo dá um nome por oferta. Não existe um nome de marketing separado do nome da documentação. A primeira menção pode trazer o nome completo com a sigla entre parênteses, e toda menção depois dela usa só a sigla:

- Correto: `Web Application Firewall (WAF) inspeciona requisições HTTP e HTTPS. Aplique um conjunto de regras WAF ao firewall.`
- Incorreto: um segundo `Web Application Firewall (WAF)` na mesma página.

Chame a plataforma de **Azion Platform**, ou de **Azion Web Platform** quando o contexto pedir. Nunca escreva `Azion Edge Platform` nem `Plataforma Edge da Azion`. No possessivo, a plataforma é um substantivo comum, em minúscula: `a plataforma da Azion`, nunca `a Plataforma da Azion`.

## Mantenha nomes depreciados fora das páginas atuais

A Azion renomeou suas ofertas ao longo do tempo. Os nomes antigos ainda aparecem em páginas antigas, URLs e nomes de diretórios, e por isso parecem atuais. Trate esses nomes como história, não como sinônimos. Um nome depreciado não muda de novo, então esta lista não fica desatualizada como uma lista de nomes atuais:

| Depreciado | Atual |
| --- | --- |
| Edge Application | Applications |
| Edge Firewall | Firewall |
| Edge Connector | Connectors |
| Real-Time Manager | Console |
| Edge AI | AI Inference |
| Application Acceleration | Application Accelerator |
| Edge Cache | Cache |
| Edge Functions | Functions |
| Image Processing | Image Processor |
| Edge Orchestrator | Orchestrator |
| Edge KV | KV Store |
| Edge Storage | Object Storage |
| Edge SQL | SQL Database |
| Network Layer Protection | Network Shield |
| Data Streaming | Data Stream |
| Azion Edge Platform | Azion Platform |

**Edge DNS** e **Edge Pulse** são nomes oficiais atuais. A palavra *Edge* neles não indica um nome depreciado.

## Nomeie o recurso em que o leitor trabalha

A Azion descreve o que oferece com quatro termos: plataforma, produto, recurso de plataforma e feature. Eles são conceitos relacionados, não quatro níveis de uma hierarquia: um recurso de plataforma pode ou não ser um produto, e uma feature pode pertencer à plataforma ou a um recurso de plataforma.

| Termo | Responde | Definição |
| --- | --- | --- |
| Plataforma | O que é a experiência integrada da Azion? | A infraestrutura distribuída da Azion, sua tecnologia integrada e as interfaces para construir, proteger e escalar workloads, como o Console, a API e a CLI |
| Produto | Que oferta a Azion leva ao mercado? | Uma oferta de mercado formada por um ou mais recursos de plataforma e features que resolve um problema do cliente, como WAF ou Object Storage |
| Recurso de plataforma | O que o leitor cria ou gerencia? | Uma entidade identificável que o cliente cria, configura, opera ou gerencia, e que o Console, a API, a CLI ou a documentação podem referenciar, como uma Application, um Firewall, uma Function ou um bucket |
| Feature | O que o leitor pode fazer ou ativar? | Uma funcionalidade visível da plataforma ou de um recurso de plataforma, que um produto pode incluir, como regras personalizadas de firewall ou DNSSEC |

A documentação usa a nomenclatura de recurso de plataforma. Produto é um termo de go-to-market, usado principalmente em material de marketing e vendas, e a tabela o define para o leitor reconhecê-lo lá. Uma página de documentação chama cada seção pelo nome oficial e chama a oferta de recurso de plataforma, nunca de produto: ela nomeia o que o leitor cria ou gerencia, e liga um recurso de plataforma a outro com um verbo. Produto nunca classifica um elemento em uma página, conforme [Declare a classe de um elemento da Azion](#declare-a-classe-de-um-elemento-da-azion).

Uma feature sempre tem escopo, então diga se ela vale para a plataforma ou para um recurso de plataforma. Um campo ou uma opção de um recurso é uma configuração, não uma feature.

**Applications**, **Firewall**, **Connectors**, **Workloads**, **Custom Pages** e **Certificate Manager** são exemplos de tipos de recurso de plataforma; o catálogo de nomes tem a lista completa. A coisa que o leitor cria é uma instância, com o nome do seu recurso de plataforma: uma Application, um Firewall, um Connector, conforme [Nomeie a instância pelo seu recurso de plataforma](#nomeie-a-instancia-pelo-seu-recurso-de-plataforma).

Azion Console, a API, a CLI, o Terraform Provider e o Copilot também são recursos de plataforma. São eles que o leitor usa para chegar à plataforma, então uma página pode chamá-los de interfaces: `Crie a Application no Console ou com a API.`

- Correto: `Configure um Firewall para proteger a Application.`
- Correto: a linha da sidebar que abre o WAF dentro de Firewall diz `WAF`, nunca `Firewall WAF` nem `Web Application Firewall`, porque um rótulo nunca repete o pai.

## Declare a classe de um elemento da Azion

A frase que define um elemento da Azion declara a classe dele: recurso de plataforma ou feature. `**Functions** é um recurso de plataforma que executa código JavaScript na infraestrutura distribuída da Azion.` Uma feature leva o escopo: `O Tiered Cache é uma feature do Cache que…`.

A classe segue a nomenclatura da documentação, não a lista de produtos do catálogo de nomes:

| O elemento | A classe dele em uma página | Exemplos |
| --- | --- | --- |
| A raiz de uma seção da documentação | Recurso de plataforma, mesmo quando o catálogo também o lista como produto | Applications, Firewall, Functions, Object Storage, Workloads |
| Aninhado em um recurso de plataforma, qualquer que seja a classe no catálogo | Recurso de plataforma | Cache, Application Accelerator, Image Processor, Load Balancer, Origin Shield, Live Ingest, WAF, Network Shield, Bot Manager, Certificate Manager, Custom Pages, DDoS Protection |
| Uma funcionalidade da plataforma ou de um recurso de plataforma, em nenhuma das listas | Feature, com o escopo | Tiered Cache, regras personalizadas de firewall, DNSSEC |

Produto é um termo de go-to-market que nomeia uma oferta, não uma classe: uma página nunca o declara como a classe de um elemento.

- **Uma vez por página, na primeira definição do elemento.** É a primeira frase de uma visão geral, cada entrada da seção de recursos dela, a frase de uma página de conceito que apresenta o elemento, uma linha de glossário que o define e a primeira frase de qualquer outra página que diz o que o elemento é.
- **Uma menção de passagem não leva classe.** `Crie um Firewall` e `Abra a Application` ficam como estão. Uma entrada de changelog descreve uma mudança, não o elemento, e mantém a abertura que [Páginas de changelog](/pt-br/documentacao/guia-de-estilo/conteudo/changelog/) define.
- **A classe não substitui o conceito.** A classe diz o que o elemento é dentro da Azion. As frases de conceito depois dela continuam dizendo o que é a classe da coisa em qualquer fornecedor: um proxy reverso é um servidor na frente das suas origens.
- **Em inglês dos EUA**, as classes são `Platform Resource` e `Feature`: `**Functions** is a Platform Resource that runs JavaScript code on Azion's distributed infrastructure.`

- Correto: `**Applications** é um recurso de plataforma que executa um proxy reverso na infraestrutura distribuída da Azion.`
- Incorreto: `Applications é um produto.` A classe está errada.
- Incorreto: `Application Accelerator é um produto que…` Produto não é uma classe em uma página.
- Incorreto: `Functions é um produto serverless.` Uma categoria de mercado substitui a classe.

## Classifique o que vive dentro de um recurso

As palavras *módulo* e *add-on* estão aposentadas. O que uma página chamava de módulo é um recurso de plataforma aninhado em outro e ativado nele, como Application Accelerator, Image Processor, WAF ou Network Shield. Também pode ser uma feature de um recurso, como o Tiered Cache, ou uma Function instanciada em uma Application ou em um Firewall. A aposentadoria cobre a classificação de uma oferta da Azion, e nada mais.

- Correto: `Web Application Firewall (WAF) é um recurso de plataforma que inspeciona as requisições HTTP e HTTPS que chegam a um Firewall. Aplique um conjunto de regras WAF ao Firewall.`
- Incorreto: `Firewall é um produto que inclui o WAF.`
- Incorreto: `O WAF é um produto que…`
- Incorreto: `WAF é um módulo do Firewall.`

*Modules* continua onde o Console mostra, dentro de um caminho de cliques: `Na seção **Modules**, ative o Application Accelerator.` Um módulo JavaScript, um módulo ES e um campo de API como `modules.application_accelerator` mantêm seus nomes.

## Use verbo no singular com um nome de forma plural

Um nome de recurso de plataforma nomeia uma coisa só, qualquer que seja a forma. Applications, Functions e Connectors levam verbo no singular: `Applications armazena conteúdo em cache`, `Functions executa seu código` — nunca `Applications armazenam`. O inglês dos EUA concorda da mesma forma: `Applications caches content`, nunca `Applications cache`.

## Nomeie a instância pelo seu recurso de plataforma

A coisa que o cliente cria com um recurso de plataforma leva o nome desse recurso, no singular, com maiúscula e sem tradução, nos dois idiomas:

| Recurso de plataforma | Uma instância | Várias | Inglês dos EUA |
| --- | --- | --- | --- |
| Applications | uma Application | as suas Applications | an Application |
| Firewall | um Firewall | os seus Firewalls | a Firewall |
| Functions | uma Function | as suas Functions | a Function |
| Connectors | um Connector | os seus Connectors | a Connector |
| Workloads | um Workload | os seus Workloads | a Workload |

Um elemento da Azion com nome próprio que o Console ou o catálogo de nomes lista como recurso segue a mesma regra: uma Function Instance, a instância de uma Function em uma Application ou em um Firewall, e uma Network List.

Três coisas continuam substantivos comuns, em minúscula:

- **Um elemento cujo nome não é nome de recurso**: uma regra, um behavior, um bucket, um cache setting, um deployment, uma origem, uma zona, um registro. O português do Brasil usa a palavra que as páginas já usam: `uma regra`, `um bucket`, `um deployment`.
- **O software do próprio cliente**, o app na origem: `a sua aplicação`, `your application`.
- **O conceito genérico** nas frases de conceito de um bloco de definição, que valem para qualquer fornecedor: `Um firewall para tráfego web é um ponto de controle entre os clientes na internet e uma aplicação.`

O leitor distingue o recurso de plataforma das instâncias dele pela gramática. O recurso de plataforma leva verbo no singular e, quando o nome tem forma de plural, nenhum artigo: `Applications encaminha…`, `Applications routes…`. Uma instância leva artigo indefinido, possessivo ou número: `uma Application`, `as suas Applications`, `duas Applications`, `an Application`.

O nome já liga a instância ao seu recurso de plataforma, então nenhuma frase precisa fazer isso. Quando uma frase precisa dizer o que uma instância é, o substantivo de classe é `entidade`, `entity` em inglês dos EUA, nunca `objeto` nem `object`: `Um Workload é a entidade que guarda os seus domínios…`. Uma instância em minúscula ou traduzida se lê como o app do próprio cliente ou como uma função genérica, e um leitor que conhece o produto lê a tradução como outro nome para ele.

- Correto: `Faça o deploy da sua primeira Application.`
- Correto: `Uma Application recebe as requisições dos Workloads cujo deployment a define.`
- Incorreto: `uma aplicação`, `uma função`, `um connector` ou `an application` para a entidade criada na Azion.
- Incorreto: `Use **Applications** para construir as suas próprias Applications.` O software do próprio cliente continua `aplicações`.

## Mantenha nomes históricos em documentos históricos

Changelogs, release notes e contratos datados registram o que era verdade no dia da publicação. Esses documentos mantêm os nomes da época da publicação. Uns Termos de Serviço de 2020 mantêm os nomes que eram corretos em 2020.

Não renomeie uma oferta em um documento histórico. Um nome atualizado reescreve o registro e separa o texto da sua data.

## Deixe estes termos em inglês dos EUA

Os nomes da plataforma, dos produtos e dos recursos de plataforma nunca são traduzidos, e a instância também não, conforme [Nomeie a instância pelo seu recurso de plataforma](#nomeie-a-instancia-pelo-seu-recurso-de-plataforma): `Functions executa as suas Functions`.

Estes termos são vocabulário técnico genérico, não nomes de recurso de plataforma. Eles ficam em inglês dos EUA nos dois idiomas:

`data center` · `serverless` · `on-premise` · `template` · `compliance` · `e-commerce` · `e-mail` · `keywords` · `meta description` · `authoritative DNS`

Uma tradução cria um segundo nome para um conceito que o leitor já conhece em inglês dos EUA. A documentação usa um termo para cada conceito, em todas as páginas.

As strings `edge` e `edge computing` também ficam sem tradução onde já aparecem. Isso é orientação de tradução, não permissão para usá-las. Texto novo nomeia a infraestrutura distribuída da Azion.

## Nomeie a infraestrutura

A plataforma roda na infraestrutura distribuída da Azion, nunca "na rede global". O local físico é um `data center`, nunca um edge location nem um PoP; `data center` fica em inglês, nunca "centro de dados". A unidade de infraestrutura dentro de um data center não tem nome oficial: escreva `a infraestrutura no data center`, nunca `nó` nem `edge node`. A rede em si aparece só como o recurso de plataforma **Our Network**.

Nomeie o data center que atende a requisição, não uma distância: `do data center mais próximo ao seu usuário`, nunca `perto dos seus usuários` nem `próximo aos seus usuários`. O data center mais próximo é escolhido por latência, condições de rede e carga, então nunca escreva `geograficamente mais próximo`.
