## Propósito

Um hub de navegação leva o leitor para dentro da documentação. Ele carrega links e uma frase de orientação, e nada mais.

Ele **não** aplica nenhuma forma base do Diátaxis. Um hub não ensina, não instrui, não descreve e não explica: ele direciona. Por isso ele não tem orçamento de frase para um texto que não deveria estar ali.

## Quando usar

- Escreva um hub quando uma seção tem mais páginas do que a sidebar consegue mostrar de forma legível.
- Escreva um para uma seção que reúne páginas de vários recursos da plataforma, como uma área de solução do hub de guias, ou o índice de arquiteturas.
- Escreva um para o slot Guias e tutoriais da seção de um recurso da plataforma, que é uma única linha na sidebar apontando para um hub, e não um dropdown. [Arquitetura de informação](/pt-br/documentacao/guia-de-estilo/conteudo/arquitetura-de-informacao/) carrega essa regra.
- Escreva um hub de grupo para cada grupo da sidebar que reúne páginas e não tem página própria, como um grupo **Referência**. O grupo aparece como um item no breadcrumb de cada página dentro dele, e esse item precisa de uma página para abrir.

Não escreva um hub quando:

- A página seria a raiz da seção de um recurso da plataforma. Essa raiz é uma [visão geral](/pt-br/documentacao/guia-de-estilo/conteudo/visao-geral/), que orienta e aponta.
- A página explicaria longamente do que a seção trata. Isso é uma [página de conceito](/pt-br/documentacao/guia-de-estilo/conteudo/conceito/).
- A sidebar já torna as páginas encontráveis. Um hub que duplica a sidebar é mais uma coisa para manter e mais uma coisa para desatualizar. O hub de grupo é a exceção: o layout monta a lista dele a partir da sidebar, então ela não fica dessincronizada.

## Registro

Descritivo: 25 palavras por frase, voz ativa, passiva apenas quando o ator é desconhecido. Tom: breve, claro, orientador. [Estrutura de frases](/pt-br/documentacao/guia-de-estilo/escrita/estrutura-de-frases/) tem as regras.

## Estrutura

As três formas abrem e fecham do mesmo jeito. Só o corpo muda.

- **Abertura**: uma frase de orientação dizendo o que a seção contém.
- **Fechamento**: nenhum. O último link ou a última linha da tabela encerra a página.

### Forma 1: links agrupados

O padrão. Use quando os destinos são diferentes entre si e o leitor precisa de uma frase para distinguir um do outro.

- **Corpo**: grupos de links sob títulos `##` em frase nominal.
- **Forma do link**: `[Título](/caminho/) - uma frase sobre o que o leitor encontra lá.`

### Forma 2: uma tabela

Use quando o hub lista um conjunto homogêneo e o leitor escolhe por tipo e atualidade, e não por descrição. O slot Guias e tutoriais tem essa forma, porque cada linha é um how-to ou um tutorial do mesmo recurso da plataforma e uma frase por linha repetiria o título da página.

- **Corpo**: um `<ProductGuidesSection>`, sem títulos `##` e sem grupos.
- **Colunas**: nome, tipo, última atualização.
- **A tabela é gerada, nunca digitada.** Uma página aparece quando o catálogo de guias a marca com o recurso da plataforma, o tipo vem do catálogo e a data vem da última alteração da página, então o hub não fica dessincronizado das páginas que lista. O hub de um recurso também lista os guias dos recursos da plataforma aninhados nele; um recurso da plataforma aninhado não tem hub de Guias e tutoriais próprio.

### Forma 3: um hub de grupo

A página que o item do breadcrumb de um grupo da sidebar abre. Ela não é uma linha da sidebar: o grupo mantém as suas linhas e não ganha uma linha de Visão geral.

- **Corpo**: só a frase de orientação. O layout lista as linhas do grupo depois dela, na ordem da sidebar, cada uma com o rótulo de navegação e a descrição da página. Um subgrupo aparece como uma linha que abre o próprio hub de grupo.
- **Título**: o nome do grupo com o dono dele, para que o título seja único em toda a documentação: `Referência do Certificate Manager`, `Comandos de conta da Azion CLI`, `Versões anteriores dos Termos de Serviço`.
- **Registro**: a linha do grupo na árvore de navegação traz o namespace do hub em `page` e `landing: true`. Um grupo sem `segment` também traz um `slug`, que define a última parte da URL do hub.
- **A lista é gerada, nunca digitada.** Uma página adicionada ao grupo aparece no hub sem nenhuma edição no hub.

## Template

Copie o template da forma que você precisa e substitua cada `<placeholder>`.

Links agrupados:

```md
<Uma frase: o que a seção contém.>

## <Nome do grupo>

- [<Título da página>](<url>) - <o que o leitor encontra lá, em uma frase>.
- [<Título da página>](<url>) - <o que o leitor encontra lá, em uma frase>.

## <Nome do próximo grupo>

- [<Título da página>](<url>) - <o que o leitor encontra lá, em uma frase>.
```

Uma tabela:

```mdx
import ProductGuidesSection from '~/components/ProductGuidesSection.astro'

<Uma frase: o que a seção contém.>

<ProductGuidesSection product="<o id da seção, como applications>" />
```

Um hub de grupo, depois do frontmatter:

```md
<Uma frase: o que o grupo contém.>
```

A linha dele na árvore de navegação:

```json
{
  "label": { "en": "Reference", "pt-br": "Referência" },
  "page": "<o namespace do hub>",
  "slug": { "en": "reference", "pt-br": "referencia" },
  "landing": true,
  "items": [ ... ]
}
```

## Regras

- **Nenhum fechamento e nenhum outro texto.** Uma frase de orientação; a explicação vai em uma [página de conceito](/pt-br/documentacao/guia-de-estilo/conteudo/conceito/).
- **Faça cada link justificar o seu lugar.** Um hub é julgado pelo que ele deixa de fora; um hub que lista tudo não hierarquiza nada.
- **Escreva descrições que diferenciam.** Diga o que esta página dá que as vizinhas não dão.
- **Agrupe quando a lista passa de sete**, pelo que o leitor está tentando fazer. Um hub de grupo também não agrupa: ele lista as linhas do seu grupo da sidebar, na ordem da sidebar, quantas forem. Uma tabela não agrupa: ela ordena em ordem alfabética pelo rótulo de navegação de cada linha, no idioma do leitor. O grupo Recursos de Plataforma da sidebar raiz é a única exceção: todos os recursos da plataforma na ordem em que o leitor os adota, por decisão, porque agrupá-los por intenção traria de volta os pilares aposentados.
- **Escolha a forma pelo que o leitor compara.** Destinos variados precisam de uma frase cada, então pedem links agrupados. Um conjunto homogêneo de páginas, comparado por tipo e atualidade, pede a tabela.
- **Dê um hub de grupo a cada grupo da sidebar que reúne páginas.** Um grupo sem página própria deixa no breadcrumb um item que não abre nada. O hub de grupo é a única forma que a sidebar decide, não o leitor.
- **Nunca escreva uma linha de tabela à mão.** Uma data digitada fica errada na primeira vez que alguém esquece, e é por isso que este é o único lugar em que o guia permite uma data fora de um changelog.
- **Registre a página no catálogo de guias.** Uma página que o catálogo não lista falta no hub. O primeiro recurso da plataforma que o catálogo indica para uma página é o dono dela e dá nome ao tópico dela na seção de Guias.
- **Mantenha o hub em dia com a seção.** Atualize o hub na mesma mudança que adiciona uma página.
- **Defina `type: homepage` somente em um hub em grade de cards.** Todas as outras páginas omitem o campo. Para mais informações, consulte [Frontmatter](/pt-br/documentacao/guia-de-estilo/convencoes/frontmatter/).

## Exemplos

- [Casos de uso](/pt-br/documentacao/casos-de-uso/) - Uma linha de orientação, e depois os designs agrupados por solução.
- [Guias e tutoriais de Applications](/pt-br/documentacao/plataforma/applications/guias/) - A forma em tabela: uma frase, e depois cada guia e tutorial com seu tipo e sua data.

Um hub de Object Storage, cortado até a frase de orientação e o primeiro grupo:

```mdx
Esta seção reúne os guias para gerenciar buckets e objetos do Object Storage, e a referência do Object Storage.

## Buckets

- [Criar um bucket](/pt-br/documentacao/guias/desenvolvimento-de-aplicacoes/dados/criar-e-modificar-um-bucket/) - Crie um bucket, altere o nível de acesso dele e exclua-o.
- [Upload e download de objetos](/pt-br/documentacao/guias/desenvolvimento-de-aplicacoes/dados/upload-e-download-de-objetos-do-bucket/) - Coloque objetos em um bucket e leia-os de volta.
- [Use um bucket como origem de uma aplicação](/pt-br/documentacao/guias/desenvolvimento-de-aplicacoes/dados/bucket-como-connector/) - Sirva os objetos de um bucket a partir do seu próprio domínio.
```
