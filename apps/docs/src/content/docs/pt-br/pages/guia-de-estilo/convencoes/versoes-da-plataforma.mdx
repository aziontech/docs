A documentação cobre duas versões da Azion Platform: a API v4, a versão atual, e a API v3, que está descontinuada. Estas regras decidem quais páginas existem em cada versão e como nomear e ligar a página de uma versão anterior. Elas também definem como uma versão sai da documentação. O select de versão, o banner e os campos do frontmatter que os montam estão em [Componentes](/pt-br/documentacao/guia-de-estilo/componentes/#avisos-de-versao).

## Decida quais versões uma página cobre

A maioria das páginas vale para todas as versões e não declara versão. Escreva uma página por versão só quando o conteúdo muda entre as versões.

| O conteúdo | Páginas | Frontmatter |
| --- | --- | --- |
| Vale para todas as versões, como um conceito, um exemplo de código do Functions ou um recurso da plataforma que não mudou | Uma página | Sem o campo `versions` |
| Muda entre as versões para o mesmo recurso: o modelo da API, um caminho no Console, um campo ou um nome | Uma página por versão | `versions` em cada página e `counterpart` com a página da outra versão |
| Existe em uma só versão, como Workloads na API v4 ou Domains na API v3 | Uma página | `versions` com essa versão e `counterpart` com a página mais próxima da outra versão |

- Nunca copie uma página para uma versão anterior só para que cada versão tenha uma. Uma página que vale para as duas versões continua sendo uma página.
- Declare `versions` na árvore de navegação quando todas as páginas de um produto compartilham o valor, como faz a árvore de Domains. A página então declara só o que difere da árvore.
- Quando só alguns passos de um guia mudam, mantenha um guia com os passos das duas versões. O snippet `versionDualSteps` fica no fim da introdução dele.

## Nomeie e posicione a página de uma versão anterior

Uma página da API v3 que tem uma página equivalente na API v4 assume a identidade dessa página, com um marcador de versão:

| Campo | Regra | Exemplo |
| --- | --- | --- |
| `permalink` | O permalink da página da API v4, seguido de `v3/` | `/documentacao/plataforma/applications/v3/` |
| `namespace` | O namespace da página da API v4, seguido de `_v3` | `documentation_products_edge_applications_v3` |
| `title` | O título da página da API v4, sem sufixo de versão | `Applications` |
| Arquivo | Ao lado da página da API v4, na pasta dela ou em uma pasta `v3/` dentro dela | `edge-application/v3/edge-application-v3.mdx` |

A página em inglês dos EUA segue as mesmas regras: o permalink dela é o permalink da página em inglês da API v4 seguido de `v3/`, e o `namespace` é idêntico ao desta página.

- Dê à página de uma versão anterior um título diferente só quando essa versão nomeia o recurso de outro jeito. Domains na API v3 e Workloads na API v4 são um exemplo. Um nome depreciado de [Terminologia da documentação](/pt-br/documentacao/guia-de-estilo/escrita/terminologia/#mantenha-nomes-depreciados-fora-das-paginas-atuais) fica fora do título em todas as versões: uma página da API v3 sobre aplicações se chama Applications, não Edge Application.
- Um recurso que existe só na API v3, com nome próprio, mantém o próprio permalink, sem marcador. Domains fica em `/documentacao/plataforma/domains/`.
- Registre a página na árvore de navegação da página equivalente da API v4, em uma linha com `"hidden": true`. A página declara `versions: [v3]`, `stage: deprecated` e `counterpart`.
- Algumas páginas da API v3 terminam em `-v3/` em vez de `/v3/`. Escreva `/v3/` em toda página que você criar. Mover uma página existente para `/v3/` muda a URL dela, então a mudança precisa de um redirect, como [Frontmatter](/pt-br/documentacao/guia-de-estilo/convencoes/frontmatter/#defina-o-permalink) exige.

## Ligue as versões

Cada versão se lê como uma documentação própria. O campo `counterpart` é o único link de uma página para a equivalente dela na outra versão. O select de versão e o banner o mostram.

- Nunca escreva um aside, uma frase ou um snippet que anuncie a outra versão, como "Existe uma versão anterior desta página".
- Ligue dentro da versão. Uma página da API v3 liga para páginas da API v3 ou para páginas que valem para todas as versões. Uma página da API v4 nunca liga para uma página da API v3.
- Uma página sobre a passagem entre versões é a exceção: [Migração para API v4](/pt-br/documentacao/fundamentos/api-v4-migration/) e [Migre do provider v1.x para o v2.0](/pt-br/documentacao/devtools/terraform/migration-v3-to-v4/) ligam para as duas versões no texto.
- Para abrir em uma versão específica uma página que vale para todas as versões, adicione `?api=v3` ou `?api=v4` ao link. O select muda para essa versão e a guarda como a escolha do leitor. Uma página de uma só versão não precisa do parâmetro, porque abre na própria versão.

## Marque o conteúdo descontinuado

O estágio de uma versão ou de uma funcionalidade vem do campo `stage`, nunca do corpo. Os estágios e o que cada um compromete a Azion a fazer estão na [seção 1.3 dos Termos de Serviço](/pt-br/documentacao/contratos/tds/#13-estagios-de-liberacao-de-produtos).

- **Uma versão descontinuada.** Toda página da versão traz `stage: deprecated`, pela árvore de navegação ou pelo próprio frontmatter quando fica em uma árvore de outra versão.
- **Uma funcionalidade descontinuada dentro da versão atual.** Quando a funcionalidade tem página própria, essa página traz `stage: deprecated`. Quando a funcionalidade é um campo ou uma opção em uma página de referência, a entrada dela nomeia a substituta em uma frase, sem data.
- **O conteúdo de uma página descontinuada.** Corrija o que estiver errado nela e não documente nenhuma novidade. Uma versão descontinuada não recebe atualizações.
- **A data de desligamento.** A data em que uma versão é desligada aparece só em [Migração para API v4](/pt-br/documentacao/fundamentos/api-v4-migration/), como [Números e unidades](/pt-br/documentacao/guia-de-estilo/formatacao/numeros/) define.

## Encerre o suporte a uma versão

Quando uma versão chega ao fim da vida, as páginas dela saem da documentação em uma única mudança, em inglês dos EUA e em português do Brasil:

- Remova todas as páginas da versão.
- Adicione um redirect para cada permalink removido no arquivo de maior número de `apps/docs/redirects/en/` e de `apps/docs/redirects/pt-br/`. O redirect vai para a página que `counterpart` indica. Uma página sem `counterpart` redireciona para a página do mesmo recurso na versão que fica, ou para a página-pai dela. Nunca redirecione para a página inicial da documentação.
- Remova os passos da versão de todo guia que reúne passos das duas versões, junto com o snippet `versionDualSteps`.
- Remova a versão da lista de versões da plataforma no código. Remova-a também de todo campo `versions` e `counterpart` nas árvores de navegação e no frontmatter.
- Deixe as entradas de changelog e os contratos datados como estão. Eles mantêm a versão com que foram publicados, como [Terminologia da documentação](/pt-br/documentacao/guia-de-estilo/escrita/terminologia/#mantenha-nomes-historicos-em-documentos-historicos) explica.

## Adicione uma versão antes da Disponibilidade Geral

Uma versão que a documentação cobre antes de chegar à Disponibilidade Geral segue as mesmas regras. As páginas dela trazem `stage: experimental` ou `stage: preview`, e as páginas da versão atual mantêm os permalinks sem marcador. O select de versão lista só as versões que o código declara, então adicionar uma versão é uma mudança de código antes de ser uma mudança de conteúdo.
