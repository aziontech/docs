Você pode calibrar uma Function Instance do [Bot Manager](/pt-br/documentacao/plataforma/firewall/bot-manager/) pelo Azion Console e ler o log de report que ela escreve pelo Azion Console ou pela API GraphQL. Para o que cada escolha custa e por quanto tempo mantê-la, consulte [Boas práticas de Firewall](/pt-br/documentacao/plataforma/firewall/boas-praticas/#bot-manager).

Os passos são os mesmos para o [Bot Manager Lite](/pt-br/documentacao/plataforma/firewall/bot-manager/bot-manager-lite/). Onde os argumentos das duas edições diferem, a seção informa cada um.

---

## Pré-requisitos

- Uma Function Instance do Bot Manager em um Firewall, executada por uma regra do [Rules Engine para Firewall](/pt-br/documentacao/plataforma/firewall/rules-engine/). Para mais informações, consulte [Primeiros passos com Bot Manager](/pt-br/documentacao/plataforma/firewall/bot-manager/primeiros-passos/).
- Acesso ao Azion Console. Para entrar, consulte [Acesse Azion Console](/pt-br/documentacao/guias/plataforma/conta-e-billing/como-acessar-o-azion-console/).
- Um personal token, para a consulta que lê o log de report. Para mais informações, consulte [Tokens pessoais](/pt-br/documentacao/fundamentos/personal-tokens/).
- Para pontuar endereços contra uma lista de reputação, o ID de cada [Network List](/pt-br/documentacao/plataforma/firewall/network-shield/network-lists/) que você quer usar.

## Eleve o nível de log

Uma linha de report é o único registro de como uma requisição pontuou. A Function escreve uma linha só para as requisições que `internal_logs` seleciona, e o argumento é entregue em `0`. Eleve-o para `2` para que toda requisição produza uma linha, inclusive uma que pontue `0`. Defina `action` como `allow` para que uma requisição igual ou acima do threshold seja pontuada e ainda assim atendida:

```json
{
  "threshold": 30,
  "action": "allow",
  "internal_logs": 2,
  "log_tag": "bot-calibration",
  "log_headers": [
    "accept",
    "accept-encoding",
    "accept-language",
    "content-type",
    "host",
    "referer",
    "user-agent",
    "x-forwarded-for",
    "x-request-id"
  ]
}
```

| Argumento | O que ele faz na janela de observação |
| --- | --- |
| `action` | Em `allow`, uma requisição igual ou acima do threshold segue para a Application |
| `internal_logs` | Em `2`, a Function escreve uma linha para toda requisição. O valor é um número: a API armazena a string `"2"` como foi enviada, e o Bot Manager Lite lê um valor que não reconhece como `0` |
| `log_tag` | A tag que o prefixo da linha carrega, que separa as linhas de uma Function Instance das linhas de outra |
| `log_headers` | Os cabeçalhos de requisição que a Function escreve na linha. Os nove do exemplo são o padrão entregue |

:::caution[Atenção]
A API verifica se os argumentos são um objeto ou um array JSON, e não verifica nenhuma chave. Uma chave digitada errado, como `thresold`, é armazenada e lida de volta como foi digitada, a API e o Azion CLI não retornam nenhum erro, e `threshold` continua ausente da Function Instance. Para ver o que a Function faz sem ele, consulte [Threshold](/pt-br/documentacao/plataforma/firewall/bot-manager/argumentos/#threshold).
:::

Para substituir os argumentos da Function Instance no Azion Console:

<DocSteps>
  <DocStep title="Abra o Firewall que executa a Function Instance">

  Acesse [Azion Console](https://console.azion.com/) > **Firewalls** e selecione esse Firewall.

  </DocStep>
  <DocStep title="Selecione a aba Functions Instances" />
  <DocStep title="Abra a Function Instance">

  Selecione a Function Instance do Bot Manager que você quer calibrar.

  </DocStep>
  <DocStep title="Substitua os argumentos">

  Na seção **Arguments**, informe o objeto. O Bot Manager Lite não carrega esquema de argumentos, então a seção traz um editor JSON e não constrói formulário a partir dele.

  </DocStep>
  <DocStep title="Selecione Save" />
</DocSteps>

A Function Instance pontua toda requisição que a regra envia a ela e não recusa nenhuma. Uma alteração nos argumentos de uma Function Instance leva até alguns minutos para alcançar a infraestrutura distribuída da Azion, e nenhuma duração é garantida. Enquanto ela se propaga, as respostas a uma mesma requisição alternam entre a configuração anterior e a nova. Para mais informações, consulte [Propagação](/pt-br/documentacao/plataforma/firewall/como-funciona/#propagacao).

Altere um argumento por vez, para que cada leitura descreva uma alteração. Volte `action` para o valor que você executa em produção quando as linhas responderem à sua pergunta.

## Leia o log de report no Real-Time Events

O [Real-Time Events](/pt-br/documentacao/plataforma/real-time-events/) entrega cada linha de report como um registro do dataset `functionConsoleEvents`. O Azion Console não tem uma coluna própria do Bot Manager, então o objeto JSON de uma linha chega inteiro, e não dividido em colunas.

Para ler as linhas no Azion Console:

<DocSteps>
  <DocStep title="Abra o Real-Time Events">

  Acesse [Azion Console](https://console.azion.com/) > **Real-Time Events**.

  </DocStep>
  <DocStep title="Selecione a aba Functions Console">

  A aba mostra uma coluna **Time** e uma coluna **Log Body**.

  </DocStep>
  <DocStep title="Restrinja o período à sua janela de observação" />
  <DocStep title="Leia as linhas cujo prefixo carrega o seu log_tag" />
</DocSteps>

Para ler os mesmos registros com a API, envie a consulta a seguir para `https://api.azion.com/v4/events/graphql` com um cabeçalho `Authorization: Token [TOKEN VALUE]` e um `tsRange` que cubra a janela:

```graphql
{
  functionConsoleEvents(
    limit: 200
    filter: { tsRange: { begin: "2026-01-01T11:30:00", end: "2026-01-01T13:00:00" } }
    orderBy: [ts_ASC]
  ) {
    ts
    line
    level
    lineSource
    functionId
    configurationId
  }
}
```

A consulta responde `200` e retorna um registro por linha que a Function escreveu. `line` carrega a linha de report inteira. `functionId` é o ID da Function instalada, e não da Function Instance dela. `configurationId` é o ID do Workload em que a requisição chegou, e não do Firewall.

Uma linha abre com o prefixo `[Bot-Protection][<log_tag>] Report:` e continua como um único objeto JSON:

```text
[Bot-Protection][bot-calibration] Report:  {"request_id":"0123456789abcdef0123456789abcdef","remote_addr":"203.0.113.42","fingerprint":"ge20cn020000_000000000000_000000000000_000000000000","host":"<your-workload-domain>","http_user_agent":"","request_uri":"/","geoip_country":"DE","geoip_region":"HE","asn":"64496","score":28,"bot_category":"Bad Bot Signatures, Malicious Intent detected","classified":"legitimate","action":"allow","matched_rules":[1,10,18,19,20]}
```

Quatro valores carregam a calibração. `score` é o total que a Function calculou, `matched_rules` informa as regras que o produziram, `action` é o que a Function aplicou e `classified` é o veredito a que ela chegou. Na linha anterior, a pontuação é `28` sob um threshold de `30`, então `action` mostra `allow` e `classified` mostra `legitimate`. Sob um threshold que `28` alcança, a mesma requisição mostra `bad bot` e recebe a ação configurada.

`bot_category` é uma lista, separada por vírgulas, das categorias das regras que corresponderam, então uma linha classificada como `legitimate` ainda pode informar categorias de bad bot. Para cada campo que uma linha carrega e os quatro valores que `classified` assume, consulte [Logs](/pt-br/documentacao/plataforma/firewall/bot-manager/logs/#campos).

Os dois datasets de Real-Time Metrics que os dashboards do Bot Manager leem contam requisições por classificação, ação, modo, host, geografia e URL, e nenhum dos dois carrega uma pontuação. Leia uma distribuição de pontuações no log de report. Para as contagens, consulte [Consulte dados do Bot Manager com GraphQL](/pt-br/documentacao/guias/plataforma/observabilidade/consultar-dados-bot-manager-com-graphql/), [Consulte as URLs mais atingidas por bots com GraphQL](/pt-br/documentacao/guias/plataforma/observabilidade/consultar-dados-bot-manager-breakdown-com-graphql/) e [Real-Time Metrics](/pt-br/documentacao/plataforma/real-time-metrics/dashboards-secure/#bot-manager).

## Defina o threshold a partir das pontuações que você leu

`threshold` é a pontuação a partir da qual `action` é aplicada. O valor vem da distribuição no seu próprio log de report: os clientes que você reconhece se agrupam na ponta baixa, os clientes automatizados se agrupam mais acima, e o threshold fica no intervalo entre os dois.

Para definir o threshold:

<DocSteps>
  <DocStep title="Colete as pontuações da janela">

  Leia `score` nas linhas que a janela produziu e separe as requisições que você reconhece das que você não reconhece.

  </DocStep>
  <DocStep title="Escolha um valor no intervalo">

  Defina-o acima das pontuações do tráfego que você reconhece, e igual ou abaixo das pontuações do tráfego que você não reconhece.

  </DocStep>
  <DocStep title="Aplique o threshold e a ação">

  Substitua os argumentos da Function Instance pelo novo `threshold` e pela `action` que uma requisição igual ou acima dele recebe.

  </DocStep>
  <DocStep title="Espere a alteração se propagar">

  Uma alteração nos argumentos leva até alguns minutos, e as respostas alternam enquanto isso.

  </DocStep>
  <DocStep title="Leia as linhas mais próximas do threshold">

  Leia as linhas classificadas como `legitimate` cuja pontuação fica logo abaixo dele. Essas requisições estão a uma regra correspondida da ação.

  </DocStep>
</DocSteps>

A Function Instance aplica a ação ao tráfego igual ou acima do threshold, e as linhas abaixo dele informam as requisições que chegaram mais perto. Repita o ciclo: diminua o threshold enquanto tráfego automatizado ainda passa, e aumente-o quando requisições que você reconhece forem recusadas.

:::caution[Atenção]
`classified` é calculado contra o threshold em vigor, e não apenas contra a pontuação. Aumentar um threshold reclassifica o tráfego além de interromper a ação, então registre o threshold ao lado de qualquer contagem de classificação que você compare entre dois períodos. `score` e `matched_rules` descrevem a requisição e não mudam.
:::

## Retire uma regra da pontuação

Uma pontuação é a soma dos incrementos das regras a que uma requisição correspondeu. `matched_rules` carrega os IDs dessas regras, e `score` carrega o total. Adicione um ID aos argumentos só depois que ele aparecer nas suas próprias linhas.

Para impedir que uma regra aumente uma pontuação:

<DocSteps>
  <DocStep title="Encontre as linhas que você não esperava">

  Leia as linhas classificadas como `legitimate` cuja pontuação fica no threshold ou perto dele, e as linhas que carregam requisições que você reconhece.

  </DocStep>
  <DocStep title="Leia os IDs das regras nessas linhas">

  `matched_rules` carrega os IDs das regras a que cada requisição correspondeu. Compare várias linhas, para que uma única requisição não decida a questão.

  </DocStep>
  <DocStep title="Adicione os IDs aos argumentos">

  No Bot Manager Lite, adicione-os a `disabled_rules`. No Bot Manager, adicione-os a `disabled_static_rules`. Os dois são arrays.

  </DocStep>
  <DocStep title="Espere a alteração se propagar e leia as linhas de novo" />
</DocSteps>

As requisições que corresponderam à regra pontuam menos pelo incremento dela. No Bot Manager Lite, a Function não processa mais uma regra em `disabled_rules`. No Bot Manager, uma regra em `disabled_static_rules` continua sendo executada, e cada correspondência vai para o campo `disabled_matched_rules` da linha. Uma regra retirada da pontuação fica fora dela para toda requisição que a Function Instance pontua.

Para os dois argumentos e os tipos que eles aceitam, consulte [Regras desabilitadas](/pt-br/documentacao/plataforma/firewall/bot-manager/argumentos/#regras-desabilitadas).

## Pontue um endereço contra uma Network List de reputação

`reputation_network_lists` aceita um array de IDs de Network Lists. A Function verifica o endereço de toda requisição que pontua contra cada lista e aumenta a pontuação uma vez para cada lista em que o endereço é encontrado. A Azion mantém listas próprias: a Network List `2` é _Azion IP Tor Exit Nodes_, uma lista de endereços IP. Uma lista que você mesmo cria é informada da mesma forma, pelo ID dela.

No Bot Manager Lite, o argumento é entregue vazio, e uma correspondência é a regra `14`, que vale 6 pontos para cada lista. No Bot Manager, o argumento tem como padrão as Network Lists mantidas pela Azion na conta. Seis pontos não alcançam o threshold de `30` com que o Bot Manager Lite é entregue, então um endereço listado só recebe a ação quando outras regras também correspondem.

Para pontuar endereços contra uma lista:

<DocSteps>
  <DocStep title="Substitua os argumentos pelos IDs das listas">

  Substitua os argumentos da Function Instance, como em [Eleve o nível de log](#eleve-o-nivel-de-log), por um objeto que informa as listas:

  ```json
  {
    "threshold": 30,
    "action": "allow",
    "internal_logs": 2,
    "reputation_network_lists": [2],
    "log_tag": "bot-reputation"
  }
  ```

  </DocStep>
  <DocStep title="Espere a alteração se propagar" />
  <DocStep title="Leia as linhas dos endereços listados">

  No Bot Manager Lite, uma linha cujo endereço está em uma lista carrega a regra `14` em `matched_rules`, e o `score` dela é 6 pontos maior para cada lista.

  </DocStep>
</DocSteps>

A Function Instance verifica cada endereço que a regra envia a ela contra as listas que você informou. Para cada regra que o Bot Manager Lite executa e o que cada uma soma, consulte [Bot Manager Lite](/pt-br/documentacao/plataforma/firewall/bot-manager/bot-manager-lite/#regras).

## Eleve a tolerância das regras dinâmicas

O Bot Manager documenta um método de regras dinâmicas, que pontua uma requisição contra a linha de base do tráfego da Application. `dynamic_rules_tolerance` define o quão estrita é essa comparação. Os valores documentados são `soft`, `medium` e `hard`, e `soft` é o padrão documentado. O Bot Manager Lite não tem esse método.

Avance um nível por vez. Uma alteração de tolerância repontua toda requisição que a Function Instance vê, então cada nível precisa de uma janela de observação própria. Dois níveis aplicados juntos produzem os seus falsos positivos juntos, e nada nas linhas diz qual nível os produziu.

Para elevar a tolerância um nível:

<DocSteps>
  <DocStep title="Substitua os argumentos pela próxima tolerância">

  Substitua os argumentos da Function Instance, como em [Eleve o nível de log](#eleve-o-nivel-de-log). Defina `dynamic_rules_tolerance` um nível acima e `dynamic_rules_logs_enabled` como `true`, que escreve os logs de depuração do método:

  ```json
  {
    "threshold": 18,
    "action": "deny",
    "dynamic_rules_tolerance": "medium",
    "dynamic_rules_logs_enabled": true,
    "log_tag": "tolerance-medium"
  }
  ```

  </DocStep>
  <DocStep title="Espere a alteração se propagar" />
  <DocStep title="Leia as linhas da janela">

  Compare as requisições que você reconhece com as da janela anterior e procure novas recusas.

  </DocStep>
  <DocStep title="Desative os logs de depuração">

  Quando a janela fechar, defina `dynamic_rules_logs_enabled` como `false`, por causa do volume que ele adiciona ao log.

  </DocStep>
</DocSteps>

A Function Instance compara cada requisição com a linha de base na nova tolerância. Para os quatro argumentos que o método aceita, consulte [Regras dinâmicas](/pt-br/documentacao/plataforma/firewall/bot-manager/argumentos/#regras-dinamicas).

## Guarde uma cópia do log de report

As linhas de report aparecem no Real-Time Events, e a plataforma descarta esses dados com o tempo. Uma cópia em um destino seu dura o quanto você a mantiver, ao lado dos registros da Application que essas requisições alcançaram. O [Data Stream](/pt-br/documentacao/plataforma/data-stream/) encaminha as linhas de report da data source _Functions_ para um endpoint que você configura.

Para guardar uma cópia:

<DocSteps>
  <DocStep title="Crie um stream na data source Functions">

  No stream, selecione _Functions_ como data source e _Functions Event Collector_ como template e, em seguida, selecione o seu endpoint. Para o procedimento completo, consulte [Depure functions com o Data Stream](/pt-br/documentacao/guias/plataforma/observabilidade/debugging-functions-data-stream/).

  </DocStep>
  <DocStep title="Diminua internal_logs quando a janela fechar">

  Em `2`, toda requisição produz uma linha, e esse é o volume que o stream carrega.

  </DocStep>
</DocSteps>

O endpoint recebe as linhas que a Function escreve, no formato do template. Para os endpoints em que um stream escreve, consulte [Endpoints](/pt-br/documentacao/plataforma/data-stream/endpoints/).
