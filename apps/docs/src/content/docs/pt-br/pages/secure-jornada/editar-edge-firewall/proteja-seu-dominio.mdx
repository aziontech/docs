Você pode definir um [Firewall](/pt-br/documentacao/plataforma/firewall/) existente em um [Workload](/pt-br/documentacao/plataforma/workloads/) pelo Azion Console ou pela [Azion CLI](/pt-br/documentacao/devtools/cli/), para que ele inspecione as requisições aos domínios do Workload. Para criar um Firewall, adicionar a primeira regra dele e defini-lo de uma só vez, consulte [Primeiros passos com Firewall](/pt-br/documentacao/plataforma/firewall/primeiros-passos/).

## Defina o Firewall no Workload

Um Firewall não tem domínio próprio: o deployment do Workload define o Firewall, e o registro do Workload não tem campo de Firewall. Um deployment carrega três configurações: a Application, o Firewall e o [conjunto de custom pages](/pt-br/documentacao/plataforma/custom-pages/configuracoes/) dele. A Application e o conjunto de custom pages continuam os que o Workload usa hoje, então o Firewall é a única configuração que muda. Até que um deployment defina o Firewall, as regras dele não veem nenhuma requisição ao Workload.

Um Workload tem um único deployment, então você altera o deployment que ele já tem. Um segundo deployment é recusado com `The maximum number of deployments allowed per workload is 1.` Para todos os campos do deployment, consulte [Configurações de Workload](/pt-br/documentacao/plataforma/workloads/configuracoes/#deployment).

<Tabs client:visible sharedStore="interface">

<Fragment slot="panel.console">

### Console

Para definir o Firewall no Azion Console:

<DocSteps>
  <DocStep title="Abra a página Workloads">

  Acesse [Azion Console](https://console.azion.com/) > **Workloads**.

  </DocStep>
  <DocStep title="Abra o Workload">

  Selecione o Workload cujas requisições o Firewall inspeciona. O formulário de edição dele abre.

  </DocStep>
  <DocStep title="Selecione o seu Firewall">

  Na seção **Deployment Settings**, selecione o seu Firewall no campo **Firewall**. Em um Workload sem Firewall, o campo mostra _Select a Firewall_.

  **Application** e **Custom Page** mantêm os valores que o Workload serve hoje.

  </DocStep>
  <DocStep title="Salve o Workload">

  Selecione **Save**.

  </DocStep>
</DocSteps>

Depois de salvar, o deployment do Workload define o seu Firewall.

</Fragment>

<Fragment slot="panel.cli">

### CLI

A Azion CLI não tem comando que atualiza um deployment, e o seu Workload já tem um. Para definir o Firewall, siga o painel do Console.

Em um Workload que ainda não tem deployment, passe `--firewall-id` para `azion create workload-deployment` ao criar o deployment. Em um projeto que declara o Workload no `azion.config.js`, defina o Firewall em `strategy.attributes.firewall` da entrada [`deployments`](/pt-br/documentacao/devtools/cli/azion-config-js/#deployments-do-workload) dele e execute `azion deploy`. Para todas as flags, consulte [Azion CLI workload-deployment](/pt-br/documentacao/devtools/cli/recursos/workload-deployment/).

</Fragment>

</Tabs>

## Defina o Firewall em um domínio v3

Uma conta na API v3 tem [Domains](/pt-br/documentacao/plataforma/workloads/domains/) em vez de Workloads e define o Firewall nas configurações de cada domínio. Para saber em qual modelo a sua conta opera, consulte [Verifique a migração da sua conta](/pt-br/documentacao/guias/seguranca-de-aplicacoes/acesso-e-compliance/verificar-migracao-conta/).

Para definir um Firewall em um domínio no Azion Console:

<DocSteps>
  <DocStep title="Abra o domínio">

  Acesse [Azion Console](https://console.azion.com/) > **Domains** > **o domínio cujas requisições o Firewall inspeciona**.

  </DocStep>
  <DocStep title="Escolha o Firewall">

  Na seção **Settings**, abra o seletor **Firewall** e escolha o Firewall.

  </DocStep>
  <DocStep title="Salve o domínio">

  Selecione **Save**.

  </DocStep>
</DocSteps>

O Firewall passa a inspecionar as requisições desse domínio. A verificação de confirmação lê a resposta de uma requisição, qualquer que seja o modelo que a atendeu.

## Confirme que o Firewall aplica as regras dele

A verificação é a mesma para todas as interfaces. Ela precisa de uma regra do Firewall cuja resposta você reconheça. Esta seção usa uma regra que nega todo caminho que começa com `/deny-test`, como a de [Crie uma regra de Firewall](/pt-br/documentacao/guias/seguranca-de-aplicacoes/firewall-e-waf/trabalhar-com-rules-engine/).

As regras do Firewall podem levar vários minutos para chegar ao Workload depois que o deployment dele define o Firewall, e nenhuma duração é garantida. Até lá, as requisições chegam à sua Application como antes e, enquanto a alteração se propaga, as respostas à mesma requisição alternam entre o resultado antigo e o novo. Repita a requisição até que ela retorne `403`. Para mais informações, consulte [Como Firewall funciona](/pt-br/documentacao/plataforma/firewall/como-funciona/#propagacao).

Envie uma requisição para o caminho negado. Substitua `<your-domain>` por um domínio que o Workload serve, como o workload domain dele, no formato `<id>.map.azionedge.net`:

```bash
curl -i https://<your-domain>/deny-test
```

O Firewall recusa a requisição com `403`. Este trecho da resposta omite o longo header `content-security-policy`:

```text
HTTP/2 403
server: nginx
date: Thu, 01 Jan 2026 12:00:00 GMT
content-type: text/html; charset=utf-8
x-content-type-options: nosniff
x-azion-request-id: 0123456789abcdef0123456789abcdef
x-azion-edge-location: <edge-location>
alt-svc: h3=":443"; ma=86400
```

O corpo é a página de erro padrão da Azion, com o título Forbidden, e mostra o seu endereço IP e o ID da requisição. Nenhum header da resposta identifica o Firewall ou a regra por trás da recusa. Os caminhos a que nenhuma regra corresponde continuam chegando à sua Application.

Se `/deny-test` continuar chegando à sua Application depois que a alteração teve vários minutos para se propagar, consulte [Solucione problemas de Firewall](/pt-br/documentacao/plataforma/firewall/solucao-de-problemas/#um-firewall-nao-age-sobre-as-requisicoes-de-um-workload).
