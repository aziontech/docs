Você pode definir as configurações principais de um [Firewall](/pt-br/documentacao/plataforma/firewall/) pelo Azion Console, pela Azion CLI ou pela API: o nome dele, os switches de WAF, Network Shield e Functions, Debug Rules e o status dele. As regras que o Firewall executa ficam, em vez disso, na aba **Rules Engine** dele. Para adicionar uma, consulte [Crie uma regra de Firewall](/pt-br/documentacao/guias/seguranca-de-aplicacoes/firewall-e-waf/trabalhar-com-rules-engine/).

Um Firewall não carrega domínios: o deployment de um Workload o define. Para definir um Firewall em um Workload, consulte [Defina um Firewall em um Workload](/pt-br/documentacao/guias/seguranca-de-aplicacoes/firewall-e-waf/proteja-seu-dominio/).

## Ative ou desative WAF, Network Shield ou Functions

A seção **Modules** das configurações principais tem um switch para cada um entre [Web Application Firewall (WAF)](/pt-br/documentacao/plataforma/firewall/waf/), [Network Shield](/pt-br/documentacao/plataforma/firewall/network-shield/) e [Functions](/pt-br/documentacao/plataforma/firewall/functions/). Uma regra não pode usar os critérios e comportamentos que um switch controla enquanto ele está desativado, e um Firewall aceita regras apenas enquanto pelo menos um dos três switches está ativado. Para saber o que cada switch acrescenta a uma regra, consulte [Recursos aninhados e switches em um Firewall](/pt-br/documentacao/plataforma/firewall/como-funciona/#recursos-aninhados-e-switches-em-um-firewall).

Um Firewall criado pela API, pela Azion CLI ou pela página **Create Firewall** começa com Network Shield e Functions ativados e WAF desativado. Um Firewall criado a partir de um drawer no Azion Console começa com Functions desativado. Confirme que **Functions** está ativado antes de adicionar uma Function Instance.

Bot Manager não tem switch próprio. [Bot Manager](/pt-br/documentacao/plataforma/firewall/bot-manager/) é executado como uma Function Instance que um comportamento _Run Function_ executa, então ele precisa de Functions no Firewall. Para configurá-lo, consulte [Primeiros passos com Bot Manager](/pt-br/documentacao/plataforma/firewall/bot-manager/primeiros-passos/).

### Console

Para ativar WAF, Network Shield ou Functions no Azion Console:

<DocSteps>
  <DocStep title="Abra o Firewall">

  Acesse [Azion Console](https://console.azion.com/) > **Firewalls** e selecione o Firewall.

  </DocStep>
  <DocStep title="Selecione a aba Main Settings" />
  <DocStep title="Ative o switch">

  Na seção **Modules**, ative cada switch de que você precisa: **Web Application Firewall**, **Network Shield** ou **Functions**.

  </DocStep>
  <DocStep title="Salve as configurações">

  Selecione **Save**.

  </DocStep>
</DocSteps>

Azion Console mostra `Your Firewall has been updated`. Para desativar um deles, desative o switch dele na mesma seção e selecione **Save**.

</Fragment>

<Fragment slot="panel.cli">

### CLI

Para ativar WAF, Network Shield ou Functions pela Azion CLI, execute `azion update firewall` com a flag correspondente definida como `true`. Este comando ativa Network Shield, com o ID do seu Firewall no lugar de `<firewall-id>`:

```bash
azion update firewall --firewall-id <firewall-id> --network-protection true
```

O comando imprime o ID do Firewall que ele atualizou:

```text
Updated Firewall with ID <firewall-id>
```

A flag de WAF é `--waf-enabled`, e a flag de Functions é `--functions-enabled`. Defina uma flag como `false` para desativar o switch dela.

Enquanto uma regra do Firewall usa o critério `${network}`, a CLI se recusa a desativar Network Shield:

```bash
azion update firewall --firewall-id <firewall-id> --network-protection false
```

O erro lista os IDs das regras que usam o critério:

```text
Error: Failed to update the Firewall: ["Cannot disable firewall network protection module, because it is being referenced by the following rules: <rule-id>. Delete those rules or remove their network criteria, then disable the module."]. Check your settings and try again. If the error persists, contact Azion support
```

</Fragment>

<Fragment slot="panel.api">

### API

Para ativar WAF, Network Shield ou Functions pela API, envie uma requisição `PATCH` para o Firewall. O corpo define a chave `enabled` correspondente dentro de `modules`. Esta requisição ativa Network Shield:

```bash
curl --request PATCH \
  --url https://api.azion.com/v4/workspace/firewalls/<firewall-id> \
  --header 'Accept: application/json' \
  --header 'Authorization: Token [TOKEN VALUE]' \
  --header 'Content-Type: application/json' \
  --data '{"modules":{"network_protection":{"enabled":true}}}'
```

A API responde `202` e retorna o Firewall com Network Shield ativado:

```text
{"state":"pending","data":{"id":<firewall-id>,…,"modules":{…,"network_protection":{"enabled":true},…}}}
```

A chave de WAF é `modules.waf.enabled`, e a chave de Functions é `modules.functions.enabled`. `modules.ddos_protection` é somente leitura. Defina `"enabled": false` para desativar um switch. A [referência da Azion API](https://api.azion.com/) documenta todas as chaves de um Firewall.

Enquanto uma regra do Firewall usa o critério `${network}`, um `PATCH` que define `network_protection` como `"enabled": false` é recusado com `400`:

```text
{"errors":[{"code":"24005","title":"Cannot Disable Firewall Network Protection Module","detail":"Cannot disable firewall network protection module, because it is being referenced by the following rules: <rule-id>. Delete those rules or remove their network criteria, then disable the module.","status":"400","source":{"pointer":"/data/modules/network_protection/enabled"},"meta":{"referenced_in_rules":"<rule-id>"}}]}
```

</Fragment>

</Tabs>

Network Shield não pode ser desativado enquanto alguma regra do Firewall usa o critério `${network}`. A recusa lista o ID de cada uma dessas regras.

Salve as configurações principais antes de criar uma regra que precisa de um switch. A aba **Rules Engine** lê as configurações salvas. Enquanto um switch está desativado, as opções que ele controla ainda aparecem nessa aba com um sufixo, como _Set WAF - required WAF_ ou _Network - required Network Shield_, mas não podem ser selecionadas. Para saber de qual switch cada critério e comportamento precisa, consulte [Rules Engine para Firewall](/pt-br/documentacao/plataforma/firewall/rules-engine/#criterios).

## Registre as regras que um Firewall executa

Com Debug Rules ativado, o Firewall registra em log cada regra do Rules Engine executada em uma requisição. [Real-Time Events](/pt-br/documentacao/plataforma/real-time-events/) e [Data Stream](/pt-br/documentacao/plataforma/data-stream/) mostram essas regras no campo `$traceback`. A API GraphQL do Real-Time Events as mostra no campo `stacktrace`. Debug Rules vem desativado em um Firewall novo.

Para ativar Debug Rules no Azion Console:

<DocSteps>
  <DocStep title="Abra o Firewall">

  Acesse [Azion Console](https://console.azion.com/) > **Firewalls** e selecione o Firewall.

  </DocStep>
  <DocStep title="Selecione a aba Main Settings" />
  <DocStep title="Ative Debug Rules">

  Na seção **Debug Rules**, ative **Active**.

  </DocStep>
  <DocStep title="Salve as configurações">

  Selecione **Save**.

  </DocStep>
</DocSteps>

Azion Console mostra `Your Firewall has been updated`. Uma regra que não aparece no campo `$traceback` de uma requisição não foi executada nessa requisição. Para ler o campo, consulte [Depure regras criadas com Rules Engine](/pt-br/documentacao/guias/desenvolvimento-de-aplicacoes/primeiros-passos/debug-regras/).

## Renomeie um Firewall

O nome identifica o Firewall na lista **Firewalls** e é o título da página do Firewall. Todo Firewall precisa de um nome, então o campo **Name** não pode ficar vazio.

Para renomear o Firewall no Azion Console:

<DocSteps>
  <DocStep title="Abra o Firewall">

  Acesse [Azion Console](https://console.azion.com/) > **Firewalls** e selecione o Firewall.

  </DocStep>
  <DocStep title="Selecione a aba Main Settings" />
  <DocStep title="Informe o novo nome">

  Na seção **General**, informe um **Name** único e descritivo, como `storefront-firewall`.

  </DocStep>
  <DocStep title="Salve as configurações">

  Selecione **Save**.

  </DocStep>
</DocSteps>

Azion Console mostra `Your Firewall has been updated`, e o novo nome aparece na coluna **Name** da lista **Firewalls**.

---

## Desative um Firewall

A seção **Status** das configurações principais tem o switch **Active** do Firewall. O switch vem ativado em um Firewall novo.

Para desativar o Firewall no Azion Console:

<DocSteps>
  <DocStep title="Abra o Firewall">

  Acesse [Azion Console](https://console.azion.com/) > **Firewalls** e selecione o Firewall.

  </DocStep>
  <DocStep title="Selecione a aba Main Settings" />
  <DocStep title="Desative o Firewall">

  Na seção **Status**, desative **Active**.

  </DocStep>
  <DocStep title="Salve as configurações">

  Selecione **Save**.

  </DocStep>
</DocSteps>

Azion Console mostra `Your Firewall has been updated`. Para ativar o Firewall de novo, ative **Active** na seção **Status** e selecione **Save**.

## Confirme as configurações principais de um Firewall

Uma leitura do Firewall depois de uma alteração retorna as configurações salvas. Leia essas configurações antes de criar uma regra que precisa de um switch.

<Tabs client:visible sharedStore="interface">

<Fragment slot="panel.console">

### Console

Para confirmar as configurações no Azion Console:

<DocSteps>
  <DocStep title="Abra o Firewall">

  Acesse [Azion Console](https://console.azion.com/) > **Firewalls** e selecione o Firewall.

  </DocStep>
  <DocStep title="Selecione a aba Main Settings">

  A aba tem quatro seções: **General**, **Modules**, **Debug Rules** e **Status**.

  </DocStep>
</DocSteps>

Cada switch da seção **Modules** mostra se WAF, Network Shield ou Functions está ativado no Firewall.

</Fragment>

<Fragment slot="panel.cli">

### CLI

Para confirmar as configurações pela Azion CLI, descreva o Firewall em JSON, com o ID dele no lugar de `<firewall-id>`:

```bash
azion describe firewall --firewall-id <firewall-id> --format json
```

A saída carrega o objeto `modules`, com uma chave `enabled` por switch:

```json
{
 "modules": {
  "ddos_protection": { "enabled": true },
  "functions":       { "enabled": true },
  "network_protection": { "enabled": true },
  "waf":             { "enabled": false }
 },
 "product_version": "2.0"
}
```

Neste Firewall, todos os switches, exceto WAF, estão ativados.

</Fragment>

<Fragment slot="panel.api">

### API

Para confirmar as configurações pela API, envie uma requisição `GET` para o Firewall:

```bash
curl --request GET \
  --url https://api.azion.com/v4/workspace/firewalls/<firewall-id> \
  --header 'Accept: application/json' \
  --header 'Authorization: Token [TOKEN VALUE]'
```

A API responde `200` e retorna o Firewall:

```text
{"data":{"id":<firewall-id>,"name":"<firewall-name>",
 "modules":{"ddos_protection":{"enabled":true},"functions":{"enabled":true},
            "network_protection":{"enabled":true},"waf":{"enabled":true}},
 "debug":false,"active":true,…}}
```

`modules` contém uma chave `enabled` por switch, `debug` contém Debug Rules e `active` contém o status. Neste Firewall, todos os switches estão ativados e Debug Rules está desativado.

</Fragment>

</Tabs>

Cada configuração principal tem um nome em cada interface. As flags da CLI se aplicam a `azion create firewall` e `azion update firewall`, e todas as flags desta tabela, exceto `--name`, recebem `true` ou `false`:

| Configuração | Azion Console | Flag da Azion CLI | Chave da API |
| --- | --- | --- | --- |
| Nome | **Name**, em **General** | `--name` | `name` |
| Functions | **Functions**, em **Modules** | `--functions-enabled` | `modules.functions.enabled` |
| Network Shield | **Network Shield**, em **Modules** | `--network-protection` | `modules.network_protection.enabled` |
| WAF | **Web Application Firewall**, em **Modules** | `--waf-enabled` | `modules.waf.enabled` |
| DDoS Protection | **DDoS Protection Unmetered**, em **Modules** | Nenhuma | `modules.ddos_protection.enabled`, somente leitura |
| Debug Rules | **Active**, em **Debug Rules** | `--debug-rules` | `debug` |
| Status | **Active**, em **Status** | `--active` | `active` |

As configurações salvas só chegam ao tráfego depois que a alteração se propaga. Para mais informações sobre propagação, consulte [Como Firewall funciona](/pt-br/documentacao/plataforma/firewall/como-funciona/#propagacao).
