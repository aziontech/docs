[Image Processor](/pt-br/documentacao/plataforma/applications/image-processor/) é um recurso da plataforma que constrói uma imagem derivada a partir da imagem de origem na origem de uma [Application](/pt-br/documentacao/plataforma/applications/). Ele vem desativado em uma Application nova, e cada Application o ativa separadamente. Com Image Processor ativado, uma requisição de imagem pode carregar uma query string `ims` que descreve uma transformação. Esta página traz o campo, a flag e a interface que define cada um, além dos behaviors, campos de cache, headers e datasets que Image Processor alcança.

---

## Ativação

Cinco interfaces definem o mesmo switch, e o switch pertence à Application: uma Application pode ter Image Processor ativado enquanto outra não.

| Interface | Onde você define | Campo ou flag |
| --- | --- | --- |
| Azion Console | O grupo **Default Modules** da seção **Modules**, na aba **Main Settings** de uma Application | O switch **Image Processor**, com o texto de ajuda "Enable dynamic image editing options." |
| Azion API v4 | `PATCH /v4/workspace/applications/<id>` | `modules.image_processor.enabled` |
| Azion API v3 | `PATCH https://api.azionapi.net/edge_applications/<id>` | `image_optimization` |
| [Azion CLI](/pt-br/documentacao/devtools/cli/) | `azion create application` e `azion update application` | `--image-processor` |
| [`azion.config.js`](/pt-br/documentacao/devtools/cli/azion-config-js/) e [Azion Lib](/pt-br/documentacao/devtools/azion-lib/) | Uma entrada de `applications`, uma por Application | `imageProcessorEnabled` |

`modules.image_processor.enabled` e `imageProcessorEnabled` são booleanos, e os dois assumem `false` por padrão. A flag da Azion CLI recebe uma string: `--image-processor true`. Em Azion Console, o switch é salvo com **Save**.

API v4 carrega o switch no objeto `modules` da Application:

```json
{
  "modules": {
    "image_processor": {
      "enabled": true
    }
  }
}
```

O mesmo objeto `modules` carrega `application_accelerator`, `cache` e `functions`, cada um com seu próprio booleano `enabled`. API v3 nomeia o switch `image_optimization` e o recebe no nível superior do corpo.

## Behaviors do Rules Engine

Uma regra que processa uma imagem usa três behaviors do [Rules Engine](/pt-br/documentacao/plataforma/applications/rules-engine/). **Optimize Images** exige Image Processor ativado na Application que executa a regra.

| Behavior | Fase | Tipo na API | O que faz |
| --- | --- | --- | --- |
| **Optimize Images** | **Request Phase** | `optimize_images` | Aplica Image Processor à requisição correspondente. Não recebe atributos. |
| **Set Cache Policy** | **Request Phase** | `set_cache_policy` | Aplica um cache setting à requisição correspondente. |
| **Add Request Header** | **Request Phase** | `add_request_header` | Adiciona um header à requisição. |

Em **Set Cache Policy**, `attributes.value` carrega o id do cache setting, e no Azion Console você o seleciona em um segundo dropdown. Em **Add Request Header**, `attributes.value` assume o formato `Field: value`, como `Accept: image/webp` ou `Accept: image/avif`, que é o que uma conversão para esses formatos exige.

Um critério da mesma regra carrega `variable`, `operator`, `conditional` e `argument`. Uma regra que corresponde a requisições de imagem lê `${request_uri}` ou `${uri}` com o operador `matches`, usando um argumento como `\.(jpg|jpeg|gif|bmp|png|ico|webp|avif)`. `${request_uri}` exige Application Accelerator na Application: enquanto Application Accelerator está desativado, a API recusa uma regra que o lê e retorna o erro `25047`. `${uri}` não depende de nenhum recurso da plataforma.

## Variação de cache

Uma imagem derivada é armazenada em cache sob uma cache key própria quando o cache setting dela varia o cache por `ims`, porque a cache key passa a incluir a query string `ims`. Uma variação com um formato convertido também carrega o formato do arquivo após o separador `@@`, como em `httpsstatic.example.com/static/images/image_1.jpg?ims=880x@@webp`.

Variar o cache por query string usa um campo do [Application Accelerator](/pt-br/documentacao/plataforma/applications/application-accelerator/): `cache_vary_by_querystring`, sob `modules.application_accelerator` em um cache setting. Então, variar o cache por `ims` exige Application Accelerator, enquanto processar uma imagem não o exige.

No Azion Console, cada campo corresponde a um controle do painel **Cache vary by Query String**, na seção **Application Accelerator** de um cache setting:

| Campo | Controle no Console | O que define |
| --- | --- | --- |
| `cache_vary_by_querystring.behavior` | **Behavior** | Como o cache trata os parâmetros da query string. O dropdown oferece _Allowlist_, _Denylist_, _Ignore_ e _All_. |
| `cache_vary_by_querystring.fields` | **Fields** | Os parâmetros de query string considerados para a variação de cache, um por linha. |
| `cache_vary_by_querystring.sort_enabled` | **Sort** | Se os parâmetros de query string são ordenados, de forma que o comportamento do cache não dependa da ordem em que chegam. |

Um cache setting para imagens carrega `ims` em `fields`. Para o restante dos campos que um cache setting carrega, incluindo a idade máxima do objeto em cache, consulte [Cache settings](/pt-br/documentacao/plataforma/applications/cache/cache-settings/). Para os demais campos que Application Accelerator libera, consulte [Configurações do Application Accelerator](/pt-br/documentacao/plataforma/applications/application-accelerator/configuracoes/).

## Headers de resposta

Azion retorna dois headers em uma resposta que Image Processor processou.

| Header | O que carrega |
| --- | --- |
| `x-ims` | Se Image Processor processou a resposta. Uma resposta processada carrega `x-ims: Enabled`. |
| `x-original-image-size` | O tamanho em bytes da imagem de origem, antes da transformação. |

## Dados de uso e eventos

Azion reporta a atividade de Image Processor em seis superfícies: quatro no Azion Console, duas em Real-Time Metrics e duas em Real-Time Events, e duas em GraphQL.

| Superfície | O que carrega |
| --- | --- |
| A aba **Image Processor** de [Real-Time Metrics](/pt-br/documentacao/plataforma/real-time-metrics/) | Métricas das requisições feitas às imagens processadas por Image Processor na sua conta, nos gráficos Total Requests e Total Requests per Second. |
| O dashboard **Bandwidth Saving** na aba **Applications** de Real-Time Metrics | Os bytes que Image Processor economizou nas imagens que processou e entregou. |
| O dataset **Image Processor** de [Real-Time Events](/pt-br/documentacao/plataforma/real-time-events/) | Os registros de eventos das requisições feitas a Applications que usam Image Processor. |
| O campo **Proxy Upstream** de Real-Time Events | `ims_http`, o valor que o campo assume quando Image Processor respondeu como o upstream. |
| O dataset de consumo de [GraphQL](/pt-br/documentacao/devtools/graphql/campos-gql-consumption/) | `productId` `1441110021` e a métrica `images_processed`, o número total de imagens processadas por Image Processor. |
| Os [datasets de métricas](/pt-br/documentacao/devtools/graphql/campos-gql-real-time-metrics/) de GraphQL | O dataset `imagesProcessedMetrics` e seus campos. |

No Azion Console, o dataset **Image Processor** de Real-Time Events exige Image Processor ativado, e em GraphQL ele é o dataset `imagesProcessedEvents`. Os dados de consumo ficam disponíveis por até 24 meses, e um registro de Real-Time Events é mantido por 7 dias. Para criar a consulta de consumo e ler sua resposta, consulte [Consultar dados de uso do Image Processor](/pt-br/documentacao/guias/plataforma/observabilidade/consultar-dados-de-uso-image-processor-com-graphql/).

## Biblioteca WASM Image Processor

WASM Image Processor é uma biblioteca WebAssembly que processa imagens dentro de uma [Function](/pt-br/documentacao/plataforma/functions/). Ela fornece `loadImage`, `resize`, `getImageResponse` e `clean`, e grava `webp`, `jpeg` e `png`. Ela é executada no código dessa Function, separada do recurso da plataforma Image Processor e dos campos desta página. Para mais informações, consulte [WASM Image Processor](/pt-br/documentacao/devtools/azion-lib/wasm-image-processor/).
