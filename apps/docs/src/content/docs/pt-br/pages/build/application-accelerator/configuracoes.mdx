[Application Accelerator](/pt-br/documentacao/plataforma/applications/application-accelerator/) varia a cache key de uma [aplicação](/pt-br/documentacao/plataforma/applications/) além da URL, e você o ativa para uma aplicação por vez. Ele libera os campos que variam a cache key, o cache de respostas `POST` e `OPTIONS`, um **Max Age** abaixo de 60 segundos e os behaviors e as variáveis do [Rules Engine](/pt-br/documentacao/plataforma/applications/rules-engine/) listados abaixo. Esta página traz o nome, o tipo e o padrão de cada campo, e a interface que o define.

---

## Switch do Application Accelerator

O switch vem desativado por padrão, e todas as interfaces abaixo acionam o mesmo controle. O controle pertence à aplicação, não a um [cache setting](/pt-br/documentacao/plataforma/applications/cache/cache-settings/), portanto uma aplicação pode tê-lo ativado enquanto outra não.

| Interface | Onde você define | Campo ou flag |
| --- | --- | --- |
| Azion Console | A seção **Modules** da aba **Main Settings** de uma aplicação | O switch **Application Accelerator** |
| Azion API v4 | `PATCH /workspace/applications/{id}` | `modules.application_accelerator.enabled` |
| [Azion CLI](/pt-br/documentacao/devtools/cli/) | `azion update application` | `--application-accelerator` |
| [`azion.config.js`](/pt-br/documentacao/devtools/cli/azion-config-js/) | O objeto `AzionApplication` | `applicationAcceleratorEnabled` |
| [Azion Lib](/pt-br/documentacao/devtools/azion-lib/application/) | Os dados da atualização de uma aplicação, porque API v3 recusa o campo na criação | `application_acceleration` |

`modules.application_accelerator.enabled` é um booleano e assume `false` por padrão. `applicationAcceleratorEnabled` e `application_acceleration` são booleanos, e a flag da Azion CLI recebe uma string.

O [Azion Terraform Provider](/pt-br/documentacao/devtools/terraform/) gerencia o recurso de aplicação que carrega o switch. Ativar Application Accelerator pode gerar custos relacionados ao uso. Para mais informações, consulte [Preços](/pt-br/documentacao/fundamentos/precos/#application-accelerator).

## Cache variation

Todo cache setting carrega o objeto `modules.application_accelerator`, e Application Accelerator permite que os campos dele saiam do padrão. Esses campos configuram a Advanced Cache Key. Eles decidem quais partes de uma requisição, além da URL, produzem um objeto separado em cache. Em Azion Console, os mesmos campos ficam na seção **Application Accelerator** de um cache setting. Uma variação por cookie, por device group ou de `POST` ou `OPTIONS` em cache acrescenta o separador `@@` à cache key. Uma variação por query string acrescenta, em vez disso, o separador `?` e os seus argumentos. Para o formato de uma cache key, consulte [Formato da cache key](/pt-br/documentacao/plataforma/applications/cache/cache-keys/#formato-da-key).

| Campo | Tipo | Padrão | Controle no Console | O que define |
| --- | --- | --- | --- | --- |
| `cache_vary_by_method` | array de enum, no máximo 2 valores: `options`, `post` | `[]` | **Cache vary by Method**, um checkbox por método | Os métodos de requisição cujas respostas são armazenadas em cache. |
| `cache_vary_by_querystring.behavior` | enum: `ignore`, `all`, `allowlist`, `denylist` | `ignore` | **Cache vary by Query String** > **Behavior** | O modo que decide como a query string varia a cache key. |
| `cache_vary_by_querystring.fields` | array de string | `[]` | **Cache vary by Query String** > **Fields** | Os argumentos de query string aos quais o modo se aplica. |
| `cache_vary_by_querystring.sort_enabled` | booleano | `false` | **Cache vary by Query String** > **Sort** | Se as variações se agrupam sob uma única cache key, em ordem alfabética. |
| `cache_vary_by_cookies.behavior` | enum: `ignore`, `all`, `allowlist`, `denylist` | `ignore` | **Cache vary by Cookies** > **Behavior** | O modo que decide como os cookies variam a cache key. |
| `cache_vary_by_cookies.cookie_names` | array de string | `[]` | **Cache vary by Cookies** > **Fields** | Os cookies aos quais o modo se aplica. |
| `cache_vary_by_devices.behavior` | enum: `ignore`, `allowlist` | `ignore` | **Cache vary by Devices** > **Behavior** | O modo que decide como os device groups variam a cache key. |
| `cache_vary_by_devices.device_group` | array de inteiros | `[]` | **Cache vary by Devices** > **Device Group** | Os [device groups](/pt-br/documentacao/plataforma/applications/device-groups/) aos quais o modo se aplica. |

Os dropdowns **Behavior** de **Cache vary by Query String** e de **Cache vary by Cookies** mostram _Allowlist_, _Denylist_, _Ignore_ e _All_. O de **Cache vary by Devices** mostra _Allowlist_ e _Ignore_.

_Allowlist_ e _Denylist_ na query string exigem pelo menos um argumento em `fields`, ou a API retorna o erro `21018`. Enviada com Application Accelerator desativado, uma variação retorna o erro `21013`. Para todos os erros que um cache setting retorna, consulte [Cache settings](/pt-br/documentacao/plataforma/applications/cache/cache-settings/#erros).

Um campo do mesmo cache setting fica fora desse objeto e ainda assim exige Application Accelerator:

| Campo | Tipo | Padrão | Controle no Console | O que define |
| --- | --- | --- | --- | --- |
| `modules.cache.max_age` | inteiro, de `0` a `31536000` segundos | `60` | **Cache** > **Max Age** | Por quanto tempo o cache guarda o objeto. Abaixo de 60, exige Application Accelerator. |

Sem Application Accelerator, um `max_age` abaixo de 60 retorna o erro `21021`. Com Application Accelerator e Tiered Cache ativos, um valor abaixo de 3 retorna o erro `21020`.

Para os tetos que limitam um cache setting, consulte [Limites](/pt-br/documentacao/plataforma/applications/limites/#application-accelerator).

## Flags de cache setting na Azion CLI

`azion create cache-setting` grava a maior parte desses campos pela linha de comando. Cada flag abaixo define um campo do cache setting.

| Flag | Campo que define | Padrão |
| --- | --- | --- |
| `--cache-by-query-string` | `cache_vary_by_querystring.behavior` | `ignore` |
| `--query-string-fields` | `cache_vary_by_querystring.fields` | Nenhum |
| `--cache-by-cookies` | `cache_vary_by_cookies.behavior` | `ignore` |
| `--cookie-names` | `cache_vary_by_cookies.cookie_names` | Nenhum |
| `--enable-caching-for-post` | `options` e `post` em `cache_vary_by_method`, com qualquer um dos dois valores | Nenhum |
| `--enable-caching-for-options` | `options` em `cache_vary_by_method`, com qualquer um dos dois valores | `false` |

Na criação, `false` não desativa um método, então armazenar `POST` em cache sem `OPTIONS` exige `cache_vary_by_method` no corpo do `--file`. [`azion update cache-setting`](/pt-br/documentacao/devtools/cli/recursos/cache-setting/#atualizar) respeita `true` e `false`. Na atualização, uma chamada que passa uma flag de método remove o outro método, então passe as duas flags para manter os dois.

Nenhuma flag de `azion create cache-setting` define **Sort**, a variação por device group ou o **Max Age** do cache, então envie esses valores em um corpo `--file`. Em `azion update cache-setting`, `--enable-caching-string-sort` define `sort_enabled`. `--browser-cache-max-age` define apenas o valor do navegador.

## HTTP methods

Application Accelerator adiciona cinco métodos aos `GET` e `HEAD` que uma aplicação atende. As respostas de dois deles podem ser armazenadas em cache por meio de `cache_vary_by_method`.

| Método adicionado pelo Application Accelerator | A resposta pode ser armazenada em cache |
| --- | --- |
| `OPTIONS` | Sim, quando `cache_vary_by_method` carrega `options` |
| `POST` | Sim, quando `cache_vary_by_method` carrega `post` |
| `PUT` | Não |
| `PATCH` | Não |
| `DELETE` | Não |

Um objeto `POST` ou `OPTIONS` em cache recebe a própria cache key. Para o formato dessa key, consulte [Variações da cache key](/pt-br/documentacao/plataforma/applications/cache/cache-keys/#variacoes).

## Behaviors do Rules Engine

Estes behaviors do Rules Engine exigem Application Accelerator na aplicação que executa a regra. A tabela indexa esses behaviors; [Rules Engine](/pt-br/documentacao/plataforma/applications/rules-engine/#behaviors) traz os argumentos e a sintaxe de cada um.

| Behavior | Fases | O que faz |
| --- | --- | --- |
| [Add Request Cookie, Add Response Cookie](/pt-br/documentacao/plataforma/applications/rules-engine/#add-request-cookie-e-add-response-cookie) | Request, Response | Adiciona um cookie ao header `Set-Cookie`. |
| [Bypass Cache](/pt-br/documentacao/plataforma/applications/rules-engine/#bypass-cache) | Request | Impede que o cache da Azion guarde a resposta da origem e não altera o cache do navegador. |
| [Capture Match Groups](/pt-br/documentacao/plataforma/applications/rules-engine/#capture-match-groups) | Request, Response | Guarda em uma variável temporária a captura de uma expressão regular sobre um campo da requisição. |
| [Filter Request Cookie, Filter Response Cookie](/pt-br/documentacao/plataforma/applications/rules-engine/#filter-request-cookie) | Request, Response | Remove um cookie da requisição à origem ou da resposta ao usuário. |
| [Forward Cookies](/pt-br/documentacao/plataforma/applications/rules-engine/#forward-cookies) | Request | Encaminha o header `Set-Cookie` da origem aos usuários, inclusive em um cache hit. |
| [Rewrite Request](/pt-br/documentacao/plataforma/applications/rules-engine/#rewrite-request) | Request | Altera o caminho do recurso requisitado à origem. |

_Bypass Cache_ age sobre o cache da Azion e não sobre a camada do [Tiered Cache](/pt-br/documentacao/plataforma/applications/cache/tiered-cache/). Uma aplicação cujos cache settings têm Tiered Cache ativo continua a armazenar objetos nessa camada pelo tempo de vida mínimo.

Os critérios de uma regra podem ler `${request_uri}` e `${device_group}`, e os dois exigem Application Accelerator. Uma regra que lê `${request_uri}` sem ele é recusada com `25047`. Para as variáveis, consulte [Variáveis](/pt-br/documentacao/plataforma/applications/rules-engine/#variaveis), e para os grupos aos quais `${device_group}` corresponde, consulte [Device Groups](/pt-br/documentacao/plataforma/applications/device-groups/).

[Set Cache Policy](/pt-br/documentacao/plataforma/applications/rules-engine/#set-cache-policy) não exige Application Accelerator. Ele aplica um cache setting da aba **Cache Settings**, e é assim que um cache setting alcança uma requisição.

[Run Function](/pt-br/documentacao/plataforma/applications/rules-engine/#run-function) também não exige Application Accelerator. Ele executa uma função instanciada na aplicação e exige [Functions](/pt-br/documentacao/plataforma/functions/).
