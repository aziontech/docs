**Image Processor** é um recurso da plataforma que constrói imagens derivadas de imagens da origem na infraestrutura distribuída da Azion, para requisições recebidas por [Applications](/pt-br/documentacao/plataforma/applications/). A transformação de imagens sob demanda é um modelo de entrega em que o servidor constrói cada variante na requisição, conforme descrito na URL. Use Image Processor para servir uma imagem em vários tamanhos, recortes, qualidades ou formatos, como WEBP para navegadores que o aceitam, de um arquivo.

## Caminho da requisição

O parâmetro de query string `ims` não transforma uma imagem por si só: antes, uma regra com o behavior [Optimize Images](/pt-br/documentacao/plataforma/applications/rules-engine/#optimize-images) precisa corresponder à requisição. Ativar Image Processor em uma Application apenas disponibiliza esse behavior para as regras do [Rules Engine](/pt-br/documentacao/plataforma/applications/rules-engine/) dela.

As setas sólidas levam a requisição, e as setas pontilhadas levam a resposta. Cada rótulo começa com o número do seu passo abaixo.

  App -->|"5. sem cópia em cache"| IP

1. Uma requisição para um path que contém uma imagem chega à Application, que executa as suas regras da Request Phase, como uma regra com _Optimize Images_ que corresponde a requisições de imagem. Para criar essa regra passo a passo, consulte [Configure Image Processor em uma aplicação](/pt-br/documentacao/guias/performance-e-confiabilidade/otimizacao-de-entrega/processar-imagens/).
2. Quando nenhuma regra com _Optimize Images_ corresponde à requisição, a imagem de origem, o arquivo no servidor de origem, é entregue sem processamento.
3. Uma regra que corresponde à requisição aplica os seus behaviors. _Optimize Images_ aplica Image Processor à requisição. Quando a regra também carrega _Set Cache Policy_, esse behavior aplica o [cache setting](/pt-br/documentacao/plataforma/applications/cache/cache-settings/) que guarda a imagem derivada. Uma regra pode carregar _Optimize Images_ sozinho, porque o behavior não recebe argumento.
4. Quando a imagem derivada já está em cache, [Cache](/pt-br/documentacao/plataforma/applications/cache/) a entrega sem processamento.
5. Caso contrário, Image Processor lê a imagem de origem sem alterá-la e aplica `ims` a ela, como em `?ims=fit-in/400x400`. A imagem derivada é entregue. O cache da Application só a armazena quando a regra aplica um cache setting com _Set Cache Policy_. Sem esse cache setting, toda requisição chega ao Image Processor, que responde a uma transformação repetida a partir do próprio cache.

Para saber como o formato entregue é escolhido, como o cache diferencia as imagens derivadas e onde Image Processor para, consulte [Entrega de imagens](/pt-br/documentacao/plataforma/applications/image-processor/entrega-de-imagens/).
