Definições dos termos que a documentação de [Applications](/pt-br/documentacao/plataforma/applications/) usa, incluindo os de [Cache](/pt-br/documentacao/plataforma/applications/cache/), [Application Accelerator](/pt-br/documentacao/plataforma/applications/application-accelerator/) e [Image Processor](/pt-br/documentacao/plataforma/applications/image-processor/).

| Termo | Definição |
| --- | --- |
| Add Request Header | O behavior do [Rules Engine para Applications](/pt-br/documentacao/plataforma/applications/rules-engine/) que adiciona um header na forma `Field: value` à requisição, na Request Phase, `add_request_header` na API. Uma requisição que Image Processor converte para WEBP precisa carregar `Accept: image/webp`, e este behavior o adiciona. A API recusa o nome `add_header` com `10039 Invalid Choice`. |
| Advanced Cache Key | Uma feature de Application Accelerator que varia a cache key por partes de uma requisição além da URL: a query string, os cookies, os device groups e o método da requisição. Ela exige Application Accelerator ativo na Application, e cada cache setting a configura no seu objeto `modules.application_accelerator`, por meio dos quatro controles Cache vary by. [Configurações do Application Accelerator](/pt-br/documentacao/plataforma/applications/application-accelerator/configuracoes/#cache-variation) documenta cada controle e onde ele fica no Azion Console e na API. |
| allowlist | O valor `behavior` de um controle Cache vary by que varia a cache key só pelos atributos que o cache setting nomeia. O dropdown **Behavior** do Azion Console o mostra como _Allowlist_. Ele limita quantos objetos uma variação cria, porque só um atributo que o setting nomeia produz um objeto a mais; [Configurações do Application Accelerator](/pt-br/documentacao/plataforma/applications/application-accelerator/configuracoes/#cache-variation) lista os valores que cada controle aceita. |
| Application | A entidade que executa as suas regras nas requisições dos [Workloads](/pt-br/documentacao/plataforma/workloads/) cujo deployment a define. Uma Application nova começa com Cache e Functions ativos, Application Accelerator e Image Processor desativados e nenhuma regra. O campo **Application** das **Deployment Settings** de um Workload no Azion Console a define, a API serve as suas Applications em `/v4/workspace/applications`, e [Applications](/pt-br/documentacao/plataforma/applications/) documenta o recurso da plataforma. |
| Application Accelerator | Um recurso da plataforma aninhado em Applications que permite que um cache setting acrescente a query string, os cookies, o device group ou o método da requisição à cache key. Ele vem desativado em uma Application nova, `modules.application_accelerator.enabled` na API, e ativá-lo libera a variação de cache, o cache de respostas `POST` e `OPTIONS`, um Max Age menor que 60 segundos, as variáveis `${request_uri}` e `${device_group}` e os behaviors do Rules Engine que Azion Console marca com _- Required Application Accelerator_. [Applications](/pt-br/documentacao/plataforma/applications/#application-accelerator) o descreve, e a [visão geral do Application Accelerator](/pt-br/documentacao/plataforma/applications/application-accelerator/#caminho-da-requisicao) acompanha uma requisição por ele. |
| behavior | A ação que uma regra executa sobre as requisições às quais os seus critérios correspondem, como _Set Cache Policy_, _Set Connector_ ou _Run Function_. Uma regra executa os seus behaviors na ordem em que os lista, um behavior que encerra o processamento interrompe os behaviors e as regras depois dele na sua fase, e [Rules Engine para Applications](/pt-br/documentacao/plataforma/applications/rules-engine/) nomeia o recurso da plataforma de que cada behavior precisa. Em um cache setting, `behavior` também é o campo de cada controle Cache vary by, e [Configurações do Application Accelerator](/pt-br/documentacao/plataforma/applications/application-accelerator/configuracoes/#cache-variation) lista os valores de cada um. |
| Bypass Cache | O behavior do [Rules Engine para Applications](/pt-br/documentacao/plataforma/applications/rules-engine/#bypass-cache) que envia à origem uma requisição que corresponde à regra e mantém a resposta fora do cache da Azion, `bypass_cache` na API. Ele roda na Request Phase, exige Application Accelerator, deixa o browser cache a cargo de _Set Cache Policy_ e difere de um TTL de 0 segundos, como [Bypass Cache e um TTL de 0](/pt-br/documentacao/plataforma/applications/application-accelerator/variacao-de-cache/#bypass-cache-e-um-ttl-de-0) explica. Ele age só sobre o cache da Azion, então uma Application com cache settings de Tiered Cache ativos continua armazenando objetos na camada do [Tiered Cache](/pt-br/documentacao/plataforma/applications/cache/tiered-cache/#bypass-cache) pelo TTL mínimo. |
| Cache | Um recurso da plataforma aninhado em Applications que atende às requisições seguintes pelo mesmo objeto com uma cópia de uma resposta da origem, armazenada no data center que a buscou. Ele vem ativo em uma Application nova, `modules.cache.enabled` na API, e, no Azion Console, a nota sobre Cache diz `Automatically enabled in all accounts.` [Applications](/pt-br/documentacao/plataforma/applications/#cache) o descreve, e a [visão geral do Cache](/pt-br/documentacao/plataforma/applications/cache/#caminho-da-requisicao) acompanha uma requisição por ele. |
| cache key | A entrada de índice sob a qual Cache armazena um objeto, com diferenciação entre maiúsculas e minúsculas. No Cache, a configuração padrão ignora a query string, então a key concatena o scheme, o host e o path, como em `httpsstatic.example.com/page/site.js`, e cada variação acrescenta algo a ela: os argumentos de query string que um setting nomeia ou um valor depois do separador `@@`. Quando o cache setting que serve imagens varia o cache em `ims`, a key carrega a query string `ims`, e uma imagem convertida também carrega o seu formato depois de `@@`; [Cache keys](/pt-br/documentacao/plataforma/applications/cache/cache-keys/#formato-da-key) documenta cada forma. |
| cache setting | A configuração de uma Application que guarda os TTLs do cache da Azion e do navegador, e as entradas que distinguem duas requisições. Um cache setting pertence a uma Application e traz Max Age, stale cache, Large File Optimization e Tiered Cache, além dos quatro controles Cache vary by no seu objeto `modules.application_accelerator`. Ele só age por meio de uma regra que o aplica com _Set Cache Policy_ às requisições às quais a regra corresponde; [Cache settings](/pt-br/documentacao/plataforma/applications/cache/cache-settings/) documenta cada campo, e [Primeiros passos com Cache](/pt-br/documentacao/plataforma/applications/cache/primeiros-passos/) cria o primeiro. |
| Connector | A entidade que encaminha as requisições de uma Application à sua origem, definida pelo seu ID em uma regra com o behavior _Set Connector_. Ela pertence a [Connectors](/pt-br/documentacao/plataforma/connectors/), o recurso da plataforma que substitui as origens que as versões anteriores de Applications configuravam na Application. Com [Load Balancer](/pt-br/documentacao/plataforma/connectors/load-balancer/) ativado, um Connector do tipo `http` pode distribuir o tráfego entre várias origens. |
| critério | Uma condição única dentro de uma regra: uma variável como `${uri}`, um operador de comparação e um argumento quando o operador aceita um, enviados na API como `variable`, `operator`, `conditional` e `argument`. Dentro de um grupo, os critérios se combinam com `and` e `or`, e `and` tem precedência sobre `or`. Os grupos de uma regra se unem por `and`, e a API os carrega como um array de grupos, `[[{...}]]`. [Rules Engine para Applications](/pt-br/documentacao/plataforma/applications/rules-engine/) lista cada variável e operador. |
| Debug Rules | A configuração de uma Application que registra as regras do Rules Engine que cada requisição executou, `debug` na API e desativada em uma Application nova. Com ela ativa, as regras executadas aparecem no campo `$traceback` em Data Stream e em [Real-Time Events](/pt-br/documentacao/plataforma/real-time-events/), e no campo `stacktrace` da [API GraphQL do Real-Time Events](/pt-br/documentacao/devtools/graphql/campos-gql-real-time-events/). [Main Settings](/pt-br/documentacao/plataforma/applications/main-settings/#debug-rules) mostra onde ativá-la no Azion Console, e [Depure regras criadas com Rules Engine](/pt-br/documentacao/guias/desenvolvimento-de-aplicacoes/primeiros-passos/debug-regras/) mostra como ler esses logs. |
| denylist | O valor `behavior` de Cache vary by Query String e de Cache vary by Cookies que varia a cache key por todos os argumentos de query string, ou por todos os cookies, exceto os que o cache setting nomeia. O dropdown **Behavior** do Azion Console o mostra como _Denylist_, e [Configurações do Application Accelerator](/pt-br/documentacao/plataforma/applications/application-accelerator/configuracoes/#cache-variation) lista os valores que cada controle aceita. |
| device group | Um conjunto nomeado de dispositivos que uma Application reconhece comparando o header `User-Agent` de uma requisição com uma expressão regular. Cada device group pertence a uma Application, e uma regra o testa por meio da variável `${device_group}`, que exige Application Accelerator. [Cache vary by Devices](/pt-br/documentacao/plataforma/applications/application-accelerator/configuracoes/#cache-variation) varia a cache key por ele, e [Device Groups](/pt-br/documentacao/plataforma/applications/device-groups/) documenta a correspondência. |
| fase | Um dos dois estágios em que uma Application executa regras: a Request Phase, sobre a requisição antes que exista uma resposta, e a Response Phase, sobre a resposta entregue ao usuário. Você define a fase de uma regra ao criá-la e não pode mudá-la depois, então uma regra na outra fase é uma nova regra. O cache é decidido na Request Phase, e [Rules Engine para Applications](/pt-br/documentacao/plataforma/applications/rules-engine/) lista as fases em que cada variável e cada behavior estão disponíveis. |
| filtro | O componente de `ims` que transforma uma imagem além de um redimensionamento ou de um recorte, escrito `filters:name(argument)`, como em `filters:quality(15)`. Uma string `ims` combina vários filtros, separados por `:`. [Parâmetros de URL do Image Processor](/pt-br/documentacao/plataforma/applications/image-processor/parametros-de-url/) documenta `rotate`, `quality`, `watermark`, `format` e `fill`. |
| `fit-in` | O prefixo de `ims` que ajusta a imagem derivada dentro de uma caixa `WidthxHeight` e mantém a proporção da imagem de origem, como em `?ims=fit-in/400x400`. Uma imagem menor que a caixa mantém o seu tamanho original. As duas dimensões são opcionais, e [Parâmetros de URL do Image Processor](/pt-br/documentacao/plataforma/applications/image-processor/parametros-de-url/#redimensionamento) mostra cada forma. |
| Forward Cookies | O behavior do [Rules Engine para Applications](/pt-br/documentacao/plataforma/applications/rules-engine/) que envia ao usuário o header `Set-Cookie` da origem mesmo quando a resposta vem do cache. Ele roda na Request Phase e exige Application Accelerator. |
| Function Instance | A entidade que adiciona uma das suas [Functions](/pt-br/documentacao/plataforma/functions/) a uma Application, com os argumentos com que ela roda, servida pela API em `/v4/workspace/applications/<application-id>/functions`. Ela pertence a uma Application, e uma regra com o behavior _Run Function_ a invoca pelo seu ID em `attributes.value`. [Function Instances](/pt-br/documentacao/plataforma/applications/functions-instances/) documenta os seus campos. |
| Image Processor | Um recurso da plataforma aninhado em Applications que retorna uma imagem derivada construída a partir de uma imagem de origem guardada na origem, seguindo a query string `ims` da requisição. Ele vem desativado em uma Application nova, e cada Application o ativa separadamente, em `modules.image_processor.enabled` na API ou com `--image-processor` no Azion CLI. [Applications](/pt-br/documentacao/plataforma/applications/#image-processor) o descreve, e a [visão geral do Image Processor](/pt-br/documentacao/plataforma/applications/image-processor/#caminho-da-requisicao) acompanha uma requisição por ele. |
| imagem de origem | A imagem original, armazenada na origem, que Image Processor lê para responder a uma requisição que carrega uma query string `ims`. Image Processor a lê sem alterá-la, e cada transformação produz uma imagem derivada separada. O caminho entre as duas está na [visão geral do Image Processor](/pt-br/documentacao/plataforma/applications/image-processor/#caminho-da-requisicao). |
| imagem derivada | A imagem que Image Processor constrói a partir da imagem de origem guardada na origem e retorna a uma requisição que carrega uma query string `ims`. Image Processor a retorna sem salvá-la como um ativo da conta, e a imagem de origem permanece inalterada. A [visão geral do Image Processor](/pt-br/documentacao/plataforma/applications/image-processor/#caminho-da-requisicao) descreve como uma requisição produz uma. |
| Images | O medidor de uso que [Preços](/pt-br/documentacao/fundamentos/precos/#image-processor) lista para Image Processor, com a sua tarifa. A página [Preços da Azion](https://www.azion.com/pt-br/precos/) lista o volume que cada plano inclui. |
| `ims` | O parâmetro de query string que informa a Image Processor qual transformação aplicar, como em `?ims=400x`. Ele vai por último na URL, porque uma requisição que carrega outro parâmetro depois de `ims=` pode retornar um erro `504`. [Parâmetros de URL do Image Processor](/pt-br/documentacao/plataforma/applications/image-processor/parametros-de-url/#posicao-do-parametro-ims) documenta cada valor que ele aceita e a sua posição. |
| Large File Optimization | Uma feature de Cache que armazena um objeto grande em fragmentos de 1.024 kB, desativada por padrão e ativada por cache setting em `modules.cache.large_file_cache.enabled`. A Azion coloca cada fragmento em cache quando um usuário o requisita, sob a sua própria cache key terminada em `@@bytes=<start>-<end>`, e a feature também se aplica ao Tiered Cache quando essa camada está ativa. [Expiração e atualização](/pt-br/documentacao/plataforma/applications/cache/expiracao-e-atualizacao/#large-file-optimization) descreve o mecanismo. |
| Main Settings | A aba do Azion Console de uma Application cujas quatro seções são **General**, que traz o nome, **Modules**, **Debug Rules** e **Status**. As configurações de entrega e de protocolo pertencem ao [Workload](/pt-br/documentacao/plataforma/workloads/) que serve a Application, e não a esta aba. [Main Settings de Applications](/pt-br/documentacao/plataforma/applications/main-settings/) documenta cada seção. |
| Max Age | O campo do cache setting para quantos segundos o cache da Azion mantém uma cópia de um objeto, `modules.cache.max_age` na API, com padrão `60` no Azion Console, na API e na CLI. A API recusa um valor menor que 60 com `21021` enquanto Application Accelerator está desativado, um valor menor que 3 com `21020` enquanto Application Accelerator e Tiered Cache estão ativos e um valor maior que `31536000` com `10068`. O cache do navegador tem um Max Age próprio, `browser_cache.max_age`; [Limites de Applications](/pt-br/documentacao/plataforma/applications/limites/#application-accelerator) traz os limites que dependem dos recursos da plataforma ativos. |
| `modules` | O objeto da API que traz os switches de uma Application, `application_accelerator`, `cache`, `functions` e `image_processor`, cada um com um valor `enabled`. Azion Console o apresenta como a seção **Modules** de [Main Settings](/pt-br/documentacao/plataforma/applications/main-settings/#recursos-da-plataforma), cujos **Default Modules** são os mesmos quatro, ao lado de um grupo **Subscription modules** com uma ação **Contact sales**. Tiered Cache não é um desses switches: cada cache setting a ativa no seu próprio campo `modules.cache.tiered_cache.enabled`. |
| Optimize Images | O behavior do [Rules Engine para Applications](/pt-br/documentacao/plataforma/applications/rules-engine/) que envia a Image Processor as requisições às quais a sua regra corresponde, `optimize_images` na API. Ele roda na Request Phase, não aceita argumentos e exige Image Processor ativo na Application. A API o aceita sozinho em uma regra, sem nenhum _Set Cache Policy_ ao lado. |
| purge por cache key | Um tipo de [Real-Time Purge](/pt-br/documentacao/plataforma/applications/cache/real-time-purge/#purge-por-cache-key), `cachekey` na API, que remove os objetos armazenados sob cada key de uma lista. Uma key pode nomear uma variação, por query string, cookie ou formato de imagem, então um purge de todas as variações de um objeto lista cada key. É o único tipo de purge que alcança a camada do [Tiered Cache](/pt-br/documentacao/plataforma/applications/cache/tiered-cache/#purge). |
| purge por URL | Um tipo de [Real-Time Purge](/pt-br/documentacao/plataforma/applications/cache/real-time-purge/#purge-por-url), `url` na API, que remove o objeto por trás de cada URL de uma lista. Ele não é recursivo, e a Azion converte cada URL na sua cache key sem as variações, então um objeto que varia por cookie, device group ou formato de imagem exige um purge por cache key ou por wildcard. Enviada sem scheme, uma URL remove a cópia em HTTP e a cópia em HTTPS. |
| purge por wildcard | Um tipo de [Real-Time Purge](/pt-br/documentacao/plataforma/applications/cache/real-time-purge/#purge-por-wildcard), `wildcard` na API, que remove todo objeto que corresponde a uma expressão com `*` no path ou na query string. Uma expressão pode ter mais de um `*`, mas uma requisição carrega uma expressão, e a API recusa uma segunda com `10065`. Ele age só sobre o cache da Azion: um purge por wildcard enviado à camada do Tiered Cache é recusado com `30001`. |
| Real-Time Purge | Um recurso da plataforma que remove objetos do Cache ou do Tiered Cache antes do fim do seu TTL, para que a próxima requisição busque a versão atual na origem. Um purge nomeia os seus objetos por URL, por cache key ou por uma expressão de wildcard, e a Azion o coloca em fila e o lista no histórico de purges quando ele termina. [Real-Time Purge](/pt-br/documentacao/plataforma/applications/cache/real-time-purge/) documenta os três tipos e a camada que cada um alcança. |
| recorte automático | O recorte centralizado que um redimensionamento `WidthxHeight` pode aplicar para que a imagem derivada preencha a caixa solicitada. O recorte é vertical ou horizontal, dependendo de como as dimensões originais se encaixam nas solicitadas, como [Parâmetros de URL do Image Processor](/pt-br/documentacao/plataforma/applications/image-processor/parametros-de-url/#redimensionamento) mostra. |
| regra | Uma entrada no Rules Engine para Applications que executa os seus behaviors, em uma fase, sobre as requisições às quais os seus critérios correspondem. Cada regra traz um nome e a sua fase, as regras rodam na ordem em que você as organiza, e uma Application nova não tem nenhuma. A API serve as regras da Request Phase em `/v4/workspace/applications/<application-id>/request_rules` e as da Response Phase em `/v4/workspace/applications/<application-id>/response_rules`, e [Rules Engine para Applications](/pt-br/documentacao/plataforma/applications/rules-engine/) lista os seus campos. |
| Rules Engine para Applications | Uma feature de Applications que contém as regras de uma Application e as executa em ordem como lógica se/então, com os critérios como o se e os behaviors como o então. Azion Console a mostra como a aba **Rules Engine** de cada Application, com as regras agrupadas por fase. [Rules Engine para Applications](/pt-br/documentacao/plataforma/applications/rules-engine/) documenta cada variável, operador e behavior. |
| Run Function | O behavior do [Rules Engine para Applications](/pt-br/documentacao/plataforma/applications/rules-engine/) que executa uma Function Instance sobre as requisições às quais a sua regra corresponde, `run_function` na API, com o ID da Function Instance em `attributes.value`. Ele roda na Request Phase e na Response Phase, que aceita só Functions escritas em Lua, e exige Functions ativo na Application, `modules.functions.enabled` na API. [Function Instances](/pt-br/documentacao/plataforma/applications/functions-instances/#behavior-run-function) documenta como ele referencia a Function Instance. |
| Set Cache Policy | O behavior do [Rules Engine para Applications](/pt-br/documentacao/plataforma/applications/rules-engine/#set-cache-policy) que aplica um cache setting a uma requisição que corresponde à regra, `set_cache_policy` na API, com o ID do cache setting em `attributes.value`. Ele roda na Request Phase e funciona com Application Accelerator ativo ou desativado. Um cache setting só age por meio de uma regra que carrega este behavior, e a API se recusa a excluir um setting em uso com `21014 Cannot Delete Cache Setting`. |
| Set Connector | O behavior do [Rules Engine para Applications](/pt-br/documentacao/plataforma/applications/rules-engine/) que encaminha as requisições às quais a sua regra corresponde a um [Connector](/pt-br/documentacao/plataforma/connectors/), `set_connector` na API, com o ID do Connector em `attributes.value`. Ele roda na Request Phase, e, quando mais de uma regra correspondente o carrega, só a última roda. |
| stale cache | Uma feature de Cache que pode responder com uma cópia expirada durante uma janela de stale, quando a revalidação com a origem falha ou ainda está em andamento. Cada cache setting a ativa em `modules.cache.stale_cache.enabled`, e a janela é o valor de `stale-while-revalidate` da origem sob _Honor cache policies_, ou 300 segundos sob _Override cache behavior_ ou quando a origem omite a diretiva. Durante a janela, a Azion busca uma versão atual em background, como [Expiração e atualização](/pt-br/documentacao/plataforma/applications/cache/expiracao-e-atualizacao/#stale-cache) descreve. |
| status de cache | O estado de uma resposta no Cache, no início do header `x-cache`: `HIT`, `MISS`, `EXPIRED`, `STALE`, `UPDATING`, `REVALIDATED` ou `BYPASS`. Uma resposta que a plataforma não coloca em cache informa `-`. [Cache keys](/pt-br/documentacao/plataforma/applications/cache/cache-keys/#status-de-cache) dá o significado de cada um. |
| Tiered Cache | Uma feature de Cache que acrescenta uma segunda camada de cache entre o cache da Azion e a origem, na região que a topology do cache setting seleciona. Em um miss na primeira camada, o data center consulta essa camada antes da origem, e cada cache setting ativa Tiered Cache no seu próprio campo `modules.cache.tiered_cache.enabled`, em todo plano. O setting precisa usar _Override cache behavior_, ou a API responde `21001`, e, com Application Accelerator ativo, um Max Age de pelo menos 3 segundos; [Tiered Cache](/pt-br/documentacao/plataforma/applications/cache/tiered-cache/) cobre as regiões em que ela roda e o tipo de purge que a limpa. |
| topology | A configuração do Tiered Cache que seleciona a região onde a segunda camada de cache mantém os objetos, como `nearest-region` ou `us-east-1`, em `modules.cache.tiered_cache.topology`. Azion Console chama o campo de **Tiered Cache Region**. A API recusa um valor que não aceita com `10039 Invalid Choice`, e [Tiered Cache](/pt-br/documentacao/plataforma/applications/cache/tiered-cache/#topology) documenta cada região. |
| TTL | Tempo de vida (time to live): o número de segundos que o cache da Azion ou o navegador mantém uma cópia de um objeto. Sob _Honor cache policies_, os headers `Cache-Control` e `Expires` que a origem envia o definem. Quando um [cache setting](/pt-br/documentacao/plataforma/applications/cache/cache-settings/) os substitui, o seu Max Age o define: `modules.cache.max_age` para o cache da Azion e `browser_cache.max_age` para o navegador. |
| variação de cache | Uma cópia adicional de um objeto armazenada sob a sua própria key porque o método da requisição, um argumento de query string, um cookie, um device group, um formato de imagem ou um intervalo de bytes de um arquivo grande difere. Enquanto Application Accelerator está desativado na Application, a API recusa uma variação com `21013`, e isso inclui a variação por query string em `ims` que [Configurações do Image Processor](/pt-br/documentacao/plataforma/applications/image-processor/configuracoes/#variacao-de-cache) descreve. Image Processor processa uma imagem com Application Accelerator ativo ou desativado; [Configurações do Application Accelerator](/pt-br/documentacao/plataforma/applications/application-accelerator/configuracoes/#cache-variation) documenta os quatro controles. |
| variável | Um valor da requisição ou da resposta, escrito `${name}`, que um critério testa ou que um argumento de behavior insere, como `${uri}`, `${host}` ou `${device_group}`. Cada variável está disponível na Request Phase, na Response Phase ou nas duas, como lista [Rules Engine para Applications](/pt-br/documentacao/plataforma/applications/rules-engine/#variaveis). Em uma Application, `${request_uri}` exige Application Accelerator, e uma regra que a usa com Application Accelerator desativado é recusada com `25047 Missing Required Modules`, enquanto a mesma regra com `${uri}` é aceita. |
| WASM Image Processor | A biblioteca WebAssembly que processa imagens dentro de uma [Function](/pt-br/documentacao/plataforma/functions/), por meio de `loadImage`, `resize`, `getImageResponse` e `clean`, para os formatos `webp`, `jpeg` e `png`. Ela é separada do recurso da plataforma Image Processor: Image Processor transforma uma requisição por meio da query string `ims`, e a biblioteca roda dentro do seu código. [Configurações do Image Processor](/pt-br/documentacao/plataforma/applications/image-processor/configuracoes/#biblioteca-wasm-image-processor) aponta para a sua referência. |
| WebSocket Proxy | Uma feature de Applications que mantém uma conexão WebSocket, uma única conexão TCP bidirecional, aberta entre os seus usuários e a sua origem. Uma Application com ela ativa trata uma requisição que carrega `Upgrade: websocket` e `Connection: upgrade` como uma conexão WebSocket e faz proxy dela para a origem, e uma conexão válida responde `101 Switching Protocols`. [WebSocket Proxy](/pt-br/documentacao/plataforma/applications/websocket/) documenta os seus requisitos e a sua disponibilidade. |
| `x-cache` | O header de debug da resposta que traz o status de cache de uma resposta, o endereço IP do servidor que respondeu e o protocolo, na forma `<STATUS> from <IP> with <protocol>`. Uma requisição precisa carregar `Pragma: azion-debug-cache` para que a Azion o acrescente à resposta. [Cache keys](/pt-br/documentacao/plataforma/applications/cache/cache-keys/#headers-de-debug) lista cada status que ele pode trazer. |
| `x-cache-key` | O header de debug da resposta que traz a cache key de uma resposta, como em `x-cache-key: httpsstatic.example.com/page/site.js`. Ele só volta em uma requisição enviada com `Pragma: azion-debug-cache`, e mostra `x-cache-key: -` em uma resposta que a plataforma não coloca em cache. [Cache keys](/pt-br/documentacao/plataforma/applications/cache/cache-keys/#formato-da-key) decompõe a key elemento por elemento. |
