Este guia conduz você pelo seu primeiro cache setting que varia a cache key. O exemplo é uma página de listagem cuja resposta muda com um argumento de query string.

- Ativar [Application Accelerator](/pt-br/documentacao/plataforma/applications/application-accelerator/) em uma aplicação.
- Criar um [cache setting](/pt-br/documentacao/plataforma/applications/cache/cache-settings/) que mantém a listagem por 30 segundos e varia pelo argumento `category`.
- Adicionar uma regra do Rules Engine que aplica o cache setting às requisições para `/products`.
- Requisitar a listagem duas vezes, com dois valores de `category`, e ler a cache key de cada resposta.

Três objetos produzem esse resultado, e cada um depende do anterior:

1. O switch **Application Accelerator** pertence à aplicação. Ele libera os campos que variam a cache key e remove o piso de 60 segundos do cache TTL.
2. Um **cache setting** é um objeto da aplicação que guarda o behavior de cache, o **Max Age** e a variação. Ele define o que o cache faz, não a quais requisições ele faz isso.
3. A regra do [Rules Engine](/pt-br/documentacao/plataforma/applications/rules-engine/) aplica o cache setting com o behavior [Set Cache Policy](/pt-br/documentacao/plataforma/applications/rules-engine/#set-cache-policy). Os critérios dela decidem quais requisições o cache setting cobre.

Criar um cache setting não altera nenhum tráfego. Um cache setting que nenhuma regra aplica nunca alcança uma requisição.

`azion.config.js` e Azion Lib carregam as mesmas configurações. Para o campo que cada interface define, consulte [Configurações do Application Accelerator](/pt-br/documentacao/plataforma/applications/application-accelerator/configuracoes/).

## Ative Application Accelerator

O switch vem desativado por padrão e pertence a uma aplicação por vez.

<Tabs client:visible sharedStore="interface">

<Fragment slot="panel.console">

### Console

Para ativar Application Accelerator pelo Azion Console:

<DocSteps>
  <DocStep title="Abra a página Applications">

  Acesse [Azion Console](https://console.azion.com/) > **Applications**.

  </DocStep>
  <DocStep title="Selecione a aplicação que serve a listagem" />
  <DocStep title="Vá para a aba Main Settings" />
  <DocStep title="Ative Application Accelerator">

  Na seção **Modules**, ative **Application Accelerator**.

  </DocStep>
  <DocStep title="Selecione Save" />
</DocSteps>

A aplicação agora aceita os campos de cache que o restante deste guia usa.

</Fragment>

<Fragment slot="panel.cli">

### CLI

Encontre o ID da sua aplicação no endereço dela no Azion Console, `console.azion.com/applications/edit/<application_id>/main-settings`, ou na saída de `azion list application`. Para ativar Application Accelerator com a Azion CLI, substitua `<application_id>` por esse ID:

<DocSteps>
  <DocStep title="Execute o comando de atualização">

  <Code client:visible lang="bash" code={`azion update application --application-id <application_id> --application-accelerator true`} />

  </DocStep>
  <DocStep title="Leia a saída">

  O comando confirma a aplicação que ele atualizou:

  ```text
  Updated Application with ID <application_id>
  ```

  </DocStep>
</DocSteps>

A aplicação agora aceita os campos de cache que o restante deste guia usa.

</Fragment>

<Fragment slot="panel.api">

### API

Encontre o ID da sua aplicação no endereço dela no Azion Console, `console.azion.com/applications/edit/<application_id>/main-settings`. Para ativar Application Accelerator com a Azion API, substitua `[TOKEN VALUE]` pelo seu personal token e `<application_id>` por esse ID:

<DocSteps>
  <DocStep title="Envie a requisição de atualização">

  <Code client:visible lang="bash" code={`curl --request PATCH \\
    --url https://api.azion.com/v4/workspace/applications/<application_id> \\
    --header 'Accept: application/json' \\
    --header 'Authorization: Token [TOKEN VALUE]' \\
    --header 'Content-Type: application/json' \\
    --data '{
    "modules": {
      "application_accelerator": {
        "enabled": true
      }
    }
  }'`} />

  </DocStep>
  <DocStep title="Leia a resposta">

  Um `202` carrega `"state": "pending"`, e a resposta repete cada chave de `modules`:

  ```json
  {
    "cache": { "enabled": true },
    "functions": { "enabled": true },
    "application_accelerator": { "enabled": true },
    "image_processor": { "enabled": false }
  }
  ```

  As outras chaves de `modules` mantêm os valores que a aplicação já tinha. Só `application_accelerator` mudou.

  </DocStep>
</DocSteps>

A aplicação agora aceita os campos de cache que o restante deste guia usa.

</Fragment>

</Tabs>

:::caution[Atenção]
Ativar Application Accelerator pode gerar custos relacionados ao uso. Para mais informações, consulte [Preços](/pt-br/documentacao/fundamentos/precos/#application-accelerator).
:::

## Crie um cache setting que varia por query string

O cache setting guarda o behavior de cache e a variação. O **Max Age** de `30` segundos abaixo é o ponto do exercício. Sem Application Accelerator, o menor cache TTL que uma aplicação aceita é 60 segundos.

<Tabs client:visible sharedStore="interface">

<Fragment slot="panel.console">

### Console

Para criar o cache setting pelo Azion Console:

<DocSteps>
  <DocStep title="Vá para a aba Cache Settings" />
  <DocStep title="Selecione + Cache" />
  <DocStep title="Nomeie o cache setting">

  Digite um valor em **Name**. Por exemplo: `product-listing`.

  </DocStep>
  <DocStep title="Defina o behavior de cache e o TTL">

  Em **Cache**, selecione _Override cache behavior_ e defina **Max Age** como `30`.

  </DocStep>
  <DocStep title="Varie a cache key pela query string">

  Em **Application Accelerator**, abra **Cache vary by Query String** e defina **Behavior** como _Allowlist_.

  </DocStep>
  <DocStep title="Nomeie o argumento que varia a key">

  Em **Fields**, digite `category`.

  </DocStep>
  <DocStep title="Ordene os argumentos da query string">

  Ative **Sort**.

  </DocStep>
  <DocStep title="Selecione Save" />
</DocSteps>

O cache setting aparece na aba **Cache Settings**. Ele mantém um objeto por 30 segundos e dá a cada valor de `category` o seu próprio objeto em cache.

</Fragment>

<Fragment slot="panel.cli">

### CLI

As flags do comando não alcançam o **Max Age**. Para criar o cache setting com a Azion CLI, envie o corpo a partir de um arquivo:

<DocSteps>
  <DocStep title="Escreva o cache setting em um arquivo">

  Salve o seguinte como `cache-setting.json`:

  <Code client:visible lang="json" code={`{
    "name": "product-listing",
    "browser_cache": { "behavior": "honor" },
    "modules": {
      "cache": {
        "behavior": "override",
        "max_age": 30
      },
      "application_accelerator": {
        "cache_vary_by_querystring": {
          "behavior": "allowlist",
          "fields": ["category"],
          "sort_enabled": true
        }
      }
    }
  }`} />

  </DocStep>
  <DocStep title="Crie o cache setting">

  <Code client:visible lang="bash" code={`azion create cache-setting --application-id <application_id> --file cache-setting.json`} />

  O comando imprime o id do novo cache setting:

  ```text
  Created Cache Settings configuration with ID 123462
  ```

  </DocStep>
  <DocStep title="Leia o cache setting de volta">

  <Code client:visible lang="bash" code={`azion describe cache-setting --application-id <application_id> --cache-setting-id 123462 --format json`} />

  Este trecho da saída carrega os campos que o arquivo definiu:

  ```json
  {
    "id": 123462,
    "name": "product-listing",
    "modules": {
      "cache": {
        "max_age": 30
      },
      "application_accelerator": {
        "cache_vary_by_querystring": {
          "behavior": "allowlist",
          "fields": ["category"],
          "sort_enabled": true
        }
      }
    }
  }
  ```

  </DocStep>
</DocSteps>

O cache setting mantém um objeto por 30 segundos e dá a cada valor de `category` o seu próprio objeto em cache. Guarde o id: a regra da próxima etapa seleciona o cache setting por ele. Para todas as flags que o comando aceita, consulte [`azion create cache-setting`](/pt-br/documentacao/devtools/cli/recursos/cache-setting/#criar).

</Fragment>

<Fragment slot="panel.api">

### API

Para criar o cache setting com a Azion API, substitua `[TOKEN VALUE]` pelo seu personal token e `<application_id>` pelo ID da sua aplicação:

<DocSteps>
  <DocStep title="Envie a requisição de criação">

  <Code client:visible lang="bash" code={`curl --request POST \\
    --url https://api.azion.com/v4/workspace/applications/<application_id>/cache_settings \\
    --header 'Accept: application/json' \\
    --header 'Authorization: Token [TOKEN VALUE]' \\
    --header 'Content-Type: application/json' \\
    --data '{
    "name": "product-listing",
    "browser_cache": { "behavior": "honor" },
    "modules": {
      "cache": {
        "behavior": "override",
        "max_age": 30
      },
      "application_accelerator": {
        "cache_vary_by_querystring": {
          "behavior": "allowlist",
          "fields": ["category"],
          "sort_enabled": true
        }
      }
    }
  }'`} />

  </DocStep>
  <DocStep title="Leia a resposta">

  Um `201` carrega `"state": "executed"` e o cache setting. Este trecho carrega o `id` e os campos que a requisição definiu:

  ```json
  {
    "state": "executed",
    "data": {
      "id": 123461,
      "name": "product-listing",
      "modules": {
        "cache": {
          "behavior": "override",
          "max_age": 30
        },
        "application_accelerator": {
          "cache_vary_by_querystring": {
            "behavior": "allowlist",
            "fields": ["category"],
            "sort_enabled": true
          }
        }
      }
    }
  }
  ```

  Um `max_age` abaixo de 60 é aceito apenas enquanto Application Accelerator está ativo.

  </DocStep>
</DocSteps>

O cache setting mantém um objeto por 30 segundos e dá a cada valor de `category` o seu próprio objeto em cache. Guarde o `id`: a regra da próxima etapa seleciona o cache setting por ele.

</Fragment>

</Tabs>

## Aplique o cache setting com uma regra

Um cache setting alcança uma requisição apenas quando uma regra o aplica.

<Tabs client:visible sharedStore="interface">

<Fragment slot="panel.console">

### Console

Para aplicar o cache setting ao path da listagem pelo Azion Console:

<DocSteps>
  <DocStep title="Vá para a aba Rules Engine" />
  <DocStep title="Selecione + Rule" />
  <DocStep title="Nomeie a regra">

  Digite um nome para a regra. Por exemplo: `Cache the product listing`.

  </DocStep>
  <DocStep title="Defina a fase">

  Selecione **Request Phase**.

  </DocStep>
  <DocStep title="Selecione a variável">

  Na seção **Criteria**, selecione a variável `${uri}`.

  </DocStep>
  <DocStep title="Selecione o operador de comparação">

  Selecione _starts with_ como operador de comparação.

  </DocStep>
  <DocStep title="Digite o argumento">

  Digite `/products` como argumento.

  </DocStep>
  <DocStep title="Selecione o behavior">

  Na seção **Behaviors**, selecione _Set Cache Policy_.

  </DocStep>
  <DocStep title="Selecione o cache setting que você criou" />
  <DocStep title="Selecione Save" />
</DocSteps>

A regra aplica o cache setting a toda requisição cuja URI começa com `/products`.

</Fragment>

<Fragment slot="panel.cli">

### CLI

Para adicionar a regra com a Azion CLI, envie o corpo a partir de um arquivo, para que o shell nunca leia `${uri}`.

<DocSteps>
  <DocStep title="Escreva a regra em um arquivo">

  Salve o seguinte como `rule.json`, com o id do seu cache setting em `attributes.value`:

  <Code client:visible lang="json" code={`{
    "name": "Cache the product listing",
    "active": true,
    "criteria": [
      [
        {
          "conditional": "if",
          "variable": "\${uri}",
          "operator": "starts_with",
          "argument": "/products"
        }
      ]
    ],
    "behaviors": [
      {
        "type": "set_cache_policy",
        "attributes": { "value": 123462 }
      }
    ]
  }`} />

  </DocStep>
  <DocStep title="Crie a regra">

  <Code client:visible lang="bash" code={`azion create rules-engine --application-id <application_id> --phase request --file rule.json`} />

  O comando imprime o id da nova regra:

  ```text
  Created Rules Engine with ID 234570
  ```

  </DocStep>
</DocSteps>

A regra aplica o cache setting a toda requisição cuja URI começa com `/products`.

</Fragment>

<Fragment slot="panel.api">

### API

Para adicionar a regra com a Azion API, substitua `[TOKEN VALUE]` pelo seu personal token e `<application_id>` pelo ID da sua aplicação. Envie o corpo a partir de um arquivo, para que o shell nunca leia `${uri}`.

<DocSteps>
  <DocStep title="Escreva a regra em um arquivo">

  Salve o seguinte como `rule.json`, com o `id` que a criação do cache setting retornou em `attributes.value`:

  <Code client:visible lang="json" code={`{
    "name": "Cache the product listing",
    "active": true,
    "criteria": [
      [
        {
          "conditional": "if",
          "variable": "\${uri}",
          "operator": "starts_with",
          "argument": "/products"
        }
      ]
    ],
    "behaviors": [
      {
        "type": "set_cache_policy",
        "attributes": { "value": 123461 }
      }
    ]
  }`} />

  </DocStep>
  <DocStep title="Envie a requisição de criação">

  <Code client:visible lang="bash" code={`curl --request POST \\
    --url https://api.azion.com/v4/workspace/applications/<application_id>/request_rules \\
    --header 'Accept: application/json' \\
    --header 'Authorization: Token [TOKEN VALUE]' \\
    --header 'Content-Type: application/json' \\
    --data @rule.json`} />

  </DocStep>
  <DocStep title="Leia a resposta">

  Um `202` carrega `"state": "pending"` e a regra. A regra carrega o seu `id`, o seu `name`, se ela está `active` e os behaviors que ela tem. Ela também carrega o `order` que ocupa entre as regras da aplicação.

  </DocStep>
</DocSteps>

A regra aplica o cache setting a toda requisição cuja URI começa com `/products`.

</Fragment>

</Tabs>

Uma nova regra leva alguns minutos para propagar. Aguarde antes de requisitar o path.

## Leia a cache key

A Azion retorna a cache key de um objeto quando a requisição carrega o header de debug da Azion `Pragma: azion-debug-cache`. Ler essa key para dois valores de `category` mostra a variação que o cache setting criou.

O workload que entrega a sua aplicação responde no workload domain dele, no formato `xxxxxxxxx.map.azionedge.net`. Para definir o domínio da sua aplicação, consulte [Adicione um domínio a um workload](/pt-br/documentacao/guias/plataforma/migracao/configurar-dominio/).

Substitua `<your-azion-domain>` por esse domínio e requisite a listagem com um valor:

<Code client:visible lang="bash" code={`curl -I -H "Pragma: azion-debug-cache" "https://<your-azion-domain>/products?category=shoes"`} />

A resposta carrega dois headers de debug da Azion. Este trecho é de uma aplicação servida em `www.example.com`, e HTTP/2 envia os nomes dos headers em minúsculas:

```text
x-cache: MISS from 203.0.113.10 with HTTP/2.0
x-cache-key: httpswww.example.com/products?category=shoes
```

`x-cache` carrega o status de cache, o endereço IP do servidor que respondeu e o protocolo da requisição. `x-cache-key` carrega a cache key, que concatena o scheme, o host, o path e os argumentos de query string que a allowlist nomeou.

Requisite o mesmo path com um valor diferente:

<Code client:visible lang="bash" code={`curl -I -H "Pragma: azion-debug-cache" "https://<your-azion-domain>/products?category=hats"`} />

O argumento mudou, então a key mudou junto:

```text
x-cache-key: httpswww.example.com/products?category=hats
```

Duas keys são dois objetos em cache, que é o que a allowlist pediu. Para o formato completo de uma cache key, consulte [Formato da cache key](/pt-br/documentacao/plataforma/applications/cache/cache-keys/#formato-da-key).

Sua aplicação agora mantém a listagem `/products` em cache por 30 segundos e guarda um objeto por valor de `category`.
