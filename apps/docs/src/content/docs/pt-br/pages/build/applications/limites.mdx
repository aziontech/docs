Uma [Application](/pt-br/documentacao/plataforma/applications/) executa [regras](/pt-br/documentacao/plataforma/applications/rules-engine/) de requisição e de resposta sobre as requisições dos [Workloads](/pt-br/documentacao/plataforma/workloads/) cujo deployment a define. Com [WebSocket Proxy](/pt-br/documentacao/plataforma/applications/websocket/) ativado na conta, ela também pode fazer proxy de conexões WebSocket para a origem.

Cada recurso da plataforma ativado na Application acrescenta limites próprios. [Cache](/pt-br/documentacao/plataforma/applications/cache/) limita os [cache settings](/pt-br/documentacao/plataforma/applications/cache/cache-settings/) e os objetos que armazena, e [Real-Time Purge](/pt-br/documentacao/plataforma/applications/cache/real-time-purge/) limita as requisições de purge. [Application Accelerator](/pt-br/documentacao/plataforma/applications/application-accelerator/) move o piso do time to live (TTL) de cache, e [Image Processor](/pt-br/documentacao/plataforma/applications/image-processor/) limita o tamanho, a largura e a altura de uma imagem. Esta página informa cada limite e a resposta que uma chamada recebe quando a API o recusa.

Um plano de serviço também inclui uma quantidade de uso antes que uma tarifa se aplique. Essa quantidade é um valor de cobrança: ultrapassá-la muda o valor cobrado da conta, e não o que a chamada retorna. A página [Preços da Azion](https://www.azion.com/pt-br/precos/) lista os planos e o uso que cada um inclui. Para as tarifas, consulte [Preços](/pt-br/documentacao/fundamentos/precos/#applications).

## Applications, regras e conexões

Estes limites se aplicam a toda Application, quaisquer que sejam os recursos da plataforma ativados nela. Eles cobrem as regras do seu Rules Engine, o log de [Debug Rules](/pt-br/documentacao/plataforma/applications/main-settings/#debug-rules) e as conexões que ela mantém abertas.

### Limites padrão

Sete limites se aplicam a toda Application. A Azion pode aumentar o tempo de conexão WebSocket mediante solicitação. Para solicitar um aumento, entre em contato com o time de [suporte técnico](/pt-br/documentacao/suporte/).

| Escopo | Limite |
| --- | --- |
| Regras em uma Application, fases de requisição e de resposta somadas | 200 regras |
| Grupos de critérios por regra | 1 a 5 grupos |
| Critérios por grupo | 1 a 10 critérios |
| Behaviors por regra | 1 a 10 behaviors |
| Argumento de behavior | 1.600 caracteres |
| Tamanho do log de Debug Rules | 1,5 kB |
| Tempo de conexão WebSocket | 15 minutos |

Outros três limites se aplicam a nomes: o nome de uma Application aceita de 1 a 100 caracteres, o nome de um device group aceita de 1 a 250 e a expressão `user_agent` de um device group aceita de 1 a 512.

As 200 regras são um único total que a fase de requisição e a fase de resposta compartilham. Por exemplo, uma Application pode ter 150 regras de requisição e 50 regras de resposta, mas não 200 de cada.

A Azion recicla as conexões keepalive dos seus servidores aproximadamente a cada 15 minutos. Esse ciclo limita por quanto tempo uma conexão entre um usuário e uma Application fica aberta. Uma conexão ativa que precisa de mais tempo pode ser encerrada. Quando uma conexão WebSocket se fecha dessa forma, o código do seu cliente precisa detectar a conexão fechada e abri-la de novo.

Para um arquivo grande, qualquer uma de duas opções permite que cada transferência termine antes que a conexão seja reciclada. Com `modules.cache.large_file_cache.enabled` definido como `true` em um cache setting, Cache armazena o arquivo em fragmentos de 1.024 kB. A outra opção, a compressão, reduz o arquivo.

Para armazenar um arquivo grande em fragmentos, consulte [Cache settings](/pt-br/documentacao/plataforma/applications/cache/cache-settings/#cache). Para comprimi-lo, consulte [Comprima as respostas de uma aplicação com gzip](/pt-br/documentacao/guias/performance-e-confiabilidade/otimizacao-de-entrega/gzip-compression/).

## Cache

Cache limita um cache setting e um objeto que ele armazena, e Real-Time Purge limita uma requisição de purge. Quando um valor ultrapassa um limite que a API verifica, a chamada retorna HTTP `400` com um código de erro e um título. [Tiered Cache](/pt-br/documentacao/plataforma/applications/cache/tiered-cache/) altera dois limites de um cache setting: o menor TTL que ele aceita e o comportamento de cache que ele permite.

Para um limite maior na conta, entre em contato com o time de [suporte técnico](/pt-br/documentacao/suporte/). Os limites de TTL são a exceção: a API os valida em todo cache setting, e a Azion não os aumenta mediante solicitação.

Para as tarifas de Cache, consulte [Preços](/pt-br/documentacao/fundamentos/precos/#cache). Para obter os dados que Tiered Cache transferiu, use o guia [Consulte dados de uso do Tiered Cache](/pt-br/documentacao/guias/plataforma/observabilidade/consultar-dados-de-uso-tiered-cache-com-graphql/).

### Cache settings

Cada limite desta tabela se aplica a um cache setting, qualquer que seja a interface que o escreve. A coluna Escopo nomeia o campo da API e, quando existe, o rótulo do Console. A coluna Além do limite traz o código e o título da resposta `400`. Os títulos dos erros mantêm nomes antigos: `Edge Cache` corresponde a Cache, e `Module` corresponde a um recurso da plataforma ativado na Application.

| Escopo | Limite | Além do limite |
| --- | --- | --- |
| TTL mínimo de cache, **Max Age** (`modules.cache.max_age`) | 60 segundos; 0 segundos com Application Accelerator ativo na Application | Erro `21021`, `Edge Cache Max Age Lower Than The Minimum Allowed By Application's Application Accelerator Module`, com `meta.min_value` definido como `60`. |
| TTL mínimo de cache com Tiered Cache ativo | 3 segundos, com Application Accelerator ativo; sem ele, o mínimo de 60 segundos continua valendo | Erro `21020`, `Edge Cache Max Age Lower Than The Minimum Allowed By The Tiered Cache Module`, com `meta.min_value` definido como `3`. |
| TTL máximo de cache | 31.536.000 segundos, um ano | Erro `10068`, `Max Value`, com o detalhe `Ensure this value is less than or equal to 31536000.` |
| Comportamento de cache com Tiered Cache ativo (`modules.cache.behavior`) | Apenas `override` | Erro `21001`, `It's Not Possible To Use This Edge Cache Behavior.` |
| TTL do browser cache (`browser_cache.max_age`) | 0 a 31.536.000 segundos | Erro `10068`, `Max Value`. |
| Nome do cache setting, **Name** (`name`) | 250 caracteres | Erro `10046`, `Max Length`, com o detalhe `Ensure this field has no more than 250 characters.` |

Outro limite se aplica a um cache setting: o seu array `cache_vary_by_method` aceita no máximo 2 valores, `post` e `options`.

Um cache setting com `modules.cache.stale_cache.enabled` definido como `true` pode servir uma cópia expirada durante uma janela limitada. Sob o comportamento `honor`, a janela é o valor da diretiva `stale-while-revalidate=<ttl>` da origem. Sob `override`, ou quando a origem omite a diretiva, a janela é de 300 segundos.

### Objetos em cache

Dois limites se aplicam a um objeto que Cache armazena: o seu tamanho e o tamanho de cada fragmento de um arquivo grande armazenado em partes. A API verifica o tamanho do fragmento em todo cache setting.

| Escopo | Limite | Além do limite |
| --- | --- | --- |
| Tamanho do fragmento de um arquivo grande (`modules.cache.large_file_cache.offset`) | 1.024 kB por fragmento, fixo | Erro `10068`, `Max Value`, com o detalhe `Ensure this value is less than or equal to 1024.` |

Um objeto único em cache aceita até 10 GB.

### Real-Time Purge

Cada limite desta tabela se aplica a uma requisição de purge, qualquer que seja a interface que a envia. A coluna Além do limite traz o que a API retorna além do limite.

| Escopo | Limite | Além do limite |
| --- | --- | --- |
| Objetos em uma requisição de purge por URL ou por cache key | 50 objetos | Erro `10065`, `List Field Max Length`, com o detalhe `Ensure this field has no more than 50 elements.` |
| Wildcards em uma requisição de purge | 1 wildcard | Erro `10065`, `List Field Max Length`, com o detalhe `Ensure this field has no more than 1 elements.` |

Uma URL ou uma cache key em um purge aceita até 4.096 caracteres.

Outros seis limites definem a taxa de requisições de purge, o tamanho de um wildcard e quanto histórico de purges a Azion mantém.

| Escopo | Limite |
| --- | --- |
| Requisições de purge por URL e por cache key por cliente | 200 requisições, de 50 objetos cada |
| Objetos purgados por URL e por cache key a cada 60 segundos | 10.000 objetos |
| Requisições de purge por wildcard por dia, em um intervalo de 24 horas | 2.000 requisições |
| Tamanho de um wildcard | 256 caracteres |
| Requisições mantidas no histórico de purges | 1.000.000 de requisições |
| Tempo de permanência de uma requisição no histórico de purges | 6 meses |

## Application Accelerator

Application Accelerator altera um limite de um cache setting: o menor tempo que Cache mantém um objeto. O Max Age de um cache setting, o seu campo `modules.cache.max_age`, define em segundos por quanto tempo Cache mantém um objeto. O campo aceita um inteiro de 0 a 31.536.000 e recusa qualquer valor fora dessa faixa. O estado de Application Accelerator e de Tiered Cache, ativos ou não, decide até onde um cache setting desce dentro da faixa.

Para as tarifas de Application Accelerator, consulte [Preços](/pt-br/documentacao/fundamentos/precos/#application-accelerator).

### Limites padrão

Cada linha nomeia um limite de TTL de cache e a condição que o coloca em vigor.

| Escopo | Limite | Aplica-se quando |
| --- | --- | --- |
| TTL mínimo de cache | 60 segundos | Application Accelerator está desativado na Application, com Tiered Cache ativo ou desativado. |
| TTL mínimo de cache | 0 segundos | Application Accelerator está ativo e Tiered Cache está desativado. |
| TTL mínimo de cache | 3 segundos | Application Accelerator está ativo e Tiered Cache está ativo. |
| TTL máximo de cache | 31.536.000 segundos, um ano | Todo cache setting, quaisquer que sejam os recursos da plataforma ativos. |

Um Max Age menor que o mínimo em vigor retorna HTTP `400`. O erro é `21021` enquanto Application Accelerator está desativado, e `21020` enquanto Application Accelerator e Tiered Cache estão ambos ativos. Um valor maior que o máximo retorna o erro `10068`. Para os títulos dos erros, consulte [Cache settings](#cache-settings).

Para saber como um Max Age de 0 segundos e o behavior _Bypass Cache_ tratam uma requisição, consulte [Bypass Cache e um TTL de 0](/pt-br/documentacao/plataforma/applications/application-accelerator/variacao-de-cache/#bypass-cache-e-um-ttl-de-0).

Uma requisição que Application Accelerator varia continua limitada pelos recursos da plataforma que armazenam o objeto e executam código sobre ele. Cache limita o próprio objeto: o tamanho de um objeto em cache e o tamanho de cada fragmento de um arquivo grande. Para esses valores, consulte [Objetos em cache](#objetos-em-cache). Uma [Function](/pt-br/documentacao/plataforma/functions/) que a Application executa tem os seus próprios limites de código e de cada invocação. Para esses valores, consulte [Limites de Functions](/pt-br/documentacao/plataforma/functions/limites/).

## Image Processor

Image Processor limita uma única imagem com três limites padrão: o seu tamanho, a sua largura e a sua altura.

Para as tarifas da métrica Images, consulte [Preços](/pt-br/documentacao/fundamentos/precos/#image-processor). Para obter o número de imagens que a conta processou, use o guia [Consulte dados de uso do Image Processor](/pt-br/documentacao/guias/plataforma/observabilidade/consultar-dados-de-uso-image-processor-com-graphql/).

### Limites padrão

Image Processor aplica três limites padrão a uma imagem: um tamanho máximo de 150 MB, uma largura máxima de 3.840 pixels e uma altura máxima de 2.160 pixels. Para aumentar um deles para a conta, entre em contato com o time de [suporte técnico](/pt-br/documentacao/suporte/).

Cada parâmetro `ims` também aceita uma faixa de valores própria. Para a faixa de cada parâmetro, consulte [Parâmetros de URL](/pt-br/documentacao/plataforma/applications/image-processor/parametros-de-url/).
