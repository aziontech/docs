Este guia conduz você pela requisição da sua primeira imagem derivada a partir de uma Application. Ao final, você terá:

- Image Processor ativado em uma Application.
- Um cache setting que armazena cada transformação como um objeto próprio.
- Uma regra do Rules Engine que envia requisições de imagem ao Image Processor.
- Uma imagem redimensionada retornada a partir de uma URL que você escreveu.

Três entidades e uma URL produzem esse resultado, e cada uma está ligada à anterior. A **Application** tem Image Processor ativado. O **cache setting** pertence à Application e faz o cache armazenar duas transformações diferentes como dois objetos diferentes. A **regra** pertence à Application, corresponde a requisições de imagem e aplica tanto o cache setting quanto o behavior _Optimize Images_. A URL da imagem carrega então a transformação na própria query string `ims`. Uma requisição à qual nenhuma regra corresponde é entregue sem processamento, então é a regra que dá sentido à query string.

## Ative Image Processor e Application Accelerator

Image Processor é um recurso da plataforma que vem desativado em uma Application nova até você ativá-lo. Esta etapa ativa dois recursos da plataforma.

**Application Accelerator** é o segundo por dois motivos. O campo que varia o cache por uma query string pertence a ele, e o cache setting usa esse campo. A regra deste guia também lê `${request_uri}`, e a Azion recusa uma regra que o lê enquanto Application Accelerator está desativado. Processar uma imagem não exige Application Accelerator, mas armazenar cada transformação separadamente em cache exige.

<Tabs client:visible sharedStore="interface">

<Fragment slot="panel.console">

### Console

Para ativar os dois recursos da plataforma pelo Azion Console:

<DocSteps>
  <DocStep title="Abra a Application">

  Acesse [Azion Console](https://console.azion.com/) > **Applications** > **sua Application**.

  </DocStep>
  <DocStep title="Vá para a aba Main Settings" />
  <DocStep title="Ative Image Processor">

  Na seção **Modules**, ative **Image Processor**, descrito como *Enable dynamic image editing options*.

  </DocStep>
  <DocStep title="Ative Application Accelerator">

  O switch fica na mesma seção.

  </DocStep>
  <DocStep title="Selecione Save" />
</DocSteps>

A Application agora tem os dois recursos da plataforma ativados, e o behavior _Optimize Images_ fica disponível para as suas regras.

</Fragment>

<Fragment slot="panel.cli">

### CLI

Um comando ativa os dois recursos da plataforma. Substitua `<application_id>` pelo [ID da sua Application](/pt-br/documentacao/guias/desenvolvimento-de-aplicacoes/primeiros-passos/definir-configuracoes-principais/):

<DocSteps>
  <DocStep title="Execute o comando de atualização">

  <Code client:visible lang="bash" code={`azion update application --application-id <application_id> --image-processor true --application-accelerator true`} />

  </DocStep>
  <DocStep title="Leia a saída">

  O comando confirma a Application que alterou:

  ```text
  Updated Application with ID <application_id>
  ```

  </DocStep>
</DocSteps>

A Application agora tem os dois recursos da plataforma ativados, e o behavior _Optimize Images_ fica disponível para as suas regras.

</Fragment>

<Fragment slot="panel.api">

### API

Uma requisição ativa os dois recursos da plataforma. Substitua `[TOKEN VALUE]` pelo seu personal token e `<application_id>` pelo [ID da sua Application](/pt-br/documentacao/guias/desenvolvimento-de-aplicacoes/primeiros-passos/definir-configuracoes-principais/):

<DocSteps>
  <DocStep title="Envie a requisição de atualização">

  <Code client:visible lang="bash" code={`curl --request PATCH \\
    --url https://api.azion.com/v4/workspace/applications/<application_id> \\
    --header 'Accept: application/json' \\
    --header 'Authorization: Token [TOKEN VALUE]' \\
    --header 'Content-Type: application/json' \\
    --data '{
    "modules": {
      "application_accelerator": { "enabled": true },
      "image_processor": { "enabled": true }
    }
}'`} />

  </DocStep>
  <DocStep title="Leia a resposta">

  Um `202` carrega `"state": "pending"`, porque a alteração ainda está propagando. O objeto `modules` da resposta repete todos os switches da Application, inclusive os que você não alterou:

  ```json
  {
    "cache": { "enabled": true },
    "functions": { "enabled": false },
    "application_accelerator": { "enabled": true },
    "image_processor": { "enabled": true }
  }
  ```

  </DocStep>
</DocSteps>

A Application agora tem os dois recursos da plataforma ativados, e o behavior _Optimize Images_ fica disponível para as suas regras.

</Fragment>

## Crie um cache setting que varia pela query string ims

Sem esta etapa, o cache não consegue diferenciar uma transformação de outra. Ele pode responder a uma requisição de imagem de 400 pixels com uma de 200 pixels.

<Tabs client:visible sharedStore="interface">

<Fragment slot="panel.console">

### Console

Para criar o cache setting pelo Azion Console:

<DocSteps>
  <DocStep title="Abra a Application">

  Acesse [Azion Console](https://console.azion.com/) > **Applications** > **sua Application**.

  </DocStep>
  <DocStep title="Vá para a aba Cache Settings" />
  <DocStep title="Selecione + Cache" />
  <DocStep title="Nomeie o cache setting">

  Em **Name**, digite `images`.

  </DocStep>
  <DocStep title="Defina Cache Behavior como Override cache behavior">

  Na seção **Cache**, defina **Cache Behavior** como _Override cache behavior_.

  </DocStep>
  <DocStep title="Defina a idade máxima">

  Na seção **Cache**, em **Max Age**, digite `31536000`.

  </DocStep>
  <DocStep title="Expanda Cache vary by Query String">

  O painel fica na seção **Application Accelerator**.

  </DocStep>
  <DocStep title="Defina Behavior como Allowlist" />
  <DocStep title="Adicione o campo ims">

  Em **Fields**, digite `ims`.

  </DocStep>
  <DocStep title="Ative Sort" />
  <DocStep title="Selecione Save" />
</DocSteps>

A Application agora tem um cache setting que armazena um objeto por valor distinto de `ims`.

</Fragment>

<Fragment slot="panel.cli">

### CLI

O comando da Azion CLI envia o body inteiro a partir de um arquivo, porque nenhuma flag de criação define o `max_age` do cache nem o `sort_enabled`.

<DocSteps>
  <DocStep title="Escreva o cache setting em um arquivo">

  Salve o conteúdo a seguir como `cache-setting.json`:

  <Code client:visible lang="json" code={`{
    "name": "images",
    "browser_cache": { "behavior": "honor" },
    "modules": {
      "cache": { "behavior": "override", "max_age": 31536000 },
      "application_accelerator": {
        "cache_vary_by_querystring": {
          "behavior": "allowlist",
          "fields": ["ims"],
          "sort_enabled": true
        }
      }
    }
}`} />

  `31536000` segundos é o teto de `max_age`, o que serve bem para imagens, porque elas mudam raramente.

  </DocStep>
  <DocStep title="Crie o cache setting">

  Substitua `<application_id>` pelo [ID da sua Application](/pt-br/documentacao/guias/desenvolvimento-de-aplicacoes/primeiros-passos/definir-configuracoes-principais/):

  <Code client:visible lang="bash" code={`azion create cache-setting --application-id <application_id> --file cache-setting.json`} />

  O comando imprime o id do novo cache setting:

  ```text
  Created Cache Settings configuration with ID 123464
  ```

  </DocStep>
  <DocStep title="Leia o cache setting de volta">

  <Code client:visible lang="bash" code={`azion describe cache-setting --application-id <application_id> --cache-setting-id 123464 --format json`} />

  A saída informa a allowlist de `ims` e a idade máxima que o arquivo definiu.

  </DocStep>
</DocSteps>

A Application agora tem um cache setting que armazena um objeto por valor distinto de `ims`. Registre o id que o comando imprimiu, porque a regra o aplica. Para todas as flags que o comando aceita, consulte [Azion CLI cache-setting](/pt-br/documentacao/devtools/cli/recursos/cache-setting/).

</Fragment>

<Fragment slot="panel.api">

### API

Uma requisição carrega o comportamento de cache e a allowlist de query string juntos.

<DocSteps>
  <DocStep title="Envie a requisição de criação">

  Substitua `<application_id>` pelo [ID da sua Application](/pt-br/documentacao/guias/desenvolvimento-de-aplicacoes/primeiros-passos/definir-configuracoes-principais/):

  <Code client:visible lang="bash" code={`curl --request POST \\
    --url https://api.azion.com/v4/workspace/applications/<application_id>/cache_settings \\
    --header 'Accept: application/json' \\
    --header 'Authorization: Token [TOKEN VALUE]' \\
    --header 'Content-Type: application/json' \\
    --data '{
    "name": "images",
    "browser_cache": { "behavior": "honor" },
    "modules": {
      "cache": { "behavior": "override", "max_age": 31536000 },
      "application_accelerator": {
        "cache_vary_by_querystring": {
          "behavior": "allowlist",
          "fields": ["ims"],
          "sort_enabled": true
        }
      }
    }
}'`} />

  `31536000` segundos é o teto de `max_age`, o que serve bem para imagens, porque elas mudam raramente.

  </DocStep>
  <DocStep title="Leia a resposta">

  Um `201` carrega `"state": "executed"` e o cache setting que ele criou. A resposta devolve `modules.cache.max_age` como `31536000` e repete `cache_vary_by_querystring` exatamente como você enviou.

  Registre `data.id`, como `123463`, porque a regra o aplica.

  </DocStep>
</DocSteps>

A Application agora tem um cache setting que armazena um objeto por valor distinto de `ims`.

</Fragment>

</Tabs>

Para o restante dos campos que um cache setting carrega, incluindo por quanto tempo um objeto permanece em cache, consulte [Cache settings](/pt-br/documentacao/plataforma/applications/cache/cache-settings/).

## Crie uma regra que envia as requisições de imagem ao Image Processor

A regra é o que converte a query string em uma transformação. Ela corresponde a requisições de paths de imagem, aplica o cache setting que você criou e carrega o behavior _Optimize Images_.

<Tabs client:visible sharedStore="interface">

<Fragment slot="panel.console">

### Console

Para criar a regra pelo Azion Console:

<DocSteps>
  <DocStep title="Abra a Application">

  Acesse [Azion Console](https://console.azion.com/) > **Applications** > **sua Application**.

  </DocStep>
  <DocStep title="Vá para a aba Rules Engine" />
  <DocStep title="Selecione + Rule" />
  <DocStep title="Nomeie a regra">

  Em **Name**, digite `Optimize images`.

  </DocStep>
  <DocStep title="Selecione Request Phase" />
  <DocStep title="Selecione a variável">

  Nos critérios, selecione `${request_uri}`.

  </DocStep>
  <DocStep title="Selecione o operador matches" />
  <DocStep title="Digite o argumento">

  Digite `\.(jpg|jpeg|gif|bmp|png|ico|webp|avif)`.

  </DocStep>
  <DocStep title="Adicione o behavior Set Cache Policy">

  Nos behaviors, selecione **Set Cache Policy** e escolha o cache setting `images`.

  </DocStep>
  <DocStep title="Selecione Add Behavior" />
  <DocStep title="Selecione Optimize Images" />
  <DocStep title="Selecione Save" />
</DocSteps>

Toda requisição para um path com uma dessas extensões agora recebe o cache setting `images` e o behavior _Optimize Images_. Image Processor transforma a imagem quando a URL dela carrega `ims`.

</Fragment>

<Fragment slot="panel.cli">

### CLI

Os critérios carregam `${request_uri}`, que um shell expande, e o argumento carrega barras invertidas, então a regra vai em um arquivo.

<DocSteps>
  <DocStep title="Escreva a regra em um arquivo">

  Salve o conteúdo a seguir como `rule.json`, com o id do seu cache setting no behavior `set_cache_policy`:

  <Code client:visible lang="json" code={`{
    "name": "Optimize images",
    "description": "Apply the cache setting and optimize images",
    "active": true,
    "criteria": [
      [
        {
          "conditional": "if",
          "variable": "\${request_uri}",
          "operator": "matches",
          "argument": "\\\\.(jpg|jpeg|gif|bmp|png|ico|webp|avif)"
        }
      ]
    ],
    "behaviors": [
      { "type": "set_cache_policy", "attributes": { "value": 123464 } },
      { "type": "optimize_images" }
    ]
}`} />

  Uma regra carrega os dois behaviors, e `optimize_images` não recebe atributos.

  </DocStep>
  <DocStep title="Crie a regra">

  <Code client:visible lang="bash" code={`azion create rules-engine --application-id <application_id> --phase request --file rule.json`} />

  O comando imprime o id da nova regra:

  ```text
  Created Rules Engine with ID 234571
  ```

  </DocStep>
</DocSteps>

Toda requisição para um path com uma dessas extensões agora recebe o cache setting `images` e o behavior _Optimize Images_. Image Processor transforma a imagem quando a URL dela carrega `ims`.

</Fragment>

<Fragment slot="panel.api">

### API

Os critérios carregam `${request_uri}`, que um shell expande, e o argumento carrega barras invertidas, então o body é enviado a partir de um arquivo.

<DocSteps>
  <DocStep title="Escreva a regra em um arquivo">

  Salve o conteúdo a seguir como `rule.json`, com o id do seu cache setting no behavior `set_cache_policy`:

  <Code client:visible lang="json" code={`{
    "name": "Optimize images",
    "description": "Apply the cache setting and optimize images",
    "active": true,
    "criteria": [
      [
        {
          "conditional": "if",
          "variable": "\${request_uri}",
          "operator": "matches",
          "argument": "\\\\.(jpg|jpeg|gif|bmp|png|ico|webp|avif)"
        }
      ]
    ],
    "behaviors": [
      { "type": "set_cache_policy", "attributes": { "value": 123463 } },
      { "type": "optimize_images" }
    ]
}`} />

  Uma regra carrega os dois behaviors, e `optimize_images` não recebe atributos.

  </DocStep>
  <DocStep title="Envie a requisição de criação">

  <Code client:visible lang="bash" code={`curl --request POST \\
    --url https://api.azion.com/v4/workspace/applications/<application_id>/request_rules \\
    --header 'Accept: application/json' \\
    --header 'Authorization: Token [TOKEN VALUE]' \\
    --header 'Content-Type: application/json' \\
    --data @rule.json`} />

  </DocStep>
  <DocStep title="Leia a resposta">

  Um `202` carrega `"state": "pending"`, porque a regra ainda está propagando. Ela repete os critérios e os dois behaviors, e carrega o `order` que a regra ocupa entre as regras da Application.

  </DocStep>
</DocSteps>

Toda requisição para um path com uma dessas extensões agora recebe o cache setting `images` e o behavior _Optimize Images_. Image Processor transforma a imagem quando a URL dela carrega `ims`.

</Fragment>

</Tabs>

:::note[nota]
Esta parte é opcional. Converter uma imagem para WEBP ou AVIF exige que a requisição carregue `Accept: image/webp` ou `Accept: image/avif`. O behavior **Add Request Header** o adiciona à mesma regra, então a conversão deixa de depender do que o navegador enviou. Na Azion CLI e na API, é um behavior do tipo `add_request_header`, cujos `attributes` carregam `"value": "Accept: image/webp"`. Para os campos do behavior, consulte [Configurações do Image Processor](/pt-br/documentacao/plataforma/applications/image-processor/configuracoes/).
:::

## Requisite uma imagem derivada

Peça uma largura e veja a resposta mudar.

Requisite uma das suas imagens com uma query string `ims`, substituindo o host e o path pelos seus próprios:

<Code client:visible lang="bash" code={`curl -s -o /dev/null -w "%{http_code} %{content_type} %{size_download} bytes\\n" \\
    -H "Accept: image/webp,image/*" \\
    "https://www.example.com/images/photo.jpg?ims=400x"`} />

A resposta informa o status, o tipo e o tamanho dela:

```text
200 image/webp 8312 bytes
```

Requisite a mesma imagem sem query string e compare o tamanho. A resposta redimensionada é menor quando a imagem de origem tem mais de 400 pixels de largura. As duas respostas podem carregar um formato diferente do arquivo na sua origem, porque Image Processor converte as imagens para os navegadores que aceitam outro formato, como WEBP.

Para confirmar que Image Processor, e não a origem, processou a resposta, leia os headers:

<Code client:visible lang="bash" code={`curl -sI -H "Accept: image/webp" "https://www.example.com/images/photo.jpg?ims=400x"`} />

Uma resposta processada carrega `x-ims: Enabled` e o tamanho da imagem de origem antes da transformação:

```text
HTTP/2 200
content-type: image/webp
x-ims: Enabled
x-original-image-size: 484156
```

Agora você tem uma Application que transforma imagens sob demanda, e uma URL que descreve a transformação.

:::tip[dica]
Mantenha `ims=` como o último parâmetro na URL. Uma requisição que carrega outro parâmetro de query string depois dele pode retornar um erro `504`.
:::
