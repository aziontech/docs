[Real-Time Events](/pt-br/documentacao/plataforma/real-time-events/) limita por quanto tempo mantém um registro e quanto uma consulta pode ler e retornar. Esta página indica o que Real-Time Events cobre, cada limite e a resposta que uma consulta recebe além dele.

Para o custo de Real-Time Events, consulte [Preços](/pt-br/documentacao/fundamentos/precos/#real-time-events).

---

## Escopo

- **Ativação**: Real-Time Events não precisa de ativação, porque os recursos da plataforma que servem o seu tráfego escrevem os registros dele. O [Terraform Provider](/pt-br/documentacao/devtools/terraform/) não tem recurso para ele.
- **Interfaces**: o Azion Console e a API GraphQL consultam os registros. A Azion CLI mostra os logs recentes de eventos HTTP e de console das Functions com [Azion CLI logs](/pt-br/documentacao/devtools/cli/logs/).
- **Atraso da busca**: um registro fica disponível para busca alguns segundos depois da requisição dele, então uma busca feita na mesma hora pode não encontrá-lo. Busque de novo antes de concluir que a requisição não foi servida.
- **Retenção**: um período que vai além da retenção retorna os registros dentro dela e nenhum mais antigo, sem erro. A remoção é permanente.
- **Buscas amplas**: uma busca sem filtro sobre um período longo pode alcançar o limite de linhas que uma consulta lê. Ela então falha em vez de retornar parte dos registros. Para ver como um filtro muda a leitura, consulte [Como uma consulta é limitada](/pt-br/documentacao/plataforma/real-time-events/como-funciona/#como-uma-consulta-e-limitada).
- **Taxa de requisições**: a API GraphQL limita as requisições de cada endereço IP e responde `429` com `You have reached the request rate limit!` além desse limite.
- **Exportação e métricas**: o Azion Console baixa o resultado de uma busca como arquivo CSV, como mostra [Exportar resultados de consulta para CSV](/pt-br/documentacao/guias/plataforma/observabilidade/exportar-events-csv/). Real-Time Events não envia os registros para fora por conta própria e os mantém só durante a retenção. O [Data Stream](/pt-br/documentacao/plataforma/data-stream/) envia os registros de Activity History, Applications, Functions e WAF para um endpoint seu. Para métricas agregadas do mesmo tráfego, use [Real-Time Metrics](/pt-br/documentacao/plataforma/real-time-metrics/).

---

## Retenção de eventos

Real-Time Events mantém um registro de evento por 168 horas, ou seja, 7 dias. A retenção é, portanto, o limite externo do período que uma consulta pode pedir, qualquer que seja a fonte de dados que ela lê.

[Activity History](/pt-br/documentacao/fundamentos/activity-history/) é a exceção. A fonte de dados dela mantém os registros por 2 anos, e a API GraphQL do Real-Time Events consulta esse período completo.

## Limites de consulta

Uma consulta carrega três limites próprios: as linhas que ela retorna, os campos que ela seleciona e o tamanho do payload. O banco de dados de logs acrescenta um quarto, sobre as linhas que uma consulta lê antes de retornar qualquer coisa.

### Limites padrão

Cada linha indica o que é limitado, o limite e o que uma consulta além dele recebe. Para o corpo de cada resposta de erro, consulte [Respostas de erro da API GraphQL](/pt-br/documentacao/devtools/graphql/mensagens-erro/).

:::tip[dica]
A Azion pode aumentar esses limites padrão mediante solicitação, de acordo com o seu plano. Para solicitar um aumento, entre em contato com a equipe de [suporte técnico](/pt-br/documentacao/suporte/).
:::

| Escopo | Limite | Além do limite |
| --- | --- | --- |
| Linhas retornadas por consulta | 10.000 linhas | `400` e `The value for the query limit is invalid (must be between 0 to 10000 rows).` |
| Campos selecionados por consulta | 37 campos, e 36 em `workloadEvents` | `400` e `You have exceeded the limit amount allowed for selected fields (37 fields).` Em `workloadEvents`, o 37º campo retorna `400` e `The query has reached a system limit. Please adjust your query and try again.` |
| Linhas lidas dentro do banco de dados de logs | 10 bilhões de linhas | `500` e uma mensagem que informa o limite, `max rows: 10.00 billion` |

Os limites de linhas e de campos pertencem à própria API GraphQL. O argumento `limit` de uma consulta define o número de linhas, até 10.000. Para os dois limites, consulte [Limites da API GraphQL](/pt-br/documentacao/devtools/graphql/limites/).

Um payload da API GraphQL carrega no máximo 5 GB. Um registro fica disponível para busca alguns segundos depois do evento que o produziu, e o atraso pode passar de 30 segundos.

O limite de 10 bilhões de linhas é aplicado pelo banco de dados de logs, e não pela API GraphQL. Ele conta as linhas que uma consulta lê, não as linhas que a consulta retorna. Uma consulta sobre um período longo e sem nenhum outro filtro pode alcançá-lo, como uma busca por todos os 7 dias de retenção. Para ficar dentro do limite, estreite o período ou filtre por host, endereço IP ou código de status HTTP.
