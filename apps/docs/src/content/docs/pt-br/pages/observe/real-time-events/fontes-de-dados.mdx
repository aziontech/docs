Uma fonte de dados é o produto ou serviço da Azion que gerou os eventos que você consulta. Em uma consulta, ela é o índice de onde os registros são lidos, portanto selecionar uma fonte de dados é obrigatório. [Real-Time Events](/pt-br/documentacao/plataforma/real-time-events/) expõe oito delas, e cada uma carrega seu próprio conjunto de variáveis pré-organizadas, porque cada produto escreve um registro diferente.

Os mesmos registros são alcançados de duas maneiras: pelo Azion Console e pela API GraphQL do Real-Time Events. Esta página carrega os nomes de variáveis que a **classic view** do Azion Console exibe, que é a visualização em que Real-Time Events abre. A API GraphQL guarda cada fonte de dados como um dataset e nomeia seus campos em camelCase, portanto a variável `Remote Address` abaixo é o campo `remoteAddress` lá. Um payload do [Data Stream](/pt-br/documentacao/plataforma/data-stream/) escreve esse mesmo campo em snake_case novamente. O campo **Filter by** usa uma terceira forma do mesmo nome: a variável em minúsculas, com underscores, portanto uma busca por `Geoloc Country Name` se escreve `geoloc_country_name='Germany'`. Para a sintaxe e um conjunto completo, consulte [Filtrar eventos](/pt-br/documentacao/guias/plataforma/observabilidade/adicionar-filtros-events/). Cada seção abaixo nomeia seu dataset e aponta para a lista de campos. Para enviar uma primeira consulta, consulte [Primeiros passos da API GraphQL](/pt-br/documentacao/devtools/graphql/primeiros-passos/).

:::note[nota]
Azion Console também oferece uma visualização mais recente de Real-Time Events, em Preview, acessada por **Switch to new view**. Essa visualização chama o seletor de **Dataset** e exibe os nomes de campo em camelCase que a API GraphQL usa, em vez dos nomes de variáveis desta página.
:::

## HTTP Requests

HTTP Requests carrega um registro por requisição que chega a uma [aplicação](/pt-br/documentacao/plataforma/applications/) ou a um [firewall](/pt-br/documentacao/plataforma/firewall/). O registro guarda a linha da requisição, o status da resposta, o status do cache e os campos de Web Application Firewall (WAF) daquela requisição.

Esses registros exigem uma aplicação, um firewall e WAF.

Na API GraphQL, esses mesmos registros são o dataset `workloadEvents`, antes chamado de `httpEvents`. Para os campos dele, consulte [workloadEvents](/pt-br/documentacao/devtools/graphql/campos-gql-real-time-events/#workloadevents-anteriormente-httpevents-applications-waf).

| Variável | Descrição |
| -------- | --------- |
| Bytes Sent | Número de bytes enviados a um cliente. Este campo é o resultado de uma soma. Exemplo: `191` |
| Debug Log | Valor de qualquer variável da requisição, definido por um comportamento do Rules Engine. Exemplo: `{"idHash":"pQ04xXYD4JSYyOERu3mcwA==","type":"product_screen_element_element_action","message":{"event":"product_screen_element_element_action","action":"value","product":"value","screen":"value","element":"value"},"date":"2023-10-27T19:44:57.251Z"}` |
| Geoloc ASN | Alocação de Autonomous System Number (ASN) consultada na tabela MaxMind. Exemplo: `AS52580 Azion Technologies Ltda.` |
| Geoloc Country Name | País do cliente remoto detectado pela geolocalização do endereço IP. Exemplo: `United States`, `Germany` |
| Geoloc Region Name | Região do cliente remoto detectada pela geolocalização do endereço IP. Exemplo: `California`, `Bavaria` |
| Host | Informação de host enviada na linha da requisição. Armazena: o nome do host da linha da requisição, ou o nome do host do campo de cabeçalho `Host` da requisição, ou o nome do servidor que corresponde a uma requisição. Exemplo: `xxxxxxxxxx.map.azionedge.net` |
| HTTP Referer | Endereço da página de onde o usuário fez a requisição. Exemplo: `https://example.com` |
| HTTP User Agent | Aplicação, sistema operacional, fornecedor e versão do usuário final. Valor do cabeçalho `User-Agent`. Exemplo: `Mozilla/5.0 (Windows NT 10.0; Win64; x64)` |
| Proxy Status | Código de status de erro HTTP ou da origem quando nenhuma resposta é obtida da origem. Exemplo: `520`. **Em caso de cache, a resposta é `-`.** |
| Request Length | Tamanho da requisição em bytes, incluindo a linha da requisição, os cabeçalhos e o corpo. Este campo é o resultado de uma soma. Exemplo: `167` |
| Request Method | Método HTTP da requisição. Exemplo: `GET` ou `POST` |
| Request Time | Tempo de processamento da requisição, em segundos, desde que os primeiros bytes foram lidos do cliente. Este campo é o resultado de uma soma. Exemplo: `0.234` |
| Request Uri | URI da requisição feita pelo usuário final, sem as informações de host e de protocolo e com argumentos. Exemplo: `/v1?v=bo%20dim` |
| Remote Address | Endereço IP da origem que gerou a requisição. Exemplo: `127.0.0.1` |
| Remote Port | Porta da origem que gerou a requisição. Exemplo: `8080` |
| Scheme | Esquema da requisição. Exemplo: `HTTP` ou `HTTPS` |
| Server Protocol | Versão do protocolo da requisição. Exemplo: `HTTP/1.1`, `HTTP/2.0`, `HTTP/3.0` |
| Sent HTTP Content Type | Cabeçalho `Content-Type` enviado na resposta da origem. Exemplo: `text/html; charset=UTF-8` |
| SSL Cipher | String da cipher usada para estabelecer a conexão TLS. Exemplo: `TLS_AES_256_GCM_SHA384` |
| SSL Protocol | Protocolo de uma conexão TLS estabelecida. Exemplo: `TLS v1.2` |
| Stack Trace | Fornece os nomes das Rules Engine da sua aplicação ou do seu firewall que são executadas pela requisição. Exemplo: `{\\\"edge_firewall\\\":[\\\"Global - Set WAF\\\"]}` |
| Status | Código de status HTTP da requisição. Exemplo: `200` |
| Upstream Addr | Endereço IP e porta do cliente. Também pode armazenar múltiplos servidores ou grupos de servidores. Exemplo: `192.168.1.1:80`. Quando a resposta é `127.0.0.1:1666`, o upstream é [Azion Runtime](/pt-br/documentacao/devtools/runtime/). |
| Upstream Bytes Received | Número de bytes recebidos da origem quando o conteúdo não está em cache. Exemplo: `8304` |
| Upstream Bytes Sent | Número de bytes enviados à origem. Exemplo: `2733` |
| Upstream Cache Status | Status do cache local. Pode ser: `MISS`, `BYPASS`, `EXPIRED`, `STALE`, `UPDATING`, `REVALIDATED`, `HIT` ou `-` |
| Upstream Response Time | Tempo para receber uma resposta padrão da origem, em segundos, incluindo cabeçalhos e corpo. Exemplo: `0.876`. **Em caso de cache, a resposta é `-`** |
| Upstream Status | Código de status HTTP da origem. Se um servidor não puder ser selecionado, a variável mantém o código de status 502 (Bad Gateway). Exemplo: `200`. **Em caso de cache, a resposta é `0`** |
| Waf Block | Informa se o WAF bloqueou ou não a ação. `0` quando a ação não foi bloqueada; `1` quando a ação foi bloqueada. Em *Learning Mode*, ela não é bloqueada, independentemente do retorno. |
| Waf Ev Headers | Quando os cabeçalhos da requisição enviados pelo usuário são analisados pelo WAF e marcados como **bloqueados** com `$waf_block = 1`, contém uma string codificada em base64. Caso contrário, contém um caractere de traço `-`. Aplica-se aos dois modos do WAF, *Learning* e *Blocking*. |
| Waf Learning | Informa se o WAF está em Learning mode. Retorna `0` se não estiver e `1` se estiver. |
| Waf Match | Lista de infrações encontradas na requisição do usuário final. É formada por elementos chave-valor: a *chave* se refere ao tipo de violação detectada; o *valor* mostra a string que gerou a infração. Exemplo: `0:1402:HEADERS:cookie` |
| Waf Score | Informa a pontuação que será incrementada em caso de match com as regras definidas para o WAF. Pode ser `SQL`, `XSS`, `TRAVERSAL` ou `RFI`. |
| Waf Total Blocked | Número total de requisições bloqueadas. Exemplo: `2` |
| Waf Total Processed | Número total de requisições processadas. Exemplo: `5` |

A variável `Stack Trace` só é preenchida quando a funcionalidade **Debug Rules** está ativada na aplicação. Para saber como ativá-la e como ler o que ela escreve, consulte [Depure regras criadas com Rules Engine](/pt-br/documentacao/guias/desenvolvimento-de-aplicacoes/primeiros-passos/debug-regras/).

O comportamento `Set WAF [Your WAF]` em um firewall realiza um processamento especial e permite que outras regras sejam executadas ao mesmo tempo. Por isso, a variável `Stack Trace` lista essas outras regras mesmo quando o rule set do WAF está configurado para bloquear e retornar a requisição. As regras do WAF continuam bloqueando as requisições que atendem aos seus critérios, e esse é o comportamento padrão da plataforma.

## Functions

Functions carrega um registro por requisição que invoca uma [function](/pt-br/documentacao/plataforma/functions/). O registro guarda as instâncias de function que a requisição executou, a ordem em que as executou e o tempo que levaram.

Esses registros exigem Functions.

Na API GraphQL, esses mesmos registros são o dataset `functionEvents`, antes chamado de `edgeFunctionsEvents`. Para os campos dele, consulte [functionEvents](/pt-br/documentacao/devtools/graphql/campos-gql-real-time-events/#functionevents-anteriormente-edgefunctionsevents-functions).

Para as outras maneiras de ler o que uma function escreveu, consulte [Solução de problemas de Functions](/pt-br/documentacao/plataforma/functions/solucao-de-problemas/).

| Variável | Descrição |
| -------- | --------- |
| Configuration ID | Identificador único de configuração da Azion definido no arquivo de configuração do virtual host. Exemplo: `1595368520` |
| Functions Instance ID List | Lista de instâncias de Functions que foram invocadas durante a requisição. Exemplo: `10728` |
| Functions Initiator Type List | Lista de initiators usados na function, separados por `;`. Pode ser `1` (Application) ou `2` (Firewall). |
| Functions List | Lista de Functions que foram invocadas durante a requisição, em ordem. A ordem começa da esquerda para a direita, ou seja, as functions à esquerda foram invocadas primeiro. Exemplo: `3324;43` |
| Functions Solution ID | Identificador da sua function. Exemplo: `1321` |
| Functions Time | Tempo total de execução, em segundos, da function durante seu processamento. Este campo é o resultado de uma soma. Exemplo: `0.021` |
| Function Language | Linguagem usada na function. Exemplo: `javascript` |
| Virtual Host ID | ID único disponível no Azion Console. Definido no arquivo de configuração do virtual host. Exemplo: `2410001a` |

## Functions Console

Functions Console carrega as linhas de log que uma function escreve no console enquanto é executada em [Azion Runtime](/pt-br/documentacao/devtools/runtime/). Uma requisição produz várias linhas, e a variável `ID` agrupa as linhas de uma única requisição.

Na API GraphQL, esses mesmos registros são o dataset `functionConsoleEvents`, antes chamado de `cellsConsoleEvents`. Para os campos dele, consulte [functionConsoleEvents](/pt-br/documentacao/devtools/graphql/campos-gql-real-time-events/#functionconsoleevents-anteriormente-cellsconsoleevents-azion-runtime).

| Variável | Descrição |
| -------- | --------- |
| Configuration ID | Identificador único de configuração da Azion definido no arquivo de configuração do virtual host. Exemplo: `1595368520` |
| Function ID | Número identificador único da function na Azion. Pode ser encontrado no path da URL da function no Azion Console ou por requisição de API. Exemplo: `1111` |
| ID | Identificador da requisição. Agrega várias mensagens de uma única requisição. Exemplo: `240g95f04832f2872dd6e8ae308e8a73` |
| Level | Mensagem com o tipo de nível da function. Pode ser `MDN`, `DEBUG`, `INFO`, `ERROR`, `LOG` ou `WARN` |
| Line | Mensagem de log gerada por Azion Runtime. Exemplo: `at async mainFetch (ext:deno_fetch/26_fetch.js:266:12)` |
| Line Source | Categoria da mensagem de log. Exemplo: `CONSOLE`, `RUNTIME` |
| Solution ID | ID único da Azion definido no arquivo de configuração do virtual host para a solução. Exemplo: `1441740010` |

## Tiered Cache

Esses registros exigem Tiered Cache.

Na API GraphQL, esses mesmos registros são o dataset `tieredCacheEvents`, que não tem nome anterior. Para os campos dele, consulte [tieredCacheEvents](/pt-br/documentacao/devtools/graphql/campos-gql-real-time-events/#tieredcacheevents-tiered-cache).

## Edge DNS

Edge DNS carrega um registro por consulta respondida por [Edge DNS](/pt-br/documentacao/plataforma/edge-dns/). O registro nomeia a zona, o tipo de registro solicitado e o status que o resolver retornou.

Esses registros exigem Edge DNS.

Na API GraphQL, esses mesmos registros são o dataset `edgeDnsQueriesEvents`, que não tem nome anterior. Para os campos dele, consulte [edgeDnsQueriesEvents](/pt-br/documentacao/devtools/graphql/campos-gql-real-time-events/#dnsqueriesevents-edge-dns).

| Variável | Descrição |
| -------- | --------- |
| Level | Nível do gerador do log: `ERROR`, `WARN`, `INFO`, `DEBUG` ou `TRACE` |
| Q Type | Definição do tipo de registro que será usado. Exemplo: `PTR`, `A`, `AAAA`, `HTTPS`, `NS`, `SRV` |
| Resolution Type | Tipos de método usados para resolver hosts. Exemplo: `standard` |
| Source | Servidor que gerou a linha do log. Exemplo: `edg-fln-ggn001p` |
| Status Code | Código de status HTTP da requisição. Exemplo: `200` |
| Solution ID | Identificador da sua instância de Edge DNS. Exemplo: `1321` |
| UUID | Identificador único da requisição. Exemplo: `b204b8c3-e463-4c3d-af3d-025703a4` |
| Zone ID | Identificador único da zona de Edge DNS. Exemplo: `1340` |

## Data Stream

Data Stream carrega um registro por entrega feita a um endpoint configurado. O registro nomeia o endpoint, o volume que ele carregou e o status com que o endpoint respondeu. Um destino que rejeita uma entrega fica visível, portanto, no mesmo lugar que o tráfego que o alimentou.

Esses registros exigem Data Stream.

Na API GraphQL, esses mesmos registros são o dataset `dataStreamedEvents`, que não tem nome anterior. Para os campos dele, consulte [dataStreamedEvents](/pt-br/documentacao/devtools/graphql/campos-gql-real-time-events/#datastreamedevents-data-stream).

| Variável | Descrição |
| -------- | --------- |
| Configuration ID | Identificador único de configuração da Azion definido no arquivo de configuração do virtual host. Exemplo: `1595368520` |
| Data Streamed | Quantidade total de dados transmitidos, em bytes, ao endpoint configurado. Este campo é o resultado de uma soma. Exemplo: `1270` |
| Endpoint Type | Tipo de endpoint usado no Data Stream configurado. Pode ser: `HTTP_POST`, `S3`, `ELASTICSEARCH`, `QRADAR`, `AWS_KINESIS_FIREHOSE`, `KAFKA`, `DATADOG`, `BIG_QUERY`, `SPLUNK`, `AZURE_MONITOR`, `AZURE_BLOB_STORAGE` |
| Job Name | Identificador único da Azion para o tipo de stream criado. Exemplo: `Data Stream HTTP`, `Data Stream WAF` |
| Source | Servidor que gerou a linha do log. Exemplo: `edg-fln-ggn001p` |
| Status Code | Código de status HTTP da requisição. Exemplo: `200` |
| Streamed Lines | Quantidade total de linhas transmitidas ao endpoint configurado. Valor máximo de `2000`. Este campo é o resultado de uma soma. Exemplo: `837` |
| URL | A URL para a qual os dados do cliente foram enviados (sink). Exemplo para um endpoint **HTTP POST**: `https://log-receiver.azion.com:9200` |

## Activity History

Activity History carrega um registro por ação executada em uma conta Azion, conforme [Activity History](/pt-br/documentacao/fundamentos/activity-history/) a registra. O registro nomeia quem executou a ação, o recurso que ela alterou e o payload que a requisição carregou.

Os registros de Activity History são mantidos por 2 anos, uma janela mais longa que a de todas as outras fontes de dados. A API GraphQL do Real-Time Events é o que alcança os mais antigos. Para a retenção das outras sete fontes de dados, consulte [Limites](/pt-br/documentacao/plataforma/real-time-events/limites/).

Na API GraphQL, esses mesmos registros são o dataset `activityHistoryEvents`, que não tem nome anterior. Para os campos dele, consulte [activityHistoryEvents](/pt-br/documentacao/devtools/graphql/campos-gql-real-time-events/#activityhistoryevents-activity-history).

| Author Email | Endereço de e-mail do usuário do Console que executou a ação. Exemplo: `myemail@gmail.com` |

## Filtro de tempo

O filtro de tempo delimita o período que uma busca cobre. Ele se aplica sobre a fonte de dados: a fonte de dados decide quais registros são lidos e o filtro de tempo decide até onde a busca alcança no passado. Toda busca é executada com um filtro de tempo, e o filtro abre nos últimos 15 minutos até que outro período seja escolhido.

A classic view oferece onze períodos:

| Período |
| --- |
| Last 15 minutes |
| Last 1 hour |
| Last 3 hours |
| Last 6 hours |
| Last 12 hours |
| Last day |
| Last 2 days |
| Last 3 days |
| Last 5 days |
| Last 7 days |
| Custom time range |

Um intervalo personalizado seleciona um intervalo de data e hora dentro das últimas 168 horas. A janela de retenção é, portanto, o limite externo do que uma busca pode pedir. Activity History é a exceção, porque seus registros são mantidos por 2 anos. Para os valores de retenção e os limites que uma consulta carrega, consulte [Limites](/pt-br/documentacao/plataforma/real-time-events/limites/).

## Datasets sem fonte de dados no Console

Quatro datasets da API GraphQL do Real-Time Events não têm fonte de dados no Azion Console. Dois deles carregam telemetria do Azion Mobile SDK e são alcançados somente pela API: `telemetryDeviceInfoEvents` guarda os registros de dispositivo e `telemetrySensorsEvents` guarda os registros de sensores.

Os outros dois estão descontinuados e são substituídos por datasets que esta página já documenta. `l2CacheEvents` é substituído por `tieredCacheEvents` e `idnsQueriesEvents` é substituído por `edgeDnsQueriesEvents`. Escreva uma nova consulta contra o substituto, em vez de usar o nome descontinuado. Para os campos dos quatro, consulte [Campos da API GraphQL do Real-Time Events](/pt-br/documentacao/devtools/graphql/campos-gql-real-time-events/).
