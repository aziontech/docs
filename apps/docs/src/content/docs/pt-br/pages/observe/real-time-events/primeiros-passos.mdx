Este guia conduz você pela leitura do seu primeiro registro de evento no [Real-Time Events](/pt-br/documentacao/plataforma/real-time-events/).

- Abra Real-Time Events e identifique os controles que compõem uma busca.
- Leia os registros da fonte de dados HTTP Requests em um período que você define.
- Reduza o resultado aos registros que carregam um valor.
- Abra um registro e leia os campos que a requisição escreveu.

Uma busca não cria nada. Ela é formada por três escolhas, e todo resultado vem da combinação delas:

1. A fonte de dados guarda os registros de um tipo de evento, como as requisições das suas [Applications](/pt-br/documentacao/plataforma/applications/) e [Firewalls](/pt-br/documentacao/plataforma/firewall/). Uma busca sempre lê uma.
2. O intervalo de tempo delimita o período. Um registro fora desse período não é lido, não importa o que mais corresponda a ele.
3. Um filtro reduz o que os dois primeiros selecionaram. Ele nunca os amplia.

A API GraphQL faz as mesmas três escolhas. Ela recebe um nome de dataset, um argumento `tsRange` e os outros argumentos de filtro desse dataset.

## Abra Real-Time Events

Os registros são alcançados de duas maneiras, e as duas leem o mesmo armazenamento.

<Tabs client:visible sharedStore="interface">

<Fragment slot="panel.console">

### Console

Para abrir a página, acesse [Azion Console](https://console.azion.com/) > **Real-Time Events**.

A página apresenta estes controles:

- Uma aba por fonte de dados, como **HTTP Requests**, seleciona os registros que a busca lê.
- O campo de período delimita o período que a busca cobre. Ele abre em _Last 5 minutes_.
- O ícone de filtro abre o diálogo **Filter**, que reduz o resultado aos registros que correspondem a um valor. O campo de consulta mostra cada filtro em Azion Query Language.
- **Refresh** executa a busca de novo. Depois que você muda o período ou a consulta, o botão passa a mostrar **Update**.

Uma busca é uma combinação desses controles.

</Fragment>

<Fragment slot="panel.api">

### API

A API GraphQL serve os mesmos registros em `https://api.azion.com/v4/events/graphql`. Esse endereço também serve o GraphiQL Playground em um navegador. Entre no Azion Console em `https://console.azion.com` e depois abra o endpoint. Toda consulta deste guia roda ali.

Uma consulta enviada de um terminal carrega, em vez disso, um cabeçalho `Authorization: Token [TOKEN VALUE]`. Para esse caminho, consulte [Primeiros passos da API GraphQL](/pt-br/documentacao/devtools/graphql/primeiros-passos/).

O Playground é onde você escreve e envia cada consulta deste guia.

</Fragment>

</Tabs>

## Busque os registros de uma fonte de dados

HTTP Requests carrega um registro por requisição que uma Application ou um Firewall recebeu. O período que uma busca pode pedir é limitado por quanto tempo um registro de evento é mantido. Para esse limite e os outros que uma consulta carrega, consulte [Limites](/pt-br/documentacao/plataforma/real-time-events/limites/).

<Tabs client:visible sharedStore="interface">

<Fragment slot="panel.console">

### Console

Para ler os registros de uma fonte de dados no Azion Console:

<DocSteps>
  <DocStep title="Selecione a fonte de dados">

  Selecione a aba **HTTP Requests**.

  </DocStep>
  <DocStep title="Abra o período">

  Selecione o campo de período, que mostra _Last 5 minutes_.

  </DocStep>
  <DocStep title="Selecione o período">

  Selecione **Quick** e depois _Last 15 minutes_.

  </DocStep>
  <DocStep title="Execute a busca">

  Selecione **Update**.

  </DocStep>
</DocSteps>

Os registros desse período aparecem em uma tabela, uma linha por requisição, com **Time** e **Log Body**.

A página tem uma aba por fonte de dados. Para cada uma delas e as variáveis que ela carrega, consulte [Fontes de dados](/pt-br/documentacao/plataforma/real-time-events/fontes-de-dados/).

</Fragment>

<Fragment slot="panel.api">

### API

Na API GraphQL, a fonte de dados HTTP Requests é o dataset `workloadEvents`. Os controles do Azion Console são argumentos dele:

- `tsRange` carrega o período, como um timestamp `begin` e um `end`.
- `orderBy` define a ordem em que as linhas voltam, como `[ts_DESC]` para as mais recentes primeiro.
- `limit` limita quantas linhas a consulta retorna.

Esses três argumentos são o que a próxima etapa envia. Para o dataset de cada fonte de dados, consulte [Fontes de dados](/pt-br/documentacao/plataforma/real-time-events/fontes-de-dados/). Para os campos que cada dataset carrega, consulte [Campos da API GraphQL do Real-Time Events](/pt-br/documentacao/devtools/graphql/campos-gql-real-time-events/).

</Fragment>

</Tabs>

## Reduza a busca

Uma busca sobre um período sem nenhuma outra condição lê todos os registros dele. Um valor reduz isso aos registros que valem a leitura. Ele também mantém uma busca dentro dos limites do banco de dados de logs.

<Tabs client:visible sharedStore="interface">

<Fragment slot="panel.console">

### Console

Para reduzir o resultado no Azion Console:

<DocSteps>
  <DocStep title="Abra o filtro">

  Selecione o ícone de filtro.

  </DocStep>
  <DocStep title="Selecione o campo">

  Em **Filter**, selecione _Status_.

  </DocStep>
  <DocStep title="Defina a condição">

  Em **Operator**, selecione _Equals_ e digite `400` no campo de valor.

  </DocStep>
  <DocStep title="Aplique o filtro">

  Selecione **Apply**.

  </DocStep>
</DocSteps>

A busca é executada na mesma hora. O campo de consulta mostra `status = 400`, e a tabela carrega apenas os registros cujo status é `400`.

Um filtro recebe um campo, um operador, como _Equals_, _Not Equals_ ou _Between_, e um valor.

</Fragment>

<Fragment slot="panel.api">

### API

Um argumento de filtro reduz o dataset da mesma maneira. `statusIn` recebe uma lista de códigos de status, portanto `statusIn: [400]` retorna os registros cujo status é `400`.

Para retornar o registro mais recente que correspondeu:

```graphql
{
  workloadEvents(
    limit: 1
    filter: {
      tsRange: { begin: "<your-period-start>", end: "<your-period-end>" }
      statusIn: [400]
    }
    orderBy: [ts_DESC]
  ) {
    ts
    requestId
    host
    status
  }
}
```

Substitua `<your-period-start>` e `<your-period-end>` por timestamps em Tempo Universal Coordenado (UTC), no formato `YYYY-MM-DDTHH:MM:SS`, dentro dos últimos 7 dias. A linha que a consulta retorna:

```json
{
  "ts": "2026-11-26T20:18:46Z",
  "requestId": "485876cf3a7499bcac0545a095e2ef76",
  "host": "<your-workload-domain>",
  "status": 400
}
```

A linha é um registro de evento, e seu `requestId` identifica a requisição que o produziu.

</Fragment>

</Tabs>

## Leia um registro de evento

Um registro carrega muito mais do que os poucos valores que uma lista de resultados mostra. Ler o registro inteiro é o motivo da busca.

<Tabs client:visible sharedStore="interface">

<Fragment slot="panel.console">

### Console

Para abrir o registro inteiro no Azion Console, selecione uma linha na tabela de resultados.

A visualização **More Details** abre, com todos os campos daquele registro e o valor de cada um, como `remoteAddress`. Você passa a ter os valores que uma requisição escreveu, campo por campo.

Para o significado de cada variável, fonte de dados por fonte de dados, consulte [Fontes de dados](/pt-br/documentacao/plataforma/real-time-events/fontes-de-dados/). Para saber como ler os valores de um registro, consulte [Ler um registro de evento](/pt-br/documentacao/guias/plataforma/observabilidade/entender-logs/).

</Fragment>

<Fragment slot="panel.api">

### API

Uma resposta carrega somente os campos que a consulta selecionou. Para ler mais campos de um mesmo registro, nomeie-os na consulta. Filtre pelo `requestId` que a etapa anterior retornou e amplie o conjunto de seleção:

```graphql
{
  workloadEvents(
    limit: 1
    filter: {
      tsRange: { begin: "<your-period-start>", end: "<your-period-end>" }
      requestIdEq: "<your-request-id>"
    }
  ) {
    ts
    requestId
    host
    requestUri
    status
    upstreamStatus
  }
}
```

Substitua `<your-request-id>` pelo `requestId` que a etapa anterior retornou e use o mesmo período. A linha carrega um valor por campo nomeado:

```json
{
  "ts": "2026-11-26T20:18:46Z",
  "requestId": "485876cf3a7499bcac0545a095e2ef76",
  "host": "<your-workload-domain>",
  "requestUri": "-",
  "status": 400,
  "upstreamStatus": 0
}
```

Você passa a ter o registro de uma requisição, campo por campo. Um campo sem valor, como `requestUri` aqui, traz `-`. `upstreamStatus` traz `0` porque a requisição nunca chegou a uma origem. Para os campos de `workloadEvents` e dos outros datasets, consulte [Campos da API GraphQL do Real-Time Events](/pt-br/documentacao/devtools/graphql/campos-gql-real-time-events/).

</Fragment>

</Tabs>
