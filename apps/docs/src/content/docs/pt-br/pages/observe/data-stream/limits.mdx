[Data Stream](/pt-br/documentacao/plataforma/data-stream/) aplica limites padrão à forma como um stream agrupa e entrega as linhas de log e aos campos de um stream. Para o uso que cada plano inclui, consulte [Preços da Azion](https://www.azion.com/pt-br/precos/). A Azion pode aumentar um limite padrão de acordo com o seu plano. Para solicitar um aumento, entre em contato com a equipe de [suporte técnico](/pt-br/documentacao/suporte/).

---

## Escopo

- **Escopo de um stream**: um stream de Applications, Functions ou WAF Events carrega um item de sampling ou um filtro de workloads. A API recusa um `transform` sem nenhum dos dois (`32002`) ou com os dois (`32007`). Para os dois itens, consulte [Configurações do stream](/pt-br/documentacao/plataforma/data-stream/configuracoes-do-stream/#transform).
- **Escopo de um stream de Activity History**: um stream de Activity History aceita um item de sampling ou nenhum item de escopo, e a API recusa um filtro de workloads nele (`10088`). Um stream de Activity History salvo sem item de sampling é aceito e não envia nenhum evento.
- **Sampling e os outros streams**: salvar um stream ativo com sampling em Applications, Functions ou WAF Events desativa todos os outros streams da conta, exceto os streams de Activity History. Os streams desativados incluem os streams com filtro de workloads em qualquer uma dessas três fontes de dados. Uma taxa de sampling de 1 os desativa como uma taxa de 100. Uma edição que muda só o nome de um stream ativo com sampling também desativa os outros streams.
- **Streams que continuam ativos**: salvar um stream de Activity History com sampling não desativa nenhum outro stream. Um stream inativo com sampling não desativa nenhum quando você o salva. Um stream com filtro de workloads que você salva ou ativa depois roda ao lado do stream com sampling até que esse stream seja salvo de novo.
- **Início de um stream**: salvar um stream como ativo é a única etapa de ativação de que ele precisa. Depois que você cria ou ativa um stream, ele pode levar vários minutos para começar a coletar eventos. Ele não envia os eventos de antes disso.
- **Edições e desativação**: uma edição, como uma nova credencial do endpoint, pode levar vários minutos para entrar em vigor, e até lá o stream mantém as configurações anteriores. Um stream que você desativa pode continuar enviando por alguns minutos.
- **Falhas no endpoint**: quando um endpoint está indisponível ou responde com um erro, as linhas de log desse envio não chegam a ele. Quando um endpoint S3 recusa a credencial do stream, Real-Time Events registra cada envio com status `503`. As linhas de log desses envios não chegam ao endpoint, e o stream não as envia de novo depois que você corrige a credencial. Para as causas e as correções, consulte [Solucione problemas de Data Stream](/pt-br/documentacao/plataforma/data-stream/solucao-de-problemas/).
- **Armazenamento dos logs**: Data Stream não armazena nem consulta logs. [Real-Time Events](/pt-br/documentacao/plataforma/real-time-events/) guarda os eventos brutos dos seus produtos por 7 dias e os do Activity History por 2 anos. O seu endpoint mantém o que um stream envia pelo tempo que você decidir.

## Limites padrão

Cada valor desta tabela se aplica a cada stream ou à conta que o contém. A API responde a uma requisição que ultrapassa o limite de um campo com `400` e um array `errors`, e não cria nada.

| Escopo | Limite | Além do limite |
| --- | --- | --- |
| Lote de linhas de log | 2.000 registros ou 60 segundos, o que ocorrer primeiro. Um registro é uma linha de log. Para *Standard HTTP/HTTPS POST*, o lote também fecha em **Payload Max Size**, em bytes. | O stream envia o lote para o endpoint. Um stream com pouco tráfego envia lotes pequenos. |
| Lote de linhas de log para *AWS Kinesis Data Firehose* | 500 registros ou 60 segundos, o que ocorrer primeiro | O stream envia o lote para o endpoint. |
| **Payload Max Size**, `outputs[0].attributes.max_size` em um endpoint `standard` | 1.000.000 bytes ou mais. O Console preenche `1000000`. | Um valor abaixo de `1000000` é recusado com `10050` `Min Value`. |
| Timeout de envio para um endpoint HTTP POST | 20 segundos | Quando o endpoint passa na verificação de disponibilidade, mas não recebe o lote em até 20 segundos, o envio termina com status `504`. |
| Verificação de disponibilidade do endpoint | Uma vez por minuto. Todos os servidores da Azion precisam informar que o endpoint está disponível. | Enquanto o endpoint está indisponível, Data Stream não envia para ele e descarta os logs desse intervalo. Real-Time Events registra a tentativa com status `503`. A verificação roda de novo no minuto seguinte. |
| Endpoints por stream | 1 | Quando `outputs` contém dois endpoints do mesmo tipo, a API responde `201` e mantém o último. Com um endpoint S3 e um Standard HTTP/HTTPS POST, ela responde `500`. |
| Streams ativos logo depois que você salva um stream ativo com sampling em Applications, Functions ou WAF Events | Esse stream, mais os streams de Activity History | Salvar esse stream como ativo desativa todos os outros streams, exceto os de Activity History, sem erro na API. Uma taxa de `100` conta como sampling. O Console avisa antes de salvar. |
| `name` do stream | 1 a 100 caracteres | Um nome mais longo é recusado com `10046` `Max Length`. |
| Taxa de sampling, `transform[sampling].attributes.rate` | 1 a 100, uma porcentagem inteira | `0` é recusado com `10050` `Min Value`, e `101` com `10068` `Max Value`. |
| Filtro de workloads, `transform[filter_workloads].attributes.workloads` | 1 a 600 IDs de workload, cada um de um Workload da conta | Uma lista fora desse intervalo é recusada. Um ID que não é de um Workload da conta é recusado com `32003` `Workloads Not Belong Account`. |
| Workloads na conta, para Azion Console | Menos de 3.000 | Com 3.000 Workloads ou mais, o Console bloqueia os formulários de criação e edição, e a conta gerencia os streams apenas pela API. |

Para rodar vários streams de Applications, Functions ou WAF Events ao mesmo tempo, dê a cada um deles um item `filter_workloads` em vez de sampling. Para os códigos de erro e as correções, consulte [Configurações do stream](/pt-br/documentacao/plataforma/data-stream/configuracoes-do-stream/#erros).

Outros limites se aplicam:

- A entrega dos logs para a sua infraestrutura leva até 3 minutos.
- Em um endpoint `standard`, `payload_format` aceita até 250 caracteres, `log_line_separator` até 100 e `max_size` até 2.147.483.647 bytes.
- O Console aceita até cinco **Custom Headers** em um endpoint *Standard HTTP/HTTPS POST*.
- O `data_set` de um template aceita até 65.535 caracteres, e o `name` até 100.
- O `stream_name` de um *AWS Kinesis Data Firehose* aceita até 64 caracteres.
- O `kafka_topic` e o `bootstrap_servers` de um *Apache Kafka*, e o `bucket_name` de um S3, aceitam até 150 caracteres cada.

Para os limites de cada campo de endpoint, consulte [Endpoints](/pt-br/documentacao/plataforma/data-stream/endpoints/).

## Registros de uso

[Real-Time Events](/pt-br/documentacao/plataforma/real-time-events/fontes-de-dados/#data-stream) registra cada envio de um stream com o número de linhas de log em `streamedLines` e o tamanho em bytes em `dataStreamed`. O tamanho de uma linha de log depende do template e do evento. Para ler o consumo da conta, consulte o guia [Consulte dados de uso do Data Stream](/pt-br/documentacao/guias/plataforma/observabilidade/consultar-dados-de-uso-data-stream-com-graphql/). Para os valores por unidade, consulte [Preços](/pt-br/documentacao/fundamentos/precos/#data-stream).
