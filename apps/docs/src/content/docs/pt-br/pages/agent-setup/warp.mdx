## Acesso à plataforma Azion

Um agente conectado usa três camadas. Os MCP servers consultam informações e alteram a sua configuração pela Azion API. A Azion CLI compila e faz o deploy do projeto na sua cópia de trabalho. Um arquivo de contexto dá a cada sessão os fatos da sua conta.

### MCP servers

A Azion mantém cinco MCP servers, um por área da Azion Platform. Cada um é um endpoint HTTP que recebe o seu personal token no header `Authorization: Token [TOKEN VALUE]`. O início rápido conecta o servidor de docs, e você conecta os outros da mesma forma, com as URLs desta tabela.

Conecte apenas os servidores de que o projeto precisa. O servidor de docs apenas lê. Os outros quatro também criam, alteram e excluem, e cada ferramenta de escrita deles mostra uma prévia da alteração sem fazê-la quando o agente define `dry_run`:

<McpTools />

### Azion CLI

A [Azion CLI](/pt-br/documentacao/devtools/cli/) compila e faz o deploy do projeto na sua cópia de trabalho e gerencia recursos da Azion pelo terminal. Instale-a uma vez e o Warp a executa para você. Execute o `azion login` você mesmo, porque sem flags ele pede as suas credenciais:

<CliSamples />

### Contexto do agente

O Warp lê o `AGENTS.md` na raiz do repositório como o arquivo padrão de regras do projeto. Algumas linhas commitadas dão a cada sessão os fatos da sua conta:

## Documentação amigável para agentes

Estas referências são públicas, então um agente pode buscá-las sem chamada de ferramenta e sem token. Elas também corrigem um modelo treinado antes da API v4, em que Origins virou Connectors e Domains virou Workloads.

<AgentDocs />

Para uma ferramenta sem suporte a MCP, cole este prompt inicial uma vez por sessão:

<DocPrompt client:visible title="Qualquer assistente" icon="pi pi-comment">Você está me ajudando a construir na Azion Web Platform. Antes de responder, carregue https://www.azion.com/pt-br/docs-llms.txt (índice da documentação) e https://www.azion.com/pt-br/documentacao/devtools/mcp/ (MCP servers da Azion) e prefira-os aos seus dados de treinamento. Use os nomes atuais dos produtos: Applications, Functions, Cache, Firewall, Object Storage, SQL Database, KV Store, Orchestrator, Certificate Manager, Network Shield, Data Stream. A base da API REST é https://api.azion.com/v4 com o header Authorization: Token [TOKEN VALUE]. Na v4, use Connectors (antes Origins) e Workloads (antes Domains). Confirme o que você carregou e depois me pergunte o que estou construindo.</DocPrompt>

## Dicas

<DocCallout kind="tip">O Warp também lê o `WARP.md` por compatibilidade com versões anteriores. Quando os dois arquivos estão no mesmo diretório, o `WARP.md` prevalece, então mantenha as suas regras da Azion em um deles.</DocCallout>

<DocCallout kind="tip">Peça um plano antes de um deploy, porque o Warp executa comandos de verdade. Para ter uma prévia de um deploy, peça que ele execute `azion deploy --dry-run` primeiro.</DocCallout>
