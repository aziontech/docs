Você pode distribuir as requisições de uma [Application](/pt-br/documentacao/plataforma/applications/) entre vários servidores de origem com [Load Balancer](/pt-br/documentacao/plataforma/connectors/load-balancer/) em um [Connector](/pt-br/documentacao/plataforma/connectors/), pelo Azion Console ou pela API. Uma regra do [Rules Engine](/pt-br/documentacao/plataforma/applications/rules-engine/) com o behavior _Set Connector_ define esse Connector, e Load Balancer distribui as requisições entre os endereços dele com um método de balanceamento. Para conectar uma Application a uma única origem, consulte [Conecte uma aplicação a uma origem](/pt-br/documentacao/guias/desenvolvimento-de-aplicacoes/primeiros-passos/definir-origens/).

Uma conta que [não migrou para a API v4](/pt-br/documentacao/guias/seguranca-de-aplicacoes/acesso-e-compliance/verificar-migracao-conta/) configura o balanceamento de carga nas Origins legadas da Application. Para mais informações, consulte [Origins](/pt-br/documentacao/plataforma/connectors/origins/#load-balancer).

:::caution[Atenção]
Com Load Balancer habilitado, a transferência de dados pode gerar custos relacionados ao uso. Para mais informações, consulte [Preços](/pt-br/documentacao/fundamentos/precos/).
:::

## Planeje os endereços

O exemplo desta página balanceia três servidores de origem. Cada um está hospedado em um provedor de armazenamento ou serviço de cloud diferente, porque quedas de servidor raramente ocorrem ao mesmo tempo. Os três guardam o mesmo conteúdo e estão configurados da mesma forma para a Application. Dois deles dividem o tráfego, e o terceiro fica de reserva para o caso em que os dois falham.

| Endereço | Servidor | Capacidade de carga | Peso | Função do servidor | Ativo |
| --- | --- | --- | --- | --- | --- |
| `example.com` | Primário | Alta | `3` | `primary` | Sempre |
| `example.net` | Secundário | Média, suficiente para grandes picos de tráfego | `2` | `primary` | Sempre |
| `example.org` | Backup | Baixa | `1`, o padrão quando o peso fica em branco | `backup` | Sempre |

O peso acompanha a capacidade de carga de cada servidor. Tanto `example.com` quanto `example.net` são primários, então `example.com` recebe cerca de três requisições para cada duas que `example.net` recebe. `example.org` recebe requisições só quando os dois endereços primários falham. Ele fica ativo, porque um endereço que não está ativo não recebe nenhuma requisição, nem como backup. Para saber como o peso, a função do servidor e o estado ativo distribuem as requisições, consulte [Métodos de balanceamento](/pt-br/documentacao/plataforma/connectors/load-balancer/metodos-de-balanceamento/#peso).

## Crie um Connector com Load Balancer

Load Balancer pertence ao Connector, em `attributes.modules` na API. Um Connector criado sem Load Balancer o mantém desativado até que você o ative. Este é o objeto `attributes.modules` de um Connector do tipo `http` que a API criou sem Load Balancer:

```json
{
  "load_balancer": {
    "enabled": false,
    "config": null
  },
  "origin_shield": {
    "enabled": false,
    "config": null
  }
}
```

Para balancear os três endereços do exemplo com o [algoritmo Round-Robin](/pt-br/documentacao/plataforma/connectors/load-balancer/metodos-de-balanceamento/#metodo-de-balanceamento), o Connector traz estes valores. Cada chave fica em `attributes`:

| Chave | Valor no exemplo |
| --- | --- |
| `type` | `http` |
| `modules.load_balancer.enabled` | `true` |
| `modules.load_balancer.config.method` | `round_robin` |
| `modules.load_balancer.config.max_retries` | `0` |
| `modules.load_balancer.config.connection_timeout` | `60` |
| `modules.load_balancer.config.read_write_timeout` | `120` |
| `addresses[].address` | `example.com`, `example.net` e `example.org` |
| `addresses[].modules.load_balancer.weight` | `3`, `2` e `1` |
| `addresses[].modules.load_balancer.server_role` | `primary`, `primary` e `backup` |
| `addresses[].active` | `true`, `true` e `true` |
| `connection_options.transport_policy` | `preserve` |
| `connection_options.host` | `${host}`, que encaminha o header `Host` da requisição do usuário |

No Azion Console, você configura um Connector em **Connectors**, e não em uma aba da Application. Para cada campo, consulte [Load Balancer](/pt-br/documentacao/plataforma/connectors/load-balancer/) e [Configurações de Connector](/pt-br/documentacao/plataforma/connectors/configuracoes/#enderecos).

### Console

Para criar o Connector no Azion Console:

<DocSteps>
  <DocStep title="Abra a página Connectors">

  Acesse [Azion Console](https://console.azion.com/) > **Connectors**.

  </DocStep>
  <DocStep title="Inicie um novo Connector">

  Selecione **+ Connectors**.

  </DocStep>

  Na seção **General**, insira `balanced-origins` em **Name**.

  </DocStep>
  <DocStep title="Selecione o tipo HTTP">

  Na seção **Connector Type**, selecione _HTTP_.

  </DocStep>

  Na seção **Modules**, ative **Load Balancer**. O Connector passa a aceitar mais de um endereço.

  </DocStep>

  Na seção **Load Balancer Configuration**, selecione _Round Robin_ em **Method**.

  </DocStep>
  <DocStep title="Insira o primeiro endereço">

  Na seção **Address Management**, insira `example.com` em **Address** e `3` em **Weight**.

  </DocStep>
  <DocStep title="Torne o primeiro endereço primário">

  Selecione _Primary_ em **Server Role** e mantenha **Active** ativado.

  </DocStep>
  <DocStep title="Adicione um segundo endereço">

  Selecione **Add Address**.

  </DocStep>
  <DocStep title="Insira o segundo endereço">

  Insira `example.net` em **Address** e `2` em **Weight**.

  </DocStep>
  <DocStep title="Torne o segundo endereço primário">

  Selecione _Primary_ em **Server Role** e mantenha **Active** ativado.

  </DocStep>
  <DocStep title="Adicione um terceiro endereço">

  Selecione **Add Address**.

  </DocStep>
  <DocStep title="Insira o terceiro endereço">

  Insira `example.org` em **Address** e `1` em **Weight**.

  </DocStep>
  <DocStep title="Torne o terceiro endereço um backup">

  Selecione _Backup_ em **Server Role** e mantenha **Active** ativado.

  </DocStep>
  <DocStep title="Mantenha o protocolo da requisição do usuário">

  Em **Transport Protocol Policy**, selecione _Preserve_.

  </DocStep>
  <DocStep title="Encaminhe o header Host da requisição do usuário">

  Em **Host**, insira `${host}`. O Connector envia esse valor à origem no header `Host`.

  </DocStep>
  <DocStep title="Selecione Save" />

Azion Console mostra `Connector successfully created`.

<Fragment slot="panel.api">

### API

Para criar o Connector com a API, envie os valores da tabela em uma requisição `POST` ao endpoint de connectors:

```bash
curl --request POST \
  --url https://api.azion.com/v4/workspace/connectors \
  --header 'Accept: application/json' \
  --header 'Authorization: Token [TOKEN VALUE]' \
  --header 'Content-Type: application/json' \
  --data '{
  "name": "balanced-origins",
  "type": "http",
  "attributes": {
    "addresses": [
      { "address": "example.com", "active": true, "modules": { "load_balancer": { "weight": 3, "server_role": "primary" } } },
      { "address": "example.net", "active": true, "modules": { "load_balancer": { "weight": 2, "server_role": "primary" } } },
      { "address": "example.org", "active": true, "modules": { "load_balancer": { "weight": 1, "server_role": "backup" } } }
    ],
    "connection_options": { "transport_policy": "preserve", "host": "${host}" },
    "modules": {
      "load_balancer": {
        "enabled": true,
        "config": { "method": "round_robin", "max_retries": 0, "connection_timeout": 60, "read_write_timeout": 120 }
      }
    }
  }
}'
```

A API responde `202` com `"state": "pending"` e o Connector, com o ID dele em `data.id`:

```json
{
  "state": "pending",
  "data": {
    "id": <connector-id>,
    "name": "balanced-origins",
    "active": true,
    "type": "http"
  }
}
```

Copie o ID. A regra que define o Connector guarda esse ID em `attributes.value`.

## Envie as requisições ao Connector

Um Connector não recebe nenhuma requisição até que uma regra o defina. A regra desta seção é executada na Request Phase da Application. O critério dela corresponde a todos os paths, com a variável `${uri}`, o operador `starts_with` e `/` como argumento, então o Connector recebe todas as requisições da Application. O behavior dela define o Connector.

A variável `${uri}` funciona em todas as Applications. Um critério com `${request_uri}` precisa de [Application Accelerator](/pt-br/documentacao/plataforma/applications/application-accelerator/primeiros-passos/) ativado na Application. Para todas as variáveis e todos os operadores, consulte [Rules Engine para Applications](/pt-br/documentacao/plataforma/applications/rules-engine/#criterios).

  <DocStep title="Selecione o Connector">

  No behavior _Set Connector_, selecione `balanced-origins`.

  </DocStep>

  Selecione **Save**.

  </DocStep>
</DocSteps>

<Fragment slot="panel.api">

### API

Para criar a regra com a API, envie uma requisição `POST` ao endpoint `request_rules` da Application. Substitua `<application-id>` pelo ID da sua Application e `<connector-id>` pelo ID do Connector:

```bash
curl --request POST \
  --url https://api.azion.com/v4/workspace/applications/<application-id>/request_rules \
  --header 'Accept: application/json' \
  --header 'Authorization: Token [TOKEN VALUE]' \
  --header 'Content-Type: application/json' \
  --data '{
  "name": "balance-origins",
  "active": true,
  "criteria": [
    [
      {
        "variable": "${uri}",
        "conditional": "if",
        "operator": "starts_with",
        "argument": "/"
      }
    ]
  ],
  "behaviors": [
    {
      "type": "set_connector",
      "attributes": {
        "value": <connector-id>
      }
    }
  ]
}'
```

A API responde `202` e retorna a regra:

```json
{
  "state": "pending",
  "data": {
    "id": <rule-id>,
    "name": "balance-origins",
    "active": true,
    "criteria": [
      [
        {
          "conditional": "if",
          "variable": "${uri}",
          "operator": "starts_with",
          "argument": "/"
        }
      ]
    ],
    "behaviors": [
      {
        "type": "set_connector",
        "attributes": {
          "value": <connector-id>
        }
      }
    ],
    "description": "",
    "order": 0,
    "last_editor": "user@example.com",
    "last_modified": "2026-01-01T12:00:26.750242Z",
    "created_at": "2026-01-01T12:00:26.750262Z"
  }
}
```

Em uma Application sem outra regra na Request Phase, a regra recebe `order` `0`.

## Confirme que a Application responde

A regra leva alguns minutos para se propagar. Até lá, a Application responde como respondia antes de a regra existir.

Para confirmar a rota, envie uma requisição ao workload domain do seu Workload, com esse domínio no lugar de `<your-workload-domain>`:

```bash
curl -i https://<your-workload-domain>/
```

A resposta começa com a linha de status que um dos endereços primários retorna, como `HTTP/2 200`, seguida dos headers de resposta desse servidor de origem. Um header que cada servidor de origem define com o próprio valor, como `server`, mostra qual endereço respondeu. Se a resposta ainda não vier dos seus servidores de origem, envie a requisição novamente até que venha. Se nunca vier, consulte [Solucione problemas de Applications](/pt-br/documentacao/plataforma/applications/solucao-de-problemas/).

## Balanceie os endereços em uma Application v3

Uma conta que opera na API v3 não tem Connectors: o balanceamento pertence a uma origin da Application, do tipo _Load Balancer_. Para saber qual modelo sua conta usa, consulte [Verifique a migração da sua conta](/pt-br/documentacao/guias/seguranca-de-aplicacoes/acesso-e-compliance/verificar-migracao-conta/).

<Tabs client:visible>
<Fragment slot="tab.console">Console</Fragment>
<Fragment slot="tab.api">API v3</Fragment>

<Fragment slot="panel.console">

Load Balancer é uma configuração na Application, e os endereços ficam em uma origin. Para definir os dois no Azion Console:

<DocSteps>
  <DocStep title="Abra a Application">

  Acesse [Azion Console](https://console.azion.com/) > **Applications** > **sua Application**.

  </DocStep>
  <DocStep title="Ative o Load Balancer">

  Na aba **Main Settings**, em **Modules**, ative **Load Balancer**.

  </DocStep>
  <DocStep title="Salve a Application" />
  <DocStep title="Abra a origin">

  Na aba **Origins**, selecione **Default Origin** para balancear os endereços que a Application já usa, ou **+ Origin** para adicionar uma separada. Editar a origin padrão substitui o endereço com que a Application foi criada.

  </DocStep>
  <DocStep title="Nomeie a origin e escolha o tipo dela">

  Informe um nome e defina **Type** como _Load Balancer_.

  </DocStep>
  <DocStep title="Escolha o método de balanceamento">

  Em **Method**, selecione um método, como _Round-Robin_.

  </DocStep>
  <DocStep title="Adicione o primeiro endereço">

  No primeiro campo **Address**, informe o servidor primário. Em **Weight**, informe a parcela de requisições dele, como `3` para um servidor com mais capacidade. Em **Server Role**, mantenha _Primary_, e mantenha o endereço **Active**.

  </DocStep>
  <DocStep title="Adicione os demais endereços">

  Selecione **+ Add Origin** para cada endereço adicional. Um **Weight** em branco assume `1`. Um endereço com **Server Role** em _Backup_ recebe requisições somente quando os primários falham, e um endereço com **Active** desligado não recebe nenhuma.

  </DocStep>
  <DocStep title="Salve a origin">

  Selecione **Save**.

  </DocStep>
</DocSteps>

</Fragment>

<Fragment slot="panel.api">

Para balancear os endereços pela API v3, primeiro leia o `origin_key` da origin que você quer alterar. A requisição carrega o header `Accept: application/json; version=3`:

```bash
curl --request GET \
  --url https://api.azionapi.net/edge_applications/<application-id> \
  --header 'Accept: application/json; version=3' \
  --header 'Authorization: Token [TOKEN VALUE]'
```

A resposta carrega `origin_key`, um UUID, ao lado de `origin_type` e do nome da origin:

```json
{
  "results": {
    "origin_id": 123456,
    "origin_key": "bdcd7003-ba53-4ed8-8ca0-05b1357cdafd",
    "name": "Default Origin",
    "origin_type": "single_origin"
  }
}
```

Depois envie um `PATCH` para essa origin com a lista completa de endereços:

```bash
curl --request PATCH \
  --url https://api.azionapi.net/edge_applications/<application-id>/origins/<origin-key> \
  --header 'Accept: application/json; version=3' \
  --header 'Content-Type: application/json' \
  --header 'Authorization: Token [TOKEN VALUE]' \
  --data '{
  "name": "Default Origin (RR3)",
  "origin_type": "load_balancer",
  "method": "round_robin",
  "host_header": "${host}",
  "addresses": [
    { "address": "example.com", "weight": 3, "server_role": "primary", "is_active": true },
    { "address": "example.net", "weight": 2, "server_role": "primary", "is_active": true },
    { "address": "example.org", "weight": 1, "server_role": "backup", "is_active": true }
  ]
}'
```

| Chave | O que carrega |
| --- | --- |
| `origin_type` | `load_balancer` transforma a origin em balanceada. Load Balancer precisa estar ativo |
| `method` | O método de balanceamento, como `round_robin` |
| `addresses[].weight` | A parcela de requisições do endereço. Omitido, vale `1` |
| `addresses[].server_role` | `primary`, ou `backup` para um endereço que só atende quando os primários falham |
| `addresses[].is_active` | `false` mantém o endereço na lista e fora da rotação |

A resposta devolve a origin como a Azion a armazenou, com os endereços na ordem em que você os enviou:

```json
{
  "results": {
    "origin_id": 123456,
    "origin_key": "bdcd7003-ba53-4ed8-8ca0-05b1357cdafd",
    "name": "Default Origin (RR3)",
    "origin_type": "load_balancer",
    "method": "round_robin",
    "addresses": [
      { "address": "example.com", "weight": 3, "server_role": "primary", "is_active": true },
      { "address": "example.net", "weight": 2, "server_role": "primary", "is_active": true },
      { "address": "example.org", "weight": 1, "server_role": "backup", "is_active": true }
    ]
  }
}
```

</Fragment>

</Tabs>


Em uma Application v3, o behavior de regra que define a origin é _Set Origin_, em lugar de _Set Connector_. Para cada campo da origin, consulte [Origins](/pt-br/documentacao/plataforma/connectors/origins/).
