Você pode colocar um app Vue na Azion a partir de um template no Azion Console, de um repositório do GitHub que você tem ou com a [Azion CLI](/pt-br/documentacao/devtools/cli/). Os três caminhos terminam com o app no ar em um domínio da Azion.

A Azion executa um app Vue como uma aplicação estática. O deploy envia os arquivos do build para um bucket de armazenamento, e uma [aplicação](/pt-br/documentacao/plataforma/applications/) os serve a partir dele. Para ver de quais outros frameworks a Azion faz o build, consulte [Compatibilidade com web frameworks](/pt-br/documentacao/devtools/runtime/frameworks/compatibilidade-frameworks/).

## Templates Vue

Um template Vue é um projeto inicial completo de que a Azion faz o build e o deploy para você. O seletor de templates do preset Vue no `azion init` inclui estes três:

| Template | Uso |
| --- | --- |
| [Vue.js with ButterCMS Starter Project](/pt-br/documentacao/guias/desenvolvimento-de-aplicacoes/frameworks/butter-templates-collection/) | Integração com CMS |
| [Vue3/Vite Boilerplate](/pt-br/documentacao/guias/desenvolvimento-de-aplicacoes/frameworks/vue-vite-boilerplate/) | Single-page application com Vite |
| [Vue Boilerplate](/pt-br/documentacao/guias/desenvolvimento-de-aplicacoes/frameworks/vue-boilerplate/) | Single-page application |

Cada template tem link para o seu guia. O starter ButterCMS compartilha o guia com os templates ButterCMS de outros frameworks. Para mais informações sobre templates, consulte [Marketplace da Azion](/pt-br/documentacao/plataforma/marketplace/).

## Faça o deploy do app

Todo caminho faz o build do projeto Vue e cria os recursos que o servem na Azion. Use o painel do caminho que você escolheu:

<Tabs client:visible sharedStore="interface">

<Fragment slot="panel.console">

### Console

Para fazer o deploy de um template Vue pelo Azion Console:

<DocSteps>
  <DocStep title="Abra os templates">

  Acesse [Azion Console](https://console.azion.com/) > **Create** > **Templates**.

  </DocStep>
  <DocStep title="Pesquise por Vue">

  Em **Search by name, framework, or keyword**, digite `Vue`.

  </DocStep>
  <DocStep title="Selecione o template para o deploy" />
  <DocStep title="Conecte sua conta do GitHub">

  Quando o formulário mostrar **GitHub Connection**, selecione **Connect with GitHub** e instale o [Azion GitHub App](/pt-br/documentacao/guias/desenvolvimento-de-aplicacoes/automacao/azion-github-app/).

  </DocStep>
  <DocStep title="Selecione um Git Scope">

  Em **Git Scope**, selecione o escopo em que o template cria o repositório dele.

  </DocStep>
  <DocStep title="Preencha as configurações que o template solicita" />
  <DocStep title="Selecione Deploy" />
</DocSteps>

Uma página de deploy abre com o **Deploy Log** do build. Em caso de sucesso, aparece **Successfully created!**, junto com a URL do domínio e um botão **Manage** que abre a aplicação.

### CLI

Para criar o projeto, execute `azion init` com um nome de projeto. No seletor de presets, selecione _Vue_ e, no seletor de templates, selecione um template:

```bash
azion init --name my-app --auto -y
```

Com `-y`, o comando instala as dependências. Com `--auto`, ele não pergunta se deve iniciar um servidor de desenvolvimento local nem se deve fazer o deploy. Para as perguntas que ele faz sem essas opções, consulte [Azion CLI init](/pt-br/documentacao/devtools/cli/init/). Com o template _Vue Boilerplate_, a saída é:

O projeto é criado em uma pasta `my-app`. O `azion.config.cjs` dele define o preset `vue` e envia `./.edge/assets` para um bucket de armazenamento que os workloads só podem ler. O arquivo também gera duas regras de requisição para a aplicação:

- `Deliver Static Assets and Set Cache Policy` serve a partir do bucket os arquivos com extensão estática, como `.js` ou `.css`. A política de cache dela define `maxAgeSeconds` como `7200` para o navegador e para o cache.
- `Redirect to index.html` reescreve as requisições de rotas para `/index.html`, para que o roteador do Vue resolva cada rota no navegador.

Para todas as configurações desse arquivo, consulte [azion.config.js](/pt-br/documentacao/devtools/cli/azion-config-js/).

Para fazer o build do app, entre na pasta do projeto e execute `azion build`:

```bash
cd my-app
azion build
```

Para fazer o deploy do app, execute `azion deploy` na pasta do projeto:

```bash
azion deploy
```

O deploy envia o projeto e abre a página do Azion Console que o acompanha. Se o navegador não abrir, use a URL dessa página, que o comando imprime. No final, o comando imprime a URL do domínio do app. Para a saída completa e as flags que alteram um deploy, consulte [Azion CLI deploy](/pt-br/documentacao/devtools/cli/deploy/).

Para executar o app na sua máquina antes, consulte [Azion CLI dev](/pt-br/documentacao/devtools/cli/dev-comando/). Para um projeto Vue que você já tem, execute `azion link` na pasta dele e selecione o preset Vue, como descreve [Azion CLI link](/pt-br/documentacao/devtools/cli/link-comando/).

### GitHub

Para fazer o deploy de um projeto Vue a partir de um repositório do GitHub:

<DocSteps>
  <DocStep title="Abra o Import from GitHub">

  Acesse [Azion Console](https://console.azion.com/) > **Create** > **Import from GitHub**.

  </DocStep>
  <DocStep title="Selecione o card de importação">

  Na aba **Import from GitHub**, selecione o card. A página **Import from GitHub** abre.

  </DocStep>
  <DocStep title="Conecte sua conta do GitHub">

  Se nenhuma conta do GitHub estiver conectada ainda, selecione **Connect with GitHub** em **GitHub Connection**.

  </DocStep>
  <DocStep title="Selecione o repositório">

  Selecione um **Git Scope** e depois selecione o **Repository** que contém o projeto Vue.

  </DocStep>
  <DocStep title="Dê um nome à aplicação">

  Em **General**, digite um **Application Name**. O nome do repositório preenche o campo primeiro. O bucket de armazenamento e a [function](/pt-br/documentacao/plataforma/functions/) recebem o nome que você digitar.

  </DocStep>
  <DocStep title="Selecione o preset Vue">

  Defina **Preset** como _Vue_.

  </DocStep>
  <DocStep title="Defina o diretório raiz">

  Em **Root Directory**, mantenha `/` se o projeto Vue estiver na raiz do repositório.

  </DocStep>
  <DocStep title="Digite o comando de instalação">

  Em **Install Command**, digite `npm install`.

  </DocStep>
  <DocStep title="Selecione Deploy" />
</DocSteps>

Uma página de deploy abre, com o título `Deploy:` e o nome da aplicação, e com o **Deploy Log** do build. Em caso de sucesso, aparece **Successfully created!** com a URL do domínio.

Para definir **Variables** ou qualquer outro campo do formulário de importação, consulte [Importe um projeto do GitHub](/pt-br/documentacao/guias/desenvolvimento-de-aplicacoes/automacao/importar-um-projeto-existente-do-github/).

## Faça o deploy de um app Vue com o build pronto

Quando você mesmo faz o build do app, como com `npm run build`, o Vite grava o app na pasta `dist`. A Azion CLI pode fazer o deploy dessa pasta. Execute os comandos na pasta do projeto, que tem o `package.json` e o código-fonte do app.

O primeiro deploy do projeto executa o `vite build` antes de enviar os arquivos. Uma pasta que tem só a `dist` não consegue executar esse build, então o deploy dela falha.

:::note[nota]
Estes passos precisam da Azion CLI 4.27.0 ou de uma versão seguinte. Para ver a versão instalada, execute `azion --version`. Para atualizar a CLI, consulte [Instalar a Azion CLI](/pt-br/documentacao/devtools/cli/#instalar-a-azion-cli).
:::

Para instalar as dependências do projeto, execute este comando na pasta do projeto:

<Code client:visible lang="bash" code={`npm install`} />

O comando grava a pasta `node_modules`. O `azion link` precisa das dependências para gerar a configuração do preset.

Para vincular o projeto com o preset Vue, execute este comando:

<Code client:visible lang="bash" code={`azion link --name <your-app-name> --preset vue --auto`} />

Substitua `<your-app-name>` por um nome para a Application. Com `--auto`, o comando não faz nenhuma pergunta e não faz o build nem o deploy do projeto. Ele grava a pasta `azion` e um arquivo `azion.config`, e imprime `Project successfully configured`.

Para fazer o primeiro deploy do app, execute o deploy com o build na sua máquina:

<Code client:visible lang="bash" code={`azion deploy --local`} />

O primeiro deploy executa o `vite build`, que grava a `dist` de novo, e envia o resultado. O comando termina com o domínio do app:

```text
Your Application was deployed successfully

To visualize your application access the Domain: https://xxxxxxxxxx.map.azionedge.net
Your application is being deployed to all Azion Edge Locations and it might take a few minutes.
```

Depois de uma mudança no app, faça o build com o seu próprio comando:

<Code client:visible lang="bash" code={`npm run build`} />

O Vite grava o app em `dist`:

```text
vite v8.3.8 building client environment for production...
…
dist/index.html                  0.45 kB │ gzip:  0.29 kB
dist/assets/vite-BF8QNONU.svg    8.70 kB │ gzip:  1.60 kB
dist/assets/hero-CLDdwZDr.png   13.05 kB
dist/assets/index-CsUDhMuy.css   4.10 kB │ gzip:  1.46 kB
dist/assets/index-CxOOyHPi.js   66.48 kB │ gzip: 26.09 kB

✓ built in 310ms
```

:::caution[Atenção]
Mantenha `--local` no próximo comando. Sem essa flag, o deploy executa o build na Azion e ignora `--skip-framework-build`. A Azion então executa o `vite build` de novo e envia a saída dele em vez da sua pasta `dist`.
:::

Para fazer o deploy dessa pasta `dist` sem executar o `vite build` de novo, execute o deploy com `--skip-framework-build`:

<Code client:visible lang="bash" code={`azion deploy --local --skip-framework-build`} />

A saída mostra `Skipping framework build`. O preset `vue` copia a pasta que o `build.outDir` define no `vite.config`, a `dist` por padrão, para `.edge/assets`. O deploy envia essa pasta com um novo prefixo de storage. Um prefixo de storage é a pasta do bucket que guarda os arquivos de um deploy.

O comando termina com o mesmo domínio. Para o efeito de cada flag de skip no primeiro deploy ou sem `--local`, consulte [flags do Azion CLI deploy](/pt-br/documentacao/devtools/cli/deploy/#flags).

A mensagem de sucesso não lista os arquivos que o deploy enviou. Para verificá-los, liste os objetos do bucket:

<Code client:visible lang="bash" code={`azion list storage object --bucket-name <your-bucket-name> --page-size 1000`} />

Substitua `<your-bucket-name>` pelo campo `bucket` do `azion/azion.json`. O bucket guarda os arquivos dos deploys anteriores, cada um com o seu prefixo de storage. A lista começa pelas chaves mais antigas, e uma página tem 50 objetos por padrão. Quando a página termina antes dos arquivos do último deploy, execute o comando de novo com `--next-page`.

Depois de um deploy bem-sucedido, as chaves dele começam com o campo `prefix` do `azion/azion.json`:

```text
KEY                                       LAST MODIFIED
20260101120000/assets/hero-CLDdwZDr.png   2026-01-01 12:00:57.496 +0000 UTC
…
20260101120100/assets/hero-CLDdwZDr.png   2026-01-01 12:01:30.796 +0000 UTC
20260101120100/assets/index-CsUDhMuy.css  2026-01-01 12:01:30.79 +0000 UTC
20260101120100/assets/index-CxOOyHPi.js   2026-01-01 12:01:30.805 +0000 UTC
20260101120100/assets/vite-BF8QNONU.svg   2026-01-01 12:01:30.797 +0000 UTC

```

Cada arquivo da `dist` aparece uma vez no prefixo do último deploy.

## Verifique o app

Cada caminho retorna a URL do domínio da Azion do app, no formato `https://xxxxxxxxxx.map.azionedge.net`. A página do deploy no Console mostra a URL, e o `azion deploy` a imprime ao terminar. Abra a URL em um navegador para carregar o app Vue.

O primeiro deploy pode levar vários minutos para responder em todas as localidades; os deploys seguintes levam cerca de dois minutos. Uma localidade que ainda não recebeu o app responde com uma página `404` que diz `There's nothing here yet`. Se você receber essa página, aguarde e solicite a URL novamente.
