Você pode fazer o deploy de um site Hugo na Azion a partir de um template no Azion Console ou com a [Azion CLI](/pt-br/documentacao/devtools/cli/). Os dois caminhos deixam o site em execução na Azion, respondendo em um domínio da Azion.

A Azion serve um site Hugo como uma aplicação estática. O build grava o site em `./public`, e o deploy envia essa pasta para um bucket de armazenamento que uma [aplicação](/pt-br/documentacao/plataforma/applications/) serve. Para a lista completa de frameworks de que a Azion faz o build, consulte [Compatibilidade com web frameworks](/pt-br/documentacao/devtools/runtime/frameworks/compatibilidade-frameworks/).

---

## Pré-requisitos

- Uma conta na Azion. Para criar uma, consulte [Criar uma conta](/pt-br/documentacao/fundamentos/criar-uma-conta/).

<Tabs client:visible sharedStore="interface">

<Fragment slot="panel.console">

- Acesso ao Azion Console. Para entrar, consulte [Como acessar o Azion Console](/pt-br/documentacao/guias/plataforma/conta-e-billing/como-acessar-o-azion-console/).
- Uma conta no GitHub. O formulário do template conecta essa conta quando a solicita.

</Fragment>

<Fragment slot="panel.cli">

- A Azion CLI instalada e com login feito. Para configurá-la, consulte [Primeiros passos com a Azion CLI](/pt-br/documentacao/devtools/cli/primeiros-passos/).
- Node.js 18 ou posterior e o npm. O Hugo Boilerplate instala o Hugo como uma dependência npm, então você não instala o Hugo separadamente.
- Um terminal e um editor de código.

</Fragment>

</Tabs>

## Templates Hugo

A Azion faz o deploy de um template Hugo como um projeto pronto. O caminho pelo Console começa por um destes templates, e a CLI oferece os mesmos três:

| Template | Uso |
| --- | --- |
| [Hugo Boilerplate](/pt-br/documentacao/guias/desenvolvimento-de-aplicacoes/frameworks/hugo-boilerplate/) | Projeto inicial |
| Influencer Hugo | Vitrine de produtos |
| Vex Hugo | Landing page de produto |

O Hugo Boilerplate tem um guia próprio, com link na tabela. Influencer Hugo e Vex Hugo compartilham um guia: [Deploy de e-commerce com Hugo usando templates](/pt-br/documentacao/guias/desenvolvimento-de-aplicacoes/frameworks/hugo-ecommerce-collection/). Para mais informações sobre templates, consulte [Marketplace da Azion](/pt-br/documentacao/plataforma/marketplace/).

## Faça o deploy do site

Os dois caminhos fazem o build do projeto Hugo e criam os recursos que o servem na Azion. Siga o painel do seu caminho:

<Tabs client:visible sharedStore="interface">

<Fragment slot="panel.console">

Para fazer o deploy de um template Hugo pelo Azion Console:

<DocSteps>
  <DocStep title="Abra os templates">

  Acesse [Azion Console](https://console.azion.com/) > **Create** > **Templates**.

  </DocStep>
  <DocStep title="Pesquise por Hugo">

  Em **Search by name, framework, or keyword**, digite `Hugo`.

  </DocStep>
  <DocStep title="Selecione o template Hugo que você quer" />
  <DocStep title="Conecte sua conta do GitHub">

  Quando o formulário mostrar **GitHub Connection**, selecione **Connect with GitHub** e instale o [Azion GitHub App](/pt-br/documentacao/guias/desenvolvimento-de-aplicacoes/automacao/azion-github-app/).

  </DocStep>
  <DocStep title="Selecione um Git Scope">

  Em **Git Scope**, selecione o escopo do template.

  </DocStep>
  <DocStep title="Preencha as configurações que o template solicita" />
  <DocStep title="Selecione Deploy" />
</DocSteps>

A página do deploy mostra o **Deploy Log** enquanto o projeto passa pelo build. Em caso de sucesso, ela mostra **Successfully created!**, a URL do domínio e um botão **Manage** que abre a aplicação.

</Fragment>

<Fragment slot="panel.cli">

Execute `azion init` com um nome de projeto. No primeiro seletor, selecione _Hugo_; no segundo, selecione um template:

```bash
azion init --name my-site --auto -y
```

Com `-y`, o comando instala as dependências. Com `--auto`, ele não pergunta sobre um servidor de desenvolvimento local nem sobre um deploy. O projeto fica em uma pasta `my-site`. O `azion.config.cjs` dele define o preset `hugo` e envia `./public` para um bucket de armazenamento que os workloads só podem ler. Para todas as configurações desse arquivo, consulte [azion.config.js](/pt-br/documentacao/devtools/cli/azion-config-js/).

Para fazer o build do site, execute `azion build` na pasta do projeto:

```bash
cd my-site
azion build
```

Para fazer o deploy do site, execute `azion deploy` na pasta do projeto:

```bash
azion deploy
```

O deploy envia o projeto e abre a página do Console que o acompanha, e imprime a URL dessa página caso nenhum navegador abra. No final, ele imprime a URL do domínio do site. Para a saída completa e todas as flags, consulte [Azion CLI deploy](/pt-br/documentacao/devtools/cli/deploy/).

Para visualizar o site na sua máquina antes, consulte [Azion CLI dev](/pt-br/documentacao/devtools/cli/dev-comando/). Para um projeto Hugo que você já tem, execute `azion link` na pasta dele e selecione o preset Hugo, como descreve [Azion CLI link](/pt-br/documentacao/devtools/cli/link-comando/).

## Verifique o site

O deploy fornece a URL do domínio da Azion do site, no formato `https://xxxxxxxxxx.map.azionedge.net`. A página do deploy no Console mostra essa URL, e o `azion deploy` a imprime ao terminar. Abra essa URL em um navegador para ver o site Hugo.

O primeiro deploy pode levar vários minutos para responder em todas as localidades; os deploys seguintes levam cerca de dois minutos. Uma localidade que ainda não recebeu o site responde com uma página `404` que diz `There's nothing here yet`. Se você receber essa página, aguarde e solicite a URL novamente.
