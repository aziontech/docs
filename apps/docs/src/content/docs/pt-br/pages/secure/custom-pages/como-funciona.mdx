Quando uma origem não encontra um recurso, ou não responde a tempo, o cliente recebe uma resposta de erro, como `404` ou `504`. Uma custom page substitui essa resposta por um conteúdo que você escolhe.

[Custom Pages](/pt-br/documentacao/plataforma/custom-pages/) é um recurso da plataforma que substitui por uma página sua a resposta de erro retornada por um [Connector](/pt-br/documentacao/plataforma/connectors/), uma página por status code de erro. Na API v4, Custom Pages substitui Error Responses, as configurações de página de erro de uma Application na API v3. Para uma Application que ainda roda na API v3, consulte [Error Responses](/pt-br/documentacao/plataforma/custom-pages/error-responses/).

Esta página cobre os mecanismos, e não os campos: todos os campos estão em [Configurações de custom page](/pt-br/documentacao/plataforma/custom-pages/configuracoes/), e todos os limites estão em [Limites do Custom Pages](/pt-br/documentacao/plataforma/custom-pages/limites/). Para o caminho de uma requisição por Custom Pages, com um diagrama, consulte [Caminho da requisição](/pt-br/documentacao/plataforma/custom-pages/#caminho-da-requisicao). As seções cobrem, nesta ordem, as respostas de erro, as custom pages e os conjuntos de custom pages, o conteúdo da página em um Connector, os status codes que uma página pode substituir, a página de erro padrão da Azion e o deployment.

---

## Respostas de erro

Uma resposta de erro traz um status code que diz que a requisição falhou: um erro de cliente (4xx) ou um erro de servidor (5xx). Na Azion, a Application envia uma requisição à origem por um Connector, e o Connector responde com um status code. Uma custom page age depois que a Application recebe essa resposta, e o status code decide se uma página se aplica.

---

## Custom pages e conjuntos de custom pages

Uma custom page substitui a resposta de erro de um status code. Um conjunto de custom pages é a lista nomeada que agrupa essas páginas. Quando o Connector responde com um status code, a Azion procura uma página com esse código no conjunto de custom pages que o deployment do [Workload](/pt-br/documentacao/plataforma/workloads/) define. Cada página age apenas sobre o status code que lista, como `"404"`, então um conjunto contém uma página para cada código que substitui.

Quando uma página corresponde, o cliente recebe o conteúdo da página no lugar da resposta. A resposta não traz redirecionamento nem header `Location`, então o navegador permanece na URL que pediu. Um conjunto contém pelo menos uma página, como informa [Limites do Custom Pages](/pt-br/documentacao/plataforma/custom-pages/limites/).

---

## Conteúdo da página em um Connector

Uma página do tipo `page_connector` define um Connector e o caminho do conteúdo da página nesse Connector. A Azion busca o conteúdo no Connector da página, no `uri` da página. O `ttl` da página define o tempo de cache desse conteúdo. Uma página também pode definir `custom_status_code`, o status code que o cliente recebe no lugar do original.

Por exemplo, a sua origem responde `404` para a página de um produto removido. Uma página para o código `404` serve, então, o documento do `uri` dela, como `/myerrors/404.html`, ainda com o status `404`, e o navegador mostra a sua página.

Para o tipo e o padrão de cada campo, consulte [Campos da página](/pt-br/documentacao/plataforma/custom-pages/configuracoes/#campos-da-pagina).

---

## Status codes que uma página pode substituir

Uma página só substitui um dos 22 status codes de uma lista fixa: 16 erros de cliente (4xx) e seis erros de servidor (5xx). Para cada código da lista e o que ele significa quando o Connector o retorna, consulte [Status codes](/pt-br/documentacao/plataforma/custom-pages/configuracoes/#status-codes).

---

## Página de erro padrão da Azion

Quando o conjunto de custom pages não tem página para um status code, o cliente recebe a resposta do Connector sem alteração. Oito códigos são a exceção: `400`, `401`, `403`, `406`, `500`, `502`, `503` e `504` recebem a página de erro padrão da Azion. Uma página para um desses oito códigos substitui a página de erro padrão da Azion pela sua.

Por exemplo, um conjunto que contém apenas uma página `404` responde a um `502` do Connector com a página de erro padrão da Azion, e não com a resposta da origem. Um Workload cujo deployment não define um conjunto de custom pages entrega toda resposta sem alteração.

---

## O deployment

Um [Workload](/pt-br/documentacao/plataforma/workloads/) usa um conjunto de custom pages somente depois que o deployment desse Workload define esse conjunto. Um Workload guarda no máximo um deployment, então um conjunto de custom pages cobre todos os hostnames do Workload. Para os campos do deployment, consulte [Configurações de Workload](/pt-br/documentacao/plataforma/workloads/configuracoes/#deployment).

Atribuir um conjunto é uma mudança no deployment do Workload, e essa mudança se propaga. Ela se espalha pela infraestrutura distribuída da Azion, data center por data center, ao longo de vários minutos. Enquanto isso, as requisições podem receber a configuração anterior ou a atualizada, dependendo do data center que responde. Por isso, a Azion não garante quando um conjunto atribuído começa a ser servido, como explica [Propagação](/pt-br/documentacao/plataforma/workloads/como-funciona/#propagacao).

Para definir o conjunto de custom pages no deployment, consulte [Personalize uma página de erro](/pt-br/documentacao/guias/desenvolvimento-de-aplicacoes/primeiros-passos/personalizar-pagina-resposta-erro/#atribua-o-conjunto-no-deployment-do-workload).
