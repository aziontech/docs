Você pode criar uma exceção do WAF que impede uma regra interna de pontuar os valores dos headers da requisição em um caminho pela API. Para uma exceção em um parâmetro de query string, com o Console e a CLI, consulte [Isente valores de query string de uma regra do WAF](/pt-br/documentacao/guias/seguranca-de-aplicacoes/firewall-e-waf/isentar-parametro-query/).

O exemplo impede que a regra `1005`, a regra do caractere pipe, pontue os headers das requisições a `/account`, no rule set `<waf-id>`. Substitua-os pela sua regra, pelo seu caminho e pelo seu rule set.

---

## Pré-requisitos

- O WAF rule set que bloqueou a requisição e o ID dele.
- O ID da regra interna que correspondeu a um header, lido no campo `wafMatch` do registro da requisição, como `0:1005:HEADERS:cookie`. Para lê-lo, consulte [Leia o score de uma requisição bloqueada](/pt-br/documentacao/guias/seguranca-de-aplicacoes/firewall-e-waf/ler-score-do-bloqueio/).
- Um [personal token](/pt-br/documentacao/guias/plataforma/conta-e-billing/personal-tokens/).

---

## Crie a exceção

A condição é `any_http_header_value`, que cobre o valor de todo header da requisição. Uma condição que indica um header, `specific_http_header_name` com `cookie` ou `HTTP_COOKIE`, é aceita pela API, e nos testes ela não eliminou uma correspondência no header `Cookie`.

Uma condição mais restrita carrega o nome do header em `value`: `{"match": "specific_http_header_value", "value": "cookie"}`. Em outro teste, com a regra `1005` e sem `path`, ela eliminou a correspondência apenas no header `Cookie`. Um parâmetro de query string da mesma requisição ainda foi recusado.

Para criar a exceção, envie uma requisição `POST` para o endpoint de exceções do rule set, com o ID da regra, o caminho e a condição:

```bash
curl --request POST \
  --url https://api.azion.com/v4/workspace/wafs/<waf-id>/exceptions \
  --header 'Accept: application/json' \
  --header 'Authorization: Token [TOKEN VALUE]' \
  --header 'Content-Type: application/json' \
  --data '{
  "rule_id": 1005,
  "name": "Allow the pipe character in request headers",
  "path": "/account",
  "operator": "contains",
  "active": true,
  "conditions": [
    { "match": "any_http_header_value" }
  ]
}'
```

A API responde `202` e retorna a exceção:

```json
{
  "state": "pending",
  "data": {
    "id": <exception-id>,
    "rule_id": 1005,
    "name": "Allow the pipe character in request headers",
    "path": "/account",
    "conditions": [
      { "match": "any_http_header_value" }
    ],
    "operator": "contains",
    "active": true,
    "last_editor": "user@example.com",
    "last_modified": "2026-01-01T12:00:00.000000Z"
  }
}
```

A regra `1005` para de pontuar os valores dos headers das requisições a `/account` e continua pontuando a query string delas. Em um teste, a exceção eliminou a regra em um header `Cookie` com `|`, e um argumento de query string com `|` no mesmo caminho ainda recebeu `400`. Envie uma requisição a que a regra correspondia antes e verifique se ela agora passa.

:::note[nota]
`any_http_header_value` não carrega nome de header. Uma chave `name` enviada com ela é descartada em vez de recusada: a API responde `202` e armazena apenas `{"match": "any_http_header_value"}`. Em um teste com `contains`, a exceção se aplicou ao seu `path` exato: um caminho mais longo que começava com ele, ou que o continha, ainda recebeu `400` para o mesmo header `Cookie`. Uma exceção sem `path` se aplicou em todo caminho testado.
:::

Para as chaves que cada uma das quinze match zones carrega, consulte [Configurações de exceção](/pt-br/documentacao/plataforma/firewall/waf/custom-allowed-rules/#match-zones).
