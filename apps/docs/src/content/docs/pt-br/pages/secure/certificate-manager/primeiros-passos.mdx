Este guia orienta você a vincular o seu primeiro certificado próprio a um [Workload](/pt-br/documentacao/plataforma/workloads/) com [Certificate Manager](/pt-br/documentacao/plataforma/workloads/#certificate-manager).

- Envie um certificado de servidor e a chave privada dele ao Certificate Manager.
- Vincule o certificado ao seu Workload.
- Confirme que Certificate Manager informa o certificado como ativo.

Três elementos participam, e cada um se liga ao seguinte:

1. O **certificado** é um certificado de servidor que você envia ao Certificate Manager com a chave privada dele. A API o armazena com `type` definido como `edge_certificate`. O status dele fica `inactive` até que você o vincule a um Workload.
2. O **Workload** guarda o certificado no campo `tls.certificate` e o apresenta para os seus domínios. Enquanto esse campo for `null`, o Workload apresenta o certificado SAN da Azion. Esse é o certificado da própria Azion, e ele lista os hostnames que cobre como Subject Alternative Names (SANs).
3. Os **domínios** do Workload são os hostnames que o certificado precisa cobrir. A API não compara os nomes do certificado com os domínios, então aceita um certificado que não os cobre. A verificação dos nomes feita pelo cliente então falha.

Um certificado enviado não protege nenhum tráfego até que você o vincule a um Workload. O certificado SAN da Azion cobre somente o workload domain e o hostname `azion.app`. Um Workload continua a apresentá-lo para esses dois hostnames depois que você vincula o seu próprio certificado. Este guia altera somente as configurações de `tls` do Workload e mantém os domínios, as portas e o deployment dele como estão.

Para que a Azion solicite um certificado ao Let's Encrypt e o renove por você, consulte [Solicite um certificado Let's Encrypt](/pt-br/documentacao/guias/seguranca-de-aplicacoes/tls-e-certificados/como-gerar-um-certificado-lets-encrypt/). No Azion Console, o campo **Digital Certificate** do Workload também oferece os presets do Let's Encrypt, descritos em [Certificados](/pt-br/documentacao/plataforma/workloads/certificate-manager/certificados/#certificado-lets-encrypt).

## Envie o certificado

Um certificado de servidor contém o certificado e a chave privada dele. Depois de salva, a chave privada não pode ser lida de volta pelo Azion Console nem pela API. Você pode enviar o certificado sozinho ou com os certificados intermediários dele.

<Tabs client:visible sharedStore="interface">

<Fragment slot="panel.console">

### Console

Para enviar o certificado no Azion Console:

<DocSteps>
  <DocStep title="Abra a página Certificate Manager">

  Acesse [Azion Console](https://console.azion.com/) > **Certificate Manager**.

  </DocStep>
  <DocStep title="Inicie um certificado">

  Selecione **Create Digital Certificate**. A página **Create Digital Certificate** abre.

  </DocStep>
  <DocStep title="Selecione o preset Server Certificate" />
  <DocStep title="Nomeie o certificado">

  Em **Name**, digite um nome para o certificado, como `my-certificate`.

  </DocStep>
  <DocStep title="Cole o certificado">

  Em **Certificate**, cole o certificado PEM, incluindo as linhas `-----BEGIN CERTIFICATE-----` e `-----END CERTIFICATE-----`. O texto de ajuda diz "Intermediate certificates are accepted."

  </DocStep>
  <DocStep title="Cole a chave privada">

  Em **Private Key**, cole a chave privada PEM, incluindo as linhas `-----BEGIN` e `-----END` dela.

  </DocStep>
  <DocStep title="Selecione Create" />
</DocSteps>

O certificado aparece na lista de **Certificate Manager** como **TLS Certificate**. Ele fica `inactive` até que você o vincule a um Workload.

</Fragment>

<Fragment slot="panel.cli">

### CLI

Para enviar o certificado com a Azion CLI, passe os caminhos dos dois arquivos PEM:

<Code client:visible lang="bash" code={`azion create digital-certificate --name my-certificate \\
  --certificate server.pem --private-key server.key`} />

O comando imprime o ID do certificado novo:

```text
Created Digital Certificate with ID <certificate-id>
```

Anote o ID para vincular o certificado ao seu Workload. Liste os certificados da sua conta:

<Code client:visible lang="bash" code={`azion list digital-certificate --details`} />

A saída mostra o seu certificado com o tipo `edge_certificate` e o status `inactive`:

```text
ID                NAME            STATUS    ISSUER  VALIDITY                   TYPE              MANAGED  LAST EDITOR   LAST MODIFIED
<certificate-id>  my-certificate  inactive          2026-01-31 12:00:00+00:00  edge_certificate  false    <your-email>  2026-01-01 12:00:00.000000 +0000 UTC
```

O certificado existe no Certificate Manager, e nenhum Workload o usa ainda.

</Fragment>

<Fragment slot="panel.api">

### API

Para enviar o certificado com a API, envie uma requisição `POST` para o endpoint de certificados. `type` definido como `edge_certificate` faz dele um certificado de servidor. No corpo, `certificate` e `private_key` são strings JSON. Escreva cada um como uma única string contínua que mantém as linhas `-----BEGIN` e `-----END`, com cada quebra de linha escrita como `\n`. Substitua `[TOKEN VALUE]` pelo seu personal token:

<Code client:visible lang="bash" code={`curl --request POST \\
  --url https://api.azion.com/v4/workspace/tls/certificates \\
  --header 'Accept: application/json' \\
  --header 'Authorization: Token [TOKEN VALUE]' \\
  --header 'Content-Type: application/json' \\
  --data '{
  "name": "my-certificate",
  "type": "edge_certificate",
  "certificate": "-----BEGIN CERTIFICATE-----\\n<certificate-body>\\n-----END CERTIFICATE-----\\n",
  "private_key": "-----BEGIN PRIVATE KEY-----\\n<private-key-body>\\n-----END PRIVATE KEY-----\\n"
}'`} />

A API responde com `201` e retorna o certificado novo. Anote o `id` dele para vincular o certificado ao seu Workload. O certificado existe no Certificate Manager, e nenhum Workload o usa ainda.

</Fragment>

</Tabs>

## Vincule o certificado ao seu Workload

Um Workload apresenta um certificado de servidor para os seus domínios somente depois que você o vincula no campo `tls.certificate` do Workload. Antes de vincular o certificado, verifique se ele cobre os domínios do Workload. A API aceita um certificado que não os cobre, e a verificação dos nomes feita pelo cliente então falha.

<Tabs client:visible sharedStore="interface">

<Fragment slot="panel.console">

### Console

Para vincular o certificado no Azion Console:

<DocSteps>
  <DocStep title="Abra a página Workloads">

  Acesse [Azion Console](https://console.azion.com/) > **Workloads**.

  </DocStep>
  <DocStep title="Abra o seu Workload">

  Selecione o seu Workload. A página **Edit Workload** abre.

  </DocStep>
  <DocStep title="Ative o suporte a HTTPS">

  Em **Protocol Settings**, ative **HTTPS support** se estiver desativado. **Digital Certificate** aparece somente enquanto ele estiver ativado.

  </DocStep>
  <DocStep title="Selecione o seu certificado">

  Em **Digital Certificate**, selecione o seu certificado no grupo **My certificates**.

  </DocStep>
  <DocStep title="Selecione Save" />
</DocSteps>

Azion Console mostra a mensagem "Your workload has been updated". O seu certificado está vinculado ao Workload em `tls.certificate`.

</Fragment>

<Fragment slot="panel.cli">

### CLI

Para vincular o certificado com a Azion CLI, salve este JSON como `tls.json`, com os seus IDs no lugar dos placeholders:

<Code client:visible lang="json" code={`{
  "id": <workload-id>,
  "tls": {
    "certificate": <certificate-id>,
    "ciphers": 7,
    "minimum_version": "tls_1_3"
  }
}`} />

O arquivo envia o objeto `tls` inteiro. Ele define o seu certificado e mantém os padrões de um Workload novo: o conjunto de cifras `7` e TLS 1.3 como versão mínima. Se o seu Workload usa outros valores, envie esses valores. Envie o arquivo:

<Code client:visible lang="bash" code={`azion update workload --file tls.json`} />

O comando imprime o ID do Workload:

```text
Updated Workload with ID <workload-id>
```

O seu certificado está vinculado ao Workload em `tls.certificate`.

</Fragment>

<Fragment slot="panel.api">

### API

Para vincular o certificado com a API, envie uma requisição `PATCH` para o seu Workload com o objeto `tls`. Ele define o seu certificado e mantém os padrões de um Workload novo: o conjunto de cifras `7` e TLS 1.3 como versão mínima. Se o seu Workload usa outros valores, envie esses valores. Substitua `<workload-id>` e `<certificate-id>`:

<Code client:visible lang="bash" code={`curl --request PATCH \\
  --url https://api.azion.com/v4/workspace/workloads/<workload-id> \\
  --header 'Accept: application/json' \\
  --header 'Authorization: Token [TOKEN VALUE]' \\
  --header 'Content-Type: application/json' \\
  --data '{
  "tls": {
    "certificate": <certificate-id>,
    "ciphers": 7,
    "minimum_version": "tls_1_3"
  }
}'`} />

A API aceita a atualização, e o seu certificado está vinculado ao Workload em `tls.certificate`.

</Fragment>

</Tabs>

## Confirme que o certificado está ativo

Certificate Manager informa um certificado como `active` assim que você o vincula a um Workload. O status mostra que o seu Workload usa o certificado.

<Tabs client:visible sharedStore="interface">

<Fragment slot="panel.console">

### Console

Para confirmar o status no Azion Console:

<DocSteps>
  <DocStep title="Abra a página Certificate Manager">

  Acesse [Azion Console](https://console.azion.com/) > **Certificate Manager**.

  </DocStep>
  <DocStep title="Encontre o seu certificado">

  Encontre o seu certificado na lista e confirme que o status dele é `active`. Um certificado `pending` mostra um ícone de aviso, e um certificado `failed` mostra um ícone de erro com o motivo.

  </DocStep>
</DocSteps>

O seu certificado está ativo, e o seu Workload o usa.

</Fragment>

<Fragment slot="panel.cli">

### CLI

Para confirmar o status com a Azion CLI, liste os certificados da sua conta:

<Code client:visible lang="bash" code={`azion list digital-certificate --details`} />

A saída mostra o seu certificado com o status `active`:

```text
ID                NAME            STATUS  ISSUER  VALIDITY                   TYPE              MANAGED  ...
<certificate-id>  my-certificate  active          2026-01-31 12:00:00+00:00  edge_certificate  false    ...
```

O seu certificado está ativo, e o seu Workload o usa.

</Fragment>

<Fragment slot="panel.api">

### API

Para confirmar o status com a API, envie uma requisição `GET` para o seu certificado. Substitua `<certificate-id>`:

<Code client:visible lang="bash" code={`curl --request GET \\
  --url https://api.azion.com/v4/workspace/tls/certificates/<certificate-id> \\
  --header 'Accept: application/json' \\
  --header 'Authorization: Token [TOKEN VALUE]'`} />

A resposta retorna o seu certificado. Estes são alguns dos campos dele, com `status` definido como `active`:

```json
{
 "id": <certificate-id>,
 "managed": false,
 "name": "my-certificate",
 "status": "active",
 "type": "edge_certificate"
}
```

O seu certificado está ativo, e o seu Workload o usa.

</Fragment>

</Tabs>

Vincular um certificado é uma alteração no Workload. A alteração leva vários minutos para chegar a toda a infraestrutura distribuída da Azion, sem duração garantida. Enquanto isso, as requisições podem encontrar a configuração antiga ou a nova. Para mais informações, consulte [Propagação](/pt-br/documentacao/plataforma/workloads/como-funciona/#propagacao).
