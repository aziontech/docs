[Certificate Manager](/pt-br/documentacao/plataforma/certificate-manager/) é um recurso da plataforma que armazena os certificados que um [Workload](/pt-br/documentacao/plataforma/workloads/) usa para Transport Layer Security (TLS): certificados de servidor, certificados de CA confiável para o TLS mútuo (mTLS) e as listas de revogação de certificados (CRLs) que um Workload lista. Ele também solicita os certificados Let's Encrypt que a Azion gerencia para você. Certificate Manager não tem quantidade incluída por plano.

---

## Escopo

- **Certificado SAN da Azion**: um Workload não precisa de nada de Certificate Manager para o seu workload domain e o seu hostname `azion.app`, porque o certificado SAN da Azion cobre os dois. Um domínio seu precisa de um certificado de servidor de Certificate Manager. Para os tipos de certificado, consulte [Certificados](/pt-br/documentacao/plataforma/certificate-manager/certificados/#tipos-de-certificado).
- **Nomes em um certificado Let's Encrypt**: um certificado solicitado pelo formulário do Workload cobre os domínios do Workload, porque o formulário preenche `common_name` e `alternative_names` a partir deles. Uma solicitação pela API nomeia os seus hostnames nesses dois campos. Um Workload recusa um domínio wildcard, então o formulário do Workload não consegue solicitar um nome wildcard. Para um nome wildcard, consulte [Certificados wildcard](/pt-br/documentacao/plataforma/certificate-manager/emissao-e-renovacao/#certificados-wildcard).
- **Serviço Let's Encrypt**: o suporte da Azion a certificados Let's Encrypt depende da disponibilidade e dos limites do serviço Let's Encrypt. Um certificado wildcard no lugar de um certificado por subdomínio reduz a chance de atingir esses limites. Para os limites, consulte os [rate limits do Let's Encrypt](https://letsencrypt.org/docs/rate-limits/).

---

## Limites padrão

Azion API verifica cada limite desta tabela em toda chamada, e uma chamada que passa de um limite falha.

| Escopo | Limite |
| --- | --- |
| Certificado, de servidor ou de CA confiável, em `certificate` | Até 1.000.000 caracteres |
| Chave privada, em `private_key` | Até 64.000 caracteres |
| CRL, em `crl` | Até 30.720.000 caracteres |
| CRLs por Workload, em `mtls.config.crl` | Até 100 |

Um limite a mais se aplica: um certificado Let's Encrypt cobre até 50 dos domínios do Workload. Para o número de domínios que um Workload lista, consulte [Limites de Workloads](/pt-br/documentacao/plataforma/workloads/limites/).
