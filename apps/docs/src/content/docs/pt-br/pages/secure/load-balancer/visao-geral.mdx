**Load Balancer** é um recurso da plataforma que balanceia requisições entre os endereços de um [Connector](/pt-br/documentacao/plataforma/connectors/) do tipo `http`, na infraestrutura distribuída da Azion. Um [balanceador de carga](https://www.azion.com/pt-br/learning/performance/o-que-e-balanceamento-de-carga/) é um proxy à frente de servidores com o mesmo conteúdo, e o método de balanceamento escolhe o servidor por requisição. Use Load Balancer para tolerar falhas de origem, favorecer servidores maiores, manter uma origem de reserva ou fixar cada IP de cliente em um servidor.

## Caminho da requisição

Ativar Load Balancer não altera nenhuma regra: um Connector continua recebendo somente as requisições das regras de [Application](/pt-br/documentacao/plataforma/applications/) que o definem. Load Balancer então escolhe qual endereço desse Connector recebe cada uma.

O diagrama acompanha uma requisição que uma regra envia a um Connector do tipo `http` com Load Balancer ativado. As setas contínuas levam a requisição, e as setas pontilhadas levam a resposta. Cada rótulo começa com o número da etapa correspondente na lista depois do diagrama.

```mermaid
flowchart TD
  Client(["Cliente"])
  App["Application"]
  Conn["Connector"]
  LB["Load Balancer"]
  Primary[["servidor de origem primário"]]
  Backup[["servidor de origem de backup"]]
  Client -->|"1. requisição"| App
  App -->|"1. Set Connector"| Conn
  Conn -->|"2. requisição"| LB
  LB -->|"3. endereço escolhido"| Primary
  LB -->|"4. todo primário falha"| Backup
  Primary -.->|"5. resposta"| Conn
  Backup -.->|"5. resposta"| Conn
  Conn -.->|"5. resposta"| App
  App -.->|"5. resposta"| Client
```

1. Uma Application recebe a requisição do cliente, que vai para o Connector que uma regra com _Set Connector_ define. Os critérios dessa regra, como o caminho, decidem quais requisições são balanceadas.
2. Load Balancer recebe a requisição e considera somente os endereços ativos do Connector. Um endereço inativo, com `active` igual a `false`, continua no Connector e sai da rotação.
3. O método de balanceamento, _Round Robin_, _Least Connections_ ou _IP Hash_, escolhe um endereço primário, e o peso de cada endereço molda essa escolha. O Connector envia a requisição a esse endereço com o mesmo header `Host`, o mesmo prefixo de caminho e o mesmo protocolo de todos os endereços.
4. Quando a conexão falha, o Connector tenta de novo quantas vezes `max_retries` permitir. Um endereço de backup recebe requisições somente quando todos os endereços primários falham.
5. O servidor de origem responde ao Connector, e a resposta volta pela Application até o cliente.

Para saber como cada método escolhe um endereço e como o peso e a função do servidor alteram o resultado, consulte [Métodos de balanceamento](/pt-br/documentacao/plataforma/connectors/load-balancer/metodos-de-balanceamento/).
