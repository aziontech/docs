Este guia orienta você a enviar o seu primeiro caminho para uma segunda origem com um [Connector](/pt-br/documentacao/plataforma/connectors/).

- Crie um Connector do tipo `http` que alcança uma segunda origem por HTTPS e envia o próprio header `Host` dessa origem.
- Adicione uma regra cujo behavior _Set Connector_ define esse Connector para um caminho da sua Application.
- Envie uma requisição para esse caminho pelo seu Workload e receba a resposta da segunda origem.

Quatro partes formam a cadeia, listadas na ordem em que este guia as usa:

1. O **Connector** guarda o endereço da segunda origem, o header `Host` que ele envia e o protocolo que ele usa para se conectar.
2. A **regra** na sua Application corresponde a um caminho na fase de requisição. O behavior _Set Connector_ dela define o Connector.
3. O **Workload** que já atende a sua Application recebe a requisição. O deployment dele não precisa de nenhuma mudança.
4. A **requisição** para esse caminho corresponde à regra, e o Connector a encaminha para a segunda origem. Todos os outros caminhos continuam chegando à origem do seu primeiro Connector.

Um Connector não recebe requisições até que uma regra o defina. Este guia usa `httpbin.org` como segunda origem, um serviço público que responde a toda requisição sob `/anything` com uma cópia em JSON da requisição que recebeu. Por isso, a resposta que você verifica no fim mostra o que o Connector enviou. Para usar a sua própria origem, substitua `httpbin.org` pelo hostname dela e `/anything` pelo caminho dela, como `/api/`.

Os recursos da plataforma aninhados de Connectors partem do Connector que este guia deixa pronto. [Load Balancer](/pt-br/documentacao/plataforma/connectors/load-balancer/) balanceia as requisições entre os endereços de um Connector do tipo `http`, até 15. [Origin Shield](/pt-br/documentacao/plataforma/connectors/origin-shield/) permite que a sua origem aceite somente as requisições que um Connector envia, pelo endereço IP de saída com Origin IP ACL (access control list), pela assinatura de hash-based message authentication code (HMAC) ou pelos dois. Com [Live Ingest](/pt-br/documentacao/plataforma/connectors/live-ingest/), um Connector do tipo `live_ingest` define a região em que o Live Ingest recebe a sua transmissão.

## Crie um Connector para a sua segunda origem

Um Connector do tipo `http` guarda o endereço de uma origem e as configurações que a Azion usa para alcançá-la. Você o cria à parte, fora de qualquer Application. Este Connector tem um endereço, `httpbin.org`, e se conecta a ele somente por HTTPS.

O header `Host` informa à origem para qual site é uma requisição. Por padrão, um Connector envia o host que o cliente requisitou, que é o seu workload domain. Este Connector envia `httpbin.org` no lugar, então a origem recebe o próprio nome. Para mais informações, consulte [Header Host](/pt-br/documentacao/plataforma/connectors/como-funciona/#header-host).

O Connector mantém o caminho de cada requisição como o cliente o enviou. Para adicionar um diretório da origem na frente de todo caminho, consulte [Prefixo de caminho](/pt-br/documentacao/plataforma/connectors/como-funciona/#prefixo-de-caminho). Para servir os objetos de um bucket no lugar de uma origem HTTP, consulte [Use um bucket como origem de uma aplicação](/pt-br/documentacao/guias/desenvolvimento-de-aplicacoes/dados/bucket-como-connector/).

<Fragment slot="panel.console">

### Console

Para criar o Connector no Azion Console:

<DocSteps>
  <DocStep title="Abra a página Connectors">

  Acesse [Azion Console](https://console.azion.com/) > **Connectors**.

  </DocStep>
  <DocStep title="Inicie um Connector">

  Selecione **+ Connectors**.

  </DocStep>
  <DocStep title="Nomeie o Connector">

  Em **General**, digite `my-connector` em **Name**.

  </DocStep>
  <DocStep title="Mantenha o tipo HTTP">

  Em **Connector Type**, mantenha _HTTP_ selecionado.

  </DocStep>
  <DocStep title="Digite o endereço da segunda origem">

  Em **Address Management**, digite `httpbin.org` em **Address**, sem protocolo e sem porta.

  </DocStep>
  <DocStep title="Envie o próprio nome da origem no header Host">

  Em **Connection Options**, substitua `${host}` em **Host** por `httpbin.org`.

  </DocStep>
  <DocStep title="Conecte-se à origem somente por HTTPS">

  Em **Transport Protocol Policy**, selecione _Force HTTPS_.

  </DocStep>
  <DocStep title="Selecione Save" />
</DocSteps>

Azion Console mostra a mensagem "Connector successfully created". O Connector existe na sua conta, e a regra que você adiciona à sua Application define esse Connector.

</Fragment>

<Fragment slot="panel.cli">

### CLI

Para criar o Connector com a Azion CLI, coloque-o primeiro em um arquivo JSON. Salve este corpo como `connector.json`:

<Code client:visible lang="json" code={`{
  "name": "my-connector",
  "active": true,
  "type": "http",
  "attributes": {
    "addresses": [{ "address": "httpbin.org" }],
    "connection_options": {
      "transport_policy": "force_https",
      "host": "httpbin.org"
    }
  }
}`} />

`addresses` lista os servidores de origem, e `connection_options.host` é o header `Host` que o Connector envia. `force_https` faz toda conexão com a origem usar HTTPS.

Crie o Connector a partir do arquivo. O comando precisa de `--type`, mesmo que o arquivo também carregue `type`:

<Code client:visible lang="bash" code={`azion create connector --type http --file connector.json`} />

A saída traz o ID do Connector novo:

```text
Created Connector with ID <connector-id>
```

Leia o Connector de volta em JSON. Substitua `<connector-id>` pelo ID do comando anterior:

<Code client:visible lang="bash" code={`azion describe connector --connector-id <connector-id> --format json`} />

Este trecho da saída mostra as opções de conexão, com um valor para cada opção que o arquivo deixou de fora:

```json
{
 "active": true,
 "attributes": {
  "addresses": [
   {
    "active": true,
    "address": "httpbin.org",
    "http_port": 80,
    "https_port": 443,
    "modules": null
   }
  ],
  "connection_options": {
   "dns_resolution": "both",
   "following_redirect": false,
   "host": "httpbin.org",
   "http_version_policy": "http1_1",
   "path_prefix": "",
   "real_ip_header": "X-Real-IP",
   "real_port_header": "X-Real-PORT",
   "transport_policy": "force_https"
  },
  …
 },
 …
 "id": <connector-id>,
 …
 "name": "my-connector",
 …
 "type": "http",
 …
}
```

`path_prefix` está vazio, então o caminho chega à origem sem mudança. Anote o `id`: a regra o passa como `<connector-id>`. O Connector existe na sua conta.

</Fragment>

### API

Para criar o Connector com a API, envie uma requisição `POST` para o endpoint de connectors. Substitua `[TOKEN VALUE]` pelo seu personal token:

<Code client:visible lang="bash" code={`curl --request POST \\
  --url https://api.azion.com/v4/workspace/connectors \\
  --header 'Accept: application/json' \\
  --header 'Authorization: Token [TOKEN VALUE]' \\
  --header 'Content-Type: application/json' \\
  --data '{
  "name": "my-connector",
  "type": "http",
  "attributes": {
    "addresses": [{ "address": "httpbin.org" }],
    "connection_options": {
      "transport_policy": "force_https",
      "host": "httpbin.org"
    }
  }
}'`} />

`addresses` lista os servidores de origem, e `connection_options.host` é o header `Host` que o Connector envia. A API responde com `202`. Este trecho da resposta mostra o Connector, com um valor para cada configuração que a requisição deixou de fora:

```json
{
  "state": "pending",
  "data": {
    …
    "id": <connector-id>,
    "name": "my-connector",
    …
    "active": true,
    "product_version": "1.0",
    "type": "http",
    "attributes": {
      "addresses": [
        {
          "active": true,
          "address": "httpbin.org",
          "http_port": 80,
          "https_port": 443,
          "modules": null
        }
      ],
      "connection_options": {
        "dns_resolution": "both",
        "transport_policy": "force_https",
        "http_version_policy": "http1_1",
        "host": "httpbin.org",
        "path_prefix": "",
        "following_redirect": false,
        "real_ip_header": "X-Real-IP",
        "real_port_header": "X-Real-PORT"
      },
      "modules": {
        "load_balancer": { "enabled": false, "config": null },
        "origin_shield": { "enabled": false, "config": null }
      }
    },
    …
  }
}
```

`path_prefix` está vazio, então o caminho chega à origem sem mudança. Anote o `id`: a regra o passa como `<connector-id>`. O Connector existe na sua conta.

## Envie um caminho para o Connector

Uma regra no [Rules Engine para Applications](/pt-br/documentacao/plataforma/applications/rules-engine/) combina critérios com behaviors, e esta regra roda na fase de requisição da sua Application. O critério dela, `${uri}` começando com `/anything`, corresponde a toda requisição sob esse caminho. O behavior dela, _Set Connector_, define o Connector novo para cada requisição correspondente. Para mais informações, consulte [Set Connector](/pt-br/documentacao/plataforma/applications/rules-engine/#set-connector).

A regra dos primeiros passos com Applications corresponde a todo caminho, inclusive `/anything`. Quando várias regras correspondentes carregam _Set Connector_, somente a última roda. Mantenha esta regra depois da regra que corresponde a tudo, para que ela defina o Connector de `/anything`.

<Tabs client:visible sharedStore="interface">

<Fragment slot="panel.console">

### Console

Para criar a regra no Azion Console:

<DocSteps>
  <DocStep title="Abra a Application">

  Acesse [Azion Console](https://console.azion.com/) > **Applications** e selecione a Application dos primeiros passos com Applications.

  </DocStep>
  <DocStep title="Selecione a aba Rules Engine" />
  <DocStep title="Selecione + Rule" />
  <DocStep title="Nomeie a regra">

  Em **General**, digite `send-path-to-connector` em **Name**.

  </DocStep>
  <DocStep title="Selecione a fase de requisição">

  Em **Phase**, selecione _Request Phase_. A fase de uma regra não pode mudar depois que você cria a regra.

  </DocStep>
  <DocStep title="Defina o critério">

  Em **Criteria**, mantenha `${uri}` e _starts with_ e digite `/anything` como argumento.

  </DocStep>
  <DocStep title="Selecione o behavior Set Connector">

  Em **Behaviors**, selecione _Set Connector_.

  </DocStep>
  <DocStep title="Selecione o seu Connector">

  No behavior _Set Connector_, selecione `my-connector`, o Connector que você criou para a segunda origem.

  </DocStep>
  <DocStep title="Selecione Save" />
</DocSteps>

A regra aparece na aba **Rules Engine**, sob o título **Request**.

</Fragment>

<Fragment slot="panel.cli">

### CLI

A Azion CLI lê a regra de um arquivo JSON. Salve este corpo como `rule.json` e substitua `<connector-id>` pelo ID do Connector novo:

<Code client:visible lang="json" code={`{
  "name": "send-path-to-connector",
  "active": true,
  "criteria": [
    [
      {
        "variable": "\${uri}",
        "conditional": "if",
        "operator": "starts_with",
        "argument": "/anything"
      }
    ]
  ],
  "behaviors": [
    {
      "type": "set_connector",
      "attributes": { "value": <connector-id> }
    }
  ]
}`} />

Crie a regra na fase de requisição da sua Application. Substitua `<application-id>` pelo ID da sua Application:

<Code client:visible lang="bash" code={`azion create rules-engine --application-id <application-id> --phase request --file rule.json`} />

A saída traz o ID da regra nova:

```text
Created Rules Engine with ID <rule-id>
```

A regra está ativa na sua Application e define o Connector para toda requisição sob `/anything`.

</Fragment>

<Fragment slot="panel.api">

### API

Para criar a regra com a API, mantenha o corpo da requisição em um arquivo, para que o shell nunca expanda `${uri}`. Salve este corpo como `rule.json` e substitua `<connector-id>` pelo ID do Connector novo:

<Code client:visible lang="json" code={`{
  "name": "send-path-to-connector",
  "active": true,
  "criteria": [
    [
      {
        "variable": "\${uri}",
        "conditional": "if",
        "operator": "starts_with",
        "argument": "/anything"
      }
    ]
  ],
  "behaviors": [
    {
      "type": "set_connector",
      "attributes": { "value": <connector-id> }
    }
  ]
}`} />

Envie uma requisição `POST` para as regras da fase de requisição da sua Application. Substitua `[TOKEN VALUE]` pelo seu personal token e `<application-id>` pelo ID da sua Application:

<Code client:visible lang="bash" code={`curl --request POST \\
  --url https://api.azion.com/v4/workspace/applications/<application-id>/request_rules \\
  --header 'Accept: application/json' \\
  --header 'Authorization: Token [TOKEN VALUE]' \\
  --header 'Content-Type: application/json' \\
  --data @rule.json`} />

A API responde com `202`. Este trecho da resposta mantém o `id` da regra armazenada, o critério, o behavior e o `order` dela:

```json
{
  "state": "pending",
  "data": {
    "id": <rule-id>,
    "name": "send-path-to-connector",
    "active": true,
    "criteria": [
      [
        {
          "conditional": "if",
          "variable": "${uri}",
          "operator": "starts_with",
          "argument": "/anything"
        }
      ]
    ],
    "behaviors": [
      {
        "type": "set_connector",
        "attributes": { "value": <connector-id> }
      }
    ],
    "description": "",
    "order": 1,
    …
  }
}
```

Uma regra nova vai depois das regras que a Application já tem, então `order` é `1`, depois da regra que corresponde a tudo em `0`. A regra está ativa na sua Application e define o Connector para toda requisição sob `/anything`.

</Fragment>

## Verifique a resposta

A verificação é a mesma, qualquer que seja a interface que criou o Connector e a regra. No comando, substitua `<workload-domain>` pelo workload domain do seu Workload.

Um Connector novo e uma regra nova levam vários minutos para chegar à infraestrutura distribuída da Azion, e os data centers os aplicam em momentos diferentes. Até lá, uma requisição para `/anything` ainda pode chegar à origem do seu primeiro Connector. Repita a requisição até a segunda origem responder. Para mais informações, consulte [Propagação](/pt-br/documentacao/plataforma/connectors/como-funciona/#propagacao).

Envie uma requisição para o caminho a que a regra corresponde:

<Code client:visible lang="bash" code={`curl -s https://<workload-domain>/anything`} />

`httpbin.org` responde com uma cópia em JSON da requisição que recebeu. Este trecho mantém o header `Host` e a URL:

```json
{
  …
  "headers": {
    …
    "Host": "httpbin.org",
    …
  },
  …
  "url": "https://httpbin.org/anything"
}
```

`Host` é `httpbin.org`, o valor que o Connector envia, e não o seu workload domain. `url` mostra que o caminho chegou à origem sem mudança. Uma requisição para qualquer outro caminho, como `/`, continua chegando à origem do seu primeiro Connector. A sua Application envia um caminho para uma segunda origem por um Connector próprio.
