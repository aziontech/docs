Você pode declarar um [Firewall](/pt-br/documentacao/plataforma/firewall/) e a regra que aplica um WAF rule set no `azion.config.js` e criar os dois a partir do arquivo com a [Azion CLI](/pt-br/documentacao/devtools/cli/). Para aplicar um rule set pelo Azion Console, pelos comandos da CLI ou pela API, consulte [Crie e aplique um WAF rule set](/pt-br/documentacao/guias/seguranca-de-aplicacoes/firewall-e-waf/criar-waf-rule-set/).

O exemplo declara o Firewall `storefront-firewall`, com uma regra que aplica o rule set de ID `12345` a toda requisição. Substitua-os pelo seu Firewall e pelo ID do seu rule set.

---

## Pré-requisitos

- A Azion CLI, instalada e autorizada. Os comandos desta página correspondem à Azion CLI 4.26.2.
- O pacote `@aziontech/config` na pasta do projeto. Para adicioná-lo, execute `npm install -D @aziontech/config`.
- Um WAF rule set e o ID dele. Para criar um, consulte [Crie e aplique um WAF rule set](/pt-br/documentacao/guias/seguranca-de-aplicacoes/firewall-e-waf/criar-waf-rule-set/).

---

## Declare o Firewall e a regra

Para declará-los, adicione o Firewall sob `firewall` no `azion.config.js`, com `waf: true` e uma regra cujo behavior `set_waf` carrega o ID do seu rule set em `wafId`:

```javascript
import { defineConfig } from '@aziontech/config';

export default defineConfig({
  firewall: [
    {
      name: 'storefront-firewall',
      active: true,
      waf: true,
      rules: [
        {
          name: 'Apply storefront-waf',
          active: true,
          criteria: [
            {
              variable: '${request_uri}',
              conditional: 'if',
              operator: 'starts_with',
              argument: '/',
            },
          ],
          behaviors: [
            {
              type: 'set_waf',
              attributes: { mode: 'blocking', wafId: 12345 },
            },
          ],
        },
      ],
    },
  ],
});
```

O arquivo declara um Firewall com o WAF ligado e uma regra que aplica o rule set em modo _Blocking_ a toda requisição.

---

## Crie o Firewall a partir do arquivo

Para criar o Firewall e a regra dele, execute este comando na pasta do projeto:

```bash
azion config apply
```

O comando cria cada recurso e imprime o ID dele:

```text
[Azion] [IaC] › ✔  success   Manifest generated successfully at <project-dir>/.edge/manifest.json
Creating azion.json file
Reading manifest.json file
Firewall storefront-firewall with id <firewall-id> successfully created
Firewall Rule Apply storefront-waf with id <rule-id> successfully created
Rules Engine of Firewall with id <firewall-id> successfully ordered
Configuration applied successfully: 1 resource(s) applied
```

A conta tem o Firewall, com o WAF ligado, e a regra que aplica o rule set. Executar o comando de novo atualiza o mesmo Firewall e a mesma regra e mantém os IDs deles. A regra não inspeciona nenhuma requisição até que o deployment de um Workload defina o Firewall. Para defini-lo, consulte [Defina um Firewall em um Workload](/pt-br/documentacao/guias/seguranca-de-aplicacoes/firewall-e-waf/proteja-seu-dominio/).

Na Azion CLI 4.26.2, o `azion config apply` tratou quatro declarações de forma diferente do arquivo:

- **`wafId` recebe um ID.** Um `wafId` com o nome de um rule set falha com `set_waf requires integer 'waf_id' attribute`, e o comando para depois de criar o Firewall.
- **`mode` recebe `blocking`.** `learning` passa pela validação do arquivo e a API o recusa com `"learning" is not a valid choice.` `logging` falha na validação com `The mode must be one of: learning, blocking`.
- **Uma entrada `waf` não cria nenhum rule set.** O comando não reporta nenhum rule set, e a conta não tem nenhum depois.
- **Um deployment sob `workloads` não define o Firewall.** O comando cria o Workload e o deployment dele, e o deployment mostra `firewall: null`, quer o arquivo indique o Firewall pelo nome ou pelo ID.

Para cada campo do arquivo, consulte [azion.config.js](/pt-br/documentacao/devtools/cli/azion-config-js/#firewall).
