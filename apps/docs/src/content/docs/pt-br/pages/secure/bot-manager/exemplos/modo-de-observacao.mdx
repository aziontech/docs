Você pode criar uma Function Instance do [Bot Manager Lite](/pt-br/documentacao/plataforma/firewall/bot-manager/bot-manager-lite/) que pontua toda requisição e não recusa nenhuma, pelo Azion Console, pelo Azion CLI ou pela API. Use-a na primeira vez que colocar o Bot Manager na frente de tráfego real, enquanto ainda precisa descobrir o que o seu próprio tráfego pontua.

## Crie a Function Instance

A Function Instance recebe um único objeto JSON de argumentos. `threshold` é a pontuação a partir da qual `action` é acionada, e o Bot Manager Lite é entregue com `30`. Com `action` em `allow`, nada é aplicado nesse valor, então uma requisição que ultrapassa o threshold é pontuada, registrada e atendida como qualquer outra. Em `2`, `internal_logs` escreve uma linha de report por requisição, incluindo uma requisição que pontua `0`. `log_tag` identifica esta Function Instance nessas linhas, então substitua `storefront-bots` por uma tag sua.

```json
{
  "threshold": 30,
  "action": "allow",
  "internal_logs": 2,
  "log_tag": "storefront-bots"
}
```

Para cada argumento que uma Function Instance aceita, consulte [Campos](/pt-br/documentacao/plataforma/firewall/bot-manager/argumentos/#campos).

<Fragment slot="panel.console">

### Console

Para criar a Function Instance pelo Azion Console:

<DocSteps>
  <DocStep title="Abra o Firewall que o deployment do seu Workload define">

  Acesse [Azion Console](https://console.azion.com/) > **Firewalls** e selecione esse Firewall.

  </DocStep>
  <DocStep title="Selecione a aba Functions Instances" />
  <DocStep title="Selecione Function">

  O botão mostra **Function Instance** enquanto o Firewall ainda não tem nenhuma Function Instance.

  </DocStep>
  <DocStep title="Dê um nome à Function Instance">

  Na seção **General**, informe um **Name**, como `bot-manager-observation`.

  </DocStep>
  <DocStep title="Selecione a Function do Bot Manager Lite">

  A seção **Function** oferece a Function instalada. Só as Functions que são executadas em um Firewall aparecem no seletor.

  </DocStep>
  <DocStep title="Informe o objeto na seção Arguments">

  Cole-o no editor JSON. A seção mostra um editor porque o Bot Manager Lite não é entregue com um esquema de argumentos a partir do qual construir um formulário.

  </DocStep>
  <DocStep title="Selecione Save" />
</DocSteps>

A Function Instance aparece na lista **Functions Instances**, que mostra **Name**, **Function**, **Last Editor** e **Last Modified**. A lista não mostra nenhum argumento, então o objeto que você informou só fica visível quando você abre a Function Instance de novo.

</Fragment>

<Fragment slot="panel.cli">

### CLI

Para criar a Function Instance com o Azion CLI, salve o objeto como `bmargs.json`:

```json
{
  "threshold": 30,
  "action": "allow",
  "internal_logs": 2,
  "log_tag": "storefront-bots"
}
```

A flag `--args` de `azion create firewall-instance` recebe o caminho desse arquivo, e não JSON inline:

```bash
azion create firewall-instance --name bot-manager-observation --firewall-id <firewall-id> \
  --function-id <function-id> --args bmargs.json --active true
```

```text
Created Firewall Function Instance with ID 12347
```

O Azion CLI confirma a Function Instance com o ID que ela recebeu. Anote esse ID: uma [regra](/pt-br/documentacao/guias/seguranca-de-aplicacoes/bots-e-rede/executar-em-toda-requisicao/) executa a Function Instance por ele, nunca pelo ID da Function.

</Fragment>

<Fragment slot="panel.api">

### API

Envie uma requisição `POST` para a coleção `functions` do seu Firewall, com o nome, o ID da Function instalada e os argumentos em um único corpo. Substitua `<firewall-id>` pelo ID do seu Firewall, `[TOKEN VALUE]` pelo seu personal token e `12345` pelo ID da Function do Bot Manager Lite instalada:

```bash
curl --request POST \
  --url https://api.azion.com/v4/workspace/firewalls/<firewall-id>/functions \
  --header 'Accept: application/json' \
  --header 'Authorization: Token [TOKEN VALUE]' \
  --header 'Content-Type: application/json' \
  --data '{
  "name": "bot-manager-observation",
  "function": 12345,
  "active": true,
  "args": {
    "threshold": 30,
    "action": "allow",
    "internal_logs": 2,
    "log_tag": "storefront-bots"
  }
}'
```

A chamada responde `202`. O corpo abre com `"state": "pending"`, o que significa que a alteração ainda está se propagando. Em `data`, ele carrega a Function Instance como a plataforma a armazenou: o `id` que ela atribuiu, os `args` retornados com os valores sem alteração e `"azion_form": {}`. Esse formulário vazio é o motivo pelo qual o Azion Console mostra um editor JSON para esta Function em vez de um formulário. Anote o `id`.

</Fragment>

</Tabs>

:::note[nota]
A API verifica se os argumentos são um objeto ou um array JSON, e não verifica nenhuma chave. Toda chave que você envia é armazenada e lida de volta como foi digitada, incluindo uma chave que a Function nunca lê. Um `thresold` digitado errado deixa `threshold` ausente da Function Instance, e a API e o Azion CLI não retornam nenhum erro. Para ver o que a Function faz sem `threshold`, consulte [Threshold](/pt-br/documentacao/plataforma/firewall/bot-manager/argumentos/#threshold).

Uma alteração em uma Function Instance leva até alguns minutos para se propagar, e as respostas alternam enquanto isso, então espere antes de tirar qualquer conclusão de uma resposta. Para mais informações, consulte [Propagação](/pt-br/documentacao/plataforma/firewall/como-funciona/#propagacao).

Mantenha o threshold fixo durante toda a janela: `classified` é relativo ao threshold em vigor, então uma alteração reclassifica o tráfego que você está observando. Para saber como o threshold o define, consulte [Score de bots](/pt-br/documentacao/plataforma/firewall/bot-manager/score-de-bots/).
:::
