Você pode elevar a sensibilidade de uma família de ameaças de um WAF rule set pela API e deixar as outras sete onde estão. Para o que um nível altera no score com que uma família bloqueia, consulte [Score e modos](/pt-br/documentacao/plataforma/firewall/waf/score-e-modos/#score-e-sensibilidade).

O exemplo eleva `sql_injection` para `high` no rule set `<waf-id>` e mantém as outras sete famílias em `medium`. Substitua-os pela sua família, pelo seu nível e pelo seu rule set.

---

## Pré-requisitos

- Um WAF rule set e o ID dele. Para criar um, consulte [Crie e aplique um WAF rule set](/pt-br/documentacao/guias/seguranca-de-aplicacoes/firewall-e-waf/criar-waf-rule-set/).
- Um [personal token](/pt-br/documentacao/guias/plataforma/conta-e-billing/personal-tokens/).

---

## Eleve a família

Um `PATCH` cujo `engine_settings` carrega `thresholds` substitui o array inteiro, então um corpo que carrega apenas `sql_injection` deixa o rule set com essa única família. Envie todas as oito famílias, cada uma uma vez.

Para elevar a família, envie uma requisição `PATCH` para o endpoint do rule set, com todas as oito famílias em `thresholds`:

```bash
curl --request PATCH \
  --url https://api.azion.com/v4/workspace/wafs/<waf-id> \
  --header 'Accept: application/json' \
  --header 'Authorization: Token [TOKEN VALUE]' \
  --header 'Content-Type: application/json' \
  --data '{
  "engine_settings": {
    "engine_version": "2021-Q3",
    "type": "score",
    "attributes": {
      "rulesets": [1],
      "thresholds": [
        { "threat": "cross_site_scripting", "sensitivity": "medium" },
        { "threat": "directory_traversal", "sensitivity": "medium" },
        { "threat": "evading_tricks", "sensitivity": "medium" },
        { "threat": "file_upload", "sensitivity": "medium" },
        { "threat": "identified_attack", "sensitivity": "medium" },
        { "threat": "remote_file_inclusion", "sensitivity": "medium" },
        { "threat": "sql_injection", "sensitivity": "high" },
        { "threat": "unwanted_access", "sensitivity": "medium" }
      ]
    }
  }
}'
```

A API responde `202` e retorna o rule set com as oito entradas que você enviou:

```json
{
  "state": "pending",
  "data": {
    "id": <waf-id>,
    "engine_settings": {
      "engine_version": "2021-Q3",
      "type": "score",
      "attributes": {
        "rulesets": [1],
        "thresholds": [
          { "threat": "cross_site_scripting", "sensitivity": "medium" },
          ...
          { "threat": "sql_injection", "sensitivity": "high" },
          { "threat": "unwanted_access", "sensitivity": "medium" }
        ]
      }
    },
    ...
  }
}
```

O rule set é lido de volta com `sql_injection` em `high` e as outras sete famílias em `medium`.

`sensitivity` aceita `highest`, `high`, `medium`, `low` ou `lowest`, e outro valor retorna `400` com `10039 Invalid Choice`. Um `threat` repetido no array retorna `500` com `10067 Internal Server Error` e a mensagem `A server error occurred.`, que não indica nem o campo nem a duplicata. Para cada erro que o endpoint retorna, consulte [Rule sets](/pt-br/documentacao/plataforma/firewall/waf/rule-sets/#erros).
