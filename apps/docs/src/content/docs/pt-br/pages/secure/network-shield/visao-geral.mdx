**Network Shield** é um recurso da plataforma aninhado ao [Firewall](/pt-br/documentacao/plataforma/firewall/) que compara as requisições aos seus [Workloads](/pt-br/documentacao/plataforma/workloads/) pelo endereço do cliente, antes da [Application](/pt-br/documentacao/plataforma/applications/). Um filtro de camada de rede compara o endereço de cada cliente com listas de endereços, redes ou países e recusa quem uma política exclui. Use Network Shield para bloquear endereços e redes abusivos, recusar países que você não atende ou barrar todo cliente fora das suas próprias redes.

Network Shield compara o cliente com uma entidade própria:

- [Network Lists](/pt-br/documentacao/plataforma/firewall/network-shield/network-lists/) guardam os endereços IP e intervalos, os Autonomous System Numbers (ASNs) ou os países que uma regra compara com o cliente. Mantenha cada conjunto de clientes em uma lista, para que uma mudança nos itens dela alcance toda regra que a usa.

## Caminho da requisição

Uma Network List não bloqueia nada sozinha. Uma regra do Firewall usa a lista por meio do critério _Network_, e os comportamentos dessa regra decidem o que acontece com um cliente a que a lista corresponde. Esse Firewall inspeciona apenas as requisições aos Workloads cujos deployments o definem.

O diagrama acompanha uma requisição por uma regra com o critério _Network_. As setas contínuas levam a requisição, as setas pontilhadas levam a resposta, e cada rótulo começa com o número da sua etapa.

```mermaid
flowchart TD
  Client(["Cliente"])
  WL["Workload"]
  FW["Firewall"]
  NS["Network Shield"]
  App["Application"]
  Client -->|"1. requisição"| WL
  WL -->|"1. requisição"| FW
  FW -->|"2. endereço do cliente"| NS
  NS -->|"3. corresponde ou não"| FW
  FW -.->|"4. resposta do Firewall"| Client
  FW -->|"5. requisição"| App
  App -.->|"6. resposta"| Client
```

1. A requisição de um cliente chega a um Workload, cujo deployment define o Firewall e a Application. O Firewall inspeciona a requisição antes da Application.
2. O Firewall executa as suas regras em ordem. Uma regra com o critério _Network_ faz Network Shield comparar o endereço do cliente com uma Network List.
3. Network Shield informa se o cliente está na lista. Com _matches_, o critério é verdadeiro para um cliente listado, e com _does not match_, é verdadeiro para um cliente fora da lista.
4. Quando os critérios da regra correspondem, a regra aplica os seus comportamentos. _Deny (403 Forbidden)_, por exemplo, responde ao cliente com uma recusa, e as regras depois dela nunca são executadas.
5. Quando os critérios não correspondem, ou nenhum comportamento encerra a requisição, o Firewall passa para a próxima regra. A Application recebe apenas as requisições que todas as regras deixaram passar.
6. A Application responde, e a resposta dela chega ao cliente.

Para ver como uma lista se torna uma blocklist ou uma allowlist, consulte [Correspondência de listas](/pt-br/documentacao/plataforma/firewall/network-shield/correspondencia-de-listas/#comparacao-do-endereco-do-cliente).
