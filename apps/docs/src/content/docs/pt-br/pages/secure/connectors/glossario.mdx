Definições dos termos que a documentação de **Connectors** usa.

| Termo | Definição |
| --- | --- |
| Connector | A entidade que você cria em [Connectors](/pt-br/documentacao/plataforma/connectors/), o recurso da plataforma que encaminha requisições das suas Applications às [origens](https://www.azion.com/pt-br/learning/cdn/o-que-e-um-servidor-de-origem/) que guardam o seu conteúdo. Um Connector é o upstream de um [proxy reverso](https://www.azion.com/en/learning/performance/what-is-a-reverse-proxy/): onde o seu conteúdo está e como cada requisição chega até ele. Uma regra de uma Application com o behavior _Set Connector_ define um Connector pelo ID dele, então várias Applications podem compartilhá-lo. |
| endereço | O endereço IPv4, o endereço IPv6 ou o hostname de um servidor que um Connector do tipo `http` alcança, escrito sem protocolo e sem porta. Um Connector contém um endereço, ou até 15 com Load Balancer ativado, e cada endereço tem seus próprios `http_port` e `https_port`. [Configurações de Connector](/pt-br/documentacao/plataforma/connectors/configuracoes/#enderecos) lista todos os campos de endereço. |
| função do servidor | A função de um endereço de um Connector com Load Balancer ativado: _Primary_ (`primary`, o padrão quando o `modules.load_balancer` do endereço omite `server_role`) ou _Backup_ (`backup`). Um endereço de backup recebe requisições somente quando todos os endereços primários falham, e o método _IP Hash_ recusa endereços de backup com `28005`. **Server Role** no Azion Console e `server_role` na API a definem, como descreve [Função do servidor](/pt-br/documentacao/plataforma/connectors/load-balancer/metodos-de-balanceamento/#funcao-do-servidor). |
| header Host | O header HTTP que a origem lê para selecionar qual dos seus sites, chamados de hosts virtuais, atende uma requisição. **Host** no Azion Console e `host` na API têm `${host}` como padrão, o host que o cliente requisitou, e o Connector envia qualquer outro valor como está escrito. [Header Host](/pt-br/documentacao/plataforma/connectors/como-funciona/#header-host) explica o mecanismo, e [Defina o Host header e o path prefix de uma origem](/pt-br/documentacao/guias/desenvolvimento-de-aplicacoes/primeiros-passos/defina-o-host-header-e-o-path-prefix/) mostra quando enviar o nome da própria origem. |
| HMAC | Uma feature de Origin Shield que [assina cada requisição à origem](/pt-br/documentacao/plataforma/connectors/origin-shield/origin-ip-acl-e-hmac/#autenticacao-hmac) com um código de autenticação de mensagem baseado em hash, para que um bucket privado compatível com S3 a aceite. Ela usa `aws4_hmac_sha256` e um conjunto de credenciais do seu provedor de object storage para todos os endereços: **Region**, **Service**, **Access Key** e **Secret Key** no Azion Console. Desativá-la remove as credenciais armazenadas, e [Assine requisições de origem com HMAC](/pt-br/documentacao/guias/desenvolvimento-de-aplicacoes/primeiros-passos/assine-requisicoes-de-origem-com-hmac/) a configura. |
| lista Azion Origin Shield | A [network list](/pt-br/documentacao/plataforma/firewall/network-shield/network-lists/) chamada `Azion Origin Shield`, que guarda os prefixos IPv4 e IPv6 que a infraestrutura da Azion usa para se conectar às origens. Com Origin IP ACL, o firewall da sua origem permite somente esses prefixos, e você mantém essa allowlist atualizada conforme a lista muda. Para aplicá-la na sua origem, consulte [Libere os IPs da Azion na sua origem](/pt-br/documentacao/suporte/obter-ranges-ip-azion/). |
| Live Ingest | Um recurso da plataforma aninhado em Connectors que recebe a transmissão ao vivo que o seu encoder envia por Real-Time Messaging Protocol (RTMP). Um Connector do tipo `live_ingest` define a região que recebe a transmissão, e uma Application entrega a transmissão aos espectadores por meio desse Connector. [Live Ingest](/pt-br/documentacao/plataforma/connectors/live-ingest/) o descreve, e [Ingestão e entrega](/pt-br/documentacao/plataforma/connectors/live-ingest/ingestao-e-entrega/) explica como ele funciona. |
| Load Balancer | Um recurso da plataforma aninhado em Connectors que balanceia requisições entre os endereços de um Connector do tipo `http`, uma prática chamada de [balanceamento de carga](https://www.azion.com/pt-br/learning/performance/o-que-e-balanceamento-de-carga/). Você o ativa, para até 15 endereços, com o switch **Load Balancer** no Azion Console ou com `attributes.modules.load_balancer.enabled` na API. [Load Balancer](/pt-br/documentacao/plataforma/connectors/load-balancer/) o descreve, e [Primeiros passos com Load Balancer](/pt-br/documentacao/plataforma/connectors/load-balancer/primeiros-passos/) balanceia um primeiro Connector. |
| método de balanceamento | O método que Load Balancer usa para escolher o endereço de um Connector para cada requisição. **Method** no Azion Console e `method` na API aceitam _Round Robin_ (`round_robin`, o padrão), _Least Connections_ (`least_conn`) ou _IP Hash_ (`ip_hash`). [Métodos de balanceamento](/pt-br/documentacao/plataforma/connectors/load-balancer/metodos-de-balanceamento/#metodo-de-balanceamento) descreve como cada método escolhe. |
| Origin IP ACL | Uma feature de Origin Shield que entrega à sua conta a lista Azion Origin Shield, para que o firewall da sua origem aceite conexões somente dos endereços da Azion. **Origin IP ACL** no Azion Console e `attributes.modules.origin_shield.config.origin_ip_acl.enabled` na API a ativam, e ela vem desativada por padrão. [Origin IP ACL e HMAC](/pt-br/documentacao/plataforma/connectors/origin-shield/origin-ip-acl-e-hmac/#origin-ip-acl) explica o mecanismo. |
| Origin Shield | Um recurso da plataforma aninhado em Connectors que permite que a sua origem aceite somente as requisições que um Connector envia a partir da Azion, pelo endereço IP de saída (Origin IP ACL), pela assinatura (HMAC) ou pelos dois. Você ativa [Origin Shield](/pt-br/documentacao/plataforma/connectors/origin-shield/) em um Connector do tipo `http`, com o switch **Origin Shield** no Azion Console ou com `attributes.modules.origin_shield.enabled` na API. A camada de cache que alguns provedores chamam de origin shield é o [Tiered Cache](/pt-br/documentacao/plataforma/applications/cache/tiered-cache/), uma feature de Cache. |
| peso | A parcela de requisições que um endereço recebe em relação aos outros endereços do seu Connector com Load Balancer ativado, um número inteiro de 1 a 100. **Weight** no Azion Console e `weight` na API têm `1` como padrão, e um peso maior destina mais tráfego ao endereço. [Peso](/pt-br/documentacao/plataforma/connectors/load-balancer/metodos-de-balanceamento/#peso) descreve como ele muda a escolha. |
| prefixo de caminho | O caminho que um Connector do tipo `http` adiciona na frente de cada caminho requisitado: **Path** no Azion Console, `path_prefix` na API. Ele começa com `/` e é vazio por padrão, e com `/anything`, uma requisição para `/get` chega à origem como `/anything/get`. [Prefixo de caminho](/pt-br/documentacao/plataforma/connectors/como-funciona/#prefixo-de-caminho) explica o efeito dele, e [Configurações de Connector](/pt-br/documentacao/plataforma/connectors/configuracoes/#opcoes-de-conexao) lista os limites dele. |
| Set Connector | O behavior de uma regra de uma Application que define o Connector das requisições que correspondem à regra: _Set Connector_ no Azion Console, `set_connector` na API. A regra define o Connector pelo ID dele em `attributes.value` e, quando várias regras correspondentes carregam o behavior, somente a última é executada. [Rules Engine para Applications](/pt-br/documentacao/plataforma/applications/rules-engine/) documenta o behavior. |
| SNI Check | Uma feature da Azion Platform que responde `421 Misdirected Request` a uma requisição HTTPS para um Workload quando o certificado do Workload não cobre o host da requisição e a verificação obrigatória está ativada. Ela lê o Server Name Indication (SNI) e o header `Host` da requisição antes que qualquer Application ou Connector seja executado. A verificação obrigatória não tem configuração no Azion Console nem na API, então o suporte da Azion a ativa, e [SNI Check](/pt-br/documentacao/plataforma/connectors/sni-check/) descreve cada verificação. |
| tipo de Connector | O tipo de origem que um Connector alcança: `http` para servidores que você opera, `storage` para um bucket do [Object Storage](/pt-br/documentacao/plataforma/object-storage/) ou `live_ingest` para o [Live Ingest](/pt-br/documentacao/plataforma/connectors/live-ingest/). **Connector Type** no Azion Console o oferece como os cards _HTTP_, _Object Storage_ e _Live Ingest_, e `type` na API o carrega. [Configurações de Connector](/pt-br/documentacao/plataforma/connectors/configuracoes/#geral) lista os campos que cada tipo aceita. |
