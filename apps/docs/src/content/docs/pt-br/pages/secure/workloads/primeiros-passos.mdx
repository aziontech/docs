Este guia orienta você a encaminhar requisições para a sua [Application](/pt-br/documentacao/plataforma/applications/) a partir do seu primeiro [Workload](/pt-br/documentacao/plataforma/workloads/).

- Crie um Workload na infraestrutura de produção.
- Defina a Application que você já tem no deployment do Workload.
- Envie uma requisição para o workload domain e receba a resposta da sua Application.

Você cria um Workload e o deployment dele:

1. **Workloads** é um recurso da plataforma que recebe, como ponto de entrada, as requisições feitas aos seus domínios, na infraestrutura distribuída da Azion. A Azion atribui a cada Workload um workload domain, um hostname no formato `<id>.map.azionedge.net`. O Workload responde nesse hostname depois que o deployment dele se propaga, antes que você tenha ou aponte qualquer domínio.
2. O **deployment** do Workload define a sua Application. Um Workload contém no máximo um deployment.

Depois de receber uma requisição, o Workload a encaminha para a Application que o deployment desse Workload define. Essa Application executa as suas regras nessa requisição. A sua Application já existe, e o Workload não acrescenta nada a ela.

Este guia mantém os padrões de um Workload novo: a infraestrutura de produção, as configurações padrão de Transport Layer Security (TLS), as portas `80` e `443` e nenhum domínio seu.

O Workload que este guia deixa pronto é o ponto de partida de outros dois primeiros passos. Com [Certificate Manager](/pt-br/documentacao/plataforma/workloads/#certificate-manager), você vincula um certificado ao Workload. Com [Custom Pages](/pt-br/documentacao/plataforma/workloads/#custom-pages), você define um conjunto de custom pages no deployment do Workload para substituir respostas de erro.

[DDoS Protection](/pt-br/documentacao/plataforma/workloads/#ddos-protection) é uma feature da Azion Platform que mitiga ataques de negação de serviço em todo Workload. Ela está sempre ativa e não precisa de ativação nem de configuração.

## Crie o Workload

Um Workload novo é executado na infraestrutura de produção, e a Azion gera o workload domain dele na criação. A infraestrutura não pode mudar depois da criação, então um Workload criado em staging não pode passar para produção depois. O workload domain continua acessível enquanto `workload_domain_allow_access` for `true`, o padrão. No Azion Console, essa configuração é a chave **Workload Domain Allow Access**.

<Tabs client:visible sharedStore="interface">

<Fragment slot="panel.console">

### Console

No Azion Console, um único formulário cria o Workload e o deployment dele ao mesmo tempo. O campo **Application** de **Deployment Settings** define a sua Application no deployment, e **Save** exige esse campo.

Para criar o Workload no Azion Console:

<DocSteps>
  <DocStep title="Abra a página Workloads">

  Acesse [Azion Console](https://console.azion.com/) > **Workloads**.

  </DocStep>
  <DocStep title="Inicie um Workload">

  Selecione **+ Workload**. A página **Create Workload** abre.

  </DocStep>
  <DocStep title="Nomeie o Workload">

  Digite um nome para o Workload, como `my-workload`.

  </DocStep>
  <DocStep title="Selecione a infraestrutura de produção">

  Em **Infrastructure**, selecione _Production Infrastructure (All Edge Locations)_.

  </DocStep>
  <DocStep title="Mantenha o workload domain aberto">

  Em **Domains**, mantenha **Workload Domain Allow Access** ativado.

  </DocStep>
  <DocStep title="Selecione a sua Application">

  Em **Deployment Settings**, selecione a sua Application em **Application**. Deixe **Firewall** e **Custom Page** vazios.

  </DocStep>
  <DocStep title="Selecione Save" />
</DocSteps>

Azion Console mostra a mensagem "Your Workload has been created. After propagation the domain will be available in the Workload URL. You also can add a custom domain." Para copiar o workload domain para o qual você envia a requisição, selecione **Copy Workload URL**. A mensagem fecha depois de alguns segundos, e a coluna **Workload Domain** da lista de Workloads também mostra o workload domain. O Workload existe, e o deployment dele define a sua Application.

</Fragment>

<Fragment slot="panel.cli">

### CLI

Para criar o Workload com a Azion CLI:

<Code client:visible lang="bash" code={`azion create workload --name my-workload`} />

O comando imprime o ID do Workload novo:

```text
Created Workload with ID <workload-id>
```

Leia o Workload de volta em JSON. Substitua `<workload-id>` pelo ID do comando anterior:

<Code client:visible lang="bash" code={`azion describe workload --workload-id <workload-id> --format json`} />

A saída mostra os padrões de um Workload novo e o workload domain que a Azion atribuiu a ele:

<Fragment slot="panel.api">

### API

Para criar o Workload com a API, envie uma requisição `POST` para o endpoint de workloads. `infrastructure` definido como `1` seleciona a infraestrutura de produção, e `workload_domain_allow_access` definido como `true` mantém o workload domain aberto. Substitua `[TOKEN VALUE]` pelo seu personal token:

<Code client:visible lang="bash" code={`curl --request POST \\
  --url https://api.azion.com/v4/workspace/workloads \\
  --header 'Accept: application/json' \\
  --header 'Authorization: Token [TOKEN VALUE]' \\
  --header 'Content-Type: application/json' \\
  --data '{
  "name": "my-workload",
  "active": true,
  "infrastructure": 1,
  "workload_domain_allow_access": true
}'`} />

A API responde com `202`. A resposta traz os padrões do Workload novo e o workload domain que a Azion atribuiu a ele:

```json
{
  "state": "pending",
  "data": {
    "id": <workload-id>,
    "name": "my-workload",
    "active": true,
    "last_editor": "<your-email>",
    "last_modified": "2026-01-01T12:00:00.000000Z",
    "created_at": "2026-01-01T12:00:00.000000Z",
    "infrastructure": 1,
    "tls": {
      "certificate": null,
      "ciphers": 7,
      "minimum_version": "tls_1_3"
    },
    "protocols": {
      "http": {
        "versions": ["http1", "http2", "http3"],
        "http_ports": [80],
        "https_ports": [443],
        "quic_ports": [443]
      }
    },
    "mtls": {
      "enabled": false,
      "config": {
        "certificate": null,
        "crl": null,
        "verification": null
      }
    },
    "domains": [],
    "workload_domain_allow_access": true,

    "product_version": "1.0"

```

Anote o `id` para o deployment e o `workload_domain` para a requisição. O Workload existe e ainda não tem deployment.

## Defina a sua Application no deployment

Depois de receber uma requisição, o Workload a encaminha para a Application que o deployment desse Workload define. O deployment também pode definir o [Firewall](/pt-br/documentacao/plataforma/firewall/) que inspeciona as requisições primeiro e o conjunto de custom pages que substitui as respostas de erro. Um Workload contém no máximo um deployment, e um segundo é recusado. Até que o Workload tenha um deployment que defina uma Application, o workload domain dele responde `404`.

<Tabs client:visible sharedStore="interface">

<Fragment slot="panel.console">

### Console

O formulário **Create Workload** já criou o deployment, então **Application** mostra a sua Application. Um Workload criado pela API ou pela Azion CLI ainda não tem deployment, e **Application** fica vazio até você selecionar a sua Application e salvar o Workload.

Para conferir ou definir a Application no Azion Console:

<DocSteps>
  <DocStep title="Abra a página Workloads">

  Acesse [Azion Console](https://console.azion.com/) > **Workloads**.

  </DocStep>
  <DocStep title="Abra o seu Workload">

  Selecione o Workload que você criou. A página **Edit Workload** abre.

  </DocStep>
  <DocStep title="Selecione a sua Application">

  Em **Deployment Settings**, se **Application** estiver vazio, selecione a sua Application nele.

  </DocStep>
  <DocStep title="Selecione Save" />
</DocSteps>

Azion Console mostra a mensagem "Your workload has been updated". O deployment do Workload define a sua Application.

</Fragment>

<Fragment slot="panel.cli">

### CLI

Para definir a sua Application, crie o deployment do Workload com a Azion CLI. Substitua `<workload-id>` pelo ID do Workload e `<application-id>` pelo ID da sua Application:

<Code client:visible lang="bash" code={`azion create workload-deployment --workload-id <workload-id> --name my-deployment --application-id <application-id>`} />

O comando imprime o ID do deployment novo:

```text
Created Workload Deployment with ID <deployment-id>
```

Para conferir qual Application o deployment define, liste os deployments do Workload com os detalhes deles:

<Code client:visible lang="bash" code={`azion list workload-deployment --workload-id <workload-id> --details`} />

A coluna `EDGE APPLICATION` mostra o ID da sua Application:

```text
ID              CURRENT  EDGE APPLICATION  EDGE FIREWALL
<deployment-id> true     <application-id>  0
```

O deployment do Workload define a sua Application. Um projeto que declara o Workload no `azion.config.js` recebe o deployment do `azion deploy` em vez disso. Esse deployment define a Application que o deploy cria para o projeto, mesmo quando a entrada [`deployments`](/pt-br/documentacao/devtools/cli/azion-config-js/#deployments-do-workload) traz o ID de outra Application. Para todas as flags, consulte [Azion CLI workload-deployment](/pt-br/documentacao/devtools/cli/recursos/workload-deployment/).

</Fragment>

<Fragment slot="panel.api">

### API

A referência publicada da API v4 da Azion não tem endpoint de deployment, então você cria o deployment com a Azion CLI. No Azion Console, o campo **Application** de **Deployment Settings** do Workload também define a sua Application.

Substitua `<workload-id>` pelo ID do Workload e `<application-id>` pelo ID da sua Application:

<Code client:visible lang="bash" code={`azion create workload-deployment --workload-id <workload-id> --name my-deployment --application-id <application-id>`} />

O comando imprime o ID do deployment novo:

```text
Created Workload Deployment with ID <deployment-id>
```

O deployment do Workload define a sua Application.

</Fragment>

</Tabs>

## Envie uma requisição para o workload domain

A verificação é a mesma, qualquer que seja a interface que criou o Workload. Nos comandos, substitua `<your-workload-domain>` pelo workload domain do Workload que você criou, no formato `<id>.map.azionedge.net`.

Um Workload novo responde com a sua Application somente depois que o deployment dele se propaga pela infraestrutura distribuída da Azion. Isso leva vários minutos, sem duração garantida. Até lá, o workload domain responde `404` com a página de erro HTML da Azion. Enquanto o deployment se propaga, as respostas à mesma requisição podem alternar entre esse `404` e a resposta da sua Application. Envie a requisição de novo até a sua Application responder. Para mais informações, consulte [Propagação](/pt-br/documentacao/plataforma/workloads/como-funciona/#propagacao).

Antes que o deployment se propague, uma requisição `HEAD` recebe `404` e os cabeçalhos da página de erro da Azion:

<Code client:visible lang="bash" code={`curl -sI https://<your-workload-domain>/`} />

```text
HTTP/2 404
server: nginx
date: <date>
content-type: text/html
x-azion-request-id: <request-id>
x-azion-edge-location: <edge-location>
```

O cabeçalho `x-azion-request-id` identifica a requisição. Quando o deployment se propagar, envie uma requisição para o caminho raiz do seu workload domain:

<Code client:visible lang="bash" code={`curl -i https://<your-workload-domain>/`} />

A resposta é a que a sua Application retorna para `/`: o status, os cabeçalhos e o corpo. O seu Workload recebe as requisições feitas ao workload domain dele e as encaminha para a sua Application.
