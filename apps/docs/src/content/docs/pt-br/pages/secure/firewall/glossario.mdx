Definições dos termos que a documentação do **Firewall** usa.

| Termo | Definição |
| --- | --- |
| Allowed Rules | O nome que Azion Console dá às exceções de WAF, e a aba de um rule set onde você as cria e gerencia. A API e a CLI chamam a mesma entidade de exceção, e [Configurações de exceção](/pt-br/documentacao/plataforma/firewall/waf/custom-allowed-rules/) a documenta sob os dois nomes. |
| allowlist | Uma Network List que uma regra usa para admitir somente os clientes que ela contém. Uma regra com o critério Network, o operador _does not match_ (`is_not_in_list`) e o comportamento _Deny (403 Forbidden)_ (`deny`) bloqueia todo cliente fora da lista. Allowlist nomeia um uso, e não um tipo de lista: [Network Lists](/pt-br/documentacao/plataforma/firewall/network-shield/network-lists/) oferece somente os tipos _IP/CIDR_, _ASN_ e _Countries_. |
| argumentos | O objeto JSON que uma Function Instance passa para a sua Function, editado na seção **Arguments** do formulário da instância e enviado como `args` pela API e pela CLI. No Bot Manager, ele define o limite, a ação e o registro em log, e uma chave que a Function não lê é armazenada e ignorada, como [Argumentos](/pt-br/documentacao/plataforma/firewall/bot-manager/argumentos/#campos) documenta. Em um critério, um argumento é o valor com que uma variável é comparada. |
| `az_asm` | Um dos dois cookies de sessão que Bot Manager Lite define, ao lado de `az_botm`. O valor dele é uma cópia assinada do valor em `az_botm`, e Bot Manager Lite pontua uma divergência entre os dois. [Score de bots](/pt-br/documentacao/plataforma/firewall/bot-manager/score-de-bots/#cookies-de-sessao) documenta o par. |
| `az_botm` | O cookie não assinado do par de sessão que Bot Manager Lite define, que carrega o `x-azion-request-id` da resposta que o definiu. [Score de bots](/pt-br/documentacao/plataforma/firewall/bot-manager/score-de-bots/#cookies-de-sessao) documenta o par e quanto tempo ele dura. |
| Azion IP Tor Exit Nodes | A Network List mantida pela Azion com os exit nodes do Tor, os pontos finais em que a rede Tor se conecta à internet. É uma lista `ip_cidr` com ID `2` que a Azion mantém atualizada, e uma regra pode usá-la, mas não alterá-la. Para bloquear os clientes que ela contém, consulte [Bloqueie exit nodes do Tor](/pt-br/documentacao/guias/seguranca-de-aplicacoes/bots-e-rede/bloquear-redes-tor/). |
| Blocking | O modo do WAF que recusa uma requisição cujo score alcança o limite de uma família de ameaças antes que ela chegue à sua Application, respondendo `400`. É um dos dois modos que o comportamento _Set WAF_ aceita, `blocking` na API, e é definido na regra, e não no rule set. [Score e modos](/pt-br/documentacao/plataforma/firewall/waf/score-e-modos/#modos) compara os dois modos. |
| blocklist | Uma Network List que uma regra usa para recusar os clientes que ela contém. Uma regra com o critério Network, o operador _matches_ (`is_in_list`) e o comportamento _Deny (403 Forbidden)_ (`deny`) bloqueia todo cliente da lista e deixa os outros passarem. Para criar uma, consulte [Bloqueie requisições por IP, ASN ou país](/pt-br/documentacao/guias/seguranca-de-aplicacoes/bots-e-rede/blocklists-enderecos-ip-edge/). |
| Bot Manager | Um recurso da plataforma aninhado ao Firewall que pontua cada requisição pelas evidências que ela carrega, como os headers, o endereço e a sessão, e age sobre a requisição quando o score alcança um limite. Ele não é um switch em **Modules**: é executado como uma Function Instance no Firewall, e uma regra com o comportamento _Run Function_ o executa. [A visão geral do Bot Manager](/pt-br/documentacao/plataforma/firewall/bot-manager/) o descreve, e Bot Manager Lite é a edição self-service dele. |
| Bot Manager Lite | A edição self-service do Bot Manager, instalada a partir do Azion Marketplace e executada como uma Function Instance em um Firewall. Ela pontua cada requisição com 26 regras estáticas e não calcula nenhum score dinâmico. [Bot Manager Lite](/pt-br/documentacao/plataforma/firewall/bot-manager/bot-manager-lite/) lista as regras, os argumentos e o log de report. |
| categoria de bot | A categoria que Bot Manager registra para uma requisição no campo de log `bot_category`, com valores como `Search Engine Bot`, `Bad Bot Signatures` e `Credential Stuffing`. Bot Manager grava a única categoria em que a requisição melhor se encaixa, e Bot Manager Lite grava uma lista, separada por vírgulas, das classes de todas as regras a que a requisição correspondeu. [Logs](/pt-br/documentacao/plataforma/firewall/bot-manager/logs/#classificacao) lista todos os valores. |
| classificação | O veredito que Bot Manager registra para uma requisição no campo de log `classified`: `legitimate`, `good bot`, `bad bot` ou `under evaluation`. O veredito segue o limite em vigor, então o mesmo score aparece como `legitimate` com um limite e como `bad bot` com um limite menor. [Logs](/pt-br/documentacao/plataforma/firewall/bot-manager/logs/#classificacao) dá as condições de cada um, e [Real-Time Metrics](/pt-br/documentacao/plataforma/real-time-metrics/dashboards-secure/#bot-manager) mostra os quatro juntos em gráficos. |
| colisão | Dois usuários ou dispositivos distintos que compartilham um fingerprint, de modo que Bot Manager os pontua como uma única identidade. Com o argumento `engine_version` definido como `2`, Bot Manager deriva o fingerprint com um método JA4H que produz menos colisões que a versão `1`. [Argumentos](/pt-br/documentacao/plataforma/firewall/bot-manager/argumentos/#engine-version) compara as duas versões. |
| comentário | Uma nota escrita depois de `#` no fim de um item de uma lista `ip_cidr`, armazenada com o item e sempre por último na linha, depois de qualquer data de expiração. Uma linha que começa com `#` não é uma linha desativada: a API a recusa como um item inválido com `22005 Invalid IP CIDR`. Listas dos tipos `asn` e `countries` recusam comentários, e [Network Lists](/pt-br/documentacao/plataforma/firewall/network-shield/network-lists/#anotacoes-de-item) documenta a sintaxe completa do item. |
| comportamento | O que uma regra aplica a cada requisição a que os critérios dela correspondem. Um Firewall oferece seis, _Deny (403 Forbidden)_, _Drop (Close Without Response)_, _Set Rate Limit_, _Set Custom Response_, _Set WAF_ e _Run Function_, e recusa toda regra enquanto WAF, Network Shield e Functions estão todos desativados. Somente _Set WAF_ e _Run Function_ podem ser seguidos de outro comportamento na mesma regra; [Rules Engine para Firewall](/pt-br/documentacao/plataforma/firewall/rules-engine/#comportamentos) documenta cada um e o que ele precisa. |
| condição | No WAF, a parte de uma requisição a que uma exceção corresponde: uma match zone e, para uma zona específica, o nome ou o valor a que ela se aplica. O campo no Azion Console é **Condition**, e a API recebe `conditions` como um array com pelo menos uma entrada; [Configurações de exceção](/pt-br/documentacao/plataforma/firewall/waf/custom-allowed-rules/#match-zones) lista todas as opções. Em uma regra de Firewall, as condições são os critérios da regra. |
| critério | Uma condição que uma regra testa: uma variável como `${request_uri}`, um operador de comparação e um argumento, quando o operador recebe um. Algumas variáveis são recusadas até que um recurso aninhado esteja ativado: `${network}` precisa de Network Shield, e as sete variáveis de header, `${request_args}` e `${request_method}` precisam de WAF. [Rules Engine para Firewall](/pt-br/documentacao/plataforma/firewall/rules-engine/#criterios) lista todas as variáveis e como os critérios se combinam com `and` e `or`. |
| critério Network | O critério do [Rules Engine para Firewall](/pt-br/documentacao/plataforma/firewall/rules-engine/#criterios) que compara o endereço IP do cliente de uma requisição com uma Network List: _Network_ no Azion Console e `${network}` na API. É o único critério que Network Shield acrescenta, então, enquanto Network Shield está desativado, Azion Console mostra _Network - required Network Shield_ e a API responde `25047 Missing Required Modules`. O argumento dele é o ID da lista como um inteiro JSON, e uma string falha com `25042 Invalid Operator Argument Type`. |
| Custom Allowed Rules | Um nome descontinuado das exceções de WAF, que não aparece em nenhuma interface da Azion. A aba do Azion Console diz **Allowed Rules**, e a API e a CLI chamam a entidade de exceção. |
| data de expiração | A data em que expira um item de uma lista `ip_cidr` que a carrega: `--LT` e uma data e hora em UTC no formato `YYYY-MM-DDTHH:MM:SSZ`, como em `192.0.2.2 --LT2030-01-01T00:00:00Z`. A Azion a verifica quando você grava os itens da lista, então um item com a data já vencida é descartado nesse momento. A ajuda do Console a chama de expiration date, e [Network Lists](/pt-br/documentacao/plataforma/firewall/network-shield/network-lists/#anotacoes-de-item) documenta a sintaxe dela. |
| DDoS Protection | Uma feature da plataforma Azion que mitiga ataques de negação de serviço distribuída (DDoS) em todo Workload, antes do Firewall que o deployment de um Workload define. A seção **Modules** de um Firewall a mostra como **DDoS Protection Unmetered**, marcada com **Automatically enabled in all accounts**, com um switch que não pode ser desativado. A API informa `modules.ddos_protection.enabled` como `true`, e [DDoS Protection](/pt-br/documentacao/plataforma/workloads/ddos-protection/ddos-mitigation/) documenta a feature. |
| Debug Rules | A seção de **Main Settings** que registra em log as regras do Rules Engine executadas em cada requisição, `debug` na API e desativada quando você cria um Firewall. Com o switch **Active** ativado, as regras executadas aparecem no campo `$traceback` em [Data Stream](/pt-br/documentacao/plataforma/data-stream/) e em [Real-Time Events](/pt-br/documentacao/plataforma/real-time-events/), e no campo `stacktrace` da [API GraphQL do Real-Time Events](/pt-br/documentacao/devtools/graphql/campos-gql-real-time-events/). [Depure regras criadas com Rules Engine](/pt-br/documentacao/guias/desenvolvimento-de-aplicacoes/primeiros-passos/debug-regras/) mostra como lê-las. |
| does not match | O rótulo, no Azion Console, do operador de comparação que é verdadeiro quando um valor não corresponde a uma expressão regular ou, no critério Network, quando o endereço IP do cliente não tem correspondência na Network List, caso em que ele envia `is_not_in_list`. Com o comportamento `deny` no critério Network, ele transforma a lista em uma allowlist. [Rules Engine para Firewall](/pt-br/documentacao/plataforma/firewall/rules-engine/#operadores) lista os operadores que cada variável aceita. |
| exceção | Uma entrada em um rule set que isenta parte de uma requisição de uma regra interna do WAF, ou de todas elas, para que um falso positivo deixe de ser bloqueado. Azion Console a chama de allowed rule, e a API e a CLI a chamam de exceção. [Configurações de exceção](/pt-br/documentacao/plataforma/firewall/waf/custom-allowed-rules/#campos) documenta o ID da regra, as condições e o operador que ela carrega. |
| falso positivo | Uma requisição legítima que alcança o limite de uma família de ameaças e é tratada como um ataque. [Tuning](/pt-br/documentacao/plataforma/firewall/waf/custom-allowed-rules/#tuning) é onde você encontra um, e uma exceção o elimina. Um falso negativo é o inverso, um ataque cujo score não alcança o limite, e aumentar um nível de sensibilidade troca um pelo outro. |
| família de ameaças | Uma das oito classes de ataque que um rule set do WAF pontua, cada uma com o próprio nível de sensibilidade, como SQL injection, cross-site scripting e directory traversal. [Rule sets](/pt-br/documentacao/plataforma/firewall/waf/rule-sets/#familias-de-ameacas) nomeia as oito e o que cada uma detecta. |
| fase | O estágio de uma requisição em que as regras são executadas. Um Firewall tem um, a fase de requisição, então toda regra que ele guarda é uma regra de requisição, mantida em `request_rules` na API. Uma Application acrescenta uma fase de resposta, e [Como Firewall funciona](/pt-br/documentacao/plataforma/firewall/como-funciona/#functions-em-um-firewall) mostra onde uma Function em um Firewall é executada. |
| fingerprint | O identificador que Bot Manager deriva para o cliente por trás de uma requisição, a partir do que a requisição e a sessão do dispositivo carregam, como o endereço IP e o header `User-Agent`. Ele liga entre si as requisições posteriores de um mesmo dispositivo. Bot Manager o reporta no campo de log `azion_fingerprint`, e Bot Manager Lite em `fingerprint`, como quatro segmentos separados por sublinhado; [Logs](/pt-br/documentacao/plataforma/firewall/bot-manager/logs/#campos) documenta os dois. |
| Firewall | Um recurso da plataforma que inspeciona as requisições aos seus Workloads antes que a sua Application as receba, na infraestrutura distribuída da Azion. Cada Firewall que você cria guarda as próprias regras, e o deployment de um [Workload](/pt-br/documentacao/plataforma/workloads/) o define, junto com a Application, no campo **Firewall** das **Deployment Settings** dele. Um Firewall não carrega domínio próprio, e [Firewall](/pt-br/documentacao/plataforma/firewall/) documenta o recurso e os seus recursos aninhados. |
| Function Instance | A entidade que guarda uma Function e os argumentos que essa Function recebe em um Firewall, listada no Azion Console na aba **Functions Instances**. A Function precisa ser criada para o ambiente de execução `firewall`. Uma regra com o comportamento _Run Function_ executa a instância, que é como Bot Manager é executado, e [Function Instances no Firewall](/pt-br/documentacao/plataforma/firewall/functions-instances/) documenta a entidade. |
| global network list | O nome que a API dá a uma lista mantida pela Azion, presente no erro `22004 Cannot Change Global Network List` que responde a qualquer gravação em uma delas. Para as listas que a Azion mantém, consulte [Network Lists](/pt-br/documentacao/plataforma/firewall/network-shield/network-lists/#listas-mantidas-pela-azion). |
| ID da regra | O identificador de uma regra interna do WAF, que uma exceção carrega para limitar o seu escopo a essa regra. `0` significa todas as regras e é o padrão. A API aceita 63 IDs, `0` incluído, listados em [Rule sets](/pt-br/documentacao/plataforma/firewall/waf/rule-sets/#regras-internas). |
| item | Uma entrada de uma Network List: um endereço IP ou intervalo CIDR, um ASN ou um código de país, conforme o tipo da lista. Duplicatas exatas são removidas sem aviso, enquanto notações equivalentes, como `192.0.2.80` e `192.0.2.80/32`, são mantidas. [Network Lists](/pt-br/documentacao/plataforma/firewall/network-shield/network-lists/) documenta o formato que cada tipo aceita. |
| limite (threshold) | O score em que WAF ou Bot Manager age sobre uma requisição. No WAF, o nível de sensibilidade de uma família de ameaças o fixa, e uma sensibilidade maior define um limite menor, conforme descreve [Score e modos](/pt-br/documentacao/plataforma/firewall/waf/score-e-modos/#score-e-sensibilidade). No Bot Manager, o argumento `threshold` o define: com um score igual ou maior, a Function Instance executa a sua `action`, que [Argumentos](/pt-br/documentacao/plataforma/firewall/bot-manager/argumentos/#action) lista, e, com um score menor, a requisição segue para a sua Application. |
| lista ASN | Uma Network List do tipo `asn`, _ASN_ no Azion Console, que corresponde a uma requisição pelo Autonomous System Number (ASN) a que pertence o endereço IP do cliente dela. Um ASN identifica um grupo de redes IP que um ou mais operadores gerenciam sob uma única política de roteamento, clara e exclusiva. A API aceita somente dígitos, como `64496`, e o formulário do Console também aceita um prefixo `AS`; [Network Lists](/pt-br/documentacao/plataforma/firewall/network-shield/network-lists/#tipos-de-lista) compara os três tipos. |
| lista de países | Uma Network List do tipo `countries`, _Countries_ no Azion Console, que corresponde a uma requisição pelo país que a Azion resolve a partir do endereço IP do cliente dela. A API aceita códigos ISO 3166-1 alpha-2 de duas letras maiúsculas, como `DE`, e o formulário do Console seleciona países pelo nome. Uma blocklist desse tipo bloqueia requisições por país, a tarefa conhecida como geoblocking; [Network Lists](/pt-br/documentacao/plataforma/firewall/network-shield/network-lists/#tipos-de-lista) compara os três tipos. |
| lista IP/CIDR | Uma Network List do tipo `ip_cidr`, _IP/CIDR_ no Azion Console, que contém endereços IPv4 e IPv6 e intervalos CIDR como `198.51.100.0/24`. Uma regra corresponde a uma requisição quando o endereço IP do cliente dela está dentro de uma das entradas. É o único tipo cujos itens aceitam uma data de expiração e um comentário, e [Network Lists](/pt-br/documentacao/plataforma/firewall/network-shield/network-lists/#tipos-de-lista) compara os três tipos. |
| lista mantida pela Azion | Uma Network List que a Azion cria e mantém atualizada, como Azion IP Tor Exit Nodes. Uma regra a usa como qualquer outra Network List, mas qualquer gravação nela falha com `22004 Cannot Change Global Network List`. [Network Lists](/pt-br/documentacao/plataforma/firewall/network-shield/network-lists/#listas-mantidas-pela-azion) relaciona essas listas. |
| log tag | O identificador que uma Function Instance carimba nas linhas de report que escreve, para você separar os registros de uma instância dos de outra em [Real-Time Events](/pt-br/documentacao/plataforma/real-time-events/). O argumento `log_tag` o define, como [Argumentos](/pt-br/documentacao/plataforma/firewall/bot-manager/argumentos/#campos) documenta. Bot Manager Lite o grava no prefixo da linha, `[Bot-Protection][<log_tag>]`, e Bot Manager o grava como um campo `log_tag`. |
| Logging | O modo do WAF que pontua uma requisição e registra a correspondência sem bloqueá-la, `logging` na API e o outro modo que o comportamento _Set WAF_ aceita. A API recusa `learning` com `10039`, mas outras superfícies mantêm esse nome, como o campo `wafLearning` do [Real-Time Events](/pt-br/documentacao/plataforma/real-time-events/), rotulado **WAF Learning**. [Score e modos](/pt-br/documentacao/plataforma/firewall/waf/score-e-modos/#modos) compara os dois modos e nomeia as outras superfícies. |
| Main Settings | A aba de um Firewall que guarda as configurações dele em quatro seções: **General**, para o nome, **Modules**, **Debug Rules** e **Status**. Ela não guarda domínios, porque o deployment de um Workload define o Firewall. [Defina as configurações principais de um Firewall](/pt-br/documentacao/guias/seguranca-de-aplicacoes/firewall-e-waf/firewall-definir-main-settings/) cobre cada seção. |
| match zone | A parte de uma requisição que uma condição do WAF inspeciona, como o valor de uma query string, o nome de um header ou o corpo bruto, entre 15 no total. Azion Console define uma pelo campo **Condition**, e não por um controle chamado match zone, e a API a recebe como `conditions[].match`. [Configurações de exceção](/pt-br/documentacao/plataforma/firewall/waf/custom-allowed-rules/#match-zones) lista as 15. |
| matches | O rótulo, no Azion Console, do operador de comparação que testa um valor contra uma expressão regular ou, no critério Network, o endereço IP do cliente contra uma Network List, caso em que ele envia `is_in_list`. Com o comportamento `deny` no critério Network, é assim que uma blocklist funciona. Na API, o próprio `matches` é recusado em `${network}` com `25039 Invalid Operator`, e [Rules Engine para Firewall](/pt-br/documentacao/plataforma/firewall/rules-engine/#operadores) lista os operadores que cada variável aceita. |
| `modules` | O campo da API que carrega os quatro switches de um Firewall: `ddos_protection`, `functions`, `network_protection` e `waf`, cada um com um valor `enabled`. Azion Console o mostra como a seção **Modules** de **Main Settings**. Bot Manager não tem chave nele porque é executado como uma Function Instance, e [Firewall](/pt-br/documentacao/plataforma/firewall/) descreve os recursos aninhados. |
| Network List | Uma entidade que contém itens de um único tipo, fixado quando você a cria: uma lista IP/CIDR, uma lista ASN ou uma lista de países. Uma regra a usa pelo ID por meio do critério Network, e uma lista pode servir a muitas regras e Firewalls, então uma alteração nos itens dela muda aquilo a que cada um deles corresponde. [Network Lists](/pt-br/documentacao/plataforma/firewall/network-shield/network-lists/) documenta os campos dela. |
| Network Lists | A página do Azion Console onde você cria e gerencia Network Lists, servida na API em `/v4/workspace/network_lists`. Network Lists guarda as listas, e Network Shield é o que permite que uma regra de Firewall compare requisições com elas. Para campos, tipos e erros, consulte [Network Lists](/pt-br/documentacao/plataforma/firewall/network-shield/network-lists/). |
| Network Shield | Um recurso da plataforma aninhado ao Firewall que compara as requisições aos seus Workloads pelo endereço do cliente: uma regra compara o cliente com uma Network List por meio do critério Network. Ele vem ativado quando você cria um Firewall e, enquanto uma regra usa `${network}`, não pode ser desativado: a API responde `24005 Cannot Disable Firewall Network Protection Module`. O switch dele é **Network Shield** na seção **Modules** de **Main Settings**; [a visão geral do Network Shield](/pt-br/documentacao/plataforma/firewall/network-shield/) o descreve, e [Preços](/pt-br/documentacao/fundamentos/precos/) traz a disponibilidade dele por plano. |
| `network_protection` | O nome que a API dá ao Network Shield em um Firewall: `modules.network_protection.enabled` no corpo de uma requisição a `/v4/workspace/firewalls`, `true` por padrão. O erro `25047` chama a mesma configuração de `network_protection_enabled`. [Network Shield](/pt-br/documentacao/plataforma/firewall/network-shield/) descreve o recurso. |
| nível de sensibilidade | A configuração que fixa o limite de uma família de ameaças, com cinco valores, de `highest` a `lowest`, e padrão `medium`. Uma sensibilidade maior define um limite menor, então WAF bloqueia mais requisições. [Rule sets](/pt-br/documentacao/plataforma/firewall/waf/rule-sets/#niveis-de-sensibilidade) traz o score em que cada nível bloqueia. |
| Operator | O campo da exceção de WAF que decide como a exceção compara as suas strings: `regex` ou `contains`, com `contains` como padrão. Ele rege ao mesmo tempo o `path` da exceção e o nome ou o valor da condição dela, e Azion Console o define com o switch **Active** na seção **Regex** do formulário de allowed rule, ativado para `regex`. [Configurações de exceção](/pt-br/documentacao/plataforma/firewall/waf/custom-allowed-rules/#campos) o documenta com os outros campos. |
| propagação | O tempo que uma alteração salva leva para chegar à infraestrutura distribuída da Azion, durante o qual as respostas alternam entre a configuração anterior e a que você salvou. [Como Firewall funciona](/pt-br/documentacao/plataforma/firewall/como-funciona/#propagacao) cobre o que esperar de cada tipo de alteração. |
| regra | Uma entrada no Rules Engine de um Firewall que aplica os seus comportamentos a toda requisição a que os critérios dela correspondem. Um Firewall avalia as regras em ordem, e um comportamento como _Deny (403 Forbidden)_ encerra a avaliação para aquela requisição. Cada regra pertence a um Firewall, em `/v4/workspace/firewalls/<firewall-id>/request_rules` na API; [Rules Engine para Firewall](/pt-br/documentacao/plataforma/firewall/rules-engine/#campos-da-regra) lista os campos dela. |
| regra estática | Uma verificação que Bot Manager executa sobre os atributos de uma única requisição, como os headers e os metadados, sem referência ao tráfego anterior. Cada regra a que uma requisição corresponde aumenta o score dela. [Bot Manager Lite](/pt-br/documentacao/plataforma/firewall/bot-manager/bot-manager-lite/#regras) publica as regras que essa edição executa e o score que cada uma soma. |
| Reputation Intelligence | A verificação que aumenta o score de uma requisição quando o endereço IP dela está em uma [Network List](/pt-br/documentacao/plataforma/firewall/network-shield/network-lists/) de reputação. Bot Manager verifica por padrão as Network Lists gerenciadas pela Azion na conta, e Bot Manager Lite executa a verificação como regra `14` contra as listas em `reputation_network_lists`, que fica vazio por padrão. Também é um valor de `bot_category`, listado em [Logs](/pt-br/documentacao/plataforma/firewall/bot-manager/logs/#classificacao). |
| rule set | A entidade do WAF que carrega as oito famílias de ameaças e o nível de sensibilidade escolhido para cada uma, listada no Azion Console em **WAF Rules**. Um rule set não detecta nada sozinho: uma regra de Firewall com o comportamento _Set WAF_ o aplica às requisições a que a regra corresponde. [Rule sets](/pt-br/documentacao/plataforma/firewall/waf/rule-sets/#campos) documenta os campos dele. |
| Rules Engine para Firewall | A feature do Firewall que guarda as regras de um Firewall e as aplica, em ordem, a toda requisição que o Firewall inspeciona. Azion Console a mostra como a aba **Rules Engine** de um Firewall, onde cada regra combina critérios com os comportamentos que ela aplica. [Rules Engine para Firewall](/pt-br/documentacao/plataforma/firewall/rules-engine/) documenta todos os critérios e comportamentos. |
| Run Function | O comportamento do Rules Engine para Firewall que executa uma Function Instance nas requisições a que uma regra corresponde, `run_function` na API, com no máximo um por regra. Ele precisa do switch **Functions** em **Modules**, que vem ativado quando você cria o Firewall pela API, pela CLI ou pela página **Create Firewall**. [Rules Engine para Firewall](/pt-br/documentacao/plataforma/firewall/rules-engine/#run-function) o documenta. |
| score | Um número que WAF ou Bot Manager calcula para uma requisição e compara com um limite. WAF mantém um por família de ameaças, aumentado por cada nova evidência dessa ameaça, e no modo _Blocking_ recusa uma requisição cujo score alcança o limite da família, conforme descreve [Score e modos](/pt-br/documentacao/plataforma/firewall/waf/score-e-modos/#score-e-sensibilidade). Bot Manager mantém um total, aumentado por cada regra estática correspondida e, fora do Bot Manager Lite, pelo score dinâmico, e executa a `action` da Function Instance quando o total alcança o limite, conforme descreve [Score de bots](/pt-br/documentacao/plataforma/firewall/bot-manager/score-de-bots/#calculo-do-score). |
| score dinâmico | A parte de um score que Bot Manager deriva do histórico de comportamento de um fingerprint, medida contra o padrão geral de tráfego do host. Bot Manager Lite executa somente regras estáticas, então o score dele não tem parte dinâmica. [Score de bots](/pt-br/documentacao/plataforma/firewall/bot-manager/score-de-bots/#o-score-dinamico) descreve o modelo. |
| Set WAF | O comportamento do Rules Engine para Firewall que aplica um rule set às requisições a que uma regra corresponde, junto com o modo em que ele é executado, `set_waf` na API. Uma regra carrega no máximo um, e Azion Console só o oferece enquanto WAF está ativado para o Firewall. Sem ele, um rule set nunca é executado; [Rules Engine para Firewall](/pt-br/documentacao/plataforma/firewall/rules-engine/#set-waf) documenta os campos dele. |
| Tuning | A aba de um rule set do WAF que lista as requisições a que cada regra interna correspondeu em uma janela de até os últimos 3 dias, agrupadas por ID da regra. Uma consulta filtra por domínio, intervalo de tempo, [Network List](/pt-br/documentacao/plataforma/firewall/network-shield/network-lists/), endereço IP e país, e **More Details** filtra ainda mais as ocorrências de uma regra por caminho. Os registros selecionados viram allowed rules em lote, conforme [Configurações de exceção](/pt-br/documentacao/plataforma/firewall/waf/custom-allowed-rules/#tuning) documenta. |
| under evaluation | A classificação que Bot Manager registra quando não identificou um bot e ainda não tem dados de fingerprint suficientes para descartar um ataque. Um fingerprint que Bot Manager não vê há algum tempo volta a esse estado. [Score de bots](/pt-br/documentacao/plataforma/firewall/bot-manager/score-de-bots/#em-avaliacao) dá os tempos, e [Logs](/pt-br/documentacao/plataforma/firewall/bot-manager/logs/#classificacao) cobre as quatro classificações. |
| WAF | Um recurso da plataforma aninhado ao Firewall que detecta ataques nas requisições aos seus Workloads e as recusa ou registra: ele pontua cada requisição contra oito famílias de ameaças e, quando o score alcança um limite, recusa a requisição no modo _Blocking_ ou a registra no modo _Logging_. O nome completo dele é Web Application Firewall, o rótulo do switch dele em **Modules**, `modules.waf.enabled` na API, e ele vem desativado quando você cria um Firewall. Azion Console oferece o comportamento _Set WAF_ somente enquanto ele está ativado, e [a visão geral do WAF](/pt-br/documentacao/plataforma/firewall/waf/) o descreve. |
