Você pode ler quais regras internas corresponderam a uma requisição bloqueada, e o score que cada família de ameaças deu a ela, pela API GraphQL do [Real-Time Events](/pt-br/documentacao/plataforma/real-time-events/). Para encontrar o mesmo registro no Azion Console, consulte [Encontre o score do WAF de uma requisição bloqueada](/pt-br/documentacao/guias/seguranca-de-aplicacoes/firewall-e-waf/como-encontrar-score-de-requisicoes-bloqueadas-pelo-waf/).

Uma resposta bloqueada carrega `400` e a página de erro padrão da Azion, com o título **Bad Request**, e nenhum header indica o WAF. O header `x-azion-request-id` dela encontra o registro da requisição.

---

## Pré-requisitos

- Um [Firewall](/pt-br/documentacao/plataforma/firewall/) definido pelo deployment do seu Workload, com uma regra cujo behavior _Set WAF_ aplica um WAF rule set em modo `blocking`. Para criar a regra, consulte [Crie e aplique um WAF rule set](/pt-br/documentacao/guias/seguranca-de-aplicacoes/firewall-e-waf/criar-waf-rule-set/). Para as requisições que o WAF inspecionou nos testes, consulte [Modos](/pt-br/documentacao/plataforma/firewall/waf/score-e-modos/#modos).
- Um [personal token](/pt-br/documentacao/guias/plataforma/conta-e-billing/personal-tokens/), para a query GraphQL.

---

## Leia o request ID

Para ler o request ID, envie uma requisição que o WAF bloqueia e imprima os headers da resposta:

```bash
curl -i "https://<your-workload-domain>/?q=1%27%20OR%20%271%27%3D%271"
```

A resposta é `HTTP/2 400`, e o header `x-azion-request-id` carrega o request ID:

```text
HTTP/2 400
server: nginx
date: Wed, 01 Jan 2026 12:00:00 GMT
content-type: text/html
x-azion-request-id: 0123456789abcdef0123456789abcdef
x-azion-edge-location: <location>
```

O request ID é o valor pelo qual a query da próxima seção filtra.

---

## Consulte o registro da requisição

Para consultar o registro, envie uma query GraphQL para `https://api.azion.com/v4/events/graphql`, sobre o dataset `workloadEvents`, filtrada pelo request ID e por uma janela ao redor da requisição:

```graphql
query {
  workloadEvents(
    limit: 1
    filter: { tsGte: "<start>", tsLt: "<end>", requestIdEq: "<request-id>" }
  ) {
    ts
    requestUri
    status
    upstreamStatus
    wafBlock
    wafLearning
    wafMatch
    wafScore
    wafAttackFamily
    wafAttackAction
  }
}
```

A API retorna uma linha:

```json
{
  "ts": "2026-01-01T12:00:00Z",
  "requestUri": "/?q=1%27%20OR%20%271%27%3D%271",
  "status": 400,
  "upstreamStatus": 0,
  "wafBlock": "1",
  "wafLearning": "0",
  "wafMatch": "0:1009:ARGS:q,1:1013:ARGS:q",
  "wafScore": "0:$SQL:18,1:$XSS:32",
  "wafAttackFamily": "$SQL,$XSS",
  "wafAttackAction": "$BLOCK"
}
```

A linha lista uma entrada por regra interna que correspondeu em `wafMatch` e um score por família de ameaças em `wafScore`.

Uma entrada de `wafMatch` tem o formato `<index>:<ruleId>:<zone>:<varName>`, então `1:1013:ARGS:q` indica a regra `1013` no argumento `q`. Uma entrada de `wafScore` tem o formato `<index>:$<family>:<score>`, então uma requisição carrega um score por família em vez de um único score. `upstreamStatus` vale `0` porque a requisição nunca chegou a uma origem.

`wafBlock` vale `1` também em modo _Logging_. `wafLearning` `1` e `wafAttackAction` `$LEARNING-BLOCK` marcam uma requisição que o WAF registrou e deixou passar, e `wafLearning` `0` com `$BLOCK` marca uma requisição que ele recusou.

:::note[nota]
Uma requisição à qual nenhum behavior _Set WAF_ se aplicou carrega `-` em todo campo do WAF, e uma requisição que o WAF inspecionou sem correspondência mostra `wafBlock` `0` e `$PASS`. Consulte o caminho v4: o antigo `https://api.azion.com/events/graphql` responde `204` com um corpo vazio. Os campos aqui são camelCase, em vez das grafias em snake_case que um payload do [Data Stream](/pt-br/documentacao/plataforma/data-stream/) usa.
:::
