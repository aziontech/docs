**Error Responses** é uma feature de Applications na API v3: as configurações de página de erro que personalizam a página que um usuário recebe para um status code da origem. Na API v4, [Custom Pages](/pt-br/documentacao/plataforma/custom-pages/) substitui Error Responses.

Quando um usuário solicita conteúdo de uma Application, a Azion envia a requisição para os servidores de origem. A origem responde com um status code HTTP, que indica se a requisição foi concluída.

Os status codes HTTP são números de três dígitos, agrupados em cinco categorias:

- Respostas de informação (1xx): o status da conexão ou o progresso antes de a requisição ser concluída.
- Respostas de sucesso (2xx): a origem recebeu, compreendeu, aceitou e processou a requisição.
- Mensagens de redirecionamento (3xx): a requisição precisa de um redirecionamento para ser atendida.
- Respostas de erro do cliente (4xx): a requisição não pôde ser concluída por causa de um aparente erro do lado do cliente.
- Respostas de erro do servidor (5xx): o servidor não consegue processar a requisição.

Para mais informações sobre status HTTP, consulte as [especificações de status codes HTTP](https://httpwg.org/specs/rfc9110.html#overview.of.status.codes).

Error Responses personaliza como uma Application trata as respostas de erro de cliente (4xx) e de erro de servidor (5xx). Quando uma requisição chega a uma URL que a origem não encontra, ou o servidor não consegue responder, o usuário é redirecionado para uma página de erro personalizada, cujo conteúdo pode ser armazenado em cache.

---

## Status Code

O código que a Azion recebe quando se conecta à origem.

---

## Error Caching TTL

O tempo, em segundos, que a página de erro fica em cache antes de a Azion atualizá-la. Para mais informações sobre as configurações de expiração, consulte [Cache settings](/pt-br/documentacao/plataforma/applications/cache/cache-settings/#browser-cache).

:::tip[dica]
Uma página de erro costuma ser estática e muda pouco, então a Azion recomenda um tempo de cache alto. Um valor alto melhora a performance da Application e reduz o custo de processamento na origem.
:::

---

## URI

O caminho do arquivo, geralmente HTML, que contém o conteúdo da página de erro. A Azion anexa esse caminho ao domínio da Application, por exemplo, `/404.html`.

---

## Custom Status Code

O status code que o usuário recebe no lugar do original. Por exemplo, uma página pode entregar o código `404` em resposta a um erro `403`.

---

## Set Origin

A origem que contém o arquivo da URI. Você só pode alterá-la depois de informar uma URI, e configura a origem em **Origins**. Para mais informações, consulte [Origins](/pt-br/documentacao/plataforma/connectors/origins/).

---

## Códigos de erro disponíveis

Error Responses aceita estes status codes de erro de cliente e de erro de servidor:

| Status code | Descrição |
| --- | --- |
| 400: Bad Request | Um erro na requisição, como parâmetros inválidos ou ausência de parâmetros obrigatórios. |
| 401: Unauthorized | A requisição não tem o header HTTP `Authentication`. |
| 403: Forbidden | O usuário não tem permissão para executar a operação. |
| 404: Not Found | O recurso solicitado não existe. |
| 405: Method Not Allowed | O método solicitado não pode ser aplicado à URL. |
| 406: Not Acceptable | O header `Accept` falta ou pede um formato ou uma versão que a API não suporta. |
| 408: Request Timeout | A requisição chega mais devagar do que o servidor está preparado para esperar, então o servidor quer encerrar a conexão. |
| 409: Conflict | A requisição gera um conflito na execução, como criar um registro que já existe. |
| 410: Gone | O conteúdo solicitado foi excluído do servidor permanentemente, sem endereço de redirecionamento predefinido. |
| 411: Length Required | O servidor rejeitou a requisição porque o header obrigatório `Content-Length` não está definido. |
| 414: URI Too Long | A URI solicitada é maior do que os limites do servidor. |
| 415: Unsupported Media Type | O servidor não suporta o formato de mídia dos dados solicitados, então os rejeita. |
| 416: Request Range Not Satisfiable | O servidor não consegue atender ao valor do header `Range`, provavelmente fora dos dados da URI de destino. |
| 426: Upgrade Required | O servidor recusa a requisição no protocolo atual e a aceita depois que o cliente troca de protocolo. |
| 429: Too Many Requests | A requisição foi rejeitada por um tempo porque excedeu os limites de operação. |
| 431: Request Header Fields Too Large | Os headers da requisição são longos demais, ou a requisição envia cookies demais. |
| 500: Internal Server Error | Uma falha não intencional e não identificada ocorreu durante o processamento da requisição. |
| 501: Not Implemented | O servidor não suporta o método da requisição, e o método não pode ser modificado. |
| 502: Bad Gateway | O servidor, atuando como gateway para obter uma resposta de que a requisição precisa, recebeu uma resposta inválida. |
| 503: Service Unavailable | O servidor não está pronto para tratar a requisição, geralmente porque está sobrecarregado ou em manutenção. |
| 504: Gateway Timeout | O servidor, atuando como gateway, não recebe uma resposta a tempo. |
| 505: HTTP Version Not Supported | O servidor não suporta a versão HTTP usada na requisição. |

Seis dos códigos trazem mais detalhes:

- **408**: essa resposta é comum porque alguns navegadores, como Chrome, Firefox 27+ e IE9, usam pré-conexão HTTP para acelerar a navegação. Alguns servidores também encerram a conexão sem enviar essa mensagem.
- **410**: quando esse erro acontece, os caches e os links para o recurso devem ser removidos. A especificação HTTP descreve esse código para "serviços promocionais limitados", e uma API não deve usá-lo para indicar quais recursos foram removidos.
- **426**: o servidor envia um header `Upgrade` na resposta para indicar os protocolos que exige.
- **429**: o cliente deve aguardar até o momento definido no header `X-Ratelimit-Reset` antes de tentar novamente.
- **501**: os únicos métodos que um servidor precisa suportar são `GET` e `HEAD`, então um servidor não retorna esse código para eles.
- **503**: envie, com essa resposta, uma página que explique o problema. O código serve para condições temporárias, e o header `Retry-After` deve trazer o tempo estimado para recuperar o serviço. Tome cuidado com os headers de cache enviados com essa resposta, porque uma condição temporária normalmente não deve ser armazenada em cache.
