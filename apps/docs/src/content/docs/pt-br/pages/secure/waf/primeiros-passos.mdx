Este guia orienta você a pontuar a sua primeira requisição contra o [Web Application Firewall (WAF)](/pt-br/documentacao/plataforma/firewall/waf/).

- Crie um rule set que carrega oito famílias de ameaças com sensibilidade `medium`.
- Aplique esse rule set com um comportamento _Set WAF_ em modo Blocking, a partir de uma regra no seu Firewall.
- Envie uma requisição com formato de injeção e leia a recusa.

Quatro partes colocam uma requisição sob inspeção, e cada uma se liga à seguinte:

1. O **rule set** guarda as famílias de ameaças e a sensibilidade escolhida para cada uma.
2. O **Firewall** tem WAF ativado, e o deployment do [Workload](/pt-br/documentacao/plataforma/workloads/) que atende a sua [Application](/pt-br/documentacao/plataforma/applications/) define esse Firewall.
3. A **regra** nesse Firewall carrega um comportamento _Set WAF_, que aplica o rule set em um modo.
4. A **requisição** é o que WAF então pontua contra o rule set.

Um rule set não inspeciona nada sozinho. Enquanto um comportamento _Set WAF_ não o aplicar, nenhuma requisição é pontuada.

## Crie o WAF rule set

O rule set guarda o que detectar. Ele carrega oito famílias de ameaças, e cada família tem um nível de sensibilidade que fixa o score em que ela bloqueia. Toda família começa em `medium`, que é o nível que este guia usa.

<Tabs client:visible sharedStore="interface">

<Fragment slot="panel.console">

### Console

Para criar o rule set no Azion Console:

<DocSteps>
  <DocStep title="Abra a página WAF Rules">

  Acesse [Azion Console](https://console.azion.com/) > **WAF Rules**.

  </DocStep>
  <DocStep title="Inicie um novo rule set">

  Selecione **WAF Rule**. A página **Create WAF Rule** abre.

  </DocStep>
  <DocStep title="Dê um nome ao rule set">

  Na seção **General**, informe um **Name**. Por exemplo: `storefront-waf`.

  </DocStep>
  <DocStep title="Deixe todas as famílias na sensibilidade padrão">

  A seção **Threat Type Configuration** lista oito famílias de ameaças. Cada uma abre em _Sensitivity Medium_.

  </DocStep>
  <DocStep title="Mantenha o switch Active ativado" />
  <DocStep title="Selecione Save" />
</DocSteps>

Azion Console mostra a mensagem "Your WAF rule has been created". O rule set aparece em **WAF Rules**, que lista o seu **Threat Type Configuration**, **Status**, **Last Editor** e **Last Modified**.

</Fragment>

<Fragment slot="panel.cli">

### CLI

A Azion CLI cria um rule set completo a partir apenas de um nome. Para criá-lo:

<DocSteps>
  <DocStep title="Execute o comando de criação">

  ```bash
  azion create waf --name "storefront-waf"
  ```

  </DocStep>
  <DocStep title="Leia a saída">

  O comando imprime o ID do novo rule set:

  ```text
  Created WAF with ID 12349
  ```

  </DocStep>
</DocSteps>

O rule set está ativo, roda no ruleset `1` e carrega as oito famílias de ameaças em `medium`. Anote o ID. Você o passa para a regra.

</Fragment>

## Aplique o rule set com uma regra do Rules Engine

Uma regra do [Rules Engine para Firewall](/pt-br/documentacao/plataforma/firewall/rules-engine/) seleciona requisições pelos seus próprios critérios. O comportamento _Set WAF_ dela então aplica um rule set em um modo. A regra desta etapa aplica o seu rule set a todas as requisições que o Firewall recebe.

O modo é obrigatório, e ele pertence ao comportamento, não ao rule set. _Blocking_ recusa uma requisição cujo score alcança um limite. _Logging_ registra essa mesma requisição e a entrega. Este guia usa _Blocking_.

:::caution[Atenção]
Baseie o critério na URI da requisição, nunca na query string. Um critério como `${request_args}` `matches` `.*` não corresponde a uma requisição sem query string. Ele ignora silenciosamente todo `POST` cujo payload fica no corpo.
:::

<Tabs client:visible sharedStore="interface">

<Fragment slot="panel.console">

### Console

Para aplicar o rule set no Azion Console:

<DocSteps>
  <DocStep title="Abra o Firewall que o deployment do seu Workload define">

  Ainda no Azion Console, vá para **Firewalls** e selecione esse Firewall.

  </DocStep>
  <DocStep title="Selecione a aba Rules Engine" />
  <DocStep title="Inicie uma nova regra">

  Selecione **Rule**. O drawer **Create Rule** abre.

  </DocStep>
  <DocStep title="Dê um nome à regra">

  Na seção **General**, informe um **Name**. Por exemplo: `Apply storefront-waf`.

  </DocStep>
  <DocStep title="Defina o critério">

  Na seção **Criteria**, selecione a variável _Request Uri_, o operador _starts with_ e `/` como argumento.

  </DocStep>
  <DocStep title="Adicione o comportamento Set WAF">

  Na seção **Behaviors**, selecione _Set WAF_ e então selecione o rule set que você criou em **Select a WAF**.

  </DocStep>
  <DocStep title="Selecione Blocking como o modo">

  Em **Select a WAF mode**, selecione _Blocking_.

  </DocStep>
  <DocStep title="Selecione Save" />
</DocSteps>

O Firewall agora pontua contra o rule set todas as requisições que recebe. Uma regra carrega no máximo um comportamento _Set WAF_.

</Fragment>

<Fragment slot="panel.cli">

### CLI

O `azion create firewall-rule` lê a regra inteira de um arquivo JSON. Ele não tem flag para um comportamento nem para um modo.

<DocSteps>
  <DocStep title="Escreva a regra em um arquivo">

  Salve o seguinte como `fw-rule.json`, com o ID do seu rule set em `waf_id`:

  ```json
  {
    "name": "Apply storefront-waf",
    "active": true,
    "description": "",
    "criteria": [
      [
        {
          "conditional": "if",
          "variable": "${request_uri}",
          "operator": "starts_with",
          "argument": "/"
        }
      ]
    ],
    "behaviors": [
      {
        "type": "set_waf",
        "attributes": {
          "waf_id": 12349,
          "mode": "blocking"
        }
      }
    ]
  }
  ```

  </DocStep>
  <DocStep title="Crie a regra">

  Substitua `<firewall-id>` pelo ID do seu Firewall:

  ```bash
  azion create firewall-rule --firewall-id <firewall-id> --file fw-rule.json
  ```

  </DocStep>
  <DocStep title="Leia a saída">

  O comando imprime o ID da nova regra:

  ```text
  Created Firewall Rule with ID 123457
  ```

  </DocStep>
</DocSteps>

O Firewall agora pontua contra o rule set todas as requisições que recebe.

</Fragment>

### API

Os critérios carregam `${request_uri}`, então o corpo é enviado a partir de um arquivo.

<DocSteps>
  <DocStep title="Escreva a regra em um arquivo">

  Salve o seguinte como `rule.json`, com o ID do seu rule set em `waf_id`:

  ```json
  {
    "name": "Apply storefront-waf",
    "active": true,
    "criteria": [
      [
        {
          "conditional": "if",
          "variable": "${request_uri}",
          "operator": "starts_with",
          "argument": "/"
        }
      ]
    ],
    "behaviors": [
      {
        "type": "set_waf",
        "attributes": {
          "waf_id": 12349,
          "mode": "blocking"
        }
      }
    ]
  }
  ```

  </DocStep>
  <DocStep title="Envie a requisição de criação">

  Substitua `<firewall-id>` pelo ID do seu Firewall:

  ```bash
  curl --request POST \
    --url https://api.azion.com/v4/workspace/firewalls/<firewall-id>/request_rules \
    --header 'Accept: application/json' \
    --header 'Authorization: Token [TOKEN VALUE]' \
    --header 'Content-Type: application/json' \
    --data @rule.json
  ```

  </DocStep>
  <DocStep title="Leia a resposta">

  Um `202` carrega a regra, com a `order` que ela ocupa entre as regras do Firewall. Um Firewall que já tem uma regra dá à nova regra a `order` `1`:

  ```json
  {
    "state": "pending",
    "data": {
      "id": 123456,
      "name": "Apply storefront-waf",
      "last_editor": "user@example.com",
      "last_modified": "2026-01-01T12:00:00.000000Z",
      "created_at": "2026-01-01T12:00:00.000000Z",
      "active": true,
      "criteria": [
        [
          {
            "conditional": "if",
            "variable": "${request_uri}",
            "operator": "starts_with",
            "argument": "/"
          }
        ]
      ],
      "behaviors": [
        {
          "type": "set_waf",
          "attributes": {
            "waf_id": 12349,
            "mode": "blocking"
          }
        }
      ],
      "description": "",
      "order": 1
    }
  }
  ```

  </DocStep>
</DocSteps>

Um corpo que omite `mode` é recusado com `400` e o erro `10059 Required Field`, que aponta para `/data/behaviors/0/attributes/mode`. Uma regra que carrega dois comportamentos _Set WAF_ é recusada com `25011 Duplicated Behavior`.

## Verifique que WAF bloqueia uma requisição

A verificação é a mesma qualquer que seja a interface que criou a regra. O seu Workload responde em um domínio no formato `<id>.map.azionedge.net`, escrito nesta etapa como `<your-workload-domain>`.

Uma regra acrescentada a um Firewall que já atende tráfego pode levar vários minutos para entrar em vigor, e nenhuma duração é garantida. Enquanto a alteração se espalha, as respostas à mesma requisição alternam entre a resposta anterior e a nova. Uma requisição que ainda retorna a resposta anterior não quebrou nada: envie-a de novo até que as respostas concordem. Para mais informações, consulte [Propagação](/pt-br/documentacao/plataforma/firewall/como-funciona/#propagacao).

Envie primeiro uma requisição limpa:

```bash
curl -i https://<your-workload-domain>/
```

A requisição não é pontuada como ameaça e alcança a Application, que a responde:

```text
HTTP/2 200
```

A sua própria Application e o seu próprio Connector decidem esse status. O que importa é que a requisição não é recusada.

Agora envie uma requisição com formato de injeção, carregando `1' OR '1'='1` na query string:

```bash
curl -i "https://<your-workload-domain>/?q=1%27%20OR%20%271%27%3D%271"
```

WAF a recusa:

```text
HTTP/2 400
server: nginx
date: Thu, 01 Jan 2026 12:00:00 GMT
content-type: text/html
x-azion-request-id: 0123456789abcdef0123456789abcdef
x-azion-edge-location: <edge-location>
```

O corpo é a página de erro padrão da Azion, com o título **Bad Request**, e a linha Status Code dela mostra `0`. Nada na resposta nomeia WAF, a regra que correspondeu ou o score. Anote o `x-azion-request-id`: esse valor encontra a requisição no [Real-Time Events](/pt-br/documentacao/plataforma/real-time-events/).

Essa requisição disparou as regras internas `1009` e `1013`, ambas no argumento `q`. Ela pontuou nas famílias SQL injection e cross-site scripting. O seu rule set agora está pontuando tráfego.
