Um [Firewall](/pt-br/documentacao/plataforma/firewall/) guarda [regras](/pt-br/documentacao/plataforma/firewall/rules-engine/) e [Function Instances](/pt-br/documentacao/plataforma/firewall/functions-instances/). Cada recurso da plataforma aninhado acrescenta entidades próprias: [Web Application Firewall (WAF)](/pt-br/documentacao/plataforma/firewall/waf/) acrescenta [rule sets](/pt-br/documentacao/plataforma/firewall/waf/rule-sets/) e [exceções](/pt-br/documentacao/plataforma/firewall/waf/custom-allowed-rules/), e [Network Shield](/pt-br/documentacao/plataforma/firewall/network-shield/) acrescenta [Network Lists](/pt-br/documentacao/plataforma/firewall/network-shield/network-lists/). [Bot Manager](/pt-br/documentacao/plataforma/firewall/bot-manager/) é executado como uma Function Instance. Esta página informa onde termina o escopo de um Firewall, o limite que a Azion aplica a cada uma dessas entidades e a resposta que uma chamada recebe além dele.

Os dois tipos de valor são coisas diferentes. Um limite padrão é verificado em toda chamada, e a chamada falha além dele. Uma quantidade incluída é um valor de cobrança, e ultrapassá-la muda o valor cobrado da conta, e não o que a chamada retorna. Para as quantidades que cada plano inclui, como requisições do Firewall e regras por Firewall, consulte [Preços da Azion](https://www.azion.com/pt-br/precos/).

## Escopo

- **Recursos aninhados a ativar**: um Firewall aceita regras apenas enquanto pelo menos um entre WAF, Network Shield e Functions está ativado. Com os três desativados, a API recusa toda regra com `25047`, mesmo uma regra _Deny (403 Forbidden)_ sobre _Host_. Um Firewall criado apenas com um nome começa com Network Shield e Functions ativados e com WAF desativado, como [Como Firewall funciona](/pt-br/documentacao/plataforma/firewall/como-funciona/#recursos-aninhados-e-switches-em-um-firewall) mostra.
- **Critérios que precisam de um recurso aninhado**: o critério _Network_ precisa de Network Shield, e os critérios de header e _Request Method_ precisam de WAF. A API recusa uma regra que usa um deles enquanto o seu recurso está desativado, com `25047`. Para o recurso que cada critério e cada comportamento precisam, consulte [Rules Engine para Firewall](/pt-br/documentacao/plataforma/firewall/rules-engine/#criterios).
- **Inspeção do WAF**: em testes, WAF não inspecionou nenhuma requisição em uma Application sem [Connector](/pt-br/documentacao/plataforma/connectors/). Em uma Application que enviava os seus outros caminhos a um Connector, WAF também inspecionou e bloqueou uma requisição que uma Function respondeu. Um teste do WAF contra uma Application sem Connector não mostra bloqueio, como [Score e modos](/pt-br/documentacao/plataforma/firewall/waf/score-e-modos/) explica.
- **DDoS Protection**: [DDoS Protection](/pt-br/documentacao/plataforma/workloads/ddos-protection/ddos-mitigation/) mitiga ataques de negação de serviço em todo Workload, antes do Firewall, sem configuração. Um Firewall a mostra como o switch **DDoS Protection Unmetered**, que tem a tag **Automatically enabled in all accounts** e não pode ser desativado. Para uma defesa contra um ataque específico, adicione regras ao Firewall.
- **Firewalls compartilhados**: os deployments de vários Workloads podem definir o mesmo Firewall, e uma mudança nas suas regras chega então a todos eles. Cada regra pertence ao único Firewall em que foi criada. Para dar uma política diferente a um Workload, clone o Firewall com **Clone** na lista **Firewalls** ou com `POST /v4/workspace/firewalls/<firewall-id>/clone`: a cópia leva as regras, na mesma ordem, e as Function Instances com os seus argumentos. Para saber quando compartilhar um Firewall, consulte [Boas práticas de Firewall](/pt-br/documentacao/plataforma/firewall/boas-praticas/#compartilhe-um-firewall-entre-workloads-com-a-mesma-politica-de-seguranca).
- **Exclusão**: a API recusa excluir um Firewall enquanto o deployment de um Workload ainda o define, com `24003`, e a mensagem lista esses Workloads. Altere os deployments deles primeiro, como [Solucione problemas de Firewall](/pt-br/documentacao/plataforma/firewall/solucao-de-problemas/#a-exclusao-de-um-firewall-e-recusada-com-cannot-delete-firewall) mostra.
- **Proteção contra bots de terceiros**: [Radware Bot Manager](/pt-br/documentacao/guias/desenvolvimento-de-aplicacoes/integracoes/radware-bot-manager/) e [DataDome Bot Protection](/pt-br/documentacao/guias/desenvolvimento-de-aplicacoes/integracoes/datadome-bot-protection/) são instalados pelo Azion Marketplace como Functions que um Firewall executa. Cada um precisa de uma chave do seu fornecedor, que a sua Function Instance recebe como argumento, como o guia de cada um mostra.
- **Observabilidade**: nenhum header de resposta informa o Firewall ou a regra que decidiu. Para descobrir quais regras uma requisição executou, ative a configuração **Debug Rules** do Firewall, que fica desativada quando você cria um Firewall, como [Como Firewall funciona](/pt-br/documentacao/plataforma/firewall/como-funciona/#observabilidade) mostra.

## Regras e Function Instances

Um Firewall guarda as suas regras no Rules Engine, e o comportamento _Run Function_ de uma regra executa uma Function Instance, que associa uma Function aos seus argumentos. Os limites desta seção se aplicam às regras e às Function Instances de todo Firewall, quaisquer que sejam os recursos ativados nele entre WAF, Network Shield e Functions.

### Limites padrão

Cada linha indica o que é limitado, o limite e o que recebe uma chamada que o ultrapassa.

| Escopo | Limite | Ao ultrapassar o limite |
| --- | --- | --- |
| `name` da regra | 1 a 100 caracteres | `400` `10046 Max Length`, `Ensure this field has no more than 100 characters.` |
| `description` da regra | Até 1.000 caracteres | `400` `10046 Max Length`. Azion Console mostra `Description should not exceed 1000 characters`. |
| Grupos de critérios por regra | 1 a 5 | `400` `10065 List Field Max Length` acima de 5, e `10049 Min Length List Field` para nenhum. Azion Console desativa **Add Criteria** ao chegar a 5 grupos. |
| Critérios por grupo | 1 a 10 | `400` `10065 List Field Max Length` acima de 10. Azion Console desativa **And** e **Or** ao chegar a 10 critérios em um grupo. |
| Comportamentos por regra | 1 a 10 | `400` `10065 List Field Max Length` acima de 10, e `10049 Min Length List Field` para nenhum. |
| **Average Rate Limit** em um comportamento _Set Rate Limit_ | No mínimo 1 | `400` `10050 Min Value`. Azion Console recusa um valor menor. |
| **Maximum Burst Size** em um comportamento _Set Rate Limit_ | No mínimo 1, somente com o tipo _Req/s_ | `400` `10050 Min Value` abaixo de 1, `25035 Required Rate Limit Parameter` quando ele falta com _Req/s_ e `25034 Invalid Rate Limit Parameter` quando ele é enviado com _Req/min_. Azion Console recusa um valor menor e não envia o campo com o tipo _Req/min_. |
| `name` da Function Instance | Até 100 caracteres | `400` `10046 Max Length`, `Ensure this field has no more than 100 characters.` |
| Payload de argumentos, o objeto ou array JSON que uma Function Instance carrega | 100.000 bytes | `400` `23000 JSON Args Size Too Big`, `Value size (in bytes) is too big. Maximum size allowed is 100000 bytes.` |
| Requisições à Azion API | 200 por minuto, no escopo `global-default` | Uma resposta carrega `x-ratelimit-limit`, `x-ratelimit-remaining`, `x-ratelimit-reset` e `x-ratelimit-scope`, que informam o saldo restante na janela e o momento em que ela é reiniciada. |

Mais um limite se aplica: um log de **Debug Rules** carrega 1,5 kB.

Um Firewall não carrega uma lista de domínios. O deployment de um Workload define o Firewall que inspeciona as requisições do Workload, então o número de domínios não é um limite do Firewall. O limite de 200 domínios pertence à API v3. Nela, um Firewall lista os domínios que protege no array `domains` e aceita até 200 deles.

O limite do payload de argumentos é decimal: 100 KB significa 100.000 bytes, e não 100 KiB, então um payload de 102.400 bytes é recusado. Um objeto com uma chave, enviado como JSON compacto, é recusado com 100.000 bytes e aceito com 99.999 bytes.

A Azion pode aumentar, mediante solicitação e de acordo com o seu plano, o limite do payload de argumentos e os outros limites padrão de uma Function em um Firewall. Para solicitar um aumento, entre em contato com o time de [suporte técnico](/pt-br/documentacao/suporte/).

A API verifica os argumentos apenas quanto ao tamanho e ao tipo: um valor que não é um objeto ou array JSON é recusado com `23001`. Toda chave que uma instância envia é armazenada e retornada como foi enviada, qualquer que seja o nome. Por exemplo, um argumento com erro de digitação passa na chamada, e a Function nunca o lê.

O número de Function Instances que um Firewall carrega não tem limite. A quantidade que um Firewall alcança é uma escolha operacional, e não um valor que a plataforma verifica.

Uma Function executada em um Firewall compartilha os limites de memória, de variáveis de ambiente, de sub-requisições e de tempo de CPU de toda Function. Esses limites e o tamanho do código da Function pertencem à Function, e não ao Firewall. Para os valores, consulte [Limites de Functions](/pt-br/documentacao/plataforma/functions/limites/).

O rate limit é o valor que os headers de resposta anunciam. Uma resposta da Azion API carrega `x-ratelimit-limit: 200`, `x-ratelimit-scope: global-default` e um timestamp em `x-ratelimit-reset` cerca de 60 segundos depois da chamada. `x-ratelimit-remaining` fica algumas chamadas abaixo do limite e não diminui durante uma rajada de chamadas em um minuto. A resposta a uma chamada além de 200 chamadas em um minuto não foi observada.

Uma chamada que a API aceita não entra em vigor de imediato. Uma regra nova, ou um Workload cujo deployment passa a definir um Firewall, pode levar vários minutos para chegar ao tráfego, e nenhuma duração é garantida. Enquanto uma alteração se propaga, requisições sucessivas podem receber alternadamente a resposta anterior e a nova, então repita a requisição até que ela responda como esperado. Para saber como uma alteração chega ao tráfego, consulte [Como Firewall funciona](/pt-br/documentacao/plataforma/firewall/como-funciona/).

Firewall mede toda requisição que passa por um Firewall, inclusive as requisições que uma regra de Network Shield avalia. Para a tarifa, consulte [Preços](/pt-br/documentacao/fundamentos/precos/#firewall).

## WAF

WAF limita o nome que um rule set recebe, as condições que uma exceção carrega, o tamanho do corpo da requisição que ele inspeciona e o que uma requisição de listagem retorna.

### Limites padrão

WAF aplica cada limite desta tabela em todos os planos de serviço. A API responde a uma chamada recusada com um `code` numérico, um `title`, um `detail` e um ponteiro `source` que indica o campo que falhou. A coluna Ao ultrapassar o limite traz o status, o código e o título, e o texto que chega com eles.

| Escopo | Limite | Ao ultrapassar o limite |
| --- | --- | --- |
| `name` do rule set | Até 250 caracteres | `400` `10046 Max Length`, `Ensure this field has no more than 250 characters.` |
| `name` da exceção | Até 255 caracteres | `400` `10046 Max Length`, `Ensure this field has no more than 255 characters.` |
| `name` e `value` da condição de uma exceção | 1 a 255 caracteres | Um valor vazio retorna `400` `10018 Blank Field`, `This field may not be blank.` Um valor mais longo retorna `400` `10046 Max Length`, `Ensure this field has no more than 255 characters.` |
| Condições por exceção | No mínimo 1, com no máximo uma condição `specific_*` | Um array vazio retorna `400` `10049 Min Length List Field`, `Ensure this field has at least 1 elements.` Uma segunda condição `specific_*` retorna `400` `26004 Only One 'specific' Match Condition Is Allowed Per WAF Exception.` |
| Registros por resposta de listagem (`page_size`) | 100 no máximo, padrão 10 | `400` `10097 Invalid Page Size`, `Page size must be between 0 and 100.` |
| Requisições à Azion API | 200 por minuto, no escopo `global-default` | Uma resposta carrega `x-ratelimit-limit`, `x-ratelimit-remaining`, `x-ratelimit-reset` e `x-ratelimit-scope`, que informam o saldo restante na janela e o momento em que ela é reiniciada. |
| Entradas de `thresholds` em um rule set | Até 8, uma por família de ameaças | Nove entradas, ou um `threat` repetido, retornam `500` `10067 Internal Server Error`, `A server error occurred.` |
| `operator` em uma exceção | `contains` ou `regex`, padrão `contains` | `400` `10039 Invalid Choice` |
| `mode` em um comportamento `set_waf` | `logging` ou `blocking`, e obrigatório | Um valor fora da lista, como `learning`, retorna `400` `10039 Invalid Choice`. Um `mode` ausente retorna `400` `10059 Required Field`, `This field is required.` |
| Corpo da requisição que WAF inspeciona | 131.072 bytes, que são 128 KiB | No modo `blocking`, `400` e a página de erro padrão da Azion, e não um `413`. No modo `logging`, a requisição passa e é registrada. |
| Janela de consulta do WAF Tuning | 3 dias | Azion Console não oferece um intervalo maior. |

WAF analisa o corpo de um `POST` quando o `Content-Type` dele é `application/x-www-form-urlencoded`, `multipart/form-data`, `application/json` ou `application/csp-report`. Em testes, um corpo `application/vnd.api+json` não foi analisado, como [Score e modos](/pt-br/documentacao/plataforma/firewall/waf/score-e-modos/) descreve. O limite do corpo conta somente o corpo, sem a linha de requisição e os headers.

Com `Content-Type: application/x-www-form-urlencoded` e um corpo sem nenhum padrão de ataque, um corpo de 131.072 bytes retorna `200`, e um corpo de 131.073 bytes retorna `400`. O evento registrado para a requisição recusada indica a regra `2` na zona `BODY`, como `wafMatch` `0:2:BODY:-`, com `wafAttackFamily` `$OTHERS`. A regra `2` verifica o tamanho em vez de somar a um score, então o limite vale em qualquer sensibilidade: um corpo de 170 KB também é recusado na sensibilidade padrão, `medium`. O `requestLength` desse evento também conta a linha de requisição e os headers, por isso mostra um valor maior que o tamanho do corpo: `131148` para um corpo de 131.073 bytes. O mesmo corpo enviado como `application/json` ou `text/plain` é recusado nos dois tamanhos, porque as regras `15` e `11` correspondem à requisição antes da verificação de tamanho. Para testar esse limite, envie `application/x-www-form-urlencoded` ou `multipart/form-data`.

O `500` que nove entradas ou um `threat` repetido retornam é uma falha de validação, e não um defeito no serviço. Envie cada uma das oito famílias de ameaças no máximo uma vez em `thresholds`.

Para os campos a que esses limites se aplicam, consulte [Rule sets](/pt-br/documentacao/plataforma/firewall/waf/rule-sets/) e [Configurações de exceção](/pt-br/documentacao/plataforma/firewall/waf/custom-allowed-rules/).

Uma requisição de criação além do número de rule sets ou de exceções que um plano inclui é aceita. A contagem que uma conta alcança é um custo a acompanhar, e não uma recusa a tratar. Para as tarifas das métricas de cobrança do WAF, consulte [Preços](/pt-br/documentacao/fundamentos/precos/#web-application-firewall).

## Network Shield

Network Shield permite que uma regra use uma Network List por meio do critério _Network_, que compara o endereço do cliente de uma requisição com a lista. A Azion API limita o tamanho de uma Network List, os itens e o nome dela, os registros por resposta de listagem e a taxa de chamadas.

Network Shield não tem métrica de cobrança própria, como [Preços](/pt-br/documentacao/fundamentos/precos/#network-shield) mostra. Uma regra que usa o critério _Network_ é uma regra de Firewall, então conta para as regras por Firewall que cada plano inclui. Firewall também mede as requisições que avalia.

### Limites padrão

A Azion API aplica cada limite desta tabela por padrão. Uma chamada além de um limite de Network List é recusada com o status `400` e um array `errors`. Cada entrada carrega um `code`, um `title`, um `detail` e um ponteiro `source` que indica o campo que falhou.

| Escopo | Limite | Ao ultrapassar o limite |
| --- | --- | --- |
| Itens por Network List | Até 20.000 itens | `400` `10065 List Field Max Length`, `Ensure this field has no more than 20000 elements.` |
| Itens por Network List, mínimo | No mínimo 1 item | `400` `10049 Min Length List Field`, `Ensure this field has at least 1 elements.` |
| Caracteres por item, anotações incluídas | Até 250 caracteres | `400` `10046 Max Length`, `Ensure this field has no more than 250 characters.` |
| Caracteres no `name` da lista | Até 250 caracteres | `400` `10046 Max Length`, `Ensure this field has no more than 250 characters.` |
| Registros por resposta de listagem (`page_size`) | 100 no máximo, padrão 10 | `400` `10097 Invalid Page Size`, `Page size must be between 0 and 100.` |
| Requisições à Azion API | 200 por minuto, no escopo `global-default` | Uma resposta carrega `x-ratelimit-limit`, `x-ratelimit-remaining`, `x-ratelimit-reset` e `x-ratelimit-scope`, que informam o saldo restante na janela e o momento em que ela é reiniciada. |

O teto de itens é exato e se aplica igualmente aos itens de uma lista IP/CIDR e de uma lista ASN. Uma chamada de criação com 20.000 itens retorna `201`, e a mesma chamada com 20.001 itens retorna este corpo:

```json
{
  "errors": [
    {
      "code": "10065",
      "title": "List Field Max Length",
      "detail": "Ensure this field has no more than 20000 elements.",
      "status": "400",
      "source": { "pointer": "/data/items" }
    }
  ]
}
```

Os 250 caracteres de um item incluem as anotações dele: a data de expiração `--LT` e o comentário `#` que um item `ip_cidr` pode carregar. Por exemplo, um item `ip_cidr` de exatamente 250 caracteres, um endereço seguido de um espaço e de um comentário `#`, é armazenado sem alteração. Para os formatos de item e as anotações de cada tipo de lista, consulte [Network Lists](/pt-br/documentacao/plataforma/firewall/network-shield/network-lists/).

Quando uma chamada não define `page_size`, o endpoint de listagem retorna 10 registros por página. Um `page_size` de `0` é recusado com a mesma mensagem `10097`, embora a mensagem indique 0 como permitido.

O teto de 20.000 itens é um limite padrão, e a Azion pode aumentá-lo mediante solicitação, de acordo com o plano. Para solicitar um aumento, entre em contato com o time de [suporte técnico](/pt-br/documentacao/suporte/).

Uma alteração nos itens de uma lista não entra em vigor de imediato. Ela chega ao tráfego até alguns minutos depois da chamada (observado: de 41 s a 156 s) e, até se estabilizar, as requisições recebem alternadamente a resposta anterior e a nova.

## Bot Manager

Bot Manager é executado em um Firewall como uma Function Instance, que o comportamento _Run Function_ de uma regra executa. Os limites de Function Instance de todo Firewall se aplicam a ele. Mais dois limites se aplicam às superfícies em volta dele: o log de report e os datasets do GraphQL.

### Limites padrão

Uma chamada além do limite do `name` da Function Instance ou do payload de argumentos retorna `400` com o código e a mensagem da coluna Ao ultrapassar o limite. Os dois limites de superfície restringem o que o campo de log e uma consulta retornam, e nenhuma chamada falha por causa deles.

| Escopo | Limite | Ao ultrapassar o limite |
| --- | --- | --- |
| `name` da Function Instance | Até 100 caracteres | `400` `10046 Max Length`, `Ensure this field has no more than 100 characters.` |
| Payload de argumentos | 100.000 bytes | `400` `23000 JSON Args Size Too Big`, `Value size (in bytes) is too big. Maximum size allowed is 100000 bytes.` |
| Campo `request_headers` do log de report | 10.000 caracteres | Cada nome e cada valor de header descontam do total, e o campo não recebe mais nenhum header depois que o total é alcançado. |
| `limit` do GraphQL nos datasets do Bot Manager | `10000` no máximo | Uma consulta retorna no máximo 10.000 resultados. |

O limite do payload de argumentos é decimal, então um payload de 102.400 bytes, que são 100 KiB, é recusado. Para os argumentos que o payload guarda e o padrão de cada um, consulte [Argumentos](/pt-br/documentacao/plataforma/firewall/bot-manager/argumentos/). Para o log de report, consulte [Logs](/pt-br/documentacao/plataforma/firewall/bot-manager/logs/). Para a consulta GraphQL, consulte [Consulte dados do Bot Manager com GraphQL](/pt-br/documentacao/guias/plataforma/observabilidade/consultar-dados-bot-manager-com-graphql/).

[Bot Manager Lite](/pt-br/documentacao/plataforma/firewall/bot-manager/bot-manager-lite/) é a edição self-service. A edição completa está em Preview: ela não vem habilitada na conta por padrão, e a Azion a habilita mediante solicitação. Para solicitá-la, consulte [Diretrizes de suporte](/pt-br/documentacao/suporte/). Para as tarifas das requisições e dos perfis dela, consulte [Preços](/pt-br/documentacao/fundamentos/precos/#bot-manager).
