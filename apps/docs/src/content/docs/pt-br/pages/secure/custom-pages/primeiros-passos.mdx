Este guia orienta você a substituir o `404` que a sua origem retorna pela sua primeira página de [Custom Pages](/pt-br/documentacao/plataforma/workloads/#custom-pages).

- Crie um conjunto de custom pages com uma página para o status code `404`.
- Atribua o conjunto no deployment do seu [Workload](/pt-br/documentacao/plataforma/workloads/).
- Envie uma requisição para um caminho que a sua origem não tem e receba a sua própria página no lugar.

Quatro elementos participam, e cada um leva ao seguinte:

1. A sua página de erro está em um caminho no **Connector**. O Connector já existe. Para mais informações, consulte [Connectors](/pt-br/documentacao/plataforma/connectors/).
2. O **conjunto de custom pages** guarda uma página que substitui o status code `404` pelo conteúdo desse caminho no Connector.
3. O **deployment** do Workload define o conjunto de custom pages, ao lado da Application que ele já define.
4. A **requisição** chega a um caminho que o Connector que a sua Application usa responde com `404`, e o conjunto de custom pages substitui essa resposta.

Um Workload usa um conjunto de custom pages somente depois que o deployment desse Workload define esse conjunto. A partir daí, quando o Connector que a sua Application usa responde `404`, o visitante recebe o conteúdo da sua página no lugar dessa resposta. A resposta não traz redirecionamento, e o status code dela é o que a página define. Este guia trata do Azion Console e da API, e você atribui o conjunto no Azion Console. A Azion CLI não tem comando que atualiza um deployment, e a referência publicada da API v4 não tem endpoint para um deployment.

## Crie o conjunto de custom pages

Um conjunto de custom pages é uma lista nomeada de páginas e precisa de pelo menos uma página. Cada página substitui um status code pelo conteúdo de um caminho em um Connector e pode responder com um status code próprio. A página desta etapa fica em cache por `0` segundos, o tempo de vida (TTL, time to live) dela, e responde com `404`.

<Tabs client:visible sharedStore="interface">

<Fragment slot="panel.console">

### Console

Para criar o conjunto no Azion Console:

<DocSteps>
  <DocStep title="Abra a página Custom Pages">

  Acesse [Azion Console](https://console.azion.com/) > **Custom Pages**.

  </DocStep>
  <DocStep title="Inicie um conjunto">

  Selecione **Create Custom Page**. A página **Create Custom Page** abre.

  </DocStep>
  <DocStep title="Nomeie o conjunto">

  Em **Name**, digite um nome para o conjunto, como `my-custom-pages`.

  </DocStep>
  <DocStep title="Adicione um código de página">

  Selecione **+ Custom Page Code**.

  </DocStep>
  <DocStep title="Selecione o status code">

  Em **Page Code**, selecione `404`.

  </DocStep>
  <DocStep title="Mantenha o tipo Page Connector">

  Em **Type**, mantenha _Page Connector_.

  </DocStep>
  <DocStep title="Selecione o seu Connector">

  Em **Connector**, selecione o Connector com a sua página de erro.

  </DocStep>
  <DocStep title="Digite o caminho da página">

  Em **Page Path (URI)**, digite o caminho da sua página no Connector, como `/html`.

  </DocStep>
  <DocStep title="Defina o tempo de cache">

  Em **Response TTL**, digite `0`.

  </DocStep>
  <DocStep title="Defina o status da resposta">

  Em **Response Custom Status Code**, digite `404`.

  </DocStep>
  <DocStep title="Selecione Apply" />
  <DocStep title="Selecione Create" />
</DocSteps>

O conjunto existe com uma página para o código `404`. Ele não serve nada até que você o atribua ao seu Workload. Um conjunto sem código de página é recusado com a mensagem "You must have at least one custom page code".

</Fragment>

<Fragment slot="panel.api">

### API

Para criar o conjunto com a API, envie uma requisição `POST` para o endpoint de custom pages. Substitua `[TOKEN VALUE]` pelo seu personal token e `<connector-id>` pelo ID do seu Connector. Substitua `/html` pelo caminho da sua página no Connector:

<Code client:visible lang="bash" code={`curl --request POST \\
  --url https://api.azion.com/v4/workspace/custom_pages \\
  --header 'Accept: application/json' \\
  --header 'Authorization: Token [TOKEN VALUE]' \\
  --header 'Content-Type: application/json' \\
  --data '{"name": "my-custom-pages", "active": true, "pages": [
  {"code": "404", "page": {"type": "page_connector", "attributes": {"connector": <connector-id>, "ttl": 0, "uri": "/html", "custom_status_code": 404}}}
]}'`} />

A API responde com `202`, `"state": "pending"` e o conjunto novo em `data`, incluindo o `id` dele. Uma requisição com a lista `pages` vazia é recusada com `Ensure this field has at least 1 elements.` Anote o `id` do conjunto novo para atribuí-lo ao seu Workload. O conjunto existe com uma página para o código `404` e não serve nada até que você o atribua.

</Fragment>

</Tabs>

## Atribua o conjunto ao seu Workload

O deployment de um Workload define a Application que responde às requisições dele e também pode definir um Firewall e um conjunto de custom pages. Um Workload guarda no máximo um deployment, então você atribui o conjunto de custom pages editando esse deployment. A Application que o deployment já define continua no lugar.

<Tabs client:visible sharedStore="interface">

<Fragment slot="panel.console">

### Console

Para atribuir o conjunto no Azion Console:

<DocSteps>
  <DocStep title="Abra a página Workloads">

  Acesse [Azion Console](https://console.azion.com/) > **Workloads**.

  </DocStep>
  <DocStep title="Abra o seu Workload">

  Selecione o seu Workload. A página **Edit Workload** abre.

  </DocStep>
  <DocStep title="Selecione o conjunto">

  Em **Deployment Settings**, selecione o seu conjunto em **Custom Page**. Mantenha **Application** como está.

  </DocStep>
  <DocStep title="Selecione Save" />
</DocSteps>

Azion Console mostra a mensagem "Your workload has been updated". O deployment do Workload define o seu conjunto de custom pages.

</Fragment>

<Fragment slot="panel.api">

### API

A referência publicada da API v4 da Azion não tem endpoint para o deployment de um Workload. Para atribuir o conjunto, siga o painel do Console.

</Fragment>

</Tabs>

## Solicite uma página que a sua origem responde com 404

A verificação é a mesma, qualquer que seja a interface que atribuiu o conjunto. No comando, substitua `<your-workload-domain>` pelo workload domain do seu Workload, no formato `<id>.map.azionedge.net`. Substitua `<missing-path>` pelo caminho que o Connector que a sua Application usa responde com `404`.

Um conjunto atribuído não serve de imediato. A alteração no deployment se espalha pela infraestrutura distribuída da Azion, e isso leva vários minutos, sem duração garantida. Enquanto ela se espalha, uma requisição pode receber o `404` da sua origem ou a sua página. Repita a requisição até a sua página responder. Para mais informações, consulte [Propagação](/pt-br/documentacao/plataforma/workloads/como-funciona/#propagacao).

Envie uma requisição para o caminho ausente e imprima os cabeçalhos da resposta com o corpo:

<Code client:visible lang="bash" code={`curl -s -D - https://<your-workload-domain>/<missing-path>`} />

A resposta mantém o status `404`, que vem do `custom_status_code` da página. O corpo dela é o documento do caminho da página no seu Connector. Quando esse documento é uma página HTML, a resposta começa como neste exemplo, com o seu documento no corpo:

```text
HTTP/2 404 
content-type: text/html; charset=utf-8

<!DOCTYPE html>
<html>
  <head>
  </head>
  <body>
      <h1>Page not found</h1>
```

A resposta não traz o cabeçalho `Location`, então o cliente não é redirecionado. O seu Workload responde a um caminho ausente com a sua própria página.
