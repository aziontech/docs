Esta página mostra até onde vai o [Edge DNS](/pt-br/documentacao/plataforma/edge-dns/) e os limites padrão dos campos de uma zona e dos campos e valores de um registro. Para o uso que cada plano inclui, consulte [Preços da Azion](https://www.azion.com/pt-br/precos/). Para solicitar um aumento, entre em contato com a equipe de [suporte técnico](/pt-br/documentacao/suporte/).

---

## Escopo

- **Apenas os seus domínios**: Edge DNS responde às consultas pelos domínios que as zonas dele contêm e não resolve nenhum outro nome. Uma consulta por qualquer outro domínio recebe `REFUSED`, então os seus usuários continuam com os próprios resolvers, como mostra [Como o Edge DNS funciona](/pt-br/documentacao/plataforma/edge-dns/como-funciona/#o-caminho-da-resolucao).
- **Tipos de registro**: uma zona contém 11 tipos de registro, A, AAAA, ANAME, CAA, CNAME, DS, MX, NS, PTR, SRV e TXT, como descreve [Tipos de registro](/pt-br/documentacao/plataforma/edge-dns/tipos-de-registro/). A API recusa qualquer outro tipo, como `SOA`, com `10039`. A Azion escreve o registro SOA de cada zona e os registros NS do apex dela, como mostra [Como o Edge DNS funciona](/pt-br/documentacao/plataforma/edge-dns/como-funciona/#aname-no-apex).
- **Apex**: um registro CNAME é recusado no apex, o próprio domínio da zona, com `19005`. Um registro ANAME aponta o apex para um hostname no lugar: ele responde como um registro A, e o destino dele precisa estar sob `azioncdn.net`, `azionedge.net` ou `azionedge.com`. Para os passos, consulte [Aponte um domínio raiz com ANAME](/pt-br/documentacao/guias/seguranca-de-aplicacoes/dns/acessar-root-domain/).
- **Política weighted**: os pesos dividem as respostas, não as requisições. Cada nameserver guarda a resposta que escolheu pelo TTL do registro ou por alguns minutos, o que for menor. Cada resolver guarda essa resposta pelo TTL que recebe, então as proporções se equilibram só ao longo de muitas consultas, como explica [Como o Edge DNS funciona](/pt-br/documentacao/plataforma/edge-dns/como-funciona/#politicas-de-registro). A política vale para registros A, AAAA, ANAME, CNAME e MX, e a API recusa a política nos outros tipos com `19017`.
- **Nameservers**: os mesmos três nameservers, `ns1.aziondns.net`, `ns2.aziondns.com` e `ns3.aziondns.org`, servem todas as zonas, e a API os retorna somente para leitura. Delegue o domínio aos três no registrador dele, como mostra [Zonas e registros](/pt-br/documentacao/plataforma/edge-dns/zonas-e-registros/#nameservers-e-soa).
- **Propagação**: uma zona ou um registro salvo não precisa de etapa de deployment, e cada nameserver responde a partir de um cache, como explica [Como o Edge DNS funciona](/pt-br/documentacao/plataforma/edge-dns/como-funciona/#cache-e-propagacao). Uma zona ou um registro novo pode levar cerca de um minuto para responder em todos os nameservers, e uma alteração em um registro existente pode levar alguns minutos. Uma consulta por um nome antes que ele responda guarda `NXDOMAIN` em cache nesse nameserver por até uma hora, o mínimo do SOA, então espere cerca de um minuto depois de salvar um nome novo antes de consultá-lo.
- **Observabilidade**: as consultas que as suas zonas recebem aparecem como contagens no [dashboard de Edge DNS do Real-Time Metrics](/pt-br/documentacao/plataforma/real-time-metrics/dashboards-secure/#edge-dns), como um registro por consulta no [Real-Time Events](/pt-br/documentacao/plataforma/real-time-events/fontes-de-dados/#edge-dns) e nas duas formas pela [API GraphQL](/pt-br/documentacao/devtools/graphql/recursos/#datasets).
- **Proteção contra DDoS**: [DDoS Protection](/pt-br/documentacao/plataforma/workloads/ddos-protection/ddos-mitigation/) também protege o serviço DNS, e os ataques que ela mitiga incluem DNS flood, mesmo com consultas DNS bem formadas. Ela está sempre ativa e não precisa de configuração.
- **Registro do domínio**: o domínio continua registrado no seu registrador, onde você define os nameservers dele e o renova, e cabe a você manter corretos as zonas e os registros dele. A Azion pode remover zonas que não estão em uso, como determinam os [Termos de Serviço](/pt-br/documentacao/contratos/tds/).

## Limites padrão

Cada valor abaixo se aplica a uma zona, a um registro ou a uma requisição de lista. Uma requisição que ultrapassa um limite da API retorna `400` com um array `errors`, e a zona ou o registro continua como estava. Cada erro da API aparece com o código, o título e a frase de `detail`.

| Escopo | Limite | Além do limite |
| --- | --- | --- |
| `name` da zona | 1 a 50 caracteres | `10046` `Max Length`: `Ensure this field has no more than 50 characters.` |
| `domain` da zona | Até 200 caracteres, o limite que a API declara. O domínio precisa terminar em um domínio de topo (TLD) válido, não pode estar hospedado em nenhuma outra zona na Azion nem ficar sob um domínio que outra conta hospeda. Ele fica fixo na criação. | `19035` `Invalid Domain TLD`: `Your domain must use a valid TLD.` Quando uma zona de qualquer conta já hospeda o domínio, `10012` `Unique Field`: `This field must be unique.` Quando o domínio é um subdomínio de um domínio que outra conta hospeda, `19001` `Domain Already In Use`: `Domain Belongs to Another Account.` Uma atualização que envia `domain` recebe `19036` `Domain Cannot Be Modified`: `The domain cannot be changed in update operations. Please create a new record instead.` No Console, um domínio cujo último rótulo não tem de 2 a 63 letras, ou cujos outros rótulos têm algo além de letras, dígitos e hífens, mostra `Invalid domain`. |
| `name` do registro | Até 255 caracteres | `10046` `Max Length`: `Ensure this field has no more than 255 characters.` |
| Rótulo em um `name` de registro | Até 63 caracteres por rótulo separado por ponto | `10076` `Invalid Pattern Match.` |
| `ttl` do registro, na API | 1 a 2.147.483.647 segundos | `0` recebe `10050` `Min Value`: `Ensure this value is greater than or equal to 1.` Um valor acima de 2.147.483.647 recebe `10068` `Max Value`: `Ensure this value is less than or equal to 2147483647.` |
| **TTL (seconds)**, no Console | 1 a 604.800 segundos. O campo vem preenchido com `3600`. | O campo aceita `0`, e a API então recusa o registro com `10050` `Min Value`: `Ensure this value is greater than or equal to 1.` |
| `ttl` de um registro ANAME | Apenas `20`. O Console preenche 20 quando você seleciona ANAME. | Qualquer outro valor, inclusive o padrão `3600`, recebe `19011` `Invalid TTL For QTYPE`: `The TTL value is not valid for the selected record type.` |
| Valores em um registro A, AAAA, ANAME, DS, MX ou NS | Até 10 valores em `rdata` | `19007` `Invalid RData Size`: `The 'rdata' cannot contain more than 10 items for the selected record type.` |
| Valores em um registro CNAME ou PTR | Exatamente 1 valor em `rdata` | `19006` `Invalid RData For CNAME Record`: `The 'rdata' cannot contain more than one item when 'type' is 'CNAME'.` Um registro PTR recebe o mesmo código, o mesmo título e o mesmo `detail`. |
| Valores em um registro TXT, CAA ou SRV | Mais de 10 valores são aceitos | Nenhum limite de 10 valores se aplica. |
| Registros SRV em um nome | 1 registro. Os valores dele não têm limite de 10 valores. | Um segundo registro SRV no mesmo nome recebe `19004` `Record Already Exists`: `There is already another record matching those data.` |
| Valor TXT | Até 1.000 caracteres por valor | `19024` `Invalid TXT Record Answer Size`: `You need to provide an answer with less than 1000 characters.` Um valor de exatamente 1.000 caracteres é aceito. |
| `weight` do registro | 0 a 255. Um registro com peso `0` é mantido e nunca é respondido. | `10068` `Max Value`: `Ensure this value is less than or equal to 255.` |
| `description` do registro | Até 45 caracteres | `10046` `Max Length`: `Ensure this field has no more than 45 characters.` O texto de ajuda de **Description** no Console informa o limite de 45 caracteres, mas não o verifica, então a API recusa o valor mais longo quando você seleciona **Save**. |
| Itens por página de lista, `page_size` | Até 100 | `10097` `Invalid Page Size`: `Page size must be between 0 and 100.` |

Para ler uma lista maior que uma página, defina `page_size` como 100 e percorra as páginas com o parâmetro de consulta `page`. Para cada erro e a correção dele, consulte [Zonas e registros](/pt-br/documentacao/plataforma/edge-dns/zonas-e-registros/#erros).
