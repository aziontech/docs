Você pode criar uma exceção do WAF que impede uma regra interna de pontuar os valores de query string em um caminho pelo Azion Console, pela Azion CLI ou pela API. Para uma exceção nos headers da requisição, consulte [Isente headers de requisição de uma regra do WAF](/pt-br/documentacao/guias/seguranca-de-aplicacoes/firewall-e-waf/isentar-header/).

Os exemplos impedem que a regra `1013`, a regra do apóstrofo, pontue a query string das requisições a `/search`, no rule set `<waf-id>`. Substitua-os pela sua regra, pelo seu caminho e pelo seu rule set.

## Crie a exceção

A condição é _Any Query String Value_, `any_query_string_value` na API, que cobre o valor de todo argumento da query string. Uma condição que indica um argumento, _Specific Query String Name_, é aceita, e nos testes ela não eliminou uma correspondência no argumento que indicava.

Uma condição mais restrita carrega o nome do argumento em **Value**: _Specific Query String Value_, `specific_query_string_value` na API. Em outro teste, com a regra `1013` e o argumento `filter` em **Value**, ela eliminou a correspondência apenas em `filter`. Outro argumento no mesmo caminho ainda foi recusado, e o valor do argumento em **Value** não eliminou nada.

<Tabs client:visible sharedStore="interface">

<Fragment slot="panel.console">

### Console

Para criar a exceção no Azion Console:

<DocSteps>
  <DocStep title="Abra a página WAF Rules">

  Acesse [Azion Console](https://console.azion.com/) > **WAF Rules**.

  </DocStep>
  <DocStep title="Selecione o rule set que bloqueou a requisição" />
  <DocStep title="Abra a aba Allowed Rules e selecione + Allowed Rule" />
  <DocStep title="Selecione a regra a isentar">

  Em **Rule ID**, selecione `1013`.

  </DocStep>
  <DocStep title="Descreva a exceção e restrinja-a a um caminho">

  Em **Description**, insira `Allow apostrophes in the storefront search`. Em **Path**, insira `/search`.

  </DocStep>
  <DocStep title="Selecione a parte da requisição">

  Em **Condition**, selecione _Any Query String Value_. Mantenha desligado o switch **Active** da seção **Regex**, para que as strings sejam comparadas como texto.

  </DocStep>
  <DocStep title="Selecione Save" />
</DocSteps>

A aba **Allowed Rules** lista a exceção.

</Fragment>

<Fragment slot="panel.cli">

### CLI

Para criar a exceção com a Azion CLI, salve-a como `exception.json`:

```json
{
  "rule_id": 1013,
  "name": "Allow apostrophes in the storefront search",
  "path": "/search",
  "operator": "contains",
  "active": true,
  "conditions": [
    { "match": "any_query_string_value" }
  ]
}
```

Depois, crie a exceção a partir do arquivo:

```bash
azion create waf-exceptions --waf-id <waf-id> --file exception.json
```

O comando imprime o ID da nova exceção:

```text
Created WAF Exception with ID <exception-id>
```

Passe o corpo com `--file`. Na Azion CLI 4.26.2, a flag `--conditions` envia um array vazio qualquer que seja o valor que ela tenha, e a API o recusa com `10049 Min Length List Field`.

</Fragment>

<Fragment slot="panel.api">

### API

Para criar a exceção com a API, envie uma requisição `POST` para o endpoint de exceções do rule set:

```bash
curl --request POST \
  --url https://api.azion.com/v4/workspace/wafs/<waf-id>/exceptions \
  --header 'Accept: application/json' \
  --header 'Authorization: Token [TOKEN VALUE]' \
  --header 'Content-Type: application/json' \
  --data '{
  "rule_id": 1013,
  "name": "Allow apostrophes in the storefront search",
  "path": "/search",
  "operator": "contains",
  "active": true,
  "conditions": [
    { "match": "any_query_string_value" }
  ]
}'
```

A API responde `202` e retorna a exceção:

```json
{
  "state": "pending",
  "data": {
    "id": <exception-id>,
    "rule_id": 1013,
    "name": "Allow apostrophes in the storefront search",
    "path": "/search",
    "conditions": [
      { "match": "any_query_string_value" }
    ],
    "operator": "contains",
    "active": true,
    ...
  }
}
```

</Fragment>

</Tabs>

A regra `1013` para de pontuar os valores de query string das requisições a `/search`. Em um teste, a exceção eliminou a regra em uma requisição ao caminho dela, e o mesmo apóstrofo na query string ainda recebeu `400` em outro caminho. Envie uma requisição a que a regra correspondia antes e verifique se ela agora passa.

:::caution[Atenção]
Uma exceção também elimina o que a regra pegava em ataques. No mesmo teste, na sensibilidade `highest`, a injeção `1' OR '1'='1` passou no caminho isento: sem a regra `1013`, ela pontuou `2` em SQL injection, abaixo do limiar.
:::

:::note[nota]
Nos testes, uma exceção entrou em vigor vários minutos depois de criada e, até lá, as respostas alternaram. Com `contains`, a exceção se aplicou ao seu `path` exato: um caminho mais longo que começava com ele ainda recebeu `400`. O `rule_id` tem como padrão `0`, que é toda regra interna, então defina-o como a regra que correspondeu.
:::
