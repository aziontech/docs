You can measure the speed of an application on Azion from two sides. [Edge Pulse](/en/documentation/platform/edge-pulse/) collects what real users' browsers see, and [Real-Time Metrics](/en/documentation/platform/real-time-metrics/) charts what Azion served for every request. To compare a page before and after the move to Azion, refer to the last section.

---

## Prerequisites

- An application served by a workload on Azion. To set them up, refer to [Migrate an application to Azion](/en/documentation/fundamentals/migrate-to-azion/) or [First deploy](/en/documentation/fundamentals/first-deploy/).
- Access to the HTML of the pages you want to monitor, to add the Edge Pulse tag.

---

## Measure what real users see with Edge Pulse

Edge Pulse is Real User Monitoring. A JavaScript tag in your pages collects navigation, availability, latency, and bandwidth data from real visitors' browsers. Each browser tests three addresses of Azion's infrastructure at a time, once every 30 minutes. The collection does not burden the visitor. To add the tag:

<DocSteps>
  <DocStep title="Open the Edge Pulse page">

  Access [Azion Console](https://console.azion.com/) > **Edge Pulse**.

  </DocStep>
  <DocStep title="Copy the tag">

  Select **Copy to Clipboard** on the tag you need. The **Default Tag** runs after the page loads. The **Pre-loading Tag** is for pages whose Content Security Policy blocks inline JavaScript.

  </DocStep>
  <DocStep title="Add the tag to every page you want to monitor">

  Paste it in the HTML of each page, before the closing `body` tag.

  </DocStep>
  <DocStep title="Publish the pages" />
</DocSteps>

The browsers of your visitors start sending measurements, and the collected data is available in [Real-Time Events](/en/documentation/platform/real-time-events/).

:::note
Edge Pulse respects the Do Not Track setting of the browser. With it on, a new identifier is generated on every visit.
:::

## Read the request metrics in Real-Time Metrics

Real-Time Metrics charts every request Azion served, in near real time. For speed, the useful number is how much of the traffic the cache answered without waiting for your origin. To open the charts:

<DocSteps>
  <DocStep title="Open Real-Time Metrics">

  Access [Azion Console](https://console.azion.com/) > **Real-Time Metrics**.

  </DocStep>
  <DocStep title="Select the Build tab, then Applications" />
  <DocStep title="Compare saved and missed data">

  In the **Data Transferred** subtab, compare **Saved Data** with **Missed Data**. The first is what the cache answered. The second is what reached your origin.

  </DocStep>
  <DocStep title="Narrow the period">

  Use the time filters to compare the window before a change with the window after it.

  </DocStep>
</DocSteps>

A larger share of saved data after a change means fewer requests waited for your origin.

## Compare a page before and after the move

Before you point the domain to Azion, your own computer can reach the application through the `hosts` file. Everyone else still reaches the current provider, so you get the same page from both places. To compare:

1. Load the page from the current provider and note the load time your browser's developer tools report.
2. Stage the application through the `hosts` file. For the steps, refer to [How to stage an application through the hosts file](/en/documentation/guides/application-development/getting-started/stage-applications-through-hosts-file/).
3. Load the same page twice in a private browser window and keep the second time. The first load fills the cache. The second is what visitors get.

The difference between the two times is what Azion adds for that page. Repeat it with the pages your users open most.
