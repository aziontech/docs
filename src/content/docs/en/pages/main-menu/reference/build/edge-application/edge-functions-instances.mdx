A function instance binds one function to one application. The instance carries the **Args**, the arguments passed into the context of the function's execution in JSON format. The code of the function cannot be edited at instantiation: an instance sets the Args and nothing else.

A rule in [Rules Engine](/en/documentation/platform/applications/rules-engine/) invokes the instance, not the function. The same function can be instantiated in more than one application, and each instance carries its own Args. An instance that no rule names never runs.

A firewall instantiates functions the same way. Refer to [Functions Instances for Firewall](/en/documentation/platform/firewall/functions-instances/) for the firewall object and its own limits.

---

## Instance fields

The [Azion API](https://api.azion.com/) creates an instance under the application it belongs to. These are the fields you set:

| Field | Type | Required | Description |
| --- | --- | --- | --- |
| `name` | string | Yes | Name of the instance. |
| `edge_function` | integer | Yes | ID of the function the instance binds. This ID differs from the ID of the instance. |
| `args` | JSON object | No | Arguments passed into the context of the function's execution. The default is an empty object, `{}`. |
| `active` | boolean | No | Whether the instance is active. |

The API returns three more fields: `id`, the ID of the instance; `last_editor`, the email address of the account that last changed it; and `last_modified`, the timestamp of that change.

A `POST` request to the `functions` resource of an application creates an instance:

<Code lang="bash" code={`
curl --request POST \\
  --url https://api.azion.com/v4/edge_application/applications/<application_id>/functions \\
  --header 'Accept: application/json' \\
  --header 'Authorization: Token [TOKEN VALUE]' \\
  --header 'Content-Type: application/json' \\
  --data '{
  "name": "My instance Name",
  "edge_function": <function_id>,
  "active": true
}'
`} />

The API answers with the created object:

<Code lang="json" code={`
{
  "state": "pending",
  "data": {
    "id": <edge_function_instance_id>,
    "name": "My Function Instance",
    "args": {},
    "edge_function": 123456,
    "active": true,
    "last_editor": "your-email@example.com",
    "last_modified": "2025-08-14T16:41:56.699896Z"
  }
}`} />

The `"state": "pending"` value means the change takes a few minutes to propagate before it takes effect.

You create the same object in the **Functions Instances** tab of an application in Azion Console. In the `azion.config.js` file that [Azion CLI](/en/documentation/devtools/cli/) reads, an instance carries `name`, `args`, and `active`, and `ref` names the function by name or by ID.

## Args

Args are the arguments an instance passes into the context of the function's execution, written as a JSON object. The code reads a key at run time and the instance decides its value, so one function behaves differently in each place it is instantiated. A function can define default Args of its own: the Args of an instance override the keys they repeat, and every key the instance leaves out keeps its default value.

An Args object that sets one key:

<Code lang="json" code={`
{
  "value": "hello_world"
}
`} />

The Args object holds a maximum of 100 KB, and an object above that ceiling makes the function fail at instantiation. For every Functions limit, refer to [Limits](/en/documentation/build/functions/limits/).

Args are per-instance configuration. Sensitive values such as API keys, credentials, and access tokens belong in [environment variables](/en/documentation/build/functions/environment-variables/) instead.

---

## Run Function behavior

**Run Function** is the [Rules Engine](/en/documentation/platform/applications/rules-engine/#run-function) behavior that invokes an instance. The rule names the instance, the execution phase, and the criteria that trigger it. When a request meets those criteria, the function runs on Azion's distributed infrastructure.

Run Function is available in the Request Phase and in the Response Phase, and it requires the [Application Accelerator](/en/documentation/build/application-accelerator/) module. In the Azion API, the behavior is `run_function` and its `value` attribute holds the ID of the instance.

For the execution phases, the criteria, and the order behaviors run in, refer to [How Functions works](/en/documentation/build/functions/how-it-works/).
