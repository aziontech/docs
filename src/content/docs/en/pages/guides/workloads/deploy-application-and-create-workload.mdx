An [Application](/en/documentation/platform/applications/) holds the settings, rules, and functions that define how your code runs on Azion's edge network. A [Workload](/en/documentation/platform/workloads/) is the entry point that exposes an Application to the internet, binding it to a domain and an infrastructure. To go live, you need both: an Application to run your code, and a Workload to route traffic to it.

This guide walks through that flow: deploying an Application with the Azion CLI, then creating a Workload to make it reachable.

<DocSteps>
  <DocStep title="Deploy your Application">

  Inside your project's folder, use the Azion CLI to initialize, build, and deploy your Application.

  ```sh
  azion init
  ```

  Answer the prompts to name your project and pick a template. Once initialized, build and deploy it:

  ```sh
  azion build
  ```

  ```sh
  azion deploy
  ```

  Output:

  ```sh
  ✔ Application deployed successfully
  Application Name: my-application
  Application ID: 1234567
  ```

  Your Application is now created and running on Azion, but it doesn't have a public address yet — that's what a Workload provides.

  </DocStep>
  <DocStep title="Create a Workload">

  A Workload links your Application to a domain. You can create one through the Azion Console, or declare it as code with Terraform.

  **Using the Azion Console**

  1. Access [Azion Console](/en/documentation/guides/platform/account-and-billing/how-to-access-azion-console/) > **Workloads**.
  2. Click the **+ Workload** button.
  3. Give your Workload a name.
  4. Select the **Infrastructure**: **Production Infrastructure** or **Staging Infrastructure**.
  5. In **Application**, select the Application you deployed in the previous step.
  6. Click the **Save** button.

  **Using Terraform**

  To manage the same flow as code, declare the Application and the Workload as resources:

  ```hcl
  resource "azion_application_main_setting" "my_app" {
    name = "my-application"
  }

  resource "azion_workload" "my_workload" {
    name = "my-workload"

    # Points the Workload at the Application deployed above
    workload_id = azion_application_main_setting.my_app.id
  }

  resource "azion_workload_deployment" "my_deployment" {
    workload_id = azion_workload.my_workload.id
  }
  ```

  ```sh
  terraform init
  ```

  ```sh
  terraform apply
  ```

  For the full set of arguments for each resource, see the [Applications](/en/documentation/devtools/terraform/applications/) and [Workloads](/en/documentation/devtools/terraform/workloads/) Terraform resource references.

  </DocStep>
  <DocStep title="Verify your deployment">

  Wait a few minutes for the Workload to propagate, then access the domain you configured — or the generated `xxxxxxxxxx.azion.app` address — to see your Application online.

  </DocStep>
</DocSteps>
