You deploy the SQL Database Starter Kit from Azion Console, and the deployment builds a JavaScript CRUD project on [SQL Database](/en/documentation/store/sql-database/).

The deployment creates a GitHub repository holding the project, an application, a database, and a domain that reaches the application from a browser. The template runs on [Application Accelerator](/en/documentation/build/application-accelerator/), [Functions](/en/documentation/build/functions/), and [Cache](/en/documentation/build/cache/).

---

## Prerequisites

- SQL Database enabled on your account. The product is in Preview and is not enabled by default, so request access through [Technical Support](/en/documentation/support/). The number of databases each plan includes is on [SQL Database limits](/en/documentation/store/sql-database/limits/).
- A GitHub account. The deployment creates the project repository under it, and every push to that repository is deployed automatically.
- An account that reaches Azion Console. Refer to [How to access Azion Console](/en/documentation/guides/platform/account-and-billing/how-to-access-azion-console/).
- The products the template runs on can generate usage costs. Refer to [Pricing](/en/documentation/fundamentals/pricing/#sql-database).

## Deploy the template

You obtain and configure the template from Azion Console. To start the deployment:

<DocSteps>
  <DocStep title="Open the template in Azion Console">

  Access the [SQL Database Starter Kit](https://console.azion.com/create/azion/edgesql-starter-kit) template in [Azion Console](https://console.azion.com/).

  </DocStep>
</DocSteps>

The configuration form opens, carrying the fields the deployment reads. Fields marked with an asterisk are mandatory.

---

## Set up the template

The form asks for the GitHub connection that creates the repository and for the name the deployed resources take. To set up the template:

<DocSteps>
  <DocStep title="Connect Azion with your GitHub account">

  A window opens to confirm the installation of the [Azion GitHub App](/en/documentation/guides/application-development/automation/azion-github-app/), which connects your GitHub account with Azion. Define your permissions and repository access there.

  </DocStep>
  <DocStep title="Select the Git Scope" />
  <DocStep title="Name the application">

  Enter a name for the application. The storage bucket and the function take the same name, so use a unique and memorable one. A name already in use is refused with an error message.

  </DocStep>
  <DocStep title="Start the deployment">

  Select **Deploy**.

  </DocStep>
</DocSteps>

A window shows the logs while the deployment runs. When it finishes, the page shows the information about the application and the options to continue.

:::note
The link on the finished page opens the application in a browser. The application takes a few minutes to propagate across Azion's distributed infrastructure, so the address can stay inactive until the propagation finishes.
:::

## Manage the template

The settings the deployment writes are a starting point, and every one of them is edited from Azion Console afterwards. To reach the settings of the application:

<DocSteps>
  <DocStep title="Open the application list">

  Access [Azion Console](https://console.azion.com/) > **Applications**. The page lists every application your account created.

  </DocStep>
  <DocStep title="Select the application">

  Find the application the template created and select it. The list is ordered alphabetically, and the search filters by **Application Name** only.

  </DocStep>
</DocSteps>

The application opens on the page that carries every setting you can configure. For more information, refer to [Applications first steps](/en/documentation/platform/applications/first-steps/) and [Create and manage databases](/en/documentation/guides/application-development/data/manage-sql-database/).

### Add a custom domain

The deployment assigns the application an Azion Workload domain, in the format `xxxxxxxxxx.map.azionedge.net/`, and that address reaches the application from a browser. A custom domain reaches the same application under a name of your own. For more information, refer to [How to configure a domain](/en/documentation/guides/platform/migration/configure-a-domain/).
