[Rules Engine](/en/documentation/platform/applications/rules-engine/) is a feature of [Applications](/en/documentation/platform/applications/) that applies the business rules of your application without code. The reverse-proxy architecture of an application runs each rule in one of two phases. The **Request Phase** carries the data a client sends to an origin server. The **Response Phase** carries the data the origin sends to the client. You create a rule for either phase from Azion Console.

Some Rules Engine variables and behaviors are available only while [Application Accelerator](/en/documentation/build/application-accelerator/) is on. **Rewrite Request**, used in the first task, is one of them. **Filter Response Header**, used in the second, is not.

---

## Prerequisites

- An application. To create one, refer to [Build an application](/en/documentation/guides/application-development/getting-started/build-an-application/).
- Access to Azion Console. Refer to [Access Azion Console](/en/documentation/guides/platform/account-and-billing/how-to-access-azion-console/).
- Application Accelerator on the application, for the request rule only. The module can generate usage-related costs. For the rates, refer to [Pricing](/en/documentation/fundamentals/pricing/#application-accelerator).

---

## Turn on Application Accelerator

The module is off by default, and a rule uses **Rewrite Request** only while the module is on. To turn it on:

<DocSteps>
  <DocStep title="Open the application">

  Access [Azion Console](https://console.azion.com/) > **Applications** > **your application**.

  </DocStep>
  <DocStep title="Turn on the module">

  On the **Main Settings** tab, in the **Modules** section, turn on **Application Accelerator**.

  </DocStep>
  <DocStep title="Select Save" />
</DocSteps>

The application runs with Application Accelerator, and a rule can use **Rewrite Request**.

## Rewrite a request path

A rule in the **Request Phase** runs before the request to the origin servers is completed. With **Rewrite Request**, a client receives content from a URI that does not match its path at the origin.

The goal of this task is to deliver the contents of `/content/page.html` when a client requests `https://www.domain.com/page`. To create the rule that rewrites the request:

<DocSteps>
  <DocStep title="Go to the Rules Engine tab">

  Access [Azion Console](https://console.azion.com/) > **Applications** > **your application**, then go to the **Rules Engine** tab.

  </DocStep>
  <DocStep title="Select + Rule" />
  <DocStep title="Name the rule">

  Enter a name that identifies the rule, and a description if you need one.

  </DocStep>
  <DocStep title="Select Request Phase" />
  <DocStep title="Select the variable in the Criteria section">

  In the **Criteria** section, select the `${uri}` variable.

  </DocStep>
  <DocStep title="Set the comparison operator">

  Set the comparison operator to _is equal to_.

  </DocStep>
  <DocStep title="Enter the argument">

  Enter `/page` as the argument. The criteria identifies the URL of the request by the URI trailing slash `/`.

  </DocStep>
  <DocStep title="In the Behaviors section, select Rewrite Request" />
  <DocStep title="Enter the behavior argument">

  Enter `${uri}content/page.html`. The argument concatenates the `${uri}` variable, whose value is `/`, with the path of the page.

  </DocStep>
  <DocStep title="Select Save" />
</DocSteps>

A request to `https://www.domain.com/page` returns the contents of `/content/page.html`. The client does not enter the entire address in the browser. A new rule takes a few minutes to propagate.

## Remove a header from the response

A rule in the **Response Phase** runs before the response is delivered to the client. With **Filter Response Header**, the rule removes an HTTP header from that response. The behavior does not require Application Accelerator.

A response carries the `Server` header, which holds information about the server that produced it. Removing that header keeps clients from receiving information about the infrastructure of your application. The removal reduces what an attacker can read about that infrastructure.

:::note
Exercise caution when you remove a header from your application. Confirm that the removal does not interfere with applicable standards and guidelines.
:::

To filter the `Server` header from the response:

<DocSteps>
  <DocStep title="Go to the Rules Engine tab">

  Access [Azion Console](https://console.azion.com/) > **Applications** > **your application**, then go to the **Rules Engine** tab.

  </DocStep>
  <DocStep title="Select + Rule" />
  <DocStep title="Name the rule">

  Enter a name that identifies the rule, and a description if you need one.

  </DocStep>
  <DocStep title="Select Response Phase" />
  <DocStep title="Select the variable in the Criteria section">

  In the **Criteria** section, select the `${uri}` variable.

  </DocStep>
  <DocStep title="Set the comparison operator">

  Set the comparison operator to _starts with_.

  </DocStep>
  <DocStep title="Enter the argument">

  Enter `/` as the argument. The criteria runs the rule for the entire application.

  </DocStep>
  <DocStep title="In the Behaviors section, select Filter Response Header" />
  <DocStep title="Enter the behavior argument">

  Enter `Server`. The argument removes every instance of the `Server` header from all responses.

  </DocStep>
  <DocStep title="Select Save" />
</DocSteps>

Responses from the application no longer carry the `Server` header. A new rule takes a few minutes to propagate.
