[Application Accelerator](/en/documentation/build/application-accelerator/) unlocks the caching of `POST` and `OPTIONS` responses, beyond the `GET` and `HEAD` requests an application caches natively. You select the methods in a cache setting from Azion Console, then apply that cache setting with [Rules Engine](/en/documentation/platform/applications/rules-engine/).

A cached `POST` object does not share a [cache key](/en/documentation/build/cache/cache-keys/) with the `GET` response for the same path. Azion prefixes the method to the key of any request other than `GET` or `HEAD`. For a cached `POST` or `OPTIONS` object, the key also appends `@@` and the MD5 hash of the request body. An `OPTIONS` request to `https://static.yourdomain.com/page` is stored under the key `optionshttpsstatic.yourdomain.com/page`. A `POST` to a dynamic path is stored under `httpsdynamic.yourdomain.com/path@@md5_of_post_arguments`.

A `POST` body that varies per request therefore produces one cached object per request. For what a variation costs, refer to [How Application Accelerator works](/en/documentation/build/application-accelerator/how-it-works/).

## Prerequisites

- An application. To create one, refer to [Build an application](/en/documentation/guides/application-development/getting-started/build-an-application/).
- Access to Azion Console. Refer to [Access Azion Console](/en/documentation/guides/platform/account-and-billing/how-to-access-azion-console/).
- Application Accelerator can generate usage-related costs. For the rates, refer to [Pricing](/en/documentation/fundamentals/pricing/#application-accelerator).

## Turn on Application Accelerator

The module is off by default, and a cache setting stores a `POST` or `OPTIONS` response only while the module is on. To turn it on:

<DocSteps>
  <DocStep title="Open the application">

  Access [Azion Console](https://console.azion.com/) > **Applications** > **your application**.

  </DocStep>
  <DocStep title="Turn on the module">

  On the **Main Settings** tab, in the **Modules** section, turn on **Application Accelerator**.

  </DocStep>
  <DocStep title="Select Save" />
</DocSteps>

The application runs with Application Accelerator, and its cache settings can select the `POST` and `OPTIONS` methods.

## Cache the responses to POST requests

An application serves a search API at `/api/search`. The endpoint answers a `POST` request whose body carries the search terms, and the results change every 30 seconds. To store one object per body, and to expire it at the same interval:

<DocSteps>
  <DocStep title="Open the Cache Settings tab">

  Access [Azion Console](https://console.azion.com/) > **Applications** > **your application**, then go to the **Cache Settings** tab.

  </DocStep>
  <DocStep title="Select + Cache" />
  <DocStep title="Name the cache setting">

  In **Name**, enter a name that identifies the setting. For example: `search-post`.

  </DocStep>
  <DocStep title="Set Max Age">

  Under **Cache**, select _Override cache behavior_ and set **Max Age** to `30`.

  </DocStep>
  <DocStep title="Select the POST method">

  Under **Application Accelerator**, open **Cache vary by Method** and select the **POST** checkbox.

  </DocStep>
  <DocStep title="Select Save" />
</DocSteps>

The cache setting appears in the **Cache Settings** tab. It stores the response to a `POST` request once a rule applies it.

**Cache vary by Method** holds two checkboxes, **POST** and **OPTIONS**. To cache `OPTIONS` responses, select **OPTIONS** in the same control; one cache setting can carry both methods. The Azion API sets the same methods with the `cache_vary_by_method` field of a cache setting, documented in [Application Accelerator settings](/en/documentation/build/application-accelerator/settings/).

A cache setting takes effect only when a rule applies it. To apply this one to the `/api/search` URI:

<DocSteps>
  <DocStep title="Go to the Rules Engine tab" />
  <DocStep title="Select + Rule" />
  <DocStep title="Name the rule">

  Enter a name for the rule. For example: `search-post rule`.

  </DocStep>
  <DocStep title="Select Request Phase" />
  <DocStep title="Select the variable in the Criteria section">

  In the **Criteria** section, select the `${uri}` variable.

  </DocStep>
  <DocStep title="Select starts with as the comparison operator" />
  <DocStep title="Enter the argument">

  Enter `/api/search` as the argument.

  </DocStep>
  <DocStep title="In the Behaviors section, select Set Cache Policy" />
  <DocStep title="Select the cache setting you created" />
  <DocStep title="Select Save" />
</DocSteps>

Requests whose URI starts with `/api/search` carry the cache setting. Azion stores one object per request body and holds each object for 30 seconds. A new rule takes a few minutes to propagate.

:::note
Before a cache setting selects **POST**, a `POST` request logs no cache status: the `X-Cache` header carries `-`, because the content is restricted from caching. To read the header on a request, refer to [Verify cache indicators with ModHeader](/en/documentation/guides/application-performance/cache-and-purge/check-page-cache-time/).
:::

A cached `POST` or `OPTIONS` object expires with a cache key purge that lists each variation, or with a wildcard purge ending in `@@*`. For the purge types, refer to [Real-Time Purge](/en/documentation/build/cache/real-time-purge/#purge-content-that-varies).
