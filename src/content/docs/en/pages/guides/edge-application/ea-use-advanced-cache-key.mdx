[Application Accelerator](/en/documentation/build/application-accelerator/) unlocks [Advanced Cache Key](/en/documentation/build/cache/cache-settings/#advanced-cache-key), which varies a cached object by query string argument or by cookie. You configure it in a cache setting from Azion Console, then apply that cache setting with [Rules Engine](/en/documentation/platform/applications/rules-engine/).

For content that does not vary between requests, refer to [Configure cache policies](/en/documentation/guides/application-performance/cache-and-purge/cache-settings/). For what a variation changes in the cache key, refer to [How Application Accelerator works](/en/documentation/build/application-accelerator/how-it-works/).

---

## Prerequisites

- An application. To create one, refer to [Build an application](/en/documentation/guides/application-development/getting-started/build-an-application/).
- Access to Azion Console. Refer to [Access Azion Console](/en/documentation/guides/platform/account-and-billing/how-to-access-azion-console/).
- Application Accelerator can generate usage-related costs. For the rates, refer to [Pricing](/en/documentation/fundamentals/pricing/#application-accelerator).

---

## Turn on Application Accelerator

The module is off by default, and a cache setting varies the cached object only while the module is on. To turn it on:

<DocSteps>
  <DocStep title="Open the application">

  Access [Azion Console](https://console.azion.com/) > **Applications** > **your application**.

  </DocStep>
  <DocStep title="Turn on the module">

  On the **Main Settings** tab, in the **Modules** section, turn on **Application Accelerator**.

  </DocStep>
  <DocStep title="Select Save" />
</DocSteps>

The application runs with Application Accelerator, and its cache settings can vary the cached object by query string or cookie.

## Vary the cache by a query string argument

An application serves the URL `domain.com/page?city=city_name`. The `/page` URI calls an API that lists content for the city in the `city` argument. The API refreshes that content every five minutes. To store one object per city, and to expire it at the same interval:

<DocSteps>
  <DocStep title="Open the Cache Settings tab">

  Access [Azion Console](https://console.azion.com/) > **Applications** > **your application**, then go to the **Cache Settings** tab.

  </DocStep>
  <DocStep title="Select + Cache" />
  <DocStep title="Name the cache setting">

  In **Name**, enter a name that identifies the setting. For example: `city-listing`.

  </DocStep>
  <DocStep title="Set the browser cache">

  Under **Browser Cache**, select _Override cache settings_ and set the maximum age to `300`.

  </DocStep>
  <DocStep title="Set Max Age">

  Under **Cache**, select _Override cache behavior_ and set **Max Age** to `300`.

  </DocStep>
  <DocStep title="Allowlist the argument">

  Under **Application Accelerator**, open **Cache vary by Query String** and set **Behavior** to _Allowlist_.

  </DocStep>
  <DocStep title="Enter the argument">

  Add `city` to the list of query string arguments.

  </DocStep>
  <DocStep title="Select Save" />
</DocSteps>

The cache setting appears in the **Cache Settings** tab, and it varies the cached object by the `city` argument.

:::note
Cache keys are case sensitive. Azion stores `?city=Lisbon` and `?city=lisbon` as two objects.
:::

A cache setting takes effect only when a rule applies it. To apply this one to the `/page` URI:

<DocSteps>
  <DocStep title="Go to the Rules Engine tab" />
  <DocStep title="Select + Rule" />
  <DocStep title="Name the rule">

  Enter a name for the rule. For example: `city-listing rule`.

  </DocStep>
  <DocStep title="Select Request Phase" />
  <DocStep title="Select the variable in the Criteria section">

  In the **Criteria** section, select the `${uri}` variable.

  </DocStep>
  <DocStep title="Select starts with as the comparison operator" />
  <DocStep title="Enter the argument">

  Enter `/page` as the argument.

  </DocStep>
  <DocStep title="In the Behaviors section, select Set Cache Policy" />
  <DocStep title="Select the cache setting you created" />
  <DocStep title="Select Save" />
</DocSteps>

Requests whose URI starts with `/page` carry the cache setting. The browser and Azion hold each city object for 300 seconds. A new rule takes a few minutes to propagate.

## Vary the cache by a cookie

An application authenticates users with a cookie, and the `/profile` page it serves after a login must differ per session. The cookie `session_cookie` carries the value that identifies the session. To store one object per session:

<DocSteps>
  <DocStep title="Open the Cache Settings tab">

  Access [Azion Console](https://console.azion.com/) > **Applications** > **your application**, then go to the **Cache Settings** tab.

  </DocStep>
  <DocStep title="Select + Cache" />
  <DocStep title="Name the cache setting">

  In **Name**, enter a name that identifies the setting. For example: `profile-by-session`.

  </DocStep>
  <DocStep title="Set the cache behavior">

  In the **Browser Cache** and **Cache** sections, set the behavior and the age the profile page needs.

  </DocStep>
  <DocStep title="Allowlist the cookie">

  Under **Application Accelerator**, open **Cache vary by Cookies** and set **Behavior** to _Allowlist_.

  </DocStep>
  <DocStep title="Enter the cookie name">

  Add `session_cookie` to the list of cookie names.

  </DocStep>
  <DocStep title="Select Save" />
</DocSteps>

The cache setting appears in the **Cache Settings** tab, and it varies the cached object by the value of `session_cookie`. Cookie names are case sensitive, like every value that composes a cache key.

To apply this cache setting to the `/profile` URI:

<DocSteps>
  <DocStep title="Go to the Rules Engine tab" />
  <DocStep title="Select + Rule" />
  <DocStep title="Name the rule">

  Enter a name for the rule. For example: `profile rule`.

  </DocStep>
  <DocStep title="Select Request Phase" />
  <DocStep title="Select the variable in the Criteria section">

  In the **Criteria** section, select the `${uri}` variable.

  </DocStep>
  <DocStep title="Select starts with as the comparison operator" />
  <DocStep title="Enter the argument">

  Enter `/profile` as the argument.

  </DocStep>
  <DocStep title="In the Behaviors section, select Set Cache Policy" />
  <DocStep title="Select the cache setting you created" />
  <DocStep title="Select Save" />
</DocSteps>

Requests whose URI starts with `/profile` carry the cache setting. Each session receives the object cached for its own `session_cookie` value. A new rule takes a few minutes to propagate.
