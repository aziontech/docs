You can debug a deployment that fails with error 503 by asking a coding agent connected to the [Azion MCP server](/en/documentation/devtools/mcp/) for a workflow, then checking each point it raises. The same agent proposes ways to improve the Core Web Vitals scores of a site. No tool of the MCP server changes your account: you apply every fix yourself. For problems with the MCP server itself, refer to [Troubleshoot the MCP server](/en/documentation/devtools/mcp/troubleshooting/).

---

## Prerequisites

- An application deployed on Azion that returns error 503, and its URL.
- A coding agent connected to the MCP server. To connect one, refer to [MCP server quickstart](/en/documentation/devtools/mcp/configuration/).
- The Azion CLI, installed and logged in. To set it up, refer to [Azion CLI quickstart](/en/documentation/devtools/cli/quickstart/).
- `curl` on your machine.

---

## Debug a 503 error with your agent

The agent searches the Azion documentation for the error and returns a debugging workflow of five checks. You run each check, in order, and give the agent what you find. To debug the deployment:

<DocSteps>
  <DocStep title="Ask your agent about the error">

  Send the agent a prompt that names the error, such as:

  ```text
  My deployment is failing with error 503. How can I debug this?
  ```

  The prompt reaches the `search_azion_docs_and_site` tool, which returns Azion documentation on debugging.

  </DocStep>
  <DocStep title="Check the deployment logs">

  Read the HTTP event logs of your applications with the Azion CLI:

  ```bash
  azion logs http --tail
  ```

  The command prints the logs of the last 5 minutes and keeps running, one entry per request with its status. Look for the entries with status `503`. `--limit` sets how many entries the command shows, and `--pretty` prints each field on its own line. For the console logs of a function, run `azion logs cells`. For every flag, refer to [Azion CLI logs](/en/documentation/devtools/cli/logs/).

  </DocStep>
  <DocStep title="Verify the connector configuration">

  Azion reaches your origin through a connector. The agent searches for connector troubleshooting documentation and gives you a checklist of common connector issues. For the symptoms and their fixes, refer to [Troubleshoot Connectors](/en/documentation/platform/connectors/troubleshooting/).

  </DocStep>
  <DocStep title="Test the connectivity of the origin">

  Request the headers of your origin directly, replacing the host with yours:

  ```bash
  curl -I https://<your-origin-host>
  ```

  The command prints the status line and the headers the origin returns.

  </DocStep>
  <DocStep title="Review the Rules Engine">

  With the agent, check the rules of your application for redirect loops, and validate the cache configurations the rules apply. For the criteria and behaviors a rule takes, refer to [Rules Engine for Applications](/en/documentation/platform/applications/rules-engine/).

  </DocStep>
  <DocStep title="Monitor Real-Time Metrics">

  Ask the agent for a GraphQL query that analyzes the errors of your application in [Real-Time Metrics](/en/documentation/platform/real-time-metrics/). For how the MCP server writes and validates a query, refer to [Generate GraphQL queries with the MCP server](/en/documentation/guides/platform/observability/generate-graphql-queries-with-mcp/).

  </DocStep>
</DocSteps>

You end with the log entries of the failing requests, the results of the connector and origin checks, and the rules to correct. The agent proposes changes as text, and you apply each one in your application.

## Optimize Core Web Vitals with your agent

A request to improve the Core Web Vitals scores of a site returns proposals in four areas. To ask for them, send the agent a prompt such as:

```text
Optimize my site's Core Web Vitals scores
```

The agent provides:

- Image optimization strategies.
- Cache configuration recommendations.
- Rules Engine rules for resource hints.
- GraphQL queries to monitor the improvements.

The proposals are text. You apply the rules and cache changes in your application, and you run the queries with the GraphQL API. To turn a rule proposal into a rule, refer to [Generate Rules Engine rules with the MCP server](/en/documentation/guides/application-development/getting-started/generate-rules-engine-rules-with-mcp/).
