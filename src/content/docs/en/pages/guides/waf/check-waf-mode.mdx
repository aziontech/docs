You can read the mode of a [Web Application Firewall (WAF)](/en/documentation/secure/waf/) rule set, and change it, from Azion Console or the API.

The mode is an attribute of the `Set WAF` behavior on a [Rules Engine for Firewall](/en/documentation/platform/firewall/rules-engine/) rule. It is not a field of the rule set. One rule set can therefore run in one mode on one rule, and in another mode elsewhere. Applying a rule set for the first time belongs to [Create and apply a WAF rule set](/en/documentation/guides/application-security/firewall-and-waf/create-waf-rule-set/).

## Prerequisites

- A firewall bound to the workload that serves your application. Refer to [Protect your domain](/en/documentation/guides/application-security/firewall-and-waf/firewall-protect-your-domain/).
- A rule on that firewall carrying a `Set WAF` behavior. Refer to [Create and apply a WAF rule set](/en/documentation/guides/application-security/firewall-and-waf/create-waf-rule-set/).

## Check the mode

A firewall holds several rules, and only the one carrying `Set WAF` decides the mode. Find that rule first.

<Tabs client:visible sharedStore="interface">

<Fragment slot="panel.console">

To read the mode in Azion Console:

<DocSteps>
  <DocStep title="Open the firewall">

  Access [Azion Console](https://console.azion.com/) > **Firewalls**, then select the firewall that runs the rule set.

  </DocStep>
  <DocStep title="Select the Rules Engine tab" />
  <DocStep title="Select the rule that applies the rule set">

  A rule that applies a rule set to every request reads `If` `Request URI` `starts with` `/` under **Criteria**, and **Set WAF** under **Behaviors**.

  </DocStep>
  <DocStep title="Read the mode">

  In the **Behaviors** section, the **Set WAF** behavior names the rule set. The mode dropdown beside it shows _Logging_ or _Blocking_.

  </DocStep>
</DocSteps>

That value is the mode every request selected by this rule runs under. A rule carries at most one **Set WAF** behavior.

</Fragment>

<Fragment slot="panel.api">

To read the mode over the API:

<DocSteps>
  <DocStep title="List the rules of the firewall">

  Replace `<firewall-id>` with the id of your firewall, and `[TOKEN VALUE]` with your personal token:

  ```bash
  curl --request GET \
    --url https://api.azion.com/v4/workspace/firewalls/<firewall-id>/request_rules \
    --header 'Accept: application/json' \
    --header 'Authorization: Token [TOKEN VALUE]'
  ```

  </DocStep>
  <DocStep title="Find the set_waf behavior">

  The call answers `200`. The rule that applies a rule set reads back with this behavior:

  ```json
  "behaviors": [
    { "type": "set_waf", "attributes": { "waf_id": 21717, "mode": "blocking" } }
  ]
  ```

  </DocStep>
</DocSteps>

`mode` carries `logging` or `blocking`, the two values Azion Console renders as _Logging_ and _Blocking_. Record the `id` of that rule. Changing the mode needs it.

</Fragment>

</Tabs>

## Change the mode

The mode has exactly two values, and `learning` is not one of them. For what each mode does to a request that reaches a threshold, refer to [How WAF works](/en/documentation/secure/waf/how-it-works/#modes).

<Tabs client:visible sharedStore="interface">

<Fragment slot="panel.console">

To change the mode in Azion Console:

<DocSteps>
  <DocStep title="Open the rule">

  Reach the rule through the steps in [Check the mode](#check-the-mode).

  </DocStep>
  <DocStep title="Open the mode dropdown on the Set WAF behavior" />
  <DocStep title="Select Logging or Blocking" />
  <DocStep title="Select Save" />
</DocSteps>

The rule now names the new mode. The change takes time to reach Azion's distributed infrastructure. A request that still behaves under the earlier mode has broken nothing: wait, then send it again.

</Fragment>

<Fragment slot="panel.api">

Send the whole `set_waf` behavior, because `mode` is required inside it. A behavior that omits `mode` is refused with `400` and the error `10059 Required Field`, on the pointer `/data/behaviors/0/attributes/mode`.

<DocSteps>
  <DocStep title="Send the change">

  Replace `<firewall-id>` and `<rule-id>` with the ids you recorded, and `waf_id` with the id of your rule set. Send the rule's complete `behaviors` array rather than the `set_waf` entry alone:

  ```bash
  curl --request PATCH \
    --url https://api.azion.com/v4/workspace/firewalls/<firewall-id>/request_rules/<rule-id> \
    --header 'Accept: application/json' \
    --header 'Authorization: Token [TOKEN VALUE]' \
    --header 'Content-Type: application/json' \
    --data '{
    "behaviors": [
      {
        "type": "set_waf",
        "attributes": {
          "waf_id": 21717,
          "mode": "logging"
        }
      }
    ]
  }'
  ```

  </DocStep>
  <DocStep title="Read the mode back">

  Run the `GET` from [Check the mode](#check-the-mode) again, and confirm that `mode` carries the value you sent.

  </DocStep>
</DocSteps>

Any other value is refused. Other Azion surfaces spell this mode `learning`, and a behavior carrying that value returns:

```json
{
  "errors": [
    {
      "code": "10039",
      "title": "Invalid Choice",
      "detail": "\"learning\" is not a valid choice.",
      "status": "400",
      "source": { "pointer": "/data/behaviors/0/attributes/mode" }
    }
  ]
}
```

</Fragment>

</Tabs>
