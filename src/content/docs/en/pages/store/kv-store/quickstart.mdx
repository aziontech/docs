This guide instructs you through storing and reading your first key in [KV Store](/en/documentation/store/kv-store/). By the end you will have:

- Your first namespace, created through the Azion API.
- A function that opens the namespace, writes one key, and reads it back.
- A function instance and a Rules Engine rule that run that function.
- A URI on your own application that answers with the stored value.

The guide uses two interfaces, because KV Store has no screen in Azion Console. The **namespace** is created through the Azion API, and it is permanent: it cannot be renamed, emptied, or deleted afterwards, so the name is worth choosing before the first request. The **function** holds the code that opens the namespace and calls the client. The **function instance** binds the function to an application, and the **Rules Engine** rule selects that instance and sets which requests run it. Creating a function does not execute it, and an instance without a rule never runs.

---

## Prerequisites

- An Azion account. To create one, refer to [How to create an account on Azion](/en/documentation/fundamentals/creating-account/).
- KV Store Preview access on the account. The product is in Preview, and access is requested through the technical support team. To request it, refer to [Technical Support](/en/documentation/support/).
- A personal token. Stage 1 sends it in the `Authorization` header. To create one, refer to [How to manage a personal token](/en/documentation/guides/platform/account-and-billing/personal-tokens/).
- The **Edit Functions** and **Edit Applications** permissions on the account. They grant permission to create the function and to change the application that runs it. For more information, refer to [Teams Permissions](/en/documentation/fundamentals/teams-permissions/).
- An application. To create one, refer to [Build an application](/en/documentation/guides/application-development/getting-started/build-an-application/).

## 1. Create a namespace

A namespace is the container KV Store keeps keys and values in, and its name is its identifier. The name runs 3 to 63 characters, and uses letters, numbers, the hyphen, and the underscore. To create your first one:

<DocSteps>
  <DocStep title="Send the create request">

  Replace `[TOKEN VALUE]` with your personal token, and `my-namespace` with a name of your own:

  ```bash
  curl --request POST \
    --url https://api.azion.com/v4/workspace/kv/namespaces \
    --header 'Accept: application/json' \
    --header 'Authorization: Token [TOKEN VALUE]' \
    --header 'Content-Type: application/json' \
    --data '{
    "name": "my-namespace"
  }'
  ```

  </DocStep>
  <DocStep title="Read the response">

  A `201` carries the whole namespace:

  ```json
  {
    "name": "my-namespace",
    "created_at": "2026-09-18T16:35:27.577829",
    "last_modified": "2026-09-18T16:35:27.577829"
  }
  ```

  A `400` with the message `Namespace already exists` means the account already holds that name. Choose a different name and send the request again.

  </DocStep>
</DocSteps>

The request is synchronous, and there is no provisioning state to poll. The `name` the response carries is the handle every later call uses, including the function you write next. For every field, operation, and error on this endpoint, refer to [Namespaces](/en/documentation/store/kv-store/namespaces/).

## 2. Create the function

`Azion.KV` is a global of Azion Runtime, so a [function](/en/documentation/build/functions/) reaches it with no import line and no credential. The function below opens the namespace, writes one key, reads it back, and returns the value.

:::caution
A call to `Azion.KV.open()` can answer `NotFound: KV namespace "my-namespace" does not exist` for a namespace that exists and that the Azion API lists. Azion has observed this on an account that holds KV Store Preview access. If your function returns that error, contact the [Technical Support](/en/documentation/support/) team with the namespace name and the account it belongs to.
:::

To create the function:

<DocSteps>
  <DocStep title="Open the Functions page">

  Access [Azion Console](https://console.azion.com/) > **Products Menu** > **Libraries** > **Functions**.

  </DocStep>
  <DocStep title="Select + Function" />
  <DocStep title="Name the function">

  Enter a name for the function. For example: `kv-quickstart`.

  </DocStep>
  <DocStep title="Paste the code in the Code tab">

  In the **Code** tab, paste the following code, with the name of the namespace you created:

  ```javascript
  export default {
    async fetch(request, env, ctx) {
      const kv = await Azion.KV.open('my-namespace');

      await kv.put('user-42', 'active');
      const value = await kv.get('user-42', 'text');

      return new Response(value ?? 'No value for that key');
    },
  };
  ```

  </DocStep>
  <DocStep title="Select Save" />
</DocSteps>

The function is saved and holds the code that reaches the namespace. It does not run yet: the next stage binds it to an application and adds the rule that triggers it. For every method the client carries, refer to [KV client](/en/documentation/store/kv-store/kv-client/).

## 3. Instantiate the function and add the rule

An instance binds the function to an application, and a rule decides which requests run the instance. To set both up:

<DocSteps>
  <DocStep title="Open the application that runs the function">

  Still in Azion Console, go to **Products Menu** > **Build** > **Applications**, then select your application.

  </DocStep>
  <DocStep title="In the Main Settings tab, turn on the Functions module" />
  <DocStep title="Select Save" />
  <DocStep title="Go to the Functions Instances tab" />
  <DocStep title="Select + Function Instance" />
  <DocStep title="Name the instance">

  Enter a name for the instance. For example: `kv-quickstart instance`.

  </DocStep>
  <DocStep title="Select the kv-quickstart function" />
  <DocStep title="Select Save" />
  <DocStep title="Go to the Rules Engine tab" />
  <DocStep title="Select + Rule" />
  <DocStep title="Name the rule">

  Enter a name for the rule. For example: `Run kv-quickstart`.

  </DocStep>
  <DocStep title="Select Request Phase" />
  <DocStep title="Set the criteria">

  In the **Criteria** section, select the `${uri}` variable and the _is equal_ operator, and enter `/kv-quickstart` as the argument.

  </DocStep>
  <DocStep title="In the Behaviors section, select Run Function" />
  <DocStep title="Select the instance you created" />
  <DocStep title="Select Save" />
</DocSteps>

The rule runs the instance on every request whose URI is `/kv-quickstart`. New rules can take a few minutes to propagate. Wait before you request the URI. For each instance and rule field this guide passes over, refer to [Functions quickstart](/en/documentation/build/functions/quickstart/).

---

## 4. Request the URI

Your application answers on its own domain. To reach the function, request the URI the rule matches:

```bash
curl https://<your-azion-domain>/kv-quickstart
```

A successful response carries the body the function returns, which is the value it stored under `user-42` and read back: the string `active`. A response carrying `No value for that key` means the read returned `null`, so the key was not found under that name.

Your first namespace holds one key, and a function writes and reads it on every request the rule matches.
