This guide instructs you through storing your first object in [Object Storage](/en/documentation/store/object-storage/), using Azion Console. By the end you will have:

- Your first bucket, set to _Read Only_.
- An object stored in that bucket, addressed by its key.
- The object listed in the bucket, which confirms the upload.

Prefer the API? Refer to [Object Storage quickstart using the API](/en/documentation/store/object-storage/quickstart-api/).

A bucket is not a public folder: an object you upload answers no request from the internet until an application is pointed at it. The result rests on three objects, in this order. The **bucket** is the top-level container for objects, and buckets do not nest. Each **object** inside it is a file, its key, and its content type. The key addresses the object: a `/` in a key is part of the key, not a folder. A **connector** of type Object Storage, paired with a Rules Engine rule on an [application](/en/documentation/platform/applications/), is what sends a request to the bucket. This guide creates the first two and stops there.

---

## Prerequisites

- Access to Azion Console. To sign in, refer to [Access Azion Console](/en/documentation/guides/platform/account-and-billing/how-to-access-azion-console/).
- Permission to create buckets and objects in your account. For more information, refer to [Teams Permissions](/en/documentation/fundamentals/teams-permissions/).
- A file on your machine to upload, such as an image.

---

## 1. Create a bucket

A bucket holds the objects you upload. This one is set to _Read Only_, the access level for content the Azion platform serves without changing it.

<DocSteps>
  <DocStep title="Open the bucket list">

  Access [Azion Console](https://console.azion.com/) > **Object Storage** > **Buckets**.

  </DocStep>
  <DocStep title="Open the create form">

  Start a new bucket from the **Buckets** list. An account with no buckets yet offers **Bucket** on the empty list.

  </DocStep>
  <DocStep title="Name the bucket">

  Under **General**, in **Name**, enter a name of 6 to 63 characters, using letters, numbers, and hyphens. The name cannot begin with `azion`. It is unique across every Azion account: a name another account holds is refused.

  </DocStep>
  <DocStep title="Keep the access level">

  Under **Settings**, keep **Workloads Access** as _Read Only_, the default, so the platform reads the objects but cannot modify them.

  </DocStep>
  <DocStep title="Select Create Bucket" />
</DocSteps>

The bucket appears in **Buckets**, which lists its **Name**, **Size**, **Last Editor**, and **Last Modified**. Its name is taken across every Azion account, so no other account can create a bucket with it.

:::note
**Workloads Access** decides only what the Azion platform may do with the bucket. It does not restrict the API or the S3 protocol: a credential that carries write capability writes to a _Read Only_ bucket. For more information, refer to [How Object Storage works](/en/documentation/store/object-storage/how-it-works/).
:::

---

## 2. Upload an object

An object is stored under a key, and the key is how every interface addresses it afterwards.

<DocSteps>
  <DocStep title="Open the bucket">

  In **Buckets**, select the bucket you created.

  </DocStep>
  <DocStep title="Add the file">

  Select **Upload files**, or drag the file onto the drop target. The file name becomes the object key, which holds 1 to 1,024 characters. The Console refuses a file larger than 300 MB.

  </DocStep>
</DocSteps>

The object is stored in the bucket, under the key taken from the file name.

---

## 3. Confirm the object is stored

The bucket lists what it holds, so you can confirm the upload without another interface.

<DocSteps>
  <DocStep title="Open the bucket list">

  Access [Azion Console](https://console.azion.com/) > **Object Storage** > **Buckets**.

  </DocStep>
  <DocStep title="Select the bucket">

  Select the bucket you created.

  </DocStep>
  <DocStep title="Find the object by its key">

  The object is listed under its key. A key that holds a `/`, such as `images/logo.svg`, groups under the segment before it: that segment is a prefix, not a folder.

  </DocStep>
</DocSteps>

Your first object is stored in Object Storage and addressed by its key. The bucket is reachable through the Azion API and the S3 protocol, and by nothing else yet.

To serve the object to end users, point a [connector](/en/documentation/platform/connectors/) of type Object Storage at the bucket. A Rules Engine rule on the application then sends matching requests to it. For more information, refer to [Use a bucket as an application origin](/en/documentation/guides/application-development/data/use-bucket-as-origin/).
