This guide instructs you through storing and reading your first row in [SQL Database](/en/documentation/store/sql-database/), using the Azion API. By the end you will have:

- Your first database, with the status `created`.
- A `users` table inside it.
- One row stored in that table.
- The same row returned by a `SELECT` statement.

Prefer Azion Console? Refer to [SQL Database quickstart using Azion Console](/en/documentation/store/sql-database/quickstart/).

The result rests on two objects. The **database** is the container, and its name cannot be changed after creation. Each **table** lives inside one database, and this guide creates the table with a `CREATE TABLE` statement sent to the query endpoint. A database is provisioned asynchronously. Its status reads `creating` first, and a statement runs against it only after the status reads `created`.

---

## Prerequisites

- A [personal token](/en/documentation/guides/platform/account-and-billing/personal-tokens/). Every request on this page sends it in the `Authorization` header.
- SQL Database enabled on the account. The product is in Preview, and access is requested through the technical support team. To request it, refer to [Technical Support](/en/documentation/support/).
- The **Edit SQL Database** permission on the account. It grants permission to create and edit databases and their data through the Azion API. For more information, refer to [Teams Permissions](/en/documentation/fundamentals/teams-permissions/).

## 1. Create a database

A database holds the tables you create. Its name is 6 to 50 characters, and uses letters, numbers, and the hyphen. To create your first one:

<DocSteps>
  <DocStep title="Send the create request">

  Replace `[TOKEN VALUE]` with your personal token, and `my-database` with a name of your own:

  ```bash
  curl --request POST \
    --url https://api.azion.com/v4/workspace/sql/databases \
    --header 'Accept: application/json' \
    --header 'Authorization: Token [TOKEN VALUE]' \
    --header 'Content-Type: application/json' \
    --data '{
    "name": "my-database"
  }'
  ```

  </DocStep>
  <DocStep title="Read the response">

  A `202` carries the database:

  ```json
  {
    "state": "pending",
    "data": {
      "id": 1851,
      "name": "my-database",
      "status": "creating",
      "active": true,
      "last_modified": "2026-09-18T02:10:35.433088Z",
      "last_editor": "user@example.com",
      "product_version": "1.0"
    }
  }
  ```

  A `400` with the code `14001` means the account already holds a database with that name. Choose a different name and send the request again.

  </DocStep>
</DocSteps>

Record the `id` the response carries, `1851` in this sample. Every request below addresses the database by it. The envelope's `state` reads `pending` while the database's `status` reads `creating`, because provisioning has not finished.

## 2. Wait for the database to be ready

A statement cannot succeed against a database whose status reads `creating`. Poll the database until the status reads `created`:

<DocSteps>
  <DocStep title="Send the retrieve request">

  Replace `1851` with the `id` the create response returned:

  ```bash
  curl --request GET \
    --url https://api.azion.com/v4/workspace/sql/databases/1851 \
    --header 'Accept: application/json' \
    --header 'Authorization: Token [TOKEN VALUE]'
  ```

  </DocStep>
  <DocStep title="Read the status">

  A `200` carries the database, and this response has no `state` key:

  ```json
  {
    "data": {
      "id": 1851,
      "name": "my-database",
      "status": "created",
      "active": true,
      "last_modified": "2026-09-18T02:10:59.058568Z",
      "last_editor": "user@example.com",
      "product_version": "1.0"
    }
  }
  ```

  </DocStep>
  <DocStep title="Send the request again while the status reads creating">

  Provisioning takes about 15 seconds. Wait a few seconds between requests.

  </DocStep>
</DocSteps>

The database is ready when `status` reads `created`. Do not skip this stage: a query sent while the status reads `creating` cannot succeed.

## 3. Create a table and insert a row

The query endpoint runs SQL against one database. The body carries a `statements` array, and Azion runs the statements in order. To create the `users` table and store the first row:

<DocSteps>
  <DocStep title="Send the query request">

  The `INSERT` statement carries single quotes, so the body is sent on standard input:

  ```bash
  curl --request POST \
    --url https://api.azion.com/v4/workspace/sql/databases/1851/query \
    --header 'Accept: application/json' \
    --header 'Authorization: Token [TOKEN VALUE]' \
    --header 'Content-Type: application/json' \
    --data @- <<'EOF'
  {
    "statements": [
      "CREATE TABLE users (id INTEGER PRIMARY KEY, name TEXT, email TEXT);",
      "INSERT INTO users (name, email) VALUES ('Ada', 'ada@example.com');"
    ]
  }
  EOF
  ```

  </DocStep>
  <DocStep title="Read the response">

  A `200` carries one entry per statement:

  ```json
  {
    "state": "executed",
    "data": [
      {
        "results": {
          "columns": [],
          "rows": [],
          "rows_read": 1,
          "rows_written": 2,
          "query_duration_ms": 2.391
        }
      },
      {
        "results": {
          "columns": [],
          "rows": [],
          "rows_read": 1,
          "rows_written": 1,
          "query_duration_ms": 0.092
        }
      }
    ]
  }
  ```

  Neither statement returns rows, so `columns` and `rows` are empty in both entries. Both still report rows read and written, because `CREATE TABLE` writes the schema itself. Azion bills on `rows_read` and `rows_written`, and returns both per statement.

  </DocStep>
</DocSteps>

The database holds a `users` table with one row.

## 4. Read the row back

A `SELECT` statement returns what the table holds. To read the row you inserted:

<DocSteps>
  <DocStep title="Send the query request">

  Replace `1851` with the `id` of your database:

  ```bash
  curl --request POST \
    --url https://api.azion.com/v4/workspace/sql/databases/1851/query \
    --header 'Accept: application/json' \
    --header 'Authorization: Token [TOKEN VALUE]' \
    --header 'Content-Type: application/json' \
    --data '{
    "statements": ["SELECT id, name, email FROM users;"]
  }'
  ```

  </DocStep>
  <DocStep title="Read the response">

  A `200` carries the column names and one array per row:

  ```json
  {
    "state": "executed",
    "data": [
      {
        "results": {
          "columns": ["id", "name", "email"],
          "rows": [[1, "Ada", "ada@example.com"]],
          "rows_read": 1,
          "rows_written": 0,
          "query_duration_ms": 0.08
        }
      }
    ]
  }
  ```

  </DocStep>
</DocSteps>

Your first database holds a `users` table with one row, and the API reads it back. The same statements run in Azion Console and inside a function.

A statement that fails does not fail the request. The response answers HTTP `200`, and the entry for that statement carries `error` in place of `results`:

```json
{
  "state": "executed",
  "data": [
    {
      "error": "no such table: nope"
    }
  ]
}
```

Check `data[].error` on every statement, not the HTTP status code. For more information, refer to [Databases and queries](/en/documentation/store/sql-database/databases-and-queries/).
