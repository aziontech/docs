This guide instructs you through running your first function on Azion. The steps take about 10 minutes.

- Create a function that returns `Hello World!`.
- Instantiate the function on an application.
- Add a Rules Engine rule that runs the instance on the `/hello-world` URI.
- Request that URI and read the response.

Three objects make a function run, and each one links to the next:

1. The **function** holds the JavaScript code.
2. The **function instance** binds the function to an application. It also carries the Args, a JSON object passed into the execution context.
3. The **Rules Engine** rule selects the instance with the **Run Function** behavior. The rule sets the execution phase and the criteria that trigger it.

Creating a function does not execute it. An instance without a Rules Engine rule never runs.

The [Azion Terraform provider](/en/documentation/devtools/terraform/) manages the same three objects. For every interface that carries them, refer to [Functions](/en/documentation/build/functions/#scope-and-limits).

## Prerequisites

- An Azion account. To create one, refer to [How to create an account on Azion](/en/documentation/fundamentals/creating-account/).
- The **Edit Functions** permission on the account. It grants permission to create, edit, and remove functions, and it also requires the permission **View Functions**.
- The **Edit Applications** permission on the account. Stages 2 and 3 change an application, and this permission grants permission to edit, create, and remove applications. It also requires the permission **View Applications**. Refer to [Teams Permissions](/en/documentation/fundamentals/teams-permissions/).
- An application. To create one, refer to [Build an application](/en/documentation/guides/application-development/getting-started/build-an-application/).

- Access to Azion Console. To sign in, refer to [Access Azion Console](/en/documentation/guides/platform/account-and-billing/how-to-access-azion-console/).

</Fragment>

- The [Azion CLI](/en/documentation/devtools/cli/) installed and authorized.

</Fragment>

- A [personal token](/en/documentation/guides/platform/account-and-billing/personal-tokens/) and `curl`.

## 1. Create the function

The function holds the code that answers the request. This one returns the string `Hello World!`.

<Tabs client:visible sharedStore="interface">

<Fragment slot="panel.console">

To create the function in Azion Console:

<DocSteps>
  <DocStep title="Open the Functions page">

  Access [Azion Console](https://console.azion.com/) > **Products Menu** > **Libraries** > **Functions**.

  </DocStep>
  <DocStep title="Select + Function" />
  <DocStep title="Name the function">

  Enter a name for the function. For example: `hello-world`.

  </DocStep>
  <DocStep title="Paste the code in the Code tab">

  In the **Code** tab, paste the following code:

  ```javascript
  export default {
    async fetch(request, env, ctx) {
      return new Response('Hello World!');
    },
  };
  ```

  </DocStep>
  <DocStep title="Select Save" />
</DocSteps>

The function is saved and available to instantiate on an application.

:::tip
To read the response of the function before it serves traffic, use [Preview deployment](/en/documentation/build/functions/preview-deployment/). It runs the code in Azion Console without a deployment.
:::

</Fragment>

<Fragment slot="panel.cli">

The CLI reads the code from a local file. To create the function:

<DocSteps>
  <DocStep title="Save the code to a file">

  Write the following code to `index.js`:

  ```javascript
  export default {
    async fetch(request, env, ctx) {
      return new Response('Hello World!');
    },
  };
  ```

  </DocStep>
  <DocStep title="Run the create command">

  ```bash
  azion create function --name hello-world --code ./index.js --active true
  ```

  </DocStep>
  <DocStep title="Read the output">

  The command prints the id of the new function:

  ```text
  Created function with ID 56278
  ```

  </DocStep>
</DocSteps>

Record the id. Stage 2 passes it to the instance. For every flag the command accepts, refer to [Azion CLI create](/en/documentation/devtools/cli/create/).

</Fragment>

<Fragment slot="panel.api">

The request body carries the code as a JSON string, so newlines are escaped as `\n`.

<DocSteps>
  <DocStep title="Send the create request">

  Replace `[TOKEN VALUE]` with your personal token:

  ```bash
  curl --request POST \
    --url https://api.azion.com/v4/workspace/functions \
    --header 'Accept: application/json' \
    --header 'Authorization: Token [TOKEN VALUE]' \
    --header 'Content-Type: application/json' \
    --data '{
    "name": "hello-world",
    "code": "export default {\n  async fetch(request, env, ctx) {\n    return new Response(\"Hello World!\");\n  },\n};"
  }'
  ```

  </DocStep>
  <DocStep title="Read the response">

  A `202` carries the function:

  ```json
  {
    "state": "pending",
    "data": {
      "id": 56277,
      "name": "hello-world",
      "last_editor": "user@example.com",
      "last_modified": "2026-09-19T02:34:58.385220Z",
      "product_version": "2.0",
      "active": true,
      "runtime": "azion_js",
      "execution_environment": "application",
      "default_args": {},
      "reference_count": 0,
      "code": "export default {\n  async fetch(request, env, ctx) {\n    return new Response(\"Hello World!\");\n  },\n};"
    }
  }
  ```

  </DocStep>
</DocSteps>

Record the `id`. Stage 2 passes it to the instance. The `"state": "pending"` value means the change takes a few minutes to propagate.

</Fragment>

</Tabs>

## 2. Instantiate the function on your application

An instance binds the function to one application, and one function can back several instances. Each path turns on the **Functions** module for the application, then creates the instance.

:::caution
Computing time and invocations for functions generate usage-related costs. For the rates, refer to [Pricing](/en/documentation/fundamentals/pricing/).
:::

<Tabs client:visible sharedStore="interface">

<Fragment slot="panel.console">

To bind the function to an application in Azion Console:

<DocSteps>
  <DocStep title="Still in Azion Console, go to Products Menu > Build > Applications" />
  <DocStep title="Select the application that runs the function" />
  <DocStep title="In the Main Settings tab, turn on the Functions module" />
  <DocStep title="Select Save" />
  <DocStep title="Go to the Functions Instances tab" />
  <DocStep title="Select + Function Instance" />
  <DocStep title="Name the instance">

  Enter a name for the instance. For example: `hello-world instance`.

  </DocStep>
  <DocStep title="Select the function">

  Select the `hello-world` function.

  </DocStep>
  <DocStep title="Select Save" />
</DocSteps>

The new instance appears in the **Functions Instances** tab.

</Fragment>

<Fragment slot="panel.cli">

To turn on the module and create the instance with the Azion CLI, replace the application id and the function id with your own:

<DocSteps>
  <DocStep title="Turn on the Functions module">

  ```bash
  azion update application --application-id <application_id> --functions true
  ```

  The command confirms the application:

  ```text
  Updated Application with ID <application_id>
  ```

  </DocStep>
  <DocStep title="Create the instance">

  ```bash
  azion create function-instance --application-id <application_id> --function-id <function_id> --name "hello-world instance"
  ```

  </DocStep>
  <DocStep title="Read the output">

  The command prints the id of the new instance:

  ```text
  Created Function Instance with ID 50206
  ```

  </DocStep>
</DocSteps>

Record the instance id. Stage 3 passes it to the rule.

</Fragment>

<Fragment slot="panel.api">

Two requests turn on the module and create the instance.

<DocSteps>
  <DocStep title="Turn on the Functions module">

  Replace `<application_id>` with [your application ID](/en/documentation/guides/application-development/getting-started/configure-main-settings/):

  ```bash
  curl --request PATCH \
    --url https://api.azion.com/v4/workspace/applications/<application_id> \
    --header 'Accept: application/json' \
    --header 'Authorization: Token [TOKEN VALUE]' \
    --header 'Content-Type: application/json' \
    --data '{
    "modules": {
      "functions": {
        "enabled": true
      }
    }
  }'
  ```

  The response returns the modules the application now carries:

  ```json
  {
    "cache": { "enabled": true },
    "functions": { "enabled": true },
    "application_accelerator": { "enabled": false },
    "image_processor": { "enabled": false }
  }
  ```

  </DocStep>
  <DocStep title="Create the instance">

  Replace `<function_id>` with the `id` the function create returned:

  ```bash
  curl --request POST \
    --url https://api.azion.com/v4/workspace/applications/<application_id>/functions \
    --header 'Accept: application/json' \
    --header 'Authorization: Token [TOKEN VALUE]' \
    --header 'Content-Type: application/json' \
    --data '{
    "name": "hello-world instance",
    "function": <function_id>,
    "args": {},
    "active": true
  }'
  ```

  </DocStep>
  <DocStep title="Read the response">

  A `202` carries the instance:

  ```json
  {
    "state": "pending",
    "data": {
      "id": 50205,
      "name": "hello-world instance",
      "args": {},
      "function": 56277,
      "active": true,
      "last_editor": "user@example.com",
      "last_modified": "2026-09-19T02:35:19.272376Z"
    }
  }
  ```

  The `function` field holds the id of the function the instance runs. It differs from `id`, which is unique for each instance.

  </DocStep>
</DocSteps>

Record the instance `id`. Stage 3 passes it to the rule.

</Fragment>

</Tabs>

## 3. Add the rule that runs the function

An instance runs only when a Rules Engine rule selects it. This rule runs the instance on requests to `/hello-world`.

<Tabs client:visible sharedStore="interface">

<Fragment slot="panel.console">

To add the rule in Azion Console:

<DocSteps>
  <DocStep title="In the same application, go to the Rules Engine tab" />
  <DocStep title="Select + Rule" />
  <DocStep title="Name the rule">

  Enter a name for the rule. For example: `Run hello-world`.

  </DocStep>
  <DocStep title="Select Request Phase" />
  <DocStep title="Select the variable in the Criteria section">

  In the **Criteria** section, select the `${uri}` variable.

  </DocStep>
  <DocStep title="Select is equal as the comparison operator" />
  <DocStep title="Enter the argument">

  Enter `/hello-world` as the argument.

  </DocStep>
  <DocStep title="In the Behaviors section, select Run Function" />
  <DocStep title="Select the instance you created" />
  <DocStep title="Select Save" />
</DocSteps>

The rule runs the instance on every request whose URI is `/hello-world`.

:::note
If **Run Function** is not in the **Behaviors** list, the application also needs the **Application Accelerator** module. Refer to [Run Function is missing from the behaviors list](/en/documentation/build/functions/troubleshooting/#run-function-is-missing-from-the-behaviors-list) for the fix.
:::

</Fragment>

<Fragment slot="panel.cli">

The CLI reads the rule from a JSON file. To add the rule:

<DocSteps>
  <DocStep title="Write the rule to a file">

  Save the following as `rule.json`, with the id of your instance in `attributes.value`:

  ```json
  {
    "name": "Run hello-world",
    "description": "Run the function on /hello-world",
    "active": true,
    "criteria": [
      [
        {
          "conditional": "if",
          "variable": "${uri}",
          "operator": "is_equal",
          "argument": "/hello-world"
        }
      ]
    ],
    "behaviors": [
      {
        "type": "run_function",
        "attributes": { "value": 50206 }
      }
    ]
  }
  ```

  </DocStep>
  <DocStep title="Create the rule">

  ```bash
  azion create rules-engine --application-id <application_id> --phase request --file rule.json
  ```

  </DocStep>
  <DocStep title="Read the output">

  The command prints the id of the new rule:

  ```text
  Created Rules Engine with ID 712403
  ```

  </DocStep>
</DocSteps>

The rule runs the instance on every request whose URI is `/hello-world`.

</Fragment>

<Fragment slot="panel.api">

To add the rule with the Azion API:

<DocSteps>
  <DocStep title="Write the rule to a file">

  The criteria carry `${uri}`, which a shell expands, so the body is sent from a file. Save the following as `rule.json`, with the id of your instance in `attributes.value`:

  ```json
  {
    "name": "Run hello-world",
    "description": "Run the function on /hello-world",
    "active": true,
    "criteria": [
      [
        {
          "conditional": "if",
          "variable": "${uri}",
          "operator": "is_equal",
          "argument": "/hello-world"
        }
      ]
    ],
    "behaviors": [
      {
        "type": "run_function",
        "attributes": { "value": 50205 }
      }
    ]
  }
  ```

  </DocStep>
  <DocStep title="Send the create request">

  ```bash
  curl --request POST \
    --url https://api.azion.com/v4/workspace/applications/<application_id>/request_rules \
    --header 'Accept: application/json' \
    --header 'Authorization: Token [TOKEN VALUE]' \
    --header 'Content-Type: application/json' \
    --data @rule.json
  ```

  </DocStep>
  <DocStep title="Read the response">

  A `202` carries the rule, with the `order` it holds among the rules of the application:

  ```json
  {
    "state": "pending",
    "data": {
      "id": 712402,
      "name": "Run hello-world",
      "active": true,
      "behaviors": [
        {
          "type": "run_function",
          "attributes": { "value": 50205 }
        }
      ],
      "order": 0,
      "last_editor": "user@example.com",
      "last_modified": "2026-09-19T02:36:23.270982Z"
    }
  }
  ```

  </DocStep>
</DocSteps>

The rule runs the instance on every request whose URI is `/hello-world`.

</Fragment>

</Tabs>

New rules can take a few minutes to propagate. Wait before you request the URI.

---

## 4. Verify the response

Your application answers on a domain in the format `xxxxxxxxx.map.azionedge.net`. To set the domain for your application, refer to [How to configure a domain](/en/documentation/guides/platform/migration/configure-a-domain/).

To confirm that the function runs, request the URI set in the rule:

```bash
curl https://<your-azion-domain>/hello-world
```

The response body is the string the function returns:

```
Hello World!
```

The function now runs on every request that matches the rule criteria.
