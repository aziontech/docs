This guide instructs you through running your first function on Azion. The steps take about 10 minutes.

- Create a function that returns `Hello World!`.
- Instantiate the function on an application.
- Add a Rules Engine rule that runs the instance on the `/hello-world` URI.
- Request that URI and read the response.

Three objects make a function run, and each one links to the next:

1. The **function** holds the JavaScript code.
2. The **function instance** binds the function to an application. It also carries the Args, a JSON object passed into the execution context.
3. The **Rules Engine** rule selects the instance with the **Run Function** behavior. The rule sets the execution phase and the criteria that trigger it.

Creating a function does not execute it. An instance without a Rules Engine rule never runs.

This guide uses Azion Console. Azion CLI, the Azion API, and the Azion Terraform provider manage the same three objects. For every interface, refer to [Functions](/en/documentation/build/functions/#scope-and-limits).

---

## Prerequisites

- An Azion account. To create one, refer to [How to create an account on Azion](/en/documentation/fundamentals/creating-account/).
- The **Edit Functions** permission on the account. It grants permission to create, edit, and remove functions, and it also requires the permission **View Functions**.
- The **Edit Applications** permission on the account. Stages 2 and 3 change an application, and this permission grants permission to edit, create, and remove applications. It also requires the permission **View Applications**. Refer to [Teams Permissions](/en/documentation/fundamentals/teams-permissions/).
- An application. To create one, refer to [Build an application](/en/documentation/guides/application-development/getting-started/build-an-application/).

## 1. Create the function

To create the function that returns the response:

<DocSteps>
  <DocStep title="Open the Functions page">

  Access [Azion Console](https://console.azion.com/) > **Products Menu** > **Libraries** > **Functions**.

  </DocStep>
  <DocStep title="Select + Function" />
  <DocStep title="Name the function">

  Enter a name for the function. For example: `hello-world`.

  </DocStep>
  <DocStep title="Paste the code in the Code tab">

  In the **Code** tab, paste the following code:

  ```javascript
  export default {
    async fetch(request, env, ctx) {
      return new Response('Hello World!');
    },
  };
  ```

  </DocStep>
  <DocStep title="Select Save" />
</DocSteps>

The function is saved and available to instantiate on an application.

:::tip
To read the response of the function before it serves traffic, use [Preview deployment](/en/documentation/build/functions/preview-deployment/). It runs the code in Azion Console without a deployment.
:::

## 2. Instantiate the function on your application

:::caution
Computing time and invocations for functions generate usage-related costs. For the rates, refer to [Pricing](/en/documentation/fundamentals/pricing/).
:::

To bind the function to an application:

<DocSteps>
  <DocStep title="Still in Azion Console, go to Products Menu > Build > Applications" />
  <DocStep title="Select the application that runs the function" />
  <DocStep title="In the Main Settings tab, turn on the Functions module" />
  <DocStep title="Select Save" />
  <DocStep title="Go to the Functions Instances tab" />
  <DocStep title="Select + Function Instance" />
  <DocStep title="Name the instance">

  Enter a name for the instance. For example: `hello-world instance`.

  </DocStep>
  <DocStep title="Select the function">

  Select the `hello-world` function.

  </DocStep>
  <DocStep title="Select Save" />
</DocSteps>

The new instance appears in the **Functions Instances** tab.

---

## 3. Add the rule that runs the function

An instance runs only when a Rules Engine rule selects it. To run the instance on requests to `/hello-world`:

<DocSteps>
  <DocStep title="In the same application, go to the Rules Engine tab" />
  <DocStep title="Select + Rule" />
  <DocStep title="Name the rule">

  Enter a name for the rule. For example: `Run hello-world`.

  </DocStep>
  <DocStep title="Select Request Phase" />
  <DocStep title="Select the variable in the Criteria section">

  In the **Criteria** section, select the `${uri}` variable.

  </DocStep>
  <DocStep title="Select is equal as the comparison operator" />
  <DocStep title="Enter the argument">

  Enter `/hello-world` as the argument.

  </DocStep>
  <DocStep title="In the Behaviors section, select Run Function" />
  <DocStep title="Select the instance you created" />
  <DocStep title="Select Save" />
</DocSteps>

The rule runs the instance on every request whose URI is `/hello-world`. New rules can take a few minutes to propagate. Wait before you request the URI.

:::note
If **Run Function** is not in the **Behaviors** list, the application also needs the **Application Accelerator** module. Refer to [Run Function is missing from the behaviors list](/en/documentation/build/functions/troubleshooting/#run-function-is-missing-from-the-behaviors-list) for the fix.
:::

---

## 4. Verify the response

Your application answers on a domain in the format `xxxxxxxxx.map.azionedge.net`. To set the domain for your application, refer to [How to configure a domain](/en/documentation/guides/platform/migration/configure-a-domain/).

To confirm that the function runs, request the URI set in the rule:

```bash
curl https://<your-azion-domain>/hello-world
```

The response body is the string the function returns:

```
Hello World!
```

The function now runs on every request that matches the rule criteria.
