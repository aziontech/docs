Definitions for the terms the [Application Accelerator](/en/documentation/build/application-accelerator/) documentation uses.

| Term | Definition |
| --- | --- |
| Advanced Cache Key | The feature that varies the cache key by parts of a request beyond the URL. Application Accelerator unlocks it, and the four **Cache vary by** controls of a [cache setting](/en/documentation/build/application-accelerator/settings/#cache-variation) configure it. |
| allowlist | The `behavior` value that varies the cache key only by the attributes a [cache setting](/en/documentation/build/application-accelerator/settings/#cache-variation) names, ignoring every other one that arrives. Azion Console renders it as _Allowlist_. It is the control on how many objects a variation creates, because an attribute nobody names cannot produce another object. |
| Application Accelerator | The [Applications](/en/documentation/platform/applications/) module that puts the rest of a request into the cache key. One switch per application unlocks cache variation, the caching of `POST` and `OPTIONS` responses, a cache TTL below 60 seconds, and seven [Rules Engine](/en/documentation/platform/applications/rules-engine/) behaviors. |
| Bypass Cache | The Rules Engine behavior that sends every matching request to the origin and caches nothing. It requires Application Accelerator, it does not change the browser cache, and it is not the same as a cache TTL of 0 seconds. [How Application Accelerator works](/en/documentation/build/application-accelerator/how-it-works/) sets out the difference. |
| cache key | The index entry under which the cache stores an object. Azion builds it from the request's scheme, host, path, and query string, and a variation appends a separator and what varies. The format and every input it carries belong to [Cache](/en/documentation/build/cache/cache-keys/#key-format). |
| cache setting | The object that holds how long the cache keeps a response and what makes two requests different. It belongs to one application, and it reaches a request only when a **Set Cache Policy** rule applies it. Its fields are in [Settings](/en/documentation/build/application-accelerator/settings/). |
| Cache vary by Cookies | The control that varies the cache key by the value of named cookies. It carries a `behavior` and the list of cookie names the behavior applies to. |
| Cache vary by Devices | The control that varies the cache key by [device group](/en/documentation/platform/applications/device-groups/). It carries a `behavior` and the list of device groups the behavior applies to. |
| Cache vary by Method | The control that names the request methods whose responses are cached. It accepts `POST`, `OPTIONS`, or both, and nothing else. |
| Cache vary by Query String | The control that varies the cache key by named query string arguments. It carries a `behavior`, the list of arguments, and **Sort**. |
| complex request | A request using any method other than `GET` or `HEAD`. Azion prefixes the method to the cache key of a complex request, so an `OPTIONS` response and a `GET` response for one path are separate objects. |
| denylist | The `behavior` value that varies the cache key by every attribute that arrives except the ones a [cache setting](/en/documentation/build/application-accelerator/settings/#cache-variation) names. Azion Console renders it as _Denylist_. |
| device group | A set of devices an application recognizes, defined in [Device Groups](/en/documentation/platform/applications/device-groups/). Application Accelerator can vary the cache key by device group, and the `${device_group}` variable in a Rules Engine rule requires the module. |
| Forward Cookies | The Rules Engine behavior that sends the origin's `Set-Cookie` header to the user even when the response comes from cache. It requires Application Accelerator. |
| Max Age | The Azion Console label for how long the cache holds an object, in seconds. The field is `modules.cache.max_age`, and the floor it can reach depends on which modules are on, per [Limits](/en/documentation/build/application-accelerator/limits/). |
| Set Cache Policy | The Rules Engine behavior that applies a cache setting to the requests a rule matches. It does not require Application Accelerator, and it is how every cache setting reaches a request. |
| Sort | The control that groups the same query string arguments under one cache key whatever order they arrive in. Without it, `?a=1&b=2` and `?b=2&a=1` are two objects holding one response, and with it a URL purge has to send the arguments alphabetically. |
