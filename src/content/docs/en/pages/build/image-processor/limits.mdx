[Image Processor](/en/documentation/build/image-processor/) carries three default limits on an image, and each service plan includes a number of processed images every month. This page carries both kinds of bound: the values that apply to a single image, and the amount that applies to a month.

---

## Default limits

The values below are the default limits Image Processor applies to an image. To request a higher limit for the account, contact the [technical support](/en/documentation/support/) team.

| Scope | Limit |
| --- | --- |
| Maximum size | 150 MB |
| Maximum width | 3840 pixels |
| Maximum height | 2160 pixels |

Each `ims` parameter also accepts its own range of values. That range sits with the parameter it belongs to rather than in this table. For more information, refer to [URL parameters](/en/documentation/build/image-processor/url-parameters/).

---

## Included usage per plan

Every service plan includes a number of processed images each month. The maximum size, width, and height bound one image. The amount below bounds one month, and it differs by plan.

| Metric | Hobby | Pro | Enterprise |
| --- | --- | --- | --- |
| Images | 5,000 / month | 10,000 / month | Custom |

An image is one image processed by Image Processor on a request, whether the request optimizes, crops, resizes, filters, or converts the format. Images that [Cache](/en/documentation/build/cache/) serves without processing are not counted. A derived image already held in cache adds nothing to the month's total on the requests the cache answers. For example, an application that serves one photograph in three widths counts three images, and none on the later requests the cache answers.

For the rates that apply to the Images metric, refer to [Pricing](/en/documentation/fundamentals/pricing/#image-processor). To read how many images the account has processed so far, refer to [Query usage data from Image Processor](/en/documentation/guides/platform/observability/query-image-processor-usage-data-with-graphql/).
