The terms the [Image Processor](/en/documentation/build/image-processor/) documentation uses, each with the page that covers it in full.

| Term | Definition |
| --- | --- |
| Add Request Header | The [Rules Engine](/en/documentation/platform/applications/rules-engine/) behavior that adds a header to the request, in the form `Field: value`, in the **Request Phase**. Converting an image to WEBP or AVIF requires the request to carry `Accept: image/webp` or `Accept: image/avif`, and this behavior adds it. The API type is `add_request_header`. |
| autocrop | The centered crop a `WidthxHeight` resize may apply so the derived image fits the requested box. It runs vertically or horizontally depending on how the original dimensions fit the requested ones. A dimension set to `orig` prevents it, as [URL parameters](/en/documentation/build/image-processor/url-parameters/) shows. |
| cache key | The index entry under which [Cache](/en/documentation/build/cache/) stores an object. With Image Processor on, the key of a processed image carries the `ims` query string, and a variation converted to another format carries the file format after the separator. |
| cache variation | The cache setting field that varies the cache key by named query string arguments, `cache_vary_by_querystring`. Varying the cache on `ims` requires the [Application Accelerator](/en/documentation/build/application-accelerator/) module, because the field belongs to `modules.application_accelerator`, but processing an image does not. [Settings](/en/documentation/build/image-processor/settings/) carries its **Behavior**, **Fields**, and **Sort** controls. |
| derived image | The image Image Processor returns when a request carries an `ims` query string, built from the source image on the origin. Azion never modifies the original and stores no derived image as an asset. [How Image Processor works](/en/documentation/build/image-processor/how-it-works/) describes how a request produces one. |
| filter | The `ims` component that transforms an image beyond a resize or a crop, written `filters:name(argument)`. One `ims` string combines several filters by separating them with `:`. [URL parameters](/en/documentation/build/image-processor/url-parameters/) documents `rotate`, `quality`, `watermark`, `format`, and `fill`. |
| `fit-in` | The `ims` prefix that fits the derived image inside a `WidthxHeight` box and preserves the [aspect ratio](https://www.azion.com/en/learning/) of the source image. It never enlarges an image: when the specified area is larger than the image dimensions, the image keeps its original size. Both dimensions are optional, and [URL parameters](/en/documentation/build/image-processor/url-parameters/) shows the forms it takes. |
| `imageProcessedMetrics` | The GraphQL dataset that returns request metrics for the images Image Processor processed. [Real-Time Metrics GraphQL API Fields](/en/documentation/devtools/graphql/gql-real-time-metrics-fields/) lists every field it carries. |
| Image Processor | The [Applications](/en/documentation/platform/applications/) module that returns a derived image built from a source image on the origin, following the `ims` query string of the request. One switch turns it on per application, and [How Image Processor works](/en/documentation/build/image-processor/how-it-works/) describes the path a request takes through it. |
| Images | The usage-based meter that counts the volume of images Image Processor processes, whether for optimization, cropping, resizing, filters, or format conversion. One image is counted for each request Image Processor processes, and an image served from [Cache](/en/documentation/build/cache/) without processing is not counted. [Pricing](/en/documentation/fundamentals/pricing/#image-processor) carries the volume each plan includes. |
| `images_processed` | The `metricName` of the consumption GraphQL query that returns the total number of images processed by Image Processor, under `productId` `1441110021`. [Consumption GraphQL API Fields](/en/documentation/devtools/graphql/gql-consumption-fields/) lists it, and [Query usage data from Image Processor](/en/documentation/guides/platform/observability/query-image-processor-usage-data-with-graphql/) carries the full query. |
| `ims` | The [query string](https://www.azion.com/en/learning/) parameter that describes the transformation Image Processor applies, as in `?ims=400x`. It must be the last parameter in the URL, and a request that carries another parameter after `ims=` may return a `504` error. [URL parameters](/en/documentation/build/image-processor/url-parameters/) documents every value it accepts. |
| `ims_http` | The value the **Proxy Upstream** field of a [Real-Time Events](/en/documentation/observe/real-time-events/) record carries when Image Processor answered as the upstream. In some cases the [Tiered Cache](/en/documentation/build/cache/tiered-cache/) origin can be Image Processor, which processes the image and then caches it. |
| Optimize Images | The [Rules Engine](/en/documentation/platform/applications/rules-engine/) behavior that enables Image Processor for the requests a rule matches. It runs in the **Request Phase**, takes no arguments, and requires the Image Processor module. The API type is `optimize_images`. |
| `orig` | The `ims` dimension value that keeps the original measurement of the source image on one axis. The other axis takes the requested value, and the derived image is not autocropped. [URL parameters](/en/documentation/build/image-processor/url-parameters/) shows the form it takes. |
| source image | The image on the origin that Image Processor reads when a request carries an `ims` query string. Azion never modifies it: a transformation produces a derived image and leaves the original in place. [How Image Processor works](/en/documentation/build/image-processor/how-it-works/) describes the path between the two. |
| WASM Image Processor | The WebAssembly library that processes images inside a function on [Functions](/en/documentation/build/functions/), through `loadImage`, `resize`, `getImageResponse`, and `clean`, for the `webp`, `jpeg`, and `png` formats. It is not the Image Processor module: the module transforms a request through the `ims` query string, and this library runs inside your code. [WASM Image Processor library](/en/documentation/devtools/azion-lib/wasm-image-processor/) documents it. |
