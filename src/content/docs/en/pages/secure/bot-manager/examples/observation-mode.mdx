One JSON object holds everything a function instance does, and two of its arguments settle whether anything is refused at all. The object below sets `action` to `allow`, so [Bot Manager Lite](/en/documentation/secure/bot-manager/bot-manager-lite/) scores every request and refuses none, and raises `internal_logs`, so it writes a report line for each one. Reach for it the first time you put Bot Manager in front of real traffic, while you still have to find out what your own traffic scores.

```json
{
  "threshold": 30,
  "action": "allow",
  "internal_logs": 2,
  "log_tag": "storefront-bots"
}
```

`threshold` is the score at which `action` fires, and `30` is the value Bot Manager Lite ships. `action` at `allow` applies nothing when a score reaches that value, so a request that crosses the threshold is scored, logged, and served like any other. At `2`, `internal_logs` writes one report line per request, including a request that scores `0`. `log_tag` names this instance in those lines, so replace `storefront-bots` with a tag of your own. For every argument an instance accepts, refer to [Arguments](/en/documentation/secure/bot-manager/arguments/#fields).

:::caution
The object is not validated. Azion stores every key you send and reads it back exactly as you typed it, including a key the function never reads. A misspelled `thresold` sits in the instance looking configured while the threshold stays at `30`, and no interface reports it.
:::

Save the object as `bmargs.json`:

```json
{
  "threshold": 30,
  "action": "allow",
  "internal_logs": 2,
  "log_tag": "storefront-bots"
}
```

The `--args` flag of `azion create firewall-instance` takes the path to that file, and no inline JSON:

```bash
azion create firewall-instance --name bot-manager-observation --firewall-id <firewall-id> \
  --function-id <function-id> --args bmargs.json --active true
```

```text
Created Firewall Function Instance with ID 15841
```

Record that id. A Rules Engine rule names the instance by it, never by the id of the function.

<Fragment slot="panel.api">

The create call carries the name, the id of the installed function, and the arguments in one body. Replace `<firewall-id>` with the id of your firewall, `[TOKEN VALUE]` with your personal token, and `53145` with the id of the installed Bot Manager Lite function:

```bash
curl --request POST \
  --url https://api.azion.com/v4/workspace/firewalls/<firewall-id>/functions \
  --header 'Accept: application/json' \
  --header 'Authorization: Token [TOKEN VALUE]' \
  --header 'Content-Type: application/json' \
  --data '{
  "name": "bot-manager-observation",
  "function": 53145,
  "active": true,
  "args": {
    "threshold": 30,
    "action": "allow",
    "internal_logs": 2,
    "log_tag": "storefront-bots"
  }
}'
```

The call answers `202`. The body opens with `"state": "pending"`, which means the change is still propagating, and carries under `data` the instance as the platform stored it: the `id` it assigned, the `args` echoed back unchanged, and `"azion_form": {}`, which is why Azion Console renders a JSON editor for this function instead of a form. Record the `id`.

## How it works

`threshold` and `action` are one decision, not two settings: the function applies `action` to a request whose score reaches `threshold`. With `action` at `allow`, reaching the threshold applies nothing, so the only difference between a request that crosses it and one that does not is the value the report line carries. The same holds at the bottom of the range. A `threshold` of `0` puts every request at or above the threshold and fires the configured action on all of them, which with `allow` still refuses nothing.

Reading the lines is the point of this configuration, and the verdict inside them moves with the threshold you set. `classified` is relative to the threshold in force rather than a property of the request: Azion measured the same score of `28`, from the same matched rules, reading `legitimate` under a threshold of `30` and `bad bot` under a threshold that `28` reaches. Changing the threshold during an observation window relabels the traffic you are observing.

The failure mode here is silence. Azion sent one instance twenty-one keys, one of them meaningless, and all twenty-one were stored and read back byte for byte, with nothing rejected, coerced, or dropped. An instance created with an empty object also stores an empty object, because the function's defaults are a runtime fallback rather than a copy, so an instance you open to find out what threshold it runs at shows `{}` and not `30`. Allow about two minutes after any change: Azion polled a workload every 15 seconds after switching one argument, and the eighth attempt was the first to answer differently.
