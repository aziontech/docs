A function instance scores nothing until a [Rules Engine for Firewall](/en/documentation/platform/firewall/rules-engine/) rule hands it a request. The rule below matches every request its firewall receives and runs one Bot Manager instance on each of them. Reach for it as the rule that puts Bot Manager in the path, and whenever you need the criterion that skips nothing.

```json
{
  "name": "Run Bot Manager on every request",
  "active": true,
  "criteria": [
    [
      {
        "conditional": "if",
        "variable": "${request_uri}",
        "operator": "starts_with",
        "argument": "/"
      }
    ]
  ],
  "behaviors": [
    {
      "type": "run_function",
      "attributes": {
        "value": 15841
      }
    }
  ]
}
```

`value` holds the id of the **function instance** on this firewall, so replace `15841` with your own. It never holds the id of the installed function, which is the same for every instance of it in the account.

<Fragment slot="panel.cli">

`azion create firewall-rule` reads the whole rule from a JSON file. It carries no flag for a criterion or a behavior, so save the rule above as `rule.json`, then:

```bash
azion create firewall-rule --firewall-id <firewall-id> --file rule.json
```

```text
Created Firewall Rule with ID 132159
```

Read the rule back and the platform has added one key it assigns itself, `"order": 0`, which is the position the rule holds among the rules of that firewall.

<Fragment slot="panel.api">

Save the rule above as `rule.json`, then send it to the firewall that carries the instance:

```bash
curl --request POST \
  --url https://api.azion.com/v4/workspace/firewalls/<firewall-id>/request_rules \
  --header 'Accept: application/json' \
  --header 'Authorization: Token [TOKEN VALUE]' \
  --header 'Content-Type: application/json' \
  --data @rule.json
```

The API answers `202` and returns the rule with one key it assigned: the `order` the rule holds among the rules of that firewall, `0` for the first one. The collection is `request_rules`.

## How it works

`criteria` is a list of lists, and the behavior takes the key `type`. A file that writes `name` instead is refused with `Failed to decode the given 'json' file`, a message that names neither the field nor the reason: the file is valid JSON and the defect is the shape. The attribute is `value`, and a rule carries at most one `run_function` behavior, which Azion Console enforces by disabling the option once one is in the rule. Running a second instance on the same request takes a second rule.

Key the criterion on the request URI. The `${request_args}` variable with the `matches` operator and `.*` as the argument looks like a match on everything and is not: the variable is empty whenever a request carries no query string, and an empty variable matches nothing. A rule keyed that way passes silently over every `POST` whose payload sits in the body. In Azion Console the `Request Uri` variable needs nothing else turned on, while `Header User Agent` and `Request Args` are offered only when [Web Application Firewall](/en/documentation/secure/waf/) is enabled on the firewall.

The behavior selector lists instances, not functions, and only the active ones. An instance has to exist before this rule can name it, which is why the object and the rule are two snippets rather than one.
