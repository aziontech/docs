[Bot Manager](/en/documentation/secure/bot-manager/) runs as a function instance on a firewall. The platform bounds the name that instance carries and the size of the arguments object it holds. This page states each bound, the answer the platform returns past it, and the Bot Manager usage a service plan includes.

The two sections hold different kinds of value. A default limit is checked on every call, and the call fails past it. An included quantity is a billing amount, and passing it changes what the account is charged rather than what the call returns.

---

## Default limits

Azion applies both bounds below on every service plan and through every interface. A call past either one returns `400` with the message the third column carries.

| Scope | Limit | Past the limit |
| --- | --- | --- |
| Function instance `name` | 100 characters | `400` and `["Ensure this field has no more than 100 characters."]` |
| Arguments payload | 100,000 bytes | `400` and `["Value size (in bytes) is too big. Maximum size allowed is 100000 bytes."]` |

The payload bound is decimal. The measured value is 100,000 bytes, and a payload of 102,400 bytes, which is 100 KiB, is rejected. Size the arguments object against the decimal figure.

Size is also the only property of that object the API checks. Every key an instance sends is stored and returned as sent, whatever the key is named. A misspelled argument therefore passes the call, and the function never reads it. For more information, refer to [Arguments](/en/documentation/secure/bot-manager/arguments/).

The number of function instances a firewall carries is not bounded. One firewall took twelve instances created one after another, and the platform accepted every call. The count a firewall reaches is an operational choice rather than a value the platform checks.

Two further bounds apply to the surfaces around an instance rather than to the instance itself, and the page that owns each surface states it.

The report log field `request_headers` holds 10,000 characters. Each header name and value deducts from that amount, and the field takes no further header once the amount is reached. For more information, refer to [Logs](/en/documentation/secure/bot-manager/logs/).

The `limit` argument of a GraphQL query against the Bot Manager datasets takes `10000` at most, so one query returns no more than 10,000 results. For more information, refer to [Query Bot Manager data with GraphQL](/en/documentation/guides/platform/observability/query-bot-manager-data-with-graphql/).

## Included usage per plan

Azion offers three service plans: Hobby, Pro, and Enterprise. Each plan carries an amount of the metrics Bot Manager is billed on.

The amounts below are billing quantities rather than bounds applied on a call. Passing one of them fails no request, so no error string belongs to this table. The section above holds the opposite case: a value the API checks and rejects a call on.

| Metric | Hobby | Pro | Enterprise |
| --- | --- | --- | --- |
| Bot Manager Lite | Included | Included | Custom |
| Bot Manager | Not listed | Not listed | Custom |
| Requests | Billed per 10,000 | Billed per 10,000 | Custom |
| Profiles | 1 | 1 | Custom |

[Bot Manager Lite](/en/documentation/secure/bot-manager/bot-manager-lite/) is included on all three plans. The full edition is listed on Enterprise alone, where each amount is custom.

No included volume of requests is published for Bot Manager on any plan. The published value is the increment requests are billed in, which is 10,000. The table carries that increment rather than an amount.

Each plan carries one profile, and a profile past the first is billed. For the rate that applies to requests and to profiles, refer to [Pricing](/en/documentation/fundamentals/pricing/#bot-manager). For what each plan carries across the platform, refer to [Azion pricing](https://www.azion.com/en/pricing/).
