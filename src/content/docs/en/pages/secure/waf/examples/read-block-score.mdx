Nothing in a blocked response identifies WAF. The request receives `400` and Azion's default error page, headed **Bad Request**, with no WAF header and no message naming a rule or a score. The `x-azion-request-id` header is the handle that finds the record. Reach for this pair whenever you need to know which internal rule fired before you write an exception for it.

```bash
curl -i "https://<your-workload-domain>/?q=1%27%20OR%20%271%27%3D%271"
```

```text
HTTP/2 400
content-type: text/html
x-azion-request-id: 1123d5bf29651faaaaf6e09dbafcc4e3
```

[Real-Time Events](/en/documentation/observe/real-time-events/) answers a GraphQL query at `https://api.azion.com/v4/events/graphql`, over the `workloadEvents` dataset. Send it with a personal token, filtered on the request id and a window around it:

```graphql
query {
  workloadEvents(
    limit: 1
    filter: { tsGte: "<start>", tsLt: "<end>", requestIdEq: "<request-id>" }
  ) {
    ts
    requestUri
    status
    upstreamStatus
    wafBlock
    wafMatch
    wafScore
    wafAttackFamily
    wafAttackAction
  }
}
```

```json
{
  "ts": "2026-09-20T16:03:51Z",
  "requestUri": "/?q=1%27%20OR%20%271%27%3D%271",
  "status": 400,
  "upstreamStatus": 0,
  "wafBlock": "1",
  "wafMatch": "0:1009:ARGS:q,1:1013:ARGS:q",
  "wafScore": "0:$SQL:18,1:$XSS:32",
  "wafAttackFamily": "$SQL,$XSS",
  "wafAttackAction": "$BLOCK"
}
```

## How it works

`wafMatch` carries one entry per internal rule that matched, shaped `<index>:<ruleId>:<zone>:<varName>`. This request matched rule `1009` and rule `1013` on the `q` argument, which are the equal sign and the apostrophe, not the rule that runs a SQL injection parser over the same value. `wafScore` reports one score per threat family that fired, shaped `<index>:$<family>:<score>`, so a request has several scores rather than one. `upstreamStatus` reads `0` because the request never reached an origin: a `400` paired with `0` is what a WAF block looks like from outside.

A request the WAF did not act on carries `-` in every one of these fields, and a `400` with no such row is not a WAF block. Query the v4 path: the older `https://api.azion.com/events/graphql` answers `204` with an empty body, and the fields are camelCase there rather than the snake_case spellings a [Data Stream](/en/documentation/observe/data-stream/) payload uses.
