A rule set holds the eight threat families and the sensitivity level chosen for each one. The body below creates a rule set with every family at `medium`, which is the level a family opens on and the one to start from before any traffic has told you otherwise. Reach for it when you need a rule set to name in a `Set WAF` behavior and have no reason yet to raise a family.

```bash
curl --request POST \
  --url https://api.azion.com/v4/workspace/wafs \
  --header 'Accept: application/json' \
  --header 'Authorization: Token [TOKEN VALUE]' \
  --header 'Content-Type: application/json' \

  "name": "storefront-waf",
  "active": true,
  "product_version": "1.0",
  "engine_settings": {
    "engine_version": "2021-Q3",
    "type": "score",
    "attributes": {
      "rulesets": [1],
      "thresholds": [
        { "threat": "cross_site_scripting", "sensitivity": "medium" },
        { "threat": "directory_traversal", "sensitivity": "medium" },
        { "threat": "evading_tricks", "sensitivity": "medium" },
        { "threat": "file_upload", "sensitivity": "medium" },
        { "threat": "identified_attack", "sensitivity": "medium" },
        { "threat": "remote_file_inclusion", "sensitivity": "medium" },
        { "threat": "sql_injection", "sensitivity": "medium" },
        { "threat": "unwanted_access", "sensitivity": "medium" }
      ]
    }
  }
}'
```

The API answers `202` and echoes the object under `data`, where `"state": "pending"` means the change is still propagating. Record `data.id`: that is the value a `Set WAF` behavior names.

## How it works

A bare create is already complete. The rule set comes back active, running on ruleset `1` with engine version `2021-Q3` and engine type `score`, and carrying all eight threat families at `medium`. The eight-family list is what the form in Azion Console fills in for you; the API accepts fewer, and a `thresholds` array holding one entry creates a rule set that scores only that family.

The sensitivity level fixes the score at which a family blocks. A family at `medium` needs more evidence before it reaches its threshold than the same family at `high`, so it produces fewer false positives and catches less. Raise one family at a time, from what the traffic recorded, rather than raising the whole rule set at once. For the threshold each level sets, refer to [WAF Rule Sets](/en/documentation/secure/waf/rules-set/#sensitivity-levels).
