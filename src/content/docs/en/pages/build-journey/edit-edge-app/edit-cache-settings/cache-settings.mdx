You create a cache setting on an application from Azion Console, the Azion API v4, or the Azion CLI, and apply it to requests with a [Rules Engine](/en/documentation/platform/applications/rules-engine/) rule. A setting holds the TTLs and the variation rules; until a rule names it through the **Set Cache Policy** behavior, it applies to no request.

For a first cache setting through the Console alone, refer to the [Cache quickstart](/en/documentation/build/cache/quickstart/). To vary the cache by a query string argument or a cookie, refer to [Configure Advanced Cache Key for an application](/en/documentation/guides/application-performance/cache-and-purge/advanced-cache-key/).

---

## Prerequisites

- An application. To create one, refer to [Build an application](/en/documentation/guides/application-development/getting-started/build-an-application/).
- Access to Azion Console, for the Console procedures. Refer to [Access Azion Console](/en/documentation/guides/platform/account-and-billing/how-to-access-azion-console/).
- A [personal token](/en/documentation/guides/platform/account-and-billing/personal-tokens/), for the API procedures.
- The [Azion CLI](/en/documentation/devtools/cli/) installed and authorized, for the CLI procedures.
- [Application Accelerator](/en/documentation/build/application-accelerator/) on the application, for a **Max Age** below 60 seconds or for cache variation.

---

## Create the cache setting through Azion Console

The **Create Cache Settings** drawer carries every field of a setting. To create one:

<DocSteps>
  <DocStep title="Open the application">

  Access [Azion Console](https://console.azion.com/) > **Applications**, then select the application.

  </DocStep>
  <DocStep title="Go to the Cache Settings tab" />
  <DocStep title="Select + Cache" />
  <DocStep title="Name the cache setting">

  In **Name**, enter a unique, descriptive name.

  </DocStep>
  <DocStep title="Choose the browser cache behavior">

  Under **Browser Cache**, select one option. _Honor cache policies_ forwards the origin's `Cache-Control` and `Expires` headers to the browser. _Override cache settings_ replaces them with a TTL you enter. _No cache_ disables browser caching, so content is always fetched from the server.

  </DocStep>
  <DocStep title="Choose the cache behavior">

  Under **Cache**, select _Honor cache policies_ to keep the origin's headers, or _Override cache behavior_ to replace them.

  </DocStep>
  <DocStep title="Set Max Age">

  In **Max Age**, enter the seconds Azion keeps a copy. A new setting carries `60`.

  </DocStep>
  <DocStep title="Turn on Stale cache">

  With the toggle on, Azion serves an expired copy when a revalidation attempt with the origin fails.

  </DocStep>
  <DocStep title="Turn on Large file optimization">

  With the toggle on, Azion caches a large object in fragments rather than as one piece.

  </DocStep>
  <DocStep title="Turn on Tiered Cache">

  The toggle adds a second cache layer between Azion's cache and the origin. It requires _Override cache behavior_ and a **Max Age** of at least 3 seconds.

  </DocStep>
  <DocStep title="Select Save" />
</DocSteps>

The setting appears in the **Cache Settings** list with its **Name**, **ID**, **Browser Cache**, and **Cache**. For every field with its type, its default, and its bounds, refer to [Cache settings](/en/documentation/build/cache/cache-settings/).

## Apply the setting with a rule

A rule in the request phase decides which requests the setting covers. To create it:

<DocSteps>
  <DocStep title="Go to the Rules Engine tab" />
  <DocStep title="Select + Rule" />
  <DocStep title="Name the rule" />
  <DocStep title="Select Request Phase" />
  <DocStep title="Set the criteria">

  Under **Criteria**, select `${uri}`, an operator, and the argument that matches the paths to cache.

  </DocStep>
  <DocStep title="Add the Set Cache Policy behavior">

  Under **Behaviors**, select **Set Cache Policy**, then select the cache setting.

  </DocStep>
  <DocStep title="Select Save" />
</DocSteps>

The rule appears in the list and applies the setting to every request its criteria match.

:::note
A new rule can take a few minutes to propagate. Wait before you check the cache status of a response.
:::

## Create the cache setting through the API

Two requests create the setting and the rule that applies it. To send them:

<DocSteps>
  <DocStep title="Create the cache setting">

  ```bash
  curl --location --request POST 'https://api.azion.com/v4/workspace/applications/{application_id}/cache_settings' \
  --header 'Accept: application/json' \
  --header 'Content-Type: application/json' \
  --header 'Authorization: Token [TOKEN VALUE]' \
  --data '{
    "name": "static-assets",
    "browser_cache": { "behavior": "no-cache" },
    "modules": {
      "cache": {
        "behavior": "override",
        "max_age": 300,
        "stale_cache": { "enabled": true },
        "large_file_cache": { "enabled": true, "offset": 1024 },
        "tiered_cache": { "enabled": true, "topology": "nearest-region" }
      }
    }
  }'
  ```

  </DocStep>
  <DocStep title="Read the id in the response">

  The API answers with HTTP `201`, `state` set to `executed`, and the new setting under `data`:

  ```json
  {"state":"executed","data":{"id":344164,"name":"static-assets","browser_cache":{"behavior":"no-cache","max_age":0},"modules":{"cache":{"behavior":"override","max_age":300,"stale_cache":{"enabled":true},"large_file_cache":{"enabled":true,"offset":1024},"tiered_cache":{"topology":"nearest-region","enabled":true}}},"created_at":"2026-09-17T17:38:27.577248Z"}}
  ```

  </DocStep>
  <DocStep title="Create the rule that applies it">

  Replace `[CACHE SETTING ID]` with the `id` the response returned:

  ```bash
  curl --location --request POST 'https://api.azion.com/v4/workspace/applications/{application_id}/request_rules' \
  --header 'Accept: application/json' \
  --header 'Content-Type: application/json' \
  --header 'Authorization: Token [TOKEN VALUE]' \
  --data '{
    "name": "apply-static-assets-cache",
    "criteria": [[{ "variable": "${uri}", "operator": "starts_with", "conditional": "if", "argument": "/static/" }]],
    "behaviors": [{ "type": "set_cache_policy", "attributes": { "value": "[CACHE SETTING ID]" } }]
  }'
  ```

  </DocStep>
  <DocStep title="Read the rule response">

  The API answers with HTTP `202` and the rule with `state` set to `pending`, because a new rule propagates before it applies:

  ```json
  {"state":"pending","data":{"id":710871,"name":"apply-static-assets-cache","active":true,"order":0}}
  ```

  </DocStep>
</DocSteps>

The setting now applies to every request whose path starts with the argument. To list the settings of an application, send `GET` to the same `cache_settings` path.

## Create the cache setting through the Azion CLI

The CLI covers part of the object with flags, and the whole of it with a JSON file. To create a setting from flags:

<DocSteps>
  <DocStep title="Run the create command">

  ```bash
  azion create cache-setting \
  --application-id <application-id> \
  --name "product-listing" \
  --browser-cache-behavior override \
  --browser-cache-max-age 30 \
  --cache-by-query-string allowlist \
  --query-string-fields "category,page" \
  --cache-by-cookies allowlist \
  --cookie-names "session_id"
  ```

  </DocStep>
  <DocStep title="Read the id in the output">

  ```text
  Created Cache Settings configuration with ID 344170
  ```

  </DocStep>
  <DocStep title="Read the setting back">

  ```bash
  azion describe cache-setting --application-id <application-id> --cache-setting-id 344170 --format json
  ```

  The object carries the browser cache and the variation fields the flags set, and `modules.cache` at its defaults: `honor` and `60`.

  </DocStep>
</DocSteps>

To create a setting with the fields the flags do not cover, send the request body from a file:

<DocSteps>
  <DocStep title="Write the body to a file">

  Save the API request body above as `cache-setting.json`.

  </DocStep>
  <DocStep title="Create the setting from the file">

  ```bash
  azion create cache-setting --application-id <application-id> --file cache-setting.json
  ```

  The command prints the id of the new setting:

  ```text
  Created Cache Settings configuration with ID 344171
  ```

  </DocStep>
</DocSteps>

:::note
The CLI flags do not set **Max Age**, the cache behavior, stale cache, Large File Optimization, or Tiered Cache. Use `--file` with the request body for those fields.
:::

The CLI does not create the rule that applies the setting. Create it through the Console or the API, with either procedure on this page. For every flag, refer to [Azion CLI create](/en/documentation/devtools/cli/create/).
