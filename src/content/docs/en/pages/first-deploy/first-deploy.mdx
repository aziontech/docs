## Before you start

All you need is an Azion account. You can create one for free, and it doesn't ask for a credit card. Anything path-specific is listed in the path itself.

## Deploy a template via Console

Templates are ready-made projects (e-commerce, blogs, APIs, full-stack SSR) that go live in a few clicks. You don't need any local tooling.

<DocCallout kind="note">Some templates are integrated with third-party services, so you may need to create accounts, generate tokens, or activate Azion products before deploying. Templates integrated with GitHub ask you to connect your account: click Connect with GitHub when prompted and confirm the connection in the pop-up. Each template's guide lists its specific prerequisites.</DocCallout>

<DocSteps>
  <DocStep title="Access Azion Console." />
  <DocStep title="Click + Create on the homepage." />
  <DocStep title="In the modal, select Templates." />
  <DocStep title="Browse and pick the one you want to start with." />
  <DocStep title="Fill in the configuration page." />
  <DocStep title="Click Deploy, in the bottom-right corner." />
</DocSteps>

Follow the deploy through the logs window. When it finishes, the page shows your application's name, its deploy logs, and its Azion domain. Some templates also create a function and apply pre-defined configurations to optimize your application's performance. The template's guide lists what's included.

### Test it

Copy the Azion domain from the confirmation page:

```bash
curl -I https://<your-azion-domain>
# HTTP/2 200
```

Open the same URL in the browser to see your application running.

<DocCallout kind="note">New URLs can take a few minutes to propagate to Azion's edge locations. If you get an error right after deploying, wait a moment and try again.</DocCallout>

## Import a project from GitHub

<DocCallout kind="info">You need a GitHub account and a repository using one of the supported frameworks.</DocCallout>

<DocSteps>
  <DocStep title="In Azion Console, click + Create." />
  <DocStep title="Select Import from Git." />
  <DocStep title="Connect the Git account that owns the repository." />
  <DocStep title="Pick the repository to import." />
  <DocStep title="Name the application and check the build and deploy commands.">

  Azion reads the commands from the repository, so both arrive filled in for a project it recognises — change them only if your build differs. The name becomes part of the deployed URL.

  </DocStep>
  <DocStep title="Leave Protect with Azion Firewall off, or turn it on to deploy a firewall alongside the application." />
  <DocStep title="Click Create and deploy, then follow the logs until the Azion domain shows up." />
</DocSteps>

### Test it

```bash
curl -I https://<your-azion-domain>
# HTTP/2 200
```

Open the Azion domain in the browser to see your application running. If you get an error right away, wait a few minutes: new URLs take a moment to propagate to Azion's edge locations.

## Deploy with Azion CLI

<DocCallout kind="info">You need the Azion CLI (installed below) and a local project using one of the supported frameworks, with its dependencies installed.</DocCallout>

<DocCallout kind="tip">Starting from scratch instead? Run `azion init` to create a new project from a framework template, then deploy it the same way. See the [CLI overview](/en/documentation/devtools/cli/) and the [link command reference](/en/documentation/devtools/cli/link-command/) for details.</DocCallout>

<DocPrompt client:visible kind="line" title="AI Assistant">Install the Azion CLI, link this project to my Azion account using the preset that matches its framework, deploy it, and print the Azion domain once it answers 200.</DocPrompt>

<DocSteps>
  <DocStep title="Install the Azion CLI">

  ```bash
  curl -fsSL https://cli.azion.app/install.sh | bash
  ```

  </DocStep>
  <DocStep title="Link and deploy">

  Authenticate:

  ```bash
  azion login
  ```

  In the project's root folder, link it to Azion:

  ```bash
  azion link
  ```

  The CLI guides you from there: confirm the linking, accept or change the suggested application name, and pick a preset matching your framework. When it asks `Do you want to deploy your project?`, answer yes. (If you answer no, run `azion deploy` when you're ready.)

  At the end of the deploy, the CLI prints your application's Azion domain.

  </DocStep>
  <DocStep title="Test it">

  ```bash
  curl -I https://<your-azion-domain>
  # HTTP/2 200
  ```

  If you get an error right away, wait a few minutes: new URLs take a moment to propagate to Azion's edge locations.

  </DocStep>
</DocSteps>

## What you built

You deployed an application to Azion's global network and confirmed it answers on its own domain. The workflow is the same one you'll use for production projects.
