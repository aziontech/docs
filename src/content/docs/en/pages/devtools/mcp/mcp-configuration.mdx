This guide instructs you through your first question to the Azion MCP server from Claude Code.

- Create a personal token in Azion Console.
- Register the server in Claude Code with one command.
- Check the tools and resources the server exposes with the MCP Inspector.
- Ask Claude Code a question that the server answers from the Azion documentation.

Three pieces connect, in this order:

1. The **personal token** identifies your Azion account.
2. The **server entry** `azion-mcp` in Claude Code points at `https://mcp.azion.com` and sends the token in the `Authorization` header of every request.
3. The **Azion MCP server** checks the token and gives Claude Code its tools and resources.

For more information about the server, refer to [MCP server](/en/documentation/devtools/mcp/).

---

## Prerequisites

- An Azion account. To create one, refer to [Create an account](/en/documentation/fundamentals/creating-account/).
- Claude Code, installed on your machine.
- Node.js and npm. The MCP Inspector runs with `npx`.

---

## 1. Create a personal token

The server accepts an Azion personal token as its credential. To create the token in Azion Console:

<DocSteps>
  <DocStep title="Open the personal tokens page">

  Access [Azion Console](https://console.azion.com/) > **Account** > **Personal Token**. **Account** is the avatar menu.

  </DocStep>
  <DocStep title="Select + Personal Token" />
  <DocStep title="Name the token">

  In the **General** section, enter a **Name**. For example: `mcp-server`.

  </DocStep>
  <DocStep title="Set the expiration">

  In the **Token** section, select a value in **Expires within**. The default is _1 day_.

  </DocStep>
  <DocStep title="Select Save" />
  <DocStep title="Copy the token">

  In the **Personal Token has been created** dialog, select **Copy**. The dialog shows the token only once, so store it before you continue.

  </DocStep>
  <DocStep title="Select Confirm" />
</DocSteps>

The token appears in the **Personal Tokens** list, and its value is in your clipboard. For more information, refer to [How to manage a personal token](/en/documentation/guides/platform/account-and-billing/personal-tokens/).

Keep the token safe:

- Never commit a token. Add every configuration file that holds one to `.gitignore`.
- Store the token in an environment variable when your client supports it.
- Rotate your tokens regularly.

## 2. Connect Claude Code

The `claude mcp add` command registers the server. The `-t http` flag selects the HTTP transport, and `-H` sets the header that carries your token. Run the command, and replace `[TOKEN VALUE]` with your token:

```bash
claude mcp add "azion-mcp" "https://mcp.azion.com" -t http -H "Authorization: Bearer [TOKEN VALUE]"
```

Claude Code stores the server in your user configuration, which is not a file in your project. The server also accepts the token with the `Token` scheme, `Authorization: Token [TOKEN VALUE]`, and answers both schemes the same way.

Claude Code has the Azion MCP server registered as `azion-mcp`. For more information about Claude Code with Azion, refer to [Claude Code + Azion](/en/documentation/agent-setup/claude-code/).

---

## 3. Check the connection

The MCP Inspector connects to an MCP server and lists what the server exposes. Start the Inspector:

```bash
npx @modelcontextprotocol/inspector
```

To install the Inspector instead of running it through `npx`, run `npm install -g @modelcontextprotocol/inspector`.

To connect the Inspector to the Azion MCP server:

<DocSteps>
  <DocStep title="Select the transport">

  Set **Transport type** to _streamable-http_.

  </DocStep>
  <DocStep title="Enter the server address">

  In **URL**, enter `https://mcp.azion.com`.

  </DocStep>
  <DocStep title="Enter the header">

  In **Authentication**, enter `Authorization: Bearer [TOKEN VALUE]`, with your token in place of `[TOKEN VALUE]`.

  </DocStep>
  <DocStep title="Select Connect" />
  <DocStep title="Open the Tools tab" />
  <DocStep title="Open the Resources tab" />
</DocSteps>

For an account on the v4 API profile, the **Tools** tab lists eight tools, and the **Resources** tab lists seven resources. An account on the v3 API profile sees one more tool. For the full list, refer to [Tools and resources](/en/documentation/devtools/mcp/tools/#tool-set-by-api-profile).

A request without a valid token fails with `401`. To diagnose a failed connection, refer to [Troubleshoot the MCP server](/en/documentation/devtools/mcp/troubleshooting/).

## 4. Ask your first question

The `search_azion_docs_and_site` tool searches the Azion documentation and website. In a Claude Code session, ask a question that needs it:

```text
Search the Azion documentation: how to configure cache
```

The tool returns the documentation pages that best match the question, each with its title, content, and source URL. Claude Code builds its answer from these pages.

The other tools of the server return code samples, Azion CLI commands, Azion API operations, Rules Engine rule proposals, GraphQL queries, and guides to deploy a static site. No tool creates, changes, or deletes anything in your account. Try one of these prompts next:

- `I have a static website with HTML, CSS, and JavaScript files. Help me deploy it to Azion.`
- `Generate a query to analyze cache hit rates for my images.`
- `Create Rules Engine rules to add security headers including HSTS, X-Frame-Options, and CSP for my application.`
- `My deployment is failing with error 503. How can I debug this?`

Claude Code answers questions about Azion from the Azion MCP server.

## Connect another client

Each client in the table below has its own setup page. All of them connect to `https://mcp.azion.com` with your personal token:

| Client | Where the server is configured | Setup page |
| --- | --- | --- |
| Cursor | `.cursor/mcp.json` | [Cursor + Azion](/en/documentation/agent-setup/cursor/) |
| GitHub Copilot | `.vscode/mcp.json` | [GitHub Copilot + Azion](/en/documentation/agent-setup/github-copilot/) |
| Windsurf | `.codeium/windsurf/mcp_config.json` | [Windsurf + Azion](/en/documentation/agent-setup/windsurf/) |
| Codex | `~/.codex/config.toml` | [Codex + Azion](/en/documentation/agent-setup/codex/) |
| Gemini CLI | `~/.gemini/settings.json` | [Gemini CLI + Azion](/en/documentation/agent-setup/gemini-cli/) |
| OpenCode | `opencode.json` | [OpenCode + Azion](/en/documentation/agent-setup/opencode/) |

Cursor uses the `Token` scheme instead of `Bearer` in the `Authorization` header.

Claude Desktop, Warp, and Kiro have no setup page. Their configurations follow.

### Claude Desktop

Claude Desktop starts the connection through `mcp-remote`, a bridge between a local client and a remote MCP server. The `npx` command downloads `mcp-remote` on first use, and the bridge needs Node.js 18 or later. It takes about 10 seconds to connect.

In the Claude Desktop settings, open the MCP configuration and add the server. Replace `[TOKEN VALUE]` with your token:

```json
{
  "mcpServers": {
    "azion": {
      "command": "npx",
      "args": [
        "-y",
        "mcp-remote@latest",
        "https://mcp.azion.com",
        "--header",
        "Authorization: Bearer [TOKEN VALUE]"
      ]
    }
  }
}
```

### Warp

Warp also connects through `mcp-remote`, with the same Node.js requirement. In the Warp MCP settings, add the server. This configuration has no `mcpServers` key around the server. Replace `[TOKEN VALUE]` with your token:

```json
{
  "azion": {
    "command": "npx",
    "args": [
      "-y",
      "mcp-remote@latest",
      "https://mcp.azion.com",
      "--header",
      "Authorization: Bearer [TOKEN VALUE]"
    ]
  }
}
```

### Kiro

Kiro reads the token from a `token` field instead of a header. Create the file `.kiro/settings/mcp.json` with the server. Replace `[TOKEN VALUE]` with your token:

```json
{
  "servers": {
    "azion": {
      "url": "https://mcp.azion.com",
      "token": "[TOKEN VALUE]"
    }
  }
}
```
