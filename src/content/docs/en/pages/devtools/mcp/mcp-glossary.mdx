This glossary defines the terms that the [Azion MCP server](/en/documentation/devtools/mcp/) uses in its answers, in the configuration of a coding agent, and across its documentation.

| Term | Definition |
| --- | --- |
| API profile | The Azion API version, `v3` or `v4`, that an account resolves to when the MCP server authenticates its token. The profile decides which tools the server lists: 8 on the `v4` profile, and 9 on the `v3` profile, which adds `search_azion_api_v3_commands`. [Tools and resources](/en/documentation/devtools/mcp/tools/) lists every tool. |
| MCP server | The hosted [Model Context Protocol](https://modelcontextprotocol.io) server that Azion runs at `https://mcp.azion.com/`, where a coding agent searches Azion documentation, code samples, CLI commands, API operations, and Terraform resources. It answers at the bare host only, and `/mcp` returns 404. [MCP server](/en/documentation/devtools/mcp/) describes what it offers, and [Agent Setup](/en/documentation/agent-setup/) connects each coding agent to it. |
| `mcp-remote` | The package that bridges a client that starts its servers as local processes to the MCP server over HTTP. `npx` downloads and runs it with the server URL and the `Authorization` header, as in `npx -y mcp-remote@latest https://mcp.azion.com --header "Authorization: Bearer [TOKEN VALUE]"`. [MCP server quickstart](/en/documentation/devtools/mcp/configuration/) shows the clients that use it. |
| personal token | The Azion credential that authenticates every request to the MCP server: `azion` followed by 35 letters and digits, 40 characters in all. A client sends it as `Authorization: Bearer [TOKEN VALUE]` or `Authorization: Token [TOKEN VALUE]`, which the server treats the same, and a request without it gets 401 `No authentication provided`. [Personal Tokens](/en/documentation/fundamentals/personal-tokens/) describes how a token is created and when it expires. |
| `Pragma: azion-debug-cache` | The request header that makes an Azion response carry its cache debug headers, such as `x-cache`, `x-cache-key`, and `x-cache-expires-in`. [Test cache behavior with the MCP server](/en/documentation/guides/application-performance/cache-and-purge/test-cache-with-mcp/) uses it to read the cache state of a deployed site, and [Cache quickstart](/en/documentation/platform/applications/cache/quickstart/) explains `x-cache` and `x-cache-key`. |
| prompt | A message template that a Model Context Protocol server can offer to its clients. The Azion MCP server offers none, so a request for its prompts returns `-32601 Method not found`. [Run an MCP server on Azion](/en/documentation/guides/application-development/automation/run-mcp-server/) shows how to add prompts to a server of your own. |
| resource | A document that a client reads from the MCP server by its URI, the way it reads a file, without calling a tool. The Azion MCP server serves seven Markdown resources, under `azion://static-site/deploy/` and `azion://static-site/test-cache/`. [Tools and resources](/en/documentation/devtools/mcp/tools/) lists each URI. |
| streamable HTTP | The Model Context Protocol transport that the MCP server uses: a client sends each message as an HTTP POST to `https://mcp.azion.com/`, and the server answers with a `text/event-stream` response. The server keeps no session between requests and requires TLS 1.3. Client configurations name this transport `http` or `streamable-http`, and [How the MCP server works](/en/documentation/devtools/mcp/how-it-works/) describes the request flow. |
| tool | A function that the MCP server offers and a coding agent calls by name with JSON arguments, such as `search_azion_docs_and_site` with a `query`. Every tool returns text, and none changes the account. [Tools and resources](/en/documentation/devtools/mcp/tools/) lists each tool with its arguments. |
