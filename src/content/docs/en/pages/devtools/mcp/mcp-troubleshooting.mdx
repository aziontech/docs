This page lists the symptoms you can meet with the [MCP server](/en/documentation/devtools/mcp/), each with its cause and its fix. Authentication and connection come first, then the tool set, the client configuration, the tool answers, sign-in, the staging server, and local development. When a symptom persists, contact Azion support as [Get help](/en/documentation/support/get-help/) describes, with the error message, the client and its version, the configuration without the token, and the steps that reproduce the symptom.

---

## The server answers 401 with No authentication provided

The client cannot connect, and the server answers `401` with this body:

```text
{"message":"No authentication provided","status":401}
```

The request reached the server without an `Authorization` header. The client configuration has no header, or the client does not send it.

- **Add the header to the client configuration**: send `Authorization: Bearer [TOKEN VALUE]` with your personal token. The server also accepts `Authorization: Token [TOKEN VALUE]`, with the same result. For the configuration of each client, refer to [Agent Setup](/en/documentation/agent-setup/).

The server answers `200` to the client, and the client lists the tools.

---

## The server answers Invalid Bearer token or Authentication failed

The client sends an `Authorization` header, and the server still answers `401`. The body names the problem:

| Body | Cause |
| --- | --- |
| `{"message":"Invalid Bearer token","status":401}` | The value after `Bearer` is not a valid token. |
| `{"message":"Authentication failed","status":403}` | The value after `Token` is not a valid personal token. The body reports `403` inside a `401` response. |
| `{"message":"Invalid authentication header format","status":401}` | The header carries the token without a scheme. |

These bodies come as plain text, not as JSON-RPC errors.

- **Check the token**: a personal token is 40 characters long and starts with `azion`. Copy the whole value. Check that the token is active, has not expired, and has the permissions you need. To create another one, refer to [How to manage a personal token](/en/documentation/guides/platform/account-and-billing/personal-tokens/).
- **Write the scheme before the token**: `Authorization: Bearer [TOKEN VALUE]` or `Authorization: Token [TOKEN VALUE]`.
- **Use Token in Cursor**: the Cursor setup sends `Token` instead of `Bearer`. For the configuration, refer to [Cursor + Azion](/en/documentation/agent-setup/cursor/).
- **Test the connection with MCP Inspector**: run `npx @modelcontextprotocol/inspector`, choose the `streamable-http` transport, and pass the header with your token.

:::caution
Keep your personal token out of version control and out of messages to other people. Remove it from logs and screenshots before you send them.
:::

The server answers `200`, and the client lists the tools.

## The client times out or cannot reach the server

A request times out, the server sends no response, or the client reports a network error.

The client points at the wrong URL, or the network between the client and the server blocks the connection.

- **Check the URL**: the server address is the bare host `https://mcp.azion.com`, with no path.
- **Test that the server is reachable**: `curl -I https://mcp.azion.com` answers `HTTP/2 401` without a token. A `401` means the server is reachable. A timeout or a connection error means the network does not reach it.
- **Try another network**: a VPN can interfere. A firewall or a proxy must allow HTTPS traffic to `mcp.azion.com`.
- **Test your token outside the client**: send the `initialize` request with `curl`.

This request opens a connection with your token:

```bash
curl -s https://mcp.azion.com \
  -H "Authorization: Bearer [TOKEN VALUE]" \
  -H "Content-Type: application/json" \
  -H "Accept: application/json, text/event-stream" \
  -d '{"jsonrpc":"2.0","method":"initialize","id":1,"params":{"protocolVersion":"2025-03-26","capabilities":{},"clientInfo":{"name":"my-client","version":"0.1"}}}'
```

The server answers `200` with an event stream. Its `data:` line carries this JSON:

```json
{
  "result": {
    "protocolVersion": "2025-03-26",
    "capabilities": {
      "logging": {},
      "resources": {
        "listChanged": true
      },
      "tools": {
        "listChanged": true
      },
      "completions": {}
    },
    "serverInfo": {
      "name": "azion-mcp-server",
      "version": "1.0.0"
    }
  },
  "jsonrpc": "2.0",
  "id": 1
}
```

With a response that names `azion-mcp-server`, the server and the token work, and the fix is in the client configuration.

## The server answers 404 Not Found

The client points at `https://mcp.azion.com/mcp`, and the server answers `404` with the body `404 Not Found`, even with a valid token.

The server answers at the root path of the host. No other path serves it.

- **Remove the path**: set the server URL to `https://mcp.azion.com`.
- **Keep paths for your own servers**: the `/mcp` path in [Run an MCP server on Azion](/en/documentation/guides/application-development/automation/run-mcp-server/) belongs to the example server that guide builds, not to the Azion MCP server.

The server answers `200` at the root path, and the client lists the tools.

## The client lists eight tools or a call fails with Tool not found

The client lists eight tools where you expect nine, or a tool call fails with this error:

```text
MCP error -32602: Tool search_azion_api_v3_commands not found
```

The tool set depends on the API profile of the account. `search_azion_api_v3_commands` appears only to an account on the v3 API profile. An account on the v4 profile sees eight tools, and a call to a name outside its set fails with the JSON-RPC error `-32602`.

- **Call the tools the server lists**: an account on the v4 profile sees `search_azion_docs_and_site`, `search_azion_code_samples`, `search_azion_cli_commands`, `search_azion_api_v4_commands`, `search_azion_terraform`, `create_rules_engine`, `create_graphql_query`, and `deploy_azion_static_site`. For the inputs of each tool, refer to [Tools](/en/documentation/devtools/mcp/tools/#tools).
- **Search the API v4 instead**: on the v4 profile, `search_azion_api_v4_commands` searches the API documentation. For the profiles, refer to [Tool set by API profile](/en/documentation/devtools/mcp/tools/#tool-set-by-api-profile).

The client calls only the tools that `tools/list` returns, and each call answers.

## A prompts request fails with Method not found

A client that asks the server for prompts gets the JSON-RPC error `-32601` with the message `Method not found`.

The server exposes no prompts. Its `initialize` response declares no `prompts` capability, so a `prompts/list` request has no method to answer it.

- **Use the tools and the resources**: the server offers its guides as tools and resources. For the list, refer to [Static site resources](/en/documentation/devtools/mcp/tools/#static-site-resources).
- **Ignore the error in client logs**: it comes from the prompt request only. Tool and resource requests on the same connection answer as usual.

The client lists the tools and the resources, and tool calls answer.

## The connection fails with TLSV1_ALERT_PROTOCOL_VERSION

The client fails the TLS handshake with an error such as `SSLError TLSV1_ALERT_PROTOCOL_VERSION`.

The server accepts TLS 1.3 only. A client built on a TLS library without TLS 1.3 cannot connect. The system Python 3 of macOS, built against LibreSSL 2.8.3, fails this way.

- **Run the client on a runtime with TLS 1.3**: a runtime whose TLS library supports TLS 1.3 connects, such as Node.js 24.
- **Check the TLS library of your tool**: a script or a proxy between the client and the server must also support TLS 1.3.

The handshake completes, and the server answers the request.

## The client takes several seconds to connect through mcp-remote

A client that starts the server through `mcp-remote` shows the tools about 10 to 13 seconds after it starts.

Before it connects, `mcp-remote` reads the OAuth configuration of the server, even when you pass the header. That discovery takes about 4 seconds of the total. With the header present, no browser window opens and no OAuth sign-in runs.

This command starts the bridge with your token:

```bash
npx -y mcp-remote@latest https://mcp.azion.com --header "Authorization: Bearer [TOKEN VALUE]"
```

The bridge reports each stage of the connection:

```text
[12345] Discovering OAuth server configuration...
[12345] Using callback port derived from the server URL: 21077
[12345] Using custom headers: Authorization
[12345] Discovered authorization server: https://sso.azion.com
[12345] Using transport strategy: http-first
[12345] [12345] Connecting to remote server: https://mcp.azion.com
[12345] Connected to remote server using StreamableHTTPClientTransport
[12345] Local STDIO server running
[12345] Press Ctrl+C to exit
[12345] Proxy established successfully between local STDIO and remote StreamableHTTPClientTransport
```

- **Wait for the proxy line**: the tools appear after `Proxy established successfully`.
- **Connect over HTTP directly**: a client that supports streamable HTTP connects without `mcp-remote`, such as Claude Code with `-t http` or Cursor with `streamable-http`. For each client, refer to [Agent Setup](/en/documentation/agent-setup/).

The client lists the tools once the proxy line appears.

## The client shows no Azion tools

The client shows no Azion tools, reports `No tools available`, or does not recognize the commands.

The client does not support MCP, has not loaded its configuration, or has not registered the server.

- **Check MCP support**: use a client version that supports MCP. Update the client if it does not.
- **Check the configuration location**: Windsurf reads `.codeium/windsurf/mcp_config.json`. For each client, refer to [Agent Setup](/en/documentation/agent-setup/).
- **Check that the server is registered**: in Claude Code, `claude mcp list` names the servers it knows. For the setup, refer to [Claude Code + Azion](/en/documentation/agent-setup/claude-code/).
- **Restart the client**: close and reopen the application so it reads the configuration again.

The client lists the tools of the server.

## The client reports Invalid JSON

The client reports `Invalid JSON` and does not load the configuration.

The configuration file breaks a JSON rule. Common causes are a missing comma between properties, a trailing comma, single quotes instead of double quotes, and an unclosed bracket or brace.

- **Validate the file**: `cat mcp_config.json | python -m json.tool` prints the file when it is valid and names the first error when it is not.
- **Compare with a valid configuration**: a client that starts the server through `mcp-remote` reads a configuration of this shape.

```json
{
  "mcpServers": {
    "azion": {
      "command": "npx",
      "args": [
        "-y",
        "mcp-remote@latest",
        "https://mcp.azion.com",
        "--header",
        "Authorization: Bearer [TOKEN VALUE]"
      ]
    }
  }
}
```

The client loads the configuration and lists the tools.

## The client fails with npx command not found

The client fails with `npx: command not found` or `Node.js is required`.

`mcp-remote` runs on Node.js. It needs Node.js 18 or later, and `npx` comes with npm.

- **Check the installed versions**: `node --version` and `npm --version` print the versions, or fail when Node.js is missing.
- **Install Node.js**: on macOS, run `brew install node`. On Ubuntu or Debian, run `sudo apt install nodejs npm`.
- **Update npm**: run `npm install -g npm@latest`.

`npx -y mcp-remote@latest` starts the bridge, as [The client takes several seconds to connect through mcp-remote](#the-client-takes-several-seconds-to-connect-through-mcp-remote) shows.

---

## The client fails with Cannot find module mcp-remote

The client fails with `Cannot find module 'mcp-remote'`, or the package install fails.

The npm cache or the installed copy of `mcp-remote` is broken or missing.

- **Clear the npm cache**: run `npm cache clean --force`.
- **Install the package globally**: run `npm install -g mcp-remote`.
- **Run the latest version**: start the bridge with `npx mcp-remote@latest`.

The bridge starts and prints `Proxy established successfully`.

## A search returns documents that do not match the query

A search tool returns no result, a partial result, or general answers instead of Azion information.

The search tools rank documents by how close they are to the words of the query, not by what the query means. A broad query can rank a document about another product or operation first.

- **Name the product and the task**: ask "How do I configure cache TTL for images in Azion?" instead of "Help with cache".
- **Name the tool or the source**: ask "Search Azion docs for Rules Engine cache configuration".
- **Ask for more documents**: the search tools take `docsAmount`, which defaults to `5`. For the inputs, refer to [Tools](/en/documentation/devtools/mcp/tools/#tools).
- **Split the request**: ask one question per prompt.

The tool returns documents about the product and the task you named.

## The GraphQL tool answers It was not possible to retrieve the requested information

`create_graphql_query` returns the text `It was not possible to retrieve the requested information with GraphQL.` instead of a query. The text then points to the GraphQL API documentation.

The tool writes a query for your goal and runs it against the analytics data of your account, with your token, to validate it. The tool returns this text when it cannot produce a query that runs. The server does not return the cause to the client.

- **Check that the data exists**: confirm that the GraphQL API carries the data you ask for. For the datasets, refer to [GraphQL API](/en/documentation/devtools/graphql/).
- **Check the data source**: `dataSource` takes `real-time-metrics`, `real-time-events`, `accounting`, or `consumption`. Pick the one that holds the data.
- **Write the query yourself**: build the query from the GraphQL API documentation and run it there.

You get the data from a query that the GraphQL API runs.

## Tool calls answer slowly

Tool calls take a long time to answer.

The network path to the server is slow, many requests run at once, or the query is broad. `create_graphql_query` also generates and validates queries on the server, and can take more than 15 seconds.

- **Check the network**: use a stable connection. `ping mcp.azion.com` measures the latency to the server.
- **Send fewer requests at once**: run fewer concurrent tool calls.
- **Narrow the query**: ask a specific question instead of a broad search.

Tool calls answer in less time.

## An OAuth token is refused or the client is not authorized

After an OAuth sign-in, the server reports an invalid token, the user information request answers `401`, or the client is not authorized.

The server checks an OAuth access token against the user information endpoint of its authorization server. A token from another environment, an expired token, or a client registered with different settings fails that check.

- **Send the token with Bearer**: an OAuth access token goes in `Authorization: Bearer [TOKEN VALUE]`.
- **Check the authorization server**: the server advertises `https://sso.azion.com`, with the endpoints `/oauth/authorize`, `/oauth/token`, and `/oauth/jwks`. The staging server uses `https://stage-sso.azion.com`.
- **Request another token**: OAuth tokens expire after a set period.
- **Check the client registration**: the client ID and secret must be correct, and the redirect URI must match the registered one exactly. The server advertises the scopes `openid`, `profile`, `email`, and `offline_access`.

The server accepts the token, and the client lists the tools.

---

## The staging server does not answer

A client pointed at `https://stage-mcp.azion.com` does not connect.

The staging server answers `401` without a token, like production, and needs a valid token. Its availability can differ from production.

- **Check the URL and the token**: use `https://stage-mcp.azion.com` with the `Authorization` header.
- **Use production for critical work**: point the client at `https://mcp.azion.com`.

The client connects to the server you chose.

---

## The local server does not answer on port 3333

`curl http://localhost:3333` fails with `curl: (7) Failed to connect to localhost port 3333`.

No local server is running. `azion dev` serves the server on port 3333, and it needs a linked and built project.

- **Link before you build**: `azion build` fails with `Azion configuration not found` until `azion link` links the project. Run `azion link` first.
- **Set the OpenAI key**: the server requires `OPENAI_API_KEY` in the `.env` file of the project.
- **Start the server again**: stop `azion dev` and run it again.

For the full order of the steps, refer to [Run the Azion MCP server locally](/en/documentation/guides/application-development/automation/run-azion-mcp-server-locally/).

`curl http://localhost:3333` reaches the local server instead of failing to connect.
