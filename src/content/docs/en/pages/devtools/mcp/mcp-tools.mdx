The [Azion MCP server](/en/documentation/devtools/mcp/) exposes tools and resources to a coding agent that connects with an Azion [personal token](/en/documentation/fundamentals/personal-tokens/), and no prompts. Every tool returns text, and no tool creates, changes, or deletes anything in your account.

---

## Tools

An account on the v4 API profile sees the eight tools in the table below. Each search tool returns one `text` item whose value is a JSON array of documents, and every document carries `title`, `content`, `source`, `similarity`, `search_type`, and `relevance_score`.

| Tool | Returns | Inputs |
| --- | --- | --- |
| `search_azion_docs_and_site` | Documents from the Azion documentation and website, for a question such as how to configure DDoS protection | `query` (string, required); `docsAmount` (number, optional, default `5`) |
| `search_azion_code_samples` | Code libraries and code samples, for a request such as Next.js deployment examples | `query` (string, required); `docsAmount` (number, optional, default `5`) |
| `search_azion_cli_commands` | Documents on the [Azion CLI](/en/documentation/devtools/cli/) commands and their usage, for a question such as which commands manage functions | `query` (string, required); `docsAmount` (number, optional, default `5`) |
| `search_azion_api_v4_commands` | Documents from the [Azion API](/en/documentation/devtools/api/) v4 reference, such as the OpenAPI fragment of an operation | `query` (string, required); `docsAmount` (number, optional, default `5`) |
| `search_azion_terraform` | Documents from the [Azion Terraform Provider](/en/documentation/devtools/terraform/) documentation, for a question such as how to create a Terraform resource | `query` (string, required); `docsAmount` (number, optional, default `5`) |
| `create_rules_engine` | A rule proposal for the Rules Engine of an [application](/en/documentation/platform/applications/rules-engine/) or a [firewall](/en/documentation/platform/firewall/rules-engine/), as JSON text with `criteria`, `behaviors`, `phase`, and `explanation` inside `data`; no rule is created | `useCase` (string, required): `edge_application`, `edge_firewall`, or `""`; `query` (string, optional) |
| `create_graphql_query` | A query for the [GraphQL API](/en/documentation/devtools/graphql/) that answers the goal in `query`; when no valid query results, the text says so and points to the GraphQL API documentation | `query` (string, required); `dataSource` (string, required): `real-time-metrics`, `real-time-events`, `accounting`, or `consumption` |
| `deploy_azion_static_site` | Guide text for deploying a static site and testing its cache; `help` lists the seven resources, `deploy` returns the four deployment steps, and `test-cache` returns the three cache-testing steps | `action` (string, optional): `deploy`, `test-cache`, or `help` |

Three inputs need more than the table holds:

- `docsAmount` sets how many documents a search tool returns. Send it only when you want a number other than five.
- `useCase` filters the documents `create_rules_engine` reads: `edge_application` for application rules and `edge_firewall` for firewall rules. The schema requires only `useCase`, but the tool builds the rule from `query`, so send the goal there too. For example, the goal `redirect requests for /old to /new with a 301` can return a rule whose criterion matches `${uri}` against `/old` and whose behavior is `Redirect_to_301`.
- `action` is a free string, not an enum. The tool documents `deploy`, `test-cache`, and `help` as its values.

`create_graphql_query` runs the queries it generates against the analytics GraphQL API of your account, with your token, to validate them. Those queries only read data.

## Static site resources

A client that supports MCP resources lists seven guides under `azion://static-site/deploy/` and `azion://static-site/test-cache/`, and reads each one with `resources/read`. Every resource is `text/markdown`, its name is its URI path joined with hyphens, as in `static-site-deploy-step-0-preparation`, and the server offers no resource templates.

| URI | Content |
| --- | --- |
| `azion://static-site/deploy/step-0-preparation` | Instructions to analyze the project structure, detect the framework and the package manager, and gather the deployment requirements |
| `azion://static-site/deploy/step-1-configuration` | Instructions to install the Azion CLI, authenticate, link the project, and test the build configuration |
| `azion://static-site/deploy/step-2-execute` | Instructions to deploy the project and verify the deployment status |
| `azion://static-site/deploy/step-3-basic-test` | Instructions to run basic tests of the deployment and its cache behavior |
| `azion://static-site/test-cache/step-0-preparation` | Instructions to analyze the cache configuration of the deployed site and prepare test scenarios |
| `azion://static-site/test-cache/step-1-execution` | Instructions to run cache tests for every static asset type and check the hit-miss ratios |
| `azion://static-site/test-cache/step-2-validation` | Instructions to validate the test results, calculate the rate of cache hits, and write a test report |

A client without resource support reaches the same guides through `deploy_azion_static_site`, with `action` set to `deploy` or `test-cache`.

## Prompts

The Azion MCP server exposes no prompts. Its `initialize` response declares no `prompts` capability, and a `prompts/list` request returns the JSON-RPC error `-32601` with the message `Method not found`.

---

## Tool set by API profile

The tools an account sees depend on its API profile. An account on the v3 API profile sees a ninth tool, `search_azion_api_v3_commands`, which searches the documentation of the Azion API v3.

An account on the v4 profile does not see that tool, and a `tools/call` request for it returns the JSON-RPC error `-32602` with this message:

```text
MCP error -32602: Tool search_azion_api_v3_commands not found
```

## Search tool call

The request below calls `search_azion_docs_and_site` with a query and two documents. It is a `POST` to `https://mcp.azion.com` with the headers `Authorization: Bearer [TOKEN VALUE]`, `Content-Type: application/json`, and `Accept: application/json, text/event-stream`, and this body:

```json
{
  "jsonrpc": "2.0",
  "method": "tools/call",
  "id": 1,
  "params": {
    "name": "search_azion_docs_and_site",
    "arguments": {
      "query": "how to configure cache",
      "docsAmount": 2
    }
  }
}
```

The server answers with status `200` and one server-sent event. Its data, decoded, is the result below, with the `text` value cut at `…`; the full value holds the two documents that `docsAmount` asks for:

```json
{
  "result": {
    "content": [
      {
        "type": "text",
        "text": "[\n  {\n    \"title\": \"application-acceleration\",\n    \"content\": \"Title: application-acceleration\\nDescription: Application Accelerator speeds up web applications and APIs through protocol optimizations and manages dynamic content requirements.\\nMetatag Keywords: Application Accelerator, Serveless, Edg…"
      }
    ]
  },
  "jsonrpc": "2.0",
  "id": 1
}
```
