You can run the Azion MCP server on your machine from its source code, to test changes, customize the server, or contribute to the project. The source is in the [aziontech/mcp-server](https://github.com/aziontech/mcp-server) repository. To connect a client to the hosted server at `https://mcp.azion.com` instead, refer to [MCP server quickstart](/en/documentation/devtools/mcp/configuration/).

---

## Prerequisites

- Node.js 20 or later.
- Yarn, the package manager the repository uses.
- Git.
- The [Azion CLI](/en/documentation/devtools/cli/), installed.
- An Azion personal token. To create one, refer to [Personal Tokens](/en/documentation/fundamentals/personal-tokens/).
- An OpenAI API key. The server needs it for its AI features.

---

## Set up the server

The CLI builds the project only after `azion link` connects it to your account, so link before you build.

To set up the server:

<DocSteps>
  <DocStep title="Clone the repository">

  ```bash
  git clone https://github.com/aziontech/mcp-server.git
  cd mcp-server
  ```

  The `mcp-server` folder holds the source code of the server.

  </DocStep>
  <DocStep title="Install the dependencies">

  ```bash
  yarn install
  ```

  Yarn prints warnings about unmet peer dependencies and deprecated APIs, then ends with a line such as:

  ```text
  Done in 23.61s
  ```

  </DocStep>
  <DocStep title="Create the environment file">

  Copy the sample file that the repository ships:

  ```bash
  cp .env.sample .env
  ```

  Open `.env` and set a value for each variable you need. `AZION_TOKEN` and `OPENAI_API_KEY` are required. For the full list, refer to [Environment variables](#environment-variables).

  </DocStep>
  <DocStep title="Link the project to your account">

  ```bash
  azion link
  ```

  The command asks a series of questions about the project. At the end, it offers to start a local development server and to deploy the project. To keep the server on your machine, answer `n` to the deploy question. For every option, refer to [Azion CLI link](/en/documentation/devtools/cli/link-command/).

  </DocStep>
  <DocStep title="Build the server">

  ```bash
  azion build
  ```

  The CLI builds the server with the settings in the repository's `azion.config.ts`.

  </DocStep>
</DocSteps>

The project is linked to your account and built, ready to run.

### Environment variables

The `.env.sample` file lists 11 variables. Set values only in your `.env` file, and never commit it.

| Variable | Required | Description |
| --- | --- | --- |
| `NODE_ENV` | No | Runtime environment: `production` or `development`. |
| `DEBUG` | No | Turns on debug logging: `true` or `false`. |
| `DATABASE_NAME` | No | Database name for local development. |
| `MCP_COPILOT_SERVER_TOKEN` | No | Fast Pass token for the Azion Copilot integration. A request that sends this token is served with the v3 API profile and the server's own `AZION_TOKEN`. |
| `MCP_BASE_URL` | No | Base URL of the MCP server. |
| `AZION_TOKEN` | Yes | An Azion personal token. |
| `OPENAI_API_KEY` | Yes | OpenAI API key for the AI features of the server. |
| `API_ORIGIN_URL` | No | Base URL of the internal API origin, which keeps API requests from looping through the CDN. |
| `SSO_ORIGIN_URL` | No | URL of the internal SSO origin. |
| `EDGE_AI_URL` | No | Endpoint URL of the AI service the server calls. |
| `EDGE_AI_TOKEN` | No | Token for that AI service. |

## Run the server

To start the server on your machine, run this command from the `mcp-server` folder:

```bash
azion dev
```

The server listens on `http://localhost:3333` while the command runs. To use another port, pass it with `--port`. For every option, refer to [Azion CLI dev](/en/documentation/devtools/cli/dev-command/).

## Connect a client

A client connects to the local server the same way it connects to the hosted one: with the local URL and your personal token in the `Authorization` header.

To add the local server to Claude Code, replace `[TOKEN VALUE]` with your personal token and run:

```bash
claude mcp add "azion-mcp-local" "http://localhost:3333" -t http -H "Authorization: Bearer [TOKEN VALUE]"
```

Claude Code adds the server under the name `azion-mcp-local`. For other clients, use the configuration in [MCP server quickstart](/en/documentation/devtools/mcp/configuration/) and replace `https://mcp.azion.com` with `http://localhost:3333`.

### Test the server with MCP Inspector

MCP Inspector connects to an MCP server to test its tools. To start it, run:

```bash
npx @modelcontextprotocol/inspector
```

To keep it installed, run `npm install -g @modelcontextprotocol/inspector` once.

To connect MCP Inspector to the local server:

<DocSteps>
  <DocStep title="Select the transport">

  Select _streamable-http_ as the transport type.

  </DocStep>
  <DocStep title="Enter the URL">

  Enter `http://localhost:3333`.

  </DocStep>
  <DocStep title="Add the authentication header">

  Add the header `Authorization: Bearer [TOKEN VALUE]`, with your personal token in place of `[TOKEN VALUE]`.

  </DocStep>
  <DocStep title="Select Connect" />
</DocSteps>

MCP Inspector lists the tools and resources of the server, and you can call each tool from it. For what each tool takes and returns, refer to [Tools and resources](/en/documentation/devtools/mcp/tools/).

## Change the server

The server starts at the root `index.ts`, which runs the application in `src/app.ts`. To add capabilities to the server:

| To add | Edit |
| --- | --- |
| A tool | `src/core/tools.ts` |
| A resource | `src/core/resources.ts` |
| The types a tool or a resource uses | `src/types/index.ts` |

Authentication is in `src/middlewares/auth.ts`, and the server setup is in `src/core/server.ts`.

## Fix common problems

### The build fails with Azion configuration not found

`azion build` fails when the project is not linked to your account yet:

```text
Error: Failed to build your resource. Azion configuration not found. Make sure you are in the root directory of your local repository and have already initialized or linked your resource with the commands 'azion init' or 'azion link'
```

Run `azion link` from the `mcp-server` folder, then run `azion build` again.

### The server does not start

- Run `node --version` and confirm that the version is 20 or later.
- Confirm that no other process uses port 3333, or start the server on another port with `--port`.
- Run `yarn install` again to restore missing dependencies.

### The client cannot authenticate

- Confirm that the personal token is valid. A personal token is `azion` followed by 35 letters and digits.
- Confirm that the header reads `Authorization: Bearer [TOKEN VALUE]`, with your token in place of `[TOKEN VALUE]`.
- Confirm that `.env` sets `AZION_TOKEN` and `OPENAI_API_KEY`.

For problems with the hosted server, refer to [Troubleshoot the MCP server](/en/documentation/devtools/mcp/troubleshooting/).
