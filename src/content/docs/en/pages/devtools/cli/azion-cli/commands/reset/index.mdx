The Azion CLI `reset` command returns the settings the CLI stores to their defaults and deletes your personal token when it can. Use it when the local configuration is inconsistent, or to start again from a clean configuration. The command affects only the CLI and does not change your projects. The options every command accepts, such as `--config` and `-y`, are on [Global options](/en/documentation/devtools/cli/globals/).

---

## Usage

`azion reset` empties the stored settings of the CLI configuration:

```bash
azion reset [flags]
```

The command takes no flags of its own. With the global `-c` option, it resets the configuration in the folder that holds the `.toml` path you pass.

:::caution
`azion reset` asks for no confirmation. It empties the stored token, client ID, and email, so a command that needs your account, such as `azion whoami`, fails until you log in again with [Azion CLI login](/en/documentation/devtools/cli/login/).
:::

---

## Examples

Each example shows the command and the output it prints.

### Reset the CLI settings

This command returns the CLI settings to their defaults:

```bash
azion reset
```

The command prints one line when the reset ends:

```text
Sucessfully reset to default settings
```

After the reset, every value in the CLI's `settings.toml` file is empty or zero:

```text
Token = ''
UUID = ''
LastCheck = 0001-01-01T00:00:00Z
LastVulcanVersion = ''
AuthorizeMetricsCollection = 0
ClientId = ''
Email = ''
ContinuationToken = ''
S3AccessKey = ''
S3SecretKey = ''
S3Bucket = ''
```

### Check the configuration after a reset

This command shows which account the CLI uses:

```bash
azion whoami
```

The reset sets `AuthorizeMetricsCollection` back to `0`, so the command first asks whether you agree to share anonymous usage data. It then fails, because no account is stored:

```text
🤔 To better understand user needs and enhance our application, we gather anonymous data. Do you agree to participate? (Y/n) Error: You must be logged in to use the 'whoami' command
```
