[Real-Time Events](/pt-br/documentacao/plataforma/real-time-events/) limita três coisas diferentes: por quanto tempo um registro é mantido, quanto uma consulta pode ler e retornar e quanto uso é cobrado da conta. Esta página indica cada limite, a resposta que uma consulta recebe além dele e o uso que está incluído antes de uma tarifa ser aplicada.

Um limite padrão e um valor incluído se comportam de maneiras diferentes. Azion verifica um limite padrão em toda consulta, e a consulta falha além dele. Um valor incluído é uma quantidade de cobrança, portanto passar dele muda o que é cobrado da conta, e não o que a consulta retorna.

---

## Retenção de eventos

Real-Time Events mantém um registro de evento por 168 horas, ou seja, 7 dias. A retenção é, portanto, o limite externo do período que uma consulta pode pedir, qualquer que seja a fonte de dados que ela lê. Um intervalo personalizado seleciona um intervalo de data e hora dentro dessas mesmas 168 horas.

[Activity History](/pt-br/documentacao/fundamentos/activity-history/) é a exceção. Sua fonte de dados mantém os registros por 2 anos, e a API GraphQL do Real-Time Events consulta esse período completo.

---

## Limites de consulta

Uma consulta carrega quatro limites próprios: as linhas que ela retorna, os campos que ela seleciona, o tamanho do seu payload e a taxa com que a API GraphQL aceita requisições. Um quinto limite se aplica dentro do banco de dados de logs, sobre as linhas que uma consulta lê antes de retornar qualquer coisa.

### Limites padrão

Cada linha nomeia o que é limitado, o limite e o que uma consulta além dele recebe. Para o corpo que uma resposta de erro carrega, consulte [Respostas de erro da API GraphQL](/pt-br/documentacao/devtools/graphql/mensagens-erro/).

| Escopo | Limite | Além do limite |
| --- | --- | --- |
| Linhas retornadas por consulta | 10.000 linhas | A API GraphQL retorna uma resposta de erro que nomeia o limite. |
| Campos selecionados por consulta | 37 campos | A API GraphQL retorna uma resposta de erro que nomeia o limite. |
| Requisições à API GraphQL | 120 por minuto | `429` |
| Linhas lidas dentro do banco de dados de logs | 10 bilhões de linhas | A consulta falha com `A query limit was exceeded. Try to refine your filter parameters or query a smaller period for a more precise search.` |

Os limites de linhas e de campos pertencem à própria API GraphQL e se aplicam a todos os datasets que ela serve. O campo `limit` de uma consulta define o número de linhas, até 10.000. Para os dois valores, consulte [Limites da API GraphQL](/pt-br/documentacao/devtools/graphql/limites/).

Outros dois valores se aplicam: o payload de uma consulta chega a 5 GB e um registro fica disponível para uma consulta até 30 segundos depois do evento que o produziu.

O limite de 10 bilhões de linhas é aplicado pelo banco de dados de logs, e não pela API GraphQL. Ele conta as linhas que uma consulta lê, não as linhas que a consulta retorna. Uma consulta sobre um período amplo e sem nenhum outro filtro pode alcançá-lo, e uma busca por todos os 7 dias de retenção é o caso comum. Para ficar dentro do limite, estreite o período ou adicione um filtro por host, endereço IP, código de status HTTP ou outro parâmetro da busca.

Azion pode aumentar esses limites padrão mediante solicitação, de acordo com o seu plano. Para solicitar um aumento, entre em contato com a equipe de [suporte técnico](/pt-br/documentacao/suporte/).

## Uso incluído

Real-Time Events é cobrado por duas métricas, Storage e Data Scan. As duas são medidas por GB por mês, e cada uma inclui um primeiro valor antes de uma tarifa ser aplicada.

| Métrica | Incluído |
| --- | --- |
| Storage | Primeiro 1 GB por mês |
| Data Scan | Primeiro 1 GB por mês |

Esses valores são quantidades de cobrança, e não limites aplicados a uma consulta. Uma consulta que passa de um deles retorna seus registros normalmente, e o uso além do valor incluído é cobrado.

Para a tarifa que se aplica além de um valor incluído, consulte [Preços](/pt-br/documentacao/fundamentos/precos/#real-time-events).
