O [Data Stream](/pt-br/documentacao/plataforma/data-stream/) aplica limites padrão à forma como um stream agrupa e entrega as linhas de log, aos campos de um stream e ao uso que cada plano inclui todo mês. A Azion pode aumentar um limite padrão de acordo com o seu plano. Para solicitar um aumento, entre em contato com a equipe de [suporte técnico](/pt-br/documentacao/suporte/).

---

## Limites padrão

Cada valor desta tabela se aplica a cada stream ou à conta que o contém. A API responde a uma requisição que ultrapassa o limite de um campo com `400` e um array `errors`, e não cria nada.

| Escopo | Limite | Além do limite |
| --- | --- | --- |
| Lote de linhas de log | 2.000 registros ou 60 segundos, o que ocorrer primeiro. Um registro é uma linha de log. Para *Standard HTTP/HTTPS POST*, o lote também fecha em **Payload Max Size**, em bytes. | O stream envia o lote para o endpoint. Um stream com pouco tráfego envia lotes pequenos: um lote observado de 2 linhas de log chegou ao endpoint 23 segundos depois do último evento. |
| Lote de linhas de log para *AWS Kinesis Data Firehose* | 500 registros ou 60 segundos, o que ocorrer primeiro | O stream envia o lote para o endpoint. |
| **Payload Max Size**, `outputs[0].attributes.max_size` em um endpoint `standard` | 1.000.000 bytes ou mais. O Console preenche `1000000`. | Um valor abaixo de `1000000` é recusado com `10050` `Min Value`. |
| Timeout de envio para um endpoint HTTP POST | 20 segundos | Quando o endpoint passa na verificação de disponibilidade, mas não recebe o lote em até 20 segundos, o envio termina com status `504`. |
| Verificação de disponibilidade do endpoint | Uma vez por minuto. Todos os servidores da Azion precisam informar que o endpoint está disponível. | Enquanto o endpoint está indisponível, o Data Stream não envia para ele e descarta os logs desse intervalo. O Real-Time Events registra a tentativa com status `503`. A verificação roda de novo no minuto seguinte. |
| Endpoints por stream | 1 | Uma segunda entrada em `outputs` é descartada sem erro. A API responde `201` e mantém a primeira entrada. |
| Streams ativos enquanto um deles usa sampling | 1 | Salvar um stream ativo com um item `sampling` desativa todos os outros streams da conta, sem erro na API. Uma taxa de `100` conta como sampling. O Console avisa antes de salvar. |
| `name` do stream | 1 a 100 caracteres | Um nome mais longo é recusado com `10046` `Max Length`. |
| Taxa de sampling, `transform[sampling].attributes.rate` | 1 a 100, uma porcentagem inteira | `0` é recusado com `10050` `Min Value`, e `101` com `10068` `Max Value`. |
| Filtro de workloads, `transform[filter_workloads].attributes.workloads` | 1 a 600 IDs de workload, cada um de um workload da conta | Uma lista fora desse intervalo é recusada. Um ID que não é de um workload da conta é recusado com `32003` `Workloads Not Belong Account`. |
| Workloads na conta, para o Azion Console | Menos de 3.000 | Com 3.000 workloads ou mais, o Console bloqueia os formulários de criação e edição, e a conta gerencia os streams apenas pela API. |

Uma mudança de estado ativo entra em vigor depois de um a dois minutos e, durante esse intervalo, o stream que estava ativo continua enviando. Para rodar vários streams ao mesmo tempo, dê a cada um deles um item `filter_workloads` em vez de sampling. Para os códigos de erro e as correções, consulte [Configurações do stream](/pt-br/documentacao/plataforma/data-stream/configuracoes-do-stream/#erros).

Outros limites se aplicam, sem consequência observada:

- A entrega dos logs para a sua infraestrutura leva até 3 minutos.
- Em um endpoint `standard`, `payload_format` aceita até 250 caracteres, `log_line_separator` até 100 e `max_size` até 2.147.483.647 bytes.
- O Console aceita até cinco **Custom Headers** em um endpoint *Standard HTTP/HTTPS POST*.
- O `data_set` de um template aceita até 65.535 caracteres, e o `name` até 100.
- O `stream_name` de um *AWS Kinesis Data Firehose* aceita até 64 caracteres.
- O `kafka_topic` e o `bootstrap_servers` de um *Apache Kafka*, e o `bucket_name` de um S3, aceitam até 150 caracteres cada.

Para os limites de cada campo de endpoint, consulte [Endpoints](/pt-br/documentacao/plataforma/data-stream/endpoints/).

## Uso incluído por plano

O Data Stream é cobrado por duas métricas: Requests e Data Transfer. Cada plano inclui as quantidades mensais abaixo.

| Métrica | Hobby | Pro | Enterprise |
| --- | --- | --- | --- |
| Requests | 1M / mês | 2M / mês | Personalizado |
| Data Transfer | 10 GB / mês | 20 GB / mês | Personalizado |

A comparação dos planos está em [Preços da Azion](https://www.azion.com/pt-br/precos/). Para os valores por unidade, consulte [Preços](/pt-br/documentacao/fundamentos/precos/#data-stream).

O [Real-Time Events](/pt-br/documentacao/plataforma/real-time-events/fontes-de-dados/#data-stream) registra cada envio de um stream com o número de linhas de log em `streamedLines` e o tamanho em bytes em `dataStreamed`. O tamanho de uma linha de log depende do template e do evento: um envio observado de 2 linhas de log de [Activity History](/pt-br/documentacao/fundamentos/activity-history/) levou 2.797 bytes. Para ler o consumo da conta, consulte o guia [Consulte dados de uso do Data Stream](/pt-br/documentacao/guias/plataforma/observabilidade/consultar-dados-de-uso-data-stream-com-graphql/).
