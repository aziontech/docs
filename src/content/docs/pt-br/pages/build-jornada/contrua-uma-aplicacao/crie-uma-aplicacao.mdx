Você pode habilitar os Produtos que uma [aplicação](/pt-br/documentacao/plataforma/applications/) executa pelo Azion Console, pela Azion CLI ou pela API. Cada Produto adiciona variáveis e behaviors que as regras da aplicação podem usar. Para criar a própria aplicação, na frente da sua origem, consulte [Primeiros passos com Applications](/pt-br/documentacao/plataforma/applications/primeiros-passos/).

Protocolos, portas e configurações de TLS pertencem ao [workload](/pt-br/documentacao/plataforma/workloads/) que serve a aplicação. O workload também carrega os domínios que chegam a ele.

## Habilite um Produto na aplicação

Uma aplicação nova executa Cache e Functions. Application Accelerator e Image Processor ficam desativados até que você os habilite. Azion Console rotula Cache como "Automatically enabled in all accounts."

Cada Produto muda o que as regras e as configurações da aplicação podem fazer:

- **Application Accelerator** adiciona a variável `${request_uri}` e outras opções do Rules Engine. Ele também permite que um cache setting varie por query string, cookies, device group e método de requisição. Um cache setting pode então receber um **Max Age** menor que 60 segundos. A transferência de dados pelo Application Accelerator pode gerar custos relacionados ao uso. Para mais informações, consulte [Configurações do Application Accelerator](/pt-br/documentacao/plataforma/applications/application-accelerator/configuracoes/) e [Preços](/pt-br/documentacao/fundamentos/precos/).
- **Image Processor** adiciona o behavior **Optimize Images**, que edita imagens à medida que a aplicação as entrega. Para mais informações, consulte [Primeiros passos com Image Processor](/pt-br/documentacao/plataforma/applications/image-processor/primeiros-passos/).
- **Functions** permite instanciar uma função na aplicação e executá-la com o behavior **Run Function**. Para mais informações, consulte [Instancie uma função em uma aplicação](/pt-br/documentacao/guias/desenvolvimento-de-aplicacoes/primeiros-passos/instanciar-functions/).

No Azion Console, uma opção do Rules Engine que precisa de um Produto carrega uma nota como `- Required Image Processor`.

<Tabs client:visible sharedStore="interface">

<Fragment slot="panel.console">

Para habilitar um Produto pelo Azion Console:

<DocSteps>
  <DocStep title="Abra a aplicação">

  Acesse [Azion Console](https://console.azion.com/) > **Applications** e selecione a sua aplicação.

  </DocStep>
  <DocStep title="Selecione a aba Main Settings" />
  <DocStep title="Ative o Produto">

  Em **Modules**, sob **Default Modules**, ative o Produto, como **Application Accelerator**.

  </DocStep>
  <DocStep title="Selecione Save" />
</DocSteps>

A aplicação executa o Produto, e as regras dela podem usar as variáveis e os behaviors que o Produto adiciona. A aba **Main Settings** também tem um grupo **Subscription modules**, com uma ação **Contact sales**.

</Fragment>

<Fragment slot="panel.cli">

Para habilitar Application Accelerator pela Azion CLI, execute `azion update application` com o ID da sua aplicação no lugar de `<application-id>`:

```bash
azion update application --application-id <application-id> --application-accelerator true
```

O comando confirma a atualização:

```text
Updated Application with ID <application-id>
```

O mesmo comando aceita `--image-processor true` para habilitar Image Processor e `--functions true` para habilitar Functions.

</Fragment>

<Fragment slot="panel.api">

Para habilitar Application Accelerator pela API, envie uma requisição `PATCH` à sua aplicação. O corpo nomeia o Produto dentro de `modules`:

```bash
curl --request PATCH \
  --url https://api.azion.com/v4/workspace/applications/<application-id> \
  --header 'Accept: application/json' \
  --header 'Authorization: Token [TOKEN VALUE]' \
  --header 'Content-Type: application/json' \
  --data '{
  "modules": {
    "application_accelerator": {
      "enabled": true
    }
  }
}'
```

A API responde `202` com `"state": "pending"` e retorna a aplicação. O objeto `modules` dela lista `cache`, `functions`, `application_accelerator` e `image_processor`, cada um com um valor `enabled`. Para habilitar Image Processor ou Functions, nomeie `image_processor` ou `functions` em `modules`.

</Fragment>

</Tabs>

## Leia os Produtos que uma aplicação executa

A aplicação informa os Produtos dela no Azion Console, na CLI e na API. Leia-os depois de uma atualização para confirmar quais Produtos estão habilitados.

<Tabs client:visible sharedStore="interface">

<Fragment slot="panel.console">

Abra a aba **Main Settings** da aplicação. Em **Modules**, o toggle de cada Produto habilitado está ativado.

</Fragment>

<Fragment slot="panel.cli">

Para ler a aplicação pela Azion CLI, execute `azion describe application`:

```bash
azion describe application --application-id <application-id>
```

A saída carrega um objeto `modules`. Uma aplicação que executa os quatro Produtos retorna:

```json
"modules": {
  "application_accelerator": { "enabled": true },
  "cache": { "enabled": true },
  "functions": { "enabled": true },
  "image_processor": { "enabled": true }
}
```

</Fragment>

<Fragment slot="panel.api">

Para ler a aplicação pela API, envie uma requisição `GET` a ela:

```bash
curl --request GET \
  --url https://api.azion.com/v4/workspace/applications/<application-id> \
  --header 'Accept: application/json' \
  --header 'Authorization: Token [TOKEN VALUE]'
```

A API responde `200` e retorna a aplicação com o objeto `modules` dela. Em uma aplicação nova, `cache` e `functions` informam `"enabled": true`, e `application_accelerator` e `image_processor` informam `"enabled": false`.

</Fragment>

</Tabs>
