Você cria um cache setting em uma aplicação pelo Azion Console, pela Azion API v4 ou pela Azion CLI, e o aplica às requisições com uma regra do [Rules Engine](/pt-br/documentacao/plataforma/applications/rules-engine/). Um setting carrega os TTLs e as regras de variação; enquanto uma regra não o nomear pelo behavior **Set Cache Policy**, ele não se aplica a nenhuma requisição.

Para um primeiro cache setting apenas pelo Console, consulte [Primeiros passos com Cache](/pt-br/documentacao/build/cache/primeiros-passos/). Para variar o cache por um argumento de query string ou por um cookie, consulte [Configure a Advanced Cache Key para uma aplicação](/pt-br/documentacao/guias/performance-e-confiabilidade/cache-e-purge/advanced-cache-key/).

---

## Pré-requisitos

- Uma aplicação. Para criar uma, consulte [Crie uma aplicação](/pt-br/documentacao/guias/desenvolvimento-de-aplicacoes/primeiros-passos/criar-uma-aplicacao/).
- Acesso ao Azion Console, para os procedimentos pelo Console. Consulte [Como acessar o Azion Console](/pt-br/documentacao/guias/plataforma/conta-e-billing/como-acessar-o-azion-console/).
- Um [personal token](/pt-br/documentacao/guias/plataforma/conta-e-billing/personal-tokens/), para os procedimentos pela API.
- A [Azion CLI](/pt-br/documentacao/devtools/cli/) instalada e autorizada, para os procedimentos pela CLI.
- O [Application Accelerator](/pt-br/documentacao/build/application-accelerator/) na aplicação, para um **Max Age** abaixo de 60 segundos ou para variação de cache.

## Crie o cache setting pelo Azion Console

O drawer **Create Cache Settings** carrega cada campo de um setting. Para criar um:

<DocSteps>
  <DocStep title="Abra a aplicação">

  Acesse [Azion Console](https://console.azion.com/) > **Applications** e selecione a aplicação.

  </DocStep>
  <DocStep title="Vá para a aba Cache Settings" />
  <DocStep title="Selecione + Cache" />
  <DocStep title="Nomeie o cache setting">

  Em **Name**, insira um nome único e descritivo.

  </DocStep>
  <DocStep title="Escolha o comportamento do browser cache">

  Em **Browser Cache**, selecione uma opção. _Honor cache policies_ repassa ao browser os headers `Cache-Control` e `Expires` da origem. _Override cache settings_ os substitui por um TTL que você insere. _No cache_ desativa o cache no browser, de modo que o conteúdo é sempre buscado no servidor.

  </DocStep>
  <DocStep title="Escolha o comportamento de cache">

  Em **Cache**, selecione _Honor cache policies_ para manter os headers da origem, ou _Override cache behavior_ para substituí-los.

  </DocStep>
  <DocStep title="Defina o Max Age">

  Em **Max Age**, insira os segundos que a Azion mantém uma cópia. Um setting novo carrega `60`.

  </DocStep>
  <DocStep title="Ative o Stale cache">

  Com o toggle ativo, a Azion entrega uma cópia expirada quando uma tentativa de revalidação com a origem falha.

  </DocStep>
  <DocStep title="Ative o Large file optimization">

  Com o toggle ativo, a Azion coloca um objeto grande em cache em fragmentos, e não como uma peça única.

  </DocStep>
  <DocStep title="Ative o Tiered Cache">

  O toggle adiciona uma segunda camada de cache entre o cache da Azion e a origem. Ele exige _Override cache behavior_ e um **Max Age** de pelo menos 3 segundos.

  </DocStep>
  <DocStep title="Selecione Save" />
</DocSteps>

O setting aparece na lista de **Cache Settings** com o seu **Name**, **ID**, **Browser Cache** e **Cache**. Para cada campo, com o seu tipo, o seu padrão e os seus limites, consulte [Cache settings](/pt-br/documentacao/build/cache/cache-settings/).

## Aplique o setting com uma regra

Uma regra na request phase decide quais requisições o setting cobre. Para criá-la:

<DocSteps>
  <DocStep title="Vá para a aba Rules Engine" />
  <DocStep title="Selecione + Rule" />
  <DocStep title="Nomeie a regra" />
  <DocStep title="Selecione Request Phase" />
  <DocStep title="Defina os criteria">

  Em **Criteria**, selecione `${uri}`, um operador e o argumento que casa os paths a colocar em cache.

  </DocStep>
  <DocStep title="Adicione o behavior Set Cache Policy">

  Em **Behaviors**, selecione **Set Cache Policy** e depois selecione o cache setting.

  </DocStep>
  <DocStep title="Selecione Save" />
</DocSteps>

A regra aparece na lista e aplica o setting a cada requisição que os seus criteria casam.

:::note[nota]
Uma regra nova pode levar alguns minutos para propagar. Aguarde antes de verificar o status de cache de uma resposta.
:::

## Crie o cache setting pela API

Duas requisições criam o setting e a regra que o aplica. Para enviá-las:

<DocSteps>
  <DocStep title="Crie o cache setting">

  ```bash
  curl --location --request POST 'https://api.azion.com/v4/workspace/applications/{application_id}/cache_settings' \
  --header 'Accept: application/json' \
  --header 'Content-Type: application/json' \
  --header 'Authorization: Token [TOKEN VALUE]' \
  --data '{
    "name": "static-assets",
    "browser_cache": { "behavior": "no-cache" },
    "modules": {
      "cache": {
        "behavior": "override",
        "max_age": 300,
        "stale_cache": { "enabled": true },
        "large_file_cache": { "enabled": true, "offset": 1024 },
        "tiered_cache": { "enabled": true, "topology": "nearest-region" }
      }
    }
  }'
  ```

  </DocStep>
  <DocStep title="Leia o id na resposta">

  A API responde com HTTP `201`, `state` igual a `executed` e o novo setting em `data`:

  ```json
  {"state":"executed","data":{"id":344164,"name":"static-assets","browser_cache":{"behavior":"no-cache","max_age":0},"modules":{"cache":{"behavior":"override","max_age":300,"stale_cache":{"enabled":true},"large_file_cache":{"enabled":true,"offset":1024},"tiered_cache":{"topology":"nearest-region","enabled":true}}},"created_at":"2026-09-17T17:38:27.577248Z"}}
  ```

  </DocStep>
  <DocStep title="Crie a regra que o aplica">

  Substitua `[CACHE SETTING ID]` pelo `id` que a resposta retornou:

  ```bash
  curl --location --request POST 'https://api.azion.com/v4/workspace/applications/{application_id}/request_rules' \
  --header 'Accept: application/json' \
  --header 'Content-Type: application/json' \
  --header 'Authorization: Token [TOKEN VALUE]' \
  --data '{
    "name": "apply-static-assets-cache",
    "criteria": [[{ "variable": "${uri}", "operator": "starts_with", "conditional": "if", "argument": "/static/" }]],
    "behaviors": [{ "type": "set_cache_policy", "attributes": { "value": "[CACHE SETTING ID]" } }]
  }'
  ```

  </DocStep>
  <DocStep title="Leia a resposta da regra">

  A API responde com HTTP `202` e a regra com `state` igual a `pending`, porque uma regra nova propaga antes de se aplicar:

  ```json
  {"state":"pending","data":{"id":710871,"name":"apply-static-assets-cache","active":true,"order":0}}
  ```

  </DocStep>
</DocSteps>

O setting agora se aplica a cada requisição cujo path começa com o argumento. Para listar os settings de uma aplicação, envie um `GET` para o mesmo path `cache_settings`.

## Crie o cache setting pela Azion CLI

A CLI cobre parte do objeto com flags, e o objeto inteiro com um arquivo JSON. Para criar um setting por flags:

<DocSteps>
  <DocStep title="Execute o comando de criação">

  ```bash
  azion create cache-setting \
  --application-id <application-id> \
  --name "product-listing" \
  --browser-cache-behavior override \
  --browser-cache-max-age 30 \
  --cache-by-query-string allowlist \
  --query-string-fields "category,page" \
  --cache-by-cookies allowlist \
  --cookie-names "session_id"
  ```

  </DocStep>
  <DocStep title="Leia o id na saída">

  ```text
  Created Cache Settings configuration with ID 344170
  ```

  </DocStep>
  <DocStep title="Leia o setting de volta">

  ```bash
  azion describe cache-setting --application-id <application-id> --cache-setting-id 344170 --format json
  ```

  O objeto carrega o browser cache e os campos de variação que as flags definiram, e o `modules.cache` nos seus padrões: `honor` e `60`.

  </DocStep>
</DocSteps>

Para criar um setting com os campos que as flags não cobrem, envie o corpo da requisição a partir de um arquivo:

<DocSteps>
  <DocStep title="Escreva o corpo em um arquivo">

  Salve o corpo da requisição da API acima como `cache-setting.json`.

  </DocStep>
  <DocStep title="Crie o setting a partir do arquivo">

  ```bash
  azion create cache-setting --application-id <application-id> --file cache-setting.json
  ```

  O comando imprime o id do novo setting:

  ```text
  Created Cache Settings configuration with ID 344171
  ```

  </DocStep>
</DocSteps>

:::note[nota]
As flags da CLI não definem o **Max Age**, o comportamento de cache, o stale cache, o Large File Optimization nem o Tiered Cache. Use o `--file` com o corpo da requisição para esses campos.
:::

A CLI não cria a regra que aplica o setting. Crie-a pelo Console ou pela API, com qualquer um dos procedimentos desta página. Para cada flag, consulte [Azion CLI create](/pt-br/documentacao/devtools/cli/create/).
