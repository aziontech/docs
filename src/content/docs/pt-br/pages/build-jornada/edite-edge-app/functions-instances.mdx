Você pode criar uma instância de função em uma aplicação pelo Azion Console ou pela Azion API. A instância vincula uma função a uma aplicação e carrega os Args passados para o contexto de execução.

Uma instância sem uma regra do Rules Engine nunca é executada. A regra seleciona a instância com o comportamento **Run Function** e define os critérios que a acionam. Para adicionar essa regra, consulte [Execute uma função em uma aplicação](/pt-br/documentacao/guias/desenvolvimento-de-aplicacoes/functions-e-runtime/funcoes-serverless/).

Para criar o mesmo objeto em um firewall, consulte [Instancie uma função em um firewall](/pt-br/documentacao/guias/seguranca-de-aplicacoes/firewall-e-waf/instanciar-functions/).

---

## Pré-requisitos

- Uma aplicação. Para criar uma, consulte [Criar uma aplicação](/pt-br/documentacao/guias/desenvolvimento-de-aplicacoes/primeiros-passos/criar-uma-aplicacao/).
- Uma função na conta. Use uma do [Azion Marketplace](/pt-br/documentacao/marketplace/) ou escreva a sua, como em [Primeiros passos com Functions](/pt-br/documentacao/build/functions/primeiros-passos/).
- Um [personal token](/pt-br/documentacao/guias/plataforma/conta-e-billing/personal-tokens/), para o caminho pela API.

:::caution[Atenção]
Tempo de computação e invocações de funções geram custos relacionados ao uso. Para as taxas, consulte [Preços](/pt-br/documentacao/fundamentos/precos/).
:::

## Crie a instância de função

Uma aplicação executa uma função por meio de uma instância, e uma mesma função pode sustentar várias instâncias. Cada caminho ativa o módulo **Functions** na aplicação e então cria a instância:

<Tabs client:visible>
    <Fragment slot="tab.console">Console</Fragment>
    <Fragment slot="tab.api">API</Fragment>

<Fragment slot="panel.console">

Para criar a instância pelo Azion Console:

<DocSteps>
  <DocStep title="Abra a aplicação">

  Acesse [Azion Console](https://console.azion.com/) > **Applications** > **sua aplicação**.

  </DocStep>
  <DocStep title="Na aba Main Settings, ative o módulo Functions" />
  <DocStep title="Selecione Save" />
  <DocStep title="Vá para a aba Functions Instances" />
  <DocStep title="Selecione + Function Instance" />
  <DocStep title="Nomeie a instância">

  Digite um nome para a instância. Por exemplo: `hello-world instance`.

  </DocStep>
  <DocStep title="Selecione a função">

  Selecione a função que a instância executa. Por exemplo, a função pré-configurada *Azion - Hello World*.

  </DocStep>
  <DocStep title="Digite os Args">

  (Opcional) Na aba **Args**, digite os argumentos da instância em JSON.

  </DocStep>
  <DocStep title="Selecione Save" />
</DocSteps>

A instância aparece na aba **Functions Instances**. Ela não é executada até que uma regra do Rules Engine a selecione.

</Fragment>

<Fragment slot="panel.api">

Para criar a instância pela Azion API, envie três requisições. A primeira ativa o módulo **Functions**, a segunda lê o ID da função e a terceira cria a instância.

Envie uma requisição `PATCH` para a aplicação, substituindo `[TOKEN VALUE]` pelo seu [personal token](/pt-br/documentacao/guias/plataforma/conta-e-billing/personal-tokens/) e `<application_id>` pelo [ID da sua aplicação](/pt-br/documentacao/guias/desenvolvimento-de-aplicacoes/primeiros-passos/definir-configuracoes-principais/):

<Code lang="bash" code={`curl --request PATCH \\
  --url https://api.azion.com/v4/edge_application/applications/<application_id> \\
  --header 'Accept: application/json' \\
  --header 'Authorization: Token [TOKEN VALUE]' \\
  --header 'Content-Type: application/json' \\
  --data '{
  "modules": {
    "edge_functions": {
      "enabled": true
    }
  }
}'`} />

A resposta retorna o valor atualizado.

Envie uma requisição `GET` para o endpoint de functions:

<Code lang="bash" code={`curl --request GET \\
  --url https://api.azion.com/v4/edge_functions/functions \\
  --header 'Accept: application/json' \\
  --header 'Authorization: Token [TOKEN VALUE]'`} />

A resposta lista as funções da conta. Copie o `id` da função que você quer instanciar:

```json
{
  "count": 1,
  "results": [
    {
      "id": <function_id>,
      "name": "My Function",
      "last_editor": "your-email@example.com",
      "last_modified": "2025-08-14T16:37:54.966088Z",
      "product_version": "2.0",
      "active": true,
      "runtime": "azion_js",
      "execution_environment": "application",
      "code": "",
      "default_args": {},
      "reference_count": 0,
      "version": "-",
      "vendor": null
    }
  ]
}
```

Envie uma requisição `POST` para o recurso functions da aplicação, substituindo `<function_id>` pelo ID que você copiou:

<Code lang="bash" code={`curl --request POST \\
  --url https://api.azion.com/v4/edge_application/applications/<application_id>/functions \\
  --header 'Accept: application/json' \\
  --header 'Authorization: Token [TOKEN VALUE]' \\
  --header 'Content-Type: application/json' \\
  --data '{
  "name": "My instance Name",
  "edge_function": <function_id>,
  "args": {},
  "active": true
}'`} />

A resposta retorna a instância que a aplicação agora carrega:

```json
{
  "state": "pending",
  "data": {
    "id": <edge_function_instance_id>,
    "name": "My Function Instance",
    "args": {},
    "edge_function": 123456,
    "active": true,
    "last_editor": "your-email@example.com",
    "last_modified": "2025-08-14T16:41:56.699896Z"
  }
}
```

| Chave | Descrição |
| --- | --- |
| `id` | O ID da instância de função |
| `name` | O nome da instância de função |
| `edge_function` | O ID da função que a instância executa. Ele difere de `id`, que é único para cada instância |
| `args` | Os argumentos passados para o contexto de execução da função. Algumas funções não recebem argumentos |

O valor `"state": "pending"` indica que a alteração leva alguns minutos para propagar antes de entrar em vigor. A instância não é executada até que uma regra do Rules Engine a selecione.

:::tip[dica]
Para cada endpoint e seus campos, consulte a [documentação da Azion API](https://api.azion.com/) e a [especificação OpenAPI](https://github.com/aziontech/azionapi-openapi/).
:::

## Args da instância

Args são os argumentos que uma instância passa para o contexto de execução da função, escritos como um objeto JSON. O código da função não pode ser alterado na instanciação, então os Args são o que faz uma mesma função se comportar de forma diferente em cada aplicação que a instancia. Um objeto Args que define uma chave:

```json
{
  "value": "hello_world"
}
```

O código lê a chave em tempo de execução e a instância decide o valor dela. Uma função pode definir Args padrão próprios, e os Args de uma instância substituem as chaves que repetem. O objeto Args comporta no máximo 100 KB, e um objeto acima desse teto faz a função falhar na instanciação. Valores sensíveis como chaves de API, credenciais e tokens de acesso pertencem às [variáveis de ambiente](/pt-br/documentacao/build/functions/environment-variables/).

Para os valores padrão e as regras de substituição, consulte [Como Functions funciona](/pt-br/documentacao/build/functions/como-funciona/). Para cada campo do objeto de instância, consulte [Instâncias de função](/pt-br/documentacao/build/functions/functions-instances/).
