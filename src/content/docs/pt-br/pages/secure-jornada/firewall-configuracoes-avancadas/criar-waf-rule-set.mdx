Crie um rule set do [Web Application Firewall (WAF)](/pt-br/documentacao/secure/waf/) e aplique-o a um firewall com uma regra do Rules Engine. As duas tarefas rodam a partir do Azion Console, da Azion CLI ou da API.

Para uma primeira execução que termina em uma requisição bloqueada, consulte [Primeiros passos com WAF](/pt-br/documentacao/secure/waf/primeiros-passos/). Aquela página fixa cada opção do caminho. Esta as deixa em aberto: você escolhe as famílias de ameaças, a sensibilidade de cada uma e o modo.

## Pré-requisitos

- Uma conta Azion. Para criar uma, consulte [Como criar uma conta na Azion](/pt-br/documentacao/fundamentos/criar-uma-conta/).

- Um workload vinculado a esse firewall, para que a regra que você criar receba tráfego. Consulte [Proteja seu domínio](/pt-br/documentacao/guias/seguranca-de-aplicacoes/firewall-e-waf/proteja-seu-dominio/).

## Crie o rule set

Um rule set carrega até oito famílias de ameaças, e cada família tem a sua própria sensibilidade. A sensibilidade fixa o score que uma requisição precisa alcançar para que essa família a bloqueie. Toda família começa em `medium`. Uma sensibilidade maior bloqueia em um score menor: ela pega ataques que carregam menos evidência e, junto com eles, recusa mais tráfego legítimo. Para o que cada família detecta e o que cada nível custa, consulte [WAF Rule Sets](/pt-br/documentacao/secure/waf/rule-sets/).

<Tabs client:visible sharedStore="interface">

<Fragment slot="panel.console">

O formulário lista as oito famílias, então toda sensibilidade é definida em um só lugar. Para criar o rule set no Azion Console:

<DocSteps>
  <DocStep title="Abra a página WAF Rules">

  Acesse o [Azion Console](https://console.azion.com/) > **Edge Libraries** > **WAF Rules**.

  </DocStep>
  <DocStep title="Selecione + WAF Rule" />
  <DocStep title="Nomeie o rule set">

  Na seção **General**, informe um **Name**. Por exemplo: `checkout-waf`.

  </DocStep>
  <DocStep title="Defina a sensibilidade de cada família de ameaças">

  A seção **Threat Type Configuration** lista oito famílias, cada uma abrindo em _Sensitivity Medium_. Por exemplo, defina **SQL Injection** como _Sensitivity High_.

  </DocStep>
  <DocStep title="Habilite o switch Active" />
  <DocStep title="Salve o rule set" />
</DocSteps>

O rule set aparece em **WAF Rules**, com o seu **Threat Type Configuration** e o seu **Status**. Ele não pontua nada enquanto uma regra do Rules Engine não o nomear.

</Fragment>

<Fragment slot="panel.cli">

O `--thresholds` recebe pares `threat=sensitivity` separados por vírgula. Uma criação que omite a flag carrega as oito famílias em `medium`. Para criar o rule set com a Azion CLI:

<DocSteps>
  <DocStep title="Execute o comando de criação">

  ```bash
  azion create waf --name "checkout-waf" --active true --rulesets 1 \
    --thresholds "sql_injection=medium,cross_site_scripting=medium,directory_traversal=medium,evading_tricks=medium,file_upload=medium,identified_attack=medium,remote_file_inclusion=medium,unwanted_access=medium"
  ```

  </DocStep>
  <DocStep title="Leia a saída">

  O comando imprime o id do rule set:

  ```text
  Created WAF with ID 21718
  ```

  </DocStep>
</DocSteps>

O rule set está ativo e roda no ruleset `1`. Anote o id: a regra da próxima seção o nomeia.

</Fragment>

<Fragment slot="panel.api">

Cada entrada de `thresholds` nomeia uma família de ameaças e a sensibilidade que ela carrega. Para criar o rule set:

<DocSteps>
  <DocStep title="Envie a requisição de criação">

  Substitua `[TOKEN VALUE]` pelo seu personal token:

  ```bash
  curl --request POST \
    --url https://api.azion.com/v4/workspace/wafs \
    --header 'Accept: application/json' \
    --header 'Authorization: Token [TOKEN VALUE]' \
    --header 'Content-Type: application/json' \
    --data '{
    "name": "checkout-waf",
    "active": true,
    "product_version": "1.0",
    "engine_settings": {
      "engine_version": "2021-Q3",
      "type": "score",
      "attributes": {
        "rulesets": [1],
        "thresholds": [
          { "threat": "cross_site_scripting", "sensitivity": "medium" },
          { "threat": "directory_traversal", "sensitivity": "medium" },
          { "threat": "evading_tricks", "sensitivity": "medium" },
          { "threat": "file_upload", "sensitivity": "medium" },
          { "threat": "identified_attack", "sensitivity": "medium" },
          { "threat": "remote_file_inclusion", "sensitivity": "medium" },
          { "threat": "sql_injection", "sensitivity": "medium" },
          { "threat": "unwanted_access", "sensitivity": "medium" }
        ]
      }
    }
  }'
  ```

  </DocStep>
  <DocStep title="Leia a resposta">

  O status é `202`, e `"state": "pending"` diz que a Azion aceitou o rule set e ainda está propagando-o:

  ```json
  {
    "state": "pending",
    "data": {
      "id": 21717,
      "active": true,
      "name": "checkout-waf",
      "last_editor": "user@example.com",
      "last_modified": "2026-09-20T15:42:56.755684Z",
      "product_version": "1.0",
      "engine_settings": {
        "engine_version": "2021-Q3",
        "type": "score",
        "attributes": {
          "rulesets": [1],
          "thresholds": [
            { "threat": "cross_site_scripting", "sensitivity": "medium" },
            { "threat": "directory_traversal", "sensitivity": "medium" },
            { "threat": "evading_tricks", "sensitivity": "medium" },
            { "threat": "file_upload", "sensitivity": "medium" },
            { "threat": "identified_attack", "sensitivity": "medium" },
            { "threat": "remote_file_inclusion", "sensitivity": "medium" },
            { "threat": "sql_injection", "sensitivity": "medium" },
            { "threat": "unwanted_access", "sensitivity": "medium" }
          ]
        }
      },
      "version_id": null,
      "version_state": null,
      "is_versioned": false,
      "version": null
    }
  }
  ```

  </DocStep>
</DocSteps>

Anote o `id`. A regra da próxima seção o nomeia.

:::note[nota]
Um array `thresholds` com menos de oito entradas é aceito. O rule set então carrega apenas as famílias que você enviou. Um `threat` repetido não é aceito: ele responde `500` com `10067 Internal Server Error`.
:::

## Aplique o rule set a um firewall

Uma regra do [Rules Engine for Firewall](/pt-br/documentacao/plataforma/firewall/rules-engine/) seleciona requisições pelos seus próprios critérios e executa behaviors sobre elas. O behavior `Set WAF` nomeia um rule set e um modo. Uma regra carrega no máximo um behavior `Set WAF`.

O modo pertence ao behavior, e não ao rule set, e é obrigatório. O `Logging` pontua uma requisição, registra-a e a entrega. O `Blocking` recusa uma requisição cujo score alcança um limiar da sua família. Para a ordem em que passar de um para o outro, consulte [Boas práticas de WAF](/pt-br/documentacao/secure/waf/boas-praticas/).

:::caution[Atenção]
Um critério baseado em `${request_args}` corresponde apenas a uma requisição que carrega uma query string. Todo `POST` que mantém o seu payload no body passa então sem ser pontuado. Baseie o critério em `${request_uri}`.
:::

<Tabs client:visible sharedStore="interface">

<Fragment slot="panel.console">

Para aplicar o rule set no Azion Console:

<DocSteps>
  <DocStep title="Abra o firewall">

  Acesse o [Azion Console](https://console.azion.com/) > **Firewalls** e selecione o firewall vinculado ao seu workload.

  </DocStep>
  <DocStep title="Selecione a aba Rules Engine" />
  <DocStep title="Selecione + Rule" />
  <DocStep title="Nomeie a regra">

  Informe um nome para a regra. Por exemplo: `Apply checkout-waf`.

  </DocStep>
  <DocStep title="Defina o critério">

  Na seção **Criteria**, selecione a variável `Request URI`, o operador _starts with_ e `/` como argumento.

  </DocStep>
  <DocStep title="Adicione o behavior Set WAF">

  Na seção **Behaviors**, selecione **Set WAF** e então selecione `checkout-waf` como o rule set.

  </DocStep>
  <DocStep title="Defina o modo como Blocking" />
  <DocStep title="Salve a regra" />
</DocSteps>

O firewall pontua contra o rule set todas as requisições que recebe.

</Fragment>

<Fragment slot="panel.cli">

O `azion create firewall-rule` recebe apenas `--firewall-id` e `--file`, então o behavior e o modo viajam no JSON. Para aplicar o rule set com a Azion CLI:

<DocSteps>
  <DocStep title="Escreva a regra em um arquivo">

  Salve o seguinte como `fw-rule.json`, com o id do seu rule set em `waf_id`:

  ```json
  {
    "name": "Apply checkout-waf",
    "active": true,
    "description": "",
    "criteria": [
      [
        {
          "conditional": "if",
          "variable": "${request_uri}",
          "operator": "starts_with",
          "argument": "/"
        }
      ]
    ],
    "behaviors": [
      {
        "type": "set_waf",
        "attributes": {
          "waf_id": 21718,
          "mode": "blocking"
        }
      }
    ]
  }
  ```

  </DocStep>
  <DocStep title="Crie a regra">

  Substitua `<firewall-id>` pelo id do seu firewall:

  ```bash
  azion create firewall-rule --firewall-id <firewall-id> --file fw-rule.json
  ```

  </DocStep>
  <DocStep title="Leia a saída">

  O comando imprime o id da regra:

  ```text
  Created Firewall Rule with ID 131733
  ```

  </DocStep>
</DocSteps>

O firewall pontua contra o rule set todas as requisições que recebe.

</Fragment>

<Fragment slot="panel.api">

O shell expande `${request_uri}`, então o body viaja em um arquivo, e não inline. Para aplicar o rule set:

<DocSteps>
  <DocStep title="Escreva a regra em um arquivo">

  Salve o seguinte como `rule.json`, com o id do seu rule set em `waf_id`:

  ```json
  {
    "name": "Apply checkout-waf",
    "active": true,
    "criteria": [
      [
        {
          "conditional": "if",
          "variable": "${request_uri}",
          "operator": "starts_with",
          "argument": "/"
        }
      ]
    ],
    "behaviors": [
      {
        "type": "set_waf",
        "attributes": {
          "waf_id": 21717,
          "mode": "blocking"
        }
      }
    ]
  }
  ```

  </DocStep>
  <DocStep title="Envie a requisição de criação">

  Substitua `<firewall-id>` pelo id do seu firewall:

  ```bash
  curl --request POST \
    --url https://api.azion.com/v4/workspace/firewalls/<firewall-id>/request_rules \
    --header 'Accept: application/json' \
    --header 'Authorization: Token [TOKEN VALUE]' \
    --header 'Content-Type: application/json' \
    --data @rule.json
  ```

  </DocStep>
  <DocStep title="Leia a resposta">

  O `202` ecoa a regra e acrescenta dois campos que a API atribui, `description` e `order`:

  ```json
  {
    "state": "pending",
    "data": {
      "id": 131732,
      "name": "Apply checkout-waf",
      "last_editor": "user@example.com",
      "last_modified": "2026-09-20T15:53:29.020679Z",
      "created_at": "2026-09-20T15:53:29.020695Z",
      "active": true,
      "criteria": [
        [
          {
            "conditional": "if",
            "variable": "${request_uri}",
            "operator": "starts_with",
            "argument": "/"
          }
        ]
      ],
      "behaviors": [
        {
          "type": "set_waf",
          "attributes": {
            "waf_id": 21717,
            "mode": "blocking"
          }
        }
      ],
      "description": "",
      "order": 1
    }
  }
  ```

  </DocStep>
</DocSteps>

O firewall pontua contra o rule set todas as requisições que recebe.

Um body que omite `mode` é recusado com `400`:

```json
{"errors":[{"code":"10059","title":"Required Field","detail":"This field is required.","status":"400","source":{"pointer":"/data/behaviors/0/attributes/mode"}}]}
```

O campo aceita `logging` ou `blocking`. Qualquer outro valor responde `400` com `10039 Invalid Choice`.

</Fragment>

</Tabs>

Uma nova regra leva alguns minutos para alcançar a infraestrutura distribuída da Azion. Até que isso aconteça, uma requisição ainda pode ser respondida como era antes de a regra existir.
