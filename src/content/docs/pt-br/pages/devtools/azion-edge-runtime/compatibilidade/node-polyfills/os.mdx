O módulo `node:os` fornece funções e propriedades utilitárias do sistema operacional, como descreve a [documentação do os do Node.js](https://nodejs.org/api/os.html). No Azion Runtime, o build aceita `import os from "node:os"`, e todos os membros listados abaixo funcionam sem lançar erros, em uma function com deploy feito e com `azion dev`.

Os valores são os mesmos nos dois ambientes e, por isso, não identificam a máquina que executa o seu código. `os.platform()` retorna `linux` e `os.type()` retorna `Linux`. `os.homedir()` retorna `/`, `os.tmpdir()` retorna `/tmp`, `os.endianness()` retorna `LE` e `os.EOL` é `\n`. `os.arch()`, `os.release()`, `os.hostname()`, `os.machine()` e `os.version()` retornam uma string vazia, e `os.totalmem()`, `os.freemem()` e `os.uptime()` retornam `0`. `os.availableParallelism()` retorna `8`, `os.cpus()` retorna 8 entradas e `os.networkInterfaces()` lista uma interface, `lo0`.

## Exemplo

A function abaixo lê o nome da plataforma, registra esse nome em log e o retorna no corpo da resposta:

```javascript
/**
 * An example of using the Node.js OS API in an Azion Function.
 * @example
 * // Build and run locally with the Azion CLI:
 * azion build
 * azion dev
 */
import os from "node:os";

/**
 * An example of using the Node.js OS API in an Azion Function.
 * @param {*} event
 * @returns Promise<Response>
 */
const main = async (event) => {
  return new Promise((resolve, reject) => {
    const platform = os.platform();
    console.log("Platform", platform);
    resolve(new Response(`platform: ${platform}`));
  });
};

export default main;
```

A function registra `Platform linux` em log e responde com este corpo:

```text
platform: linux
```
