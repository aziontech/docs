Você pode executar o MCP server da Azion na sua máquina a partir do código-fonte, para testar alterações, personalizar o servidor ou contribuir com o projeto. O código-fonte fica no repositório [aziontech/mcp-server](https://github.com/aziontech/mcp-server). Para conectar um cliente ao servidor hospedado em `https://mcp.azion.com`, consulte [Primeiros passos com o MCP server](/pt-br/documentacao/devtools/mcp/configuracao/).

---

## Pré-requisitos

- Node.js 20 ou posterior.
- Yarn, o gerenciador de pacotes que o repositório usa.
- Git.
- A [Azion CLI](/pt-br/documentacao/devtools/cli/), instalada.
- Um personal token da Azion. Para criar um, consulte [Tokens pessoais](/pt-br/documentacao/fundamentos/personal-tokens/).
- Uma chave de API da OpenAI. O servidor precisa dela para as funcionalidades de IA.

---

## Configure o servidor

A CLI só faz o build do projeto depois que `azion link` conecta o projeto à sua conta. Por isso, vincule o projeto antes de fazer o build.

Para configurar o servidor:

<DocSteps>
  <DocStep title="Clone o repositório">

  ```bash
  git clone https://github.com/aziontech/mcp-server.git
  cd mcp-server
  ```

  A pasta `mcp-server` contém o código-fonte do servidor.

  </DocStep>
  <DocStep title="Instale as dependências">

  ```bash
  yarn install
  ```

  O Yarn exibe avisos sobre dependências peer não atendidas e APIs obsoletas e termina com uma linha como esta:

  ```text
  Done in 23.61s
  ```

  </DocStep>
  <DocStep title="Crie o arquivo de ambiente">

  Copie o arquivo de exemplo que o repositório inclui:

  ```bash
  cp .env.sample .env
  ```

  Abra `.env` e defina um valor para cada variável de que você precisa. `AZION_TOKEN` e `OPENAI_API_KEY` são obrigatórias. Para a lista completa, consulte [Variáveis de ambiente](#variaveis-de-ambiente).

  </DocStep>
  <DocStep title="Vincule o projeto à sua conta">

  ```bash
  azion link
  ```

  O comando faz uma série de perguntas sobre o projeto. No final, ele pergunta se você quer iniciar um servidor de desenvolvimento local e fazer o deploy do projeto. Para manter o servidor na sua máquina, responda `n` à pergunta do deploy. Para todas as opções, consulte [Azion CLI link](/pt-br/documentacao/devtools/cli/link-comando/).

  </DocStep>
  <DocStep title="Faça o build do servidor">

  ```bash
  azion build
  ```

  A CLI faz o build do servidor com as configurações do arquivo `azion.config.ts` do repositório.

  </DocStep>
</DocSteps>

O projeto está vinculado à sua conta e com o build pronto para ser executado.

### Variáveis de ambiente

O arquivo `.env.sample` lista 11 variáveis. Defina valores apenas no seu arquivo `.env` e nunca faça commit dele.

| Variável | Obrigatória | Descrição |
| --- | --- | --- |
| `NODE_ENV` | Não | Ambiente de execução: `production` ou `development`. |
| `DEBUG` | Não | Ativa os logs de depuração: `true` ou `false`. |
| `DATABASE_NAME` | Não | Nome do banco de dados para o desenvolvimento local. |
| `MCP_COPILOT_SERVER_TOKEN` | Não | Token Fast Pass para a integração com o Azion Copilot. Uma requisição que envia esse token é atendida com o perfil de API v3 e com o `AZION_TOKEN` do próprio servidor. |
| `MCP_BASE_URL` | Não | URL base do MCP server. |
| `AZION_TOKEN` | Sim | Um personal token da Azion. |
| `OPENAI_API_KEY` | Sim | Chave de API da OpenAI para as funcionalidades de IA do servidor. |
| `API_ORIGIN_URL` | Não | URL base da origem interna da API, que evita que as requisições à API passem em loop pela CDN. |
| `SSO_ORIGIN_URL` | Não | URL da origem interna de SSO. |
| `EDGE_AI_URL` | Não | URL do endpoint do serviço de IA que o servidor chama. |
| `EDGE_AI_TOKEN` | Não | Token desse serviço de IA. |

## Execute o servidor

Para iniciar o servidor na sua máquina, execute este comando na pasta `mcp-server`:

```bash
azion dev
```

O servidor escuta em `http://localhost:3333` enquanto o comando está em execução. Para usar outra porta, informe-a com `--port`. Para todas as opções, consulte [Azion CLI dev](/pt-br/documentacao/devtools/cli/dev-comando/).

## Conecte um cliente

Um cliente se conecta ao servidor local da mesma forma que se conecta ao servidor hospedado: com a URL local e o seu personal token no header `Authorization`.

Para adicionar o servidor local ao Claude Code, substitua `[TOKEN VALUE]` pelo seu personal token e execute:

```bash
claude mcp add "azion-mcp-local" "http://localhost:3333" -t http -H "Authorization: Bearer [TOKEN VALUE]"
```

O Claude Code adiciona o servidor com o nome `azion-mcp-local`. Para outros clientes, use a configuração de [Primeiros passos com o MCP server](/pt-br/documentacao/devtools/mcp/configuracao/) e substitua `https://mcp.azion.com` por `http://localhost:3333`.

### Teste o servidor com o MCP Inspector

O MCP Inspector se conecta a um MCP server para testar as ferramentas dele. Para iniciá-lo, execute:

```bash
npx @modelcontextprotocol/inspector
```

Para mantê-lo instalado, execute `npm install -g @modelcontextprotocol/inspector` uma vez.

Para conectar o MCP Inspector ao servidor local:

<DocSteps>
  <DocStep title="Selecione o transporte">

  Selecione _streamable-http_ como tipo de transporte.

  </DocStep>
  <DocStep title="Insira a URL">

  Insira `http://localhost:3333`.

  </DocStep>
  <DocStep title="Adicione o header de autenticação">

  Adicione o header `Authorization: Bearer [TOKEN VALUE]`, com o seu personal token no lugar de `[TOKEN VALUE]`.

  </DocStep>
  <DocStep title="Selecione Connect" />
</DocSteps>

O MCP Inspector lista as ferramentas e os recursos do servidor, e você pode chamar cada ferramenta a partir dele. Para saber o que cada ferramenta recebe e retorna, consulte [Ferramentas e recursos](/pt-br/documentacao/devtools/mcp/ferramentas/).

## Altere o servidor

O servidor começa no arquivo `index.ts` da raiz, que executa a aplicação em `src/app.ts`. Para adicionar funcionalidades ao servidor:

| Para adicionar | Edite |
| --- | --- |
| Uma ferramenta | `src/core/tools.ts` |
| Um recurso | `src/core/resources.ts` |
| Os tipos que uma ferramenta ou um recurso usa | `src/types/index.ts` |

A autenticação fica em `src/middlewares/auth.ts`, e a configuração do servidor fica em `src/core/server.ts`.

## Corrija problemas comuns

### O build falha com Azion configuration not found

O `azion build` falha quando o projeto ainda não está vinculado à sua conta:

```text
Error: Failed to build your resource. Azion configuration not found. Make sure you are in the root directory of your local repository and have already initialized or linked your resource with the commands 'azion init' or 'azion link'
```

Execute `azion link` na pasta `mcp-server` e depois execute `azion build` novamente.

### O servidor não inicia

- Execute `node --version` e confirme que a versão é 20 ou posterior.
- Confirme que nenhum outro processo usa a porta 3333, ou inicie o servidor em outra porta com `--port`.
- Execute `yarn install` novamente para restaurar as dependências que faltam.

### O cliente não consegue se autenticar

- Confirme que o personal token é válido. Um personal token é `azion` seguido de 35 letras e dígitos.
- Confirme que o header é `Authorization: Bearer [TOKEN VALUE]`, com o seu token no lugar de `[TOKEN VALUE]`.
- Confirme que o arquivo `.env` define `AZION_TOKEN` e `OPENAI_API_KEY`.

Para problemas com o servidor hospedado, consulte [Solucionar problemas do MCP server](/pt-br/documentacao/devtools/mcp/solucao-de-problemas/).
