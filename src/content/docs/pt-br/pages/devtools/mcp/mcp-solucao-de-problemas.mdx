Esta página lista os sintomas que você pode encontrar com o [MCP server](/pt-br/documentacao/devtools/mcp/), cada um com a causa e a correção. A autenticação e a conexão vêm primeiro. Em seguida vêm o conjunto de ferramentas, a configuração do cliente, as respostas das ferramentas, o login, o servidor de staging e o desenvolvimento local. Quando um sintoma persistir, entre em contato com o suporte da Azion como [Obter ajuda](/pt-br/documentacao/suporte/obter-ajuda/) descreve, com a mensagem de erro, o cliente e a versão dele, a configuração sem o token e os passos que reproduzem o sintoma.

---

## O servidor responde 401 com No authentication provided

O cliente não consegue se conectar, e o servidor responde `401` com este body:

```text
{"message":"No authentication provided","status":401}
```

A requisição chegou ao servidor sem um header `Authorization`. A configuração do cliente não tem o header, ou o cliente não o envia.

- **Adicione o header à configuração do cliente**: envie `Authorization: Bearer [TOKEN VALUE]` com o seu personal token. O servidor também aceita `Authorization: Token [TOKEN VALUE]`, com o mesmo resultado. Para a configuração de cada cliente, consulte [Configuração de agentes](/pt-br/documentacao/agent-setup/).

O servidor responde `200` ao cliente, e o cliente lista as ferramentas.

---

## O servidor responde Invalid Bearer token ou Authentication failed

O cliente envia um header `Authorization`, e o servidor ainda responde `401`. O body indica o problema:

| Body | Causa |
| --- | --- |
| `{"message":"Invalid Bearer token","status":401}` | O valor depois de `Bearer` não é um token válido. |
| `{"message":"Authentication failed","status":403}` | O valor depois de `Token` não é um personal token válido. O body informa `403` dentro de uma resposta `401`. |
| `{"message":"Invalid authentication header format","status":401}` | O header traz o token sem um esquema. |

Esses bodies chegam como texto simples, não como erros JSON-RPC.

- **Verifique o token**: um personal token tem 40 caracteres e começa com `azion`. Copie o valor inteiro. Verifique se o token está ativo, se não expirou e se tem as permissões de que você precisa. Para criar outro, consulte [Gerencie personal tokens](/pt-br/documentacao/guias/plataforma/conta-e-billing/personal-tokens/).
- **Escreva o esquema antes do token**: `Authorization: Bearer [TOKEN VALUE]` ou `Authorization: Token [TOKEN VALUE]`.
- **Use Token no Cursor**: a configuração do Cursor envia `Token` em vez de `Bearer`. Para a configuração, consulte [Cursor + Azion](/pt-br/documentacao/agent-setup/cursor/).
- **Teste a conexão com o MCP Inspector**: execute `npx @modelcontextprotocol/inspector`, escolha o transporte `streamable-http` e passe o header com o seu token.

:::caution[Atenção]
Mantenha o seu personal token fora do controle de versão e fora de mensagens para outras pessoas. Remova o token de logs e capturas de tela antes de enviá-los.
:::

O servidor responde `200`, e o cliente lista as ferramentas.

## O cliente excede o tempo limite ou não alcança o servidor

Uma requisição excede o tempo limite, o servidor não envia resposta, ou o cliente informa um erro de rede.

O cliente aponta para a URL errada, ou a rede entre o cliente e o servidor bloqueia a conexão.

- **Verifique a URL**: o endereço do servidor é o host sem caminho `https://mcp.azion.com`.
- **Teste se o servidor está acessível**: `curl -I https://mcp.azion.com` responde `HTTP/2 401` sem token. Um `401` significa que o servidor está acessível. Um tempo limite excedido ou um erro de conexão significa que a rede não alcança o servidor.
- **Tente outra rede**: uma VPN pode interferir. Um firewall ou um proxy precisa permitir tráfego HTTPS para `mcp.azion.com`.
- **Teste o seu token fora do cliente**: envie a requisição `initialize` com `curl`.

Esta requisição abre uma conexão com o seu token:

```bash
curl -s https://mcp.azion.com \
  -H "Authorization: Bearer [TOKEN VALUE]" \
  -H "Content-Type: application/json" \
  -H "Accept: application/json, text/event-stream" \
  -d '{"jsonrpc":"2.0","method":"initialize","id":1,"params":{"protocolVersion":"2025-03-26","capabilities":{},"clientInfo":{"name":"my-client","version":"0.1"}}}'
```

O servidor responde `200` com um event stream. A linha `data:` dele traz este JSON:

```json
{
  "result": {
    "protocolVersion": "2025-03-26",
    "capabilities": {
      "logging": {},
      "resources": {
        "listChanged": true
      },
      "tools": {
        "listChanged": true
      },
      "completions": {}
    },
    "serverInfo": {
      "name": "azion-mcp-server",
      "version": "1.0.0"
    }
  },
  "jsonrpc": "2.0",
  "id": 1
}
```

Com uma resposta que nomeia `azion-mcp-server`, o servidor e o token funcionam, e a correção está na configuração do cliente.

## O servidor responde 404 Not Found

O cliente aponta para `https://mcp.azion.com/mcp`, e o servidor responde `404` com o body `404 Not Found`, mesmo com um token válido.

O servidor responde no caminho raiz do host. Nenhum outro caminho serve o servidor.

- **Remova o caminho**: defina a URL do servidor como `https://mcp.azion.com`.
- **Mantenha caminhos para os seus próprios servidores**: o caminho `/mcp` em [Execute um MCP server na Azion](/pt-br/documentacao/guias/desenvolvimento-de-aplicacoes/automacao/executar-mcp-server/) pertence ao servidor de exemplo que esse guia constrói, não ao MCP server da Azion.

O servidor responde `200` no caminho raiz, e o cliente lista as ferramentas.

## O cliente lista oito ferramentas ou uma chamada falha com Tool not found

O cliente lista oito ferramentas quando você espera nove, ou uma chamada de ferramenta falha com este erro:

```text
MCP error -32602: Tool search_azion_api_v3_commands not found
```

O conjunto de ferramentas depende do perfil de API da conta. `search_azion_api_v3_commands` aparece somente para uma conta no perfil v3 da API. Uma conta no perfil v4 vê oito ferramentas, e uma chamada a um nome fora do conjunto dela falha com o erro JSON-RPC `-32602`.

- **Chame as ferramentas que o servidor lista**: uma conta no perfil v4 vê `search_azion_docs_and_site`, `search_azion_code_samples`, `search_azion_cli_commands`, `search_azion_api_v4_commands`, `search_azion_terraform`, `create_rules_engine`, `create_graphql_query` e `deploy_azion_static_site`. Para as entradas de cada ferramenta, consulte [Ferramentas](/pt-br/documentacao/devtools/mcp/ferramentas/#ferramentas).
- **Busque na API v4 em vez disso**: no perfil v4, `search_azion_api_v4_commands` busca na documentação da API. Para os perfis, consulte [Conjunto de ferramentas por perfil de API](/pt-br/documentacao/devtools/mcp/ferramentas/#conjunto-de-ferramentas-por-perfil-de-api).

O cliente chama somente as ferramentas que `tools/list` retorna, e cada chamada responde.

## Uma requisição de prompts falha com Method not found

Um cliente que pede prompts ao servidor recebe o erro JSON-RPC `-32601` com a mensagem `Method not found`.

O servidor não expõe prompts. A resposta de `initialize` dele não declara a capacidade `prompts`, então uma requisição `prompts/list` não tem um método que responda a ela.

- **Use as ferramentas e os recursos**: o servidor oferece os guias dele como ferramentas e recursos. Para a lista, consulte [Recursos de site estático](/pt-br/documentacao/devtools/mcp/ferramentas/#recursos-de-site-estatico).
- **Ignore o erro nos logs do cliente**: ele vem somente da requisição de prompts. As requisições de ferramentas e de recursos na mesma conexão respondem normalmente.

O cliente lista as ferramentas e os recursos, e as chamadas de ferramentas respondem.

## A conexão falha com TLSV1_ALERT_PROTOCOL_VERSION

O cliente falha no handshake TLS com um erro como `SSLError TLSV1_ALERT_PROTOCOL_VERSION`.

O servidor aceita somente TLS 1.3. Um cliente construído sobre uma biblioteca TLS sem TLS 1.3 não consegue se conectar. O Python 3 do sistema no macOS, compilado com LibreSSL 2.8.3, falha dessa forma.

- **Execute o cliente em um runtime com TLS 1.3**: um runtime cuja biblioteca TLS suporta TLS 1.3 se conecta, como o Node.js 24.
- **Verifique a biblioteca TLS da sua ferramenta**: um script ou um proxy entre o cliente e o servidor também precisa suportar TLS 1.3.

O handshake é concluído, e o servidor responde à requisição.

## O cliente leva vários segundos para se conectar pelo mcp-remote

Um cliente que inicia o servidor pelo `mcp-remote` mostra as ferramentas cerca de 10 a 13 segundos depois de iniciar.

Antes de se conectar, o `mcp-remote` lê a configuração OAuth do servidor, mesmo quando você passa o header. Essa descoberta leva cerca de 4 segundos do total. Com o header presente, nenhuma janela do navegador abre e nenhum login OAuth é executado.

Este comando inicia a ponte com o seu token:

```bash
npx -y mcp-remote@latest https://mcp.azion.com --header "Authorization: Bearer [TOKEN VALUE]"
```

A ponte informa cada etapa da conexão:

```text
[12345] Discovering OAuth server configuration...
[12345] Using callback port derived from the server URL: 21077
[12345] Using custom headers: Authorization
[12345] Discovered authorization server: https://sso.azion.com
[12345] Using transport strategy: http-first
[12345] [12345] Connecting to remote server: https://mcp.azion.com
[12345] Connected to remote server using StreamableHTTPClientTransport
[12345] Local STDIO server running
[12345] Press Ctrl+C to exit
[12345] Proxy established successfully between local STDIO and remote StreamableHTTPClientTransport
```

- **Aguarde a linha do proxy**: as ferramentas aparecem depois de `Proxy established successfully`.
- **Conecte-se diretamente por HTTP**: um cliente que suporta streamable HTTP se conecta sem o `mcp-remote`, como o Claude Code com `-t http` ou o Cursor com `streamable-http`. Para cada cliente, consulte [Configuração de agentes](/pt-br/documentacao/agent-setup/).

O cliente lista as ferramentas assim que a linha do proxy aparece.

## O cliente não mostra ferramentas da Azion

O cliente não mostra ferramentas da Azion, informa `No tools available` ou não reconhece os comandos.

O cliente não suporta MCP, não carregou a configuração dele ou não registrou o servidor.

- **Verifique o suporte a MCP**: use uma versão do cliente que suporte MCP. Atualize o cliente se ele não suportar.
- **Verifique o local da configuração**: o Windsurf lê `.codeium/windsurf/mcp_config.json`. Para cada cliente, consulte [Configuração de agentes](/pt-br/documentacao/agent-setup/).
- **Verifique se o servidor está registrado**: no Claude Code, `claude mcp list` nomeia os servidores que ele conhece. Para a configuração, consulte [Claude Code + Azion](/pt-br/documentacao/agent-setup/claude-code/).
- **Reinicie o cliente**: feche e abra a aplicação novamente para que ela leia a configuração outra vez.

O cliente lista as ferramentas do servidor.

## O cliente informa Invalid JSON

O cliente informa `Invalid JSON` e não carrega a configuração.

O arquivo de configuração quebra uma regra do JSON. As causas comuns são uma vírgula faltando entre propriedades, uma vírgula final, aspas simples em vez de aspas duplas e um colchete ou uma chave sem fechamento.

- **Valide o arquivo**: `cat mcp_config.json | python -m json.tool` imprime o arquivo quando ele é válido e indica o primeiro erro quando não é.
- **Compare com uma configuração válida**: um cliente que inicia o servidor pelo `mcp-remote` lê uma configuração neste formato.

```json
{
  "mcpServers": {
    "azion": {
      "command": "npx",
      "args": [
        "-y",
        "mcp-remote@latest",
        "https://mcp.azion.com",
        "--header",
        "Authorization: Bearer [TOKEN VALUE]"
      ]
    }
  }
}
```

O cliente carrega a configuração e lista as ferramentas.

## O cliente falha com npx command not found

O cliente falha com `npx: command not found` ou `Node.js is required`.

O `mcp-remote` é executado no Node.js. Ele precisa do Node.js 18 ou posterior, e o `npx` vem com o npm.

- **Verifique as versões instaladas**: `node --version` e `npm --version` imprimem as versões, ou falham quando o Node.js não está instalado.
- **Instale o Node.js**: no macOS, execute `brew install node`. No Ubuntu ou no Debian, execute `sudo apt install nodejs npm`.
- **Atualize o npm**: execute `npm install -g npm@latest`.

`npx -y mcp-remote@latest` inicia a ponte, como mostra [O cliente leva vários segundos para se conectar pelo mcp-remote](#o-cliente-leva-varios-segundos-para-se-conectar-pelo-mcp-remote).

---

## O cliente falha com Cannot find module mcp-remote

O cliente falha com `Cannot find module 'mcp-remote'`, ou a instalação do pacote falha.

O cache do npm ou a cópia instalada do `mcp-remote` está corrompida ou ausente.

- **Limpe o cache do npm**: execute `npm cache clean --force`.
- **Instale o pacote globalmente**: execute `npm install -g mcp-remote`.
- **Execute a versão mais recente**: inicie a ponte com `npx mcp-remote@latest`.

A ponte inicia e imprime `Proxy established successfully`.

## Uma busca retorna documentos que não correspondem à query

Uma ferramenta de busca não retorna nenhum resultado, retorna um resultado parcial ou retorna respostas genéricas em vez de informações da Azion.

As ferramentas de busca classificam os documentos pela proximidade com as palavras da query, não pelo que a query significa. Uma query ampla pode colocar em primeiro lugar um documento sobre outro produto ou outra operação.

- **Nomeie o produto e a tarefa**: pergunte "Como configuro o TTL de cache para imagens na Azion?" em vez de "Ajuda com cache".
- **Nomeie a ferramenta ou a fonte**: peça "Busque na documentação da Azion a configuração de cache do Rules Engine".
- **Peça mais documentos**: as ferramentas de busca recebem `docsAmount`, cujo padrão é `5`. Para as entradas, consulte [Ferramentas](/pt-br/documentacao/devtools/mcp/ferramentas/#ferramentas).
- **Divida a requisição**: faça uma pergunta por prompt.

A ferramenta retorna documentos sobre o produto e a tarefa que você nomeou.

## A ferramenta GraphQL responde It was not possible to retrieve the requested information

`create_graphql_query` retorna o texto `It was not possible to retrieve the requested information with GraphQL.` em vez de uma query. Em seguida, o texto aponta para a documentação da GraphQL API.

A ferramenta escreve uma query para o seu objetivo e a executa nos dados de analytics da sua conta, com o seu token, para validá-la. A ferramenta retorna esse texto quando não consegue produzir uma query que seja executada. O servidor não retorna a causa ao cliente.

- **Verifique se os dados existem**: confirme que a GraphQL API traz os dados que você pede. Para os datasets, consulte [GraphQL API](/pt-br/documentacao/devtools/graphql/).
- **Verifique a fonte de dados**: `dataSource` recebe `real-time-metrics`, `real-time-events`, `accounting` ou `consumption`. Escolha a que contém os dados.
- **Escreva a query você mesmo**: monte a query a partir da documentação da GraphQL API e execute-a na GraphQL API.

Você obtém os dados de uma query que a GraphQL API executa.

## As chamadas de ferramentas respondem devagar

As chamadas de ferramentas demoram para responder.

O caminho de rede até o servidor é lento, muitas requisições são executadas ao mesmo tempo, ou a query é ampla. `create_graphql_query` também gera e valida queries no servidor e pode levar mais de 15 segundos.

- **Verifique a rede**: use uma conexão estável. `ping mcp.azion.com` mede a latência até o servidor.
- **Envie menos requisições ao mesmo tempo**: execute menos chamadas de ferramentas simultâneas.
- **Restrinja a query**: faça uma pergunta específica em vez de uma busca ampla.

As chamadas de ferramentas respondem em menos tempo.

## Um token OAuth é recusado ou o cliente não está autorizado

Depois de um login OAuth, o servidor informa um token inválido, a requisição de informações do usuário responde `401`, ou o cliente não está autorizado.

O servidor confere um access token OAuth no endpoint de informações do usuário do servidor de autorização dele. Um token de outro ambiente, um token expirado ou um cliente registrado com configurações diferentes falha nessa verificação.

- **Envie o token com Bearer**: um access token OAuth vai em `Authorization: Bearer [TOKEN VALUE]`.
- **Verifique o servidor de autorização**: o servidor anuncia `https://sso.azion.com`, com os endpoints `/oauth/authorize`, `/oauth/token` e `/oauth/jwks`. O servidor de staging usa `https://stage-sso.azion.com`.
- **Solicite outro token**: os tokens OAuth expiram após um período definido.
- **Verifique o registro do cliente**: o client ID e o secret precisam estar corretos, e a URI de redirecionamento precisa corresponder exatamente à URI registrada. O servidor anuncia os escopos `openid`, `profile`, `email` e `offline_access`.

O servidor aceita o token, e o cliente lista as ferramentas.

## O servidor de staging não responde

Um cliente apontado para `https://stage-mcp.azion.com` não se conecta.

O servidor de staging responde `401` sem token, como a produção, e precisa de um token válido. A disponibilidade dele pode ser diferente da disponibilidade da produção.

- **Verifique a URL e o token**: use `https://stage-mcp.azion.com` com o header `Authorization`.
- **Use a produção para trabalho crítico**: aponte o cliente para `https://mcp.azion.com`.

O cliente se conecta ao servidor que você escolheu.

---

## O servidor local não responde na porta 3333

`curl http://localhost:3333` falha com `curl: (7) Failed to connect to localhost port 3333`.

Nenhum servidor local está em execução. O `azion dev` serve o servidor na porta 3333 e precisa de um projeto vinculado e com o build feito.

- **Vincule o projeto antes do build**: `azion build` falha com `Azion configuration not found` até que `azion link` vincule o projeto. Execute `azion link` primeiro.
- **Defina a chave da OpenAI**: o servidor exige `OPENAI_API_KEY` no arquivo `.env` do projeto.
- **Inicie o servidor novamente**: pare o `azion dev` e execute-o outra vez.

Para a ordem completa dos passos, consulte [Execute o MCP server da Azion localmente](/pt-br/documentacao/guias/desenvolvimento-de-aplicacoes/automacao/executar-mcp-server-da-azion-localmente/).

`curl http://localhost:3333` alcança o servidor local em vez de falhar na conexão.
