Você pode descrever uma regra do [Rules Engine](/pt-br/documentacao/plataforma/applications/rules-engine/) em linguagem natural para um agente de código conectado ao [MCP server da Azion](/pt-br/documentacao/devtools/mcp/) e receber de volta uma proposta de regra. O servidor não cria nenhuma regra: você revisa a proposta e cria a regra. Para criar uma regra sem um agente, consulte [Crie uma regra de aplicação](/pt-br/documentacao/guias/desenvolvimento-de-aplicacoes/primeiros-passos/trabalhar-com-rules-engine/).

---

## Pré-requisitos

- Um agente de código conectado ao MCP server. Para conectar um, consulte [Primeiros passos com o MCP server](/pt-br/documentacao/devtools/mcp/configuracao/).
- Uma aplicação para receber a regra, ou um firewall para uma regra do [Rules Engine para Firewall](/pt-br/documentacao/plataforma/firewall/rules-engine/).

---

## Peça ao seu agente uma proposta de regra

O MCP server transforma um objetivo em uma proposta de regra com a ferramenta `create_rules_engine`. A ferramenta pede a regra a um modelo de linguagem, então a proposta pode variar entre chamadas. Ela não usa o seu token e não cria nada na sua conta. Para obter uma proposta que adiciona headers de segurança:

<DocSteps>
  <DocStep title="Descreva a regra ao seu agente">

  Informe ao agente o objetivo e diga se a regra é para uma aplicação ou para um firewall. Por exemplo: `Crie regras do Rules Engine para adicionar headers de segurança incluindo HSTS, X-Frame-Options e CSP para minha aplicação.`

  </DocStep>
  <DocStep title="Confira os argumentos da chamada da ferramenta">

  O agente chama `create_rules_engine` com o seu objetivo em `query` e o tipo de regra em `useCase`. Use `edge_application` para uma regra de aplicação e `edge_firewall` para uma regra de firewall. Apenas `useCase` é obrigatório, mas a ferramenta monta a regra a partir de `query`.

  </DocStep>
  <DocStep title="Leia a proposta">

  A ferramenta retorna um texto JSON. Dentro de `data`, a proposta traz os `criteria`, os `behaviors` e a `phase` da regra, além de uma `explanation`.

  </DocStep>
</DocSteps>

A ferramenta retorna uma proposta como esta:

```json
{
  "success": true,
  "data": {
    "criteria": [
      {
        "logic": null,
        "criteria": [
          {
            "variable": "${request_uri}",
            "operator": "matches",
            "argument": ".*"
          }
        ]
      }
    ],
    "behaviors": [
      {
        "type": "Add_response_header",
        "args": "Strict-Transport-Security: max-age=31536000; includeSubDomains"
      },
      {
        "type": "Add_response_header",
        "args": "X-Frame-Options: DENY"
      },
      {
        "type": "Add_response_header",
        "args": "Content-Security-Policy: default-src 'self'"
      }
    ],
    "phase": "RESPONSE",
    "explanation": "This rule adds the HSTS, X-Frame-Options, and Content-Security-Policy headers to all responses. Adjust the CSP value as needed for your application's requirements."
  }
}
```

A proposta adiciona três behaviors `Add_response_header` na fase `RESPONSE`, um por header. O critério dela compara `${request_uri}` com `.*`, então a regra age sobre todas as requisições. `${request_uri}` exige [Application Accelerator](/pt-br/documentacao/plataforma/applications/application-accelerator/configuracoes/) na aplicação. Sem esse Produto, use `${uri}` no critério, como explica [Variáveis](/pt-br/documentacao/plataforma/applications/rules-engine/#variaveis). Ajuste o valor de `Content-Security-Policy` à sua aplicação, como diz a `explanation`. A regra só existe depois que você aplica a proposta.

## Revise uma proposta de cache

Uma proposta pode depender de objetos que ainda não existem ou precisar de mudanças antes de fazer o que você pediu. Para o objetivo `Configure o Rules Engine para cachear assets estáticos por 1 ano e respostas da API por 5 minutos.`, a ferramenta retorna uma proposta como esta:

```json
{
  "success": true,
  "data": {
    "criteria": [
      {
        "logic": "OR",
        "criteria": [
          {
            "variable": "${uri}",
            "operator": "matches",
            "argument": ".*\\.(jpg|jpeg|png|gif|css|js|svg|woff|woff2|ttf|eot|ico|mp4|webm|ogg|mp3|wav|pdf|zip|tar|gz|rar|7z)$"
          },
          {
            "variable": "${uri}",
            "operator": "starts with",
            "argument": "/api/"
          }
        ]
      }
    ],
    "behaviors": [
      {
        "type": "Set_cache_policy",
        "args": "StaticAssetsCachePolicy"
      },
      {
        "type": "Set_cache_policy",
        "args": "ApiCachePolicy"
      }
    ],
    "phase": "RESPONSE",
    "explanation": "You need to create two cache policies in Azion: one named 'StaticAssetsCachePolicy' with a TTL of 1 year for static assets, and another named 'ApiCachePolicy' with a TTL of 5 minutes for API responses. The rules engine will apply the appropriate cache policy based on the URI pattern. For more details on creating cache policies, refer to the Azion documentation."
  }
}
```

Antes de aplicar essa proposta, faça três mudanças:

- Crie os cache settings primeiro. Cada behavior `Set_cache_policy` nomeia uma cache policy que a `explanation` pede para você criar. Em Applications, o objeto que esse behavior aplica é um cache setting, que guarda o TTL. Crie um com TTL de 1 ano e outro com TTL de 5 minutos. Para o procedimento, consulte [Crie um cache setting](/pt-br/documentacao/guias/performance-e-confiabilidade/cache-e-purge/ajustar-cache-settings/).
- Divida a regra em duas. A proposta une o critério de assets estáticos e o critério de `/api/` com `OR`, então os dois behaviors se aplicam aos dois tipos de requisição. Crie uma regra por critério, cada uma com o seu cache setting. Para saber como os critérios se combinam, consulte [Condicionais](/pt-br/documentacao/plataforma/applications/rules-engine/#condicionais).
- Crie as duas regras na Request Phase. A proposta indica `RESPONSE`, mas _Set Cache Policy_ é executado apenas na Request Phase, como informa [Set Cache Policy](/pt-br/documentacao/plataforma/applications/rules-engine/#set-cache-policy).

## Aplique a proposta

A proposta não é o corpo de uma requisição da API, então você a traduz para os campos de regra do Rules Engine. Na API e na Azion CLI, o `type` de um behavior é escrito em minúsculas, como `add_response_header` ou `set_cache_policy`, e o argumento dele vai em `attributes.value`. Para `set_cache_policy`, o valor é o ID do cache setting. Cada critério traz um `conditional` (`if`, `and` ou `or`), e o `operator` dele é um dos [Operadores](/pt-br/documentacao/plataforma/applications/rules-engine/#operadores), como `starts_with`.

Para criar a regra no Azion Console, siga [Crie uma regra de aplicação](/pt-br/documentacao/guias/desenvolvimento-de-aplicacoes/primeiros-passos/trabalhar-com-rules-engine/). Para criá-la com a API, consulte a seção [API](/pt-br/documentacao/plataforma/applications/rules-engine/#api) de Rules Engine para Applications. Para criá-la a partir de um arquivo JSON com a CLI, consulte [Azion CLI rules-engine](/pt-br/documentacao/devtools/cli/recursos/rules-engine/). Para uma regra de firewall, consulte [Rules Engine para Firewall](/pt-br/documentacao/plataforma/firewall/rules-engine/).

A regra aparece na aba **Rules Engine** da aplicação, na lista da fase dela. Se o agente não encontrar a ferramenta `create_rules_engine`, consulte [Solucionar problemas do MCP server](/pt-br/documentacao/devtools/mcp/solucao-de-problemas/).
