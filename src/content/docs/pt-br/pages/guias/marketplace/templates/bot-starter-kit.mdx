Você vê o [Bot Manager Lite](/pt-br/documentacao/secure/bot-manager/bot-manager-lite/) pontuar uma requisição que você mesmo envia implantando o template Bot Manager Lite Starter Kit pelo Azion Console.

O template implanta um sandbox: uma aplicação, uma função que serve uma página de teste, um [firewall](/pt-br/documentacao/plataforma/firewall/) carregando uma instância de função do Bot Manager Lite e um domínio que alcança tudo isso pelo navegador. Ele mesmo cria o firewall, então a implantação não pede nenhum objeto que você já execute.

Para acrescentar o Bot Manager Lite a um firewall que você já executa, consulte [Adicione o Bot Manager Lite a um firewall](/pt-br/documentacao/guias/desenvolvimento-de-aplicacoes/integracoes/bot-manager-lite-integration-kit/).

---

## Pré-requisitos

- Bot Manager Lite instalado pelo Marketplace. Para mais informações, consulte [Instale o Bot Manager Lite](/pt-br/documentacao/guias/desenvolvimento-de-aplicacoes/integracoes/bot-manager-lite/).
- Acesso ao Azion Console. Para entrar, consulte [Como acessar o Azion Console](/pt-br/documentacao/guias/plataforma/conta-e-billing/como-acessar-o-azion-console/).
- A instância é executada como uma instância de [Functions](/pt-br/documentacao/build/functions/), o que pode gerar custos de uso. Para as métricas pelas quais o Bot Manager é cobrado, consulte [Preços](/pt-br/documentacao/fundamentos/precos/#bot-manager).

O template verifica se o Bot Manager Lite está instalado antes de criar qualquer coisa. Quando não está, a implantação falha e escreve uma linha de log que nomeia o motivo.

## Implante o template

Para implantar o template no Azion Console:

<DocSteps>
  <DocStep title="Abra o template">

  Acesse o template [Bot Manager Lite Starter Kit](https://console.azion.com/create/azion/bot-manager-starter-kit).

  </DocStep>
  <DocStep title="Nomeie a aplicação">

  Em **Applications Name**, informe um nome. O template dá o mesmo nome à instância de firewall que ele cria. Um campo marcado com asterisco é obrigatório.

  </DocStep>
  <DocStep title="Nomeie a função de exemplo">

  Em **Sample Function Name**, informe um nome para a função que serve a página de teste.

  </DocStep>
  <DocStep title="Selecione Deploy" />
</DocSteps>

A implantação mostra o seu log enquanto é executada. Quando ela termina, a conta carrega a aplicação, a função, o firewall e o domínio.

O domínio leva alguns minutos para se propagar pela infraestrutura distribuída da Azion. Até ele responder, a página de teste não abre no navegador.

## O que o template configura

O template cria quatro objetos:

- Uma aplicação com o módulo **Functions** ligado, que executa a função de exemplo.
- Uma função que serve a página de teste e os seus botões de requisição.
- Um firewall carregando uma instância de função do Bot Manager Lite e uma regra do [Rules Engine](/pt-br/documentacao/plataforma/firewall/rules-engine/) que a executa.
- Um [workload](/pt-br/documentacao/plataforma/workloads/), que responde em um domínio no formato `<id>.map.azionedge.net`.

A instância aparece na aba **Functions Instances** do firewall, e a regra que a executa na aba **Rules Engine**. A instância carrega `action` definido como `deny`, então uma requisição cuja pontuação alcança o threshold recebe uma resposta `403` com a página de erro padrão da Azion. Ela também escreve uma linha de log de report para toda requisição que pontua, que é o que `internal_logs` controla.

Leia e mude esse objeto na seção **Arguments** da instância. A função instalada não publica esquema de argumentos, então o editor não tem formulário para construir a partir dele e o objeto é escrito como JSON puro. Nada o valida, tampouco: toda chave que uma instância carrega é armazenada e lida de volta exatamente como foi enviada, incluindo uma chave que a função nunca lê. Para cada argumento que uma instância aceita, consulte [Argumentos](/pt-br/documentacao/secure/bot-manager/argumentos/).

A aplicação serve a função de exemplo em vez de uma origem sua, então a configuração é uma demonstração e não um site em operação. Para alcançar o sandbox em um domínio seu, acrescente esse domínio ao workload que o template criou.

## Envie uma requisição boa e uma ruim

Para pontuar uma requisição que você mesmo envia:

<DocSteps>
  <DocStep title="Abra a página de teste">

  No navegador, acesse o domínio que o template criou.

  </DocStep>
  <DocStep title="Envie a requisição boa">

  Selecione **Send Request** na requisição boa. A página renderiza uma mensagem de sucesso.

  </DocStep>
  <DocStep title="Envie a requisição ruim">

  Selecione **Send Request** na requisição ruim. A página renderiza a resposta `403` que a ação `deny` devolve.

  </DocStep>
</DocSteps>

Cada requisição que a página envia produz uma linha de log de report, qualquer que seja a pontuação.

Para enviar uma requisição recusada a um endereço que você escolhe, em vez da página de erro padrão, defina `action` como `redirect` e informe o destino em `redirect_to`. Para mais informações, consulte [Argumentos](/pt-br/documentacao/secure/bot-manager/argumentos/#action).

---

## Leia o que a instância pontuou

Leia as linhas do log de report no [Real-Time Events](/pt-br/documentacao/observe/real-time-events/), ou encaminhe-as para um destino seu com o [Data Stream](/pt-br/documentacao/observe/data-stream/). Para os campos que uma linha carrega, consulte [Logs](/pt-br/documentacao/secure/bot-manager/logs/).

As pontuações que a página de teste produz vêm de requisições que o sandbox formou, não do seu próprio tráfego. Defina `threshold` e `action` pelas pontuações que o seu próprio tráfego produz antes de uma instância recusar qualquer coisa na frente de uma aplicação sua. Para mais informações, consulte [Monitore e calibre o Bot Manager](/pt-br/documentacao/guias/seguranca-de-aplicacoes/bots-e-rede/monitorar-e-calibrar-bot-manager/#leia-o-log-de-report-no-real-time-events).
