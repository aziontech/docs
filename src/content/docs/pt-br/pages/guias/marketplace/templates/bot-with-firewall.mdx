Você acrescenta o [Bot Manager Lite](/pt-br/documentacao/secure/bot-manager/bot-manager-lite/) a um [firewall](/pt-br/documentacao/plataforma/firewall/) que você já executa implantando o template Bot Manager Lite Integration Kit pelo Azion Console.

O template cria uma instância de função do Bot Manager Lite no firewall que você nomeia, e uma regra do [Rules Engine](/pt-br/documentacao/plataforma/firewall/rules-engine/) que a executa. Ele acrescenta a um firewall em vez de criar um, então a implantação pede o ID do firewall.

Para criar você mesmo a instância e a regra, consulte [Primeiros passos com Bot Manager](/pt-br/documentacao/secure/bot-manager/primeiros-passos/).

---

## Pré-requisitos

- Um [firewall](/pt-br/documentacao/plataforma/firewall/) na sua conta, e o ID dele. Para mais informações, consulte [Como configurar as main settings do Firewall](/pt-br/documentacao/guias/seguranca-de-aplicacoes/firewall-e-waf/firewall-definir-main-settings/).
- O módulo **Functions** ligado nesse firewall.
- Bot Manager Lite instalado pelo Marketplace. Para mais informações, consulte [Instale o Bot Manager Lite](/pt-br/documentacao/guias/desenvolvimento-de-aplicacoes/integracoes/bot-manager-lite/).
- Acesso ao Azion Console. Para entrar, consulte [Como acessar o Azion Console](/pt-br/documentacao/guias/plataforma/conta-e-billing/como-acessar-o-azion-console/).
- A instância é executada como uma instância de [Functions](/pt-br/documentacao/build/functions/), o que pode gerar custos de uso. Para as métricas pelas quais o Bot Manager é cobrado, consulte [Preços](/pt-br/documentacao/fundamentos/precos/#bot-manager).

O template verifica os três primeiros requisitos antes de criar qualquer coisa. Quando um deles não é atendido, a implantação falha e escreve uma linha de log que nomeia o motivo.

## Implante o template

Para implantar o template no Azion Console:

<DocSteps>
  <DocStep title="Copie o ID do firewall">

  Acesse [Azion Console](https://console.azion.com/) > **Firewalls**, selecione o firewall e copie o ID do endereço. O endereço termina em `/firewalls/edit/<firewall-id>`.

  </DocStep>
  <DocStep title="Abra o template">

  Acesse o template [Bot Manager Lite Integration Kit](https://console.azion.com/create/azion/bot-manager-integration-kit).

  </DocStep>
  <DocStep title="Informe o ID do firewall">

  Em **Firewall ID**, informe o ID que você copiou. Um campo marcado com asterisco é obrigatório.

  </DocStep>
  <DocStep title="Selecione Deploy" />
</DocSteps>

Quando a implantação termina, o firewall carrega a nova instância de função e a regra que a executa.

## O que o template configura

A instância de função aparece na aba **Functions Instances** do firewall, e a regra que a executa na aba **Rules Engine**. A instância carrega três argumentos:

```json
{
  "threshold": 10,
  "action": "allow",
  "internal_logs": 2
}
```

| Argumento | Valor | O que faz |
| --- | --- | --- |
| `threshold` | `10` | A pontuação a partir da qual `action` é executada. A função entrega um padrão de `30`, então o template age sobre mais requisições do que uma instância que não define nada |
| `action` | `allow` | A instância pontua toda requisição e não recusa nenhuma. Os sete valores que `action` assume estão listados em [Argumentos](/pt-br/documentacao/secure/bot-manager/argumentos/#action) |
| `internal_logs` | `2` | Toda requisição produz uma linha de log de report, qualquer que seja a pontuação. Os quatro valores estão listados em [Bot Manager Lite](/pt-br/documentacao/secure/bot-manager/bot-manager-lite/) |

Nada valida esse objeto. Toda chave que uma instância carrega é armazenada e lida de volta exatamente como foi enviada, incluindo uma chave que a função nunca lê. Escreva `thresold` no lugar de `threshold` e a instância guarda `thresold`, a função continua pontuando contra `30`, e nenhuma interface reporta um problema.

Edite os argumentos na seção **Arguments** da instância. A função instalada não publica esquema de argumentos, então o editor não tem formulário para construir a partir dele e o objeto é escrito como JSON puro. Para cada argumento que uma instância aceita, consulte [Argumentos](/pt-br/documentacao/secure/bot-manager/argumentos/).

---

## Leia o que a instância pontuou

Com `internal_logs` definido como `2`, a instância escreve uma linha de log de report para toda requisição que pontua, incluindo uma requisição que pontuou `0`. Leia essas linhas no [Real-Time Events](/pt-br/documentacao/observe/real-time-events/), ou encaminhe-as para um destino seu com o [Data Stream](/pt-br/documentacao/observe/data-stream/). Para os campos que uma linha carrega, consulte [Logs](/pt-br/documentacao/secure/bot-manager/logs/).

Como `action` é `allow`, a instância não recusa nada enquanto você as lê. Defina `threshold` e `action` pelas pontuações que o seu próprio tráfego produz, e não pelos valores com que o template começa. Para mais informações, consulte [Monitore e calibre o Bot Manager](/pt-br/documentacao/guias/seguranca-de-aplicacoes/bots-e-rede/monitorar-e-calibrar-bot-manager/#leia-o-log-de-report-no-real-time-events).
