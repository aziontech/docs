Você verifica se o [Cache](/pt-br/documentacao/build/cache/) entregou uma resposta por uma cópia armazenada requisitando o objeto com um header de debug e lendo dois headers da resposta. A verificação roda de qualquer máquina com `curl`, e não exige nenhuma alteração na aplicação.

A mesma resposta carrega a cache key sob a qual a cópia está armazenada, que é o argumento que um purge por cache key recebe. Para o formato da key e cada valor de status, consulte [Cache keys](/pt-br/documentacao/build/cache/cache-keys/).

---

## Pré-requisitos

- O `curl` na sua máquina.
- A URL de um objeto que a sua aplicação entrega.

---

## Requisite os headers de debug

O header de requisição `Pragma: azion-debug-cache` faz a Azion retornar o estado de cache da resposta. Para lê-lo:

<DocSteps>
  <DocStep title="Requisite o objeto com o header de debug">

  A flag `-I` pede apenas os headers da resposta, então o corpo não é baixado:

  ```bash
  curl -sI -H "Pragma: azion-debug-cache" https://www.example.com/static/site.js
  ```

  </DocStep>
  <DocStep title="Leia o status de cache">

  O header `x-cache` carrega três valores: o status de cache, o endereço IP do servidor que respondeu a requisição e o protocolo. Em HTTP/2, os nomes dos headers chegam em minúsculas:

  ```http
  x-cache: MISS from 179.191.169.65 with HTTP/2.0
  x-cache-key: httpswww.example.com/static/site.js
  ```

  </DocStep>
  <DocStep title="Leia a cache key">

  O header `x-cache-key` carrega a key sob a qual a cópia está armazenada. Um purge por cache key recebe esse valor como argumento.

  </DocStep>
  <DocStep title="Execute o mesmo comando novamente">

  Compare o status da segunda resposta com o da primeira.

  </DocStep>
</DocSteps>

Agora você sabe se a resposta veio do cache, da origem, ou não foi colocada em cache.

---

## Leia o status

`HIT` significa que a resposta foi entregue por uma cópia armazenada e a origem não foi consultada. `MISS` significa que o objeto não estava no cache, então a Azion o buscou na origem e pode armazenar a resposta para as requisições seguintes. Um `-` nos dois headers significa que o conteúdo está restrito de cache.

Os outros valores que uma resposta pode carregar são `EXPIRED`, `STALE`, `UPDATING`, `REVALIDATED` e `BYPASS`. Para o significado de cada um, consulte [Cache keys](/pt-br/documentacao/build/cache/cache-keys/).

Um `-` em uma requisição `POST` ou `OPTIONS` significa que o cache está desativado para esse método. Para ativá-lo, consulte [Armazene em cache respostas de POST e OPTIONS](/pt-br/documentacao/guias/performance-e-confiabilidade/cache-e-purge/cache-de-respostas-post-e-options/).
