Um stream HLS é entregue como dois tipos de arquivo, e eles não pedem o mesmo cache. Você dá a cada um um cache setting próprio e o aplica com uma regra do [Rules Engine](/pt-br/documentacao/plataforma/applications/rules-engine/) que casa a extensão do arquivo, pelo Azion Console ou pela Azion API v4.

Um arquivo de segmento é escrito uma vez e nunca muda, então ele recebe o TTL de cache mais longo. A playlist é reescrita conforme o stream avança, então ela recebe um TTL de poucos segundos. O TTL de playlist que este guia usa está abaixo de 60 segundos, o que exige o [Application Accelerator](/pt-br/documentacao/build/application-accelerator/) na aplicação.

---

## Pré-requisitos

- Uma aplicação que entrega a playlist e os segmentos do seu stream. Para criar uma, consulte [Crie uma aplicação](/pt-br/documentacao/guias/desenvolvimento-de-aplicacoes/primeiros-passos/criar-uma-aplicacao/).
- Um domínio no workload que entrega a aplicação. Para mais informações, consulte [Workloads](/pt-br/documentacao/plataforma/workloads/).
- O Application Accelerator ativo na aplicação. Para os passos, consulte [Configure políticas de cache para uma aplicação](/pt-br/documentacao/guias/performance-e-confiabilidade/cache-e-purge/cache-settings/), cuja primeira tarefa ativa o módulo.
- Acesso ao Azion Console, para os procedimentos pelo Console. Consulte [Como acessar o Azion Console](/pt-br/documentacao/guias/plataforma/conta-e-billing/como-acessar-o-azion-console/).
- Um [personal token](/pt-br/documentacao/guias/plataforma/conta-e-billing/personal-tokens/), para os procedimentos pela API.

Arquivos de vídeo armazenados no [Object Storage](/pt-br/documentacao/store/object-storage/) podem servir como origem do stream: envie os arquivos de vídeo e aponte o encoder que produz a saída HLS para o bucket.

---

## Crie o cache setting dos segmentos

Os segmentos recebem um TTL de cache de 60 segundos e um TTL de browser de 0 segundos. Para criar o setting:

<DocSteps>
  <DocStep title="Abra a aplicação">

  Acesse [Azion Console](https://console.azion.com/) > **Applications** e selecione a aplicação que entrega o stream.

  </DocStep>
  <DocStep title="Vá para a aba Cache Settings" />
  <DocStep title="Selecione + Cache" />
  <DocStep title="Nomeie o cache setting">

  Em **Name**, insira `hls-segments`.

  </DocStep>
  <DocStep title="Defina o browser cache">

  Em **Browser Cache**, selecione _Override cache settings_ e defina o TTL como `0`.

  </DocStep>
  <DocStep title="Defina o Max Age">

  Em **Cache**, mantenha _Override cache behavior_ selecionado e, em **Max Age**, insira `60`.

  </DocStep>
  <DocStep title="Ative o Tiered Cache">

  O toggle está na mesma seção. Ele adiciona uma segunda camada de cache entre o cache da Azion e a sua origem.

  </DocStep>
  <DocStep title="Selecione Save" />
</DocSteps>

O setting aparece na lista de **Cache Settings**.

---

## Crie o cache setting da playlist

A playlist recebe um TTL de cache de 5 segundos, para que um cliente que a lê receba os segmentos que o encoder já escreveu. Para criar o setting:

<DocSteps>
  <DocStep title="Selecione + Cache" />
  <DocStep title="Nomeie o cache setting">

  Em **Name**, insira `hls-playlist`.

  </DocStep>
  <DocStep title="Defina o browser cache">

  Em **Browser Cache**, selecione _Override cache settings_ e defina o TTL como `0`.

  </DocStep>
  <DocStep title="Defina o Max Age">

  Em **Cache**, mantenha _Override cache behavior_ selecionado e, em **Max Age**, insira `5`.

  </DocStep>
  <DocStep title="Ative o Tiered Cache" />
  <DocStep title="Selecione Save" />
</DocSteps>

Os dois settings agora aparecem na lista, e nenhum dos dois se aplica a uma requisição ainda.

:::note[nota]
Um **Max Age** abaixo de 60 segundos exige o Application Accelerator na aplicação. Sem o módulo, a API rejeita o setting com o erro `21021`. Para o piso, consulte [Limites do Cache](/pt-br/documentacao/build/cache/limites/).
:::

## Aplique os settings com regras

Cada setting precisa de uma regra que case a sua extensão de arquivo. Para criar a regra dos segmentos:

<DocSteps>
  <DocStep title="Vá para a aba Rules Engine" />
  <DocStep title="Selecione + Rule" />
  <DocStep title="Nomeie a regra">

  Insira `cache-hls-segments`.

  </DocStep>
  <DocStep title="Selecione Request Phase" />
  <DocStep title="Defina os criteria">

  Em **Criteria**, selecione `${uri}`, o operador *matches* e insira `.*.ts` como argumento.

  </DocStep>
  <DocStep title="Adicione o behavior Set Cache Policy">

  Em **Behaviors**, selecione **Set Cache Policy** e depois selecione `hls-segments`.

  </DocStep>
  <DocStep title="Selecione Save" />
</DocSteps>

Repita o procedimento para a playlist: nomeie a regra `cache-hls-playlist`, insira `.*.m3u8` como argumento dos criteria e selecione `hls-playlist` como cache policy.

As duas regras agora aparecem na lista, e cada uma aplica o seu setting aos arquivos que o seu padrão casa.

:::note[nota]
Uma regra nova pode levar alguns minutos para propagar.
:::

## Configure pela API

Os mesmos dois settings e as mesmas duas regras são criados com quatro requisições. Para criar os cache settings:

<DocSteps>
  <DocStep title="Crie o setting dos segmentos">

  ```bash
  curl --location --request POST 'https://api.azion.com/v4/workspace/applications/{application_id}/cache_settings' \
  --header 'Accept: application/json' \
  --header 'Content-Type: application/json' \
  --header 'Authorization: Token [TOKEN VALUE]' \
  --data '{
    "name": "hls-segments",
    "browser_cache": { "behavior": "override", "max_age": 0 },
    "modules": {
      "cache": {
        "behavior": "override",
        "max_age": 60,
        "tiered_cache": { "enabled": true, "topology": "nearest-region" }
      }
    }
  }'
  ```

  </DocStep>
  <DocStep title="Leia o id na resposta">

  A API responde com HTTP `201` e o novo setting em `data`:

  ```json
  {"state":"executed","data":{"id":344164,"name":"hls-segments","browser_cache":{"behavior":"override","max_age":0},"modules":{"cache":{"behavior":"override","max_age":60,"tiered_cache":{"topology":"nearest-region","enabled":true}}}}}
  ```

  </DocStep>
  <DocStep title="Crie o setting da playlist">

  Envie a mesma requisição com `"name": "hls-playlist"` e `"max_age": 5` em `modules.cache`. A resposta carrega o seu próprio `id`.

  </DocStep>
</DocSteps>

Para aplicar cada setting com uma regra:

<DocSteps>
  <DocStep title="Crie a regra dos segmentos">

  Substitua `[CACHE SETTING ID]` pelo `id` do setting `hls-segments`:

  ```bash
  curl --location --request POST 'https://api.azion.com/v4/workspace/applications/{application_id}/request_rules' \
  --header 'Accept: application/json' \
  --header 'Content-Type: application/json' \
  --header 'Authorization: Token [TOKEN VALUE]' \
  --data '{
    "name": "cache-hls-segments",
    "criteria": [[{ "variable": "${uri}", "operator": "matches", "conditional": "if", "argument": ".*.ts" }]],
    "behaviors": [{ "type": "set_cache_policy", "attributes": { "value": "[CACHE SETTING ID]" } }]
  }'
  ```

  </DocStep>
  <DocStep title="Leia a resposta">

  A API responde com HTTP `202` e a regra com `state` igual a `pending`:

  ```json
  {"state":"pending","data":{"id":710871,"name":"cache-hls-segments","active":true,"order":0}}
  ```

  </DocStep>
  <DocStep title="Crie a regra da playlist">

  Envie a mesma requisição com `"name": "cache-hls-playlist"`, o argumento `.*.m3u8` e o `id` do setting `hls-playlist`.

  </DocStep>
</DocSteps>

O stream agora é colocado em cache por tipo de arquivo: cada segmento por 60 segundos, a playlist por 5 segundos.
