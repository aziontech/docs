[Application Accelerator](/pt-br/documentacao/build/application-accelerator/) libera o cache de respostas `POST` e `OPTIONS`, além das requisições `GET` e `HEAD` que uma aplicação armazena em cache nativamente. Você seleciona os métodos em um cache setting a partir de Azion Console e depois aplica esse cache setting com o [Rules Engine](/pt-br/documentacao/plataforma/applications/rules-engine/).

Um objeto `POST` em cache não compartilha a [cache key](/pt-br/documentacao/build/cache/#cache-keys) com a resposta `GET` do mesmo path. A Azion adiciona o método como prefixo à key de qualquer requisição diferente de `GET` ou `HEAD`. Para um objeto `POST` ou `OPTIONS` em cache, a key também acrescenta `@@` e o hash MD5 do corpo da requisição. Uma requisição `OPTIONS` para `https://static.yourdomain.com/page` é armazenada sob a key `optionshttpsstatic.yourdomain.com/page`. Um `POST` para um path dinâmico é armazenado sob `httpsdynamic.yourdomain.com/path@@md5_of_post_arguments`.

Um corpo de `POST` que varia a cada requisição produz, portanto, um objeto em cache por requisição. Para o que uma variação custa, consulte [Como Application Accelerator funciona](/pt-br/documentacao/build/application-accelerator/como-funciona/).

## Pré-requisitos

- Uma aplicação. Para criar uma, consulte [Criar uma aplicação](/pt-br/documentacao/guias/desenvolvimento-de-aplicacoes/primeiros-passos/criar-uma-aplicacao/).
- Acesso a Azion Console. Consulte [Como acessar o Azion Console](/pt-br/documentacao/guias/plataforma/conta-e-billing/como-acessar-o-azion-console/).
- Application Accelerator pode gerar custos relacionados ao uso. Para as tarifas, consulte [Preços](/pt-br/documentacao/fundamentos/precos/#application-accelerator).

---

## Ative Application Accelerator

O módulo vem desativado por padrão, e um cache setting armazena uma resposta `POST` ou `OPTIONS` apenas enquanto o módulo está ativo. Para ativá-lo:

<DocSteps>
  <DocStep title="Abra a aplicação">

  Acesse [Azion Console](https://console.azion.com/) > **Applications** > **sua aplicação**.

  </DocStep>
  <DocStep title="Ative o módulo">

  Na aba **Main Settings**, na seção **Modules**, ative **Application Accelerator**.

  </DocStep>
  <DocStep title="Selecione Save" />
</DocSteps>

A aplicação roda com Application Accelerator, e os cache settings dela podem selecionar os métodos `POST` e `OPTIONS`.

## Armazene em cache as respostas de requisições POST

Uma aplicação serve uma API de busca em `/api/search`. O endpoint responde a uma requisição `POST` cujo corpo carrega os termos da busca, e os resultados mudam a cada 30 segundos. Para armazenar um objeto por corpo e expirá-lo nesse mesmo intervalo:

<DocSteps>
  <DocStep title="Abra a aba Cache Settings">

  Acesse [Azion Console](https://console.azion.com/) > **Applications** > **sua aplicação** e vá para a aba **Cache Settings**.

  </DocStep>
  <DocStep title="Selecione + Cache" />
  <DocStep title="Nomeie o cache setting">

  Em **Name**, digite um nome que identifique o cache setting. Por exemplo: `search-post`.

  </DocStep>
  <DocStep title="Defina o Max Age">

  Em **Cache**, selecione _Override cache behavior_ e defina **Max Age** como `30`.

  </DocStep>
  <DocStep title="Selecione o método POST">

  Em **Application Accelerator**, abra **Cache vary by Method** e marque o checkbox **POST**.

  </DocStep>
  <DocStep title="Selecione Save" />
</DocSteps>

O cache setting aparece na aba **Cache Settings**. Ele armazena a resposta de uma requisição `POST` assim que uma regra o aplica.

**Cache vary by Method** carrega dois checkboxes, **POST** e **OPTIONS**. Para armazenar em cache respostas `OPTIONS`, marque **OPTIONS** no mesmo controle; um cache setting pode carregar os dois métodos. A Azion API define os mesmos métodos com o campo `cache_vary_by_method` de um cache setting, documentado em [Configurações do Application Accelerator](/pt-br/documentacao/build/application-accelerator/configuracoes/).

Um cache setting entra em vigor apenas quando uma regra o aplica. Para aplicar este à URI `/api/search`:

<DocSteps>
  <DocStep title="Vá para a aba Rules Engine" />
  <DocStep title="Selecione + Rule" />
  <DocStep title="Nomeie a regra">

  Digite um nome para a regra. Por exemplo: `search-post rule`.

  </DocStep>
  <DocStep title="Selecione Request Phase" />
  <DocStep title="Selecione a variável na seção Criteria">

  Na seção **Criteria**, selecione a variável `${uri}`.

  </DocStep>
  <DocStep title="Selecione starts with como operador de comparação" />
  <DocStep title="Digite o argumento">

  Digite `/api/search` como argumento.

  </DocStep>
  <DocStep title="Na seção Behaviors, selecione Set Cache Policy" />
  <DocStep title="Selecione o cache setting que você criou" />
  <DocStep title="Selecione Save" />
</DocSteps>

As requisições cuja URI começa com `/api/search` carregam o cache setting. A Azion armazena um objeto por corpo de requisição e mantém cada objeto por 30 segundos. Uma nova regra leva alguns minutos para propagar.

:::note[nota]
Antes de um cache setting selecionar **POST**, uma requisição `POST` não registra status de cache: o header `X-Cache` carrega `-`, porque o conteúdo está restrito de permanecer em cache. Para ler o header em uma requisição, consulte [Verificar indicadores de cache com o ModHeader](/pt-br/documentacao/guias/performance-e-confiabilidade/cache-e-purge/verificar-tempo-de-cache-da-pagina/).
:::

Um objeto `POST` ou `OPTIONS` em cache expira com um purge por cache key que lista cada variação, ou com um purge por wildcard terminado em `@@*`. Para os tipos de purge, consulte [Real-Time Purge](/pt-br/documentacao/build/cache/real-time-purge/#purge-de-application-accelerator).
