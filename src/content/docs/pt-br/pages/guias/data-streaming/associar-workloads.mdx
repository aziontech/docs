Você pode associar [workloads](/pt-br/documentacao/plataforma/workloads/) a um stream do [Data Stream](/pt-br/documentacao/plataforma/data-stream/) pelo Azion Console ou com a Azion API. Para coletar de todos os workloads com sampling em vez de escolhê-los, consulte [Configure sampling em um stream](/pt-br/documentacao/guias/plataforma/observabilidade/configurar-sampling/).

Um stream coleta os logs dos workloads associados a ele e os envia ao endpoint dele. Um stream pode coletar de um único workload ou de vários. Ao contrário do sampling, um filtro de workloads mantém seus outros streams ativos. Para cada campo do filtro, consulte [Configurações do stream](/pt-br/documentacao/plataforma/data-stream/configuracoes-do-stream/#transform).

## Pré-requisitos

- Um ou mais [workloads](/pt-br/documentacao/plataforma/workloads/) na sua conta.
- A permissão **Edit Data Stream**. Para mais informações, consulte [Configurações do stream](/pt-br/documentacao/plataforma/data-stream/configuracoes-do-stream/#permissoes).

<Tabs client:visible sharedStore="interface">

<Fragment slot="panel.console">

- Acesso ao Azion Console. Para entrar, consulte [Como acessar o Azion Console](/pt-br/documentacao/guias/plataforma/conta-e-billing/como-acessar-o-azion-console/).
- Uma conta com menos de 3.000 workloads. Com 3.000 workloads ou mais, o Console bloqueia os formulários de stream e você gerencia os streams apenas pela API.

</Fragment>

<Fragment slot="panel.api">

- Um personal token. Para criar um, consulte [Como criar um personal token](/pt-br/documentacao/guias/plataforma/conta-e-billing/personal-tokens/).
- O ID de cada workload do qual o stream coleta.
- `curl`.

</Fragment>

</Tabs>

## Crie um stream para seus workloads

Você escolhe os workloads no mesmo formulário que define a fonte de dados, o template e o endpoint do stream. O exemplo usa a fonte de dados *Applications*. Os eventos do Activity History pertencem à conta, e não a um workload, então um stream de Activity History usa sampling no lugar do filtro.

<Tabs client:visible sharedStore="interface">

<Fragment slot="panel.console">

Para criar o stream no Azion Console:

<DocSteps>
  <DocStep title="Abra a página Data Stream">

  Acesse [Azion Console](https://console.azion.com/) > **Data Stream**.

  </DocStep>
  <DocStep title="Selecione + Stream" />
  <DocStep title="Dê um nome ao stream">

  Na seção **General**, insira um **Name**. Por exemplo: `workloads-to-http`.

  </DocStep>
  <DocStep title="Selecione a fonte de dados">

  Na seção **Input**, selecione *Applications* em **Data Source**. Para as outras fontes de dados, consulte [Fontes de dados e variáveis](/pt-br/documentacao/plataforma/data-stream/fontes-de-dados-e-variaveis/).

  </DocStep>
  <DocStep title="Desative Sampling">

  Na seção **Transform**, **Option** começa em *All Current and Future Workloads*, com **Sampling** ativado. Desative **Sampling** antes de alterar **Option**, para que o stream não tenha sampling.

  *All Current and Future Workloads* cobre todos os workloads da conta, incluindo os que você criar depois. Um stream salvo com **Sampling** ativado desativa todos os outros streams da conta.

  </DocStep>
  <DocStep title="Escolha Filter Workloads">

  Defina **Option** como *Filter Workloads*. A lista de seleção **Workloads** se abre. Em algumas contas, os valores são *All Current and Future Domains* e *Filter Domains*.

  </DocStep>
  <DocStep title="Mova os workloads para Chosen Workload">

  Use os controles da lista de seleção:

  - Para encontrar um workload em **Available Workload**, insira caracteres na caixa de busca ou role a lista.
  - Para mover um workload para **Chosen Workload**, selecione-o e depois selecione a seta `>`.
  - Para mover vários de uma vez, selecione-os com `ctrl` no Windows e no Linux ou `command` no Mac e depois selecione `>`.
  - Para mover todos os workloads que a lista mostra, selecione `>>`.
  - Para remover workloads de **Chosen Workload**, selecione-os e depois selecione `<`. Para remover todos, selecione `<<`.

  </DocStep>
  <DocStep title="Selecione o template">

  Na seção **Render Template**, selecione *Applications Event Collector* em **Template**. Para os outros templates, consulte [Templates e payload](/pt-br/documentacao/plataforma/data-stream/templates-e-payload/#templates-predefinidos).

  </DocStep>
  <DocStep title="Defina o endpoint">

  Na seção **Output**, selecione seu endpoint no campo rotulado **Connector** e preencha os campos dele. Para os campos de cada endpoint, consulte [Endpoints](/pt-br/documentacao/plataforma/data-stream/endpoints/).

  </DocStep>
  <DocStep title="Mantenha o stream ativo">

  Na seção **Status**, mantenha **Active** ativado.

  </DocStep>
  <DocStep title="Selecione Save" />
  <DocStep title="Cancele o aviso de sampling">

  Se a caixa de diálogo **Attention** abrir, **Sampling** ainda está ativado. Selecione **Cancel**, defina **Option** de volta como *All Current and Future Workloads* e desative **Sampling**. Defina **Option** como *Filter Workloads* de novo, confirme que seus workloads estão em **Chosen Workload** e selecione **Save**.

  </DocStep>
</DocSteps>

O Console mostra `Your data stream has been created`, e a lista **Data Stream** mostra o stream com o status *Active*.

</Fragment>

<Fragment slot="panel.api">

Para criar o stream com a API, envie uma requisição `POST` com um item `filter_workloads` em `transform`. Substitua `[TOKEN VALUE]` pelo seu personal token, `<workload-id>` pelo ID do seu workload e os valores do endpoint pelos seus:

```bash
curl -X POST 'https://api.azion.com/v4/workspace/stream/streams' \
  -H 'Content-Type: application/json' \
  -H 'Authorization: Token [TOKEN VALUE]' \
  -d '{
    "name": "workloads-to-http",
    "active": true,
    "inputs": [
      { "type": "raw_logs", "attributes": { "data_source": "workloads" } }
    ],
    "transform": [
      { "type": "filter_workloads", "attributes": { "workloads": [<workload-id>] } },
      { "type": "render_template", "attributes": { "template": 2 } }
    ],
    "outputs": [
      {
        "type": "standard",
        "attributes": {
          "url": "https://logs.example.com/ingest",
          "headers": { "Authorization": "Bearer [TOKEN]" }
        }
      }
    ]
  }'
```

A fonte de dados `workloads` é *Applications* no Console, e o template `2` é *Applications Event Collector*. Para coletar de vários workloads, liste os IDs deles em `workloads`, de 1 a 600. A API responde `201` com o stream armazenado:

```json
{
  "state": "executed",
  "data": {
    "id": 19555,
    "name": "workloads-to-http",
    "last_editor": "user@example.com",
    "created": "2026-10-02T19:55:22.174134Z",
    "last_modified": "2026-10-02T19:55:22.174111Z",
    "product_version": "1.0",
    …
    "transform": [
      { "type": "filter_workloads", "attributes": { "workloads": [<workload-id>] } },
      { "type": "render_template", "attributes": { "template": 2 } }
    ],
    …
  }
}
```

O array `transform` contém o filtro de workloads que você enviou. Um ID que não é um workload da sua conta é recusado com `400`:

```json
{"errors":[{"code":"32003","title":"Workloads Not Belong Account","detail":"Workloads [1] do not belong to the account.","status":"400","source":{"pointer":"/data/transform/0/attributes/workloads"},"meta":{"invalid_workloads":[1]}}]}
```

A API não tem opção para todos os workloads. Um stream sem `filter_workloads` precisa de um item `sampling`, e salvá-lo desativa todos os outros streams da conta. Para esse caminho, consulte [Configure sampling em um stream](/pt-br/documentacao/guias/plataforma/observabilidade/configurar-sampling/).

</Fragment>

</Tabs>

O stream é salvo sem contatar o endpoint, e uma ativação entra em vigor após um a dois minutos.

## Confirme a entrega

[Real-Time Events](/pt-br/documentacao/plataforma/real-time-events/#data-stream) registra cada envio de um stream, entregue ou não, com o status code que o endpoint retornou. Envie algumas requisições a um workload escolhido e aguarde cerca de um minuto.

<Tabs client:visible sharedStore="interface">

<Fragment slot="panel.console">

Para encontrar os envios no Azion Console:

<DocSteps>
  <DocStep title="Abra a página Real-Time Events">

  Acesse [Azion Console](https://console.azion.com/) > **Real-Time Events**.

  </DocStep>
  <DocStep title="Selecione a fonte de dados Data Stream" />
  <DocStep title="Leia os envios mais recentes">

  Cada linha é um envio. Leia **Endpoint Type**, **Status Code** e **Streamed Lines** dela.

  </DocStep>
</DocSteps>

Um **Status Code** `200` significa que o endpoint aceitou o lote.

</Fragment>

<Fragment slot="panel.api">

Para ler os envios com a API, consulte o dataset `dataStreamedEvents` da API GraphQL do Real-Time Events. Substitua as datas por um intervalo que cubra a ativação do stream:

```bash
curl -X POST 'https://api.azion.com/v4/events/graphql' \
  -H 'Content-Type: application/json' \
  -H 'Authorization: Token [TOKEN VALUE]' \
  -d '{"query":"query { dataStreamedEvents(limit: 20, filter: {tsRange: {begin: \"2026-10-02T19:45:00\", end: \"2026-10-02T20:30:00\"}}, orderBy: [ts_DESC]) { ts endpointType statusCode streamedLines dataStreamed } }"}'
```

A API responde `200` com um registro para cada envio, o mais recente primeiro:

```json
{
  "data": {
    "dataStreamedEvents": [
      {
        "ts": "2026-10-02T19:47:04Z",
        "endpointType": "S3",
        "statusCode": 200,
        "streamedLines": 2,
        "dataStreamed": 2797
      }
    ]
  }
}
```

Nesse registro, um endpoint S3 aceitou um lote de 2 linhas de log com o status `200`. Uma lista `dataStreamedEvents` vazia significa que o stream não enviou nada no intervalo.

</Fragment>

</Tabs>

Um status diferente de `200` é a resposta do endpoint, e `503` significa que Data Stream encontrou o endpoint indisponível. Para as causas, consulte [Solucionar problemas de Data Stream](/pt-br/documentacao/plataforma/data-stream/solucao-de-problemas/).
