Você pode enviar as mensagens de log das suas functions para um endpoint com um stream do [Data Stream](/pt-br/documentacao/plataforma/data-stream/), pelo Azion Console ou pela Azion API. Para rastrear quais regras do Rules Engine rodaram em uma requisição, consulte [Depure regras criadas com Rules Engine](/pt-br/documentacao/guias/desenvolvimento-de-aplicacoes/primeiros-passos/debug-regras/).

Uma function escreve mensagens de log com `console.log`. A fonte de dados *Functions* traz cada mensagem com o nível, a origem e o ID da requisição, e o template *Functions Event Collector* coloca cada mensagem em uma linha de log própria. Para conhecer todas as variáveis da fonte de dados, consulte [Fontes de dados e variáveis](/pt-br/documentacao/plataforma/data-stream/fontes-de-dados-e-variaveis/#functions).

## Pré-requisitos

- Uma conta Azion com a permissão **Edit Data Stream**. Para as permissões, consulte [Configurações do stream](/pt-br/documentacao/plataforma/data-stream/configuracoes-do-stream/#permissoes).
- Uma function que escreve mensagens de log com `console.log`, rodando em uma aplicação servida por um [workload](/pt-br/documentacao/plataforma/workloads/). Para criar uma, consulte [Functions](/pt-br/documentacao/plataforma/functions/).
- Um endpoint que recebe as linhas de log, como um endpoint HTTP. Para os endpoints aos quais um stream pode enviar, consulte [Endpoints](/pt-br/documentacao/plataforma/data-stream/endpoints/).

## Crie o stream

O stream lê a fonte de dados *Functions* de um workload por meio de um filtro de workloads. Diferente de sampling, um filtro de workloads mantém seus outros streams ativos.

<Tabs client:visible sharedStore="interface">

<Fragment slot="panel.console">

Para criar o stream no Azion Console:

<DocSteps>
  <DocStep title="Abra Data Stream">

  Acesse [Azion Console](https://console.azion.com/) > **Data Stream**.

  </DocStep>
  <DocStep title="Selecione + Stream" />
  <DocStep title="Dê um nome ao stream">

  Na seção **General**, insira um **Name**. Por exemplo: `functions-debug`.

  </DocStep>
  <DocStep title="Selecione a fonte de dados Functions">

  Na seção **Input**, selecione *Functions* em **Data Source**.

  </DocStep>
  <DocStep title="Desative Sampling">

  Na seção **Transform**, desative **Sampling** enquanto **Option** ainda está em *All Current and Future Workloads*, o valor inicial. Um stream não pode ter sampling e um filtro de workloads ao mesmo tempo.

  </DocStep>
  <DocStep title="Escolha o workload">

  Na seção **Transform**, defina **Option** como *Filter Workloads*. Em **Available Workload**, selecione o workload da function e mova-o para **Chosen Workload** com a seta. Para os controles da lista de seleção, consulte [Associe workloads a um stream](/pt-br/documentacao/guias/plataforma/observabilidade/data-stream-associar-workloads/).

  </DocStep>
  <DocStep title="Selecione o template">

  Na seção **Render Template**, selecione *Functions Event Collector* em **Template**. O campo **Data Set** mostra as chaves de cada linha de log.

  </DocStep>
  <DocStep title="Selecione o endpoint">

  Na seção **Output**, selecione seu endpoint em **Connector** e preencha os campos que ele mostra. Cada endpoint tem os próprios campos, listados em [Endpoints](/pt-br/documentacao/plataforma/data-stream/endpoints/).

  </DocStep>
  <DocStep title="Mantenha o stream ativo">

  Na seção **Status**, mantenha **Active** ativado.

  </DocStep>
  <DocStep title="Selecione Save" />
</DocSteps>

O Console mostra `Your data stream has been created`. O stream aparece na lista **Data Stream** com `functions_console` na coluna **Source** e o status *Active*.

</Fragment>

<Fragment slot="panel.api">

Para criar o stream com a API, envie uma requisição `POST` para `https://api.azion.com/v4/workspace/stream/streams`. Este exemplo envia as linhas de log para um endpoint HTTP. Substitua `<workload-id>` pelo ID do seu workload, e a `url` e o header pelos valores do seu endpoint:

```bash
curl -X POST 'https://api.azion.com/v4/workspace/stream/streams' \
  -H 'Content-Type: application/json' \
  -H 'Authorization: Token [TOKEN VALUE]' \
  -d '{
    "name": "functions-debug",
    "active": true,
    "inputs": [
      { "type": "raw_logs", "attributes": { "data_source": "functions_console" } }
    ],
    "transform": [
      { "type": "filter_workloads", "attributes": { "workloads": [<workload-id>] } },
      { "type": "render_template", "attributes": { "template": 86 } }
    ],
    "outputs": [
      {
        "type": "standard",
        "attributes": {
          "url": "https://logs.example.com/ingest",
          "headers": { "Authorization": "Bearer [API KEY]" }
        }
      }
    ]
  }'
```

A fonte de dados `functions_console` é *Functions* no Console, e o template `86` é *Functions Event Collector*. Uma resposta `201` traz o stream armazenado em `data`. Guarde o `id` dele: ele identifica o stream em todas as requisições seguintes, como `/v4/workspace/stream/streams/<stream-id>`. Para todas as chaves do corpo, consulte [Configurações do stream](/pt-br/documentacao/plataforma/data-stream/configuracoes-do-stream/#objeto-do-stream).

</Fragment>

</Tabs>

Salvar o stream verifica o formato de cada campo e não contata o endpoint. Uma URL ou uma credencial errada só aparece quando o stream envia. Uma ativação passa a valer depois de um a dois minutos.

## Confirme a entrega

[Real-Time Events](/pt-br/documentacao/plataforma/real-time-events/#data-stream) registra cada envio de um stream, entregue ou não, com o status code que o endpoint retornou. Envie algumas requisições que executam a function e aguarde cerca de um minuto: um stream envia um lote a cada 60 segundos, ou antes, quando chega a 2.000 linhas de log.

<Tabs client:visible sharedStore="interface">

<Fragment slot="panel.console">

Para encontrar os envios no Azion Console:

<DocSteps>
  <DocStep title="Abra Real-Time Events">

  Acesse [Azion Console](https://console.azion.com/) > **Real-Time Events**.

  </DocStep>
  <DocStep title="Selecione a fonte de dados Data Stream" />
  <DocStep title="Leia os envios mais recentes">

  Cada linha é um envio. Encontre as linhas cujo **Endpoint Type** corresponde ao seu endpoint, como `HTTP_POST`, e leia o **Status Code** delas.

  </DocStep>
</DocSteps>

Um **Status Code** `200` significa que o endpoint aceitou o lote. **Streamed Lines** informa o número de linhas de log do lote.

</Fragment>

<Fragment slot="panel.api">

Para ler os envios com a API, consulte o dataset `dataStreamedEvents` da GraphQL API do Real-Time Events. Substitua as datas por um intervalo que inclua a ativação do stream:

```bash
curl -X POST 'https://api.azion.com/v4/events/graphql' \
  -H 'Content-Type: application/json' \
  -H 'Authorization: Token [TOKEN VALUE]' \
  -d '{"query":"query { dataStreamedEvents(limit: 20, filter: {tsRange: {begin: \"2026-10-02T19:25:00\", end: \"2026-10-02T19:45:00\"}}, orderBy: [ts_DESC]) { ts jobName endpointType statusCode streamedLines url } }"}'
```

A API responde `200` com um registro para cada envio, do mais recente para o mais antigo:

```json
{
  "data": {
    "dataStreamedEvents": [
      {
        "ts": "2026-10-02T19:29:00Z",
        …
        "endpointType": "HTTP_POST",
        "statusCode": 405,
        "streamedLines": 2,
        "url": "https://example.com/logs"
      },
      …
    ]
  }
}
```

Nesse registro, um endpoint HTTP recusou um lote de 2 linhas de log com o status `405`. Um `statusCode` `200` significa que o endpoint aceitou o lote, e uma lista `dataStreamedEvents` vazia significa que o stream não enviou nada no intervalo. Para todos os campos, consulte [Campos da API GraphQL do Real-Time Events](/pt-br/documentacao/devtools/graphql/campos-gql-real-time-events/#datastreamedevents-data-stream).

</Fragment>

</Tabs>

Um status diferente de `200` é a resposta do endpoint, e `503` significa que Data Stream encontrou o endpoint indisponível. Para as causas, consulte [Solucionar problemas de Data Stream](/pt-br/documentacao/plataforma/data-stream/solucao-de-problemas/).

No endpoint, cada linha de log traz as chaves do template *Functions Event Collector*. Leia estas chaves para depurar a function:

- `logLevel` contém o nível da mensagem: `ERROR`, `WARN`, `INFO`, `DEBUG` ou `TRACE`. Ela traz a variável `$log_level`.
- `logMessage` contém a mensagem que a function passou para a função de log. Ela traz a variável `$log_message`.
- `messageSource` mostra `CONSOLE` para uma mensagem escrita com a console API, como `console.log`, e `RUNTIME` para uma mensagem de erro.
- `requestID` identifica a requisição, então as mensagens de uma mesma requisição compartilham esse valor.

Para manter os nomes das variáveis como chaves, ou para enviar menos variáveis, selecione um template personalizado. Para um exemplo de data set, consulte [Templates e payload](/pt-br/documentacao/plataforma/data-stream/templates-e-payload/#templates-personalizados).
