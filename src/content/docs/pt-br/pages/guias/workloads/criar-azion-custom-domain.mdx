Você pode dar a um [workload](/pt-br/documentacao/plataforma/workloads/) um hostname gratuito sob `azion.app` pelo Azion Console, pela [Azion CLI](/pt-br/documentacao/devtools/cli/) ou pela API. Para atender um domínio seu, como `www.example.com`, consulte [Adicione um domínio a um workload](/pt-br/documentacao/guias/plataforma/migracao/configurar-dominio/).

O Azion custom domain é um hostname que você escolhe, no formato `<your-name>.azion.app`, como `my-custom-name.azion.app`. Ele é diferente do workload domain, o hostname `<id>.map.azionedge.net` que a Azion gera ao criar o workload. O workload armazena o Azion custom domain como uma entrada dos seus domínios, ao lado de qualquer domínio seu. O Azion custom domain está disponível sem custo adicional.

## Pré-requisitos

- Um workload na infraestrutura de produção cujo deployment nomeia uma aplicação. Um workload de staging não aceita Azion custom domain. Para criar o workload e o deployment dele, consulte [Primeiros passos com Workloads](/pt-br/documentacao/plataforma/workloads/primeiros-passos/).
- Um nome que nenhum outro workload carrega sob `azion.app`.

## Adicione o Azion custom domain ao workload

O workload responde no Azion custom domain assim que o hostname completo está nos domínios dele. Você escolhe apenas o nome: o sufixo `.azion.app` é fixo.

<Tabs client:visible sharedStore="interface">

<Fragment slot="panel.console">

No Azion Console, a seção **Domains** do formulário do workload contém o switch **Custom Domain**, descrito como "You can use an free azion.app domain." O formulário **Create Workload** traz o mesmo switch e o mesmo campo, então você também pode definir o nome ao criar um workload.

Para adicionar o Azion custom domain a um workload existente:

<DocSteps>
  <DocStep title="Abra a página Workloads">

  Acesse [Azion Console](https://console.azion.com/) > **Workloads**.

  </DocStep>
  <DocStep title="Abra o workload">

  Selecione o workload de produção. O formulário de edição dele abre.

  </DocStep>
  <DocStep title="Ative Custom Domain">

  Na seção **Domains**, ative **Custom Domain**. O campo **Azion Custom Domain** aparece.

  </DocStep>
  <DocStep title="Digite o nome">

  Em **Azion Custom Domain**, digite o nome, como `my-custom-name`. O campo acrescenta `.azion.app`.

  </DocStep>
  <DocStep title="Salve o workload">

  Selecione **Save**.

  </DocStep>
</DocSteps>

Azion Console mostra "Your workload has been updated". O workload lista `<your-name>.azion.app` nos domínios dele.

</Fragment>

<Fragment slot="panel.cli">

Para adicionar o Azion custom domain com a Azion CLI, salve um arquivo JSON com o ID do workload e a lista `domains`, aqui como `azion-app.json`. Mantenha na mesma lista todos os domínios que o workload já lista:

```json
{
  "id": <workload-id>,
  "domains": ["<your-name>.azion.app"]
}
```

Atualize o workload com o arquivo:

```bash
azion update workload --file azion-app.json
```

O comando imprime o ID do workload atualizado:

```text
Updated Workload with ID <workload-id>
```

Para confirmar a alteração, descreva o workload:

```bash
azion describe workload --workload-id <workload-id> --format json
```

Este trecho da saída lista o Azion custom domain em `domains`, separado do workload domain:

```json
{
 "domains": ["<your-name>.azion.app"],
 …
 "workload_domain": "<id>.map.azionedge.net"
}
```

</Fragment>

<Fragment slot="panel.api">

Para adicionar o Azion custom domain com a API, envie uma requisição `PATCH` para o workload. Mantenha na mesma lista `domains` todos os domínios que o workload já lista:

```bash
curl --request PATCH \
  --url https://api.azion.com/v4/workspace/workloads/<workload-id> \
  --header 'Accept: application/json' \
  --header 'Authorization: Token [TOKEN VALUE]' \
  --header 'Content-Type: application/json' \
  --data '{
  "domains": ["<your-name>.azion.app"]
}'
```

A API aceita a atualização, e o workload passa a listar `<your-name>.azion.app` em `domains`.

</Fragment>

</Tabs>

A API armazena o nome com a caixa que você envia, então `My-Site.azion.app` é lido de volta como `My-Site.azion.app`. A alteração é recusada em quatro casos, cada um com a sua mensagem:

- **Um segundo hostname `azion.app` no mesmo workload.** Um workload carrega um só, quer a lista repita um nome, quer traga dois nomes: `Duplicated usage of suffix in alternate_domains: 'azion.app'.`
- **Um nome que outro workload carrega.** Um nome `azion.app` pertence a um workload e não é compartilhado entre contas ou configurações: `The custom hostname is not available.`
- **Um nome wildcard**, como `*.azion.app`: `The domain does not conform to the format defined in RFC 1035.`
- **Um workload de staging.** O Console desativa o switch **Custom Domain** e o torna indisponível, e a CLI e a API retornam `Custom hostname is not available in the environment 'Staging Infrastructure'.`

Para as causas e as correções, consulte [Solucionar problemas de Workloads](/pt-br/documentacao/plataforma/workloads/solucao-de-problemas/).

## Abra o Azion custom domain

O Azion custom domain não precisa de nenhum registro DNS seu nem de nenhum certificado seu. Com `tls.certificate` definido como `null`, o padrão, o workload atende HTTPS com o certificado SAN da Azion, que cobre o Azion custom domain e o workload domain. Para mais informações, consulte [Como Workloads funciona](/pt-br/documentacao/plataforma/workloads/como-funciona/).

Uma alteração no workload leva vários minutos para chegar a toda a infraestrutura distribuída da Azion. Até a alteração chegar, uma requisição para `https://<your-name>.azion.app` responde `404` com a página de erro HTML da Azion. As requisições podem receber a configuração antiga ou a nova por um tempo, então repita a requisição até as respostas coincidirem.

Depois que a alteração se propaga, uma requisição para `https://<your-name>.azion.app` chega à aplicação no deployment do workload e retorna a resposta dela, como `200`.
