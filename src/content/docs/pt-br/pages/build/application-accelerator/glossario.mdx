Definições dos termos usados na documentação de [Application Accelerator](/pt-br/documentacao/build/application-accelerator/).

| Termo | Definição |
| --- | --- |
| Advanced Cache Key | O recurso que varia a cache key por partes de uma requisição além da URL. Application Accelerator o libera, e os quatro controles **Cache vary by** de um [cache setting](/pt-br/documentacao/build/application-accelerator/configuracoes/#cache-variation) o configuram. |
| allowlist | O valor de `behavior` que varia a cache key apenas pelos atributos que um [cache setting](/pt-br/documentacao/build/application-accelerator/configuracoes/#cache-variation) nomeia, ignorando todos os demais que chegam. Azion Console o apresenta como _Allowlist_. É o controle sobre quantos objetos uma variação cria, porque um atributo que ninguém nomeia não gera outro objeto. |
| Application Accelerator | O módulo de [Applications](/pt-br/documentacao/plataforma/applications/) que coloca o restante de uma requisição na cache key. Um switch por aplicação libera a variação de cache, o cache de respostas `POST` e `OPTIONS`, um cache TTL abaixo de 60 segundos e sete behaviors do [Rules Engine](/pt-br/documentacao/plataforma/applications/rules-engine/). |
| Bypass Cache | O behavior do Rules Engine que envia à origem todas as requisições que correspondem à regra e não armazena nada em cache. Exige Application Accelerator, não altera o cache do navegador e não equivale a um cache TTL de 0 segundos. [Como Application Accelerator funciona](/pt-br/documentacao/build/application-accelerator/como-funciona/) expõe a diferença. |
| cache key | A entrada de índice sob a qual o cache armazena um objeto. Azion a constrói a partir do scheme, do host, do path e da query string da requisição, e uma variação acrescenta um separador e aquilo que varia. O formato e tudo o que ela carrega pertencem a [Cache](/pt-br/documentacao/build/cache/cache-keys/#formato-da-key). |
| cache setting | O objeto que guarda por quanto tempo o cache mantém uma resposta e o que torna duas requisições diferentes. Pertence a uma aplicação, e só alcança uma requisição quando uma regra **Set Cache Policy** o aplica. Os campos dele estão em [Configurações](/pt-br/documentacao/build/application-accelerator/configuracoes/). |
| Cache vary by Cookies | O controle que varia a cache key pelo valor de cookies nomeados. Carrega um `behavior` e a lista de nomes de cookie aos quais o behavior se aplica. |
| Cache vary by Devices | O controle que varia a cache key por [device group](/pt-br/documentacao/plataforma/applications/device-groups/). Carrega um `behavior` e a lista de device groups aos quais o behavior se aplica. |
| Cache vary by Method | O controle que nomeia os métodos de requisição cujas respostas são armazenadas em cache. Aceita `POST`, `OPTIONS` ou ambos, e nada além disso. |
| Cache vary by Query String | O controle que varia a cache key por argumentos de query string nomeados. Carrega um `behavior`, a lista de argumentos e **Sort**. |
| denylist | O valor de `behavior` que varia a cache key por todos os atributos que chegam, exceto os que um [cache setting](/pt-br/documentacao/build/application-accelerator/configuracoes/#cache-variation) nomeia. Azion Console o apresenta como _Denylist_. |
| device group | Um conjunto de dispositivos que uma aplicação reconhece, definido em [Device Groups](/pt-br/documentacao/plataforma/applications/device-groups/). Application Accelerator pode variar a cache key por device group, e a variável `${device_group}` em uma regra do Rules Engine exige o módulo. |
| Forward Cookies | O behavior do Rules Engine que envia ao usuário o header `Set-Cookie` da origem mesmo quando a resposta vem do cache. Exige Application Accelerator. |
| Max Age | O rótulo em Azion Console para o tempo que o cache mantém um objeto, em segundos. O campo é `modules.cache.max_age`, e o piso que ele alcança depende de quais módulos estão ativados, conforme [Limites](/pt-br/documentacao/build/application-accelerator/limites/). |
| requisição complexa | Uma requisição que usa qualquer método diferente de `GET` ou `HEAD`. Azion prefixa o método à cache key de uma requisição complexa, de modo que uma resposta `OPTIONS` e uma resposta `GET` de um mesmo path são objetos separados. |
| Set Cache Policy | O behavior do Rules Engine que aplica um cache setting às requisições que correspondem a uma regra. Não exige Application Accelerator, e é assim que todo cache setting alcança uma requisição. |
| Sort | O controle que agrupa os mesmos argumentos de query string sob uma única cache key, em qualquer ordem que cheguem. Sem ele, `?a=1&b=2` e `?b=2&a=1` são dois objetos que guardam uma mesma resposta, e com ele um purge por URL precisa enviar os argumentos em ordem alfabética. |
