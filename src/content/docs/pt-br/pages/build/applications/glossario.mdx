[Applications](/pt-br/documentacao/plataforma/applications/) e os Produtos habilitados em uma aplicação, [Cache](/pt-br/documentacao/plataforma/applications/#cache), [Application Accelerator](/pt-br/documentacao/plataforma/applications/#application-accelerator) e [Image Processor](/pt-br/documentacao/plataforma/applications/#image-processor), usam cada termo desta tabela em um sentido próprio.

| Termo | Definição |
| --- | --- |
| ação | O nome que outras plataformas dão ao que uma regra faz com uma requisição a que corresponde, e que uma aplicação chama de behavior. Uma regra que encaminha por path em outro lugar se transfere com a condição de correspondência como critérios, a ação como behaviors e o servidor de backend como um connector. [Rules Engine para Applications](/pt-br/documentacao/plataforma/applications/rules-engine/#behaviors) lista cada behavior. |
| Add Request Header | O behavior do [Rules Engine para Applications](/pt-br/documentacao/plataforma/applications/rules-engine/) que adiciona um header na forma `Field: value` à requisição, na **Request Phase**, `add_request_header` na API. Uma requisição que Image Processor converte para WEBP precisa carregar `Accept: image/webp`, e este behavior o adiciona. A API recusa o nome `add_header` com `10039 Invalid Choice`. |
| Advanced Cache Key | O recurso que varia a cache key por partes de uma requisição além da URL: a query string, os cookies, os device groups e o método da requisição. Ele exige Application Accelerator na aplicação, e um cache setting o configura por meio dos seus quatro controles **Cache vary by**. Azion Console não dá o nome dele a nenhum controle: os controles ficam na seção **Application Accelerator** do cache setting, que [Configurações do Application Accelerator](/pt-br/documentacao/plataforma/applications/application-accelerator/configuracoes/#cache-variation) documenta. |
| allowlist | O valor do campo `behavior` de um controle **Cache vary by** que varia a cache key só pelos atributos que o cache setting nomeia e ignora todos os outros que a requisição carrega. O dropdown **Behavior** de Azion Console o mostra como _Allowlist_. Ele limita quantos objetos uma variação cria, porque um atributo que o setting não nomeia não produz mais nenhum objeto; [Configurações do Application Accelerator](/pt-br/documentacao/plataforma/applications/application-accelerator/configuracoes/#cache-variation) lista os valores que cada controle aceita. |
| aplicação | Uma instância de Applications, o recurso de plataforma que contém a lógica que um workload executa sobre as suas requisições, definida nas abas **Main Settings**, **Device Groups**, **Cache Settings**, **Functions Instances** e **Rules Engine**. Uma nova aplicação começa com Cache e Functions ativos, Application Accelerator e Image Processor desativados e nenhuma regra. Um [workload](/pt-br/documentacao/plataforma/workloads/) a seleciona no campo **Application** das suas **Deployment Settings**, a API a serve em `/v4/workspace/applications`, e [Applications](/pt-br/documentacao/plataforma/applications/) documenta o recurso. |
| Application Accelerator | O Produto habilitado em uma aplicação que coloca o restante de uma requisição na cache key. O seu switch, **Application Accelerator** em **Main Settings** › **Modules**, fica desativado em uma nova aplicação e libera a variação de cache, o cache de respostas `POST` e `OPTIONS`, um **Max Age** menor que 60 segundos, sete behaviors do Rules Engine e as variáveis `${request_uri}` e `${device_group}`. [Applications](/pt-br/documentacao/plataforma/applications/#application-accelerator) o descreve, e [Como Applications funciona](/pt-br/documentacao/plataforma/applications/como-funciona/#application-accelerator) acompanha uma requisição por ele. |
| behavior | A ação que uma regra executa sobre as requisições às quais os seus critérios correspondem, como **Set Cache Policy**, **Set Connector** ou **Run Function**. Uma regra executa os seus behaviors na ordem em que os lista, um behavior finalizador interrompe todo behavior e toda regra depois dele, e [Rules Engine para Applications](/pt-br/documentacao/plataforma/applications/rules-engine/) nomeia o Produto que cada behavior exige. Em um cache setting, `behavior` também é o campo de cada controle **Cache vary by**, com os valores `ignore`, `all`, `allowlist` e `denylist`. |
| Bypass Cache | O behavior do [Rules Engine para Applications](/pt-br/documentacao/plataforma/applications/rules-engine/#bypass-cache) que envia à origem cada requisição à qual a sua regra corresponde e mantém a resposta fora do cache da Azion, `bypass_cache` na API. Ele roda na **Request Phase**, exige Application Accelerator, deixa o browser cache a cargo de **Set Cache Policy** e difere de um TTL de 0 segundos, como [Como Applications funciona](/pt-br/documentacao/plataforma/applications/como-funciona/#application-accelerator) explica. Ele não alcança [Tiered Cache](/pt-br/documentacao/plataforma/applications/cache/tiered-cache/#bypass-cache): uma aplicação com cache settings de Tiered Cache ativos continua armazenando objetos nessa camada pelo TTL mínimo. |
| Cache | O Produto habilitado em uma aplicação que armazena cópias de respostas na infraestrutura distribuída da Azion e responde a requisições posteriores a partir delas. O seu switch em **Main Settings** › **Modules** traz o texto de ajuda "Automatically enabled in all accounts.", e uma nova aplicação informa `modules.cache.enabled` como `true`. [Applications](/pt-br/documentacao/plataforma/applications/#cache) o descreve, e [Como Applications funciona](/pt-br/documentacao/plataforma/applications/como-funciona/#cache) acompanha uma requisição por ele. |
| cache key | A entrada de índice sob a qual Cache armazena um objeto, com diferenciação entre maiúsculas e minúsculas. No Cache, a configuração padrão ignora a query string, então a key concatena o scheme, o host e o path, como em `httpsstatic.example.com/page/site.js`, e cada variação acrescenta algo a ela: um prefixo de método, os argumentos de query string que um setting nomeia ou um valor depois do separador `@@`. No Image Processor, o cache setting que serve imagens nomeia `ims` na sua allowlist de query string, e uma imagem convertida carrega o seu formato depois de `@@`; [Cache keys](/pt-br/documentacao/plataforma/applications/cache/cache-keys/#formato-da-key) documenta cada forma. |
| cache setting | O objeto, criado com **+ Cache** na aba **Cache Settings** de uma aplicação, que define por quanto tempo o cache da Azion e o navegador mantêm uma resposta e o que torna duas requisições diferentes. As suas seções **Browser Cache** e **Cache** trazem **Max Age**, **Stale cache**, **Large file optimization** e **Tiered Cache**, e a sua seção **Application Accelerator** traz os quatro controles **Cache vary by**. Ele pertence a uma aplicação e não se aplica a nenhuma requisição até que uma regra com **Set Cache Policy** o nomeie; [Cache settings](/pt-br/documentacao/plataforma/applications/cache/cache-settings/) documenta cada campo. |
| Cache vary by Cookies | O controle do cache setting que varia a cache key pelo valor de cookies nomeados, `cache_vary_by_cookies` na API. Ele traz um `behavior` e, em `cookie_names`, a lista de cookies a que o behavior se aplica. |
| Cache vary by Devices | O controle do cache setting que varia a cache key por [device group](/pt-br/documentacao/plataforma/applications/device-groups/), `cache_vary_by_devices` na API. Ele traz um **Behavior**, com as opções _Allowlist_, _Denylist_, _Ignore_ e _All_ em Azion Console, e, em `device_group`, a lista de device groups a que o behavior se aplica. |
| Cache vary by Method | O controle do cache setting que nomeia os métodos de requisição cujas respostas a Azion coloca em cache, `cache_vary_by_method` na API e vazio por padrão. Ele aceita `POST`, `OPTIONS` ou os dois, enviados como `post` e `options`, e nada além disso. Sem Application Accelerator na aplicação, a API recusa um valor com `21013`. |
| Cache vary by Query String | O controle do cache setting que varia a cache key por argumentos de query string nomeados, `cache_vary_by_querystring` na API. Ele traz um **Behavior**, os **Fields** a que o behavior se aplica, um por linha em Azion Console, e **Sort**. |
| condição de correspondência | O nome que outras plataformas dão ao teste que decide se uma regra age sobre uma requisição, e que uma aplicação chama de critério. Os critérios se combinam com `and` e `or`, e [Rules Engine para Applications](/pt-br/documentacao/plataforma/applications/rules-engine/#criterios) lista cada variável e operador. |
| connector | O objeto para o qual uma aplicação envia requisições para que elas cheguem à sua origem, criado em [Connectors](/pt-br/documentacao/plataforma/connectors/), o recurso de plataforma que assumiu as configurações antes feitas em **Origins**. Uma regra com o behavior **Set Connector** o seleciona pelo ID. Um connector pode alcançar várias origens e distribuir o tráfego entre elas por meio de [Load Balancer](/pt-br/documentacao/plataforma/connectors/load-balancer/). |
| critério | Uma condição única dentro de uma regra: uma variável como `${uri}`, um operador de comparação e um argumento quando o operador aceita um, enviados na API como `variable`, `operator`, `conditional` e `argument`. Os critérios se combinam com `and` e `or`, `and` tem precedência implícita, e a API os carrega como um array de grupos, `[[{...}]]`. [Rules Engine para Applications](/pt-br/documentacao/plataforma/applications/rules-engine/) lista cada variável e operador. |
| Debug Rules | A seção de **Main Settings** que registra as regras do Rules Engine que cada requisição executou, `debug` na API e desativada em uma nova aplicação. Com ela ativa, as regras executadas aparecem no campo `$traceback` em Data Stream e em [Real-Time Events](/pt-br/documentacao/plataforma/real-time-events/), e na variável `$stacktrace` na API GraphQL. Para ler esses logs, consulte [Depure regras criadas com Rules Engine](/pt-br/documentacao/guias/desenvolvimento-de-aplicacoes/primeiros-passos/debug-regras/). |
| denylist | O valor do campo `behavior` de um controle **Cache vary by** que varia a cache key por todos os atributos que a requisição carrega, exceto os que o cache setting nomeia. O dropdown **Behavior** o mostra como _Denylist_, e [Configurações do Application Accelerator](/pt-br/documentacao/plataforma/applications/application-accelerator/configuracoes/#cache-variation) lista os controles que o aceitam. |
| device group | Um conjunto nomeado de dispositivos que uma aplicação reconhece comparando o header `User-Agent` de uma requisição com uma expressão regular, criado na aba **Device Groups**. Uma regra o testa por meio da variável `${device_group}`, que exige Application Accelerator, e **Cache vary by Devices** varia a cache key por ele. [Device Groups](/pt-br/documentacao/plataforma/applications/device-groups/) documenta a correspondência. |
| edge hostname | O nome que outras plataformas dão ao hostname que elas atribuem à configuração que serve os seus domínios. Na Azion, é o domínio do workload, que a Azion atribui a um workload novo em `map.azionedge.net`. Os domínios pertencem ao [workload](/pt-br/documentacao/plataforma/workloads/), não à aplicação, e [Primeiros passos com Applications](/pt-br/documentacao/plataforma/applications/primeiros-passos/) envia uma primeira requisição ao domínio do workload. |
| fase | Um dos dois estágios em que uma aplicação executa regras: a **Request Phase**, que trata a requisição antes que exista uma resposta, e a **Response Phase**, que trata a resposta entregue ao usuário. Você escolhe a fase ao criar uma regra, e ela não pode ser alterada depois, então uma regra na outra fase é uma nova regra. O cache é decidido na **Request Phase**, e [Rules Engine para Applications](/pt-br/documentacao/plataforma/applications/rules-engine/) lista as fases em que cada variável e cada behavior estão disponíveis. |
| filtro | O componente de `ims` que transforma uma imagem além de um redimensionamento ou de um recorte, escrito `filters:name(argument)`, como em `filters:quality(15)`. Uma string `ims` combina vários filtros, separados por `:`. [Parâmetros de URL do Image Processor](/pt-br/documentacao/plataforma/applications/image-processor/parametros-de-url/) documenta `rotate`, `quality`, `watermark`, `format` e `fill`. |
| `fit-in` | O prefixo de `ims` que ajusta a imagem derivada dentro de uma caixa `WidthxHeight` e mantém a proporção da imagem de origem, como em `?ims=fit-in/400x400`. Uma imagem menor que a caixa não é ampliada e mantém o seu tamanho original. As duas dimensões são opcionais, e [Parâmetros de URL do Image Processor](/pt-br/documentacao/plataforma/applications/image-processor/parametros-de-url/#redimensionamento) mostra cada forma. |
| Forward Cookies | O behavior do [Rules Engine para Applications](/pt-br/documentacao/plataforma/applications/rules-engine/) que envia ao usuário o header `Set-Cookie` da origem mesmo quando a resposta vem do cache. Ele roda na **Request Phase** e exige Application Accelerator. |
| Image Processor | O Produto habilitado em uma aplicação que retorna uma imagem derivada construída a partir de uma imagem de origem guardada na origem, seguindo a query string `ims` da requisição. O seu switch, **Image Processor** em **Main Settings** › **Modules**, fica desativado em uma nova aplicação, `modules.image_processor.enabled` na API e `--image-processor` no Azion CLI. [Applications](/pt-br/documentacao/plataforma/applications/#image-processor) o descreve, e [Como Applications funciona](/pt-br/documentacao/plataforma/applications/como-funciona/#image-processor) acompanha uma requisição por ele. |
| imagem de origem | A imagem original, armazenada na origem, que Image Processor lê para responder a uma requisição que carrega uma query string `ims`. A Azion não grava nada de volta nela, porque cada transformação produz uma imagem derivada e deixa o original onde está. [Como Applications funciona](/pt-br/documentacao/plataforma/applications/como-funciona/#image-processor) descreve o caminho entre as duas. |
| imagem derivada | A saída que Image Processor constrói a partir da imagem de origem guardada na origem e retorna a uma requisição que carrega uma query string `ims`. O original permanece intacto, e a Azion não mantém nenhuma imagem derivada como um asset armazenado. [Como Applications funciona](/pt-br/documentacao/plataforma/applications/como-funciona/#image-processor) descreve como uma requisição produz uma. |
| `imageProcessedMetrics` | O dataset GraphQL que contém as métricas de requisição das imagens que passaram por Image Processor. [Configurações do Image Processor](/pt-br/documentacao/plataforma/applications/image-processor/configuracoes/#dados-de-uso-e-eventos) o lista com as outras superfícies que informam a atividade de Image Processor. |
| Images | O medidor de uso que conta as imagens que Image Processor processa, seja para otimizar, recortar, redimensionar, aplicar filtros ou converter. Cada requisição que Image Processor trata conta como uma imagem, e uma imagem servida do cache sem processamento não conta. [Limites de Applications](/pt-br/documentacao/plataforma/applications/limites/#image-processor) traz o volume que cada plano inclui, e [Preços](/pt-br/documentacao/fundamentos/precos/#image-processor) traz a tarifa. |
| `images_processed` | O `metricName` da query GraphQL de consumption que retorna o número total de imagens que Image Processor processou, sob o `productId` `1441110021`. [Consulte dados de uso do Image Processor](/pt-br/documentacao/guias/plataforma/observabilidade/consultar-dados-de-uso-image-processor-com-graphql/) traz a query completa. |
| `ims` | O parâmetro de query string que informa a Image Processor qual transformação aplicar, como em `?ims=400x`. Ele vai por último na URL, porque uma requisição que carrega outro parâmetro depois de `ims=` pode retornar um erro `504`. [Parâmetros de URL do Image Processor](/pt-br/documentacao/plataforma/applications/image-processor/parametros-de-url/#posicao-do-parametro-ims) documenta cada valor que ele aceita e a sua posição. |
| `ims_http` | O valor do campo **Proxy Upstream** em um registro de [Real-Time Events](/pt-br/documentacao/plataforma/real-time-events/) quando Image Processor respondeu como o upstream. Em alguns casos, Image Processor é a origem do [Tiered Cache](/pt-br/documentacao/plataforma/applications/cache/tiered-cache/) e processa a imagem antes de armazená-la em cache. |
| instância de função | O objeto que associa uma função criada em [Functions](/pt-br/documentacao/plataforma/functions/) a uma aplicação, com os argumentos com que ela roda, listado na aba **Functions Instances** e servido pela API em `/v4/workspace/applications/<application-id>/functions`. Uma regra com o behavior **Run Function** a invoca, nomeando o seu ID em `attributes.value`. [Instâncias de função](/pt-br/documentacao/plataforma/applications/functions-instances/) documenta os seus campos. |
| Large File Optimization | O recurso do Cache, ativado por cache setting com o toggle **Large file optimization**, que armazena um objeto grande em fragmentos de 1.024 kB. A Azion coloca cada fragmento em cache quando um usuário o requisita, sob a sua própria cache key terminada em `@@bytes=<start>-<end>`, e o recurso também se aplica ao Tiered Cache quando essa camada está ativa. [Como Applications funciona](/pt-br/documentacao/plataforma/applications/como-funciona/#cache) descreve o mecanismo. |
| Main Settings | A aba da aplicação cujas quatro seções são **General**, que traz o nome, **Modules**, **Debug Rules** e **Status**. As configurações de entrega e de protocolo não estão nela, porque pertencem ao [workload](/pt-br/documentacao/plataforma/workloads/) que serve a aplicação. [Main Settings de Applications](/pt-br/documentacao/plataforma/applications/main-settings/) documenta cada seção. |
| Max Age | O campo de Azion Console para quantos segundos o cache da Azion mantém uma cópia de um objeto, `modules.cache.max_age` na API, com padrão `60` no Console, na API e na CLI. A API recusa um valor menor que 60 com `21021` enquanto Application Accelerator está desativado, um valor menor que 3 com `21020` enquanto Tiered Cache está ativo e um valor maior que `31536000` com `10068`. A seção **Browser Cache** tem um **Max Age** próprio, `browser_cache.max_age`; [Limites de Applications](/pt-br/documentacao/plataforma/applications/limites/#application-accelerator) traz os limites que dependem dos Produtos ativos. |
| `modules` | O objeto da API que traz os switches de uma aplicação, `application_accelerator`, `cache`, `functions` e `image_processor`, cada um com um valor `enabled`. Azion Console o apresenta como a seção **Modules** de **Main Settings**, cujos **Default Modules** são os mesmos quatro, ao lado de um grupo **Subscription modules** com uma ação **Contact sales**. Tiered Cache não tem chave nele, porque é um switch dentro de um cache setting. |
| Optimize Images | O behavior do [Rules Engine para Applications](/pt-br/documentacao/plataforma/applications/rules-engine/) que ativa Image Processor para as requisições às quais a sua regra corresponde, `optimize_images` na API. Ele roda na **Request Phase**, não aceita argumentos e exige Image Processor na aplicação. A API o aceita sozinho em uma regra, sem nenhum **Set Cache Policy** ao lado. |
| `orig` | O valor de dimensão de `ims` que mantém a medida original da imagem de origem em um eixo, enquanto o outro eixo recebe o valor solicitado. Uma imagem derivada com uma dimensão `orig` não sofre recorte automático, como [Parâmetros de URL do Image Processor](/pt-br/documentacao/plataforma/applications/image-processor/parametros-de-url/#redimensionamento) mostra. |
| property | O nome que outras plataformas dão à configuração que serve um site: os seus hostnames e as regras aplicadas às requisições deles. Na Azion, são dois objetos: um [workload](/pt-br/documentacao/plataforma/workloads/) guarda os domínios, os protocolos e os certificados, e a aplicação que o deployment dele nomeia guarda as regras. [Como Applications funciona](/pt-br/documentacao/plataforma/applications/como-funciona/#o-caminho-que-uma-requisicao-percorre) acompanha uma requisição pelos dois. |
| purge por cache key | Um tipo de [Real-Time Purge](/pt-br/documentacao/plataforma/applications/cache/real-time-purge/#purge-por-cache-key), `cachekey` na API, que remove os objetos armazenados sob cada key de uma lista. Uma key pode nomear uma variação, por query string, cookie ou formato de imagem, então um purge de todas as variações de um objeto lista cada key. É o único tipo de purge que alcança a camada do [Tiered Cache](/pt-br/documentacao/plataforma/applications/cache/tiered-cache/#purge). |
| purge por URL | Um tipo de [Real-Time Purge](/pt-br/documentacao/plataforma/applications/cache/real-time-purge/#purge-por-url), `url` na API, que remove o objeto por trás de cada URL de uma lista. Ele não é recursivo, e a Azion converte cada URL na sua cache key sem as variações, então um objeto que varia por cookie, device group ou formato de imagem exige um purge por cache key ou por wildcard. Enviada sem scheme, uma URL remove a cópia em HTTP e a cópia em HTTPS. |
| purge por wildcard | Um tipo de [Real-Time Purge](/pt-br/documentacao/plataforma/applications/cache/real-time-purge/#purge-por-wildcard), `wildcard` na API, que remove todo objeto que corresponde a uma expressão com `*` no path ou na query string. Uma expressão pode ter mais de um `*`, mas uma requisição carrega uma expressão, e a API recusa uma segunda com `10065`. Ele não alcança a camada do Tiered Cache, e um purge por wildcard enviado a essa camada é recusado com `30001`. |
| Real-Time Purge | O recurso de plataforma que remove objetos do Cache ou do Tiered Cache antes do fim do seu TTL, para que a origem sirva a versão mais recente na próxima requisição. Um purge nomeia os seus objetos por URL, por cache key ou por uma expressão de wildcard, e a Azion o coloca em fila depois da mensagem de confirmação e o lista no histórico quando ele termina. [Real-Time Purge](/pt-br/documentacao/plataforma/applications/cache/real-time-purge/) documenta os três tipos e a camada que cada um alcança. |
| recorte automático | O recorte centralizado que um redimensionamento `WidthxHeight` pode aplicar para que a imagem derivada preencha a caixa solicitada, na vertical ou na horizontal, dependendo de como as dimensões originais se encaixam nas solicitadas. Definir uma dimensão como `orig` o impede, como [Parâmetros de URL do Image Processor](/pt-br/documentacao/plataforma/applications/image-processor/parametros-de-url/#redimensionamento) mostra. |
| regra | Uma entrada no Rules Engine para Applications que executa os seus behaviors, em uma fase, sobre as requisições às quais os seus critérios correspondem. As regras rodam na ordem em que você as organiza, e uma nova aplicação não tem nenhuma: você cria cada uma com **+ Rule**, nomeando-a em **General** antes de escolher a sua **Phase**. A API serve as regras da **Request Phase** em `/v4/workspace/applications/<application-id>/request_rules`, e [Rules Engine para Applications](/pt-br/documentacao/plataforma/applications/rules-engine/) lista os seus campos. |
| requisição complexa | Uma requisição cujo método é qualquer um diferente de `GET` ou `HEAD`. A Azion prefixa o método à cache key de uma requisição complexa, como em `optionshttpsstatic.example.com/page`, então uma resposta `OPTIONS` e uma resposta `GET` para um mesmo path são objetos separados. [Cache keys](/pt-br/documentacao/plataforma/applications/cache/cache-keys/#variacoes) lista o prefixo com as outras variações. |
| rota | O nome que outras plataformas dão a um padrão de path e ao que serve as requisições que correspondem a ele. Em uma aplicação, é uma regra da **Request Phase**: um critério em `${uri}` corresponde ao path, e **Set Connector** envia a requisição a um connector. Duas regras assim enviam `/api/` para uma origem e todo outro path para outra, como [Como Applications funciona](/pt-br/documentacao/plataforma/applications/como-funciona/#o-caminho-que-uma-requisicao-percorre) mostra. |
| Rules Engine para Applications | O recurso de uma aplicação que contém as suas regras e as executa em ordem, com lógica se/então: os critérios são o se, e os behaviors são o então. Azion Console o mostra como a aba **Rules Engine**, com as regras agrupadas por fase. [Rules Engine para Applications](/pt-br/documentacao/plataforma/applications/rules-engine/) documenta cada variável, operador e behavior. |
| Run Function | O behavior do [Rules Engine para Applications](/pt-br/documentacao/plataforma/applications/rules-engine/) que executa uma instância de função sobre as requisições às quais a sua regra corresponde, `run_function` na API, com o ID da instância em `attributes.value`. Ele roda na **Request Phase** e na **Response Phase** e exige o switch **Functions** ativo em **Main Settings** › **Modules**. [Instâncias de função](/pt-br/documentacao/plataforma/applications/functions-instances/#comportamento-run-function) documenta como ele nomeia a instância. |
| Set Cache Policy | O behavior do [Rules Engine para Applications](/pt-br/documentacao/plataforma/applications/rules-engine/#set-cache-policy) que nomeia um cache setting e o coloca em vigor para as requisições às quais a sua regra corresponde, `set_cache_policy` na API, com o ID do cache setting em `attributes.value`. Ele roda na **Request Phase** e não exige Application Accelerator. Um cache setting que nenhuma regra com **Set Cache Policy** nomeia não se aplica a nenhuma requisição, e a API se recusa a excluir um setting em uso com `21014 Cannot Delete Cache Setting`. |
| Set Connector | O behavior do [Rules Engine para Applications](/pt-br/documentacao/plataforma/applications/rules-engine/) que envia as requisições às quais a sua regra corresponde a um [connector](/pt-br/documentacao/plataforma/connectors/), `set_connector` na API, com o ID do connector em `attributes.value`. Ele roda na **Request Phase**, e, quando mais de uma regra correspondente o carrega, só a última roda. |
| Sort | O controle de **Cache vary by Query String** que agrupa os mesmos argumentos de query string sob uma única cache key, qualquer que seja a ordem em que chegam, `sort_enabled` na API e desativado por padrão. Sem ele, `?a=1&b=2` e `?b=2&a=1` são dois objetos que guardam uma mesma resposta. Com ele, um purge por URL precisa enviar os argumentos em ordem alfabética. |
| stale cache | O comportamento do Cache que responde com uma cópia expirada durante uma janela de stale quando a revalidação com a origem falha, ativado por cache setting com o toggle **Stale cache**. Sob _Honor cache policies_, a janela é o valor de `stale-while-revalidate` da origem, e sob _Override cache behavior_, ou quando a origem omite a diretiva, ela é de 300 segundos. Durante a janela, a Azion busca uma versão atual em background, como [Como Applications funciona](/pt-br/documentacao/plataforma/applications/como-funciona/#cache) descreve. |
| status de cache | O estado de uma resposta no Cache, no início do header `x-cache`: `HIT`, `MISS`, `EXPIRED`, `STALE`, `UPDATING`, `REVALIDATED` ou `BYPASS`. Uma resposta que a plataforma não coloca em cache informa `-`. [Cache keys](/pt-br/documentacao/plataforma/applications/cache/cache-keys/#status-de-cache) dá o significado de cada um. |
| Tiered Cache | A segunda camada de cache entre o cache da Azion e a origem, mantida em uma região, compartilhada por todos os data centers e que guarda os objetos por mais tempo que a primeira camada. Todo plano a inclui, e o seu toggle **Tiered Cache** fica em um cache setting, e não em **Main Settings**. O setting precisa usar _Override cache behavior_, ou a API responde `21001`, e um **Max Age** de pelo menos 3 segundos; [Tiered Cache](/pt-br/documentacao/plataforma/applications/cache/tiered-cache/) cobre as regiões em que ela roda e o tipo de purge que a limpa. |
| topology | A configuração do Tiered Cache que seleciona a região onde a segunda camada de cache mantém os objetos: `nearest-region`, `br-east-1` ou `us-east-1`, em `modules.cache.tiered_cache.topology`. A API recusa qualquer outro valor com `10039 Invalid Choice`, e [Tiered Cache](/pt-br/documentacao/plataforma/applications/cache/tiered-cache/#topology) documenta cada região. |
| TTL | O número de segundos que o cache da Azion ou o navegador mantém uma cópia de um objeto, definido por [cache setting](/pt-br/documentacao/plataforma/applications/cache/cache-settings/) pelo **Max Age**: `modules.cache.max_age` para o cache da Azion e `browser_cache.max_age` para o navegador. |
| variação de cache | No Cache, uma cópia adicional de um objeto armazenada sob a sua própria key porque o método da requisição, um argumento de query string, um cookie, um device group, um formato de imagem ou um intervalo de bytes de um arquivo grande difere. No Image Processor, o campo `cache_vary_by_querystring` que varia o cache em `ims`, definido pelos seus controles **Behavior**, **Fields** e **Sort**, como [Configurações do Image Processor](/pt-br/documentacao/plataforma/applications/image-processor/configuracoes/#cache-variation) mostra. Todo controle **Cache vary by** exige Application Accelerator, porque os seus campos pertencem a `modules.application_accelerator`, enquanto processar uma imagem não exige; [Configurações do Application Accelerator](/pt-br/documentacao/plataforma/applications/application-accelerator/configuracoes/#cache-variation) documenta os quatro controles. |
| variável | Um valor da requisição ou da resposta, escrito `${name}`, que um critério testa ou que um argumento de behavior insere, como `${uri}`, `${host}` ou `${device_group}`. Cada variável está disponível na **Request Phase**, na **Response Phase** ou nas duas. Em uma aplicação, `${request_uri}` exige Application Accelerator, e uma regra que a usa sem esse Produto é recusada com `25047 Missing Required Modules`, enquanto a mesma regra com `${uri}` é aceita. |
| WASM Image Processor | A biblioteca WebAssembly que processa imagens dentro de uma função de [Functions](/pt-br/documentacao/plataforma/functions/), por meio de `loadImage`, `resize`, `getImageResponse` e `clean`, para os formatos `webp`, `jpeg` e `png`. Ela não é o Produto Image Processor: Image Processor transforma uma requisição por meio da query string `ims`, e a biblioteca roda dentro do seu código. [Configurações do Image Processor](/pt-br/documentacao/plataforma/applications/image-processor/configuracoes/#biblioteca-wasm-image-processor) aponta para a sua referência. |
| WebSocket Proxy | O recurso da aplicação que mantém uma conexão WebSocket, uma única conexão TCP bidirecional, aberta entre os seus usuários e a sua origem. Uma aplicação com ele ativo trata uma requisição que carrega `Upgrade: websocket` e `Connection: upgrade` como uma conexão WebSocket e faz proxy dela para a origem, e uma conexão válida responde `101 Switching Protocols`. [WebSocket Proxy](/pt-br/documentacao/plataforma/applications/websocket/) documenta os seus requisitos e a sua disponibilidade. |
| `x-cache` | O header de debug da resposta que traz o status de cache de uma resposta, o endereço IP do servidor que respondeu e o protocolo, na forma `<STATUS> from <IP> with <protocol>`. Uma requisição precisa carregar `Pragma: azion-debug-cache` para que a Azion o acrescente à resposta. [Cache keys](/pt-br/documentacao/plataforma/applications/cache/cache-keys/#headers-de-debug) lista cada status que ele pode trazer. |
| `x-cache-key` | O header de debug da resposta que traz a cache key de uma resposta, como em `x-cache-key: httpsstatic.example.com/page/site.js`. Ele só volta em uma requisição enviada com `Pragma: azion-debug-cache`, e mostra `x-cache-key: -` em uma resposta que a plataforma não coloca em cache. [Cache keys](/pt-br/documentacao/plataforma/applications/cache/cache-keys/#formato-da-key) decompõe a key elemento por elemento. |
