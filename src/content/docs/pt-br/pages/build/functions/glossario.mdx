Definições para os termos que a documentação de [Functions](/pt-br/documentacao/build/functions/) usa.

| Termo | Definição |
| --- | --- |
| Args | O objeto JSON que uma [instância de função](/pt-br/documentacao/build/functions/functions-instances/) passa para o contexto de execução da função. Uma instância sobrescreve, chave por chave, os Args padrão definidos na função. [Como funciona](/pt-br/documentacao/build/functions/como-funciona/) mostra como os dois se combinam. |
| Azion Bundler | O adaptador de frameworks open source que transforma um projeto de framework em funções que rodam no Azion Runtime. [Como funciona](/pt-br/documentacao/build/functions/como-funciona/) descreve as quatro etapas do build, da detecção do framework ao deploy das funções geradas. |
| Azion Runtime | O ambiente que executa o handler de uma função. [Azion Runtime](/pt-br/documentacao/devtools/runtime/) executa JavaScript construído sobre padrões Web, então uma função chama Web APIs em vez de uma interface proprietária. |
| Cell | O ambiente de isolamento dentro do qual uma função roda, baseado em isolates V8. Cada Cell é um contexto de execução leve, sem acesso direto ao sistema operacional subjacente, e é por isso que uma função não consegue ler propriedades do SO, resolver DNS por chamadas nativas de sistema nem abrir sockets de baixo nível. [Compatibilidade com Node.js](/pt-br/documentacao/devtools/runtime/node/) lista o que isso exclui. |
| contexto de execução | O parâmetro `ctx` que um handler recebe, depois de `request` e `env`. `ctx.waitUntil(promise)` estende a duração da execução para além do ponto em que o handler retorna e, em um handler firewall, `ctx.deny()` bloqueia a requisição imediatamente. [Handlers](/pt-br/documentacao/devtools/runtime/api-reference/handlers/) lista todos os parâmetros dos dois handlers. |
| editor de código | O editor em Azion Console onde você escreve e edita o código de uma função. O [editor de código](/pt-br/documentacao/build/functions/code-editor/) usa o editor Monaco do VS Code e mostra a saída da função por meio de Preview deployment. |
| fase de execução | A etapa do processamento da requisição à qual uma regra de [Rules Engine](/pt-br/documentacao/plataforma/applications/rules-engine/) pertence. Request Phase trata o que o usuário enviou e Response Phase trata o que a aplicação retorna. [Como funciona](/pt-br/documentacao/build/functions/como-funciona/) descreve as duas fases e os critérios que acionam uma regra. |
| função | O código JavaScript que você cria em Functions. Uma função pertence ao produto, e não a uma única aplicação, então o mesmo código pode ser instanciado em mais de um lugar. Criar uma função não a executa: uma instância e uma regra a invocam, como [Como funciona](/pt-br/documentacao/build/functions/como-funciona/) descreve. |
| Functions Event Collector | O template de [Data Stream](/pt-br/documentacao/observe/data-stream/) que formata as mensagens de log das suas funções para o endpoint que as recebe. O preset preenche o Data Set com o identificador da requisição, o nível do log e a mensagem do log. [Debugging](/pt-br/documentacao/build/functions/solucao-de-problemas/) lista todas as variáveis que ele carrega. |
| handler | A função que o seu código exporta para Azion Runtime executar. Em uma aplicação, o handler se chama `fetch`; em um firewall, ele se chama `firewall` e pode chamar `ctx.deny()` para bloquear a requisição. [Handlers](/pt-br/documentacao/devtools/runtime/api-reference/handlers/) documenta os parâmetros que os dois recebem. |
| instância de função | O objeto que vincula uma função a uma aplicação ou a um [firewall](/pt-br/documentacao/plataforma/firewall/functions-instances/) e carrega os Args passados para o contexto de execução dela. A instanciação não abre o código para edição: uma [instância](/pt-br/documentacao/build/functions/functions-instances/) define apenas os Args. |
| isolate | O contexto de execução V8 no qual uma invocação de uma função é executada. O limite de memória de uma função se aplica por isolate, e [Limites](/pt-br/documentacao/build/functions/limites/) carrega o valor. |
| padrão ES Modules | O padrão de handler que o código novo usa: uma função exporta um objeto default cujo método `fetch` recebe `request`, `env` e `ctx`. [Boas práticas](/pt-br/documentacao/build/functions/boas-praticas/) o compara com o padrão Service Worker, e [Handlers](/pt-br/documentacao/devtools/runtime/api-reference/handlers/) documenta a assinatura. |
| padrão Service Worker | O padrão de handler que registra um listener com `addEventListener('fetch', ...)` e lê a requisição, o ambiente e o contexto de execução de um objeto de evento. A Azion o mantém por compatibilidade retroativa e recomenda migrar as funções que ainda o usam, como [Boas práticas](/pt-br/documentacao/build/functions/boas-praticas/) descreve. [Migrando padrões de handler em Functions](/pt-br/documentacao/guias/desenvolvimento-de-aplicacoes/functions-e-runtime/migrar-padroes-de-handler/) mostra o antes e o depois de cada handler. |
| Preview deployment | O recurso que mostra a saída de uma função ao lado do [editor de código](/pt-br/documentacao/build/functions/code-editor/), antes de a função atender ao tráfego de produção. [Preview deployment](/pt-br/documentacao/build/functions/preview-deployment/) renderiza o resultado de `PreviewProvider`, uma função auxiliar no seu código-fonte. |
| PreviewProvider | A função auxiliar no seu código-fonte que monta uma requisição simulada para [Preview deployment](/pt-br/documentacao/build/functions/preview-deployment/). Sem ela, o preview não tem nada para renderizar. |
| Run Function | O comportamento de [Rules Engine](/pt-br/documentacao/plataforma/applications/rules-engine/#run-function) que invoca uma instância de função. A regra carrega a fase de execução e os critérios que a acionam, e nada mais invoca uma função. O comportamento exige o módulo [Application Accelerator](/pt-br/documentacao/build/application-accelerator/). |
| secret | O campo booleano de uma [variável de ambiente](/pt-br/documentacao/build/functions/environment-variables/) que indica se o valor é confidencial. Azion CLI define o campo com a flag `--secret`, cujo valor padrão é `true`. |
| sub-requisição | Uma chamada `fetch()` de saída que uma função faz durante uma invocação, com teto de 50. O teto é por invocação, e não por segundo, então ele limita o formato do código e não o tráfego que a aplicação recebe. [Boas práticas](/pt-br/documentacao/build/functions/boas-praticas/) cobre a consolidação que isso exige. |
| tempo de CPU | A computação ativa que uma única invocação realiza, com teto de 2 segundos. Ele exclui o tempo gasto esperando por `fetch()`, então uma função que espera por uma origem permanece longe desse teto por mais longa que seja a requisição. Uma função que o excede é encerrada. Compare com tempo de relógio, e consulte [Limites](/pt-br/documentacao/build/functions/limites/). |
| tempo de relógio | O tempo total decorrido de uma invocação, com teto de 5 minutos, incluindo espera de I/O, chamadas `fetch()` e operações assíncronas. É o teto que limita o trabalho entregue a `ctx.waitUntil()`. Compare com tempo de CPU, e consulte [Limites](/pt-br/documentacao/build/functions/limites/). |
| variável de ambiente | Um valor armazenado fora do código de uma função e lido a partir do parâmetro `env` do handler. [Variáveis de ambiente](/pt-br/documentacao/build/functions/environment-variables/) mantêm chaves de API, credenciais e tokens de acesso fora da base de código. |
