Este guia conduz você por executar sua primeira função na Azion. Os passos levam cerca de 10 minutos.

- Criar uma função que retorna `Hello World!`.
- Instanciar a função em uma aplicação.
- Adicionar uma regra do Rules Engine que executa a instância na URI `/hello-world`.
- Requisitar essa URI e ler a resposta.

Três objetos fazem uma função ser executada, e cada um se conecta ao seguinte:

1. A **função** contém o código JavaScript.
2. A **instância de função** vincula a função a uma aplicação. Ela também carrega os Args, um objeto JSON passado para o contexto de execução.
3. A regra do **Rules Engine** seleciona a instância com o comportamento **Run Function**. A regra define a fase de execução e os critérios que a acionam.

Criar uma função não a executa. Uma instância sem uma regra do Rules Engine nunca é executada.

O [Azion Terraform provider](/pt-br/documentacao/devtools/terraform/) gerencia os mesmos três objetos. Para conhecer todas as interfaces que os carregam, consulte [Functions](/pt-br/documentacao/build/functions/#escopo-e-limites).

## Pré-requisitos

- Uma conta Azion. Para criar uma, consulte [Como criar uma conta na Azion](/pt-br/documentacao/fundamentos/criar-uma-conta/).
- A permissão **Edit Functions** na conta. Ela concede permissão para criar, editar e remover funções, e também requer a permissão **View Functions**.
- A permissão **Edit Applications** na conta. As etapas 2 e 3 alteram uma aplicação, e essa permissão concede permissão para editar, criar e remover aplicações. Ela também requer a permissão **View Applications**. Consulte [Teams Permissions](/pt-br/documentacao/fundamentos/teams-permissions/).
- Uma aplicação. Para criar uma, consulte [Criar uma aplicação](/pt-br/documentacao/guias/desenvolvimento-de-aplicacoes/primeiros-passos/criar-uma-aplicacao/).

## 1. Crie a função

A função contém o código que responde à requisição. Esta retorna a string `Hello World!`.

<Tabs client:visible sharedStore="interface">

<Fragment slot="panel.console">

Para criar a função pelo Azion Console:

<DocSteps>
  <DocStep title="Abra a página Functions">

  Acesse [Azion Console](https://console.azion.com/) > **Products Menu** > **Libraries** > **Functions**.

  </DocStep>
  <DocStep title="Selecione + Function" />
  <DocStep title="Nomeie a função">

  Digite um nome para a função. Por exemplo: `hello-world`.

  </DocStep>
  <DocStep title="Cole o código na aba Code">

  Na aba **Code**, cole o código a seguir:

  ```javascript
  export default {
    async fetch(request, env, ctx) {
      return new Response('Hello World!');
    },
  };
  ```

  </DocStep>
  <DocStep title="Selecione Save" />
</DocSteps>

A função é salva e fica disponível para ser instanciada em uma aplicação.

:::tip[dica]
Para ler a resposta da função antes que ela atenda tráfego, use o [Preview deployment](/pt-br/documentacao/build/functions/preview-deployment/). Ele roda o código no Azion Console sem um deployment.
:::

</Fragment>

<Fragment slot="panel.cli">

A CLI lê o código de um arquivo local. Para criar a função:

<DocSteps>
  <DocStep title="Salve o código em um arquivo">

  Escreva o código a seguir em `index.js`:

  ```javascript
  export default {
    async fetch(request, env, ctx) {
      return new Response('Hello World!');
    },
  };
  ```

  </DocStep>
  <DocStep title="Execute o comando de criação">

  ```bash
  azion create function --name hello-world --code ./index.js --active true
  ```

  </DocStep>
  <DocStep title="Leia a saída">

  O comando imprime o id da nova função:

  ```text
  Created function with ID 56278
  ```

  </DocStep>
</DocSteps>

Registre o id. A etapa 2 o passa para a instância. Para todas as flags que o comando aceita, consulte [Azion CLI create](/pt-br/documentacao/devtools/cli/create/).

</Fragment>

<Fragment slot="panel.api">

O body da requisição carrega o código como uma string JSON, então as quebras de linha são escapadas como `\n`.

<DocSteps>
  <DocStep title="Envie a requisição de criação">

  Substitua `[TOKEN VALUE]` pelo seu personal token:

  ```bash
  curl --request POST \
    --url https://api.azion.com/v4/workspace/functions \
    --header 'Accept: application/json' \
    --header 'Authorization: Token [TOKEN VALUE]' \
    --header 'Content-Type: application/json' \
    --data '{
    "name": "hello-world",
    "code": "export default {\n  async fetch(request, env, ctx) {\n    return new Response(\"Hello World!\");\n  },\n};"
  }'
  ```

  </DocStep>
  <DocStep title="Leia a resposta">

  Um `202` carrega a função:

  ```json
  {
    "state": "pending",
    "data": {
      "id": 56277,
      "name": "hello-world",
      "last_editor": "user@example.com",
      "last_modified": "2026-09-19T02:34:58.385220Z",
      "product_version": "2.0",
      "active": true,
      "runtime": "azion_js",
      "execution_environment": "application",
      "default_args": {},
      "reference_count": 0,
      "code": "export default {\n  async fetch(request, env, ctx) {\n    return new Response(\"Hello World!\");\n  },\n};"
    }
  }
  ```

  </DocStep>
</DocSteps>

Registre o `id`. A etapa 2 o passa para a instância. O valor `"state": "pending"` significa que a alteração leva alguns minutos para propagar.

</Fragment>

</Tabs>

## 2. Instancie a função na sua aplicação

Uma instância vincula a função a uma aplicação, e uma função pode sustentar várias instâncias. Cada caminho ativa o módulo **Functions** na aplicação e então cria a instância.

:::caution[Atenção]
Tempo de computação e invocações de funções geram custos relacionados ao uso. Para as taxas, consulte [Preços](/pt-br/documentacao/fundamentos/precos/).
:::

<Tabs client:visible sharedStore="interface">

<Fragment slot="panel.console">

Para vincular a função a uma aplicação pelo Azion Console:

<DocSteps>
  <DocStep title="Ainda em Azion Console, vá para Products Menu > Build > Applications" />
  <DocStep title="Selecione a aplicação que executa a função" />
  <DocStep title="Na aba Main Settings, ative o módulo Functions" />
  <DocStep title="Selecione Save" />
  <DocStep title="Vá para a aba Functions Instances" />
  <DocStep title="Selecione + Function Instance" />
  <DocStep title="Nomeie a instância">

  Digite um nome para a instância. Por exemplo: `hello-world instance`.

  </DocStep>
  <DocStep title="Selecione a função">

  Selecione a função `hello-world`.

  </DocStep>
  <DocStep title="Selecione Save" />
</DocSteps>

A nova instância aparece na aba **Functions Instances**.

</Fragment>

<Fragment slot="panel.cli">

Para ativar o módulo e criar a instância com a Azion CLI, substitua o id da aplicação e o id da função pelos seus:

<DocSteps>
  <DocStep title="Ative o módulo Functions">

  ```bash
  azion update application --application-id <application_id> --functions true
  ```

  O comando confirma a aplicação:

  ```text
  Updated Application with ID <application_id>
  ```

  </DocStep>
  <DocStep title="Crie a instância">

  ```bash
  azion create function-instance --application-id <application_id> --function-id <function_id> --name "hello-world instance"
  ```

  </DocStep>
  <DocStep title="Leia a saída">

  O comando imprime o id da nova instância:

  ```text
  Created Function Instance with ID 50206
  ```

  </DocStep>
</DocSteps>

Registre o id da instância. A etapa 3 o passa para a regra.

</Fragment>

<Fragment slot="panel.api">

Duas requisições ativam o módulo e criam a instância.

<DocSteps>
  <DocStep title="Ative o módulo Functions">

  Substitua `<application_id>` pelo [ID da sua aplicação](/pt-br/documentacao/guias/desenvolvimento-de-aplicacoes/primeiros-passos/definir-configuracoes-principais/):

  ```bash
  curl --request PATCH \
    --url https://api.azion.com/v4/workspace/applications/<application_id> \
    --header 'Accept: application/json' \
    --header 'Authorization: Token [TOKEN VALUE]' \
    --header 'Content-Type: application/json' \
    --data '{
    "modules": {
      "functions": {
        "enabled": true
      }
    }
  }'
  ```

  A resposta retorna os módulos que a aplicação agora carrega:

  ```json
  {
    "cache": { "enabled": true },
    "functions": { "enabled": true },
    "application_accelerator": { "enabled": false },
    "image_processor": { "enabled": false }
  }
  ```

  </DocStep>
  <DocStep title="Crie a instância">

  Substitua `<function_id>` pelo `id` que a criação da função retornou:

  ```bash
  curl --request POST \
    --url https://api.azion.com/v4/workspace/applications/<application_id>/functions \
    --header 'Accept: application/json' \
    --header 'Authorization: Token [TOKEN VALUE]' \
    --header 'Content-Type: application/json' \
    --data '{
    "name": "hello-world instance",
    "function": <function_id>,
    "args": {},
    "active": true
  }'
  ```

  </DocStep>
  <DocStep title="Leia a resposta">

  Um `202` carrega a instância:

  ```json
  {
    "state": "pending",
    "data": {
      "id": 50205,
      "name": "hello-world instance",
      "args": {},
      "function": 56277,
      "active": true,
      "last_editor": "user@example.com",
      "last_modified": "2026-09-19T02:35:19.272376Z"
    }
  }
  ```

  O campo `function` carrega o id da função que a instância executa. Ele é diferente de `id`, que é único para cada instância.

  </DocStep>
</DocSteps>

Registre o `id` da instância. A etapa 3 o passa para a regra.

</Fragment>

</Tabs>

## 3. Adicione a regra que executa a função

Uma instância é executada apenas quando uma regra do Rules Engine a seleciona. Esta regra executa a instância em requisições para `/hello-world`.

<Tabs client:visible sharedStore="interface">

<Fragment slot="panel.console">

Para adicionar a regra pelo Azion Console:

<DocSteps>
  <DocStep title="Na mesma aplicação, vá para a aba Rules Engine" />
  <DocStep title="Selecione + Rule" />
  <DocStep title="Nomeie a regra">

  Digite um nome para a regra. Por exemplo: `Run hello-world`.

  </DocStep>
  <DocStep title="Selecione Request Phase" />
  <DocStep title="Selecione a variável na seção Criteria">

  Na seção **Criteria**, selecione a variável `${uri}`.

  </DocStep>
  <DocStep title="Selecione is equal como operador de comparação" />
  <DocStep title="Digite o argumento">

  Digite `/hello-world` como argumento.

  </DocStep>
  <DocStep title="Na seção Behaviors, selecione Run Function" />
  <DocStep title="Selecione a instância que você criou" />
  <DocStep title="Selecione Save" />
</DocSteps>

A regra executa a instância em toda requisição cuja URI é `/hello-world`.

:::note[nota]
Se **Run Function** não estiver na lista de **Behaviors**, a aplicação também precisa do módulo **Application Accelerator**. Consulte [Run Function não aparece na lista de comportamentos](/pt-br/documentacao/build/functions/solucao-de-problemas/#run-function-nao-aparece-na-lista-de-comportamentos) para a correção.
:::

</Fragment>

<Fragment slot="panel.cli">

A CLI lê a regra de um arquivo JSON. Para adicionar a regra:

<DocSteps>
  <DocStep title="Escreva a regra em um arquivo">

  Salve o conteúdo a seguir como `rule.json`, com o id da sua instância em `attributes.value`:

  ```json
  {
    "name": "Run hello-world",
    "description": "Run the function on /hello-world",
    "active": true,
    "criteria": [
      [
        {
          "conditional": "if",
          "variable": "${uri}",
          "operator": "is_equal",
          "argument": "/hello-world"
        }
      ]
    ],
    "behaviors": [
      {
        "type": "run_function",
        "attributes": { "value": 50206 }
      }
    ]
  }
  ```

  </DocStep>
  <DocStep title="Crie a regra">

  ```bash
  azion create rules-engine --application-id <application_id> --phase request --file rule.json
  ```

  </DocStep>
  <DocStep title="Leia a saída">

  O comando imprime o id da nova regra:

  ```text
  Created Rules Engine with ID 712403
  ```

  </DocStep>
</DocSteps>

A regra executa a instância em toda requisição cuja URI é `/hello-world`.

</Fragment>

<Fragment slot="panel.api">

Para adicionar a regra com a Azion API:

<DocSteps>
  <DocStep title="Escreva a regra em um arquivo">

  Os critérios carregam `${uri}`, que um shell expande, então o body é enviado a partir de um arquivo. Salve o conteúdo a seguir como `rule.json`, com o id da sua instância em `attributes.value`:

  ```json
  {
    "name": "Run hello-world",
    "description": "Run the function on /hello-world",
    "active": true,
    "criteria": [
      [
        {
          "conditional": "if",
          "variable": "${uri}",
          "operator": "is_equal",
          "argument": "/hello-world"
        }
      ]
    ],
    "behaviors": [
      {
        "type": "run_function",
        "attributes": { "value": 50205 }
      }
    ]
  }
  ```

  </DocStep>
  <DocStep title="Envie a requisição de criação">

  ```bash
  curl --request POST \
    --url https://api.azion.com/v4/workspace/applications/<application_id>/request_rules \
    --header 'Accept: application/json' \
    --header 'Authorization: Token [TOKEN VALUE]' \
    --header 'Content-Type: application/json' \
    --data @rule.json
  ```

  </DocStep>
  <DocStep title="Leia a resposta">

  Um `202` carrega a regra, com o `order` que ela ocupa entre as regras da aplicação:

  ```json
  {
    "state": "pending",
    "data": {
      "id": 712402,
      "name": "Run hello-world",
      "active": true,
      "behaviors": [
        {
          "type": "run_function",
          "attributes": { "value": 50205 }
        }
      ],
      "order": 0,
      "last_editor": "user@example.com",
      "last_modified": "2026-09-19T02:36:23.270982Z"
    }
  }
  ```

  </DocStep>
</DocSteps>

A regra executa a instância em toda requisição cuja URI é `/hello-world`.

</Fragment>

</Tabs>

Novas regras podem levar alguns minutos para propagar. Aguarde antes de requisitar a URI.

---

## 4. Verifique a resposta

Sua aplicação responde em um domínio no formato `xxxxxxxxx.map.azionedge.net`. Para definir o domínio da sua aplicação, consulte [Como configurar um domínio](/pt-br/documentacao/guias/plataforma/migracao/configurar-dominio/).

Para confirmar que a função é executada, requisite a URI definida na regra:

```bash
curl https://<your-azion-domain>/hello-world
```

O corpo da resposta é a string que a função retorna:

```
Hello World!
```

A função agora é executada em toda requisição que corresponde aos critérios da regra.
