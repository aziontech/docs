Os termos que a documentação de [Image Processor](/pt-br/documentacao/build/image-processor/) usa, cada um com a página que o cobre por completo.

| Termo | Definição |
| --- | --- |
| Add Request Header | O behavior do [Rules Engine](/pt-br/documentacao/plataforma/applications/rules-engine/) que adiciona um header à requisição, na forma `Field: value`, na **Request Phase**. Converter uma imagem para WEBP ou AVIF exige que a requisição carregue `Accept: image/webp` ou `Accept: image/avif`, e esse behavior o adiciona. O tipo na API é `add_request_header`. |
| autocrop | O recorte centralizado que um redimensionamento `WidthxHeight` pode aplicar para que a imagem derivada caiba na caixa solicitada. Ele age na vertical ou na horizontal, dependendo de como as dimensões originais se encaixam nas solicitadas. Uma dimensão definida como `orig` o impede, como [Parâmetros de URL](/pt-br/documentacao/build/image-processor/parametros-de-url/) mostra. |
| cache key | A entrada de índice sob a qual [Cache](/pt-br/documentacao/build/cache/) armazena um objeto. Com Image Processor ativado, a chave de uma imagem processada carrega a query string `ims`, e uma variação convertida para outro formato carrega o formato do arquivo após o separador. |
| filtro | O componente `ims` que transforma uma imagem além de um redimensionamento ou um recorte, escrito `filters:name(argument)`. Uma string `ims` combina vários filtros separando-os com `:`. [Parâmetros de URL](/pt-br/documentacao/build/image-processor/parametros-de-url/) documenta `rotate`, `quality`, `watermark`, `format` e `fill`. |
| `fit-in` | O prefixo `ims` que ajusta a imagem derivada dentro de uma caixa `WidthxHeight` e preserva a [proporção](https://www.azion.com/en/learning/) da imagem de origem. Ele nunca amplia uma imagem: quando a área especificada é maior do que as dimensões da imagem, a imagem mantém o seu tamanho original. As duas dimensões são opcionais, e [Parâmetros de URL](/pt-br/documentacao/build/image-processor/parametros-de-url/) mostra as formas que ele assume. |
| Image Processor | O módulo de [Applications](/pt-br/documentacao/plataforma/applications/) que retorna uma imagem derivada construída a partir de uma imagem de origem na origin, seguindo a query string `ims` da requisição. Um switch o ativa por aplicação, e [Como Image Processor funciona](/pt-br/documentacao/build/image-processor/como-funciona/) descreve o caminho que uma requisição percorre por ele. |
| imagem de origem | A imagem na origin que Image Processor lê quando uma requisição carrega uma query string `ims`. Azion nunca a modifica: uma transformação produz uma imagem derivada e deixa o original no lugar. [Como Image Processor funciona](/pt-br/documentacao/build/image-processor/como-funciona/) descreve o caminho entre as duas. |
| imagem derivada | A imagem que Image Processor retorna quando uma requisição carrega uma query string `ims`, construída a partir da imagem de origem na origin. Azion nunca modifica o original e não armazena nenhuma imagem derivada como asset. [Como Image Processor funciona](/pt-br/documentacao/build/image-processor/como-funciona/) descreve como uma requisição produz uma. |
| `imageProcessedMetrics` | O dataset GraphQL que retorna métricas de requisição para as imagens que Image Processor processou. [Campos da API GraphQL do Real-Time Metrics](/pt-br/documentacao/devtools/graphql/campos-gql-real-time-metrics/) lista todos os campos que ele carrega. |
| Images | O medidor de uso que conta o volume de imagens que Image Processor processa, seja para otimização, recorte, redimensionamento, filtros ou conversão de formato. Uma imagem é contada para cada requisição que Image Processor processa, e uma imagem servida a partir de [Cache](/pt-br/documentacao/build/cache/) sem processamento não é contada. [Preços](/pt-br/documentacao/fundamentos/precos/#image-processor) traz o volume que cada plano inclui. |
| `images_processed` | O `metricName` da query GraphQL de consumption que retorna o número total de imagens processadas por Image Processor, sob o `productId` `1441110021`. [Campos da API GraphQL de Consumption](/pt-br/documentacao/devtools/graphql/campos-gql-consumption/) o lista, e [Consulte dados de uso do Image Processor](/pt-br/documentacao/guias/plataforma/observabilidade/consultar-dados-de-uso-image-processor-com-graphql/) traz a query completa. |
| `ims` | O parâmetro de [query string](https://www.azion.com/en/learning/) que descreve a transformação que Image Processor aplica, como em `?ims=400x`. Ele precisa ser o último parâmetro na URL, e uma requisição que carrega outro parâmetro depois de `ims=` pode retornar um erro `504`. [Parâmetros de URL](/pt-br/documentacao/build/image-processor/parametros-de-url/) documenta todos os valores que ele aceita. |
| `ims_http` | O valor que o campo **Proxy Upstream** de um registro de [Real-Time Events](/pt-br/documentacao/observe/real-time-events/) carrega quando Image Processor respondeu como o upstream. Em alguns casos, a origin do [Tiered Cache](/pt-br/documentacao/build/cache/tiered-cache/) pode ser Image Processor, que processa a imagem e depois a armazena em cache. |
| Optimize Images | O behavior do [Rules Engine](/pt-br/documentacao/plataforma/applications/rules-engine/) que ativa Image Processor para as requisições que uma regra corresponde. Ele roda na **Request Phase**, não recebe argumentos e exige o módulo Image Processor. O tipo na API é `optimize_images`. |
| `orig` | O valor de dimensão `ims` que mantém a medida original da imagem de origem em um eixo. O outro eixo recebe o valor solicitado, e a imagem derivada não sofre autocrop. [Parâmetros de URL](/pt-br/documentacao/build/image-processor/parametros-de-url/) mostra a forma que ele assume. |
| variação de cache | O campo do cache setting que varia a cache key por argumentos de query string nomeados, `cache_vary_by_querystring`. Variar o cache em `ims` exige o módulo [Application Accelerator](/pt-br/documentacao/build/application-accelerator/), porque o campo pertence a `modules.application_accelerator`, mas processar uma imagem não exige. [Configurações](/pt-br/documentacao/build/image-processor/configuracoes/) traz os seus controles **Behavior**, **Fields** e **Sort**. |
| WASM Image Processor | A biblioteca WebAssembly que processa imagens dentro de uma função em [Functions](/pt-br/documentacao/build/functions/), por meio de `loadImage`, `resize`, `getImageResponse` e `clean`, para os formatos `webp`, `jpeg` e `png`. Ela não é o módulo Image Processor: o módulo transforma uma requisição por meio da query string `ims`, e esta biblioteca roda dentro do seu código. [Biblioteca WASM Image Processor](/pt-br/documentacao/devtools/azion-lib/wasm-image-processor/) a documenta. |
