Esta página corrige sintomas observados no [Image Processor](/pt-br/documentacao/build/image-processor/): um erro `504`, uma imagem que ignora sua query string `ims`, uma conversão ou uma rotação que não se aplica, e um medidor de Images que sobe mais rápido do que as solicitações enviadas. Cada seção é independente, e você pode lê-las em qualquer ordem.

---

## Um erro `504` em uma solicitação cujo `ims` não é o último parâmetro

Você solicita uma imagem cuja URL carrega `ims=` seguido de outro parâmetro na query string, e a resposta é um erro `504`.

O parâmetro `ims=` precisa ser o último parâmetro na URL. Quando outro parâmetro vem depois dele, a solicitação pode retornar um erro `504`, embora uma solicitação com um parâmetro posterior nem sempre falhe dessa forma.

- **Mova `ims` para o final**: coloque todos os outros parâmetros da query string antes de `ims=`, como em `example.com/image.jpeg?ts=1234&ims=1000x1000`, e nunca depois dele. Para a gramática completa que `ims` aceita, consulte [Parâmetros de URL](/pt-br/documentacao/build/image-processor/parametros-de-url/).

A solicitação retorna a imagem derivada em vez de um erro `504`.

---

## A imagem é entregue sem processamento, e a query string `ims` é ignorada

Você solicita uma imagem com uma query string `ims` válida, e a resposta retorna a imagem de origem sem alterações, sem redimensionamento, recorte ou filtro aplicado.

Uma transformação não é executada porque existe uma query string `ims`. Ela é executada porque uma regra do [Rules Engine](/pt-br/documentacao/plataforma/applications/rules-engine/) correspondeu à solicitação e aplicou o behavior **Optimize Images**. Uma solicitação que não corresponde a nenhuma regra é entregue sem processamento, `ims` incluído.

- **Verifique os critérios da regra**: abra a regra na aba **Rules Engine** da aplicação e confirme que o critério corresponde à solicitação, como `${request_uri}` ou `${uri}` com o operador `matches` contra um argumento como `\.(jpg|jpeg|gif|bmp|png|ico|webp|avif)`.
- **Confirme que o behavior está presente**: a **Request Phase** da regra precisa aplicar o behavior **Optimize Images**. Para os campos do behavior, consulte [Configurações do Image Processor](/pt-br/documentacao/build/image-processor/configuracoes/).
- **Siga o procedimento**: os passos para construir a regra estão em [Configurar o Image Processor](/pt-br/documentacao/guias/performance-e-confiabilidade/otimizacao-de-entrega/processar-imagens/).

A próxima solicitação que corresponde à regra retorna uma imagem derivada, e a resposta carrega `x-ims: Enabled`.

## A imagem não é convertida para WEBP ou AVIF

Você solicita uma conversão de formato para WEBP ou AVIF, e a resposta não é entregue nesse formato.

Converter para WEBP ou AVIF exige que a solicitação carregue um header `Accept` nomeando o formato: `Accept: image/webp` ou `Accept: image/avif`. Uma solicitação que não carrega esse header não recebe o formato convertido.

- **Adicione o header com uma regra**: adicione o behavior **Add Request Header** à **Request Phase** da regra, com o valor definido como `Accept: image/webp` ou `Accept: image/avif`. Para os campos do behavior, consulte [Configurações do Image Processor](/pt-br/documentacao/build/image-processor/configuracoes/).

A próxima solicitação correspondente recebe a imagem no formato solicitado.

---

## Toda solicitação para a mesma imagem derivada é processada novamente, e o medidor de Images sobe

Você solicita a mesma imagem com a mesma query string `ims` mais de uma vez, e cada solicitação conta como uma imagem processada contra o medidor de Images da conta, em vez de ser servida a partir do cache.

A chave de cache de uma imagem derivada carrega a query string `ims`, mas variar o cache por uma query string é um campo do [Application Accelerator](/pt-br/documentacao/build/application-accelerator/): `cache_vary_by_querystring` fica em `modules.application_accelerator` em uma cache setting. Variar o cache por `ims` exige esse módulo; processar uma imagem não exige. Enquanto `ims` estiver ausente desse campo, o cache não diferencia uma imagem derivada de outra, e o Image Processor executa novamente a cada solicitação.

- **Liste `ims` no allowlist da query string**: na seção **Application Accelerator** da cache setting, defina **Behavior** como _Allowlist_ e adicione `ims` em **Fields**. Para a descrição dos campos, consulte [Configurações do Image Processor](/pt-br/documentacao/build/image-processor/configuracoes/).

Uma solicitação repetida para o mesmo valor de `ims` retorna do cache, e apenas a solicitação que construiu essa imagem derivada conta contra o medidor de Images.

## Um redimensionamento maior do que a original não amplia a imagem

Você solicita `fit-in/WidthxHeight`, ou uma largura ou altura maior do que a imagem de origem, e a imagem derivada não é maior do que a original.

Esse é o comportamento do redimensionamento, não uma falha. `fit-in` nunca amplia uma imagem: quando a área solicitada é maior do que as dimensões da imagem, a imagem mantém seu tamanho original. Fora do `fit-in`, uma solicitação para uma resolução maior do que a original é renderizada na maior resolução possível que a origem suporta.

A imagem derivada é renderizada no tamanho da imagem de origem, ou no maior tamanho que a caixa solicitada comporta. Para o restante da gramática de redimensionamento, consulte [Parâmetros de URL](/pt-br/documentacao/build/image-processor/parametros-de-url/).

---

## Um valor de rotação não tem efeito

Você define `?ims=filters:rotate(Angle)` com um valor fora de `0`, `90`, `180`, `270` e `360`, e a imagem derivada não é rotacionada.

A rotação aceita apenas esses cinco valores. Um valor fora dessa lista não rotaciona a imagem.

- **Use um dos cinco valores aceitos**: `0`, `90`, `180`, `270` ou `360`. Para a sintaxe completa, consulte [Parâmetros de URL](/pt-br/documentacao/build/image-processor/parametros-de-url/).

A imagem rotaciona para a esquerda pelo ângulo solicitado.
