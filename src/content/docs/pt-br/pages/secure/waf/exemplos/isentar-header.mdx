`specific_http_header_name` é o único valor de match que nomeia um header. A exceção abaixo impede que a regra `1005`, a regra do caractere pipe, dispare no header `Cookie`, e a deixa disparando no corpo, no path e na query string. Recorra a ela quando o próprio formato de um cookie de sessão disparar uma regra de que o resto do seu tráfego ainda precisa.

```bash
curl --request POST \
  --url https://api.azion.com/v4/workspace/wafs/<waf-id>/exceptions \
  --header 'Accept: application/json' \
  --header 'Authorization: Token [TOKEN VALUE]' \
  --header 'Content-Type: application/json' \
  --data '{
  "rule_id": 1005,
  "name": "Allow the session cookie on the storefront",
  "path": "/",
  "operator": "contains",
  "active": true,
  "conditions": [
    { "match": "specific_http_header_name", "name": "cookie" }
  ]
}'
```

```json
{
  "state": "pending",
  "data": {
    "id": 281937,
    "rule_id": 1005,
    "name": "Allow the session cookie on the storefront",
    "path": "/",
    "conditions": [
      { "match": "specific_http_header_name", "name": "cookie" }
    ],
    "operator": "contains",
    "active": true,
    "last_editor": "user@example.com",
    "last_modified": "2026-09-20T16:01:39.708534Z"
  }
}
```

O Azion CLI envia o mesmo corpo a partir de um arquivo com `azion create waf-exceptions --waf-id <waf-id> --file exception.json`.

## Como funciona

Uma condition carrega apenas as chaves que o seu próprio formato declara. Os valores de match `specific_` carregam uma segunda chave: `specific_http_header_name`, `specific_query_string_name` e `specific_body_form_field_name` carregam `name`, enquanto `specific_http_header_value`, `specific_query_string_value` e `specific_body_form_field_value` carregam `value`. Os nove valores genéricos carregam apenas `match`.

Uma chave que o formato não declara é descartada em vez de recusada. Enviar `{"match": "any_http_header_value", "name": "cookie"}` responde `202` e é lido de volta como `{"match": "any_http_header_value"}`: a exceção que um leitor pretendia para um header agora cobre todos os headers, e nenhuma resposta, releitura ou tela reporta a diferença. Leia a condition armazenada depois de criar uma. A API também armazena o nome do header exatamente como enviado, então `cookie`, `Cookie` e `HTTP_COOKIE` são mantidos como escritos em vez de normalizados para uma única forma.
