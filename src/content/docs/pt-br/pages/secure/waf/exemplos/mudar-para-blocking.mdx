O modo pertence ao behavior `Set WAF`, não ao rule set. `Logging` pontua uma requisição, registra o que correspondeu e a entrega; `Blocking` a recusa com `400`. Recorra a isto quando um rule set tiver rodado em `Logging` por tempo suficiente para você ler o que ele correspondeu, e você estiver pronto para que ele comece a recusar requisições.

Envie a regra de novo com `mode` definido como `blocking`. Um `PUT` para `/v4/workspace/firewalls/<firewall-id>/request_rules/<rule-id>` substitui a regra, então o corpo carrega os criteria também:

```json
{
  "name": "Apply storefront-waf",
  "active": true,
  "criteria": [
    [
      {
        "conditional": "if",
        "variable": "${request_uri}",
        "operator": "starts_with",
        "argument": "/"
      }
    ]
  ],
  "behaviors": [
    {
      "type": "set_waf",
      "attributes": {
        "waf_id": 21717,
        "mode": "blocking"
      }
    }
  ]
}
```

No Azion Console, abra o firewall, selecione a aba **Rules Engine** e a regra, e defina o modo no behavior **Set WAF** dela como _Blocking_.

## Como funciona

`mode` aceita `logging` ou `blocking` e nada mais. Um corpo carregando `"mode": "learning"` é recusado com `400` e o erro `10039 Invalid Choice`, apontando para `/data/behaviors/0/attributes/mode`; um corpo sem nenhum `mode` é recusado com `10059 Required Field` no mesmo ponteiro.

Como o modo fica no behavior, o mesmo rule set pode rodar em `logging` em uma regra e em `blocking` em outra. É assim que você move um path por vez: mantenha o rule set inalterado, e mude as regras que o aplicam uma a uma. Uma mudança leva vários minutos para alcançar a infraestrutura distribuída da Azion, e as requisições alternam entre o behavior antigo e o novo enquanto ela chega.
