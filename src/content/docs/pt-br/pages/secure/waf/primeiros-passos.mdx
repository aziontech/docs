Este guia orienta você a pontuar a sua primeira requisição contra o [Web Application Firewall (WAF)](/pt-br/documentacao/secure/waf/).

- Crie um rule set que carrega oito famílias de ameaças com sensibilidade `medium`.
- Aplique esse rule set a um firewall com um behavior `Set WAF` em modo blocking.
- Envie uma requisição com forma de injection e leia a recusa.

Quatro objetos colocam uma requisição sob inspeção, e cada um se liga ao seguinte:

1. O **rule set** guarda as famílias de ameaças e a sensibilidade escolhida para cada uma.
2. O **firewall** carrega o módulo WAF, e o **workload** que atende a sua aplicação está vinculado a esse firewall.
3. A **regra do Rules Engine** nesse firewall carrega um behavior `Set WAF`, que nomeia o rule set e o modo.
4. A **requisição** é o que o WAF então pontua contra o rule set.

Um rule set não inspeciona nada por conta própria. Enquanto uma regra do Rules Engine não o nomear, nenhuma requisição é pontuada.

## 1. Crie o WAF rule set

O rule set guarda o que detectar. Ele carrega oito famílias de ameaças, e cada família tem um nível de sensibilidade que fixa o score em que ela bloqueia. Toda família começa em `medium`, que é o nível que este guia usa.

<Tabs client:visible sharedStore="interface">

<Fragment slot="panel.console">

Para criar o rule set no Azion Console:

<DocSteps>
  <DocStep title="Abra a página WAF Rules">

  Acesse o [Azion Console](https://console.azion.com/) > **Edge Libraries** > **WAF Rules**.

  </DocStep>
  <DocStep title="Selecione + WAF Rule" />
  <DocStep title="Nomeie o rule set">

  Na seção **General**, informe um **Name**. Por exemplo: `storefront-waf`.

  </DocStep>
  <DocStep title="Deixe todas as famílias na sensibilidade padrão">

  A seção **Threat Type Configuration** lista oito famílias de ameaças. Cada uma abre em _Sensitivity Medium_.

  </DocStep>
  <DocStep title="Mantenha o switch Active habilitado" />
  <DocStep title="Salve o rule set" />
</DocSteps>

O rule set aparece em **WAF Rules**, que lista o seu **Threat Type Configuration**, **Status**, **Last Editor** e **Last Modified**.

</Fragment>

<Fragment slot="panel.cli">

A Azion CLI cria um rule set completo a partir apenas de um nome. Para criá-lo:

<DocSteps>
  <DocStep title="Execute o comando de criação">

  ```bash
  azion create waf --name "storefront-waf"
  ```

  </DocStep>
  <DocStep title="Leia a saída">

  O comando imprime o id do novo rule set:

  ```text
  Created WAF with ID 21719
  ```

  </DocStep>
</DocSteps>

O rule set está ativo, roda no ruleset `1` e carrega as oito famílias de ameaças em `medium`. Anote o id. A etapa 2 o passa para a regra.

</Fragment>

## 2. Aplique o rule set com uma regra do Rules Engine

Uma regra do [Rules Engine for Firewall](/pt-br/documentacao/plataforma/firewall/rules-engine/) seleciona requisições pelos seus próprios critérios. O seu behavior `Set WAF` então nomeia um rule set e um modo. A regra abaixo aplica o seu rule set a todas as requisições que o firewall recebe.

O modo é obrigatório, e ele pertence ao behavior, não ao rule set. `Blocking` recusa uma requisição cujo score alcança um limiar. `Logging` registra essa mesma requisição e a entrega. Este guia usa `Blocking`.

:::caution[Atenção]
Baseie o critério na URI da requisição, nunca na query string. Um critério como `${request_args}` `matches` `.*` não corresponde a uma requisição sem query string. Ele ignora silenciosamente todo `POST` cujo payload fica no body.
:::

<Tabs client:visible sharedStore="interface">

<Fragment slot="panel.console">

Para aplicar o rule set no Azion Console:

<DocSteps>
  <DocStep title="Abra o firewall vinculado ao seu workload">

  Ainda no Azion Console, vá para **Firewalls** e selecione esse firewall.

  </DocStep>
  <DocStep title="Selecione a aba Rules Engine" />
  <DocStep title="Selecione + Rule" />
  <DocStep title="Nomeie a regra">

  Informe um nome para a regra. Por exemplo: `Apply storefront-waf`.

  </DocStep>
  <DocStep title="Defina o critério">

  Na seção **Criteria**, selecione a variável `Request URI`, o operador de comparação _starts with_ e `/` como argumento.

  </DocStep>
  <DocStep title="Adicione o behavior Set WAF">

  Na seção **Behaviors**, selecione **Set WAF** e então selecione o rule set que você criou.

  </DocStep>
  <DocStep title="Selecione Blocking como o modo" />
  <DocStep title="Salve a regra" />
</DocSteps>

O firewall agora pontua contra o rule set todas as requisições que recebe. Uma regra carrega no máximo um behavior `Set WAF`.

</Fragment>

<Fragment slot="panel.cli">

O `azion create firewall-rule` lê a regra inteira de um arquivo JSON. Ele não tem flag para um behavior nem para um modo.

<DocSteps>
  <DocStep title="Escreva a regra em um arquivo">

  Salve o seguinte como `fw-rule.json`, com o id do seu rule set em `waf_id`:

  ```json
  {
    "name": "Apply storefront-waf",
    "active": true,
    "description": "",
    "criteria": [
      [
        {
          "conditional": "if",
          "variable": "${request_uri}",
          "operator": "starts_with",
          "argument": "/"
        }
      ]
    ],
    "behaviors": [
      {
        "type": "set_waf",
        "attributes": {
          "waf_id": 21717,
          "mode": "blocking"
        }
      }
    ]
  }
  ```

  </DocStep>
  <DocStep title="Crie a regra">

  Substitua `<firewall-id>` pelo id do seu firewall:

  ```bash
  azion create firewall-rule --firewall-id <firewall-id> --file fw-rule.json
  ```

  </DocStep>
  <DocStep title="Leia a saída">

  O comando imprime o id da nova regra:

  ```text
  Created Firewall Rule with ID 131733
  ```

  </DocStep>
</DocSteps>

O firewall agora pontua contra o rule set todas as requisições que recebe.

</Fragment>

<Fragment slot="panel.api">

Os critérios carregam `${request_uri}`, então o body é enviado a partir de um arquivo.

<DocSteps>
  <DocStep title="Escreva a regra em um arquivo">

  Salve o seguinte como `rule.json`, com o id do seu rule set em `waf_id`:

  ```json
  {
    "name": "Apply storefront-waf",
    "active": true,
    "criteria": [
      [
        {
          "conditional": "if",
          "variable": "${request_uri}",
          "operator": "starts_with",
          "argument": "/"
        }
      ]
    ],
    "behaviors": [
      {
        "type": "set_waf",
        "attributes": {
          "waf_id": 21717,
          "mode": "blocking"
        }
      }
    ]
  }
  ```

  </DocStep>
  <DocStep title="Envie a requisição de criação">

  Substitua `<firewall-id>` pelo id do seu firewall:

  ```bash
  curl --request POST \
    --url https://api.azion.com/v4/workspace/firewalls/<firewall-id>/request_rules \
    --header 'Accept: application/json' \
    --header 'Authorization: Token [TOKEN VALUE]' \
    --header 'Content-Type: application/json' \
    --data @rule.json
  ```

  </DocStep>
  <DocStep title="Leia a resposta">

  Um `202` carrega a regra, com a `order` que ela ocupa entre as regras do firewall:

  ```json
  {
    "state": "pending",
    "data": {
      "id": 131732,
      "name": "Apply storefront-waf",
      "last_editor": "user@example.com",
      "last_modified": "2026-09-20T15:53:29.020679Z",
      "created_at": "2026-09-20T15:53:29.020695Z",
      "active": true,
      "criteria": [
        [
          {
            "conditional": "if",
            "variable": "${request_uri}",
            "operator": "starts_with",
            "argument": "/"
          }
        ]
      ],
      "behaviors": [
        {
          "type": "set_waf",
          "attributes": {
            "waf_id": 21717,
            "mode": "blocking"
          }
        }
      ],
      "description": "",
      "order": 1
    }
  }
  ```

  </DocStep>
</DocSteps>

Um body que omite `mode` é recusado com `400` e o erro `10059 Required Field`, apontando para `/data/behaviors/0/attributes/mode`.

</Fragment>

</Tabs>

## 3. Verifique que o WAF bloqueia uma requisição

A verificação é a mesma qualquer que seja a interface que construiu a regra. O seu workload responde em um domínio no formato `<id>.map.azionedge.net`.

Um novo vínculo leva tempo para alcançar a infraestrutura distribuída da Azion. Espere perto de seis minutos até a regra entrar em vigor. O domínio então responde de forma inconsistente por vários minutos, enquanto a alteração chega em diferentes lugares. Uma requisição que ainda retorna a resposta anterior não quebrou nada: espere e envie-a de novo.

Envie primeiro uma requisição limpa:

```bash
curl -i https://<your-workload-domain>/
```

A requisição não é pontuada como ameaça e alcança a aplicação, que a responde:

```text
HTTP/2 200
```

A sua própria aplicação decide esse status. O que importa é que a requisição não é recusada.

Agora envie uma requisição com forma de injection, carregando `1' OR '1'='1` na query string:

```bash
curl -i "https://<your-workload-domain>/?q=1%27%20OR%20%271%27%3D%271"
```

O WAF a recusa:

```text
HTTP/2 400
content-type: text/html
x-azion-request-id: 1123d5bf29651faaaaf6e09dbafcc4e3
```

O body é a página de erro padrão da Azion, encabeçada por **Bad Request**. Nada na resposta nomeia o WAF, a regra que correspondeu ou o score. Anote o `x-azion-request-id`: esse valor encontra a requisição no [Real-Time Events](/pt-br/documentacao/observe/real-time-events/).

Essa requisição disparou as regras internas `1009` e `1013`, ambas no argumento `q`. Ela pontuou sob as famílias SQL injection e cross-site scripting. O seu rule set agora está pontuando tráfego.
