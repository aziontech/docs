Um único objeto JSON carrega tudo o que uma instância de função faz, e dois dos seus argumentos decidem se algo chega a ser recusado. O objeto abaixo define `action` como `allow`, então [Bot Manager Lite](/pt-br/documentacao/secure/bot-manager/bot-manager-lite/) pontua toda requisição e não recusa nenhuma, e aumenta `internal_logs`, então grava uma linha de report para cada uma. Recorra a ele na primeira vez que colocar Bot Manager na frente de tráfego real, enquanto ainda precisa descobrir o que o seu próprio tráfego pontua.

```json
{
  "threshold": 30,
  "action": "allow",
  "internal_logs": 2,
  "log_tag": "storefront-bots"
}
```

`threshold` é a pontuação na qual `action` dispara, e `30` é o valor que Bot Manager Lite traz. Com `action` em `allow`, nada é aplicado quando uma pontuação atinge esse valor, então uma requisição que cruza o threshold é pontuada, registrada e entregue como qualquer outra. Em `2`, `internal_logs` grava uma linha de report por requisição, inclusive por uma requisição que pontua `0`. `log_tag` nomeia esta instância nessas linhas, então substitua `storefront-bots` por uma tag sua. Para todos os argumentos que uma instância aceita, consulte [Argumentos](/pt-br/documentacao/secure/bot-manager/argumentos/#campos).

:::caution[Atenção]
O objeto não é validado. Azion armazena toda chave que você envia e a devolve exatamente como foi digitada, inclusive uma chave que a função nunca lê. Um `thresold` escrito errado fica na instância com aparência de configurado enquanto o threshold permanece em `30`, e nenhuma interface reporta isso.
:::

Salve o objeto como `bmargs.json`:

```json
{
  "threshold": 30,
  "action": "allow",
  "internal_logs": 2,
  "log_tag": "storefront-bots"

```

A flag `--args` de `azion create firewall-instance` recebe o caminho desse arquivo, e não JSON inline:

```bash
azion create firewall-instance --name bot-manager-observation --firewall-id <firewall-id> \
  --function-id <function-id> --args bmargs.json --active true
```

```text
Created Firewall Function Instance with ID 15841
```

Anote esse id. Uma regra do Rules Engine nomeia a instância por ele, nunca pelo id da função.

<Fragment slot="panel.api">

A chamada de criação carrega o nome, o id da função instalada e os argumentos em um único corpo. Substitua `<firewall-id>` pelo id do seu firewall, `[TOKEN VALUE]` pelo seu personal token e `53145` pelo id da função Bot Manager Lite instalada:

```bash
curl --request POST \
  --url https://api.azion.com/v4/workspace/firewalls/<firewall-id>/functions \
  --header 'Accept: application/json' \
  --header 'Authorization: Token [TOKEN VALUE]' \
  --header 'Content-Type: application/json' \
  --data '{
  "name": "bot-manager-observation",
  "function": 53145,
  "active": true,
  "args": {
    "threshold": 30,
    "action": "allow",
    "internal_logs": 2,
    "log_tag": "storefront-bots"
  }
}'
```

A chamada responde `202`. O corpo abre com `"state": "pending"`, que indica que a alteração ainda está se propagando, e traz em `data` a instância como a plataforma a armazenou: o `id` atribuído, os `args` devolvidos sem alteração e `"azion_form": {}`, o motivo pelo qual Azion Console renderiza um editor JSON para esta função em vez de um formulário. Anote o `id`.

</Fragment>

## Como funciona

`threshold` e `action` são uma decisão só, não duas configurações: a função aplica `action` a uma requisição cuja pontuação atinge `threshold`. Com `action` em `allow`, atingir o threshold não aplica nada, então a única diferença entre uma requisição que o cruza e outra que não o cruza é o valor que a linha de report carrega. O mesmo vale na outra ponta da escala. Um `threshold` de `0` deixa toda requisição no threshold ou acima dele e dispara a ação configurada em todas, o que com `allow` continua não recusando nada.

Ler as linhas é o objetivo desta configuração, e o veredito dentro delas se move com o threshold que você define. `classified` é relativo ao threshold em vigor, e não uma propriedade da requisição: Azion mediu a mesma pontuação de `28`, das mesmas regras correspondidas, lendo `legitimate` sob um threshold de `30` e `bad bot` sob um threshold que `28` atinge. Alterar o threshold durante uma janela de observação reclassifica o tráfego que você está observando.

O modo de falha aqui é o silêncio. Azion enviou vinte e uma chaves a uma instância, uma delas sem significado, e todas as vinte e uma foram armazenadas e devolvidas byte a byte, sem nada rejeitado, convertido ou descartado. Uma instância criada com um objeto vazio também armazena um objeto vazio, porque os padrões da função são um fallback de execução e não uma cópia, então uma instância que você abre para descobrir em que threshold ela roda mostra `{}` e não `30`. Reserve cerca de dois minutos depois de qualquer alteração: Azion consultou um workload a cada 15 segundos após trocar um argumento, e a oitava tentativa foi a primeira a responder de outra forma.
