Uma requisição pontuada deixa atrás de si uma linha de report, com a pontuação, as regras que a produziram e o veredito a que a função chegou. A query abaixo lê essas linhas do dataset `functionConsoleEvents`, que é a rota que Azion verificou. Recorra a ela sempre que quiser as pontuações que o seu próprio tráfego produz, esteja algo sendo recusado ou não.

Envie a query para `https://api.azion.com/v4/events/graphql` com um header `Authorization: Token [TOKEN VALUE]` e um `tsRange` que cubra a janela que você quer ler:

```graphql
{
  functionConsoleEvents(
    limit: 200
    filter: { tsRange: { begin: "2026-09-21T11:30:00", end: "2026-09-21T13:00:00" } }
    orderBy: [ts_ASC]
  ) {
    ts
    line
    level
    lineSource
    functionId
    configurationId
  }
}
```

A resposta é `200`, com um registro para cada linha que a função gravou. Em um registro do Bot Manager, `level` lê `LOG` e `lineSource` lê `CONSOLE`. `functionId` é o id da função instalada, e `configurationId` é o id do workload em que a requisição chegou, não o id do firewall que executou a instância.

`line` carrega a linha de report inteira: um prefixo e, em seguida, um objeto JSON.

```text
[Bot-Protection][storefront-bots] Report:  {"request_id":"f377c02e9b8c032ee3d426dc187d24b5","remote_addr":"203.0.113.42","fingerprint":"ge20cn020000_236f06e2e1da_aea9e0ce93d5_5311f4c13046","host":"<your-workload-domain>","http_user_agent":"","request_uri":"/","geoip_country":"BR","geoip_region":"PE","asn":"264046","score":28,"bot_category":"Bad Bot Signatures, Malicious Intent detected","classified":"legitimate","action":"allow","matched_rules":[1,10,18,19,20]}
```

Quatro valores respondem o que a instância fez com a requisição. `score` é o número a que a função chegou, `matched_rules` guarda as regras que o produziram, `action` é o que a função aplicou no threshold em vigor e `classified` é o veredito que ela registrou. Para todos os campos que uma linha carrega, consulte [Logs](/pt-br/documentacao/secure/bot-manager/logs/#campos).

## Como funciona

O segundo colchete do prefixo carrega o `log_tag` dos argumentos da instância, não o host. O host é um campo dentro do objeto, e `log_tag` não é: ele aparece apenas no prefixo, e é isso que o torna a forma de distinguir as linhas de uma instância das de outra. `functionId` não faz esse trabalho, porque toda instância da função instalada compartilha o mesmo valor. Dê a cada instância uma tag própria antes de sair procurando as linhas dela.

Uma linha existe apenas para uma requisição que o valor de `internal_logs` da instância cobre. Em `2` a função grava uma para toda requisição, inclusive para uma que pontua `0`, que é o valor que uma janela de observação pede. O veredito na linha também se move com o threshold: `classified` é relativo ao threshold em vigor, e não uma propriedade da requisição, e Azion mediu a mesma pontuação de `28`, das mesmas regras correspondidas, lendo `legitimate` sob um threshold de `30` e `bad bot` sob um threshold que `28` atinge.

Dois valores de um registro são lidos errado com mais frequência que os demais. `configurationId` é o id do workload, então um filtro montado em torno de um id de firewall não retorna nada, em vez de retornar um erro. E `geoip_country` é um código de país, `BR` e não `Brazil`, enquanto `fingerprint` são quatro segmentos separados por underscore, e não um hash de um comprimento qualquer.
