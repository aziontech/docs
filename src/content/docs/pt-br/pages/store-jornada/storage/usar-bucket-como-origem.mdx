Você serve os objetos de um bucket do [Object Storage](/pt-br/documentacao/store/object-storage/) para a internet ao combinar um connector com uma regra do Rules Engine em uma [aplicação](/pt-br/documentacao/plataforma/applications/). Uma requisição ao domínio do [workload](/pt-br/documentacao/plataforma/workloads/) então retorna o objeto armazenado sob a key correspondente.

Uma conta que não migrou para a API v4 constrói o mesmo caminho de entrega por Origins. Para mais informações, consulte [Verifique a migração da sua conta para a API v4](/pt-br/documentacao/guias/seguranca-de-aplicacoes/acesso-e-compliance/verificar-migracao-conta/), [Connectors](/pt-br/documentacao/plataforma/connectors/) e [Origins](/pt-br/documentacao/plataforma/connectors/origins/).

---

## Pré-requisitos

- Um bucket com `workloads_access` definido como `read_only` ou `read_write`. Um bucket `restricted` não pode servir de origem para uma aplicação. Para mais informações, consulte [Criar um bucket](/pt-br/documentacao/guias/desenvolvimento-de-aplicacoes/dados/criar-e-modificar-um-bucket/).
- Uma [aplicação](/pt-br/documentacao/plataforma/applications/) e um [workload](/pt-br/documentacao/plataforma/workloads/) que carrega o domínio em que a aplicação responde.
- Um [personal token](/pt-br/documentacao/guias/plataforma/conta-e-billing/personal-tokens/), para os procedimentos pela API.
- Acesso ao Azion Console, para os procedimentos pelo Console. Para mais informações, consulte [Como acessar o Azion Console](/pt-br/documentacao/guias/plataforma/conta-e-billing/como-acessar-o-azion-console/).

:::caution[Atenção]
Um bucket definido como `read_write` e servido por uma aplicação pode ser modificado por qualquer pessoa que o alcance, por uma requisição que sobrescreve um objeto. Sirva conteúdo estático de um bucket `read_only` e coloque uma função na frente do bucket quando um caminho tiver que aceitar escritas. Para mais informações, consulte [Boas práticas](/pt-br/documentacao/store/object-storage/boas-praticas/).
:::

## Faça upload dos objetos a servir

O connector serve o que o bucket já guarda, então os objetos entram primeiro. Este exemplo serve uma página de dois objetos, ambos armazenados sob o prefix `src` de um bucket chamado `app-origin`:

```text
src/index.html
src/styles/style.css
```

Para criar os dois arquivos e armazená-los:

<DocSteps>
  <DocStep title="Crie o arquivo HTML">

  Em um diretório local `src`, crie `index.html`, que referencia a folha de estilos por um caminho relativo:

  ```html
  <!DOCTYPE html>
  <html lang="en">
  <head>
      <meta charset="UTF-8">
      <meta name="viewport" content="width=device-width, initial-scale=1.0">
      <title>Document</title>
      <link rel="stylesheet" href="styles/style.css">
  </head>
  <body>
      <h1>Hello world!</h1>
      <p>I am an object from a bucket.</p>
  </body>
  </html>
  ```

  </DocStep>
  <DocStep title="Crie a folha de estilos">

  Em um diretório `styles` dentro de `src`, crie `style.css`, o arquivo ao qual a página se refere:

  ```css
  body {
    background-color: black;
  }

  h1,
  p {
    color: white;
  }
  ```

  </DocStep>
  <DocStep title="Faça upload do arquivo HTML">

  A key do objeto é o caminho que o arquivo mantém dentro do bucket, e `Content-Type` define o tipo com que o objeto é armazenado e servido:

  ```bash
  curl --request POST \
    --url https://api.azion.com/v4/workspace/storage/buckets/app-origin/objects/src/index.html \
    --header 'Accept: application/json' \
    --header 'Authorization: Token [TOKEN VALUE]' \
    --header 'Content-Type: text/html' \
    --data-binary '@./src/index.html'
  ```

  A resposta carrega a key sob a qual o objeto é armazenado:

  ```json
  {
    "state": "executed",
    "data": {
      "object_key": "src/index.html"
    }
  }
  ```

  </DocStep>
  <DocStep title="Faça upload da folha de estilos">

  ```bash
  curl --request POST \
    --url https://api.azion.com/v4/workspace/storage/buckets/app-origin/objects/src/styles/style.css \
    --header 'Accept: application/json' \
    --header 'Authorization: Token [TOKEN VALUE]' \
    --header 'Content-Type: text/css' \
    --data-binary '@./src/styles/style.css'
  ```

  A resposta carrega a key do segundo objeto:

  ```json
  {
    "state": "executed",
    "data": {
      "object_key": "src/styles/style.css"
    }
  }
  ```

  </DocStep>
</DocSteps>

O bucket guarda os dois objetos, e o segmento `src/` de cada key faz parte da key em vez de ser uma pasta. Azion Console e a Azion CLI armazenam os mesmos objetos. Para mais informações, consulte [Upload e download de objetos](/pt-br/documentacao/guias/desenvolvimento-de-aplicacoes/dados/upload-e-download-de-objetos-do-bucket/).

## Crie o connector

Um connector do tipo Object Storage nomeia o bucket do qual uma aplicação lê e o prefix dentro dele. O prefix decide onde o caminho da aplicação começa: com o prefix `/src`, o objeto armazenado sob `src/index.html` responde em `/index.html`, e `src/styles/style.css` responde em `/styles/style.css`.

### Azion Console

Para criar o connector:

<DocSteps>
  <DocStep title="Abra a lista de connectors">

  Acesse [Azion Console](https://console.azion.com/) > **Connectors** e inicie um novo connector.

  </DocStep>
  <DocStep title="Nomeie o connector">

  Em **General**, insira um nome que identifique o que o connector serve.

  </DocStep>
  <DocStep title="Selecione o tipo do connector">

  Em **Connector Type**, selecione _Object Storage_.

  </DocStep>
  <DocStep title="Selecione o bucket">

  Em **Connection Options**, selecione o seu bucket em **Bucket**. O seletor lista os buckets da sua conta e carrega um campo de busca.

  </DocStep>
  <DocStep title="Defina o prefix">

  Em **Connection Options**, insira `/src` em **Prefix**, o prefix sob o qual você fez upload dos objetos.

  </DocStep>
  <DocStep title="Ative o connector">

  Defina **Status** como _Active_.

  </DocStep>
  <DocStep title="Selecione Save" />
</DocSteps>

O connector lê do bucket e do prefix que você definiu.

### A API

Envie uma requisição `POST` ao endpoint de connectors. O campo `type` é a string `storage`, e `attributes` carrega o bucket e o prefix. Para criar o connector:

<DocSteps>
  <DocStep title="Envie a requisição de criação">

  ```bash
  curl --request POST \
    --url https://api.azion.com/v4/workspace/connectors \
    --header 'Accept: application/json' \
    --header 'Authorization: Token [TOKEN VALUE]' \
    --header 'Content-Type: application/json' \
    --data '{
    "name": "object storage connector",
    "active": true,
    "type": "storage",
    "attributes": {
      "bucket": "app-origin",
      "prefix": "/src"
    }
  }'
  ```

  </DocStep>
  <DocStep title="Leia a resposta">

  Um `201` carrega o connector que a Azion armazenou:

  ```json
  {
    "state": "executed",
    "data": {
      "id": "<connector_id>",
      "name": "object storage connector",
      "last_editor": "user@example.com",
      "last_modified": "2026-09-17T22:34:31.009649Z",
      "active": true,
      "product_version": "1.0",
      "type": "storage",
      "attributes": {
        "bucket": "app-origin",
        "prefix": "/src"
      }
    }
  }
  ```

  </DocStep>
</DocSteps>

Copie o valor de `data.id`. A regra do Rules Engine endereça o connector por ele.

## Roteie requisições para o connector

Um connector não serve nada até que uma regra do Rules Engine envie requisições para ele. A regra roda na **Request Phase** da aplicação, corresponde aos caminhos que o bucket responde e define o connector em cada requisição correspondente.

### Azion Console

O behavior é **Set Connector**, e um criteria de `${uri}` começando com `/` envia toda a aplicação para o bucket. Para rotear as requisições:

<DocSteps>
  <DocStep title="Abra as regras da aplicação">

  Acesse [Azion Console](https://console.azion.com/) > **Applications** > a sua aplicação, depois vá para a aba **Rules Engine**.

  </DocStep>
  <DocStep title="Abra uma regra de request">

  Edite a regra padrão ou adicione uma regra na **Request Phase**.

  </DocStep>
  <DocStep title="Corresponda os caminhos a servir">

  Em **Criteria**, defina o criteria como `If ${uri} starts with /`.

  </DocStep>
  <DocStep title="Defina o connector">

  Em **Behavior**, selecione o behavior **Set Connector**, depois selecione o connector que você criou.

  </DocStep>
  <DocStep title="Selecione Save" />
</DocSteps>

A regra envia toda requisição correspondente para o bucket. A mudança leva algum tempo para propagar antes que o domínio responda com os objetos.

### A API

Envie uma requisição `POST` para as request rules da aplicação. O tipo do behavior é `set_connector` e ele carrega o identificador do connector em `value`. Para rotear as requisições:

<DocSteps>
  <DocStep title="Envie a requisição de criação">

  Substitua `<application_id>` pelo identificador da sua aplicação e `<connector_id>` pelo identificador do connector:

  ```bash
  curl --request POST \
    --url https://api.azion.com/v4/workspace/applications/<application_id>/request_rules \
    --header 'Accept: application/json' \
    --header 'Authorization: Token [TOKEN VALUE]' \
    --header 'Content-Type: application/json' \
    --data '{
    "name": "serve the bucket",
    "active": true,
    "criteria": [
      [
        {
          "conditional": "if",
          "variable": "${uri}",
          "operator": "starts_with",
          "argument": "/"
        }
      ]
    ],
    "behaviors": [
      {
        "type": "set_connector",
        "attributes": {
          "value": "<connector_id>"
        }
      }
    ]
  }'
  ```

  </DocStep>
  <DocStep title="Leia a resposta">

  A resposta retorna a regra, com `state` definido como `pending`:

  ```json
  {
    "state": "pending",
    "data": {
      "id": "<rule_id>",
      "name": "serve the bucket",
      "active": true,
      "criteria": [
        [
          {
            "conditional": "if",
            "variable": "${uri}",
            "operator": "starts_with",
            "argument": "/"
          }
        ]
      ],
      "behaviors": [
        {
          "type": "set_connector",
          "attributes": {
            "value": "<connector_id>"
          }
        }
      ],
      "description": "",
      "order": 1,
      "last_editor": "user@example.com",
      "last_modified": "2025-07-25T19:29:30.684210Z"
    }
  }
  ```

  </DocStep>
</DocSteps>

A regra é criada na **Request Phase** da aplicação. A mudança leva algum tempo para propagar antes que o domínio responda com os objetos.

## Verifique a configuração

Uma requisição ao domínio do workload retorna o objeto que o connector mapeia para o caminho. Um workload carrega um domínio no formato `xxxxxxxxxxx.azionedge.net`.

Para confirmar o caminho de entrega:

<DocSteps>
  <DocStep title="Requisite a página">

  Substitua `<workload-domain>` pelo domínio que o seu workload carrega:

  ```bash
  curl https://<workload-domain>/index.html
  ```

  </DocStep>
  <DocStep title="Leia a resposta">

  O corpo da resposta é o objeto armazenado sob `src/index.html`, que o prefix `/src` mapeia para `/index.html`. Ele carrega o título e o parágrafo da página:

  ```html
  <h1>Hello world!</h1>
  <p>I am an object from a bucket.</p>
  ```

  </DocStep>
  <DocStep title="Abra a página em um navegador">

  Vá para o mesmo endereço. O navegador renderiza a página com a folha de estilos aplicada, que ele carrega de `/styles/style.css` sob o mesmo prefix.

  </DocStep>
</DocSteps>

A aplicação serve o bucket. Uma requisição que ainda não retorna o objeto é uma mudança que não propagou: espere, envie de novo e procure outra causa somente depois disso.
