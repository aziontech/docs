Este guia orienta você a armazenar e ler a sua primeira key no [KV Store](/pt-br/documentacao/store/kv-store/). No fim, você vai ter:

- O seu primeiro namespace, criado pela API da Azion.
- Uma function que abre o namespace, grava uma key e a lê de volta.
- Uma instância da function e uma regra do Rules Engine que executam essa function.
- Uma URI na sua própria aplicação que responde com o valor armazenado.

Este guia usa duas interfaces, porque KV Store não tem tela no Azion Console. O **namespace** é criado pela API da Azion, e ele é permanente: não pode ser renomeado, esvaziado nem excluído depois, então vale escolher o nome antes da primeira requisição. A **function** guarda o código que abre o namespace e chama o cliente. A **instância da function** liga a function a uma aplicação, e a regra do **Rules Engine** seleciona essa instância e define quais requisições a executam. Criar uma function não a executa, e uma instância sem regra nunca é executada.

---

## Pré-requisitos

- Uma conta Azion. Para criar uma, consulte [Como criar uma conta na Azion](/pt-br/documentacao/fundamentos/criar-uma-conta/).
- Acesso ao Preview do KV Store na conta. O produto está em Preview, e o acesso é solicitado ao time de suporte técnico. Para solicitá-lo, consulte [Technical Support](/pt-br/documentacao/suporte/).
- Um personal token. A etapa 1 o envia no cabeçalho `Authorization`. Para criar um, consulte [Como criar um personal token](/pt-br/documentacao/guias/plataforma/conta-e-billing/personal-tokens/).
- As permissões **Edit Functions** e **Edit Applications** na conta. Elas concedem permissão para criar a function e para alterar a aplicação que a executa. Para mais informações, consulte [Teams Permissions](/pt-br/documentacao/fundamentos/teams-permissions/).
- Uma aplicação. Para criar uma, consulte [Criar uma aplicação](/pt-br/documentacao/guias/desenvolvimento-de-aplicacoes/primeiros-passos/criar-uma-aplicacao/).

## 1. Crie um namespace

Um namespace é o container em que KV Store guarda keys e values, e o nome dele é o seu identificador. O nome tem de 3 a 63 caracteres, e usa letras, números, o hífen e o underscore. Para criar o seu primeiro:

<DocSteps>
  <DocStep title="Envie a requisição de criação">

  Substitua `[TOKEN VALUE]` pelo seu personal token, e `my-namespace` por um nome seu:

  ```bash
  curl --request POST \
    --url https://api.azion.com/v4/workspace/kv/namespaces \
    --header 'Accept: application/json' \
    --header 'Authorization: Token [TOKEN VALUE]' \
    --header 'Content-Type: application/json' \
    --data '{
    "name": "my-namespace"
  }'
  ```

  </DocStep>
  <DocStep title="Leia a resposta">

  Um `201` carrega o namespace inteiro:

  ```json
  {
    "name": "my-namespace",
    "created_at": "2026-09-18T16:35:27.577829",
    "last_modified": "2026-09-18T16:35:27.577829"
  }
  ```

  Um `400` com a mensagem `Namespace already exists` significa que a conta já tem esse nome. Escolha um nome diferente e envie a requisição de novo.

  </DocStep>
</DocSteps>

A requisição é síncrona, e não há estado de provisionamento a consultar. O `name` que a resposta carrega é o identificador que toda chamada seguinte usa, inclusive a function que você escreve a seguir. Para todos os campos, operações e erros desse endpoint, consulte [Namespaces](/pt-br/documentacao/store/kv-store/namespaces/).

## 2. Crie a function

`Azion.KV` é um global do Azion Runtime, então uma [function](/pt-br/documentacao/build/functions/) o alcança sem linha de import e sem credencial. A function abaixo abre o namespace, grava uma key, a lê de volta e retorna o valor.

:::caution[Atenção]
Uma chamada a `Azion.KV.open()` pode responder `NotFound: KV namespace "my-namespace" does not exist` para um namespace que existe e que a API da Azion lista. A Azion observou isso em uma conta que tem acesso ao Preview do KV Store. Se a sua function retornar esse erro, entre em contato com o time de [Technical Support](/pt-br/documentacao/suporte/) com o nome do namespace e a conta a que ele pertence.
:::

Para criar a function:

<DocSteps>
  <DocStep title="Abra a página Functions">

  Acesse [Azion Console](https://console.azion.com/) > **Products Menu** > **Libraries** > **Functions**.

  </DocStep>
  <DocStep title="Selecione + Function" />
  <DocStep title="Nomeie a function">

  Insira um nome para a function. Por exemplo: `kv-quickstart`.

  </DocStep>
  <DocStep title="Cole o código na aba Code">

  Na aba **Code**, cole o código a seguir, com o nome do namespace que você criou:

  ```javascript
  export default {
    async fetch(request, env, ctx) {
      const kv = await Azion.KV.open('my-namespace');

      await kv.put('user-42', 'active');
      const value = await kv.get('user-42', 'text');

      return new Response(value ?? 'No value for that key');
    },
  };
  ```

  </DocStep>
  <DocStep title="Selecione Save" />
</DocSteps>

A function é salva e guarda o código que alcança o namespace. Ela ainda não é executada: a etapa seguinte a liga a uma aplicação e adiciona a regra que a aciona. Para todos os métodos que o cliente carrega, consulte [Cliente KV](/pt-br/documentacao/store/kv-store/cliente-kv/).

## 3. Instancie a function e adicione a regra

Uma instância liga a function a uma aplicação, e uma regra decide quais requisições executam a instância. Para configurar as duas:

<DocSteps>
  <DocStep title="Abra a aplicação que executa a function">

  Ainda no Azion Console, vá para **Products Menu** > **Build** > **Applications**, e então selecione a sua aplicação.

  </DocStep>
  <DocStep title="Na aba Main Settings, ative o módulo Functions" />
  <DocStep title="Selecione Save" />
  <DocStep title="Vá para a aba Functions Instances" />
  <DocStep title="Selecione + Function Instance" />
  <DocStep title="Nomeie a instância">

  Insira um nome para a instância. Por exemplo: `kv-quickstart instance`.

  </DocStep>
  <DocStep title="Selecione a function kv-quickstart" />
  <DocStep title="Selecione Save" />
  <DocStep title="Vá para a aba Rules Engine" />
  <DocStep title="Selecione + Rule" />
  <DocStep title="Nomeie a regra">

  Insira um nome para a regra. Por exemplo: `Run kv-quickstart`.

  </DocStep>
  <DocStep title="Selecione Request Phase" />
  <DocStep title="Defina os critérios">

  Na seção **Criteria**, selecione a variável `${uri}` e o operador _is equal_, e insira `/kv-quickstart` como argumento.

  </DocStep>
  <DocStep title="Na seção Behaviors, selecione Run Function" />
  <DocStep title="Selecione a instância que você criou" />
  <DocStep title="Selecione Save" />
</DocSteps>

A regra executa a instância em toda requisição cuja URI é `/kv-quickstart`. Regras novas podem levar alguns minutos para propagar. Espere antes de requisitar a URI. Para cada campo de instância e de regra que este guia não detalha, consulte [Primeiros passos com Functions](/pt-br/documentacao/build/functions/primeiros-passos/).

---

## 4. Requisite a URI

A sua aplicação responde no domínio dela. Para alcançar a function, requisite a URI correspondente à regra:

```bash
curl https://<your-azion-domain>/kv-quickstart
```

Uma resposta bem-sucedida carrega o corpo que a function retorna, que é o valor que ela armazenou sob `user-42` e leu de volta: a string `active`. Uma resposta que carrega `No value for that key` significa que a leitura retornou `null`, ou seja, a key não foi encontrada sob esse nome.

O seu primeiro namespace guarda uma key, e uma function a grava e a lê em toda requisição correspondente à regra.
