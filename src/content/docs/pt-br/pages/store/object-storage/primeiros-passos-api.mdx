Este guia orienta você a armazenar o seu primeiro objeto no [Object Storage](/pt-br/documentacao/store/object-storage/), pela Azion API. No fim, você vai ter:

- O seu primeiro bucket, criado com `workloads_access` definido como `read_only`.
- Um objeto armazenado nesse bucket, endereçado pela sua key.
- O objeto listado e lido de volta, o que confirma o upload.

Prefere o Azion Console? Consulte [Primeiros passos com Object Storage usando Azion Console](/pt-br/documentacao/store/object-storage/primeiros-passos/).

Um bucket não é uma pasta pública: um objeto do qual você faz upload não responde a nenhuma requisição vinda da internet enquanto uma aplicação não apontar para ele. O resultado se apoia em três objetos, nesta ordem. O **bucket** é o container de nível mais alto para objetos e buckets não são aninhados. Cada **objeto** dentro dele é um arquivo, a sua key e o seu content type. A key endereça o objeto: uma `/` em uma key faz parte da key, não é uma pasta. Um **connector** do tipo Object Storage, combinado com uma regra do Rules Engine em uma [aplicação](/pt-br/documentacao/plataforma/applications/), é o que envia uma requisição ao bucket. Este guia cria os dois primeiros e para por aí.

---

## Pré-requisitos

- Um [personal token](/pt-br/documentacao/guias/plataforma/conta-e-billing/personal-tokens/). Cada requisição desta página o envia no header `Authorization`.
- Permissão para criar buckets e objetos na sua conta. Para mais informações, consulte [Como gerenciar permissões de times](/pt-br/documentacao/fundamentos/teams-permissions/).
- O `curl`, ou outro cliente que envia requisições HTTP.
- Um arquivo na sua máquina para fazer upload, como uma imagem.

---

## 1. Crie um bucket

Um bucket guarda os objetos dos quais você faz upload. Este é criado com `read_only`, o nível de acesso para conteúdo que a Azion Platform entrega sem modificar.

Os nomes de bucket são únicos em todas as contas Azion, então um nome curto e genérico provavelmente já está reservado. Um nome tem de 6 a 63 caracteres, usa letras, números e o hífen e nunca começa com `azion`.

<DocSteps>
  <DocStep title="Envie a requisição de criação">

  Substitua `[TOKEN VALUE]` pelo seu personal token e `my-first-bucket` por um nome seu:

  ```bash
  curl --request POST \
    --url https://api.azion.com/v4/workspace/storage/buckets \
    --header 'Accept: application/json' \
    --header 'Authorization: Token [TOKEN VALUE]' \
    --header 'Content-Type: application/json' \
    --data '{
    "name": "my-first-bucket",
    "workloads_access": "read_only"
  }'
  ```

  </DocStep>
  <DocStep title="Leia a resposta">

  Um `201` carrega o bucket:

  ```json
  {
    "state": "executed",
    "data": {
      "name": "my-first-bucket",
      "workloads_access": "read_only",
      "last_editor": "user@example.com",
      "last_modified": "2026-09-17T22:39:45.442763+00:00",
      "product_version": "1.0"
    }
  }
  ```

  Um `400` com o código `17000` significa que o nome já está em uso, na sua conta ou em outra. Escolha um nome diferente e envie a requisição novamente.

  </DocStep>
</DocSteps>

O bucket existe e não guarda nenhum objeto.

---

## 2. Faça upload de um objeto

O upload nomeia o bucket e a key no path e envia o arquivo como o body. Não existe uma sequência de criar e depois escrever: o objeto existe quando a requisição tem sucesso.

<DocSteps>
  <DocStep title="Envie a requisição de upload">

  Substitua a key e o caminho do arquivo pelos seus. Defina o `Content-Type` com o tipo do seu arquivo, porque o valor armazenado é o que esse header carrega:

  ```bash
  curl --request POST \
    --url https://api.azion.com/v4/workspace/storage/buckets/my-first-bucket/objects/images/logo.png \
    --header 'Accept: application/json' \
    --header 'Authorization: Token [TOKEN VALUE]' \
    --header 'Content-Type: image/png' \
    --data-binary '@./logo.png'
  ```

  </DocStep>
  <DocStep title="Leia a resposta">

  Um `201` carrega a key sob a qual o objeto está armazenado:

  ```json
  {
    "state": "executed",
    "data": {
      "object_key": "images/logo.png"
    }
  }
  ```

  </DocStep>
</DocSteps>

O objeto está armazenado. O segmento `images/` faz parte da key, não é uma pasta que precisava existir antes.

---

## 3. Confirme que o objeto está armazenado

Duas requisições confirmam o upload: uma lista o bucket e outra lê o objeto de volta.

<DocSteps>
  <DocStep title="Liste os objetos no bucket">

  ```bash
  curl --request GET \
    --url https://api.azion.com/v4/workspace/storage/buckets/my-first-bucket/objects \
    --header 'Accept: application/json' \
    --header 'Authorization: Token [TOKEN VALUE]'
  ```

  A resposta lista a key, quando ela foi modificada pela última vez, o seu tamanho em bytes e se a entrada é um prefix:

  ```json
  {
    "continuation_token": null,
    "results": [
      {
        "key": "images/logo.png",
        "last_modified": "2026-09-17T22:40:32.054000Z",
        "size": 5364,
        "is_folder": false
      }
    ]
  }
  ```

  </DocStep>
  <DocStep title="Faça download do objeto">

  Leia o objeto de volta para um arquivo local e confirme o content type que a Azion armazenou:

  ```bash
  curl --request GET \
    --url https://api.azion.com/v4/workspace/storage/buckets/my-first-bucket/objects/images/logo.png \
    --header 'Authorization: Token [TOKEN VALUE]' \
    --output ./logo-downloaded.png --dump-header -
  ```

  Os headers da resposta carregam `HTTP/2 200` e o `content-type` que o upload definiu. O arquivo é escrito em `./logo-downloaded.png`.

  </DocStep>
</DocSteps>

O objeto está armazenado sob a sua key e é lido de volta com o content type que você definiu. Ele é alcançável pela Azion API, pela Azion CLI e pelo protocolo S3. Pela internet, ainda não.
