Este guia orienta você a armazenar e ler a sua primeira linha no [SQL Database](/pt-br/documentacao/store/sql-database/), pela Azion API. No fim, você vai ter:

- O seu primeiro banco de dados, com o status `created`.
- Uma tabela `users` dentro dele.
- Uma linha armazenada nessa tabela.
- A mesma linha retornada por uma instrução `SELECT`.

Prefere o Azion Console? Consulte [Primeiros passos com SQL Database usando Azion Console](/pt-br/documentacao/store/sql-database/primeiros-passos/).

O resultado se apoia em dois objetos. O **banco de dados** é o container, e o seu nome não pode ser alterado depois da criação. Cada **tabela** vive dentro de um banco de dados, e este guia cria a tabela com uma instrução `CREATE TABLE` enviada ao endpoint de consulta. Um banco de dados é provisionado de forma assíncrona. O seu status é `creating` primeiro, e uma instrução só é executada contra ele depois que o status for `created`.

---

## Pré-requisitos

- Um [personal token](/pt-br/documentacao/guias/plataforma/conta-e-billing/personal-tokens/). Cada requisição desta página o envia no header `Authorization`.
- SQL Database habilitado na conta. O produto está em Preview, e o acesso é solicitado ao time de suporte técnico. Para solicitar, consulte [Technical Support](/pt-br/documentacao/suporte/).
- A permissão **Edit SQL Database** na conta. Ela concede permissão para criar e editar bancos de dados e os seus dados pela Azion API. Para mais informações, consulte [Teams Permissions](/pt-br/documentacao/fundamentos/teams-permissions/).

## 1. Crie um banco de dados

Um banco de dados guarda as tabelas que você cria. O seu nome tem de 6 a 50 caracteres e usa letras, números e o hífen. Para criar o seu primeiro:

<DocSteps>
  <DocStep title="Envie a requisição de criação">

  Substitua `[TOKEN VALUE]` pelo seu personal token e `my-database` por um nome seu:

  ```bash
  curl --request POST \
    --url https://api.azion.com/v4/workspace/sql/databases \
    --header 'Accept: application/json' \
    --header 'Authorization: Token [TOKEN VALUE]' \
    --header 'Content-Type: application/json' \
    --data '{
    "name": "my-database"
  }'
  ```

  </DocStep>
  <DocStep title="Leia a resposta">

  Um `202` carrega o banco de dados:

  ```json
  {
    "state": "pending",
    "data": {
      "id": 1851,
      "name": "my-database",
      "status": "creating",
      "active": true,
      "last_modified": "2026-09-18T02:10:35.433088Z",
      "last_editor": "user@example.com",
      "product_version": "1.0"
    }
  }
  ```

  Um `400` com o código `14001` significa que a conta já tem um banco de dados com esse nome. Escolha um nome diferente e envie a requisição novamente.

  </DocStep>
</DocSteps>

Anote o `id` que a resposta carrega, `1851` neste exemplo. Cada requisição abaixo endereça o banco de dados por ele. O `state` do envelope é `pending` enquanto o `status` do banco de dados é `creating`, porque o provisionamento não terminou.

## 2. Espere o banco de dados ficar pronto

Uma instrução não tem sucesso contra um banco de dados cujo status é `creating`. Consulte o banco de dados até que o status seja `created`:

<DocSteps>
  <DocStep title="Envie a requisição de leitura">

  Substitua `1851` pelo `id` que a resposta de criação retornou:

  ```bash
  curl --request GET \
    --url https://api.azion.com/v4/workspace/sql/databases/1851 \
    --header 'Accept: application/json' \
    --header 'Authorization: Token [TOKEN VALUE]'
  ```

  </DocStep>
  <DocStep title="Leia o status">

  Um `200` carrega o banco de dados, e esta resposta não tem a chave `state`:

  ```json
  {
    "data": {
      "id": 1851,
      "name": "my-database",
      "status": "created",
      "active": true,
      "last_modified": "2026-09-18T02:10:59.058568Z",
      "last_editor": "user@example.com",
      "product_version": "1.0"
    }
  }
  ```

  </DocStep>
  <DocStep title="Envie a requisição novamente enquanto o status for creating">

  O provisionamento leva cerca de 15 segundos. Espere alguns segundos entre as requisições.

  </DocStep>
</DocSteps>

O banco de dados está pronto quando o `status` é `created`. Não pule esta etapa: uma consulta enviada enquanto o status é `creating` não tem sucesso.

## 3. Crie uma tabela e insira uma linha

O endpoint de consulta executa SQL contra um banco de dados. O body carrega um array `statements`, e a Azion executa as instruções em ordem. Para criar a tabela `users` e armazenar a primeira linha:

<DocSteps>
  <DocStep title="Envie a requisição de consulta">

  A instrução `INSERT` carrega aspas simples, então o body é enviado pela entrada padrão:

  ```bash
  curl --request POST \
    --url https://api.azion.com/v4/workspace/sql/databases/1851/query \
    --header 'Accept: application/json' \
    --header 'Authorization: Token [TOKEN VALUE]' \
    --header 'Content-Type: application/json' \
    --data @- <<'EOF'
  {
    "statements": [
      "CREATE TABLE users (id INTEGER PRIMARY KEY, name TEXT, email TEXT);",
      "INSERT INTO users (name, email) VALUES ('Ada', 'ada@example.com');"
    ]
  }
  EOF
  ```

  </DocStep>
  <DocStep title="Leia a resposta">

  Um `200` carrega uma entrada por instrução:

  ```json
  {
    "state": "executed",
    "data": [
      {
        "results": {
          "columns": [],
          "rows": [],
          "rows_read": 1,
          "rows_written": 2,
          "query_duration_ms": 2.391
        }
      },
      {
        "results": {
          "columns": [],
          "rows": [],
          "rows_read": 1,
          "rows_written": 1,
          "query_duration_ms": 0.092
        }
      }
    ]
  }
  ```

  Nenhuma das duas instruções retorna linhas, então `columns` e `rows` estão vazios nas duas entradas. Mesmo assim, as duas reportam linhas lidas e escritas, porque `CREATE TABLE` escreve o próprio schema. A Azion cobra por `rows_read` e `rows_written`, e retorna os dois por instrução.

  </DocStep>
</DocSteps>

O banco de dados tem uma tabela `users` com uma linha.

---

## 4. Leia a linha de volta

Uma instrução `SELECT` retorna o que a tabela guarda. Para ler a linha que você inseriu:

<DocSteps>
  <DocStep title="Envie a requisição de consulta">

  Substitua `1851` pelo `id` do seu banco de dados:

  ```bash
  curl --request POST \
    --url https://api.azion.com/v4/workspace/sql/databases/1851/query \
    --header 'Accept: application/json' \
    --header 'Authorization: Token [TOKEN VALUE]' \
    --header 'Content-Type: application/json' \
    --data '{
    "statements": ["SELECT id, name, email FROM users;"]
  }'
  ```

  </DocStep>
  <DocStep title="Leia a resposta">

  Um `200` carrega os nomes das colunas e um array por linha:

  ```json
  {
    "state": "executed",
    "data": [
      {
        "results": {
          "columns": ["id", "name", "email"],
          "rows": [[1, "Ada", "ada@example.com"]],
          "rows_read": 1,
          "rows_written": 0,
          "query_duration_ms": 0.08
        }
      }
    ]
  }
  ```

  </DocStep>
</DocSteps>

O seu primeiro banco de dados tem uma tabela `users` com uma linha, e a API a lê de volta. As mesmas instruções são executadas no Azion Console e dentro de uma function.

Uma instrução que falha não faz a requisição falhar. A resposta responde HTTP `200`, e a entrada dessa instrução carrega `error` no lugar de `results`:

```json
{
  "state": "executed",
  "data": [
    {
      "error": "no such table: nope"
    }
  ]
}
```

Verifique `data[].error` em cada instrução, e não o código de status HTTP. Para mais informações, consulte [Bancos de dados e consultas](/pt-br/documentacao/store/sql-database/bancos-de-dados-e-consultas/).
